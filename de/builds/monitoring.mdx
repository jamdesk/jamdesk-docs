Jeder Build durchläuft mehrere Phasen – von der Warteschlange bis zur Live-Schaltung. Überwache den Fortschritt über den Tab **Deployments**.

## Build-Phasen

<Steps>
  <Step title="Queued">
    Der Build wartet auf den Start. Die meisten Builds starten innerhalb weniger Sekunden.
  </Step>
  <Step title="Cloning">
    Der Repository-Inhalt wird von GitHub abgerufen.
  </Step>
  <Step title="Validating">
    Die `docs.json`-Konfiguration und die MDX-Syntax werden überprüft.
  </Step>
  <Step title="Processing">
    MDX-Dateien werden analysiert und Imports aufgelöst.
  </Step>
  <Step title="Building">
    MDX wird zu HTML kompiliert und Syntax-Highlighting angewendet.
  </Step>
  <Step title="Deploying">
    Die Dateien werden auf das CDN hochgeladen und der Cache wird geleert.
  </Step>
  <Step title="Live">
    Der Build ist abgeschlossen. Deine Dokumentation ist aktualisiert.
  </Step>
</Steps>

## Build-Status anzeigen

### Dashboard-Übersicht

Auf der Hauptseite deines Projekts werden folgende Informationen angezeigt:

- Aktueller Build-Status
- Zeitpunkt des letzten erfolgreichen Bereitstellens
- Verlauf der letzten Builds

### Build-Details

Klicke auf einen Build, um Folgendes anzuzeigen:

- Start- und Endzeit
- Dauer
- Ausgelöst durch (Push, manuell, CLI)
- Commit-Hash und -Nachricht
- Vollständiges Build-Log

### Warnungen und Vorschläge

Abgeschlossene Builds können Feedback in zwei Stufen enthalten:

- **Warnings** (orangefarbenes Badge) – Probleme, die behoben werden sollten, etwa defekte Links oder fehlende Assets. Sie schlagen beim Build niemals fehl.
- **Suggestions** (Glühbirne) – optionale Verbesserungen für Branding und SEO deiner Website, etwa das Hinzufügen eines [Favicons, einer Beschreibung oder eines Logos](/de/customization/branding). Suggestions werden nur bei deinem letzten abgeschlossenen Build angezeigt, zählen nicht zum Warnings-Badge und werden niemals per E-Mail versendet.

Viele Warnungen zu defekten Links und fehlenden Beschreibungen können automatisch behoben werden. Wenn dein letzter Build behebbare Probleme enthält, verwende [Fix with AI](/de/builds/fix-with-ai), um die Änderungen zu überprüfen und anzuwenden, ohne MDX manuell zu bearbeiten.

## Build-Logs

Detaillierte Logs helfen bei der Fehlersuche:

```text
[12:34:56] Starting build...
[12:34:57] Cloning repository...
[12:34:59] Found docs.json at root
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Build-Benachrichtigungen

Jamdesk kann dich per E-Mail oder Slack benachrichtigen, wenn ein Build abgeschlossen ist oder fehlschlägt:

### E-Mail

Aktiviere Benachrichtigungen bei fehlgeschlagenen Builds unter **Settings** → **Notifications**.

### Slack

Verbinde Slack, um Build-Benachrichtigungen in deinem Kanal zu erhalten. Siehe [Slack-Integration](/de/integrations/slack).

## Build-Verlauf

Zeige deine letzten 30 Builds im Tab **Deployments** an:

- Build-Status (success, failed, cancelled)
- Dauer
- Auslösetyp
- Commit-Informationen

## Builds abbrechen

So brichst du einen laufenden Build ab:

1. Öffne den Tab **Deployments**
2. Suche den laufenden Build
3. Klicke auf **Cancel**

Der vorherige erfolgreiche Build bleibt live.
