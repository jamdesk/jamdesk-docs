Jeder Build durchläuft mehrere Phasen von der Warteschlange bis zur Live-Schaltung. Den Fortschritt verfolgen Sie im Tab Deployments.

## Build-Phasen

<Steps>
  <Step title="Queued">
    Der Build wartet auf den Start. Die meisten Builds starten innerhalb weniger Sekunden.
  </Step>
  <Step title="Cloning">
    Ihre Repository-Inhalte werden von GitHub abgerufen.
  </Step>
  <Step title="Validating">
    `docs.json`-Konfiguration und MDX-Syntax werden geprüft.
  </Step>
  <Step title="Processing">
    MDX-Dateien werden geparst und Importe aufgelöst.
  </Step>
  <Step title="Building">
    MDX wird zu HTML kompiliert und Syntaxhervorhebung angewendet.
  </Step>
  <Step title="Deploying">
    Upload zum CDN und Leeren des Caches.
  </Step>
  <Step title="Live">
    Build abgeschlossen. Ihre Dokumentation ist aktualisiert.
  </Step>
</Steps>

## Build-Status anzeigen

### Dashboard-Übersicht

Die Hauptseite Ihres Projekts zeigt:

- Aktuellen Build-Status
- Zeitpunkt des letzten erfolgreichen Deployments
- Verlauf der letzten Builds

### Build-Details

Klicken Sie auf einen beliebigen Build, um Folgendes zu sehen:

- Start- und Endzeit
- Dauer
- Auslöser (Push, manuell, CLI)
- Commit-Hash und Commit-Nachricht
- Vollständiges Build-Log

### Warnungen und Vorschläge

Abgeschlossene Builds können zwei Stufen von Rückmeldungen enthalten:

- **Warnungen** (orangefarbenes Badge): Probleme, die Sie beheben sollten, etwa defekte Links oder fehlende Assets. Sie lassen den Build nie fehlschlagen.
- **Vorschläge** (Glühbirne): optionale Verbesserungen für Branding und SEO Ihrer Website, etwa das Hinzufügen eines [Favicons, einer Beschreibung oder eines Logos](/de/customization/branding). Vorschläge erscheinen nur im neuesten abgeschlossenen Build. Sie zählen nicht zum Warnungs-Badge. Jamdesk sendet sie niemals per E-Mail.

[Mit KI beheben](/de/builds/fix-with-ai) repariert viele Warnungen zu defekten Links und fehlenden Beschreibungen im neuesten Build. Sie prüfen und übernehmen die Änderungen, ohne MDX von Hand zu bearbeiten.

## Build-Logs

Detaillierte Logs helfen beim Debuggen von Problemen:

```text
[12:34:56] Starting build...
[12:34:57] Cloning repository...
[12:34:59] Found docs.json at root
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Build-Benachrichtigungen

Jamdesk kann Sie per E-Mail oder Slack benachrichtigen, wenn ein Build abgeschlossen ist oder fehlschlägt:

### E-Mail

Aktivieren Sie Benachrichtigungen bei fehlgeschlagenen Builds unter **Settings** → **Notifications**.

### Slack

Verbinden Sie Slack, um Build-Benachrichtigungen in Ihrem Kanal zu erhalten. Siehe [Slack-Integration](/de/integrations/slack).

## Build-Verlauf

Ihre letzten 30 Builds sehen Sie im Tab **Deployments**:

- Build-Status (erfolgreich, fehlgeschlagen, abgebrochen)
- Dauer
- Auslösertyp
- Commit-Informationen

## Builds abbrechen

So brechen Sie einen laufenden Build ab:

1. Gehen Sie zum Tab **Deployments**
2. Suchen Sie den laufenden Build
3. Klicken Sie auf **Cancel**

Der vorherige erfolgreiche Build bleibt live.
