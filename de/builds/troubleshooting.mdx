Das Build-Log zeigt, was fehlgeschlagen ist und wo. Finden Sie Ihre Fehlermeldung unten.

## Fehlerdetails anzeigen

1. Öffnen Sie den Tab **Deployments** Ihres Projekts
2. Klicken Sie auf den fehlgeschlagenen Build
3. Lesen Sie die Fehlermeldung und scrollen Sie durch das Build-Log

Das Log zeigt die genaue Datei und Zeile, die den Build gestoppt hat.

## Häufige Fehler

### Konfigurationsfehler

`Invalid docs.json` bedeutet, dass Ihre Konfigurationsdatei nicht geparst werden kann. Die übliche Ursache ist ein überflüssiges Komma, eine nicht geschlossene Klammer oder ein fehlendes Anführungszeichen.

<Steps>
  <Step title="JSON-Syntax prüfen">
    Achten Sie auf fehlende Kommas, Klammern oder Anführungszeichen.
  </Step>
  <Step title="Lokal validieren">
    Führen Sie `jamdesk validate` aus, um die genauen Fehler zu sehen.
  </Step>
  <Step title="Korrigieren und pushen">
    Korrigieren Sie sie und pushen Sie, um einen neuen Build auszulösen.
  </Step>
</Steps>

### Fehlende Seiten

`Page not found` bedeutet, dass Ihre Navigation auf eine Datei verweist, die nicht existiert. Vergleichen Sie den Dateinamen mit dem Pfad in `docs.json`. Groß- und Kleinschreibung müssen exakt übereinstimmen. Lassen Sie die Endung `.mdx` weg.

### MDX-Syntaxfehler

`MDX compilation failed` weist auf fehlerhaftes MDX oder JSX auf einer Seite hin. Meist handelt es sich um einen nicht geschlossenen Tag (eine `<Card>` ohne passendes `</Card>`), um ein nicht maskiertes Zeichen wie eine wörtliche `{`, wo Sie `\{` meinten, oder um eine ungültige Prop-Syntax.

### Build-Timeout

`Build exceeded time limit` bedeutet, dass der Build die erlaubte Zeit überschritten hat. Große, nicht optimierte Bilder sind die übliche Ursache. Komprimieren Sie sie, teilen Sie sehr große Seiten auf und entfernen Sie Seiten, die Sie nicht mehr veröffentlichen.

## Build-Warnungen

Warnungen lassen einen Build nie fehlschlagen. Ihre Website wird trotzdem veröffentlicht. Warnungen erscheinen in der E-Mail mit Build-Warnungen, im Eintrag des Builds im Tab **Deployments** und im Terminal, wenn Sie `jamdesk validate` oder `jamdesk dev` ausführen.

### Fehlende Bilder

`Image not found` warnt, dass eine Seite auf ein Bild verweist, das Ihr Projekt nicht enthält.

Jamdesk prüft jede Bildreferenz (Markdown `![alt](/images/photo.webp)` sowie das `src` von `<img>`- und `<Image>`-Tags) gegen die Dateien in Ihrem Repository. Die Warnung nennt die Seite, die Zeilennummer und den Pfad, der nicht aufgelöst werden konnte.

Laden Sie das Bild hoch oder verweisen Sie den Pfad auf eine existierende Datei. Pfade sind case-sensitiv. Ein Pfad mit führendem `/` wird vom Projektstamm aus aufgelöst. Jeder andere Pfad wird relativ zur Seite aufgelöst. Eine Referenz auf `photo.png` funktioniert weiterhin, nachdem die [Bildoptimierung](/de/builds/image-optimization) sie in WebP umgewandelt hat.

Jamdesk überspringt externe URLs, `data:`-URIs und Bild-Syntax innerhalb von Codeblöcken.

## Schritte zur Fehlerbehebung

<Accordion title="Schritt 1: Build-Log prüfen">
  Das Log nennt die genaue Datei und Zeile hinter dem Fehler. Beginnen Sie dort.
</Accordion>

<Accordion title="Schritt 2: Lokal testen">
  Führen Sie `jamdesk dev` aus, um den Fehler lokal zu reproduzieren.
</Accordion>

<Accordion title="Schritt 3: Konfiguration validieren">
  Führen Sie `jamdesk validate` aus, um `docs.json` zu prüfen. Führen Sie `jamdesk broken-links` aus, um defekte interne Links zu finden.
</Accordion>

<Accordion title="Schritt 4: Letzte Änderungen prüfen">
  Sehen Sie sich Ihren letzten Commit an. Haben Sie eine Seite hinzugefügt oder die Konfiguration geändert?
</Accordion>

## Problem weiterhin nicht gelöst?

Falls nichts davon das Problem löst:

1. Kopieren Sie das vollständige Build-Log
2. Notieren Sie Ihre Projekt-ID (sie steht in der URL)
3. [Kontaktieren Sie den Support](/de/help/support/contact)
