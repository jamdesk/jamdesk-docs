Pushen Sie zu GitHub, und Jamdesk erstellt automatisch einen Build. Sie können Builds auch über das Dashboard auslösen.

## Automatische Builds

Jeder Push in Ihren verbundenen Branch löst automatisch einen Build aus:

1. Sie pushen Änderungen zu GitHub
2. GitHub sendet einen Webhook an Jamdesk
3. Jamdesk stellt Ihren Build in die Warteschlange und startet ihn
4. Die erstellte Dokumentation wird im CDN bereitgestellt

<Tip>
Builds werden entprellt. Wenn Sie schnell mehrere Commits pushen, wartet Jamdesk 10 Sekunden, bis sich die Aktivität beruhigt hat, bevor der Build gestartet wird.
</Tip>

## Manuelle Builds

Lösen Sie einen Build aus, ohne Änderungen zu pushen:

<Steps>
  <Step title="Projekt öffnen">
    Öffnen Sie Ihr Projekt im Dashboard.
  </Step>
  <Step title="Zu den Einstellungen wechseln">
    Klicken Sie in der Seitenleiste auf **Settings**.
  </Step>
  <Step title="Rebuild anklicken">
    Wählen Sie **Rebuild**, um einen neuen Build zu starten.
  </Step>
</Steps>

### Wann manuelle Builds verwendet werden

- Nach dem Ändern von Umgebungsvariablen
- Zum Aktualisieren nach einem fehlgeschlagenen Build
- Nach Aktualisierungen der Jamdesk-Plattform
- Zum Löschen zwischengespeicherter Inhalte

## Build-Warteschlange

Bei hohem Datenverkehr können Builds kurzzeitig in die Warteschlange gestellt werden. Die Position in der Warteschlange wird im Dashboard angezeigt. Builds werden in der Reihenfolge ihres Eingangs verarbeitet.

## Gleichzeitige Builds

Für jedes Projekt kann jeweils nur ein Build ausgeführt werden. Neue Auslöser werden in die Warteschlange gestellt, solange ein Build ausgeführt wird.

| Plan | Gleichzeitige Projekte |
|------|------------------------|
| Trial | 1 |
| Pro | 3 |
