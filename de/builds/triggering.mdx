Jamdesk erstellt Ihre Dokumentation bei jedem Push zu GitHub. Sie können einen Build auch über das Dashboard auslösen.

## Automatische Builds

Jeder Push auf Ihren verbundenen Branch löst einen Build aus:

1. Sie pushen Änderungen zu GitHub
2. GitHub sendet einen Webhook an Jamdesk
3. Jamdesk reiht Ihren Build ein und startet ihn
4. Die erstellte Dokumentation wird im CDN bereitgestellt

<Tip>
Builds werden entprellt. Jamdesk wartet, bis 10 Sekunden ohne neuen Push vergangen sind, und startet dann den Build.
</Tip>

## Manuelle Builds

Einen Build ohne Pushen von Änderungen auslösen:

<Steps>
  <Step title="Projekt öffnen">
    Öffnen Sie Ihr Projekt im Dashboard.
  </Step>
  <Step title="Zu Settings wechseln">
    Klicken Sie in der Seitenleiste auf **Settings**.
  </Step>
  <Step title="Auf Rebuild klicken">
    Wählen Sie **Rebuild**. Ein neuer Build wird gestartet.
  </Step>
</Steps>

### Wann manuelle Builds verwendet werden

- Nach einer Änderung von Umgebungsvariablen
- Zum Aktualisieren nach einem fehlgeschlagenen Build
- Nach Updates der Jamdesk-Plattform
- Zum Leeren zwischengespeicherter Inhalte

## Build-Warteschlange

Builds können bei hoher Auslastung kurzzeitig in der Warteschlange stehen. Das Dashboard zeigt die Position in der Warteschlange an. Builds werden in der Reihenfolge ihres Eingangs ausgeführt.

## Gleichzeitige Builds

Jedes Projekt führt jeweils einen Build aus. Ein Auslöser, der während eines laufenden Builds eintrifft, wartet in der Warteschlange.

| Plan | Parallele Projekte |
|------|---------------------|
| Trial | 1 |
| Pro | 3 |
