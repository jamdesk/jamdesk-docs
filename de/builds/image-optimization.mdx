---
title: Automatische Bildkonvertierung
description: >-
  Aktivieren Sie in Jamdesk die automatische Konvertierung von PNG und JPG in WebP, um Bildgrößen zu reduzieren und Seiten schneller zu laden.
---

Jamdesk kann PNG- und JPG-Bilder während des Builds in das WebP-Format konvertieren. WebP-Dateien sind normalerweise 60–80 % kleiner als die Originale, ohne sichtbaren Qualitätsverlust. Dadurch laden Ihre Seiten schneller, ohne dass eine manuelle Bildverarbeitung erforderlich ist.

Die Funktion ist **standardmäßig deaktiviert**. Aktivieren Sie sie in Ihrer `docs.json`.

## Aktivieren

Fügen Sie das Feld `images.convertToWebp` zu Ihrer `docs.json` hinzu:

```json docs.json
{
  "images": {
    "convertToWebp": true
  }
}
```

Das ist die einzige Einstellung. Die Settings-Seite im Dashboard zeigt den aktuellen Status unter **Config Highlights** an, verfügt aber nicht über einen eigenen Schalter. `docs.json` ist die maßgebliche Quelle.

## Was konvertiert wird

| Quelle | Konvertiert? |
|--------|--------------|
| PNG | Ja |
| JPG / JPEG | Ja |
| SVG | Nein (bereits Vektorgrafik) |
| GIF | Nein (die Animation würde verloren gehen) |
| ICO | Nein (zu klein, um relevant zu sein) |
| WebP | Nein (bereits optimiert) |

Konvertierte Bilder behalten ihren Basisnamen und erhalten die Erweiterung `.webp`. Jede Referenz in Ihrem MDX, benutzerdefiniertem CSS, benutzerdefiniertem JS und in der `docs.json` wird automatisch aktualisiert. Sie müssen keine Pfade ändern.

## Was als Original erhalten bleibt

Einige Bilder bleiben auch bei aktivierter Konvertierung unverändert.

**Favicons.** Nicht jeder Browser und E-Mail-Client rendert WebP-Favicons zuverlässig.

Bilder für soziale Medien (`og:image` und `twitter:image` in Ihren `seo.metatags`) bleiben ebenfalls in ihrem ursprünglichen Format. Crawler sozialer Medien wie Facebook, LinkedIn, WhatsApp und ältere Versionen von Twitter/X rendern nicht alle WebP. Eine fehlerhafte Vorschaudarstellung ist schlechter als ein geringfügig größeres JPG.

Auch nicht verwendete Bilder werden übersprungen. Wenn eine Datei in Ihrem Verzeichnis `/images` liegt, aber weder von Ihrem MDX noch von der Konfiguration referenziert wird, wird das Original weiterhin in das CDN hochgeladen, aber nicht konvertiert. Es ist nicht sinnvoll, CPU-Zeit für etwas aufzuwenden, auf das nichts verweist.

Bilder, die von der Konvertierung nicht profitieren würden, bleiben als Originale erhalten. Wenn die WebP-Ausgabe größer als die Quelldatei wäre, wie es bei bereits komprimierten JPGs und sehr kleinen PNGs häufig vorkommt, behält Jamdesk das Original. Diese Bilder erscheinen in den Build-Statistiken als `skipped`.

Eine Ausnahme, die *konvertiert wird*, ist `background.image`. Dabei handelt es sich um einen vom Browser gerenderten Vollbildhintergrund, der wie jedes andere Bild von WebP profitiert.

## Build-Fortschrittsanzeige

Wenn die Funktion aktiviert ist, zeigt Ihr Build den Schritt **Optimizing images** in der Fortschrittsliste des Dashboards an, zwischen „Building documentation“ und „Uploading to CDN“. Die `jamdesk deploy` CLI zeigt denselben Schritt in ihrer Fortschrittsausgabe im Terminal an. Wenn die Funktion deaktiviert ist, wird der Schritt überhaupt nicht angezeigt.

## Build-Caching

Jamdesk speichert im Build-Manifest einen Hash jedes Quellbilds. Wenn sich eine Datei seit dem letzten Build nicht geändert hat, überspringt Jamdesk die Konvertierung und verwendet das zwischengespeicherte WebP erneut. Rebuilds bleiben auch bei Hunderten von Bildern schnell.

## Fehlerbehandlung

Wenn die Konvertierung eines einzelnen Bildes fehlschlägt (beschädigte Datei, unzureichender Arbeitsspeicher, unerwartetes Format), bleibt das Original erhalten und der restliche Build wird fortgesetzt. Ihre Dokumentation wird durch einen Fehler bei der Bildkonvertierung nicht beschädigt.

## Build-Protokolle

Zusätzlich zur Anzeige im Dashboard enthalten Ihre Build-Protokolle eine Zeile wie diese:

```text
Optimizing images... done (4 converted, 2 cached, 1 skipped, 0 failed, saved 1.2 MB)
```

| Feld | Bedeutung |
|-------|-----------|
| converted | In diesem Build von PNG/JPG in WebP konvertierte Bilder |
| cached | Unveränderte Bilder, die aus dem vorherigen Build übernommen wurden |
| skipped | Als Originale beibehaltene Bilder (geschützte Felder, nicht verwendete Dateien oder Formate, die keine Konvertierung benötigen) |
| failed | Fehlgeschlagene Konvertierungen (Originale bleiben erhalten) |
| saved | Insgesamt eingesparte Bytes über alle konvertierten Bilder hinweg |
