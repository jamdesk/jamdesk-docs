---
title: Automatische Bildkonvertierung
description: >-
  Aktivieren Sie die automatische Konvertierung von PNG und JPG in WebP in Jamdesk, um Bilddateien zu verkleinern und Seitenladezeiten ohne manuelle Bearbeitung zu verkürzen.
---

Jamdesk kann PNG- und JPG-Bilder während des Builds in das WebP-Format konvertieren. WebP-Dateien sind in der Regel 60–80 % kleiner als die Originale, ohne sichtbaren Qualitätsverlust. Seiten laden schneller, und eine manuelle Bildbearbeitung ist nicht nötig.

Die Funktion ist **standardmäßig deaktiviert**. Aktivieren Sie sie in Ihrer `docs.json`.

## Aktivieren

Fügen Sie das Feld `images.convertToWebp` in Ihrer `docs.json` hinzu:

```json docs.json
{
  "images": {
    "convertToWebp": true
  }
}
```

Das ist der einzige Schalter. Die Einstellungsseite im Dashboard zeigt den aktuellen Status unter **Config Highlights** an. Sie hat keinen eigenen Schalter. Die `docs.json` ist die maßgebliche Quelle.

## Was konvertiert wird

| Quelle | Konvertiert? |
|--------|--------------|
| PNG | Ja |
| JPG / JPEG | Ja |
| SVG | Nein (bereits Vektor) |
| GIF | Nein (Animation ginge verloren) |
| ICO | Nein (zu klein, um relevant zu sein) |
| WebP | Nein (bereits optimiert) |

Konvertierte Bilder behalten ihren Basisnamen und erhalten die Endung `.webp`. Jamdesk schreibt jede Referenz in Ihrem MDX, Ihrem benutzerdefinierten CSS, Ihrem benutzerdefinierten JS und Ihrer `docs.json` um. Sie müssen keine Pfade ändern.

## Was als Original erhalten bleibt

Manche Bilder bleiben auch dann unverändert, wenn die Konvertierung aktiviert ist.

**Favicons.** Nicht jeder Browser oder jeder E-Mail-Client stellt WebP-Favicons zuverlässig dar.

Bilder für Social Media (`og:image` und `twitter:image` in Ihren `seo.metatags`) behalten ebenfalls ihr Originalformat. Social-Media-Crawler wie Facebook, LinkedIn, WhatsApp und ältere Versionen von Twitter/X unterstützen WebP nicht durchgehend. Vorschaukarten, die nicht angezeigt werden, sind schlechter als ein etwas größeres JPG.

Nicht verwendete Bilder werden ebenfalls nicht konvertiert. Eine Datei in Ihrem Verzeichnis `/images`, auf die weder Ihr MDX noch Ihre Konfiguration verweist, wird als Original auf das CDN hochgeladen.

Jamdesk behält das Original, wenn die WebP-Ausgabe größer wäre als die Quelldatei. Das tritt häufig bei bereits komprimierten JPGs und sehr kleinen PNGs auf. Diese erscheinen in den Build-Statistiken als `skipped`.

`background.image` *wird* konvertiert. Es handelt sich um einen Vollbild-Hintergrund, der vom Browser gerendert wird.

## Build-Fortschrittsanzeige

Bei Builds mit aktivierter Funktion erscheint im Dashboard in der Fortschrittsliste der Schritt **Optimizing images**, zwischen „Building documentation“ und „Uploading to CDN“. Die CLI `jamdesk deploy` zeigt denselben Schritt in ihrer Terminalausgabe an. Ist die Funktion deaktiviert, erscheint der Schritt nicht.

## Build-Caching

Jamdesk speichert in dem Build-Manifest einen Hash jedes Quellbilds. Eine Datei, die sich seit dem letzten Build nicht geändert hat, wird nicht erneut konvertiert, und das zwischengespeicherte WebP wird wiederverwendet. Rebuilds bleiben auch bei hunderten Bildern schnell.

## Fehlerbehandlung

Schlägt die Konvertierung eines Bildes fehl (beschädigte Datei, Speicherüberlauf, unerwartetes Format), behält Jamdesk das Original. Der restliche Build läuft weiter.

## Build-Protokolle

Ihre Build-Logs enthalten eine Zeile wie diese:

```text
Optimizing images... done (4 converted, 2 cached, 1 skipped, 0 failed, saved 1.2 MB)
```

| Feld | Bedeutung |
|------|-----------|
| converted | Bilder, die in diesem Build von PNG/JPG in WebP konvertiert wurden |
| cached | Unveränderte Bilder, die aus dem vorherigen Build übernommen wurden |
| skipped | Als Original belassene Bilder (geschützte Felder, ungenutzte Dateien oder Formate, die keine Konvertierung benötigen) |
| failed | Fehlgeschlagene Konvertierungen (Originale bleiben erhalten) |
| saved | Gesamte eingesparte Bytes bei konvertierten Bildern |
