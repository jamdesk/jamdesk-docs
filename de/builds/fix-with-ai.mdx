Wenn ein Build mit defekten Links oder Seiten ohne Beschreibung abgeschlossen wird, kann Jamdesk viele dieser Probleme für Sie beheben. Die Schaltfläche **Fix with AI** liest die Build-Warnungen, schlägt für jede eine konkrete Änderung vor und committet die von Ihnen genehmigten Korrekturen in Ihr verbundenes GitHub-Repository. Dadurch wird ein neuer Build gestartet. Diese Seite richtet sich an alle, die eine Jamdesk-Website betreuen und Build-Warnungen beheben möchten, ohne MDX von Hand zu bearbeiten.

Für eine lokale Version desselben Ansatzes im Terminal siehe den [`jamdesk fix` CLI command](/de/cli/fix-broken-links). Der Dashboard-Ablauf committet die Änderungen für Sie; die CLI schreibt sie in Ihre Arbeitskopie und überlässt Ihnen den Commit.

## Was wird behoben?

Fix with AI funktioniert bei drei Arten von Build-Warnungen:

- **Defekte interne Links.** Ein Linkfragment verweist auf eine Überschrift, die auf der Zielseite nicht mehr vorhanden ist, etwa wegen eines Tippfehlers (`#instalation` → `#installation`) oder weil die Überschrift einer übersetzten Seite umbenannt wurde.
- **Fehlende Seitenbeschreibungen.** Eine Seite hat in ihrem Frontmatter keine `description`. Jamdesk erstellt aus dem Seiteninhalt eine kurze Zusammenfassung, die Sie prüfen können.
- **Fehlende Seitentitel.** Für eine Seite ohne Titel wird ein Vorschlag aus dem Seiteninhalt erstellt, den Sie prüfen können.

Eine Änderung wird nur vorgeschlagen, wenn sich das Ziel eindeutig bestimmen lässt. Alles Unklare bleibt unverändert und wird separat aufgeführt, damit Sie es von Hand beheben können.

Fix with AI führt pro Projekt innerhalb von 24 Stunden bis zu 1.000 KI-Anfragen aus. Ergebnisse für unveränderte Seiten werden wiederverwendet und zählen nicht zum Limit.

<Note>
  Die Anzahl der behebbaren Probleme entspricht nicht der Anzahl der Warnungen. Ein Build kann fünf Warnungen anzeigen, während Fix with AI nur drei davon beheben kann, weil es für die übrigen zwei keine eindeutige Korrektur gibt. Das Banner zeigt immer die Anzahl der tatsächlich behebbaren Probleme an.
</Note>

## Voraussetzungen

- Ein [verbundenes GitHub-Repository](/de/integrations/github) für das Projekt.
- Schreibzugriff für die Jamdesk GitHub App, damit sie die Korrekturen committen kann. Fehlt der Zugriff, zeigt das Modal den Link **Grant access**, über den Sie GitHub öffnen und den Zugriff gewähren können.
- Ein abgeschlossener Build mit Warnungen zu defekten Links oder fehlenden Beschreibungen.

## Banner finden

Öffnen Sie Ihr Projekt und scrollen Sie auf der Projektstartseite zu **Build History**. Wenn Ihr letzter Build behebbare Probleme enthält, erscheint über der Build-Liste ein Banner mit der Anzahl und einer Schaltfläche **Fix with AI**.

Das Banner erscheint nur bei Ihrem neuesten abgeschlossenen Build. Bei älteren Builds im Verlauf wird es nicht angezeigt, da Korrekturen immer auf den aktuellen Stand Ihrer Dokumentation angewendet werden.

## Fixes prüfen und anwenden

<Steps>
  <Step title="Vorschau öffnen">
    Klicken Sie auf **Fix with AI**. Das Modal wird geöffnet, und der KI-Agent prüft Ihre Dokumentation, um einen Korrekturplan zu erstellen. Das dauert einige Sekunden.
  </Step>
  <Step title="Vorgeschlagene Änderungen prüfen">
    Die Korrekturen sind nach Typ gruppiert. **Broken links** zeigt die jeweils geänderten Anker, **Missing descriptions** die vorgeschlagene Zusammenfassung für jede Seite und **Missing titles** den vorgeschlagenen Titel. Deaktivieren Sie das Kontrollkästchen bei allen Änderungen, die Sie diesmal überspringen möchten, oder verwenden Sie die Schaltfläche zum Ignorieren, um [eine Empfehlung dauerhaft auszublenden](#empfehlungen-ignorieren). Probleme ohne eindeutige Korrektur werden unter **Can't be fixed automatically** aufgeführt und müssen von Ihnen von Hand behoben werden.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="Das Modal Fix with AI. Im Abschnitt Broken links sind drei ausgewählte Korrekturen aufgeführt, jeweils mit durchgestrichenem altem Anker und korrigiertem Anker. Der Abschnitt Can't be fixed automatically enthält zwei Probleme, die von Hand behoben werden müssen. Darunter befinden sich die Schaltflächen Cancel und Apply 3 fixes." />
    </Frame>
  </Step>
  <Step title="Anwenden">
    Klicken Sie auf **Apply fixes**. Jamdesk committet die ausgewählten Änderungen in Ihren verbundenen Branch. Die Commit-Nachricht lautet `docs: apply AI-suggested fixes (via Jamdesk)`. Anschließend wird ein neuer Build gestartet.
  </Step>
  <Step title="Neuen Build prüfen">
    Beobachten Sie den neuen Build in [Build History](/de/builds/monitoring). Sobald er live ist, sind die behobenen Warnungen verschwunden. Übrig gebliebene Warnungen konnte Fix with AI entweder nicht beheben oder sie sind durch neue Inhalte entstanden.
  </Step>
</Steps>

<Note>
  Beim Anwenden wird ein echter Commit in Ihrem Repository erstellt. Die Änderung ist damit in Ihrem Git-Verlauf dokumentiert und kann wie jeder andere Commit auf GitHub geprüft oder rückgängig gemacht werden.
</Note>

## Wenn manche Probleme nicht behoben werden können

Hat eine Warnung keine eindeutige Korrektur, wird sie im Modal unter einer separaten Überschrift aufgeführt und bleibt unverändert. Häufige Gründe:

- Bei einem defekten Link existieren weder die Zielseite noch die Zielüberschrift, sodass es kein gültiges Linkziel gibt.
- Für einen Navigationseintrag gibt es keine passende Quelldatei.
- Der Agent konnte für eine Seite nicht automatisch eine Beschreibung erstellen.

Diese Probleme müssen manuell behoben werden. Öffnen Sie die Seite im [Editor](/de/development/local-preview) oder in Ihrem Code-Editor, korrigieren Sie den Link oder fügen Sie die Beschreibung hinzu und pushen Sie die Änderungen, um einen neuen Build zu starten.

## Empfehlungen ignorieren

Manche Warnungen müssen nicht behoben werden: etwa ein Link, den Sie absichtlich kaputt gemacht haben, oder eine Platzhalterseite, die keine Beschreibung benötigt. Wenn Sie eine Korrektur abwählen, wird sie nur dieses eine Mal übersprungen. Durch das Ignorieren wird sie aus der Anzahl entfernt, bis Sie sie wieder einblenden.

Jede Zeile im Modal hat eine Schaltfläche zum Ignorieren, unabhängig davon, ob das Problem behebbar ist. Klicken Sie darauf, und der Eintrag wird in den eingeklappten Abschnitt **Ignored** am unteren Rand verschoben. Wenn Sie das Modal schließen, wird die Anzahl im Banner auf der Projektstartseite entsprechend reduziert. Die passenden Warnungen verschwinden außerdem aus **Build History** – beim aktuellen und bei allen folgenden Builds. **Ignore all** führt dieselbe Aktion für alle noch aufgeführten Einträge aus.

So funktioniert das Ignorieren:

- **Für das ganze Projekt und dauerhaft.** Ignorierte Einträge gelten für das gesamte Projekt. Alle Mitglieder sehen dieselbe Liste, und die Einträge bleiben auch bei folgenden Builds ignoriert. Jamdesk erkennt jede Warnung anhand ihres Inhalts und nicht anhand ihrer Zeilennummer. Änderungen an anderen Stellen der Seite lassen einen ignorierten Eintrag daher nicht wieder erscheinen.
- **Wiederherstellen.** Klappen Sie den Abschnitt **Ignored** auf und klicken Sie beim gewünschten Eintrag auf **Restore**. Wenn Sie alle Warnungen eines Builds ignorieren, verschwindet das Banner. Ein kleiner Link „N ignored recommendations“ unter **Build History** öffnet das Modal erneut.
- **Geänderte Warnungen erscheinen wieder.** Ändert sich das zugrunde liegende Problem – etwa wenn der defekte Link nun auf ein anderes Ziel verweist –, stimmt es nicht mehr mit dem ignorierten Eintrag überein und wird als neue Empfehlung angezeigt.

## Mit KI beheben vs. CLI

Beide Tools korrigieren Anker defekter Links. Sie unterscheiden sich darin, wo sie ausgeführt werden und wie die Änderungen übernommen werden.

| | Fix with AI (Dashboard) | [`jamdesk fix`](/de/cli/fix-broken-links) (CLI) |
|---|---|---|
| Ausführung | Im Dashboard, für einen Build | Im Terminal, für lokale Dateien |
| Korrekturen | Defekte Links und fehlende Beschreibungen | Anker defekter Links |
| Commit | Committet die Änderungen für Sie in Ihren Branch | Schreibt lokale Dateien; Sie committen die Änderungen |
| Start | Ein Klick auf das Build-Banner | `jamdesk fix` |

Nutzen Sie den Dashboard-Ablauf für eine schnelle Korrektur direkt in Jamdesk. Verwenden Sie die CLI, wenn Sie die Änderungen zuerst in Ihrer Arbeitskopie übernehmen möchten, zum Beispiel, um sie mit anderen Änderungen zu bündeln.
