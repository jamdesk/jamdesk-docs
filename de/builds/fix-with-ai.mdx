Jamdesk kann viele der defekten Links und fehlenden Seitenbeschreibungen beheben, die ein Build meldet. Die Schaltfläche **Fix with AI** liest diese Build-Warnungen aus und schlägt für jede eine Änderung vor. Die von dir genehmigten Korrekturen werden in dein verbundenes GitHub-Repository übernommen. Der Commit startet einen neuen Build.

Der [CLI-Befehl `jamdesk fix`](/de/cli/fix-broken-links) erledigt dasselbe in deinem Terminal. Er schreibt in deine Arbeitskopie; den Commit führst du selbst aus.

## Was wird behoben?

Fix with AI behebt drei Arten von Build-Warnungen:

- **Defekte interne Links:** Ein Linkfragment verweist auf eine Überschrift, die auf der Zielseite nicht mehr existiert, etwa aufgrund eines Tippfehlers (`#instalation` → `#installation`) oder weil die Überschrift einer übersetzten Seite umbenannt wurde.
- **Fehlende Seitenbeschreibungen:** Eine Seite enthält keine `description` im Frontmatter. Jamdesk erstellt anhand des Seiteninhalts eine kurze Zusammenfassung, die du prüfen kannst.
- **Fehlende Seitentitel:** Für eine Seite ohne Titel wird anhand des Seiteninhalts ein Vorschlag erstellt, den du prüfen kannst.

Eine Änderung wird nur vorgeschlagen, wenn das Ziel zuverlässig bestimmt werden kann. Alles, was mehrdeutig ist, wird separat aufgeführt und muss manuell behoben werden.

Fix with AI führt innerhalb von 24 Stunden bis zu 1.000 KI-Anfragen pro Projekt aus. Ergebnisse für unveränderte Seiten werden wiederverwendet und zählen nicht zum Limit.

<Note>
  Die Anzahl der behebbaren Probleme entspricht nicht der Anzahl der Warnungen. Ein Build kann fünf Warnungen anzeigen, während Fix with AI nur drei davon beheben kann. Für die anderen beiden gibt es keine eindeutige Lösung.
</Note>

## Voraussetzungen

- Ein [verbundenes GitHub-Repository](/de/integrations/github) für das Projekt.
- Schreibzugriff für die Jamdesk GitHub App, damit sie die Korrekturen committen kann. Fehlt der Zugriff, zeigt das Modal einen Link **Grant access** zu GitHub an.
- Ein abgeschlossener Build mit Warnungen zu defekten Links oder fehlenden Seitenbeschreibungen.

## Banner finden

Öffne dein Projekt und scrolle auf der Projektstartseite zu **Build History**. Wenn dein letzter Build behebbare Probleme enthält, wird über der Build-Liste ein Banner mit der Anzahl und einer Schaltfläche **Fix with AI** angezeigt.

## Fixes prüfen und anwenden

<Steps>
  <Step title="Vorschau öffnen">
    Klicke auf **Fix with AI**. Das Modal wird geöffnet. Die KI benötigt einige Sekunden, um deine Dokumentation zu prüfen und einen Korrekturplan zu erstellen.
  </Step>
  <Step title="Jede vorgeschlagene Änderung prüfen">
    Die Korrekturen sind nach Typ gruppiert. Unter **Broken links** werden alle geänderten Anker angezeigt. Unter **Missing descriptions** erscheint die vorgeschlagene Zusammenfassung für jede Seite. Unter **Missing titles** wird der vorgeschlagene Titel angezeigt. Deaktiviere das Kontrollkästchen bei allen Änderungen, die du diesmal überspringen möchtest. Über die Schaltfläche zum Ignorieren kannst du eine Empfehlung [dauerhaft ausblenden](#empfehlungen-ignorieren). Probleme ohne eindeutige Lösung findest du unter **Can't be fixed automatically**; behebe sie manuell.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="Das Modal „Fix with AI“. Im Abschnitt „Broken links“ sind drei Korrekturen aktiviert. Jede zeigt den durchgestrichenen alten Anker und den korrigierten Anker. Im Abschnitt „Can't be fixed automatically“ werden zwei Probleme aufgeführt, die manuell behoben werden müssen. Darunter befinden sich die Schaltflächen „Cancel“ und „Apply 3 fixes“." />
    </Frame>
  </Step>
  <Step title="Anwenden">
    Klicke auf **Apply fixes**. Jamdesk committet die ausgewählten Änderungen in deinen verbundenen Branch. Die Commit-Nachricht lautet `docs: apply AI-suggested fixes (via Jamdesk)`. Anschließend wird ein neuer Build gestartet.
  </Step>
  <Step title="Neuen Build prüfen">
    Beobachte den neuen Build unter [Build History](/de/builds/monitoring). Sobald er live ist, sind die behobenen Warnungen verschwunden. Alle verbleibenden Warnungen konnte Fix with AI entweder nicht beheben oder sie sind durch neuere Inhalte entstanden.
  </Step>
</Steps>

<Note>
  Beim Anwenden wird ein echter Commit in deinem Repository erstellt. Du kannst ihn wie jeden anderen Commit auf GitHub prüfen oder rückgängig machen.
</Note>

## Wenn manche Probleme nicht behoben werden können

Das Modal führt Warnungen ohne eindeutige Lösung unter einer separaten Überschrift auf und lässt sie unverändert. Häufige Gründe:

- Ein defekter Link, dessen Zielseite oder Überschrift nirgends existiert.
- Ein Navigationseintrag ohne passende Quelldatei.
- Eine Seite, für die der Agent keine Beschreibung erstellen konnte.

Diese Probleme müssen manuell behoben werden. Öffne die Seite im [Editor](/de/development/local-preview) oder in deinem Code-Editor. Korrigiere den Link oder füge die Beschreibung hinzu. Pushe die Änderungen, um einen neuen Build zu starten.

## Empfehlungen ignorieren

Manche Warnungen musst du nicht beheben: etwa einen absichtlich defekten Link oder eine Platzhalterseite, die keine Beschreibung benötigt. Wenn du eine Korrektur abwählst, wird sie nur dieses eine Mal übersprungen. Durch Ignorieren wird sie aus der Anzahl entfernt, bis du sie wiederherstellst.

Jede Zeile im Modal hat eine Schaltfläche zum Ignorieren, unabhängig davon, ob das Problem behoben werden kann. Wenn du darauf klickst, wird der Eintrag in den eingeklappten Abschnitt **Ignored** am unteren Rand verschoben. Nachdem du das Modal geschlossen hast, wird die Anzahl im Banner auf der Projektstartseite entsprechend angepasst. Die zugehörigen Warnungen verschwinden aus **Build History** für den aktuellen und alle folgenden Builds. Mit **Ignore all** werden alle noch aufgeführten Einträge ignoriert.

So funktionieren ignorierte Empfehlungen:

- **Für alle freigegeben und dauerhaft:** Ignorierungen gelten für das ganze Projekt. Alle Mitglieder sehen dieselbe Liste. Sie bleiben auch für künftige Builds bestehen. Jamdesk ordnet Warnungen anhand ihres Inhalts zu, nicht anhand der Zeilennummer. Änderungen an anderen Teilen der Seite bringen einen ignorierten Eintrag nicht zurück.
- **Wiederherstellen:** Klappe den Abschnitt **Ignored** auf und klicke bei einem Eintrag auf **Restore**. Wenn du alle Warnungen eines Builds ignorierst, wird das Banner ausgeblendet. Ein kleiner Link „N ignored recommendations“ unter **Build History** öffnet das Modal erneut.
- **Geänderte Warnungen erscheinen erneut:** Ein ignorierter Eintrag wird als neue Empfehlung angezeigt, wenn sich das zugrunde liegende Problem ändert, zum Beispiel wenn der defekte Link nun auf ein anderes Ziel verweist.

## Mit KI beheben vs. CLI

Das Dashboard und die CLI korrigieren Anker defekter Links. Sie unterscheiden sich darin, wo sie ausgeführt werden und wie die Änderung übernommen wird.

| | Fix with AI (Dashboard) | [`jamdesk fix`](/de/cli/fix-broken-links) (CLI) |
|---|---|---|
| Ausführung | Im Dashboard, für einen Build | Im Terminal, für lokale Dateien |
| Korrekturen | Defekte Links und fehlende Seitenbeschreibungen | Anker defekter Links |
| Commit | Committet Änderungen für dich in deinen Branch | Schreibt lokale Dateien; du committest |
| Start | Ein Klick auf das Build-Banner | `jamdesk fix` |

Nutze den Dashboard-Ablauf für eine schnelle Korrektur, ohne Jamdesk zu verlassen. Verwende die CLI, wenn du die Änderungen zuerst in deiner Arbeitskopie haben möchtest, zum Beispiel um sie mit anderen Änderungen zu bündeln.
