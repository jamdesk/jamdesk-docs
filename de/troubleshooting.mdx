## Build-Fehler

Ihr Dashboard zeigt einen Build als „Failed“ an. Häufige Ursachen:

- Eine MDX-Seite mit einem fehlerhaften Import oder einer fehlerhaften Komponente.
- Ungültige `docs.json` (nicht geschlossene Klammern, nachgestellte Kommas nach dem letzten Array-Element).
- Eine in der Navigation von `docs.json` aufgeführte Seite, die nicht als `.mdx`-Datei existiert.

Führen Sie `jamdesk dev` vor dem Push aus. Die ersten beiden Fehlerarten werden lokal erkannt.

<Tip>
Das Build-Protokoll in Ihrem Dashboard zeigt die genaue Datei und Zeile des Fehlers. Beginnen Sie dort.
</Tip>

Für spezifische Fehlercodes siehe [Build-Fehler](/de/help/troubleshooting/build-failures) und die [Fehlerreferenz](/de/help/troubleshooting/error-reference).

## Benutzerdefinierte Domain wird nicht verifiziert

Wenn Ihre Domain nach dem Hinzufügen der DNS-Einträge weiterhin „Pending“ bleibt, prüfen Sie der Reihe nach Folgendes:

1. Bestätigen Sie, dass Sie den `_jamdesk.<hostname>`-**TXT**-Eintrag hinzugefügt haben. Ohne ihn wird das Routing nicht aktiviert. Ein fehlender TXT-Eintrag ist die häufigste Ursache für eine ausstehende Domain. Der Hostname ist die vollständige Domain, die Sie verifizieren (für `docs.example.com` lautet der Name des TXT-Eintrags `_jamdesk.docs.example.com`).
2. Bestätigen Sie, dass Sie für Subdomains einen **CNAME**-Eintrag (und keinen A-Eintrag) hinzugefügt haben.
3. Wenn Sie Cloudflare verwenden, stellen Sie den Proxy für beide Einträge auf **Nur DNS** (graue Wolke).
4. Prüfen Sie die Propagierung auf [whatsmydns.net](https://www.whatsmydns.net/).

```bash
# Verify the TXT verification record
dig TXT _jamdesk.docs.yourdomain.com

# Verify your CNAME is resolving
dig CNAME docs.yourdomain.com
```

Das Dashboard kann bis zu 30 Minuten nach der Auflösung Ihrer Einträge durch `dig` weiterhin „Pending“ anzeigen. Der Verifizierer arbeitet hinter vorgelagerten Resolvern, die negative DNS-Antworten zwischenspeichern. Warten Sie eine halbe Stunde, bevor Sie nach einem tieferliegenden Problem suchen.

[DNS-Fehlerbehebung](/de/help/troubleshooting/dns-issues) behandelt anbieterspezifische Besonderheiten.

## Gültige OpenAPI-Spezifikation lässt sich nicht validieren

`jamdesk dev` lehnt eine gültige Spezifikation mit Fehlern wie `#/servers/0/variables/host must NOT have unevaluated properties` ab. Das betrifft meist Server-Variablen mit einer `description` oder eine Lizenz mit nur einem `name`. Das Problem liegt in der Kopie des OpenAPI-3.1-Meta-Schemas, die die CLI mitbringt. npm 12 blockiert Paket-Install-Skripte standardmäßig. Dadurch wird der Schritt übersprungen, der zwei bekannte Fehler im Schema korrigiert.

Aktualisieren Sie die CLI. Version 1.1.167 und neuer repariert das Schema zur Validierungszeit:

```bash
npm install -g jamdesk@latest
```

Bei einer älteren, fixierten Version führen Sie `npm install -g --allow-scripts=jamdesk jamdesk` aus, damit der Installationsschritt laufen kann.

## GitHub-Repository wird nicht angezeigt

Ein fehlendes Repo in der Liste bedeutet meist, dass die Jamdesk-GitHub-App nicht in der Organisation des Repos installiert ist. Der Repository-Zugriff kann auch auf „Selected repositories“ gesetzt sein, ohne Ihr Repo. Autorisieren Sie erneut unter [github.com/settings/installations](https://github.com/settings/installations) und erteilen Sie Zugriff auf „All repositories“ oder das bestimmte Repo.

Siehe [GitHub-Probleme](/de/help/troubleshooting/github-issues) für Webhook- und Berechtigungsprobleme.

## Analysedaten fehlen

Analysen können bis zu 24 Stunden nach dem ersten Deployment einer Website erscheinen. Werbeblocker und „Do Not Track“ verhindern, dass manche Besuche gezählt werden. Ihre Zahlen liegen daher immer hinter Ihren Server-Logs. Wenn Ihr Dashboard weiterhin null Besucher anzeigt, prüfen Sie, ob Ihre Website deployt und öffentlich erreichbar ist.

[Analyse-Probleme](/de/help/troubleshooting/analytics-issues) behandelt verzögerte oder fehlende Daten genauer.

## Anmeldeprobleme

Wenn Sie sich nicht anmelden können oder immer wieder zum Anmeldebildschirm zurückgeleitet werden, löschen Sie Cache und Cookies für `dashboard.jamdesk.com`. Versuchen Sie es danach in einem Inkognito-Fenster. Die Anmeldung über GitHub setzt voraus, dass Ihre GitHub-E-Mail-Adresse mit der E-Mail-Adresse Ihres Jamdesk-Kontos übereinstimmt.

Siehe [Anmeldeprobleme](/de/help/troubleshooting/login-issues) für Schritte zur Kontowiederherstellung.
