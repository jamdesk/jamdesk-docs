Vor dem Schreiben von Dokumentation benötigen Sie ein Projekt. Sie können mit einer Vorlage beginnen (Jamdesk erstellt das Repository für Sie auf GitHub oder Bitbucket Cloud) oder ein vorhandenes Repository verbinden, das bereits eine `docs.json` enthält. In beiden Fällen ist Ihre Website innerhalb weniger Minuten live.

## Ein neues Projekt erstellen

<Steps>
  <Step title="Bei Jamdesk anmelden">
    Gehen Sie zu [dashboard.jamdesk.com](https://dashboard.jamdesk.com) und melden Sie sich mit Ihrem GitHub-Konto an.

    Erstnutzer werden aufgefordert, die Jamdesk GitHub App zu autorisieren.
  </Step>

  <Step title="Auf New Project klicken">
    Klicken Sie im Dashboard oben rechts auf **New Project**.
  </Step>

  <Step title="Ausgangspunkt auswählen">
    <Tabs>
      <Tab title="From Template">
        Beginnen Sie mit einer vorgefertigten Vorlage. Jamdesk erstellt für Sie ein neues GitHub-Repository mit bereits konfigurierten Beispielinhalten, einer Navigation und Komponenten.

        Die standardmäßige [Starter Template](https://github.com/jamdesk/starter-docs) enthält Beispielseiten, eine OpenAPI-Spezifikation und Beispiele für alle Komponenten. Ersetzen Sie die Inhalte durch Ihre eigenen Inhalte, und schon sind Sie fertig.
      </Tab>
      <Tab title="From Repository">
        Verbinden Sie ein vorhandenes GitHub-Repository:

        1. Wählen Sie das Repository aus dem Dropdown-Menü aus
        2. Wählen Sie den bereitzustellenden Branch aus (normalerweise `main`)
        3. Geben Sie den Pfad zu `docs.json` an, falls sich die Datei nicht im Stammverzeichnis befindet

        Repository auf Bitbucket Cloud? Geben Sie es als `workspace/repository-slug` ein. Siehe [Bitbucket verbinden](/de/setup/connecting-bitbucket).
      </Tab>
    </Tabs>
  </Step>

  <Step title="Projekteinstellungen konfigurieren">
    Legen Sie die grundlegenden Informationen Ihres Projekts fest:

    | Feld | Beschreibung |
    |-------|-------------|
    | **Name** | Im Dashboard angezeigter Name |
    | **Slug** | URL-freundlicher Bezeichner (z. B. `my-docs`) |
    | **Domain** | Ihre `*.jamdesk.app`-Subdomain |
  </Step>
</Steps>

## Minimale Repository-Struktur

Ein Jamdesk-Projekt benötigt lediglich eine `docs.json` und mindestens eine Seite:

```bash
my-docs/
├── docs.json
└── introduction.mdx
```

Beispiel für eine `docs.json`:

```json docs.json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

## Projekteinstellungen

Konfigurieren Sie Ihr Projekt nach der Erstellung unter **Settings**:

### Allgemein

- **Name** – Aktualisieren Sie den Anzeigenamen
- **Slug** – Ändern Sie den Projektbezeichner
- **Delete Project** – Entfernen Sie das Projekt dauerhaft

### Repository

- **Branch** – Der Branch, der Bereitstellungen auslöst
- **Docs Path** – Speicherort der `docs.json` in Monorepos

### Domain

- **Subdomain** – Ihre `*.jamdesk.app`-URL
- **Custom Domain** – Fügen Sie Ihre eigene Domain hinzu
- **Host at a subpath** – Stellen Sie die Dokumentation unter einem Pfad wie `/docs` oder `/help` statt im Stammverzeichnis der Website bereit

### Build

- **Show Jamdesk Branding** – Zeigen Sie den Link „Powered by Jamdesk“ in Ihrer Fußzeile an (standardmäßig aktiviert)
- **Rebuild** – Lösen Sie manuell einen neuen Build aus

<Note>
Änderungen an den Build-Einstellungen werden erst nach einem neuen Build wirksam.
</Note>
