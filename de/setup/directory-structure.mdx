Organisieren Sie die Dateien in einem Jamdesk-Dokumentations-Repository, vom minimalen Zwei-Dateien-Setup bis zu einem vollständigen Layout mit mehreren Verzeichnissen.

## Minimale Struktur

Das einfachste Jamdesk-Projekt benötigt zwei Dateien:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

## Empfohlene Struktur

Für größere Dokumentationsseiten organisieren Sie Seiten in Verzeichnissen:

```bash
my-docs/
├── docs.json
├── introduction.mdx
├── quickstart.mdx
│
├── guides/
│   ├── getting-started.mdx
│   ├── authentication.mdx
│   └── deployment.mdx
│
├── api-reference/
│   ├── overview.mdx
│   ├── endpoints/
│   │   ├── users.mdx
│   │   └── projects.mdx
│   └── webhooks.mdx
│
├── images/
│   ├── logo.svg
│   ├── favicon.svg
│   └── screenshots/
│       └── dashboard.png
│
└── snippets/
    └── api-base-url.mdx
```

<Tip>
Das [Jamdesk-Dokumentations-Repo](https://github.com/jamdesk/jamdesk-docs) ist ein produktives Beispiel für diese Struktur: zwei Tabs, über 120 Seiten, OpenAPI-Spezifikationen und eigene Skripte.
</Tip>

## Erforderliche Dateien

### docs.json

Die Konfigurationsdatei, die Ihre Seite definiert. Sie muss im Stammverzeichnis Ihres Dokumentationsverzeichnisses liegen (oder im Pfad, der in den Projekteinstellungen angegeben ist).

```json docs.json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Documentation",
  "theme": "jam",
  "colors": {
    "primary": "#635BFF"
  },
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "quickstart"]
      }
    ]
  }
}
```

Alle Optionen finden Sie in der [docs.json-Referenz](/de/config/docs-json-reference).

## Seitenorganisation

### Flach oder verschachtelt

Wählen Sie je nach Umfang Ihrer Dokumentation:

<Tabs>
  <Tab title="Flach (< 20 Seiten)">
    Behalten Sie alle Seiten im Stammverzeichnis:

    ```bash
    docs/
    ├── docs.json
    ├── introduction.mdx
    ├── installation.mdx
    ├── configuration.mdx
    └── troubleshooting.mdx
    ```

    Referenzieren Sie Seiten direkt in der Navigation:

    ```json
    "pages": ["introduction", "installation"]
    ```
  </Tab>
  <Tab title="Verschachtelt (20+ Seiten)">
    Gruppieren Sie zusammengehörige Seiten in Verzeichnissen:

    ```bash
    docs/
    ├── docs.json
    ├── introduction.mdx
    ├── guides/
    │   ├── quickstart.mdx
    │   └── advanced.mdx
    └── reference/
        ├── api.mdx
        └── cli.mdx
    ```

    Nehmen Sie das Verzeichnis in den Pfad auf:

    ```json
    "pages": ["introduction", "guides/quickstart", "reference/api"]
    ```
  </Tab>
</Tabs>

### Namenskonventionen

| Konvention | Beispiel | URL |
|------------|---------|-----|
| Kleinbuchstaben | `getting-started.mdx` | `/de/getting-started` |
| Kebab-Case | `api-reference.mdx` | `/de/api-reference` |
| Verzeichnisse | `guides/auth.mdx` | `/de/guides/auth` |

<Warning>
Vermeiden Sie Leerzeichen und Sonderzeichen in Dateinamen. Verwenden Sie Bindestriche, um Wörter zu trennen.
</Warning>

## Besondere Verzeichnisse

### images/

Speichern Sie Bilder, Logos und Favicons:

```bash
images/
├── logo-light.webp     # Light mode logo
├── logo-dark.webp      # Dark mode logo
├── favicon.svg         # Browser favicon
└── screenshots/        # Documentation screenshots
    └── dashboard.png
```

Referenzieren in docs.json:

```json docs.json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp"
  },
  "favicon": "/images/favicon.svg"
}
```

### snippets/

Wiederverwendbare Inhaltsblöcke:

```bash
snippets/
├── api-base-url.mdx
└── auth-header.mdx
```

Einbinden in Seiten:

```mdx
<Snippet file="api-base-url.mdx" />
```

### openapi/

OpenAPI-Spezifikationsdateien für API-Dokumentation:

```bash
openapi/
├── api.yaml
└── webhooks.yaml
```

Referenzieren in docs.json:

```json docs.json
{
  "api": {
    "openapi": ["/openapi/api.yaml"]
  }
}
```

Ein Live-Beispiel finden Sie unter [OpenAPI-Beispiel](/de/api-reference/openapi-example).

#### Sprachspezifische Spezifikationsdateien

Für mehrsprachige Dokumentationsseiten fügen Sie übersetzte Spezifikationsdateien neben der Quelldatei mit einem Sprachcode-Infix hinzu:

```bash
openapi/
├── api.yaml
├── api.fr.yaml
├── api.es.yaml
└── api.zh.yaml
```

Jamdesk liefert automatisch die richtige Spezifikation aus, wenn eine Seite unter einem Sprachpräfix (`/fr/…`, `/es/…` usw.) gerendert wird. Die vollständigen Regeln dazu, was übersetzt und was identisch belassen werden soll, finden Sie unter [Mehrsprachige Unterstützung → OpenAPI-Spezifikationen übersetzen](/de/setup/languages#translating-openapi-specs).

## Zu ignorierende Dateien

Erstellen Sie eine `.gitignore`, um Build-Artefakte auszuschließen:

```bash
.jamdesk/
node_modules/
.DS_Store
*.log
```

Das Verzeichnis `.jamdesk/` enthält den lokalen Entwicklungscache. Committen Sie es nicht.
