Migriere ein Mintlify-Projekt mit einem Befehl: `jamdesk migrate` liest `mint.json`, schreibt `docs.json` und schreibt deine MDX-Dateien direkt um. Für GitBook, Docusaurus, ReadMe, Confluence oder eine andere Plattform folge den manuellen Schritten im Tab „Von anderen Plattformen“.

<YouTube id="DvIHWeBliK0" />

<Info>
**Exportiere die Inhalte zuerst als Markdown, wenn möglich.** Jamdesk basiert auf MDX. Eine Markdown-Datei muss nur in `.mdx` umbenannt werden und einige Zeilen Frontmatter erhalten.
</Info>

    ### Automatische Migration

    <Steps>
      <Step title="CLI installieren">
        ```bash
        npm install -g jamdesk
        ```
      </Step>
      <Step title="Migration ausführen">
        ```bash
        jamdesk migrate
        ```

        Führe den Befehl im Projektstammverzeichnis aus. Er erledigt Folgendes:

        - Liest `mint.json` und schreibt `docs.json`
        - Benennt veraltete Komponenten in MDX-Dateien um (z. B. `CardGroup` → `Columns`)
        - Verschiebt verwaiste MDX-Snippet-Dateien nach `/snippets/` und schreibt alle relativen Imports mit `../` auf root-relative Imports um (`../foo/bar.mdx` wird zu `/snippets/foo/bar.mdx`)
        - Extrahiert Inline-Komponenten mit React Hooks nach `/snippets/<name>.tsx`, ergänzt die Direktive `'use client'` und ändert den ursprünglichen MDX-Import so, dass er aus `/snippets/` importiert
        - Behebt automatisch mechanische MDX-Syntaxprobleme, die den Build zum Absturz bringen würden

        Der Befehl ist idempotent. Führe ihn nach Änderungen erneut aus, um nur neue Inhalte zu erfassen. Alles, was sich nicht sicher beheben lässt, wird als Warnung mit Datei, Import und erforderlicher Maßnahme ausgegeben.
      </Step>
      <Step title="Prüfen und anpassen">
        Prüfe die erzeugten Dateien `docs.json` und MDX. Überprüfe die Navigationsstruktur und behebe alle von der CLI ausgegebenen Warnungen.
      </Step>
    </Steps>

    ### Konfigurationszuordnung

    Die CLI konvertiert `mint.json` in `docs.json`. Prüfe die Ausgabe anhand dieser Unterschiede.

    **Mintlify (`mint.json`):**
    ```json
    {
      "name": "My Docs",
      "navigation": [
        { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
      ],
      "colors": { "primary": "#0D9373" },
      "topbarLinks": [{ "name": "Blog", "url": "https://example.com/blog" }]
    }
    ```

    **Jamdesk (`docs.json`):**
    ```json
    {
      "$schema": "https://jamdesk.com/docs.json",
      "name": "My Docs",
      "theme": "jam",
      "colors": { "primary": "#0D9373" },
      "navbar": {
        "links": [{ "label": "Blog", "href": "https://example.com/blog" }]
      },
      "navigation": {
        "groups": [
          { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
        ]
      }
    }
    ```

    ### Komponentenkompatibilität

    Die meisten Mintlify-Komponenten haben direkte Jamdesk-Entsprechungen. Einige haben andere Namen oder Syntax.

    | Mintlify-Komponente | Jamdesk-Entsprechung | Hinweise |
    |---|---|---|
    | `<Card>` | `<Card>` | Gleiche Syntax |
    | CardGroup | `<Columns>` | Verwende die Prop `cols`, um die Spaltenanzahl festzulegen |
    | `<Columns>` | `<Columns>` | Gleiche Syntax |
    | `<Accordion>` | `<Accordion>` | Gleiche Syntax |
    | `<Tabs>` / `<Tab>` | `<Tabs>` / `<Tab>` | Gleiche Syntax |
    | `<Steps>` / `<Step>` | `<Steps>` / `<Step>` | Gleiche Syntax |
    | `<CodeGroup>` | `<CodeGroup>` | Gleiche Syntax |
    | `<Tip>`, `<Note>`, `<Warning>` | `<Tip>`, `<Note>`, `<Warning>` | Gleiche Syntax |
    | `<ResponseField>` | `<ParamField>` | Anderer Name |
    | `<Snippet>` | Import aus `/snippets/` | Andere Vorgehensweise |

    ### Häufige Probleme

    <AccordionGroup>
      <Accordion title="CardGroup wird zu Columns">
        `jamdesk migrate` benennt `CardGroup` in jeder MDX-Datei in `Columns` um. Die Prop `cols` bleibt unverändert erhalten. Prüfe alle Dateien, die du nach der Migration bearbeitet hast.
      </Accordion>
      <Accordion title="ResponseField wird zu ParamField">
        Benenne `<ResponseField>` in `<ParamField>` um. Die Props bleiben gleich.

        ```mdx
        {/* Before */}
        <ResponseField name="id" type="string" required>
          The unique identifier
        </ResponseField>

        {/* After */}
        <ParamField name="id" type="string" required>
          The unique identifier
        </ParamField>
        ```
      </Accordion>
      <Accordion title="Snippets werden automatisch verschoben und angepasst">
        Jamdesk löst nur root-relative `/snippets/*`-Imports auf. In Mintlify-Projekten liegen MDX-Snippet-Dateien oft an beliebigen Stellen in der Verzeichnisstruktur und werden über relative Pfade mit `../` importiert (`import X from '../shared/x.mdx'`).

        `jamdesk migrate` behebt das:

        - Verschiebt MDX-Dateien, die als Snippets importiert werden, aber außerhalb von `/snippets/` liegen, nach `/snippets/`. Der relative Pfad bleibt erhalten, damit Snippets mit Locale-Präfix wie `de/foo.mdx` nicht kollidieren.
        - Schreibt alle relativen Snippet-Imports mit `../` in sämtlichen MDX-Dateien auf den neuen root-relativen Pfad um.
        - Extrahiert jede Inline-Komponente mit React Hooks in eine Datei mit `'use client'` unter `/snippets/<name>.tsx` und ersetzt den Inline-Export durch einen Import aus `/snippets/`.

        Ersetze das JSX-Element `<Snippet file="my-snippet.mdx" />` von Mintlify durch einen MDX-Import. Die CLI schreibt es nicht um:

        ```mdx
        {/* Before (Mintlify) */}
        <Snippet file="my-snippet.mdx" />

        {/* After (Jamdesk) */}
        import MySnippet from '/snippets/my-snippet.mdx'

        <MySnippet />
        ```

        Der Verschiebevorgang wird abgebrochen, ohne Änderungen vorzunehmen, wenn dein Projekt keine aufgelöste Navigation hat oder die geplanten Verschiebungen mehr als `max(5, 25%)` aller MDX-Dateien betreffen. Der Grund wird ausgegeben. Behebe das Problem und führe den Befehl erneut aus.
      </Accordion>
      <Accordion title="topbarLinks wird navbar.links zugeordnet">
        Mintlifys `topbarLinks` und `topbarCtaButton` werden in `docs.json` `navbar.links` zugeordnet. Das Feld `name` wird zu `label`. Das Feld `url` wird zu `href`.
      </Accordion>
    </AccordionGroup>

    ### Von GitBook

    GitBook speichert Inhalte als Markdown und verwendet die Datei `SUMMARY.md` für die Navigation.

    <Steps>
      <Step title="Inhalte exportieren">
        Exportiere deinen GitBook-Bereich als Markdown. Bei GitBooks Git-Sync liegen deine Inhalte bereits als `.md`-Dateien in einem Git-Repository.
      </Step>
      <Step title="Dateien in MDX konvertieren">
        Benenne `.md`-Dateien in `.mdx` um und füge jeder Datei Frontmatter hinzu:

        ```mdx
        ---
        title: Your Page Title
        description: A short description of the page
        ---

        Your existing Markdown content here.
        ```
      </Step>
      <Step title="Navigation aus SUMMARY.md zuordnen">
        Übertrage die Seitenleiste aus `SUMMARY.md` in Navigationsgruppen in `docs.json`.

        **GitBook (`SUMMARY.md`):**
        ```markdown
        # Summary

        ## Getting Started
        * [Introduction](introduction.md)
        * [Quick Start](quickstart.md)

        ## API Reference
        * [Authentication](api/auth.md)
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["introduction", "quickstart"]
              },
              {
                "group": "API Reference",
                "pages": ["api/auth"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Bilder verschieben">
        Verschiebe alle Bilder in ein Verzeichnis `/images` und aktualisiere die Verweise in deinen MDX-Dateien, sodass sie absolute Pfade verwenden (z. B. `/images/screenshot.png`).
      </Step>
      <Step title="Lokal testen">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Von Docusaurus

    Docusaurus-Projekte verwenden bereits MDX. Die meisten Inhalte lassen sich direkt übernehmen.

    <Steps>
      <Step title="MDX-Dateien kopieren">
        Kopiere den Inhalt des Docusaurus-Verzeichnisses `docs/` in das Stammverzeichnis deines Jamdesk-Projekts. Behalte die vorhandene Verzeichnisstruktur bei.
      </Step>
      <Step title="Frontmatter bereinigen">
        Entferne Docusaurus-spezifische Frontmatter-Felder. Behalte `title` und `description`, und entferne die übrigen Felder.

        ```yaml
        ---
        # Remove these Docusaurus fields
        sidebar_position: 3
        sidebar_label: "Custom Label"
        slug: /custom-url
        pagination_next: null

        # Keep these
        title: Your Page Title
        description: A short description
        ---
        ```
      </Step>
      <Step title="sidebars.js docs.json zuordnen">
        Übertrage die Kategorienstruktur aus `sidebars.js` in Navigationsgruppen in `docs.json`.

        **Docusaurus (`sidebars.js`):**
        ```javascript
        module.exports = {
          docs: [
            {
              type: 'category',
              label: 'Getting Started',
              items: ['intro', 'installation'],
            },
          ],
        };
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["intro", "installation"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Docusaurus-Komponenten ersetzen">
        Ersetze Docusaurus-spezifische Komponenten durch Jamdesk-Entsprechungen.

        | Docusaurus | Jamdesk | Beispiel |
        |---|---|---|
        | `:::note` / `:::tip` / `:::warning` | `<Note>` / `<Tip>` / `<Warning>` | Siehe [Hinweiskomponenten](/de/components/overview) |
        | `import Tabs from '@theme/Tabs'` | `<Tabs>` (global verfügbar) | Kein Import erforderlich |
        | `import TabItem from '@theme/TabItem'` | `<Tab>` (global verfügbar) | Verwende `title` statt `label` |
      </Step>
      <Step title="Lokal testen">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Von anderen Tools

    Für Confluence, Notion, ReadMe oder eine andere Plattform übertrage deine Inhalte in Markdown. Richte anschließend die Jamdesk-Projektstruktur ein.

    <Steps>
      <Step title="Als Markdown exportieren">
        Die meisten Plattformen bieten einen Markdown- oder HTML-Export. Verwende Markdown, wenn verfügbar. Konvertiere HTML mit einem Tool wie [Pandoc](https://pandoc.org/) in Markdown.

        ```bash
        # Convert HTML to Markdown with Pandoc
        pandoc input.html -f html -t markdown -o output.md
        ```
      </Step>
      <Step title="docs.json erstellen">
        Beginne mit einer minimalen Konfiguration. Ergänze die Navigation, wenn du Seiten hinzufügst.
      </Step>
      <Step title="Dateien in MDX konvertieren">
        Benenne `.md`-Dateien in `.mdx` um und füge jeder Datei Frontmatter (`title`, `description`) hinzu.
      </Step>
      <Step title="Assets verschieben">
        Verschiebe Bilder und andere Assets in ein Verzeichnis `/images`. Aktualisiere die Dateiverweise, sodass sie absolute Pfade verwenden.
      </Step>
      <Step title="Lokal testen">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>
