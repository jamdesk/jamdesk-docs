Diese Seite ist ein live generierter Endpunkt auf Basis einer [OpenAPI-Spezifikation](https://spec.openapis.org/oas/latest.html). Jamdesk erzeugt aus der Spezifikation das Anfrageschema, die Antwortmodelle und die Codebeispiele im rechten Bereich.

<Info>
Dieses Beispiel verwendet die Acme Support API. Verweisen Sie `api.openapi` in `docs.json` auf Ihre Spezifikationsdatei, um Ihre Endpunkte zu generieren.
</Info>

<Info>
**Mehrsprachige Dokumentation?** Legen Sie neben Ihrer Quellspezifikation eine Datei `<spec>.<lang>.<ext>` ab (z. B. `example-api.fr.yaml`). Jamdesk rendert die übersetzte Version auf Seiten unter `/fr/...`. Siehe [Übersetzung von OpenAPI-Spezifikationen](/de/setup/languages).
</Info>

<Tip>
Auf dieser Seite ist der [API-Playground](/de/api-reference/playground) aktiviert. Klicken Sie oben auf den Endpunkt auf **Try it**, um die API live zu testen.
</Tip>

## Was generiert wird

Aus einer einzigen `openapi`-Zeile im Frontmatter erzeugt Jamdesk:

- Ein Endpunkt-Badge mit Methode und Pfad, farblich codiert
- Parameterdokumentation für Pfad-, Query-, Header- und Body-Parameter
- Anfrage- und Antwortschemata, einschließlich verschachtelter Objekte und Arrays
- Codebeispiele in cURL, Python, JavaScript, Go, Ruby, C#, Java, Rust und PHP (konfigurierbar über `api.examples.languages`)
- Authentifizierungsdetails aus den Security Schemes der Spezifikation

Jamdesk löst jedes `$ref` in Ihrer Spezifikation auf. Organisieren Sie Schemata wie gewohnt mit `components/schemas`.

Jamdesk rendert Beschreibungen in Ihrer Spezifikation als Markdown, nicht als Rohtext. Beschreibungen von Operationen, Parametern, Request-Bodies, Antworten und Schemata unterstützen dieselben **fettgedruckten** Texte, `Code`, Listen, Links und GFM-Tabellen, die Sie auch in einer `.mdx`-Seite verwenden würden.

## OpenAPI einrichten

Legen Sie Ihre OpenAPI-3.x-Spezifikation (YAML oder JSON) im Verzeichnis `openapi/` ab. Registrieren Sie sie in `docs.json` unter `api.openapi`. Fügen Sie anschließend `openapi: /openapi/your-spec.yaml METHOD /path` im Frontmatter einer beliebigen Seite hinzu. Vollständige Details finden Sie im [OpenAPI-Setup-Leitfaden](/de/setup/directory-structure#openapi).

## Eine Seite für jede Operation generieren

Richten Sie einen Navigationstab auf die Spezifikation, damit Jamdesk die gesamte Referenz erstellt, statt für jeden Endpunkt eine eigene Seite zu schreiben:

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": { "source": "/openapi/api.yaml", "generate": true }
      }
    ]
  }
}
```

Jede Operation erhält eine Seite. Die Seitenleiste ist nach Tags gruppiert. Committete `.mdx`-Dateien haben bei Slug-Kollisionen Vorrang. Sie können dies Seite für Seite übernehmen. Wenn Sie einen Pfad in Ihrer Spezifikation umbenennen, wird die alte URL weitergeleitet, statt zu brechen. Die vollständigen Regeln und aktuellen Grenzen finden Sie unter [navigation openapi](/de/config/docs-json-reference).

<Tip>
  Schreiben Sie Ihre Spezifikation in YAML? Prüfen Sie sie mit dem kostenlosen [YAML Validator](https://jamdesk.com/utilities/yaml-validator), um Einrückungs- und Syntaxfehler zu finden, bevor der Build sie parst.
</Tip>
