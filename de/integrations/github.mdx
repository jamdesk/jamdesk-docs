Jamdesk nutzt **zwei separate GitHub-Verbindungen**, die jeweils eine andere Aufgabe erfüllen. Auf dieser Seite erfahren Sie, wofür die einzelnen Verbindungen da sind und wann Sie sie benötigen.

<Info>
**Kurz gesagt:** Die GitHub App ermöglicht Jamdesk den Zugriff auf Ihr Repository. Durch die Verknüpfung Ihres persönlichen Kontos werden Ihre Commits Ihnen zugeordnet.
</Info>

<Note>
Bitbucket-Cloud-Projekte funktionieren anders: Eine einzelne OAuth-Autorisierung deckt den Repository-Zugriff, den Webhook und die Zuordnung von Builds ab. Siehe [Bitbucket verbinden](/de/setup/connecting-bitbucket).
</Note>

## Übersicht

| Verbindung | Zweck | Umfang | Erforderlich? |
|------------|---------|-------|-----------|
| **GitHub App** | Repository-Zugriff & Webhooks | Pro Projekt | Ja |
| **Persönliches Konto** | Benutzeridentität & Zuordnung | Pro Benutzer | Empfohlen |

## GitHub App (Projektebene)

Die **Jamdesk GitHub App** wird in Ihrem GitHub-Konto oder Ihrer Organisation installiert. Sie erlaubt Jamdesk den Zugriff auf bestimmte Repositories.

### Was sie tut

- **Liest Repository-Inhalte** – Klont Ihre Dokumentation, um sie zu Builden
- **Empfängt Webhooks** – Wird benachrichtigt, wenn Sie Änderungen pushen
- **Meldet den Build-Status** – Zeigt den Bereitstellungsstatus bei Commits an

### Warum Sie sie benötigen

Ohne installierte GitHub App kann Jamdesk Folgendes nicht:
- Auf Ihr Repository zugreifen, um die Dokumentation zu Builden
- Bei einem Push automatisch bereitstellen
- Den Build-Status bei GitHub-Commits anzeigen

### So funktioniert sie

Wenn Sie ein Projekt einrichten, führt Jamdesk Sie durch die Verbindung mit GitHub. Dabei gibt es zwei Möglichkeiten.

#### Starter-Dokumentations-Repository erstellen (Standard für neue Projekte)

<Steps>
  <Step title="Mit GitHub anmelden">
    Autorisieren Sie Jamdesk, damit die App ein Repository in Ihrem Konto oder Ihrer Organisation erstellen kann.
  </Step>
  <Step title="Speicherort auswählen">
    Wählen Sie Ihr persönliches Konto oder eine Organisation aus. Jamdesk erstellt ein neues Repository mit einer vorbefüllten Starter-Dokumentation.
  </Step>
  <Step title="GitHub App installieren">
    Installieren Sie die Jamdesk GitHub App (oder gewähren Sie ihr Zugriff auf das neue Repository), damit sie Ihre Dokumentation Builden und automatisch bereitstellen kann.
  </Step>
  <Step title="Push löst Builds aus">
    Jeder Push in Ihren konfigurierten Branch löst automatisch eine Bereitstellung aus. Passen Sie die Starter-Dokumentation an, sobald Sie bereit sind.
  </Step>
</Steps>

#### Vorhandenes Repository verbinden

Sie haben bereits ein Repository für Ihre Dokumentation? Installieren Sie die Jamdesk GitHub App, gewähren Sie ihr Zugriff auf das Repository und wählen Sie dann in Jamdesk unter **Project Settings → Git Repository** das Repository und den Branch aus. Danach funktioniert alles wie gewohnt.

### Eine App, mehrere Projekte

Eine einzelne Installation der GitHub App kann mehrere Jamdesk-Projekte unterstützen:
- Installieren Sie die App einmal in Ihrem Konto oder Ihrer Organisation
- Verbinden Sie unterschiedliche Repositories mit unterschiedlichen Jamdesk-Projekten
- Jedes Projekt hat eine eigene Branch- und Pfadkonfiguration

<Tip>
Bei Organisationen muss ein Administrator die GitHub App nur einmal installieren. Danach kann jedes Teammitglied Jamdesk-Projekte mit Repositories erstellen, auf die die App Zugriff hat.
</Tip>

## Persönliches GitHub-Konto (Benutzerebene)

Wenn Sie Ihr **persönliches GitHub-Konto** verknüpfen, wird Ihre GitHub-Identität mit Ihrem Jamdesk-Profil verbunden. Diese Verbindung ist von der GitHub App unabhängig.

### Was es tut

- **Identifiziert Sie** – Verknüpft Ihren GitHub-Benutzernamen mit Ihrem Jamdesk-Konto
- **Ordnet Builds zu** – Zeigt an, wer die jeweilige Bereitstellung ausgelöst hat
- **Sorgt für Transparenz im Team** – Andere Teammitglieder können sehen, wer Änderungen vorgenommen hat

### Warum Sie es benötigen

Wenn Sie zu GitHub pushen, muss Jamdesk ermitteln, welcher Benutzer den Build ausgelöst hat. Ohne verknüpftes Konto:

- Versucht Jamdesk stattdessen, den Benutzer anhand der E-Mail-Adresse zuzuordnen
- Wenn die E-Mail-Adresse Ihres Git-Commits von Ihrer Jamdesk-E-Mail-Adresse abweicht, schlägt die Zuordnung fehl
- In der Build-Historie wird bei Ihren Commits möglicherweise „Unknown user“ angezeigt

<Warning>
**Häufiges Problem:** Ihr Git ist mit einer persönlichen E-Mail-Adresse konfiguriert, Sie haben sich bei Jamdesk jedoch mit Ihrer geschäftlichen E-Mail-Adresse registriert. Verknüpfen Sie Ihr GitHub-Konto, damit Ihre Commits korrekt zugeordnet werden.
</Warning>

### Git-E-Mail prüfen

```bash
git config user.email
git config --global user.email "you@company.com"
```

Verwenden Sie dieselbe E-Mail-Adresse wie für Ihr Jamdesk-Konto, damit in der Build-Historie nicht „Unknown user“ angezeigt wird.

### Konto verknüpfen

<Steps>
  <Step title="User Settings öffnen">
    Klicken Sie oben rechts auf Ihren Avatar und wählen Sie dann **User Settings** aus.
  </Step>
  <Step title="Abschnitt GitHub Account suchen">
    Scrollen Sie zur Karte **GitHub Account**.
  </Step>
  <Step title="Link GitHub Account auswählen">
    Ein Popup-Fenster mit GitHub wird geöffnet. Autorisieren Sie Jamdesk, Ihr Profil zu lesen.
  </Step>
  <Step title="Verbindung bestätigen">
    Ihr GitHub-Benutzername wird in Ihrem Jamdesk-Profil angezeigt.
  </Step>
</Steps>

## Zusammenspiel der Verbindungen

Stellen Sie sich die beiden Verbindungen als separate Schlüssel vor:

| Schlüssel | Ermöglicht Zugriff auf | Gehört zu |
|-----|-------|----------|
| GitHub App | Repositories | Projekt/Organisation |
| Persönliche Verknüpfung | Ihre Identität | Einzelner Benutzer |

### Beispiel: Team

Stellen Sie sich ein Team mit 3 Entwicklern vor, die an der Unternehmensdokumentation arbeiten:

1. **Administrator installiert die GitHub App** in der Organisation
2. **Administrator erstellt ein Jamdesk-Projekt**, das mit dem Repository für die Dokumentation verbunden ist
3. **Jeder Entwickler verknüpft sein persönliches Konto**

Wenn nun ein Entwickler pusht:
- Mit der **GitHub App** kann Jamdesk das Repository lesen und den Build ausführen
- Die **persönliche Verknüpfung** identifiziert, wer den Build ausgelöst hat

### Beispiel: Einzelner Entwickler

Auch wenn Sie allein entwickeln, erfüllen beide Verbindungen unterschiedliche Aufgaben:
- **GitHub App** – Verbindet Ihr Repository mit Jamdesk
- **Persönliche Verknüpfung** – Stellt sicher, dass Ihre Commits in der Build-Historie unter Ihrem Namen angezeigt werden

## GitHub trennen und Verknüpfung aufheben

Jede Aktion entfernt einen anderen Teil des Zugriffs. Hier erfahren Sie, was jeweils betroffen ist.

### GitHub trennen (Project Settings)

**Funktion:** Entfernt die Repository-Verbindung aus einem einzelnen Jamdesk-Projekt.

**Auswirkungen:**
- Automatische Bereitstellungen werden für dieses Projekt gestoppt
- Die GitHub App bleibt auf GitHub installiert
- Andere Jamdesk-Projekte sind nicht betroffen
- Die Verknüpfung Ihres persönlichen Kontos bleibt bestehen

**Wann verwenden:** Wenn Sie ein anderes Repository verbinden oder Bereitstellungen vorübergehend stoppen möchten.

**Erneut verbinden:** Öffnen Sie **Project Settings → Git Repository** und wählen Sie ein Repository aus.

### GitHub-Verknüpfung aufheben (User Settings)

**Funktion:** Entfernt Ihre GitHub-Identität aus Ihrem Jamdesk-Profil.

**Auswirkungen:**
- Ihr GitHub-Benutzername wird nicht mehr in Ihrem Profil angezeigt
- Builds werden wieder anhand der E-Mail-Adresse zugeordnet
- Alle Repository-Verbindungen bleiben bestehen
- Die GitHub App bleibt installiert

**Wann verwenden:** Wenn Sie ein anderes GitHub-Konto verknüpfen oder die Verbindung entfernen möchten.

**Erneut verknüpfen:** Öffnen Sie **User Settings → GitHub Account → Link GitHub Account**.

### GitHub App deinstallieren (in GitHub)

**Funktion:** Entfernt den Zugriff von Jamdesk auf Ihr GitHub-Konto vollständig.

**Auswirkungen:**
- **Alle** Jamdesk-Projekte, die diese Installation verwenden, verlieren den Zugriff
- Automatische Bereitstellungen werden für alle betroffenen Projekte gestoppt
- Webhooks werden entfernt
- Verknüpfungen persönlicher Konten bleiben bestehen

<Warning>
Deinstallieren Sie die GitHub App nur, wenn Sie den Jamdesk-Zugriff auf **alle** Ihre Repositories entfernen möchten. Davon ist jedes Jamdesk-Projekt betroffen, das mit Ihrem GitHub-Konto verbunden ist.
</Warning>

**Deinstallieren:**
1. Öffnen Sie [GitHub Settings → Applications → Installed GitHub Apps](https://github.com/settings/installations)
2. Suchen Sie nach „Jamdesk“ und klicken Sie auf **Configure**
3. Scrollen Sie nach unten und klicken Sie auf **Uninstall**

## Schnellreferenz

| Aktion | Ort | Umfang | Rückgängig? |
|--------|----------|-------|-------------|
| **GitHub trennen** | Project Settings → Git Repository | Einzelnes Projekt | Ja – jederzeit erneut verbinden |
| **GitHub entknüpfen** | User Settings → GitHub Account | Ihr Konto | Ja – jederzeit erneut verknüpfen |
| **GitHub App deinstallieren** | GitHub Settings | Alle Projekte | Ja – erneut installieren |

## Fehlerbehebung

### „Jamdesk ist bereits installiert?“

Wenn Sie die Jamdesk GitHub App bereits installiert haben, gelangen Sie durch Klicken auf „Install GitHub App“ zur GitHub-Einstellungsseite statt zur Installationsseite. Das ist normal. So schließen Sie die Einrichtung ab:

<Steps>
  <Step title="Repository access suchen">
    Scrollen Sie auf der GitHub-Einstellungsseite zum Abschnitt **Repository access**.
  </Step>
  <Step title="Save-Schaltfläche aktivieren">
    Wenn die Schaltfläche Save deaktiviert (ausgegraut) ist, wechseln Sie von „All repositories“ zu „Only select repositories“ und anschließend wieder zurück.
  </Step>
  <Step title="Save auswählen">
    Klicken Sie auf die grüne Schaltfläche **Save**. Jamdesk erkennt die Änderung und setzt die Einrichtung fort.
  </Step>
</Steps>

### Popup wird blockiert

Wenn sich das GitHub-Popup nicht öffnet, wurde es möglicherweise von Ihrem Browser blockiert. Suchen Sie in der Adressleiste nach einem Symbol für den Popup-Blocker, erlauben Sie Popups von Jamdesk und klicken Sie dann auf **Try Again**.

### „Meine Builds zeigen ‚Unbekannter Benutzer‘“

Ihr persönliches GitHub-Konto ist nicht verknüpft. Öffnen Sie **User Settings → Link GitHub Account**.

### „Repository wird nicht angezeigt“

Die GitHub App hat keinen Zugriff auf dieses Repository. Öffnen Sie [GitHub Settings](https://github.com/settings/installations), suchen Sie Jamdesk und fügen Sie das Repository hinzu.

### „Builds werden nicht ausgelöst“

1. Prüfen Sie, ob das Repository unter **Project Settings → Git Repository** verbunden ist
2. Vergewissern Sie sich, dass Sie in den konfigurierten Branch pushen
3. Prüfen Sie die Webhook-Zustellung in den GitHub-Repository-Einstellungen

Wenn diese Einstellungen stimmen, ist die Person, die den Push ausgeführt hat, möglicherweise kein Projektmitglied. Jamdesk führt einen Build nach einem Push nur für Projektmitglieder aus. Jamdesk ordnet den Pushenden anhand des verknüpften GitHub-Kontos oder anhand der E-Mail-Adresse des Commits zu, die mit der E-Mail-Adresse übereinstimmen muss, mit der sich die Person bei Jamdesk anmeldet.

Wenn keine Zuordnung möglich ist, wird der Build mit dem entsprechenden Grund als fehlgeschlagen angezeigt. Der Projekteigentümer erhält eine E-Mail, höchstens einmal pro Woche und Person. Bei einem Push, der nichts in Ihrem Dokumentationsordner ändert, wird keine E-Mail gesendet.

Um das Problem zu beheben, laden Sie die Person unter **Project Settings → Members** mit der E-Mail-Adresse ihres Commits ein. Sie muss sich mit dieser E-Mail-Adresse bei Jamdesk anmelden, um die Einladung anzunehmen. Ist sie bereits Mitglied, kann sie stattdessen in den User Settings ihr [GitHub-Konto verknüpfen](#persönliches-github-konto-benutzerebene).

### „Ich kann nicht auf Organisations-Repositories zugreifen“

Ein Organisationsadministrator muss die Installation der GitHub App genehmigen. Bitten Sie Ihren Administrator, Jamdesk in den Organisationseinstellungen zu installieren oder zu genehmigen.

### „GitHub leitet mich immer wieder zur Jamdesk-App-Seite zurück“

Wahrscheinlich verwaltet Ihr Unternehmen Ihr GitHub-Konto. GitHub erlaubt es diesen Konten nicht, Apps im eigenen Konto zu installieren. Informationen zur Fehlerbehebung finden Sie unter [von Unternehmen verwaltete GitHub-Konten](/de/help/troubleshooting/github-issues#von-unternehmen-verwaltete-github-konten).
