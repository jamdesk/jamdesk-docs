Die Docs-Such-API bietet über eine semantische Suche programmatischen Zugriff auf Ihre Dokumentation. Ein Endpoint (`POST /_api/search`) nimmt eine natürlichsprachliche Suchanfrage entgegen und gibt die relevantesten Passagen aus Ihrer Dokumentation zurück, nach Relevanz sortiert.

## Anwendungsfälle

<Columns cols={2}>
  <Card title="Support-Chatbots" icon="comment-dots">

  </Card>
  <Card title="Slack-Bots" icon="slack">
    Erstellen Sie einen Slack-Befehl `/docs`, der Ihre Dokumentation durchsucht und die relevantesten Ergebnisse in einem beliebigen Kanal veröffentlicht.
  </Card>
  <Card title="Eigene Suchfunktion" icon="magnifying-glass">
    Ergänzen Sie Ihr Produkt, Dashboard oder Ihre internen Tools um eine Suchoberfläche, die passende Dokumentationsinhalte im jeweiligen Kontext anzeigt.
  </Card>
  <Card title="KI-Agenten" icon="robot">

## Schnellstart

<Steps>
  <Step title="API-Schlüssel erstellen">
    Öffnen Sie im [Jamdesk-Dashboard](https://dashboard.jamdesk.com) **Project Settings → API Keys**. Klicken Sie auf **Generate Key**, vergeben Sie einen Namen und kopieren Sie den Schlüssel. Er beginnt mit `jd_live_`, gefolgt von 32 Hexadezimalzeichen (insgesamt 40 Zeichen), und wird nur einmal angezeigt.
  </Step>
  <Step title="Erste Suchanfrage senden">
    Senden Sie eine `POST`-Anfrage an `/_api/search` auf Ihrer Dokumentations-Subdomain:

    ```bash
    curl -X POST https://your-project.jamdesk.app/_api/search \
      -H "Authorization: Bearer jd_live_c83003a54ae0a83123454c3f7ec82f0a" \
      -H "Content-Type: application/json" \
      -d '{"query": "How do I set up a custom domain?", "limit": 5, "language": "en"}'
    ```
  </Step>
  <Step title="Ergebnisse verwenden">
    Die Antwort enthält ein Array passender Passagen mit Relevanzwerten und Seitenmetadaten:

    ```json
    {
      "query": "How do I set up a custom domain?",
      "language": "en",
      "results": [
        {
          "title": "Custom Domains",
          "section": "Step 4: Deploy",
          "slug": "deploy/custom-domains",
          "content": "To add a custom domain, go to Project Settings and enter your domain. You'll need to add a CNAME record pointing to your Jamdesk subdomain.",
          "url": "https://your-project.jamdesk.app/deploy/custom-domains",
          "score": 0.94
        }
      ],
      "total": 1,
      "durationMs": 85
    }
    ```
  </Step>
</Steps>

## Authentifizierung

Alle Anfragen benötigen ein Bearer-Token im `Authorization`-Header.

```http
Authorization: Bearer jd_live_c83003a54ae0a83123454c3f7ec82f0a
```

<Info>
  Die Such-API funktioniert auch für Websites mit Passwort- oder JWT-Authentifizierung. Sie prüft Ihren API-Schlüssel, nicht die Anmeldung eines Besuchers. Daher müssen Sie `/_api/search` nicht zu `auth.jwt.public` hinzufügen. Ergebnisse können Seiten enthalten, die eine Anmeldung erfordern. Rufen Sie die API deshalb von Ihrem Server aus auf und verwenden Sie den Schlüssel niemals im Browsercode. Für die Ergebnisse gelten dieselben Regeln wie für die Website-Suche: Seiten mit Gruppenbeschränkung werden nie zurückgegeben. Verborgene Seiten oder Seiten mit `search: false` bleiben ausgeschlossen, sofern Sie sie nicht für die Suche freigegeben haben.
</Info>

### API-Schlüssel generieren

<Steps>
  <Step title="Project Settings öffnen">
    Navigieren Sie im Jamdesk-Dashboard zu Ihrem Projekt und klicken Sie auf **Settings**.
  </Step>
  <Step title="API Keys aufrufen">
    Wählen Sie den Tab **API Keys**.
  </Step>
  <Step title="Schlüssel erstellen">
    Klicken Sie auf **Generate Key**, geben Sie einen aussagekräftigen Namen ein (z. B. „Intercom-Chatbot“) und klicken Sie auf **Create**.
  </Step>
  <Step title="Schlüssel kopieren">
    Kopieren Sie den Schlüssel sofort. Er beginnt mit `jd_live_`, gefolgt von 32 Hexadezimalzeichen, und wird **nur einmal** angezeigt. Speichern Sie ihn in einem Secret-Manager oder in Umgebungsvariablen.
  </Step>
</Steps>

### Schlüsselverwaltung

<Info>
API-Schlüssel gelten jeweils für ein einzelnes Projekt. Ein Schlüssel für `acme.jamdesk.app` kann die Dokumentation eines anderen Projekts nicht abfragen.
</Info>

| Regel | Details |
|------|--------|
| **Format** | `jd_live_<32 hex chars>` (insgesamt 40 Zeichen, läuft nie ab) |
| **Geltungsbereich** | Ein Schlüssel pro Projekt (kein Zugriff auf andere Projekte) |
| **Rotation** | Jederzeit unter Project Settings widerrufen und neu erstellen |
| **Speicherung** | In Umgebungsvariablen oder einem Secret-Manager speichern; niemals in die Versionsverwaltung einchecken |

### Schlüssel widerrufen

Um einen Schlüssel zu widerrufen, öffnen Sie **Project Settings → API Keys**, suchen Sie den Schlüssel anhand seines Namens und klicken Sie auf **Revoke**. Widerrufene Schlüssel funktionieren ab sofort nicht mehr. Erstellen Sie einen neuen Schlüssel als Ersatz.

## Rate-Limits

Anfragen werden pro API-Schlüssel begrenzt.

| Tarif | Limit |
|------|-------|
| **Pro** | 60 Anfragen / Minute |
| **Enterprise** | Individuell; kontaktieren Sie den [Support](mailto:support@jamdesk.com) |

Wenn Sie das Limit überschreiten, gibt die API `429 Too Many Requests` mit einem `Retry-After: 60`-Header und `{"error": "Rate limit exceeded"}` im Antworttext zurück.

<Warning>
Wenn Sie für eine produktive Integration höhere Ratenlimits benötigen, [kontaktieren Sie uns](mailto:support@jamdesk.com), um Enterprise-Optionen zu besprechen.
</Warning>

## Abfragelimits

Jede Anfrage akzeptiert einen Parameter `limit`, der die Anzahl der zurückgegebenen Ergebnisse steuert. Der Höchstwert ist **20**, der Standardwert **5** und der Mindestwert **1**. Es gibt keine Paginierung; alle passenden Ergebnisse kommen in einer einzigen Antwort zurück. Wenn Sie mehr Kontext benötigen, formulieren Sie die Suchanfrage genauer, statt das Limit zu erhöhen.

Eine Suchanfrage ohne Treffer gibt HTTP 200 mit einem leeren Ergebnis-Array zurück:

```json
{"query": "quantum entanglement", "results": [], "total": 0, "durationMs": 48}
```

## Nach Sprache filtern

Wenn Ihre Dokumentationswebsite mehrere Sprachen unterstützt, filtert die API die Ergebnisse pro Anfrage nach einer einzelnen Sprache. Übergeben Sie `language` im Anfragekörper mit einem BCP-47-Code (z. B. `en`, `es`, `fr`, `pt-BR`, `zh-Hans`).

```bash
curl -X POST https://your-project.jamdesk.app/_api/search \
  -H "Authorization: Bearer jd_live_c83003a54ae0a83123454c3f7ec82f0a" \
  -H "Content-Type: application/json" \
  -d '{"query": "¿Cómo configuro un dominio personalizado?", "language": "es"}'
```

| Regel | Details |
|------|--------|
| **Standardwert** | `en` (Englisch). Lassen Sie das Feld weg oder übergeben Sie `null`, um den Standardwert zu verwenden. |
| **Format** | BCP-47 (`^[a-zA-Z]{2,3}([-_][a-zA-Z]{2,4})?$`). Beispiele: `en`, `es`, `fr`, `pt-BR`, `zh-Hans`. |
| **Validierung** | Ungültig formatierte Werte geben `400` mit `{"error": "Invalid language code"}` zurück. |
| **Tags mit 3 Segmenten** | Werden derzeit nicht unterstützt. Codes wie `zh-Hant-HK` und `sr-Latn-RS` geben `400` zurück. [Kontaktieren Sie den Support](mailto:support@jamdesk.com), wenn Sie diese benötigen. |
| **Mehrsprachige Projekte** | Der Filter ist strikt: Es werden nur Abschnitte zurückgegeben, die mit der angeforderten Sprache gekennzeichnet sind. Eine Anfrage für `de` an ein Projekt, das nur Englisch und Französisch enthält, liefert eine leere Ergebnismenge statt `400`. |
| **Einsprachige Projekte** | Der Filter wird ignoriert; Sie erhalten immer die vollständige Ergebnismenge. Das Senden von `language` ist unproblematisch und kein Fehler. |
| **Sprache in der Antwort** | Jede erfolgreiche Antwort enthält ein Feld `language` mit dem vom Server ermittelten Wert (Anfragewert oder Standardwert `en`). |

<Info>
Ein Projekt ist mehrsprachig, wenn seine `docs.json` ein Array `navigation.languages` mit mindestens zwei Einträgen enthält. Um zu prüfen, ob Ihre Website mehrsprachig ist, öffnen Sie im Dashboard den Tab **Settings → Languages** oder direkt die Datei `docs.json`.
</Info>

<Warning>
Der Standardwert `en` gilt auch für Projekte ohne englische Version. Wenn Ihr mehrsprachiges Projekt beispielsweise nur Französisch und Spanisch enthält, filtert ein Aufruf des Endpoints ohne Feld `language` nach `en` und gibt eine leere Ergebnismenge zurück. Übergeben Sie bei Websites ohne englische Version immer einen expliziten Wert für `language`.
</Warning>

## Fehlerbehandlung

Alle Fehlerantworten enthalten ein maschinenlesbares Feld `error`, das Sie programmatisch auswerten können.

| Status | Wert von `error` | Bedeutung | Maßnahme |
|--------|---------------|---------|--------|
| **400** | `Missing or empty "query" field` | Im Anfragekörper fehlt `query` oder das Feld ist leer | Eine nicht leere Zeichenfolge für `query` hinzufügen |
| **400** | `Invalid language code` | Das Feld `language` ist keine Zeichenfolge oder entspricht nicht dem BCP-47-Muster (`null` ist zulässig; leere Zeichenfolgen, Zeichenfolgen nur aus Leerraum und Tags mit 3 Segmenten sind es nicht) | Einen gültigen Code mit 1 oder 2 Segmenten wie `en`, `es`, `fr` oder `pt-BR` verwenden |
| **401** | `invalid_key_format` | Der `Authorization`-Header fehlt oder der Schlüssel entspricht nicht `jd_live_<32 hex>` | Header-Format prüfen; es muss `Bearer jd_live_...` sein |
| **401** | `invalid_key` | Der Schlüssel wird nicht erkannt oder wurde widerrufen | Im Dashboard einen neuen Schlüssel erstellen |
| **403** | `wrong_project` | Der Schlüssel ist gültig, wurde aber für ein anderes Projekt erstellt | Einen Schlüssel verwenden, der zum Projekt-Slug in der URL passt |
| **429** | `Rate limit exceeded` | Mehr als 60 Anfragen pro Minute gesendet | Die im `Retry-After`-Header angegebene Anzahl von Sekunden warten |
| **502** | `Search temporarily unavailable` | Das Backend für die Vektorsuche ist nicht verfügbar | Nach einer kurzen Wartezeit erneut versuchen |
| **503** | `lookup_failed` oder `redis_unavailable` | Das Backend zur Schlüsselprüfung ist nicht erreichbar | Nach einer kurzen Wartezeit erneut versuchen |

<Info>
401 und 403 sind dauerhafte Fehler. Ein erneuter Versuch mit demselben Schlüssel hilft nicht. 429, 502 und 503 sind vorübergehende Fehler; versuchen Sie es mit exponentiell zunehmenden Wartezeiten erneut.
</Info>

## CORS

CORS ist auf allen Endpoints aktiviert. Browserbasierte Clients (Single-Page-Apps, Browsererweiterungen und statische Websites) können `/_api/search` direkt und ohne Backend-Proxy aufrufen. Alle Origins sind erlaubt.

## SDKs

Derzeit gibt es keine offiziellen SDKs für Programmiersprachen. Verwenden Sie die REST-API direkt über `fetch`, `requests`, `curl` oder einen beliebigen HTTP-Client. Die [Postman-Sammlung](#postman-sammlung) unten enthält Beispiele, die Sie direkt forken können.

## Versionierung

Die API liegt derzeit in Version **v1.0.0** vor. Nicht abwärtskompatible Änderungen (umbenannte Felder, entfernte Endpoints oder geänderte Authentifizierung) werden im [Jamdesk-Blog](https://jamdesk.com/blog) und durch einen Hinweis im `X-Deprecation`-Antwortheader mindestens 90 Tage vor der Entfernung angekündigt.
