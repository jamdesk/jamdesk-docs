**Jamdesk ist eine Dokumentationssoftware**, die ein GitHub-Repository mit Markdown als gehostete Dokumentationsseite veröffentlicht. Sie erzeugt automatisch KI-lesbare Ausgaben: `llms.txt`, `.md`-Endpunkte pro Seite und einen MCP-Server.

Stellen Sie eine Dokumentationsseite mit zwei Dateien bereit: `docs.json` und einer MDX-Seite. Wählen Sie den Weg, der zu Ihrem Ausgangspunkt passt.

## Voraussetzungen

Sie benötigen:
- Ein [GitHub](https://github.com)-Konto
- Ein Repository mit Ihrer Dokumentation (oder wir erstellen eines)

## Option 1: Mit der Startervorlage beginnen

Dies ist der schnellste Einstieg. Die [Starter-Vorlage](https://github.com/jamdesk/starter-docs) enthält Beispielinhalte, eine OpenAPI-Spezifikation und Beispiele für jede Komponente. Sehen Sie sich an, wie alles funktioniert, und ersetzen Sie es dann durch Ihre eigenen Inhalte.

<Steps>
  <Step title="Ein Jamdesk-Konto erstellen">
    Gehen Sie zu [dashboard.jamdesk.com](https://dashboard.jamdesk.com) und registrieren Sie sich mit GitHub.
  </Step>

  <Step title="Ein Projekt aus einer Vorlage erstellen">
    Klicken Sie auf **New Project** → **From Template** → **Starter Docs**.

    Jamdesk erstellt für Sie ein GitHub-Repository mit einer vollständig vorkonfigurierten Umgebung.
  </Step>

  <Step title="Ihre Seite ist live">
    Ihre Dokumentation ist unter `your-project.jamdesk.app` bereitgestellt. Bearbeiten Sie die MDX-Dateien und pushen Sie die Änderungen. Die Seite wird automatisch neu erstellt.
  </Step>
</Steps>

<Tip>
Sie können die Starter-Vorlage auch direkt klonen: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

<Tip>
**Möchten Sie einige Seiten privat halten?** Fügen Sie `private: true` im Frontmatter einer beliebigen MDX-Datei hinzu. Legen Sie nach dem nächsten Build ein Passwort unter **Project Settings** fest. Alle vier Optionen (öffentlich, Passwort für die gesamte Seite, gemischt, SSO) finden Sie unter [Zugriffskontrolle](/de/setup/access-control).
</Tip>

## Option 2: Vorhandenes Repository verbinden

Sie haben bereits ein Repository mit für Jamdesk geeigneter Dokumentation? Verbinden Sie es direkt. Wenn Sie von Mintlify oder einer anderen Dokumentationsplattform kommen, verwenden Sie zuerst Option 3.

<Steps>
  <Step title="Ein Jamdesk-Konto erstellen">
    Gehen Sie zu [dashboard.jamdesk.com](https://dashboard.jamdesk.com) und registrieren Sie sich mit GitHub.
  </Step>

  <Step title="Ein Projekt erstellen">
    Klicken Sie auf **New Project** und verbinden Sie Ihr Repository.

    1. Wählen Sie Ihr GitHub-Repository aus
    2. Wählen Sie den Branch, der bereitgestellt werden soll
    3. Jamdesk erkennt Ihre `docs.json` automatisch

    Falls Ihr Repository noch keine `docs.json` enthält, fügen Sie vor dem Verbinden die minimale Datei aus [Aufbau eines Dokumentationsprojekts](#was-enthält-ein-docs-projekt) hinzu.

    Informationen zu Repository-Berechtigungen, Branch-Auswahl und Dokumentationspfaden finden Sie unter [GitHub verbinden](/de/setup/connecting-github).
  </Step>

  <Step title="Ihre Seite ist live">
    Ihre Dokumentation ist unter `your-project.jamdesk.app` bereitgestellt. Jamdesk erzeugt automatisch `llms.txt` für KI-Tools.

    Jeder Push auf den verbundenen Branch löst einen automatischen Neuaufbau aus.
  </Step>
</Steps>

## Option 3: Von Mintlify oder einer anderen Dokumentationsplattform migrieren

Ihre Dokumentation liegt bereits in Mintlify, GitBook, Docusaurus, ReadMe, Confluence oder einer anderen Plattform? Beginnen Sie mit dem Migrationsleitfaden, bevor Sie ein neues Projekt erstellen. Er behandelt den Befehl `jamdesk migrate` für Mintlify und die manuellen Schritte für andere Dokumentationstools. Verbinden Sie danach das migrierte Repository gemäß [Option 2](#option-2-vorhandenes-repository-verbinden).

## Was enthält ein Docs-Projekt

Ein minimales Jamdesk-Projekt besteht aus zwei Dingen:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Für größere Seiten finden Sie unter [Verzeichnisstruktur](/de/setup/directory-structure) empfohlene Ordner, Assets und Snippets.

### docs.json

Die Konfigurationsdatei, die Ihre Seite definiert:

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Alle Konfigurationsoptionen finden Sie in der [docs.json-Referenz](/de/config/docs-json-reference).

### MDX-Seiten

Dokumentationsseiten, geschrieben in MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Frontmatter, Überschriften, Links und Komponentensyntax werden unter [MDX-Grundlagen](/de/content/mdx-basics) erklärt.

## Lokale Entwicklung

Sehen Sie Änderungen lokal mit der Jamdesk CLI, bevor Sie zu GitHub pushen. Sie fängt MDX-Syntaxfehler ab, bevor sie Ihre Live-Seite erreichen. Alle Installationsmethoden und Befehle finden Sie in der [Jamdesk-CLI-Übersicht](https://jamdesk.com/docs/cli/overview).

Starten Sie sie:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Öffnen Sie **http://localhost:3000**, um Ihre Dokumentation mit Hot Reload zu sehen.

## Weitere Seiten hinzufügen

1. Erstellen Sie eine neue MDX-Datei:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Fügen Sie sie zur `docs.json` hinzu:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Pushen Sie zu GitHub. Ihre neue Seite wird automatisch bereitgestellt.

Weitere Verlinkungsmuster, einschließlich Anker und Cards, finden Sie unter [Links & Navigation](/de/content/links).

## Benutzerdefinierte Domain

Fügen Sie Ihre eigene Domain unter **Settings** → **Domains** hinzu:

1. Geben Sie Ihre Domain ein (z. B. `docs.example.com`)
2. Fügen Sie die angezeigten DNS-Einträge hinzu
3. Warten Sie auf die Verifizierung (bis zu 48 Stunden)

SSL-Zertifikate werden automatisch bereitgestellt. [Vollständige Anleitung →](/de/deploy/custom-domains)
