Jede Jamdesk-Website enthält einen integrierten MCP-Server (Model Context Protocol). Während `llms.txt` KI-Tools einen statischen Überblick über Ihre Dokumentation bietet, können sie mit MCP interaktiv suchen und Abfragen stellen – nützlich, wenn KI-Agenten gezielt Antworten finden sollen, statt alles zu lesen.

## Was ist MCP?

Das [Model Context Protocol](https://modelcontextprotocol.io) ist ein offener Standard, über den KI-Tools auf externe Datenquellen zugreifen können. Ihre Jamdesk-Dokumentation stellt über MCP zwei Tools bereit:

| Tool | Zweck |
|------|---------|
| `searchDocs` | Durchsucht die Dokumentation nach Stichwörtern und gibt sortierte Ergebnisse zurück |
| `getPage` | Ruft den vollständigen Inhalt einer bestimmten Seite ab |

## Ihre Endpoint-URL

Ihr MCP-Endpoint ist Ihre Dokumentations-URL mit angehängtem `/_mcp`. Wenn Ihre [eigene Domain](/de/deploy/custom-domains) aktiv ist, verwenden Sie diese:

| Setup | Endpoint |
|-------|----------|
| Eigene Domain unter `docs.acme.com` | `https://docs.acme.com/_mcp` |
| Keine eigene Domain | `https://my-project.jamdesk.app/_mcp` |

<Note>
  Verwenden Sie nach Möglichkeit den Endpoint Ihrer eigenen Domain, sobald diese verbunden ist. So bleibt Ihr Branding in allen URLs erhalten, die KI-Tools sehen, und der Endpoint funktioniert auch dann weiter, wenn Sie Ihre `.jamdesk.app`-Subdomain später mit [Nur eigene Domain](/de/deploy/custom-domain-only) ausblenden.
</Note>

## Schnellstart

<Tabs>
  <Tab title="Claude Code">
    Fügen Sie Ihre Dokumentation als MCP-Server hinzu:

    ```bash
    claude mcp add --transport http my-docs https://docs.acme.com/_mcp
    ```

    Ersetzen Sie `docs.acme.com` durch Ihre Dokumentationsdomain – oder durch `my-project.jamdesk.app`, wenn Sie noch keine eigene Domain verbunden haben.

    Wenn Sie Claude jetzt etwas zu Ihrem Projekt fragen, kann es Ihre Dokumentation direkt durchsuchen und lesen.
  </Tab>
  <Tab title="Cursor">
    Fügen Sie Folgendes zur Datei `.cursor/mcp.json` Ihres Projekts hinzu:

    ```json
    {
      "mcpServers": {
        "my-docs": {
          "url": "https://docs.acme.com/_mcp"
        }
      }
    }
    ```

    Cursor stellt automatisch eine Verbindung zu Ihrer Dokumentation her, wenn Sie das Projekt öffnen.
  </Tab>
</Tabs>

## Verfügbare Tools

### searchDocs

Durchsucht Ihre Dokumentation und gibt sortierte Ergebnisse zurück.

**Parameter:**

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `query` | string | Yes | Suchbegriffe (z. B. "authentication", "getting started") |
| `limit` | number | No | Maximale Anzahl der Ergebnisse (Standard: 10, maximal: 50) |
| `type` | string | No | Nach Inhaltstyp filtern: `all`, `api`, `guide`, `quickstart`, `help`, `component` |

**Beispielanfrage:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "searchDocs",
    "arguments": {
      "query": "authentication",
      "limit": 5
    }
  }
}
```

**Beispielantwort:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"query\":\"authentication\",\"total\":1,\"results\":[{\"title\":\"Authentication\",\"description\":\"How to authenticate API requests\",\"url\":\"/docs/api/authentication\",\"type\":\"api\",\"score\":0.95}]}"
    }]
  }
}
```

### getPage

Ruft den vollständigen Inhalt einer bestimmten Dokumentationsseite ab.

**Parameter:**

| Parameter | Typ | Erforderlich | Beschreibung |
|-----------|------|----------|-------------|
| `slug` | string | Yes | Seitenpfad ohne das Präfix `/docs` (z. B. `api/authentication`) |

**Beispielanfrage:**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "getPage",
    "arguments": {
      "slug": "api/authentication"
    }
  }
}
```

**Beispielantwort:**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"title\":\"Authentication\",\"description\":\"How to authenticate\",\"content\":\"## Overview\\n\\nUse API keys to authenticate...\",\"url\":\"/docs/api/authentication\"}"
    }]
  }
}
```

## Endpoint testen

Sie können Ihren MCP-Endpoint direkt mit curl testen:

```bash
# List available tools
curl -X POST https://docs.acme.com/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

# Search for content
curl -X POST https://docs.acme.com/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"searchDocs","arguments":{"query":"getting started"}}}'
```

## Websites mit Login-Schutz

Wenn Ihre Website Passwort- oder JWT-Authentifizierung verwendet, benötigt der MCP-Server einen Projekt-API-Schlüssel. Erstellen Sie einen unter **Project Settings > API Keys** und senden Sie ihn als Header:

```bash
claude mcp add --transport http my-docs https://docs.example.com/_mcp \
  --header "Authorization: Bearer jd_live_..."
```

Mit dem Schlüssel kann ein MCP-Client die durchsuchbaren Seiten der Website durchsuchen und lesen – also dieselben Seiten, die auch die Website-Suche abdeckt. Seiten mit Gruppenzugriff sind über MCP niemals verfügbar, unabhängig davon, ob ein Schlüssel verwendet wird. Ausgeblendete Seiten und Seiten mit `search: false` werden ausgelassen, sofern Sie sie nicht für die Suche freigegeben haben. Behandeln Sie den Schlüssel wie ein Passwort und widerrufen Sie ihn im Dashboard, falls er offengelegt wird.

Ohne Schlüssel antwortet der Server mit `401` und einem JSON-Text, der erklärt, wie Sie einen Schlüssel hinzufügen. Ein Schlüssel aus einem anderen Projekt wird abgelehnt. Folgende Fehlercodes sind möglich:

| Status | `error` | Bedeutung |
|--------|---------|---------|
| 401 | `auth_required` | Es wurde kein Schlüssel gesendet. |
| 401 | `invalid_api_key` | Der Schlüssel ist für diese Website ungültig. |
| 503 | `auth_unavailable` | Der Schlüssel konnte nicht überprüft werden. Versuchen Sie es nach der in `Retry-After` angegebenen Anzahl von Sekunden erneut. |

## Funktionsweise

Der MCP-Endpoint verwendet einen Suchindex, der zusammen mit Ihrer Dokumentation erstellt wird:

- **BM25-Ranking** - Sortiert Ergebnisse nach Relevanz
- **Unscharfe Suche** - Gleicht Tippfehler ab (Toleranz: 1 Zeichen)
- **Feldgewichtung** - Titel und Abschnittsüberschriften werden stärker gewichtet als der Fließtext
- **Filter nach Inhaltstyp** - Filtert Ergebnisse nach Inhaltstyp (API, Leitfaden usw.)

Der Index wird bei jeder Bereitstellung neu erstellt.

## Ratenbegrenzungen

Der MCP-Endpoint ist auf **60 Anfragen pro Minute** und IP-Adresse begrenzt. Das reicht für die übliche Nutzung durch KI-Assistenten aus. Bei Überschreitung des Limits erhalten Sie eine 429-Antwort.

## Fehlerbehebung

<Accordion title="MCP-Server stellt keine Verbindung her">
  Prüfen Sie, ob Ihre Endpoint-URL korrekt und erreichbar ist:

  ```bash
  curl https://docs.acme.com/_mcp
  ```

  Sie sollten eine JSON-Antwort mit Serverinformationen erhalten. Falls nicht, stellen Sie sicher, dass Ihre Dokumentation mindestens einmal erstellt wurde.
</Accordion>

<Accordion title="Die Suche liefert keine Ergebnisse">
  Der Suchindex wird beim Build erstellt. Wenn Sie kürzlich Inhalte hinzugefügt haben, starten Sie über Ihr Jamdesk-Dashboard einen erneuten Build, um den Index zu aktualisieren.
</Accordion>

<Accordion title="getPage gibt null zurück">
  Prüfen Sie, ob der Slug genau mit dem Seitenpfad übereinstimmt (ohne die Erweiterung `.mdx`). Wenn sich Ihre Seite beispielsweise unter `api/authentication.mdx` befindet, verwenden Sie `api/authentication` als Slug.
</Accordion>

<Accordion title="401 auth_required auf einer geschützten Website">
  Die Website verwendet Passwort- oder JWT-Authentifizierung. Deshalb benötigt die Anfrage einen Projekt-API-Schlüssel. Fügen Sie den Header `Authorization: Bearer` mit einem Schlüssel aus **Project Settings > API Keys** hinzu. Weitere Informationen finden Sie unter [Websites mit Login-Schutz](#websites-mit-login-schutz).
</Accordion>
