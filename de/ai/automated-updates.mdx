Der Skill `/update-jamdesk` für Claude Code überwacht Ihre Code-Änderungen und erzeugt passende Dokumentationsupdates. Führen Sie ihn aus, nachdem Sie ein nutzerseitiges Feature ausgeliefert haben. Er ermittelt, welche Dokumentationsseiten erstellt oder bearbeitet werden müssen.

<Note>
**Suchen Sie allgemeine Tipps zum Schreiben mit KI?** Die Einrichtung des Tools finden Sie unter [Claude Code](/de/ai/claude-code). Allgemeinere Hinweise zum Verfassen von Dokumentation mit KI-Tools finden Sie unter [Schreiben mit KI](/de/ai/writing-with-ai).
</Note>

## Wann Sie den Skill verwenden sollten

**Verwenden, wenn:** Sie nutzerseitige Änderungen an APIs, CLI-Befehlen, der Benutzeroberfläche, Konfigurationsoptionen oder dem Verhalten von Komponenten vorgenommen haben.

**Überspringen, wenn:** interne Refactorings, reine Teständerungen, Build- oder CI-Konfiguration oder Performance-Arbeiten ohne Verhaltensänderung vorliegen.

## Voraussetzungen

- [Claude Code](https://claude.ai/code) ist installiert und konfiguriert
- Ein Jamdesk-Dokumentationsprojekt mit `docs.json`
- Optional: [Jamdesk CLI](/de/cli/overview) zur Verifikation (`npm install -g jamdesk`)

## Schnellstart

<Steps>
  <Step title="Konfigurationsdatei erstellen">
    Erstellen Sie in Ihrem Code-Repository eine Datei `.jamdesk-docs-path`, die auf Ihre Dokumentation verweist:

    ```yaml .jamdesk-docs-path
    docs_path: ../my-docs
    ```

    Der Pfad kann relativ (ausgehend von der Konfigurationsdatei) oder absolut sein.
  </Step>
  <Step title="Skill ausführen">
    Führen Sie dies aus, nachdem Sie ein Feature implementiert haben:

    ```text
    /update-jamdesk
    ```

    Claude analysiert Ihre Änderungen und stellt Rückfragen, bevor die Dokumentation geschrieben wird.
  </Step>
  <Step title="Prüfen und committen">
    Prüfen Sie die erzeugte Dokumentation. Claude verifiziert sie mit `jamdesk validate` und `jamdesk broken-links`, bevor committet wird.
  </Step>
</Steps>

## Format der Konfigurationsdatei

Die Datei `.jamdesk-docs-path` teilt Claude mit, wo Ihre Dokumentation liegt.

**Einfaches Format** nur mit dem Pfad:

```text
../my-docs
```

**Vollständiges Format** mit Optionen:

```yaml .jamdesk-docs-path
# Path to documentation repository
docs_path: ../my-docs

# Optional: Branch for doc updates (default: main)
docs_branch: main
```

<Note>
  Der Skill sucht die Konfigurationsdatei, indem er vom aktuellen Verzeichnis bis zur Git-Wurzel nach oben geht. Legen Sie sie im Wurzelverzeichnis Ihres Repositorys ab.
</Note>

## Funktionsweise

Claude führt für `/update-jamdesk` diese Schritte aus:

1. **Dokumentation finden:** sucht die Konfigurationsdatei `.jamdesk-docs-path`
2. **Rückfragen stellen:** klärt Branch-Strategie, Umfang und Inhalt
3. **Bestehende Dokumentation analysieren:** sucht nach verwandten Inhalten, die aktualisiert oder erweitert werden können
4. **Dokumentation schreiben:** erstellt oder aktualisiert Seiten gemäß den Jamdesk-Standards, zuerst mit einfachen Beispielen
5. **Tonalität prüfen:** Prüfen Sie die Ausgabe auf KI-Füllfloskeln. Claude schreibt besser mit einer CLAUDE.md, die den Stil vorgibt (siehe [Claude Code](/de/ai/claude-code))
6. **Verifizieren:** führt `jamdesk validate` und `jamdesk broken-links` aus
7. **Committen:** stellt Änderungen bereit und bietet Commit, Push bzw. PR an

<Tip>
  Führen Sie vor dem Committen `git checkout .` aus, um alle Änderungen zurückzusetzen.
</Tip>

<Accordion title="Wie Claude entscheidet, was erstellt und was aktualisiert wird">
  | Szenario | Aktion |
  |----------|--------|
  | Neues Feature | Neue Seite erstellen |
  | Verhaltensänderung | Bestehende Seite aktualisieren |
  | Kleine Ergänzung | Abschnitt zu bestehender Seite hinzufügen |
  | Große Funktion | Neue eigenständige Seite |
  | Veraltung/Entfernung | Bestehende Seite aktualisieren + Migrationshinweise ergänzen |
</Accordion>

## Beispielsitzung

```text
User: I just added a webhook feature. Can you document it?

Claude: I'm using the update-jamdesk skill to update your documentation.

Found .jamdesk-docs-path: ../customer-docs

How should I handle changes to the docs repository?
1. Create a new feature branch (recommended)
2. Update directly on main
3. Use current branch

User: 1

Claude: Based on the webhook implementation, I plan to:
- Create: webhooks/overview.mdx
- Update: getting-started.mdx (add link)

Any changes to this plan?

User: Looks good

Claude: [Creates documentation...]

✓ jamdesk validate passed
✓ jamdesk broken-links passed

Commit these changes?
```

## Vorschaumodus

Führen Sie den Befehl mit `--preview` aus, um zu sehen, was sich ändern würde, ohne Bearbeitungen vorzunehmen:

```text
/update-jamdesk --preview
```

Der Vorschaumodus ermöglicht Ihnen:
- zu prüfen, welche Dokumentation aktualisiert werden muss
- vorgeschlagene Änderungen vor dem Commit zu prüfen
- die Analyse des Skills ohne Nebenwirkungen zu sehen

## Proaktive Vorschläge

Claude kann dies vorschlagen, nachdem Sie nutzerseitige Code-Änderungen committet haben:

```text
Tip: These changes affect user-facing features.
Run /update-jamdesk to update your documentation.
```

Dies erscheint, wenn:
- eine Konfigurationsdatei `.jamdesk-docs-path` vorhanden ist UND
- Ihr Commit Dateien enthält, die nutzerseitigen Mustern entsprechen (API, CLI, Komponenten)

## Skill installieren

Installieren Sie den Skill `/update-jamdesk` mit der skills-CLI:

```bash
npx skills add jamdesk/skills --skill update-jamdesk
```

Dadurch wird der Skill nach `.claude/skills/update-jamdesk/` in Ihrem Projekt installiert.

<Tabs>
  <Tab title="Projektinstallation (Standard)">
    Installiert in Ihr aktuelles Projektverzeichnis:

    ```bash
    npx skills add jamdesk/skills --skill update-jamdesk
    ```

    Der Skill ist verfügbar, wenn Sie in diesem Projekt arbeiten.
  </Tab>
  <Tab title="Globale Installation">
    Installiert in Ihr Home-Verzeichnis für die Nutzung in jedem Projekt:

    ```bash
    npx skills add jamdesk/skills --skill update-jamdesk -g
    ```

    Der Skill ist in jedem Projekt verfügbar.
  </Tab>
  <Tab title="Andere Agenten">
    Installation für Cursor, Codex, Windsurf oder andere unterstützte Agenten:

    ```bash
    # Install to Cursor
    npx skills add jamdesk/skills --skill update-jamdesk -a cursor

    # Install to multiple agents
    npx skills add jamdesk/skills --skill update-jamdesk -a claude-code -a cursor
    ```

    Führen Sie `npx skills add --help` aus, um alle unterstützten Agenten zu sehen.
  </Tab>
</Tabs>

### Verfügbare Skills auflisten

Alle Jamdesk-Skills anzeigen:

```bash
npx skills add jamdesk/skills --list
```

### Aktualisieren

Führen Sie den Installationsbefehl erneut aus, um die neueste Version zu erhalten:

```bash
npx skills add jamdesk/skills --skill update-jamdesk
```

<Note>
  Starten Sie Claude Code neu oder beginnen Sie eine neue Sitzung nach der Installation oder Aktualisierung.
</Note>

## Fehlerbehebung

<Accordion title="Skill wird nicht erkannt">
  Prüfen Sie, ob die Skill-Datei unter `.claude/skills/update-jamdesk/SKILL.md` liegt. Starten Sie danach Ihre Claude-Code-Sitzung neu.
</Accordion>

<Accordion title="Konfigurationsdatei nicht gefunden">
  Erstellen Sie `.jamdesk-docs-path` im Wurzelverzeichnis Ihres Repositorys mit dem Pfad zu Ihrem Dokumentationsverzeichnis. Der Skill sucht vom aktuellen Verzeichnis bis zur Git-Wurzel.
</Accordion>

<Accordion title="jamdesk CLI nicht installiert">
  Installieren Sie sie mit `npm install -g jamdesk`. Der Skill funktioniert auch ohne sie, überspringt aber die automatisierte Validierung.
</Accordion>
