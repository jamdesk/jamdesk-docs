Wenn KI-Tools wie ChatGPT, Claude oder Copilot genaue Antworten zu Ihrem Produkt geben sollen, benötigen sie strukturierten Zugriff auf Ihre Dokumentation – nicht nur auf Inhalte, die in ihre Trainingsdaten gelangt sind.

Jede Jamdesk-Website erzeugt `llms.txt` und `llms-full.txt` gemäß der Spezifikation von [llmstxt.org](https://llmstxt.org). KI-Tools lesen diese Dateien, statt einzelne Seiten zu crawlen.

<Note>
  Google prüft `llms.txt` inzwischen als Teil der [agentischen Browsing-Prüfungen von Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Websites, die eine gültige `llms.txt` veröffentlichen, werden für KI-Agenten besser auffindbar – und zunehmend auch für Google selbst, wenn Inhalte für KI-gestützte Antworten bewertet werden. Jamdesk stellt Ihnen dies kostenlos zur Verfügung.
</Note>

<Tip>
  **Prüfen Sie Ihren Score.** Mit dem kostenlosen Tool [AI Score](https://jamdesk.com/ai-score) sehen Sie, wie gut jede Dokumentationswebsite für Agenten geeignet ist. Die Veröffentlichung einer gültigen `llms.txt` gehört zu den ersten Prüfungen. Außerdem gibt es eine [AI Score Chrome-Erweiterung](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj), mit der Sie Websites beim Browsen bewerten können.
</Tip>

## Was Jamdesk generiert

| Datei | Inhalt |
|------|---------|
| `llms.txt` | Seitentitel, Beschreibungen und URLs (ein strukturiertes Inhaltsverzeichnis) |
| `llms-full.txt` | Vollständiger Inhalt der Dokumentation in einer einzelnen Datei |

Jamdesk generiert beide Dateien beim Build und stellt sie über dasselbe CDN wie Ihre Dokumentation bereit.

## Dateien überprüfen

Prüfen Sie nach Ihrem ersten Build, ob Ihre Dateien vorhanden sind:

<Tabs>
  <Tab title="Stamm-Domain">
    Wenn sich Ihre Dokumentation im Stammverzeichnis Ihrer Domain befindet (z. B. `docs.acme.com` oder `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="/docs-Unterpfad">
    Wenn sich Ihre Dokumentation unter `/docs` auf Ihrer Hauptwebsite befindet (wie auf dieser Website unter `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Dateiformat

Die Datei `llms.txt` listet jede Seite mit Titel, Beschreibung und URL auf. Die Einträge sind in Abschnitte gruppiert, die Ihrer Navigation entsprechen:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Die Datei `llms-full.txt` enthält den vollständigen Markdown-Inhalt jeder Seite. Die Seiten werden an Überschriften erkennbaren Seitengrenzen aneinandergereiht.

## Struktur

`llms.txt` folgt dem Vorschlag von [llmstxt.org](https://llmstxt.org/): einem H1-Titel,
einer Blockquote-Zusammenfassung und Ihren Navigationstabs und -gruppen als `##`-Abschnitte mit
Markdown-Links.

## Mehrsprachige Websites

Websites mit mehr als einer Sprache erhalten für jede Sprache einen eigenen
Dateisatz, sodass ein KI-Tool nur die benötigte Sprache abrufen kann. Für eine Website auf Englisch (Standard) und Französisch:

| URL | Inhalt |
|-----|---------|
| `/llms.txt` | Englischer Index mit Links zu den Indizes aller anderen Sprachen am Ende |
| `/en/llms.txt` | Dieselbe Datei wie `/llms.txt` |
| `/fr/llms.txt` | Französischer Index mit Links zurück zu den anderen Sprachen |
| `/llms-full.txt` | Vollständiger Inhalt aller Sprachen, nacheinander |
| `/en/llms-full.txt` | Nur der vollständige Inhalt der englischen Seiten |
| `/fr/llms-full.txt` | Nur der vollständige Inhalt der französischen Seiten |

Die Root-Datei `llms-full.txt` enthält weiterhin alle Sprachen, sodass sich für Tools, die diese Datei bereits lesen, nichts ändert. Verweisen Sie einen Agenten auf die sprachspezifische Datei, wenn er nur diese Sprache benötigt:

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

Eine Sprache erhält eigene Dateien, sobald mindestens eine Seite in dieser Sprache vorhanden ist. Websites mit nur einer Sprache behalten ausschließlich die Root-Dateien.

## Agentenanweisung auf jeder Seite

Jede Seite enthält außerdem einen unsichtbaren, für Screenreader stummen Hinweis für KI-Agenten, der auf `llms.txt` verweist. Jeder Markdown-Export beginnt mit einer Blockquote, die auf den Index verlinkt. Agenten, die auf Ihrem HTML landen, finden den Markdown-Pfad daher ohne Crawling.

## So wird die Datei erstellt

- Beim Build zusammen mit Ihrem HTML generiert
- Über ein CDN mit derselben Cache-Richtlinie wie Ihre Dokumentation bereitgestellt
- Bei jedem Build automatisch aktualisiert
- Keine Konfiguration erforderlich; standardmäßig werden alle Seiten eingeschlossen

## llms.txt deaktivieren

`llms.txt` und `llms-full.txt` werden standardmäßig veröffentlicht. Um ihre Generierung zu stoppen (z. B. wenn KI-Tools Ihre Inhalte nicht erfassen sollen), setzen Sie `seo.ai.llmsTxt` in Ihrer `docs.json` auf `false`:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Beim nächsten Build überspringt Jamdesk beide Dateien einschließlich aller sprachspezifischen Kopien. Die aktiven URLs `/llms.txt` und `/llms-full.txt` geben dann `404` zurück.

<Note>
  **KI-Erfassung und Suchindexierung sind separate Einstellungen.** `seo.ai.llmsTxt` steuert ausschließlich die Dateien `llms.txt`/`llms-full.txt`, die KI-Tools lesen. Die Indexierung Ihrer Website durch Suchmaschinen wird dadurch nicht geändert; diese wird durch [`robots`-Metadaten und das seitenbezogene `noindex`](/de/content/seo#indexierung-steuern) gesteuert. Eine Seite kann von Google indexiert und gleichzeitig von der KI-Erfassung ausgeschlossen werden – oder umgekehrt.
</Note>

## KI-Crawler

Die standardmäßige `robots.txt` von Jamdesk erlaubt allen wichtigen KI-Crawlern (Claude, ChatGPT, Copilot, Gemini) den Zugriff. Ihre Dokumentation ist sofort für KI-Tools zugänglich.

<Accordion title="Wie sich llms.txt von sitemap.xml unterscheidet">
  `sitemap.xml` listet URLs auf, die Suchmaschinen crawlen und indexieren sollen. Sie enthält keine Inhalte, sondern nur Links und Metadaten wie Änderungsdaten.

  `llms.txt` wurde für KI-Modelle entwickelt. Sie enthält Seitentitel, Beschreibungen und in `llms-full.txt` den tatsächlichen Inhalt. KI-Tools können die vollständige Datei lesen, um Ihre Dokumentation zu verstehen, ohne mehrere HTTP-Anfragen zu stellen.
</Accordion>
