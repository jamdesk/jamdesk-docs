Wenn KI-Tools wie ChatGPT, Claude oder Copilot genaue Antworten zu Ihrem Produkt geben sollen, benötigen sie strukturierten Zugriff auf Ihre Dokumentation und nicht nur das, was in ihren Trainingsdaten enthalten ist.

Jede Jamdesk-Website erzeugt `llms.txt` und `llms-full.txt` gemäß der Spezifikation von [llmstxt.org](https://llmstxt.org). KI-Tools lesen diese Dateien, anstatt einzelne Seiten zu crawlen.

<Note>
  Google prüft `llms.txt` jetzt als Teil der [agentischen Browsing-Prüfungen von Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Websites, die eine gültige `llms.txt` veröffentlichen, werden für KI-Agenten und zunehmend auch für Google selbst besser auffindbar, wenn Inhalte für KI-gestützte Antworten bewertet werden. Jamdesk stellt diese Funktion kostenlos bereit.
</Note>

<Tip>
  **Prüfen Sie Ihren Score.** Mit dem kostenlosen Tool [AI Score](https://jamdesk.com/ai-score) sehen Sie, wie gut eine beliebige Dokumentationswebsite für Agenten geeignet ist. Das Veröffentlichen einer gültigen `llms.txt` gehört zu den ersten Prüfungen. Außerdem gibt es eine [Chrome-Erweiterung für AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj), mit der Sie Websites beim Browsen bewerten können.
</Tip>

## Was Jamdesk generiert

| Datei | Inhalt |
|------|---------|
| `llms.txt` | Seitentitel, Beschreibungen und URLs (ein strukturiertes Inhaltsverzeichnis) |
| `llms-full.txt` | Vollständiger Inhalt der Dokumentation in einer einzigen Datei |

Jamdesk generiert beide Dateien zur Build-Zeit und stellt sie über dasselbe CDN wie Ihre Dokumentation bereit.

## Dateien überprüfen

Prüfen Sie nach Ihrem ersten Build, ob Ihre Dateien vorhanden sind:

<Tabs>
  <Tab title="Stammdomain">
    Wenn sich Ihre Dokumentation im Stammverzeichnis Ihrer Domain befindet (z. B. `docs.acme.com` oder `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="/docs-Unterpfad">
    Wenn sich Ihre Dokumentation unter `/docs` auf Ihrer Hauptwebsite befindet (wie auf dieser Website unter `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Dateiformat

Die Datei `llms.txt` listet jede Seite mit Titel, Beschreibung und URL auf. Die Seiten sind in Abschnitte gruppiert, die Ihre Navigation abbilden:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Die Datei `llms-full.txt` enthält den vollständigen Markdown-Inhalt jeder Seite, verkettet mit Überschriften, die die Seitengrenzen markieren.

## Struktur

`llms.txt` folgt dem Vorschlag von [llmstxt.org](https://llmstxt.org/): einem H1-Titel,
einer Blockquote-Zusammenfassung sowie Ihren Navigationstabs und -gruppen als
`##`-Abschnitten mit Markdown-Links.

## Mehrsprachige Websites

Websites mit mehr als einer Sprache erhalten für jede Sprache einen eigenen Dateisatz, sodass ein KI-Tool nur die benötigte Sprache abrufen kann. Für eine Website auf Englisch (der Standardsprache) und Französisch sieht das so aus:

| URL | Inhalt |
|-----|---------|
| `/llms.txt` | Englischer Index mit Links zu den Indizes aller anderen Sprachen am Ende |
| `/fr/llms.txt` | Französischer Index mit Links zurück zu den anderen Sprachen |
| `/llms-full.txt` | Vollständiger Inhalt jeder Sprache, nacheinander |
| `/en/llms-full.txt` | Vollständiger Inhalt ausschließlich der englischen Seiten |
| `/fr/llms-full.txt` | Vollständiger Inhalt ausschließlich der französischen Seiten |

Die Root-`llms-full.txt` enthält weiterhin alle Sprachen. Für Tools, die diese Datei bereits lesen, ändert sich daher nichts. Verweisen Sie auf die sprachspezifische Datei, wenn ein Agent nur diese Sprache benötigt:

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

Eine Sprache erhält eigene Dateien, sobald mindestens eine Seite für sie vorhanden ist. Websites mit nur einer Sprache behalten ausschließlich die Root-Dateien.

## Agentenanweisung auf jeder Seite

Jede Seite enthält außerdem eine unsichtbare, für Screenreader stumme Notiz für KI-Agenten, die auf `llms.txt` verweist. Jeder Markdown-Export beginnt mit einer Blockquote, die auf den Index verlinkt. Agenten, die auf Ihrem HTML landen, finden den Markdown-Pfad somit ohne Crawling.

## So wird die Datei erstellt

- Zur Build-Zeit zusammen mit Ihrem HTML generiert
- Über ein CDN mit derselben Cache-Richtlinie wie Ihre Dokumentation bereitgestellt
- Bei jedem Build automatisch aktualisiert
- Keine Konfiguration erforderlich; standardmäßig werden alle Seiten eingeschlossen

## llms.txt deaktivieren

`llms.txt` und `llms-full.txt` werden standardmäßig veröffentlicht. Um ihre Generierung zu stoppen (beispielsweise wenn KI-Tools Ihre Inhalte nicht einlesen sollen), setzen Sie `seo.ai.llmsTxt` in Ihrer `docs.json` auf `false`:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Beim nächsten Build überspringt Jamdesk beide Dateien einschließlich aller sprachspezifischen Kopien. Die aktiven URLs `/llms.txt` und `/llms-full.txt` geben dann `404` zurück.

<Note>
  **Das Einlesen durch KI und die Suchindexierung sind getrennte Einstellungen.** `seo.ai.llmsTxt` steuert ausschließlich die Dateien `llms.txt` und `llms-full.txt`, die KI-Tools lesen. Die Einstellung ändert nicht, wie Suchmaschinen Ihre Website indexieren. Dies wird durch [ `robots`-Metadaten und seitenweises `noindex`]( /de/content/seo#controlling-indexing) gesteuert. Eine Seite kann von Google indexiert und gleichzeitig vom Einlesen durch KI ausgeschlossen werden oder umgekehrt.
</Note>

## KI-Crawler

Die standardmäßige `robots.txt` von Jamdesk erlaubt allen wichtigen KI-Crawlern (Claude, ChatGPT, Copilot, Gemini) den Zugriff. Ihre Dokumentation ist ohne weitere Konfiguration für KI-Tools zugänglich.

<Accordion title="Wie sich llms.txt von sitemap.xml unterscheidet">
  `sitemap.xml` listet URLs auf, die Suchmaschinen crawlen und indexieren sollen. Sie enthält keine Inhalte, sondern nur Links und Metadaten wie Änderungsdaten.

  `llms.txt` wurde für KI-Modelle entwickelt. Sie enthält Seitentitel, Beschreibungen und in `llms-full.txt` den tatsächlichen Inhalt. KI-Tools können die vollständige Datei lesen, um Ihre Dokumentation zu verstehen, ohne mehrere HTTP-Anfragen zu stellen.
</Accordion>
