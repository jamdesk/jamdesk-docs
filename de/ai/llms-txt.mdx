KI-Tools wie ChatGPT, Claude oder Copilot geben nur dann präzise Antworten über Ihr Produkt, wenn sie strukturierten Zugriff auf Ihre Dokumentation haben. Ihre Trainingsdaten reichen dafür nicht aus.

Jede Jamdesk-Website erzeugt `llms.txt` und `llms-full.txt` gemäß der Spezifikation auf [llmstxt.org](https://llmstxt.org). KI-Tools lesen diese Dateien, anstatt einzelne Seiten zu crawlen.

<Note>
  Google prüft `llms.txt` inzwischen im Rahmen der [agentischen Browsing-Prüfungen von Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Websites, die eine gültige `llms.txt` veröffentlichen, sind für KI-Agenten leichter auffindbar. Google berücksichtigt sie außerdem zunehmend beim Ranking von Inhalten für KI-gestützte Antworten. Jamdesk veröffentlicht sie kostenlos.
</Note>

<Tip>
  **Prüfen Sie Ihren Score.** Das kostenlose Tool [AI Score](https://jamdesk.com/ai-score) bewertet, wie gut jede Dokumentationsseite für Agenten nutzbar ist. Eine gültige `llms.txt` gehört zu den ersten Dingen, die es prüft. Die [AI Score Chrome-Erweiterung](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) bewertet Websites während des Surfens.
</Tip>

## Was Jamdesk generiert

| Datei | Inhalt |
|------|---------|
| `llms.txt` | Seitentitel, Beschreibungen und URLs (ein strukturiertes Inhaltsverzeichnis) |
| `llms-full.txt` | Vollständiger Dokumentationsinhalt in einer einzigen Datei |

Jamdesk erzeugt die Dateien zur Build-Zeit. Sie werden über dasselbe CDN ausgeliefert wie Ihre Dokumentation.

## Dateien überprüfen

Prüfen Sie nach dem ersten Build, ob Ihre Dateien vorhanden sind:

<Tabs>
  <Tab title="Root-Domain">
    Wenn Ihre Dokumentation im Root Ihrer Domain liegt (z. B. `docs.acme.com` oder `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="/docs-Unterpfad">
    Wenn Ihre Dokumentation unter `/docs` auf Ihrer Hauptseite liegt (wie diese Seite unter `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Dateiformat

Die Datei `llms.txt` listet jede Seite mit Titel, Beschreibung und URL auf, gruppiert in Abschnitte, die Ihrer Navigation entsprechen:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Die Datei `llms-full.txt` enthält den vollständigen Markdown-Inhalt jeder Seite, aneinandergereiht, wobei Seitengrenzen durch Überschriften markiert sind.

## Struktur

`llms.txt` folgt dem Vorschlag von [llmstxt.org](https://llmstxt.org/): einem H1-Titel, einer Zusammenfassung als Blockzitat und Ihren Navigations-Tabs und -Gruppen als `##`-Abschnitte mit Markdown-Links.

## Mehrsprachige Websites

Websites mit mehr als einer Sprache erhalten pro Sprache einen eigenen Satz Dateien. Ein KI-Tool kann so nur die Sprache abrufen, die es benötigt. Für eine Website auf Englisch (Standard) und Französisch:

| URL | Inhalt |
|-----|---------|
| `/llms.txt` | Englisches Verzeichnis, am Ende mit Links zu den Verzeichnissen der anderen Sprachen |
| `/en/llms.txt` | Dieselbe Datei wie `/llms.txt` |
| `/fr/llms.txt` | Französisches Verzeichnis, mit Links zurück zu den anderen Sprachen |
| `/llms-full.txt` | Vollständiger Inhalt aller Sprachen, nacheinander |
| `/en/llms-full.txt` | Vollständiger Inhalt nur der englischen Seiten |
| `/fr/llms-full.txt` | Vollständiger Inhalt nur der französischen Seiten |

Die `llms-full.txt` im Root enthält weiterhin alle Sprachen. Tools, die sie bereits lesen, sehen keine Änderung. Verweisen Sie einen Agenten auf die Datei einer Sprache, wenn er nur diese Sprache benötigt:

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

Eine Sprache erhält eigene Dateien, sobald sie mindestens eine Seite hat. Einsprachige Websites behalten nur die Root-Dateien.

## Websites mit Login-Schutz

Auf einer Website hinter [Passwortschutz](/de/setup/password-protection) oder [JWT-Authentifizierung](/de/setup/jwt-authentication) leiten `llms.txt` und `llms-full.txt` Besucher zur Login-Seite weiter, und `.md`-URLs liefern `401`. Ein Projekt-API-Schlüssel öffnet alle drei für Tools, die sich nicht anmelden können. Erstellen Sie ihn unter **Project Settings > API Keys** und senden Sie ihn als `Authorization: Bearer <key>`:

```bash
curl https://docs.example.com/llms.txt \
  -H "Authorization: Bearer jd_live_..."

curl https://docs.example.com/using/scope.md \
  -H "Authorization: Bearer jd_live_..."
```

Mit einem Schlüssel liefern `.md`-URLs die Seiten, die in der Suche erscheinen. Gruppenbeschränkte Seiten, ausgeblendete Seiten und Seiten mit `search: false` liefern `404`. Ein Schlüssel, der für die Website nicht gültig ist, erhält einen `401`-JSON-Fehler mit `invalid_api_key`. Ohne Schlüssel ändert sich nichts.

Der Schlüssel öffnet nie HTML-Seiten oder den KI-Chat. Diese benötigen weiterhin einen Login. Anfragen mit einem Schlüssel teilen sich ein Limit von 120 pro Minute und Schlüssel mit dem [MCP-Server](/de/ai/mcp-server#ratenbegrenzungen). Über dem Limit erhalten Sie ein `429` mit `Retry-After: 60`.

## Agenten-Hinweis auf jeder Seite

Jede Seite enthält einen unsichtbaren, für Screenreader stummen Hinweis, der KI-Agenten auf `llms.txt` verweist. Jeder Markdown-Export beginnt mit einem Blockzitat, das auf das Verzeichnis verlinkt. Agenten, die auf Ihrer HTML-Seite landen, finden den Markdown-Pfad, ohne zu crawlen.

## So wird es erstellt

- Wird zur Build-Zeit zusammen mit Ihrem HTML erzeugt
- Wird vom CDN mit derselben Cache-Richtlinie wie Ihre Dokumentation ausgeliefert
- Wird bei jedem Build automatisch aktualisiert
- Keine Konfiguration nötig. Standardmäßig ist jede Seite enthalten

## llms.txt deaktivieren

Jamdesk veröffentlicht `llms.txt` und `llms-full.txt` standardmäßig. Setzen Sie `seo.ai.llmsTxt` in `docs.json` auf `false`, um die Erzeugung zu beenden, zum Beispiel damit KI-Tools Ihre Inhalte nicht aufnehmen:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Jamdesk überspringt die Dateien beim nächsten Build, einschließlich aller sprachspezifischen Kopien. Die Live-URLs `/llms.txt` und `/llms-full.txt` liefern `404`.

<Note>
  **KI-Aufnahme und Suchindexierung sind getrennte Steuerungen.** `seo.ai.llmsTxt` steuert nur die Dateien `llms.txt`/`llms-full.txt`, die KI-Tools lesen. Es ändert nichts daran, wie Suchmaschinen Ihre Website indexieren. [`robots`-Metadaten und seitenbezogenes `noindex`](/de/content/seo#indexierung-steuern) steuern die Indexierung. Eine Seite kann von Google indexiert werden und trotzdem von der KI-Aufnahme ausgeschlossen sein, oder umgekehrt.
</Note>

## KI-Crawler

Die Standard-`robots.txt` von Jamdesk erlaubt alle gängigen KI-Crawler (Claude, ChatGPT, Copilot, Gemini).

<Accordion title="Wie sich llms.txt von sitemap.xml unterscheidet">
  `sitemap.xml` listet URLs auf, damit Suchmaschinen sie crawlen und indexieren können. Sie enthält keinen Inhalt, nur Links und Metadaten wie Datumsangaben zur letzten Änderung.

  `llms.txt` richtet sich an KI-Modelle. Sie enthält Seitentitel, Beschreibungen und (in `llms-full.txt`) den Seiteninhalt. KI-Tools lesen die vollständige Datei in einer einzigen HTTP-Anfrage, statt vieler einzelner.
</Accordion>
