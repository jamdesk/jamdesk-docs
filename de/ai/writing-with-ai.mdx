Diese Strategien funktionieren mit jedem KI-Tool, einschließlich Claude Code, Cursor, Codex und Copilot. Die toolspezifische Einrichtung finden Sie unter [Claude Code](/de/ai/claude-code), [Cursor](/de/ai/cursor) oder [Codex](/de/ai/codex).

## Warum MDX gut mit KI funktioniert

MDX ist eines der einfachsten Formate, die KI-Tools schreiben können:

- Vertraute Syntax: KI-Modelle wurden mit Millionen von Markdown-Dateien trainiert. Sie erzeugen gültiges MDX mit wenig Prompting.
- Strukturierte Komponenten: `<Card>`, `<Steps>` und `<Tabs>` folgen vorhersehbaren Mustern, die Modelle schnell lernen.
- Klartext: MDX besitzt keine Binärformate, proprietären Schemata oder Build-Artefakte, die ein KI-Tool interpretieren müsste.

## Bessere Prompts schreiben

Der Prompt entscheidet meist darüber, ob KI-Dokumentation mittelmäßig oder gut wird. Seien Sie präzise, was Sie wollen.

<Tabs>
  <Tab title="Schwache Prompts">
    ```text
    Write docs for the webhook feature.
    ```

    ```text
    Document authentication.
    ```

    ```text
    Create a getting started guide.
    ```

    Diese Prompts erzeugen generische, aufgeblähte Ausgaben. Die KI hat keine Vorgaben.
  </Tab>
  <Tab title="Starke Prompts">
    ```text
    Write a page documenting our webhook feature. The reader is a developer
    integrating webhooks for the first time. Start with a 3-step quickstart,
    then cover payload format and retry behavior. Reference /src/webhooks
    for the implementation.
    ```

    ```text
    Add a troubleshooting section to the authentication page. Cover these
    three errors: expired tokens, missing scopes, and rate limits. Use
    Accordions for each error. Keep each answer under 4 lines.
    ```

    ```text
    Create a getting started guide that gets the reader from zero to a
    working hello-world in under 2 minutes. Skip the theory and background,
    and jump straight into the install command.
    ```

    Vorgaben erzeugen fokussierte Ausgaben. Sagen Sie der KI, wer der Leser ist, welche Struktur sie verwenden soll und was sie weglassen soll.
  </Tab>
</Tabs>

### Funktionierende Prompt-Muster

| Muster | Beispiel |
|---------|---------|
| **Leser festlegen** | „Der Leser ist ein Backend-Entwickler, der unsere API noch nie verwendet hat“ |
| **Struktur benennen** | „Verwende Steps für den Setup-Ablauf, dann Tabs für Sprachvarianten“ |
| **Längenbegrenzungen setzen** | „Halte die Einleitung unter 2 Sätzen“ oder „Jede Accordion-Antwort sollte 3–4 Zeilen lang sein“ |
| **Auf Quellcode verweisen** | „Referenziere die Implementierung in /src/auth für Genauigkeit“ |
| **Angeben, was wegzulassen ist** | „Erkläre nicht, was REST ist. Lass die Theorie weg.“ |
| **Eine Beispielseite geben** | „Passe Ton und Struktur an /quickstart an“ |

## KI-Ausgaben prüfen

KI-Tools erzeugen meist strukturell korrektes MDX. Die subtileren Probleme liegen in Ton, Genauigkeit und Aufblähung. Gehen Sie diese Checkliste durch, bevor Sie committen.

### Sprachstil prüfen

Lesen Sie die Ausgabe laut vor. Wenn sie wie ein Chatbot klingt, schreiben Sie sie um. Achten Sie auf:

- Füllphrasen: „Es ist wichtig zu beachten, dass“, „Dies ermöglicht Ihnen“, „Um zu“
- Relativierungen: „Sie sollten eventuell in Betracht ziehen“, „Es wird im Allgemeinen empfohlen“
- Leere Übergänge: „Nachdem wir X behandelt haben, kommen wir nun zu Y“
- Schlagworte: „nahtlos“, „robust“, „nutzen“, „optimieren“

Streichen Sie diese.

### Genauigkeit prüfen

KI-Tools liefern selbstbewusst falsche Informationen. Prüfen Sie:

- Funktionieren die Codebeispiele tatsächlich? Kopieren Sie sie und führen Sie sie aus.
- Sind die Konfigurationsoptionen real? Gegen den Quellcode prüfen.
- Sind die Komponentennamen korrekt? Verwenden Sie nur [Komponenten, die existieren](/de/components/overview).
- Beschreibt die Seite das aktuelle Verhalten, nicht angestrebte Funktionen?

### Struktur prüfen

- [ ] Frontmatter enthält sowohl `title` als auch `description`
- [ ] Es gibt einen einleitenden Absatz ohne Überschrift davor
- [ ] Die Seite endet mit „Wie geht es weiter?“-Karten in einem `<Columns>`-Wrapper
- [ ] Neue Seiten sind in der `docs.json`-Navigation ergänzt
- [ ] Keine erfundenen Komponenten; nur die aus der [Komponentenreferenz](/de/components/overview)

## Häufige Fehler von KI

<AccordionGroup>
  <Accordion title="Komponenten erfinden, die nicht existieren">
    KI-Tools erzeugen `<CodeBlock>`, `<Alert>`, `<Section>`, `<Callout>` und andere Komponenten, die es in Jamdesk nicht gibt. Verwenden Sie nur die Komponenten aus der [Übersicht](/de/components/overview).
  </Accordion>
  <Accordion title="Die docs.json-Navigation vergessen">
    Eine Seite anzulegen, ohne sie zu `docs.json` hinzuzufügen, ist der häufigste Fehler. Die Seite existiert, erscheint aber nicht in der Seitenleiste. Ergänzen Sie jede neue Seite in der Navigation.
  </Accordion>
  <Accordion title="Hinweisboxen übermäßig verwenden">
    KI-Tools packen gern jeden zweiten Absatz in ein `<Note>` oder `<Warning>`. Ein oder zwei Hinweisboxen pro Seite reichen völlig.
  </Accordion>
  <Accordion title="Zu viel schreiben">
    Eine 200-zeilige Seite von der KI hat meist nur 100 Zeilen echten Inhalt. Achten Sie auf wiederholte Erklärungen, unnötigen Hintergrund und Absätze, die dasselbe mit anderen Worten sagen. Kürzen Sie rigoros.
  </Accordion>
  <Accordion title="Generische Beschreibungen">
    „Diese leistungsstarke Funktion ermöglicht es Ihnen, …“ sagt dem Leser nichts. Sagen Sie, was sie tut: „Sendet HTTP-POST-Anfragen an Ihren Endpunkt, wenn Ereignisse auftreten.“
  </Accordion>
</AccordionGroup>

## Dokumentation synchron halten

Dokumentation schreiben ist der einfache Teil. Sie aktuell zu halten, wenn sich der Code ändert, ist schwieriger.

<Tabs>
  <Tab title="Manuelles Prompting">
    Prompten Sie Ihr KI-Tool nach dem Ausliefern einer Funktion:

    ```text
    I just added [feature]. Update the docs to reflect this change.
    Reference the implementation in /src/[file] for accuracy.
    ```
  </Tab>
  <Tab title="Automatisiert mit /update-jamdesk">
    Der `/update-jamdesk`-Skill für Claude Code analysiert Ihre Codeänderungen und erzeugt passende Dokumentationsupdates. Führen Sie ihn nach der Implementierung nutzerseitiger Funktionen aus:

    ```text
    /update-jamdesk
    ```

    Die vollständige Einrichtung finden Sie unter [Automatisierte Updates](/de/ai/automated-updates).
  </Tab>
</Tabs>

## Seitengerüst

Verwenden Sie dies als Start-Prompt, wenn Sie die KI bitten, eine neue Seite zu erstellen:

<Prompt title="Eine Jamdesk-Dokumentationsseite erstellen" actions={["cursor", "claude", "chatgpt"]}>
Create a Jamdesk documentation page using this structure. Replace each placeholder with specific, accurate content for the feature I describe.

```mdx
---
title: Feature Name
description: One sentence summarizing what this page covers.
---

Opening paragraph: what problem this solves and who should read this.

## Quick Start

<Steps>
  <Step title="First step">What to do.</Step>
  <Step title="Second step">What to do next.</Step>
</Steps>

## How It Works

Explain the mechanics. Use code examples.

## What's Next?

<Columns cols={2}>
  <Card title="Related Page" icon="arrow-right" href="/path">
    Why the reader would go here next
  </Card>
</Columns>
```
</Prompt>
