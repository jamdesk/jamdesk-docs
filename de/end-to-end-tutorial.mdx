Vom leeren Repo zur live verfügbaren Dokumentationsseite. Überspringen Sie Schritte, die Sie bereits erledigt haben.

## Voraussetzungen

- Ein GitHub-Konto
- Ein Repository mit Dokumentationsinhalten (oder verwenden Sie die [Starter-Vorlage](https://github.com/jamdesk/starter-docs))
- Node.js 20+, falls Sie die CLI mit npm installieren möchten

<Steps>
  <Step title="Projekt anlegen und GitHub verbinden">
    Legen Sie im Jamdesk-Dashboard ein Projekt an und verbinden Sie ein Repository.

    - Folgen Sie [Projekte erstellen](/de/setup/creating-projects), um Projektname, Slug und Dokumentationspfad festzulegen
    - Installieren Sie bei Aufforderung die GitHub-App und gewähren Sie Zugriff auf das Repository ([GitHub verbinden](/de/setup/connecting-github))
  </Step>

  <Step title="Seiten mit der CLI bearbeiten und in der Vorschau prüfen">
    Prüfen Sie Seitenänderungen mit der Jamdesk-CLI in der Vorschau, bevor Sie sie nach GitHub übertragen.

    <Tabs>
      <Tab title="npm">
        ```bash
        npm install -g jamdesk
        cd your-docs
        jamdesk dev
        ```
      </Tab>
      <Tab title="npx">
        ```bash
        cd your-docs
        npx jamdesk dev
        ```
      </Tab>
    </Tabs>

    Ihre lokale Vorschau läuft unter **http://localhost:3000**. Mehr dazu unter [Lokale Vorschau](/de/development/local-preview).

    Öffnen Sie eine `.mdx`-Seite in Ihrem Editor. Speichern Sie eine Änderung und aktualisieren Sie die lokale Vorschau. Veröffentlichen Sie sie mit dem Git-Workflow im nächsten Schritt.
  </Step>

  <Step title="Mit einem Push zu GitHub bereitstellen">
    Jeder Push auf Ihren konfigurierten Branch löst einen Build aus. Der Build wird auf Ihrer Jamdesk-Subdomain veröffentlicht.

    ```bash
    git add .
    git commit -m "Add docs content"
    git push origin main
    ```

    Ersetzen Sie `main` durch den konfigurierten Branch Ihres Projekts.

    Ihre Dokumentation ist unter `your-project.jamdesk.app` live, sobald der Build abgeschlossen ist. Details finden Sie unter [Bereitstellung](/de/development/deployment).
  </Step>

  <Step title="Optional: Eigene Domain hinzufügen">
    Stellen Sie Ihre Dokumentation über Ihre eigene Domain statt über die Jamdesk-Subdomain bereit.

    1. Gehen Sie im Jamdesk-Dashboard zu **Settings** → **Domains**
    2. Fügen Sie Ihre Domain hinzu (zum Beispiel `docs.example.com`)
    3. Erstellen Sie die im Dashboard angezeigten DNS-Einträge
    4. Warten Sie, bis Verifizierung und SSL abgeschlossen sind

    Hinweise zur Fehlerbehebung finden Sie unter [Eigene Domains](/de/deploy/custom-domains).
  </Step>
</Steps>

## End-to-End-Ablauf überprüfen

- Ihre Jamdesk-Subdomain lädt und zeigt den neuesten Build
- Die lokale Vorschau zeigt denselben Inhalt und dieselbe Navigation
- Falls konfiguriert, ist die eigene Domain verifiziert und liefert HTTPS aus
- Der Build-Verlauf zeigt den neuesten Commit und die Autorenzuordnung

## Optional: Unter /docs hosten

Um die Dokumentation unter einem Unterpfad wie `example.com/docs` bereitzustellen, siehe [Bereitstellungsübersicht](/de/deploy/overview) und [Hosting unter Unterpfad](/de/deploy/subpath-hosting).
