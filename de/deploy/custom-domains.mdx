Stellen Sie Ihre Dokumentation über Ihre eigene Domain statt über die Standard-Subdomain `*.jamdesk.app` bereit.

## Übersicht zur Einrichtung

<Steps>
  <Step title="Domain im Dashboard hinzufügen">
    Gehen Sie zu **Settings** → **Domain** in Ihrem Projekt und geben Sie Ihre Domain ein (z. B. `docs.example.com` oder `example.com`).
  </Step>
  <Step title="DNS konfigurieren">
    Fügen Sie die im Dashboard angezeigten DNS-Einträge bei Ihrem DNS-Anbieter hinzu. Welche Einträge nötig sind, hängt vom Domaintyp ab (siehe unten).
  </Step>
  <Step title="Verifizieren und warten">
    Jamdesk prüft die Inhaberschaft und stellt ein SSL-Zertifikat bereit.
  </Step>
</Steps>

## Hosting-Optionen

Wählen Sie einen Hosting-Modus, wenn Sie eine Domain hinzufügen.

### Standarddomain

Jamdesk stellt Ihre Dokumentation direkt unter Ihrer benutzerdefinierten Domain bereit:

```text
docs.example.com → acme.jamdesk.app
```

Der DNS-Eintrag zeigt auf Jamdesk. Jamdesk stellt das SSL-Zertifikat aus und erneuert es.

### Hosting unter /docs (Proxy-basiertes, anpassbares Unterverzeichnis)

Ihre Dokumentation liegt unter einem Unterpfad Ihrer bestehenden Website:

```text
example.com/docs → acme.jamdesk.app/docs
```

`/docs` ist der Standardwert. Über denselben Schalter können Sie stattdessen einen beliebigen einstufigen Unterpfad wählen (`/help`, `/guide` usw.). Konfigurieren Sie einen Proxy (Cloudflare, Vercel, nginx usw.), der Anfragen für diesen Unterpfad an Jamdesk weiterleitet. Einrichtungsanleitungen und die Regeln zur Wahl eines Unterpfads finden Sie unter [Unterpfad-Hosting](/de/deploy/subpath-hosting).

<Note>
Das Umschalten von „Host at a subpath“ oder das Ändern des Unterpfads löst einen neuen Build aus. Die URL-Struktur ändert sich.
</Note>

## DNS-Konfiguration

Welche Einträge Sie benötigen, hängt davon ab, ob Sie eine Subdomain oder eine Apex-Domain (Root-Domain) verwenden.

### Subdomains (z. B. docs.example.com)

| Typ | Name | Wert |
|------|------|-------|
| CNAME | `docs` | `cname.jamdesk.com` |
| TXT | `_jamdesk.docs` | *(im Dashboard angezeigt)* |

Das Feld „Name“ enthält den Subdomain-Teil. Für `docs.example.com` tragen Sie `docs` ein.

### Apex-Domains (z. B. example.com)

| Typ | Name | Wert |
|------|------|-------|
| A | `@` | `76.76.21.21` |
| TXT | `_jamdesk` | *(im Dashboard angezeigt)* |

Apex-Domains verwenden einen A-Eintrag statt eines CNAME. Die DNS-Standards (RFC 1034) verbieten CNAME-Einträge an der Zonenspitze.

<Note>
DNS-Änderungen können bis zu 48 Stunden brauchen, bis sie weltweit wirksam sind. Meistens dauert es nur wenige Minuten. Den Status prüfen Sie unter [whatsmydns.net](https://www.whatsmydns.net/).
</Note>

## Verifizierung

Sobald Sie die DNS-Einträge hinzugefügt haben, führt Jamdesk diese Schritte aus:

1. Erkennt Ihre DNS-Einträge (CNAME oder A-Eintrag sowie TXT)
2. Verifiziert die Domain-Inhaberschaft über den TXT-Eintrag
3. Stellt ein SSL-Zertifikat über Let's Encrypt bereit
4. Leitet den Datenverkehr zu Ihrer Dokumentation

Den Verifizierungsstatus sehen Sie unter **Settings** → **Domain**. Mögliche Status:
- **Pending** – Warten auf die DNS-Verbreitung
- **Active** – Domain verifiziert und aktiv
- **Needs Attention** – Konfigurationsabweichung oder Konflikt (prüfen Sie die E-Mail-Benachrichtigung)
- **Error** – Konfigurationsproblem (Details im Dashboard)

Klicken Sie im Dashboard auf **Refresh**, um den Verifizierungsstatus sofort zu prüfen.

## SSL-Zertifikate

Jamdesk stellt SSL-Zertifikate bereit und erneuert sie vor Ablauf. HTTP-Anfragen werden auf HTTPS umgeleitet.

## Root-Domains

Root-Domains (Apex-Domains) wie `example.com` werden unterstützt. Das Dashboard zeigt dann einen A-Eintrag mit dem Ziel `76.76.21.21` statt eines CNAME an. Die DNS-Standards verbieten CNAME-Einträge an der Zonenspitze.

## Mehrere Domains

Jedes Projekt hat genau eine benutzerdefinierte Domain. Um weitere Domains auf dieselbe Dokumentation zu leiten:

1. Richten Sie Ihre primäre Domain in Jamdesk ein
2. Konfigurieren Sie zusätzliche Domains so, dass sie auf DNS- bzw. CDN-Ebene auf die primäre Domain weiterleiten

## Domain entfernen

1. Gehen Sie zu **Settings** → **Domain**
2. Klicken Sie auf **Remove Domain**
3. Ihre Dokumentation bleibt unter der Subdomain `*.jamdesk.app` erreichbar

<Warning>
Das Entfernen einer Domain bei aktiviertem „Host at a subpath“ löst einen Build aus, der die URL-Pfade aktualisiert. Jamdesk entfernt außerdem jeden benutzerdefinierten Unterpfad. Eine Domain, die Sie später wieder verbinden, startet mit dem Standardwert `/docs`.
</Warning>

## Cloudflare-Nutzer

Gehen Sie so vor, wenn Cloudflare Ihr DNS-Anbieter ist:

1. Setzen Sie den Proxy-Status während der Domain-Verifizierung auf **DNS only** (graue Wolke)
2. Überlassen Sie SSL Vercel: Deaktivieren Sie in Cloudflare „Always Use HTTPS“ für die Dokumentations-Subdomain
3. Nach Abschluss der Verifizierung können Sie das Proxying wieder aktivieren (orange Wolke)

<Note>
**Sie verwenden einen Cloudflare Worker?** Der DNS-Eintrag muss proxied sein (orange Wolke), damit der Worker ausgeführt wird. Verwenden Sie die graue Wolke nur während der Verifizierung und schalten Sie danach zurück. Details finden Sie unter [Cloudflare-Workers-Einrichtung](/de/deploy/cloudflare).
</Note>

## Fehlerbehebung

| Problem | Lösung |
|-------|----------|
| Domain bleibt auf „Pending“ hängen | Prüfen Sie die DNS-Einträge mit `dig` (CNAME für Subdomains, A für Apex-Domains) |
| SSL-Zertifikatsfehler | Stellen Sie sicher, dass keine CAA-Einträge Let's Encrypt blockieren |
| Weiterleitungsschleifen | Bei Cloudflare während der Verifizierung auf graue Wolke stellen (siehe [Cloudflare-Nutzer](#cloudflare-nutzer) oben) |
| CNAME wird nicht aufgelöst | Eintrag beim DNS-Anbieter prüfen und auf die Verbreitung warten |
| Domain bereits in Verwendung | Die Domain ist aus einer früheren Einrichtung bei Vercel registriert; die Verifizierung gelingt meist automatisch |

### DNS mit dig überprüfen

```bash
# Check CNAME record (subdomains)
dig CNAME docs.example.com

# Check A record (apex domains)
dig A example.com

# Check TXT record
dig TXT _jamdesk.example.com
```

Ausführliche Diagnosen finden Sie unter [DNS-Fehlerbehebung](/de/help/troubleshooting/dns-issues).

## Konkurriert die jamdesk.app-Subdomain in der Suche mit meiner Domain?

Nein. Seiten, die über Ihre Subdomain `[slug].jamdesk.app` ausgeliefert werden, enthalten einen Canonical-Link auf Ihre aktive benutzerdefinierte Domain. Suchmaschinen rechnen die Ranking-Signale Ihrer Domain zu.
