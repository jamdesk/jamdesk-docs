---
title: Broken Links reparieren
description: >-
  Erfahren Sie, wie jamdesk fix defekte interne Links und fehlerhafte Anker repariert, mit einer Vorschau vor dem Schreiben von Änderungen.
---

`jamdesk fix` repariert, was `jamdesk broken-links` meldet. Es liest dieselben Warnungen und schreibt einen Link neu, wenn es ein eindeutig korrektes Ziel findet. Mehrdeutige Fälle bleiben zur manuellen Prüfung unverändert.

<Tip>
  [Mit KI reparieren](/de/builds/fix-with-ai) führt dieselbe Reparatur für einen Build im Dashboard aus. Außerdem ergänzt es fehlende Seitenbeschreibungen. Die Änderungen werden auf GitHub committet.
</Tip>

Es repariert zwei Arten defekter interner Links:

- **Fehlerhafte Anker**: ein Fragment, das eine eindeutige Falschschreibung einer echten Überschrift auf der Zielseite ist (z. B. `#instalation` → `#installation`)
- **Anker-Drift zwischen Sprachversionen**: Eine übersetzte Seite hat ihre Überschriften umbenannt, aber Links in dieser Sprachversion verweisen noch auf das alte englische Fragment (z. B. `/fr/ai/selectors#ai-strategies` → `/fr/ai/selectors#stratégies-ia`)

## Schritt 1: Defekte Links finden

Führen Sie `jamdesk broken-links` aus, um zu sehen, was repariert werden muss:

```bash
jamdesk broken-links
```

Prüfen Sie die Ausgabe. `jamdesk fix` zielt auf Warnungen, bei denen es einen wahrscheinlichen Anker einer echten Überschrift zuordnen kann.

## Schritt 2: Korrekturen in der Vorschau anzeigen

Führen Sie den Befehl mit `--dry-run` aus, um zu sehen, was sich ändern würde, ohne Dateien zu schreiben:

```bash
jamdesk fix --dry-run
```

**Beispielausgabe:**

```text
Planned fixes:

  fr/ai/overview.mdx:9
    /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

(dry run — no files written)
```

Prüfen Sie jede geplante Reparatur. Wenn eine Änderung falsch aussieht, korrigieren Sie diesen Link stattdessen von Hand.

## Schritt 3: Korrekturen anwenden

Führen Sie den Befehl ohne `--dry-run` aus, um sie anzuwenden. Die CLI bittet um Bestätigung:

```bash
jamdesk fix
```

```text
Apply 1 fix(es) to local files? (y/N)
```

Drücken Sie `y`, um die Änderungen zu schreiben. In CI oder Skripten überspringen Sie die Abfrage mit `-y`:

```bash
jamdesk fix -y
```

Der Befehl gibt anschließend aus:

```text
Fixed 1 file(s); 0 warning(s) left for manual review.
```

`jamdesk fix` lässt eine Warnung mit einem mehrdeutigen Ziel für Sie zur manuellen Korrektur stehen.

## Schritt 4: Diff prüfen und committen

Prüfen Sie die Änderungen vor dem Commit:

```bash
git diff
```

Stellen Sie sicher, dass jeder umgeschriebene Link dorthin zeigt, wo Sie es erwarten. Committen Sie dann:

```bash
git add -A
git commit -m "fix(docs): auto-fix broken internal links"
```

## Optionen

| Flag | Beschreibung |
|------|-------------|
| `--dry-run` | Geplante Reparaturen anzeigen, ohne Dateien zu schreiben |
| `-y, --yes` | Reparaturen ohne Bestätigungsabfrage anwenden |
| `--types <list>` | Kommagetrennte Warnungstypen, die repariert werden sollen (Standard: alle unterstützten) |
