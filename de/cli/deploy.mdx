Der Befehl `deploy` packt Ihre Dokumentation, lädt sie zu Jamdesk hoch und startet einen Build direkt aus dem Terminal. Verwenden Sie ihn für schnelle Iterationen, zum Testen von Änderungen oder für Projekte, die nicht mit einem GitHub-Repository verbunden sind.

## Schnellstart

```bash
jamdesk login        # First time only
jamdesk deploy       # From your project directory
```

## Optionen

| Flag | Beschreibung |
|------|-------------|
| `--detach` | Stellt den Build in die Warteschlange und beendet sich sofort (gibt einen Dashboard-Link aus) |
| `--full-rebuild` | Erzwingt einen vollständigen Rebuild unter Umgehung des Build-Caches |
| `--project <id>` | Deployt in ein bestimmtes Projekt mit dieser ID (überspringt die interaktive Auswahl) |
| `--allow-empty` | Erlaubt das Deployen ohne `.mdx`-Inhaltsseiten. Standardmäßig verweigert die CLI das Deployen eines leeren Projekts. So wird verhindert, dass ein falsches Arbeitsverzeichnis eine leere Site veröffentlicht. Snippets zählen nicht als Inhaltsseiten |

`jamdesk push` ist ein Alias für `jamdesk deploy`.

## Funktionsweise

<Steps>
  <Step title="Authentifizieren">
    Überprüft Ihre Sitzung. Ein abgelaufenes Token fordert Sie auf, `jamdesk login` auszuführen.
  </Step>
  <Step title="Konfiguration laden">
    Liest und validiert `docs.json` aus dem aktuellen Verzeichnis.
  </Step>
  <Step title="Projekt ermitteln">
    Liest `projectId` aus `docs.json`. Beim ersten Deploy fehlt sie. Die CLI fordert Sie dann auf, ein Projekt auszuwählen. Die CLI speichert Ihre Auswahl in `docs.json`. Beim nächsten Deploy entfällt die Abfrage.

    Verwenden Sie `--project <id>`, um dies zu überschreiben.
  </Step>
  <Step title="Dateien packen">
    Erstellt ein komprimiertes Tarball Ihrer Dokumentation. Dateien in `.gitignore` werden ausgelassen. Die CLI warnt vor Dateien, die wie Geheimnisse aussehen. Die Warnung blockiert den Upload nicht.
  </Step>
  <Step title="Hochladen">
    Sendet das Tarball über eine signierte URL an Jamdesk. Die maximale Upload-Größe beträgt 100 MB.
  </Step>
  <Step title="Build">
    Stellt einen Build in die Warteschlange und fragt den Status ab. Jede Phase wird bei Abschluss ausgegeben. Drücken Sie Strg+C, um die Abfrage zu beenden. Der Build läuft im Hintergrund weiter.
  </Step>
  <Step title="Fertig">
    Gibt die Live-URL aus, sobald der Build abgeschlossen ist.
  </Step>
</Steps>

## Build-Phasen

Die CLI gibt jede Phase in der Reihenfolge aus, während sie abfragt:

| Phase | Beschreibung |
|-------|-------------|
| Dateien extrahieren | Entpackt das hochgeladene Tarball |
| Konfiguration validieren | Prüft Schema und Inhalt von `docs.json` |
| Inhalte vorbereiten | Verarbeitet MDX-Dateien und Assets |
| Dokumentation erstellen | Kompiliert Seiten und erzeugt statische Artefakte |
| Ins CDN hochladen | Überträgt die erstellte Ausgabe ins Edge-Netzwerk |
| Cache aktualisieren | Leert veraltete Inhalte aus dem CDN |

## Dateiausschlüsse

Diese werden unabhängig von Ihrer `.gitignore` immer vom Upload ausgeschlossen:

`.git`, `node_modules`, `.next`, `.env`, `.env.*`, `*.pem`, `*.key`, `credentials.json`, `.gcloud`, `.DS_Store`, `Thumbs.db`

Alles in Ihrer `.gitignore` wird ebenfalls ausgeschlossen.

### Warnungen zu geheimen Dateien

Die CLI warnt (blockiert aber nicht), wenn sie Dateien erkennt, die wie Geheimnisse aussehen:

- `.env`- und `.env.*`-Dateien
- `*.pem`- und `*.key`-Dateien
- `credentials.json`
- `service_account*.json`
- Dateien, die mit `secret` beginnen

Fügen Sie sie zu `.gitignore` hinzu, um die Warnung zu unterdrücken und sie vom Upload auszuschließen.

## Fehlerreferenz

| Fehler | Code | Ursache | Behebung |
|-------|------|-----|-----|
| Nicht angemeldet | `AUTH_REQUIRED` | Keine gespeicherten Zugangsdaten | `jamdesk login` |
| Sitzung abgelaufen | `AUTH_EXPIRED` | Token-Erneuerung fehlgeschlagen | `jamdesk login` |
| Zugriff verweigert | `FORBIDDEN` | Kein Mitglied dieses Projekts | Projektmitgliedschaft im Dashboard prüfen |
| Projekt nicht gefunden | `NOT_FOUND` | Ungültige Projekt-ID | ID prüfen oder `projectId` aus docs.json entfernen |
| Build läuft | `BUILD_IN_PROGRESS` | Ein anderer Build läuft | Warten oder Dashboard prüfen |
| Upload zu groß | `TOO_LARGE` | Server hat Upload abgelehnt (Limit 100 MB) | Große Dateien über `.gitignore` ausschließen |
| Projekt zu groß | `PROJECT_TOO_LARGE` | Tarball überschreitet 100 MB beim Packen | Große Dateien über `.gitignore` ausschließen |
| Keine Projekte | `NO_PROJECTS` | Keine Projekte in Ihrem Konto | Zuerst im Dashboard ein Projekt erstellen |
| Keine Dateien | `EMPTY_PROJECT` | Alle Dateien ausgeschlossen | `.gitignore` prüfen |
| Keine Inhaltsseiten | `NO_CONTENT` | Keine `.mdx`-Inhaltsseiten gefunden (Snippets zählen nicht) | Aus Ihrem Dokumentationsverzeichnis ausführen oder `--allow-empty` übergeben, falls die leere Veröffentlichung beabsichtigt ist |
| Konfiguration ungültig | `CONFIG_NOT_FOUND` | `docs.json` fehlt oder ist ungültig | Aus dem Projektstamm ausführen, Konfiguration prüfen |
| Upload fehlgeschlagen | `UPLOAD_FAILED` | Netzwerkproblem beim Upload | Internetverbindung prüfen, erneut versuchen |
| Build fehlgeschlagen | `BUILD_FAILED` | Fehler im Build-Dienst | Build-Logs im Dashboard prüfen |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title='"A build is already in progress"'>
    Jedes Projekt führt jeweils einen Build aus. Warten Sie, bis der aktuelle Build abgeschlossen ist. Prüfen Sie den Status im Dashboard unter **Deployments**.
  </Accordion>

  <Accordion title='"docs.json not found or invalid"'>
    Führen Sie den Befehl in dem Verzeichnis aus, das `docs.json` enthält. Führen Sie `jamdesk validate` aus, um nach Konfigurationsfehlern zu suchen.
  </Accordion>

  <Accordion title='"Upload too large"'>
    Das Limit von 100 MB gilt für das komprimierte Tarball aller nicht ausgeschlossenen Dateien. Große Bilder, Videos oder Datendateien sind häufige Ursachen. Fügen Sie sie zu `.gitignore` hinzu, um sie auszuschließen.
  </Accordion>

  <Accordion title="Deploy hangs during polling">
    Drücken Sie Strg+C, um zu beenden. Der Build läuft im Hintergrund weiter. Prüfen Sie den Status im Dashboard. Ein wiederkehrendes Hängen kann bedeuten, dass Ihr Netzwerk die Abfrage-Anfragen verwirft.
  </Accordion>

  <Accordion title='"No projects found"'>
    Sie benötigen mindestens ein Projekt in Ihrem Jamdesk-Konto. Erstellen Sie eines unter [dashboard.jamdesk.com](https://dashboard.jamdesk.com).
  </Accordion>
</AccordionGroup>
