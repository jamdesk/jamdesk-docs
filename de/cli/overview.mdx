Mit der Jamdesk CLI kannst du deine Dokumentation lokal in der Vorschau anzeigen, Konfigurationen validieren, defekte Links prüfen und von anderen Plattformen migrieren. Sie ist Open Source unter der [Apache License 2.0](https://github.com/jamdesk/jamdesk-cli).

## Installation

<Tabs>
  <Tab title="npm (Empfohlen)">
    Installiere sie global über [npm](https://www.npmjs.com/package/jamdesk), um `jamdesk` von überall aus zu verwenden:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Installiere mit Homebrew:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Installiere über das Skript:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Aktualisieren oder deinstallieren:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Installiere über das Skript:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Aktualisieren oder deinstallieren:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Ausführen ohne Installation:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Überprüfe die Installation:

```bash
jamdesk --version
```

### Voraussetzungen

- **Node.js** 22.18+ oder 24.11+ (Node.js 23 wird nicht unterstützt)
- **npm** v8 oder höher (empfohlen)

## Schnellstart

<Steps>
  <Step title="Ein Projekt erstellen">
    Erstelle ein neues Dokumentationsprojekt:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Entwicklungsserver starten">
    Starte den lokalen Entwicklungsserver mit Hot Reload:

    ```bash
    jamdesk dev
    ```

    Deine Dokumentation läuft unter **http://localhost:3000/docs**
  </Step>
  <Step title="Vor dem Bereitstellen validieren">
    Prüfe auf Konfigurationsfehler, defekte Links und Rechtschreibung:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Befehle

Führe `jamdesk <command> --help` aus, um Details zu einem Befehl zu erhalten.

### Entwicklung

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Starte den lokalen Entwicklungsserver mit Hot Reload.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Funktionen:**
  - Automatische Validierung beim Start (docs.json-Schema, MDX-Syntax und referenzierte OpenAPI-Spezifikationen. Eine ungültige Spezifikation stoppt den Server.)
  - Hot Reload bei Änderungen an MDX-Dateien
  - Automatischer Neuaufbau der Navigation bei Änderungen an docs.json
  - Benutzerdefiniertes CSS (`style.css`) wird beim Neuladen des Browsers neu geladen
  - Suche
  - Alle Themes und Komponenten

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `-p, --port <port>` | Port, auf dem ausgeführt wird (Standard: 3000) |
  | `-v, --verbose` | Ausführliche Ausgabe aktivieren |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Erstelle ein neues Dokumentationsprojekt.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Dies erstellt ein neues Projekt mit:
  - Konfigurationsdatei `docs.json`
  - Beispiel-MDX-Seiten
  - Empfohlener Ordnerstruktur
</Accordion>

### Validierung

<Accordion title="jamdesk validate" icon="check">
  Validiere deine `docs.json`-Konfiguration, MDX-Syntax und OpenAPI-Spezifikationen.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Prüft auf:**
  - Gültige JSON-Syntax in docs.json
  - Pflichtfelder (name, navigation)
  - Gültige Theme-Werte
  - MDX-Syntaxfehler (z. B. nicht maskierte `<`-Zeichen)
  - OpenAPI-Spezifikationsvalidierung (falls konfiguriert)
  - Schema-Konformität

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--skip-mdx` | MDX-Syntaxvalidierung überspringen |
  | `-v, --verbose` | Detaillierte Validierungsausgabe anzeigen |

  Führe dies vor dem Bereitstellen aus, um Fehler frühzeitig zu erkennen.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Durchsuche deine Dokumentation nach defekten internen Links.

  ```bash
  jamdesk broken-links
  ```

  **Beispielausgabe:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Erkennt Links zu fehlenden Seiten und Tippfehler. Details findest du unter [Links & Navigation](/de/content/links#erkennung-interner-links).
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Behebt automatisch Warnungen zu defekten internen Links, die ein eindeutiges Ziel haben. Es werden zwei Arten behoben:
  - **Fehlerhafte Anker**: ein Fragment wie `#instalation`, das eindeutig `#installation` sein soll
  - **Anker-Abweichung zwischen Sprachen**: Eine übersetzte Seite hat ihre Überschriften umbenannt, Links in dieser Sprachversion zeigen aber noch auf das alte englische Fragment

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **Beispielausgabe des Dry-Runs:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  `jamdesk fix` schreibt eine Korrektur nur, wenn der korrigierte Anker auf eine tatsächlich vorhandene Überschrift auf der Zielseite verweist. Mehrdeutige Fälle werden zur manuellen Prüfung belassen.

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--dry-run` | Geplante Korrekturen anzeigen, ohne Dateien zu schreiben |
  | `-y, --yes` | Korrekturen ohne Bestätigungsabfrage anwenden |
  | `--types <list>` | Kommagetrennte Warnungstypen, die behoben werden sollen (Standard: alle unterstützten) |
  | `--no-ai` | KI-Korrekturen überspringen und nur Korrekturen verwenden, die Jamdesk ohne KI ermitteln kann |
  | `--project <id>` | Projekt-ID für KI-Korrekturen (Standard: `projectId` in `docs.json`) |
  | `--json` | Korrekturplan und nicht behebbare Probleme als JSON für einen KI-Agenten ausgeben. Schreibt keine Dateien und stellt keine Rückfragen. Benötigt CLI 1.1.229 oder neuer |

  <Card title="Leitfaden: Defekte Links beheben" icon="wrench" href="/de/cli/fix-broken-links">
    Schritt-für-Schritt-Anleitung: Vorschau, Anwenden, Prüfen und Committen
  </Card>
</Accordion>

<Accordion title="jamdesk ai-fix" icon="wand-magic-sparkles">
  Zeige die Einstellung **AI Fixes** des Projekts an oder ändere sie. Dies ist dieselbe Einstellung wie in den Dashboard-Einstellungen.

  ```bash
  # Show the current setting
  jamdesk ai-fix

  # Commit fixes to your build branch after each build
  jamdesk ai-fix auto

  # Suggest fixes for you to review in the dashboard
  jamdesk ai-fix review

  # Turn off dashboard scans
  jamdesk ai-fix off
  ```

  **Beispielausgabe:**
  ```text
  ✓ AI Fixes set to Auto-fix
  Jamdesk commits fixes to main after the next build. Pull before you push. Undo runs from the dashboard.
  ```

  Führe zuerst `jamdesk login` aus. Der Befehl verwendet die `projectId` in `docs.json` oder das Projekt, das du mit `--project` angibst. Benötigt CLI 1.1.229 oder neuer.

  | Flag | Beschreibung |
  |------|-------------|
  | `--project <id>` | Projekt-ID (Standard: `projectId` in `docs.json`) |

  <Card title="Mit KI korrigieren" icon="wand-magic-sparkles" href="/de/builds/fix-with-ai#ablauf-wählen">
    Was jeder Modus bewirkt und wie du eine automatische Korrektur rückgängig machst
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Prüfe deine Dokumentation auf Rechtschreibfehler.

  ```bash
  jamdesk spellcheck
  ```

  **Beispielausgabe:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Verwendet ein englisches Wörterbuch mit über 150 integrierten Fachbegriffen (API, GraphQL, Kubernetes, React usw.). Überspringt Codeblöcke, Inline-Code, Frontmatter, JSX, URLs und Dateipfade. Derzeit nur Englisch. Mehrsprachige Wörterbücher sind geplant.

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--fix` | Rechtschreibfehler interaktiv korrigieren oder zur Ignorierliste hinzufügen |
  | `--json` | Ausgabe als JSON (für CI-Pipelines) |
  | `-v, --verbose` | Jede Datei anzeigen, während sie geprüft wird |

  **Interaktiver Korrekturmodus (`--fix`)** geht jedes eindeutige falsch geschriebene Wort durch:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** ersetzt das Wort in jeder Datei durch einen Vorschlag. Codeblöcke oder JSX-Attribute werden niemals verändert. Die Abfrage zeigt bis zu 3 Vorschläge und markiert den besten Treffer als empfohlen.
  - **Ignore** fügt das Wort zu `spellcheck.ignore` in deiner docs.json hinzu. Das Wort wird nicht mehr markiert.
  - **Skip** tut in diesem Durchlauf nichts

  Du siehst Änderungen in der Vorschau und bestätigst sie, bevor sie angewendet werden.

  **Eigene Ignorierliste:** Füge projektspezifische Begriffe zu deiner docs.json hinzu:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  Spellcheck ignoriert den Projektnamen aus `docs.json`.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Validiere eine einzelne OpenAPI-Spezifikationsdatei.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Validiert:**
  - Gültige YAML-/JSON-Syntax
  - OpenAPI-3.x-Schemakonformität
  - Endpunktdefinitionen
  - Korrekte Auflösung von `$ref`-Referenzen
</Accordion>

<Note>
  **Jamdesk validiert OpenAPI-Spezifikationen an drei Stellen.** `jamdesk dev` stoppt beim Start, wenn eine referenzierte Spezifikation ungültig ist. `jamdesk validate` und `jamdesk openapi-check` prüfen Spezifikationen bei Bedarf. Der Cloud-Build prüft referenzierte Spezifikationen beim Deployment, wo eine ungültige Spezifikation eine **nicht fatale Warnung** ist. Der Rest deiner Dokumentation wird weiterhin veröffentlicht. Die E-Mail und die Build-Liste im Dashboard benennen das Problem: einen Parse-Fehler mit Zeile und Spalte, ein nicht auflösbares `$ref` oder eine doppelte `operationId`. Behebe die Spezifikation und pushe erneut, um die Warnung zu entfernen.
</Note>

### Dateiverwaltung

<Accordion title="jamdesk rename" icon="file-pen">
  Benenne eine Seite um und aktualisiere alle Verweise darauf.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Dies wird:**
  - Die Datei umbenennen
  - Die docs.json-Navigation aktualisieren
  - Links in allen anderen MDX-Dateien aktualisieren
  - Snippet-Verweise aktualisieren

  Verwende dies statt manuellem Umbenennen. So bleiben Verweise synchron.
</Accordion>

### Migration

<Accordion title="jamdesk migrate" icon="right-left">
  Migriere Dokumentation von Mintlify zu Jamdesk.

  ```bash
  jamdesk migrate
  ```

  Erkennt deine Mintlify-Konfiguration und konvertiert sie in das Jamdesk-Format. Derselbe Durchlauf:

  - Benennt veraltete Komponenten um (z. B. `CardGroup` → `Columns`)
  - Verschiebt verwaiste Snippet-MDX-Dateien nach `/snippets/` und schreibt Importe mit relativen Elternpfaden um
  - Extrahiert Inline-Komponenten, die React-Hooks verwenden, nach `/snippets/<name>.tsx` mit `'use client'`
  - Behebt mechanische MDX-Syntaxprobleme

  Der Befehl ist idempotent. Ein erneutes Ausführen ist sicher.

### Bereitstellung

<Accordion title="jamdesk pull" icon="cloud-arrow-down">
  Lade ein Projekt herunter, dessen Dokumentation Jamdesk hostet (ohne GitHub), als Git-Repository oder führe neue Jamdesk-Änderungen in eine bereits gezogene Kopie zusammen.

  ```bash
  jamdesk pull
  jamdesk pull --project your-project
  jamdesk pull --dir ./docs-copy
  ```

  Bearbeite die Dateien und führe dann `jamdesk deploy` in diesem Ordner aus, um sie zu veröffentlichen. Benötigt CLI 1.1.227 oder neuer und Git.

  | Flag | Beschreibung |
  |------|-------------|
  | `--project <id-or-slug>` | Ein bestimmtes Projekt herunterladen (überspringt die interaktive Auswahl) |
  | `--dir <path>` | Zielordner (Standard: `./<slug>`) |
  | `--force` | Einen Ordner mit vorhandenen Dateien, etwa eine alte schreibgeschützte Kopie, in eine Git-Kopie umwandeln. Seine Dateien bleiben als nicht committete Änderungen erhalten |

  <Card title="Auf deinem Computer bearbeiten" icon="laptop" href="/de/setup/without-github#auf-deinem-computer-bearbeiten">
    Veröffentlichung, Zusammenführen von Jamdesk-Änderungen, Konflikte und Dateien, die deploy ablehnt
  </Card>
</Accordion>

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Lade deine Dokumentation hoch und starte einen Build über das Terminal.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  Die CLI zeigt jede Build-Phase an, sobald sie abgeschlossen ist. Auch verfügbar als `jamdesk push`.

  | Flag | Beschreibung |
  |------|-------------|
  | `--detach` | In die Warteschlange stellen und sofort beenden |
  | `--full-rebuild` | Vollständigen Neuaufbau erzwingen (ohne Cache) |
  | `--project <id>` | Auf ein bestimmtes Projekt bereitstellen |
  | `--allow-empty` | Bereitstellung mit null `.mdx`-Inhaltsseiten erlauben (standardmäßig abgelehnt) |
  | `-m, --message <text>` | Commit-Nachricht in einem Ordner, der mit `jamdesk pull` erstellt wurde |
  | `--allow-secret-files` | Dateien, die nach Geheimnissen aussehen, aus einem mit `jamdesk pull` erstellten Ordner veröffentlichen |

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  Erstelle und deploye einen Cloudflare Worker, der `/docs` auf deiner eigenen Domain an deine Jamdesk-Website weiterleitet.

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --yes
  ```

  Der Befehl ist standardmäßig interaktiv. Er prüft Wrangler, verifiziert dein Cloudflare-Konto, erkennt deinen Slug aus `docs.json`, generiert die Worker-Dateien und bietet an, sie direkt zu deployen. `--yes` generiert die Dateien und stoppt dann. Deploye sie mit `npx wrangler deploy` aus dem Ausgabeverzeichnis.

  | Flag | Beschreibung |
  |------|-------------|
  | `--slug <slug>` | Jamdesk-Projekt-Slug |
  | `--domain <domain>` | Zieldomain (z. B. `example.com`) |
  | `--path <path>` | Pfadpräfix (Standard: `/docs`) |
  | `--output-dir <dir>` | Ausgabeverzeichnis (Standard: `cloudflare-worker/`) |
  | `--skip-deploy` | Die Abfrage „jetzt deployen?“ bei einem interaktiven Lauf überspringen |
  | `--force` | Das Ausgabeverzeichnis überschreiben, falls es bereits existiert |
  | `--yes` | Jede Abfrage mit ihrem Standardwert beantworten (CI-Modus). Deployt nie und überschreibt niemals ein bestehendes Verzeichnis |

### Wartung

<Accordion title="jamdesk doctor" icon="stethoscope">
  Prüfe deine Umgebung und diagnostiziere Probleme.

  ```bash
  jamdesk doctor
  ```

  **Prüft:**
  - Node.js-Version (erfordert 22.18+ oder 24.11+)
  - Das Node.js, das in deinem PATH zuerst steht und von `jamdesk dev` verwendet wird
  - npm-Version
  - docs.json existiert und ist gültig
  - Status des ~/.jamdesk-Caches
  - Schreibberechtigungen

  Führe dies aus, wenn die CLI sich falsch verhält.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Leere das Cache-Verzeichnis ~/.jamdesk.

  ```bash
  jamdesk clean
  ```

  Dies entfernt zwischengespeicherte Abhängigkeiten und Build-Artefakte. Verwende es, um:
  - Speicherplatz freizugeben
  - Einen beschädigten Cache zu beheben
  - Eine frische Installation der Abhängigkeiten zu erzwingen

  Der nächste `jamdesk dev`-Aufruf installiert die Abhängigkeiten neu.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Aktualisiere die CLI auf die neueste Version.

  ```bash
  jamdesk update
  ```

  Du kannst auch manuell aktualisieren:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Konfiguration

Erstelle `~/.jamdeskrc`, um Standardoptionen festzulegen:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Option | Typ | Standard | Beschreibung |
|--------|------|---------|-------------|
| `defaultPort` | number | 3000 | Standardport für den Entwicklungsserver |
| `verbose` | boolean | false | Ausführliche Ausgabe standardmäßig aktivieren |
| `checkUpdates` | boolean | true | Beim Start nach CLI-Updates suchen |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="MDX-Syntaxfehler">
    MDX wird als JSX geparst. Einige Zeichen haben eine besondere Bedeutung.

    **Häufiges Problem:** Das Zeichen `<` wird als Beginn eines JSX-Tags interpretiert.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Lösungen:**
    - Verwende `&lt;` für ein wörtliches Kleiner-als: `Werte &lt;50% sind niedrig`
    - Formuliere es um, um das Zeichen zu vermeiden: `"Unter 50%"` statt `"<50%"`
    - Führe `jamdesk validate` aus, um detaillierte Fehlermeldungen mit Zeilennummern zu erhalten
  </Accordion>

  <Accordion title="docs.json nicht gefunden">
    Führe den Befehl in einem Verzeichnis mit einer `docs.json`-Datei aus.

    **Lösungen:**
    - Führe `jamdesk init` aus, um ein neues Projekt zu erstellen
    - Prüfe, ob du im richtigen Verzeichnis bist
    - Stelle sicher, dass die Datei exakt `docs.json` heißt (nicht `doc.json` oder ähnlich)
  </Accordion>

  <Accordion title="Entwicklungsserver startet nicht">
    **Versuche diese Schritte:**
    1. Führe `jamdesk doctor` aus, um deine Umgebung zu prüfen
    2. Führe `jamdesk clean` aus, um den Cache zu leeren
    3. Verwende `jamdesk dev --verbose` für detaillierte Fehlerausgaben
    4. Prüfe, ob Node.js 22.18+ oder 24.11+ installiert ist: `node --version`
  </Accordion>

  <Accordion title="Langsamer erster Start">
    Beim ersten Start werden Abhängigkeiten nach `~/.jamdesk/node_modules` installiert.

    Dies passiert nur einmal. Spätere Starts sind schneller.
  </Accordion>

  <Accordion title="Port bereits belegt">
    Ein anderer Prozess verwendet den Standardport.

    **Lösungen:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Berechtigungsfehler">
    Du hast möglicherweise keine Schreibrechte für das Cache-Verzeichnis.

    **Lösungen:**
    1. Prüfe die Berechtigungen von `~/.jamdesk`: `ls -la ~/.jamdesk`
    2. Korrigiere den Besitzer: `sudo chown -R $(whoami) ~/.jamdesk`
    3. Führe `jamdesk clean` aus und versuche es erneut
  </Accordion>
</AccordionGroup>
