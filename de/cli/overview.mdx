Mit der Jamdesk CLI kannst du Dokumentation lokal vorschauen, Konfiguration validieren, defekte Links prüfen und von anderen Plattformen migrieren. Sie ist Open Source unter der [Apache License 2.0](https://github.com/jamdesk/jamdesk-cli).

## Installation

<Tabs>
  <Tab title="npm (Empfohlen)">
    Global über [npm](https://www.npmjs.com/package/jamdesk) installieren, um `jamdesk` von überall zu nutzen:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Mit Homebrew installieren:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Über das Skript installieren:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Aktualisieren oder deinstallieren:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Über das Skript installieren:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Aktualisieren oder deinstallieren:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Ohne Installation ausführen:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Installation prüfen:

```bash
jamdesk --version
```

### Voraussetzungen

- **Node.js** v20.0.0 oder höher
- **npm** v8 oder höher (empfohlen)

## Schnellstart

<Steps>
  <Step title="Projekt erstellen">
    Ein neues Dokumentationsprojekt anlegen:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Entwicklungsserver starten">
    Den lokalen Entwicklungsserver mit Hot Reload starten:

    ```bash
    jamdesk dev
    ```

    Deine Dokumentation läuft unter **http://localhost:3000/docs**
  </Step>
  <Step title="Vor dem Deployment validieren">
    Auf Konfigurationsfehler, defekte Links und Rechtschreibung prüfen:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Befehle

Führe `jamdesk <command> --help` aus, um Details zu einem Befehl zu erhalten.

### Entwicklung

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Den lokalen Entwicklungsserver mit Hot Reload starten.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Funktionen:**
  - Automatische Validierung beim Start (docs.json-Schema, MDX-Syntax und referenzierte OpenAPI-Spezifikationen. Eine ungültige Spezifikation stoppt den Server.)
  - Hot Reload bei Änderungen an MDX-Dateien
  - Automatischer Neuaufbau der Navigation bei Änderungen an docs.json
  - Eigenes CSS (`style.css`) wird beim Neuladen des Browsers geladen
  - Suche
  - Alle Themes und Komponenten

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `-p, --port <port>` | Port für den Server (Standard: 3000) |
  | `-v, --verbose` | Ausführliche Ausgabe aktivieren |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Ein neues Dokumentationsprojekt anlegen.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Dies erstellt ein neues Projekt mit:
  - Konfigurationsdatei `docs.json`
  - Beispielseiten in MDX
  - Empfohlener Ordnerstruktur
</Accordion>

### Validierung

<Accordion title="jamdesk validate" icon="check">
  `docs.json`-Konfiguration, MDX-Syntax und OpenAPI-Spezifikationen validieren.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Prüft auf:**
  - Gültige JSON-Syntax in docs.json
  - Pflichtfelder (name, navigation)
  - Gültige Theme-Werte
  - MDX-Syntaxfehler (z. B. nicht maskierte `<`-Zeichen)
  - OpenAPI-Spezifikationsvalidierung (falls konfiguriert)
  - Schema-Konformität

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--skip-mdx` | MDX-Syntaxvalidierung überspringen |
  | `-v, --verbose` | Detaillierte Validierungsausgabe anzeigen |

  Vor dem Deployment ausführen, um Fehler frühzeitig zu erkennen.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Die Dokumentation auf defekte interne Links prüfen.

  ```bash
  jamdesk broken-links
  ```

  **Beispielausgabe:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Erkennt Links zu fehlenden Seiten und Tippfehler. Details unter [Links & Navigation](/de/content/links#erkennung-interner-links).
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Warnungen zu defekten internen Links mit eindeutigem Ziel automatisch beheben. Es werden zwei Arten behoben:
  - **Fehlerhafte Anker**: ein Fragment wie `#instalation`, das eindeutig `#installation` sein soll
  - **Anker-Abweichung bei Übersetzungen**: Eine übersetzte Seite hat ihre Überschriften umbenannt, Links in dieser Sprache verweisen aber noch auf das alte englische Fragment

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **Beispielausgabe der Vorschau:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  `jamdesk fix` schreibt eine Korrektur nur, wenn der korrigierte Anker auf eine tatsächlich vorhandene Überschrift der Zielseite verweist. Mehrdeutige Fälle werden zur manuellen Prüfung belassen.

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--dry-run` | Geplante Korrekturen anzeigen, ohne Dateien zu schreiben |
  | `-y, --yes` | Korrekturen ohne Bestätigungsabfrage anwenden |
  | `--types <list>` | Kommagetrennte Warntypen, die behoben werden sollen (Standard: alle unterstützten) |
  | `--no-ai` | KI-Korrekturen überspringen und nur Korrekturen ohne KI verwenden |
  | `--project <id>` | Projekt-ID für KI-Korrekturen (Standard: `projectId` in `docs.json`) |
  | `--json` | Korrekturplan und nicht behebbare Probleme als JSON für einen KI-Agenten ausgeben. Schreibt keine Dateien und fragt nicht nach. Erfordert CLI 1.1.229 oder neuer |

  <Card title="Leitfaden zur Behebung defekter Links" icon="wrench" href="/de/cli/fix-broken-links">
    Schritt-für-Schritt-Anleitung: Vorschau, Anwenden, Prüfen und Committen
  </Card>
</Accordion>

<Accordion title="jamdesk ai-fix" icon="wand-magic-sparkles">
  Die Einstellung **AI Fixes** des Projekts anzeigen oder ändern, dieselbe wie in den Einstellungen des Dashboards.

  ```bash
  # Show the current setting
  jamdesk ai-fix

  # Commit fixes to your build branch after each build
  jamdesk ai-fix auto

  # Suggest fixes for you to review in the dashboard
  jamdesk ai-fix review

  # Turn off dashboard scans
  jamdesk ai-fix off
  ```

  **Beispielausgabe:**
  ```text
  ✓ AI Fixes set to Auto-fix
  Jamdesk commits fixes to main after the next build. Pull before you push. Undo runs from the dashboard.
  ```

  Führe zuerst `jamdesk login` aus. Der Befehl verwendet die `projectId` in `docs.json` oder das Projekt, das du mit `--project` angibst. Erfordert CLI 1.1.229 oder neuer.

  | Flag | Beschreibung |
  |------|-------------|
  | `--project <id>` | Projekt-ID (Standard: `projectId` in `docs.json`) |

  <Card title="Mit KI korrigieren" icon="wand-magic-sparkles" href="/de/builds/fix-with-ai#ablauf-wählen">
    Was jeder Modus bewirkt und wie du eine automatische Korrektur rückgängig machst
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Die Dokumentation auf Rechtschreibfehler prüfen.

  ```bash
  jamdesk spellcheck
  ```

  **Beispielausgabe:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Verwendet ein englisches Wörterbuch mit über 150 integrierten Fachbegriffen (API, GraphQL, Kubernetes, React usw.). Überspringt Codeblöcke, Inline-Code, Frontmatter, JSX, URLs und Dateipfade. Derzeit nur Englisch. Mehrsprachige Wörterbücher sind geplant.

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--fix` | Rechtschreibfehler interaktiv korrigieren oder zur Ignorierliste hinzufügen |
  | `--json` | Ausgabe als JSON (für CI-Pipelines) |
  | `-v, --verbose` | Jede geprüfte Datei anzeigen |

  **Interaktiver Korrekturmodus (`--fix`)** geht jedes eindeutige falsch geschriebene Wort durch:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** ersetzt das Wort in allen Dateien durch einen Vorschlag. Codeblöcke und JSX-Attribute werden nie verändert. Die Abfrage zeigt bis zu 3 Vorschläge und markiert den besten Treffer als empfohlen.
  - **Ignore** fügt das Wort unter `spellcheck.ignore` in deiner docs.json hinzu. Es wird nicht erneut markiert.
  - **Skip** tut in diesem Durchlauf nichts

  Änderungen werden vor dem Übernehmen angezeigt und müssen bestätigt werden.

  **Eigene Ignorierliste:** Projektspezifische Begriffe in docs.json hinzufügen:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  Spellcheck ignoriert den Projektnamen aus `docs.json`.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Eine einzelne OpenAPI-Spezifikationsdatei validieren.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Validiert:**
  - Gültige YAML/JSON-Syntax
  - Konformität mit OpenAPI 3.x-Schema
  - Endpunktdefinitionen
  - `$ref`-Referenzen werden korrekt aufgelöst
</Accordion>

<Note>
  **Jamdesk validiert OpenAPI-Spezifikationen an drei Stellen.** `jamdesk dev` bricht beim Start ab, wenn eine referenzierte Spezifikation ungültig ist. `jamdesk validate` und `jamdesk openapi-check` prüfen Spezifikationen auf Anforderung. Der Cloud-Build prüft referenzierte Spezifikationen beim Deployment, wobei eine ungültige Spezifikation eine **nicht fatale Warnung** ist. Der Rest deiner Dokumentation wird weiterhin veröffentlicht. Die E-Mail und die Build-Liste im Dashboard benennen das Problem: einen Parse-Fehler mit Zeile und Spalte, eine nicht aufgelöste `$ref` oder eine doppelte `operationId`. Korrigiere die Spezifikation und pushe erneut, um die Warnung zu beheben.
</Note>

### Dateiverwaltung

<Accordion title="jamdesk rename" icon="file-pen">
  Eine Seite umbenennen und alle Verweise darauf aktualisieren.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Dabei wird:**
  - die Datei umbenannt
  - die Navigation in docs.json aktualisiert
  - die Links in allen anderen MDX-Dateien aktualisiert
  - die Snippet-Verweise aktualisiert

  Verwende dies statt manuellem Umbenennen. Verweise bleiben so synchron.
</Accordion>

### Migration

<Accordion title="jamdesk migrate" icon="right-left">
  Dokumentation von Mintlify zu Jamdesk migrieren.

  ```bash
  jamdesk migrate
  ```

  Erkennt deine Mintlify-Konfiguration und konvertiert sie in das Jamdesk-Format. Der gleiche Durchlauf:

  - Benennt veraltete Komponenten um (z. B. `CardGroup` → `Columns`)
  - Verschiebt verwaiste Snippet-MDX-Dateien nach `/snippets/` und schreibt eltern-relative Importe um
  - Extrahiert Inline-Komponenten, die React-Hooks verwenden, nach `/snippets/<name>.tsx` mit `'use client'`
  - Behebt mechanische MDX-Syntaxprobleme

  Der Befehl ist idempotent. Ein erneuter Aufruf ist unbedenklich.

### Deployment

<Accordion title="jamdesk pull" icon="cloud-arrow-down">
  Ein Projekt herunterladen, dessen Dokumentation Jamdesk hostet (ohne GitHub), als Git-Repository, oder neue Jamdesk-Änderungen in eine bereits gezogene Kopie zusammenführen.

  ```bash
  jamdesk pull
  jamdesk pull --project your-project
  jamdesk pull --dir ./docs-copy
  ```

  Bearbeite die Dateien und führe dann `jamdesk deploy` in diesem Ordner aus, um sie zu veröffentlichen. Erfordert CLI 1.1.227 oder neuer und Git.

  | Flag | Beschreibung |
  |------|-------------|
  | `--project <id-or-slug>` | Ein bestimmtes Projekt ziehen (überspringt die interaktive Auswahl) |
  | `--dir <path>` | Zielordner (Standard: `./<slug>`) |
  | `--force` | Einen Ordner mit bereits vorhandenen Dateien, etwa eine alte schreibgeschützte Kopie, in eine Git-Kopie umwandeln. Seine Dateien bleiben als nicht committete Änderungen erhalten |

  <Card title="Auf deinem Computer bearbeiten" icon="laptop" href="/de/setup/without-github#auf-deinem-computer-bearbeiten">
    Veröffentlichung, Zusammenführen von Jamdesk-Änderungen, Konflikte und Dateien, die deploy ablehnt
  </Card>
</Accordion>

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Deine Dokumentation hochladen und einen Build aus dem Terminal starten.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  Die CLI zeigt jede Build-Phase an, sobald sie abgeschlossen ist. Auch als `jamdesk push` verfügbar.

  | Flag | Beschreibung |
  |------|-------------|
  | `--detach` | In die Warteschlange einreihen und sofort beenden |
  | `--full-rebuild` | Vollständigen Neuaufbau erzwingen (ohne Cache) |
  | `--project <id>` | Auf ein bestimmtes Projekt deployen |
  | `--allow-empty` | Deployment mit null `.mdx`-Inhaltsseiten erlauben (standardmäßig abgelehnt) |
  | `-m, --message <text>` | Commit-Nachricht in einem mit `jamdesk pull` erstellten Ordner |
  | `--allow-secret-files` | Geheim aussehende Dateien aus einem mit `jamdesk pull` erstellten Ordner veröffentlichen |

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  Einen Cloudflare Worker erstellen und bereitstellen, der `/docs` auf deiner eigenen Domain an deine Jamdesk-Website weiterleitet.

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --yes
  ```

  Der Befehl ist standardmäßig interaktiv. Er prüft Wrangler, verifiziert dein Cloudflare-Konto, erkennt deinen Slug aus `docs.json`, generiert die Worker-Dateien und bietet an, sie bereitzustellen. `--yes` generiert nur die Dateien und stoppt dann. Stelle sie anschließend mit `npx wrangler deploy` aus dem Ausgabeverzeichnis bereit.

  | Flag | Beschreibung |
  |------|-------------|
  | `--slug <slug>` | Jamdesk-Projekt-Slug |
  | `--domain <domain>` | Zieldomain (z. B. `example.com`) |
  | `--path <path>` | Pfadpräfix (Standard: `/docs`) |
  | `--output-dir <dir>` | Ausgabeverzeichnis (Standard: `cloudflare-worker/`) |
  | `--skip-deploy` | Die Abfrage „jetzt bereitstellen?“ in einem interaktiven Lauf überspringen |
  | `--force` | Das Ausgabeverzeichnis überschreiben, falls es bereits existiert |
  | `--yes` | Jede Abfrage mit ihrem Standardwert beantworten (CI-Modus). Stellt nie bereit und überschreibt nie ein bestehendes Verzeichnis |

</Accordion>

### Wartung

<Accordion title="jamdesk doctor" icon="stethoscope">
  Deine Umgebung prüfen und Probleme diagnostizieren.

  ```bash
  jamdesk doctor
  ```

  **Prüft:**
  - Node.js-Version (erfordert v20+)
  - npm-Version
  - docs.json existiert und ist gültig
  - Status des ~/.jamdesk-Caches
  - Schreibrechte

  Führe dies aus, wenn sich die CLI fehlerhaft verhält.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Das Cache-Verzeichnis ~/.jamdesk leeren.

  ```bash
  jamdesk clean
  ```

  Dies entfernt zwischengespeicherte Abhängigkeiten und Build-Artefakte. Verwende es, um:
  - Speicherplatz freizugeben
  - einen beschädigten Cache zu beheben
  - eine frische Installation der Abhängigkeiten zu erzwingen

  Das nächste `jamdesk dev` installiert die Abhängigkeiten erneut.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Die CLI auf die neueste Version aktualisieren.

  ```bash
  jamdesk update
  ```

  Du kannst auch manuell aktualisieren:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Konfiguration

Erstelle `~/.jamdeskrc`, um Standardoptionen festzulegen:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Option | Typ | Standard | Beschreibung |
|--------|------|---------|-------------|
| `defaultPort` | number | 3000 | Standardport für den Entwicklungsserver |
| `verbose` | boolean | false | Ausführliche Ausgabe standardmäßig aktivieren |
| `checkUpdates` | boolean | true | Beim Start nach CLI-Updates suchen |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="MDX-Syntaxfehler">
    MDX wird als JSX geparst. Einige Zeichen haben eine besondere Bedeutung.

    **Häufiges Problem:** Das Zeichen `<` wird als Beginn eines JSX-Tags interpretiert.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Lösungen:**
    - Für ein wörtliches Kleiner-als `&lt;` verwenden: `Werte &lt;50 % sind niedrig`
    - Umformulieren, um das Zeichen zu vermeiden: `"Unter 50 %"` statt `"<50 %"`
    - `jamdesk validate` ausführen, um detaillierte Fehlermeldungen mit Zeilennummern zu erhalten
  </Accordion>

  <Accordion title="docs.json nicht gefunden">
    Führe den Befehl aus einem Verzeichnis mit einer `docs.json`-Datei aus.

    **Lösungen:**
    - `jamdesk init` ausführen, um ein neues Projekt zu erstellen
    - Prüfen, ob du im richtigen Verzeichnis bist
    - Prüfen, ob die Datei exakt `docs.json` heißt (nicht `doc.json` oder ähnlich)
  </Accordion>

  <Accordion title="Entwicklungsserver startet nicht">
    **Probiere diese Schritte:**
    1. `jamdesk doctor` ausführen, um deine Umgebung zu prüfen
    2. `jamdesk clean` ausführen, um den Cache zu leeren
    3. `jamdesk dev --verbose` für detaillierte Fehlerausgabe verwenden
    4. Prüfen, ob Node.js v20+ installiert ist: `node --version`
  </Accordion>

  <Accordion title="Langsamer erster Start">
    Beim ersten Start werden die Abhängigkeiten nach `~/.jamdesk/node_modules` installiert.

    Das passiert nur einmal. Spätere Starts sind schneller.
  </Accordion>

  <Accordion title="Port bereits belegt">
    Ein anderer Prozess verwendet den Standardport.

    **Lösungen:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Berechtigungsfehler">
    Du hast möglicherweise keine Schreibrechte im Cache-Verzeichnis.

    **Lösungen:**
    1. Berechtigungen für `~/.jamdesk` prüfen: `ls -la ~/.jamdesk`
    2. Eigentümer korrigieren: `sudo chown -R $(whoami) ~/.jamdesk`
    3. `jamdesk clean` ausführen und es erneut versuchen
  </Accordion>
</AccordionGroup>
