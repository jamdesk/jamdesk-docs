Mit der Jamdesk-CLI kannst du Dokumentation lokal in der Vorschau anzeigen, Konfiguration validieren, auf defekte Links prüfen und von anderen Plattformen migrieren. Sie ist Open Source unter der [Apache License 2.0](https://github.com/jamdesk/jamdesk-cli).

## Installation

<Tabs>
  <Tab title="npm (empfohlen)">
    Global über [npm](https://www.npmjs.com/package/jamdesk) installieren, um `jamdesk` von überall aus zu verwenden:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Mit Homebrew installieren:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Über das Skript installieren:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Aktualisieren oder deinstallieren:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Über das Skript installieren:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Aktualisieren oder deinstallieren:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Ohne Installation ausführen:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Installation überprüfen:

```bash
jamdesk --version
```

### Voraussetzungen

- **Node.js** v20.0.0 oder höher
- **npm** v8 oder höher (empfohlen)

## Schnellstart

<Steps>
  <Step title="Projekt erstellen">
    Ein neues Dokumentationsprojekt erstellen:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Entwicklungsserver starten">
    Den lokalen Entwicklungsserver mit Hot Reload starten:

    ```bash
    jamdesk dev
    ```

    Deine Dokumentation läuft unter **http://localhost:3000/docs**
  </Step>
  <Step title="Vor der Bereitstellung validieren">
    Auf Konfigurationsfehler, defekte Links und Rechtschreibung prüfen:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Befehle

Führe `jamdesk <command> --help` aus, um Details zu einem Befehl zu sehen.

### Entwicklung

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Den lokalen Entwicklungsserver mit Hot Reload starten.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Funktionen:**
  - Automatische Validierung beim Start (docs.json-Schema, MDX-Syntax und referenzierte OpenAPI-Spezifikationen. Eine ungültige Spezifikation stoppt den Server.)
  - Hot Reload bei Änderungen an MDX-Dateien
  - Automatische Neuerstellung der Navigation bei Änderungen an docs.json
  - Eigenes CSS (`style.css`) wird beim Neuladen des Browsers geladen
  - Suche
  - Alle Designs und Komponenten

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `-p, --port <port>` | Port, auf dem ausgeführt wird (Standard: 3000) |
  | `-v, --verbose` | Ausführliche Ausgabe aktivieren |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Ein neues Dokumentationsprojekt erstellen.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Dadurch wird ein neues Projekt mit folgenden Elementen erstellt:
  - Konfigurationsdatei `docs.json`
  - Beispielhafte MDX-Seiten
  - Empfohlene Ordnerstruktur
</Accordion>

### Validierung

<Accordion title="jamdesk validate" icon="check">
  `docs.json`-Konfiguration, MDX-Syntax und OpenAPI-Spezifikationen validieren.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Prüft auf:**
  - Gültige JSON-Syntax in docs.json
  - Erforderliche Felder (name, navigation)
  - Gültige Designwerte
  - MDX-Syntaxfehler (z. B. nicht maskierte `<`-Zeichen)
  - OpenAPI-Spezifikationsvalidierung (falls konfiguriert)
  - Schema-Konformität

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--skip-mdx` | MDX-Syntaxvalidierung überspringen |
  | `-v, --verbose` | Detaillierte Validierungsausgabe anzeigen |

  Vor der Bereitstellung ausführen, um Fehler frühzeitig zu erkennen.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Die Dokumentation auf defekte interne Links prüfen.

  ```bash
  jamdesk broken-links
  ```

  **Beispielausgabe:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Erkennt Links zu fehlenden Seiten und Tippfehler. Details finden sich unter [Links & Navigation](/de/content/links#erkennung-interner-links).
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Warnungen zu defekten internen Links automatisch beheben, wenn das Ziel eindeutig ist. Es werden zwei Arten behoben:
  - **Fehlerhafte Anker**: ein Fragment wie `#instalation`, das eindeutig `#installation` sein soll
  - **Anker-Abweichung zwischen Sprachversionen**: Eine übersetzte Seite hat ihre Überschriften umbenannt, aber Links in dieser Sprachversion zeigen noch auf das alte englische Fragment

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **Beispielausgabe der Vorschau:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  `jamdesk fix` schreibt eine Korrektur nur, wenn der korrigierte Anker auf eine echte Überschrift auf der Zielseite verweist. Mehrdeutige Fälle bleiben zur manuellen Prüfung.

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--dry-run` | Geplante Korrekturen anzeigen, ohne Dateien zu schreiben |
  | `-y, --yes` | Korrekturen ohne Bestätigungsabfrage anwenden |
  | `--types <list>` | Kommagetrennte Warnungstypen, die behoben werden sollen (Standard: alle unterstützten) |

  <Card title="Leitfaden: Defekte Links beheben" icon="wrench" href="/de/cli/fix-broken-links">
    Schritt-für-Schritt-Anleitung: Vorschau, Anwendung, Prüfung und Commit
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Die Dokumentation auf Rechtschreibfehler prüfen.

  ```bash
  jamdesk spellcheck
  ```

  **Beispielausgabe:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Verwendet ein englisches Wörterbuch mit über 150 integrierten Fachbegriffen (API, GraphQL, Kubernetes, React usw.). Überspringt Codeblöcke, Inline-Code, Frontmatter, JSX, URLs und Dateipfade. Derzeit nur Englisch. Mehrsprachige Wörterbücher sind geplant.

  **Optionen:**

  | Flag | Beschreibung |
  |------|-------------|
  | `--fix` | Rechtschreibfehler interaktiv korrigieren oder zur Ignorierliste hinzufügen |
  | `--json` | Ausgabe als JSON (für CI-Pipelines) |
  | `-v, --verbose` | Jede geprüfte Datei anzeigen |

  **Interaktiver Korrekturmodus (`--fix`)** geht jedes eindeutige falsch geschriebene Wort durch:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** ersetzt das Wort in allen Dateien durch einen Vorschlag. Codeblöcke und JSX-Attribute werden nie verändert. Die Abfrage zeigt bis zu 3 Vorschläge und markiert die beste Übereinstimmung als empfohlen.
  - **Ignore** fügt das Wort zu `spellcheck.ignore` in deiner docs.json hinzu. Das Wort wird nicht erneut markiert.
  - **Skip** tut in diesem Durchlauf nichts

  Änderungen werden vor dem Übernehmen in der Vorschau angezeigt und müssen bestätigt werden.

  **Eigene Ignorierliste:** Projektspezifische Begriffe in docs.json hinzufügen:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  Spellcheck ignoriert deinen Projektnamen aus `docs.json`.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Eine einzelne OpenAPI-Spezifikationsdatei validieren.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Validiert:**
  - Gültige YAML-/JSON-Syntax
  - Konformität mit OpenAPI 3.x-Schema
  - Endpunktdefinitionen
  - `$ref`-Referenzen werden korrekt aufgelöst
</Accordion>

<Note>
  **Jamdesk validiert OpenAPI-Spezifikationen an drei Stellen.** `jamdesk dev` stoppt beim Start, wenn eine referenzierte Spezifikation ungültig ist. `jamdesk validate` und `jamdesk openapi-check` prüfen Spezifikationen auf Anfrage. Der Cloud-Build prüft referenzierte Spezifikationen beim Deploy. Dort ist eine ungültige Spezifikation eine **nicht fatale Warnung**. Der Rest deiner Dokumentation wird weiterhin veröffentlicht. Die E-Mail und die Build-Liste im Dashboard benennen das Problem: ein Parsing-Fehler mit Zeile und Spalte, ein nicht auflösbares `$ref` oder eine doppelte `operationId`. Behebe die Spezifikation und pushe erneut, um die Warnung zu beseitigen.
</Note>

### Dateiverwaltung

<Accordion title="jamdesk rename" icon="file-pen">
  Eine Seite umbenennen und alle Verweise darauf aktualisieren.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Dabei wird:**
  - die Datei umbenannt
  - die docs.json-Navigation aktualisiert
  - Links in allen anderen MDX-Dateien aktualisiert
  - Verweise auf Snippets aktualisiert

  Verwende diesen Befehl statt manuellem Umbenennen. So bleiben Verweise synchron.
</Accordion>

### Migration

<Accordion title="jamdesk migrate" icon="right-left">
  Dokumentation von Mintlify zu Jamdesk migrieren.

  ```bash
  jamdesk migrate
  ```

  Erkennt deine Mintlify-Konfiguration und konvertiert sie in das Jamdesk-Format. Der gleiche Durchlauf:

  - Benennt veraltete Komponenten um (z. B. `CardGroup` → `Columns`)
  - Verschiebt verwaiste Snippet-MDX-Dateien nach `/snippets/` und schreibt relative Importe um
  - Extrahiert Inline-Komponenten, die React-Hooks verwenden, nach `/snippets/<name>.tsx` mit `'use client'`
  - Behebt mechanische MDX-Syntaxprobleme

  Der Befehl ist idempotent. Ein erneuter Aufruf ist unbedenklich.

### Bereitstellung

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Deine Dokumentation hochladen und über das Terminal einen Build starten.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  Die CLI zeigt jede Build-Phase an, sobald sie abgeschlossen ist. Auch verfügbar als `jamdesk push`.

  | Flag | Beschreibung |
  |------|-------------|
  | `--detach` | In die Warteschlange stellen und sofort beenden |
  | `--full-rebuild` | Vollständigen Neuaufbau erzwingen (ohne Cache) |
  | `--project <id>` | Auf ein bestimmtes Projekt bereitstellen |
  | `--allow-empty` | Bereitstellung mit null `.mdx`-Inhaltsseiten erlauben (standardmäßig abgelehnt) |

  <Card title="CLI-Bereitstellungsleitfaden" icon="cloud-arrow-up" href="/de/cli/deploy">
    Vollständige Bereitstellungspipeline, Build-Phasen, Fehlerreferenz und Fehlerbehebung
  </Card>
</Accordion>

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  Einen Cloudflare Worker einrichten und bereitstellen, der `/docs` auf deiner eigenen Domain an deine Jamdesk-Website weiterleitet.

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --yes
  ```

  Der Befehl ist standardmäßig interaktiv. Er prüft Wrangler, verifiziert dein Cloudflare-Konto, erkennt deinen Slug aus `docs.json`, generiert die Worker-Dateien und bietet die Bereitstellung an. `--yes` generiert nur die Dateien und stoppt dann. Stelle sie mit `npx wrangler deploy` aus dem Ausgabeverzeichnis bereit.

  | Flag | Beschreibung |
  |------|-------------|
  | `--slug <slug>` | Jamdesk-Projekt-Slug |
  | `--domain <domain>` | Zieldomain (z. B. `example.com`) |
  | `--path <path>` | Pfadpräfix (Standard: `/docs`) |
  | `--output-dir <dir>` | Ausgabeverzeichnis (Standard: `cloudflare-worker/`) |
  | `--skip-deploy` | Die Abfrage „Jetzt bereitstellen?" in einem interaktiven Lauf überspringen |
  | `--force` | Das Ausgabeverzeichnis überschreiben, falls es bereits existiert |
  | `--yes` | Jede Abfrage mit ihrem Standardwert beantworten (CI-Modus). Stellt nie bereit und überschreibt nie ein bestehendes Verzeichnis |

  </Card>
</Accordion>

### Wartung

<Accordion title="jamdesk doctor" icon="stethoscope">
  Deine Umgebung prüfen und Probleme diagnostizieren.

  ```bash
  jamdesk doctor
  ```

  **Prüfungen:**
  - Node.js-Version (erfordert v20+)
  - npm-Version
  - docs.json existiert und ist gültig
  - Status des ~/.jamdesk-Caches
  - Schreibberechtigungen

  Ausführen, wenn sich die CLI unerwartet verhält.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Das Cache-Verzeichnis ~/.jamdesk leeren.

  ```bash
  jamdesk clean
  ```

  Dadurch werden zwischengespeicherte Abhängigkeiten und Build-Artefakte entfernt. Verwende den Befehl, um:
  - Speicherplatz freizugeben
  - einen beschädigten Cache zu reparieren
  - eine frische Installation der Abhängigkeiten zu erzwingen

  Das nächste `jamdesk dev` installiert die Abhängigkeiten neu.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Die CLI auf die neueste Version aktualisieren.

  ```bash
  jamdesk update
  ```

  Du kannst auch manuell aktualisieren:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Konfiguration

Erstelle `~/.jamdeskrc`, um Standardoptionen festzulegen:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Option | Typ | Standard | Beschreibung |
|--------|------|---------|-------------|
| `defaultPort` | number | 3000 | Standardport für den Entwicklungsserver |
| `verbose` | boolean | false | Ausführliche Ausgabe standardmäßig aktivieren |
| `checkUpdates` | boolean | true | Beim Start nach CLI-Updates suchen |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="MDX-Syntaxfehler">
    MDX wird als JSX geparst. Manche Zeichen haben eine besondere Bedeutung.

    **Häufiges Problem:** Das Zeichen `<` wird als Beginn eines JSX-Tags interpretiert.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Lösungen:**
    - `&lt;` für ein wörtliches Kleiner-als-Zeichen verwenden: `Values &lt;50% are low`
    - Umformulieren, um das Zeichen zu vermeiden: `"Below 50%"` statt `"<50%"`
    - `jamdesk validate` ausführen, um detaillierte Fehlermeldungen mit Zeilennummern zu erhalten
  </Accordion>

  <Accordion title="docs.json nicht gefunden">
    Führe den Befehl aus einem Verzeichnis mit einer Datei `docs.json` aus.

    **Lösungen:**
    - `jamdesk init` ausführen, um ein neues Projekt zu erstellen
    - Prüfen, ob du im richtigen Verzeichnis bist
    - Prüfen, ob die Datei genau `docs.json` heißt (nicht `doc.json` oder ähnlich)
  </Accordion>

  <Accordion title="Entwicklungsserver startet nicht">
    **Probiere diese Schritte:**
    1. `jamdesk doctor` ausführen, um deine Umgebung zu prüfen
    2. `jamdesk clean` ausführen, um den Cache zu leeren
    3. `jamdesk dev --verbose` für detaillierte Fehlerausgaben verwenden
    4. Prüfen, ob Node.js v20+ installiert ist: `node --version`
  </Accordion>

  <Accordion title="Langsamer erster Start">
    Beim ersten Start werden die Abhängigkeiten nach `~/.jamdesk/node_modules` installiert.

    Das geschieht nur einmal. Spätere Starts sind schneller.
  </Accordion>

  <Accordion title="Port bereits belegt">
    Ein anderer Prozess verwendet den Standardport.

    **Lösungen:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Berechtigungsfehler">
    Du hast möglicherweise keine Schreibberechtigung für das Cache-Verzeichnis.

    **Lösungen:**
    1. Berechtigungen für `~/.jamdesk` prüfen: `ls -la ~/.jamdesk`
    2. Besitzer korrigieren: `sudo chown -R $(whoami) ~/.jamdesk`
    3. `jamdesk clean` ausführen und es erneut versuchen
  </Accordion>
</AccordionGroup>
