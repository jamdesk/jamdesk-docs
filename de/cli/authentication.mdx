Die CLI meldet dich über den Browser bei deinem Jamdesk-Konto an. Melde dich an, bevor du bereitstellst.

## Anmeldung

```bash
jamdesk login
```

Dies öffnet das Jamdesk-Dashboard in deinem Browser. Der Ablauf:

1. Die CLI startet einen lokalen HTTP-Server auf `127.0.0.1:9876` (weicht auf einen vom Betriebssystem zugewiesenen Port aus, falls 9876 belegt ist)
2. Dein Browser öffnet `dashboard.jamdesk.com/cli-auth`
3. Du authentifizierst dich mit einer beliebigen Anmeldemethode des Dashboards (E-Mail/Passwort, Google, GitHub)
4. Das Dashboard sendet deine Zugangsdaten an den lokalen Server der CLI zurück
5. Zugangsdaten werden in `~/.jamdeskrc` gespeichert

Die CLI prüft beim Callback einen State-Parameter, um Cross-Site-Request-Forgery zu verhindern. Der Login-Ablauf läuft nach 2 Minuten ab.

```bash Expected output
$ jamdesk login
ℹ Open this URL in your browser to log in:

  https://dashboard.jamdesk.com/cli-auth?port=9876&state=abc123...

ℹ Waiting for authentication...
✔ Logged in as you@example.com
```

**Headless- und SSH-Umgebungen**: Die CLI gibt die URL immer im Terminal aus, auch wenn sie keinen Browser öffnen kann. Füge die URL in einen beliebigen Browser ein.

## Abmelden

```bash
jamdesk logout
```

Entfernt gespeicherte Zugangsdaten aus `~/.jamdeskrc`. Ohne aktive Anmeldung passiert nichts.

```bash Expected output
$ jamdesk logout
✔ Logged out (you@example.com)
```

## Whoami

```bash
jamdesk whoami
```

Zeigt deine angemeldete E-Mail-Adresse. Dabei wird das Token erneuert, um die Sitzung zu validieren. Es wird nie ein lokaler Cache gelesen.

Mögliche Zustände:

<CodeGroup>
```bash Logged in
$ jamdesk whoami
✔ Logged in as you@example.com
```

```bash Session expired
$ jamdesk whoami
⚠ Logged in as you@example.com (session expired)
  Run `jamdesk login` to re-authenticate.
```

```bash Not logged in
$ jamdesk whoami
ℹ Not logged in. Run `jamdesk login` to authenticate.
```
</CodeGroup>

## Funktionsweise von Sitzungen

Zugangsdaten werden in `~/.jamdeskrc` als JSON mit den Berechtigungen `0600` (nur Lesen/Schreiben für den Eigentümer) gespeichert:

```json ~/.jamdeskrc
{
  "auth": {
    "refreshToken": "AGK...",
    "email": "you@example.com",
    "uid": "abc123",
    "expiresAt": 1700000000000
  }
}
```

Die CLI verwendet eine Architektur aus **Refresh-Token + ID-Token**:

- **ID-Tokens** laufen nach etwa einer Stunde ab und werden für API-Aufrufe verwendet
- Die CLI **erneuert** ID-Tokens automatisch mit dem gespeicherten Refresh-Token 5 Minuten vor Ablauf
- Refresh-Tokens sind langlebig, können aber widerrufen werden (Passwortänderung, Kontolöschung)
- Die CLI entfernt gespeicherte Authentifizierungsdaten, wenn das Refresh-Token dauerhaft ungültig ist (`TOKEN_EXPIRED`, `USER_NOT_FOUND`, `INVALID_REFRESH_TOKEN`)

Die CLI erneuert Tokens bei jedem authentifizierten Befehl. Du musst sie nie manuell erneuern.

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Login times out after 2 minutes">
    Eine Firewall blockiert möglicherweise den lokalen Callback-Server der CLI. Kopiere die ausgegebene URL und öffne sie in deinem Browser.

    Die CLI wählt einen anderen Port, wenn ein anderer Prozess 9876 verwendet. Prüfe die URL in der Terminalausgabe.
  </Accordion>

  <Accordion title='"Session expired" on every command'>
    Dein Refresh-Token ist nicht mehr gültig. Das passiert nach Passwortänderungen oder längerer Inaktivität.

    Führe `jamdesk login` aus, um eine neue Sitzung zu erhalten.
  </Accordion>

  <Accordion title="Browser doesn't open">
    Headless-Umgebungen (SSH, Docker, CI) können keinen Browser öffnen. Kopiere die URL aus dem Terminal und öffne sie in einem beliebigen Browser, der den Callback-Port deines Rechners erreichen kann.
  </Accordion>

  <Accordion title='"Not logged in" right after logging in'>
    Prüfe, ob `~/.jamdeskrc` existiert und einen `auth`-Schlüssel enthält:

    ```bash
    cat ~/.jamdeskrc
    ```

    Die Dateiberechtigungen sollten `0600` sein. Eine fehlende Datei kann auf ein Berechtigungsproblem in deinem Home-Verzeichnis hinweisen. Prüfe es mit `ls -la ~`.
  </Accordion>
</AccordionGroup>

Weitere Hinweise zur CLI-Fehlerbehebung findest du im [CLI-Leitfaden des Help Centers](/de/help/troubleshooting/cli-issues).
