Mit Jamdesk können Sie eigenes JavaScript hinzufügen, das auf jeder Seite Ihrer Dokumentationswebsite ausgeführt wird. Verwenden Sie es für Chat-Widgets, Analytics oder andere clientseitige Skripts, die Sie benötigen.

## Benutzerdefiniertes JavaScript hinzufügen

Erstellen Sie eine JavaScript-Datei in Ihrem Dokumentationsverzeichnis und verweisen Sie in `docs.json` darauf:

```json docs.json
{
  "styling": {
    "js": "/script.js"
  }
}
```

```javascript script.js
// Your custom JavaScript runs on every page
console.log('Hello from custom JS!');
```

Ihr Skript wird direkt in den HTML-Code der Seite eingefügt und beim Laden der Seite ausgeführt.

## Automatische Erkennung

Wenn Sie `styling.js` nicht konfigurieren, erkennt Jamdesk automatisch `.js`-Dateien im Stammverzeichnis Ihres Projekts. Legen Sie einfach eine Datei namens `script.js` neben Ihrer `docs.json` ab, damit sie eingebunden wird.

```bash
my-docs/
├── docs.json
├── script.js      ← auto-detected
├── introduction.mdx
└── getting-started.mdx
```

Wenn `styling.js` in `docs.json` konfiguriert ist, wird die automatische Erkennung deaktiviert und es werden nur die angegebenen Dateien verwendet.

<Note>Die automatische Erkennung umfasst **alle** `.js`-Dateien im Stammverzeichnis Ihres Projekts. Wenn sich neben Ihren Dokumentationsdateien Hilfsskripte wie `eslint.config.js` oder `postcss.config.js` befinden, legen Sie mit `styling.js` in `docs.json` genau fest, welche Dateien eingebunden werden sollen.</Note>

## Mehrere Dateien

Binden Sie mehrere Skripts ein, indem Sie ein Array übergeben:

```json docs.json
{
  "styling": {
    "js": ["/chat.js", "/analytics.js"]
  }
}
```

Bei der automatischen Erkennung werden alle `.js`-Dateien im Stammverzeichnis alphabetisch sortiert eingebunden. Wenn Sie `analytics.js` und `chat.js` haben, werden sie in dieser Reihenfolge geladen.

## Beispiele

Eine ausführlichere Anleitung, die ein Skript mit CSS kombiniert, finden Sie unter [CSS- und JavaScript-Beispiele](/de/customization/custom-code-examples). Dabei werden eine schwebende Ask-AI-Schaltfläche und eine Kopfzeile in den Markenfarben hinzugefügt.

### Chat-Widget (Crisp)

```javascript script.js
window.$crisp = [];
window.CRISP_WEBSITE_ID = "your-website-id";
(function () {
  var d = document;
  var s = d.createElement("script");
  s.src = "https://client.crisp.chat/l.js";
  s.async = 1;
  d.getElementsByTagName("head")[0].appendChild(s);
})();
```

### Benutzerdefiniertes Analytics

```javascript script.js
// Track outbound link clicks
document.addEventListener('click', function (e) {
  var link = e.target.closest('a[href^="http"]');
  if (link && !link.href.includes(window.location.hostname)) {
    console.log('Outbound click:', link.href);
    // Send to your analytics service
  }
});
```

### Feedback-Widget

```javascript script.js
// Load a feedback widget after the page is ready
window.addEventListener('load', function () {
  var s = document.createElement('script');
  s.src = 'https://your-feedback-tool.com/widget.js';
  s.setAttribute('data-project', 'your-project-id');
  document.body.appendChild(s);
});
```

## Funktionsweise

Ihre JavaScript-Dateien werden während des Build-Prozesses eingelesen und direkt in den HTML-Code jeder Seite eingebettet. Das Script-Tag wird am Ende von `<body>` platziert, sodass das DOM verfügbar ist, wenn Ihr Code ausgeführt wird.

Eigenes JavaScript wird nur auf Ihrer veröffentlichten Website ausgeführt. `jamdesk dev` lässt es weg. Um ein Skript lokal auszuprobieren, fügen Sie es daher in der Browserkonsole der Vorschauseite ein.

Das Skript wird einmal ausgeführt, wenn ein Besucher Ihre Website zum ersten Mal lädt. Wenn Sie in der Dokumentation auf einen Link klicken, wird der Seiteninhalt ohne vollständiges Neuladen ausgetauscht. Das Skript wird dann nicht erneut ausgeführt. Wenn Ihr Code mit dem Seiteninhalt arbeitet, [reagieren Sie auf Seitenänderungen](/de/customization/custom-code-examples#code-nach-jedem-seitenwechsel-ausführen).

## Einschränkungen

- Skripts werden auf **jeder Seite** ausgeführt – einzelne Seiten lassen sich nicht gezielt auswählen
- Änderungen werden erst mit dem nächsten **Build** wirksam; `jamdesk dev` führt keine eigenen Skripts aus
- Skripts werden in den HTML-Code **eingebettet** und nicht als separate Dateien bereitgestellt
- Für Analytics können Sie stattdessen die integrierten [Integrationen](/de/integrations/google-analytics) verwenden, die Einwilligung und Performance automatisch berücksichtigen
