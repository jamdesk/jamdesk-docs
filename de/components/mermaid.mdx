Schreiben Sie Diagramme als Text in umschlossenen Codeblöcken. Jamdesk rendert sie beim Build als SVG.

<Tip>
  Entwerfen und testen Sie Ihr Diagramm im [Jamdesk Mermaid-Editor](https://jamdesk.com/utilities/mermaid-editor),
  einem quelloffenen, browserbasierten Editor und Viewer. Schreiben Sie Mermaid-Syntax, sehen Sie sich
  das Ergebnis live an und fügen Sie es anschließend hier in einen umschlossenen `mermaid`-Block ein.
</Tip>

<Tip>
  Jamdesk unterstützt auch [D2-Diagramme](/de/components/d2) in umschlossenen `d2`-Blöcken.
  Verwenden Sie D2, wenn ein Diagramm verschachtelte Container, ein SQL-Schema mit
  Primär- und Fremdschlüsseln oder einen Wechsel der Layout-Engine erfordert. Zu den
  Mermaid-Beispielen auf dieser Seite gibt es D2-Entsprechungen auf der [D2-Seite](/de/components/d2).
</Tip>

## Grundlegende Verwendung

Verwenden Sie einen umschlossenen Codeblock mit der Sprachkennung `mermaid`:

````mdx
```mermaid
flowchart LR
    A[Start] --> B[Process] --> C[End]
```
````

```mermaid
flowchart LR
    A[Start] --> B[Process] --> C[End]
```

## Diagrammtypen

### Flussdiagramme

Die Richtung kann von oben nach unten (`TD`), von links nach rechts (`LR`), von unten nach oben (`BT`) oder von rechts nach links (`RL`) verlaufen.

```mermaid
flowchart TD
    A[User Request] --> B{Valid?}
    B -->|Yes| C[Process]
    B -->|No| D[Error]
    C --> E[Response]
    D --> E
```

````mdx
```mermaid
flowchart TD
    A[User Request] --> B{Valid?}
    B -->|Yes| C[Process]
    B -->|No| D[Error]
    C --> E[Response]
    D --> E
```
````

#### Untergraphen

Gruppieren Sie zusammengehörige Knoten mithilfe von Untergraphen. So lassen sich komplexe Flussdiagramme in logische Abschnitte wie „Frontend“ und „Backend“ oder in verschiedene Phasen einer Pipeline gliedern.

```mermaid
flowchart TB
    subgraph Frontend
        A[React App] --> B[Components]
    end
    subgraph Backend
        C[API Server] --> D[(Database)]
    end
    B -->|HTTP| C
```

````mdx
```mermaid
flowchart TB
    subgraph Frontend
        A[React App] --> B[Components]
    end
    subgraph Backend
        C[API Server] --> D[(Database)]
    end
    B -->|HTTP| C
```
````

### Sequenzdiagramme

Sequenzdiagramme zeigen, wie Komponenten im zeitlichen Verlauf interagieren. Verwenden Sie ein Sequenzdiagramm für Abläufe von API-Aufrufen und Authentifizierungs-Handshake-Prozesse. Beteiligte werden als vertikale Lebenslinien dargestellt, zwischen denen Nachrichten ausgetauscht werden.

```mermaid
sequenceDiagram
    participant Client
    participant Server
    participant Database

    Client->>Server: Request
    Server->>Database: Query
    Database-->>Server: Results
    Server-->>Client: Response
```

````mdx
```mermaid
sequenceDiagram
    participant Client
    participant Server
    participant Database

    Client->>Server: Request
    Server->>Database: Query
    Database-->>Server: Results
    Server-->>Client: Response
```
````

### Klassendiagramme

Klassendiagramme stellen die Struktur objektorientierter Systeme dar, etwa ein Datenmodell oder die zentralen Typen eines Dienstes. Sie zeigen Klassen mit ihren Attributen und Methoden sowie ihre Beziehungen untereinander.

```mermaid
classDiagram
    class User {
        +String name
        +String email
        +login()
        +logout()
    }
    class Order {
        +int id
        +Date created
        +addItem()
        +checkout()
    }
    class Item {
        +String name
        +float price
    }
    User "1" --> "*" Order : places
    Order "1" --> "*" Item : contains
```

````mdx
```mermaid
classDiagram
    class User {
        +String name
        +String email
        +login()
        +logout()
    }
    class Order {
        +int id
        +Date created
        +addItem()
        +checkout()
    }
    class Item {
        +String name
        +float price
    }

    Order "1" --> "*" Item : contains
```
````

### Zustandsdiagramme

Zustandsdiagramme modellieren den Lebenszyklus eines Objekts oder Prozesses. Sie zeigen alle möglichen Zustände und die Übergänge zwischen ihnen. Bestellstatus und Workflows zur Dokumentfreigabe sind typische Beispiele.

```mermaid
stateDiagram-v2
    [*] --> Draft
    Draft --> Review
    Review --> Published
    Review --> Draft
    Published --> [*]
```

````mdx
```mermaid
stateDiagram-v2
    [*] --> Draft
    Draft --> Review
    Review --> Published
    Review --> Draft
    Published --> [*]
```
````

### Entity-Relationship-Diagramme

ER-Diagramme dokumentieren Datenbankschemas und Datenmodelle. Sie zeigen Entitäten (Tabellen), ihre Attribute (Spalten) und die Beziehungen zwischen ihnen. Die Symbole geben die Kardinalität an: eins zu eins, eins zu viele oder viele zu viele.

```mermaid
erDiagram
    USER ||--o{ ORDER : places
    ORDER ||--|{ ITEM : contains
    USER {
        string name
        string email
    }
    ORDER {
        int id
        date created
    }
```

````mdx
```mermaid
erDiagram
    USER ||--o{ ORDER : places
    ORDER ||--|{ ITEM : contains
    USER {
        string name
        string email
    }
    ORDER {
        int id
        date created
    }
```
````

### Gantt-Diagramme

Gantt-Diagramme veranschaulichen Projektpläne und Zeitabläufe. Aufgaben werden als horizontale Balken auf einer Zeitleiste angezeigt, die Dauer, Abhängigkeiten und parallele Arbeit darstellen. Ein Projektplan oder eine Roadmap eignet sich dafür besonders gut.

```mermaid
gantt
    title Project Timeline
    dateFormat YYYY-MM-DD
    section Planning
        Research       :a1, 2024-01-01, 7d
        Design         :a2, after a1, 5d
    section Development
        Backend        :b1, after a2, 14d
        Frontend       :b2, after a2, 14d
    section Launch
        Testing        :c1, after b1, 7d
        Deployment     :c2, after c1, 2d
```

````mdx
```mermaid
gantt
    title Project Timeline
    dateFormat YYYY-MM-DD
    section Planning
        Research       :a1, 2024-01-01, 7d
        Design         :a2, after a1, 5d

        Frontend       :b2, after a2, 14d
    section Launch
````

### Git-Graphen

Git-Graphen veranschaulichen Branching-Strategien und Workflows zur Versionsverwaltung. Sie zeigen Commits, Branches, Merges und den gesamten Verlauf eines Repositorys. Jeder Branch ist zur einfachen Erkennung farblich gekennzeichnet.

```mermaid
gitGraph
    commit id: "Initial"
    branch feature
    checkout feature
    commit id: "Add login"
    commit id: "Add auth"
    checkout main
    merge feature id: "v1.0"
    branch release
    checkout release
    commit id: "Prep 1.1"
    checkout main
    branch hotfix
    checkout hotfix
    commit id: "Fix bug"
    checkout main
    merge hotfix id: "v1.0.1"
    checkout release
    commit id: "Final QA"
    checkout main
    merge release id: "v1.1"
```

### Zeitachsendiagramme

Zeitachsen zeigen Ereignisse über bestimmte Zeiträume hinweg. Beginnen Sie mit dem Schlüsselwort `timeline`, fügen Sie optional einen `title` hinzu und anschließend eine Zeile pro Zeitraum mit durch Doppelpunkte getrennten Ereignissen:

```mermaid
timeline
    title Product Launch Timeline
    2024 : Research
         : First prototype
    2025 : Private beta
         : Public beta
    2026 : GA launch
```

````mdx
```mermaid
timeline
    title Product Launch Timeline
    2024 : Research
         : First prototype
    2025 : Private beta
         : Public beta
    2026 : GA launch
```
````

### Kreisdiagramme

Kreisdiagramme zeigen proportionale Daten als Kreissegmente. Verwenden Sie sie, wenn Teile ein Ganzes ergeben, etwa bei Marktanteilen oder Umfrageergebnissen. Beschränken Sie die Anzahl der Segmente für bessere Lesbarkeit auf höchstens 6.

```mermaid
pie title Browser Market Share
    "Chrome" : 65
    "Safari" : 19
    "Firefox" : 10
    "Edge" : 4
    "Other" : 2
```

## Formen in Flussdiagrammen

Verschiedene Formen stehen in Flussdiagrammen für unterschiedliche Bedeutungen:

| Syntax     | Form                | Verwendung |
| ---------- | ------------------- | ------- |
| `[text]`   | Rechteck            | Prozessschritte, Aktionen |
| `(text)`   | Abgerundetes Rechteck | Start- und Endpunkte |
| `{text}`   | Raute                | Entscheidungen, Bedingungen |
| `([text])` | Stadion              | Ereignisse, Auslöser |
| `[[text]]` | Unterprogramm        | Vordefinierte Prozesse |
| `[(text)]` | Zylinder             | Datenbanken, Speicher |

## Pfeiltypen

Pfeile geben die Flussrichtung und die Art der Beziehung an:

| Syntax      | Beschreibung         | Verwendung |
| ----------- | -------------------- | ------- |
| `-->`       | Durchgezogener Pfeil | Normaler Ablauf |
| `---`       | Durchgezogene Linie  | Zuordnungen |
| `-.->`      | Gepunkteter Pfeil    | Optionaler oder asynchroner Ablauf |
| `==>`       | Dicker Pfeil         | Wichtige Pfade |
| `--text-->` | Pfeil mit Beschriftung | Übergang beschreiben |

## Breite Diagramme skalieren

Bei breiten Diagrammen wie Gantt-Diagrammen oder komplexen Git-Graphen können Sie die Komponente `Mermaid` direkt mit der Property `minWidth` verwenden, damit das Diagramm nicht gestaucht wird:

```mdx
<Mermaid minWidth="700px">
gantt
    title Wide Project Timeline
    ...
</Mermaid>
```

## Zum Vergrößern anklicken

Auf Bildschirmen ab 768 px öffnet sich ein Diagramm im Vollbild, wenn Sie darauf klicken. Mit der Tastatur können Sie das Diagramm fokussieren und Enter drücken. Drücken Sie Escape, klicken Sie auf die Schließen-Schaltfläche oder außerhalb des Diagramms, um es zu schließen.

Um diese Funktion für ein einzelnes Diagramm zu deaktivieren, verwenden Sie die Komponentenform mit `noZoom`:

```mdx
<Mermaid noZoom>
graph LR
    A[Request] --> B[Response]
</Mermaid>
```

Diagramme in ```` ```mermaid ````-Codeblöcken werden immer im Vollbild geöffnet.

## Tipps zur Gestaltung

<Tip>
  Mermaid-Diagramme passen sich automatisch an helle und dunkle Modi an. Die Farben
  sind in beiden Designs auf gute Lesbarkeit abgestimmt.
</Tip>

Für aussagekräftige Diagramme:

- Halten Sie es einfach: Teilen Sie komplexe Abläufe in mehrere kleinere Diagramme auf.
- Beschriften Sie Ihre Pfeile, um Übergänge zu erklären.
- Wählen Sie eine Richtung: `TD` (von oben nach unten) für hohe Diagramme, `LR` (von links nach rechts) für breite Diagramme.
- Begrenzen Sie jedes Diagramm zur besseren Übersicht auf 10–15 Knoten.

Um einen Knoten einzufärben, verwenden Sie `style` für einen einzelnen Knoten oder `classDef` für eine Gruppe:

```mermaid
graph LR
    A[Start] --> B[Review] --> C[Done]
    classDef good fill:#d1fae5,stroke:#059669
    style B fill:#fef3c7,stroke:#d97706
    class C good
```

Ihre Farben bleiben im hellen und dunklen Modus erhalten. Wenn Sie eine Füllfarbe, aber keine Textfarbe festlegen, wählt Jamdesk eine Beschriftungsfarbe, die sich gut von der Füllung abhebt.
