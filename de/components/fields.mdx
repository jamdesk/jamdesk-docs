Felder dokumentieren API-Parameter und Antwortfelder in einem einheitlichen Format.

## Verwendung

```mdx
<ParamField query="limit" type="number" default={10}>
  Maximum number of results to return.
</ParamField>
```

## ParamField

Verwenden Sie `ParamField`, um API-Anfrageparameter zu dokumentieren. Legen Sie den Parameterort mit `body`, `query`, `path` oder `header` fest.

<ParamField body="user_id" type="string" required>
  Die eindeutige Kennung für den Benutzer.
</ParamField>

<ParamField query="limit" type="number" default={10}>
  Maximale Anzahl der zurückzugebenden Ergebnisse.
</ParamField>

<ParamField header="Authorization" type="string" required>
  Bearer-Token zur Authentifizierung.
</ParamField>

```mdx
<ParamField body="user_id" type="string" required>
  The unique identifier for the user.
</ParamField>

<ParamField query="limit" type="number" default={10}>
  Maximum number of results to return.
</ParamField>

<ParamField header="Authorization" type="string" required>
  Bearer token for authentication.
</ParamField>
```

### Pfadparameter

<ParamField path="id" type="string" required>
  Ressourcenkennung im URL-Pfad.
</ParamField>

```mdx
<ParamField path="id" type="string" required>
  Resource identifier in the URL path.
</ParamField>
```

### Props von ParamField

<ParamField name="body" type="string">
  Parametername für Body-Parameter.
</ParamField>

<ParamField name="query" type="string">
  Parametername für Query-String-Parameter.
</ParamField>

<ParamField name="path" type="string">
  Parametername für URL-Pfadparameter.
</ParamField>

<ParamField name="header" type="string">
  Parametername für Header-Parameter.
</ParamField>

<ParamField name="type" type="string">
  Datentyp (string, number, boolean, array, object).
</ParamField>

<ParamField name="required" type="boolean">
  Zeigt ein „required“-Badge an.
</ParamField>

<ParamField name="default" type="string | number | boolean">
  Standardwert, wenn keiner angegeben wird.
</ParamField>

## ResponseField

Verwenden Sie `ResponseField`, um API-Antworteigenschaften zu dokumentieren.

<ResponseField name="id" type="string" required>
  Eindeutige Kennung der Ressource.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO-8601-Zeitstempel der Ressourcenerstellung.
</ResponseField>

<ResponseField name="status" type="string" default="pending">
  Aktueller Status der Anfrage.
</ResponseField>

```mdx
<ResponseField name="id" type="string" required>
  Unique identifier for the resource.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the resource was created.
</ResponseField>

<ResponseField name="status" type="string" default="pending">
  Current status of the request.
</ResponseField>
```

### Veraltete Felder

Markieren Sie ein Feld, das in einer künftigen Version entfernt wird, als `deprecated`:

<ResponseField name="legacy_id" type="number" deprecated>
  Verwenden Sie stattdessen `id`. Dieses Feld wird in v2 entfernt.
</ResponseField>

```mdx
<ResponseField name="legacy_id" type="number" deprecated>
  Use `id` instead. This field will be removed in v2.
</ResponseField>
```

### Beschriftungen

Fügen Sie mit `pre` und `post`-Labels Kontext hinzu:

<ResponseField name="webhook_url" type="string" pre={["optional"]} post={["v2.1+"]}>
  URL, über die Webhook-Benachrichtigungen empfangen werden.
</ResponseField>

```mdx
<ResponseField name="webhook_url" type="string" pre={["optional"]} post={["v2.1+"]}>
  URL to receive webhook notifications.
</ResponseField>
```

### Verschachtelte Objekte

Verschachteln Sie Felder innerhalb von `Expandable`, um Objekteigenschaften zu dokumentieren:

<ResponseField name="user" type="object">
  Der Benutzer, der die Ressource erstellt hat.
  <Expandable title="user properties">
    <ResponseField name="id" type="string" required>
      Eindeutige Kennung des Benutzers.
    </ResponseField>
    <ResponseField name="email" type="string" required>
      E-Mail-Adresse des Benutzers.
    </ResponseField>
    <ResponseField name="name" type="string">
      Anzeigename des Benutzers.
    </ResponseField>
  </Expandable>
</ResponseField>

```mdx
<ResponseField name="user" type="object">
  The user who created the resource.
  <Expandable title="user properties">
    <ResponseField name="id" type="string" required>
      User's unique identifier.
    </ResponseField>
    <ResponseField name="email" type="string" required>
      User's email address.
    </ResponseField>
    <ResponseField name="name" type="string">
      User's display name.
    </ResponseField>
  </Expandable>
</ResponseField>
```

### Props von ResponseField

<ParamField name="name" type="string" required>
  Feldname.
</ParamField>

<ParamField name="type" type="string">
  Datentyp.
</ParamField>

<ParamField name="required" type="boolean">
  Zeigt ein „required“-Badge an.
</ParamField>

<ParamField name="deprecated" type="boolean">
  Zeigt das Feld als veraltet mit Durchstreichung an.
</ParamField>

<ParamField name="default" type="string | number | boolean">
  Standardwert.
</ParamField>

<ParamField name="pre" type="string[]">
  Labels, die vor dem Feldnamen angezeigt werden.
</ParamField>

<ParamField name="post" type="string[]">
  Labels, die nach dem Feldnamen angezeigt werden.
</ParamField>
