title: Update
description: Zeitleisten-artige Changelog-Einträge mit Datum, Beschreibung und Kategorie-Tags. Integriert sich in Ihr Inhaltsverzeichnis für die Navigation.
---

Die Komponente Update erstellt Changelog-Einträge im Zeitleisten-Stil. Die Einträge erscheinen im Inhaltsverzeichnis. Ein Eintrag kann ein Datumslabel, eine Beschreibung und Kategorie-Tags enthalten. Verwenden Sie sie für Seiten mit „Neuigkeiten“, API-Changelogs und Release-Notes.

Verwenden Sie Update, wenn Sie:
- **Releases dokumentieren** mit Versionsnummern oder Datumsangaben
- **Changelogs aufbauen**, durch die Leser über das ToC navigieren können
- **Funktionen ankündigen** mit kategorisierten Tags (new, fix, breaking)

<Tip>
Zeigen Sie das Changelog in Ihrem Produkt mit einer Schaltfläche „Was ist neu?“ und einem Punkt für ungelesene Einträge an. Siehe [Changelog einbetten](/de/development/embed-page).
</Tip>

## Grundlegende Verwendung

<Update label="January 10, 2025">
Added support for dark mode across all themes.
</Update>

```mdx
<Update label="January 10, 2025">
Added support for dark mode across all themes.
</Update>
```

## Mit Beschreibung

Fügen Sie Kontext unterhalb des Datums hinzu:

<Update label="January 5, 2025" description="Breaking change">
The `getData()` function now requires an options object.
</Update>

```mdx
<Update label="January 5, 2025" description="Breaking change">
The `getData()` function now requires an options object.
</Update>
```

## Mit Tags

Kategorisieren Sie Einträge mit Tags:

<Update label="December 20, 2024" tags={["breaking", "api"]}>
- Removed deprecated `legacyMode` option
- Updated authentication flow
</Update>

```mdx
<Update label="December 20, 2024" tags={["breaking", "api"]}>
- Removed deprecated `legacyMode` option
- Updated authentication flow
</Update>
```

## Mehrere Einträge

Stapeln Sie Update-Komponenten für ein vollständiges Changelog:

<Update label="December 15, 2024" tags={["feature"]}>
New export functionality for PDF and CSV formats.
</Update>

<Update label="December 10, 2024" tags={["fix"]}>
Fixed timezone handling in scheduled posts.
</Update>

<Update label="December 1, 2024" tags={["deprecation"]}>
The `v1` API endpoints are now deprecated. Migrate to `v2` by March 2025.
</Update>

## Ankerlinks und Inhaltsverzeichnis

Jedes Update erzeugt aus seinem Label eine Anker-ID (`label="January 10, 2025"` erzeugt `#january-10-2025`). Labels erscheinen außerdem im Inhaltsverzeichnis für die schnelle Navigation.

## Props

<ParamField name="label" type="string">
  Datums- oder Versionslabel (erzeugt Anker-ID).
</ParamField>

<ParamField name="description" type="string">
  Sekundärer Text unterhalb des Labels.
</ParamField>

<ParamField name="tags" type="string[]">
  Kategorie-Tags, angezeigt als Badges.
</ParamField>

<ParamField name="date" type="string">
  ISO-Datumsstring (z. B. `"2025-03-15"`), der für das `pubDate` des RSS-Feeds verwendet wird. Wird nicht visuell angezeigt; das `label` bleibt Ihr Anzeigetext.
</ParamField>

## RSS-Feed

Fügen Sie `rss: true` zu jeder Seite mit Update-Komponenten hinzu. Jamdesk erzeugt bei Builds einen `feed.xml`. Leser abonnieren ihn für Changelog-Updates.

```yaml
---
title: Changelog
rss: true
---
```

Wenn aktiviert:
- Erscheint ein RSS-Symbol neben dem Seitentitel, das auf den Feed verlinkt
- Wird ein `<link rel="alternate">`-Tag im `<head>` für die automatische Erkennung durch RSS-Reader und Browser hinzugefügt
- Wird jedes `<Update>` zu einem RSS-Item mit seinem Label als Titel und einem Anker-Link zurück zum Eintrag

### Veröffentlichungsdaten festlegen

Verwenden Sie das Prop `date`, um das `<pubDate>` für jeden Eintrag im Feed festzulegen. Ohne `date` erscheint der Eintrag im Feed, aber ohne Zeitstempel.

```mdx
<Update label="March 2025" date="2025-03-15" tags={["feature"]}>
Added dark mode support across all themes.
</Update>
```

### Feed-Inhalt

RSS-Feeds enthalten nur Klartext. Markdown-Formatierung, MDX-Komponenten, Code-Blöcke und HTML werden aus der Feed-Beschreibung entfernt. Schreiben Sie den ersten Satz als Zusammenfassung, die auch ohne Formatierung gut lesbar ist.

### Feed-URL

Der Feed ist unter `/feed.xml` verfügbar (bzw. `/docs/feed.xml`, falls Ihre Site [hostAtDocs](/de/deploy/custom-domains) verwendet).

Der erzeugte Feed sieht so aus:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">
  <channel>
    <title>Acme Docs Changelog</title>
    <link>https://docs.acme.com</link>
    <description>Updates and changelog for Acme Docs</description>
    <item>
      <title>March 2025 — New dashboard</title>
      <link>https://docs.acme.com/changelog#march-2025</link>
      <pubDate>Sat, 15 Mar 2025 00:00:00 GMT</pubDate>
      <description>Added dark mode support across all themes.</description>
    </item>
  </channel>
</rss>
```

### Integration mit anderen Tools

Fügen Sie die Feed-URL zu jedem RSS-kompatiblen Dienst hinzu:

- Slack: Fügen Sie die [RSS-App](https://slack.com/apps/A0F81R7U7-rss) mit `/feed` zu einem Kanal hinzu.
- Discord: Verwenden Sie [MonitoRSS](https://monitorss.xyz/) oder einen ähnlichen Bot, um Updates automatisch zu posten.
- E-Mail: Verbinden Sie den Feed mit [Zapier](https://zapier.com/) oder [IFTTT](https://ifttt.com/), um Abonnenten bei neuen Einträgen per E-Mail zu informieren.
- Browser: Safari, Vivaldi und Firefox (über Erweiterungen) unterstützen RSS nativ.

<Tip>
  Fügen Sie `rss: true` bei Bedarf zu mehr als einer Seite hinzu. Jamdesk kombiniert die Update-Einträge aller RSS-fähigen Seiten in einem seitenweiten `feed.xml`.
</Tip>

## Bewährte Vorgehensweisen

<AccordionGroup>
  <Accordion title="Use unique labels" icon="fingerprint" defaultOpen>
    Jedes Label erzeugt eine Anker-ID. Halten Sie Labels eindeutig, damit Deep-Links funktionieren:
    - Verwenden Sie konkrete Daten: `January 10, 2025` (nicht nur `January 2025`)
    - Nennen Sie Versionsnummern: `v2.1.0` vs. `v2.0.0`
    - Doppelte Labels erzeugen doppelte IDs und brechen Anker-Links
  </Accordion>

  <Accordion title="Use consistent date formats" icon="calendar">
    Wählen Sie ein Format und bleiben Sie dabei:
    - `January 10, 2025` (empfohlen)
    - `2025-01-10` (ISO-Format)
    - `v2.0.0` (für versionsbasierte Changelogs)
  </Accordion>

  <Accordion title="Use meaningful tags" icon="tags">
    Gängige Tags mit automatischer Farbcodierung:

    | Tag | Farbe | Verwendung für |
    |-----|-------|---------|
    | `breaking` | Rot | Breaking Changes |
    | `feature` / `new` | Grün | Neue Funktionen |
    | `deprecation` / `deprecated` | Bernstein | Veraltete Funktionen |
    | Andere Tags | Grau | Allgemeine Kategorien wie `api`, `fix` |
  </Accordion>

  <Accordion title="Keep entries scannable" icon="eye">
    - Beginnen Sie mit der wichtigsten Änderung
    - Verwenden Sie Aufzählungspunkte für mehrere Punkte
    - Verlinken Sie bei komplexen Änderungen auf ausführliche Dokumentation
  </Accordion>
</AccordionGroup>
