Mit Views können Sie Dokumentation erstellen, die sich an das Framework oder die Sprachwahl der Lesenden anpasst. Anders als Tabs, die mehrere Optionen nebeneinander anzeigen, blenden Views nicht ausgewählte Inhalte vollständig aus. So bleibt die Seite übersichtlicher, wenn sich ganze Abschnitte je nach Framework unterscheiden.

Verwenden Sie Views, wenn:
- **Ganze Seitenabschnitte** sich je nach Framework unterscheiden, nicht nur Codeausschnitte
- **Tutorials** für unterschiedliche Technologien verschiedene Schritte enthalten
- **Einstiegsleitfäden** je nach Plattform deutlich variieren

<Tip>
Verwenden Sie für Codebeispiele, die sich je nach Programmiersprache unterscheiden, [CodeGroup](/de/components/code-group). Für Verfahren mit geringfügigen Unterschieden eignen sich [Tabs](/de/components/tabs). Verwenden Sie Views, wenn **ganze Abschnitte** vom Framework abhängen.
</Tip>

## Grundlegende Verwendung

Erstellen Sie Views für verschiedene Programmiersprachen:

<View title="JavaScript" icon="js">
  Dieser Inhalt ist nur sichtbar, wenn JavaScript ausgewählt ist.

  ```javascript
  console.log("Hello from JavaScript!");
  ```
</View>

<View title="Python" icon="python">
  Dieser Inhalt ist nur sichtbar, wenn Python ausgewählt ist.

  ```python
  print("Hello from Python!")
  ```
</View>


## Funktionsweise

Wenn Sie einer Seite View-Komponenten hinzufügen:

1. Oben im Inhalt erscheint ein Dropdown-Menü
2. Über das Dropdown-Menü können Nutzer zwischen den Ansichten wechseln
3. Nur der Inhalt der ausgewählten Ansicht ist sichtbar

## Ansicht vs. Tabs vs. CodeGroup

| Komponente | Geeignet für | Umfang |
|-----------|----------|-------|
| **View** | Ganze Abschnitte, die sich je nach Framework unterscheiden | Umschalten seitenweiter Inhalte |
| **Tabs** | Schnelle Vergleiche, Paketmanager | Umschalten eingebetteter Inhalte |
| **CodeGroup** | Derselbe Vorgang in mehreren Programmiersprachen | Nur Codeblöcke |

**Beispiele:**
- „Mit npm oder yarn installieren“ → **Tabs** (kleiner Unterschied)
- „JavaScript fetch oder Python requests“ → **CodeGroup** (Codevergleich)
- „React- oder Vue-Tutorial“ → **View** (ganzer Abschnitt unterscheidet sich)

## Props

<ParamField name="title" type="string" required>
  Der Titel, der im Dropdown-Menü angezeigt wird. Muss innerhalb der Seite eindeutig sein.
</ParamField>

<ParamField name="icon" type="string">
  Ein Font Awesome-Symbol, eine URL zu einem Symbol oder ein relativer Pfad zu einem Symbol.
</ParamField>

<ParamField name="iconType" type="string" default="solid">
  Nur für Font Awesome-Symbole. Optionen: `regular`, `solid`, `light`, `thin`, `sharp-solid`, `duotone`, `brands`.
</ParamField>
