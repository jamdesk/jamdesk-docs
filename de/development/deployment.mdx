Jamdesk übernimmt Bereitstellungen automatisch. Pushen Sie zu Ihrem verbundenen GitHub-Branch, und Ihre Dokumentation ist innerhalb weniger Minuten live.

## CLI-Bereitstellung

Sie können direkt über das Terminal bereitstellen, ohne zu GitHub zu pushen. Das ist nützlich für schnelle Iterationen, zum Testen von Änderungen oder für Projekte, die nicht mit einem Repository verbunden sind.

```bash
jamdesk login     # First time only
jamdesk deploy
```

Die CLI packt Ihre Dateien, lädt sie hoch und zeigt den Build-Fortschritt live an. Verwenden Sie `--detach`, um den Build in die Warteschlange zu stellen und sofort zu beenden.

## Der Workflow

<Steps>
  <Step title="Lokal Änderungen vornehmen">
    Bearbeiten Sie Ihre MDX-Dateien und sehen Sie sich eine Vorschau mit `jamdesk dev` an.
  </Step>
  <Step title="Zu GitHub pushen">
    Committen und pushen Sie zu Ihrem verbundenen Branch:

    ```bash
    git add .
    git commit -m "Update authentication docs"
    git push
    ```
  </Step>
  <Step title="Automatische Bereitstellung">
    Jamdesk erkennt Ihren Push, erstellt Ihre Dokumentation und stellt sie im CDN bereit. Die meisten Websites werden in 30–90 Sekunden erstellt.
  </Step>
</Steps>

## Bereitstellungsstatus

Überprüfen Sie den Status im Dashboard unter **Deployments**:

| Status | Bedeutung |
|--------|---------|
| **Building** | Build wird ausgeführt |
| **Deployed** | Unter Ihrer Domain live |
| **Failed** | Build-Fehler – überprüfen Sie die Logs |
| **Queued** | Wartet auf den vorherigen Build |

## Manueller Build

Lösen Sie einen erneuten Build aus, ohne zu pushen:

1. Öffnen Sie **Settings** in Ihrem Projekt.
2. Klicken Sie auf **Rebuild**.

Verwenden Sie dies, wenn Sie Umgebungsvariablen aktualisieren oder festgefahrene Builds beheben.

## Build-Logs

Wenn Builds fehlschlagen, überprüfen Sie **Deployments** → klicken Sie auf eine Bereitstellung → sehen Sie sich die Logs an. Häufige Probleme:

- Ungültige MDX-Syntax
- Fehlende Bilder
- Fehlerhafte interne Links
- Konfigurationsfehler

## Rollbacks

Setzen Sie auf eine vorherige Version zurück:

1. Öffnen Sie **Deployments**.
2. Suchen Sie die wiederherzustellende Bereitstellung.
3. Klicken Sie auf **Rollback**.

Die vorherige Version ist sofort live.
