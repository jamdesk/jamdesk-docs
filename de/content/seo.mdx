## Inhalte optimieren

### Aussagekräftiges Frontmatter verfassen

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Wichtige Keywords an den Anfang stellen.** „Authentication setup“ ist besser als „How to set up authentication“.
</Tip>

### Seitentitel

- Halten Sie den Titel unter 60 Zeichen, einschließlich des Seitennamens, den Ihr Titelformat hinzufügt, damit er in Suchergebnissen nicht abgeschnitten wird
- Platzieren Sie Ihr wichtigstes Keyword möglichst weit vorne
- Verwenden Sie für jede Seite Ihrer Dokumentation einen eigenen Titel

Standardmäßig lautet der Titel im Browser-Tab und in den Suchergebnissen `Page title — Site name`. Ändern Sie ihn mit `seo.titleTemplate` in `docs.json`. Setzen Sie `%s` an die Stelle des Seitentitels:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Eine Seite mit dem Titel `Getting started` wird dann als `Getting started | Acme` angezeigt. Verwenden Sie nur `"%s"`, um den Seitennamen wegzulassen. Enthält die Vorlage kein `%s`, schlägt der Build fehl und `jamdesk validate` zeigt den Fehler an. Linkvorschauen (`og:title` und `twitter:title`) zeigen weiterhin nur den Seitentitel.

Zwei Arten von Seiten verwenden die Vorlage nicht. Wenn eine Seite keinen `title` hat, werden Ihr `name` und anschließend „Documentation“ angezeigt, zum Beispiel `Acme Documentation`. Endet der Name bereits mit „Docs“ oder „Documentation“, wird nur Ihr `name` angezeigt. Lautet der Titel einer Seite genauso wie Ihr `name`, wird nur dieser Titel angezeigt.

`jamdesk validate` und `jamdesk dev` unterstützen `seo.titleTemplate` ab CLI-Version 1.1.220. Aktualisieren Sie mit `npm i -g jamdesk@latest`.

### Beschreibungen

- Streben Sie 120–160 Zeichen an
- Fassen Sie zusammen, was Leser erfahren
- Binden Sie passende Keywords natürlich ein

<Note>
**Automatisch generierter Ersatz.** Fehlt `description` im Frontmatter, extrahiert Jamdesk automatisch den ersten Fließtextabsatz Ihrer Seite (bis zu 155 Zeichen). Überschriften, Codeblöcke, Bilder und MDX-Komponenten werden übersprungen. Dieser Text wird für `<meta name="description">`, Open Graph und Twitter Cards verwendet. Für optimale Ergebnisse empfiehlt sich weiterhin eine explizite Beschreibung.
</Note>

## Indexierung steuern

### Einstellungen für die gesamte Website

Konfigurieren Sie in Ihrer `docs.json` das Standardverhalten für Robots:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Einstellungen für einzelne Seiten

Überschreiben Sie die Indexierung für bestimmte Seiten im Frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Verwenden Sie `noindex` für:
- Entwürfe oder Seiten in Bearbeitung
- Interne Dokumentation
- Veraltete Inhalte, die Sie als Referenz behalten

### Suchmaschinenindexierung und KI-Verarbeitung

`robots`-Metadaten und `noindex` steuern **Suchmaschinen**: Sie bestimmen, ob eine Seite bei Google und in Ihrer `sitemap.xml` erscheint. Auf die Dateien `llms.txt` und `llms-full.txt`, die KI-Tools lesen, haben sie keinen Einfluss. Um deren Veröffentlichung zu verhindern, setzen Sie `seo.ai.llmsTxt` auf `false` (siehe [llms.txt deaktivieren](/de/ai/llms-txt#llmstxt-deaktivieren)). Die beiden Einstellungen sind unabhängig voneinander: Eine Seite kann von Suchmaschinen indexiert, aber von der KI-Verarbeitung ausgeschlossen werden – oder umgekehrt.

## Kanonische URLs

Wenn Ihre Dokumentation unter mehreren URLs erreichbar ist, legen Sie eine kanonische URL fest:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Sie können in `docs.json` auch eine kanonische Basis-URL für die gesamte Website festlegen. Jamdesk hängt den Pfad jeder Seite daran an, sodass jede Seite die passende kanonische URL erhält:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Social-Media-Vorschauen und Open Graph

Jamdesk erstellt automatisch für jede Seite eine gebrandete Social Card im Format 1200×630. Überschreiben Sie beliebige Social-Tags im Frontmatter. Sie können **einfache Schlüssel auf oberster Ebene** oder einen verschachtelten **`seo:`**-Block verwenden. Beides funktioniert. Ist derselbe Schlüssel an beiden Stellen festgelegt, hat der Wert auf oberster Ebene Vorrang.

<Card title="OpenGraph-Vorschau" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Sehen Sie sich mit dem OpenGraph Preview-Tool an, wie die Card einer beliebigen Seite auf X, Facebook, LinkedIn und weiteren Plattformen dargestellt wird. Außerdem können Sie damit ihre Open-Graph-Tags überprüfen.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Unterstützte Tags

| Gruppe | Tags |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artikel | `og:type: article` mit `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, App-Card-Tags |
| Sonstige | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` sowie beliebige benutzerdefinierte Tags (benutzerdefinierte Tags unter `seo:` platzieren) |

<Note>
**Abmessungen benutzerdefinierter OG-Bilder.** `og:image:width` und `og:image:height` gelten nur, wenn
[`customImage`](#social-card-anpassen) auf `"replace"` gesetzt ist. Legen Sie sie an derselben Stelle fest wie das zugehörige
`og:image`: entweder im Frontmatter der Seite oder unter `seo.metatags`. Die generierte
Card hat immer das Format 1200×630.
</Note>

<Note>
**Benutzerdefinierte Tags.** Beliebige Meta-Tags (z. B. `x-pinterest`) werden als `<meta name="...">` ausgegeben.
Platzieren Sie sie im `seo:`-Block. Auf oberster Ebene werden nur erkannte SEO-Schlüssel berücksichtigt.
</Note>

### Twitter-/X-Kartentyp

Das Tag `twitter:card` bestimmt, welches Layout X (und andere Plattformen) beim Teilen Ihres Links verwendet:

| Wert | Darstellung |
|-------|--------------------|
| `summary` | Kleines quadratisches Vorschaubild links, Titel und Beschreibung daneben. Kompaktes Layout. |
| `summary_large_image` | Großes, breites Bild oben, Titel und Beschreibung darunter. Die große, auffällige Variante. |

Verwenden Sie für eine gebrandete Card im Format 1200×630 `summary_large_image`, damit das Bild in voller Breite angezeigt wird.

### Standardbild für die gesamte Website

Legen Sie in `docs.json` ein Ersatzbild für alle Seiten fest. Seiten mit einem eigenen `og:image` überschreiben diese Einstellung:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Vor der Veröffentlichung prüfen.** Fügen Sie nach einem Build die Seiten-URL in das Tool [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) ein. Dort sehen Sie, wie die Card auf den einzelnen Plattformen dargestellt wird, und können die Open-Graph-Tags prüfen. Das Tool überprüft auch die Bildabmessungen und erklärt, wie Sie gefundene Probleme beheben.
</Tip>

### Social Card anpassen

Das aktuelle Erscheinungsbild Ihrer generierten Card bleibt erhalten, sofern Sie `seo.socialCard` nicht zu `docs.json` hinzufügen.
Legen Sie nur die Schlüssel fest, die Sie ändern möchten:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Schlüssel | Standard | Wirkung |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` verwendet hellen Text auf dunklem Hintergrund und Ihr Bild `logo.dark`. |
| `brandColor` | `false` | `true` färbt die untere Leiste und das Abschnitts-Badge mit `colors.primary`. Bei einer dunklen Card wird `colors.light` verwendet, sofern Sie es festlegen. Wenn Sie keine `colors` haben, verwendet die Card die Akzentfarbe Ihres Themes. `false` behält das Standardrot bei. |
| `accentBar` | `true` | `false` entfernt die farbige Leiste am unteren Rand der Card. |
| `siteName` | `true` | `false` blendet den Seitennamen unter dem Logo aus. Verwenden Sie diese Einstellung, wenn Ihr Logo den Namen bereits zeigt. |
| `customImage` | `"background"` | `"background"` platziert den Seitentitel über Ihrem `og:image`. `"replace"` verwendet Ihr `og:image` als vollständige Card. |

Die Card kann nur SVG-, PNG- und JPG-Logos darstellen. Jamdesk wandelt PNG- und JPG-Logodateien in Ihrem Repository beim Build Ihrer Website in WebP um. Deshalb zeigt die Card normalerweise stattdessen Ihr Favicon und behält den Seitennamen bei – auch wenn `siteName: false` gesetzt ist. Verwenden Sie ein SVG-Logo, um Ihr vollständiges Logo auf der Card anzuzeigen, und setzen Sie bei einer dunklen Card `logo.dark`.

Die Card kann keinen Text innerhalb eines SVG-Logos darstellen; der Text wird daher leer angezeigt. Wandeln Sie den Text in Ihrem Design-Tool in Pfade um und exportieren Sie das SVG erneut. Wählen Sie in Figma den Text aus und verwenden Sie **Flatten**. Wählen Sie in Illustrator **Type > Create Outlines**. Wenn der Card-Generator Text im verwendeten SVG-Logo findet, zeigt Ihr Build einen Hinweis an. Logos, die als vollständige URL (`https://...`) festgelegt sind, werden nicht überprüft.

Wenn sich Ihre Markenfarbe nicht deutlich genug von der Card abhebt, verwendet der Badge-Text stattdessen die normale Textfarbe. Die Leiste behält Ihre Markenfarbe bei, es sei denn, sie ähnelt der Hintergrundfarbe der Card zu sehr. In diesem Fall wird die Leiste grau.

Standardmäßig platziert Jamdesk den Seitentitel über Ihrem `og:image`. Wenn Ihr Bild bereits eigenen Text oder ein eigenes Design enthält, setzen Sie `"customImage": "replace"`, damit es unverändert angezeigt wird.

Wenn Ihr `og:image` als Hintergrund der Card dient, wählen Sie das passende `theme`: `dark` für ein dunkles Bild und `light` für ein helles.

Im Modus `replace` platziert Jamdesk keinen Titel auf dem Bild. Wenn `seo.metatags` ein `og:image` festlegt, verwenden es alle Seiten. Seiten mit einem eigenen `og:image` verwenden stattdessen dieses Bild. Nur Seiten ohne eines dieser Bilder erhalten eine generierte Card. Verwenden Sie ein PNG- oder JPG-Bild im Format 1200×630. Einige Plattformen zeigen keine WebP- oder SVG-Bilder an.

Soziale Netzwerke speichern Linkvorschauen im Cache. Deshalb kann ein bereits geteilter Link nach einer Änderung dieser Einstellungen eine Zeit lang weiterhin die alte Card anzeigen. Prüfen Sie die neue Card mit dem Tool
[OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Ältere Versionen der Jamdesk CLI weisen `seo.socialCard` und `seo.titleTemplate` in
`jamdesk validate` und `jamdesk dev` zurück. Aktualisieren Sie mit `npm i -g jamdesk@latest`.
</Note>

## Sitemap und Robots.txt

Jede Jamdesk-Website erstellt bei jedem Build automatisch `sitemap.xml` und `robots.txt`.

| Datei | Zweck |
|------|---------|
| `sitemap.xml` | Listet alle Seiten mit Änderungsdaten für Suchmaschinen auf |
| `robots.txt` | Erlaubt allen Crawlern den Zugriff und verweist sie auf die Sitemap |

### Wo du die Dateien findest

Die URLs hängen davon ab, ob Ihre Dokumentation unter einer Root-Domain oder in einem `/docs`-Unterpfad liegt:

<Tabs>
  <Tab title="Root-Domain">
    Liegt Ihre Dokumentation im Stammverzeichnis Ihrer Domain (z. B. `docs.acme.com` oder `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="/docs-Unterpfad">
    Liegt Ihre Dokumentation im `/docs`-Unterpfad Ihrer Hauptwebsite (wie diese Website unter `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Was die Sitemap enthält

- Alle veröffentlichten Seiten (außer Seiten mit `noindex` oder `hidden` im Frontmatter)
- Änderungsdaten aus dem Frontmatter, sofern verfügbar
- Wöchentliche Änderungsfrequenz

### Seiten aus der Sitemap ausschließen

Fügen Sie `noindex` zum Frontmatter hinzu, um eine Seite sowohl aus der Sitemap als auch aus den Suchmaschinen auszuschließen:

```yaml
---
title: Internal Notes
noindex: true
---
```

Seiten mit `hidden: true` werden ebenfalls automatisch ausgeschlossen.

## Strukturierte JSON-LD-Daten

Jede Seite enthält automatisch strukturierte Daten nach [schema.org](https://schema.org) in einem `<script type="application/ld+json">`-Tag mit zwei Schemas:

- `WebSite`: Name, URL und Beschreibung Ihrer Website (aus `docs.json`).
- `BreadcrumbList`: Navigationspfad von der Startseite zur aktuellen Seite, abgeleitet aus Ihrer `navigation`-Konfiguration.

Eine Konfiguration ist nicht erforderlich. Suchmaschinen verwenden diese Daten für umfangreiche Suchergebnisse wie Breadcrumb-Pfade in Suchergebnissen.

<Tip>
**Markup überprüfen.** Fügen Sie eine beliebige Seiten-URL in den [Rich-Suchergebnisse-Test von Google](https://search.google.com/test/rich-results) ein, um zu prüfen, ob die strukturierten Daten erkannt werden.
</Tip>

## IndexNow

Nach jedem Build übermittelt Jamdesk automatisch geänderte Seiten-URLs an [IndexNow](https://www.indexnow.org), damit Suchmaschinen sie schneller indexieren. So werden Bing, Yandex und andere teilnehmende Suchmaschinen über Änderungen an Ihren Inhalten informiert, ohne dass der nächste Crawl-Zyklus abgewartet werden muss.

- Wird nach jedem erfolgreichen Build ausgelöst
- Übermittelt nur Seiten, die tatsächlich geändert wurden
- Blockiert den Build nicht und verzögert ihn daher nie
- Keine Konfiguration erforderlich

## Bewährte Methoden

Gehen Sie diese Checkliste vor der Veröffentlichung durch:

<Note>
**Checkliste vor der Veröffentlichung**

- **Einzigartige Titel.** Jede Seite hat einen eigenen, aussagekräftigen Titel mit weniger als 60 Zeichen.
- **Präzise Beschreibungen.** Beschreibungen fassen den Seiteninhalt in 120–160 Zeichen zusammen.
- **Logische Überschriften.** Überschriften folgen einer klaren Hierarchie: eine H1, dann H2 → H3.
- **Aussagekräftige Links.** Interne Links verwenden sinnvolle Ankertexte, niemals „hier klicken“.
- **Alt-Texte für Bilder.** Jedes Bild hat einen Alt-Text für Barrierefreiheit und die Bildersuche.
- **Social-Media-Bild.** Legen Sie für wichtige Seiten ein eigenes `og:image` fest oder verwenden Sie die automatisch generierte Card. Überprüfen Sie sie mit dem Tool [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
