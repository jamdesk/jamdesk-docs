## Inhalte optimieren

### Aussagekräftiges Frontmatter verfassen

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Keywords nach vorne stellen.** „Authentifizierung einrichten“ ist besser als „So richten Sie eine Authentifizierung ein“.
</Tip>

### Seitentitel

- Halten Sie Titel unter 60 Zeichen, einschließlich des Site-Namens, den Ihr Titelformat hinzufügt. Längere Titel werden in den Suchergebnissen abgeschnitten
- Platzieren Sie Ihr wichtigstes Keyword möglichst am Anfang
- Machen Sie jeden Titel in Ihrer Dokumentation eindeutig

Standardmäßig lautet der Titel im Browser-Tab und in den Suchergebnissen `Seitentitel — Site-Name`. Ändern Sie ihn mit `seo.titleTemplate` in `docs.json`. Setzen Sie `%s` an die Stelle, an der der Seitentitel stehen soll:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Eine Seite mit dem Titel `Getting started` zeigt dann `Getting started | Acme`. Verwenden Sie `"%s"` allein, um den Site-Namen wegzulassen. Eine Vorlage ohne `%s` lässt den Build fehlschlagen. `jamdesk validate` zeigt den Fehler an. Link-Vorschauen (`og:title` und `twitter:title`) zeigen weiterhin nur den Seitentitel.

Manche Seiten verwenden die Vorlage nicht. Eine Seite ohne `title` zeigt Ihren `name` gefolgt von „Documentation“, etwa `Acme Documentation`, oder nur Ihren `name`, wenn dieser bereits auf „Docs“ oder „Documentation“ endet. Eine Seite, deren Titel mit Ihrem `name` identisch ist, zeigt nur diesen Titel.

`jamdesk validate` und `jamdesk dev` akzeptieren `seo.titleTemplate` ab CLI-Version 1.1.220. Aktualisieren Sie mit `npm i -g jamdesk@latest`.

### Beschreibungen

- Zielen Sie auf 120–160 Zeichen
- Fassen Sie zusammen, was die Leserin oder der Leser lernen wird
- Integrieren Sie relevante Keywords natürlich

<Note>
**Automatischer Ersatz.** Jamdesk extrahiert den ersten Fließtextabsatz Ihrer Seite (bis zu 155 Zeichen), wenn `description` im Frontmatter fehlt. Überschriften, Code-Blöcke, Bilder und MDX-Komponenten werden übersprungen. Dieser Text wird in `<meta name="description">`, Open Graph und Twitter-Cards eingesetzt. Eine explizite Beschreibung liefert weiterhin die besten Ergebnisse.
</Note>

## Indexierung steuern

### Einstellungen für die gesamte Website

Legen Sie das Standardverhalten der Robots in `docs.json` fest:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Einstellungen für einzelne Seiten

Überschreiben Sie die Indexierung für bestimmte Seiten im Frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Verwenden Sie `noindex` für:
- Entwurfs- oder Arbeitsstand-Seiten
- Interne Dokumentation
- Veraltete Inhalte, die Sie als Referenz behalten

### Suchmaschinenindexierung und KI-Verarbeitung

`robots`-Metadaten und `noindex` steuern **Suchmaschinen**: ob eine Seite in Google und in Ihrer `sitemap.xml` erscheint. Sie haben keinen Einfluss auf die Dateien `llms.txt` und `llms-full.txt`, die KI-Tools lesen. Setzen Sie `seo.ai.llmsTxt` auf `false`, um deren Veröffentlichung zu beenden (siehe [llms.txt deaktivieren](/de/ai/llms-txt#llmstxt-deaktivieren)). Die beiden Steuerungen sind unabhängig voneinander: Eine Seite kann von Suchmaschinen indexiert, aber von der KI-Ingestion ausgeschlossen werden, oder umgekehrt.

## Kanonische URLs

Setzen Sie eine Canonical-URL, wenn Ihre Dokumentation unter mehreren URLs erreichbar ist:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Sie können außerdem eine site-weite Canonical-Basis in `docs.json` festlegen. Jamdesk hängt den Pfad jeder Seite daran an:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Social-Media-Vorschauen und Open Graph

Jamdesk erzeugt für jede Seite eine gebrandete Social-Card mit 1200×630 Pixeln. Überschreiben Sie jedes Social-Tag im Frontmatter mit flachen Schlüsseln auf oberster Ebene oder einem verschachtelten `seo:`-Block. Der flache Wert auf oberster Ebene gewinnt, wenn derselbe Schlüssel auf beide Arten gesetzt ist.

<Card title="OpenGraph-Vorschau" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Zeigen Sie die Card einer beliebigen Seite für X, Facebook, LinkedIn und mehr an. Validieren Sie deren Open-Graph-Tags.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Unterstützte Tags

| Gruppe | Tags |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artikel | `og:type: article` mit `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, App-Card-Tags |
| Sonstige | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color`, sowie jeder benutzerdefinierte Tag (benutzerdefinierte Tags unter `seo:` ablegen) |

<Note>
**Benutzerdefinierte OG-Bildmaße.** `og:image:width` und `og:image:height` gelten nur, wenn [`customImage`](#social-card-anpassen) auf `"replace"` steht. Setzen Sie sie an derselben Stelle wie das `og:image`, das sie beschreiben, entweder im Seiten-Frontmatter oder in `seo.metatags`. Die generierte Card ist immer 1200×630.
</Note>

<Note>
**Benutzerdefinierte Tags.** Beliebige Meta-Tags (z. B. `x-pinterest`) werden als `<meta name="...">` ausgegeben. Platzieren Sie sie unter dem Block `seo:`. Nur erkannte SEO-Schlüssel werden übernommen, wenn sie flach stehen.
</Note>

### Twitter-/X-Kartentyp

Das Tag `twitter:card` steuert das Layout, das X (und andere Plattformen) beim Teilen Ihres Links verwenden:

| Wert | Aussehen |
|-------|--------------------|
| `summary` | Kleine quadratische Vorschau links, Titel + Beschreibung daneben. Kompakt. |
| `summary_large_image` | Großes Bild über die volle Breite oben, Titel + Beschreibung darunter. |

Verwenden Sie `summary_large_image` für eine gebrandete 1200×630-Card. Das Bild wird dann in voller Breite dargestellt.

### Standardbild für die gesamte Website

Legen Sie in `docs.json` ein Ersatzbild für soziale Netzwerke für jede Seite fest. Jede Seite, die ein eigenes `og:image` setzt, überschreibt es:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Vor der Veröffentlichung prüfen.** Fügen Sie die Seiten-URL nach einem Build in das Tool [OpenGraph-Vorschau](https://jamdesk.com/utilities/opengraph-preview) ein. Es zeigt, wie die Card auf den einzelnen Plattformen dargestellt wird, und validiert die Open-Graph-Tags. Außerdem prüft es die Bildmaße und erklärt, wie Probleme behoben werden.
</Tip>

### Social Card anpassen

Ihre generierte Card behält ihr aktuelles Aussehen, sofern Sie nicht `seo.socialCard` in `docs.json` ergänzen. Setzen Sie nur die Schlüssel, die Sie ändern möchten:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Schlüssel | Standard | Wirkung |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` verwendet helle Schrift auf dunklem Hintergrund und Ihr Bild `logo.dark`. |
| `brandColor` | `false` | `true` färbt die untere Leiste und das Bereichs-Badge mit `colors.primary` ein. Eine dunkle Card verwendet `colors.light`, falls Sie es setzen. Ohne `colors` verwendet die Card die Akzentfarbe Ihres Themes. `false` behält das Standardrot bei. |
| `accentBar` | `true` | `false` entfernt die farbige Leiste am unteren Rand der Card. |
| `siteName` | `true` | `false` blendet den Site-Namen unter dem Logo aus. Nutzen Sie dies, wenn Ihr Logo den Namen bereits zeigt. |
| `customImage` | `"background"` | `"background"` zeichnet den Seitentitel über Ihr `og:image`. `"replace"` verwendet Ihr `og:image` als gesamte Card. |

Die Card kann nur SVG-, PNG- und JPG-Logos darstellen. Jamdesk wandelt PNG- und JPG-Logodateien in Ihrem Repository beim Build in WebP um. Die Card zeigt dann meist stattdessen Ihr Favicon und behält den Site-Namen bei, selbst mit `siteName: false`. Verwenden Sie ein SVG-Logo, damit Ihr vollständiges Logo auf der Card erscheint. Verwenden Sie für eine dunkle Card ein SVG als `logo.dark`.

Die Card kann keinen Text innerhalb eines SVG-Logos darstellen. Dieser Text erscheint leer. Wandeln Sie den Text in Ihrem Designprogramm in Pfade um und exportieren Sie das SVG erneut. In Figma wählen Sie den Text und verwenden **Flatten**. In Illustrator verwenden Sie **Type > Create Outlines**. Der Build zeigt einen Hinweis, wenn er Text im SVG-Logo der Card findet. Logos, die als vollständige URL (`https://...`) festgelegt sind, werden nicht geprüft.

Die Badge-Schrift fällt auf die normale Textfarbe zurück, wenn sich Ihre Markenfarbe nicht genügend vom Hintergrund der Card abhebt. Die Leiste behält Ihre Markenfarbe, sofern sie dem Kartenhintergrund nicht nahezu gleicht. In diesem Fall ist die Leiste grau.

Standardmäßig zeichnet Jamdesk den Seitentitel über Ihr `og:image`. Setzen Sie `"customImage": "replace"`, um ein Bild mit eigenem Text oder Design unverändert anzuzeigen.

Wählen Sie das `theme`, das zu einem `og:image` als Card-Hintergrund passt: `dark` für ein dunkles Bild, `light` für ein helles.

Im Modus `replace` zeichnet Jamdesk keinen Titel auf das Bild. Ein `og:image` in `seo.metatags` gilt für jede Seite. Eine Seite, die ein eigenes `og:image` setzt, verwendet dieses stattdessen. Nur Seiten ohne beides erhalten eine generierte Card. Verwenden Sie ein PNG oder JPG mit 1200×630. Einige Plattformen zeigen keine WebP- oder SVG-Bilder an.

Social-Media-Plattformen speichern Link-Vorschauen zwischen. Ein bereits geteilter Link kann nach Änderungen dieser Einstellungen noch eine Zeit lang die alte Card zeigen. Prüfen Sie die neue Card mit dem Tool [OpenGraph-Vorschau](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Ältere Versionen der Jamdesk-CLI lehnen `seo.socialCard` und `seo.titleTemplate` in `jamdesk validate` und `jamdesk dev` ab. Aktualisieren Sie mit `npm i -g jamdesk@latest`.
</Note>

## Sitemap und Robots.txt

Jamdesk erzeugt bei jedem Build `sitemap.xml` und `robots.txt`.

| Datei | Zweck |
|------|---------|
| `sitemap.xml` | Listet alle Seiten mit Datum der letzten Änderung für Suchmaschinen auf |
| `robots.txt` | Erlaubt allen Crawlern den Zugriff und verweist sie auf die Sitemap |

### Wo du die Dateien findest

Die URLs hängen davon ab, ob Ihre Dokumentation auf einer Root-Domain oder unter einem Unterpfad `/docs` liegt:

<Tabs>
  <Tab title="Root-Domain">
    Wenn Ihre Dokumentation auf der Root-Domain liegt (z. B. `docs.acme.com` oder `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Unterpfad /docs">
    Wenn Ihre Dokumentation unter `/docs` auf Ihrer Hauptseite liegt (wie diese Seite unter `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Was die Sitemap enthält

- Alle veröffentlichten Seiten (ohne solche mit `noindex`- oder `hidden`-Frontmatter)
- Datum der letzten Änderung aus dem Frontmatter, wenn verfügbar
- Wöchentliche Änderungsfrequenz

### Seiten aus der Sitemap ausschließen

Fügen Sie `noindex` im Frontmatter hinzu, damit eine Seite nicht in der Sitemap und in Suchmaschinen erscheint:

```yaml
---
title: Internal Notes
noindex: true
---
```

Seiten mit `hidden: true` werden ebenfalls ausgeschlossen.

## Strukturierte JSON-LD-Daten

Jede Seite enthält [schema.org](https://schema.org)-Strukturdaten als `<script type="application/ld+json">`-Tag mit zwei Schemata:

- `WebSite`: Ihr Site-Name, Ihre URL und Beschreibung (aus `docs.json`).
- `BreadcrumbList`: Navigationspfad von Startseite zur aktuellen Seite, abgeleitet aus Ihrer `navigation`-Konfiguration.

Es ist keine Konfiguration nötig. Suchmaschinen nutzen dies für Rich Results wie Breadcrumb-Pfade in den Suchergebnissen.

<Tip>
**Markup prüfen.** Fügen Sie eine beliebige Seiten-URL in [Googles Rich-Results-Test](https://search.google.com/test/rich-results) ein, um zu bestätigen, dass die Strukturdaten erkannt werden.
</Tip>

## IndexNow

Jamdesk übermittelt nach jedem Build geänderte Seiten-URLs an [IndexNow](https://www.indexnow.org). Bing, Yandex und andere teilnehmende Suchmaschinen erfahren von den Änderungen, ohne auf ihren nächsten Crawl-Zyklus warten zu müssen.

- Wird nach jedem erfolgreichen Build ausgelöst
- Übermittelt nur geänderte Seiten
- Nicht blockierend. Es verzögert Ihren Build nie
- Keine Konfiguration erforderlich

## Bewährte Methoden

Gehen Sie vor der Veröffentlichung diese Checkliste durch:

<Note>
**Checkliste vor der Veröffentlichung**

- **Eindeutige Titel:** Jede Seite hat einen eigenen, beschreibenden Titel unter 60 Zeichen.
- **Präzise Beschreibungen:** Beschreibungen fassen die Seite in 120–160 Zeichen zusammen.
- **Logische Überschriften:** Überschriften folgen einer klaren Hierarchie: eine H1, dann H2 → H3.
- **Beschreibende Links:** Interne Links verwenden aussagekräftigen Linktext, niemals „hier klicken“.
- **Alt-Text für Bilder:** Jedes Bild hat Alt-Text für Barrierefreiheit und Bildersuche.
- **Social-Bild:** Setzen Sie auf wichtigen Seiten ein eigenes `og:image` oder verlassen Sie sich auf die automatisch erzeugte Card. Prüfen Sie es mit dem Tool [OpenGraph-Vorschau](https://jamdesk.com/utilities/opengraph-preview).
</Note>
