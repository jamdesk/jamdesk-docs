## Inhalte optimieren

### Aussagekräftiges Frontmatter verfassen

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Wichtige Schlüsselwörter an den Anfang setzen.** „Authentication setup“ ist besser als „How to set up authentication“.
</Tip>

### Seitentitel

- Halten Sie Titel unter 60 Zeichen, damit sie in Suchergebnissen nicht abgeschnitten werden.
- Platzieren Sie Ihr wichtigstes Schlüsselwort möglichst weit vorn.
- Verwenden Sie für jede Seite Ihrer Dokumentation einen eigenen Titel.

Standardmäßig lautet der Titel im Browser-Tab und im Suchergebnis `Page title — Site name`. Ändern Sie ihn, indem Sie `seo.titleTemplate` in `docs.json` festlegen. Jedes `%s` wird durch den Seitentitel ersetzt:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Verwenden Sie nur `"%s"`, wenn der Name der Website nicht angezeigt werden soll. Die Vorlage ändert nur den Titel im Browser-Tab und im Suchergebnis. Der Titel in Social-Media-Vorschauen (`og:title`) bleibt unverändert. Bei einer Seite ohne Titel oder mit einem Titel, der dem Namen der Website entspricht, wird der Website-Titel unverändert angezeigt.

### Beschreibungen

- Zielen Sie auf 120–160 Zeichen ab.
- Fassen Sie zusammen, was Leser erfahren.
- Verwenden Sie passende Schlüsselwörter auf natürliche Weise.

<Note>
**Automatischer Ersatzwert.** Fehlt `description` im Frontmatter, extrahiert Jamdesk automatisch den ersten Fließtextabsatz Ihrer Seite (bis zu 155 Zeichen). Überschriften, Codeblöcke, Bilder und MDX-Komponenten werden übersprungen. Der Text wird für `<meta name="description">`, Open Graph und Twitter Cards verwendet. Für optimale Ergebnisse empfiehlt sich weiterhin eine eigene Beschreibung.
</Note>

## Indexierung steuern

### Einstellungen für die gesamte Website

Konfigurieren Sie in Ihrer `docs.json` das Standardverhalten für Robots:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Einstellungen für einzelne Seiten

Überschreiben Sie die Indexierung für bestimmte Seiten im Frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Verwenden Sie `noindex` für:
- Entwürfe oder Seiten in Bearbeitung
- Interne Dokumentation
- Veraltete Inhalte, die Sie zu Referenzzwecken behalten

### Suchmaschinenindexierung und KI-Verarbeitung

`robots`-Metadaten und `noindex` steuern **Suchmaschinen**: Sie legen fest, ob eine Seite bei Google und in Ihrer `sitemap.xml` erscheint. Sie wirken sich nicht auf die Dateien `llms.txt` und `llms-full.txt` aus, die von KI-Tools gelesen werden. Um deren Veröffentlichung zu verhindern, setzen Sie `seo.ai.llmsTxt` auf `false` (siehe [llms.txt deaktivieren](/de/ai/llms-txt#llmstxt-deaktivieren)). Die beiden Einstellungen sind unabhängig voneinander: Eine Seite kann von Suchmaschinen indexiert, aber von der KI-Verarbeitung ausgeschlossen werden – oder umgekehrt.

## Kanonische URLs

Wenn Ihre Dokumentation unter mehreren URLs erreichbar ist, legen Sie eine Canonical-URL fest:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Sie können in `docs.json` auch eine websiteweite Canonical-Basis festlegen. Jamdesk hängt den Pfad jeder Seite daran an, sodass jede Seite eine korrekte eigene Canonical-URL erhält:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Social-Media-Vorschauen und Open Graph

Jamdesk erstellt automatisch für jede Seite eine gebrandete Social Card im Format 1200×630. Überschreiben Sie beliebige Social-Tags im Frontmatter. Sie können **einfache Top-Level-Schlüssel** oder einen verschachtelten **`seo:`-Block** verwenden. Beides funktioniert. Ist derselbe Schlüssel an beiden Stellen gesetzt, hat der Top-Level-Wert Vorrang.

<Card title="OpenGraph Preview" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Sehen Sie sich mit dem OpenGraph Preview-Tool an, wie die Card einer beliebigen Seite auf X, Facebook, LinkedIn und weiteren Plattformen dargestellt wird, und überprüfen Sie deren Open-Graph-Tags.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Unterstützte Tags

| Gruppe | Tags |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artikel | `og:type: article` mit `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, App-Card-Tags |
| Sonstige | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` sowie beliebige eigene Tags (eigene Tags unter `seo:` platzieren) |

<Note>
**Benutzerdefinierte OG-Bildabmessungen.** `og:image:width` und `og:image:height` gelten nur, wenn
[`customImage`](#social-card-anpassen) auf `"replace"` gesetzt ist. Legen Sie sie an derselben Stelle wie das zugehörige
`og:image` fest – entweder im Frontmatter der Seite oder unter `seo.metatags`. Die erstellte
Card hat immer das Format 1200×630.
</Note>

<Note>
**Eigene Tags.** Beliebige Meta-Tags (z. B. `x-pinterest`) werden als `<meta name="...">` ausgegeben.
Fügen Sie sie unter dem `seo:`-Block ein. Wenn sie auf oberster Ebene stehen, werden nur erkannte SEO-Schlüssel berücksichtigt.
</Note>

### Twitter-/X-Kartentyp

Der Tag `twitter:card` legt fest, welches Layout X und andere Plattformen beim Teilen Ihres Links verwenden:

| Wert | Darstellung |
|-------|--------------------|
| `summary` | Kleines quadratisches Vorschaubild links, daneben Titel und Beschreibung. Kompakt. |
| `summary_large_image` | Großes, bildschirmbreites Bild oben, darunter Titel und Beschreibung. Die auffällige Variante. |

Verwenden Sie für eine gebrandete Card im Format 1200×630 `summary_large_image`, damit das Bild in voller Breite angezeigt wird.

### Standardbild für die gesamte Website

Legen Sie in `docs.json` ein Social-Media-Ersatzbild für alle Seiten fest. Seiten mit einem eigenen `og:image` verwenden stattdessen dieses:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Vor der Veröffentlichung prüfen.** Fügen Sie nach einem Build die Seiten-URL in das Tool [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) ein, um die Darstellung der Card auf den einzelnen Plattformen zu überprüfen und die Open-Graph-Tags zu validieren. Das Tool prüft auch die Bildabmessungen und erklärt, wie Sie gefundene Probleme beheben.
</Tip>

### Social Card anpassen

Die erstellte Card behält ihr aktuelles Aussehen bei, sofern Sie `seo.socialCard` nicht in `docs.json` hinzufügen.
Legen Sie nur die Schlüssel fest, die Sie ändern möchten:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Schlüssel | Standard | Wirkung |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` verwendet helle Schrift auf dunklem Hintergrund und Ihr `logo.dark`-Bild. |
| `brandColor` | `false` | `true` färbt die untere Leiste und das Abschnitts-Badge mit `colors.primary`. Bei einer dunklen Card wird `colors.light` verwendet, sofern festgelegt. Wenn Sie keine `colors` festgelegt haben, verwendet die Card die Akzentfarbe Ihres Themes. `false` behält das standardmäßige Rot bei. |
| `accentBar` | `true` | `false` entfernt die farbige Leiste am unteren Rand der Card. |
| `siteName` | `true` | `false` blendet den Website-Namen unter dem Logo aus. Verwenden Sie diese Einstellung, wenn Ihr Logo den Namen bereits enthält. |
| `customImage` | `"background"` | `"background"` zeigt den Seitentitel über Ihrem `og:image` an. `"replace"` verwendet Ihr `og:image` als vollständige Card. |

Die Card kann nur SVG-, PNG- und JPG-Logos darstellen. Jamdesk konvertiert PNG- und JPG-Logodateien in Ihrem Repository beim Build Ihrer Website in WebP. Daher zeigt die Card normalerweise stattdessen Ihr Favicon an und behält den Website-Namen bei – auch mit `siteName: false`. Verwenden Sie ein SVG-Logo, um Ihr vollständiges Logo auf der Card anzuzeigen, und `logo.dark` für eine dunkle Card.

Die Card kann keinen Text innerhalb eines SVG-Logos darstellen. Wenn Ihr Logo Text enthält, wandeln Sie ihn vor dem Export in Pfade um. Findet Ihr Build Text im verwendeten SVG-Logo, schlägt er diese Änderung vor. Logos, die von einer anderen Website eingebunden werden, werden nicht überprüft.

Wenn sich Ihre Markenfarbe nicht deutlich genug von der Card abhebt, wird für den Badge-Text die normale Textfarbe verwendet. Die Leiste behält Ihre Markenfarbe bei, solange sie sich deutlich genug vom Hintergrund der Card unterscheidet. Andernfalls wird die Leiste grau.

Standardmäßig platziert Jamdesk den Seitentitel über Ihrem `og:image`. Enthält Ihr Bild bereits Text oder ein eigenes Design, setzen Sie `"customImage": "replace"`, damit es unverändert angezeigt wird.

Wenn Ihr `og:image` als Hintergrund der Card dient, wählen Sie das passende `theme`: `dark` für ein dunkles Bild, `light` für ein helles.

Im Modus `replace` fügt Jamdesk keinen Titel auf dem Bild ein. Wenn `seo.metatags` ein `og:image` festlegt, verwenden alle Seiten dieses Bild. Seiten mit einem eigenen `og:image` verwenden stattdessen ihr Bild. Nur Seiten, für die keines von beiden festgelegt ist, erhalten eine generierte Card. Verwenden Sie ein PNG- oder JPG-Bild im Format 1200×630. Manche Plattformen zeigen keine WebP- oder SVG-Bilder an.

Soziale Netzwerke speichern Link-Vorschauen zwischen. Deshalb kann ein bereits geteilter Link nach einer Änderung dieser Einstellungen eine Weile weiterhin die alte Card anzeigen. Prüfen Sie die neue Card mit dem Tool
[OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Ältere Versionen der Jamdesk CLI weisen `seo.socialCard` und `seo.titleTemplate` in
`jamdesk validate` und `jamdesk dev` zurück. Führen Sie das Upgrade mit `npm i -g jamdesk@latest` durch.
</Note>

## Sitemap und Robots.txt

Jede Jamdesk-Website erstellt bei jedem Build automatisch `sitemap.xml` und `robots.txt`.

| Datei | Zweck |
|------|---------|
| `sitemap.xml` | Listet alle Seiten mit Änderungsdaten für Suchmaschinen auf |
| `robots.txt` | Erlaubt allen Crawlern den Zugriff und verweist sie auf die Sitemap |

### Wo du die Dateien findest

Die URLs hängen davon ab, ob Ihre Dokumentation auf einer Root-Domain oder unter einem `/docs`-Unterpfad liegt:

<Tabs>
  <Tab title="Root domain">
    Wenn sich Ihre Dokumentation im Stammverzeichnis Ihrer Domain befindet (z. B. `docs.acme.com` oder `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="/docs subpath">
    Wenn sich Ihre Dokumentation unter `/docs` auf Ihrer Hauptwebsite befindet (wie auf dieser Website unter `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Was die Sitemap enthält

- Alle veröffentlichten Seiten (außer solchen mit `noindex` oder `hidden` im Frontmatter)
- Änderungsdaten aus dem Frontmatter, sofern verfügbar
- Wöchentliche Änderungsfrequenz

### Seiten aus der Sitemap ausschließen

Fügen Sie `noindex` zum Frontmatter hinzu, um eine Seite sowohl aus der Sitemap als auch aus den Suchmaschinen auszuschließen:

```yaml
---
title: Internal Notes
noindex: true
---
```

Seiten mit `hidden: true` werden ebenfalls automatisch ausgeschlossen.

## Strukturierte JSON-LD-Daten

Jede Seite enthält automatisch strukturierte [schema.org](https://schema.org)-Daten als `<script type="application/ld+json">`-Tag mit zwei Schemas:

- `WebSite`: Name, URL und Beschreibung Ihrer Website (aus `docs.json`).
- `BreadcrumbList`: Navigationspfad von der Startseite zur aktuellen Seite, abgeleitet aus Ihrer `navigation`-Konfiguration.

Eine Konfiguration ist nicht erforderlich. Suchmaschinen verwenden diese Daten für erweiterte Suchergebnisse, zum Beispiel Breadcrumb-Navigationspfade in Suchergebnissen.

<Tip>
**Markup überprüfen.** Fügen Sie eine beliebige Seiten-URL in den [Rich Results-Test von Google](https://search.google.com/test/rich-results) ein, um zu prüfen, ob die strukturierten Daten erkannt werden.
</Tip>

## IndexNow

Nach jedem Build übermittelt Jamdesk automatisch geänderte Seiten-URLs an [IndexNow](https://www.indexnow.org), damit Suchmaschinen die Seiten schneller indexieren. Bing, Yandex und andere teilnehmende Suchmaschinen werden so über Änderungen an Ihren Inhalten informiert, ohne dass der nächste Crawling-Zyklus abgewartet werden muss.

- Wird nach jedem erfolgreichen Build ausgelöst
- Übermittelt nur tatsächlich geänderte Seiten
- Blockiert den Build nicht und verzögert ihn daher nie
- Keine Konfiguration erforderlich

## Bewährte Methoden

Gehen Sie diese Checkliste vor der Veröffentlichung durch:

<Note>
**Checkliste vor der Veröffentlichung**

- **Eindeutige Titel.** Jede Seite hat einen eigenen, aussagekräftigen Titel mit weniger als 60 Zeichen.
- **Präzise Beschreibungen.** Beschreibungen fassen die Seite in 120–160 Zeichen zusammen.
- **Logische Überschriften.** Die Überschriften folgen einer klaren Hierarchie: eine H1, dann H2 → H3.
- **Aussagekräftige Links.** Interne Links verwenden sinnvolle Ankertexte, niemals „hier klicken“.
- **Alternativtexte für Bilder.** Jedes Bild hat einen Alternativtext für Barrierefreiheit und die Bildersuche.
- **Social-Media-Bild.** Legen Sie auf wichtigen Seiten ein eigenes `og:image` fest oder verwenden Sie die automatisch erstellte Card. Überprüfen Sie sie mit dem Tool [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
