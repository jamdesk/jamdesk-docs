---
title: Versteckte Seiten
description: Blende Seiten aus Sidebar und Suchergebnissen aus, ohne sie zu löschen. Steuere die Sichtbarkeit über Frontmatter, docs.json oder SEO-Einstellungen.
---

Manche Seiten gehören nicht in die öffentliche Sidebar: Entwürfe, interne Handbücher, veraltete Anleitungen, auf die du trotzdem verlinken musst. Versteckte Seiten bleiben über die direkte URL erreichbar, verschwinden aber aus der Navigation, der Suche, deiner Sitemap und dem KI-Kontext, der an LLMs übergeben wird.

## Eine einzelne Seite ausblenden

Füge `hidden: true` zum Frontmatter der Seite hinzu:

```mdx
---
title: Internal handbook
hidden: true
---
```

Die Seite wird weiterhin unter ihrer URL gerendert. Jamdesk:

- Entfernt sie aus der Sidebar
- Fügt `<meta name="robots" content="noindex, follow">` hinzu, damit Suchmaschinen sie überspringen
- Schließt sie aus `sitemap.xml`, `llms.txt`, `llms-full.txt` und der Suche auf der Website aus

## Eine ganze Gruppe oder einen Tab ausblenden

Setze `"hidden": true` für eine Gruppe oder einen Tab in `docs.json`:

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Public",
        "groups": [{ "group": "Guides", "pages": ["intro", "quickstart"] }]
      },
      {
        "tab": "Internal",
        "hidden": true,
        "groups": [{ "group": "Runbooks", "pages": ["oncall", "postmortems"] }]
      }
    ]
  }
}
```

Jede Seite unterhalb des versteckten Knotens übernimmt die Regel. Dasselbe Flag funktioniert für `tabs`, `groups`, `anchors`, `dropdowns`, `products`, `languages` und `versions`.

## Verborgene Seiten in der Suche behalten

Füge `"searchable": true` hinzu, damit ein versteckter Tab oder eine versteckte Gruppe für die Website-Suche, KI-Antworten und die Sitemap indexiert bleibt:

```json
{
  "tab": "Internal",
  "hidden": true,
  "searchable": true,
  "groups": [{ "group": "Runbooks", "pages": ["oncall"] }]
}
```

Ein `hidden: true` im Frontmatter einer untergeordneten Seite hat weiterhin Vorrang. `searchable` öffnet nur Nachfahren wieder, die sich nicht selbst abgemeldet haben.

## Eine Seite nur aus der Suche entfernen

Füge `search: false` zum Frontmatter einer Seite hinzu, die in der Sidebar bleiben und indexierbar sein soll, aber nicht in der Website-Suche oder in KI-Antworten auftauchen darf:

```yaml
---
title: Legacy v1 endpoints
search: false
---
```

Die Seite behält ihren Platz in der Navigation, in deiner Sitemap, in `llms.txt` und in deinem RSS-Feed. Suchmaschinen indexieren sie weiterhin. Sie verschwindet nur aus den *Abfrage*-Oberflächen: der Suche auf der Website, den Antworten des KI-Chats und dem MCP-Server.

<Note>
`search: false` hat die entgegengesetzte Aufgabe zu `hidden: true`. `hidden` nimmt eine Seite aus der Navigation und den Indexierungs-Oberflächen heraus. `search: false` lässt all das unberührt und verhindert nur, dass die Seite abgerufen wird. Verwechsle es nicht mit der navigationsweiten Option `searchable`, die versteckte Seiten wieder *in* die Suche aufnimmt.
</Note>

## Wie viel von einer Seite indexiert wird

Die Suche indexiert eine Seite nicht als einen Block. Sie indexiert sie **abschnittsweise**. Jede Überschrift wird zu einem eigenen Sucheintrag. Eine Suche nach „Rate limits“ landet direkt bei dieser Überschrift und nicht am Anfang einer langen Seite.

Zwei Grenzen gelten automatisch:

| Grenze | Wert | Was passiert darüber hinaus |
|---|---|---|
| Einträge pro Seite | 50 | Abschnitte werden in Seitenreihenfolge indexiert. Abschnitte ab dem 50. werden von der Suche ausgeschlossen. |
| Text pro Abschnitt | Die ersten 300 Zeichen | Formulierungen weiter hinten im Abschnitt werden nicht gefunden. |

Die Seite selbst belegt einen der 50 Plätze, also werden 49 Abschnitte indexiert.

Die Obergrenze existiert, weil die Suche jeden Eintrag gegen den Rest deines Index gewichtet. Wenn eine einzelne Seite Hunderte Einträge erzeugt, verdrängt sie die anderen aus den Ergebnissen. Ein generiertes Changelog kann die Hälfte eines Index füllen und relevante Seiten vom ersten Bildschirm verdrängen.

<Warning>
Eine Seite über der Grenze wird weiterhin vollständig gerendert. Nur ihre späteren Abschnitte werden nicht mehr auffindbar, und nichts auf der Seite zeigt deinen Lesern das an.

Teile eine Seite mit mehr als ~50 Überschriften in mehrere Seiten auf. Das verbessert auch die Navigation. Für eine maschinell erzeugte Seite, die niemand von Hand durchsucht, setze stattdessen `search: false`, um die gesamte Seite aus dem Index herauszuhalten.
</Warning>

Platziere einen Begriff dort, wo die Suche ihn am stärksten gewichtet: der Seitentitel (höchste Gewichtung), dann eine Überschrift, dann die Beschreibung. Der Fließtext wird am niedrigsten gewichtet. Nur seine ersten 300 Zeichen pro Abschnitt zählen.

<Note>
`seo.metatags.keywords` fließt *nicht* in die Website-Suche ein. Es erzeugt ein HTML-`<meta name="keywords">`-Tag. Google hat erklärt, dass es dieses Tag für das Ranking ignoriert. Du kannst einer Seite keine zusätzlichen Suchbegriffe anhängen. Setze die Wörter, nach denen gesucht werden soll, in den Titel, eine Überschrift oder die Beschreibung.
</Note>

## Projektweite Steuerungen

Diese Flags befinden sich unter `seo` in `docs.json`:

| Flag | Standard | Wirkung |
|---|---|---|
| `seo.indexing` | `"navigable"` | Nur Seiten, die in deiner Navigation aufgeführt sind, erscheinen in den Artefakten. Setze `"all"`, um jede MDX-Datei in deinem Repository einzubeziehen. |
| `seo.indexHiddenPages` | `false` | Setze `true`, um Seiten mit `hidden: true` in Sitemap, llms.txt und Suche aufzunehmen und das automatische noindex-Tag zu entfernen. |

Beispiel:

```json
{
  "seo": {
    "indexing": "all"
  }
}
```

## Schnellreferenz

| Szenario | Frontmatter | docs.json | In der Sidebar sichtbar | Direkte URL | In der Sitemap |
|---|---|---|---|---|---|
| Normale Seite | - | aufgeführt | Ja | Ja | Ja |
| Versteckt über Frontmatter | `hidden: true` | aufgeführt | Nein | Ja | Nein |
| Seite nicht in der Navigation (verwaist) | - | fehlt | Nein | Ja | Nein |
| Versteckte Gruppe | - | `hidden: true` an der Gruppe | Nein | Ja | Nein |
| Versteckte, durchsuchbare Gruppe | - | `hidden: true, searchable: true` | Nein | Ja | Ja |
| Nur aus der Suche ausgeschlossen | `search: false` | aufgeführt | Ja | Ja | Ja |
| Projekt aktiviert Indexierung aller Seiten | - | beliebig | Wie oben | Ja | Ja |

## Wann welche Option verwendet wird

- **Entwürfe und Vorschauen:** `hidden: true` im Frontmatter einzelner Seiten
- **Interne Bereiche** für ein kleines Team: eine versteckte Gruppe oder ein versteckter Tab
- **Compliance-Dokumente**, die öffentlich, aber nicht prominent sein sollen: versteckte Gruppe mit `searchable: true`
- **Vollständige Indexierung des Repositories** nur für KI-Grounding: `seo.indexing: "all"`
- **Abgelöste Seiten**, die verlinkbar und indexiert bleiben sollen, aber nicht von Suche oder KI hervorgehoben werden: `search: false` im Frontmatter

Versteckte Seiten sind keine Zugriffskontrolle. Jeder, der die URL kennt, kann sie lesen. Für Zugriffskontrolle siehe [Passwortschutz](/de/setup/password-protection).
