---
title: Ausgeblendete Seiten
description: Seiten aus Seitenleiste und Suche ausblenden, ohne sie zu löschen. Sichtbarkeit per Frontmatter, docs.json oder SEO-Steuerung verwalten.
---

Manche Seiten gehören nicht in die öffentliche Seitenleiste: Entwürfe, interne Handbücher oder veraltete Leitfäden, auf die Sie weiterhin verlinken müssen. Ausgeblendete Seiten bleiben über ihre direkte URL erreichbar, verschwinden aber aus Navigation, Suche, Sitemap und dem KI-Kontext, der an LLMs übergeben wird.

## Einzelne Seite ausblenden

Fügen Sie `hidden: true` zum Frontmatter der Seite hinzu:

```mdx
---
title: Internal handbook
hidden: true
---
```

Die Seite wird weiterhin normal dargestellt, wenn jemand ihre URL aufruft. Jamdesk:

- Entfernt sie aus der Seitenleiste
- Fügt `<meta name="robots" content="noindex, follow">` hinzu, damit Suchmaschinen sie überspringen
- Schließt sie aus `sitemap.xml`, `llms.txt`, `llms-full.txt` und der Website-Suche aus

## Eine gesamte Gruppe oder einen Tab ausblenden

Setzen Sie `"hidden": true` für eine Gruppe oder einen Tab in `docs.json`:

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Public",
        "groups": [{ "group": "Guides", "pages": ["intro", "quickstart"] }]
      },
      {
        "tab": "Internal",
        "hidden": true,
        "groups": [{ "group": "Runbooks", "pages": ["oncall", "postmortems"] }]
      }
    ]
  }
}
```

Jede Seite unterhalb des ausgeblendeten Knotens übernimmt diese Regel. Dasselbe Flag funktioniert für `tabs`, `groups`, `anchors`, `dropdowns`, `products`, `languages` und `versions`.

## Ausgeblendete Seiten in der Suche behalten

Wenn ein ausgeblendeter Tab oder eine ausgeblendete Gruppe aus der Seitenleiste, aber weiterhin für die Website-Suche, KI-Antworten und die Sitemap indexiert werden soll, fügen Sie `"searchable": true` hinzu:

```json
{
  "tab": "Internal",
  "hidden": true,
  "searchable": true,
  "groups": [{ "group": "Runbooks", "pages": ["oncall"] }]
}
```

`hidden: true` im Frontmatter einer untergeordneten Seite hat weiterhin Vorrang. `searchable` nimmt nur Nachfahren wieder auf, die sich nicht selbst abgemeldet haben.

## Eine Seite nur aus der Suche entfernen

Manchmal soll eine Seite in der Seitenleiste bleiben und weiterhin indexierbar sein, aber nicht mehr angezeigt werden, wenn jemand danach sucht oder eine Frage stellt. Fügen Sie `search: false` zum Frontmatter hinzu:

```yaml
---
title: Legacy v1 endpoints
search: false
---
```

Die Seite behält ihren Platz in Navigation, Sitemap, `llms.txt` und Ihrem RSS-Feed und wird weiterhin von Suchmaschinen indexiert. Entfernt wird sie nur aus den *Auffindbarkeitsflächen*: der Website-Suche, KI-Chat-Antworten und dem MCP-Server.

<Note>
`search: false` erfüllt die entgegengesetzte Aufgabe wie `hidden: true`. `hidden` entfernt eine Seite aus Navigation und Indexierungsflächen; `search: false` lässt all das unverändert und verhindert nur, dass die Seite abgerufen wird. Verwechseln Sie dies nicht mit dem navigationsbezogenen `searchable`, das ausgeblendete Seiten wieder *in* die Suche aufnimmt.
</Note>

## Wie viel von einer Seite indexiert wird

Die Suche indexiert eine Seite nicht als einen einzelnen Block. Sie indexiert sie **Abschnitt für Abschnitt** — jede Überschrift wird zu einem eigenen Sucheintrag, sodass Leser, die nach „Rate limits“ suchen, bei dieser Überschrift statt am Anfang einer langen Seite landen.

Dabei gelten zwei automatische Begrenzungen:

| Limit | Wert | Was danach geschieht |
|---|---|---|
| Einträge pro Seite | 50 | Abschnitte werden in der Reihenfolge der Seite indexiert. Sobald der 50. Eintrag verwendet wurde, wird jeder verbleibende Abschnitt aus der Suche ausgeschlossen. |
| Text pro Abschnitt | Erste 300 Zeichen | Tiefer im Abschnitt stehende Formulierungen werden nicht gefunden. |

Die Seite selbst belegt einen der 50 Plätze, daher werden 49 Abschnitte indexiert.

Die Begrenzung existiert, weil die Suche jeden Eintrag mit dem restlichen Index gewichtet. Eine Seite, die Hunderte von Einträgen erzeugt, verdrängt andere aus den Ergebnissen — ein automatisch generiertes Änderungsprotokoll kann allein die Hälfte eines Indexes ausmachen und wirklich relevante Seiten von der ersten Trefferseite verdrängen.

<Warning>
Eine Seite, die das Limit überschreitet, wird weiterhin vollständig dargestellt. Nur ihre späteren Abschnitte sind nicht mehr auffindbar, und auf der Seite weist nichts Ihre Leser darauf hin.

Wenn eine Seite mehr als etwa 50 Überschriften enthält, teilen Sie sie entweder in mehrere Seiten auf — was ohnehin für eine bessere Navigation sorgt — oder fügen Sie, falls sie maschinell generiert wird und niemand manuell darin sucht, `search: false` hinzu, um sie vollständig aus dem Index zu entfernen.
</Warning>

Damit die Suche einen Begriff richtig gewichten kann, verwenden Sie zunächst den Seitentitel (höchste Gewichtung), dann eine Überschrift und anschließend die Beschreibung. Fließtext wird am niedrigsten gewichtet; pro Abschnitt werden nur die ersten 300 Zeichen berücksichtigt.

<Note>
`seo.metatags.keywords` fließt nicht in die Website-Suche ein. Es erzeugt ein HTML-Tag `<meta name="keywords">`, das Google laut eigener Aussage bei der Bewertung ignoriert. Es gibt keine Möglichkeit, einer Seite zusätzliche Suchbegriffe zuzuordnen — platzieren Sie die gewünschten Begriffe im Titel, in einer Überschrift oder in der Beschreibung.
</Note>

## Projektweite Steuerung

Beide Flags befinden sich in `docs.json` unter `seo`:

| Flag | Standard | Wirkung |
|---|---|---|
| `seo.indexing` | `"navigable"` | Nur in Ihrer Navigation aufgeführte Seiten erscheinen in den Artefakten. Setzen Sie den Wert auf `"all"`, um jede MDX-Datei in Ihrem Repository einzuschließen. |
| `seo.indexHiddenPages` | `false` | Setzen Sie den Wert auf `true`, um Seiten mit `hidden: true` in Sitemap, llms.txt und Suche aufzunehmen und das automatische Noindex-Tag zu entfernen. |

Beispiel:

```json
{
  "seo": {
    "indexing": "all"
  }
}
```

## Schnellreferenz

| Szenario | Frontmatter | docs.json | In Seitenleiste sichtbar | Direkte URL | In Sitemap |
|---|---|---|---|---|---|
| Normale Seite | — | aufgeführt | Ja | Ja | Ja |
| Über Frontmatter ausgeblendet | `hidden: true` | aufgeführt | Nein | Ja | Nein |
| Seite nicht in Navigation (verwaist) | — | ausgelassen | Nein | Ja | Nein |
| Ausgeblendete Gruppe | — | `hidden: true` für Gruppe | Nein | Ja | Nein |
| Ausgeblendete und durchsuchbare Gruppe | — | `hidden: true, searchable: true` | Nein | Ja | Ja |
| Nur aus der Suche entfernt | `search: false` | aufgeführt | Ja | Ja | Ja |
| Projekt aktiviert vollständige Indexierung | — | beliebig | Wie oben | Ja | Ja |

## Wann welche Option verwendet wird

- **Entwürfe und Vorschauen:** `hidden: true` im Frontmatter einzelner Seiten
- **Interne Bereiche** für ein kleines Team: eine ausgeblendete Gruppe oder ein ausgeblendeter Tab
- **Compliance-Dokumente**, die öffentlich sein, aber nicht beworben werden sollen: ausgeblendete Gruppe mit `searchable: true`
- **Indexierung des gesamten Repositorys** nur zur KI-Verankerung: `seo.indexing: "all"`
- **Ersetzte Seiten**, auf die weiterhin verlinkt und die weiterhin indexiert werden sollen, die aber nicht über Suche oder KI erscheinen sollen: `search: false` im Frontmatter

Ausgeblendete Seiten sind keine Zugriffskontrolle. Jeder, der die URL kennt, kann sie lesen. Eine echte Zugriffskontrolle finden Sie unter [Passwortschutz](/de/setup/password-protection).
