Jamdesk stellt Bilder mit abgerundeten Ecken und einheitlichen Abständen dar. Legen Sie Dateien in Ihrem Verzeichnis `/images` ab und binden Sie sie mit der Standard-Markdown-Syntax ein.

Die Screenshots zeigen die Benutzeroberfläche auf Englisch.

## Standard-Markdown

Verwenden Sie die vertraute Syntax `![alt](path)`:

```markdown
![API response showing user data in JSON format](/images/tabs-preview.webp)
```

![API-Antwort mit Benutzerdaten im JSON-Format](/images/tabs-preview.webp)

Pfade beginnen im Stammverzeichnis Ihres Projekts. Ein Bild unter `your-docs/images/screenshot.webp` wird mit `/images/screenshot.webp` eingebunden.

## Bildabmessungen

Fügen Sie `=WIDTHxHEIGHT` (durch ein Leerzeichen getrennt) hinter der Bild-URL ein, um die Größe festzulegen:

```markdown
![Dashboard overview](/images/tabs-preview.webp =400x300)
```

Geben Sie nur eine Abmessung an, wird die andere proportional angepasst:

```markdown
![Wide banner](/images/tabs-preview.webp =800x)
![Tall graphic](/images/tabs-preview.webp =x200)
```

Das ist hilfreich, wenn Screenshots in einer Spalte dieselbe Breite haben sollen oder Sie ein hochauflösendes Bild auf eine angemessene Anzeigegröße verkleinern möchten.

## Bildunterschriften

Umschließen Sie ein Bild mit der Komponente `<Frame>`, um einen Rahmen und eine Bildunterschrift darunter hinzuzufügen:

```mdx
<Frame caption="Dashboard overview showing project statistics">
  ![Dashboard](/images/tabs-preview.webp)
</Frame>
```

<Frame caption="Beispiel für ein Bild mit Rahmen und Bildunterschrift">
  ![Jamdesk](/images/jd-blueprint-transparent.webp)

</Frame>

`Frame` zeichnet einen dezenten Rahmen um das Bild und platziert die Bildunterschrift darunter. Die Komponente funktioniert mit beliebigen Inhalten, nicht nur mit Bildern.

## Zum Vergrößern klicken

Auf Bildschirmen mit einer Breite von mindestens 768 px werden Bilder beim Anklicken bildschirmfüllend geöffnet. Drücken Sie Escape oder klicken Sie an eine beliebige Stelle, um das vergrößerte Bild zu schließen.

Damit ein Bild nicht vergrößert wird, fügen Sie `noZoom` zu einem `<img>`-Tag hinzu:

```mdx
<img src="/images/diagram.png" alt="Architecture diagram" noZoom />
```

Markdown-Bilder (`![alt](src)`) unterstützen keine Attribute und können daher nicht vom Vergrößern ausgenommen werden. Verwenden Sie ein `<img>`--Tag, wenn Sie `noZoom` benötigen.

## Hell-/Dunkelmodus

Für Dokumentationssites werden oft unterschiedliche Bildvarianten für die jeweiligen Farbschemata benötigt: Ein Logo auf weißem Hintergrund sieht im Dunkelmodus unpassend aus.

### Das Attribut `srcDark`

Die einfachste Methode: Jamdesk wechselt die Bildquelle je nach aktivem Design:

```mdx
<img
  src="/images/logo-light.webp"
  srcDark="/images/logo-dark.webp"
  alt="Company logo"
/>
```

Der Browser lädt nur das Bild, das zum aktuellen Farbschema passt.

### Das HTML-Element `<picture>`

Wenn Sie standardmäßiges HTML benötigen, das auch außerhalb von Jamdesk funktioniert, verwenden Sie `<picture>` mit einer Media Query:

```mdx
<picture>
  <source srcset="/images/logo-dark.webp" media="(prefers-color-scheme: dark)" />
  <img src="/images/logo-light.webp" alt="Company logo" />
</picture>
```

Die Methode mit `<picture>` richtet sich nach der Farbschemaeinstellung des Betriebssystems. Das Attribut `srcDark` reagiert stattdessen auf den Design-Umschalter von Jamdesk. Für Dokumentationssites ist das in der Regel die bessere Wahl.

## Unterstützte Formate

| Format | Geeignet für | Hinweise |
|--------|----------|-------|
| PNG | Screenshots, UI-Aufnahmen | Verlustfreie Qualität, unterstützt Transparenz. Größere Dateien. |
| JPEG | Fotos | Gute Komprimierung, keine Unterstützung für Transparenz. |
| SVG | Icons, Diagramme, Logos | Vektorformat, das ohne Qualitätsverlust auf jede Größe skaliert werden kann. Sehr kleine Dateien. |
| GIF | Einfache Animationen | Dateien können schnell groß werden. Für Inhalte mit mehr als wenigen Einzelbildern eignen sich kurze `.mp4`-Schleifen. |
| WebP | Allgemeine Verwendung | Kleiner als PNG und JPEG bei vergleichbarer Qualität. Funktioniert in allen modernen Browsern. |

<Tip>
WebP bietet für die meisten Dokumentationsbilder das beste Verhältnis von Dateigröße zu Qualität. Wenn Sie Transparenz benötigen, unterstützt WebP diese ebenfalls; PNG ist also nicht erforderlich.
</Tip>

## Bewährte Vorgehensweisen

<AccordionGroup>
  <Accordion title="Aussagekräftige Alternativtexte verfassen" icon="universal-access">
    Alternativtexte erfüllen zwei Zwecke: Screenreader verwenden sie für die Barrierefreiheit, und sie werden als Platzhalter angezeigt, wenn das Bild nicht geladen werden kann. Beschreiben Sie, was auf dem Bild tatsächlich zu sehen ist.

    ```markdown
    {/* Good -- says what's in the image */}
    ![API response showing user data in JSON format](/images/tabs-preview.webp)

    {/* Bad -- tells you nothing */}
    ![Screenshot](/images/tabs-preview.webp)
    ```

    Verwenden Sie für dekorative Bilder, die keine Informationen vermitteln (Hintergrundmuster, Trennlinien), einen leeren Alternativtext: `![](/images/decoration.webp)`.
  </Accordion>

  <Accordion title="Dateigrößen klein halten" icon="gauge-high">
    Große Bilder verlangsamen das Laden von Seiten, besonders bei mobilen Verbindungen. Orientieren Sie sich an diesen Größen:

    - **Screenshots/UI:** PNG oder WebP, unter 500 KB
    - **Fotos:** JPEG oder WebP, unter 200 KB
    - **Icons und Diagramme:** nach Möglichkeit SVG

    [Squoosh](https://squoosh.app) und [TinyPNG](https://tinypng.com) komprimieren Bilder ohne sichtbaren Qualitätsverlust. Optimieren Sie Screenshots mit einem dieser Tools, bevor Sie sie committen.

    Oder überlassen Sie die Optimierung Jamdesk zur Build-Zeit. Aktivieren Sie die [automatische WebP-Konvertierung](/de/builds/image-optimization) in Ihrer `docs.json`, damit alle committeten PNG- oder JPG-Dateien bei jedem Build optimiert werden.
  </Accordion>

  <Accordion title="Einheitliche Abmessungen verwenden" icon="ruler-combined">
    Screenshots mit wechselnden Breiten wirken unübersichtlich. Legen Sie eine Standardbreite für Aufnahmen fest (1200 px eignen sich gut) und verwenden Sie diese durchgehend in Ihrer Dokumentation. Jamdesk passt Bilder automatisch an den Inhaltsbereich an. Einheitliche Quelldateien sorgen daher für einheitliche Ergebnisse.
  </Accordion>

  <Accordion title="Das Bild für soziale Netzwerke prüfen" icon="share-nodes">
    Jamdesk generiert automatisch für jede Seite eine gebrandete Social-Media-Karte mit den Maßen 1200×630. Sie können sie für einzelne Seiten mit `og:image` im Frontmatter überschreiben. Prüfen Sie nach einem Build die Seiten-URL mit dem kostenlosen Tool [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview), um zu sehen, wie die Karte auf X, Facebook, LinkedIn, Slack, Discord und anderen Plattformen dargestellt wird. Die vollständige Einrichtung finden Sie unter [SEO-Optimierung](/de/content/seo).
  </Accordion>
</AccordionGroup>

## Dateiorganisation

Ordnen Sie Bilder in Unterverzeichnissen an, die Ihrer Inhaltsstruktur entsprechen. So finden Sie Dateien leichter, wenn Ihre Dokumentation wächst:

```bash
your-docs/
├── images/
│   ├── getting-started/
│   │   ├── step-1.png
│   │   └── step-2.png
│   ├── api/
│   │   └── response.png
│   └── logo.svg
└── docs.json
```

Binden Sie sie mit dem vollständigen Pfad ab dem Stammverzeichnis Ihres Projekts ein:

```markdown
![GitHub repository access](/images/getting-started/step-1.png)
```

<Warning>
Vermeiden Sie Leerzeichen in Bilddateinamen. Verwenden Sie stattdessen Bindestriche: `api-response.webp` statt `api response.webp`.
</Warning>
