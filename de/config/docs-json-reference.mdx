Die Datei `docs.json` ist die zentrale Konfiguration für deine Jamdesk-Dokumentationswebsite.

<Tip>
  Wichtige Einstellungen aus deiner docs.json werden im Dashboard unter
  **Project Settings → Configuration Highlights** angezeigt. Diese Ansicht ist schreibgeschützt
  und wird nach jedem erfolgreichen Build automatisch aktualisiert.
</Tip>

## Erforderliche Felder

### name

**Typ:** `string` (erforderlich)

Der Name deiner Dokumentationswebsite. Wird im Header und im Browser-Tab angezeigt.

```json
{ "name": "Acme API Docs" }
```

### theme

**Typ:** `"jam" | "nebula" | "pulsar" | "halo"` (erforderlich)

<Tabs>
  <Tab title="jam">
    Klares, modernes Design mit der Schriftart Inter. Navigation auf Basis des Headers.

    **Am besten geeignet für:** Die meisten Dokumentationswebsites, API-Referenzen
  </Tab>
  <Tab title="nebula">
    Luftige, entspannte Gestaltung mit JetBrains Mono.

    **Am besten geeignet für:** Narrative Dokumentation, Leitfäden
  </Tab>
  <Tab title="pulsar">
    Präzise, kontrastreiche Gestaltung mit Seitennavigation.

    **Am besten geeignet für:** Dichte technische Referenzen
  </Tab>
  <Tab title="halo">
    Warme, weiche Gestaltung mit Figtree, stark abgerundeten Oberflächen und Inhalten auf einer Karte.

    **Am besten geeignet für:** Komfortables Lesen längerer Texte, zugängliche Produktdokumentation
  </Tab>
</Tabs>

### colors

**Typ:** `object` (erforderlich)

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `primary` | string (hex) | Ja | Primäre Markenfarbe |
| `light` | string (hex) | Nein | Akzentfarbe des hellen Themes |
| `dark` | string (hex) | Nein | Akzentfarbe des dunklen Themes |

```json
{
  "colors": {
    "primary": "#635BFF",
    "light": "#7C75FF",
    "dark": "#4F46E5"
  }
}
```

## Branding

### favicon

**Typ:** `string` oder `object`

Pfad zu deiner Favicon-Datei (SVG empfohlen). Gib ein einzelnes Bild für beide Modi oder separate Varianten für `light` und `dark` an.

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `light` | string | Favicon für den hellen Modus (bei Verwendung der Objektform erforderlich) |
| `dark` | string | Favicon für den dunklen Modus (optional, verwendet andernfalls `light`) |

```json
{ "favicon": "/images/favicon.svg" }
```

```json
{
  "favicon": {
    "light": "/images/favicon.svg",
    "dark": "/images/favicon-dark.svg"
  }
}
```

### logo

**Typ:** `object`

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `light` | string | Logo für den hellen Modus |
| `dark` | string | Logo für den dunklen Modus |
| `href` | string | URL beim Klicken auf das Logo |

```json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp",
    "href": "https://yoursite.com"
  }
}
```

## Typografie

### fonts

**Typ:** `object` (optional)

Überschreibe die Standardschriftart des Themes für Fließtext und Überschriften. Jedes Theme enthält eine abgestimmte Standardschriftart. Setze `fonts` nur, wenn du eine andere Gestaltung benötigst.

Verwende überall dieselbe Schriftart:

```json
{
  "fonts": {
    "family": "Lora"
  }
}
```

Überschrift und Fließtext trennen:

```json
{
  "fonts": {
    "heading": { "family": "Space Grotesk" },
    "body": { "family": "Inter" }
  }
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `family` | string | Name der Schriftfamilie. Jede Google Font funktioniert; der Build lädt sie automatisch |
| `weight` | number | Einzelne zu ladende Schriftstärke (z. B. `400`). Ohne Angabe werden `400, 500, 600, 700` geladen |
| `source` | string | URL oder relativer Pfad ab `/` zu einer selbst gehosteten Schriftdatei. Überspringt Google Fonts |
| `format` | `"woff"` \| `"woff2"` | Erforderlich, wenn `source` gesetzt ist |

Sowohl `heading` als auch `body` akzeptieren dieselben Felder. Siehe [Theming → Typografie](/de/customization/theming#typografie) für Hinweise zur Auswahl von Schriftarten.

## Erscheinungsbild

### appearance

**Typ:** `object` (optional)

Steuere das standardmäßige Verhalten des Dark Mode deiner Website.

```json
{
  "appearance": {
    "default": "dark",
    "strict": true
  }
}
```

| Feld | Typ | Standard | Beschreibung |
|-------|------|---------|-------------|
| `default` | `"system"` \| `"light"` \| `"dark"` | `"system"` | Initialer Modus für Besucher beim ersten Aufruf |
| `strict` | boolean | `false` | Wenn `true`, wird der Umschalter in der Navbar ausgeblendet, sodass Besucher im Modus `default` bleiben |

Siehe [Theming → Dark Mode](/de/customization/theming#dunkelmodus), um zu erfahren, wie sich der Umschalter verhält.

## Seitenmetadaten

### metadata

**Typ:** `object` (optional)

Steuere die auf jeder Dokumentationsseite angezeigten Seitenmetadaten.

```json
{
  "metadata": {
    "timestamp": true
  }
}
```

| Feld | Typ | Standard | Beschreibung |
|-------|------|---------|-------------|
| `timestamp` | boolean | `false` | Wenn `true`, wird in der Fußzeile jeder Seite eine Zeile im Stil von „Zuletzt aktualisiert am 15. Juni 2026“ angezeigt. Das Datum stammt aus dem letzten Git-Commit, der die Seite geändert hat, und bleibt bei jedem Build automatisch korrekt. |

Das Datum wird auf deiner veröffentlichten Website und in `jamdesk dev` angezeigt. Es entspricht dem letzten Commit, der die Datei der jeweiligen Seite geändert hat. Seiten, die du nicht bearbeitet hast, behalten daher ihr ursprüngliches Datum.

## Banner

### banner

Zeige auf jeder Seite websiteweit eine Ankündigungsleiste in voller Breite über dem Header und in der Akzentfarbe deines Themes an. Verwende sie für Launches, Migrationen, Wartungsfenster oder Nachrichten, die jeder Besucher sehen soll.

```json
{
  "banner": {
    "content": "🎉 Version 2.0 is live! Read the [changelog](/changelog).",
    "dismissible": true
  }
}
```

| Feld | Typ | Standard | Beschreibung |
|-------|------|---------|-------------|
| `content` | string | - | **Erforderlich.** Der Bannertext. Unterstützt einfache Inline-Formatierung: Links `[text](url)`, **Fettdruck** (`**text**`) und *Kursivschrift* (`*text*`). Benutzerdefinierte MDX-Komponenten werden nicht unterstützt. |
| `dismissible` | boolean | `false` | Wenn `true`, wird eine Schaltfläche zum Schließen angezeigt. Nachdem ein Besucher das Banner geschlossen hat, bleibt es für ihn ausgeblendet, bis du `content` änderst. Durch Bearbeiten der Nachricht wird es wieder angezeigt. |

Das Banner wird auf deiner veröffentlichten Website und in `jamdesk dev` dargestellt. Es wird global konfiguriert (ein Banner für die gesamte Website); Banner pro Tab und Sprache werden derzeit nicht unterstützt.

## OpenAPI

### api.openapi

**Typ:** `string | string[]`

Liste die OpenAPI-3.x-Spezifikationsdateien auf, die Jamdesk validieren und für Endpoint-Seiten verwenden soll. Verwende Pfade relativ zu deiner `docs.json`.

```json docs.json
{
  "api": {
    "openapi": ["/openapi/api.yaml"]
  }
}
```

Nach der Konfiguration kannst du Endpoint-Seiten erzeugen, indem du im Frontmatter einer Seite ein Feld `openapi` hinzufügst:

```mdx
---
title: Create Ticket
openapi: /openapi/api.yaml POST /tickets
---
```

Wenn du nur eine Spezifikation aufgelistet hast, kannst du auch das Kurzformat verwenden:

```mdx
---
title: Create Ticket
openapi: POST /tickets
---
```

Siehe [OpenAPI-Beispiel](/de/api-reference/openapi-example) für eine Live-Endpoint-Seite und [Verzeichnisstruktur](/de/setup/directory-structure) für die Platzierung von Dateien.

Wenn deine Website mehrsprachig ist, lege neben jeder Quellspezifikation eine Datei im Format `<spec>.<lang>.<ext>` ab (z. B. `openapi/api.fr.yaml`); Jamdesk stellt sie unter den URLs der jeweiligen Sprache bereit. Siehe [OpenAPI-Spezifikationen übersetzen](/de/setup/languages#openapi-spezifikationen-übersetzen).

<Warning>
Ein Schlüssel `asyncapi` wird überall dort akzeptiert, wo auch `openapi` akzeptiert wird. Jamdesk rendert AsyncAPI-Spezifikationen jedoch noch nicht – daraus wird nichts erzeugt. `jamdesk validate` gibt eine Warnung aus, wenn ein solcher Schlüssel gefunden wird, damit eine scheinbar unterstützte Konfiguration nicht unbemerkt bis zum Build bestehen bleibt.
</Warning>

### navigation openapi (generierte Seiten)

**Typ:** `object`

Füge einem Navigation-**Tab** ein `openapi`-Objekt hinzu und setze `generate: true`. Dann erstellt Jamdesk beim Build für jede Operation in dieser Spezifikation eine Endpoint-Seite sowie die Sidebar-Gruppen, die sie aufnehmen. Kein manueller Inhalt und kein Commit erforderlich.

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": { "source": "/openapi/api.yaml", "generate": true }
      }
    ]
  }
}
```

| Schlüssel | Typ | Beschreibung |
|-----|------|-------------|
| `source` | string | Pfad zur Spezifikation, relativ zu deiner `docs.json` |
| `generate` | boolean | `true` erstellt die Seiten und die Sidebar. Ohne diese Angabe bleibt der Schlüssel inaktiv |

Generierte Seiten liegen unter dem eigenen Namen des Tabs in slugifizierter Form. Der Slug wird aus Methode und Pfad gebildet – der obige Tab platziert `POST /tickets` unter `/api-reference/post-tickets`. Operationen werden nach ihrem ersten `tag` gruppiert. Spezifikationen ohne Tags verwenden ersatzweise das erste aussagekräftige Pfadsegment; `/api/v1/auctions/{auctionId}` landet daher unter **Auctions**. Die Titel stammen aus der `summary`-Angabe der Operation, sofern die Spezifikation eine enthält, andernfalls aus Methode und Pfad. Eine Operation, die eine einzelne Ressource adressiert, erhält einen Titel im Singular (`GET /users/{id}` → „Get User“).

<Note>
`generate` ist konstruktionsbedingt eine Opt-in-Option. Ein einfaches `"openapi": "/openapi/api.yaml"` in einem Tab oder ein Objekt ohne `generate: true` verhält sich weiterhin exakt wie zuvor. Dadurch erhält keine bestehende Konfiguration beim nächsten Build plötzlich hundert Seiten.
</Note>

Eine commitete `.mdx`-Datei hat bei einer Slug-Kollision immer Vorrang. So kannst du die Generierung schrittweise übernehmen: Aktiviere sie und lösche deine manuell erstellten Endpoint-Seiten einzeln, sobald du bereit bist.

Wenn du später einen Pfad in deiner Spezifikation umbenennst, wird der generierte Slug entsprechend verschoben. Jamdesk verwaltet eine Slug-Historie pro Operation und erzeugt bei jedem Build eine Weiterleitung von jeder früheren URL zur aktuellen URL. Dadurch bleiben eingehende Links und Lesezeichen trotz der Umbenennung gültig. Deine eigenen [Weiterleitungen](/de/setup/redirects) und jede aktive Seite haben weiterhin Vorrang.

**Aktuelle Einschränkungen.** Die Generierung läuft nur für `navigation.tabs` auf oberster Ebene – nicht für Gruppen, Anker oder Tabs innerhalb von `languages` oder `versions` – und erzeugt nur Seiten für deine Standardsprache. Ein Schlüssel `directory` wird vom Schema akzeptiert, hat aber keinen Einfluss darauf, wo die Seiten abgelegt werden.

### api.mdx.server

**Typ:** `string`

Basis-URL für Codebeispiele auf Frontmatter-Seiten mit `api:` (die mit MDX erstellt werden, nicht `openapi:`-Seiten, deren Server aus der Spezifikation stammen).

```json
{
  "api": {
    "mdx": {
      "server": "https://api.example.com"
    }
  }
}
```

<Note>
Ein Array wird aus Kompatibilitätsgründen akzeptiert, aber nur der erste Eintrag wird verwendet – alle weiteren werden verworfen. `jamdesk validate` gibt eine Warnung aus, wenn du mehr als einen Eintrag angibst.
</Note>

### api.examples.languages

**Typ:** `string[]`
**Standard:** `["curl", "python", "javascript"]`

Wähle aus, welche Programmiersprachen in automatisch generierten API-Codebeispielen auf `openapi:`-Seiten angezeigt werden. Die Reihenfolge des Arrays bestimmt die Reihenfolge der Tabs; die erste Programmiersprache ist standardmäßig ausgewählt.

**Unterstützte Werte:** `curl`, `bash`, `python`, `javascript`, `go`, `ruby`, `csharp`, `java`, `rust`, `php`

<Note>`bash` ist ein Alias für `curl`; beide erzeugen dieselbe Ausgabe. Verwende die Bezeichnung, die du bevorzugst.</Note>

```json All supported languages
{
  "api": {
    "examples": {
      "languages": ["curl", "python", "javascript", "go", "ruby", "csharp", "java", "rust", "php"]
    }
  }
}
```

```json Custom subset
{
  "api": {
    "examples": {
      "languages": ["python", "javascript", "go"]
    }
  }
}
```

### api.examples.defaults

**Typ:** `"required" | "all"`
**Standard:** `"all"`

Steuere, welche Parameter in automatisch generierten Codebeispielen erscheinen.

| Wert | Verhalten |
|----------|----------|
| `"all"` | Beispiele enthalten alle Parameter mit Platzhalterwerten |
| `"required"` | Beispiele enthalten nur Parameter, die in der Spezifikation als `required` markiert sind |

```json
{
  "api": {
    "examples": {
      "defaults": "required"
    }
  }
}
```

### api.examples.prefill

**Typ:** `boolean`
**Standard:** `false`

Wenn `true`, füllt das [API Playground](/de/api-reference/playground) Parameterfelder mit `example`-Werten aus deiner OpenAPI-Spezifikation vorab aus.

```json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

### api.playground.display

**Typ:** `"interactive" | "simple" | "none"`
**Standard:** `"interactive"`

Steuert das [API Playground](/de/api-reference/playground) auf Endpoint-Seiten. Auf jeder `openapi:`- und `api:`-Seite wird standardmäßig eine Schaltfläche „Try it“ angezeigt.

| Wert | Verhalten |
|----------|----------|
| `"interactive"` | Vollständiges Playground: Parameter ausfüllen, Code erzeugen und Anfragen senden (Standard) |
| `"simple"` | Parameter ausfüllen und Code kopieren, aber keine Schaltfläche „Send“ |
| `"none"` | Playground deaktiviert |

```json
{
  "api": {
    "playground": {
      "display": "interactive"
    }
  }
}
```

Siehe [API Playground](/de/api-reference/playground) für Details zur Verwendung und seitenbezogene Überschreibungen.

### api.mdx.auth.method

**Typ:** `"bearer" | "basic" | "key" | "cobo"`

Authentifizierungsmethode für automatisch generierte Codebeispiele. Wenn sie gesetzt ist, enthalten die Beispiele den passenden Authentifizierungs-Header.

| Wert | Header-Format |
|-------|--------------|
| `"bearer"` | `Authorization: Bearer <token>` |
| `"basic"` | `Authorization: Basic <base64>` |
| `"key"` | Benutzerdefinierter Header (siehe `api.mdx.auth.name`) |
| `"cobo"` | Cobo-spezifische Authentifizierung |

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
}
```

### api.mdx.auth.name

**Typ:** `string`

Benutzerdefinierter Headername für die schlüsselbasierte Authentifizierung. Wird nur verwendet, wenn `api.mdx.auth.method` auf `"key"` gesetzt ist.

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "key",
        "name": "X-API-Key"
      }
    }
  }
}
```

## Navigation

### tabsPosition

**Typ:** `"top" | "left"`

Steuert, wo die Navigationstabs angezeigt werden.

| Wert | Beschreibung |
|-------------|-------------|
| `"top"` | Tabs erscheinen in der Tab-Leiste des Headers |
| `"left"` | Tabs erscheinen oben in der Sidebar |

Der Standardwert hängt von deinem Theme ab:

| Theme | Standard |
|---------|---------|
| jam | `"left"` |
| nebula | `"left"` |
| pulsar | `"top"` |
| halo | `"left"` |

```json
{ "tabsPosition": "left" }
```

### anchors

**Typ:** `array`

Externe Links, die auf allen Seiten oben in der Sidebar erscheinen.

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|-------------|-------------|
| `name` | string | Ja | Anzeigetext |
| `href` | string | Ja | URL (externer Link) |
| `icon` | string | Nein | Name des Font Awesome-Symbols |

```json
{
  "anchors": [
    { "name": "Blog", "href": "https://blog.example.com", "icon": "newspaper" }
  ]
}
```

### navigation (Struktur)

**Typ:** `object`

Die Navigationsstruktur deiner Dokumentation. Siehe [Navigation](/de/navigation/overview) für eine ausführliche Dokumentation.

Seiten können Zeichenfolgen sein (der Titel wird automatisch aus dem Dateinamen erzeugt) oder Objekte mit einem benutzerdefinierten Titel:

```json
"pages": [
  "introduction",
  { "page": "content/mdx-basics", "title": "MDX Basics" }
]
```

<Accordion title="Beispiel für eine einfache Navigation">
```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Docs",
        "icon": "book-open",
        "groups": [
          {
            "group": "Getting Started",
            "pages": ["introduction", "quickstart"]
          }
        ]
      }
    ]
  }
}
```
</Accordion>

## Navbar & Fußzeile

### navbar

**Typ:** `object`

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `links` | array | Navigationslinks |
| `links[].label` | string | Standardtext der Schaltfläche |
| `links[].labels` | object | Optionale sprachbezogene Überschreibungen nach Sprachcode (z. B. `fr`, `es`). Fällt auf `label` zurück |
| `links[].icon` | icon | Optionales neben dem Label angezeigtes Symbol |
| `links[].href` | string | Ziel-URL |
| `primary` | object | Primäre CTA-Schaltfläche |
| `primary.label` | string | Standardtext der Schaltfläche |
| `primary.labels` | object | Optionale sprachbezogene Überschreibungen nach Sprachcode. Fällt auf `label` zurück |

```json
{
  "navbar": {
    "links": [
      {
        "label": "Blog",
        "labels": { "fr": "Blog", "es": "Blog" },
        "href": "/blog"
      },
      {
        "label": "Pricing",
        "labels": { "fr": "Tarifs", "es": "Precios" },
        "href": "/pricing"
      }
    ],
    "primary": {
      "type": "button",
      "label": "Dashboard",
      "labels": { "fr": "Tableau de bord", "es": "Panel" },
      "href": "https://app.example.com"
    }
  }
}
```

<Note>
  `labels` ist optional. Einsprachige Dokumentationen können darauf verzichten. Wenn die Eigenschaft gesetzt ist, wählt die aktuelle URL-Sprache (z. B. `/fr/...`) die passende Überschreibung aus.
</Note>

### footer

**Typ:** `object`

Konfiguriere die Fußzeile mit Links zu sozialen Netzwerken und benutzerdefinierten Linkspalten.

```json
{
  "footer": {
    "socials": {
      "github": "https://github.com/yourorg",
      "x": "https://x.com/yourhandle",
      "discord": "https://discord.gg/yourserver"
    },
    "links": [
      {
        "header": "Resources",
        "items": [
          { "label": "Blog", "href": "https://example.com/blog" },
          { "label": "Changelog", "href": "/changelog" }
        ]
      }
    ]
  }
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `socials` | object | URLs der Social-Media-Plattformen |
| `links` | array | Konfigurationen der Linkspalten |
| `links[].header` | string | Überschrift der Spalte |
| `links[].items` | array | Array von Objekten im Format `{ label, href }` |

**Unterstützte Social-Media-Plattformen:** `github`, `x`, `twitter`, `linkedin`, `discord`, `slack`, `youtube`, `instagram`, `facebook`, `reddit`, `telegram`, `bluesky`, `threads`, `medium`, `hacker-news`, `website`

## Styling

### styling.latex

**Typ:** `boolean`

Aktiviere mathematische LaTeX-Darstellung mit KaTeX. Wenn aktiviert, kannst du `$...$` für Inline-Mathematik und `$$...$$` für Blockgleichungen verwenden.

```json
{
  "styling": {
    "latex": true
  }
}
```

Siehe [Mathematik & LaTeX](/de/content/math) für Details zur Verwendung.

### styling.js

**Typ:** `string | string[]`

Benutzerdefinierte JavaScript-Datei(en), die auf jeder Seite eingebunden werden. Die Pfade sind relativ zu deinem Dokumentationsverzeichnis und müssen mit `/` beginnen.

```json
{
  "styling": {
    "js": "/script.js"
  }
}
```

Für mehrere Dateien übergib ein Array:

```json
{
  "styling": {
    "js": ["/chat.js", "/analytics.js"]
  }
}
```

Ohne dieses Feld erkennt Jamdesk `.js`-Dateien automatisch im Projektstamm. Siehe [Benutzerdefiniertes JavaScript](/de/customization/custom-javascript) für Details.

## Suche

### search

**Typ:** `object` (optional)

Passe die Suchleiste der Dokumentation an. Die Suche funktioniert standardmäßig; dieses Feld ist nur erforderlich, wenn du den Platzhaltertext ändern oder beliebte Seiten im leeren Zustand anzeigen möchtest.

| Feld | Typ | Standard | Beschreibung |
|-------|------|---------|-------------|
| `prompt` | string | `Search documentation…` | Platzhaltertext im Sucheingabefeld |
| `popularPages` | array | Quick Start, Introduction | Schnellzugriffslinks, die angezeigt werden, bevor der Besucher eine Suchanfrage eingibt |

```json
{
  "search": {
    "prompt": "Ask me anything…",
    "popularPages": [
      { "title": "Quick Start", "slug": "quickstart", "icon": "rocket" },
      { "title": "Authentication", "slug": "guides/authentication", "icon": "key" }
    ]
  }
}
```

#### Beliebte Seiten

Jeder Eintrag in `popularPages` akzeptiert:

| Feld | Typ | Erforderlich | Beschreibung |
|-------|------|----------|-------------|
| `title` | string | Ja | Für den Link angezeigtes Label |
| `slug` | string | Ja | Seitenpfad ohne führenden Schrägstrich oder `.mdx`-Erweiterung (z. B. `quickstart` oder `guides/authentication` für die Datei `guides/authentication.mdx`) |
| `icon` | string | Nein | Neben dem Link angezeigter Name des Font Awesome-Symbols (z. B. `rocket` oder `bell`) |

Das Feld `icon` akzeptiert auch das vollständige Objekt `{ "name", "style", "library" }`. Siehe [Objektform für Symbole](/de/content/icons#objektform-für-icons). Wenn `popularPages` nicht angegeben ist, zeigt Jamdesk standardmäßig Quick Start und Introduction an.

## Chat

### chat

**Typ:** `object` (optional)

Konfiguriere den integrierten KI-Chatassistenten. Der Chat ist standardmäßig auf allen Websites aktiviert; dieses Feld ist nur erforderlich, wenn du die Einstiegsfragen anpassen oder den Chat deaktivieren möchtest.

| Feld | Typ | Standard | Beschreibung |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Setze den Wert auf `false`, um das Chatpanel von deiner Website zu entfernen |
| `starterQuestions` | string[] | automatisch erzeugt | Bis zu 4 Fragen, die beim Öffnen des Chats angezeigt werden (je 5–200 Zeichen). Wenn nicht angegeben, werden sie während der Builds automatisch erzeugt. Setze den Wert auf `[]`, um keine Fragen anzuzeigen |

```json
{
  "chat": {
    "starterQuestions": [
      "How do I get started?",
      "What API endpoints are available?"
    ]
  }
}
```

Siehe [KI-Chat](/de/ai/chat) für Details zur Funktionsweise des Chats und zur Darstellung für Besucher.

## KI-Aktionsmenü

### contextual

**Typ:** `object` (optional)

Konfiguriere das Dropdown-Menü für KI-Aktionen, das auf jeder Seite erscheint. Es ist standardmäßig mit allen Optionen aktiviert; dieses Feld ist nur erforderlich, wenn du die angezeigten Optionen anpassen oder das Menü deaktivieren möchtest.

| Feld | Typ | Standard | Beschreibung |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Setze den Wert auf `false`, um das KI-Aktionsmenü von deiner Website zu entfernen |
| `options` | array | alle integrierten Optionen | Liste von Optionsschlüsseln und/oder benutzerdefinierten Optionsobjekten |

**Integrierte Optionsschlüssel:** `copy`, `view`, `chatgpt`, `claude`, `perplexity`, `gemini`, `mcp`, `cursor`, `vscode`

```json
{
  "contextual": {
    "options": ["copy", "claude", "mcp", "cursor"]
  }
}
```

Füge neben den integrierten Optionen benutzerdefinierte Optionen hinzu:

```json
{
  "contextual": {
    "options": [
      "copy",
      "claude",
      {
        "title": "Ask on Discord",
        "description": "Get help from the community",
        "icon": "discord",
        "href": "https://discord.gg/your-server"
      }
    ]
  }
}
```

Siehe [KI-Aktionsmenü](/de/ai/ai-actions) für die vollständige Liste der Optionen und das Format benutzerdefinierter Optionen.

## Rechtschreibprüfung

### spellcheck

**Typ:** `object` (optional)

Konfiguriere den CLI-Befehl `jamdesk spellcheck`. Dieses Feld ist nur erforderlich, wenn du projektspezifische Wörter zur Ignorierliste hinzufügen möchtest.

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `ignore` | string[] | Wörter, die bei der Rechtschreibprüfung übersprungen werden sollen (Produktnamen, technische Begriffe usw.) |

```json
{
  "spellcheck": {
    "ignore": ["Acme", "kubectl", "Terraform"]
  }
}
```

Die CLI enthält mehr als 180 integrierte technische Begriffe (API, GraphQL, Kubernetes, React usw.) und ignoriert automatisch den Projektnamen aus dem Feld `name`. Füge nur projektspezifische Wörter hinzu.

## Bilder

### images.convertToWebp

**Typ:** `boolean` (optional, Standard `false`)

Aktiviere die automatische WebP-Konvertierung von PNG- und JPG-Assets während der Builds. Konvertierte Dateien sind normalerweise 60–80 % kleiner als die Originale, ohne sichtbaren Qualitätsverlust. Verweise in deinem MDX, benutzerdefiniertem CSS, benutzerdefiniertem JavaScript und in `docs.json` werden automatisch angepasst, sodass du keine Pfade ändern musst.

Favicons, `og:image` und `twitter:image` behalten ihr ursprüngliches Format. Nicht jeder Social-Crawler und nicht jeder E-Mail-Client rendert WebP zuverlässig; eine fehlerhafte Vorschaukarte ist schlechter als eine geringfügig größere JPG-Datei.

```json
{
  "images": {
    "convertToWebp": true
  }
}
```

Siehe [Automatische Bildkonvertierung](/de/builds/image-optimization) für Informationen zu konvertierten Dateien, Caching und der Fortschrittsanzeige des Builds.

## Zugriffskontrolle

### auth.password

**Typ:** `object` (optional)

Aktiviere den Schutz deiner Website durch ein gemeinsames Passwort. Die Konfiguration erfolgt deklarativ. Die eigentliche Passphrase legst du nach dem nächsten Build im [Dashboard](/de/setup/password-protection#sitzungen-ändern-und-widerrufen) fest.

Setze `auth.password.enabled: true`, um die gesamte Website zu sperren, oder liste Pfade unter `auth.password.private[]` auf, um nur bestimmte Seiten zu schützen. Beide Varianten lösen beim nächsten Build dieselbe Passwortabfrage im Dashboard aus.

```json
{
  "auth": {
    "password": {
      "enabled": true,
      "hint": "Ask your account manager",
      "public": ["/marketing/**", "/changelog"]
    }
  }
}
```

| Feld | Typ | Beschreibung |
|-------|------|-------------|
| `enabled` | `boolean` | Modus für die gesamte Website. Wenn `true`, benötigt jede Seite das Passwort (außer explizit als öffentlich markierte Seiten). |
| `hint` | `string` (max. 200 Zeichen) | Nur-Text-Hinweis auf dem Entsperrbildschirm. Kein HTML. |
| `public` | `string[]` | Pfad-Globs, die den Passwortschutz umgehen. Unterstützt `*` (ein Segment) und `**` (rekursiv). Ein einzelnes `/` wird abgelehnt. |
| `private` | `string[]` | Exakte Pfade, die das Passwort erfordern. Wird dies ohne `enabled` gesetzt, wird der Modus für bestimmte Seiten aktiviert. |

Siehe [Passwortschutz](/de/setup/password-protection) für die vollständige Anleitung, einschließlich des Dashboard-Ablaufs und der Wechselwirkung von `public: true` / `private: true` im Frontmatter mit diesen Arrays.
