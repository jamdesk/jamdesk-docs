## Automatische Builds

Jamdesk startet deinen ersten Build, sobald du ein Repository verbindest. Jeder spätere Push auf deinen verbundenen Branch löst einen neuen Build aus.

## Build-Fortschritt

Verfolge deinen Build im Dashboard:

<Steps>
  <Step title="Queued">
    Dein Build wartet darauf, zu starten. Zu Stoßzeiten kann es eine kurze Warteschlange geben.
  </Step>
  <Step title="Cloning">
    Jamdesk lädt die Inhalte deines Repositorys von GitHub herunter.
  </Step>
  <Step title="Validating">
    Jamdesk prüft deine `docs.json`- und MDX-Dateien auf Fehler.
  </Step>
  <Step title="Building">
    Jamdesk kompiliert MDX zu HTML mit Syntaxhervorhebung und einem Suchindex.
  </Step>
  <Step title="Deploying">
    Die erstellten Dateien werden in das globale CDN hochgeladen.
  </Step>
  <Step title="Live">
    Deine Dokumentation ist unter deiner Projekt-URL verfügbar.
  </Step>
</Steps>

## Ihre Live-Dokumentation anzeigen

Klicke im Dashboard auf **View Site** oder besuche `https://your-project.jamdesk.app`.

Deine Dokumentation erscheint auch auf deiner eigenen Domain, sofern du eine konfiguriert hast.

## Manuellen Build starten

Baue ohne neuen Push neu:

1. Gehe zu deinem Projekt im [Dashboard](https://dashboard.jamdesk.com)
2. Öffne **Settings**
3. Klicke auf **Rebuild**

Verwende dies nach Änderungen an Umgebungsvariablen oder um einen frischen Build zu erzwingen.

## Wenn Ihr Build fehlschlägt

Das Dashboard zeigt bei einem fehlgeschlagenen Build eine Fehlermeldung an. Häufige Ursachen:

- Ungültige `docs.json`-Syntax
- MDX-Syntaxfehler
- Fehlende Seiten, die in der Navigation referenziert werden
