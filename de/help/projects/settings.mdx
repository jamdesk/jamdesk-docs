Konfigurieren Sie auf der Seite „Settings“ den Anzeigenamen Ihres Projekts, das verbundene Repository, den Branch, Umgebungsvariablen, die eigene Domain und die Optionen der Gefahrenzone.

## Zugriff auf die Einstellungen

1. Wählen Sie Ihr Projekt im Dashboard aus
2. Klicken Sie in der Seitenleiste auf **Settings**

Die Seite „Settings“ ist in Abschnitte für Anzeige, Repository, Team, Konfiguration und Benachrichtigungen unterteilt.

## Allgemeine Einstellungen

### Projektname

Der Anzeigename in Ihrem Dashboard. Er wirkt sich nicht auf Ihre live veröffentlichte Dokumentation aus.

### Subdomain

Ihre Standard-URL unter `*.jamdesk.app`. So ändern Sie sie:

1. Geben Sie eine neue Subdomain ein
2. Klicken Sie auf **Save**
3. Warten Sie auf die DNS-Propagierung (meist sofort)

<Note>
Änderungen an der Subdomain unterbrechen bestehende Links nicht. Die alte URL leitet auf die neue weiter.
</Note>

## Repository-Einstellungen

### Verbundenes Repository

Ihr verknüpftes GitHub-Repository. Um das Repository zu wechseln, müssen Sie das Projekt löschen und ein neues anlegen.

### Branch

Der Git-Branch, der Builds auslöst. Typischerweise `main` oder `master`.

### Dokumentationspfad

Pfad zu Ihrer `docs.json` in einem Monorepo (z. B. `packages/docs`).

Lassen Sie das Feld leer, wenn sich `docs.json` im Stammverzeichnis des Repositories befindet.

## Build-Einstellungen

### Umgebungsvariablen

Legen Sie Variablen fest, die während des Builds für Ihre Dokumentation verfügbar sind:

1. Klicken Sie auf **Add Variable**
2. Geben Sie den Schlüssel und den Wert ein
3. Klicken Sie auf **Save**

Die Variablen stehen während des Builds zur Verfügung. Sie können in Ihrer Dokumentation darauf verweisen.

### Neu erstellen

Klicken Sie auf **Rebuild**, um einen neuen Build zu starten, ohne an GitHub zu pushen. Verwenden Sie dies nach Änderungen an den Einstellungen.

## Benutzerdefinierte Domain

Fügen Sie Ihre eigene Domain im Abschnitt **Domains** hinzu. Anleitung zur Einrichtung finden Sie unter [Eigene Domains](/de/deploy/custom-domains).

## Gefahrenbereich

### Projekt löschen

Löscht das Projekt und alle zugehörigen Daten dauerhaft:

- Build-Verlauf
- Analysedaten
- Konfiguration der eigenen Domain

<Warning>
Diese Aktion kann nicht rückgängig gemacht werden. Erwägen Sie eine Übertragung des Eigentums, wenn Teammitglieder weiterhin Zugriff benötigen.
</Warning>
