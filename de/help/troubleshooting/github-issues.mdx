Die meisten Probleme mit der GitHub-Integration sind auf Berechtigungen, Webhook-Fehler oder abweichende Branches zurückzuführen.

## Organisation wird beim Setup nicht angezeigt

Während des Einstiegsassistenten für die Dokumentation zeigt Jamdesk deine GitHub-Organisationen an, damit du auswählen kannst, wo das Repository erstellt werden soll. Die Liste stammt aus der OAuth API von GitHub. GitHub blendet Organisationen in zwei Fällen aus:

- OAuth-App-Einschränkungen: Deine Organisation beschränkt den Zugriff durch Drittanbieter-Apps (die Standardeinstellung für neue Organisationen bei GitHub) und hat Jamdesk noch nicht genehmigt.
- SAML-SSO: Deine Organisation verlangt eine SAML-Authentifizierung, bevor die API sie zurückgibt.

<Accordion title="Zugriff selbst gewähren (Organisationsinhaber)">
  Wenn du Inhaber der Organisation bist, kannst du Jamdesk sofort genehmigen:

  1. Klicke unter der Organisationsauswahl auf **grant Jamdesk access on GitHub** (oder gehe zu GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. Klicke unter **Organization access** neben deiner Organisation auf **Grant**
  3. Klicke im Jamdesk-Setup erneut auf **refresh the list**. Deine Organisation wird sofort angezeigt

  Wenn du Mitglied, aber kein Inhaber bist, wird stattdessen die Schaltfläche **Request** angezeigt. Wenn du darauf klickst, wird eine Genehmigungsanfrage an die Administratoren deiner Organisation gesendet.
</Accordion>

<Accordion title="Jamdesk vom Organisationsadministrator genehmigen lassen (Mitglieder)">
  Wenn du Mitglied bist und keine Inhaberrechte hast, sende zuerst eine Genehmigungsanfrage an die Administratoren:

  1. Gehe zu GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. Klicke unter **Organization access** neben deiner Organisation auf **Request**. Dadurch werden die Administratoren deiner Organisation benachrichtigt
  3. Ein Administrator genehmigt die Anfrage unter **Settings** → **Third-party access** → **OAuth application policy** der Organisation (bei ausstehenden Anfragen wird die Schaltfläche **Approve** angezeigt)
  4. Kehre zum Jamdesk-Setup zurück und klicke auf **refresh the list**. Deine Organisation sollte jetzt angezeigt werden

  Eine ausführliche Anleitung findest du in GitHub [Genehmigen von OAuth-Apps für deine Organisation](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization).
</Accordion>

<Accordion title="Zuerst im persönlichen Konto erstellen und später übertragen">
  Du möchtest nicht auf die Genehmigung durch einen Administrator warten? Wähle beim Setup dein persönliches Konto aus und übertrage das Repository anschließend in deine Organisation:

  1. Schließe das Jamdesk-Setup mit deinem persönlichen Konto ab
  2. Rufe das erstellte Repository auf GitHub auf
  3. Gehe zu **Settings** → **General** → **Danger Zone**
  4. Klicke auf **Transfer** und wähle deine Organisation als Ziel aus
  5. Trenne in Jamdesk die Verbindung zum Repository und verbinde es erneut über die Seite **Settings** deines Projekts

  <Warning>
    Wenn du die Verbindung trennst und wiederherstellst, wird eine neue Dokumentations-URL erstellt (z. B. kann sich `your-project.jamdesk.app` ändern). Wenn du deine URL bereits geteilt oder eine benutzerdefinierte Domain eingerichtet hast, wende dich vor dem Trennen an den [Support](/de/help/support/contact), damit wir deine Konfiguration beibehalten können.
  </Warning>

  Das funktioniert nicht, wenn dein Unternehmen dein GitHub-Konto verwaltet. Siehe stattdessen [Von Unternehmen verwaltete GitHub-Konten](#von-unternehmen-verwaltete-github-konten).
</Accordion>

## Von Unternehmen verwaltete GitHub-Konten

Wenn dein Unternehmen dein GitHub-Konto verwaltet (GitHub nennt diese Konten Enterprise Managed Users oder EMU), kannst du bei GitHub keine Apps in deinem eigenen Konto installieren, sondern nur in einer Organisation. Wenn du keine Organisation verwenden kannst, führt dich ein Klick auf **Install** auf GitHub einfach zurück zur Jamdesk-App-Seite. Während der Registrierung zeigt Jamdesk die Meldung „Your organization manages this GitHub account“ an.

Verwaltete Benutzernamen enden mit einem Unterstrich und einem Unternehmenscode, zum Beispiel `jsmith_acme`. GitHub erläutert die Einschränkungen auf der Seite zu [verwalteten Benutzerkonten](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts).

Du kannst das Problem auf zwei Arten beheben.

<Accordion title="Repository in eine Organisation verschieben">
  1. Bitte einen Enterprise-Inhaber, über den Tab **Organizations** deines Enterprise-Kontos eine [Organisation zu erstellen](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise). Bitte darum, dass du darin Repositories erstellen darfst.
  2. [Übertrage dein Dokumentations-Repository](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository) in die Organisation. Gehe im Repository zu **Settings**, klicke unten auf **Transfer** und wähle die neue Organisation aus.
  3. Klicke in Jamdesk auf **Connect an existing repository** (oder in den Projekteinstellungen auf **Install GitHub App**). Wähle auf GitHub die Organisation aus, dann **Only select repositories**, markiere dein Repository und installiere die App.

  Wenn GitHub statt **Install** die Schaltfläche **Request** anzeigt, erhält ein Organisationsinhaber eine E-Mail zur Genehmigung. Klicke anschließend erneut auf die Jamdesk-Schaltfläche.
</Accordion>

<Accordion title="Persönliches GitHub-Konto verwenden">
  Verwende diese Möglichkeit, wenn dein Unternehmen keine Organisation hinzufügen kann. Kläre das zuerst mit deinem GitHub-Administrator ab, da die Dokumentation außerhalb des GitHub-Kontos deines Unternehmens gespeichert wird.

  1. Melde dich in einem privaten Browserfenster mit einem persönlichen Konto bei GitHub an (oder erstelle eines).
  2. Erstelle in diesem Konto ein leeres privates Repository.
  3. Übertrage eine Kopie deiner Dokumentation dorthin. GitHub kann Repositories nicht aus einem verwalteten Enterprise übertragen, deshalb ist eine Kopie erforderlich.

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     Lass `jsmith@` in der URL stehen, damit Git nach den Anmeldedaten deines persönlichen Kontos fragt.

  4. Klicke in Jamdesk auf **Connect an existing repository** (oder in den Projekteinstellungen auf **Install GitHub App**), installiere Jamdesk in deinem persönlichen Konto und wähle das Repository aus.

  Verwaltete Konten können keine Änderungen an Repositories außerhalb ihres Enterprise-Kontos übertragen. Daher benötigt jede Person, die die Dokumentation bearbeitet, ein persönliches GitHub-Konto. Füge sie als Mitwirkende zum Repository hinzu.
</Accordion>

## Repository wird nicht angezeigt

Wenn dein Repository nicht in der Liste erscheint:

<Accordion title="Repository-Berechtigungen prüfen">
  1. Gehe zu GitHub → Settings → Applications → Jamdesk
  2. Prüfe, ob der Zugriff auf das Repository gewährt wurde
  3. Klicke auf **Configure**, um weitere Repositories hinzuzufügen
</Accordion>

<Accordion title="Organisations-Repositories">
  Für Repositories von Organisationen:
  1. Ein Organisationsadministrator muss Jamdesk genehmigen
  2. Gehe zu den Organisationseinstellungen → Third-party access
  3. Genehmige die Zugriffsanfrage von Jamdesk
</Accordion>

<Accordion title="Private Repositories">
  Für private Repositories ist eine GitHub-Autorisierung erforderlich. Autorisiere Jamdesk bei Bedarf erneut.
</Accordion>

## Builds werden nicht ausgelöst

Wenn durch Pushes keine Builds ausgelöst werden:

<Steps>
  <Step title="Webhook prüfen">
    1. Rufe dein Repository auf GitHub auf
    2. Gehe zu Settings → Webhooks
    3. Suche den Jamdesk-Webhook
    4. Prüfe unter „Recent Deliveries“, ob Fehler aufgetreten sind
  </Step>
  <Step title="Branch überprüfen">
    Builds werden nur für den konfigurierten Branch ausgelöst. Prüfe **Settings** in Jamdesk.
  </Step>
  <Step title="Prüfen, wer den Push ausgeführt hat">
    Wenn der Build mit der Meldung fehlschlägt, dass die Person, die den Push ausgeführt hat, kein Mitglied ist, lade sie unter **Project Settings → Members** ein oder bitte sie, ihr GitHub-Konto zu verknüpfen. Siehe [Builds werden nicht ausgelöst](/de/integrations/github#builds-werden-nicht-ausgelöst).
  </Step>
  <Step title="Verbindung erneut synchronisieren">
    1. Gehe in Jamdesk zu den **Settings** des Projekts
    2. Klicke auf **Re-sync GitHub**
  </Step>
</Steps>

## Webhook-Fehler

### 404 Not Found

Der Webhook-Endpunkt konnte nicht erreicht werden.

**Behebung:** Synchronisiere die GitHub-Verbindung in den Projekteinstellungen erneut.

### 401 Unauthorized

Die Authentifizierung ist fehlgeschlagen.

**Behebung:**
1. Gehe zu den Einstellungen deines GitHub-Kontos
2. Gehe zu Applications → Authorized OAuth Apps
3. Widerrufe die Autorisierung für Jamdesk
4. Autorisiere Jamdesk in den Einstellungen erneut

### 500 Server Error

Vorübergehendes Problem mit Jamdesk.

**Behebung:** Warte einige Minuten und führe den Push erneut aus oder starte einen manuellen Build.

## Berechtigungsfehler

**„Repository not found“** während eines Builds:

- Das Repository wurde möglicherweise gelöscht oder umbenannt
- Jamdesk hat möglicherweise den Zugriff verloren
- Autorisiere deine GitHub-Verbindung erneut

## Branch-Probleme

### Falscher Branch wird erstellt

Prüfe den konfigurierten Branch unter **Settings** → **Repository**.

### Branch umbenannt oder gelöscht

Ändere die Branch-Einstellung so, dass sie dem neuen Branch-Namen entspricht.
