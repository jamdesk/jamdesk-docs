Die meisten GitHub-Integrationsprobleme gehen auf Berechtigungen, fehlgeschlagene Webhooks oder Branch-Abweichungen zurück.

## Organisation wird beim Setup nicht angezeigt

Der Setup-Ablauf für Starter-Dokumentation listet deine GitHub-Organisationen auf. Wähle eine aus, in der das neue Repository liegen soll. Die Liste stammt aus der OAuth-API von GitHub. GitHub blendet eine Organisation in zwei Fällen aus:

- OAuth-App-Einschränkungen: Deine Organisation beschränkt den Zugriff von Drittanbieter-Apps (GitHubs Standard für neue Organisationen) und hat Jamdesk noch nicht genehmigt.
- SAML SSO: Deine Organisation verlangt eine SAML-Authentifizierung, bevor die API sie zurückgibt.

<Accordion title="Selbst Zugriff gewähren (Organisationsinhaber)">
  Jamdesk sofort genehmigen:

  1. Klicke unter der Organisationsauswahl auf **grant Jamdesk access on GitHub** (oder gehe zu GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. Klicke unter **Organization access** neben deiner Organisation auf **Grant**
  3. Klicke im Jamdesk-Setup-Ablauf auf **refresh the list**. Deine Organisation erscheint sofort

  Mitglieder (keine Inhaber) sehen stattdessen eine Schaltfläche **Request**. Sie sendet eine Genehmigungsanfrage an deine Organisationsadministratoren.
</Accordion>

<Accordion title="Organisationsadministrator um Genehmigung von Jamdesk bitten (Mitglieder)">
  Sende deinen Administratoren eine Genehmigungsanfrage:

  1. Gehe zu GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. Klicke unter **Organization access** neben deiner Organisation auf **Request**. Dadurch werden deine Organisationsadministratoren benachrichtigt
  3. Ein Administrator genehmigt die Anfrage unter **Settings** → **Third-party access** → **OAuth application policy** der Organisation (ausstehende Anfragen zeigen eine Schaltfläche **Approve**)
  4. Kehre zum Jamdesk-Setup-Ablauf zurück und klicke auf **refresh the list**. Deine Organisation sollte nun erscheinen

  Ausführliche Schritte findest du im GitHub-Leitfaden zu [Genehmigung von OAuth-Apps für deine Organisation](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization).
</Accordion>

<Accordion title="In deinem persönlichen Konto erstellen und später übertragen">
  Wähle während des Setups dein persönliches Konto, um die Administratorgenehmigung zu überspringen. Übertrage das Repository anschließend in deine Organisation:

  1. Schließe das Jamdesk-Setup mit deinem persönlichen Konto ab
  2. Öffne das erstellte Repository auf GitHub
  3. Öffne **Settings** → **General** → **Danger Zone**
  4. Klicke auf **Transfer** und wähle deine Organisation als Ziel
  5. Trenne in Jamdesk die Verbindung zum Repository auf der Seite **Settings** deines Projekts und verbinde es erneut

  <Warning>
    Das Trennen und erneute Verbinden erzeugt eine neue Docs-URL (z. B. kann sich `your-project.jamdesk.app` ändern). Wenn du deine URL bereits geteilt oder eine eigene Domain eingerichtet hast, kontaktiere den [Support](/de/help/support/contact), bevor du die Verbindung trennst. Wir können deine Konfiguration erhalten.
  </Warning>

  Das funktioniert nicht, wenn dein Unternehmen dein GitHub-Konto verwaltet. Siehe stattdessen [firmenverwaltete GitHub-Konten](#von-unternehmen-verwaltete-github-konten).
</Accordion>

## Von Unternehmen verwaltete GitHub-Konten

GitHub blockiert App-Installationen auf firmenverwalteten Konten (GitHub nennt sie Enterprise Managed Users, kurz EMU). Nur eine Organisation kann Apps installieren. Ohne Organisation führt ein Klick auf **Install** bei GitHub zurück auf die Jamdesk-App-Seite. Die Jamdesk-Registrierung zeigt „Your organization manages this GitHub account“.

Verwaltete Benutzernamen enden auf einen Unterstrich und einen Firmencode, z. B. `jsmith_acme`. GitHub erläutert die Einschränkungen auf seiner Seite zu [verwalteten Benutzerkonten](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts).

Behebe es mit einer dieser Optionen.

<Accordion title="Repository in eine Organisation verschieben">
  1. Bitte einen Enterprise-Inhaber, eine [Organisation zu erstellen](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise) über den Tab **Organizations** deines Enterprise. Bitte ihn, dir das Erstellen von Repos darin zu erlauben.
  2. [Übertrage dein Docs-Repository](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository) in diese Organisation. Gehe im Repo zu **Settings**, klicke unten auf **Transfer** und wähle die neue Organisation.
  3. Klicke in Jamdesk auf **Connect an existing repository** (oder **Install GitHub App** in den Projekteinstellungen). Wähle bei GitHub die Organisation, wähle **Only select repositories**, wähle dein Repo aus und installiere.

  Wenn GitHub **Request** statt **Install** anzeigt, erhält ein Organisationsinhaber eine E-Mail zur Genehmigung. Klicke nach der Genehmigung erneut auf die Jamdesk-Schaltfläche.
</Accordion>

<Accordion title="Persönliches GitHub-Konto verwenden">
  Nutze das, wenn dein Unternehmen keine Organisation hinzufügen kann. Kläre das vorher mit deinem GitHub-Administrator. Die Dokumentation liegt dann außerhalb des GitHub-Accounts deines Unternehmens.

  1. Melde dich in einem privaten Browserfenster mit einem persönlichen Konto bei GitHub an (oder erstelle eines).
  2. Erstelle darauf ein leeres privates Repo.
  3. Lade eine Kopie deiner Dokumentation hinein. GitHub kann Repos nicht aus einem verwalteten Enterprise heraus übertragen.

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     Behalte `jsmith@` in der URL, damit Git nach dem Login deines persönlichen Kontos fragt.

  4. Klicke in Jamdesk auf **Connect an existing repository** (oder **Install GitHub App** in den Projekteinstellungen), installiere Jamdesk auf deinem persönlichen Konto und wähle das Repo aus.

  Verwaltete Konten können nicht in Repos außerhalb deines Enterprise pushen. Jeder Docs-Editor braucht ein persönliches GitHub-Konto. Füge sie dem Repo als Mitarbeiter hinzu.
</Accordion>

## Repository wird nicht angezeigt

Wenn dein Repository nicht in der Liste erscheint:

<Accordion title="Repository-Berechtigungen prüfen">
  1. Gehe zu GitHub → Settings → Applications → Jamdesk
  2. Prüfe, ob dem Repository Zugriff gewährt wurde
  3. Klicke auf **Configure**, um weitere Repositories hinzuzufügen
</Accordion>

<Accordion title="Organisations-Repositories">
  Für Organisations-Repos:
  1. Ein Organisationsadministrator muss Jamdesk genehmigen
  2. Gehe zu den Organisationseinstellungen → Third-party access
  3. Genehmige die Zugriffsanfrage für Jamdesk
</Accordion>

<Accordion title="Private Repositories">
  Private Repos erfordern eine GitHub-Autorisierung. Autorisiere Jamdesk bei Bedarf erneut.
</Accordion>

## Builds werden nicht ausgelöst

Wenn Pushes keine Builds auslösen:

<Steps>
  <Step title="Webhook prüfen">
    1. Gehe zu deinem Repo auf GitHub
    2. Öffne Settings → Webhooks
    3. Suche den Jamdesk-Webhook
    4. Prüfe „Recent Deliveries“ auf Fehler
  </Step>
  <Step title="Branch prüfen">
    Builds werden nur auf dem konfigurierten Branch ausgelöst. Prüfe **Settings** in Jamdesk.
  </Step>
  <Step title="Pusher prüfen">
    Wenn der Build mit einer Meldung fehlschlägt, dass die pushende Person kein Mitglied ist, lade sie unter **Project Settings → Members** ein oder bitte sie, ihr GitHub-Konto zu verknüpfen. Siehe [Builds werden nicht ausgelöst](/de/integrations/github#builds-werden-nicht-ausgelöst).
  </Step>
  <Step title="Verbindung neu synchronisieren">
    1. Gehe in Jamdesk zu den Projekt-**Settings**
    2. Klicke auf **Re-sync GitHub**
  </Step>
</Steps>

## Webhook-Fehler

### 404 Not Found

Der Webhook-Endpunkt war nicht erreichbar.

**Lösung:** Synchronisiere die GitHub-Verbindung in den Projekteinstellungen neu.

### 401 Unauthorized

Die Authentifizierung ist fehlgeschlagen.

**Lösung:**
1. Gehe zu deinen GitHub-Kontoeinstellungen
2. Öffne Applications → Authorized OAuth Apps
3. Widerrufe Jamdesk
4. Autorisiere Jamdesk in den Jamdesk-Einstellungen erneut

### 500 Server Error

Vorübergehendes Jamdesk-Problem.

**Lösung:** Warte ein paar Minuten und pushe erneut oder starte einen manuellen Rebuild.

## Berechtigungsfehler

**„Repository not found“** während des Builds:

- Das Repository wurde möglicherweise gelöscht oder umbenannt
- Jamdesk hat möglicherweise den Zugriff verloren
- Autorisiere deine GitHub-Verbindung erneut

## Branch-Probleme

### Falscher Branch wird erstellt

Prüfe deinen konfigurierten Branch unter **Settings** → **Repository**.

### Branch umbenannt oder gelöscht

Passe deine Branch-Einstellung an den neuen Branch-Namen an.
