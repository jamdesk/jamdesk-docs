Die meisten Probleme mit der GitHub-Integration lassen sich auf Berechtigungen, Webhook-Fehler oder Branch-Konflikte zurückführen.

## Organisation wird während der Einrichtung nicht angezeigt

Im Einrichtungsablauf der Starter-Dokumentation zeigt Jamdesk Ihre GitHub-Organisationen an, damit Sie auswählen können, wo das Repository erstellt werden soll. Die Liste stammt aus der OAuth API von GitHub. GitHub blendet Organisationen in zwei Fällen aus:

- OAuth-App-Einschränkungen: Ihre Organisation beschränkt den Zugriff von Drittanbieter-Apps (die Standardeinstellung für neue Organisationen bei GitHub) und hat Jamdesk noch nicht genehmigt.
- SAML SSO: Ihre Organisation erfordert eine SAML-Authentifizierung, bevor die API sie zurückgibt.

<Accordion title="Zugriff selbst gewähren (Organisationsinhaber)">
  Wenn Sie Inhaber der Organisation sind, können Sie Jamdesk sofort genehmigen:

  1. Klicken Sie unter der Organisationsauswahl auf GitHub auf **grant Jamdesk access on GitHub** (oder gehen Sie zu GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. Klicken Sie unter **Organization access** neben Ihrer Organisation auf **Grant**
  3. Klicken Sie im Jamdesk-Einrichtungsablauf auf **refresh the list**. Ihre Organisation wird sofort angezeigt

  Wenn Sie Mitglied und kein Inhaber sind, wird stattdessen eine **Request**-Schaltfläche angezeigt. Wenn Sie darauf klicken, wird eine Genehmigungsanfrage an die Administratoren Ihrer Organisation gesendet.
</Accordion>

<Accordion title="Bitten Sie den Organisationsadministrator, Jamdesk zu genehmigen (Mitglieder)">
  Wenn Sie Mitglied ohne Inhaberrechte sind, senden Sie zunächst eine Genehmigungsanfrage an Ihre Administratoren:

  1. Gehen Sie zu GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. Klicken Sie unter **Organization access** neben Ihrer Organisation auf **Request**. Dadurch werden die Administratoren Ihrer Organisation benachrichtigt
  3. Ein Administrator genehmigt die Anfrage unter **Settings** → **Third-party access** → **OAuth application policy** der Organisation (ausstehende Anfragen zeigen eine **Approve**-Schaltfläche)
  4. Kehren Sie zum Jamdesk-Einrichtungsablauf zurück und klicken Sie auf **refresh the list**. Ihre Organisation sollte nun angezeigt werden

  Eine ausführliche Anleitung finden Sie im GitHub-Leitfaden zum [Genehmigen von OAuth-Apps für Ihre Organisation](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization).
</Accordion>

<Accordion title="In Ihrem persönlichen Konto erstellen und später übertragen">
  Möchten Sie nicht auf die Genehmigung durch einen Administrator warten? Wählen Sie während der Einrichtung Ihr persönliches Konto aus und übertragen Sie das Repository anschließend in Ihre Organisation:

  1. Schließen Sie die Jamdesk-Einrichtung mit Ihrem persönlichen Konto ab
  2. Öffnen Sie das erstellte Repository auf GitHub
  3. Gehen Sie zu **Settings** → **General** → **Danger Zone**
  4. Klicken Sie auf **Transfer** und wählen Sie Ihre Organisation als Ziel aus
  5. Trennen Sie in Jamdesk die Verbindung zum Repository und stellen Sie sie auf der **Settings**-Seite Ihres Projekts wieder her

  <Warning>
    Durch das Trennen und Wiederherstellen der Verbindung wird eine neue Dokumentations-URL erstellt (z. B. kann sich `your-project.jamdesk.app` ändern). Wenn Sie Ihre URL bereits weitergegeben oder eine benutzerdefinierte Domain eingerichtet haben, wenden Sie sich vor dem Trennen an den [Support](/de/help/support/contact), damit wir Ihre Konfiguration beibehalten können.
  </Warning>

  Dies funktioniert nicht, wenn Ihr Unternehmen Ihr GitHub-Konto verwaltet. Lesen Sie stattdessen den Abschnitt [Von Unternehmen verwaltete GitHub-Konten](#von-unternehmen-verwaltete-github-konten).
</Accordion>

## Von Unternehmen verwaltete GitHub-Konten

Wenn Ihr Unternehmen Ihr GitHub-Konto verwaltet (GitHub bezeichnet diese als Enterprise Managed Users oder EMU), können Sie Apps nicht auf Ihrem eigenen Konto installieren, sondern nur in einer Organisation. Wenn Ihnen keine Organisation zur Verfügung steht, gelangen Sie durch Klicken auf **Install** bei GitHub lediglich zurück zur Jamdesk-App-Seite. Während der Registrierung zeigt Jamdesk die Meldung „Your organization manages this GitHub account“ an.

Verwaltete Benutzernamen enden mit einem Unterstrich und einem Unternehmenskürzel, z. B. `jsmith_acme`. GitHub erläutert die Einschränkungen auf der Seite zu [verwalteten Benutzerkonten](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts).

Sie können dieses Problem auf zwei Arten beheben.

<Accordion title="Repository in eine Organisation verschieben">
  1. Bitten Sie einen Enterprise-Inhaber, über die Registerkarte **Organizations** Ihres Enterprise eine [Organisation zu erstellen](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise). Bitten Sie ihn, Ihnen das Erstellen von Repositories darin zu erlauben.
  2. [Übertragen Sie Ihr Dokumentations-Repository](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository) dorthin. Gehen Sie im Repository zu **Settings**, klicken Sie unten auf **Transfer** und wählen Sie die neue Organisation aus.
  3. Klicken Sie in Jamdesk auf **Connect an existing repository** (oder in den Projekteinstellungen auf **Install GitHub App**). Wählen Sie auf GitHub die Organisation aus, wählen Sie **Only select repositories**, markieren Sie Ihr Repository und installieren Sie die App.

  Wenn GitHub statt **Install** die Option **Request** anzeigt, erhält ein Organisationsinhaber eine E-Mail zur Genehmigung. Klicken Sie anschließend erneut auf die Jamdesk-Schaltfläche.
</Accordion>

<Accordion title="Persönliches GitHub-Konto verwenden">
  Verwenden Sie diese Option, wenn Ihr Unternehmen keine Organisation hinzufügen kann. Klären Sie dies zuerst mit Ihrem GitHub-Administrator, da die Dokumentation außerhalb des GitHub-Kontos Ihres Unternehmens gespeichert wird.

  1. Melden Sie sich in einem privaten Browserfenster mit einem persönlichen Konto bei GitHub an (oder erstellen Sie eines).
  2. Erstellen Sie in diesem Konto ein leeres privates Repository.
  3. Übertragen Sie eine Kopie Ihrer Dokumentation dorthin. GitHub kann Repositories nicht aus einem verwalteten Enterprise verschieben, daher ist eine Kopie erforderlich.

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     Lassen Sie `jsmith@` in der URL stehen, damit Git nach den Anmeldedaten Ihres persönlichen Kontos fragt.

  4. Klicken Sie in Jamdesk auf **Connect an existing repository** (oder in den Projekteinstellungen auf **Install GitHub App**), installieren Sie Jamdesk in Ihrem persönlichen Konto und wählen Sie das Repository aus.

  Verwaltete Konten können keine Pushes an Repositories außerhalb Ihres Enterprise durchführen. Daher benötigt jede Person, die die Dokumentation bearbeitet, ein persönliches GitHub-Konto. Fügen Sie diese Personen als Mitbearbeiter zum Repository hinzu.
</Accordion>

## Repository wird nicht angezeigt

Wenn Ihr Repository nicht in der Liste angezeigt wird:

<Accordion title="Repository-Berechtigungen prüfen">
  1. Gehen Sie zu GitHub → Settings → Applications → Jamdesk
  2. Prüfen Sie, ob der Zugriff auf das Repository gewährt wurde
  3. Klicken Sie auf **Configure**, um weitere Repositories hinzuzufügen
</Accordion>

<Accordion title="Repositories von Organisationen">
  Für Repositories von Organisationen gilt:

  1. Ein Organisationsadministrator muss Jamdesk genehmigen
  2. Gehen Sie zu den Organisationseinstellungen → Third-party access
  3. Genehmigen Sie die Zugriffsanfrage von Jamdesk
</Accordion>

<Accordion title="Private Repositories">
  Für private Repositories ist eine Autorisierung durch GitHub erforderlich. Autorisieren Sie Jamdesk bei Bedarf erneut.
</Accordion>

## Builds werden nicht ausgelöst

Wenn Pushes keine Builds auslösen:

<Steps>
  <Step title="Webhook prüfen">
    1. Gehen Sie zu Ihrem Repository auf GitHub
    2. Gehen Sie zu Settings → Webhooks
    3. Suchen Sie den Jamdesk-Webhook
    4. Prüfen Sie **Recent Deliveries** auf Fehler
  </Step>
  <Step title="Branch überprüfen">
    Builds werden nur für Ihren konfigurierten Branch ausgelöst. Prüfen Sie **Settings** in Jamdesk.
  </Step>
  <Step title="Verbindung erneut synchronisieren">
    1. Gehen Sie in Jamdesk zu den **Settings** des Projekts
    2. Klicken Sie auf **Re-sync GitHub**
  </Step>
</Steps>

## Webhook-Fehler

### 404 Nicht gefunden

Der Webhook-Endpoint konnte nicht erreicht werden.

**Lösung:** Synchronisieren Sie die GitHub-Verbindung in den Projekteinstellungen erneut.

### 401 Nicht autorisiert

Die Authentifizierung ist fehlgeschlagen.

**Lösung:**
1. Öffnen Sie die Einstellungen Ihres GitHub-Kontos
2. Gehen Sie zu Applications → Authorized OAuth Apps
3. Entziehen Sie Jamdesk die Berechtigung
4. Autorisieren Sie Jamdesk in den Jamdesk-Einstellungen erneut

### 500 Serverfehler

Vorübergehendes Jamdesk-Problem.

**Lösung:** Warten Sie einige Minuten und führen Sie erneut einen Push durch oder lösen Sie einen manuellen Rebuild aus.

## Berechtigungsfehler

**„Repository not found“** während des Builds:

- Das Repository wurde möglicherweise gelöscht oder umbenannt
- Jamdesk hat möglicherweise den Zugriff verloren
- Autorisieren Sie Ihre GitHub-Verbindung erneut

## Branch-Probleme

### Falscher Branch wird erstellt

Prüfen Sie Ihren konfigurierten Branch unter **Settings** → **Repository**.

### Branch umbenannt oder gelöscht

Aktualisieren Sie Ihre Branch-Einstellung so, dass sie dem neuen Branchnamen entspricht.
