## Authentifizierungsprobleme

<AccordionGroup>
  <Accordion title='"Not logged in" oder "Session expired"'>
    Ihre gespeicherten Zugangsdaten fehlen oder das Refresh-Token ist nicht mehr gültig.

    **Lösung:** Führen Sie `jamdesk login` aus, um eine neue Sitzung zu starten. Dies ersetzt den bisherigen Inhalt von `~/.jamdeskrc`.

    Wenn der Fehler direkt nach der Anmeldung immer wieder auftritt, prüfen Sie, ob `~/.jamdeskrc` geschrieben wurde:

    ```bash
    cat ~/.jamdeskrc
    ```

    Die Datei sollte ein `auth`-Objekt mit `refreshToken`, `email` und `uid` enthalten. Ist sie leer oder fehlt sie, gibt es möglicherweise Berechtigungsprobleme in Ihrem Home-Verzeichnis.
  </Accordion>

  <Accordion title="Login läuft in ein Timeout">
    Die CLI startet einen lokalen Server auf Port 9876, um den Auth-Callback aus Ihrem Browser zu empfangen. Der Login läuft in ein Timeout, wenn der Callback nicht innerhalb von 2 Minuten eintrifft.

    **Häufige Ursachen:**
    - Eine Firewall blockiert den lokalen Server
    - Der Browser-Tab wurde vor Abschluss der Authentifizierung geschlossen
    - Port 9876 ist belegt (die CLI wählt automatisch einen anderen Port, aber die URL muss dazu passen)

    **Lösung:** Kopieren Sie die im Terminal ausgegebene URL und öffnen Sie sie manuell. Prüfen Sie, ob die Portnummer in der URL mit dem Port übereinstimmt, auf dem die CLI lauscht.
  </Accordion>

  <Accordion title="Browser öffnet sich beim Login nicht">
    Das ist in Headless-Umgebungen normal (SSH-Sitzungen, Docker-Container, CI-Runner). Die CLI gibt die Login-URL immer im Terminal aus.

    Kopieren Sie sie und öffnen Sie sie in einem beliebigen Browser, der Ihren Rechner über den Callback-Port erreichen kann.
  </Accordion>

  <Accordion title='"session expired" nach Passwortänderung'>
    Das Ändern Ihres Jamdesk-Passworts macht alle bestehenden Refresh-Tokens ungültig. Die CLI erkennt dies (`TOKEN_EXPIRED` oder `INVALID_REFRESH_TOKEN`) und löscht die gespeicherte Authentifizierung automatisch.

    Führen Sie `jamdesk login` erneut aus.
  </Accordion>
</AccordionGroup>

## Bereitstellungsfehler

<AccordionGroup>
  <Accordion title='"A build is already in progress"'>
    Pro Projekt läuft jeweils nur ein Build. Die CLI gibt diesen Fehler (Code `BUILD_IN_PROGRESS`) zurück, wenn ein Build eingeplant ist oder läuft.

    **Lösung:** Warten Sie, bis der aktuelle Build abgeschlossen ist. Den Status finden Sie unter **Deployments** im Dashboard. Wirkt ein Build festgefahren, bitten Sie den Projektinhaber, im Dashboard nachzusehen.
  </Accordion>

  <Accordion title='"docs.json not found or invalid"'>
    Im aktuellen Verzeichnis gibt es keine `docs.json` oder sie enthält JSON-Syntaxfehler.

    **Lösung:**
    1. Stellen Sie sicher, dass Sie im richtigen Verzeichnis sind: `ls docs.json`
    2. Führen Sie `jamdesk validate` aus, um genaue Fehlerdetails zu erhalten
    3. Prüfen Sie auf fehlende Kommas, nicht geschlossene Klammern oder abschließende Kommas (die CLI verwendet für `docs.json` JSON, nicht JSON5)
  </Accordion>

  <Accordion title='"Upload too large"'>
    Ihr komprimiertes Tarball überschreitet das Limit von 100 MB. Alles, was nicht durch `.gitignore` oder die eingebaute Ausschlussliste ausgeschlossen ist, wird gepackt.

    **Lösung:** Prüfen Sie, was mitgeliefert wird. Häufige Verursacher: Videodateien, große PDFs, unkomprimierte Bilder, Datenexporte. Fügen Sie sie zu `.gitignore` hinzu.

    Immer ausgeschlossen, unabhängig von `.gitignore`: `.git`, `node_modules`, `.next`, `.env*`, `*.pem`, `*.key`, `credentials.json`, `.DS_Store`.
  </Accordion>

  <Accordion title='"No files to deploy"'>
    Jede Datei passt auf ein Ausschlussmuster.

    **Lösung:** Prüfen Sie, ob Ihre `.gitignore` keine MDX-Dateien oder `docs.json` ausschließt.
  </Accordion>

  <Accordion title='"Project not found" oder "Access denied"'>
    Entweder passt die `projectId` in `docs.json` zu keinem Projekt in Ihrem Konto, oder Sie sind kein Mitglied dieses Projekts.

    **Lösung:**
    - Entfernen Sie das Feld `projectId` aus `docs.json` und führen Sie `jamdesk deploy` erneut aus, um ein neues Projekt auszuwählen
    - Prüfen Sie, ob Sie mit dem richtigen Konto angemeldet sind: `jamdesk whoami`
    - Prüfen Sie die Projektmitgliedschaft im Dashboard
  </Accordion>

  <Accordion title="Deploy hängt beim Abfragen des Build-Status">
    Die CLI fragt den Build-Status alle 2 Sekunden ab. Nach 3 aufeinanderfolgenden fehlgeschlagenen Abfragen gibt sie auf.

    **Lösung:** Drücken Sie Strg+C. Der Build läuft im Hintergrund weiter. Prüfen Sie den Status im Dashboard. Die CLI gibt beim Beenden einen Link aus.
  </Accordion>

  <Accordion title="Build fehlgeschlagen">
    Der Upload war erfolgreich, der Build ist fehlgeschlagen. Das Terminal zeigt den Fehler des Build-Dienstes.

    **Lösung:** Prüfen Sie das Build-Protokoll im Dashboard unter **Deployments**. Häufige Ursachen: MDX-Syntaxfehler, in der Navigation referenzierte, aber fehlende Seiten, ungültige OpenAPI-Spezifikationen. Führen Sie `jamdesk validate` lokal aus, um diese vor dem Deploy zu finden.
  </Accordion>

  <Accordion title="Warnungen zu geheimen Dateien">
    Die CLI warnt vor Dateien, die wie Geheimnisse aussehen (`.env`, `*.pem`, `*.key`, `credentials.json`, Dateien, die mit `secret` beginnen). Die Warnung blockiert das Deploy nicht.

    **Lösung:** Fügen Sie die Dateien zu `.gitignore` hinzu, um sie vom Upload auszuschließen. Sind sie beabsichtigt (z. B. Beispiel-Schlüsseldateien in Ihrer Dokumentation), ignorieren Sie die Warnung.
  </Accordion>
</AccordionGroup>

## Probleme mit dem Dev-Server

<AccordionGroup>
  <Accordion title="Dev-Server startet nicht">
    **In dieser Reihenfolge versuchen:**
    1. `jamdesk doctor`, um die Node.js-Version (v20+ erforderlich) und die Umgebung zu prüfen
    2. `jamdesk clean`, um zwischengespeicherte Abhängigkeiten zu löschen
    3. `jamdesk dev --verbose` für detaillierte Fehlerausgaben
    4. `jamdesk dev --clean`, um den Build-Cache vor dem Start zu leeren
  </Accordion>

  <Accordion title="Port bereits belegt">
    Die CLI versucht 10 aufeinanderfolgende Ports, beginnend mit dem angeforderten Port (Standard 3000). Sind alle 10 belegt, schlägt sie fehl.

    **Lösung:**
    ```bash
    # Find what's using the port
    lsof -i :3000

    # Pick a different port
    jamdesk dev --port 3001
    ```

    Legen Sie einen dauerhaften Standard fest, indem Sie `"defaultPort": 3001` zu Ihrer Datei `~/.jamdeskrc` hinzufügen. Überschreiben Sie die Datei nicht, sie kann Ihre Zugangsdaten enthalten.
  </Accordion>

  <Accordion title="Turbopack-Cache beschädigt">
    Wird der Dev-Server während der Kompilierung beendet (Zwangsbeendigung, Systemabsturz), kann der `.next`-Cache beschädigt werden. Beim nächsten Start erscheinen Meldungen wie „corrupted database“ oder Panic-Fehler.

    **Lösung:**
    ```bash
    jamdesk dev --clean
    ```

    Dies löscht das Verzeichnis `.next` und startet neu.
  </Accordion>

  <Accordion title="Langsamer erster Start">
    Der erste `jamdesk dev` installiert Laufzeitabhängigkeiten nach `~/.jamdesk/node_modules`. Das passiert einmal und kann bei langsameren Verbindungen 1–2 Minuten dauern.

    Weitere Starts überspringen die Installation, außer die CLI-Version ändert sich.
  </Accordion>

  <Accordion title="Installation der Abhängigkeiten schlägt fehl oder hängt">
    `npm install` läuft beim ersten Start nach 5 Minuten in ein Timeout.

    **Lösung:**
    1. Prüfen Sie Ihre Internetverbindung
    2. `jamdesk clean`, um Teilinstallationen zu löschen
    3. Erneut versuchen
    4. Ist npm dauerhaft langsam, prüfen Sie die npm-Registry-Konfiguration: `npm config get registry`
  </Accordion>
</AccordionGroup>

## Validierung und Link-Prüfung

<AccordionGroup>
  <Accordion title="MDX-Syntaxfehler">
    MDX behandelt `<` als JSX-Tag-Beginn. Schreiben Sie `<50%`, entsteht ein Parse-Fehler.

    **Lösung:** Mit `&lt;` maskieren oder umformulieren. Führen Sie `jamdesk validate` aus, um Zeilennummern und Vorschläge zu erhalten.
  </Accordion>

  <Accordion title="Defekte Links gefunden">
    `jamdesk broken-links` hat interne Links gefunden, die auf nicht existierende Seiten verweisen.

    **Lösung:** Prüfen Sie die Dateipfade. Häufige Fehler: falsche Groß-/Kleinschreibung (`Quickstart` statt `quickstart`), die Dateiendung `.mdx` mit angegeben oder alte, umbenannte Pfade.

    Die CLI schlägt Korrekturen für ähnliche Treffer vor (innerhalb von 3 Zeichen eines Tippfehlers).

    **Automatisch beheben.** Hat ein defekter Link ein eindeutiges korrektes Ziel (ein fehlerhafter Anker oder eine Abweichung des Anker-Ziels zwischen Sprachen), führen Sie `jamdesk fix --dry-run` aus, um die Änderungen vorab anzusehen, und dann `jamdesk fix`, um sie anzuwenden. Es werden nur Links umgeschrieben, deren korrigierter Anker eine echte Überschrift auf der Zielseite ist. Mehrdeutige Fälle beheben Sie von Hand. Siehe [Defekte Links automatisch beheben](/de/cli/fix-broken-links).
  </Accordion>

  <Accordion title="OpenAPI-Spezifikationsprüfung schlägt fehl">
    Die CLI validiert die in `docs.json` referenzierten OpenAPI-Spezifikationen. Fehlschläge umfassen ungültige `$ref`-Referenzen, fehlende Pflichtfelder oder Syntaxfehler.

    **Lösung:** Führen Sie `jamdesk openapi-check path/to/spec.yaml` für detaillierte Ausgaben aus. Verwenden Sie den [Swagger Editor](https://editor.swagger.io), um komplexe Spezifikationen zu debuggen.

    <Note>Swagger-2.0-Spezifikationen zeigen eine Warnung, bestehen die Validierung aber trotzdem.</Note>
  </Accordion>
</AccordionGroup>

## Allgemeine Probleme

<AccordionGroup>
  <Accordion title="Befehl nicht gefunden: jamdesk">
    Nicht global installiert, oder Ihre Shell findet das Programm nicht.

    **Lösung:**
    ```bash
    npm install -g jamdesk
    ```

    Wenn Sie mit `curl` installiert haben, stellen Sie sicher, dass `~/.jamdesk/bin` in Ihrem `PATH` liegt.
  </Accordion>

  <Accordion title="Berechtigung verweigert">
    Die CLI benötigt Schreibzugriff auf `~/.jamdesk` (Cache) und `~/.jamdeskrc` (Zugangsdaten).

    **Lösung:**
    ```bash
    ls -la ~/.jamdesk ~/.jamdeskrc
    sudo chown -R $(whoami) ~/.jamdesk ~/.jamdeskrc
    ```
  </Accordion>

  <Accordion title="Aktualisierung schlägt fehl">
    `jamdesk update` führt `npm install -g jamdesk@latest` aus. Es schlägt fehl, wenn npm Berechtigungsprobleme hat oder die Registry nicht erreichbar ist.

    **Lösung:** Aktualisieren Sie manuell:
    ```bash
    npm install -g jamdesk@latest
    ```

    Schlägt auch das fehl, prüfen Sie `npm config get registry` und versuchen Sie `sudo npm install -g jamdesk@latest`.
  </Accordion>
</AccordionGroup>
