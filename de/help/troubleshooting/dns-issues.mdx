DNS-Probleme sind die häufigste Ursache für Schwierigkeiten mit eigenen Domains.

## DNS-Propagation prüfen

DNS-Änderungen können bis zu 48 Stunden benötigen, bis sie wirksam sind. Die meisten sind innerhalb weniger Stunden abgeschlossen.

Propagierungsstatus prüfen:

```bash
# Check if your CNAME is resolving
dig CNAME docs.yourdomain.com

# Or use nslookup
nslookup -type=CNAME docs.yourdomain.com
```

Die erwartete Ausgabe zeigt Ihren CNAME, der auf `cname.jamdesk.com` verweist:

```text
docs.yourdomain.com. 300 IN CNAME cname.jamdesk.com.
```

Online-Tools wie [whatsmydns.net](https://www.whatsmydns.net/) zeigen die Propagierung über mehrere Regionen hinweg.

## Häufige Probleme

### CNAME wird nicht aufgelöst

**Symptom**: `dig` zeigt keinen CNAME-Eintrag oder ein falsches Ziel an.

**Ursachen**:
- Eintrag wurde beim DNS-Anbieter nicht gespeichert
- Tippfehler im Namen oder Wert des Eintrags
- DNS-Propagierung läuft noch

**Lösung**:
1. Melden Sie sich bei Ihrem DNS-Anbieter an
2. Prüfen Sie, ob der CNAME-Eintrag mit den richtigen Werten existiert
3. Warten Sie 15–30 Minuten und prüfen Sie erneut

### CNAME auf der Root-Domain

**Symptom**: Der DNS-Anbieter lehnt einen CNAME-Eintrag für `yourdomain.com` (ohne Subdomain) ab.

**Ursache**: DNS-Standards (RFC 1034) verbieten CNAME-Einträge an der Zonenspitze (Root-Domain).

**Lösung**: Das Jamdesk-Dashboard zeigt für Root-Domains automatisch einen A-Eintrag (`76.76.21.21`) statt eines CNAME an. Wenn Ihr Dashboard für eine Root-Domain noch einen CNAME anzeigt, klicken Sie auf **Refresh**, um die aktualisierten Einträge abzurufen.

### Konflikte mit dem Cloudflare-Proxy

**Symptom**: SSL-Fehler oder Weiterleitungsschleifen bei Verwendung von Cloudflare.

**Ursache**: Der Cloudflare-Proxy (orangefarbene Wolke) kann das SSL von Vercel stören.

**Lösung**:
1. Klicken Sie in den Cloudflare-DNS-Einstellungen auf das orangefarbene Wolkensymbol
2. Stellen Sie für Ihre Docs-Subdomain auf „Nur DNS“ (graue Wolke) um
3. Lassen Sie Vercel das SSL-Zertifikat ausstellen

### Konfligierende Einträge

**Symptom**: Die CNAME-Verifizierung schlägt fehl, obwohl der Eintrag korrekt aussieht.

**Ursache**: Ein bestehender A-Eintrag steht im Konflikt mit dem CNAME.

**Lösung**:
1. Prüfen Sie, ob auf derselben Subdomain A-Einträge existieren
2. Löschen Sie die widersprüchlichen A-Einträge
3. Stellen Sie sicher, dass nur der CNAME übrig bleibt

```bash
# Check for A records
dig A docs.yourdomain.com
```

### TXT-Verifizierung schlägt fehl

**Symptom**: Der TXT-Eintrag für das Hosting im Unterpfad lässt sich nicht verifizieren.

**Ursachen**:
- Eintrag wurde zur falschen Domain hinzugefügt
- Tippfehler im Eintragswert
- Widersprüchliche TXT-Einträge

**Lösung**:
1. Prüfen Sie, ob der TXT-Eintrag unter `_jamdesk.yourdomain.com` liegt
2. Kopieren Sie den genauen Verifizierungswert aus dem Dashboard
3. Prüfen Sie auf widersprüchliche TXT-Einträge

```bash
# Check TXT records
dig TXT _jamdesk.yourdomain.com
```

### SSL-Zertifikat wird nicht ausgestellt

**Symptom**: Die Domain wird unbegrenzt als „pending“ angezeigt.

**Ursachen**:
- CAA-Einträge blockieren die Ausstellung des Zertifikats
- DNS ist noch nicht vollständig propagiert
- Domain ist nicht erreichbar

**Lösung**:

Prüfen Sie auf CAA-Einträge:
```bash
dig CAA yourdomain.com
```

Falls CAA-Einträge existieren, fügen Sie einen Eintrag hinzu, der Let's Encrypt erlaubt:
```text
yourdomain.com. CAA 0 issue "letsencrypt.org"
```

## Diagnosebefehle

```bash
# Full DNS lookup
dig +trace docs.yourdomain.com

# Check all record types
dig ANY docs.yourdomain.com

# Check specific nameservers
dig @8.8.8.8 docs.yourdomain.com

# Check TTL (time to live)
dig +noall +answer docs.yourdomain.com
```

## Hinweise zu bestimmten DNS-Anbietern

### Cloudflare
- Stellen Sie den Proxy-Status während der Domain-Verifizierung auf „Nur DNS“ (graue Wolke)
- Schalten Sie nach Abschluss der Verifizierung wieder auf proxied (orangefarbene Wolke) um
- Ein Worker läuft nur, wenn der DNS-Eintrag proxied ist (orangefarbene Wolke). Verwenden Sie die graue Wolke nur während der Verifizierung.
- Deaktivieren Sie „Always Use HTTPS“ für die Docs-Subdomain, um SSL-Konflikte mit Vercel zu vermeiden

### GoDaddy
- Das CNAME-Ziel sollte nicht mit einem Punkt enden
- Änderungen können länger zur Propagierung benötigen

### Namecheap
- Verwenden Sie den Typ „CNAME Record“
- Das Host-Feld enthält nur die Subdomain (`docs`, nicht `docs.yourdomain.com`)

### Route 53
- Das CNAME-Ziel muss mit einem Punkt enden (`cname.jamdesk.com.`)
- Zielzustand prüfen: Nein

## Wann Sie den Support kontaktieren sollten

Kontaktieren Sie den Support, wenn:
- DNS-Einträge als korrekt verifiziert wurden, die Domain aber nach 48 Stunden noch ausstehend ist
- SSL-Zertifikatsfehler auch nach Befolgen aller Schritte bestehen bleiben
- Fehler auftreten, die spezifisch für die Jamdesk-Infrastruktur sind

Fügen Sie Ihrer Support-Anfrage Folgendes bei:
- Ihren Domainnamen
- Den Namen Ihres DNS-Anbieters
- Die Ausgabe der `dig`-Befehle
- Einen Screenshot der DNS-Konfiguration
