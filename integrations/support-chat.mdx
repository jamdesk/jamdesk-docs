Jamdesk can load a live-chat widget on every page of your documentation site. Add the provider's block under `integrations` in `docs.json`. Jamdesk injects the widget script.

<Info>
Jamdesk checks each value against a strict format before it loads the widget. A value in the wrong format is silently skipped. You get no error page and no broken script tag.
</Info>

## Configure from the Dashboard

Open **Dashboard → Integrations**, pick the provider's card, and paste its ID. Jamdesk commits the `docs.json` block and triggers a rebuild (GitHub-connected projects only). Use the sections below to edit `docs.json` directly, or for CLI-only projects.

## Intercom

**Format:** App ID is 6-16 letters or numbers.

<Info>
Find your App ID at **Settings → Installation → Web** in Intercom. It's your workspace ID.
</Info>

```json docs.json
{
  "integrations": {
    "intercom": {
      "appId": "abc12345"
    }
  }
}
```

## Front Chat

**Format:** Chat ID is 8-64 lowercase hex characters (`0-9`, `a-f`).

```json docs.json
{
  "integrations": {
    "frontchat": {
      "snippetId": "3f8a2e1c9b6d4a7f"
    }
  }
}
```

## Consent Gating

The Intercom and Front Chat widgets respect `integrations.cookies`. With it set, the chat script waits for your consent banner to record approval. See [Cookie Consent](/integrations/cookie-consent) for setup. Without it, the widget loads for every visitor on page load.
