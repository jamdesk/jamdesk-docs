了解 Jamdesk 如何保护您的文档和账户数据。

## 基础设施安全

### 托管

Jamdesk 运行在符合 SOC 2 标准的云服务提供商上。构建、应用数据和编译后的文档存放在这些提供商的托管、强化服务中。流量由内置 DDoS 防护的全球 CDN 提供服务。

### 加密

| 数据状态 | 保护措施 |
|------------|------------|
| 传输中 | 您、我们的边缘节点和源站之间使用 TLS 1.3 |
| 静态存储 | 我们持久化的所有内容均使用 AES-256 加密，包括数据库记录、对象存储和日志 |
| 备份 | 使用相同密钥加密，并跨多个区域复制 |

## 访问控制

### 登录

您可以使用电子邮件和密码登录控制台，也可以通过 Google 或 GitHub 使用单点登录。我们的身份验证提供商仅保存单向密码哈希，从不保存明文密码。

您的 Google 或 GitHub 账户上的多因素认证（TOTP、安全密钥、通行密钥）同样适用于通过该账户进行的 Jamdesk 登录。为获得最强保护，请在该处开启多因素认证，并使用单点登录。

### 团队访问

基于角色的访问控制（所有者、管理员、成员）在我们的数据库安全规则和每次后端调用中强制执行。会话在一段时间不活动后过期。对账单、成员、自定义域名或 API 密钥的更改会写入每个项目的审计日志。

### GitHub 集成

Jamdesk 通过 GitHub App 连接您的代码仓库，权限如下：

- 对仓库内容的读写权限
- 用于触发构建的 Webhook 投递

只有在您要求时，Jamdesk 才会写入您的仓库：在控制台编辑器中保存更改、接受 Fix with AI 建议，或开启翻译（它会提交翻译后的页面）。构建过程仅读取。您可以随时从 GitHub [Applications 设置](https://github.com/settings/installations)撤销 Jamdesk 的访问权限。

### 令牌和密钥

我们对所有密钥进行静态加密，包括：

- GitHub App 连接，我们仅保存您的数字安装 ID。短期安装令牌（有效期一小时）按需生成，从不持久化。
- 来自入门仓库流程的 GitHub OAuth 令牌。我们对每个令牌仅交换一次，用于克隆模板，然后丢弃。
- 第三方集成凭据，例如 Slack 传入 Webhook URL、自定义域名验证令牌和分析 API 密钥。

保存后，控制台绝不会将这些值返回给浏览器。只有服务器端的构建流水线可以读取它们。

程序化 API 密钥以单向哈希形式存储。明文仅在创建时向您显示一次。如果丢失，请轮换该密钥。

## 数据处理

### 我们存储的内容

- 您的 `docs.json` 配置以及任何上传的品牌资源
- 编译后的文档（HTML、CSS、JS）
- 构建日志，保留 30 天
- 您的文档站点的页面浏览事件（路径、来源、国家、浏览器、设备类型以及每个标签页的会话 ID），90 天后删除。自 2026 年 10 月 14 日起记录的页面浏览不包含 IP 地址
- AI 聊天问题（前 200 个字符，不含答案），30 天后删除
- 您配置的任何第三方集成的加密密钥

### 我们不存储的内容

- 您的源代码。我们在构建时克隆代码仓库。工作树随构建容器一并丢弃。
- 长期有效的 GitHub 凭据。请参阅上文的**令牌与密钥**。
- 任何可逆形式的用户密码。
- 支付卡号。所有卡数据由 Stripe 保管。我们仅保留客户 ID 和订阅元数据。

### 内部访问

生产数据访问仅限于少数因运营服务或响应支持请求而需要访问的员工。访问会被记录。

## 构建隔离

每次文档构建都在专用容器中运行：

- 无法访问其他客户的数据
- 每次构建使用全新环境，密钥按需注入
- 构建完成或失败后，容器即被销毁

## 合规

### GDPR

**Jamdesk 是否符合 GDPR？是的。** Jamdesk 通过以下方式满足 GDPR 要求：

- [数据处理附录](https://jamdesk.com/dpa)自动适用，可应要求从 `privacy@jamdesk.com` 获取已签署副本
- 在 [jamdesk.com/subprocessors](https://jamdesk.com/subprocessors) 公布的分包处理方列表
- 在 30 天内履行删除权
- 通过导出实现数据可携带性

### 隐私

我们内置的分析功能：

- 不使用 Cookie。随机会话 ID 保存在浏览器的会话存储中，直至标签页关闭
- 不与广告网络共享数据
- 不记录访问者的 IP 地址

详情请参阅我们的[隐私政策](https://jamdesk.com/privacy)。

## 事件响应

我们针对影响您的账户或数据的安全事件的响应：

1. 调查并遏制问题。
2. 依据我们的 GDPR 义务，在 72 小时内通知受影响的客户。
3. 在确认原因后提供书面事后报告。

## 报告漏洞

请负责任地报告安全问题：

- 发送邮件至 `security@jamdesk.com`
- 请附上问题描述、复现步骤和影响评估
- 我们将在 48 小时内确认

我们不运行付费漏洞赏金计划。我们会对善意报告的研究人员予以致谢。
