## 入门

<AccordionGroup>
  <Accordion title="Jamdesk 是什么？">
    Jamdesk 是一个文档平台，可根据你的 Markdown 文件构建文档站点。使用 MDX 编写内容，推送到 GitHub，站点便会自动部署，并提供搜索、分析和适用于 AI 的 `llms.txt`。
  </Accordion>

  <Accordion title="我需要会编程吗？">
    不需要编程知识。使用 MDX 编写内容就像使用文本编辑器：你只需编写带有简单格式的纯文本。你可以按需使用组件，但组件完全是可选的。
  </Accordion>

  <Accordion title="我可以免费试用 Jamdesk 吗？">
    可以！我们提供 14 天免费试用，期间可完整使用所有功能。  
  </Accordion>

  <Accordion title="Jamdesk 与其他文档平台有什么区别？">
    Jamdesk 以 MDX 和 GitHub 为核心：你的文档是代码仓库中的纯文本文件，不会被锁定在专有编辑器中。推送到 GitHub 后，站点会在 60 秒内完成部署，无需配置构建或 CI/CD 流水线。每个站点都会自动获得 `llms.txt` 和 MCP 服务器，因此 Claude 和 ChatGPT 等 AI 工具可以直接访问最新文档。访客还可以使用内置的 [AI 聊天助手](/cn/ai/chat)向你的文档提问。
  </Accordion>
</AccordionGroup>

## 构建与部署

<AccordionGroup>
  <Accordion title="构建需要多长时间？">
    大多数文档站点会在 30–60 秒内构建完成。页面较多的大型站点可能需要更长时间。
  </Accordion>

  <Accordion title="发布前可以预览更改吗？">
    可以！使用 Jamdesk CLI（`jamdesk dev`）即可在本地预览，并启用热重载。只有推送到 GitHub 或运行 `jamdesk deploy` 后，更改才会正式生效。
  </Accordion>

  <Accordion title="不使用 GitHub 也能部署吗？">
    可以。在项目目录中运行 `jamdesk deploy`。CLI 会打包并上传文件，然后直接触发构建。无需 Git 仓库。详情请参阅 [CLI 部署指南](/cn/cli/deploy)。
  </Accordion>

  <Accordion title="什么情况下会触发构建？">
    推送到已连接的 GitHub 分支时会自动触发构建。你也可以在仪表板中手动触发构建，或通过 CLI 运行 `jamdesk deploy`。
  </Accordion>

  <Accordion title="可以回滚到之前的版本吗？">
    可以。在项目中前往 **Deployments**，找到之前的构建，然后点击 **Rollback**。
  </Accordion>
</AccordionGroup>

## 自定义域名

<AccordionGroup>
  <Accordion title="可以使用自己的域名吗？">
    可以！在 **Settings** → **Domains** 中添加自定义域名。SSL 证书会自动配置。
  </Accordion>

  <Accordion title="DNS 传播需要多长时间？">
    DNS 更改通常会在几小时内传播完成，但最长可能需要 48 小时。
  </Accordion>

  <Accordion title="可以将文档托管在 /docs 这样的子路径下吗？">
    可以。使用反向代理（Cloudflare、AWS 或 nginx）将 Jamdesk 部署在子路径下。请参阅[子路径托管](/cn/deploy/subpath-hosting)。
  </Accordion>
</AccordionGroup>

## 团队与协作

<AccordionGroup>
  <Accordion title="如何邀请团队成员？">
    打开项目，前往 **Settings** → **Members**，在 **Invite Member** 字段中输入对方的邮箱，然后点击 **Invite**。对方会收到一封包含项目加入链接的邮件。

    <Frame>
      <img src="/images/dashboard/settings-team.webp" alt="项目设置中的 Members 标签页，显示 Invite Member 字段和当前成员列表" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    受邀用户需要拥有 Jamdesk 账户；如果还没有账户，接受邀请时系统会提示他们创建账户。已经是成员，但邀请链接显示“already been accepted”？你不需要重新邀请。只需登录，就会返回项目。有关角色和成员数量限制，请参阅[团队成员](/cn/help/projects/team-members)。
  </Accordion>

  <Accordion title="我可以添加多少名团队成员？">
    每个套餐都允许每个项目添加不限数量的团队成员，无需额外付费。
  </Accordion>

  <Accordion title="团队成员可以编辑文档吗？">
    团队成员可以查看构建并触发重新构建，但文档编辑是在你的 GitHub 仓库中进行的。拥有仓库访问权限的任何人都可以编辑文档。
  </Accordion>

  <Accordion title="如何转让项目所有权？">
    前往 **Settings** → **Members**，然后点击想要提升的成员旁边的 **Transfer Ownership**。新所有者必须是现有团队成员。
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="CLI 凭据存储在哪里？">
    凭据存储在 `~/.jamdeskrc` 中，这是一个权限为 `0600` 的 JSON 文件（只有你的用户可以读取）。文件中保存了刷新令牌、邮箱和用户 ID。运行 `jamdesk logout` 即可清除凭据。
  </Accordion>

  <Accordion title='为什么 CLI 会提示 "session expired"？'>
    你的刷新令牌已失效。这可能是密码更改、账户删除或长时间未活动导致的。运行 `jamdesk login` 获取新的会话。
  </Accordion>

  <Accordion title="可以在 CI/CD 流水线中使用 CLI 吗？">
    可以，但基于浏览器的登录方式无法在无头环境中使用。先在本地计算机上登录，然后将 `~/.jamdeskrc` 复制到 CI 运行器。之后，刷新令牌会负责身份验证。
  </Accordion>

  <Accordion title="如何自动修复失效的链接？">
    运行 `jamdesk fix`。此命令会修复目标明确的失效内部链接（拼写错误的锚点和跨语言区域的锚点偏移），并在预览后编辑本地 `.mdx` 文件。先运行 `jamdesk fix --dry-run` 查看计划进行的更改；只有修正后的锚点确实对应一个标题时，链接才会被修改，存在歧义的情况则留待手动检查。请参阅[自动修复失效链接](/cn/cli/fix-broken-links)。
  </Accordion>
</AccordionGroup>

## 内容与功能

<AccordionGroup>
  <Accordion title="支持哪些文件格式？">
    Jamdesk 支持 MDX（Markdown + JSX）和标准 Markdown 文件。
  </Accordion>

  <Accordion title="可以使用自定义 React 组件吗？">
    可以。你可以在 MDX 中使用 `export const` 直接定义内联组件，也可以在 `/snippets` 目录中创建可复用组件。对于使用 hooks 的交互式组件，请使用带有 `'use client'` 的 `.tsx` 文件。请参阅[自定义 React 组件](/cn/content/react-components)和[代码片段](/cn/content/snippets)。
  </Accordion>

  <Accordion title="页面数量有限制吗？">
    页面数量没有硬性限制。大多数文档站点都能很好地支持数百个页面。
  </Accordion>

  <Accordion title="Jamdesk 支持多种语言吗？">
    支持。在导航配置中使用 `languages` 属性即可创建语言切换器。每种语言都有自己的导航结构和内容。请参阅[多语言支持](/cn/setup/languages)。
  </Accordion>

  <Accordion title="Jamdesk 会自动翻译我的内容吗？">
    不会。Jamdesk 不会为你翻译内容。你需要提供翻译后的 MDX 文件，Jamdesk 则负责路由、导航、语言切换器和 RTL 样式。你可以使用自己的工作流程（人工翻译、机器翻译或 LLM）准备译文，并将其放在带语言前缀的目录中（`es/`、`fr/` 等）。目录结构和配置详情请参阅[多语言支持](/cn/setup/languages)。
  </Accordion>
</AccordionGroup>

## AI 聊天

<AccordionGroup>
  <Accordion title="我的文档站点有 AI 聊天功能吗？">
    有。每个 Jamdesk 站点都内置聊天助手，可以根据文档回答访客的问题。此功能默认启用，无需设置。详情请参阅 [AI 聊天](/cn/ai/chat)。
  </Accordion>

  <Accordion title="AI 聊天需要额外付费吗？">
    不需要。所有套餐都包含 AI 聊天，无需额外付费。
  </Accordion>

  <Accordion title="可以关闭 AI 聊天吗？">
    可以。在 `docs.json` 中将 `chat.enabled` 设为 `false`：

    ```json
    { "chat": { "enabled": false } }
    ```

    下次构建后，聊天面板和键盘快捷键将被移除。
  </Accordion>

  <Accordion title="聊天功能使用哪些数据来回答问题？">
    聊天功能只会使用已发布的文档页面。每次构建时，Jamdesk 都会将你的内容编入向量数据库。访客提问时，系统会检索相关内容并将其作为上下文发送给 Claude。AI 无法访问文档之外的数据。
  </Accordion>
</AccordionGroup>

## 隐私与访问

<AccordionGroup>
  <Accordion title="可以在同一个站点中同时提供公开和私有文档吗？">
    可以。在 frontmatter 中将内部页面标记为 `private: true`，或在 `docs.json` 的 `auth.password.private[]` 下列出这些页面的路径。公开页面仍然公开，私有页面则会显示解锁界面。所有内容都保留在同一个项目中，因此公开和私有页面共用同一个仓库和构建。请参阅[访问控制](/cn/setup/access-control)和[密码保护](/cn/setup/password-protection)。
  </Accordion>

  <Accordion title="如何通过密码锁定整个文档站点？">
    在 `docs.json` 中设置 `auth.password.enabled: true`，推送更改，然后在仪表板的 **Project Settings → Password Protection** 中设置密码。访客输入密码前都会看到解锁界面。请参阅[密码保护](/cn/setup/password-protection)。
  </Accordion>

  <Accordion title="读者可以使用自己的账户登录，而不是共用密码吗？">
    可以，但仅限 Enterprise 套餐。单点登录允许读者通过你的身份提供商（Okta、Google Workspace、Azure AD 等）进行身份验证，无需共用密码，并提供完整的审计记录和即时取消访问权限功能。请参阅 [SSO](/cn/setup/sso) 或[联系 Enterprise 销售团队](https://jamdesk.com/pricing)。
  </Accordion>

  <Accordion title="应该将内部文档和外部文档拆分到两个项目中吗？">
    通常不需要。在内部页面上设置 `private: true` 并使用单个项目会更简单，因为所有内容都保存在同一个仓库中，并通过同一个仪表板管理。只有当不同受众需要完全独立的品牌、自定义域名或分析数据时，才使用两个项目。有关相关方案，请参阅[访问控制](/cn/setup/access-control)。
  </Accordion>

  <Accordion title="编辑者和读者有什么区别？">
    **编辑者**通过向已连接的 GitHub 仓库提交 MDX 来编写文档。只有推送者是 Jamdesk 项目成员或你授权的自动化账户时，推送才会触发构建。**读者**查看已发布的站点：包括所有人（公开模式）、知道密码的任何人（密码模式），或通过你的 IdP 登录的任何人（SSO）。**仪表板团队成员**管理构建、分析和设置；只有成员的推送才会触发构建。请参阅[访问控制](/cn/setup/access-control)。
  </Accordion>
</AccordionGroup>
