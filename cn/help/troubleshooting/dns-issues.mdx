DNS 问题是自定义域名故障最常见的原因。

## 检查 DNS 传播

DNS 更改最长可能需要 48 小时才能传播。大多数情况下几小时内即可完成。

检查传播状态：

```bash
# Check if your CNAME is resolving
dig CNAME docs.yourdomain.com

# Or use nslookup
nslookup -type=CNAME docs.yourdomain.com
```

预期输出中，您的 CNAME 应指向 `cname.jamdesk.com`：

```text
docs.yourdomain.com. 300 IN CNAME cname.jamdesk.com.
```

[whatsmydns.net](https://www.whatsmydns.net/) 等在线工具可显示多个地区的传播情况。

## 常见问题

### CNAME 无法解析

**症状**：`dig` 未显示 CNAME 记录，或显示的目标不正确。

**原因**：
- 记录未在 DNS 服务商处保存
- 记录名称或值存在拼写错误
- DNS 仍在传播中

**解决方法**：
1. 登录您的 DNS 服务商
2. 确认 CNAME 记录存在且值正确
3. 等待 15–30 分钟后再次检查

### 根域名上的 CNAME

**症状**：DNS 服务商拒绝为 `yourdomain.com`（不带子域名）添加 CNAME 记录。

**原因**：DNS 标准（RFC 1034）禁止在区域顶点（根域名）上设置 CNAME 记录。

**解决方法**：对于顶级域名，Jamdesk 控制台会自动显示 A 记录（`76.76.21.21`）而非 CNAME。如果控制台仍为顶级域名显示 CNAME，请点击 **Refresh** 以获取更新后的记录。

### Cloudflare 代理冲突

**症状**：使用 Cloudflare 时出现 SSL 错误或重定向循环。

**原因**：Cloudflare 的代理（橙色云朵）可能干扰 Vercel 的 SSL。

**解决方法**：
1. 在 Cloudflare DNS 设置中，点击橙色云朵图标
2. 将您的文档子域名切换为"仅 DNS"（灰色云朵）
3. 由 Vercel 签发 SSL 证书

### 冲突的记录

**症状**：尽管记录看似正确，CNAME 验证仍然失败。

**原因**：已存在的 A 记录与 CNAME 冲突。

**解决方法**：
1. 检查同一子域名上是否存在 A 记录
2. 删除冲突的 A 记录
3. 确保只保留 CNAME 记录

```bash
# Check for A records
dig A docs.yourdomain.com
```

### TXT 验证失败

**症状**：用于子路径托管的 TXT 记录无法通过验证。

**原因**：
- 记录添加到了错误的域名
- 记录值存在拼写错误
- 存在冲突的 TXT 记录

**解决方法**：
1. 确认 TXT 记录位于 `_jamdesk.yourdomain.com`
2. 从控制台复制准确的验证值
3. 检查是否存在冲突的 TXT 记录

```bash
# Check TXT records
dig TXT _jamdesk.yourdomain.com
```

### SSL 证书未签发

**症状**：域名无限期显示为"待处理"。

**原因**：
- CAA 记录阻止了证书签发
- DNS 尚未完全传播
- 域名无法访问

**解决方法**：

检查 CAA 记录：
```bash
dig CAA yourdomain.com
```

如果存在 CAA 记录，请添加一条允许 Let's Encrypt 的记录：
```text
yourdomain.com. CAA 0 issue "letsencrypt.org"
```

## 诊断命令

```bash
# Full DNS lookup
dig +trace docs.yourdomain.com

# Check all record types
dig ANY docs.yourdomain.com

# Check specific nameservers
dig @8.8.8.8 docs.yourdomain.com

# Check TTL (time to live)
dig +noall +answer docs.yourdomain.com
```

## DNS 服务商特定说明

### Cloudflare
- 在域名验证期间，将代理状态设置为"仅 DNS"（灰色云朵）
- 验证完成后，切换回代理模式（橙色云朵）
- Worker 仅在 DNS 记录被代理（橙色云朵）时运行。仅在验证期间使用灰色云朵。
- 为文档子域名禁用"Always Use HTTPS"，以避免与 Vercel 的 SSL 发生冲突

### GoDaddy
- CNAME 目标不应以句点结尾
- 更改可能需要更长时间才能传播

### Namecheap
- 使用"CNAME Record"类型
- Host 字段仅填写子域名（`docs`，而非 `docs.yourdomain.com`）

### Route 53
- CNAME 目标必须以句点结尾（`cname.jamdesk.com.`）
- 评估目标健康状况：否

## 何时联系支持团队

如果出现以下情况，请联系支持团队：
- DNS 记录已确认正确，但域名在 48 小时后仍处于待处理状态
- 按照所有步骤操作后，SSL 证书错误仍然存在
- 与 Jamdesk 基础设施相关的特定错误

在支持请求中请包含：
- 您的域名
- DNS 服务商名称
- `dig` 命令的输出
- DNS 配置的屏幕截图
