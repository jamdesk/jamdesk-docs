自定义域名需要正确配置 CNAME 记录并拥有有效的 SSL 证书。

## 域名无法验证

如果您的域名显示为"待处理"或"未验证":

<Steps>
  <Step title="检查 DNS 记录">
    确认您的 CNAME 记录指向您的 Jamdesk URL:
    ```text
    docs.example.com  CNAME  your-project.jamdesk.app
    ```
  </Step>
  <Step title="等待传播">
    DNS 更改在全球范围内生效可能需要长达 48 小时。
  </Step>
  <Step title="测试 DNS">
    使用 `dig` 或 [dnschecker.org](https://dnschecker.org) 等工具验证您的记录。
  </Step>
</Steps>

## SSL 证书错误

### 证书未配置

Jamdesk 使用 Let's Encrypt 实现自动 SSL。如果签发失败:

1. 确认 DNS 已正确配置
2. 等待 15 分钟后再次签发
3. 检查您的域名是否被防火墙规则拦截

### 证书已过期

证书会自动续期。如果您的证书已过期:

1. 前往 **Settings** → **Domains**
2. 点击 **Refresh Certificate**
3. 如果仍然失败,请联系支持团队

### 混合内容警告

您的域名可以正常访问,但显示安全警告:

- 检查内容中是否存在 `http://` 链接
- 将所有资源 URL 更新为使用 `https://`

## 域名无法加载

### “无法访问网站”

1. 确认 DNS 记录正确
2. 检查域名是否已在 Jamdesk 中被删除
3. 清除浏览器的 DNS 缓存

### 显示错误网站

您的 DNS 可能指向了旧服务器:

1. 将 CNAME 更新为您的 Jamdesk URL
2. 删除所有冲突的 A 记录
3. 等待 DNS 传播完成

## 常见 DNS 错误

<Accordion title="使用 A 记录而非 CNAME">
  Jamdesk 要求使用 CNAME 记录,而不是 A 记录。
</Accordion>

<Accordion title="包含协议前缀">
  不要在 CNAME 值中包含 `https://`。仅使用域名即可:

  ✓ `your-project.jamdesk.app`
  ✗ `https://your-project.jamdesk.app`
</Accordion>

<Accordion title="记录冲突">
  删除同时存在 CNAME 记录的子域名上的任何 A 记录。
</Accordion>

## 子路径域名

对于位于子路径的域名(例如 `example.com/docs`):

1. 配置反向代理(Cloudflare、nginx 等)
2. 设置说明请参阅 [子路径托管](/cn/deploy/subpath-hosting)

<Warning>
子路径配置需要在 Jamdesk 之外进行额外设置。
</Warning>
