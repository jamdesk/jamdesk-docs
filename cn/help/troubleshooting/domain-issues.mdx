自定义域名需要正确配置的 CNAME 记录和有效的 SSL 证书。

## 域名无法验证

如果您的域名显示为“Pending”或“Not verified”：

<Steps>
  <Step title="检查 DNS 记录">
    确认您的 CNAME 记录指向您的 Jamdesk URL：
    ```text
    docs.example.com  CNAME  your-project.jamdesk.app
    ```
  </Step>
  <Step title="等待传播">
    DNS 更改在全球范围内传播最多可能需要 48 小时。
  </Step>
  <Step title="测试 DNS">
    使用 `dig` 或 [dnschecker.org](https://dnschecker.org) 等工具验证您的记录。
  </Step>
</Steps>

## SSL 证书错误

### 证书未配置

Jamdesk 使用 Let's Encrypt 自动配置 SSL。如果配置失败：

1. 确认 DNS 已正确配置
2. 等待 15 分钟以完成配置
3. 检查您的域名是否被防火墙规则阻止

### 证书已过期

证书会自动续期。如果您的证书已过期：

1. 转到 **Settings** → **Domains**
2. 点击 **Refresh Certificate**
3. 如果失败，请联系支持团队

### 混合内容警告

您的域名可以正常运行，但显示安全警告：

- 检查内容中是否存在 `http://` 链接
- 更新所有资源 URL，使其使用 `https://`

## 域名无法加载

### “无法访问网站”

1. 确认 DNS 记录正确
2. 检查域名是否已在 Jamdesk 中删除
3. 清除浏览器的 DNS 缓存

### 显示错误网站

您的 DNS 可能指向旧服务器：

1. 将 CNAME 更新为您的 Jamdesk URL
2. 删除任何冲突的 A 记录
3. 等待 DNS 传播

## 常见 DNS 错误

<Accordion title="使用 A 记录而不是 CNAME">
  Jamdesk 要求使用 CNAME 记录，而不是 A 记录。CNAME 可让我们正确路由流量。
</Accordion>

<Accordion title="包含协议">
  不要在 CNAME 值中包含 `https://`。只使用域名：

  ✓ `your-project.jamdesk.app`
  ✗ `https://your-project.jamdesk.app`
</Accordion>

<Accordion title="记录冲突">
  如果同一子域名同时存在 A 记录和 CNAME 记录，请删除 A 记录。
</Accordion>

## 子路径域名

对于位于子路径中的域名（例如 `example.com/docs`）：

1. 配置反向代理（Cloudflare、nginx 等）
2. 查看[子路径托管](/cn/deploy/subpath-hosting)了解设置说明

<Warning>
子路径配置需要在 Jamdesk 外部完成额外设置。
</Warning>
