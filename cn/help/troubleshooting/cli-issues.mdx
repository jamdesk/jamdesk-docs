## 身份验证问题

<AccordionGroup>
  <Accordion title='"Not logged in" 或 "Session expired"'>
    您存储的凭据缺失，或刷新令牌已失效。

    **解决方法：** 运行 `jamdesk login` 开始新的会话。这将替换 `~/.jamdeskrc` 中的现有内容。

    如果登录后错误立即再次出现，请检查 `~/.jamdeskrc` 是否已写入：

    ```bash
    cat ~/.jamdeskrc
    ```

    该文件应包含一个 `auth` 对象，其中包括 `refreshToken`、`email` 和 `uid`。如果文件为空或缺失，您的主目录可能存在权限问题。
  </Accordion>

  <Accordion title="登录超时">
    CLI 会在本地端口 9876 启动一个服务器，用于接收浏览器发回的身份验证回调。如果回调在 2 分钟内未到达，登录就会超时。

    **常见原因：**
    - 防火墙阻止了本地服务器
    - 浏览器标签页在完成身份验证前已被关闭
    - 端口 9876 已被占用（CLI 会自动选择其他端口，但 URL 必须与之匹配）

    **解决方法：** 复制终端中打印的 URL 并手动打开。检查 URL 中的端口号是否与 CLI 正在监听的端口一致。
  </Accordion>

  <Accordion title="登录时浏览器未打开">
    在无头环境（SSH 会话、Docker 容器、CI 运行器）中这是正常现象。CLI 始终会将登录 URL 打印到终端。

    复制该 URL，并在任意能够访问您机器回调端口的浏览器中打开。
  </Accordion>

  <Accordion title='修改密码后出现 "session expired"'>
    更改 Jamdesk 密码会使所有现有的刷新令牌失效。CLI 会检测到这一情况（`TOKEN_EXPIRED` 或 `INVALID_REFRESH_TOKEN`），并自动清除已存储的身份验证信息。

    请再次运行 `jamdesk login`。
  </Accordion>
</AccordionGroup>

## 部署错误

<AccordionGroup>
  <Accordion title='"A build is already in progress"'>
    每个项目同一时间只能运行一个构建。当构建正在排队或运行时，CLI 会返回此错误（错误代码 `BUILD_IN_PROGRESS`）。

    **解决方法：** 等待当前构建完成。在仪表板的 **Deployments** 中查看状态。如果构建似乎卡住，请让项目所有者在仪表板中检查。
  </Accordion>

  <Accordion title='"docs.json not found or invalid"'>
    当前目录中没有 `docs.json`，或其中存在 JSON 语法错误。

    **解决方法：**
    1. 确保您位于正确的目录中：`ls docs.json`
    2. 运行 `jamdesk validate` 查看具体错误详情
    3. 检查是否缺少逗号、括号未闭合或存在多余的尾随逗号（CLI 对 docs.json 使用的是 JSON，而非 JSON5）
  </Accordion>

  <Accordion title='"Upload too large"'>
    您压缩后的 tar 包超过了 100 MB 的限制。所有未被 `.gitignore` 或内置排除列表排除的文件都会被打包。

    **解决方法：** 检查被包含的内容。常见问题包括：视频文件、大型 PDF、未压缩的图片、数据转储文件。将它们添加到 `.gitignore` 中。

    无论 `.gitignore` 如何设置，以下内容始终会被排除：`.git`、`node_modules`、`.next`、`.env*`、`*.pem`、`*.key`、`credentials.json`、`.DS_Store`。
  </Accordion>

  <Accordion title='"No files to deploy"'>
    所有文件都匹配了排除规则。

    **解决方法：** 检查您的 `.gitignore` 是否排除了 MDX 文件或 `docs.json`。
  </Accordion>

  <Accordion title='"Project not found" 或 "Access denied"'>
    要么 `docs.json` 中的 `projectId` 与您账户中的任何项目都不匹配，要么您不是该项目的成员。

    **解决方法：**
    - 从 `docs.json` 中删除 `projectId` 字段，然后重新运行 `jamdesk deploy` 以选择新项目
    - 确认您登录的是正确的账户：`jamdesk whoami`
    - 在仪表板中检查项目成员身份
  </Accordion>

  <Accordion title="部署在构建轮询期间挂起">
    CLI 每 2 秒轮询一次构建状态。连续 3 次轮询失败后，它会放弃。

    **解决方法：** 按 Ctrl+C。构建会在后台继续运行。在仪表板中查看状态。退出时 CLI 会打印一个链接。
  </Accordion>

  <Accordion title="构建失败">
    上传已成功，但构建失败。终端会显示来自构建服务的错误信息。

    **解决方法：** 在仪表板的 **Deployments** 下查看构建日志。常见原因包括：MDX 语法错误、导航中引用的页面缺失、OpenAPI 规范无效。在本地运行 `jamdesk validate`，可在部署前发现这些问题。
  </Accordion>

  <Accordion title="敏感文件警告">
    CLI 会对看起来像机密的文件发出警告（`.env`、`*.pem`、`*.key`、`credentials.json`、以 `secret` 开头的文件）。该警告不会阻止部署。

    **解决方法：** 将这些文件添加到 `.gitignore` 中，使其不被上传。如果它们是有意为之（例如文档中的示例密钥文件），可以忽略此警告。
  </Accordion>
</AccordionGroup>

## 开发服务器问题

<AccordionGroup>
  <Accordion title="开发服务器无法启动">
    **按以下顺序尝试：**
    1. `jamdesk doctor`，检查 Node.js 版本（需要 v20+）和运行环境
    2. `jamdesk clean`，清除缓存的依赖项
    3. `jamdesk dev --verbose`，获取详细的错误输出
    4. `jamdesk dev --clean`，在启动前清除构建缓存
  </Accordion>

  <Accordion title="端口已被占用">
    CLI 会从您请求的端口（默认 3000）开始，依次尝试 10 个连续端口。如果这 10 个端口都被占用，则启动失败。

    **解决方法：**
    ```bash
    # Find what's using the port
    lsof -i :3000

    # Pick a different port
    jamdesk dev --port 3001
    ```

    若要设置永久默认端口，请在 `~/.jamdeskrc` 文件中添加 `"defaultPort": 3001`。请勿覆盖该文件，因为它可能包含您的身份验证凭据。
  </Accordion>

  <Accordion title="Turbopack 缓存损坏">
    在编译过程中强制终止开发服务器（强制退出、系统崩溃）可能会损坏 `.next` 缓存。下次启动时会显示 "corrupted database" 或 panic 错误。

    **解决方法：**
    ```bash
    jamdesk dev --clean
    ```

    这会清空 `.next` 目录并重新开始。
  </Accordion>

  <Accordion title="首次运行较慢">
    第一次运行 `jamdesk dev` 时，会将运行时依赖项安装到 `~/.jamdesk/node_modules`。这只会发生一次，在网络较慢的情况下可能需要 1-2 分钟。

    除非 CLI 版本发生变化，之后的运行将跳过安装步骤。
  </Accordion>

  <Accordion title="依赖安装失败或挂起">
    首次运行时，`npm install` 会在 5 分钟后超时。

    **解决方法：**
    1. 检查您的网络连接
    2. 运行 `jamdesk clean`，清除未完成的安装
    3. 重试
    4. 如果 npm 持续缓慢，请检查您的 npm 镜像源配置：`npm config get registry`
  </Accordion>
</AccordionGroup>

## 验证与链接检查

<AccordionGroup>
  <Accordion title="MDX 语法错误">
    MDX 会将 `<` 视为 JSX 标签的开始。编写 `<50%` 会导致解析错误。

    **解决方法：** 使用 `&lt;` 进行转义，或改写内容。运行 `jamdesk validate` 可获取行号和修改建议。
  </Accordion>

  <Accordion title="发现失效链接">
    `jamdesk broken-links` 发现了指向不存在页面的内部链接。

    **解决方法：** 检查文件路径。常见错误包括：大小写错误（`Quickstart` 与 `quickstart`）、包含了 `.mdx` 扩展名，或使用了已重命名的旧路径。

    对于接近的匹配项（与拼写错误相差在 3 个字符以内），CLI 会给出修正建议。

    **自动修复。** 如果某个失效链接有明确无误的正确目标（拼写错误的锚点或跨语言锚点漂移），运行 `jamdesk fix --dry-run` 预览更改，然后运行 `jamdesk fix` 应用更改。它只会重写那些修正后的锚点确实是目标页面真实标题的链接。有歧义的情况请手动修复。参见 [自动修复失效链接](/cn/cli/fix-broken-links)。
  </Accordion>

  <Accordion title="OpenAPI 规范验证失败">
    CLI 会验证 `docs.json` 中引用的 OpenAPI 规范。失败原因包括：无效的 `$ref` 引用、缺少必填字段或语法错误。

    **解决方法：** 运行 `jamdesk openapi-check path/to/spec.yaml` 获取详细输出。对于复杂的规范，可使用 [Swagger Editor](https://editor.swagger.io) 进行调试。

    <Note>Swagger 2.0 规范会显示警告，但仍会通过验证。</Note>
  </Accordion>
</AccordionGroup>

## 常见问题

<AccordionGroup>
  <Accordion title="Command not found: jamdesk">
    未全局安装，或您的 shell 无法找到该可执行文件。

    **解决方法：**
    ```bash
    npm install -g jamdesk
    ```

    如果您是通过 `curl` 安装的，请确保 `~/.jamdesk/bin` 已添加到您的 `PATH` 中。
  </Accordion>

  <Accordion title="权限被拒绝错误">
    CLI 需要对 `~/.jamdesk`（缓存）和 `~/.jamdeskrc`（凭据）具有写入权限。

    **解决方法：**
    ```bash
    ls -la ~/.jamdesk ~/.jamdeskrc
    sudo chown -R $(whoami) ~/.jamdesk ~/.jamdeskrc
    ```
  </Accordion>

  <Accordion title="更新失败">
    `jamdesk update` 实际上是对 `npm install -g jamdesk@latest` 的封装。当 npm 存在权限问题或无法访问镜像源时，它会失败。

    **解决方法：** 手动更新：
    ```bash
    npm install -g jamdesk@latest
    ```

    如果仍然失败，请检查 `npm config get registry`，并尝试 `sudo npm install -g jamdesk@latest`。
  </Accordion>
</AccordionGroup>
