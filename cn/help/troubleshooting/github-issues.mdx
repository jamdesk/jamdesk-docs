## 设置期间未显示组织

在入门文档设置流程中，Jamdesk 会显示你的 GitHub 组织，供你选择要在哪个组织中创建仓库。组织列表来自 GitHub 的 OAuth API；在以下两种情况下，GitHub 不会在列表中显示组织：

- OAuth App 限制：你的组织限制第三方 App 访问（这是 GitHub 对新组织的默认设置），且尚未批准 Jamdesk。
- SAML SSO：你的组织要求先进行 SAML 身份验证，API 才会返回该组织。

<Accordion title="自行授予访问权限（组织所有者）">
  如果你是组织所有者，可以立即批准 Jamdesk：

  1. 在组织选择器下方点击 **grant Jamdesk access on GitHub**（或前往 GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**）
  2. 在 **Organization access** 下，点击你的组织旁边的 **Grant**
  3. 返回 Jamdesk 设置流程，点击 **refresh the list**。你的组织会立即显示

  如果你是成员（而不是所有者），会看到 **Request** 按钮；点击后会向组织管理员发送审批请求。
</Accordion>

<Accordion title="请组织管理员批准 Jamdesk（成员）">
  如果你是没有所有者权限的成员，请先向管理员发送审批请求：

  1. 前往 GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. 在 **Organization access** 下，点击你的组织旁边的 **Request**。这会通知组织管理员
  3. 管理员在组织的 **Settings** → **Third-party access** → **OAuth application policy** 中批准请求（待处理请求旁会显示 **Approve** 按钮）
  4. 返回 Jamdesk 设置流程并点击 **refresh the list**；此时应该会显示你的组织

详细步骤请参阅 GitHub 的[批准组织的 OAuth App 指南](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization)。
</Accordion>

<Accordion title="先在个人账户中创建，之后再转移">
  不想等待管理员批准？设置期间选择个人账户，之后再将仓库转移到组织：

  1. 使用个人账户完成 Jamdesk 设置
  2. 前往 GitHub 上创建的仓库
  3. 前往 **Settings** → **General** → **Danger Zone**
  4. 点击 **Transfer**，并选择要转移到的组织
  5. 在 Jamdesk 中，前往项目的 **Settings** 页面，断开仓库连接后再重新连接

  <Warning>
    断开并重新连接会生成新的文档 URL（例如，`your-project.jamdesk.app` 可能会改变）。如果你已分享 URL 或设置了自定义域名，请在断开连接前联系[支持团队](/cn/help/support/contact)，以便我们保留你的配置。
  </Warning>

  如果你的 GitHub 账户由公司管理，此方法无效。请参阅[公司托管的 GitHub 账户](#公司托管的-github-账户)。
</Accordion>

## 公司托管的 GitHub 账户

如果你的 GitHub 账户由公司管理（GitHub 称之为 Enterprise Managed Users，简称 EMU），GitHub 不允许你在个人账户上安装 App，只能在组织中安装。如果没有可供你使用的组织，在 GitHub 上点击 **Install** 只会将你带回 Jamdesk App 页面。注册期间，Jamdesk 会显示“Your organization manages this GitHub account”。

受管理的用户名以一个下划线和公司代码结尾，例如 `jsmith_acme`。GitHub 在[受管理用户账户](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts)页面说明了相关限制。

你可以通过以下两种方式解决此问题。

<Accordion title="将仓库移至组织">
  1. 请企业所有者从企业的 **Organizations** 选项卡[创建一个组织](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise)，并允许你在其中创建仓库。
  2. 将[文档仓库转移](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository)到该组织。在仓库中前往 **Settings**，点击页面底部的 **Transfer**，然后选择新组织。
  3. 在 Jamdesk 中，点击 **Connect an existing repository**（或在项目设置中点击 **Install GitHub App**）。在 GitHub 上选择组织，选择 **Only select repositories**，选中你的仓库，然后安装。

  如果 GitHub 显示的是 **Request** 而不是 **Install**，组织所有者会收到批准请求的电子邮件。对方批准后，再次点击 Jamdesk 按钮。
</Accordion>

<Accordion title="使用个人 GitHub 账户">
  如果公司无法添加组织，请使用此方法。先咨询 GitHub 管理员，因为文档将存放在公司 GitHub 之外。

  1. 在私密浏览器窗口中，使用个人账户登录 GitHub（或创建一个账户）。
  2. 在该账户下创建一个空的私有仓库。
  3. 将文档副本推送到该仓库。GitHub 不允许将仓库移出受管理的企业，因此需要使用副本。

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     请在 URL 中保留 `jsmith@`，这样 Git 才会要求输入个人账户的登录信息。

  4. 在 Jamdesk 中，点击 **Connect an existing repository**（或在项目设置中点击 **Install GitHub App**），在个人账户上安装 Jamdesk，然后选择该仓库。

  受管理的账户无法向企业之外的仓库推送内容，因此所有编辑文档的人都需要个人 GitHub 账户。请将他们添加为仓库协作者。
</Accordion>

## 未显示仓库

如果仓库没有显示在列表中：

<Accordion title="检查仓库权限">
  1. 前往 GitHub → Settings → Applications → Jamdesk
  2. 确认已授予该仓库访问权限
  3. 点击 **Configure** 添加更多仓库
</Accordion>

<Accordion title="组织仓库">
  对于组织仓库：
  1. 组织管理员必须批准 Jamdesk
  2. 前往组织设置 → Third-party access
  3. 批准 Jamdesk 的访问请求
</Accordion>

<Accordion title="私有仓库">
  私有仓库需要 GitHub 授权。如有需要，请重新授权 Jamdesk。
</Accordion>

## 未触发构建

如果推送没有触发构建：

<Steps>
  <Step title="检查 Webhook">
    1. 前往 GitHub 上的仓库
    2. 前往 Settings → Webhooks
    3. 找到 Jamdesk Webhook
    4. 检查“Recent Deliveries”中是否有错误
  </Step>
  <Step title="确认分支">
    只有在你配置的分支上才会触发构建。请检查 Jamdesk 中的 **Settings**。
  </Step>
  <Step title="检查推送者">
    如果构建失败，并显示推送者不是成员的提示，请在 **Project Settings → Members** 中邀请对方，或让对方关联其 GitHub 账户。请参阅[构建未触发](/cn/integrations/github#构建没有触发)。
  </Step>
  <Step title="重新同步连接">
    1. 前往 Jamdesk 中项目的 **Settings**
    2. 点击 **Re-sync GitHub**
  </Step>
</Steps>

## Webhook 错误

### 404 Not Found

无法访问 Webhook 端点。

**解决方法：**在项目设置中重新同步 GitHub 连接。

### 401 Unauthorized

身份验证失败。

**解决方法：**
1. 前往 GitHub 账户设置
2. 前往 Applications → Authorized OAuth Apps
3. 撤销 Jamdesk 的授权
4. 在 Jamdesk 设置中重新授权

### 500 Server Error

Jamdesk 暂时出现问题。

**解决方法：**等待几分钟后再次推送，或手动触发重新构建。

## 权限错误

构建期间出现 **"Repository not found"**：

- 仓库可能已被删除或重命名
- Jamdesk 可能已失去访问权限
- 重新授权 GitHub 连接

## 分支问题

### 构建了错误的分支

在 **Settings** → **Repository** 中检查你配置的分支。

### 分支已重命名或删除

更新分支设置，使其与新分支名称一致。
