Jamdesk 可以为你翻译文档。在项目设置中选择所需语言后，Jamdesk 会在每次构建完成后翻译你的英文页面，并将结果提交到你自己的 GitHub 仓库中的语言前缀目录。翻译内容归你所有：它们位于你的仓库和 Git 历史记录中，你可以像编辑其他文件一样进行修改。

屏幕截图显示的是英文界面。

本页面适合希望让文档支持多种语言阅读、又不想运行翻译供应商或自行编写脚本的用户。有关每个区域设置的导航和语言切换器的工作方式，请参阅[多语言支持](/cn/setup/languages)——无论翻译来自 Jamdesk、你自己的译员还是其他工具，该配置都适用。

## 前提条件

- 项目需要使用一个[已连接的 GitHub 仓库](/cn/setup/connecting-github)。翻译页面会被提交回你的仓库，因此从 CLI 或 tarball 部署的项目无法使用此功能。
- Jamdesk GitHub App 需要具有写入权限，以便创建提交。如果缺少权限，Translations 面板会显示相关提示，并提供链接，让 GitHub 管理员授予权限。每个 GitHub 账户只需完成一次。

自动翻译包含在所有套餐中，试用版也包含在内。不按字数收费，也无需购买额度。

## 开启翻译

<Steps>
  <Step title="打开 Translations 面板">
    进入 [Jamdesk 仪表板](https://dashboard.jamdesk.com)中的项目，打开 **Settings**，然后滚动到 **Translations**。
  </Step>

  <Step title="选择语言">
    开启 **Translate my documentation**，然后勾选所需语言。每种语言都会以其本地名称列出，旁边显示英文名称。

    <Frame>
      <img src="/images/translations/translations-settings.webp" alt="项目设置中的 Translations 面板。已开启 Translate my documentation 切换开关，下方是包含语言复选框的两列列表。已选择简体中文、葡萄牙语、德语和意大利语。每种语言都以其本地名称列出，旁边显示英文名称。" />
    </Frame>
  </Step>

  <Step title="构建">
    构建完成后会运行翻译。首次运行会翻译所有页面，并将翻译后的文件提交到你的仓库，你可以像检查其他提交一样检查这些文件。
  </Step>
</Steps>

## 限制

每个项目有以下两项限制：

| 限制 | 数值 |
|-------|-------|
| 每个项目的语言数 | 最多 5 种 |
| 每月翻译的页面数 | 10,000 |

首次运行后，系统只会再次翻译发生变化的页面，因此稳定运行的网站只会使用每月额度的一小部分。

## 仅翻译发生变化的内容

首次运行会翻译所有内容。此后，Jamdesk 只会重新翻译英文源文件确实发生变化的页面，因此修复一个页面中的拼写错误只会消耗一个页面的额度，而不是整个网站的额度。

## Jamdesk 不会更改的翻译

以下两类翻译会被视为由你编写，Jamdesk 不会自行替换它们：

- **你已有的翻译。** 如果你开启此功能时仓库中已经包含翻译页面，Jamdesk 会采用这些页面，而不是覆盖它们。无论是你亲自编写的内容，还是付费请供应商完成的内容，都会原样保留。
- **你编辑过的翻译。** 手动修改翻译页面后，Jamdesk 会检测到这一点，因此你的措辞会在之后的每次运行中保留。

这两类页面会以相同方式记录，并且会永久保持锁定：系统不会再自动翻译这些页面，即使其英文源文件发生变化也不会。英文内容发生变化后，这些页面会显示在 Translations 面板的 **Edited by hand** 下。

其中列出的每个页面都有一个 **Replace with AI translation** 按钮。点击该按钮会将页面交还给 AI——你的版本会被丢弃，页面会在下一次构建时重新翻译，因此点击后不会立即发生变化。只有这个按钮可以解除锁定。

<Note>
  这就是“仅翻译发生变化的内容”不适用于这些页面的原因。Jamdesk 翻译的页面会在英文源文件发生变化时自动刷新；你编写或编辑的页面则会一直等待你发起请求。
</Note>

## 关闭某种语言

取消勾选某种语言后，Jamdesk 会停止将内容翻译成该语言。不会删除任何内容：已经提交的页面会原样保留在你的仓库中。
