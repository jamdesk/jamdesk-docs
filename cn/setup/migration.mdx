只需运行一条命令即可迁移 Mintlify 项目：`jamdesk migrate` 会读取 `mint.json`、写入 `docs.json`，并就地改写 MDX 文件。对于 GitBook、Docusaurus、ReadMe、Confluence 或其他平台，请按照“其他平台”标签页中的手动步骤操作。

<YouTube id="DvIHWeBliK0" />

<Info>
**如果可以，请先导出为 Markdown。** Jamdesk 基于 MDX 构建。只需将 Markdown 文件重命名为 `.mdx`，再添加几行 frontmatter 即可。
</Info>

    ### 自动迁移

    <Steps>
      <Step title="安装 CLI">
        ```bash
        npm install -g jamdesk
        ```
      </Step>
      <Step title="运行迁移">
        ```bash
        jamdesk migrate
        ```

        请在项目根目录运行。此命令会执行以下操作：

        - 读取 `mint.json` 并写入 `docs.json`
        - 重命名 MDX 文件中的弃用组件（例如 `CardGroup` → `Columns`）
        - 将无父级引用的片段 MDX 文件移至 `/snippets/`，并将所有父级相对导入路径（`../foo/bar.mdx`）改写为根目录相对路径（`/snippets/foo/bar.mdx`）
        - 将使用 React hooks 的内联组件提取到 `/snippets/<name>.tsx`，添加 `'use client'` 指令，并改写原始 MDX 文件，使其从 `/snippets/` 导入
        - 自动修复会导致构建失败的机械性 MDX 语法问题

        此命令具有幂等性。编辑后可重新运行，只处理新增内容。对于无法安全修复的问题，命令会输出警告，列出文件、导入语句和建议采取的操作。
      </Step>
      <Step title="检查并调整">
        检查生成的 `docs.json` 和 MDX 文件。确认导航结构，并修复 CLI 输出的所有警告。
      </Step>
    </Steps>

    ### 配置映射

    CLI 会将 `mint.json` 转换为 `docs.json`。请根据以下差异检查转换结果。

    **Mintlify（`mint.json`）：**
    ```json
    {
      "name": "My Docs",
      "navigation": [
        { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
      ],
      "colors": { "primary": "#0D9373" },
      "topbarLinks": [{ "name": "Blog", "url": "https://example.com/blog" }]
    }
    ```

    **Jamdesk（`docs.json`）：**
    ```json
    {
      "$schema": "https://jamdesk.com/docs.json",
      "name": "My Docs",
      "theme": "jam",
      "colors": { "primary": "#0D9373" },
      "navbar": {
        "links": [{ "label": "Blog", "href": "https://example.com/blog" }]
      },
      "navigation": {
        "groups": [
          { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
        ]
      }
    }
    ```

    ### 组件兼容性

    大多数 Mintlify 组件在 Jamdesk 中都有直接对应项。少数组件的名称或语法有所不同。

    | Mintlify 组件 | Jamdesk 对应项 | 说明 |
    |---|---|---|
    | `<Card>` | `<Card>` | 语法相同 |
    | CardGroup | `<Columns>` | 使用 `cols` 属性设置列数 |
    | `<Columns>` | `<Columns>` | 语法相同 |
    | `<Accordion>` | `<Accordion>` | 语法相同 |
    | `<Tabs>` / `<Tab>` | `<Tabs>` / `<Tab>` | 语法相同 |
    | `<Steps>` / `<Step>` | `<Steps>` / `<Step>` | 语法相同 |
    | `<CodeGroup>` | `<CodeGroup>` | 语法相同 |
    | `<Tip>`、`<Note>`、`<Warning>` | `<Tip>`、`<Note>`、`<Warning>` | 语法相同 |
    | `<ResponseField>` | `<ParamField>` | 名称不同 |
    | `<Snippet>` | 从 `/snippets/` 导入 | 用法不同 |

    ### 常见问题

    <AccordionGroup>
      <Accordion title="CardGroup 会转换为 Columns">
        `jamdesk migrate` 会在每个 MDX 文件中将 `CardGroup` 重命名为 `Columns`。`cols` 属性会原样保留。请检查迁移后编辑过的文件。
      </Accordion>
      <Accordion title="ResponseField 会转换为 ParamField">
        将 `<ResponseField>` 重命名为 `<ParamField>`。属性保持不变。

        ```mdx
        {/* Before */}
        <ResponseField name="id" type="string" required>
          The unique identifier
        </ResponseField>

        {/* After */}
        <ParamField name="id" type="string" required>
          The unique identifier
        </ParamField>
        ```
      </Accordion>
      <Accordion title="片段会自动迁移并更新导入路径">
        Jamdesk 只会解析根目录相对的 `/snippets/*` 导入路径。Mintlify 项目通常会将片段 MDX 文件放在目录树的任意位置，并使用父级相对路径导入（`import X from '../shared/x.mdx'`）。

        `jamdesk migrate` 会修复此问题：

        - 将作为片段导入、但位于 `/snippets/` 之外的 MDX 文件移至 `/snippets/`。文件的相对路径会保留，因此带有区域设置前缀的片段（如 `de/foo.mdx`）不会发生冲突。
        - 将每个 MDX 文件中的所有父级相对片段导入路径改写为新的根目录相对路径。
        - 将使用 React hooks 的内联组件提取到 `/snippets/<name>.tsx` 下的 `'use client'` 文件中，并将内联导出替换为从 `/snippets/` 导入。

        请将 Mintlify 的 `<Snippet file="my-snippet.mdx" />` JSX 元素替换为 MDX 导入。CLI 不会改写此元素：

        ```mdx
        {/* Before (Mintlify) */}
        <Snippet file="my-snippet.mdx" />

        {/* After (Jamdesk) */}
        import MySnippet from '/snippets/my-snippet.mdx'

        <MySnippet />
        ```

        如果项目没有已解析的导航，或计划移动的文件数量超过所有 MDX 文件的 `max(5, 25%)`，迁移工具会中止操作，不做任何更改，并输出原因。请修复问题后重新运行。
      </Accordion>
      <Accordion title="topbarLinks 会映射到 navbar.links">
        Mintlify 的 `topbarLinks` 和 `topbarCtaButton` 会映射到 `docs.json` 中的 `navbar.links`。`name` 字段会转换为 `label`，`url` 字段会转换为 `href`。
      </Accordion>
    </AccordionGroup>

    ### 从 GitBook 迁移

    GitBook 将内容存储为 Markdown，并使用 `SUMMARY.md` 文件设置导航。

    <Steps>
      <Step title="导出内容">
        将 GitBook 空间导出为 Markdown。如果使用 GitBook 的 Git 同步功能，内容已经以 `.md` 文件的形式存储在 Git 仓库中。
      </Step>
      <Step title="将文件转换为 MDX">
        将 `.md` 文件重命名为 `.mdx`，并为每个文件添加 frontmatter：

        ```mdx
        ---
        title: Your Page Title
        description: A short description of the page
        ---

        Your existing Markdown content here.
        ```
      </Step>
      <Step title="根据 SUMMARY.md 设置导航">
        将 `SUMMARY.md` 侧边栏转换为 `docs.json` 导航分组。

        **GitBook（`SUMMARY.md`）：**
        ```markdown
        # Summary

        ## Getting Started
        * [Introduction](introduction.md)
        * [Quick Start](quickstart.md)

        ## API Reference
        * [Authentication](api/auth.md)
        ```

        **Jamdesk（`docs.json`）：**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["introduction", "quickstart"]
              },
              {
                "group": "API Reference",
                "pages": ["api/auth"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="移动图片">
        将所有图片移至 `/images` 目录，并更新 MDX 文件中的引用，改用绝对路径（例如 `/images/screenshot.png`）。
      </Step>
      <Step title="在本地测试">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### 从 Docusaurus 迁移

    Docusaurus 项目已经使用 MDX。大多数内容都可以直接迁移。

    <Steps>
      <Step title="复制 MDX 文件">
        将 Docusaurus `docs/` 目录中的内容复制到 Jamdesk 项目根目录。保留现有目录结构。
      </Step>
      <Step title="清理 frontmatter">
        删除 Docusaurus 专用的 frontmatter 字段。保留 `title` 和 `description`，删除其他字段。

        ```yaml
        ---
        # Remove these Docusaurus fields
        sidebar_position: 3
        sidebar_label: "Custom Label"
        slug: /custom-url
        pagination_next: null

        # Keep these
        title: Your Page Title
        description: A short description
        ---
        ```
      </Step>
      <Step title="将 sidebars.js 映射到 docs.json">
        将 `sidebars.js` 中的分类结构转换为 `docs.json` 导航分组。

        **Docusaurus（`sidebars.js`）：**
        ```javascript
        module.exports = {
          docs: [
            {
              type: 'category',
              label: 'Getting Started',
              items: ['intro', 'installation'],
            },
          ],
        };
        ```

        **Jamdesk（`docs.json`）：**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["intro", "installation"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="替换 Docusaurus 组件">
        将 Docusaurus 专用组件替换为 Jamdesk 对应组件。

        | Docusaurus | Jamdesk | 示例 |
        |---|---|---|
        | `:::note` / `:::tip` / `:::warning` | `<Note>` / `<Tip>` / `<Warning>` | 请参阅[提示框组件](/cn/components/overview) |
        | `import Tabs from '@theme/Tabs'` | `<Tabs>`（全局可用） | 无需导入 |
        | `import TabItem from '@theme/TabItem'` | `<Tab>`（全局可用） | 使用 `title` 而不是 `label` |
      </Step>
      <Step title="在本地测试">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### 从其他工具迁移

    对于 Confluence、Notion、ReadMe 或其他平台，请先将内容转换为 Markdown，然后设置 Jamdesk 项目结构。

    <Steps>
      <Step title="导出为 Markdown">
        大多数平台都提供 Markdown 或 HTML 导出选项。如果可以，请使用 Markdown。也可以使用 [Pandoc](https://pandoc.org/) 等工具将 HTML 转换为 Markdown。

        ```bash
        # Convert HTML to Markdown with Pandoc
        pandoc input.html -f html -t markdown -o output.md
        ```
      </Step>
      <Step title="创建 docs.json">
        从最小配置开始。添加页面时，再将其加入导航。
      </Step>
      <Step title="将文件转换为 MDX">
        将 `.md` 文件重命名为 `.mdx`，并为每个文件添加 frontmatter（`title`、`description`）。
      </Step>
      <Step title="移动资源">
        将图片和其他资源移至 `/images` 目录，并更新文件引用，改用绝对路径。
      </Step>
      <Step title="在本地测试">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>
