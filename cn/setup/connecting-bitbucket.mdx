Jamdesk 从 Bitbucket Cloud 构建的方式与从 GitHub 构建相同。授权 Jamdesk 一次即可。之后每次推送到你选择的分支，都会发布一个新版本的站点。

<Note>
文档保存在 GitHub 上？请改为参阅[连接 GitHub](/cn/setup/connecting-github)。一个项目一次只能连接一个 Git 提供商。
</Note>

## 开始前

- **Bitbucket Cloud 账户。** 不支持 Bitbucket Data Center 和 Bitbucket Server。
- **代码仓库的管理员权限。** Jamdesk 会在代码仓库上安装推送 webhook。Bitbucket 只允许仓库管理员创建 webhook。
- **未连接代码仓库的项目。** 要将项目从 GitHub 迁移到 Bitbucket，请先在 **Settings** → **Git Repository** 下断开 GitHub。
- **允许仪表板的弹出窗口。** Bitbucket 登录会在弹出窗口中打开。

## Jamdesk 请求的权限

Jamdesk 通过 Bitbucket OAuth 应用程序进行连接。Bitbucket 会在登录时列出所请求的权限：

| 权限 | Jamdesk 需要它的原因 |
|------|----------------------|
| Account: Read | 记录连接项目的 Bitbucket 账户。Jamdesk 据此识别来自该账户的推送 |
| Repositories: Read | 克隆你的代码仓库以进行构建。在更换代码仓库时列出你的仓库 |
| Repositories: Write | 创建入门文档仓库并将入门内容推送到其中 |
| Webhooks: Read and write | 安装触发构建的推送 webhook。连接变更时将其移除 |

Jamdesk 使用 Google Cloud KMS 加密存储刷新令牌，并自行续期访问权限。你无需应用密码或个人访问令牌。

## 为项目选择 Bitbucket

在仪表板中打开项目。在未连接代码仓库时，项目页面会显示一张 **Connect your docs repository** 卡片，提供两个选项。点击 **Bitbucket**。

让 Jamdesk 创建入门仓库，或连接你已有的仓库。

### 创建文档起始仓库

<Steps>
  <Step title="输入工作区">
    输入工作区标识（slug），即 Bitbucket URL 中 `bitbucket.org/` 之后的部分。对于 `https://bitbucket.org/acme/`，输入 `acme`。
  </Step>

  <Step title="使用 Bitbucket 登录">
    点击 **Sign in with Bitbucket**。bitbucket.org 上会打开一个弹出窗口。查看权限并授予访问。
  </Step>

  <Step title="等待代码仓库">
    Jamdesk 会在该工作区中创建一个代码仓库，以你的项目名加 `-docs` 后缀命名。名为 **Acme Docs** 的项目会得到 `acme-docs`。如果该名称已被占用，Jamdesk 会改用 `-documentation`。

    代码仓库从 `main` 分支开始，并已包含入门文档。Jamdesk 会安装 webhook 并运行第一次构建。
  </Step>
</Steps>

当卡片显示 **Starter docs created and connected!** 时，你的站点即将上线。克隆新仓库并开始编辑。

### 连接现有仓库

<Steps>
  <Step title="输入代码仓库">
    以 `workspace/repository-slug` 的格式输入代码仓库，例如 `acme/developer-docs`。工作区和标识请从 bitbucket.org 上的仓库 URL 中获取。
  </Step>

  <Step title="选择分支">
    输入要部署的分支。留空则使用 `main`。
  </Step>

  <Step title="连接 Bitbucket">
    点击 **Connect Bitbucket**，并在弹出窗口中授予访问。之后 Jamdesk 会：

    1. 确认你的账户对该代码仓库具有管理员权限
    2. 在代码仓库根目录或子文件夹中查找 `docs.json`，最深三层
    3. 安装推送 webhook
    4. 注册你的 `yourproject.jamdesk.app` 地址并开始第一次构建
  </Step>
</Steps>

代码仓库需要在你输入的分支上有有效的 `docs.json`。如果 Jamdesk 找不到，请添加后重新连接。如果找到多个，每个代码仓库只保留一个 `docs.json`。如果代码仓库包含 `mint.json`，则它是 Mintlify 项目：对其运行 [`jamdesk migrate`](/cn/cli/overview)，推送，然后重新连接。

已连接的项目卡片会显示代码仓库、分支以及 **Connected** 徽章。

## 推送时自动构建

每次推送到已连接的分支都会触发构建：

```bash
git add .
git commit -m "Update API documentation"
git push origin main
```

Bitbucket 会将推送事件发送到 Jamdesk 的 webhook。Jamdesk 只会对该提交构建一次。同一提交的重复投递不会启动第二次构建。删除分支绝不会触发构建。

Bitbucket 不会重试失败的 webhook 投递。Jamdesk 还会每五分钟检查一次分支的最新提交，并构建任何尚未构建的提交。即使 webhook 丢失，推送也会在几分钟内部署。

仪表板中的手动构建与 GitHub 项目的工作方式相同。参见[触发构建](/cn/builds/triggering)。

### 哪些推送会触发构建

Jamdesk 只会构建由连接项目的 Bitbucket 账户，或最近一次重新授权它的账户所做的推送。来自任何其他账户的推送会在构建列表中显示为失败的构建，并带有授权错误。不会部署任何内容。

<Note>
Bitbucket 项目目前不支持在 **User Settings** 中关联个人账户，也不支持在 **Settings** → **Automation accounts** 中授权额外账户。如果多人推送到部署分支，请使用合并到该分支的账户连接项目，或让该账户负责推送。
</Note>

## 更换仓库或分支

点击项目卡片上的 **Change repository**。Jamdesk 会列出你的 Bitbucket 账户可访问的代码仓库。选择代码仓库和分支，然后确认。

Jamdesk 会在新代码仓库上安装 webhook，从旧代码仓库移除它，并开始构建。

<Warning>
更换代码仓库会在构建完成后立即影响你的线上文档。新代码仓库必须包含有效的 `docs.json`。
</Warning>

## 重新授权已过期的连接

当连接用户在 Bitbucket 中移除 Jamdesk 的访问权限，或刷新令牌数月未使用时，Bitbucket 会撤销 Jamdesk 的访问。此时项目卡片会显示 **Needs reauth** 徽章，以及消息 **Bitbucket connection needs attention**。

点击 **Re-authorize** 并重新登录。构建将恢复。下一次五分钟检查会获取分支上的最新提交。

## Bitbucket 与 GitHub 的区别

Bitbucket 项目使用一次 OAuth 授权。GitHub 项目使用 GitHub App，外加可选的个人账户关联。平台的大部分功能相同。区别如下：

| 功能 | GitHub | Bitbucket Cloud |
|------|--------|-----------------|
| 推送时构建 | Webhook | Webhook，外加每五分钟检查一次丢失的投递 |
| 入门文档仓库 | 支持 | 支持 |
| 自定义域名、子路径托管、手动构建、CLI 部署 | 支持 | 支持 |
| 提交上的构建状态 | 在 GitHub 的提交上显示 | 仅仪表板 |
| 用于构建归属的个人账户关联 | User Settings | 不可用。构建归属于连接账户 |
| 自动化账户白名单 | Settings → Automation accounts | 尚不支持 |
| [Web 编辑器](/cn/development/web-editor) | 支持 | 尚不支持 |
| [使用 AI 修复](/cn/builds/fix-with-ai) | 支持 | 尚不支持 |
| [AI 翻译](/cn/setup/ai-translation) | 支持 | 尚不支持 |

删除项目会从你的代码仓库中移除 webhook，并撤销 Jamdesk 的访问。

## 故障排除

### “你的 Bitbucket 账户没有此仓库的管理员权限”

Jamdesk 需要管理员权限才能安装 webhook。请让工作区管理员授予你该代码仓库的管理员权限，或让管理员连接该项目。

### “我们无法在此仓库中找到 docs.json”

Jamdesk 在你输入的分支上查找了根目录及向下三层文件夹。请添加 `docs.json`，将其推送到该分支，然后重新连接。参见 [docs.json 参考](/cn/config/docs-json-reference)。

### “找到多个 docs.json 文件”

每个代码仓库只保留一个 `docs.json`。删除或重命名其他文件，然后重新连接。

### “此仓库似乎是 Mintlify 项目”

该代码仓库包含 `mint.json`。运行 `jamdesk migrate` 进行转换，推送结果，然后重新连接。

### 弹出窗口被阻止

在浏览器中允许仪表板的弹出窗口，然后再次点击 **Sign in with Bitbucket** 或 **Connect Bitbucket**。

### 构建未触发

- 在 Bitbucket 中打开 **Repository settings** → **Webhooks**，确认 Jamdesk webhook 存在且处于活动状态
- 确认你推送的是已配置的分支
- 等待五分钟。定期检查会构建 webhook 遗漏的任何提交
- 如果项目卡片显示 **Needs reauth**，请重新授权连接
- 如果推送来自其他 Bitbucket 账户，参见[哪些推送会触发构建](#哪些推送会触发构建)
