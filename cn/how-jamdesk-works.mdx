Jamdesk 从您 GitHub 仓库中的 MDX 文件构建文档站点。使用 Markdown 搭配 React 组件编写内容，然后推送到 GitHub。您的站点将在 60 秒内上线到全球 CDN。内容以纯 MDX 文件的形式保存在您的仓库中，您可以随时将其迁移到其他工具。

## 架构概览

您的仓库是唯一的数据源。Jamdesk 连接到该仓库，构建您的站点，并部署到全球边缘网络。

## 构建流程

一次构建通常需要 30–60 秒。Jamdesk 不会预渲染页面，而是将原始内容发送到边缘节点，页面在访客请求时按需渲染。

<Steps>
  <Step title="获取源代码">
    您推送到已连接的 GitHub 分支（或在控制台中点击 Rebuild）。Jamdesk 克隆您的仓库并找到文档目录。
  </Step>
  <Step title="验证">
    Jamdesk 根据 schema 验证 `docs.json`。它会检查内部链接是否指向失效页面以及锚点是否有误。
  </Step>
  <Step title="内容处理">
    Jamdesk 根据您的内容生成搜索索引、[AI 聊天](/cn/ai/chat)嵌入、站点地图、[`llms.txt`](/cn/ai/llms-txt) 以及重定向规则。
  </Step>
  <Step title="部署到边缘">
    内容上传到 CDN 并传播到 300 多个边缘节点。仅传输有变更的文件。
  </Step>
</Steps>

## 什么会触发构建

向已连接分支执行 git push、在控制台中点击 Rebuild 按钮，或在 CLI 中运行 [`jamdesk deploy`](/cn/cli/deploy)。Jamdesk 会将短时间内连续推送的提交合并为一次构建。

有关运维细节（状态监控、回滚、分支部署），请参阅[构建与部署生命周期](/cn/deploy/lifecycle)。

## 安全性与基础设施

构建在隔离的容器中运行。构建只读取您的仓库。

<Columns cols={2}>
  <Card title="最小权限" icon="shield-check">

  </Card>
  <Card title="隔离构建" icon="box">
    每次构建都有独立的容器，部署完成后即被销毁。构建之间以及客户之间不会保留任何数据。
  </Card>
  <Card title="全程 HTTPS" icon="lock">
    为每个域名自动签发和续期 SSL 证书。
  </Card>
  <Card title="全球 CDN" icon="globe">

  </Card>

## 性能

加载速度会影响您的文档能否被发现。Google 将 [Core Web Vitals](https://jamdesk.com/blog/why-google-pagespeed-matters) 作为排名信号。GPTBot 和 ClaudeBot 等 AI 爬虫为每个页面预留 1–5 秒。无法在该时间窗口内加载的文档不会被引用。

每个 Jamdesk 站点都从边缘节点提供服务，首字节时间（TTFB）低于 50 毫秒。这一速度既满足 Google 的排名阈值，也便于 AI 爬虫抓取和引用。

| 指标 | 典型值 |
|------|--------|
| 构建时间 | 30–60 秒 |
| 部署传播时间 | < 30 秒 |
| 首字节时间（边缘） | < 50 毫秒 |
| 完整页面加载 | < 500 毫秒 |
