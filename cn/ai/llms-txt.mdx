如果您希望 ChatGPT、Claude 或 Copilot 等 AI 工具准确回答有关您产品的问题，它们需要结构化访问您的文档，而不仅仅是依赖训练数据中已有的内容。

每个 Jamdesk 网站都会根据 [llmstxt.org](https://llmstxt.org) 规范生成 `llms.txt` 和 `llms-full.txt`。AI 工具会读取这些文件，而不是逐个抓取页面。

<Note>
  Google 现在会将 `llms.txt` 纳入 [Lighthouse 的智能代理浏览检查](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt)。发布有效的 `llms.txt` 后，网站更容易被 AI 代理发现；在 Google 为 AI 驱动的答案进行内容排名时，网站也越来越容易被 Google 自身发现。Jamdesk 免费为您提供此功能。
</Note>

<Tip>
  **查看您的评分。** 使用免费的 [AI Score](https://jamdesk.com/ai-score) 工具，了解任何文档网站是否已准备好供代理使用。发布有效的 `llms.txt` 是该工具检查的首要事项之一。此外，还有一个 [AI Score Chrome 扩展程序](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj)，可在您浏览网站时为其评分。
</Tip>

## Jamdesk 生成的内容

| 文件 | 内容 |
|------|---------|
| `llms.txt` | 页面标题、描述和 URL（结构化目录） |
| `llms-full.txt` | 合并在单个文件中的完整文档内容 |

Jamdesk 会在构建时生成这两个文件，并通过与文档相同的 CDN 提供服务。

## 验证文件

首次构建后，请检查文件是否存在：

<Tabs>
  <Tab title="根域名">
    如果您的文档位于域名根目录（例如 `docs.acme.com` 或 `acme.jamdesk.app`）：

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="/docs 子路径">
    如果您的文档位于主网站的 `/docs` 下（例如本站的 `jamdesk.com/docs`）：

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## 文件格式

`llms.txt` 文件会列出每个页面的标题、描述和 URL，并按与网站导航相对应的分组组织到各个部分中：

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

`llms-full.txt` 文件包含每个页面的完整 Markdown 内容，并通过标题标记页面边界后连接在一起。

## 结构

`llms.txt` 遵循 [llmstxt.org](https://llmstxt.org/) 提案：包含 H1 标题、引用摘要，以及以 Markdown 链接形式呈现的导航选项卡和分组，每个分组使用 `##` 作为章节标题。

## 多语言网站

包含多种语言的网站会为每种语言分别生成一组文件，以便 AI 工具只获取所需的语言。对于同时提供英语（默认语言）和法语的网站：

| URL | 内容 |
|-----|---------|
| `/llms.txt` | 英语索引，末尾包含指向其他语言索引的链接 |
| `/fr/llms.txt` | 法语索引，链接回其他语言 |
| `/llms-full.txt` | 按语言依次排列的完整内容 |
| `/en/llms-full.txt` | 仅包含英语页面的完整内容 |
| `/fr/llms-full.txt` | 仅包含法语页面的完整内容 |

根目录的 `llms-full.txt` 会保留所有语言，因此已经读取该文件的工具不会感知到变化。当代理只需要某种语言时，请将其指向该语言专属的文件：

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

某种语言至少包含一个页面后，才会获得专属文件。只有一种语言的网站则仅保留根目录文件。

## 每个页面上的代理指令

每个页面还会包含一条对屏幕阅读器静默且不可见的备注，用于将 AI 代理指向 `llms.txt`；每个 Markdown 导出文件也会以一个指向索引的引用链接开头。进入 HTML 页面后，代理无需抓取页面即可找到 Markdown 路径。

## 构建方式

- 在构建时与 HTML 一起生成
- 通过 CDN 提供服务，并使用与文档相同的缓存策略
- 每次构建时自动更新
- 无需配置；默认包含所有页面

## 关闭 llms.txt

默认情况下会发布 `llms.txt` 和 `llms-full.txt`。如果您不希望 AI 工具摄取您的内容，可以在 `docs.json` 中将 `seo.ai.llmsTxt` 设置为 `false`，从而停止生成这些文件：

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

下一次构建时，Jamdesk 会跳过这两个文件，包括每种语言的副本；线上 `/llms.txt` 和 `/llms-full.txt` URL 会返回 `404`。

<Note>
  **AI 摄取和搜索索引是两个独立的控制项。** `seo.ai.llmsTxt` 仅控制 AI 工具读取的 `llms.txt`/`llms-full.txt` 文件。它不会改变搜索引擎为您的网站建立索引的方式；该方式由 [`robots` 元数据和每页的 `noindex`](/cn/content/seo#控制索引) 控制。页面可以被 Google 编入索引，同时排除在 AI 摄取之外，反之亦然。
</Note>

## AI 爬虫

Jamdesk 的默认 `robots.txt` 允许所有主要 AI 爬虫（Claude、ChatGPT、Copilot、Gemini）访问。您的文档开箱即可供 AI 工具访问。

<Accordion title="llms.txt 与 sitemap.xml 的区别">
  `sitemap.xml` 会列出供搜索引擎抓取和编入索引的 URL。它不包含任何内容，只包含链接以及最后修改日期等元数据。

  `llms.txt` 专为 AI 模型设计。它包含页面标题、描述，以及（在 `llms-full.txt` 中）实际内容。AI 工具可以读取完整文件来理解您的文档，而无需发出多个 HTTP 请求。
</Accordion>
