AI 助手根据您的文档回答有关您产品的问题。只有当它们能够读取文档时才能做到这一点。AI 评分衡量它们的读取能力。Jamdesk 在每次构建后扫描您已发布的网站，依据开放的 [AFDocs](https://afdocs.dev) 代理就绪标准进行评估。您将获得 0-100 分的评分、字母等级以及按问题划分的详细分析。

<Tip>
  **先在任意网站上试用。** 免费的 [AI 评分工具](https://jamdesk.com/ai-score)可依据同一标准为任意文档 URL 评级。[AI 评分 Chrome 扩展程序](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj)可在您浏览时为网站评级。在 Jamdesk 内部，评分会自动对您的文档运行。
</Tip>

## 评分方式

AI 评分自动运行，无需设置。Jamdesk 会等待每次成功构建上线。然后扫描您已发布的文档并记录结果。

- **每次构建时运行：**每次部署都会重新评分您的网站。退化会在发布的那一刻显现。
- **0-100 分及字母等级**（从 A+ 到 F），依据开放的 AFDocs 标准衡量。与免费公共工具使用相同的引擎。
- **随时重新运行：**打开项目的 **AI 评分**页面并点击**立即运行评分**。无需等待构建即可再次评分线上网站。

在仪表板中，进入您的项目 → **AI 评分**即可找到。

## 查看评分

AI 评分页面包含三个部分：

- **评分环形图：**您当前的分数和等级，以及自上次构建以来的变化。
- **趋势线：**您在近期构建中的分数。下降一目了然。
- **类别卡片：**您的检查项按七个领域分组，每个领域有一个等级。展开某个卡片可查看其检查项以及通过、警告或失败的状态。

页脚注明扫描的内容、抽样的页面数量以及 AFDocs 规范版本。

### 评分衡量的内容

每个类别对相关的代理就绪检查项进行分组：

| 类别 | 涵盖内容 |
|---|---|
| 内容可发现性 | `llms.txt` 以及将代理引向您内容的信号 |
| Markdown 可用性 | 供代理读取的每个页面的干净 Markdown 版本 |
| 页面大小与截断风险 | 足够小、能放入代理上下文窗口的页面 |
| 内容结构 | 标题、排序以及页面早期即开始的内容 |
| URL 稳定性与重定向 | 稳定的 URL 和正确的同主机重定向 |
| 可观察性与内容健康 | 状态码、缓存，以及读者与代理所见内容之间的一致性 |
| 身份验证与访问 | 代理是否能够访问页面 |

## 修复问题

每个警告或失败的检查项都附有通俗易懂的说明。其修复方法以您的 MDX 和 `docs.json` 为准进行描述。发现的问题分为两类：

- **需要您在内容中修复的问题：**例如，内容开始位置过于靠后的页面、需要拆分的超大页面，或由交互式组件渲染而未出现在页面 Markdown 中的内容。修复文本会说明下一步操作及其适用的页面。
- **Jamdesk 为您完成的工作：**Jamdesk 生成 `llms.txt`、Markdown 导出、状态码和缓存。此处的失败通常是暂时的构建问题。在下次构建后重新运行评分。若问题持续，请联系支持团队。

### 复制修复提示

每个可修复的检查项都有一个**复制修复提示**按钮。它会复制一段提示，其中包含检查项、发现的问题以及在您的 MDX 或 `docs.json` 中的修复方法。将其粘贴到 AI 编程代理（[Claude Code](/cn/ai/claude-code)、[Jamdesk Claude 插件](/cn/claude-code-plugin)、[Cursor](/cn/ai/cursor) 或 [Codex](/cn/ai/codex)）中即可进行编辑。推送以重新构建并重新评分。

## 评分变化时接收邮件

当构建产生您的首个评分、分数变动 3 分或以上，或使您回到 100 分时，Jamdesk 会向项目成员发送邮件，告知新分数及最重要的待修复问题。

- **按项目切换：****评分变化时通知团队**开关位于 AI 评分页面顶部，默认开启。
- **小幅变化保持安静：**一两分的变动不会发送邮件。Jamdesk 会将每次新分数与上次通知您的分数进行比较。逐步的漂移会累积。当总变化达到 3 分时您会收到邮件。

<Note>
  手动重新运行和构建触发的评分可能会发送邮件。回填的扫描和公共工具扫描从不发送邮件。
</Note>

## 故障排除

<AccordionGroup>
  <Accordion title="评分显示无法读取我的网站">
    当您的网站短暂不可访问、返回错误或阻止了扫描器时，扫描结果会为空。Jamdesk **不会**保存这些结果。暂时性故障不会固定错误的分数或拉低您的趋势线。您上一次的有效评分仍保留在页面上。点击**立即运行评分**重试。
  </Accordion>
  <Accordion title="由于我的文档受密码保护，分数较低">
    AI 代理无法读取密码保护之后的页面。评分反映了这一点。当访问限制是有意设置时（例如内部或发布前的文档），较低的分数是预期之中的。
  </Accordion>
  <Accordion title="我的项目设置为 noindex，因此没有评分">
    `noindex` 项目没有 Jamdesk 可以扫描的站点地图。Jamdesk 会为其跳过 AI 评分。AI 代理仍然可以通过 `llms.txt` 读取您的文档。无论是否 `noindex`，它都保持发布状态。若要重新获得评分，请从 `docs.json` 的 `seo.metatags.robots` 中移除 `noindex`。
  </Accordion>
  <Accordion title="某项检查失败，但我无法采取行动">
    某些检查涵盖 Jamdesk 负责的平台行为（`llms.txt`、Markdown 导出、状态码、缓存）。这些检查按设计通过。失败几乎总是意味着暂时的构建问题。在下次构建后重新运行评分。若问题持续，请联系支持团队。
  </Accordion>
</AccordionGroup>
