---
title: 隐藏页面
description: 无需删除页面，即可将其从侧边栏和搜索结果中隐藏，并通过 frontmatter、docs.json 或 SEO 控制可见性。
---

有些页面不适合出现在公开侧边栏中：草稿、内部手册、仍需通过链接访问的已弃用指南等。隐藏页面仍可通过直接 URL 访问，但会从导航、搜索、站点地图以及提供给 LLM 的 AI 上下文中消失。

## 隐藏单个页面

在页面的 frontmatter 中添加 `hidden: true`：

```mdx
---
title: Internal handbook
hidden: true
---
```

当有人访问该页面的 URL 时，页面会正常渲染，但 Jamdesk 会：

- 将其从侧边栏中移除
- 添加 `<meta name="robots" content="noindex, follow">`，使搜索引擎跳过该页面
- 将其从 `sitemap.xml`、`llms.txt`、`llms-full.txt` 和站内搜索中排除

## 隐藏整个组或标签页

在 `docs.json` 的组或标签页上设置 `"hidden": true`：

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Public",
        "groups": [{ "group": "Guides", "pages": ["intro", "quickstart"] }]
      },
      {
        "tab": "Internal",
        "hidden": true,
        "groups": [{ "group": "Runbooks", "pages": ["oncall", "postmortems"] }]
      }
    ]
  }
}
```

隐藏节点下的每个页面都会继承此规则。同一标志也适用于 `tabs`、`groups`、`anchors`、`dropdowns`、`products`、`languages` 和 `versions`。

## 将隐藏页面保留在搜索中

如果希望隐藏的标签页或组不出现在侧边栏中，但仍可用于站内搜索、AI 回答和站点地图索引，请添加 `"searchable": true`：

```json
{
  "tab": "Internal",
  "hidden": true,
  "searchable": true,
  "groups": [{ "group": "Runbooks", "pages": ["oncall"] }]
}
```

子页面 frontmatter 中的 `hidden: true` 仍具有更高优先级。`searchable` 只会重新开放那些自身未选择退出的后代页面。

## 仅将页面排除在搜索之外

有时，页面应保留在侧边栏中并继续建立索引，但不应在用户搜索或提问时显示。请在其 frontmatter 中添加 `search: false`：

```yaml
---
title: Legacy v1 endpoints
search: false
---
```

页面会继续保留在导航、站点地图、`llms.txt` 和 RSS feed 中，搜索引擎也仍会为其建立索引。它被移除的只是*查找*界面：站内搜索、AI 聊天回答和 MCP 服务器。

<Note>
`search: false` 与 `hidden: true` 的作用相反。`hidden` 会将页面从导航和索引界面中移除；`search: false` 不会改变这些设置，只会停止检索该页面。不要将它与导航级别的 `searchable` 混淆，后者会将隐藏页面重新纳入搜索。
</Note>

## 页面中有多少内容会被建立索引

搜索不会将页面作为一个整体进行索引，而是**按章节逐一索引**——每个标题都会成为独立的搜索条目，因此搜索“Rate limits”的读者会直接到达该标题，而不是长页面的顶部。

这里有两个限制，并且都会自动生效：

| 限制 | 值 | 超出限制后的行为 |
|---|---|---|
| 每页条目数 | 50 | 按页面顺序为章节建立索引。使用第 50 个条目后，剩余所有章节都会从搜索中排除。 |
| 每个章节的文本量 | 前 300 个字符 | 章节更深处的措辞不会参与匹配。 |

页面本身会占用 50 个名额中的一个，因此最多会有 49 个章节建立索引。

设置此上限，是因为搜索会将每个条目与索引中的其他内容进行权衡。一页产生数百个条目，会挤占其他页面在结果中的位置——自动生成的变更日志可能单独占据一半索引，并将真正相关的页面推到首屏之外。

<Warning>
超过上限的页面仍会完整渲染。只有后面的章节不再可搜索，并且页面不会向读者说明这一点。

如果页面包含超过约 50 个标题，请将其拆分为多个页面——这样导航也会更好；或者，如果页面是机器生成的且没有人会手动搜索它，请添加 `search: false`，将其整体排除在索引之外。
</Warning>

如果想让搜索正确评估某个术语，请使用页面标题（权重最高），其次是标题，再其次是描述。正文的权重最低，并且每个章节只计算前 300 个字符。

<Note>
`seo.metatags.keywords` 不会提供给站内搜索。它会生成 HTML `<meta name="keywords">` 标签，而 Google 已声明该标签不会影响排名。没有办法为页面附加额外的搜索词——请将希望匹配的词语放入标题、章节标题或描述中。
</Note>

## 项目级控制

两个标志都位于 `docs.json` 的 `seo` 下：

| 标志 | 默认值 | 作用 |
|---|---|---|
| `seo.indexing` | `"navigable"` | 只有列在导航中的页面才会出现在生成结果中。设置为 `"all"` 可包含仓库中的每个 MDX 文件。 |
| `seo.indexHiddenPages` | `false` | 设置为 `true` 后，会将 `hidden: true` 页面纳入站点地图、`llms.txt` 和搜索，并移除自动 noindex 标签。 |

示例：

```json
{
  "seo": {
    "indexing": "all"
  }
}
```

## 快速参考

| 场景 | Frontmatter | docs.json | 在侧边栏中可见 | 直接 URL | 在站点地图中 |
|---|---|---|---|---|---|
| 普通页面 | — | 已列出 | 是 | 是 | 是 |
| 通过 frontmatter 隐藏 | `hidden: true` | 已列出 | 否 | 是 | 否 |
| 不在导航中的页面（孤立页面） | — | 未列出 | 否 | 是 | 否 |
| 隐藏的组 | — | 组上设置 `hidden: true` | 否 | 是 | 否 |
| 隐藏且可搜索的组 | — | `hidden: true, searchable: true` | 否 | 是 | 是 |
| 仅排除在搜索之外 | `search: false` | 已列出 | 是 | 是 | 是 |
| 项目选择将所有内容纳入索引 | — | 任意 | 同上 | 是 | 是 |

## 何时使用各项设置

- **草稿和预览：** 在单个页面上使用 frontmatter `hidden: true`
- **面向小型团队的内部章节：** 使用隐藏的组或标签页
- **应公开但不应主动推广的合规文档：** 使用 `searchable: true` 的隐藏组
- **仅用于 AI grounding 的完整仓库索引：** 使用 `seo.indexing: "all"`
- **仍希望可链接和建立索引，但不希望通过搜索或 AI 展示的替代页面：** 使用 frontmatter `search: false`

隐藏页面不是访问控制。任何拥有 URL 的人都可以阅读这些页面。如需真正的访问控制，请参阅[密码保护](/cn/setup/password-protection)。
