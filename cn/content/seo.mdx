## 优化内容

### 编写有效的 Frontmatter

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**将关键词放在前面。**“身份验证设置”比“如何设置身份验证”更合适。
</Tip>

### 页面标题

- 将标题控制在 60 个字符以内，并计入标题格式附加的站点名称，避免在搜索结果中被截断
- 将主要关键词放在靠近开头的位置
- 确保文档中的每个页面都有独一无二的标题

默认情况下，浏览器标签页和搜索结果显示的标题格式为 `Page title — Site name`。要更改格式，请在 `docs.json` 中设置 `seo.titleTemplate`，并用 `%s` 表示页面标题的位置：

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

标题为 `Getting started` 的页面随后会显示为 `Getting started | Acme`。仅使用 `"%s"` 可省略站点名称。如果模板不含 `%s`，构建会失败，`jamdesk validate` 会显示错误。链接预览中的 `og:title` 和 `twitter:title` 仍只显示页面标题。

有两类页面不使用该模板。没有 `title` 的页面会显示你的 `name`，后接“Documentation”，例如 `Acme Documentation`；如果 `name` 已以“Docs”或“Documentation”结尾，则只显示 `name`。如果页面标题与 `name` 相同，也只显示该标题。

从 CLI 1.1.220 版起，`jamdesk validate` 和 `jamdesk dev` 支持 `seo.titleTemplate`。使用 `npm i -g jamdesk@latest` 升级。

### 描述

- 以 120–160 个字符为目标
- 概述读者将学到的内容
- 自然地融入相关关键词

<Note>
**自动生成的备用描述。**如果 frontmatter 中缺少 `description`，Jamdesk 会自动提取页面内容的第一个正文段落，最多 155 个字符。提取时会跳过标题、代码块、图片和 MDX 组件。这段文字会用于 `<meta name="description">`、Open Graph 和 Twitter 卡片。为获得最佳效果，仍建议明确编写描述。
</Note>

## 控制索引收录

### 全站设置

在 `docs.json` 中配置默认的爬虫行为：

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### 单页控制

在 frontmatter 中覆盖特定页面的索引设置：

```yaml
---
title: Internal Notes
noindex: true
---
```

以下页面适合使用 `noindex`：
- 草稿或尚未完成的页面
- 内部文档
- 为供参考而保留的弃用内容

### 搜索索引与 AI 摄取

`robots` 元数据和 `noindex` 控制的是**搜索引擎**：页面是否出现在 Google 和你的 `sitemap.xml` 中。它们不会影响供 AI 工具读取的 `llms.txt` 和 `llms-full.txt` 文件。要停止发布这些文件，请将 `seo.ai.llmsTxt` 设为 `false`（参见[关闭 llms.txt](/cn/ai/llms-txt#关闭-llmstxt)）。这两种控制相互独立：页面可以被搜索引擎收录但不供 AI 摄取，反之亦然。

## 规范 URL

如果文档可通过多个 URL 访问，请设置规范 URL：

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

你也可以在 `docs.json` 中设置全站规范 URL 的基础地址。Jamdesk 会在后面附加每个页面的路径，使每个页面都获得正确的规范 URL：

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## 社交预览与 Open Graph

Jamdesk 会自动为每个页面生成带有品牌标识的 1200×630 社交卡片。你可以在 frontmatter 中覆盖任意社交标签。既可以使用**顶层扁平键**，也可以使用嵌套的 **`seo:`** 块。两种方式都有效；如果同一个键在两处都有设置，顶层值优先。

<Card title="OpenGraph 预览" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  使用 OpenGraph Preview 工具查看任意页面的卡片在 X、Facebook、LinkedIn 等平台上的呈现效果，并验证其 Open Graph 标签。
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### 支持的标签

| 类别 | 标签 |
|-------|------|
| Open Graph | `og:title`、`og:description`、`og:image`、`og:image:width`、`og:image:height`、`og:image:alt`、`og:url`、`og:type`、`og:site_name`、`og:locale`、`og:video`、`og:audio` |
| 文章 | `og:type: article`，搭配 `article:published_time`、`article:modified_time`、`article:author`、`article:section`、`article:tag` |
| Twitter / X | `twitter:card`、`twitter:title`、`twitter:description`、`twitter:image`、`twitter:image:alt`、`twitter:site`、`twitter:creator`、`twitter:player`、应用卡片标签 |
| 其他 | `keywords`、`author`、`robots`、`googlebot`、`google-site-verification`、`theme-color`，以及任意自定义标签（将自定义标签放在 `seo:` 下） |

<Note>
**自定义 OG 图片尺寸。**`og:image:width` 和 `og:image:height` 仅在
[`customImage`](#自定义社交卡片) 为 `"replace"` 时生效。请将它们与所描述的
`og:image` 设在同一位置：页面 frontmatter 或 `seo.metatags` 中。生成的卡片
始终为 1200×630。
</Note>

<Note>
**自定义标签。**任意元标签（例如 `x-pinterest`）会输出为 `<meta name="...">`。
请将它们放在 `seo:` 块下。放在顶层时，只有已识别的 SEO 键会被读取。
</Note>

### Twitter / X 卡片类型

`twitter:card` 标签控制链接在 X（及其他平台）上分享时使用的布局：

| 值 | 呈现效果 |
|-------|--------------------|
| `summary` | 左侧为小型方形缩略图，旁边是标题和描述，布局紧凑。 |
| `summary_large_image` | 上方为横跨整个宽度的大图，下方是标题和描述，图片更醒目。 |

对于带有品牌标识的 1200×630 卡片，请使用 `summary_large_image`，使图片以完整宽度显示。

### 全站默认图片

在 `docs.json` 中为所有页面设置备用社交图片。单独设置了 `og:image` 的页面会覆盖它：

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**发布前预览。**构建完成后，将页面 URL 粘贴到 [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) 工具中，检查卡片在各平台的呈现效果并验证 Open Graph 标签。该工具还会检查图片尺寸，并说明如何修复发现的问题。
</Tip>

### 自定义社交卡片

除非在 `docs.json` 中添加 `seo.socialCard`，否则生成的卡片会保持现有外观。只需设置你想更改的键：

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| 键 | 默认值 | 效果 |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` 会在深色背景上使用浅色文字，并使用你的 `logo.dark` 图片。 |
| `brandColor` | `false` | `true` 会使用 `colors.primary` 为底部色条和章节徽标着色。若设置了 `colors.light`，深色卡片会使用它。如果没有设置 `colors`，卡片会使用主题的强调色。`false` 则保留默认的红色。 |
| `accentBar` | `true` | `false` 会移除卡片底部的彩色条。 |
| `siteName` | `true` | `false` 会隐藏徽标下方的站点名称。如果徽标已包含名称，可以使用此设置。 |
| `customImage` | `"background"` | `"background"` 会在你的 `og:image` 上绘制页面标题。`"replace"` 会将你的 `og:image` 用作整张卡片。 |

卡片只能绘制 SVG、PNG 和 JPG 徽标。Jamdesk 在构建网站时会将仓库中的 PNG 和 JPG 徽标文件转换为 WebP，因此即使设置了 `siteName: false`，卡片通常也会改为显示网站图标，并保留站点名称。要在卡片上显示完整徽标，请使用 SVG 徽标；深色卡片则使用 `logo.dark`。

卡片无法绘制 SVG 徽标中的文字，因此文字会显示为空白。要解决此问题，请在设计工具中将文字转换为轮廓（路径），然后重新导出 SVG。在 Figma 中，选中文字并使用 **Flatten**。在 Illustrator 中，使用 **Type > Create Outlines**。如果构建过程发现卡片所用的 SVG 徽标包含文字，会显示一条建议。设为完整 URL（`https://...`）的徽标不会接受此检查。

如果品牌色与卡片的对比度不足，徽标旁的徽标文字会改用普通文字颜色。底部色条仍使用品牌色，除非该颜色与卡片背景几乎相同；这时色条会变为灰色。

默认情况下，Jamdesk 会在你的 `og:image` 上绘制页面标题。如果图片本身已有文字或设计，请设置 `"customImage": "replace"`，按原样显示图片。

当 `og:image` 用作卡片背景时，请选择与图片相匹配的 `theme`：深色图片用 `dark`，浅色图片用 `light`。

在 `replace` 模式下，Jamdesk 不会在图片上绘制标题。如果 `seo.metatags` 设置了 `og:image`，所有页面都会使用该图片；单独设置了 `og:image` 的页面则使用自己的图片。只有两处都未设置的页面才会获得生成的卡片。请使用 1200×630 的 PNG 或 JPG 图片。部分平台不显示 WebP 或 SVG 图片。

社交网站会缓存链接预览，因此更改这些设置后，之前分享过的链接可能仍会在一段时间内显示旧卡片。请使用 [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) 工具检查新卡片。

<Note>
旧版 Jamdesk CLI 会在 `jamdesk validate` 和 `jamdesk dev` 中拒绝
`seo.socialCard` 和 `seo.titleTemplate`。请使用 `npm i -g jamdesk@latest` 升级。
</Note>

## 站点地图与 Robots.txt

每个 Jamdesk 网站都会在每次构建时自动生成 `sitemap.xml` 和 `robots.txt`。

| 文件 | 用途 |
|------|---------|
| `sitemap.xml` | 列出所有页面及其最后修改日期，供搜索引擎使用 |
| `robots.txt` | 允许所有爬虫访问，并指向站点地图 |

### 查找位置

URL 取决于文档位于域名根目录，还是位于 `/docs` 子路径下：

<Tabs>
  <Tab title="域名根目录">
    如果文档位于域名根目录（例如 `docs.acme.com` 或 `acme.jamdesk.app`）：

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="/docs 子路径">
    如果文档位于主站的 `/docs` 路径下（如本站的 `jamdesk.com/docs`）：

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### 站点地图包含的内容

- 所有已发布的页面（不包括 frontmatter 中设置了 `noindex` 或 `hidden` 的页面）
- 如果 frontmatter 中提供了最后修改日期，也会将其包含在内
- 每周更新频率

### 从站点地图中排除页面

在 frontmatter 中添加 `noindex`，即可从站点地图和搜索引擎中排除页面：

```yaml
---
title: Internal Notes
noindex: true
---
```

设置了 `hidden: true` 的页面也会自动被排除。

## JSON-LD 结构化数据

每个页面都会自动通过 `<script type="application/ld+json">` 标签包含 [schema.org](https://schema.org) 结构化数据，其中有两种模式：

- `WebSite`：从 `docs.json` 获取的站点名称、URL 和描述。
- `BreadcrumbList`：根据 `navigation` 配置生成的从首页到当前页面的导航路径。

无需配置。搜索引擎会使用这些数据，在搜索结果中展示面包屑导航等富媒体结果。

<Tip>
**验证标记。**将任意页面的 URL 粘贴到 [Google 富媒体搜索结果测试](https://search.google.com/test/rich-results)中，确认结构化数据已被识别。
</Tip>

## IndexNow

每次构建后，Jamdesk 都会自动将发生变化的页面 URL 提交到 [IndexNow](https://www.indexnow.org)，以加快搜索引擎收录。这样无需等待下一次抓取，Bing、Yandex 和其他参与的搜索引擎就能获知你的内容变更。

- 每次成功构建后都会运行
- 只提交实际发生变化的页面
- 不会阻塞或延迟构建
- 无需配置

## 最佳实践

发布前请检查以下事项：

<Note>
**发布前检查清单**

- **独一无二的标题。**每个页面都有不超过 60 个字符、内容明确且不重复的标题。
- **准确的描述。**描述用 120–160 个字符概述页面内容。
- **合理的标题层级。**标题层级清晰：一个 H1，然后依次使用 H2 → H3。
- **有意义的链接。**内部链接使用能说明目标内容的锚文本，而不是“点击这里”。
- **图片替代文本。**每张图片都有替代文本，以支持无障碍访问和图片搜索。
- **社交图片。**在重要页面设置自定义 `og:image`，或使用自动生成的卡片。使用 [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) 工具验证效果。
</Note>
