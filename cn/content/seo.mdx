## 优化内容

### 编写有效的 Frontmatter

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**关键词尽量前置。** “Authentication setup”比“How to set up authentication”更好。
</Tip>

### 页面标题

- 控制在 60 个字符以内，避免在搜索结果中被截断
- 将主要关键词放在标题靠前的位置
- 确保文档中的每个标题都不重复

默认情况下，浏览器标签页和搜索结果中的标题格式为 `Page title — Site name`。如需更改，请在 `docs.json` 中设置 `seo.titleTemplate`。每个 `%s` 都会替换为页面标题：

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

仅使用 `"%s"` 可省略站点名称。此模板只会更改浏览器标签页和搜索结果中的标题。社交预览中的标题（`og:title`）保持不变。没有标题或标题与站点名称相同的页面，会按原样显示站点标题。

### 描述

- 建议控制在 120-160 个字符
- 概括读者将会了解到的内容
- 自然地加入相关关键词

<Note>
**自动生成的后备描述。** 如果 frontmatter 中缺少 `description`，Jamdesk 会自动提取页面内容中的第一个正文段落（最多 155 个字符）。标题、代码块、图片和 MDX 组件会被跳过。提取的内容将用于 `<meta name="description">`、Open Graph 和 Twitter 卡片。为获得最佳效果，仍建议明确编写描述。
</Note>

## 控制索引收录

### 全站设置

在 `docs.json` 中配置默认的 robots 行为：

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### 单页控制

在 frontmatter 中为特定页面设置索引规则：

```yaml
---
title: Internal Notes
noindex: true
---
```

以下情况可使用 `noindex`：
- 草稿或尚未完成的页面
- 内部文档
- 保留供参考的过时内容

### 搜索索引与 AI 摄取

`robots` 元数据和 `noindex` 控制的是**搜索引擎**：页面是否会出现在 Google 和 `sitemap.xml` 中。它们不会影响 AI 工具读取的 `llms.txt` 和 `llms-full.txt` 文件。如需停止发布这些文件，请将 `seo.ai.llmsTxt` 设置为 `false`（参见[关闭 llms.txt](/cn/ai/llms-txt#关闭-llmstxt)）。这两项控制彼此独立：页面可以被搜索引擎编入索引，但不纳入 AI 内容读取，反之亦然。

## 规范 URL

如果文档可通过多个 URL 访问，请设置规范 URL：

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

你也可以在 `docs.json` 中设置全站规范 URL 基址。Jamdesk 会将每个页面的路径附加到该基址，因此每个页面都会获得正确的规范 URL：

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## 社交预览与 Open Graph

Jamdesk 会为每个页面自动生成带品牌样式的 1200×630 社交卡片。你可以在 frontmatter 中覆盖任意社交标签。可以使用**顶层平铺键**，也可以使用嵌套的 **`seo:`** 区块。两种方式都有效；如果同一个键在两处都设置了，则顶层平铺值优先。

<Card title="OpenGraph 预览" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  使用 OpenGraph 预览工具，查看任意页面的卡片在 X、Facebook、LinkedIn 等平台上的显示效果，并验证其 Open Graph 标签。
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### 支持的标签

| 分组 | 标签 |
|-------|------|
| Open Graph | `og:title`、`og:description`、`og:image`、`og:image:width`、`og:image:height`、`og:image:alt`、`og:url`、`og:type`、`og:site_name`、`og:locale`、`og:video`、`og:audio` |
| 文章 | `og:type: article`，以及 `article:published_time`、`article:modified_time`、`article:author`、`article:section`、`article:tag` |
| Twitter / X | `twitter:card`、`twitter:title`、`twitter:description`、`twitter:image`、`twitter:image:alt`、`twitter:site`、`twitter:creator`、`twitter:player`、app-card 标签 |
| 其他 | `keywords`、`author`、`robots`、`googlebot`、`google-site-verification`、`theme-color`，以及任意自定义标签（将自定义标签放在 `seo:` 下） |

<Note>
**自定义 OG 图片尺寸。** `og:image:width` 和 `og:image:height` 仅在
[`customImage`](#自定义社交卡片) 为 `"replace"` 时生效。请将它们设置在与所描述的
`og:image` 相同的位置，即页面 frontmatter 或 `seo.metatags` 中。生成的
卡片始终为 1200×630。
</Note>

<Note>
**自定义标签。** 任意元标签（例如 `x-pinterest`）都会作为 `<meta name="...">` 输出。
请将它们放在 `seo:` 区块下。以平铺方式设置时，只有可识别的 SEO 键才会被读取。
</Note>

### Twitter / X 卡片类型

`twitter:card` 标签用于控制在 X（及其他平台）分享链接时使用的布局：

| 值 | 显示效果 |
|-------|--------------------|
| `summary` | 左侧显示小型方形缩略图，旁边显示标题和描述。布局紧凑。 |
| `summary_large_image` | 顶部显示大幅全宽图片，下方显示标题和描述。视觉效果醒目。 |

如需使用带品牌样式的 1200×630 卡片，请选择 `summary_large_image`，让图片以全宽显示。

### 全站默认图片

在 `docs.json` 中为每个页面设置后备社交图片。任何自行设置 `og:image` 的页面都会覆盖此图片：

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**发布前先预览。** 构建完成后，将页面 URL 粘贴到 [OpenGraph 预览](https://jamdesk.com/utilities/opengraph-preview)工具中，检查卡片在各个平台上的显示效果并验证 Open Graph 标签。该工具还会检查图片尺寸，并说明如何修复发现的问题。
</Tip>

### 自定义社交卡片

除非在 `docs.json` 中添加 `seo.socialCard`，否则生成的卡片会保持当前样式。
只需设置想要更改的键：

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| 键 | 默认值 | 效果 |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` 会在深色背景上使用浅色文字，并使用 `logo.dark` 图片。 |
| `brandColor` | `false` | `true` 会使用 `colors.primary` 为底部栏和分区徽标着色。深色卡片在你设置了 `colors.light` 时会使用该颜色。如果没有设置 `colors`，卡片会使用主题的强调色。`false` 会保留默认的红色。 |
| `accentBar` | `true` | `false` 会移除卡片底部的彩色栏。 |
| `siteName` | `true` | `false` 会隐藏 Logo 下方的站点名称。如果 Logo 已显示名称，可使用此设置。 |
| `customImage` | `"background"` | `"background"` 会在 `og:image` 上方绘制页面标题。`"replace"` 会将 `og:image` 用作整张卡片。 |

卡片只能绘制 SVG、PNG 和 JPG 格式的 Logo。Jamdesk 会在构建网站时将仓库中的 PNG 和 JPG Logo 文件转换为 WebP，因此卡片通常会改为显示网站图标，同时保留站点名称，即使设置了 `siteName: false` 也是如此。使用 SVG Logo 可在卡片上显示完整 Logo；深色卡片则使用 `logo.dark`。

卡片无法绘制 SVG Logo 内部的文字。如果 Logo 中包含文字，请在导出前将其转换为轮廓（路径）。如果卡片使用的 SVG Logo 中检测到文字，构建时会显示建议。不会检查链接到其他网站的 Logo。

如果品牌色在卡片上的对比度不足，徽标文字会改用普通文字颜色。除非品牌色与卡片背景色非常接近，否则底部栏仍会使用品牌色；若颜色过于接近，底部栏会显示为灰色。

默认情况下，Jamdesk 会在 `og:image` 上方绘制页面标题。如果图片已有文字或设计，请设置 `"customImage": "replace"`，以原样显示图片。

当 `og:image` 用作卡片背景时，请选择与图片匹配的 `theme`：深色图片使用 `dark`，浅色图片使用 `light`。

在 `replace` 模式下，Jamdesk 不会在图片上绘制标题。如果 `seo.metatags` 设置了 `og:image`，所有页面都会使用该图片；自行设置 `og:image` 的页面则会使用各自的图片。只有两处都未设置的页面才会生成卡片。请使用 1200×630 的 PNG 或 JPG。部分平台不显示 WebP 或 SVG 图片。

社交网站会缓存链接预览，因此更改设置后，已分享的链接可能会在一段时间内继续显示旧卡片。请使用
[OpenGraph 预览](https://jamdesk.com/utilities/opengraph-preview)工具检查新卡片。

<Note>
较旧版本的 Jamdesk CLI 会在
`jamdesk validate` 和 `jamdesk dev` 中拒绝 `seo.socialCard` 和 `seo.titleTemplate`。
请使用 `npm i -g jamdesk@latest` 升级。
</Note>

## 站点地图与 Robots.txt

每个 Jamdesk 站点都会在每次构建时自动生成 `sitemap.xml` 和 `robots.txt`。

| 文件 | 用途 |
|------|---------|
| `sitemap.xml` | 列出所有页面及其最后修改日期，供搜索引擎使用 |
| `robots.txt` | 允许所有爬虫访问，并指向站点地图 |

### 查找位置

文档位于根域名还是 `/docs` 子路径下，决定了对应的 URL：

<Tabs>
  <Tab title="根域名">
    如果文档位于域名根路径（例如 `docs.acme.com` 或 `acme.jamdesk.app`）：

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="/docs 子路径">
    如果文档位于主站的 `/docs` 路径下（例如本站的 `jamdesk.com/docs`）：

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### 站点地图包含的内容

- 所有已发布页面（不包括 frontmatter 中带有 `noindex` 或 `hidden` 的页面）
- frontmatter 中提供的最后修改日期
- 每周更新频率

### 从站点地图中排除页面

在 frontmatter 中添加 `noindex`，即可将页面同时排除在站点地图和搜索引擎索引之外：

```yaml
---
title: Internal Notes
noindex: true
---
```

带有 `hidden: true` 的页面也会自动排除。

## JSON-LD 结构化数据

每个页面都会自动包含 [schema.org](https://schema.org) 结构化数据，以 `<script type="application/ld+json">` 标签呈现，其中包含两种 Schema：

- `WebSite`：站点名称、URL 和描述（来自 `docs.json`）。
- `BreadcrumbList`：从首页到当前页面的导航路径，根据 `navigation` 配置生成。

无需配置。搜索引擎会使用这些数据，在搜索结果中显示面包屑导航等丰富结果。

<Tip>
**验证标记。** 将任意页面 URL 粘贴到 [Google 的 Rich Results Test](https://search.google.com/test/rich-results)，确认是否检测到结构化数据。
</Tip>

## IndexNow

每次构建后，Jamdesk 都会自动将已更改页面的 URL 提交到 [IndexNow](https://www.indexnow.org)，以加快搜索引擎索引速度。这样无需等待搜索引擎开始下一轮抓取，就能通知 Bing、Yandex 和其他参与的搜索引擎内容已更新。

- 每次成功构建后触发
- 只提交实际发生更改的页面
- 非阻塞，不会延迟构建
- 无需配置

## 最佳实践

发布前，请逐项检查：

<Note>
**发布前检查清单**

- **标题唯一。** 每个页面都有独特且描述准确的标题，长度少于 60 个字符。
- **描述准确。** 描述在 120-160 个字符内概括页面内容。
- **标题层级合理。** 标题遵循清晰的层级结构：一个 H1，然后是 H2 → H3。
- **链接描述清晰。** 内部链接使用有意义的锚文本，避免使用“点击这里”。
- **图片替代文本。** 每张图片都设置了替代文本，以提升无障碍体验并支持图片搜索。
- **社交图片。** 为重要页面设置自定义 `og:image`，或使用自动生成的卡片。使用 [OpenGraph 预览](https://jamdesk.com/utilities/opengraph-preview)工具验证。
</Note>
