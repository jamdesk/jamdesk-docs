Jamdesk 使用**两种独立的 GitHub 连接**，各自用途不同。本页说明每种连接的作用以及何时需要使用。

<Info>
**简而言之：**GitHub App 让 Jamdesk 能够访问你的仓库。关联个人账户可确保提交归属于你。
</Info>

<Note>
Bitbucket Cloud 项目的工作方式不同：一次 OAuth 授权即可涵盖仓库访问、Webhook 和构建归属。请参阅[连接 Bitbucket](/cn/setup/connecting-bitbucket)。
</Note>

## 概览

| 连接 | 用途 | 范围 | 是否必需？ |
|------------|---------|-------|-----------|
| **GitHub App** | 仓库访问和 Webhook | 每个项目 | 是 |
| **个人账户** | 用户身份和归属 | 每位用户 | 建议 |

## GitHub App（项目级）

**Jamdesk GitHub App** 安装在你的 GitHub 账户或组织中。它授予 Jamdesk 访问指定仓库的权限。

### 功能

- **读取仓库内容** - 克隆你的文档以进行构建
- **接收 Webhook** - 在你推送更改时接收通知
- **报告构建状态** - 在提交上显示部署状态

### 为什么需要它

如果未安装 GitHub App，Jamdesk 将无法：
- 访问你的仓库以构建文档
- 在你推送更改时自动部署
- 在 GitHub 提交上显示构建状态

### 工作方式

设置项目时，Jamdesk 会引导你连接 GitHub。你可以选择以下两种方式之一。

#### 创建入门文档仓库（新项目的默认选项）

<Steps>
  <Step title="使用 GitHub 登录">
    授权 Jamdesk，以便它在你的账户或组织中创建仓库。
  </Step>
  <Step title="选择创建位置">
    选择你的个人账户或组织。Jamdesk 会创建一个预先填入入门文档的新仓库。
  </Step>
  <Step title="安装 GitHub App">
    安装 Jamdesk GitHub App（或授予它访问新仓库的权限），以便它构建并自动部署你的文档。
  </Step>
  <Step title="推送触发构建">
    每次推送到已配置的分支都会自动触发部署。准备好后，你可以自定义入门文档。
  </Step>
</Steps>

#### 连接现有仓库

已经有文档仓库？安装 Jamdesk GitHub App 并授予它访问该仓库的权限，然后在 Jamdesk 的 **Project Settings → Git Repository** 中选择仓库和分支。之后的工作方式相同。

### 一个 App，多个项目

一次 GitHub App 安装即可支持多个 Jamdesk 项目：
- 在你的账户或组织中安装一次 App
- 将不同仓库连接到不同的 Jamdesk 项目
- 每个项目都有自己的分支和路径配置

<Tip>
对于组织，只需由管理员安装一次 GitHub App。之后，任何团队成员都可以使用该 App 有权访问的仓库创建 Jamdesk 项目。
</Tip>

## 个人 GitHub 账户（用户级）

关联**个人 GitHub 账户**可将你的 GitHub 身份与 Jamdesk 个人资料关联起来。这与 GitHub App 是两项独立的连接。

### 功能

- **识别你的身份** - 将你的 GitHub 用户名与 Jamdesk 账户关联
- **标记构建归属** - 显示是谁触发了每次部署
- **团队可见性** - 其他团队成员可以查看是谁进行了更改

### 为什么需要它

当你推送到 GitHub 时，Jamdesk 需要确定是哪位用户触发了构建。如果未关联账户：

- Jamdesk 会尝试通过电子邮件地址匹配
- 如果你的 Git 提交邮箱与 Jamdesk 邮箱不同，归属标记就会失败
- 构建历史记录可能会将你的提交显示为“Unknown user”

<Warning>
**常见问题：**你的 Git 配置使用个人邮箱，但注册 Jamdesk 时使用的是工作邮箱。请关联 GitHub 账户，以确保正确标记构建归属。
</Warning>

### 检查您的 Git 邮箱

```bash
git config user.email
git config --global user.email "you@company.com"
```

请使用与你的 Jamdesk 账户相同的邮箱，以避免构建历史记录中的归属信息显示为“Unknown user”。

### 如何关联您的账户

<Steps>
  <Step title="前往用户设置">
    点击右上角的头像，然后选择 **User Settings**。
  </Step>
  <Step title="找到 GitHub 账户部分">
    向下滚动到 **GitHub Account** 卡片。
  </Step>
  <Step title="点击 Link GitHub Account">
    系统会打开一个 GitHub 弹出窗口。授权 Jamdesk 读取你的个人资料。
  </Step>
  <Step title="确认连接">
    你的 GitHub 用户名会显示在 Jamdesk 个人资料中。
  </Step>
</Steps>

## 两者如何协同工作

可以把它们看作两把不同的钥匙：

| 钥匙 | 解锁内容 | 所属对象 |
|-----|-------|----------|
| GitHub App | 仓库访问权限 | 项目/组织 |
| 个人账户关联 | 你的身份 | 个人用户 |

### 团队示例

假设一个团队有 3 位开发者在处理公司文档：

1. **管理员在组织中安装 GitHub App**
2. **管理员创建 Jamdesk 项目**并连接到文档仓库
3. **每位开发者关联自己的个人账户**

之后，无论哪位开发者进行推送：
- **GitHub App** 都会允许 Jamdesk 读取仓库并进行构建
- **个人账户关联**会标识是谁触发了构建

### 独立开发人员示例

即使你是独立开发者，这两种连接的用途也不同：
- **GitHub App** - 将你的仓库连接到 Jamdesk
- **个人账户关联** - 确保构建历史记录中的提交显示你的姓名

## 断开连接与取消关联

每项操作都会移除不同的访问权限。以下是每项操作的影响。

### 断开 GitHub（项目设置）

**功能：**移除单个 Jamdesk 项目与仓库之间的连接。

**影响：**
- 该项目的自动部署会停止
- GitHub App 仍安装在 GitHub 中
- 其他 Jamdesk 项目不受影响
- 个人账户关联不受影响

**适用情况：**你想连接其他仓库，或暂时停止部署。

**重新连接：**前往 Project Settings → Git Repository 并选择一个仓库。

### 取消关联 GitHub（用户设置）

**功能：**从你的 Jamdesk 个人资料中移除 GitHub 身份。

**影响：**
- 你的 GitHub 用户名不再显示在个人资料中
- 构建归属会改为通过邮箱匹配
- 所有仓库连接保持不变
- GitHub App 仍保持安装状态

**适用情况：**你想关联其他 GitHub 账户，或移除当前连接。

**重新关联：**前往 User Settings → GitHub Account → Link GitHub Account。

### 卸载 GitHub App（在 GitHub 中）

**功能：**完全移除 Jamdesk 对你 GitHub 账户的访问权限。

**影响：**
- 使用此安装的**所有** Jamdesk 项目都会失去访问权限
- 所有受影响项目的自动部署都会停止
- Webhook 会被移除
- 个人账户关联不受影响

<Warning>
只有在你想移除 Jamdesk 对**所有**仓库的访问权限时，才卸载 GitHub App。这会影响连接到你 GitHub 账户的每个 Jamdesk 项目。
</Warning>

**卸载方法：**
1. 前往 [GitHub Settings → Applications → Installed GitHub Apps](https://github.com/settings/installations)
2. 找到“Jamdesk”并点击 **Configure**
3. 向下滚动并点击 **Uninstall**

## 快速参考

| 操作 | 位置 | 范围 | 可撤销？ |
|--------|----------|-------|-------------|
| **断开 GitHub 连接** | Project Settings → Git Repository | 单个项目 | 可以 - 随时重新连接 |
| **取消 GitHub 关联** | User Settings → GitHub Account | 你的账户 | 可以 - 随时重新关联 |
| **卸载 GitHub App** | GitHub Settings | 所有项目 | 可以 - 重新安装 |

## 故障排除

### “已经安装 Jamdesk？”

如果你之前安装过 Jamdesk GitHub App，点击“Install GitHub App”会打开 GitHub 设置页面，而不是安装页面。这是正常现象！请按以下步骤完成设置：

<Steps>
  <Step title="找到 Repository access">
    在 GitHub 设置页面向下滚动到 **Repository access** 部分。
  </Step>
  <Step title="启用 Save 按钮">
    如果 Save 按钮处于禁用状态（显示为灰色），请先从“All repositories”切换到“Only select repositories”，再切换回来。
  </Step>
  <Step title="点击 Save">
    点击绿色的 **Save** 按钮。Jamdesk 会检测到更改并继续设置。
  </Step>
</Steps>

### 弹出窗口被阻止

如果 GitHub 弹出窗口没有打开，可能是浏览器阻止了它。请在地址栏中找到弹出窗口拦截器图标，允许来自 Jamdesk 的弹出窗口，然后点击 **Try Again**。

### “我的构建显示‘未知用户’”
你尚未关联个人 GitHub 账户。请前往 **User Settings → Link GitHub Account**。

### “找不到仓库”
GitHub App 无权访问该仓库。请前往 [GitHub Settings](https://github.com/settings/installations)，找到 Jamdesk 并添加该仓库。

### “构建没有触发”
1. 检查仓库是否已在 **Project Settings → Git Repository** 中连接
2. 确认你推送到了已配置的分支
3. 在 GitHub 仓库设置中检查 Webhook 投递情况

如果这些设置都正确，推送者可能不是项目成员。Jamdesk 只会为项目成员的推送进行构建。它会通过关联的 GitHub 账户，或通过提交邮箱与该成员登录 Jamdesk 时使用的邮箱是否匹配，来识别推送者。

如果找不到匹配的用户，构建会显示为失败并附带原因，项目所有者会收到一封电子邮件；每位推送者每周最多收到一封。只更改文档文件夹之外内容的推送不会发送这类邮件。

要解决此问题，请在 **Project Settings → Members** 中使用推送者的提交邮箱邀请其加入。对方需要使用该邮箱登录 Jamdesk 才能接受邀请。如果对方已经是项目成员，也可以在 User Settings 中[关联 GitHub 账户](#个人-github-账户用户级)。

### “我无法访问组织仓库”
组织管理员必须批准 GitHub App 的安装。请联系管理员，让其在组织设置中安装或批准 Jamdesk。

### “GitHub 一直把我带回 Jamdesk App 页面”
你的公司可能管理着你的 GitHub 账户，而 GitHub 不允许这类账户在自己的账户下安装应用。请参阅[公司管理的 GitHub 账户](/cn/help/troubleshooting/github-issues#公司管理的-github-账户)了解如何解决。
