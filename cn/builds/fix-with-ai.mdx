Jamdesk 可以修复构建报告中的许多失效链接和缺失的页面描述。**Fix with AI** 按钮会读取这些构建警告，并为每项警告提出一项修改。它会将你批准的修复提交到已连接的 GitHub 仓库。该提交会触发一次新构建。

[`jamdesk fix` CLI 命令](/cn/cli/fix-broken-links)可在终端中完成相同操作。它会写入你的工作副本，提交则由你自行完成。

## 可修复的问题

Fix with AI 可以修复三类构建警告：

- **失效的内部链接：**链接片段指向目标页面中已不存在的标题，例如拼写错误（`#instalation` → `#installation`），或标题已更名的翻译页面。
- **缺少页面描述：**页面的 frontmatter 中没有 `description`。Jamdesk 会根据页面内容生成一段简短摘要，供你审核。
- **缺少页面标题：**页面没有标题时，Jamdesk 会根据页面内容提出一个标题，供你审核。

只有在能够有把握地确定目标时，它才会提出修改。对于有歧义的项目，它会单独列出，供你手动修复。

Fix with AI 每个项目在 24 小时内最多发起 1,000 次 AI 请求。未发生变化的页面会复用已有结果，且不计入限额。

<Note>
  可修复问题的数量不等于警告数量。一次构建可能显示五条警告，而 Fix with AI 只提供其中三条的修复建议。其余两条没有明确的修复方案。
</Note>

## 前提条件

- 项目已连接 [GitHub 仓库](/cn/integrations/github)。
- Jamdesk GitHub App 具有提交修复所需的写入权限。缺少权限时，模态框会显示指向 GitHub 的 **Grant access** 链接。
- 已完成的构建中包含失效链接或缺少页面描述的警告。

## 查找横幅

打开项目，在 Project Home 页面向下滚动到 **Build History**。如果最新构建存在可修复的问题，构建列表上方就会显示一个横幅，其中包含问题数量和 **Fix with AI** 按钮。

## 查看并应用修复

<Steps>
  <Step title="打开预览">
    点击 **Fix with AI**。模态框会打开。AI 代理需要几秒钟审核文档并制定修复计划。
  </Step>
  <Step title="查看每项修改建议">
    修复按类型分组。**Broken links** 会显示每个重写后的锚点。**Missing descriptions** 会显示每个页面的摘要建议。**Missing titles** 会显示建议的标题。取消勾选要暂时跳过的项目。点击忽略按钮可[永久隐藏一条建议](#忽略建议)。没有明确修复方案的问题会显示在 **Can't be fixed automatically** 下，供你手动修复。

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="Fix with AI 模态框。Broken links 部分列出三项已勾选的修复，每项都显示带删除线的旧锚点和修正后的锚点。Can't be fixed automatically 部分列出两项需手动修复的问题，下方有 Cancel 和 Apply 3 fixes 按钮。" />
    </Frame>
  </Step>
  <Step title="应用修复">
    点击 **Apply fixes**。Jamdesk 会将所选修改提交到已连接的分支，提交说明为 `docs: apply AI-suggested fixes (via Jamdesk)`，并启动一次新构建。
  </Step>
  <Step title="确认重新构建">
    在 [Build History](/cn/builds/monitoring) 中查看新构建。修复后的警告会在新版本上线后消失。剩余的警告要么是 Fix with AI 无法解决的问题，要么是最新内容引入的新问题。
  </Step>
</Steps>

<Note>
  应用修复会向你的仓库写入一条实际提交。你可以像处理其他提交一样，在 GitHub 上审核或还原它。
</Note>

## 某些问题无法修复时

模态框会在单独的标题下列出没有明确修复方案的警告，并且不会修改这些问题。常见原因包括：

- 失效链接的目标页面或标题在任何地方都不存在。
- 导航条目没有对应的源文件。
- 代理无法为某个页面生成描述。

这些问题需要手动修改。请在[编辑器](/cn/development/local-preview)或代码编辑器中打开页面，修正链接或添加描述，然后推送更改以重新构建。

## 忽略建议

有些警告不值得处理：例如你有意设置为失效的链接，或不需要描述的占位页面。取消勾选一项修复只会跳过这一次。忽略该项后，它会从计数中移除，直到你将其恢复。

模态框中的每一行都有忽略按钮，无论该问题是否可修复。点击按钮后，该项目会移至底部折叠的 **Ignored** 部分。关闭模态框后，Project Home 页面的横幅计数会相应减少。当前构建以及之后每次构建中的对应警告也会消失。**Ignore all** 会对仍在列表中的所有项目执行相同操作。

忽略的行为方式：

- **共享且持久：**忽略设置适用于整个项目。所有成员看到的列表都相同，并且设置会在不同构建之间保留。Jamdesk 根据警告内容而非行号匹配每条警告。编辑页面的其他部分不会让已忽略的项目重新出现。
- **恢复：**展开 **Ignored** 部分，然后点击任意项目上的 **Restore**。忽略某次构建中的所有项目后，横幅会隐藏。随后，Build History 下方会出现一个小型的“N ignored recommendations”链接，点击即可重新打开模态框。
- **警告内容变化后会重新出现：**底层问题发生变化时，已忽略的项目会作为新建议重新出现，例如失效链接现在指向了其他位置。

## Fix with AI 与 CLI 对比

仪表板和 CLI 都可以修复失效链接锚点。两者的运行位置和修改写入方式不同。

| | Fix with AI（仪表板） | [`jamdesk fix`](/cn/cli/fix-broken-links)（CLI） |
|---|---|---|
| 运行位置 | 在仪表板中，针对某次构建 | 在终端中，针对本地文件 |
| 修复内容 | 失效链接和缺少的页面描述 | 失效链接锚点 |
| 提交方式 | 代你提交到分支 | 写入本地文件，由你提交 |
| 触发方式 | 点击构建横幅一次 | `jamdesk fix` |

如果想快速修复且无需离开 Jamdesk，请使用仪表板流程。如果想先在工作副本中查看修改，例如将修复与其他编辑一并提交，请使用 CLI。
