**Jamdesk 是一款文档软件**，可将包含 Markdown 的 GitHub 仓库发布为托管文档站点。它会自动生成 AI 可读的输出：`llms.txt`、每页的 `.md` 端点以及 MCP 服务器。

用两个文件即可部署文档站点：`docs.json` 和一个 MDX 页面。请选择与您起点相符的路径。

## 前置条件

您需要：
- 一个 [GitHub](https://github.com) 账户
- 一个包含您文档的仓库（或者我们为您创建一个）

## 选项 1：从入门模板开始

这是最快的入门方式。[入门模板](https://github.com/jamdesk/starter-docs)包含示例内容、OpenAPI 规范以及每个组件的示例。先了解工作原理，再替换为您自己的内容。

<Steps>
  <Step title="创建 Jamdesk 账户">
    前往 [dashboard.jamdesk.com](https://dashboard.jamdesk.com)，使用 GitHub 注册。
  </Step>

  <Step title="从模板创建项目">
    点击 **New Project** → **From Template** → **Starter Docs**。

    Jamdesk 会为您创建一个已预先配置好所有内容的 GitHub 仓库。
  </Step>

  <Step title="上线啦">
    您的文档已部署到 `your-project.jamdesk.app`。编辑 MDX 文件并推送，站点会自动重新构建。
  </Step>
</Steps>

<Tip>
您也可以直接克隆入门模板：`git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

<Tip>
**想让部分页面保持私密？** 在任意 MDX 文件的 frontmatter 中添加 `private: true`。下次构建后，在 **Project Settings** 中设置密码。关于全部四种选项（公开、全站密码、混合、SSO），请参阅[访问控制](/cn/setup/access-control)。
</Tip>

## 选项 2：连接现有仓库

如果您已有包含 Jamdesk 可用文档的仓库，可以直接连接。如果您正从 Mintlify 或其他文档平台迁移，请先使用选项 3。

<Steps>
  <Step title="创建 Jamdesk 账户">
    前往 [dashboard.jamdesk.com](https://dashboard.jamdesk.com)，使用 GitHub 注册。
  </Step>

  <Step title="创建项目">
    点击 **New Project** 并连接您的仓库。

    1. 选择您的 GitHub 仓库
    2. 选择要部署的分支
    3. Jamdesk 会自动检测您的 `docs.json`

    如果您的仓库还没有 `docs.json`，请先从 [文档项目结构](#文档项目包含什么)中添加最简文件，然后再进行连接。

    关于仓库权限、分支选择和文档路径，请参阅[连接 GitHub](/cn/setup/connecting-github)。
  </Step>

  <Step title="上线啦">
    您的文档已部署到 `your-project.jamdesk.app`。Jamdesk 会自动为 AI 工具生成 `llms.txt`。

    每次推送到您所连接的分支都会触发自动重新构建。
  </Step>
</Steps>

## 选项 3：从 Mintlify 或其他文档平台迁移

## 文档项目包含什么

一个最简的 Jamdesk 项目包含两样东西：

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

对于较大的站点，请参阅[目录结构](/cn/setup/directory-structure)，了解推荐的文件夹、资源和代码片段组织方式。

### docs.json

定义站点的配置文件：

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

所有配置选项请参阅 [docs.json 参考](/cn/config/docs-json-reference)。

### MDX 页面

以 MDX 编写的文档页面：

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

关于 frontmatter、标题、链接和组件语法，请参阅 [MDX 基础](/cn/content/mdx-basics)。

## 本地开发

在推送到 GitHub 之前，使用 Jamdesk CLI 在本地预览更改。它可以在 MDX 语法错误到达线上站点之前将其捕获。关于每种安装方式和命令，请参阅 [Jamdesk CLI 概览](https://jamdesk.com/docs/cli/overview)。

运行方式：

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

打开 **http://localhost:3000** 即可查看您的文档，并支持热重载。

## 添加更多页面

1. 创建一个新的 MDX 文件：

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. 将其添加到 `docs.json`：

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. 推送到 GitHub。您的新页面会自动部署。

关于更多链接模式（包括锚点和卡片），请参阅[链接与导航](/cn/content/links)。

## 自定义域名

在 **Settings** → **Domains** 中添加您自己的域名：

1. 输入您的域名（例如 `docs.example.com`）
2. 添加所示的 DNS 记录
3. 等待验证（最长 48 小时）

SSL 证书会自动配置。[完整指南 →](/cn/deploy/custom-domains)
