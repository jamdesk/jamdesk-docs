从空仓库开始，搭建上线的文档站点。已完成的步骤可以跳过。

## 前置条件

- 一个 GitHub 账户
- 一个包含文档内容的仓库（或使用 [Starter Template](https://github.com/jamdesk/starter-docs)）
- 如果要通过 npm 安装 CLI，需要 Node.js 20+

<Steps>
  <Step title="创建项目并连接 GitHub">
    在 Jamdesk 控制台中创建项目并连接一个仓库。

    - 按照[创建项目](/cn/setup/creating-projects)设置项目名称、slug 和文档路径
    - 如果出现提示，安装 GitHub App 并授予仓库访问权限（[连接 GitHub](/cn/setup/connecting-github)）
  </Step>

  <Step title="使用 CLI 编辑并预览页面">
    在推送到 GitHub 之前，先用 Jamdesk CLI 预览页面编辑效果。

    <Tabs>
      <Tab title="npm">
        ```bash
        npm install -g jamdesk
        cd your-docs
        jamdesk dev
        ```
      </Tab>
      <Tab title="npx">
        ```bash
        cd your-docs
        npx jamdesk dev
        ```
      </Tab>
    </Tabs>

    本地预览地址为 **http://localhost:3000**。更多信息请参阅[本地预览](/cn/development/local-preview)。

    在编辑器中打开一个 `.mdx` 页面，保存修改后刷新本地预览。在下一步中，通过 Git 工作流发布这些更改。
  </Step>

  <Step title="通过推送到 GitHub 进行部署">
    每次推送到已配置的分支都会触发一次构建，构建结果会发布到你的 Jamdesk 子域名。

    ```bash
    git add .
    git commit -m "Add docs content"
    git push origin main
    ```

    将 `main` 替换为项目中配置的分支名称。

    构建完成后，你的文档将在 `your-project.jamdesk.app` 上线。详情请参阅[部署](/cn/development/deployment)。
  </Step>

  <Step title="可选：添加自定义域名">
    使用你自己的域名提供文档服务，而不是使用 Jamdesk 子域名。

    1. 在 Jamdesk 控制台中前往 **Settings** → **Domains**
    2. 添加你的域名（例如 `docs.example.com`）
    3. 创建控制台中显示的 DNS 记录
    4. 等待验证和 SSL 配置完成

    如需排查问题，请参阅[自定义域名](/cn/deploy/custom-domains)。
  </Step>
</Steps>

## 验证端到端流程

- 你的 Jamdesk 子域名可以正常加载并显示最新构建
- 本地预览与之展示相同的内容和导航
- 如果已配置，自定义域名已通过验证并以 HTTPS 提供服务
- 构建历史中显示最新提交及作者信息

## 可选：托管于 /docs

若要将文档部署在 `example.com/docs` 这样的子路径下，请参阅[部署概览](/cn/deploy/overview)和[子路径托管](/cn/deploy/subpath-hosting)。
