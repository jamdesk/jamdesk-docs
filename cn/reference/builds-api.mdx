使用 Builds API 可在不推送新提交的情况下触发文档重新构建。这适用于 CI 流水线、定时重新构建，或在文档目录之外生成的内容。

## 身份验证

所有请求都使用项目 API 密钥：

```http
Authorization: Bearer YOUR_API_KEY
```

在项目的 **Settings** → **API** 中找到你的 API 密钥。

## 触发重建

**POST** `https://api.jamdesk.com/projects/{project_id}/rebuild`

### 请求示例

<CodeGroup>
```bash cURL
curl -X POST "https://api.jamdesk.com/projects/YOUR_PROJECT_ID/rebuild" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript JavaScript
const projectId = "YOUR_PROJECT_ID";
const apiKey = "YOUR_API_KEY";

const response = await fetch(
  `https://api.jamdesk.com/projects/${projectId}/rebuild`,
  {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${apiKey}`
    }
  }
);
const build = await response.json();
console.log(build.buildId, build.status);
```
</CodeGroup>

### 响应

成功的请求返回 `200 OK` 以及构建元数据，您可以用这些数据跟踪进度。

```json
{
  "buildId": "build_8f3k2j",
  "status": "queued",
  "createdAt": "2026-02-05T10:30:00Z",
  "commit": {
    "sha": "a1b2c3d",
    "message": "Update API docs",
    "author": "jane@example.com"
  },
  "project": {
    "id": "proj_abc123",
    "name": "My Docs"
  }
}
```

<Note>
如果收到 `429` 响应，请使用指数退避策略重试。如需更高的限额，请联系支持人员。
</Note>

### 响应字段

<ResponseField name="buildId" type="string">
  唯一构建标识符。使用它可在仪表板中引用该构建。
</ResponseField>

<ResponseField name="status" type="string">
  当前构建状态。可能的值之一：`queued`、`building`、`deployed`、`failed`。
</ResponseField>

<ResponseField name="createdAt" type="string">
  构建创建时间的 ISO 8601 时间戳。
</ResponseField>

<ResponseField name="commit.sha" type="string">
  触发构建的提交的短哈希值。
</ResponseField>

<ResponseField name="commit.message" type="string">
  源代码仓库中的提交信息。
</ResponseField>

<ResponseField name="commit.author" type="string">
  提交作者的电子邮件地址。
</ResponseField>

<ResponseField name="project.id" type="string">
  与您仪表板项目匹配的项目标识符。
</ResponseField>

<ResponseField name="project.name" type="string">
  项目的显示名称。
</ResponseField>

## 跟踪构建状态

构建状态可在仪表板的 **Deployments** 下查看。每次构建都会经历以下阶段：

1. **queued**：构建正在队列中等待。
2. **building**：构建服务正在编译您的文档。
3. **deployed**：构建完成，您的站点已上线。
4. **failed**：出现错误。请查看构建日志了解详情。

如果您的仓库已连接到 GitHub，提交状态检查会自动更新。构建部署完成时，提交上会出现绿色勾号；构建失败时，会出现红色叉号。您无需轮询 API 来获取状态更新。

## 错误响应格式

错误响应遵循统一的结构：

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API key",
    "status": 401
  }
}
```

<ResponseField name="error.code" type="string">
  机器可读的错误代码。可能的值请参见下表。
</ResponseField>

<ResponseField name="error.message" type="string">
  对出错原因的人类可读描述。
</ResponseField>

<ResponseField name="error.status" type="number">
  与响应状态一致的 HTTP 状态码。
</ResponseField>

### 错误代码

| 状态 | 代码 | 消息 | 解决方法 |
|--------|------|---------|-----|
| **401** | `unauthorized` | Invalid API key | 在 **Settings** → **API** 中重新生成密钥 |
| **403** | `forbidden` | Unauthorized project access | 确认项目 ID 与 API 密钥所属的项目一致 |
| **404** | `project_not_found` | Project not found | 在仪表板中核对项目 ID |
| **429** | `rate_limited` | Too many requests | 退避后使用指数退避策略重试 |
| **500** | `internal_error` | Internal server error | 几秒后重试。如问题持续，请联系支持人员 |
