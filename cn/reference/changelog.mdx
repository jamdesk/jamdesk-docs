<Update label="2026 年 8 月" date="2026-08-20">
**Jamdesk 可将文档翻译成 27 种语言。** 在 **Settings → Translations** 中勾选所需语言，每个项目最多五种。每次构建后，翻译页面都会提交到你的 GitHub 仓库。后续构建只会重新翻译英文源文件发生变化的页面。已有或手动编辑过的翻译会一直保留，直到你点击 **Replace with AI translation**。所有方案均包含此功能。[AI 翻译 →](/cn/setup/ai-translation)

**选择自己的文档 URL。** 子路径托管不再绑定到 `/docs`。在 Custom Domain 卡片的子路径字段中输入一个片段，例如 `help` 或 `guide`，然后保存。`/docs` 仍会继续提供服务，规范 URL 会立即切换到新路径；之前的自定义子路径会在一次重命名期间重定向到新路径，因此你可以按自己的节奏更新代理配置。[子路径托管 →](/cn/deploy/subpath-hosting)

**使用 AI 修复，现在速度更快。** 从构建横幅打开修复预览时，完成速度更快，包括大型网站；重新打开也接近即时，因为 Jamdesk 会在文档发生变化前保留扫描结果。流程保持不变：查看每项建议的编辑，应用你批准的修改，Jamdesk 会提交修改并重新构建。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**第四款主题：Halo。** 在 `docs.json` 中设置 `"theme": "halo"`，即可使用温暖圆润的外观：Figtree 字体、沙色背景，以及置于卡片上的内容区域，并拥有所有内置主题中最大的圆角。自定义颜色、字体和 CSS 覆盖方式与 Jam、Nebula 和 Pulsar 相同。[主题设置 →](/cn/customization/theming)

**仅从自己的域名提供文档。** 在 Custom Domain 卡片中启用 **Custom domain only** 后，直接访问 `YOUR_SLUG.jamdesk.app` 会返回 404，而你的 CNAME 或代理仍可正常工作。Jamdesk 会在开关启用前检查你的在线域名；如果 DNS 出现故障，子域名会重新提供服务，直到域名恢复。此功能会隐藏面向直接访问者的子域名，但不会限制谁能阅读文档；如需限制访问，请同时启用密码保护。[仅限自定义域名 →](/cn/deploy/custom-domain-only)

**根据规范构建完整的 API 参考。** 使用 `"openapi": { "source": "/openapi/api.yaml", "generate": true }` 将导航标签指向 OpenAPI 文件，每次构建都会为每个操作创建页面，并按标签在侧边栏中分组。已提交的端点页面会保留其 slug，因此你可以逐页迁移；重命名后的路径会从旧 URL 重定向，而不是返回 404。[生成的 API 页面 →](/cn/config/docs-json-reference#navigation-openapi生成的页面)

**读者可以选择要查看的 API 服务器。** 如果端点的规范列出了多个 `servers` 条目，其 URL 旁边会显示选择器。选择 sandbox 后，基础 URL、复制按钮、每个代码示例以及 playground 发送的请求都会切换，因此读者不会从 sandbox 文档中复制生产环境的 `curl`。单服务器端点保持不变。[API Playground →](/cn/api-reference/playground#多个服务器)

**Markdown 会在每个 OpenAPI 描述中渲染。** 表格、列表、链接、`code` 和 **粗体** 会在参数、请求正文、响应和架构描述中以与操作描述相同的方式渲染。此前有九处渲染方式不一致，现在全部共用一个渲染器。[OpenAPI 示例 →](/cn/api-reference/openapi-example)

**端点 Markdown 导出包含身份验证信息。** 获取 API 参考页面的 `.md` 版本时，末尾会包含 `## Authentication` 部分，列出该操作所需的方案：类型、标头名称、bearer 格式、OAuth 2 作用域，以及哪些组合有效。读取导出的代理无需打开规范即可构建可用请求。[Markdown 源文件 →](/cn/ai/markdown-source#端点页面导出的内容)

**让页面退出搜索，但不隐藏它。** 在页面 frontmatter 中添加 `search: false`，页面就会从站内搜索、AI 聊天回答和 MCP 服务器中移除，同时保留在侧边栏、站点地图和 llms.txt 中。对于仍希望可链接和可索引的旧页面，可以使用此设置。隐藏页面和 noindex 页面也会被排除在 AI 回答之外，而此前不会。[仅让页面退出搜索 →](/cn/content/hidden-pages#仅将页面排除在搜索之外)

**`jamdesk validate` 会警告无效配置。** 某些 `docs.json` 键虽然会被接受，却从未实际渲染，其中最明显的是 `asyncapi`。因此配置看似受支持，直到构建网站后才发现没有任何内容。该命令会列出这些键，也会列出超过第一个的额外 `api.mdx.server` 条目；这些条目一直都会被丢弃。[CLI 概览 →](/cn/cli/overview)

</Update>

**直接在仪表板中编辑文档。** Web 编辑器现已向所有人开放，无需设置。在侧边栏中打开 **Editor**，浏览已连接的仓库，编辑带实时预览的 MDX，并直接提交到 GitHub 分支；提交后会自动启动构建。[Web 编辑器 →](/cn/development/web-editor)

**从仪表板使用 AI 修复构建警告。** 当构建因链接损坏或页面缺少描述而完成时，构建页面上现在会显示 **Fix with AI** 横幅，并说明可以修复的问题数量。打开横幅即可预览每项建议的编辑（重写后的锚点和建议的页面描述），然后应用你批准的修改。Jamdesk 会将修改提交到你的 GitHub 分支并启动新的构建。无法明确解决的问题会单独列出，供你手动修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**无限团队成员。** 现在所有方案的每个项目都包含不限数量的团队成员，且无需额外付费。之前的 10 人上限和按席位计费均已取消——邀请整个团队吧。

**让可信机器人发布文档。** Dependabot、Renovate 或 CMS 发布机器人等自动化账户不是 Jamdesk 成员，因此默认情况下它们的推送不会触发构建。现在，当某个账户被拒绝时，构建页面会显示一个一键式 **Authorize Bot Account** 按钮。批准后，该账户的推送就会发布到线上网站，与团队成员的推送一样。只有项目成员可以授权账户；你可以随时在项目 GitHub 设置中的 **Allowed automation accounts** 下查看或撤销访问权限。

**每次构建都会为文档生成 AI Score。** Jamdesk 现在会在每次构建后自动在仪表板中，根据开放的 AFDocs 标准评估 AI 代理读取已发布文档的效果。你可以查看 0–100 分和字母等级，观察不同构建之间的趋势，并为每个问题获取通俗易懂的修复建议；每条建议都有 **Copy prompt to fix** 按钮，可将问题交给 AI 编程代理。启用 **Email team when score changes** 后，当构建明显改变分数时，你会收到通知。[AI Score →](/cn/ai/ai-score)
</Update>

**自动修复损坏的链接。** 现在可以使用一个命令修复目标明确的内部链接警告，包括拼写错误的锚点和跨语言锚点漂移。运行 `jamdesk fix --dry-run` 预览计划的修改，然后运行 `jamdesk fix` 应用修改；只有正确锚点能解析到真实标题的警告会被处理，存在歧义的情况会留待手动检查。[CLI 概览 →](/cn/cli/overview)

**使用横幅发布任何消息。** 在 `docs.json` 中添加 `banner`，消息栏就会固定在每个页面顶部、页眉上方，并使用主题的强调色。可以使用链接、**粗体** 和 *斜体* 内联内容；设置 `dismissible: true` 后，读者会看到关闭按钮（除非消息发生变化，否则横幅会保持关闭）。[横幅 →](/cn/config/docs-json-reference#横幅)

**显示每个页面的最后更新时间。** 在 `docs.json` 中设置 `metadata.timestamp: true`，每个页面的页脚都会显示类似“Last updated on June 15, 2026”的一行文字。日期来自最后一次修改该页面的 Git 提交，因此每次构建都会保持准确，无需手动维护日期。[页面元数据 →](/cn/config/docs-json-reference#metadata)

**设置导航图标样式。** 侧边栏、分组、标签、锚点和搜索图标现在会遵循图标对象中的 `style`（`{ "name": "rocket", "style": "duotone" }`）或样式前缀（`duotone/rocket`），支持 light、thin、duotone 和 sharp 系列，而不再仅支持 solid。[图标 →](/cn/content/icons#图标对象形式)

**自定义搜索栏。** 使用 `search.prompt` 设置自己的占位文本，并使用 `search.popularPages` 管理访客在空搜索面板中看到的快速链接；每个链接包含标题、页面 slug 和 Font Awesome 图标。[搜索配置 →](/cn/config/docs-json-reference#搜索)

**无需嵌入即可收集电子邮件注册。** 在 **Integrations → Email Signups** 中连接 Resend、Mailchimp、Kit、Loops、beehiiv、Brevo 或 SendGrid，Jamdesk 托管的表单就会将读者直接添加到你的受众列表中——API 密钥会保留在我们的后端，绝不会出现在已发布的网站中。将 [`EmailSubscribe`](/cn/components/email-subscribe) 组件添加到任意页面，或设置 `placement: changelog`，自动在每个更新日志页面上放置注册框。[电子邮件注册 →](/cn/integrations/email-signups)

**在 Cookie 同意后加载分析。** 在 `docs.json` 中添加 `integrations.cookies` 键后，Jamdesk 会暂停所有分析和跟踪脚本——包括 Google Analytics、GTM、Plausible、Crisp、自定义 JavaScript 和内置分析——直到访客同意；同意状态读取自同意横幅设置的 `localStorage` 标志。你也可以直接从 `docs.json` 加载 Osano 或 Termly 横幅；一小段桥接代码会在读者接受时立即切换标志，脚本无需刷新页面即可加载。[Cookie 同意 →](/cn/integrations/cookie-consent)

**结构化的 llms.txt。** 每个网站的 `llms.txt` 现在都遵循 llmstxt.org 结构——导航标签和分组会变成 `##` 部分，让 AI 代理按照侧边栏的组织方式查看文档。多语言网站每种语言都有一个索引：根文件列出默认语言，并链接到每个翻译索引（例如 `/fr/llms.txt`），使每个文件足够小，避免被代理截断。[llms.txt →](/cn/ai/llms-txt)

**让代理更快找到文档。** 每个页面现在都带有不可见且对屏幕阅读器静默的指令，将 AI 代理指向 `llms.txt` 和页面的 `.md` 版本；每个 Markdown 导出文件开头也会包含一个链接到索引的引用块。获取 HTML 的代理无需再猜测 Markdown 路径是否存在。[AI 概览 →](/cn/ai/overview)

**在任何地方嵌入更新日志。** 只需一个 `<script>` 标签，就能将“What's new?”启动器添加到自己的应用中，并在模态框中打开 Jamdesk 更新日志，同时显示每位访客的未读标记。从 **Integrations → What's New widget** 生成代码片段，然后使用 `data-` 属性调整启动器模式、角落位置、模态框大小和标记颜色。在自己的 Jamdesk 文档中，[`<Widget>`](/cn/components/widget) MDX 组件只需一个标签即可将相同的实时启动器添加到任意页面，无需脚本。[嵌入更新日志 →](/cn/development/embed-page)

**将 API 规范下载为 zip。** 在任意 API 参考页面上，AI Actions 菜单现在包含 **Download API spec** 选项，可将网站引用的所有 OpenAPI 规范——包括本地文件和远程 URL——打包到单个 `api-specs.zip` 中。多文件规范会保留其 `$ref` 文件夹结构，因此下载内容可以直接用于 Postman、客户端生成器或你自己的工具。[AI Actions →](/cn/ai/ai-actions)

**在构建时验证 OpenAPI 规范。** 每次部署都会严格验证 `docs.json` 引用的 OpenAPI 规范，并将所有问题显示为**非致命构建警告**，而不是使构建失败。文档仍会发布；你只会通过电子邮件和仪表板构建列表获知具体问题，例如 YAML 解析错误及其行列号、无法解析的 `$ref` 或重复的 `operationId`。在本地，`jamdesk dev` 仍会在规范无效时停止，以便你在推送前发现问题。[CLI 概览 →](/cn/cli/overview)
</Update>

**直接从搜索中询问 AI。** 开始输入搜索内容，然后将问题交给 AI 聊天，而不是打开搜索结果——按 ⌘/Ctrl+Enter，或点击搜索页脚中的 **Ask AI**。问题会追加到聊天会话中，方便你继续对话；普通 Enter 仍会跳转到第一个结果。[AI 聊天 →](/cn/ai/chat)

**复制回答和聊天记录。** 每条 AI 聊天回答都有复制按钮，可获取 Markdown 源代码；聊天标题栏中的 **Copy transcript** 操作可以将整个对话复制为带角色标签的 Markdown，方便粘贴到 issue 或文档中。[AI 聊天 →](/cn/ai/chat)

**更智能的聊天自动滚动。** 只有当你已经位于底部时，聊天才会跟随流式回答。向上滚动重新阅读之前的回复时，页面会保持当前位置，不会将你拉回底部；滚回底部后，它会重新固定在那里。

**本地预览中的自定义 CSS（CLI）。** `jamdesk dev` 会像已发布的构建一样应用自定义 CSS，因此你可以在部署前检查样式。将任意 `.css` 文件放入项目根目录——例如 `style.css`，也可以放入多个文件，系统会按字母顺序合并——浏览器刷新时即可加载。无需在 `docs.json` 中添加条目，这与 Mintlify 引入根目录样式表的方式一致。[自定义 CSS →](/cn/customization/custom-css)

**从 frontmatter 自定义社交预览。** 可以直接在页面 frontmatter 中设置任意 Open Graph 或 Twitter/X 元标签，包括 `og:title`、`og:description`、`og:image`、`twitter:card`、`keywords` 以及完整的 metatag 集合。可以使用顶层扁平键，也可以使用嵌套的 `seo:` 区块；两种方式都有效，页面级值会覆盖 `docs.json` 中的默认值。[SEO →](/cn/content/seo)

**隐藏页面。** 无需删除草稿、内部手册或弃用指南，即可将它们从侧边栏和搜索结果中移除。在页面 frontmatter 中添加 `hidden: true`，或在 `docs.json` 的分组或标签中添加。隐藏页面仍可通过直接 URL 访问，但会从导航、站点地图、站内搜索和 AI 上下文中消失，并自动添加 `noindex` 标签。如果希望隐藏分组中的页面仍出现在搜索排名中，请同时添加 `searchable: true`。[隐藏页面 →](/cn/content/hidden-pages)

**网格和窗口装饰。** 两种新的背景图案加入了 Jam 主题的默认渐变。将 `background.decoration` 设置为 `"grid"`，使用细微的 24px 点阵网格；或设置为 `"windows"`，在上方两个角落显示 Windows 11 风格的磨砂光斑。渐变和 `"none"` 平面填充仍可照常使用，选择适合品牌的外观即可。[背景 →](/cn/customization/background)

**背景自定义。** `docs.json` 中新增的 `background` 区块可以停用 Jam 浅色模式渐变，按模式覆盖页面颜色，或调整渐变的颜色、大小、位置和不透明度。无需自定义 CSS。[背景 →](/cn/customization/background)

**D2 图表。** Mermaid 之外新增第二种图表语言。将围栏代码块标记为 `d2`，Jamdesk 就会在构建时将其渲染为 SVG，并内置浅色和深色主题。工作流程与 Mermaid 相同，选择最适合你所绘制图表的语言即可。[D2 图表 →](/cn/components/d2)

**分组搜索结果。** 搜索不再因为同一页面匹配多个部分而重复显示该页面。搜索命中会在搜索模态框中归入其父页面，默认显示最多三个部分，其余部分可通过内联展开器查看。摘要高亮保持不变，让你用更少的扫描次数找到正确部分。

**连接时自动检测 `docs.json`。** 连接 GitHub 仓库时，无论 `docs.json` 位于何处都能被找到。连接流程会扫描整个目录树；如果发现 Mintlify 的 `mint.json`，也会将其标记出来。Monorepo 和嵌套配置无需手动设置即可使用。[连接 GitHub →](/cn/setup/connecting-github)

**CLI 中的 `docs.json` 位置提示。** 错误放置的配置现在更容易发现。`jamdesk validate`、`jamdesk dev` 和 `jamdesk doctor` 会报告 `docs.json` 实际所在的位置，或它应该放置的位置，而不是显示笼统的“未找到”错误。无需解读堆栈跟踪，几秒即可修复。[CLI 概览 →](/cn/cli/overview)

**符合标准的 hreflang。** hreflang 标签现在会生成有效的 BCP 47 代码。`cn`、`jp` 和 `ja-jp` 等区域文件夹会映射到搜索引擎实际期望的代码（`zh`、`ja`），站点地图 URL 也会进行 XML 转义。每个本地化页面都会在自己的区域获得排名，而不会被视为重复内容。[语言 →](/cn/setup/languages)
</Update>

**PDF 导出。** 在仪表板的 **Settings → PDF Exports** 中，将整个文档网站渲染为单个 [PDF](/cn/builds/pdf-export)。仅限付费方案。多语言项目可以为每次导出选择语言区域；结果会按提交缓存，渲染完成后你会收到包含下载链接的电子邮件。

**多语言 OpenAPI 规范。** 端点页面会在翻译后的 MDX 旁渲染翻译后的 OpenAPI 规范。在源规范旁放置一个 `<spec>.<lang>.<ext>` 文件（例如 `openapi/api.fr.yaml`），Jamdesk 会在该语言的 URL 上使用它；如果缺少语言版本，则回退到英文规范。操作摘要、参数描述、响应描述和架构描述都会进行本地化。设置方式：[翻译 OpenAPI 规范](/cn/setup/languages#翻译-openapi-规范)。

**Visibility 组件。** 新的 [`<Visibility for="humans|agents">`](/cn/components/visibility) 组件允许你在同一页面上分别为人类读者或 AI 代理划分内容。仅供人类查看的区块会在浏览器中渲染，但会从 `.md` 导出和 `llms-full.txt` 中移除；仅供代理查看的区块则相反。代理在规范 URL 上请求 `Accept: text/markdown` 时，会自动获得代理视图。

**重新构建的密码保护。** 可以使用共享密码锁定整个网站，或只保护部分页面而让其余页面保持公开。将 `auth.password.enabled: true` 设置为全站模式，或在页面 frontmatter 中标记 `private: true`（也可以将页面列在 `auth.password.private` 下）以使用指定页面模式。仪表板中的 Settings 页面会引导你设置、轮换和撤销密码。访客会看到带有网站徽标、主色和可选提示的品牌解锁页面。设置指南：[密码保护](/cn/setup/password-protection)。

**自动转换 WebP 图片。** Jamdesk 可以在构建时将 PNG 和 JPG 图片转换为 WebP。转换后的文件通常比原文件小 60–80%，且没有明显的质量损失，因此无需手动处理图片即可加快页面加载。通过 `docs.json` 中的 `images.convertToWebp: true` 启用。Favicons、`og:image` 和 `twitter:image` 会保留原始格式，以兼容社交爬虫。新的 **Optimizing images** 步骤会在每次构建期间于仪表板和 CLI 中显示实时进度。[自动图片转换 →](/cn/builds/image-optimization)

**API Playground。** 端点页面现在提供交互式的[“Try it”按钮](/cn/api-reference/playground)。填写参数，实时查看代码示例更新，并且无需离开文档即可发送实时请求。所有 API 页面默认启用。OpenAPI 和使用 MDX 编写的端点均可使用。

**Claude Code 插件。** 安装 [Jamdesk 的 Claude Code 插件](/cn/claude-code-plugin)，让 Claude 深入了解 MDX 组件、`docs.json` 配置、导航模式和 CLI 命令。插件市场提供两步安装流程。该插件可与 [CLAUDE.md](/cn/ai/claude-code) 及 [MCP 服务器](/cn/ai/mcp-server) 搭配使用，辅助编写文档。

**缺少品牌资源的构建警告。** 如果 `docs.json` 中的 `favicon` 或 `logo` 路径引用了项目中不存在的文件，构建现在会发出警告。警告会显示在仪表板构建详情中，也会通过 `jamdesk dev` 和 `jamdesk validate` 显示在 CLI 中。不发送电子邮件；该警告仅供提示。

**YouTube Shorts。** [`<YouTube>` 组件](/cn/content/youtube#youtube-shorts) 通过 `short` 属性支持竖屏 Shorts，渲染居中的 9:16 播放器且不显示黑边。使用 `<YouTube id="VIDEO_ID" short />`。
</Update>
