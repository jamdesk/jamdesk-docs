<Update label="2026 年 8 月" date="2026-08-20">
**从规范构建完整 API 参考。** 使用 `"openapi": { "source": "/openapi/api.yaml", "generate": true }` 将导航标签指向 OpenAPI 文件，Jamdesk 会在每次构建时为每个操作创建页面，并按标签归类到侧边栏中。无需编写内容，也无需提交代码。你已编写的端点页面会优先使用其 slug，因此可以一次切换一个页面；当你在规范中重命名路径时，旧 URL 会重定向到新 URL，而不会返回 404。[生成的 API 页面 →](/cn/config/docs-json-reference#navigation-openapi生成的页面)

**读者可以选择要查看的 API 服务器。** 如果端点的规范列出了多个 `servers` 条目，现在会在 URL 旁显示选择器。选择 sandbox 后，基础 URL、复制按钮、每个代码示例以及 playground 发送的请求都会切换，因此不会有人从 sandbox 文档中复制生产环境的 `curl`。单服务器端点保持不变。[API Playground →](/cn/api-reference/playground#多个服务器)

**每个 OpenAPI 描述都支持 Markdown 渲染。** 表格、列表、链接、`code` 和 **粗体** 现在会在参数、请求正文、响应和架构描述中以与操作描述相同的方式渲染。过去有九处渲染方式不一致，现在它们全部使用同一个渲染器。[OpenAPI 示例 →](/cn/api-reference/openapi-example)

**端点 Markdown 导出现在包含身份验证信息。** 获取 API 参考页面的 `.md` 版本后，文件末尾现在会包含 `## Authentication` 部分，其中列出操作所需的方案，包括类型、标头名称、bearer 格式、OAuth 2 作用域，以及哪些组合有效。读取导出的代理无需打开规范即可构建可用的请求。[Markdown 源码 →](/cn/ai/markdown-source#端点页面导出的内容)

**让页面不出现在搜索结果中，但无需隐藏页面。** 在页面 frontmatter 中添加 `search: false`，即可将页面从站内搜索、AI 聊天回答和 MCP 服务器中移除，同时保留在侧边栏、站点地图和 llms.txt 中。这适合仍希望访客能够链接和访问的已替代页面。隐藏页面和 noindex 页面现在也会被排除在 AI 回答之外，而此前并非如此。[仅将页面排除在搜索之外 →](/cn/content/hidden-pages#仅将页面从搜索中排除)

**`jamdesk validate` 会警告无效配置。** 某些 `docs.json` 键虽然会被接受，但从未实际渲染，其中最典型的是 `asyncapi`；因此配置看起来受支持，直到构建网站后才发现没有任何内容。现在，validate 会列出这些键，还会指出第一个 `api.mdx.server` 条目之后的额外条目，因为这些条目一直都会被丢弃。[CLI 概览 →](/cn/cli/overview)

**你的文档自动支持 27 种语言。** 在 **Settings → Translations** 中启用所需语言后，Jamdesk 会在每次构建后翻译文档，并将结果直接提交到你的 GitHub 仓库。你可以从 27 种语言中选择最多五种。首次运行后，只有英文源文件发生变化的页面才会重新翻译。已有翻译会被采用而不是覆盖；你手动编辑过的页面之后会保持不变。Jamdesk 会在仪表板中标记这些页面，并且只有在你要求时才提供替换选项。所有套餐均包含此功能，无需按字计费，也无需购买额度。[AI 翻译 →](/cn/setup/ai-translation)

**选择自定义文档 URL。** 子路径托管不再将你限制在 `/docs`：现在可以从仪表板的 Custom Domain 卡片中选择任意单段路径（如 `/help`、`/guide`，或任何适合你网站的路径）。重命名过程安全可靠：`/docs` 本身不会停止服务，规范 URL 会立即切换到新子路径，之前的自定义子路径也会在一次重命名期间转发到新路径，因此已被索引或使用的链接不会失效。准备好后，更新代理中的 `/docs` 引用即可。[子路径托管 →](/cn/deploy/subpath-hosting)

**使用 AI 修复问题，现在速度更快。** 扫描完成得更快、更可靠，包括大型文档网站；重新打开修复预览也几乎即时完成，因为 Jamdesk 会缓存扫描结果，并在文档发生变化前重复使用这些结果。几秒内即可从构建警告完成修复提交。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**第四个主题：Halo。** 在 `docs.json` 中设置 `"theme": "halo"`，即可使用温暖、柔和圆润的外观。这是第四个内置主题，具有沙色背景、焦糖色强调色、Figtree 字体，以及比其他三个主题更加圆润的边角。[主题设置 →](/cn/customization/theming)

**仅通过自有域名提供文档。** 在项目的自定义域名设置中启用 **Custom domain only** 后，`YOUR_SLUG.jamdesk.app` 将不再直接响应；你的文档只能通过自有域名访问。开关启用前，会针对线上域名运行预检检查，因此配置错误的代理不会意外阻断读者访问；如果 DNS 出现故障，子域名会重新开始提供服务，而不是让文档离线。纯 CNAME 域名无需任何配置；已经发送 `X-Jamdesk-Forwarded-Host` 的代理也无需配置；Vercel `rewrites` 用户只需为每个目标添加 `?jd_proxy=1`。此功能会让搜索引擎和普通访客看不到你的 Jamdesk 地址，但它不是密码；如果你想控制谁可以阅读文档，请同时启用密码保护。[仅自定义域名 →](/cn/deploy/custom-domain-only)

</Update>

**直接在仪表板中编辑文档。** Web 编辑器现已向所有用户开放，无需设置。打开侧边栏中的 **Editor**，浏览已连接的仓库，编辑 MDX 并实时预览，然后直接提交到 GitHub 分支，从而自动触发构建。[Web 编辑器 →](/cn/development/web-editor)

**在仪表板中使用 AI 修复构建警告。** 当构建因链接损坏或页面缺少描述而完成时，构建页面现在会显示 **Fix with AI** 横幅，并标明可以修复的问题数量。打开横幅即可预览每项建议的编辑内容（重写的锚点和建议的页面描述），然后应用你批准的修改。Jamdesk 会将修改提交到你的 GitHub 分支并启动新的构建。无法明确解决的问题会单独列出，供你手动修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**团队成员数量不受限。** 现在每个项目的所有套餐都包含不限数量的团队成员，无需额外付费。此前的 10 人上限和按席位计费均已取消，可以邀请整个团队。

**让受信任的机器人发布文档。** Dependabot、Renovate 或 CMS 发布机器人等自动化账户不是 Jamdesk 成员，因此默认情况下它们的推送不会触发构建。现在，当某个账户被拒绝时，构建页面会显示一个一键式 **Authorize Bot Account** 按钮。批准后，该账户的推送即可发布到线上网站，就像团队成员的推送一样。只有项目成员可以授权账户；你可以随时在项目 GitHub 设置中的 **Allowed automation accounts** 下查看或撤销访问权限。

**每次构建都会为文档生成 AI Score。** Jamdesk 现在会根据开放的 AFDocs 标准，自动在每次构建后评估 AI 代理读取已发布文档的效果，并直接在仪表板中显示结果。你可以查看 0–100 分和字母等级，观察各次构建的趋势，并为每个问题获取易懂的修复建议；每项建议都有 **Copy prompt to fix** 按钮，可将问题交给 AI 编码代理处理。启用 **Email team when score changes** 后，当构建导致分数出现明显变化时，你会收到通知。[AI Score →](/cn/ai/ai-score)
</Update>

**自动修复损坏的链接。** 对于目标明确的损坏内部链接警告（例如拼写错误的锚点和跨语言锚点偏移），现在可以使用一个命令修复。运行 `jamdesk fix --dry-run` 预览计划中的修改，然后运行 `jamdesk fix` 应用修改；只有能够解析到真实标题的正确锚点才会被修改，有歧义的情况会留待手动审核。[CLI 概览 →](/cn/cli/overview)

**使用横幅发布任何通知。** 在 `docs.json` 中添加 `banner`，即可在每个页面顶部固定显示消息栏，位置在页眉上方，并使用主题的强调色。支持使用链接、**粗体** 和 *斜体*，还可以设置 `dismissible: true`，为读者提供关闭按钮（除非你更改消息，否则它会保持关闭状态）。[横幅 →](/cn/config/docs-json-reference#横幅)

**显示每个页面的最后更新时间。** 在 `docs.json` 中设置 `metadata.timestamp: true`，每个页面的页脚都会显示类似“Last updated on June 15, 2026”的内容。日期来自最后一次修改该页面的 Git 提交，因此每次构建都会保持准确，无需手动维护日期。[页面元数据 →](/cn/config/docs-json-reference#metadata)

**自定义导航图标样式。** 侧边栏、分组、标签、锚点和搜索图标现在支持图标对象中的 `style`（`{ "name": "rocket", "style": "duotone" }`）或样式前缀（`duotone/rocket`），可使用 light、thin、duotone 和 sharp 系列，而不再仅限于 solid。[图标 →](/cn/content/icons#图标对象形式)

**自定义搜索栏。** 使用 `search.prompt` 设置自己的占位文本，并通过 `search.popularPages` 管理访客在空搜索面板中看到的快速链接；每个链接包含标题、页面 slug 和 Font Awesome 图标。[搜索配置 →](/cn/config/docs-json-reference#搜索)

**无需嵌入即可收集邮箱注册。** 在 **Integrations → Email Signups** 中连接 Resend、Mailchimp、Kit、Loops、beehiiv、Brevo 或 SendGrid，Jamdesk 托管的表单即可将读者直接添加到你自己的受众列表中；API 密钥会保留在我们的后端，绝不会出现在已发布的网站中。将 [`EmailSubscribe`](/cn/components/email-subscribe) 组件添加到任意页面，或设置 `placement: changelog`，即可自动在每个更新日志页面显示注册框。[邮箱注册 →](/cn/integrations/email-signups)

**在 Cookie 同意之后加载分析功能。** 在 `docs.json` 中添加 `integrations.cookies` 键后，Jamdesk 会暂停所有分析和跟踪脚本，包括 Google Analytics、GTM、Plausible、Crisp、自定义 JavaScript 以及内置分析功能，直到访客同意；同意状态读取自同意横幅设置的 `localStorage` 标志。你也可以直接从 `docs.json` 加载 Osano 或 Termly 横幅；简短的桥接代码片段会在读者接受时立即切换标志，脚本无需重新加载页面即可加载。[Cookie 同意 →](/cn/integrations/cookie-consent)

**结构化的 llms.txt。** 现在每个网站的 `llms.txt` 都遵循 llmstxt.org 结构：导航标签和分组会转换为 `##` 部分，让 AI 代理按照侧边栏的组织方式查看文档。多语言网站会为每种语言生成一个索引：根文件列出默认语言，并链接到各个翻译索引（例如 `/fr/llms.txt`），使每个索引足够小，不会被任何代理截断。[llms.txt →](/cn/ai/llms-txt)

**让代理更快找到文档。** 每个页面现在都包含一条不可见且对屏幕阅读器静默的指令，将 AI 代理指向 `llms.txt` 和页面的 `.md` 版本；每个 Markdown 导出文件开头也会包含指向索引的引用块。获取 HTML 的代理不再需要猜测 Markdown 路径是否存在。[AI 概览 →](/cn/ai/overview)

**在任何位置嵌入更新日志。** 只需一个 `<script>` 标签，即可将“What's new?”启动器添加到自己的应用中；它会在模态框中打开 Jamdesk 更新日志，并为每位访客显示未读圆点。从 **Integrations → What's New widget** 生成代码片段，然后使用 `data-` 属性调整启动器模式、角落位置、模态框大小和圆点颜色。在自己的 Jamdesk 文档中， [`<Widget>`](/cn/components/widget) MDX 组件只需一个标签，即可将相同的实时启动器添加到任意页面，无需脚本。[嵌入更新日志 →](/cn/development/embed-page)

**将 API 规范下载为 zip。** 在任意 API 参考页面中，AI Actions 菜单现在提供 **Download API spec** 选项，可将网站引用的所有 OpenAPI 规范（包括本地文件和远程 URL）打包为单个 `api-specs.zip`。多文件规范会保留其 `$ref` 文件夹结构，因此下载内容可以直接用于 Postman、客户端生成器或你自己的工具。[AI 操作 →](/cn/ai/ai-actions)

**在构建时验证 OpenAPI 规范。** 每次部署都会严格验证 `docs.json` 引用的 OpenAPI 规范，并将任何问题显示为 **非致命构建警告**，而不会使构建失败。文档仍会发布，但你会通过电子邮件和仪表板的构建列表准确获知问题所在，例如 YAML 解析错误的行列信息、无法解析的 `$ref` 或重复的 `operationId`。在本地，`jamdesk dev` 仍会在规范无效时停止，以便你在推送前发现问题。[CLI 概览 →](/cn/cli/overview)
</Update>

**直接从搜索中询问 AI。** 开始在搜索框中输入内容，然后将问题交给 AI 聊天，而不是打开搜索结果；按 ⌘/Ctrl+Enter，或点击搜索页脚中的 **Ask AI**。问题会追加到聊天对话中，方便继续交流；直接按 Enter 仍会跳转到第一个结果。[AI 聊天 →](/cn/ai/chat)

**复制回答和聊天记录。** 每条 AI 聊天回答都有复制按钮，可获取 Markdown 源码；聊天标题栏中的 **Copy transcript** 操作则会将整个对话以带角色标记的 Markdown 形式复制，方便粘贴到问题或文档中。[AI 聊天 →](/cn/ai/chat)

**更智能的聊天自动滚动。** 只有当你已经位于底部时，聊天才会跟随流式回答。向上滚动重新阅读早前的回复时，页面会保持当前位置，不会强行将你拉到底部；滚回底部后，它会重新固定在底部。

**本地预览支持自定义 CSS（CLI）。** `jamdesk dev` 现在会像已发布的构建一样应用自定义 CSS，因此你可以在部署前检查样式。将任意 `.css` 文件放入项目根目录（例如 `style.css`，也可以按字母顺序组合多个文件），浏览器刷新时就会加载。无需在 `docs.json` 中添加条目，这与 Mintlify 包含根目录样式表的方式一致。[自定义 CSS →](/cn/customization/custom-css)

**通过 frontmatter 自定义社交预览。** 可以直接在页面 frontmatter 中设置任意 Open Graph 或 Twitter/X 元标签，包括 `og:title`、`og:description`、`og:image`、`twitter:card`、`keywords` 以及完整的 metatag 集合。你可以使用顶层扁平键，也可以使用嵌套的 `seo:` 块；两者都有效，页面级值会覆盖 `docs.json` 中的默认值。[SEO →](/cn/content/seo)

**隐藏页面。** 无需删除草稿、内部手册或已弃用指南，即可将它们从侧边栏和搜索结果中移除。在页面 frontmatter 中添加 `hidden: true`，或在 `docs.json` 的分组或标签中添加该设置。隐藏页面仍可通过直接 URL 访问，但会从导航、站点地图、站内搜索和 AI 上下文中消失，并自动添加 `noindex` 标签。如果需要隐藏分组，但仍希望其中的页面出现在搜索排名中，请同时添加 `searchable: true`。[隐藏页面 →](/cn/content/hidden-pages)

**网格和窗口装饰。** 两种新的背景图案加入了 Jam 主题默认的渐变背景。将 `background.decoration` 设置为 `"grid"`，即可使用细微的 24px 点阵网格；设置为 `"windows"`，则会在上方两个角落显示 Windows 11 风格的磨砂光斑。渐变和 `"none"` 平面填充仍按之前的方式工作，可选择适合品牌的外观。[背景 →](/cn/customization/background)

**背景自定义。** `docs.json` 中新增的 `background` 块可以禁用 Jam 浅色模式渐变、按模式覆盖页面颜色，或调整渐变的颜色、大小、位置和不透明度。无需自定义 CSS。[背景 →](/cn/customization/background)

**D2 图表。** Mermaid 之外现在加入第二种图表语言。将围栏代码块标记为 `d2`，Jamdesk 就会在构建时将其渲染为 SVG，并内置浅色和深色主题。工作流程与 Mermaid 相同，可根据要绘制的图表选择合适的语言。[D2 图表 →](/cn/components/d2)

**分组搜索结果。** 搜索结果不再因为同一页面匹配多个部分而重复显示该页面。匹配项会在搜索模态框中归入父页面下，默认显示最多三个部分，其余部分可通过内嵌展开器查看。摘要高亮会保持不变，让你用更少的浏览次数找到正确部分。

**连接时自动检测 `docs.json`。** 连接 GitHub 仓库时，无论 `docs.json` 位于何处都能被找到。连接流程会扫描整个目录树；如果发现 Mintlify 的 `mint.json`，也会将其标记出来。单仓库和嵌套配置无需手动设置即可工作。[连接 GitHub →](/cn/setup/connecting-github)

**CLI 中的 `docs.json` 位置提示。** 现在更容易发现配置文件位置错误。`jamdesk validate`、`jamdesk dev` 和 `jamdesk doctor` 会报告实际的 `docs.json` 位置，或指出它应当位于何处，而不是只显示笼统的“未找到”错误。几秒内即可修复，无需解读堆栈跟踪。[CLI 概览 →](/cn/cli/overview)

**符合标准的 hreflang。** hreflang 标签现在会输出有效的 BCP 47 代码。`cn`、`jp` 和 `ja-jp` 等区域文件夹会映射到搜索引擎实际要求的代码（`zh`、`ja`），站点地图 URL 也会进行 XML 转义。每个本地化页面都会在对应地区独立排名，而不会被视为重复内容。[语言 →](/cn/setup/languages)
</Update>

**PDF 导出。** 从仪表板的 **Settings → PDF Exports** 将整个文档网站渲染为单个 [PDF](/cn/builds/pdf-export)。仅限付费套餐。多语言项目可以为每次导出选择语言环境，结果会按提交缓存；渲染完成后，你会收到包含下载链接的电子邮件。

**多语言 OpenAPI 规范。** 端点页面现在会在翻译后的 MDX 旁渲染翻译后的 OpenAPI 规范。在源规范旁放置 `<spec>.<lang>.<ext>` 文件（例如 `openapi/api.fr.yaml`），Jamdesk 就会在相应语言的 URL 中使用它；如果缺少某语言版本，则回退到英文规范。操作摘要、参数描述、响应描述和架构描述都会本地化。设置方法：[翻译 OpenAPI 规范](/cn/setup/languages#翻译-openapi-规范)。

**Visibility 组件。** 新的 [`<Visibility for="humans|agents">`](/cn/components/visibility) 组件可以在同一页面中分别为人类读者或 AI 代理划分内容。仅面向人类的区块会在浏览器中渲染，但会从 `.md` 导出和 `llms-full.txt` 中移除；仅面向代理的区块则相反。代理在规范 URL 上请求 `Accept: text/markdown` 时，会自动获取代理视图。

**重新设计的密码保护。** 可以使用共享密码锁定整个网站，也可以只保护少数页面而让其余页面保持公开。将 `auth.password.enabled: true` 设置为全站模式；对于特定页面模式，可在页面 frontmatter 中标记 `private: true`，或将页面列在 `auth.password.private` 下。仪表板中的 Settings 页面会引导你设置、轮换和撤销密码。访客会看到带品牌样式的解锁页面，其中包含网站 logo、主色和你在 `docs.json` 中定义的可选提示。设置指南：[密码保护](/cn/setup/password-protection)。

**自动转换 WebP 图片。** Jamdesk 可以在构建时将 PNG 和 JPG 图片转换为 WebP。转换后的文件通常比原文件小 60–80%，且不会出现明显的质量损失，因此页面加载速度更快，无需手动处理图片。通过 `docs.json` 中的 `images.convertToWebp: true` 启用。为保证社交爬虫兼容性，favicon、`og:image` 和 `twitter:image` 会保留原格式。新的 **Optimizing images** 步骤会在每次构建期间于仪表板和 CLI 中显示实时进度。[自动图片转换 →](/cn/builds/image-optimization)

**API Playground。** 端点页面现在提供交互式 [“Try it”按钮](/cn/api-reference/playground)。填写参数，实时查看代码示例更新，并且无需离开文档即可发送实时请求。所有 API 页面默认启用。OpenAPI 编写的端点和 MDX 编写的端点均支持。

**Claude Code 插件。** 安装 [Claude Code 的 Jamdesk 插件](/cn/claude-code-plugin)，让 Claude 深入了解 MDX 组件、`docs.json` 配置、导航模式和 CLI 命令。通过插件市场分两步安装。该插件可与 [CLAUDE.md](/cn/ai/claude-code) 和 [MCP 服务器](/cn/ai/mcp-server) 配合，用于 AI 辅助编写文档。

**缺少品牌资源的构建警告。** 如果 `docs.json` 中的 `favicon` 或 `logo` 路径引用了项目中不存在的文件，构建现在会发出警告。警告会显示在仪表板的构建详情中，也会通过 `jamdesk dev` 和 `jamdesk validate` 显示在 CLI 中。不发送电子邮件；该警告仅供参考。

**YouTube Shorts。** [`<YouTube>` 组件](/cn/content/youtube#youtube-shorts) 现在通过 `short` 属性支持竖屏 Shorts，渲染出居中的 9:16 播放器且没有黑边。使用 `<YouTube id="VIDEO_ID" short />`。
</Update>

**AI Actions 菜单。** [每个页面上的下拉菜单](/cn/ai/ai-actions)允许读者复制 Markdown，在 ChatGPT、Claude 或 Perplexity 中打开页面，获取 MCP 服务器配置，或一键安装到 Cursor 或 VS Code 中。该功能默认启用；可以通过 `docs.json` 中的 `contextual` 选择显示哪些选项。

**分析。** 无需 Cookie 的页面分析功能，可通过[逐页明细](/cn/setup/project-analytics)跟踪浏览量、流量来源和访客趋势。无需同意横幅。概览：[分析](/cn/setup/analytics-overview)。

**集成。** [Google Analytics 4](/cn/integrations/google-analytics)、[Google Tag Manager](/cn/integrations/google-tag-manager)、[Plausible Analytics](/cn/integrations/plausible-analytics) 以及 [Slack 构建通知](/cn/integrations/slack)（Pro）。

**更新日志 RSS Feed。** frontmatter 中设置 `rss: true` 的页面现在会自动生成可订阅的 RSS feed。页面标题旁会显示 RSS 图标；每次构建时，系统会根据你的 [Update](/cn/components/update#rss-feed) 组件生成 `feed.xml`。在 Update 上使用新的 `date` 属性以提供正确的 feed 日期。

**CLI 登录与部署。** [`jamdesk login`](/cn/cli/authentication) 通过浏览器完成身份验证。[`jamdesk deploy`](/cn/cli/deploy) 会打包项目，并从终端触发构建。无需连接 GitHub。CLI 遵循 `.gitignore`，会警告包含机密信息的文件，并在终端内流式显示构建进度。

**CLI 拼写检查。** `jamdesk spellcheck` 使用 180 多个内置技术术语检查文档中的拼写错误（仅支持英文）。`jamdesk spellcheck --fix` 会启动交互模式，用于修复拼写错误或将词语添加到忽略列表。

**视频嵌入。** 可以直接在文档中嵌入 `.mp4` 和 `.webm` 文件。将文件放入 `/videos` 目录，然后使用 Markdown 语法（`![Demo](/videos/demo.mp4)`）或 [`<Video>` 组件](/cn/content/videos)实现自动播放、循环播放和其他控制功能。

**自定义 JavaScript。** 通过 `docs.json` 中的 `styling.js` 添加[客户端脚本](/cn/customization/custom-javascript)，用于聊天小组件、分析功能或第三方集成。

**AI 集成。** 每个网站都会生成供 LLM 上下文窗口使用的 [`llms.txt`](/cn/ai/llms-txt)，通过 [`.md` URL](/cn/ai/markdown-source)提供原始 Markdown，并在 `/_mcp` 提供包含 `searchDocs` 和 `getPage` 工具的 [MCP 服务器](/cn/ai/mcp-server)。同时提供 [Claude Code](/cn/ai/claude-code)、[Cursor](/cn/ai/cursor) 和 [Codex](/cn/ai/codex) 的设置指南，以及：[使用 AI 编写](/cn/ai/writing-with-ai)和[自动更新](/cn/ai/automated-updates)。

**自定义域名 TXT 验证。** 所有自定义域名现在都必须先设置 TXT 记录（`_jamdesk.yourdomain.com`），路由才会激活。这可以防止未声明子域名上的域名劫持。新添加的域名会在仪表板设置流程中显示 TXT 记录。请参阅[自定义域名指南](/cn/deploy/custom-domains)。

**多语言支持。** 为每个语言环境定义[独立的导航树和内容目录](/cn/setup/languages)。读者可以从顶部栏的下拉菜单切换语言。

**搜索分析。** 查看[读者搜索的内容](/cn/setup/search-analytics)、哪些查询没有返回结果，以及哪些结果实际被点击。这有助于发现内容缺口。

**[帮助中心](/cn/help/overview)。** 提供账户管理、账单和故障排除指南。
