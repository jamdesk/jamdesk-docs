<Update label="August 2026" date="2026-08-01">
**您的文档，自动支持 27 种语言。** 在 **Settings → Translations** 中开启所需语言，Jamdesk 会在每次构建后翻译您的文档，然后直接将结果提交到您的 GitHub 仓库。从 27 种语言中最多选择五种；首次运行后，只有英文源文件发生变化的页面才会重新翻译。已有翻译会被采用而不是覆盖，您手动编辑过的页面之后也会保持不变——Jamdesk 会在仪表板中标记这些页面，只有在您要求时才提供替换选项。所有计划均包含此功能，不按字计费，也无需购买积分。[AI 翻译 →](/cn/setup/ai-translation)

**选择您自己的文档 URL。** 子路径托管不再将您锁定在 `/docs`：现在可以从仪表板的 Custom Domain 卡片中选择任意单段路径（`/help`、`/guide`，或任何适合您网站的路径）。重命名过程安全无忧：`/docs` 本身始终继续提供服务，规范 URL 会立即迁移到新的子路径，之前的自定义子路径也会在一次重命名期间转发到新路径，因此已经被索引或引用的内容不会失效。准备好后，更新代理中的 `/docs` 引用即可。[子路径托管 →](/cn/deploy/subpath-hosting)

**使用 AI 修复，现在更快。** 扫描完成得更快、更可靠——大型文档网站也不例外——重新打开修复预览几乎可以即时完成，因为 Jamdesk 会缓存扫描结果，并在文档发生变化前重复使用这些结果。几秒内即可从构建警告转到已提交的修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**第四个主题：Halo。** 在 `docs.json` 中设置 `"theme": "halo"`，即可使用温暖、柔和圆润的外观。这是第四个精美的内置主题，采用沙色背景、焦糖色强调色、Figtree 字体，圆角程度远超其他三个主题。[主题 →](/cn/customization/theming)

**仅从您自己的域名提供文档。** 在项目的自定义域名设置中开启 **Custom domain only** 后，`YOUR_SLUG.jamdesk.app` 将不再直接响应——您的文档只能通过您的域名访问。切换开关前，系统会针对您的线上域名运行预检检查，因此配置错误的代理不会意外阻断读者访问；如果 DNS 发生故障，子域名会重新开始提供服务，而不会让文档下线。纯 CNAME 域名完全无需配置；已经发送 `X-Jamdesk-Forwarded-Host` 的代理也无需配置；Vercel `rewrites` 用户只需在每个目标 URL 后添加 `?jd_proxy=1`。这会让搜索引擎和普通访客看不到您的 Jamdesk 地址——它不是密码，因此如果您希望控制文档的阅读权限，请同时启用密码保护。[仅自定义域名 →](/cn/deploy/custom-domain-only)

</Update>

**直接在仪表板中编辑文档。** Web 编辑器现已向所有人开放，无需设置。打开侧边栏中的 **Editor**，浏览已连接的仓库，编辑 MDX 并实时预览，然后直接提交到您的 GitHub 分支，同时自动触发构建。[Web 编辑器 →](/cn/development/web-editor)

**在仪表板中使用 AI 修复构建警告。** 当构建因链接损坏或页面缺少描述而完成时，构建页面现在会显示 **Fix with AI** 横幅，并说明可以修复的问题数量。打开横幅即可预览每项建议的编辑内容（重写后的锚点和建议的页面描述），然后应用您批准的修改。Jamdesk 会将这些修改提交到您的 GitHub 分支并开始新的构建。无法明确解决的内容会单独列出，供您手动修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**无限团队成员。** 现在每个项目在所有计划中都包含无限团队成员，无需额外付费。之前的 10 人上限和按席位计费均已取消——邀请整个团队加入即可。

**让受信任的机器人发布您的文档。** Dependabot、Renovate 或 CMS 发布机器人等自动化账户不是 Jamdesk 成员，因此默认情况下它们的推送不会触发构建。现在，当某个账户被拒绝时，构建页面会显示一个一键式 **Authorize Bot Account** 按钮。批准后，该账户的推送就会发布到您的线上网站，与团队成员的推送一样。只有项目成员可以授权账户；您可以随时在项目 GitHub 设置中的 **Allowed automation accounts** 下查看或撤销访问权限。

**每次构建都会为您的文档生成 AI Score。** Jamdesk 现在会在每次构建后自动评估 AI 代理读取已发布文档的效果，评分依据是开放的 AFDocs 标准，并直接显示在仪表板中。查看 0–100 分和字母等级，跟踪不同构建之间的趋势，并为每个问题获取通俗易懂的修复建议；每项建议都有 **Copy prompt to fix** 按钮，可将发现的问题交给您的 AI 编程代理。开启 **Email team when score changes**，即可在构建显著改变评分时收到通知。[AI 评分 →](/cn/ai/ai-score)
</Update>

**自动修复损坏的链接。** 现在可以使用一条命令修复目标明确的损坏内部链接警告，包括拼写错误的锚点和跨语言锚点漂移。运行 `jamdesk fix --dry-run` 预览计划中的更改，然后运行 `jamdesk fix` 应用更改；只有在正确锚点能解析到真实标题时，系统才会修改对应警告，存在歧义的情况则留待手动审核。[CLI 概览 →](/cn/cli/overview)

**使用横幅发布任何消息。** 在 `docs.json` 中添加 `banner`，消息栏就会固定在每个页面顶部——位于页眉上方，并使用主题的强调色。行内支持链接、**粗体**和*斜体*；设置 `dismissible: true` 可为读者提供关闭按钮（除非您更改消息，否则它会保持关闭状态）。[横幅 →](/cn/config/docs-json-reference#横幅)

**显示每个页面的最后更新时间。** 在 `docs.json` 中设置 `metadata.timestamp: true`，每个页面的页脚都会显示类似“Last updated on June 15, 2026”的行。日期来自最后一次修改该页面的 Git 提交，因此每次构建都会保持准确，无需手动维护日期。[页面元数据 →](/cn/config/docs-json-reference#metadata)

**设置导航图标样式。** 侧边栏、分组、标签、锚点和搜索图标现在支持图标对象上的 `style`（`{ "name": "rocket", "style": "duotone" }`）或样式前缀（`duotone/rocket`），可使用 light、thin、duotone 和 sharp 系列，而不再仅限于 solid。[图标 →](/cn/content/icons#图标对象形式)

**自定义搜索栏。** 使用 `search.prompt` 设置您自己的占位文本，并通过 `search.popularPages` 管理访客在空搜索面板中看到的快速链接——每个链接包含标题、页面 slug 和 Font Awesome 图标。[搜索配置 →](/cn/config/docs-json-reference#搜索)

**无需嵌入即可收集电子邮件订阅。** 在 **Integrations → Email Signups** 中连接 Resend、Mailchimp、Kit、Loops、beehiiv、Brevo 或 SendGrid，Jamdesk 托管的表单就会将读者直接添加到您自己的受众列表中——您的 API 密钥会保留在我们的后端，绝不会出现在已发布的网站中。将 [`EmailSubscribe`](/cn/components/email-subscribe) 组件添加到任意页面，或设置 `placement: changelog`，即可自动在每个更新日志页面上放置订阅框。[电子邮件订阅 →](/cn/integrations/email-signups)

**在 Cookie 同意后启用分析。** 在 `docs.json` 中添加 `integrations.cookies` 键，Jamdesk 会暂停所有分析和跟踪脚本——Google Analytics、GTM、Plausible、Crisp、自定义 JavaScript 以及内置分析功能——直到访客同意；同意状态读取自您的同意横幅设置的 `localStorage` 标志。也可以直接从 `docs.json` 加载 Osano 或 Termly 横幅；简短的桥接代码片段会在读者接受时立即切换标志，脚本无需重新加载页面即可运行。[Cookie 同意 →](/cn/integrations/cookie-consent)

**结构化的 llms.txt。** 每个网站的 `llms.txt` 现在都遵循 llmstxt.org 结构——导航标签和分组会变成 `##` 分区，让 AI 代理按照侧边栏的组织方式查看文档。多语言网站每种语言都有一个索引：根文件列出默认语言，并链接到每个翻译后的索引（例如 `/fr/llms.txt`），确保每个文件足够小，不会被任何代理截断。[llms.txt →](/cn/ai/llms-txt)

**让代理更快找到您的文档。** 每个页面现在都包含一个不可见且屏幕阅读器不会朗读的指令，指向 `llms.txt` 和页面的 `.md` 版本；每个 Markdown 导出文件开头也会添加一个链接到索引的引用块。抓取 HTML 的代理不再需要猜测 Markdown 路径是否存在。[AI 概览 →](/cn/ai/overview)

**在任何位置嵌入您的更新日志。** 只需一个 `<script>` 标签，“What's new?” 启动器即可嵌入您自己的应用，并在模态框中打开 Jamdesk 更新日志，同时显示每位访客的未读标记。从 **Integrations → What's New widget** 生成代码片段，然后通过 `data-` 属性调整启动器模式、角落位置、模态框大小和标记颜色。在您自己的 Jamdesk 文档中，[`<Widget>`](/cn/components/widget) MDX 组件只需一个标签、无需脚本，即可将同样的实时启动器添加到任意页面。[嵌入您的更新日志 →](/cn/development/embed-page)

**将 API 规范下载为 zip。** 在任意 API 参考页面中，AI Actions 菜单现在提供 **Download API spec** 选项，可将网站引用的所有 OpenAPI 规范（包括本地文件和远程 URL）打包到单个 `api-specs.zip` 中。多文件规范会保留其 `$ref` 文件夹结构，因此下载内容可直接导入 Postman、客户端生成器或您自己的工具。[AI 操作 →](/cn/ai/ai-actions)

**在构建时验证 OpenAPI 规范。** 每次部署都会严格验证 `docs.json` 引用的 OpenAPI 规范，并将任何问题显示为 **non-fatal build warning**，而不是使构建失败。文档仍会发布；您只会通过电子邮件和仪表板的构建列表获知具体问题（YAML 解析错误及行列号、无法解析的 `$ref` 或重复的 `operationId`）。在本地，`jamdesk dev` 仍会在规范无效时停止，以便您在推送前发现问题。[CLI 概览 →](/cn/cli/overview)
</Update>

**直接从搜索中询问 AI。** 开始在搜索框中输入内容，然后将问题交给 AI 聊天，而不是打开搜索结果——按下 ⌘/Ctrl+Enter，或点击搜索页脚中的 **Ask AI**。问题会追加到您的聊天对话中，您可以继续当前话题；直接按 Enter 仍会跳转到首个结果。[AI 聊天 →](/cn/ai/chat)

**复制回答和聊天记录。** 每条 AI 聊天回答都有复制按钮，可获取 Markdown 源代码；聊天标题栏中的 **Copy transcript** 操作则会将完整对话以带角色标签的 Markdown 复制下来，方便粘贴到问题单或文档中。[AI 聊天 →](/cn/ai/chat)

**更智能的聊天自动滚动。** 只有当您已经位于底部时，聊天才会跟随流式回答。向上滚动重新阅读较早的回复时，页面会保持当前位置，不会强行将您拉到底部；滚回底部后，自动滚动会重新固定。

**本地预览中的自定义 CSS（CLI）。** `jamdesk dev` 现在会以与已发布构建相同的方式应用自定义 CSS，因此您可以在部署前检查样式。将任意 `.css` 文件放在项目根目录中——例如 `style.css`，或多个按字母顺序合并的文件——浏览器刷新时就会加载。无需在 `docs.json` 中添加条目，这与 Mintlify 引入根目录样式表的方式一致。[自定义 CSS →](/cn/customization/custom-css)

**从 frontmatter 自定义社交预览。** 直接在页面 frontmatter 中设置任意 Open Graph 或 Twitter/X 元标签——`og:title`、`og:description`、`og:image`、`twitter:card`、`keywords` 以及完整的 metatag 集合。可以使用顶层扁平键，也可以使用嵌套的 `seo:` 区块；两种方式都有效，并且页面级值会覆盖 `docs.json` 中的默认值。[SEO →](/cn/content/seo)

**隐藏页面。** 无需删除草稿、内部手册或已弃用指南，即可将它们从侧边栏和搜索结果中移除。在页面 frontmatter 中添加 `hidden: true`，或在 `docs.json` 的分组或标签中添加该设置。隐藏页面仍可通过直接 URL 访问，但会从导航、站点地图、站内搜索和 AI 上下文中消失，并自动添加 `noindex` 标签。如果需要隐藏分组，但仍希望其中的页面出现在搜索结果中，请同时添加 `searchable: true`。[隐藏页面 →](/cn/content/hidden-pages)

**网格和窗口装饰。** 两种新的背景图案加入 Jam 主题的默认渐变。将 `background.decoration` 设置为 `"grid"`，使用细腻的 24px 点阵；或设置为 `"windows"`，在上方两个角落显示 Windows 11 风格的磨砂光斑。渐变和 `"none"` 平面填充仍按原方式工作，可选择适合您品牌的外观。[背景 →](/cn/customization/background)

**背景自定义。** `docs.json` 中新增的 `background` 区块可以停用 Jam 浅色模式渐变、按模式覆盖页面颜色，或调整渐变的颜色、大小、位置和不透明度。无需自定义 CSS。[背景 →](/cn/customization/background)

**D2 图表。** Mermaid 之外新增第二种图表语言。为围栏代码块标记 `d2`，Jamdesk 会在构建时将其渲染为 SVG，并内置浅色和深色主题。工作流程与 Mermaid 相同，可根据要绘制的图表选择合适的语言。[D2 图表 →](/cn/components/d2)

**分组搜索结果。** 搜索不再因同一页面匹配多个分区而重复显示该页面。搜索命中会在搜索模态框中归入其父页面下，默认显示最多三个分区，其余内容通过行内展开器显示。代码片段高亮仍会保留，让您用更少的浏览次数找到正确分区。

**连接时自动检测 `docs.json`。** 连接 GitHub 仓库时，系统会在其所在位置查找 `docs.json`。连接流程会扫描整个目录树；如果发现 Mintlify 的 `mint.json`，也会将其标记出来。无需手动设置即可支持 monorepo 和嵌套配置。[连接 GitHub →](/cn/setup/connecting-github)

**CLI 中的 `docs.json` 位置提示。** 现在更容易发现配置文件位置错误的问题。`jamdesk validate`、`jamdesk dev` 和 `jamdesk doctor` 会报告 `docs.json` 实际所在的位置，或它应当放置的位置，而不是显示笼统的“not found”错误。几秒内即可修复，无需解读堆栈跟踪。[CLI 概览 →](/cn/cli/overview)

**符合标准的 hreflang。** hreflang 标签现在会输出有效的 BCP 47 代码。`cn`、`jp` 和 `ja-jp` 等区域文件夹会映射到搜索引擎实际需要的代码（`zh`、`ja`），站点地图 URL 也会进行 XML 转义。每个本地化页面都会在自己的地区获得排名，而不会被视为重复内容。[语言 →](/cn/setup/languages)
</Update>

**PDF 导出。** 在仪表板的 **Settings → PDF Exports** 中，将整个文档网站渲染为单个 [PDF](/cn/builds/pdf-export)。仅限付费计划。多语言项目可以为每次导出选择语言环境，结果会按提交进行缓存；渲染完成后，您会收到包含下载链接的电子邮件。

**多语言 OpenAPI 规范。** 端点页面会在翻译后的 MDX 旁显示翻译后的 OpenAPI 规范。在源规范旁放置 `<spec>.<lang>.<ext>` 文件（例如 `openapi/api.fr.yaml`），Jamdesk 就会在该语言的 URL 中使用它；如果缺少某种语言的变体，则回退到英文规范。操作摘要、参数描述、响应描述和 schema 描述都会进行本地化。设置方法：[翻译 OpenAPI 规范](/cn/setup/languages#翻译-openapi-规范)。

**Visibility 组件。** 新的 [`<Visibility for="humans|agents">`](/cn/components/visibility) 组件可以让您在同一页面中为人类读者或 AI 代理划分内容。仅面向人类的区块会在浏览器中渲染，但会从 `.md` 导出和 `llms-full.txt` 中移除；仅面向代理的区块则相反。代理在规范 URL 上请求 `Accept: text/markdown` 时，会自动获得代理视图。

**重新构建的密码保护。** 可以使用共享密码锁定整个网站，也可以只保护少量页面，同时让其他页面保持公开。将 `auth.password.enabled: true` 设置为全站模式；对于特定页面模式，则在单个页面的 frontmatter 中标记 `private: true`，或将页面列在 `auth.password.private` 下。仪表板的 Settings 页面会引导您设置、轮换和撤销密码。访客会看到带有您网站徽标、主色和可选提示的品牌解锁页面。设置指南：[密码保护](/cn/setup/password-protection)。

**自动转换 WebP 图片。** Jamdesk 可以在构建时将 PNG 和 JPG 图片转换为 WebP。转换后的文件通常比原文件小 60–80%，且不会出现可见的质量损失，因此无需手动处理图片即可加快页面加载。通过 `docs.json` 中的 `images.convertToWebp: true` 启用。为兼容社交平台爬虫，favicon、`og:image` 和 `twitter:image` 会保留原格式。新的 **Optimizing images** 步骤会在每次构建期间于仪表板和 CLI 中显示实时进度。[自动图片转换 →](/cn/builds/image-optimization)

**API Playground。** 端点页面现在提供交互式[“Try it”按钮](/cn/api-reference/playground)。填写参数，实时查看代码示例更新，并且无需离开文档即可发送实时请求。默认在所有 API 页面上启用，同时支持 OpenAPI 和使用 MDX 编写的端点。

**Claude Code 插件。** 安装 [Jamdesk 的 Claude Code 插件](/cn/claude-code-plugin)，让 Claude 深入了解 MDX 组件、`docs.json` 配置、导航模式和 CLI 命令。通过插件市场即可完成两步安装。该插件可与 [CLAUDE.md](/cn/ai/claude-code) 和 [MCP 服务器](/cn/ai/mcp-server) 搭配，用于 AI 辅助文档编写。

**缺少品牌资源时显示构建警告。** 如果 `docs.json` 中的 `favicon` 或 `logo` 路径引用了项目中不存在的文件，构建现在会发出警告。警告会显示在仪表板的构建详情中，也会通过 `jamdesk dev` 和 `jamdesk validate` 出现在 CLI 中。不发送电子邮件；该警告仅供提示。

**YouTube Shorts。** [`<YouTube>` 组件](/cn/content/youtube#youtube-shorts) 通过 `short` 属性支持竖屏 Shorts，渲染居中的 9:16 播放器且不显示黑边。使用 `<YouTube id="VIDEO_ID" short />`。
</Update>
