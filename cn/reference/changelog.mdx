<Update label="2026 年 8 月" date="2026-08-20">
**根据规范构建完整 API 参考。** 使用 `"openapi": { "source": "/openapi/api.yaml", "generate": true }` 将导航标签指向 OpenAPI 文件，Jamdesk 会在每次构建时为每个操作创建页面，并按标签归类到侧边栏中。无需编写内容，也无需提交文件。你已经编写的端点页面会优先使用自己的 slug，因此可以一次切换一个页面；当你在规范中重命名路径时，旧 URL 会重定向到新 URL，而不会返回 404。[生成的 API 页面 →](/cn/config/docs-json-reference#navigation-openapi生成的页面)

**读者可以选择要查看的 API 服务器。** 如果某个端点的规范列出了多个 `servers` 条目，现在会在 URL 旁显示选择器。选择 sandbox 后，基础 URL、复制按钮、每个代码示例以及 playground 发送的请求都会切换，因此不会有人从 sandbox 文档中复制生产环境的 `curl`。单服务器端点不受影响。[API Playground →](/cn/api-reference/playground#多个服务器)

**每个 OpenAPI 描述都支持 Markdown 渲染。** 表格、列表、链接、`code` 和 **粗体** 现在会在参数、请求正文、响应和架构描述中以与操作描述相同的方式渲染。过去九个位置的渲染结果不一致，现在它们全部使用同一个渲染器。[OpenAPI 示例 →](/cn/api-reference/openapi-example)

**端点 Markdown 导出现在包含身份验证信息。** 获取 API 参考页面的 `.md` 版本时，页面末尾现在会添加 `## Authentication` 部分，其中列出操作所需的方案，包括类型、标头名称、bearer 格式、OAuth 2 作用域，以及哪些组合有效。读取导出的代理无需打开规范即可构建可用的请求。[Markdown 源码 →](/cn/ai/markdown-source#端点页面导出的内容)

**让页面不出现在搜索中，但无需隐藏页面。** 在页面的 frontmatter 中添加 `search: false`，页面就会从站内搜索、AI 聊天回答和 MCP 服务器中移除，同时保留在侧边栏、站点地图和 llms.txt 中。这适用于已经被替代、但仍希望读者能够链接和索引的页面。隐藏页面和 noindex 页面现在也不会出现在 AI 回答中，而此前仍会出现。[仅让页面不出现在搜索中 →](/cn/content/hidden-pages#仅将页面排除在搜索之外)

**`jamdesk validate` 会警告无效配置。** 某些 `docs.json` 键虽然会被接受，却从未实际渲染，其中最典型的是 `asyncapi`。因此，配置看起来像是受支持的，直到构建网站时才发现页面没有内容。现在，Validate 会指出这些键，同时也会报告第一个 `api.mdx.server` 条目之后的额外条目，因为这些条目一直都会被丢弃。[CLI 概览 →](/cn/cli/overview)

**自动提供 27 种语言的文档。** 在 **Settings → Translations** 中启用所需语言，Jamdesk 会在每次构建后翻译文档，然后直接将结果提交到 GitHub 仓库。你可以从 27 种语言中选择最多五种。首次运行后，只有英文源文件发生变化的页面才会重新翻译。已有翻译会被采用而不是覆盖；你手动编辑过的页面之后会保持不变。Jamdesk 会在 dashboard 中标记这些页面，并且只有在你要求时才提供替换选项。所有计划均包含此功能，无按字计费，也无需购买 credits。[AI 翻译 →](/cn/setup/ai-translation)

**自定义文档 URL。** 子路径托管不再将你限制在 `/docs`：你可以在 dashboard 的 Custom Domain 卡片中选择任意单段路径（如 `/help` 或 `/guide`）。重命名是安全的：`/docs` 本身始终继续提供服务，canonical URL 会立即迁移到新的子路径，而之前的自定义子路径会在一次重命名期间转发到新路径，因此已被索引或链接的地址都不会失效。准备好后，记得同步更新代理中的 `/docs` 引用。[子路径托管 →](/cn/deploy/subpath-hosting)

**使用 AI 修复，现在速度更快。** 扫描完成得更快、更可靠，包括大型文档网站在内；重新打开修复预览也几乎即时完成，因为 Jamdesk 会缓存扫描结果，并在文档发生变化前重复使用这些结果。几秒钟内即可从构建警告转到已提交的修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**第四个主题：Halo。** 在 `docs.json` 中设置 `"theme": "halo"`，即可使用温暖、柔和圆润的外观。这是第四个精美的内置主题，采用沙色背景、焦糖色强调色、Figtree 字体，圆角程度远超其他三个主题。[主题设置 →](/cn/customization/theming)

**仅通过自己的域名提供文档。** 在项目的自定义域名设置中启用 **Custom domain only** 后，`YOUR_SLUG.jamdesk.app` 将不再直接响应请求：你的文档只能通过自己的域名访问。开关启用前，系统会针对你的线上域名运行预检，避免配置错误的代理意外阻断读者；如果 DNS 后续发生故障，子域名会重新开始提供服务，而不是让文档离线。纯 CNAME 域名无需任何配置；已经发送 `X-Jamdesk-Forwarded-Host` 的代理也无需配置；使用 Vercel `rewrites` 的用户只需为每个目标添加 `?jd_proxy=1`。这会让搜索引擎和普通访客看不到你的 Jamdesk 地址，但它不是密码，因此如果你想控制谁可以阅读文档，请同时启用密码保护。[仅自定义域名 →](/cn/deploy/custom-domain-only)

</Update>

**直接在 dashboard 中编辑文档。** Web 编辑器现已对所有人开放，无需设置。打开侧边栏中的 **Editor**，浏览已连接的仓库，编辑带实时预览的 MDX，并直接提交到 GitHub 分支；提交会自动触发构建。[Web 编辑器 →](/cn/development/web-editor)

**在 dashboard 中使用 AI 修复构建警告。** 当构建因链接失效或页面缺少描述而完成时，构建页面现在会显示 **Fix with AI** 横幅，并指出可以修复的问题数量。打开横幅可预览每项建议的编辑内容（重写后的锚点和建议的页面描述），然后应用你批准的修改。Jamdesk 会将修改提交到 GitHub 分支并启动新的构建。无法明确解决的问题会单独列出，供你手动修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**团队成员不限量。** 现在所有计划的每个项目都包含不限量团队成员，无需额外付费。原先的 10 人上限和按席位计费均已取消，你可以邀请整个团队。

**允许受信任的机器人发布文档。** Dependabot、Renovate 或 CMS 发布机器人等自动化账户不是 Jamdesk 成员，因此默认情况下，它们的推送不会触发构建。现在，当某个账户被拒绝时，构建页面会显示一键式 **Authorize Bot Account** 按钮。批准后，该账户的推送就会发布到线上网站，与团队成员的推送一样。只有项目成员可以授权账户，你可以随时在项目 GitHub 设置中的 **Allowed automation accounts** 下查看或撤销访问权限。

**每次构建都会为文档生成 AI Score。** Jamdesk 现在会在每次构建后自动评估 AI 代理读取已发布文档的效果，并依据开放的 AFDocs 标准评分，评分结果会直接显示在 dashboard 中。查看 0–100 分和字母等级，跟踪不同构建之间的趋势，并为每个问题获取通俗易懂的修复建议。每项建议都有 **Copy prompt to fix** 按钮，可将问题交给 AI 编码代理。启用 **Email team when score changes** 后，当构建导致分数发生明显变化时，你会收到通知。[AI Score →](/cn/ai/ai-score)

**自动修复失效链接。** 对于目标明确的内部链接警告（例如拼写错误的锚点和跨语言锚点偏移），现在可以使用一条命令修复。运行 `jamdesk fix --dry-run` 预览计划中的修改，然后运行 `jamdesk fix` 应用修改；只有正确锚点能够解析到实际标题的警告会被处理，存在歧义的情况会留给你手动检查。[CLI 概览 →](/cn/cli/overview)

**使用横幅发布任何消息。** 在 `docs.json` 中添加 `banner`，消息栏就会固定在每个页面顶部、标题栏上方，并使用主题的强调色。支持内联链接、**粗体** 和 *斜体*；设置 `dismissible: true` 后，读者会看到关闭按钮（除非你更改消息，否则横幅会保持关闭状态）。[横幅 →](/cn/config/docs-json-reference#横幅)

**显示每个页面的最后更新时间。** 在 `docs.json` 中设置 `metadata.timestamp: true`，每个页面的页脚都会显示类似 “Last updated on June 15, 2026” 的行。日期取自最近一次修改该页面的 Git 提交，因此每次构建都会保持准确，无需手动维护日期。[页面元数据 →](/cn/config/docs-json-reference#metadata)

**设置导航图标样式。** 侧边栏、分组、标签、锚点和搜索图标现在会遵循图标对象中的 `style`（`{ "name": "rocket", "style": "duotone" }`）或样式前缀（`duotone/rocket`），支持 light、thin、duotone 和 sharp 系列，不再局限于 solid。[图标 →](/cn/content/icons#图标对象形式)

**自定义搜索栏。** 使用 `search.prompt` 设置自定义占位文本，并通过 `search.popularPages` 管理访客在空搜索面板中看到的快捷链接；每个链接包含标题、页面 slug 和 Font Awesome 图标。[搜索配置 →](/cn/config/docs-json-reference#搜索)

**无需嵌入代码即可收集邮箱注册。** 在 **Integrations → Email Signups** 中连接 Resend、Mailchimp、Kit、Loops、beehiiv、Brevo 或 SendGrid，Jamdesk 托管的表单就能将读者直接添加到你自己的受众列表中；API 密钥会保留在我们的后端，绝不会出现在已发布的网站中。在任意页面添加 [`EmailSubscribe`](/cn/components/email-subscribe) 组件，或设置 `placement: changelog`，即可自动在每个更新日志页面上显示注册框。[邮箱注册 →](/cn/integrations/email-signups)

**在 Cookie 同意后加载分析功能。** 在 `docs.json` 中添加 `integrations.cookies` 键，Jamdesk 会暂停所有分析和跟踪脚本，包括 Google Analytics、GTM、Plausible、Crisp、自定义 JavaScript 以及内置分析功能，直到访客同意；同意状态读取自同意横幅设置的 `localStorage` 标志。也可以直接从 `docs.json` 加载 Osano 或 Termly 横幅；简短的桥接代码会在读者接受的瞬间切换标志，脚本无需重新加载页面即可运行。[Cookie 同意 →](/cn/integrations/cookie-consent)

**整理后的 llms.txt。** 每个网站的 `llms.txt` 现在都遵循 llmstxt.org 结构：导航标签和分组会变成 `##` 部分，让 AI 代理按照侧边栏的组织方式查看文档。多语言网站每种语言都有一个索引：根文件列出默认语言，并链接到每个翻译索引（例如 `/fr/llms.txt`），使每个文件足够小，避免被代理截断。[llms.txt →](/cn/ai/llms-txt)

**让代理更快找到文档。** 每个页面现在都包含一个不可见且屏幕阅读器不会读出的指令，将 AI 代理指向 `llms.txt` 和页面的 `.md` 版本；每个 Markdown 导出文件开头也会通过引用块链接到索引。获取 HTML 的代理不再需要猜测 Markdown 路径是否存在。[AI 概览 →](/cn/ai/overview)

**在任何位置嵌入更新日志。** 只需一个 `<script>` 标签，就能将 “What's new?” 启动器添加到自己的应用中，并在模态框中打开 Jamdesk 更新日志，同时为每位访客显示未读提示点。从 **Integrations → What's New widget** 生成代码片段，然后使用 `data-` 属性调整启动器模式、角落位置、模态框大小和提示点颜色。在自己的 Jamdesk 文档中，[`<Widget>`](/cn/components/widget) MDX 组件只需一个标签、无需脚本，即可将相同的实时启动器添加到任意页面。[嵌入更新日志 →](/cn/development/embed-page)

**将 API 规范下载为 zip。** 在任意 API 参考页面中，AI Actions 菜单现在提供 **Download API spec** 选项，可将网站引用的所有 OpenAPI 规范（包括本地文件和远程 URL）打包成单个 `api-specs.zip`。多文件规范会保留其 `$ref` 文件夹结构，因此下载内容可以直接导入 Postman、客户端生成器或你自己的工具链。[AI Actions →](/cn/ai/ai-actions)

**在构建时验证 OpenAPI 规范。** 每次部署现在都会严格验证 `docs.json` 引用的 OpenAPI 规范，并将问题显示为**非致命构建警告**，而不是使构建失败。文档仍会发布，同时你会通过电子邮件和 dashboard 的构建列表准确获知问题所在，例如 YAML 解析错误及其行列号、无法解析的 `$ref` 或重复的 `operationId`。在本地，`jamdesk dev` 遇到无效规范时仍会停止，以便你在推送前发现问题。[CLI 概览 →](/cn/cli/overview)
</Update>

**直接从搜索中询问 AI。** 开始输入搜索内容后，可以将问题交给 AI 聊天，而不必打开搜索结果：按 ⌘/Ctrl+Enter，或点击搜索页脚中的 **Ask AI**。问题会追加到聊天对话中，你可以继续保持同一讨论线程；普通 Enter 仍会跳转到首个结果。[AI 聊天 →](/cn/ai/chat)

**复制回答和聊天记录。** 每条 AI 聊天回答都有复制按钮，可获取 Markdown 源码；聊天标题栏中的 **Copy transcript** 操作则会将整个对话以带角色标记的 Markdown 复制下来，方便粘贴到 issue 或文档中。[AI 聊天 →](/cn/ai/chat)

**更智能的聊天自动滚动。** 只有当你已经位于底部时，聊天才会跟随流式回答。向上滚动重新阅读之前的回复时，页面会保持当前位置，不会强行将你拉到底部；滚回底部后，页面会重新固定在底部。

**本地预览支持自定义 CSS（CLI）。** `jamdesk dev` 现在会以与已发布构建相同的方式应用自定义 CSS，因此你可以在部署前检查样式。将任意 `.css` 文件放在项目根目录中（例如 `style.css`，也可以按字母顺序合并多个文件），浏览器刷新时就会加载。无需在 `docs.json` 中添加条目，与 Mintlify 引入根目录样式表的方式一致。[自定义 CSS →](/cn/customization/custom-css)

**从 frontmatter 自定义社交预览。** 可以直接在页面 frontmatter 中设置任意 Open Graph 或 Twitter/X 元标签，包括 `og:title`、`og:description`、`og:image`、`twitter:card`、`keywords` 以及完整的 metatag 集合。可以使用顶层平铺键，也可以使用嵌套的 `seo:` 块；两种方式都支持，页面级值会覆盖 `docs.json` 中的默认值。[SEO →](/cn/content/seo)

**隐藏页面。** 无需删除草稿、内部手册或已弃用指南，即可将它们从侧边栏和搜索结果中移除。在页面 frontmatter 中添加 `hidden: true`，或在 `docs.json` 的分组或标签中添加该设置。隐藏页面仍可通过直接 URL 访问，但会从导航、站点地图、站内搜索和 AI 上下文中消失，并自动添加 `noindex` 标签。如果需要隐藏分组，但仍希望其中的页面出现在搜索结果中，请同时添加 `searchable: true`。[隐藏页面 →](/cn/content/hidden-pages)

**网格和窗口装饰。** 两种新的背景图案加入了 Jam 主题的渐变默认样式。将 `background.decoration` 设置为 `"grid"`，使用精细的 24px 点阵网格；或设置为 `"windows"`，在上方两个角落显示 Windows 11 风格的磨砂光斑。渐变和 `"none"` 平面填充仍可照常使用，选择适合品牌的外观即可。[背景 →](/cn/customization/background)

**自定义背景。** `docs.json` 中新增的 `background` 块可以禁用 Jam 浅色模式渐变、按模式覆盖页面颜色，或调整渐变的颜色、大小、位置和不透明度。无需自定义 CSS。[背景 →](/cn/customization/background)

**D2 图表。** Mermaid 之外现在新增第二种图表语言。在围栏代码块上标记 `d2`，Jamdesk 就会在构建时将其渲染为 SVG，并内置浅色和深色主题。工作流与 Mermaid 相同，可选择最适合当前图表的语言。[D2 图表 →](/cn/components/d2)

**分组搜索结果。** 搜索不再因同一页面中的多个部分匹配而重复显示该页面。结果会在搜索模态框中归入所属页面，默认显示最多三个部分，其余部分可通过内联展开器查看。片段高亮保持不变，让你用更少的浏览次数找到正确部分。

**连接时自动检测 `docs.json`。** 连接 GitHub 仓库时，无论 `docs.json` 位于何处，系统都会找到它。连接流程会扫描整个文件树；如果发现 Mintlify 的 `mint.json`，也会进行标记。Monorepo 和嵌套配置无需手动设置即可使用。[连接 GitHub →](/cn/setup/connecting-github)

**CLI 提示 `docs.json` 位置。** 错误位置的配置更容易被发现。`jamdesk validate`、`jamdesk dev` 和 `jamdesk doctor` 会报告 `docs.json` 实际所在的位置，或应当放置的位置，而不再只显示通用的“未找到”错误。几秒钟即可修复，无需解读堆栈跟踪。[CLI 概览 →](/cn/cli/overview)

**符合标准的 hreflang。** Hreflang 标签现在会生成有效的 BCP 47 代码。`cn`、`jp` 和 `ja-jp` 等区域设置文件夹会映射到搜索引擎实际期望的代码（`zh`、`ja`），站点地图 URL 也会进行 XML 转义。每个本地化页面都会在自己的区域中获得排名，而不会被视为重复内容。[语言 →](/cn/setup/languages)
</Update>

**PDF 导出。** 在 dashboard 的 **Settings → PDF Exports** 中，将整个文档网站渲染为单个 [PDF](/cn/builds/pdf-export)。仅限付费计划。多语言项目可以为每次导出选择区域设置，结果会按提交进行缓存，渲染完成后你会收到包含下载链接的电子邮件。

**多语言 OpenAPI 规范。** 端点页面现在会同时显示翻译后的 OpenAPI 规范和翻译后的 MDX。在源规范旁放置 `<spec>.<lang>.<ext>` 文件（例如 `openapi/api.fr.yaml`），Jamdesk 会在对应语言的 URL 中使用该文件；如果缺少某种语言的变体，则回退到英文规范。操作摘要、参数描述、响应描述和架构描述都会进行本地化。设置方法：[翻译 OpenAPI 规范](/cn/setup/languages#翻译-openapi-规范)。

**Visibility 组件。** 新的 [`<Visibility for="humans|agents">`](/cn/components/visibility) 组件可以在同一页面中分别提供面向人类读者或 AI 代理的内容。仅面向人类的区块会在浏览器中渲染，但会从 `.md` 导出和 `llms-full.txt` 中移除；仅面向代理的区块则相反。代理通过 canonical URL 请求 `Accept: text/markdown` 时，会自动获得代理视图。

**重新打造的密码保护。** 可以使用共享密码锁定整个网站，也可以只保护少数页面，同时让其余页面保持公开。将 `auth.password.enabled: true` 设置为全站模式；或者在页面 frontmatter 中标记 `private: true`，或将页面列在 `auth.password.private` 下，以使用指定页面模式。dashboard 的 Settings 页面会引导你设置、轮换和撤销密码。访客会看到带有网站徽标、主色和可选提示的品牌解锁页面。设置指南：[密码保护](/cn/setup/password-protection)。

**自动转换 WebP 图片。** Jamdesk 可以在构建时将 PNG 和 JPG 图片转换为 WebP。转换后的文件通常比原文件小 60–80%，且不会出现明显的质量损失，因此无需手动处理图片即可加快页面加载。通过 `docs.json` 中的 `images.convertToWebp: true` 启用。Favicons、`og:image` 和 `twitter:image` 会保持原始格式，以兼容社交爬虫。新的 **Optimizing images** 步骤会在每次构建期间于 dashboard 和 CLI 中显示实时进度。[自动图片转换 →](/cn/builds/image-optimization)

**API Playground。** 端点页面现在包含交互式的 ["Try it" 按钮](/cn/api-reference/playground)。填写参数，实时查看代码示例更新，并且无需离开文档即可发送实时请求。所有 API 页面默认启用。OpenAPI 端点和使用 MDX 编写的端点均可使用。

**Claude Code 插件。** 安装 [Jamdesk Claude Code 插件](/cn/claude-code-plugin)，让 Claude 深入了解 MDX 组件、`docs.json` 配置、导航模式和 CLI 命令。只需从插件市场进行两步安装。该插件可以与 [CLAUDE.md](/cn/ai/claude-code) 和 [MCP 服务器](/cn/ai/mcp-server) 搭配使用，以辅助编写文档。

**缺少品牌资源时显示构建警告。** 如果 `docs.json` 中的 `favicon` 或 `logo` 路径引用了项目中不存在的文件，构建现在会发出警告。警告会显示在 dashboard 构建详情中，也会通过 `jamdesk dev` 和 `jamdesk validate` 显示在 CLI 中。不发送电子邮件；该警告仅供提示。

**YouTube Shorts。** [`<YouTube>` 组件](/cn/content/youtube#youtube-shorts) 通过 `short` 属性支持竖屏 Shorts，渲染居中的 9:16 播放器且不显示黑边。使用 `<YouTube id="VIDEO_ID" short />`。
</Update>

**AI Actions 菜单。** [每个页面上的下拉菜单](/cn/ai/ai-actions)允许读者复制 Markdown，在 ChatGPT、Claude 或 Perplexity 中打开页面，获取 MCP 服务器配置，或一键安装到 Cursor 或 VS Code 中。默认启用；可以通过 `docs.json` 中的 `contextual` 选择显示哪些选项。

**分析。** 无需 Cookie 的页面分析功能可以跟踪浏览量、流量来源和访客趋势，并提供[按页面细分](/cn/setup/project-analytics)。无需同意横幅。概览：[分析](/cn/setup/analytics-overview)。

**集成。** [Google Analytics 4](/cn/integrations/google-analytics)、[Google Tag Manager](/cn/integrations/google-tag-manager)、[Plausible Analytics](/cn/integrations/plausible-analytics) 和 [Slack 构建通知](/cn/integrations/slack)（Pro）。

**更新日志的 RSS Feed。** frontmatter 中设置 `rss: true` 的页面现在会自动生成可订阅的 RSS Feed。RSS 图标会显示在页面标题旁，并且每次构建都会根据 [Update](/cn/components/update#rss-feed) 组件生成 `feed.xml`。在 Update 上使用新的 `date` 属性，即可生成正确的 Feed 日期。

**CLI 登录与部署。** [`jamdesk login`](/cn/cli/authentication) 通过浏览器完成身份验证。 [`jamdesk deploy`](/cn/cli/deploy) 会打包项目，并从终端触发构建。无需连接 GitHub。CLI 遵循 `.gitignore`，会警告秘密文件，并以内联方式流式显示构建进度。

**CLI 拼写检查。** `jamdesk spellcheck` 使用内置的 180 多个技术术语检查文档中的拼写错误（仅支持英语）。`jamdesk spellcheck --fix` 会启动交互模式，用于修复拼写错误或将词语添加到忽略列表中。

**视频嵌入。** 可以直接在文档中嵌入 `.mp4` 和 `.webm` 文件。将文件放入 `/videos` 目录，然后使用 Markdown 语法（`![Demo](/videos/demo.mp4)`）或 [`<Video>` 组件](/cn/content/videos)实现自动播放、循环播放和其他控制。

**自定义 JavaScript。** 通过 `docs.json` 中的 `styling.js` 添加[客户端脚本](/cn/customization/custom-javascript)，用于聊天组件、分析功能或第三方集成。
</Update>

<Update label="2026 年 2 月" date="2026-02-01">
**AI 聊天。** 每个文档网站都内置[聊天助手](/cn/ai/chat)。访客可以提问，并获得带有指向源页面引用链接的回答。由 Claude 提供支持，所有计划均可使用。

**AI 集成。** 每个网站都会生成用于 LLM 上下文窗口的 [`llms.txt`](/cn/ai/llms-txt)，通过 [`.md` URL](/cn/ai/markdown-source)提供原始 Markdown，并在 `/_mcp` 提供带有 `searchDocs` 和 `getPage` 工具的 [MCP 服务器](/cn/ai/mcp-server)。同时提供 [Claude Code](/cn/ai/claude-code)、[Cursor](/cn/ai/cursor) 和 [Codex](/cn/ai/codex) 的设置指南。此外还有：[使用 AI 编写](/cn/ai/writing-with-ai)和[自动更新](/cn/ai/automated-updates)。

**CLI。** 使用 `jamdesk dev` 进行支持热重载的本地预览，使用 `jamdesk validate` 检查失效链接，使用 `jamdesk migrate` 从 Mintlify、GitBook 或 Docusaurus 转换，使用 `jamdesk doctor` 排查设置问题。支持通过 npm、curl 或 Homebrew 安装。[完整参考 →](/cn/cli/overview)

**VS Code 扩展。** 可以从 VS Code 状态栏[启动、停止和重启开发服务器](/cn/development/vscode-extension)，无需终端。

**自定义域名 TXT 验证。** 所有自定义域名现在都需要 TXT 记录（`_jamdesk.yourdomain.com`）后才能启用路由，从而防止未认领子域名遭到域名接管。新添加的域名会在 dashboard 设置流程中显示 TXT 记录。请参阅[自定义域名指南](/cn/deploy/custom-domains)。

**多语言支持。** 为每个区域设置定义[独立的导航树和内容目录](/cn/setup/languages)。读者可以从顶部栏的下拉菜单切换语言。

**搜索分析。** 查看[读者搜索的内容](/cn/setup/search-analytics)、哪些查询没有结果，以及哪些结果真正获得了点击。这有助于发现内容缺口。
</Update>

Jamdesk 正式发布。使用 MDX 编写文档，推送到 GitHub，即可在全球 CDN 上获得网站。构建在 60 秒内完成。

**MDX 与组件。** 提供 20 多个内置组件：标签页、手风琴、步骤、代码组、Mermaid 图表、KaTeX 数学公式和图标。在[代码块](/cn/content/code-blocks)中使用带行号的语法高亮。使用 Tailwind 和 hooks 构建[自定义 React 组件](/cn/content/react-components)，并通过[代码片段](/cn/content/snippets)复用内容。[组件概览 →](/cn/components/overview)

**自定义。** 三种[主题](/cn/customization/theming)（`jam`、`nebula`、`pulsar`），支持自定义颜色、徽标和页脚。使用[自定义 CSS](/cn/customization/custom-css)覆盖样式。通过包含标签、分组和图标的灵活[导航](/cn/navigation/overview)组织网站。使用[重定向](/cn/setup/redirects)支持精确匹配和通配符匹配。

**搜索与 SEO。** Cmd+K 全文搜索，无需配置。开箱即用地提供[站点地图、OG 图片和页面级元数据](/cn/content/seo)。

**[docs.json 参考](/cn/config/docs-json-reference)。** 涵盖所有设置和选项的完整配置参考。

**[帮助中心](/cn/help/overview)。** 提供账户管理、账单和故障排除指南。
