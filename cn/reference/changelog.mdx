<Update label="2026 年 9 月" date="2026-09-21">
**把读者直接送到他们自己的语言。** 在 `docs.json` 中设置 `"localization": { "autoRedirect": true }`，浏览器请求法语的首次访客就会进入 `/fr`，而不是您的默认语言。他们的选择会保持一年，从语言切换器中选择语言则会覆盖这一结果。只有站点根路径会被重定向——像 `/fr` 这样的语言 URL 和像 `/guides/authentication` 这样的深层链接，对所有人都会完全按照请求打开，因此您粘贴到工单里的链接，对点击它的人来说打开的就是同一个页面。爬虫同样永远不会被重定向，由您的 `hreflang` 标签继续决定哪些内容被收录。默认关闭；需要配置两种或更多语言。[自动语言路由 →](/cn/setup/languages)

**覆盖某个页面的“最后更新”日期。** `docs.json` 中的 `metadata.timestamp` 已经可以显示一行来自该页面最后一次 Git 提交的“Last updated on …”。在页面的 frontmatter 中加入 `lastUpdatedDate: "2026-09-01"`，该日期就会在页脚中取代提交日期。无论页脚是否开启，它同样会写入站点地图的 `<lastmod>` 和页面结构化数据中的 `dateModified`，因此搜索引擎和 AI 助手看到的日期与您的读者看到的一致。在您复查过某个页面之后，或者当某次仅调整格式的提交改变了日期、却没有改动读者会注意到的任何内容时，这一点很有用。[前置元数据 →](/cn/content/frontmatter)

**关闭某个代码块的复制按钮。** 在代码栅栏上添加 `nocopy`，该代码块就会失去复制按钮，而其他代码块都会保留；它可以与标题以及其他所有栅栏选项组合使用，在 `<CodeGroup>` 内部还能按标签页生效。可用于终端记录、经过脱敏处理的示例，以及“不要这样做”的片段——任何复制渲染后的文本会让读者拿到无法直接使用内容的场合。[代码块 →](/cn/content/code-blocks)

**使用您自己的登录方式让读者登录。** JWT 身份验证可以将文档网站置于您现有的登录系统之后，因此用户无需输入共享密码。在 `docs.json` 中启用 `auth.jwt`，在 **Settings** 中生成 Ed25519 签名密钥，并让您的后端在用户打开文档时签发短期令牌。Jamdesk 会验证令牌，并启动最长持续 30 天的用户会话。在页面中添加 `groups: ["admin"]` 后，只有令牌包含该组的访问者才能打开页面或在侧边栏中看到页面；其他人会收到 404。公开路径、frontmatter 中的 `public: true` 以及公开导航组可以让更新日志或状态页面保持开放。您还可以使用令牌中的访问者凭据预填充 API playground。所有计划均包含此功能，并且可以无缝从密码保护迁移过来。[JWT 身份验证 →](/cn/setup/jwt-authentication)

**网站根路径也会导出 Markdown。** 使用 `Accept: text/markdown` 请求您的文档根路径或 `/fr` 等语言根路径，或者请求 `/index.md`，即可获得该导航中的第一页，也就是 HTML 根路径显示的同一页面。过去，没有 `index.mdx` 的网站在此处会返回 404，导致许多代理发出的第一个请求失败。[Markdown 源文件 →](/cn/ai/markdown-source#网站根路径和语言根路径)
</Update>

**Jamdesk 可将您的文档翻译成 27 种语言。** 在 **Settings → Translations** 中勾选所需语言，每个项目最多支持五种语言。每次构建后，翻译页面都会提交到您的 GitHub 仓库。后续构建只会重新翻译英文源文件发生变化的页面。已有的翻译以及您手动编辑过的翻译都会保留，直到您点击 **Replace with AI translation**。所有计划均包含此功能。[AI 翻译 →](/cn/setup/ai-translation)

**选择自己的文档 URL。** 子路径托管不再固定为 `/docs`。在 Custom Domain 卡片的子路径字段中输入 `help` 或 `guide` 等单个片段并保存。`/docs` 仍会继续提供服务，规范 URL 会立即迁移到新路径，之前的自定义子路径会在单次重命名期间重定向到新路径，因此您可以按自己的节奏更新代理配置。[子路径托管 →](/cn/deploy/subpath-hosting)

**使用 AI 修复，现在速度更快。** 从构建横幅打开修复预览后，完成速度更快，即使是大型网站也一样。由于 Jamdesk 会保留扫描结果，重新打开预览几乎可以立即完成，除非您的文档发生变化。流程保持不变：查看每项建议的编辑，应用您批准的编辑，Jamdesk 会提交更改并重新构建。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**第四个主题：Halo。** 在 `docs.json` 中设置 `"theme": "halo"`，即可获得温暖、圆润的外观：使用 Figtree 字体、沙色背景，内容置于卡片上，并采用所有内置主题中最大的圆角半径。自定义颜色、字体和 CSS 覆盖的使用方式与 Jam、Nebula 和 Pulsar 相同。[主题设置 →](/cn/customization/theming)

**仅从您自己的域名提供文档。** 在 Custom Domain 卡片中启用 **Custom domain only** 后，直接访问 `YOUR_SLUG.jamdesk.app` 会返回 404，而您的 CNAME 或代理仍可正常工作。Jamdesk 会在切换启用前检查您的线上域名；如果 DNS 出现故障，子域名会重新提供服务，直到域名恢复。此功能会隐藏供直接访问的子域名，但不会控制谁能阅读您的文档；如需控制访问权限，请配合密码保护使用。[仅限自定义域名 →](/cn/deploy/custom-domain-only)

**从规范构建完整的 API 参考。** 使用 `"openapi": { "source": "/openapi/api.yaml", "generate": true }` 将导航标签指向您的 OpenAPI 文件，每次构建都会为每个操作创建一个页面，并按标签在侧边栏中分组。已提交的端点页面会保留其 slug，因此您可以逐页迁移；重命名后的路径会从旧 URL 重定向，而不是返回 404。[生成的 API 页面 →](/cn/config/docs-json-reference#openapi)

**让读者选择要查看的 API 服务器。** 如果端点的规范列出了多个 `servers` 条目，其 URL 旁边会显示选择器。选择 sandbox 后，基础 URL、复制按钮、所有代码示例以及 playground 发送的请求都会切换，因此读者不会从 sandbox 文档中复制生产环境的 `curl`。单服务器端点保持不变。[API Playground →](/cn/api-reference/playground#多个服务器)

**所有 OpenAPI 描述均支持 Markdown 渲染。** 表格、列表、链接、`code` 和 **bold** 在参数、请求正文、响应和 schema 描述中的渲染方式，现在与操作描述中的现有行为一致。过去有九个位置的行为不一致，现在它们共享同一个渲染器。[OpenAPI 示例 →](/cn/api-reference/openapi-example)

**端点 Markdown 导出包含身份验证信息。** 获取 API 参考页面的 `.md` 版本时，末尾会包含 `## Authentication` 部分，列出操作所需的方案：类型、标头名称、bearer 格式、OAuth 2 作用域以及有效的组合。读取导出的代理无需打开您的规范即可构建可用的请求。[Markdown 源文件 →](/cn/ai/markdown-source#端点页面导出的内容)

**仅将页面从搜索中移除，而不隐藏页面。** 在页面 frontmatter 中添加 `search: false`，页面就会从站内搜索、AI 聊天答案和 MCP 服务器中移除，但仍保留在侧边栏、站点地图和 llms.txt 中。对于您仍希望能够通过链接访问和建立索引的旧页面，可以使用此功能。隐藏页面和 noindex 页面也会被阻止出现在 AI 答案中，此前并非如此。[仅将页面从搜索中移除 →](/cn/content/hidden-pages#仅将页面排除在搜索之外)

**`jamdesk validate` 会警告不起作用的配置。** 某些 `docs.json` 键虽然会被接受，却从未实际渲染，其中最典型的是 `asyncapi`，因此配置看似受支持，直到构建网站后才发现没有任何内容。该命令会列出这些配置，以及超出第一个条目的额外 `api.mdx.server` 条目；后者一直都会被丢弃。[CLI 概览 →](/cn/cli/overview)
</Update>

**直接在仪表板中编辑文档。** Web 编辑器现已向所有用户开放，无需设置。打开侧边栏中的 **Editor**，浏览已连接的仓库，编辑带实时预览的 MDX，并直接提交到您的 GitHub 分支，同时自动触发构建。[Web 编辑器 →](/cn/development/web-editor)

**从仪表板使用 AI 修复构建警告。** 当构建因链接失效或页面缺少描述而完成时，构建页面现在会显示 **Fix with AI** 横幅，并说明可以修复的问题数量。打开横幅可预览每项建议的编辑内容（重写的锚点和建议的页面描述），然后应用您批准的编辑。Jamdesk 会将其提交到您的 GitHub 分支并开始新的构建。无法明确解决的问题会单独列出，供您手动修复。[使用 AI 修复 →](/cn/builds/fix-with-ai)

**无限团队成员。** 现在所有计划的每个项目都包含无限团队成员，无需额外付费。原先的 10 人上限和按席位计费已取消，您可以邀请整个团队。

**让可信机器人发布您的文档。** Dependabot、Renovate 或 CMS 发布机器人等自动化账户不是 Jamdesk 成员，因此默认情况下它们的推送不会触发构建。现在，当其中一个账户被拒绝时，构建页面会显示一个一键式 **Authorize Bot Account** 按钮。批准后，该账户的推送就可以发布到您的线上网站，与团队成员的推送一样。只有项目成员可以授权账户，您也可以随时在项目 GitHub 设置中的 **Allowed automation accounts** 下查看或撤销访问权限。

**每次构建都会为您的文档生成 AI Score。** Jamdesk 现在会根据开放的 AFDocs 标准，在每次构建后自动评估 AI 代理读取已发布文档的效果，并直接在仪表板中显示结果。查看 0–100 分和字母等级，观察跨构建趋势，并为每个问题获取通俗易懂的修复建议。每项建议都有 **Copy prompt to fix** 按钮，可将问题交给您的 AI 编程代理。启用 **Email team when score changes** 后，当构建导致分数出现显著变化时，团队会收到通知。[AI Score →](/cn/ai/ai-score)
</Update>

**自动修复失效链接。** 对于目标明确的内部链接警告（例如拼写错误的锚点和跨语言锚点漂移），现在可以使用一个命令修复。运行 `jamdesk fix --dry-run` 预览计划中的更改，然后运行 `jamdesk fix` 应用更改；只有正确锚点能够解析到真实标题的警告会被修改，存在歧义的情况仍需手动检查。[CLI 概览 →](/cn/cli/overview)

**使用横幅发布任何消息。** 在 `docs.json` 中添加 `banner`，消息栏就会固定在每个页面顶部、页眉上方，并使用主题的强调色。可以使用链接、**bold** 和 *italic* 内联格式，并设置 `dismissible: true` 为读者提供关闭按钮（除非您更改消息，否则它会保持关闭状态）。[横幅 →](/cn/config/docs-json-reference#横幅)

**显示每个页面的最后更新时间。** 在 `docs.json` 中设置 `metadata.timestamp: true`，每个页面的页脚都会显示类似“Last updated on June 15, 2026”的文本。日期来自最后一次修改该页面的 Git 提交，因此每次构建都会保持准确，无需手动维护日期。[页面元数据 →](/cn/config/docs-json-reference#metadata)

**设置导航图标样式。** 侧边栏、组、标签、锚点和搜索图标现在会遵循图标对象中的 `style`（`{ "name": "rocket", "style": "duotone" }`）或样式前缀（`duotone/rocket`），支持 light、thin、duotone 和 sharp 系列，而不仅仅是 solid。[图标 →](/cn/content/icons#图标对象形式)

**自定义搜索栏。** 使用 `search.prompt` 选择自定义占位文本，并使用 `search.popularPages` 管理访问者在空搜索面板中看到的快速链接；每个链接都包含标题、页面 slug 和 Font Awesome 图标。[搜索配置 →](/cn/config/docs-json-reference#搜索)

**无需嵌入即可收集邮箱注册。** 在 **Integrations → Email Signups** 中连接 Resend、Mailchimp、Kit、Loops、beehiiv、Brevo 或 SendGrid，Jamdesk 托管的表单就会将读者直接添加到您自己的受众列表中；API 密钥会保留在我们的后端，不会出现在已发布的网站中。将 [`EmailSubscribe`](/cn/components/email-subscribe) 组件添加到任意页面，或设置 `placement: changelog`，自动在每个更新日志页面上放置注册框。[邮箱注册 →](/cn/integrations/email-signups)

**在 Cookie 同意后再启用分析。** 在 `docs.json` 中添加 `integrations.cookies` 键后，Jamdesk 会暂停所有分析和跟踪脚本，包括 Google Analytics、GTM、Plausible、Crisp、自定义 JavaScript 以及内置分析功能，直到访问者同意；同意状态读取自您的同意横幅设置的 `localStorage` 标志。您也可以直接从 `docs.json` 加载 Osano 或 Termly 横幅；简短的桥接代码会在读者接受时立即切换标志，脚本无需重新加载页面即可运行。[Cookie 同意 →](/cn/integrations/cookie-consent)

**结构化的 llms.txt。** 每个网站的 `llms.txt` 现在都遵循 llmstxt.org 结构，导航标签和组会成为 `##` 部分，让 AI 代理能够按照侧边栏组织方式查看文档。多语言网站每种语言都有一个索引：根文件列出默认语言，并链接到每个翻译索引（例如 `/fr/llms.txt`），使每个文件足够小，避免被代理截断。[llms.txt →](/cn/ai/llms-txt)

**让代理更快找到您的文档。** 每个页面现在都包含一条不可见且屏幕阅读器不会读出的指令，将 AI 代理指向 `llms.txt` 和页面的 `.md` 版本；每个 Markdown 导出也会以一个链接到索引的引用块开头。获取 HTML 的代理不再需要猜测 Markdown 路径的存在。[AI 概览 →](/cn/ai/overview)

**在任意位置嵌入更新日志。** 只需一个 `<script>` 标签，就能将“What's new?”启动器添加到您自己的应用中，并在模态框中打开 Jamdesk 更新日志，同时为每位访问者显示未读标记。通过 **Integrations → What's New widget** 生成代码片段，然后使用 `data-` 属性调整启动器模式、角落位置、模态框大小和标记颜色。在您自己的 Jamdesk 文档中，[`<Widget>`](/cn/components/widget) MDX 组件只需一个标签即可将相同的实时启动器添加到任意页面，无需脚本。[嵌入更新日志 →](/cn/development/embed-page)

**将 API 规范下载为 zip。** 在任意 API 参考页面上，AI Actions 菜单现在包含 **Download API spec** 选项，可将网站引用的所有 OpenAPI 规范（包括本地文件和远程 URL）打包成单个 `api-specs.zip`。多文件规范会保留其 `$ref` 文件夹结构，因此下载内容可以直接用于 Postman、客户端生成器或您自己的工具。[AI Actions →](/cn/ai/ai-actions)

**在构建时验证 OpenAPI 规范。** 每次部署都会严格验证 `docs.json` 引用的 OpenAPI 规范，并将问题显示为**非致命构建警告**，而不是使构建失败。您的文档仍会发布，但系统会通过邮件和仪表板的构建列表明确告知具体问题，例如 YAML 解析错误及行列号、无法解析的 `$ref` 或重复的 `operationId`。在本地，`jamdesk dev` 仍会在规范无效时停止，以便您在推送前发现问题。[CLI 概览 →](/cn/cli/overview)
</Update>

**直接从搜索中询问 AI。** 开始输入搜索内容，然后将问题交给 AI 聊天，而不是打开搜索结果——按 ⌘/Ctrl+Enter，或点击搜索页脚中的 **Ask AI**。问题会添加到您的聊天对话中，方便继续讨论；直接按 Enter 仍会跳转到最顶部的结果。[AI 聊天 →](/cn/ai/chat)

**复制答案和对话记录。** 每条 AI 聊天答案都有复制按钮，可获取 Markdown 源文件；聊天标题栏中的 **Copy transcript** 操作可以将完整对话复制为带角色标签的 Markdown，方便粘贴到问题单或文档中。[AI 聊天 →](/cn/ai/chat)

**更智能的聊天自动滚动。** 只有当您已经位于底部时，聊天才会跟随流式答案。向上滚动重新阅读早先的回复时，页面会保持当前位置，不会强行滚到底部；滚回底部后，聊天会重新固定在那里。

**本地预览中的自定义 CSS（CLI）。** `jamdesk dev` 现在会像已发布的构建一样应用自定义 CSS，因此您可以在部署前检查样式。将任意 `.css` 文件放入项目根目录，例如 `style.css`，也可以放入多个文件，系统会按字母顺序合并它们，并在浏览器刷新时加载。无需在 `docs.json` 中添加条目，与 Mintlify 引入根样式表的方式一致。[自定义 CSS →](/cn/customization/custom-css)

**从 frontmatter 自定义社交预览。** 直接在页面 frontmatter 中设置任意 Open Graph 或 Twitter/X 元标签，包括 `og:title`、`og:description`、`og:image`、`twitter:card`、`keywords` 以及完整的 metatag 集合。可以使用扁平的顶级键，也可以使用嵌套的 `seo:` 块；两种方式都有效，页面级值会覆盖 `docs.json` 中的默认值。[SEO →](/cn/content/seo)

**隐藏页面。** 无需删除草稿、内部手册或弃用指南，即可将其从侧边栏和搜索结果中移除。在页面 frontmatter 中添加 `hidden: true`，或在 `docs.json` 的组或标签中添加该配置。隐藏页面仍可通过直接 URL 访问，但会从导航、站点地图、站内搜索和 AI 上下文中消失，并自动添加 `noindex` 标签。如果需要隐藏组中的页面仍能出现在搜索排名中，请同时添加 `searchable: true`。[隐藏页面 →](/cn/content/hidden-pages)

**网格和窗口装饰。** 两种新的背景图案加入了 Jam 主题默认的渐变背景。将 `background.decoration` 设置为 `"grid"`，即可使用细微的 24px 点阵网格；设置为 `"windows"`，即可在上方两角显示两个 Windows 11 风格的磨砂光斑。渐变和 `"none"` 平面填充仍可照常使用，请选择符合您品牌风格的外观。[背景 →](/cn/customization/background)

**背景自定义。** `docs.json` 中新增的 `background` 块可以停用 Jam 浅色模式渐变，按模式覆盖页面颜色，或调整渐变的颜色、大小、位置和不透明度。无需使用自定义 CSS。[背景 →](/cn/customization/background)

**D2 图表。** Mermaid 之外现在支持第二种图表语言。将围栏代码块标记为 `d2`，Jamdesk 就会在构建时将其渲染为 SVG，并内置浅色和深色主题。工作流程与 Mermaid 相同，您可以选择最适合当前图表的语言。[D2 图表 →](/cn/components/d2)

**分组搜索结果。** 搜索不再因同一页面命中多个部分而重复显示该页面。命中结果会在搜索模态框中按所属页面分组，默认显示最多三个部分，其余结果可通过内联展开器查看。摘要高亮会保持不变，您可以用更少的扫描次数找到正确部分。

**连接时自动检测 `docs.json`。** 连接 GitHub 仓库时，系统会在仓库中的任意位置查找 `docs.json`。连接流程会扫描整个目录树，如果发现 Mintlify 的 `mint.json`，还会进行提示。无需手动设置即可支持 monorepo 和嵌套配置。[连接 GitHub →](/cn/setup/connecting-github)

**CLI 中的 `docs.json` 位置提示。** 错误位置的配置现在更容易发现。`jamdesk validate`、`jamdesk dev` 和 `jamdesk doctor` 会报告您的 `docs.json` 实际位置，或说明它应放置的位置，而不是显示笼统的“未找到”错误。无需解析堆栈跟踪，几秒即可修复。[CLI 概览 →](/cn/cli/overview)

**符合标准的 hreflang。** hreflang 标签现在会输出有效的 BCP 47 代码。`cn`、`jp` 和 `ja-jp` 等区域文件夹会映射到搜索引擎实际需要的代码（`zh`、`ja`），站点地图 URL 也会进行 XML 转义。每个本地化页面都会在相应区域获得排名，而不会被视为重复内容。[语言 →](/cn/setup/languages)

**自动转换 WebP 图片。** Jamdesk 可以在构建时将 PNG 和 JPG 图片转换为 WebP。转换后的文件通常比原文件小 60–80%，且没有明显的质量损失，因此页面加载更快，无需手动处理图片。在 `docs.json` 中通过 `images.convertToWebp: true` 启用。为确保社交爬虫兼容，favicon、`og:image` 和 `twitter:image` 会保留原格式。新的 **Optimizing images** 步骤会在每次构建期间于仪表板和 CLI 中显示实时进度。[自动图片转换 →](/cn/builds/image-optimization)

**API Playground。** 端点页面现在包含交互式的 ["Try it" button](/cn/api-reference/playground)。填写参数，实时查看代码示例更新，并且无需离开文档即可发送实时请求。所有 API 页面默认启用。OpenAPI 和使用 MDX 编写的端点均支持此功能。
