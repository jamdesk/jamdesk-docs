<Update label="2026 年 9 月" date="2026-09-14">
**使用您自己的登录系统让读者登录。** JWT 身份验证可将文档网站置于您现有的登录系统之后，无需任何人输入共享密码。在 `docs.json` 中启用 `auth.jwt`，在 **Settings** 中生成 Ed25519 签名密钥，并让您的后端在用户打开文档时签发短期令牌。Jamdesk 会验证令牌并启动最长持续 30 天的用户专属会话。在页面中添加 `groups: ["admin"]` 后，只有令牌携带该组的访客才能打开该页面或在侧边栏中看到它；其他人会收到 404。公共路径、frontmatter `public: true` 以及公共导航组会保持更新日志或状态页面开放。您还可以通过令牌使用访客自己的凭据预填充 API 演练场。所有套餐均包含此功能，并且可从密码保护无缝迁移。 [JWT 身份验证 →](/cn/setup/jwt-authentication)

**网站根路径也可导出 Markdown。** 使用 `Accept: text/markdown` 请求文档根路径，或诸如 `/fr` 的语言根路径，或者请求 `/index.md`，即可获得该导航中的第一页，即 HTML 根路径显示的同一页面。没有 `index.mdx` 的网站此前会在这里返回 404，导致多数代理发出的首次请求失败。 [Markdown 源码 →](/cn/ai/markdown-source#网站根路径和语言根路径)
</Update>

<Update label="2026 年 8 月" date="2026-08-20">

**Jamdesk 可将您的文档翻译为 27 种语言。** 在 **Settings → Translations** 中勾选所需语言，每个项目最多五种，且每次构建后都会将翻译页面提交至您的 GitHub 仓库。之后的构建只会重新翻译英文源文件发生变更的页面。已有的翻译或您手动编辑的翻译会保留，直到您点击 **Replace with AI translation**。所有套餐均包含此功能。 [AI 翻译 →](/cn/setup/ai-translation)

**选择您自己的文档 URL。** 子路径托管不再固定为 `/docs`。在自定义域名卡片的子路径字段中输入单个段，例如 `help` 或 `guide`，然后保存。`/docs` 会继续提供服务，规范 URL 会立即迁移到新路径，之前的自定义子路径会在一次重命名期间重定向到新路径，因此您可以按自己的节奏更新代理。 [子路径托管 →](/cn/deploy/subpath-hosting)

**使用 AI 修复，现在更快。** 从构建横幅打开修复预览会更快完成，即使对于大型网站也是如此；再次打开几乎即时完成，因为 Jamdesk 会在文档变更前保留扫描结果。流程保持不变：审核每项建议编辑，应用您批准的内容，Jamdesk 会提交这些修改并重新构建。 [使用 AI 修复 →](/cn/builds/fix-with-ai)

**第四款主题：Halo。** 在 `docs.json` 中设置 `"theme": "halo"`，即可获得温暖圆润的外观：Figtree 字体、沙色背景、卡片上凸显的内容，以及所有内置主题中最大的圆角半径。自定义颜色、字体和 CSS 覆盖与 Jam、Nebula 和 Pulsar 的使用方式相同。 [主题 →](/cn/customization/theming)

**仅通过您自己的域名提供文档。** 在自定义域名卡片中启用 **Custom domain only** 后，直接访问 `YOUR_SLUG.jamdesk.app` 会返回 404，而您的 CNAME 或代理仍可正常工作。Jamdesk 会在开关启用前检查您的在线域名；如果 DNS 出现故障，子域名会再次提供服务，直至恢复。此功能可防止直接访客访问子域名，但不会控制谁能阅读您的文档；请配合密码保护使用。 [仅自定义域名 →](/cn/deploy/custom-domain-only)

**从规范构建完整 API 参考文档。** 使用 `"openapi": { "source": "/openapi/api.yaml", "generate": true }` 将导航标签指向您的 OpenAPI 文件，每次构建都会为每项操作创建页面，并按标签在侧边栏中分组。已提交的端点页面会保留其 slug，因此您可逐页迁移；重命名的路径会从旧 URL 重定向，而非返回 404。 [生成的 API 页面 →](/cn/config/docs-json-reference#navigation-openapi生成的页面)

**读者可选择正在查看的 API 服务器。** 规范中列出多个 `servers` 条目的端点，会在其 URL 旁显示选择器。选择沙盒环境后，会切换基础 URL、复制按钮、所有代码示例以及演练场发送的请求，因此不会有人从沙盒文档中复制生产环境的 `curl`。单服务器端点保持不变。 [API 演练场 →](/cn/api-reference/playground#多个服务器)

**Markdown 会在每个 OpenAPI 描述中渲染。** 表格、列表、链接、`code` 和 **粗体** 会在参数、请求正文、响应和架构描述中以与操作描述相同的方式渲染。此前九个位置的表现不一致，现在都使用同一个渲染器。 [OpenAPI 示例 →](/cn/api-reference/openapi-example)

**端点 Markdown 导出包含身份验证信息。** 获取 API 参考页面的 `.md` 版本时，末尾会包含 `## Authentication` 部分，列出操作所需的方案：类型、请求头名称、Bearer 格式、OAuth 2 作用域以及哪些组合有效。读取导出的代理无需打开您的规范即可构建可用请求。 [Markdown 源码 →](/cn/ai/markdown-source#端点页面导出的内容)

**让页面不出现在搜索中但仍可访问。** 在页面 frontmatter 中添加 `search: false`，该页面会从站内搜索、AI 聊天回答和 MCP 服务器中移除，但仍保留在侧边栏、站点地图和 llms.txt 中。适用于您仍希望可链接和可索引的已替代页面。隐藏和 noindex 页面现在也不会出现在 AI 回答中，此前并非如此。 [仅让页面不出现在搜索中 →](/cn/content/hidden-pages#仅将页面排除在搜索之外)

**`jamdesk validate` 会警告无效配置。** 一些 `docs.json` 键虽被接受却从未渲染，其中尤其是 `asyncapi`，因此配置看似受支持，直到您构建网站才发现没有任何内容。该命令会列出这些键，以及第一个之后多余的 `api.mdx.server` 条目，这些条目始终都会被丢弃。 [CLI 概览 →](/cn/cli/overview)

</Update>

**直接在仪表板中编辑文档。** Web 编辑器现已向所有人开放，无需任何设置。在侧边栏中打开 **Editor**，浏览已连接的仓库、使用实时预览编辑 MDX，并直接提交到您的 GitHub 分支，这会自动触发构建。 [Web 编辑器 →](/cn/development/web-editor)

**在仪表板中使用 AI 修复构建警告。** 当构建完成后存在损坏链接或页面缺少描述时，构建中会显示 **Fix with AI** 横幅，显示可修复的问题数量。打开它可预览每项建议编辑（重写的锚点和建议的页面描述），然后应用您批准的内容。Jamdesk 会将其提交到您的 GitHub 分支并开始新的构建。无法明确解决的内容会单独列出，供您手动修复。 [使用 AI 修复 →](/cn/builds/fix-with-ai)

**无限团队成员。** 现在每个项目在所有套餐中都包含无限团队成员，无需额外付费。此前的 10 人上限和按席位计费已取消，邀请您的整个团队即可。

**让受信任的机器人发布文档。** Dependabot、Renovate 或 CMS 发布机器人等自动化账户不是 Jamdesk 成员，因此其推送默认不会触发构建。现在，当其中一个账户被拒绝时，构建会显示一键式 **Authorize Bot Account** 按钮。批准后，该账户的推送会发布到您的线上网站，如同团队成员的推送。只有项目成员可以授权账户，您可随时在项目 GitHub 设置的 **Allowed automation accounts** 下审核或撤销访问权限。

**您的文档会在每次构建时获得 AI Score。** Jamdesk 现在会在每次构建后自动评估 AI 代理读取已发布文档的效果，并依据开放的 AFDocs 标准评分，结果直接显示在仪表板中。查看 0–100 分数和字母等级，跟踪构建间的趋势，并获取每个问题的通俗修复建议；每项建议均提供 **Copy prompt to fix** 按钮，可将发现的问题交给您的 AI 编程代理。启用 **Email team when score changes**，即可在构建显著改变分数时收到通知。 [AI Score →](/cn/ai/ai-score)
</Update>

**自动修复损坏链接。** 具有明确目标的损坏内部链接警告（输入错误的锚点和跨语言区域锚点偏移）现在可以通过一条命令修复。运行 `jamdesk fix --dry-run` 预览计划变更，然后运行 `jamdesk fix` 应用它们；只会处理正确锚点能解析为真实标题的警告，含糊情况会保留供手动审核。 [CLI 概览 →](/cn/cli/overview)

**使用横幅发布任何通知。** 在 `docs.json` 中添加 `banner`，消息栏会固定在每个页面顶部，即页眉上方，并采用主题的强调色。可内联使用链接、**粗体** 和 *斜体*，并设置 `dismissible: true` 为读者提供关闭按钮（消息变更前将一直保持关闭）。 [横幅 →](/cn/config/docs-json-reference#横幅)

**显示每个页面的最后更新时间。** 在 `docs.json` 中设置 `metadata.timestamp: true`，每个页面的页脚都会显示类似“最后更新于 2026 年 6 月 15 日”的行。日期来自最后一次修改页面的 Git 提交，因此无需手动维护日期，每次构建都会保持准确。 [页面元数据 →](/cn/config/docs-json-reference#metadata)

**设置导航图标样式。** 侧边栏、组、标签、锚点和搜索图标现在支持图标对象上的 `style`（`{ "name": "rocket", "style": "duotone" }`）或样式前缀（`duotone/rocket`）——包括 light、thin、duotone 和 sharp 系列，不再仅限于 solid。 [图标 →](/cn/content/icons#图标对象形式)

**自定义搜索栏。** 使用 `search.prompt` 选择自己的占位文本，并通过 `search.popularPages` 精选访客在空搜索面板中看到的快速链接——每项包含标题、页面 slug 和 Font Awesome 图标。 [搜索配置 →](/cn/config/docs-json-reference#搜索)

**无需嵌入即可收集电子邮件订阅。** 在 **Integrations → Email Signups** 中连接 Resend、Mailchimp、Kit、Loops、beehiiv、Brevo 或 SendGrid，Jamdesk 托管的表单会将读者直接添加到您自己的受众列表中——您的 API 密钥始终保留在我们的后端，不会出现在已发布的网站中。在任意页面添加 [`EmailSubscribe`](/cn/components/email-subscribe) 组件，或设置 `placement: changelog`，即可自动在每个更新日志页面显示订阅框。 [电子邮件订阅 →](/cn/integrations/email-signups)

**通过 Cookie 同意控制分析。** 在 `docs.json` 中添加 `integrations.cookies` 键后，Jamdesk 会在访客同意前阻止所有分析和跟踪脚本——Google Analytics、GTM、Plausible、Crisp、自定义 JavaScript 及其内置分析——同意状态从您的同意横幅设置的 `localStorage` 标志中读取。还可直接从 `docs.json` 加载 Osano 或 Termly 横幅；简短的桥接代码片段会在读者接受时立即切换标志，无需重新加载页面即可加载脚本。 [Cookie 同意 →](/cn/integrations/cookie-consent)

**井然有序的 llms.txt。** 每个网站的 `llms.txt` 现在遵循 llmstxt.org 结构——您的导航标签和组会成为 `##` 部分，因此 AI 代理可以按照侧边栏的组织方式查看文档。多语言网站每种语言都有一个索引：根文件列出默认语言并链接每个翻译索引（例如 `/fr/llms.txt`），使每个索引足够小，避免被任何代理截断。 [llms.txt →](/cn/ai/llms-txt)

**代理可更快找到您的文档。** 每个页面现在都带有对屏幕阅读器静默的不可见指令，引导 AI 代理前往 `llms.txt` 和页面的 `.md` 版本；每个 Markdown 导出都以链接到索引的引用块开头。获取 HTML 的代理不再需要猜测 Markdown 路径是否存在。 [AI 概览 →](/cn/ai/overview)

**在任何位置嵌入更新日志。** 只需一个 `<script>` 标签，即可将“有什么新内容？”启动器放入您自己的应用，并在模态窗口中打开 Jamdesk 更新日志，同时显示按访客区分的未读提示点。从 **Integrations → What's New widget** 生成代码片段，然后使用 `data-` 属性调整启动器模式、位置、模态窗口大小和提示点颜色。在您自己的 Jamdesk 文档中，[`<Widget>`](/cn/components/widget) MDX 组件只需一个标签且无需脚本，即可将相同的实时启动器插入任何页面。 [嵌入更新日志 →](/cn/development/embed-page)

**将 API 规范下载为 zip。** 在任意 API 参考页面中，AI Actions 菜单现在提供 **Download API spec** 选项，可将网站引用的每个 OpenAPI 规范——本地文件和远程 URL——打包为单个 `api-specs.zip`。多文件规范会保留其 `$ref` 文件夹结构，因此下载内容可直接导入 Postman、客户端生成器或您自己的工具链。 [AI Actions →](/cn/ai/ai-actions)

**在构建时验证 OpenAPI 规范。** 每次部署现在都会严格验证 `docs.json` 引用的 OpenAPI 规范，并将任何问题显示为 **非致命构建警告**，而不是使构建失败。您的文档仍会发布；您只会通过电子邮件和仪表板构建列表获知具体问题（带行列号的 YAML 解析错误、无法解析的 `$ref` 或重复的 `operationId`）。在本地，`jamdesk dev` 遇到无效规范时仍会停止，以便您在推送前发现问题。 [CLI 概览 →](/cn/cli/overview)
</Update>

**直接从搜索中询问 AI。** 开始在搜索中输入，然后将问题交给 AI 聊天，而不是打开搜索结果——按 ⌘/Ctrl+Enter 或点击搜索页脚中的 **Ask AI**。问题会追加到您的聊天对话中，以便持续讨论；普通 Enter 仍会跳转至第一个结果。 [AI Chat →](/cn/ai/chat)

**复制回答和对话记录。** 每个 AI 聊天回答都提供复制按钮以获取 Markdown 源码，聊天页眉中的 **Copy transcript** 操作可将整段对话复制为按角色标记的 Markdown——便于粘贴到问题或文档中。 [AI Chat →](/cn/ai/chat)

**更智能的聊天自动滚动。** 仅当您已位于底部时，聊天才会跟随流式回答。向上滚动重新阅读先前回复时，内容会保持原位而不会将您拉回底部；滚回底部后会重新固定。

**本地预览中的自定义 CSS（CLI）。** `jamdesk dev` 会以与已发布构建相同的方式应用自定义 CSS，因此您可在部署前检查样式。将任意 `.css` 文件放在项目根目录中——`style.css`，或多个按字母顺序合并的文件——它会在浏览器刷新时加载。无需添加 `docs.json` 条目，这与 Mintlify 包含根样式表的方式一致。 [自定义 CSS →](/cn/customization/custom-css)

**通过 frontmatter 自定义社交预览。** 可直接在页面 frontmatter 中设置任意 Open Graph 或 Twitter/X 元标签——`og:title`、`og:description`、`og:image`、`twitter:card`、`keywords` 以及完整元标签集。可使用扁平的顶级键或嵌套的 `seo:` 块；两种方式均可使用，且每页值会覆盖 `docs.json` 默认值。 [SEO →](/cn/content/seo)

**隐藏页面。** 无需删除草稿、内部手册或已弃用指南，即可将其排除在侧边栏和搜索结果之外。在页面 frontmatter 中添加 `hidden: true`，或将其添加到 `docs.json` 中的组或标签。隐藏页面仍可通过直接 URL 访问，但会从导航、站点地图、站内搜索和 AI 上下文中消失，并自动获得 `noindex` 标签。需要隐藏组但仍希望页面在搜索中获得排名？在 `hidden` 旁添加 `searchable: true`。 [隐藏页面 →](/cn/content/hidden-pages)

**网格和窗口装饰。** 两种新的背景图案加入 Jam 主题的默认渐变。将 `background.decoration` 设置为 `"grid"` 可获得细微的 24px 点阵网格，或设置为 `"windows"` 可在上方角落显示两个 Windows 11 风格的磨砂光斑。渐变和 `"none"` 纯色填充仍可照常使用——选择符合您品牌的外观。 [背景 →](/cn/customization/background)

**背景自定义。** `docs.json` 中新的 `background` 块可禁用 Jam 浅色模式渐变、按模式覆盖页面颜色，或调整渐变的颜色、大小、位置和不透明度。无需自定义 CSS。 [背景 →](/cn/customization/background)

**D2 图表。** Mermaid 之外新增第二种图表语言。为围栏代码块添加 `d2` 标签，Jamdesk 会将其渲染为构建时生成的 SVG，并内置浅色和深色主题。工作流程与 Mermaid 相同——选择适合所绘图表的语言。 [D2 图表 →](/cn/components/d2)

**分组搜索结果。** 搜索不再为每个部分匹配重复显示同一页面。搜索命中会在搜索模态窗口中归入其父页面，默认最多显示三个部分，其余部分可通过内联展开器查看。代码片段高亮保持不变——您可通过更少的扫描找到正确部分。

**连接时自动检测 `docs.json`。** 连接 GitHub 仓库时，无论 `docs.json` 位于何处都能找到它。连接流程会扫描整个目录树，如果发现 Mintlify `mint.json` 也会提示。单仓库多项目和嵌套配置均无需手动设置即可使用。 [连接 GitHub →](/cn/setup/connecting-github)

**CLI 中的 `docs.json` 位置提示。** 更容易发现放错位置的配置。`jamdesk validate`、`jamdesk dev` 和 `jamdesk doctor` 会报告您的 `docs.json` 实际位置——或应放置的位置——而非显示通用的“未找到”错误。几秒即可修复，无需解读堆栈跟踪。 [CLI 概览 →](/cn/cli/overview)

**符合标准的 hreflang。** Hreflang 标签现在会生成有效的 BCP 47 代码。语言区域文件夹如 `cn`、`jp` 和 `ja-jp` 会映射为搜索引擎实际期望的代码（`zh`、`ja`），站点地图 URL 则经过 XML 转义。每个本地化页面都会在其所属区域中排名，而不会被视为重复内容。 [语言 →](/cn/setup/languages)
</Update>

**PDF 导出。** 在仪表板的 **Settings → PDF Exports** 中，将整个文档网站渲染为单个 [PDF](/cn/builds/pdf-export)。仅限付费套餐。多语言项目可为每次导出选择语言区域，结果按提交缓存，渲染完成后您会收到包含下载链接的电子邮件。

**多语言 OpenAPI 规范。** 端点页面会将翻译后的 OpenAPI 规范与翻译后的 MDX 一起渲染。将 `<spec>.<lang>.<ext>` 文件（例如 `openapi/api.fr.yaml`）放在源规范旁，Jamdesk 会在该语言的 URL 上选用它；若缺少语言变体，则回退到英文规范。操作摘要、参数描述、响应描述和架构描述都会本地化。设置方法：[翻译 OpenAPI 规范](/cn/setup/languages#翻译-openapi-规范)。

**Visibility 组件。** 新的 [`<Visibility for="humans|agents">`](/cn/components/visibility) 组件可让您在同一页面中为人类读者或 AI 代理划分内容。仅限人类的块会在浏览器中渲染，但会从 `.md` 导出和 `llms-full.txt` 中移除；仅限代理的块则相反。请求规范 URL 且使用 `Accept: text/markdown` 的代理会自动获得代理视图。

**密码保护，重新构建。** 使用共享密码锁定整个网站，或者只限制少数页面，其余页面保持公开。设置 `auth.password.enabled: true` 以启用全站模式，或在 frontmatter 中以 `private: true` 标记单个页面（或在 `auth.password.private` 下列出页面）以启用特定页面模式。仪表板中的 Settings 页面会引导您设置、轮换和撤销密码。访客会看到带有网站徽标、主色和可选提示（在 `docs.json` 中定义）的品牌解锁页面。设置指南：[密码保护](/cn/setup/password-protection)。

**自动 WebP 图像转换。** Jamdesk 可在构建时将 PNG 和 JPG 图像转换为 WebP。转换后的文件通常比原文件小 60-80%，且没有可见质量损失，因此页面加载更快，无需任何手动图像处理。在 `docs.json` 中通过 `images.convertToWebp: true` 选择启用。为了兼容社交爬虫，网站图标、`og:image` 和 `twitter:image` 会保留原始格式。新的 **Optimizing images** 步骤会在每次构建期间于仪表板和 CLI 中显示实时进度。 [自动图像转换 →](/cn/builds/image-optimization)

**API 演练场。** 端点页面现在提供交互式 [“Try it”按钮](/cn/api-reference/playground)。填写参数、实时查看代码示例更新，并且无需离开文档即可发送实时请求。默认在所有 API 页面上启用。兼容 OpenAPI 和 MDX 编写的端点。

**Claude Code 插件。** 安装 [Claude Code 的 Jamdesk 插件](/cn/claude-code-plugin)，让 Claude 深入了解 MDX 组件、`docs.json` 配置、导航模式和 CLI 命令。可通过插件市场两步安装。配合 [CLAUDE.md](/cn/ai/claude-code) 和 [MCP 服务器](/cn/ai/mcp-server)，实现 AI 辅助文档编写。

**缺少品牌资源的构建警告。** 当 `docs.json` 中的 `favicon` 或 `logo` 路径引用项目中不存在的文件时，构建现在会发出警告。警告显示在仪表板构建详情中，也可通过 CLI 的 `jamdesk dev` 和 `jamdesk validate` 查看。不会发送电子邮件；该警告仅供参考。

**YouTube Shorts。** [`<YouTube>` 组件](/cn/content/youtube#youtube-shorts) 通过 `short` prop 支持竖版 Shorts，可渲染居中的 9:16 播放器且没有黑边。使用 `<YouTube id="VIDEO_ID" short />`。
