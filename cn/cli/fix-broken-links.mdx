---
title: 修复失效链接
description: >-
  了解 jamdesk fix 如何修复失效的内部链接和拼写错误的锚点，并在写入更改前预览。
---

`jamdesk fix` 用于修复 `jamdesk broken-links` 报告的问题。它读取相同的警告，并在找到唯一明确的正确目标时重写链接。对于存在歧义的情况，它不会改动，留待人工审查。

<Tip>
  [使用 AI 修复](/cn/builds/fix-with-ai) 可在仪表板中对构建执行相同的修复。它还会补充缺失的页面描述，并将更改提交到 GitHub。
</Tip>

它可修复两类失效的内部链接：

- **拼写错误的锚点**：片段是目标页面上某个真实标题的明显拼写错误（例如 `#instalation` → `#installation`）
- **跨语言锚点漂移**：翻译页面重命名了标题，但该语言版本中的链接仍指向旧的英文片段（例如 `/fr/ai/selectors#ai-strategies` → `/fr/ai/selectors#stratégies-ia`）

## 步骤 1：查找失效链接

运行 `jamdesk broken-links` 查看需要修复的内容：

```bash
jamdesk broken-links
```

查看输出结果。`jamdesk fix` 会针对那些能够将可能的锚点与真实标题匹配的警告进行处理。

## 步骤 2：预览修复内容

使用 `--dry-run` 运行，可在不写入文件的情况下查看将要进行的更改：

```bash
jamdesk fix --dry-run
```

**示例输出：**

```text
Planned fixes:

  fr/ai/overview.mdx:9
    /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

(dry run — no files written)
```

逐条检查计划中的修复。如果某项更改看起来有误，请手动修正该链接。

## 步骤 3：应用修复

去掉 `--dry-run` 运行即可应用。CLI 会要求你确认：

```bash
jamdesk fix
```

```text
Apply 1 fix(es) to local files? (y/N)
```

按 `y` 写入更改。在 CI 或脚本中可使用 `-y` 跳过提示：

```bash
jamdesk fix -y
```

命令随后会输出：

```text
Fixed 1 file(s); 0 warning(s) left for manual review.
```

对于目标存在歧义的警告，`jamdesk fix` 会将其保留，供你手动修复。

## 步骤 4：检查差异并提交

提交前检查更改：

```bash
git diff
```

确认每个重写后的链接都指向你预期的位置。然后提交：

```bash
git add -A
git commit -m "fix(docs): auto-fix broken internal links"
```

## 选项

| 参数 | 说明 |
|------|-------------|
| `--dry-run` | 预览计划中的修复，不写入任何文件 |
| `-y, --yes` | 无需确认提示直接应用修复 |
| `--types <list>` | 要修复的警告类型，以逗号分隔（默认：所有受支持的类型） |
