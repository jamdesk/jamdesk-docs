Jamdesk CLI 让你可以在本地预览文档、验证配置、检查失效链接，并从其他平台迁移。它以 [Apache License 2.0](https://github.com/jamdesk/jamdesk-cli) 开源。

## 安装

<Tabs>
  <Tab title="npm (Recommended)">
    从 [npm](https://www.npmjs.com/package/jamdesk) 全局安装，即可在任何位置使用 `jamdesk`：

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    使用 Homebrew 安装：

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    通过脚本安装：

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    升级或卸载：

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    通过脚本安装：

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    升级或卸载：

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    无需安装直接运行：

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

验证安装：

```bash
jamdesk --version
```

### 系统要求

- **Node.js** v20.0.0 或更高版本
- **npm** v8 或更高版本（推荐）

## 快速开始

<Steps>
  <Step title="创建项目">
    创建一个新的文档项目：

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="启动开发服务器">
    运行带热重载的本地开发服务器：

    ```bash
    jamdesk dev
    ```

    你的文档运行在 **http://localhost:3000/docs**
  </Step>
  <Step title="部署前验证">
    检查配置错误、失效链接和拼写：

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## 命令

运行 `jamdesk <command> --help` 查看任意命令的详细信息。

### 开发

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  启动带热重载的本地开发服务器。

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **功能：**
  - 启动时自动验证（docs.json 架构、MDX 语法以及引用的 OpenAPI 规范。规范无效时服务器会停止。）
  - MDX 文件变更时热重载
  - docs.json 变更时自动重建导航
  - 浏览器刷新时重新加载自定义 CSS（`style.css`）
  - 搜索
  - 所有主题和组件

  **选项：**

  | 标志 | 描述 |
  |------|-------------|
  | `-p, --port <port>` | 运行端口（默认：3000） |
  | `-v, --verbose` | 启用详细输出 |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  创建一个新的文档项目。

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  这会创建一个包含以下内容的新项目：
  - `docs.json` 配置文件
  - 示例 MDX 页面
  - 推荐的文件夹结构
</Accordion>

### 验证

<Accordion title="jamdesk validate" icon="check">
  验证你的 `docs.json` 配置、MDX 语法和 OpenAPI 规范。

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **检查内容：**
  - docs.json 中的 JSON 语法是否有效
  - 必填字段（name、navigation）
  - 主题值是否有效
  - MDX 语法错误（例如未转义的 `<` 字符）
  - OpenAPI 规范验证（如已配置）
  - 架构合规性

  **选项：**

  | 标志 | 描述 |
  |------|-------------|
  | `--skip-mdx` | 跳过 MDX 语法验证 |
  | `-v, --verbose` | 显示详细的验证输出 |

  部署前运行此命令，尽早发现错误。
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  扫描文档中失效的内部链接。

  ```bash
  jamdesk broken-links
  ```

  **示例输出：**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  检测指向缺失页面的链接和拼写错误。详情请参阅[链接与导航](/cn/content/links#如何检测内部链接)。
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  自动修复目标明确的失效内部链接警告。它修复两类问题：
  - **拼写错误的锚点**：类似 `#instalation` 的片段，显然应为 `#installation`
  - **跨语言锚点漂移**：翻译页面重命名了标题，但该语言中的链接仍指向旧的英文片段

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **示例 dry-run 输出：**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  仅当修正后的锚点在目标页面上解析为真实标题时，`jamdesk fix` 才会写入修复。对于存在歧义的情况，它会留给人工审查。

  **选项：**

  | 标志 | 描述 |
  |------|-------------|
  | `--dry-run` | 预览计划中的修复，不写入任何文件 |
  | `-y, --yes` | 无需确认提示直接应用修复 |
  | `--types <list>` | 要修复的逗号分隔警告类型（默认：所有支持的类型） |

  <Card title="修复失效链接指南" icon="wrench" href="/cn/cli/fix-broken-links">
    分步指南：预览、应用、审查和提交
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  检查文档中的拼写错误。

  ```bash
  jamdesk spellcheck
  ```

  **示例输出：**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  使用包含 150 多个内置技术术语（API、GraphQL、Kubernetes、React 等）的英文词典。跳过代码块、行内代码、frontmatter、JSX、URL 和文件路径。目前仅支持英文，多语言词典已在规划中。

  **选项：**

  | 标志 | 描述 |
  |------|-------------|
  | `--fix` | 交互式修复拼写错误或添加到忽略列表 |
  | `--json` | 以 JSON 格式输出（用于 CI 流水线） |
  | `-v, --verbose` | 检查时显示每个文件 |

  **交互式修复模式（`--fix`）**会逐个处理每个不重复的拼写错误单词：

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** 会在每个文件中用建议词替换该单词。它绝不会更改代码块或 JSX 属性。提示最多显示 3 个建议，并标记最佳匹配为推荐项。
  - **Ignore** 会将该单词添加到 docs.json 中的 `spellcheck.ignore`。该单词此后不会再被标记。
  - **Skip** 本次运行不做任何处理

  更改在应用前会先预览并需要你确认。

  **自定义忽略列表：** 在 docs.json 中添加项目特定术语：

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  拼写检查会忽略 `docs.json` 中的项目名称。
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  验证单个 OpenAPI 规范文件。

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **验证内容：**
  - YAML/JSON 语法是否有效
  - OpenAPI 3.x 架构合规性
  - 端点定义
  - `$ref` 引用是否正确解析
</Accordion>

<Note>
  **Jamdesk 在三个地方验证 OpenAPI 规范。** 如果引用的规范无效，`jamdesk dev` 会在启动时停止。`jamdesk validate` 和 `jamdesk openapi-check` 按需检查规范。云端构建会在部署时检查引用的规范，此时无效规范是**非致命警告**，文档的其余部分仍会发布。邮件和控制台的构建列表会指明问题：带行号和列号的解析错误、未解析的 `$ref`，或重复的 `operationId`。修复规范并重新推送即可清除该警告。
</Note>

### 文件管理

<Accordion title="jamdesk rename" icon="file-pen">
  重命名页面并更新所有对其的引用。

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **此操作将：**
  - 重命名文件
  - 更新 docs.json 导航
  - 更新所有其他 MDX 文件中的链接
  - 更新代码片段引用

  请使用此命令代替手动重命名，引用将保持同步。
</Accordion>

### 迁移

<Accordion title="jamdesk migrate" icon="right-left">
  将文档从 Mintlify 迁移到 Jamdesk。

  ```bash
  jamdesk migrate
  ```

  它会检测你的 Mintlify 配置并将其转换为 Jamdesk 格式。同一次处理还会：

  - 重命名已弃用的组件（例如 `CardGroup` → `Columns`）
  - 将孤立的代码片段 MDX 文件移入 `/snippets/`，并重写相对父级的导入
  - 将使用 React Hook 的内联组件提取到带 `'use client'` 的 `/snippets/<name>.tsx` 中
  - 修复机械性的 MDX 语法问题

  该命令是幂等的，重复运行是安全的。

### 部署

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  从终端上传你的文档并触发构建。

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  CLI 会在每个构建阶段完成时显示进度。也可以使用 `jamdesk push`。

  | 标志 | 描述 |
  |------|-------------|
  | `--detach` | 排队后立即退出 |
  | `--full-rebuild` | 强制完整重建（不使用缓存） |
  | `--project <id>` | 部署到指定项目 |
  | `--allow-empty` | 允许在没有 `.mdx` 内容页面时部署（默认拒绝） |

  <Card title="CLI 部署指南" icon="cloud-arrow-up" href="/cn/cli/deploy">
    完整的部署流水线、构建阶段、错误参考和故障排除
  </Card>
</Accordion>

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  搭建并部署一个 Cloudflare Worker，将你自有域名上的 `/docs` 代理到你的 Jamdesk 站点。

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --yes
  ```

  该命令默认为交互式。它会检查 Wrangler、验证你的 Cloudflare 账户、从 `docs.json` 检测你的 slug、生成 Worker 文件，并询问是否部署。`--yes` 仅生成文件然后停止。随后可在输出目录中运行 `npx wrangler deploy` 进行部署。

  | 标志 | 描述 |
  |------|-------------|
  | `--slug <slug>` | Jamdesk 项目 slug |
  | `--domain <domain>` | 目标域名（例如 `example.com`） |
  | `--path <path>` | 路径前缀（默认：`/docs`） |
  | `--output-dir <dir>` | 输出目录（默认：`cloudflare-worker/`） |
  | `--skip-deploy` | 在交互式运行中跳过"现在部署？"提示 |
  | `--force` | 若输出目录已存在则覆盖 |
  | `--yes` | 对每个提示使用默认值（CI 模式）。从不部署，也从不覆盖已存在的目录 |

### 维护

<Accordion title="jamdesk doctor" icon="stethoscope">
  检查你的环境并诊断问题。

  ```bash
  jamdesk doctor
  ```

  **检查项：**
  - Node.js 版本（需要 v20+）
  - npm 版本
  - docs.json 是否存在且有效
  - ~/.jamdesk 缓存状态
  - 写入权限

  当 CLI 行为异常时运行此命令。

<Accordion title="jamdesk clean" icon="broom">
  清除 ~/.jamdesk 缓存目录。

  ```bash
  jamdesk clean
  ```

  这会删除已缓存的依赖和构建产物。可用于：
  - 释放磁盘空间
  - 修复损坏的缓存
  - 强制重新安装依赖

  下一次 `jamdesk dev` 会重新安装依赖。
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">

  ```bash
  jamdesk update
  ```

  ```bash
  npm update -g jamdesk
  ```

## 配置

创建 `~/.jamdeskrc` 以设置默认选项：

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| 选项 | 类型 | 默认值 | 描述 |
|--------|------|---------|-------------|
| `defaultPort` | number | 3000 | 开发服务器的默认端口 |
| `verbose` | boolean | false | 默认启用详细输出 |
| `checkUpdates` | boolean | true | 启动时检查 CLI 更新 |

## 故障排除

<AccordionGroup>
  <Accordion title="MDX 语法错误">
    MDX 按 JSX 解析，某些字符有特殊含义。

    **常见问题：** `<` 字符被解释为 JSX 标签的开始。

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **解决方法：**
    - 使用 `&lt;` 表示字面小于号：`Values &lt;50% are low`
    - 改写以避免该字符：使用 `"Below 50%"` 代替 `"<50%"`
    - 运行 `jamdesk validate` 获取带行号的详细错误信息
  </Accordion>

  <Accordion title="找不到 docs.json">
    请在包含 `docs.json` 文件的目录中运行命令。

    **解决方法：**
    - 运行 `jamdesk init` 创建新项目
    - 检查你是否位于正确的目录
    - 确认文件名确切为 `docs.json`（而非 `doc.json` 或类似名称）
  </Accordion>

  <Accordion title="开发服务器无法启动">
    **请尝试以下步骤：**
    1. 运行 `jamdesk doctor` 检查你的环境
    2. 运行 `jamdesk clean` 清除缓存
    3. 使用 `jamdesk dev --verbose` 获取详细的错误输出
    4. 检查是否已安装 Node.js v20+：`node --version`
  </Accordion>

  <Accordion title="首次运行较慢">
    首次运行会将依赖安装到 `~/.jamdesk/node_modules`。

    这只会发生一次，之后的运行会更快。
  </Accordion>

  <Accordion title="端口已被占用">
    另一个进程正在使用默认端口。

    **解决方法：**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="权限被拒绝错误">
    你可能没有缓存目录的写入权限。

    **解决方法：**
    1. 检查 `~/.jamdesk` 的权限：`ls -la ~/.jamdesk`
    2. 修复所有权：`sudo chown -R $(whoami) ~/.jamdesk`
    3. 运行 `jamdesk clean` 后重试
  </Accordion>
</AccordionGroup>
