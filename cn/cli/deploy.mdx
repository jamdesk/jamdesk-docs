`deploy` 命令会打包你的文档，将其上传到 Jamdesk，并从终端触发构建。适用于快速迭代、测试更改，或未连接 GitHub 仓库的项目。

## 快速开始

```bash
jamdesk login        # First time only
jamdesk deploy       # From your project directory
```

## 选项

| 参数 | 说明 |
|------|-------------|
| `--detach` | 将构建加入队列并立即退出（会打印仪表板链接） |
| `--full-rebuild` | 强制完整重建，绕过构建缓存 |
| `--project <id>` | 部署到指定的项目 ID（跳过交互式选择） |
| `--allow-empty` | 允许在没有任何 `.mdx` 内容页面的情况下部署。默认情况下，CLI 会拒绝部署空项目。这可以防止错误的工作目录发布一个空站点。代码片段不计入内容页面 |

`jamdesk push` 是 `jamdesk deploy` 的别名。

## 工作原理

<Steps>
  <Step title="身份验证">
    验证你的会话。令牌过期时会提示你运行 `jamdesk login`。
  </Step>
  <Step title="加载配置">
    读取并验证当前目录中的 `docs.json`。
  </Step>
  <Step title="确定项目">
    从 `docs.json` 中读取 `projectId`。首次部署时该值不存在，此时 CLI 会提示你选择项目。CLI 会将你的选择保存到 `docs.json`，下次部署将跳过该提示。

    使用 `--project <id>` 可覆盖此设置。
  </Step>
  <Step title="打包文件">
    创建文档的压缩 tarball。`.gitignore` 中的文件会被排除。CLI 会对看起来像机密的文件发出警告，但警告不会阻止上传。
  </Step>
  <Step title="上传">
    通过预签名 URL 将 tarball 发送到 Jamdesk。最大上传大小为 100 MB。
  </Step>
  <Step title="构建">
    将构建加入队列并轮询状态。每个阶段完成时都会打印出来。按 Ctrl+C 可停止轮询，构建将在后台继续进行。
  </Step>
  <Step title="完成">
    构建完成时打印实时 URL。
  </Step>
</Steps>

## 构建阶段

CLI 在轮询时会按顺序打印每个阶段：

| 阶段 | 说明 |
|-------|-------------|
| 提取文件 | 解压已上传的 tarball |
| 验证配置 | 检查 `docs.json` 的结构和内容 |
| 准备内容 | 处理 MDX 文件和资源 |
| 构建文档 | 编译页面并生成静态产物 |
| 上传到 CDN | 将构建输出推送到边缘网络 |
| 刷新缓存 | 清除 CDN 上的过期内容 |

## 文件排除

无论 `.gitignore` 如何设置，以下内容始终会被排除在上传之外：

`.git`、`node_modules`、`.next`、`.env`、`.env.*`、`*.pem`、`*.key`、`credentials.json`、`.gcloud`、`.DS_Store`、`Thumbs.db`

`.gitignore` 中列出的所有内容也会被排除。

### 机密文件警告

当 CLI 检测到看起来像机密的文件时会发出警告（但不会阻止操作）：

- `.env` 和 `.env.*` 文件
- `*.pem` 和 `*.key` 文件
- `credentials.json`
- `service_account*.json`
- 以 `secret` 开头的文件

将它们添加到 `.gitignore` 可以抑制警告，并将其排除在上传之外。

## 错误参考

| 错误 | 代码 | 原因 | 解决方法 |
|-------|------|-------|-----|
| 未登录 | `AUTH_REQUIRED` | 没有已保存的凭据 | `jamdesk login` |
| 会话已过期 | `AUTH_EXPIRED` | 令牌刷新失败 | `jamdesk login` |
| 拒绝访问 | `FORBIDDEN` | 不是该项目的成员 | 在仪表板中检查项目成员资格 |
| 未找到项目 | `NOT_FOUND` | 项目 ID 无效 | 核对 ID，或从 docs.json 中移除 `projectId` |
| 构建进行中 | `BUILD_IN_PROGRESS` | 另一个构建正在运行 | 等待或在仪表板中查看 |
| 上传过大 | `TOO_LARGE` | 服务器拒绝上传（100 MB 限制） | 通过 `.gitignore` 排除大文件 |
| 项目过大 | `PROJECT_TOO_LARGE` | 打包时 tarball 超过 100 MB | 通过 `.gitignore` 排除大文件 |
| 没有项目 | `NO_PROJECTS` | 你的账户中没有项目 | 先在仪表板中创建项目 |
| 没有文件 | `EMPTY_PROJECT` | 所有文件都被排除 | 检查 `.gitignore` |
| 没有内容页面 | `NO_CONTENT` | 未找到 `.mdx` 内容页面（代码片段不计入） | 在文档目录中运行，或如果确实要发布空站点，传入 `--allow-empty` |
| 配置无效 | `CONFIG_NOT_FOUND` | `docs.json` 缺失或无效 | 在项目根目录运行，检查配置 |
| 上传失败 | `UPLOAD_FAILED` | 上传期间出现网络问题 | 检查网络连接，然后重试 |
| 构建失败 | `BUILD_FAILED` | 构建服务错误 | 在仪表板中查看构建日志 |

## 故障排除

<AccordionGroup>
  <Accordion title='"A build is already in progress"'>
    每个项目同一时间只能运行一个构建。请等待当前构建完成。可在仪表板的 **Deployments** 下查看状态。
  </Accordion>

  <Accordion title='"docs.json not found or invalid"'>
    请在包含 `docs.json` 的目录中运行该命令。运行 `jamdesk validate` 可检查配置错误。
  </Accordion>

  <Accordion title='"Upload too large"'>
    100 MB 限制适用于所有未被排除的文件压缩后的 tarball。大型图片、视频或数据文件是常见原因。将它们添加到 `.gitignore` 即可排除。
  </Accordion>

  <Accordion title="Deploy hangs during polling">
    按 Ctrl+C 退出。构建会在后台继续运行。请在仪表板中查看状态。如果此问题反复出现，可能是网络丢弃了轮询请求。
  </Accordion>

  <Accordion title='"No projects found"'>
    你的 Jamdesk 账户中至少需要一个项目。请前往 [dashboard.jamdesk.com](https://dashboard.jamdesk.com) 创建。
  </Accordion>
</AccordionGroup>

更多 CLI 故障排除信息，请参阅 [帮助中心 CLI 指南](/cn/help/troubleshooting/cli-issues)。
