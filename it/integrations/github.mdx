Jamdesk usa **due connessioni GitHub separate**, ognuna con una funzione diversa. Questa pagina spiega a cosa serve ciascuna connessione e quando è necessaria.

<Info>
**In breve:** la GitHub App consente a Jamdesk di accedere al repository. Collegando il tuo account personale, i tuoi commit vengono attribuiti a te.
</Info>

<Note>
I progetti Bitbucket Cloud funzionano in modo diverso: una singola autorizzazione OAuth copre l’accesso al repository, il webhook e l’attribuzione delle build. Vedi [Connetti Bitbucket](/it/setup/connecting-bitbucket).
</Note>

## Panoramica

| Connessione | Scopo | Ambito | Obbligatoria? |
|------------|---------|-------|-----------|
| **GitHub App** | Accesso al repository e webhook | Per progetto | Sì |
| **Account personale** | Identità utente e attribuzione | Per utente | Consigliato |

## GitHub App (livello progetto)

La **GitHub App di Jamdesk** viene installata sul tuo account GitHub o sulla tua organizzazione. Concede a Jamdesk l’autorizzazione ad accedere a repository specifici.

### Cosa fa

- **Legge i contenuti del repository** - Clona la documentazione per crearne la build
- **Riceve webhook** - Riceve una notifica quando invii modifiche
- **Segnala lo stato della build** - Mostra lo stato della distribuzione nei commit

### Perché è necessaria

Senza la GitHub App installata, Jamdesk non può:
- Accedere al repository per creare la build della documentazione
- Distribuire automaticamente le modifiche quando le invii
- Mostrare lo stato della build nei commit GitHub

### Come funziona

Quando configuri un progetto, Jamdesk ti guida nella connessione a GitHub. Sono disponibili due opzioni.

#### Crea un repository docs iniziale (impostazione predefinita per i nuovi progetti)

<Steps>
  <Step title="Accedi con GitHub">
    Autorizza Jamdesk a creare un repository sul tuo account o sulla tua organizzazione.
  </Step>
  <Step title="Scegli dove crearlo">
    Seleziona il tuo account personale o un’organizzazione. Jamdesk crea un nuovo repository con una documentazione iniziale già inclusa.
  </Step>
  <Step title="Installa la GitHub App">
    Installa la GitHub App di Jamdesk (oppure concedile l’accesso al nuovo repository) per consentirle di creare la build e distribuire automaticamente la documentazione.
  </Step>
  <Step title="Gli invii avviano le build">
    Ogni invio al branch configurato avvia automaticamente una distribuzione. Personalizza la documentazione iniziale quando vuoi.
  </Step>
</Steps>

#### Connetti un repository esistente

Hai già un repository per la documentazione? Installa la GitHub App di Jamdesk, concedile l’accesso al repository, quindi scegli il repository e il branch in Jamdesk, in **Project Settings → Git Repository**. Da quel momento funziona allo stesso modo.

### Una app, più progetti

Una singola installazione della GitHub App può gestire più progetti Jamdesk:
- Installa l’app una sola volta sul tuo account o sulla tua organizzazione
- Collega repository diversi a progetti Jamdesk diversi
- Ogni progetto ha la propria configurazione di branch e percorso

<Tip>
Per le organizzazioni, è sufficiente che un amministratore installi la GitHub App una sola volta. In seguito, ogni membro del team può creare progetti Jamdesk usando i repository a cui l’app ha accesso.
</Tip>

## Account GitHub personale (livello utente)

Collegando il tuo **account GitHub personale**, associ la tua identità GitHub al tuo profilo Jamdesk. Si tratta di una connessione separata dalla GitHub App.

### Cosa fa

- **Ti identifica** - Associa il tuo nome utente GitHub al tuo account Jamdesk
- **Attribuisce le build** - Mostra chi ha avviato ogni distribuzione
- **Visibilità del team** - Gli altri membri del team possono vedere chi ha apportato le modifiche

### Perché è necessario

Quando invii modifiche a GitHub, Jamdesk deve determinare quale utente ha avviato la build. Se il tuo account non è collegato:

- Jamdesk prova a identificarti tramite l’indirizzo email
- Se l’email dei tuoi commit Git è diversa da quella del tuo account Jamdesk, l’attribuzione non riesce
- Nella cronologia delle build i tuoi commit potrebbero risultare di un "Unknown user"

<Warning>
**Problema comune:** Git è configurato con un’email personale, ma ti sei registrato a Jamdesk con un’email di lavoro. Collega il tuo account GitHub per assicurarti che l’attribuzione sia corretta.
</Warning>

### Controlla la tua email Git

```bash
git config user.email
git config --global user.email "you@company.com"
```

Usa la stessa email associata al tuo account Jamdesk per evitare che nella cronologia delle build i commit risultino di un "Unknown user".

### Come collegare il tuo account

<Steps>
  <Step title="Vai a User Settings">
    Fai clic sul tuo avatar in alto a destra, quindi seleziona **User Settings**.
  </Step>
  <Step title="Trova la sezione GitHub Account">
    Scorri fino alla scheda **GitHub Account**.
  </Step>
  <Step title="Fai clic su Link GitHub Account">
    Si apre una finestra popup di GitHub. Autorizza Jamdesk a leggere il tuo profilo.
  </Step>
  <Step title="Conferma la connessione">
    Il tuo nome utente GitHub appare nel profilo Jamdesk.
  </Step>
</Steps>

## Come funzionano insieme

Considerale come due chiavi separate:

| Chiave | Consente di accedere a | Appartiene a |
|-----|-------|----------|
| GitHub App | Repository | Progetto/organizzazione |
| Collegamento personale | La tua identità | Singolo utente |

### Esempio di team

Considera un team di 3 sviluppatori che lavorano alla documentazione aziendale:

1. **L’amministratore installa la GitHub App** sull’organizzazione
2. **L’amministratore crea un progetto Jamdesk** collegato al repository della documentazione
3. **Ogni sviluppatore collega il proprio account personale**

Da quel momento, quando uno sviluppatore invia modifiche:
- La **GitHub App** consente a Jamdesk di leggere il repository e creare la build
- Il **collegamento personale** identifica chi ha avviato la build

### Esempio di sviluppatore singolo

Anche se lavori da solo, le due connessioni hanno funzioni diverse:
- **GitHub App** - Collega il tuo repository a Jamdesk
- **Collegamento personale** - Fa sì che nella cronologia delle build i tuoi commit riportino il tuo nome

## Disconnessione e scollegamento

Ogni azione rimuove una parte diversa dell’accesso. Ecco cosa comporta ciascuna.

### Disconnettere GitHub (Project Settings)

**Cosa fa:** rimuove la connessione al repository da un singolo progetto Jamdesk.

**Effetti:**
- Le distribuzioni automatiche si interrompono per quel progetto
- La GitHub App rimane installata su GitHub
- Gli altri progetti Jamdesk non subiscono modifiche
- Il collegamento al tuo account personale non subisce modifiche

**Quando usarla:** vuoi collegare un altro repository o interrompere temporaneamente le distribuzioni.

**Come riconnettere:** vai a Project Settings → Git Repository e seleziona un repository.

### Scollegare GitHub (User Settings)

**Cosa fa:** rimuove la tua identità GitHub dal profilo Jamdesk.

**Effetti:**
- Il tuo nome utente GitHub non appare più nel profilo
- L’attribuzione delle build torna a basarsi sulla corrispondenza delle email
- Tutte le connessioni ai repository rimangono attive
- La GitHub App rimane installata

**Quando usarla:** vuoi collegare un altro account GitHub o rimuovere la connessione.

**Come ricollegare:** vai a User Settings → GitHub Account → Link GitHub Account.

### Disinstallare la GitHub App (su GitHub)

**Cosa fa:** rimuove completamente l’accesso di Jamdesk al tuo account GitHub.

**Effetti:**
- **Tutti** i progetti Jamdesk che usano questa installazione perdono l’accesso
- Le distribuzioni automatiche si interrompono per tutti i progetti interessati
- I webhook vengono rimossi
- I collegamenti agli account personali non subiscono modifiche

<Warning>
Disinstalla la GitHub App solo se vuoi rimuovere l’accesso di Jamdesk da TUTTI i tuoi repository. L’operazione interessa ogni progetto Jamdesk collegato al tuo account GitHub.
</Warning>

**Come disinstallarla:**
1. Vai a [GitHub Settings → Applications → Installed GitHub Apps](https://github.com/settings/installations)
2. Trova "Jamdesk" e fai clic su **Configure**
3. Scorri verso il basso e fai clic su **Uninstall**

## Riferimento rapido

| Azione | Posizione | Ambito | Reversibile? |
|--------|----------|-------|-------------|
| **Disconnetti GitHub** | Project Settings → Git Repository | Singolo progetto | Sì - puoi riconnetterlo in qualsiasi momento |
| **Scollega GitHub** | User Settings → GitHub Account | Il tuo account | Sì - puoi ricollegarlo in qualsiasi momento |
| **Disinstalla la GitHub App** | GitHub Settings | Tutti i progetti | Sì - puoi reinstallarla |

## Risoluzione dei problemi

### "Hai già installato Jamdesk?"

Se hai già installato la GitHub App di Jamdesk, facendo clic su "Install GitHub App" verrai indirizzato alla pagina delle impostazioni di GitHub anziché alla pagina di installazione. È normale. Ecco come completare la configurazione:

<Steps>
  <Step title="Trova Repository access">
    Scorri fino alla sezione **Repository access** nella pagina delle impostazioni di GitHub.
  </Step>
  <Step title="Attiva il pulsante Save">
    Se il pulsante Save è disattivato (in grigio), passa da "All repositories" a "Only select repositories", quindi torna all’opzione precedente.
  </Step>
  <Step title="Fai clic su Save">
    Fai clic sul pulsante verde **Save**. Jamdesk rileva la modifica e prosegue con la configurazione.
  </Step>
</Steps>

### Popup bloccato

Se la finestra popup di GitHub non si apre, il browser potrebbe averla bloccata. Cerca l’icona del blocco dei popup nella barra degli indirizzi, consenti i popup da Jamdesk, quindi fai clic su **Try Again**.

### "Le mie build mostrano 'Unknown user'"
Il tuo account GitHub personale non è collegato. Vai a **User Settings → Link GitHub Account**.

### "Il repository non viene visualizzato"
La GitHub App non ha accesso a quel repository. Vai a [GitHub Settings](https://github.com/settings/installations), trova Jamdesk e aggiungi il repository.

### "Le build non vengono attivate"
1. Verifica che il repository sia collegato in **Project Settings → Git Repository**
2. Verifica di inviare le modifiche al branch configurato
3. Controlla la consegna dei webhook nelle impostazioni del repository GitHub

Se tutto è configurato correttamente, è possibile che la persona che ha inviato le modifiche non faccia parte del progetto. Jamdesk crea una build in seguito a un invio solo se proviene da un membro del progetto. Identifica chi ha inviato le modifiche tramite l’account GitHub collegato oppure verificando che l’email del commit corrisponda a quella usata per accedere a Jamdesk.

Se non trova una corrispondenza, la build risulta non riuscita e ne viene indicato il motivo. Il proprietario del progetto riceve un’email, al massimo una alla settimana per persona. Se un invio non modifica nulla nella cartella della documentazione, non viene inviata alcuna email.

Per risolvere il problema, invita la persona in **Project Settings → Members** usando l’email del suo commit. Per accettare l’invito, dovrà accedere a Jamdesk con quell’indirizzo. Se è già un membro, può invece [collegare il proprio account GitHub](#account-github-personale-livello-utente) in User Settings.

### "Non riesco ad accedere ai repository dell'organizzazione"
Un amministratore dell’organizzazione deve approvare l’installazione della GitHub App. Chiedi all’amministratore di installare o approvare Jamdesk nelle impostazioni dell’organizzazione.

### "GitHub continua a rimandarmi alla pagina dell'app Jamdesk"
Probabilmente la tua azienda gestisce il tuo account GitHub e GitHub non consente a questi account di installare app sul proprio account. Consulta la pagina sugli [account GitHub gestiti dall’azienda](/it/help/troubleshooting/github-issues#account-github-gestiti-dallazienda) per risolvere il problema.
