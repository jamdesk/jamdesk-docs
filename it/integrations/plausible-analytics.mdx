Aggiungi Plausible Analytics al tuo sito di documentazione per ottenere dati sul traffico senza cookie né tracciamento cross-site.

<Info>
Plausible è open source e pesa meno di 1 KB. Nella maggior parte delle giurisdizioni non è richiesto un banner per il consenso ai cookie.
</Info>

Se hai bisogno di gestire il consenso (o utilizzi anche GA, GTM o Crisp), consulta [Consenso ai cookie](/it/integrations/cookie-consent).

Scegli una delle due configurazioni:

| Configurazione | Quando usarla | Campo |
|----------------|---------------|-------|
| **Standard** | Utilizzi il piano gratuito di Plausible, oppure un piano a pagamento senza necessità di proxy | `domain` |
| **Script proxy** | Utilizzi un piano a pagamento e vuoi aggirare i blocchi degli ad blocker | `scriptUrl` |

## Configurazione standard (domain)

La maggior parte dei siti utilizza questa configurazione. Registra il tuo sito in Plausible e indica il dominio.

<Steps>

### Registrati a Plausible

Crea un account su [Plausible Analytics](https://plausible.io/) e aggiungi il dominio del tuo sito di documentazione (ad esempio `docs.example.com`).

### Aggiungi il dominio a docs.json

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "domain": "docs.example.com"
    }
  }
}
```

Usa esattamente il dominio registrato: `docs.example.com`, non `www.docs.example.com`.

</Steps>

### Server self-hosted

Se utilizzi la [Community Edition](https://github.com/plausible/community-edition), aggiungi il campo `server`. Indirizza lo script e l'API degli eventi alla tua istanza:

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "domain": "docs.example.com",
      "server": "https://analytics.example.com"
    }
  }
}
```

`server` funziona solo con `domain`. Gli script proxy gestiscono il proprio instradamento.

## Configurazione dello script proxy (scriptUrl)

I piani a pagamento di Plausible offrono script proxy con un nome file univoco (come `pa-XXXXX.js`). Questi aggirano la maggior parte degli ad blocker, perché l'URL dello script non corrisponde alle liste di filtri più comuni.

<Steps>

### Ottieni l'URL dello script proxy

Nelle impostazioni del sito su Plausible, individua la sezione dello script proxy e copia l'URL completo. Ha questo aspetto: `https://plausible.io/js/pa-XXXXX.js`.

### Aggiungi l'URL dello script a docs.json

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "scriptUrl": "https://plausible.io/js/pa-XXXXX.js"
    }
  }
}
```

Ometti `domain` e `server`. L'ID dello script contiene l'identità del tuo sito, e la CDN di Plausible instrada le richieste internamente.

</Steps>

## Verifica dell'installazione

Controlla che i dati arrivino:

1. Avvia una nuova build della documentazione
2. Visita il tuo sito di documentazione pubblicato
3. Controlla la dashboard di Plausible: la tua visita dovrebbe comparire entro pochi secondi
4. In alternativa, apri DevTools, vai alla scheda Network e cerca una richiesta a `plausible.io/js/script.js` (standard) o al tuo script `pa-XXXXX.js` (proxy)

<Note>
Plausible mostra i dati in tempo reale, senza il periodo di attesa di Google Analytics.
</Note>

## Riferimento della configurazione

| Campo | Tipo | Obbligatorio | Descrizione |
|-------|------|--------------|-------------|
| `domain` | `string` | Uno tra `domain` o `scriptUrl` | Il dominio del tuo sito, così come registrato su Plausible. Viene usato come attributo `data-domain` nel tag dello script. |
| `scriptUrl` | `string` | Uno tra `domain` o `scriptUrl` | URL completo di uno script proxy a pagamento di Plausible (`pa-XXXXX.js`). L'identità del sito è incorporata nello script. Il campo domain non è necessario. |
| `server` | `string` | No | URL di un server Plausible self-hosted. Usato solo con `domain`, non con `scriptUrl`. |

## Risoluzione dei problemi

<Accordion title="Non vedo alcun dato in Plausible">
  La causa più comune è il dominio. Deve corrispondere esattamente a quello registrato su Plausible (`docs.example.com`, non `www.docs.example.com`).

  Se il dominio è corretto:

  1. Ricostruisci la documentazione. Le modifiche alla configurazione hanno effetto solo dopo una nuova build.
  2. Controlla gli ad blocker. Alcune estensioni del browser bloccano gli script di analisi, incluso Plausible. Se è questo il problema, passa alla [configurazione dello script proxy](#configurazione-dello-script-proxy-scripturl).
  3. Ispeziona il codice sorgente della pagina alla ricerca di un tag `<script>` con `data-domain` (standard) o con il nome file `pa-XXXXX.js` (proxy). Se non c'è, la configurazione non è stata applicata.
</Accordion>

<Accordion title="Uso un dominio personalizzato o una sottodirectory">
  Registra il dominio che visitano i lettori. Se la documentazione si trova su `docs.example.com`, usa quello come `domain`, non il dominio principale.
</Accordion>

<Accordion title="Lo script viene bloccato dagli ad blocker">
  Passa alla [configurazione dello script proxy](#configurazione-dello-script-proxy-scripturl). Il nome file univoco aggira la maggior parte delle liste di filtri degli ad blocker. Anche l'hosting self-hosted evita il blocco, perché lo script viene caricato dal tuo dominio.
</Accordion>

<Accordion title="Quando usare domain o scriptUrl">
  Usa `domain` se sei sul piano gratuito o non ti preoccupano gli ad blocker. Usa `scriptUrl` se sei su un piano a pagamento e vuoi la massima copertura del tracciamento. Non impostare entrambi.
</Accordion>
