Ogni build attraversa diverse fasi, dalla coda fino alla pubblicazione. Monitora l'avanzamento dalla scheda Deployments.

## Fasi della build

<Steps>
  <Step title="Queued">
    La build è in attesa di iniziare. La maggior parte delle build parte in pochi secondi.
  </Step>
  <Step title="Cloning">
    Recupero del contenuto del repository da GitHub.
  </Step>
  <Step title="Validating">
    Verifica della configurazione `docs.json` e della sintassi MDX.
  </Step>
  <Step title="Processing">
    Analisi dei file MDX e risoluzione degli import.
  </Step>
  <Step title="Building">
    Compilazione di MDX in HTML e applicazione dell'evidenziazione della sintassi.
  </Step>
  <Step title="Deploying">
    Caricamento su CDN e svuotamento della cache.
  </Step>
  <Step title="Live">
    Build completata. La documentazione è aggiornata.
  </Step>
</Steps>

## Visualizzazione dello stato della build

### Panoramica del dashboard

La pagina principale del progetto mostra:

- Stato attuale della build
- Ora dell'ultimo deploy riuscito
- Cronologia recente delle build

### Dettagli della build

Fai clic su una build qualsiasi per vedere:

- Ora di inizio e di fine
- Durata
- Avviata da (push, manuale, CLI)
- Hash e messaggio del commit
- Log completo della build

### Avvisi e suggerimenti

Le build completate possono includere due livelli di feedback:

- **Avvisi** (badge arancione): problemi da risolvere, come link interrotti o asset mancanti. Non fanno mai fallire la build.
- **Suggerimenti** (lampadina): miglioramenti facoltativi per il branding e la SEO del sito, come l'aggiunta di un [favicon, una descrizione o un logo](/it/customization/branding). I suggerimenti compaiono solo nell'ultima build completata e non contano nel badge degli avvisi. Jamdesk non li invia mai via email.

[Fix with AI](/it/builds/fix-with-ai) risolve molti avvisi di link interrotti e descrizioni mancanti nell'ultima build. Puoi rivedere e applicare le modifiche senza modificare manualmente l'MDX.

## Log delle build

I log dettagliati aiutano a fare debug dei problemi:

```text
[12:34:56] Starting build...
[12:34:57] Cloning repository...
[12:34:59] Found docs.json at root
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Notifiche delle build

Jamdesk può avvisarti via email o Slack quando una build termina o fallisce:

### Email

Abilita gli avvisi di fallimento della build in **Settings** → **Notifications**.

### Slack

Collega Slack per ricevere le notifiche di build nel tuo canale. Vedi [Integrazione Slack](/it/integrations/slack).

## Cronologia delle build

Visualizza le ultime 30 build nella scheda **Deployments**:

- Stato della build (success, failed, cancelled)
- Durata
- Tipo di attivazione
- Informazioni sul commit

## Annullamento delle build

Per annullare una build in esecuzione:

1. Vai alla scheda **Deployments**
2. Trova la build in esecuzione
3. Fai clic su **Cancel**

L'ultima build riuscita resta online.
