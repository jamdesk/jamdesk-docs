---

Ogni build attraversa diverse fasi, dalla coda alla pubblicazione. Monitora l'avanzamento dalla scheda **Deployments**.

## Fasi della build

<Steps>
  <Step title="In coda">
    La build è in attesa di iniziare. La maggior parte delle build inizia entro pochi secondi.
  </Step>
  <Step title="Clonazione">
    Recupero dei contenuti del repository da GitHub.
  </Step>
  <Step title="Validazione">
    Verifica della configurazione `docs.json` e della sintassi MDX.
  </Step>
  <Step title="Elaborazione">
    Analisi dei file MDX e risoluzione degli import.
  </Step>
  <Step title="Build">
    Compilazione di MDX in HTML e applicazione dell'evidenziazione della sintassi.
  </Step>
  <Step title="Deploy">
    Caricamento sul CDN e svuotamento della cache.
  </Step>
  <Step title="Live">
    Build completata. La documentazione è aggiornata.
  </Step>
</Steps>

## Visualizzazione dello stato della build

### Panoramica del dashboard

La pagina principale del progetto mostra:

- Stato attuale della build
- Data e ora dell'ultimo deploy riuscito
- Cronologia recente delle build

### Dettagli della build

Fai clic su una build per visualizzare:

- Ora di inizio e di fine
- Durata
- Attivata da (push, manuale, CLI)
- Hash e messaggio del commit
- Log completo della build

### Avvisi e suggerimenti

Le build completate possono includere due livelli di feedback:

- **Avvisi** (badge arancione): problemi da risolvere, come link non funzionanti o risorse mancanti. Non causano mai il fallimento della build.
- **Suggerimenti** (lampadina): miglioramenti facoltativi per il branding e la SEO del sito, come aggiungere una [favicon, una descrizione o un logo](/it/customization/branding). I suggerimenti vengono mostrati solo nell'ultima build completata, non contribuiscono al badge degli avvisi e non vengono mai inviati via email.

Molti avvisi relativi a link non funzionanti e descrizioni mancanti possono essere corretti automaticamente. Quando l'ultima build contiene problemi risolvibili, usa [Fix with AI](/it/builds/fix-with-ai) per esaminare e applicare le modifiche senza modificare manualmente i file MDX.

## Log delle build

I log dettagliati aiutano a eseguire il debug dei problemi:

```text

[12:34:57] Cloning repository...
[12:34:59] Found docs.json at root
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Notifiche delle build

Jamdesk può inviarti un avviso via email o Slack quando una build termina o non va a buon fine:

### Email

Abilita gli avvisi per i fallimenti delle build in **Settings** → **Notifications**.

### Slack

Collega Slack per ricevere le notifiche delle build nel tuo canale. Consulta [Integrazione Slack](/it/integrations/slack).

## Cronologia delle build

Visualizza le ultime 30 build nella scheda **Deployments**:

- Stato della build (riuscita, non riuscita, annullata)
- Durata
- Tipo di attivazione
- Informazioni sul commit

## Annullamento delle build

Per annullare una build in esecuzione:

1. Vai alla scheda **Deployments**
2. Individua la build in esecuzione
3. Fai clic su **Cancel**

La build riuscita precedente rimane attiva.
