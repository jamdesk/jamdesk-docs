Il log di build mostra cosa si è rotto e dove. Trova il tuo messaggio di errore qui sotto.

## Visualizzare i dettagli dell'errore

1. Apri la scheda **Deployments** del tuo progetto
2. Clicca sulla build non riuscita
3. Leggi il messaggio di errore e scorri il log di build

Il log indica il file e la riga esatta che hanno interrotto la build.

## Errori comuni

### Errori di configurazione

`Invalid docs.json` significa che il file di configurazione non può essere analizzato. La causa più comune è una virgola fuori posto, una parentesi non chiusa o un apice mancante.

<Steps>
  <Step title="Controlla la sintassi JSON">
    Cerca virgole, parentesi o apici mancanti.
  </Step>
  <Step title="Valida in locale">
    Esegui `jamdesk validate` per vedere gli errori esatti.
  </Step>
  <Step title="Correggi e pubblica">
    Correggili e fai push per avviare una nuova build.
  </Step>
</Steps>

### Pagine mancanti

`Page not found` significa che la tua navigazione punta a un file che non esiste. Controlla il nome del file rispetto al percorso in `docs.json`. Le maiuscole devono corrispondere esattamente. Ometti l'estensione `.mdx`.

### Errori di sintassi MDX

`MDX compilation failed` indica MDX o JSX malformato in una pagina. Di solito si tratta di un tag non chiuso (un `<Card>` senza il corrispondente `</Card>`), di un carattere non escapato come una `{` letterale dove intendevi `\{`, oppure di una sintassi di prop non valida.

### Timeout della build

`Build exceeded time limit` significa che la build ha superato il tempo massimo consentito. La causa più comune sono immagini grandi e non ottimizzate. Comprimile, dividi le pagine molto grandi e rimuovi quelle che non pubblichi più.

## Avvisi della build

Gli avvisi non fanno mai fallire una build. Il tuo sito viene comunque pubblicato. Gli avvisi compaiono nell'email degli avvisi di build, nella voce della build nella scheda **Deployments** e nel terminale quando esegui `jamdesk validate` o `jamdesk dev`.

### Immagini mancanti

`Image not found` avvisa che una pagina fa riferimento a un'immagine che il tuo progetto non contiene.

Jamdesk verifica ogni riferimento a un'immagine (Markdown `![alt](/images/photo.webp)` più il `src` nei tag `<img>` e `<Image>`) rispetto ai file del tuo repository. L'avviso indica la pagina, il numero di riga e il percorso che non è stato possibile risolvere.

Carica l'immagine oppure indica un percorso verso un file esistente. I percorsi sono sensibili alle maiuscole. Un percorso che inizia con `/` si risolve dalla radice del progetto. Ogni altro percorso si risolve in relazione alla pagina. Un riferimento a `photo.png` continua a funzionare dopo che [l'ottimizzazione delle immagini](/it/builds/image-optimization) la converte in WebP.

Jamdesk ignora gli URL esterni, gli URI `data:` e la sintassi delle immagini all'interno dei blocchi di codice.

## Passaggi di debug

<Accordion title="Passo 1: Controlla il log di build">
  Il log indica il file e la riga esatta alla base dell'errore. Inizia da lì.
</Accordion>

<Accordion title="Passo 2: Testa in locale">
  Esegui `jamdesk dev` per riprodurre il problema in locale.
</Accordion>

<Accordion title="Passo 3: Valida la configurazione">
  Esegui `jamdesk validate` per controllare `docs.json`. Esegui `jamdesk broken-links` per trovare i link interni non funzionanti.
</Accordion>

<Accordion title="Passo 4: Controlla le modifiche recenti">
  Osserva il tuo ultimo commit. Hai aggiunto una pagina o modificato la configurazione?
</Accordion>

## Il problema persiste?

Se nessuna delle soluzioni sopra funziona:

1. Copia l'intero log di build
2. Annota il tuo ID progetto (si trova nell'URL)
3. [Contatta il supporto](/it/help/support/contact)
