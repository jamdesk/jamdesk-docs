---
title: Conversione automatica immagini
description: >-
  Attiva la conversione automatica da PNG e JPG a WebP in Jamdesk per ridurre le dimensioni delle immagini e velocizzare il caricamento delle pagine.
---

Jamdesk può convertire le immagini PNG e JPG in formato WebP durante la build. I file WebP sono in genere più piccoli del 60-80% rispetto agli originali, senza alcuna perdita di qualità visibile. Le pagine si caricano più velocemente senza alcuna elaborazione manuale delle immagini.

La funzione è **disattivata per impostazione predefinita**. Attivala nel tuo `docs.json`.

## Attivarla

Aggiungi il campo `images.convertToWebp` al tuo `docs.json`:

```json docs.json
{
  "images": {
    "convertToWebp": true
  }
}
```

Questo è l'unico interruttore. La pagina Settings della dashboard mostra lo stato attuale in **Config Highlights**, ma non ha un proprio interruttore. Il riferimento è `docs.json`.

## Cosa viene convertito

| Origine | Convertito? |
|--------|------------|
| PNG | Sì |
| JPG / JPEG | Sì |
| SVG | No (già vettoriale) |
| GIF | No (l'animazione andrebbe persa) |
| ICO | No (troppo piccolo per essere rilevante) |
| WebP | No (già ottimizzato) |

Le immagini convertite mantengono il nome base e ricevono l'estensione `.webp`. Jamdesk riscrive ogni riferimento nei tuoi MDX, CSS personalizzato, JS personalizzato e `docs.json`. Non devi modificare nessun percorso.

## Cosa rimane nel formato originale

Alcune immagini non vengono modificate, anche quando la conversione è attiva.

**Favicon.** Non tutti i browser o client di posta visualizzano correttamente i favicon WebP.

Le immagini per i social media (`og:image` e `twitter:image` in `seo.metatags`) restano nel formato originale. I crawler dei social come Facebook, LinkedIn, WhatsApp e le versioni precedenti di Twitter/X non supportano sempre il WebP. Una scheda di anteprima non funzionante è peggio di un JPG leggermente più grande.

Anche le immagini non utilizzate non vengono convertite. Un file nella tua directory `/images` a cui nessun MDX o configurazione fa riferimento viene caricato sulla CDN nel formato originale.

Jamdesk mantiene l'originale quando l'output WebP risulterebbe più grande del file di partenza. Succede spesso con JPG già compressi e PNG molto piccoli. Questi compaiono come `skipped` nelle statistiche di build.

`background.image` *viene* convertito. È uno sfondo a schermo intero renderizzato dal browser.

## Indicatore di avanzamento del build

Le build con la funzione attiva mostrano un passaggio **Ottimizzazione immagini** nell'elenco di avanzamento della dashboard, tra "Build della documentazione" e "Caricamento sulla CDN". Anche la CLI `jamdesk deploy` mostra lo stesso passaggio nell'output del terminale. Il passaggio non compare quando la funzione è disattivata.

## Caching dei build

Jamdesk memorizza nel manifest di build un hash di ogni immagine sorgente. Jamdesk salta la conversione per un file che non è cambiato dall'ultima build e riutilizza il WebP in cache. Le ricostruzioni restano veloci anche con centinaia di immagini.

## Gestione degli errori

Jamdesk mantiene l'originale quando la conversione di un'immagine fallisce (file corrotto, memoria esaurita, formato imprevisto). Il resto della build prosegue.

## Log del build

I log di build includono una riga come questa:

```text
Optimizing images... done (4 converted, 2 cached, 1 skipped, 0 failed, saved 1.2 MB)
```

| Campo | Significato |
|-------|---------|
| converted | Immagini convertite da PNG/JPG a WebP in questa build |
| cached | Immagini invariate riportate dalla build precedente |
| skipped | Immagini lasciate come originali (campi protetti, file non utilizzati o formati che non richiedono conversione) |
| failed | Conversioni non riuscite (originali mantenuti) |
| saved | Byte totali risparmiati sulle immagini convertite |
