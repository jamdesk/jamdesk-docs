Esegui un push su GitHub e Jamdesk avvierà automaticamente la build. Puoi anche avviare le build dal dashboard.

## Build automatiche

Ogni push sul ramo collegato avvia automaticamente una build:

1. Esegui il push delle modifiche su GitHub
2. GitHub invia un Webhook a Jamdesk
3. Jamdesk mette in coda e avvia la build
4. La documentazione compilata viene pubblicata sul CDN

<Tip>
Le build utilizzano il debouncing. Se esegui rapidamente il push di più commit, Jamdesk attende 10 secondi che l'attività si stabilizzi prima di avviare la build.
</Tip>

## Build manuali

Avvia una build senza eseguire il push delle modifiche:

<Steps>
  <Step title="Apri il progetto">
    Vai al progetto nel dashboard.
  </Step>
  <Step title="Vai a Settings">
    Fai clic su **Settings** nella barra laterale.
  </Step>
  <Step title="Fai clic su Rebuild">
    Seleziona **Rebuild** per avviare una nuova build.
  </Step>
</Steps>

### Quando utilizzare le build manuali

- Dopo aver modificato le variabili d'ambiente
- Per aggiornare il progetto dopo una build non riuscita
- Dopo gli aggiornamenti della piattaforma Jamdesk
- Per eliminare i contenuti memorizzati nella cache

## Coda delle build

Durante i periodi di traffico intenso, le build possono rimanere brevemente in coda. La posizione nella coda viene mostrata nel dashboard. Le build vengono elaborate nell'ordine di ricezione.

## Build concorrenti

Ogni progetto può eseguire una sola build alla volta. I nuovi trigger durante l'esecuzione di una build vengono messi in coda.
