Jamdesk compila la tua documentazione a ogni push su GitHub. Puoi anche attivare una build dalla dashboard.

## Build automatiche

Ogni push sul branch collegato attiva una build:

1. Esegui il push delle modifiche su GitHub
2. GitHub invia un webhook a Jamdesk
3. Jamdesk accoda e avvia la tua build
4. La documentazione compilata viene distribuita sulla CDN

<Tip>
Le build sono sottoposte a debouncing. Jamdesk attende 10 secondi senza nuovi push, poi avvia la build.
</Tip>

## Build manuali

Attiva una build senza eseguire push di modifiche:

<Steps>
  <Step title="Apri il tuo progetto">
    Vai al tuo progetto nella dashboard.
  </Step>
  <Step title="Vai a Settings">
    Fai clic su **Settings** nella barra laterale.
  </Step>
  <Step title="Fai clic su Rebuild">
    Seleziona **Rebuild**. Viene avviata una nuova build.
  </Step>
</Steps>

### Quando utilizzare le build manuali

- Dopo aver modificato le variabili d'ambiente
- Per aggiornare dopo una build non riuscita
- Dopo gli aggiornamenti della piattaforma Jamdesk
- Per cancellare i contenuti in cache

## Coda delle build

Le build possono essere accodate brevemente durante i periodi di traffico elevato. La dashboard mostra la posizione in coda. Le build vengono eseguite nell'ordine di ricezione.

## Build concorrenti

Ogni progetto esegue una build alla volta. Un'attivazione che arriva durante una build in corso attende in coda.

| Piano | Progetti concorrenti |
