Jamdesk può correggere molti link non funzionanti e molte descrizioni mancanti segnalati da una build. Il pulsante **Fix with AI** legge gli avvisi della build e propone una modifica per ciascuno. Esegue il commit delle correzioni approvate nel repository GitHub collegato. Il commit avvia una nuova build.

Il [comando CLI `jamdesk fix`](/it/cli/fix-broken-links) fa lo stesso dal terminale. Modifica la copia di lavoro e lascia a te il commit.

## Cosa corregge

Fix with AI corregge tre tipi di avvisi della build:

- **Link interni non funzionanti:** un frammento di link che punta a un titolo inesistente nella pagina di destinazione, per esempio per un errore di battitura (`#instalation` → `#installation`), oppure a una pagina tradotta il cui titolo è stato rinominato.
- **Descrizioni mancanti:** una pagina senza `description` nel frontmatter. Jamdesk genera un breve riepilogo dal contenuto della pagina, che puoi rivedere.
- **Titoli mancanti:** per una pagina senza titolo, propone un titolo basato sul contenuto, che puoi rivedere.

Propone una modifica solo quando riesce a individuare la soluzione con sicurezza. Elenca separatamente gli elementi ambigui, così puoi correggerli manualmente.

Fix with AI può effettuare fino a 1.000 richieste IA per progetto in un periodo di 24 ore. I risultati per le pagine che non sono cambiate vengono riutilizzati e non concorrono al limite.

<Note>
  Il numero di elementi correggibili non coincide con quello degli avvisi. Una build può mostrare cinque avvisi, mentre Fix with AI ne propone la correzione per tre. Gli altri due non hanno una soluzione univoca.
</Note>

## Prerequisiti

- Un [repository GitHub collegato](/it/integrations/github) al progetto.
- L’app GitHub di Jamdesk deve avere accesso in scrittura per eseguire il commit delle correzioni. Se l’accesso manca, la finestra modale mostra il link **Grant access** a GitHub.
- Una build completata che segnali link non funzionanti o descrizioni mancanti.

## Trova il banner

Apri il progetto e scorri fino a **Build History** nella pagina Project Home. Quando l’ultima build presenta problemi correggibili, sopra l’elenco delle build compare un banner con il relativo conteggio e il pulsante **Fix with AI**.

## Rivedi e applica le correzioni

<Steps>
  <Step title="Apri l’anteprima">
    Fai clic su **Fix with AI**. Si apre la finestra modale. L’agente IA impiega alcuni secondi per esaminare la documentazione e preparare un piano di correzione.
  </Step>
  <Step title="Esamina ogni modifica proposta">
    Le correzioni sono raggruppate per tipo. **Broken links** mostra ogni ancora riscritta. **Missing descriptions** mostra il riepilogo suggerito per ciascuna pagina. **Missing titles** mostra il titolo proposto. Deseleziona la casella di un elemento per ignorarlo questa volta. Usa il pulsante di esclusione per [ignorare definitivamente una raccomandazione](#ignora-i-suggerimenti). Gli elementi senza una soluzione chiara compaiono in **Can't be fixed automatically** e puoi correggerli manualmente.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="Finestra modale Fix with AI. Una sezione Broken links elenca tre correzioni selezionate, ciascuna con la vecchia ancora barrata e quella corretta. Una sezione Can't be fixed automatically elenca due problemi da correggere manualmente, sopra i pulsanti Cancel e Apply 3 fixes." />
    </Frame>
  </Step>
  <Step title="Apply">
    Fai clic su **Apply fixes**. Jamdesk esegue il commit delle modifiche selezionate sul branch collegato con il messaggio `docs: apply AI-suggested fixes (via Jamdesk)` e avvia una nuova build.
  </Step>
  <Step title="Verifica la nuova build">
    Segui la nuova build in [Build History](/it/builds/monitoring). Gli avvisi corretti scompaiono una volta che la build è pubblicata. Gli eventuali avvisi rimasti non sono risolvibili da Fix with AI oppure riguardano nuovi problemi introdotti dai contenuti più recenti.
  </Step>
</Steps>

<Note>
  L’applicazione delle correzioni crea un commit effettivo nel repository. Puoi esaminarlo o annullarlo su GitHub come qualsiasi altro commit.
</Note>

## Quando alcuni problemi non possono essere corretti

La finestra modale elenca sotto un titolo separato gli avvisi senza una soluzione chiara e non li modifica. Ecco alcuni motivi comuni:

- La pagina o il titolo di destinazione di un link non funzionante non esiste.
- Una voce di navigazione non ha un file sorgente corrispondente.
- L’agente non è riuscito a generare una descrizione per una pagina.

Questi problemi richiedono una modifica manuale. Apri la pagina nell’[editor](/it/development/local-preview) o nel tuo editor di codice. Correggi il link o aggiungi la descrizione. Esegui il push per avviare una nuova build.

## Ignora i suggerimenti

Alcuni avvisi non richiedono interventi: per esempio un link che hai interrotto intenzionalmente o una pagina provvisoria che non ha bisogno di una descrizione. Deselezionare una correzione la ignora solo una volta. Ignorare un elemento lo rimuove dal conteggio finché non lo ripristini.

Nella finestra modale ogni riga ha un pulsante per ignorarla, che sia correggibile o meno. Facendo clic, l’elemento viene spostato nella sezione **Ignored**, compressa, in fondo alla finestra. Dopo averla chiusa, il conteggio del banner nella pagina Project Home si aggiorna. Gli avvisi corrispondenti scompaiono da Build History nella build attuale e in tutte quelle successive. **Ignore all** fa lo stesso per tutti gli elementi ancora elencati.

Come funzionano gli elementi ignorati:

- **Condivisi e persistenti:** gli elementi ignorati si applicano all’intero progetto. Tutti i membri vedono lo stesso elenco, che persiste tra le build. Jamdesk abbina ogni avviso in base al contenuto, non al numero di riga. Modificare altre parti della pagina non fa ricomparire un elemento ignorato.
- **Ripristino:** espandi la sezione **Ignored** e fai clic su **Restore** accanto a un elemento. Se ignori tutti gli elementi di una build, il banner scompare. Sotto Build History compare quindi un piccolo link «N ignored recommendations», che riapre la finestra modale.
- **Gli avvisi modificati ricompaiono:** un elemento ignorato viene proposto di nuovo quando cambia il problema sottostante, per esempio se il link non funzionante punta ora altrove.

## Fix with AI e CLI a confronto

Il dashboard e la CLI correggono le ancore dei link non funzionanti. Si differenziano per il luogo in cui vengono eseguiti e per il modo in cui viene applicata la modifica.

| | Fix with AI (dashboard) | [`jamdesk fix`](/it/cli/fix-broken-links) (CLI) |
|---|---|---|
| Esecuzione | Nel dashboard, su una build | Nel terminale, sui file locali |
| Correzioni | Link non funzionanti e descrizioni mancanti | Ancore dei link non funzionanti |
| Commit | Esegue il commit sul tuo branch | Modifica i file locali; esegui tu il commit |
| Avvio | Un clic sul banner della build | `jamdesk fix` |

Usa il flusso del dashboard per correggere rapidamente un problema senza uscire da Jamdesk. Usa la CLI se vuoi prima applicare le modifiche alla copia di lavoro, per esempio per includerle insieme ad altre modifiche.
