Jamdesk può riparare molti dei link interrotti e delle descrizioni di pagina mancanti segnalati durante un build. Il pulsante **Correggi con l'AI** legge gli avvisi di build e propone una modifica per ciascuno. Esegue il commit delle correzioni che approvi nel tuo repository GitHub collegato. Il commit avvia un nuovo build.

Gli screenshot mostrano l'interfaccia in inglese.

Il [comando CLI `jamdesk fix`](/it/cli/fix-broken-links) fa lo stesso dal terminale. Scrive nella tua copia di lavoro e lascia il commit a te.

## Cosa corregge

Correggi con l'AI ripara tre tipi di avviso di build:

- **Link interni interrotti:** un frammento di link che punta a un'intestazione non più presente nella pagina di destinazione, come un refuso (`#instalation` → `#installation`), oppure una pagina tradotta la cui intestazione è stata rinominata.
- **Descrizioni di pagina mancanti:** una pagina senza `description` nel frontmatter. Jamdesk scrive un breve riassunto dal contenuto della pagina da rivedere.
- **Titoli di pagina mancanti:** a una pagina senza titolo viene suggerito un titolo dal contenuto, da rivedere.

Propone una modifica solo quando può risolvere la destinazione con sicurezza. Elenca separatamente ciò che è ambiguo, da correggere a mano.

Correggi con l'AI effettua fino a 1.000 richieste AI per progetto in un periodo di 24 ore. I risultati per le pagine non modificate vengono riutilizzati e non contano nel limite.

<Note>
  Il numero di elementi correggibili non coincide con il numero di avvisi. Un build può mostrare cinque avvisi mentre Correggi con l'AI ne offre tre da riparare. Gli altri due non hanno una correzione univoca.
</Note>

## Scegli cosa succede

L'impostazione **Correzioni AI** decide cosa fa Jamdesk con gli avvisi correggibili. Per modificarla, fai clic su **Impostazioni** nella barra laterale e individua la scheda **Correzioni AI** in **Generali**.

| Modalità | Cosa succede |
|---|---|
| **Off** | Jamdesk non analizza i build. Il pulsante **Correggi con l'AI** è nascosto. |
| **Rivedi prima** | Jamdesk suggerisce le correzioni. Le revisioni e le applichi nella finestra. È l'impostazione predefinita. |
| **Correzione automatica** | Jamdesk esegue il commit delle correzioni dopo ogni build. Puoi annullare ogni esecuzione. |

### Come funziona la correzione automatica

La correzione automatica applica le stesse correzioni della finestra, comprese le descrizioni scritte dall'AI. Salta ciò che hai ignorato. Inizia dal build successivo al salvataggio dell'impostazione.

Dopo un build, Jamdesk esegue il commit delle correzioni nel branch di build del progetto. Il messaggio di commit è `docs: auto-fix 3 issues (via Jamdesk)` e l'autore è Jamdesk. Il build mostra un badge **Corretto automaticamente** nella Cronologia build. Per [documentazione senza GitHub](/it/setup/without-github), Jamdesk salva invece le correzioni nella tua documentazione.

<Warning>
  Jamdesk esegue il commit sul tuo branch. Esegui il pull prima del push. Ogni commit di correzione automatica esegue anche eventuali CI presenti nel repository su quel branch.
</Warning>

Cosa aspettarsi da ogni esecuzione:

- Jamdesk non corregge automaticamente il build del proprio commit. Se quel build ha ancora avvisi correggibili, mostra **Da rivedere** e le applichi dalla finestra.
- Una correzione viene applicata una sola volta. Se la annulli, Jamdesk non la riapplica, quindi il tuo ripristino resta. Una correzione che ritorna compare sotto **Da rivedere**.
- I build i cui avvisi non sono cambiati dall'ultima esecuzione vengono saltati.
- La correzione automatica si ferma quando il branch di build è protetto o l'app GitHub di Jamdesk perde l'accesso in scrittura. La scheda mostra **In pausa**. Risolvi la causa, quindi salva di nuovo **Correzione automatica**.
- I limiti AI giornalieri sono gli stessi della finestra. Quando un progetto raggiunge il limite, l'esecuzione salta alcune correzioni e lo segnala.
- Una nuova descrizione modifica la pagina, quindi la successiva traduzione ritradurrà quella pagina.

## Prerequisiti

- Un [repository GitHub collegato](/it/integrations/github) per il progetto.
- Accesso in scrittura per l'app GitHub di Jamdesk per eseguire il commit delle correzioni. La finestra mostra un link **Concedi accesso** a GitHub quando l'accesso manca.
- Un build completato che contiene avvisi di link interrotti o descrizioni mancanti.

## Trova il banner

Apri il progetto e scorri fino a **Cronologia build** nella pagina Home del progetto. Un banner con un conteggio e un pulsante **Correggi con l'AI** compare sopra l'elenco dei build quando l'ultimo build presenta problemi correggibili.

## Rivedi e applica le correzioni

<Steps>
  <Step title="Apri l'anteprima">
    Fai clic su **Correggi con l'AI**. La finestra si apre. L'agente AI impiega alcuni secondi per rivedere la documentazione e costruire un piano di correzione.
  </Step>
  <Step title="Leggi ogni modifica proposta">
    Le correzioni sono raggruppate per tipo. **Link interrotti** mostra ogni ancora riscritta. **Descrizioni mancanti** mostra il riassunto suggerito per ogni pagina. **Titoli mancanti** mostra il titolo proposto. Deseleziona la casella per saltare una correzione questa volta. Usa il pulsante di ignorare per [silenziare una raccomandazione in modo definitivo](#ignora-i-suggerimenti). I problemi senza una correzione chiara compaiono sotto **Non può essere corretto automaticamente** da correggere a mano.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="The Fix with AI modal. A Broken links section lists three checked fixes, each showing the old anchor struck through and the corrected anchor. A Can't be fixed automatically section lists two issues to fix by hand, above Cancel and Apply 3 fixes buttons." />
    </Frame>
  </Step>
  <Step title="Applica">
    Fai clic su **Applica correzioni**. Jamdesk esegue il commit delle modifiche selezionate sul branch collegato con il messaggio `docs: apply AI-suggested fixes (via Jamdesk)` e avvia un nuovo build.
  </Step>
  <Step title="Conferma la ricostruzione">
    Segui il nuovo build nella [Cronologia build](/it/builds/monitoring). Gli avvisi corretti spariscono una volta pubblicato. Ciò che resta è un avviso che Correggi con l'AI non ha potuto risolvere oppure un nuovo problema dal contenuto più recente.
  </Step>
</Steps>

<Note>
  Applicare scrive un vero commit nel tuo repository. Rivedilo o annullalo su GitHub come qualsiasi altro commit.
</Note>

## Quando alcuni problemi non possono essere corretti

La finestra elenca gli avvisi senza una correzione chiara sotto un'intestazione separata e non li tocca. Motivi comuni:

- Un link interrotto la cui pagina o intestazione di destinazione non esiste da nessuna parte.
- Una voce di navigazione senza un file sorgente corrispondente.
- Una pagina per la quale l'agente non è riuscito a generare una descrizione.

Questi richiedono una modifica manuale. Apri la pagina nell'[editor](/it/development/local-preview) o nel tuo editor di codice. Correggi il link o aggiungi la descrizione. Esegui il push per ricostruire.

## Ignora i suggerimenti

Alcuni avvisi non meritano di essere affrontati: un link che hai rotto di proposito, o una pagina segnaposto che non ha bisogno di descrizione. Deselezionare una correzione la salta solo una volta. Ignorare la rimuove dal conteggio finché non la ripristini.

Ogni riga della finestra ha un pulsante per ignorare, correggibile o meno. Facendo clic, l'elemento passa a una sezione compressa **Ignorati** in fondo. Il conteggio del banner nella pagina Home del progetto scende di conseguenza dopo aver chiuso la finestra. Gli avvisi corrispondenti scompaiono dalla Cronologia build del build corrente e di tutti quelli successivi. **Ignora tutti** fa lo stesso per tutto ciò che è ancora elencato.

Come si comportano gli ignorati:

- **Condivisi e persistenti:** gli ignorati si applicano all'intero progetto. Ogni membro vede lo stesso elenco. Restano attivi tra i build. Jamdesk associa ogni avviso in base al contenuto, non al numero di riga. Modificare altre parti della pagina non riporta un elemento ignorato.
- **Ripristino:** espandi la sezione **Ignorati** e fai clic su **Ripristina** per qualsiasi elemento. Ignorare tutto in un build nasconde il banner. Un piccolo link "N raccomandazioni ignorate" sotto la Cronologia build riapre la finestra.
- **Gli avvisi modificati ritornano:** un elemento ignorato torna come nuova raccomandazione quando il problema sottostante cambia, ad esempio quando il link interrotto ora punta altrove.

## Annulla una correzione automatica

Ogni esecuzione di correzione automatica ha un pulsante **Annulla**. Apri il build nella Cronologia build e trova la sezione **Correzione automatica**. Elenca ciò che Jamdesk ha modificato e collega al commit. Fai clic su **Annulla**, quindi su **Annulla correzione automatica** per confermare.

Jamdesk esegue il commit della versione precedente dei file sul tuo branch con il messaggio `docs: undo Jamdesk auto-fix (via Jamdesk)`. Se un file è cambiato dopo la correzione automatica, Jamdesk lo salta e lo elenca. Annulla quei file a mano.

Le correzioni annullate vengono ignorate. I loro avvisi sono nascosti, e Jamdesk non le riapplica. Per ripristinarle, apri **Correggi con l'AI** e ripristinale sotto **Ignorati**.

## Affida le correzioni al tuo agente AI

Puoi lasciare che un agente di programmazione come Claude Code esegua le modifiche nel tuo repository. Nella finestra Correggi con l'AI, fai clic su **Copia per il tuo agente AI**. Jamdesk copia un prompt in testo semplice che elenca ogni correzione suggerita con il suo file e la sua riga, più i problemi da correggere a mano. Gli elementi ignorati sono esclusi. Incolla il prompt nel tuo agente.

Dal terminale, `jamdesk fix --json` fornisce a un agente lo stesso elenco in formato JSON. Vedi [Usa con un agente AI](/it/cli/fix-broken-links#uso-con-un-agente-ai).

## Fix with AI e CLI a confronto

La dashboard e la CLI correggono le ancore dei link interrotti. Differiscono in dove vengono eseguite e in come la modifica arriva.

| | Correggi con l'AI (dashboard) | [`jamdesk fix`](/it/cli/fix-broken-links) (CLI) |
|---|---|---|
| Esecuzione | Nella dashboard, su un build | Nel terminale, su file locali |
| Corregge | Link interrotti, descrizioni e titoli mancanti | Ancore di link interrotti, più descrizioni mancanti con l'AI |
| Commit | Esegue il commit sul tuo branch per te | Scrive file locali; il commit è a tuo carico |
| Avvio | Un clic sul banner del build | `jamdesk fix` |

Usa il flusso della dashboard per una riparazione rapida senza uscire da Jamdesk. Usa la CLI quando vuoi che le modifiche siano già nella tua copia di lavoro, ad esempio per raggrupparle con altre modifiche.

Impostare **Correzioni AI** su **Off** ferma le analisi della dashboard. `jamdesk fix` continua a funzionare sul tuo computer. Per cambiare l'impostazione dal terminale, esegui [`jamdesk ai-fix`](/it/cli/overview) con `off`, `review` o `auto`:

```bash
jamdesk ai-fix auto
```
