Jamdesk crea siti di documentazione a partire dai file MDX nel tuo repository GitHub. Scrivi Markdown con componenti React ed esegui il push su GitHub. Il tuo sito va online su una CDN globale in meno di 60 secondi. I contenuti restano nel tuo repository come semplici file MDX. Puoi spostarli su un altro strumento in qualsiasi momento.

Nota: gli screenshot mostrano l'interfaccia in inglese.

## Panoramica dell'architettura

Il tuo repository è la fonte di verità. Jamdesk si collega ad esso, compila il tuo sito e lo distribuisce su una rete edge globale.

## La pipeline di build

Una build richiede in genere 30-60 secondi. Jamdesk non pre-renderizza le pagine. I contenuti grezzi vanno al edge. Le pagine vengono generate on demand quando i visitatori le richiedono.

<Steps>
  <Step title="Recupero del sorgente">
    Esegui il push sul branch GitHub collegato (oppure premi Rebuild nella dashboard). Jamdesk clona il tuo repository e individua la cartella della documentazione.
  </Step>
  <Step title="Validazione">
    Jamdesk valida `docs.json` rispetto allo schema. Controlla i link interni per pagine non valide e ancore errate.
  </Step>
  <Step title="Elaborazione dei contenuti">
    Jamdesk genera a partire dai tuoi contenuti l'indice di ricerca, gli embedding della [chat AI](/it/ai/chat), la sitemap, [`llms.txt`](/it/ai/llms-txt) e le regole di redirect.
  </Step>
  <Step title="Distribuzione sull'edge">
    I contenuti vengono caricati sulla CDN e propagati in oltre 300 località edge. Vengono trasferiti solo i file modificati.
  </Step>
</Steps>

## Cosa attiva un build

Un git push sul branch collegato, il pulsante Rebuild nella dashboard oppure [`jamdesk deploy`](/it/cli/deploy) dalla CLI. Jamdesk raggruppa in un'unica build i commit inviati in rapida successione.

Per i dettagli operativi (monitoraggio dello stato, rollback, deploy dei branch), consulta [Ciclo di vita di build e deploy](/it/deploy/lifecycle).

## Sicurezza e infrastruttura

Le build vengono eseguite in container isolati. Le build leggono solo il tuo repository.

<Columns cols={2}>
  <Card title="Permessi minimi" icon="shield-check">

  </Card>
  <Card title="Build isolate" icon="box">

## Prestazioni

La velocità di caricamento influisce sulla possibilità che la tua documentazione venga trovata. Google utilizza i [Core Web Vitals](https://jamdesk.com/blog/why-google-pagespeed-matters) come segnale di ranking. I crawler AI come GPTBot e ClaudeBot concedono 1-5 secondi per pagina. Le documentazioni che non si caricano in quella finestra non vengono citate.

Ogni sito Jamdesk viene servito dall'edge con un tempo al primo byte inferiore a 50 ms. È un valore sufficiente per le soglie di ranking di Google e perché i crawler AI possano recuperare e citare i contenuti.

| Metrica | Valore tipico |
|--------|---------------|
| Tempo di build | 30-60 secondi |
| Propagazione del deploy | < 30 secondi |
| Primo byte (edge) | < 50 ms |
| Caricamento completo della pagina | < 500 ms |
