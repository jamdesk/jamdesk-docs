**Jamdesk è un software per la documentazione** che pubblica un repository GitHub di Markdown come sito di documentazione ospitato. Genera automaticamente output leggibile dall'AI: `llms.txt`, endpoint `.md` per ogni pagina e un server MCP.

Distribuisci un sito di documentazione con due file: `docs.json` e una pagina MDX. Scegli il percorso che corrisponde al tuo punto di partenza.

## Prerequisiti

Ti serviranno:
- Un account [GitHub](https://github.com)
- Un repository con la tua documentazione (oppure ne creeremo uno)

## Opzione 1: parti dal template Starter

Questo è il modo più rapido per iniziare. Lo [starter template](https://github.com/jamdesk/starter-docs) include contenuti di esempio, una specifica OpenAPI ed esempi di ogni componente. Osserva come funziona, poi sostituiscili con i tuoi contenuti.

<Steps>
  <Step title="Crea un account Jamdesk">
    Vai su [dashboard.jamdesk.com](https://dashboard.jamdesk.com) e registrati con GitHub.
  </Step>

  <Step title="Crea un progetto dal template">
    Fai clic su **New Project** → **From Template** → **Starter Docs**.

    Jamdesk crea per te un repository GitHub con tutto già configurato.
  </Step>

  <Step title="Sei online">
    La tua documentazione è distribuita su `your-project.jamdesk.app`. Modifica i file MDX e fai push. Il sito si ricostruisce automaticamente.
  </Step>
</Steps>

<Tip>
Puoi anche clonare direttamente lo starter: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

<Tip>
**Vuoi tenere private alcune pagine?** Aggiungi `private: true` al frontmatter di qualsiasi file MDX. Imposta una password in **Project Settings** dopo la build successiva. Consulta [Controllo accessi](/it/setup/access-control) per tutte e quattro le opzioni (pubblico, password per l'intero sito, misto, SSO).
</Tip>

## Opzione 2: collega un repository esistente

Hai già un repository con documentazione pronta per Jamdesk? Collegalo direttamente. Se stai migrando da Mintlify o da un'altra piattaforma di documentazione, usa prima l'Opzione 3.

<Steps>
  <Step title="Crea un account Jamdesk">
    Vai su [dashboard.jamdesk.com](https://dashboard.jamdesk.com) e registrati con GitHub.
  </Step>

  <Step title="Crea un progetto">
    Fai clic su **New Project** e collega il tuo repository.

    1. Seleziona il tuo repository GitHub
    2. Scegli il branch da distribuire
    3. Jamdesk rileva automaticamente il tuo `docs.json`

    Se il tuo repository non ha ancora un `docs.json`, aggiungi il file minimo indicato in [Cosa c'è in un progetto di documentazione](#contenuto-di-un-progetto-docs) prima di collegarlo.

    Per permessi del repository, selezione del branch e percorsi della documentazione, consulta [Collega GitHub](/it/setup/connecting-github).
  </Step>

  <Step title="Sei online">
    La tua documentazione è distribuita su `your-project.jamdesk.app`. Jamdesk genera automaticamente `llms.txt` per gli strumenti AI.

    Ogni push sul branch collegato attiva una ricostruzione automatica.
  </Step>
</Steps>

## Opzione 3: esegui la migrazione da Mintlify o da un'altra piattaforma

Hai già documentazione in Mintlify, GitBook, Docusaurus, ReadMe, Confluence o un'altra piattaforma? Inizia dalla guida alla migrazione prima di creare un nuovo progetto. Essa copre il comando `jamdesk migrate` per Mintlify e i passaggi manuali per gli altri strumenti di documentazione. Poi collega il repository migrato usando l'[Opzione 2](#opzione-2-collega-un-repository-esistente).

## Contenuto di un progetto Docs

Un progetto Jamdesk minimo ha due elementi:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Per siti più grandi, consulta [Struttura delle directory](/it/setup/directory-structure) per le cartelle consigliate, gli asset e gli snippet.

### docs.json

Il file di configurazione che definisce il tuo sito:

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consulta il [Riferimento docs.json](/it/config/docs-json-reference) per tutte le opzioni di configurazione.

### Pagine MDX

Pagine di documentazione scritte in MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consulta [Nozioni base MDX](/it/content/mdx-basics) per frontmatter, titoli, link e sintassi dei componenti.

## Sviluppo locale

Visualizza in anteprima le modifiche in locale con la CLI Jamdesk prima di fare push su GitHub. Intercetta gli errori di sintassi MDX prima che raggiungano il sito live. Consulta la [panoramica della CLI Jamdesk](https://jamdesk.com/docs/cli/overview) per ogni metodo di installazione e comando.

Avvialo:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Apri **http://localhost:3000** per vedere la tua documentazione con hot reload.

## Aggiungi altre pagine

1. Crea un nuovo file MDX:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Aggiungilo a `docs.json`:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Fai push su GitHub. La tua nuova pagina viene distribuita automaticamente.

Per altri schemi di link, incluse ancore e card, consulta [Link e navigazione](/it/content/links).

## Dominio personalizzato

Aggiungi il tuo dominio in **Settings** → **Domains**:

1. Inserisci il tuo dominio (ad es. `docs.example.com`)
2. Aggiungi i record DNS mostrati
3. Attendi la verifica (fino a 48 ore)

I certificati SSL vengono generati automaticamente. [Guida completa →](/it/deploy/custom-domains)
