L’API di ricerca docs offre accesso programmatico ai contenuti della documentazione tramite ricerca semantica. Un endpoint (`POST /_api/search`) riceve una query in linguaggio naturale e restituisce i passaggi più pertinenti della documentazione, ordinati per rilevanza.

## Avvio rapido

<Steps>
  <Step title="Genera una chiave API">
    Vai a **Project Settings → API Keys** nella [dashboard Jamdesk](https://dashboard.jamdesk.com). Fai clic su **Generate Key**, assegnale un nome e copia la chiave. Inizia con `jd_live_`, seguito da 32 caratteri esadecimali (40 caratteri in totale), e viene mostrata una sola volta.
  </Step>
  <Step title="Invia la prima richiesta di ricerca">
    Invia una richiesta `POST` a `/_api/search` sul sottodominio della documentazione:

    ```bash
    curl -X POST https://your-project.jamdesk.app/_api/search \
      -H "Authorization: Bearer jd_live_c83003a54ae0a83123454c3f7ec82f0a" \
      -H "Content-Type: application/json" \
      -d '{"query": "How do I set up a custom domain?", "limit": 5, "language": "en"}'
    ```
  </Step>
  <Step title="Usa i risultati">
    La risposta restituisce un array di passaggi corrispondenti, con punteggi di rilevanza e metadati delle pagine:

    ```json
    {
      "query": "How do I set up a custom domain?",
      "language": "en",
      "results": [
        {
          "title": "Custom Domains",
          "section": "Step 4: Deploy",
          "slug": "deploy/custom-domains",
          "content": "To add a custom domain, go to Project Settings and enter your domain. You'll need to add a CNAME record pointing to your Jamdesk subdomain.",
          "url": "https://your-project.jamdesk.app/deploy/custom-domains",
          "score": 0.94
        }
      ],
      "total": 1,
      "durationMs": 85
    }
    ```
  </Step>
</Steps>

## Autenticazione

Tutte le richieste richiedono un token Bearer nell’header `Authorization`.

```http
Authorization: Bearer jd_live_c83003a54ae0a83123454c3f7ec82f0a
```

<Info>
  L’API di ricerca funziona sui siti con autenticazione tramite password o JWT. Verifica la tua chiave API, non le credenziali di accesso dei visitatori: non devi quindi aggiungere `/_api/search` a `auth.jwt.public`. I risultati possono includere pagine protette dall’accesso: chiama l’API dal server e non inserire mai la chiave nel codice del browser. I risultati seguono le stesse regole della ricerca sul sito: le pagine con accesso limitato a gruppi non vengono mai restituite, mentre le pagine nascoste o quelle con `search: false` sono escluse, a meno che tu non le abbia rese consultabili tramite ricerca.
</Info>

### Generare chiavi API

<Steps>
  <Step title="Apri Project Settings">
    Nella dashboard Jamdesk, vai al tuo progetto e fai clic su **Settings**.
  </Step>
  <Step title="Vai ad API Keys">
    Seleziona la scheda **API Keys**.
  </Step>
  <Step title="Crea una chiave">
    Fai clic su **Generate Key**, inserisci un nome descrittivo (ad esempio, "Intercom chatbot") e fai clic su **Create**.
  </Step>
  <Step title="Copia la chiave">
    Copia subito la chiave. Inizia con `jd_live_`, seguito da 32 caratteri esadecimali, e viene mostrata **una sola volta**. Conservala nel gestore dei segreti o nelle variabili d’ambiente.
  </Step>
</Steps>

### Gestione delle chiavi

<Info>
Le chiavi API sono associate a un singolo progetto. Una chiave per `acme.jamdesk.app` non può eseguire query sulla documentazione di un altro progetto.
</Info>

| Regola | Dettaglio |
|------|--------|
| **Formato** | `jd_live_<32 hex chars>` (40 caratteri in totale, non scade mai) |
| **Ambito** | Una chiave per progetto (non può accedere ad altri progetti) |
| **Rotazione** | Revoca e rigenera la chiave in qualsiasi momento da Project Settings |
| **Archiviazione** | Conservala nelle variabili d’ambiente o in un gestore dei segreti; non inserirla mai nel controllo del codice sorgente |

### Revocare le chiavi

Per revocare una chiave, vai a **Project Settings → API Keys**, individua la chiave tramite il nome e fai clic su **Revoke**. Le chiavi revocate smettono immediatamente di funzionare. Genera una nuova chiave per sostituirla.

## Limiti di frequenza

Le richieste sono soggette a limiti di frequenza per ogni chiave API.

| Piano | Limite |
|------|-------|
| **Pro** | 60 richieste / minuto |
| **Enterprise** | Personalizzato; contatta il [supporto](mailto:support@jamdesk.com) |

Quando superi il limite, l’API restituisce `429 Too Many Requests` con un header `Retry-After: 60` e `{"error": "Rate limit exceeded"}` nel corpo della risposta.

<Warning>
Se hai bisogno di limiti di frequenza più elevati per un’integrazione in produzione, [contattaci](mailto:support@jamdesk.com) per valutare le opzioni Enterprise.
</Warning>

## Limiti delle query

Ogni richiesta accetta un parametro `limit` che controlla il numero di risultati da restituire. Il massimo è **20**, il valore predefinito è **5** e il minimo è **1**. Non è prevista la paginazione: tutti i risultati corrispondenti vengono restituiti in un’unica risposta. Se hai bisogno di più contesto, prova una query più specifica invece di aumentare il limite.

Una query senza corrispondenze restituisce HTTP 200 con un array di risultati vuoto:

```json
{"query": "quantum entanglement", "results": [], "total": 0, "durationMs": 48}
```

## Filtrare per lingua

Se il sito della documentazione supporta più lingue, l’API filtra i risultati in base a una sola lingua per richiesta. Passa `language` nel corpo della richiesta con un codice BCP-47 (ad esempio `en`, `es`, `fr`, `pt-BR`, `zh-Hans`).

```bash
curl -X POST https://your-project.jamdesk.app/_api/search \
  -H "Authorization: Bearer jd_live_c83003a54ae0a83123454c3f7ec82f0a" \
  -H "Content-Type: application/json" \
  -d '{"query": "¿Cómo configuro un dominio personalizado?", "language": "es"}'
```

| Regola | Dettaglio |
|------|--------|
| **Predefinita** | `en` (inglese). Ometti il campo o passa `null` per usare il valore predefinito. |
| **Formato** | BCP-47 (`^[a-zA-Z]{2,3}([-_][a-zA-Z]{2,4})?$`). Esempi: `en`, `es`, `fr`, `pt-BR`, `zh-Hans`. |
| **Convalida** | I valori non validi restituiscono `400` con `{"error": "Invalid language code"}`. |
| **Tag a 3 segmenti** | Al momento non sono supportati. Codici come `zh-Hant-HK` e `sr-Latn-RS` restituiscono `400`. [Contatta il supporto](mailto:support@jamdesk.com) se ne hai bisogno. |
| **Progetti multilingue** | Il filtro è rigoroso: vengono restituiti solo i frammenti contrassegnati con la lingua richiesta. Una richiesta per `de` su un progetto con contenuti solo in inglese e francese restituisce un insieme di risultati vuoto, non un `400`. |
| **Progetti monolingue** | Il filtro viene ignorato; riceverai sempre l’insieme completo dei risultati. Inviare `language` è innocuo e non causa errori. |
| **Inclusa nella risposta** | Ogni risposta riuscita include un campo `language` con il valore determinato dal server (il valore della richiesta oppure `en` come valore predefinito). |

<Info>
Un progetto è multilingue quando il relativo `docs.json` ha un array `navigation.languages` con due o più voci. Per verificare se il sito è multilingue, apri la scheda **Settings → Languages** nella dashboard oppure apri direttamente `docs.json`.
</Info>

<Warning>
Il valore predefinito `en` viene applicato anche ai progetti privi di una versione in inglese. Se, ad esempio, il tuo progetto multilingue contiene solo francese e spagnolo, chiamando l’endpoint senza il campo `language` il filtro cercherà `en` e restituirà un insieme di risultati vuoto. Nei siti senza contenuti in inglese, passa sempre un valore `language` esplicito.
</Warning>

## Gestione degli errori

Tutte le risposte di errore includono un campo `error` leggibile dalle macchine, su cui puoi basare le diramazioni del codice.

| Stato | Valore `error` | Significato | Azione |
|--------|---------------|---------|--------|
| **400** | `Missing or empty "query" field` | Il corpo della richiesta è assente o non contiene `query` | Aggiungi una stringa `query` non vuota |
| **400** | `Invalid language code` | Il campo `language` non è una stringa o non corrisponde al formato BCP-47 (`null` è valido; le stringhe vuote o composte da spazi e i tag a 3 segmenti non sono validi) | Usa un codice valido a 1 o 2 segmenti, come `en`, `es`, `fr` o `pt-BR` |
| **401** | `invalid_key_format` | L’header `Authorization` è assente o la chiave non corrisponde a `jd_live_<32 hex>` | Verifica il formato dell’header: deve essere `Bearer jd_live_...` |
| **401** | `invalid_key` | La chiave non è riconosciuta o è stata revocata | Genera una nuova chiave nella dashboard |
| **403** | `wrong_project` | La chiave è valida, ma è stata generata per un altro progetto | Usa una chiave corrispondente allo slug del progetto nell’URL |
| **429** | `Rate limit exceeded` | Sono state superate 60 richieste al minuto | Attendi il numero di secondi indicato nell’header `Retry-After` |
| **502** | `Search temporarily unavailable` | Il backend di ricerca vettoriale è inattivo | Riprova dopo una breve attesa |
| **503** | `lookup_failed` o `redis_unavailable` | Il backend di verifica della chiave non è raggiungibile | Riprova dopo una breve attesa |

<Info>
Gli errori 401 e 403 sono permanenti. Riprovare con la stessa chiave non sarà utile. Gli errori 429, 502 e 503 sono temporanei: riprova aumentando progressivamente l’intervallo tra i tentativi.
</Info>

## CORS

CORS è abilitato su tutti gli endpoint. I client basati su browser (app a pagina singola, estensioni del browser e siti statici) possono chiamare direttamente `/_api/search`, senza un proxy backend. Sono consentite tutte le origini.

## SDK

Al momento non sono disponibili SDK ufficiali per i linguaggi di programmazione. Usa direttamente l’API REST tramite `fetch`, `requests`, `curl` o qualsiasi client HTTP. La [raccolta Postman](#raccolta-postman) qui sotto include esempi pronti da duplicare.

## Controllo delle versioni

L’API è attualmente alla versione **v1.0.0**. Le modifiche incompatibili (rinomina dei campi, rimozione di endpoint o modifiche all’autenticazione) saranno annunciate tramite il [blog Jamdesk](https://jamdesk.com/blog) e un avviso di deprecazione nell’header di risposta `X-Deprecation`, almeno 90 giorni prima della rimozione.
