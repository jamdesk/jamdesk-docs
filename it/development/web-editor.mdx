L'editor web consente di modificare la documentazione direttamente nel dashboard Jamdesk, senza clonare il repository né usare un terminale. Apri una pagina, modifica il relativo MDX con un'anteprima live affiancata e invia le modifiche al tuo branch GitHub. Ogni commit avvia automaticamente una build, così le modifiche vengono pubblicate proprio come con un `git push`.

Gli screenshot mostrano l'interfaccia in inglese.

È l'alternativa basata sul browser all'[anteprima locale](/it/development/local-preview) e all'[estensione VS Code](/it/development/vscode-extension). Usalo quando vuoi apportare una modifica rapida da qualsiasi luogo o preferisci non clonare affatto il repository.

## Aprire l'editor

Fai clic su **Editor** nella barra laterale del dashboard. L'editor si apre sul repository collegato del progetto e sul branch predefinito.

<Note>
L'editor richiede un [repository GitHub collegato](/it/setup/connecting-github) e uno schermo ampio (desktop). Nelle finestre più strette mostra l'avviso "wider browser needed", perché i riquadri del codice e dell'anteprima devono essere affiancati. È disponibile per ogni proprietario e membro del progetto, con tutti i piani.
</Note>

## L'interfaccia

L'editor presenta tre riquadri:

| Riquadro | Funzione |
|------|--------------|
| **Navigation** (sinistra) | Le pagine e i gruppi del sito, letti da `docs.json`. Filtra le pagine, apri l'editor **Configuration** (`docs.json`) o fai clic su **Add page**. |
| **Editor** (centro) | Un editor di codice MDX per il file aperto, con evidenziazione della sintassi e conteggio delle parole. |
| **Preview** (destra) | Una visualizzazione live della pagina, aggiornata mentre scrivi. Attiva **Desktop / Mobile** e **Light / Dark** per controllarne l'aspetto. |

Il branch che stai modificando è mostrato in alto a sinistra; cambia branch con il selettore dei branch.

## Modificare una pagina

Fai clic su una pagina nella navigazione per aprirla. Modifica l'MDX nel riquadro centrale e osserva l'anteprima aggiornarsi in tempo reale. Le modifiche vengono conservate come bozza locale nel browser finché non esegui il commit, così puoi passare da una pagina all'altra senza perdere il lavoro. Nulla viene scritto su GitHub finché non scegli di eseguire il commit.

## Aggiungere una pagina

Fai clic su **Add page** per creare una nuova pagina senza uscire dall'editor:

1. Scegli un modello iniziale.
2. Inserisci un titolo. Il nome del file della pagina viene ricavato automaticamente.
3. Scegli il gruppo di navigazione a cui appartiene.

La nuova pagina viene aperta come bozza. Quando esegui il commit, Jamdesk scrive sia il nuovo file `.mdx` sia la voce di navigazione in `docs.json` nello stesso commit.

## Eseguire il commit delle modifiche

Quando sei pronto a pubblicare, invia le modifiche in sospeso a GitHub:

<Steps>
  <Step title="Aprire la finestra di commit">
    Fai clic su **Commit**. La finestra elenca ogni file modificato (una pagina, `docs.json` o più file contemporaneamente).
  </Step>
  <Step title="Scrivere un messaggio">
    Inserisci un messaggio di commit oppure fai clic su **Generate** per permettere a Jamdesk di generarne uno a partire dal diff.
  </Step>
  <Step title="Eseguire il commit">
    Jamdesk esegue il commit delle modifiche nel branch corrente e avvia immediatamente una build. Tienila sotto controllo nella pagina **Builds** del progetto.
  </Step>
</Steps>

Preferisci eliminare le modifiche? **Revert** annulla le modifiche non salvate della pagina corrente e ripristina la versione sottoposta a commit.

## Lavorare con modifiche esterne

Se qualcun altro esegue un push sullo stesso branch mentre stai modificando, l'editor rileva lo spostamento del branch e lo segnala. Quando esegui il commit, ogni file modificato upstream viene presentato come un merge a tre vie, così puoi riconciliare le due versioni. Le modifiche locali non vengono mai eliminate.

<Tip>
Eseguire il commit dall'editor equivale esattamente a eseguire un push dal proprio computer: scrive un commit reale nel repository e attiva la stessa pipeline di build. Se la documentazione si trova in una sottodirectory del repository ([configurazione monorepo](/it/setup/monorepo-support)), l'editor la legge e vi scrive automaticamente.
</Tip>

## Requisiti

| Requisito | Dettaglio |
|-------------|--------|
| **GitHub connected** | Il progetto deve avere un repository e un branch collegati. |
| **Desktop browser** | Uno schermo ampio (circa 1400 px o più); l'editor non è disponibile su schermi con larghezza mobile. |
| **Access** | Qualsiasi proprietario o membro del progetto. La modifica scrive nel repository, quindi si applicano i normali blocchi di scrittura (ad esempio, un abbonamento scaduto). |
