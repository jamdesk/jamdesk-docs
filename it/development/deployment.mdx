## Deployment tramite CLI

Esegui il deploy dal terminale senza fare push su GitHub. Utile per iterazioni rapide, test di modifiche o progetti non collegati a un repository.

```bash
jamdesk login     # First time only
jamdesk deploy
```

La CLI impacchetta e carica i tuoi file. Mostra l'avanzamento della build in tempo reale. Usa `--detach` per mettere in coda la build e uscire immediatamente.

## Il flusso di lavoro

<Steps>
  <Step title="Apporta modifiche in locale">
    Modifica i tuoi file MDX e visualizza l'anteprima con `jamdesk dev`.
  </Step>
  <Step title="Esegui il push su GitHub">
    Esegui il commit e il push sul branch collegato:

    ```bash
    git add .
    git commit -m "Update authentication docs"
    git push
    ```
  </Step>
  <Step title="Deploy automatico">
    Jamdesk rileva il push e costruisce la documentazione. La pubblica sulla CDN. La maggior parte dei siti viene costruita in 30-90 secondi.
  </Step>
</Steps>

## Stato del deployment

Controlla lo stato nella dashboard, sotto **Deployments**:

| Stato | Significato |
|--------|---------|
| **Building** | Build in corso |
| **Deployed** | Online sul tuo dominio |
| **Failed** | Errore di build - controlla i log |
| **Queued** | In attesa della build precedente |

## Ricostruzione manuale

Avvia una ricostruzione senza fare push:

1. Vai su **Settings** nel tuo progetto
2. Fai clic su **Rebuild**

Usalo dopo aver aggiornato le variabili d'ambiente o per sbloccare una build bloccata.

## Log di build

Apri **Deployments**, fai clic su un deployment e leggi i log. Errori comuni:
- Sintassi MDX non valida
- Immagini mancanti
- Link interni non funzionanti
- Errori di configurazione

## Rollback

1. Vai su **Deployments**
2. Trova il deployment da ripristinare
3. Fai clic su **Rollback**

La versione precedente va online immediatamente.
