Ogni sito Jamdesk include un server MCP (Model Context Protocol) integrato. Mentre `llms.txt` fornisce agli strumenti AI un’istantanea statica della documentazione, MCP consente di cercare e interrogare i contenuti in modo interattivo: è utile quando gli agenti AI devono trovare risposte specifiche invece di leggere tutto.

## Che cos’è MCP?

Il [Model Context Protocol](https://modelcontextprotocol.io) è uno standard aperto che consente agli strumenti AI di accedere a fonti di dati esterne. La documentazione Jamdesk espone due strumenti tramite MCP:

| Strumento | Scopo |
|------|---------|
| `searchDocs` | Cerca nella documentazione per parola chiave e restituisce risultati ordinati per pertinenza |
| `getPage` | Recupera il contenuto completo di una pagina specifica |

## URL dell’endpoint

L’endpoint MCP è l’URL della documentazione con `/_mcp` aggiunto. Se hai attivato un [dominio personalizzato](/it/deploy/custom-domains), usalo:

| Configurazione | Endpoint |
|-------|----------|
| Dominio personalizzato su `docs.acme.com` | `https://docs.acme.com/_mcp` |
| Nessun dominio personalizzato | `https://my-project.jamdesk.app/_mcp` |

<Note>
  Quando è collegato un dominio personalizzato, preferisci il relativo endpoint: mantiene il tuo brand in tutti gli URL visibili agli strumenti AI e continua a funzionare anche se in seguito nascondi il sottodominio `.jamdesk.app` con [Solo dominio personalizzato](/it/deploy/custom-domain-only).
</Note>

## Configurazione rapida

<Tabs>
  <Tab title="Claude Code">
    Aggiungi la documentazione come server MCP:

    ```bash
    claude mcp add --transport http my-docs https://docs.acme.com/_mcp
    ```

    Sostituisci `docs.acme.com` con il dominio della documentazione oppure con `my-project.jamdesk.app` se non hai collegato un dominio personalizzato.

    Da quel momento, quando chiedi a Claude informazioni sul tuo progetto, potrà cercare e leggere direttamente la documentazione.
  </Tab>
  <Tab title="Cursor">
    Aggiungi la configurazione al file `.cursor/mcp.json` del progetto:

    ```json
    {
      "mcpServers": {
        "my-docs": {
          "url": "https://docs.acme.com/_mcp"
        }
      }
    }
    ```

    Cursor si connetterà automaticamente alla documentazione quando apri il progetto.
  </Tab>
</Tabs>

## Strumenti disponibili

### searchDocs

Cerca nella documentazione e ottieni risultati ordinati per pertinenza.

**Parametri:**

| Parametro | Tipo | Obbligatorio | Descrizione |
|-----------|------|----------|-------------|
| `query` | string | Sì | Termini di ricerca (ad es. "authentication", "getting started") |
| `limit` | number | No | Numero massimo di risultati (predefinito: 10, massimo: 50) |
| `type` | string | No | Filtra per tipo di contenuto: `all`, `api`, `guide`, `quickstart`, `help`, `component` |

**Eempio di richiesta:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "searchDocs",
    "arguments": {
      "query": "authentication",
      "limit": 5
    }
  }
}
```

**Esempio di risposta:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"query\":\"authentication\",\"total\":1,\"results\":[{\"title\":\"Authentication\",\"description\":\"How to authenticate API requests\",\"url\":\"/docs/api/authentication\",\"type\":\"api\",\"score\":0.95}]}"
    }]
  }
}
```

### getPage

Recupera il contenuto completo di una pagina specifica della documentazione.

**Parametri:**

| Parametro | Tipo | Obbligatorio | Descrizione |
|-----------|------|----------|-------------|
| `slug` | string | Sì | Percorso della pagina senza il prefisso `/docs` (ad es. `api/authentication`) |

**Esempio di richiesta:**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "getPage",
    "arguments": {
      "slug": "api/authentication"
    }
  }
}
```

**Esempio di risposta:**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"title\":\"Authentication\",\"description\":\"How to authenticate\",\"content\":\"## Overview\\n\\nUse API keys to authenticate...\",\"url\":\"/docs/api/authentication\"}"
    }]
  }
}
```

## Testare l’endpoint

Puoi testare direttamente l’endpoint MCP con curl:

```bash
# List available tools
curl -X POST https://docs.acme.com/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

# Search for content
curl -X POST https://docs.acme.com/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"searchDocs","arguments":{"query":"getting started"}}}'
```

## Siti protetti da login

Se il sito usa l’autenticazione con password o JWT, il server MCP richiede una chiave API del progetto. Creane una in **Project Settings > API Keys** e inviala come header:

```bash
claude mcp add --transport http my-docs https://docs.example.com/_mcp \
  --header "Authorization: Bearer jd_live_..."
```

Con la chiave, un client MCP può cercare e leggere le pagine consultabili del sito, ovvero lo stesso insieme di pagine coperto dalla ricerca del sito. Le pagine con accesso limitato a gruppi non sono mai disponibili tramite MCP, con o senza chiave. Le pagine nascoste e quelle con `search: false` vengono escluse, a meno che non siano state rese consultabili. Tratta la chiave come una password e revocala nel dashboard se viene esposta.

Senza una chiave, il server risponde con `401` e un corpo JSON che spiega come aggiungerne una. Le chiavi di un altro progetto vengono rifiutate. I codici di errore sono:

| Stato | `error` | Significato |
|--------|---------|---------|
| 401 | `auth_required` | Non è stata inviata alcuna chiave. |
| 401 | `invalid_api_key` | La chiave non è valida per questo sito. |
| 503 | `auth_unavailable` | Non è stato possibile verificare la chiave. Riprova dopo il numero di secondi indicato nell’header `Retry-After`. |

## Come funziona

L’endpoint MCP usa un indice di ricerca creato insieme alla documentazione:

- **Ranking BM25** - Ordina i risultati per pertinenza
- **Ricerca approssimativa** - Gestisce gli errori di battitura (tolleranza di 1 carattere)
- **Ponderazione dei campi** - Titoli e intestazioni delle sezioni hanno un peso maggiore rispetto al corpo del testo
- **Filtro per tipo** - Filtra i risultati per tipo di contenuto (API, guide e così via)

L’indice viene ricreato a ogni deploy.

## Limiti di frequenza

L’endpoint MCP ha un limite di **60 richieste al minuto** per indirizzo IP. È sufficiente per il normale utilizzo degli assistenti AI. Se superi il limite, riceverai una risposta 429.

## Risoluzione dei problemi

<Accordion title="Il server MCP non si connette">
  Verifica che l’URL dell’endpoint sia corretto e accessibile:

  ```bash
  curl https://docs.acme.com/_mcp
  ```

  Dovresti ricevere una risposta JSON con le informazioni sul server. In caso contrario, verifica che la documentazione sia stata compilata almeno una volta.
</Accordion>

<Accordion title="La ricerca non restituisce risultati">
  L’indice di ricerca viene generato durante il build. Se hai aggiunto contenuti di recente, avvia una nuova compilazione dal dashboard Jamdesk per aggiornare l’indice.
</Accordion>

<Accordion title="getPage restituisce null">
  Verifica che lo slug corrisponda esattamente al percorso della pagina, senza l’estensione `.mdx`. Ad esempio, se la pagina si trova in `api/authentication.mdx`, usa `api/authentication` come slug.
</Accordion>

<Accordion title="401 auth_required su un sito protetto">
  Il sito usa l’autenticazione con password o JWT, quindi la richiesta necessita di una chiave API del progetto. Aggiungi l’header `Authorization: Bearer` con una chiave disponibile in **Project Settings > API Keys**. Consulta [Siti protetti da login](#siti-protetti-da-login).
</Accordion>
