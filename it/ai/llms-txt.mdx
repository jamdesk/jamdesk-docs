Se vuoi che strumenti AI come ChatGPT, Claude o Copilot forniscano risposte accurate sul tuo prodotto, hanno bisogno di un accesso strutturato alla documentazione, non solo dei contenuti inclusi nei dati di addestramento.

Ogni sito Jamdesk genera `llms.txt` e `llms-full.txt` secondo la specifica [llmstxt.org](https://llmstxt.org). Gli strumenti AI leggono questi file invece di eseguire il crawling delle singole pagine.

<Note>
  Google ora verifica `llms.txt` nell'ambito dei [controlli di navigazione agentica di Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). I siti che pubblicano un `llms.txt` valido sono più facilmente individuabili dagli agenti AI e, sempre più spesso, da Google stesso quando classifica i contenuti per le risposte basate sull'AI. Jamdesk te lo offre gratuitamente.
</Note>

<Tip>
  **Controlla il tuo punteggio.** Scopri quanto è pronto per gli agenti qualsiasi sito di documentazione con lo strumento gratuito [AI Score](https://jamdesk.com/ai-score). La pubblicazione di un `llms.txt` valido è una delle prime verifiche eseguite. È disponibile anche un'[estensione AI Score per Chrome](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) per valutare i siti durante la navigazione.
</Tip>

## Cosa genera Jamdesk

| File | Contenuto |
|------|-----------|
| `llms.txt` | Titoli, descrizioni e URL delle pagine (un indice strutturato) |
| `llms-full.txt` | Contenuto completo della documentazione in un unico file |

Jamdesk genera entrambi i file durante il build e li distribuisce dalla stessa CDN della documentazione.

## Verifica dei file

Verifica che i file esistano dopo il primo build:

<Tabs>
  <Tab title="Dominio principale">
    Se la documentazione si trova alla radice del dominio (ad esempio `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Percorso /docs">
    Se la documentazione si trova sotto `/docs` nel sito principale (come in questo sito, `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Formato dei file

Il file `llms.txt` elenca ogni pagina con titolo, descrizione e URL, raggruppati in sezioni che rispecchiano la navigazione:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Il file `llms-full.txt` contiene il contenuto Markdown completo di ogni pagina, concatenato con i confini delle pagine indicati dai titoli.

## Struttura

`llms.txt` segue la proposta [llmstxt.org](https://llmstxt.org/): un titolo H1,
un riepilogo in blockquote e le schede e i gruppi di navigazione come sezioni `##` di
link Markdown.

I siti multilingue ricevono un indice per ogni lingua. Il file `llms.txt` principale elenca la lingua predefinita e collega ogni indice tradotto alla fine, ad esempio
`/fr/llms.txt` per il francese. Ogni file per lingua rimanda ai file corrispondenti nelle altre lingue.

Ogni lingua riceve anche il proprio file con tutti i contenuti, come `/fr/llms-full.txt`.
Anche la lingua predefinita ne ha uno (ad esempio `/en/llms-full.txt`). Il file principale
`llms-full.txt` contiene comunque tutte le lingue.

## Direttiva per gli agenti in ogni pagina

Ogni pagina contiene anche una nota invisibile e non accessibile agli screen reader per gli agenti AI, che rimanda a `llms.txt`, e ogni esportazione Markdown inizia con un link in blockquote all'indice. Gli agenti che raggiungono il tuo HTML trovano il percorso Markdown senza eseguire il crawling.

## Come viene creato

- Generato durante il build insieme al tuo HTML
- Distribuito dalla CDN con la stessa politica di caching della documentazione
- Aggiornato automaticamente a ogni build
- Nessuna configurazione necessaria: tutte le pagine sono incluse per impostazione predefinita

## Disattivazione di llms.txt

`llms.txt` e `llms-full.txt` vengono pubblicati per impostazione predefinita. Per interromperne la generazione (ad esempio, se non vuoi che gli strumenti AI acquisiscano i tuoi contenuti), imposta `seo.ai.llmsTxt` su `false` nel file `docs.json`:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Al build successivo, Jamdesk non genera i due file e gli URL attivi `/llms.txt` e `/llms-full.txt` restituiscono `404`.

<Note>
  **L'acquisizione da parte dell'AI e l'indicizzazione nei motori di ricerca sono controlli separati.** `seo.ai.llmsTxt` gestisce solo i file `llms.txt`/`llms-full.txt` letti dagli strumenti AI. Non modifica il modo in cui i motori di ricerca indicizzano il sito: questo è controllato dai [metadati `robots` e dal valore `noindex` per pagina](/it/content/seo#controllo-dellindicizzazione). Una pagina può essere indicizzata da Google pur essendo esclusa dall'acquisizione dell'AI, o viceversa.
</Note>

## Crawler IA

Il file `robots.txt` predefinito di Jamdesk consente l'accesso a tutti i principali crawler AI (Claude, ChatGPT, Copilot, Gemini). La documentazione è accessibile agli strumenti AI senza configurazioni aggiuntive.

<Accordion title="Differenze tra llms.txt e sitemap.xml">
  `sitemap.xml` elenca gli URL che i motori di ricerca devono sottoporre a crawling e indicizzare. Non include contenuti, ma solo link e metadati come le date dell'ultima modifica.

  `llms.txt` è progettato per i modelli AI. Include titoli e descrizioni delle pagine e, in `llms-full.txt`, il contenuto effettivo. Gli strumenti AI possono leggere il file completo per comprendere la documentazione senza effettuare più richieste HTTP.
</Accordion>
