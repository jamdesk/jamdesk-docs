Strumenti AI come ChatGPT, Claude o Copilot forniscono risposte accurate sul tuo prodotto solo con accesso strutturato alla tua documentazione. I loro dati di addestramento non bastano.

Ogni sito Jamdesk genera `llms.txt` e `llms-full.txt` seguendo la specifica di [llmstxt.org](https://llmstxt.org). Gli strumenti AI leggono questi file invece di scansionare le singole pagine.

<Note>
  Google ora verifica `llms.txt` nell'ambito dei [controlli di navigazione agentica di Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). I siti che pubblicano un `llms.txt` valido sono più facili da individuare per gli agenti AI. Google lo usa sempre più anche per posizionare i contenuti nelle risposte basate sull'AI. Jamdesk lo pubblica gratuitamente.
</Note>

<Tip>
  **Controlla il tuo punteggio.** Lo strumento gratuito [AI Score](https://jamdesk.com/ai-score) valuta quanto un sito di documentazione sia pronto per gli agenti. Un `llms.txt` valido è uno dei primi elementi che verifica. L'[estensione Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) valuta i siti mentre navighi.
</Tip>

## Cosa genera Jamdesk

| File | Contenuto |
|------|---------|
| `llms.txt` | Titoli, descrizioni e URL delle pagine (un indice strutturato) |
| `llms-full.txt` | Contenuto completo della documentazione in un unico file |

Jamdesk genera i file al momento della build. Li serve dalla stessa CDN della tua documentazione.

## Verifica i tuoi file

Controlla che i file esistano dopo la prima build:

<Tabs>
  <Tab title="Dominio principale">
    Se la documentazione si trova alla radice del dominio (ad esempio `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Sottopercorso /docs">
    Se la documentazione si trova sotto `/docs` sul sito principale (come questo sito su `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Formato del file

Il file `llms.txt` elenca ogni pagina con titolo, descrizione e URL, raggruppate in sezioni che rispecchiano la tua navigazione:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Il file `llms-full.txt` contiene il contenuto Markdown completo di ogni pagina, concatenato con i confini tra le pagine segnati da titoli.

## Struttura

`llms.txt` segue la proposta di [llmstxt.org](https://llmstxt.org/): un titolo H1, un riepilogo in blockquote e le schede e i gruppi di navigazione come sezioni `##` di link Markdown.

## Siti multilingua

I siti con più lingue ricevono un insieme separato di file per ciascuna lingua. Uno strumento AI può recuperare solo la lingua di cui ha bisogno. Per un sito in inglese (predefinito) e francese:

| URL | Contenuto |
|-----|---------|
| `/llms.txt` | Indice inglese, con link agli indici di tutte le altre lingue alla fine |
| `/en/llms.txt` | Stesso file di `/llms.txt` |
| `/fr/llms.txt` | Indice francese, con link alle altre lingue |
| `/llms-full.txt` | Contenuto completo di tutte le lingue, una dopo l'altra |
| `/en/llms-full.txt` | Contenuto completo solo delle pagine inglesi |
| `/fr/llms-full.txt` | Contenuto completo solo delle pagine francesi |

Il file `llms-full.txt` di root mantiene tutte le lingue. Gli strumenti che già lo leggono non notano alcuna differenza. Indirizza un agente al file della lingua specifica quando gli serve solo quella lingua:

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

Una lingua ottiene i propri file una volta che ha almeno una pagina. I siti monolingua mantengono solo i file di root.

## Siti protetti da login

Su un sito protetto da [protezione con password](/it/setup/password-protection) o [autenticazione JWT](/it/setup/jwt-authentication), `llms.txt` e `llms-full.txt` reindirizzano i visitatori alla pagina di login, e gli URL `.md` restituiscono `401`. Una chiave API del progetto apre tutti e tre per gli strumenti che non possono effettuare l'accesso. Creala in **Project Settings > API Keys** e inviala come `Authorization: Bearer <key>`:

```bash
curl https://docs.example.com/llms.txt \
  -H "Authorization: Bearer jd_live_..."

curl https://docs.example.com/using/scope.md \
  -H "Authorization: Bearer jd_live_..."
```

Con una chiave, gli URL `.md` restituiscono le pagine che compaiono nella ricerca. Le pagine riservate a gruppi, le pagine nascoste e le pagine con `search: false` restituiscono `404`. Una chiave non valida per il sito riceve un errore JSON `401` con `invalid_api_key`. Senza chiave, nulla cambia.

La chiave non apre mai le pagine HTML né la chat AI. Quelle richiedono ancora un login. Le richieste con una chiave condividono un limite di 120 al minuto per chiave con il [server MCP](/it/ai/mcp-server#limiti-di-frequenza). Oltre il limite ricevi un `429` con `Retry-After: 60`.

## Direttiva per agenti su ogni pagina

Ogni pagina contiene una nota invisibile, silenziosa per gli screen reader, che indirizza gli agenti AI verso `llms.txt`. Ogni esportazione Markdown inizia con un blockquote che collega l'indice. Gli agenti che atterrano sul tuo HTML trovano il percorso Markdown senza doverlo scansionare.

## Come viene costruito

- Generato al momento della build insieme all'HTML
- Servito dalla CDN con la stessa politica di cache della documentazione
- Si aggiorna automaticamente a ogni build
- Nessuna configurazione richiesta. Ogni pagina è inclusa per impostazione predefinita

## Disattivare llms.txt

Jamdesk pubblica `llms.txt` e `llms-full.txt` per impostazione predefinita. Imposta `seo.ai.llmsTxt` su `false` in `docs.json` per smettere di generarli, ad esempio per impedire agli strumenti AI di acquisire i tuoi contenuti:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Jamdesk salta i file alla build successiva, incluse tutte le copie per lingua. Gli URL live `/llms.txt` e `/llms-full.txt` restituiscono `404`.

<Note>
  **L'acquisizione da parte dell'AI e l'indicizzazione per la ricerca sono controlli separati.** `seo.ai.llmsTxt` controlla solo i file `llms.txt`/`llms-full.txt` che leggono gli strumenti AI. Non modifica il modo in cui i motori di ricerca indicizzano il tuo sito. [I metadati `robots` e il `noindex` per pagina](/it/content/seo#controllare-lindicizzazione) controllano l'indicizzazione. Una pagina può essere indicizzata da Google ed esclusa dall'acquisizione AI, o viceversa.
</Note>

## Crawler AI

Il `robots.txt` predefinito di Jamdesk consente tutti i principali crawler AI (Claude, ChatGPT, Copilot, Gemini).

<Accordion title="Differenza tra llms.txt e sitemap.xml">
  `sitemap.xml` elenca gli URL che i motori di ricerca scansionano e indicizzano. Non ha contenuto, solo link e metadati come le date di ultima modifica.

  `llms.txt` è destinato ai modelli AI. Contiene titoli e descrizioni delle pagine e (in `llms-full.txt`) il contenuto delle pagine. Gli strumenti AI leggono l'intero file in una sola richiesta HTTP invece di molte.
</Accordion>
