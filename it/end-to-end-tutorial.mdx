Passa da un repository vuoto a un sito di documentazione online. Aggiungi un dominio personalizzato quando vuoi e salta i passaggi che hai già completato.

## Prerequisiti

- Un account GitHub
- Un repository con contenuti di documentazione (oppure usa lo [Starter Template](https://github.com/jamdesk/starter-docs))
- Node.js 20+ se vuoi installare la CLI con npm

<Steps>
  <Step title="Crea un progetto e collega GitHub">
    Crea il tuo primo progetto nel dashboard di Jamdesk e collega un repository.

    - Segui [Creazione di progetti](/it/setup/creating-projects) per impostare il nome, lo slug e il percorso della documentazione del progetto
    - Se richiesto, installa la GitHub App e concedi l'accesso al repository ([Collegamento a GitHub](/it/setup/connecting-github))
  </Step>

  <Step title="Modifica e visualizza le pagine con la CLI">
    Usa la CLI di Jamdesk per visualizzare in anteprima le modifiche alle pagine prima di inviarle a GitHub.

    <Tabs>
      <Tab title="npm">
        ```bash
        npm install -g jamdesk
        cd your-docs
        jamdesk dev
        ```
      </Tab>
      <Tab title="npx">
        ```bash
        cd your-docs
        npx jamdesk dev
        ```
      </Tab>
    </Tabs>

    L'anteprima locale è disponibile all'indirizzo **http://localhost:3000**. Per saperne di più, consulta [Anteprima locale](/it/development/local-preview).

    Apri una pagina `.mdx` nell'editor, salva una modifica e aggiorna l'anteprima locale. Quando il risultato è corretto, pubblicala con il flusso Git del passaggio successivo.
  </Step>

  <Step title="Esegui il deploy inviando le modifiche a GitHub">
    Ogni push al branch configurato avvia un build e pubblica il risultato sul tuo sottodominio Jamdesk.

    ```bash
    git add .
    git commit -m "Add docs content"
    git push origin main
    ```

    Sostituisci `main` con il branch configurato nel progetto se ne utilizzi uno diverso.

    Al termine del build, la documentazione sarà disponibile all'indirizzo `your-project.jamdesk.app`. Consulta [Deploy](/it/development/deployment) per ulteriori dettagli.
  </Step>

  <Step title="Facoltativo: aggiungi un dominio personalizzato">
    Pubblica la documentazione sul tuo dominio anziché sul sottodominio Jamdesk.

    1. Vai a **Settings** → **Domains** nel dashboard di Jamdesk
    2. Aggiungi il tuo dominio (ad esempio, `docs.example.com`)
    3. Crea i record DNS mostrati nel dashboard
    4. Attendi il completamento della verifica e della configurazione SSL

    Per la risoluzione dei problemi, consulta [Domini personalizzati](/it/deploy/custom-domains).
  </Step>
</Steps>

## Convalida del flusso end-to-end

- Il tuo sottodominio Jamdesk si carica e mostra l'ultimo build
- L'anteprima locale riflette gli stessi contenuti e la stessa navigazione
- Se configurato, il dominio personalizzato è verificato e pubblica tramite HTTPS
- La cronologia dei build mostra l'ultimo commit e l'autore

## Facoltativo: ospita in /docs

Se vuoi pubblicare la documentazione in un sottopercorso come `example.com/docs`, consulta [Panoramica del deploy](/it/deploy/overview) e [Hosting in un sottopercorso](/it/deploy/subpath-hosting).
