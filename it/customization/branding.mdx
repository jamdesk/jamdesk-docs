Il branding controlla gli elementi visivi che i lettori vedono per primi: loghi, favicon e link di navigazione. Ognuno accetta varianti per la modalità chiara e scura.

## Logo

Aggiungi il tuo logo all'intestazione di navigazione:

```json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp",
    "href": "https://yourcompany.com"
  }
}
```

| Campo | Descrizione |
|-------|-------------|
| `light` | Logo per la modalità chiara (logo scuro su sfondo chiaro) |
| `dark` | Logo per la modalità scura (logo chiaro su sfondo scuro) |
| `href` | Dove porta il clic sul logo |

<Tip>
Usa loghi SVG per una resa nitida a qualsiasi dimensione. Usa lo stesso logo per `light` e `dark` se ne hai uno solo. Le anteprime dei link non possono mostrare il testo all'interno di un logo SVG. Converti qualsiasi testo in contorni (path). Vedi [Personalizza la social card](/it/content/seo#personalizzare-la-scheda-social).
</Tip>

### Dimensioni del logo

I loghi vengono visualizzati con una larghezza massima di 120px. Per risultati ottimali:
- Larghezza: 120-240px
- Altezza: 30-40px
- Formato: SVG preferito

## Favicon

Un'unica immagine per entrambe le modalità:

```json
{
  "favicon": "/images/favicon.svg"
}
```

Oppure una variante separata per ciascuna modalità:

```json
{
  "favicon": {
    "light": "/images/favicon.svg",
    "dark": "/images/favicon-dark.svg"
  }
}
```

`dark` è facoltativo. Senza di esso, `light` viene mostrato in ogni modalità. Jamdesk emette un `<link rel="icon">` per la favicon principale più un secondo link con `media="(prefers-color-scheme: dark)"` per la variante scura.

Formati supportati: SVG, PNG, ICO.

<Note>
Un SVG che usa `currentColor` per i tratti e i riempimenti si adatta da solo alla modalità. Il browser sostituisce il colore del primo piano attivo.
</Note>

## Nome del sito

Il campo `name` appare nelle schede del browser e nei risultati di ricerca:

```json
{
  "name": "Acme Docs",
  "description": "Documentation for the Acme API"
}
```

Modifica il formato del titolo, oppure escludi il nome da esso, con [`seo.titleTemplate`](/it/content/seo#titoli-delle-pagine).

Abbinalo a una [`description`](#descrizione). Senza di essa, i risultati di ricerca e le anteprime dei link mostrano un testo generico di ripiego.

## Descrizione

Il campo `description` è il riepilogo SEO predefinito del tuo sito. I motori di ricerca lo mostrano sotto il titolo del sito, e le piattaforme social lo usano per le anteprime dei link:

```json
{
  "description": "Build, ship, and scale documentation with the Acme platform."
}
```

Punta a 50-160 caratteri, scritti per un lettore che sta decidendo se cliccare. Le pagine con un proprio frontmatter `description` usano quello. Tutte le altre pagine usano la descrizione del sito.

## Link di navigazione

Aggiungi link alla navbar:

```json
{
  "navbar": {
    "links": [
      { "label": "Blog", "href": "https://yourcompany.com/blog" },
      { "label": "Pricing", "href": "https://yourcompany.com/pricing" }
    ],
    "primary": {
      "type": "button",
      "label": "Get Started",
      "href": "https://app.yourcompany.com/signup"
    }
  }
}
```

### Opzioni dei link

| Campo | Tipo | Descrizione |
|-------|------|-------------|
| `label` | string | Testo visualizzato |
| `href` | string | URL (esterno o interno) |

### Pulsante principale

Il campo `primary` crea un pulsante di invito all'azione evidenziato:

```json
{
  "primary": {
    "type": "button",
    "label": "Dashboard",
    "href": "https://app.yourcompany.com"
  }
}
```

I link e il pulsante principale si trovano nell'intestazione su tablet e desktop. Sui telefoni non c'è spazio per loro nell'intestazione: compaiono nel menu, con il pulsante principale fissato in basso. Pulsar non mostra i link della navbar né il pulsante principale.

## Piè di pagina

Il footer si trova in fondo a ogni pagina. Può contenere icone social, colonne di link e una riga di copyright. Ogni lingua può avere il proprio footer, e puoi modificarne lo stile con CSS personalizzato.

### Link social

Mostra le icone dei social media in fondo a ogni pagina:

```json
{
  "footer": {
    "socials": {
      "github": "https://github.com/yourcompany",
      "x": "https://x.com/yourcompany",
      "discord": "https://discord.gg/yourserver",
      "linkedin": "https://linkedin.com/company/yourcompany"
    }
  }
}
```

#### Piattaforme supportate

| Piattaforma | Chiave | Descrizione |
|-------------|--------|-------------|
| GitHub | `github` | Link alla tua organizzazione o repo GitHub |
| X (Twitter) | `x` o `twitter` | Link al tuo profilo X/Twitter |
| LinkedIn | `linkedin` | Link alla pagina LinkedIn della tua azienda |
| Discord | `discord` | Link al tuo server Discord |
| Slack | `slack` | Link alla tua community Slack |
| YouTube | `youtube` | Link al tuo canale YouTube |
| Instagram | `instagram` | Link al tuo profilo Instagram |
| Facebook | `facebook` | Link alla tua pagina Facebook |
| Reddit | `reddit` | Link al tuo subreddit |
| Telegram | `telegram` | Link al tuo canale Telegram |
| Bluesky | `bluesky` | Link al tuo profilo Bluesky |
| Threads | `threads` | Link al tuo profilo Threads |
| Medium | `medium` | Link alla tua pubblicazione Medium |
| Hacker News | `hacker-news` | Link al tuo profilo Hacker News |
| Sito web | `website` | Link al tuo sito web principale |

<Tip>
Le icone vengono mostrate in un ordine fisso, qualunque sia l'ordine nella tua configurazione. GitHub e X/Twitter compaiono per primi.
</Tip>

### Colonne di link

Aggiungi gruppi di link sopra le icone social:

```json
{
  "footer": {
    "links": [
      {
        "header": "Resources",
        "items": [
          { "label": "Blog", "href": "https://yourcompany.com/blog" },
          { "label": "Changelog", "href": "/changelog" }
        ]
      },
      {
        "header": "Company",
        "items": [
          { "label": "About", "href": "https://yourcompany.com/about" },
          { "label": "Careers", "href": "https://yourcompany.com/careers" }
        ]
      }
    ],
    "socials": {
      "github": "https://github.com/yourcompany",
      "x": "https://x.com/yourcompany"
    }
  }
}
```

| Campo | Tipo | Descrizione |
|-------|------|-------------|
| `links` | array | Array di oggetti colonna di link |
| `links[].header` | string | Intestazione della colonna (facoltativa) |
| `links[].items` | array | Link nella colonna |
| `links[].items[].label` | string | Testo visualizzato per il link |
| `links[].items[].href` | string | URL (percorsi interni o URL esterni) |

<Note>
I link esterni (che iniziano con `http`) si aprono in una nuova scheda. I link interni navigano all'interno della tua documentazione.
</Note>

### Riga di copyright

Aggiungi `copyright` e comparirà sulla riga inferiore del footer, accanto al link "Powered by Jamdesk":

```json
{
  "footer": {
    "copyright": "© 2026 Acme Inc. All rights reserved."
  }
}
```

È testo semplice. Markdown e HTML vengono mostrati così come scritti, quindi inserisci i link in una colonna di link. Le interruzioni di riga diventano spazi e il limite è di 200 caratteri. Digita direttamente il carattere `©`, perché `&copy;` viene mostrato letteralmente.

### Footer diverso per lingua

In un sito con più lingue, ogni voce di `navigation.languages` può avere un proprio `footer`. Accetta gli stessi campi di quello di primo livello:

```json
{
  "footer": {
    "copyright": "© 2026 Acme Inc."
  },
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [...]
      },
      {
        "language": "fr",
        "groups": [...],
        "footer": {
          "links": [
            {
              "header": "Entreprise",
              "items": [{ "label": "À propos", "href": "https://acme.com/fr/about" }]
            }
          ],
          "copyright": "© 2026 Acme Inc. Tous droits réservés."
        }
      }
    ]
  }
}
```

Il footer di una lingua sostituisce quello di primo livello. Non viene effettuata alcuna unione, quindi copia tutto ciò che vuoi mantenere. Le lingue senza un proprio `footer` usano quello di primo livello. Vedi [Lingue](/it/setup/languages) per sapere come nascondere il footer per una singola lingua.

### Personalizza il footer

Il footer ha nomi di classe che restano invariati tra una versione e l'altra, quindi il CSS personalizzato che li utilizza continua a funzionare. Ad esempio, questo rende maiuscoli i titoli delle colonne e colora di viola l'icona GitHub:

```css style.css
.jd-footer-column-title {
  text-transform: uppercase;
  letter-spacing: 0.05em;
}

.jd-footer-social[data-platform="github"] {
  color: #6e40c9;
}
```

L'elenco completo è in [CSS personalizzato](/it/customization/custom-css).

### Nascondere il piè di pagina in pagine specifiche

Usa il frontmatter per nascondere il footer su singole pagine:

```yaml
---
title: Landing Page
hideFooter: true
---
```

Usalo su pagine di destinazione personalizzate o ovunque il footer risulti d'intralcio.

## Identità visiva di Jamdesk

Per impostazione predefinita, nel footer delle tue pagine di documentazione compare un link "Powered by Jamdesk". Puoi rimuoverlo.

### Nascondere l'identità visiva

Per rimuovere il branding Jamdesk:

1. Vai su **Settings** nella tua dashboard Jamdesk
2. Trova la sezione **Build Settings**
3. Disattiva **Show Jamdesk Branding**
4. Avvia una nuova build

<Note>
L'opzione per il branding è disponibile in tutti i piani. Le modifiche hanno effetto dopo una nuova build.
</Note>

## Dominio personalizzato

Aggiungi il tuo dominio nella dashboard Jamdesk:

1. Vai su **Settings** → **Domains**
2. Aggiungi il tuo dominio (ad esempio `docs.yourcompany.com`)
3. Configura il DNS come indicato
4. Attendi la verifica

La tua documentazione verrà poi caricata sul tuo dominio personalizzato, con SSL automatico.
