Il branding controlla gli elementi visivi che i lettori vedono per primi: loghi, favicon e link di navigazione. Tutto supporta le varianti per modalità chiara e scura.

## Logo

Aggiungi il tuo logo all'intestazione di navigazione:

```json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp",
    "href": "https://yourcompany.com"
  }
}
```

| Campo | Descrizione |
|-------|-------------|
| `light` | Logo per la modalità chiara (logo scuro su sfondo chiaro) |
| `dark` | Logo per la modalità scura (logo chiaro su sfondo scuro) |
| `href` | Destinazione del clic sul logo |

<Tip>
Usa loghi SVG per una resa nitida a qualsiasi dimensione. Se hai un solo logo, usalo sia per `light` che per `dark`.
</Tip>

### Dimensioni del logo

I loghi vengono visualizzati con una larghezza massima di 120px. Per risultati ottimali:
- Larghezza: 120-240px
- Altezza: 30-40px
- Formato: preferibilmente SVG

## Favicon

Un'immagine per entrambe le modalità:

```json
{
  "favicon": "/images/favicon.svg"
}
```

Oppure una variante separata per ciascuna modalità:

```json
{
  "favicon": {
    "light": "/images/favicon.svg",
    "dark": "/images/favicon-dark.svg"
  }
}
```

La favicon `light` viene mostrata in modalità chiara; quella `dark` in modalità scura. `dark` è facoltativa. Se omessa, `light` viene usata in entrambe le modalità. Jamdesk genera un `<link rel="icon">` per la favicon principale e un secondo link con `media="(prefers-color-scheme: dark)"` per la variante scura.

Formati supportati: SVG, PNG, ICO.

<Note>
Se preferisci un unico asset, anche un SVG che usa `currentColor` per tratti e riempimenti si adatta automaticamente: il browser sostituisce il colore di primo piano attivo.
</Note>

## Nome del sito

Il campo `name` viene visualizzato nelle schede del browser e nei risultati di ricerca:

```json
{
  "name": "Acme Docs",
  "description": "Documentation for the Acme API"
}
```

Abbinalo a una [`description`](#descrizione), così i risultati di ricerca e le anteprime dei link mostrano un testo pertinente anziché un contenuto generico predefinito.

## Descrizione

Il campo `description` è il riepilogo SEO predefinito del sito. I motori di ricerca lo mostrano sotto il titolo del sito e le piattaforme social lo usano nelle anteprime dei link:

```json
{
  "description": "Build, ship, and scale documentation with the Acme platform."
}
```

Punta a 50-160 caratteri, pensati per chi deve decidere se fare clic. Le pagine che impostano una propria `description` nel frontmatter usano quella; la descrizione del sito viene applicata a tutte le altre.

## Link di navigazione

Aggiungi link alla barra di navigazione:

```json
{
  "navbar": {
    "links": [
      { "label": "Blog", "href": "https://yourcompany.com/blog" },
      { "label": "Pricing", "href": "https://yourcompany.com/pricing" }
    ],
    "primary": {
      "type": "button",
      "label": "Get Started",
      "href": "https://app.yourcompany.com/signup"
    }
  }
}
```

### Opzioni dei link

| Campo | Tipo | Descrizione |
|-------|------|-------------|
| `label` | string | Testo visualizzato |
| `href` | string | URL (esterno o interno) |

### Pulsante principale

Il campo `primary` crea un pulsante di invito all'azione in evidenza:

```json
{
  "primary": {
    "type": "button",
    "label": "Dashboard",
    "href": "https://app.yourcompany.com"
  }
}
```

Su tablet e computer, i link e il pulsante principale sono nell'intestazione. Sugli smartphone non c'è spazio nell'intestazione, quindi compaiono nel menu e il pulsante principale è fissato in basso. Pulsar non mostra i link di navigazione né il pulsante principale.

## Piè di pagina

Aggiungi link social e colonne di link personalizzate al piè di pagina della documentazione.

### Link social

Mostra le icone dei social media in fondo a ogni pagina:

```json
{
  "footer": {
    "socials": {
      "github": "https://github.com/yourcompany",
      "x": "https://x.com/yourcompany",
      "discord": "https://discord.gg/yourserver",
      "linkedin": "https://linkedin.com/company/yourcompany"
    }
  }
}
```

#### Piattaforme supportate

| Piattaforma | Chiave | Descrizione |
|----------|-----|-------------|
| GitHub | `github` | Link all'organizzazione o al repository GitHub |
| X (Twitter) | `x` o `twitter` | Link al profilo X/Twitter |
| LinkedIn | `linkedin` | Link alla pagina aziendale su LinkedIn |
| Discord | `discord` | Link al server Discord |
| Slack | `slack` | Link alla community Slack |
| YouTube | `youtube` | Link al canale YouTube |
| Instagram | `instagram` | Link al profilo Instagram |
| Facebook | `facebook` | Link alla pagina Facebook |
| Reddit | `reddit` | Link al subreddit |
| Telegram | `telegram` | Link al canale Telegram |
| Bluesky | `bluesky` | Link al profilo Bluesky |
| Threads | `threads` | Link al profilo Threads |
| Medium | `medium` | Link alla pubblicazione su Medium |
| Hacker News | `hacker-news` | Link al profilo Hacker News |
| Sito web | `website` | Link al sito web principale |

<Tip>
Le icone vengono mostrate in un ordine predefinito, indipendentemente da come le definisci nella configurazione. GitHub e X/Twitter compaiono per primi, seguiti dalle altre piattaforme.
</Tip>

### Colonne di link

Aggiungi gruppi di link organizzati sopra le icone social:

```json
{
  "footer": {
    "links": [
      {
        "header": "Resources",
        "items": [
          { "label": "Blog", "href": "https://yourcompany.com/blog" },
          { "label": "Changelog", "href": "/changelog" }
        ]
      },
      {
        "header": "Company",
        "items": [
          { "label": "About", "href": "https://yourcompany.com/about" },
          { "label": "Careers", "href": "https://yourcompany.com/careers" }
        ]
      }
    ],
    "socials": {
      "github": "https://github.com/yourcompany",
      "x": "https://x.com/yourcompany"
    }
  }
}
```

| Campo | Tipo | Descrizione |
|-------|------|-------------|
| `links` | array | Array di oggetti che rappresentano le colonne di link |
| `links[].header` | string | Intestazione della colonna (facoltativa) |
| `links[].items` | array | Link nella colonna |
| `links[].items[].label` | string | Testo visualizzato per il link |
| `links[].items[].href` | string | URL (percorsi interni o URL esterni) |

<Note>
I link esterni (che iniziano con `http`) si aprono automaticamente in una nuova scheda. I link interni portano a un'altra pagina della documentazione.
</Note>

### Nascondere il piè di pagina in pagine specifiche

Usa il frontmatter per nascondere il piè di pagina in singole pagine:

```yaml
---
title: Landing Page
hideFooter: true
---
```

È utile per le landing page personalizzate o per le pagine in cui il piè di pagina potrebbe distrarre.

## Identità visiva di Jamdesk

Per impostazione predefinita, un link "Powered by Jamdesk" compare nel piè di pagina delle pagine della documentazione. Questo link aiuta altri team a scoprire Jamdesk. Se preferisci, puoi rimuoverlo.

### Nascondere l'identità visiva

Per rimuovere il branding Jamdesk:

1. Vai a **Settings** nella dashboard Jamdesk
2. Individua la sezione **Build Settings**
3. Disattiva **Show Jamdesk Branding**
4. Avvia una nuova build

<Note>
L'opzione per il branding è disponibile in tutti i piani. Le modifiche richiedono una nuova build per diventare effettive.
</Note>


## Dominio personalizzato

Aggiungi il tuo dominio nella dashboard Jamdesk:

1. Vai a **Settings** → **Domains**
2. Aggiungi il tuo dominio (ad esempio, `docs.yourcompany.com`)
3. Configura il DNS come indicato
4. Attendi la verifica

La documentazione sarà disponibile sul tuo dominio personalizzato con SSL automatico.
