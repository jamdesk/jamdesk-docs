## Errori di build

La dashboard mostra una build come "Failed". Cause comuni:

- Una pagina MDX con un import o un componente non valido.
- Un `docs.json` non valido (parentesi non chiuse, virgole finali dopo l'ultimo elemento di un array).
- Una pagina elencata nella navigazione di `docs.json` che non esiste come file `.mdx`.

Esegui `jamdesk dev` prima di fare push. Rileva localmente i primi due problemi.

<Tip>
Il log di build nella dashboard indica il file e la riga esatti dell'errore. Parti da lì.
</Tip>

Per i codici di errore specifici, consulta [Errori di build](/it/help/troubleshooting/build-failures) e il [Riferimento errori](/it/help/troubleshooting/error-reference).

## Impossibile verificare il dominio personalizzato

Se il dominio resta "Pending" dopo aver aggiunto i record DNS, controlla questi punti in ordine:

1. Verifica di aver aggiunto il record **TXT** `_jamdesk.<hostname>`. Senza di esso il routing non si attiva. Un record TXT mancante è la causa più comune di un dominio in stato Pending. L'hostname è il dominio completo che stai verificando (per `docs.example.com`, il nome del record TXT è `_jamdesk.docs.example.com`).
2. Verifica di aver aggiunto un record **CNAME** (non un record A) per i sottodomini.
3. Se usi Cloudflare, imposta il proxy su **DNS only** (nuvola grigia) per entrambi i record.
4. Controlla la propagazione su [whatsmydns.net](https://www.whatsmydns.net/).

```bash
# Verify the TXT verification record
dig TXT _jamdesk.docs.yourdomain.com

# Verify your CNAME is resolving
dig CNAME docs.yourdomain.com
```

La dashboard può mostrare "Pending" per fino a 30 minuti dopo che `dig` ha risolto i tuoi record. Il verificatore si trova dietro resolver upstream che memorizzano nella cache le risposte DNS negative. Attendi mezz'ora prima di cercare un problema più profondo.

[Risoluzione problemi DNS](/it/help/troubleshooting/dns-issues) descrive le particolarità specifiche di ciascun provider.

## Una specifica OpenAPI valida non supera la convalida

`jamdesk dev` rifiuta una specifica valida con errori come `#/servers/0/variables/host must NOT have unevaluated properties`. Questo capita di solito con le variabili di server che includono una `description`, o con una licenza che ha solo un `name`. Il problema è la copia del meta-schema OpenAPI 3.1 fornita con la CLI. npm 12 blocca per impostazione predefinita gli script di installazione dei pacchetti, quindi salta il passaggio che corregge due difetti noti dello schema.

Aggiorna la CLI. La versione 1.1.167 e successive correggono lo schema al momento della validazione:

```bash
npm install -g jamdesk@latest
```

Su una versione fissata più vecchia, esegui `npm install -g --allow-scripts=jamdesk jamdesk` per consentire l'esecuzione dello script di installazione.

## Repository GitHub non visualizzato

Un repo mancante dall'elenco di solito significa che la GitHub App di Jamdesk non è installata sull'organizzazione del repo. È anche possibile che l'accesso ai repository sia impostato su "Selected repositories" senza includere il tuo. Riautorizza su [github.com/settings/installations](https://github.com/settings/installations) e concedi l'accesso a "All repositories" o al repo specifico.

Consulta [Problemi GitHub](/it/help/troubleshooting/github-issues) per problemi di webhook e permessi.

## Dati analytics mancanti

Le analisi possono richiedere fino a 24 ore per comparire dopo il primo deploy di un sito. Gli ad blocker e la funzione Do Not Track impediscono il conteggio di alcune visite. I tuoi numeri saranno sempre in ritardo rispetto ai log del server. Se la dashboard mostra ancora zero visitatori, verifica che il sito sia distribuito e accessibile pubblicamente.

[Problemi di analisi](/it/help/troubleshooting/analytics-issues) approfondisce i dati in ritardo o mancanti.

## Problemi di accesso

Se non riesci ad accedere o vieni rimandato alla schermata di login, cancella cache e cookie per `dashboard.jamdesk.com`. Poi prova con una finestra di navigazione in incognito. L'accesso con GitHub richiede che l'email GitHub corrisponda all'email del tuo account Jamdesk.

Consulta [Problemi di accesso](/it/help/troubleshooting/login-issues) per i passaggi di recupero dell'account.
