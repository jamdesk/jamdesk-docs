Migra un progetto Mintlify con un solo comando: `jamdesk migrate` legge `mint.json`, scrive `docs.json` e riscrive il tuo MDX sul posto. Per GitBook, Docusaurus, ReadMe, Confluence o un'altra piattaforma, segui i passaggi manuali nella scheda "Altre piattaforme".

<YouTube id="DvIHWeBliK0" />

<Info>
**Esporta prima come Markdown, se possibile.** Jamdesk è basato su MDX. Un file Markdown richiede solo la rinomina in `.mdx` e poche righe di frontmatter.
</Info>

    ### Migrazione automatica

    <Steps>
      <Step title="Installa la CLI">
        ```bash
        npm install -g jamdesk
        ```
      </Step>
      <Step title="Esegui la migrazione">
        ```bash
        jamdesk migrate
        ```

        Eseguilo dalla radice del progetto. Il comando fa quanto segue:

        - Legge `mint.json` e scrive `docs.json`
        - Rinomina i componenti deprecati nei file MDX (ad es. `CardGroup` → `Columns`)
        - Sposta i file snippet MDX orfani in `/snippets/` e riscrive ogni import relativo al genitore (`../foo/bar.mdx`) in uno relativo alla radice (`/snippets/foo/bar.mdx`)
        - Estrae i componenti inline che usano React hook in `/snippets/<name>.tsx` con la direttiva `'use client'` e riscrive l'MDX originale per importare da `/snippets/`
        - Corregge automaticamente i problemi di sintassi MDX meccanici che causerebbero il crash della build

        Il comando è idempotente. Eseguilo di nuovo dopo le modifiche per applicare solo le novità. Tutto ciò che non può essere corretto in sicurezza viene stampato come avviso con il file, l'import e l'azione da compiere.
      </Step>
      <Step title="Rivedi e adatta">
        Controlla il `docs.json` e i file MDX generati. Verifica la struttura di navigazione e correggi gli avvisi stampati dalla CLI.
      </Step>
    </Steps>

    ### Mappatura della configurazione

    La CLI converte `mint.json` in `docs.json`. Usa queste differenze per verificare l'output.

    **Mintlify (`mint.json`):**
    ```json
    {
      "name": "My Docs",
      "navigation": [
        { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
      ],
      "colors": { "primary": "#0D9373" },
      "topbarLinks": [{ "name": "Blog", "url": "https://example.com/blog" }]
    }
    ```

    **Jamdesk (`docs.json`):**
    ```json
    {
      "$schema": "https://jamdesk.com/docs.json",
      "name": "My Docs",
      "theme": "jam",
      "colors": { "primary": "#0D9373" },
      "navbar": {
        "links": [{ "label": "Blog", "href": "https://example.com/blog" }]
      },
      "navigation": {
        "groups": [
          { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
        ]
      }
    }
    ```

    ### Compatibilità dei componenti

    La maggior parte dei componenti Mintlify ha un equivalente diretto in Jamdesk. Alcuni hanno nomi o sintassi diversi.

    | Componente Mintlify | Equivalente Jamdesk | Note |
    |---|---|---|
    | `<Card>` | `<Card>` | Stessa sintassi |
    | CardGroup | `<Columns>` | Usa la prop `cols` per il numero di colonne |
    | `<Columns>` | `<Columns>` | Stessa sintassi |
    | `<Accordion>` | `<Accordion>` | Stessa sintassi |
    | `<Tabs>` / `<Tab>` | `<Tabs>` / `<Tab>` | Stessa sintassi |
    | `<Steps>` / `<Step>` | `<Steps>` / `<Step>` | Stessa sintassi |
    | `<CodeGroup>` | `<CodeGroup>` | Stessa sintassi |
    | `<Tip>`, `<Note>`, `<Warning>` | `<Tip>`, `<Note>`, `<Warning>` | Stessa sintassi |
    | `<ResponseField>` | `<ParamField>` | Nome diverso |
    | `<Snippet>` | Import da `/snippets/` | Approccio diverso |

    ### Problemi comuni

    <AccordionGroup>
      <Accordion title="CardGroup diventa Columns">
        `jamdesk migrate` rinomina `CardGroup` in `Columns` in ogni file MDX. La prop `cols` viene mantenuta invariata. Controlla i file che hai modificato dopo aver eseguito la migrazione.
      </Accordion>
      <Accordion title="ResponseField diventa ParamField">
        Rinomina `<ResponseField>` in `<ParamField>`. Le prop restano le stesse.

        ```mdx
        {/* Before */}
        <ResponseField name="id" type="string" required>
          The unique identifier
        </ResponseField>

        {/* After */}
        <ParamField name="id" type="string" required>
          The unique identifier
        </ParamField>
        ```
      </Accordion>
      <Accordion title="Gli snippet vengono spostati e ricollegati automaticamente">
        Jamdesk risolve solo gli import `/snippets/*` relativi alla radice. I progetti Mintlify spesso conservano i file snippet MDX in qualsiasi punto dell'albero e li importano con percorsi relativi al genitore (`import X from '../shared/x.mdx'`).

        `jamdesk migrate` risolve questo problema:

        - Sposta in `/snippets/` i file MDX importati come snippet ma che si trovano al di fuori di `/snippets/`. Mantiene il loro percorso relativo, così gli snippet con prefisso di locale come `de/foo.mdx` non entrano in conflitto.
        - Riscrive ogni import di snippet relativo al genitore in ogni file MDX con il nuovo percorso relativo alla radice.
        - Estrae qualsiasi componente inline che usa React hook in un file `'use client'` in `/snippets/<name>.tsx` e sostituisce l'export inline con un import da `/snippets/`.

        Sostituisci l'elemento JSX `<Snippet file="my-snippet.mdx" />` di Mintlify con un import MDX. La CLI non lo riscrive:

        ```mdx
        {/* Before (Mintlify) */}
        <Snippet file="my-snippet.mdx" />

        {/* After (Jamdesk) */}
        import MySnippet from '/snippets/my-snippet.mdx'

        <MySnippet />
        ```

        Il relocator si interrompe senza toccare nulla se il progetto non ha una navigazione risolta o se gli spostamenti pianificati superano `max(5, 25%)` di tutti i file MDX. Stampa il motivo. Correggilo e riesegui.
      </Accordion>
      <Accordion title="topbarLinks corrisponde a navbar.links">
        `topbarLinks` e `topbarCtaButton` di Mintlify corrispondono a `navbar.links` in `docs.json`. Il campo `name` diventa `label`. Il campo `url` diventa `href`.
      </Accordion>
    </AccordionGroup>

    ### Da GitBook

    GitBook memorizza i contenuti come Markdown con un file `SUMMARY.md` per la navigazione.

    <Steps>
      <Step title="Esporta i tuoi contenuti">
        Esporta il tuo spazio GitBook come Markdown. Con la sincronizzazione Git di GitBook, i tuoi contenuti sono già in un repo Git come file `.md`.
      </Step>
      <Step title="Converti i file in MDX">
        Rinomina i file `.md` in `.mdx` e aggiungi il frontmatter a ogni file:

        ```mdx
        ---
        title: Your Page Title
        description: A short description of the page
        ---

        Your existing Markdown content here.
        ```
      </Step>
      <Step title="Mappa la navigazione da SUMMARY.md">
        Converti la barra laterale di `SUMMARY.md` nei gruppi di navigazione di `docs.json`.

        **GitBook (`SUMMARY.md`):**
        ```markdown
        # Summary

        ## Getting Started
        * [Introduction](introduction.md)
        * [Quick Start](quickstart.md)

        ## API Reference
        * [Authentication](api/auth.md)
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["introduction", "quickstart"]
              },
              {
                "group": "API Reference",
                "pages": ["api/auth"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Sposta le immagini">
        Sposta tutte le immagini in una directory `/images` e aggiorna i riferimenti nei file MDX per usare percorsi assoluti (ad es. `/images/screenshot.png`).
      </Step>
      <Step title="Testa in locale">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Da Docusaurus

    I progetti Docusaurus usano già MDX. La maggior parte dei contenuti si trasferisce direttamente.

    <Steps>
      <Step title="Copia i tuoi file MDX">
        Copia il contenuto della directory `docs/` di Docusaurus nella radice del tuo progetto Jamdesk. Mantieni la struttura di directory esistente.
      </Step>
      <Step title="Pulisci il frontmatter">
        Rimuovi i campi di frontmatter specifici di Docusaurus. Mantieni `title` e `description`, elimina il resto.

        ```yaml
        ---
        # Remove these Docusaurus fields
        sidebar_position: 3
        sidebar_label: "Custom Label"
        slug: /custom-url
        pagination_next: null

        # Keep these
        title: Your Page Title
        description: A short description
        ---
        ```
      </Step>
      <Step title="Mappa sidebars.js su docs.json">
        Converti la struttura delle categorie di `sidebars.js` nei gruppi di navigazione di `docs.json`.

        **Docusaurus (`sidebars.js`):**
        ```javascript
        module.exports = {
          docs: [
            {
              type: 'category',
              label: 'Getting Started',
              items: ['intro', 'installation'],
            },
          ],
        };
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["intro", "installation"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Sostituisci i componenti Docusaurus">
        Sostituisci i componenti specifici di Docusaurus con gli equivalenti di Jamdesk.

        | Docusaurus | Jamdesk | Esempio |
        |---|---|---|
        | `:::note` / `:::tip` / `:::warning` | `<Note>` / `<Tip>` / `<Warning>` | Vedi [componenti callout](/it/components/overview) |
        | `import Tabs from '@theme/Tabs'` | `<Tabs>` (disponibile globalmente) | Nessun import necessario |
        | `import TabItem from '@theme/TabItem'` | `<Tab>` (disponibile globalmente) | Usa `title` invece di `label` |
      </Step>
      <Step title="Testa in locale">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Da altri strumenti

    Per Confluence, Notion, ReadMe o un'altra piattaforma, porta i contenuti in Markdown. Poi imposta la struttura del progetto Jamdesk.

    <Steps>
      <Step title="Esporta come Markdown">
        La maggior parte delle piattaforme offre un'opzione di esportazione in Markdown o HTML. Usa Markdown se disponibile. Converti l'HTML in Markdown con uno strumento come [Pandoc](https://pandoc.org/).

        ```bash
        # Convert HTML to Markdown with Pandoc
        pandoc input.html -f html -t markdown -o output.md
        ```
      </Step>
      <Step title="Crea docs.json">
        Parti da una configurazione minima. Aggiungi alla navigazione man mano che aggiungi pagine.
      </Step>
      <Step title="Converti i file in MDX">
        Rinomina i file `.md` in `.mdx` e aggiungi il frontmatter (`title`, `description`) a ogni file.
      </Step>
      <Step title="Sposta le risorse">
        Sposta immagini e altre risorse in una directory `/images`. Aggiorna i riferimenti ai file per usare percorsi assoluti.
      </Step>
      <Step title="Testa in locale">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>
