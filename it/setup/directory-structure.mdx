Organizza i file in un repository di documentazione Jamdesk, dal minimo di due file a un layout completo con più directory.

## Struttura minima

Il progetto Jamdesk più semplice richiede solo due file:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

## Struttura consigliata

Per siti di documentazione più grandi, organizza le pagine in directory:

```bash
my-docs/
├── docs.json
├── introduction.mdx
├── quickstart.mdx
│
├── guides/
│   ├── getting-started.mdx
│   ├── authentication.mdx
│   └── deployment.mdx
│
├── api-reference/
│   ├── overview.mdx
│   ├── endpoints/
│   │   ├── users.mdx
│   │   └── projects.mdx
│   └── webhooks.mdx
│
├── images/
│   ├── logo.svg
│   ├── favicon.svg
│   └── screenshots/
│       └── dashboard.png
│
└── snippets/
    └── api-base-url.mdx
```

<Tip>
Il [repository della documentazione Jamdesk](https://github.com/jamdesk/jamdesk-docs) è un esempio di produzione di questa struttura: due tab, oltre 120 pagine, specifiche OpenAPI e script personalizzati.
</Tip>

## File obbligatori

### docs.json

Il file di configurazione che definisce il tuo sito. Deve trovarsi nella radice della directory della documentazione (o nel percorso specificato nelle impostazioni del progetto).

```json docs.json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Documentation",
  "theme": "jam",
  "colors": {
    "primary": "#635BFF"
  },
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "quickstart"]
      }
    ]
  }
}
```

Consulta il [riferimento docs.json](/it/config/docs-json-reference) per tutte le opzioni.

## Organizzazione delle pagine

### Struttura piatta o annidata

Scegli in base alla dimensione della documentazione:

<Tabs>
  <Tab title="Piatta (< 20 pagine)">
    Mantieni tutte le pagine nella radice:

    ```bash
    docs/
    ├── docs.json
    ├── introduction.mdx
    ├── installation.mdx
    ├── configuration.mdx
    └── troubleshooting.mdx
    ```

    Fai riferimento alle pagine direttamente nella navigazione:

    ```json
    "pages": ["introduction", "installation"]
    ```
  </Tab>
  <Tab title="Annidata (20+ pagine)">
    Raggruppa le pagine correlate in directory:

    ```bash
    docs/
    ├── docs.json
    ├── introduction.mdx
    ├── guides/
    │   ├── quickstart.mdx
    │   └── advanced.mdx
    └── reference/
        ├── api.mdx
        └── cli.mdx
    ```

    Includi la directory nel percorso:

    ```json
    "pages": ["introduction", "guides/quickstart", "reference/api"]
    ```
  </Tab>
</Tabs>

### Convenzioni di denominazione

| Convenzione | Esempio | URL |
|------------|---------|-----|
| Minuscole | `getting-started.mdx` | `/getting-started` |
| Kebab-case | `api-reference.mdx` | `/api-reference` |
| Directory | `guides/auth.mdx` | `/guides/auth` |

<Warning>
Evita spazi e caratteri speciali nei nomi dei file. Usa i trattini per separare le parole.
</Warning>

## Directory speciali

### images/

Conserva immagini, loghi e favicon:

```bash
images/
├── logo-light.webp     # Light mode logo
├── logo-dark.webp      # Dark mode logo
├── favicon.svg         # Browser favicon
└── screenshots/        # Documentation screenshots
    └── dashboard.png
```

Riferimento in docs.json:

```json docs.json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp"
  },
  "favicon": "/images/favicon.svg"
}
```

### snippets/

Blocchi di contenuto riutilizzabili:

```bash
snippets/
├── api-base-url.mdx
└── auth-header.mdx
```

Inclusione nelle pagine:

```mdx
<Snippet file="api-base-url.mdx" />
```

### openapi/

File di specifiche OpenAPI per la documentazione delle API:

```bash
openapi/
├── api.yaml
└── webhooks.yaml
```

Riferimento in docs.json:

```json docs.json
{
  "api": {
    "openapi": ["/openapi/api.yaml"]
  }
}
```

Per un esempio dal vivo, consulta [Esempio OpenAPI](/it/api-reference/openapi-example).

#### File delle specifiche specifici per lingua

Per siti di documentazione multilingue, aggiungi file di specifiche tradotti accanto a quello sorgente con un infisso del codice lingua:

```bash
openapi/
├── api.yaml
├── api.fr.yaml
├── api.es.yaml
└── api.zh.yaml
```

Jamdesk serve automaticamente la specifica corretta quando una pagina viene renderizzata sotto un prefisso di lingua (`/fr/…`, `/es/…`, ecc.). Consulta [Supporto multilingue → Traduzione delle specifiche OpenAPI](/it/setup/languages#translating-openapi-specs) per le regole complete su cosa tradurre e cosa mantenere identico.

## File da ignorare

Crea un `.gitignore` per escludere gli artefatti di build:

```bash
.jamdesk/
node_modules/
.DS_Store
*.log
```

La directory `.jamdesk/` contiene la cache di sviluppo locale. Non committarla.
