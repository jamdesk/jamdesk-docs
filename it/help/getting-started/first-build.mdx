## Build automatiche

Jamdesk avvia il tuo primo build non appena colleghi un repository. Ogni push successivo sul branch collegato attiva un nuovo build.

## Avanzamento della build

Segui il tuo build nella dashboard:

<Steps>
  <Step title="Queued">
    Il tuo build è in attesa di iniziare. Negli orari di punta può esserci una breve coda.
  </Step>
  <Step title="Cloning">
    Jamdesk recupera i contenuti del tuo repository da GitHub.
  </Step>
  <Step title="Validating">
    Jamdesk controlla il tuo `docs.json` e i file MDX alla ricerca di errori.
  </Step>
  <Step title="Building">
    Jamdesk compila MDX in HTML con evidenziazione della sintassi e un indice di ricerca.
  </Step>
  <Step title="Deploying">
    I file generati vengono caricati sulla CDN globale.
  </Step>
  <Step title="Live">
    La tua documentazione è disponibile all'URL del tuo progetto.
  </Step>
</Steps>

## Visualizzare la documentazione pubblicata

Fai clic su **View Site** nella dashboard oppure visita `https://your-project.jamdesk.app`.

La tua documentazione compare anche sul tuo dominio personalizzato, se ne hai configurato uno.

## Ricostruzione manuale

Ricostruisci senza eseguire un push delle modifiche:

1. Vai al tuo progetto nella [dashboard](https://dashboard.jamdesk.com)
2. Apri **Settings**
3. Fai clic su **Rebuild**

Usalo dopo aver modificato le variabili d'ambiente o per forzare un build nuovo.

## Se la build non riesce

La dashboard mostra un messaggio di errore per un build non riuscito. Cause comuni:

- Sintassi non valida in `docs.json`
- Errori di sintassi MDX
- Pagine mancanti referenziate nella navigazione
