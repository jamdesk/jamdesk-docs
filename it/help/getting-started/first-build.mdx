La tua prima build viene avviata automaticamente quando colleghi un repository.

## Build automatiche

Quando colleghi un repository, Jamdesk avvia immediatamente una build iniziale. Ogni push successivo al branch collegato attiva automaticamente una nuova build.

## Avanzamento della build

Monitora la build nel dashboard:

<Steps>
  <Step title="Queued">
    La build è in attesa di avvio. Nei periodi di maggiore utilizzo potrebbe esserci una breve coda.
  </Step>
  <Step title="Cloning">
    Jamdesk recupera i contenuti del repository da GitHub.
  </Step>
  <Step title="Validating">
    La sintassi di `docs.json` e dei file MDX viene verificata per individuare eventuali errori.
  </Step>
  <Step title="Building">
    MDX viene compilato in HTML ottimizzato con evidenziazione della sintassi e indicizzazione per la ricerca.
  </Step>
  <Step title="Deploying">
    I file compilati vengono caricati sul CDN globale.
  </Step>
  <Step title="Live">
    La documentazione è disponibile all'URL del progetto.
  </Step>
</Steps>

## Visualizzare la documentazione pubblicata

Al termine della build, fai clic su **View Site** nel dashboard oppure visita `https://your-project.jamdesk.app`.

Se hai configurato un dominio personalizzato, la documentazione sarà disponibile anche a quell'indirizzo.

## Ricostruzione manuale

Devi eseguire una nuova build senza effettuare il push di modifiche?

1. Vai al progetto nel [dashboard](https://dashboard.jamdesk.com)
2. Apri **Settings**
3. Fai clic su **Rebuild**

Usa questa procedura dopo aver modificato le variabili d'ambiente o per forzare una nuova build.

## Se la build non riesce

Gli errori di build mostrano un messaggio di errore nel dashboard. Cause comuni:

- Sintassi non valida in `docs.json`
- Errori di sintassi MDX
- Pagine mancanti a cui si fa riferimento nella navigazione
