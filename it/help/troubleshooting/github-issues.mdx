La maggior parte dei problemi di integrazione con GitHub è dovuta a autorizzazioni, errori dei webhook o branch non corrispondenti.

## Organizzazione non visualizzata durante la configurazione

Durante il flusso di configurazione della documentazione iniziale, Jamdesk mostra le tue organizzazioni GitHub così puoi scegliere dove creare il repository. L'elenco proviene dall'API OAuth di GitHub e GitHub nasconde le organizzazioni in due casi:

- Restrizioni dell'app OAuth: la tua organizzazione limita l'accesso alle app di terze parti (impostazione predefinita di GitHub per le nuove organizzazioni) e non ha ancora approvato Jamdesk.
- SAML SSO: la tua organizzazione richiede l'autenticazione SAML prima che l'API la restituisca.

<Accordion title="Concedi tu stesso l'accesso (proprietari dell'organizzazione)">
  Se sei il proprietario dell'organizzazione, puoi approvare subito Jamdesk:

  1. Fai clic su **grant Jamdesk access on GitHub** sotto il selettore dell'organizzazione (oppure vai su GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. In **Organization access**, fai clic su **Grant** accanto alla tua organizzazione
  3. Torna al flusso di configurazione di Jamdesk e fai clic su **refresh the list**. La tua organizzazione appare immediatamente

  Se sei un membro (non un proprietario), vedrai invece un pulsante **Request**; facendo clic invierai una richiesta di approvazione agli amministratori della tua organizzazione.
</Accordion>

<Accordion title="Chiedi all'amministratore di approvare Jamdesk (membri)">
  Se sei un membro senza diritti di proprietario, invia prima una richiesta di approvazione agli amministratori:

  1. Vai su GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. In **Organization access**, fai clic su **Request** accanto alla tua organizzazione. Questa azione avvisa gli amministratori
  3. Un amministratore approva la richiesta in **Settings** → **Third-party access** → **OAuth application policy** dell'organizzazione (le richieste in sospeso mostrano un pulsante **Approve**)
  4. Torna al flusso di configurazione di Jamdesk e fai clic su **refresh the list**; ora la tua organizzazione dovrebbe essere visualizzata

  Consulta la guida di GitHub su [come approvare le app OAuth per la tua organizzazione](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization) per i passaggi dettagliati.
</Accordion>

<Accordion title="Crea nel tuo account personale e trasferisci in seguito">
  Non vuoi aspettare l'approvazione dell'amministratore? Durante la configurazione, scegli il tuo account personale e trasferisci in seguito il repository alla tua organizzazione:

  1. Completa la configurazione di Jamdesk usando il tuo account personale
  2. Vai al repository creato su GitHub
  3. Vai su **Settings** → **General** → **Danger Zone**
  4. Fai clic su **Transfer** e seleziona la tua organizzazione come destinazione
  5. In Jamdesk, disconnetti e riconnetti il repository dalla pagina **Settings** del progetto

  <Warning>
    La disconnessione e la riconnessione generano un nuovo URL della documentazione (ad esempio, `your-project.jamdesk.app` potrebbe cambiare). Se hai già condiviso l'URL o configurato un dominio personalizzato, contatta il [supporto](/it/help/support/contact) prima di disconnetterti, così potremo preservare la configurazione.
  </Warning>

  Questa procedura non funziona se la tua azienda gestisce il tuo account GitHub. Consulta invece [Account GitHub gestiti dall'azienda](#account-github-gestiti-dallazienda).
</Accordion>

## Account GitHub gestiti dall'azienda

Se la tua azienda gestisce il tuo account GitHub (GitHub li chiama Enterprise Managed Users o EMU), GitHub non ti consente di installare app sul tuo account, ma solo su un'organizzazione. Se non hai un'organizzazione da usare, facendo clic su **Install** su GitHub torni semplicemente alla pagina dell'app Jamdesk. Durante la registrazione, Jamdesk mostra il messaggio "Your organization manages this GitHub account".

I nomi utente gestiti terminano con un carattere di sottolineatura e un codice aziendale, ad esempio `jsmith_acme`. GitHub spiega queste limitazioni nella pagina sugli [account utente gestiti](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts).

Puoi risolvere il problema in uno dei due modi seguenti.

<Accordion title="Sposta il repository in un'organizzazione">
  1. Chiedi al proprietario dell'azienda di [creare un'organizzazione](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise) dalla scheda **Organizations** della tua azienda. Chiedigli di consentirti di creare repository al suo interno.
  2. [Trasferisci il repository della documentazione](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository) al suo interno. Nel repository, vai su **Settings**, fai clic su **Transfer** in fondo alla pagina e scegli la nuova organizzazione.
  3. In Jamdesk, fai clic su **Connect an existing repository** (oppure su **Install GitHub App** nelle impostazioni del progetto). Su GitHub, scegli l'organizzazione, seleziona **Only select repositories**, seleziona il repository e installa l'app.

  Se GitHub mostra **Request** invece di **Install**, un proprietario dell'organizzazione riceverà un'e-mail per approvare la richiesta. Dopo l'approvazione, fai nuovamente clic sul pulsante di Jamdesk.
</Accordion>

<Accordion title="Usa un account GitHub personale">
  Usa questa opzione se la tua azienda non può aggiungere un'organizzazione. Prima chiedi conferma all'amministratore GitHub, poiché la documentazione sarà esterna all'account GitHub aziendale.

  1. In una finestra privata del browser, accedi a GitHub con un account personale (oppure creane uno).
  2. Crea un repository privato vuoto su quell'account.
  3. Invia una copia della documentazione al repository. GitHub non può trasferire repository da un'azienda gestita, quindi è necessaria una copia.

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     Mantieni `jsmith@` nell'URL in modo che Git richieda le credenziali del tuo account personale.

  4. In Jamdesk, fai clic su **Connect an existing repository** (oppure su **Install GitHub App** nelle impostazioni del progetto), installa Jamdesk sul tuo account personale e scegli il repository.

  Gli account gestiti non possono eseguire il push verso repository esterni alla tua azienda, quindi chiunque modifichi la documentazione deve avere un account GitHub personale. Aggiungili al repository come collaboratori.
</Accordion>

## Repository non visualizzato

Se il tuo repository non appare nell'elenco:

<Accordion title="Controlla le autorizzazioni del repository">
  1. Vai su GitHub → Settings → Applications → Jamdesk
  2. Verifica che l'accesso al repository sia stato concesso
  3. Fai clic su **Configure** per aggiungere altri repository
</Accordion>

<Accordion title="Repository dell'organizzazione">
  Per i repository dell'organizzazione:
  1. Un amministratore dell'organizzazione deve approvare Jamdesk
  2. Vai alle impostazioni dell'organizzazione → Third-party access
  3. Approva la richiesta di accesso di Jamdesk
</Accordion>

<Accordion title="Repository privati">
  I repository privati richiedono l'autorizzazione di GitHub. Se necessario, autorizza nuovamente Jamdesk.
</Accordion>

## Build non avviate

Se i push non avviano le build:

<Steps>
  <Step title="Controlla il webhook">
    1. Vai al tuo repository su GitHub
    2. Vai su Settings → Webhooks
    3. Trova il webhook di Jamdesk
    4. Controlla la sezione "Recent Deliveries" per verificare la presenza di errori
  </Step>
  <Step title="Verifica il branch">
    Le build vengono avviate solo sul branch configurato. Controlla **Settings** in Jamdesk.
  </Step>
  <Step title="Sincronizza nuovamente la connessione">
    1. Vai su **Settings** del progetto in Jamdesk
    2. Fai clic su **Re-sync GitHub**
  </Step>
</Steps>

## Errori dei webhook

### 404 Not Found

Non è stato possibile raggiungere l'endpoint del webhook.

**Correzione:** sincronizza nuovamente la connessione GitHub nelle impostazioni del progetto.

### 401 Unauthorized

L'autenticazione non è riuscita.

**Correzione:**
1. Vai alle impostazioni del tuo account GitHub
2. Vai su Applications → Authorized OAuth Apps
3. Revoca Jamdesk
4. Autorizza nuovamente Jamdesk nelle impostazioni

### 500 Server Error

Problema temporaneo di Jamdesk.

**Correzione:** attendi alcuni minuti e riprova a eseguire il push oppure avvia una nuova build manualmente.

## Errori di autorizzazione

**"Repository not found"** durante la build:

- Il repository potrebbe essere stato eliminato o rinominato
- Jamdesk potrebbe non avere più accesso
- Autorizza nuovamente la connessione GitHub

## Problemi del branch

### Build sul branch sbagliato

Controlla il branch configurato in **Settings** → **Repository**.

### Branch rinominato o eliminato

Aggiorna l'impostazione del branch in modo che corrisponda al nuovo nome.
