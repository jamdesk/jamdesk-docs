La maggior parte dei problemi di integrazione con GitHub dipende da autorizzazioni, errori dei webhook o rami non corrispondenti.

## Organizzazione non visualizzata durante la configurazione

Durante la procedura iniziale di configurazione della documentazione, Jamdesk mostra le tue organizzazioni GitHub, così puoi scegliere dove creare il repository. L'elenco proviene dall'API OAuth di GitHub e GitHub nasconde le organizzazioni in due casi:

- Restrizioni delle app OAuth: la tua organizzazione limita l'accesso alle app di terze parti (impostazione predefinita di GitHub per le nuove organizzazioni) e non ha ancora approvato Jamdesk.
- SSO SAML: l'organizzazione richiede l'autenticazione SAML prima che l'API la restituisca.

<Accordion title="Concedi tu l'accesso (proprietari dell'organizzazione)">
  Se sei proprietario dell'organizzazione, puoi approvare subito Jamdesk:

  1. Fai clic su **grant Jamdesk access on GitHub** sotto il selettore dell'organizzazione (oppure vai su GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. In **Organization access**, fai clic su **Grant** accanto alla tua organizzazione
  3. Torna alla procedura di configurazione di Jamdesk e fai clic su **refresh the list**. L'organizzazione verrà visualizzata subito

  Se sei un membro, ma non un proprietario, vedrai invece il pulsante **Request**; facendo clic, invierai una richiesta di approvazione agli amministratori dell'organizzazione.
</Accordion>

<Accordion title="Chiedi all'amministratore di approvare Jamdesk (membri)">
  Se sei un membro senza i diritti di proprietario, invia prima una richiesta di approvazione agli amministratori:

  1. Vai su GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. In **Organization access**, fai clic su **Request** accanto alla tua organizzazione. Gli amministratori dell'organizzazione riceveranno una notifica
  3. Un amministratore approva la richiesta in **Settings** → **Third-party access** → **OAuth application policy** dell'organizzazione (le richieste in sospeso mostrano il pulsante **Approve**)
  4. Torna alla procedura di configurazione di Jamdesk e fai clic su **refresh the list**; ora l'organizzazione dovrebbe essere visualizzata

  Per i passaggi dettagliati, consulta la guida GitHub sull'[approvazione delle app OAuth per la tua organizzazione](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization).
</Accordion>

<Accordion title="Crea un repository nell'account personale e trasferiscilo in seguito">
  Non vuoi aspettare l'approvazione dell'amministratore? Durante la configurazione, scegli il tuo account personale e poi trasferisci il repository all'organizzazione:

  1. Completa la configurazione di Jamdesk usando il tuo account personale
  2. Vai al repository appena creato su GitHub
  3. Vai su **Settings** → **General** → **Danger Zone**
  4. Fai clic su **Transfer** e seleziona la tua organizzazione come destinazione
  5. In Jamdesk, disconnetti e riconnetti il repository dalla pagina **Settings** del progetto

  <Warning>
    Disconnettere e riconnettere il repository genera un nuovo URL della documentazione (ad esempio, `your-project.jamdesk.app` potrebbe cambiare). Se hai già condiviso l'URL o configurato un dominio personalizzato, contatta il [supporto](/it/help/support/contact) prima di disconnetterlo, così potremo mantenere la tua configurazione.
  </Warning>

  Questa soluzione non funziona se la tua azienda gestisce il tuo account GitHub. Consulta invece la sezione sugli [account GitHub gestiti dall'azienda](#account-github-gestiti-dallazienda).
</Accordion>

## Account GitHub gestiti dall'azienda

Se la tua azienda gestisce il tuo account GitHub (GitHub li chiama Enterprise Managed Users, o EMU), GitHub non ti consente di installare app sul tuo account personale, ma solo su un'organizzazione. Se non hai un'organizzazione da usare, facendo clic su **Install** su GitHub tornerai alla pagina dell'app Jamdesk. Durante la registrazione, Jamdesk mostra il messaggio "Your organization manages this GitHub account".

I nomi utente gestiti terminano con un trattino basso e un codice aziendale, ad esempio `jsmith_acme`. GitHub spiega le limitazioni nella pagina dedicata agli [account utente gestiti](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts).

Puoi risolvere il problema in uno di questi due modi.

<Accordion title="Sposta il repository in un'organizzazione">
  1. Chiedi a un proprietario Enterprise di [creare un'organizzazione](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise) dalla scheda **Organizations** della tua Enterprise. Chiedigli di consentirti di creare repository al suo interno.
  2. [Trasferisci il repository della documentazione](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository) nell'organizzazione. Nel repository, vai su **Settings**, fai clic su **Transfer** in fondo alla pagina e seleziona la nuova organizzazione.
  3. In Jamdesk, fai clic su **Connect an existing repository** (oppure su **Install GitHub App** nelle impostazioni del progetto). Su GitHub, seleziona l'organizzazione, scegli **Only select repositories**, seleziona il repository e installa l'app.

  Se GitHub mostra **Request** invece di **Install**, un proprietario dell'organizzazione riceverà un'email per approvare la richiesta. Dopo l'approvazione, fai di nuovo clic sul pulsante Jamdesk.
</Accordion>

<Accordion title="Usa un account GitHub personale">
  Usa questa opzione se la tua azienda non può aggiungere un'organizzazione. Prima, verifica con l'amministratore GitHub, perché la documentazione sarà ospitata al di fuori dell'account GitHub aziendale.

  1. In una finestra privata del browser, accedi a GitHub con un account personale (oppure creane uno).
  2. Crea un repository privato vuoto in quell'account.
  3. Esegui il push di una copia della documentazione nel repository. GitHub non consente di trasferire i repository al di fuori di un'Enterprise gestita, quindi è necessaria una copia.

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     Mantieni `jsmith@` nell'URL, così Git ti chiederà le credenziali dell'account personale.

  4. In Jamdesk, fai clic su **Connect an existing repository** (oppure su **Install GitHub App** nelle impostazioni del progetto), installa Jamdesk sul tuo account personale e seleziona il repository.

  Gli account gestiti non possono eseguire il push nei repository esterni alla propria Enterprise, quindi chiunque modifichi la documentazione deve avere un account GitHub personale. Aggiungilo al repository come collaboratore.
</Accordion>

## Repository non visualizzato

Se il repository non appare nell'elenco:

<Accordion title="Controlla le autorizzazioni del repository">
  1. Vai su GitHub → Settings → Applications → Jamdesk
  2. Verifica che l'accesso al repository sia stato concesso
  3. Fai clic su **Configure** per aggiungere altri repository
</Accordion>

<Accordion title="Repository dell'organizzazione">
  Per i repository dell'organizzazione:
  1. Un amministratore dell'organizzazione deve approvare Jamdesk
  2. Vai nelle impostazioni dell'organizzazione → Third-party access
  3. Approva la richiesta di accesso di Jamdesk
</Accordion>

<Accordion title="Repository privati">
  I repository privati richiedono l'autorizzazione di GitHub. Se necessario, autorizza di nuovo Jamdesk.
</Accordion>

## Build non avviate

Se i push non avviano le build:

<Steps>
  <Step title="Controlla il webhook">
    1. Vai al repository su GitHub
    2. Vai su Settings → Webhooks
    3. Trova il webhook di Jamdesk
    4. Controlla gli errori in "Recent Deliveries"
  </Step>
  <Step title="Verifica il ramo">
    Le build vengono avviate solo sul ramo configurato. Controlla **Settings** in Jamdesk.
  </Step>
  <Step title="Controlla chi ha eseguito il push">
    Se la build risulta non riuscita con un messaggio che indica che la persona che ha eseguito il push non è un membro, invitala in **Project Settings → Members** oppure chiedile di collegare il proprio account GitHub. Consulta la sezione [Le build non vengono avviate](/it/integrations/github#le-build-non-vengono-attivate).
  </Step>
  <Step title="Risincronizza la connessione">
    1. Vai su **Settings** del progetto in Jamdesk
    2. Fai clic su **Re-sync GitHub**
  </Step>
</Steps>

## Errori dei webhook

### 404 Not Found

Non è stato possibile raggiungere l'endpoint del webhook.

**Soluzione:** risincronizza la connessione GitHub nelle impostazioni del progetto.

### 401 Unauthorized

Autenticazione non riuscita.

**Soluzione:**
1. Vai alle impostazioni del tuo account GitHub
2. Vai su Applications → Authorized OAuth Apps
3. Revoca Jamdesk
4. Autorizza di nuovo Jamdesk nelle impostazioni

### 500 Server Error

Problema temporaneo di Jamdesk.

**Soluzione:** attendi qualche minuto ed esegui di nuovo il push, oppure avvia una build manuale.

## Errori di autorizzazione

**"Repository not found"** durante la build:

- Il repository potrebbe essere stato eliminato o rinominato
- Jamdesk potrebbe non avere più accesso
- Autorizza di nuovo la connessione GitHub

## Problemi con i rami

### Viene creata la build del ramo sbagliato

Controlla il ramo configurato in **Settings** → **Repository**.

### Ramo rinominato o eliminato

Aggiorna l'impostazione del ramo in modo che corrisponda al nuovo nome.
