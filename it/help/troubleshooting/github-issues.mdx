La maggior parte dei problemi di integrazione con GitHub dipende da permessi, errori di webhook o mancate corrispondenze di branch.

## Organizzazione non visualizzata durante la configurazione

Il flusso di configurazione della documentazione mostra le tue organizzazioni GitHub. Scegline una per ospitare il nuovo repository. L'elenco proviene dall'API OAuth di GitHub. GitHub nasconde un'organizzazione dall'elenco in due casi:

- Restrizioni dell'app OAuth: la tua organizzazione limita l'accesso alle app di terze parti (impostazione predefinita di GitHub per le nuove organizzazioni) e non ha ancora approvato Jamdesk.
- SAML SSO: la tua organizzazione richiede l'autenticazione SAML prima che l'API la restituisca.

<Accordion title="Concedi l'accesso tu stesso (proprietari dell'organizzazione)">
  Approva subito Jamdesk:

  1. Fai clic su **concedi l'accesso a Jamdesk su GitHub** sotto il selettore delle organizzazioni (oppure vai su GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. In **Organization access**, fai clic su **Grant** accanto alla tua organizzazione
  3. Torna al flusso di configurazione di Jamdesk e fai clic su **aggiorna l'elenco**. La tua organizzazione compare subito

  I membri (non i proprietari) vedono invece un pulsante **Request**. Invia una richiesta di approvazione agli amministratori dell'organizzazione.
</Accordion>

<Accordion title="Chiedi al tuo amministratore di approvare Jamdesk (membri)">
  Invia agli amministratori una richiesta di approvazione:

  1. Vai su GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. In **Organization access**, fai clic su **Request** accanto alla tua organizzazione. Questo notifica gli amministratori
  3. Un amministratore la approva in **Settings** → **Third-party access** → **OAuth application policy** dell'organizzazione (le richieste in attesa mostrano un pulsante **Approve**)
  4. Torna al flusso di configurazione di Jamdesk e fai clic su **aggiorna l'elenco**. La tua organizzazione dovrebbe ora comparire

  Per i passaggi dettagliati, consulta la guida di GitHub su [come approvare le app OAuth per la tua organizzazione](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization).
</Accordion>

<Accordion title="Crea nel tuo account personale e trasferisci in seguito">
  Scegli il tuo account personale durante la configurazione per saltare l'approvazione dell'amministratore. Trasferisci poi il repository alla tua organizzazione:

  1. Completa la configurazione di Jamdesk usando il tuo account personale
  2. Vai al repository creato su GitHub
  3. Apri **Settings** → **General** → **Danger Zone**
  4. Fai clic su **Transfer** e seleziona la tua organizzazione come destinazione
  5. In Jamdesk, scollega e ricollega il repository dalla pagina **Settings** del tuo progetto

  <Warning>
    Scollegare e ricollegare genera un nuovo URL della documentazione (ad esempio, `your-project.jamdesk.app` potrebbe cambiare). Se hai già condiviso il tuo URL o configurato un dominio personalizzato, contatta il [supporto](/it/help/support/contact) prima di scollegare. Possiamo preservare la tua configurazione.
  </Warning>

  Questo non funziona se il tuo account GitHub è gestito dall'azienda. Consulta invece [account GitHub gestiti dall'azienda](#account-github-gestiti-dallazienda).
</Accordion>

## Account GitHub gestiti dall'azienda

GitHub blocca l'installazione di app su un account gestito dall'azienda (GitHub li chiama Enterprise Managed Users, o EMU). Solo un'organizzazione può installare app. Senza un'organizzazione, cliccare su **Install** su GitHub ti riporta alla pagina dell'app Jamdesk. La registrazione a Jamdesk mostra "La tua organizzazione gestisce questo account GitHub".

I nomi utente gestiti terminano con un carattere di sottolineatura e un codice aziendale, come `jsmith_acme`. GitHub spiega i limiti nella sua pagina sugli [account utente gestiti](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-iam/understanding-iam-for-enterprises/abilities-and-restrictions-of-managed-user-accounts).

Risolvi con una di queste opzioni.

<Accordion title="Sposta il repository in un'organizzazione">
  1. Chiedi a un proprietario dell'enterprise di [creare un'organizzazione](https://docs.github.com/en/enterprise-cloud@latest/admin/managing-accounts-and-repositories/managing-organizations-in-your-enterprise/adding-organizations-to-your-enterprise) dalla scheda **Organizations** della tua enterprise. Chiedi che ti permetta di creare repository al suo interno.
  2. [Trasferisci il tuo repository della documentazione](https://docs.github.com/en/enterprise-cloud@latest/repositories/creating-and-managing-repositories/transferring-a-repository) al suo interno. Nel repository, vai su **Settings**, fai clic su **Transfer** in fondo e scegli la nuova organizzazione.
  3. In Jamdesk, fai clic su **Connect an existing repository** (oppure su **Install GitHub App** nelle impostazioni del progetto). Su GitHub, scegli l'organizzazione, seleziona **Only select repositories**, scegli il tuo repository e installa.

  Se GitHub mostra **Request** invece di **Install**, un proprietario dell'organizzazione riceve un'email per approvare la richiesta. Dopo l'approvazione, fai di nuovo clic sul pulsante di Jamdesk.
</Accordion>

<Accordion title="Usa un account GitHub personale">
  Usa questa opzione quando la tua azienda non può aggiungere un'organizzazione. Verifica prima con il tuo amministratore GitHub. La documentazione sarà ospitata al di fuori del GitHub aziendale.

  1. In una finestra privata del browser, accedi a GitHub con un account personale (oppure creane uno).
  2. Crea un repository privato vuoto su quell'account.
  3. Esegui il push di una copia della documentazione. GitHub non può trasferire repository al di fuori di un'enterprise gestita.

     ```bash
     git remote set-url origin https://jsmith@github.com/jsmith/product-docs.git
     git push -u origin main
     ```

     Mantieni `jsmith@` nell'URL così Git chiede le credenziali del tuo account personale.

  4. In Jamdesk, fai clic su **Connect an existing repository** (oppure su **Install GitHub App** nelle impostazioni del progetto), installa Jamdesk sul tuo account personale e scegli il repository.

  Gli account gestiti non possono eseguire push su repository esterni alla tua enterprise. Ogni editor della documentazione ha bisogno di un account GitHub personale. Aggiungili al repository come collaboratori.
</Accordion>

## Repository non visualizzato

Se il tuo repository non compare nell'elenco:

<Accordion title="Verifica i permessi del repository">
  1. Vai su GitHub → Settings → Applications → Jamdesk
  2. Verifica che al repository sia concesso l'accesso
  3. Fai clic su **Configure** per aggiungere altri repository
</Accordion>

<Accordion title="Repository di organizzazione">
  Per i repository di organizzazione:
  1. Un amministratore dell'organizzazione deve approvare Jamdesk
  2. Vai alle impostazioni dell'organizzazione → Third-party access
  3. Approva la richiesta di accesso di Jamdesk
</Accordion>

<Accordion title="Repository privati">
  I repository privati richiedono l'autorizzazione di GitHub. Riautorizza Jamdesk se necessario.
</Accordion>

## Build non avviate

Se i push non avviano i build:

<Steps>
  <Step title="Verifica il webhook">
    1. Vai al tuo repository su GitHub
    2. Apri Settings → Webhooks
    3. Trova il webhook di Jamdesk
    4. Controlla "Recent Deliveries" per eventuali errori
  </Step>
  <Step title="Verifica il branch">
    I build si avviano solo sul branch configurato. Controlla **Settings** in Jamdesk.
  </Step>
  <Step title="Controlla chi ha fatto il push">
    Se il build risulta fallito con un messaggio secondo cui la persona che ha fatto il push non è un membro, invitala da **Project Settings → Members** oppure chiedile di collegare il proprio account GitHub. Consulta [I build non vengono avviati](/it/integrations/github#le-build-non-vengono-attivate).
  </Step>
  <Step title="Risincronizza la connessione">
    1. Vai alle **Settings** del progetto in Jamdesk
    2. Fai clic su **Re-sync GitHub**
  </Step>
</Steps>

## Errori dei webhook

### 404 Not Found

Non è stato possibile raggiungere l'endpoint del webhook.

**Soluzione:** risincronizza la connessione GitHub nelle impostazioni del progetto.

### 401 Unauthorized

Autenticazione non riuscita.

**Soluzione:**
1. Vai alle impostazioni del tuo account GitHub
2. Apri Applications → Authorized OAuth Apps
3. Revoca Jamdesk
4. Riautorizza nelle impostazioni di Jamdesk

### 500 Server Error

Problema temporaneo di Jamdesk.

**Soluzione:** attendi qualche minuto e fai di nuovo il push, oppure avvia manualmente una nuova build.

## Errori di autorizzazione

**"Repository not found"** durante il build:

- Il repository potrebbe essere stato eliminato o rinominato
- Jamdesk potrebbe aver perso l'accesso
- Riautorizza la tua connessione GitHub

## Problemi con i rami

### Viene creata la build del ramo sbagliato

Controlla il branch configurato in **Settings** → **Repository**.

### Ramo rinominato o eliminato

Aggiorna l'impostazione del branch con il nuovo nome.
