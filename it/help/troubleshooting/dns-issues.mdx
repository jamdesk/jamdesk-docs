I problemi DNS sono la causa più frequente dei problemi con i domini personalizzati.

## Verifica della propagazione DNS

Le modifiche DNS possono richiedere fino a 48 ore per propagarsi. La maggior parte si completa in poche ore.

Verifica lo stato della propagazione:

```bash
# Check if your CNAME is resolving
dig CNAME docs.yourdomain.com

# Or use nslookup
nslookup -type=CNAME docs.yourdomain.com
```

L'output previsto mostra il tuo CNAME che punta a `cname.jamdesk.com`:

```text
docs.yourdomain.com. 300 IN CNAME cname.jamdesk.com.
```

Gli strumenti online come [whatsmydns.net](https://www.whatsmydns.net/) mostrano la propagazione in più regioni.

## Problemi comuni

### CNAME non risolto

**Sintomo**: `dig` non mostra alcun record CNAME oppure mostra una destinazione errata.

**Cause**:
- Record non salvato nel provider DNS
- Errore di battitura nel nome o nel valore del record
- Propagazione DNS ancora in corso

**Soluzione**:
1. Accedi al tuo provider DNS
2. Verifica che il record CNAME esista con i valori corretti
3. Attendi 15-30 minuti e controlla di nuovo

### CNAME sul dominio radice

**Sintomo**: il provider DNS rifiuta un record CNAME per `yourdomain.com` (senza sottodominio).

**Causa**: gli standard DNS (RFC 1034) vietano i record CNAME al vertice della zona (dominio radice).

**Soluzione**: la dashboard di Jamdesk mostra automaticamente un record A (`76.76.21.21`) al posto del CNAME per i domini apex. Se la tua dashboard mostra ancora un CNAME per un dominio apex, fai clic su **Refresh** per ottenere i record aggiornati.

### Conflitti con il proxy Cloudflare

**Sintomo**: errori SSL o cicli di reindirizzamento quando si usa Cloudflare.

**Causa**: il proxy di Cloudflare (nuvola arancione) può interferire con l'SSL di Vercel.

**Soluzione**:
1. Nelle impostazioni DNS di Cloudflare, fai clic sull'icona della nuvola arancione
2. Passa a "DNS only" (nuvola grigia) per il sottodominio della documentazione
3. Lascia che Vercel emetta il certificato SSL

### Record in conflitto

**Sintomo**: la verifica del CNAME fallisce anche se il record sembra corretto.

**Causa**: un record A esistente è in conflitto con il CNAME.

**Soluzione**:
1. Verifica la presenza di record A sullo stesso sottodominio
2. Elimina i record A in conflitto
3. Assicurati che rimanga solo il CNAME

```bash
# Check for A records
dig A docs.yourdomain.com
```

### Verifica TXT non riuscita

**Sintomo**: il record TXT per l'hosting su sottopercorso non viene verificato.

**Cause**:
- Record aggiunto al dominio sbagliato
- Errore di battitura nel valore del record
- Record TXT in conflitto

**Soluzione**:
1. Verifica che il record TXT si trovi in `_jamdesk.yourdomain.com`
2. Copia il valore di verifica esatto dalla dashboard
3. Controlla la presenza di record TXT in conflitto

```bash
# Check TXT records
dig TXT _jamdesk.yourdomain.com
```

### Certificato SSL non emesso

**Sintomo**: il dominio resta indefinitamente in stato "pending".

**Cause**:
- Record CAA che bloccano l'emissione del certificato
- DNS non completamente propagato
- Dominio non raggiungibile

**Soluzione**:

Verifica la presenza di record CAA:
```bash
dig CAA yourdomain.com
```

Se esistono record CAA, aggiungine uno che consenta Let's Encrypt:
```text
yourdomain.com. CAA 0 issue "letsencrypt.org"
```

## Comandi diagnostici

```bash
# Full DNS lookup
dig +trace docs.yourdomain.com

# Check all record types
dig ANY docs.yourdomain.com

# Check specific nameservers
dig @8.8.8.8 docs.yourdomain.com

# Check TTL (time to live)
dig +noall +answer docs.yourdomain.com
```

## Note specifiche per provider DNS

### Cloudflare
- Imposta lo stato del proxy su "DNS only" (nuvola grigia) durante la verifica del dominio
- Riattiva il proxy (nuvola arancione) al termine della verifica
- Un Worker viene eseguito solo quando il record DNS è proxy-ato (nuvola arancione). Usa la nuvola grigia solo durante la verifica.
- Disattiva "Always Use HTTPS" per il sottodominio della documentazione per evitare conflitti SSL con Vercel

### GoDaddy
- La destinazione del CNAME non deve terminare con un punto
- Le modifiche possono richiedere più tempo per propagarsi

### Namecheap
- Usa il tipo "CNAME Record"
- Il campo Host contiene solo il sottodominio (`docs`, non `docs.yourdomain.com`)

### Route 53
- La destinazione del CNAME deve terminare con un punto (`cname.jamdesk.com.`)
- Valuta lo stato di salute della destinazione: No

## Quando contattare il supporto

Contatta il supporto se:
- I record DNS risultano corretti ma il dominio è ancora in attesa dopo 48 ore
- Gli errori del certificato SSL persistono dopo aver seguito tutti i passaggi
- Si verificano errori specifici dell'infrastruttura Jamdesk

Includi nella richiesta di supporto:
- Il nome del tuo dominio
- Il nome del provider DNS
- L'output dei comandi `dig`
- Uno screenshot della configurazione DNS
