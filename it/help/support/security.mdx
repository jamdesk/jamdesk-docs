Ecco come Jamdesk protegge la documentazione e i dati del tuo account.

## Sicurezza dell'infrastruttura

### Hosting

Jamdesk si affida a provider cloud conformi a SOC 2. Le build, i dati dell’applicazione e la documentazione compilata risiedono in servizi gestiti e protetti offerti da questi provider. Il traffico passa attraverso una CDN globale con protezione DDoS integrata.

### Crittografia

| Stato dei dati | Protezione |
|------------|------------|
| In transito | TLS 1.3 tra te, la nostra rete edge e i nostri server di origine |
| A riposo | AES-256 per tutti i dati che conserviamo, inclusi record del database, archiviazione di oggetti e log |
| Backup | Crittografati con le stesse chiavi e replicati in più aree geografiche |

## Controlli di accesso

### Accesso

Puoi accedere al dashboard con email e password oppure con l’accesso Single Sign-On tramite Google o GitHub. Le password non vengono mai memorizzate in testo in chiaro: il nostro provider di autenticazione conserva solo hash unidirezionali.

Se accedi con Google o GitHub, anche le eventuali configurazioni MFA associate a quell’account (TOTP, chiavi di sicurezza, passkey) si applicano all’accesso a Jamdesk. Per la massima protezione, consigliamo di attivare MFA sul tuo account Google o GitHub e di usare SSO.

### Accesso del team

L’accesso basato sui ruoli (Owner, Admin, Member) è applicato sia nelle regole di sicurezza del database sia a ogni chiamata al backend. Le sessioni scadono automaticamente dopo periodi di inattività e le modifiche a fatturazione, membri, domini personalizzati o chiavi API vengono registrate in un log di controllo per progetto.

### Integrazione con GitHub

Jamdesk si connette ai tuoi repository tramite una GitHub App con le autorizzazioni necessarie:

- Accesso in lettura e scrittura ai contenuti dei repository
- Invio di Webhook per avviare le build

Jamdesk scrive nel tuo repository solo quando glielo chiedi: quando salvi le modifiche nell’editor del dashboard, accetti i suggerimenti di Fix with AI o attivi la traduzione, che crea commit con le pagine tradotte. Le build eseguono solo operazioni di lettura. Puoi revocare l’accesso di Jamdesk in qualsiasi momento dalle [impostazioni Applications di GitHub](https://github.com/settings/installations).

### Token e segreti

Ogni segreto che ci affidi viene crittografato a riposo. Sono inclusi:

- Connessioni alla GitHub App, per le quali conserviamo solo il tuo ID numerico di installazione. I token di installazione di breve durata (validi un’ora) vengono generati su richiesta e non vengono mai memorizzati.
- Token OAuth di GitHub usati durante il flusso di creazione del repository iniziale: vengono scambiati una volta, usati per clonare il modello e poi eliminati.
- Credenziali per integrazioni di terze parti, come gli URL dei webhook in ingresso di Slack, i token di verifica dei domini personalizzati e le chiavi API di analisi.

Dopo il salvataggio, il dashboard non restituisce questi valori al browser; solo la pipeline di build lato server può leggerli.

Le chiavi API per l’accesso programmatico vengono memorizzate come hash unidirezionali. Il testo in chiaro viene mostrato una sola volta, al momento della creazione. Se lo perdi, ruota la chiave.

## Gestione dei dati

### Cosa archiviamo

- La configurazione `docs.json` e le risorse di branding caricate
- La documentazione compilata (HTML, CSS, JS)
- I log di build, conservati per 30 giorni
- Gli eventi di visualizzazione delle pagine del tuo sito di documentazione (percorso, referrer, paese, browser, tipo di dispositivo, ID di sessione per scheda e indirizzo IP del visitatore), eliminati dopo 90 giorni
- Le domande nelle chat AI (i primi 200 caratteri, senza la risposta), eliminate dopo 30 giorni
- I segreti crittografati per le integrazioni di terze parti che hai configurato

### Cosa non archiviamo

- Il tuo codice sorgente. Cloniamo il repository al momento della build ed eliminiamo l’albero di lavoro quando il container di build viene distrutto.
- Credenziali GitHub di lunga durata. Consulta la sezione **Token e segreti** qui sopra.
- Password degli utenti in qualsiasi forma reversibile.
- Numeri delle carte di pagamento. Stripe gestisce tutti i dati delle carte; conserviamo solo l’ID cliente e i metadati dell’abbonamento.

### Accesso interno

L’accesso ai dati di produzione è limitato a un numero ristretto di dipendenti che ne hanno bisogno per gestire il servizio o rispondere alle richieste di supporto. Gli accessi vengono registrati.

## Isolamento delle build

Ogni build della documentazione viene eseguita in un container dedicato:

- Nessun accesso ai dati degli altri clienti
- Ambiente pulito per ogni build, con i segreti inseriti solo al momento necessario
- Il container viene distrutto al termine della build o in caso di errore

## Conformità

### GDPR

Jamdesk rispetta i requisiti del GDPR:

- Un [Addendum sul trattamento dei dati](https://jamdesk.com/dpa), applicato automaticamente, di cui è possibile richiedere una copia controfirmata scrivendo a `privacy@jamdesk.com`
- Un elenco pubblico dei sub-responsabili all’indirizzo [jamdesk.com/subprocessors](https://jamdesk.com/subprocessors)
- Diritto alla cancellazione garantito entro 30 giorni
- Portabilità dei dati tramite esportazione

### Privacy

Le nostre funzionalità di analisi integrate:

- Non usano cookie. Un ID di sessione casuale viene conservato nell’archiviazione di sessione del browser e cancellato alla chiusura della scheda
- Non condividono dati con reti pubblicitarie
- Conservano gli indirizzi IP dei visitatori insieme agli eventi di visualizzazione delle pagine, che vengono eliminati dopo 90 giorni

Per maggiori dettagli, consulta la nostra [Informativa sulla privacy](https://jamdesk.com/privacy).

## Risposta agli incidenti

Se un incidente di sicurezza riguarda il tuo account o i tuoi dati, interveniamo in tre modi:

1. Analizziamo e conteniamo il problema.
2. Avvisiamo i clienti interessati entro 72 ore, in conformità ai nostri obblighi ai sensi del GDPR.
3. Forniamo un rapporto scritto post-incidente una volta accertata la causa.

## Segnalazione delle vulnerabilità

Hai individuato un problema di sicurezza? Segnalalo in modo responsabile:

- Scrivi a `security@jamdesk.com`
- Includi una descrizione, i passaggi per riprodurre il problema e una valutazione dell’impatto
- Ti daremo conferma entro 48 ore

Al momento non offriamo un programma a pagamento di bug bounty, ma siamo lieti di riconoscere il merito ai ricercatori che segnalano vulnerabilità in buona fede.
