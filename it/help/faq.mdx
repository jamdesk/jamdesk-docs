## Guida introduttiva

<AccordionGroup>
  <Accordion title="Che cos'è Jamdesk?">
    Jamdesk è una piattaforma di documentazione che crea siti di documentazione dai tuoi file Markdown. Scrivi in MDX e invia le modifiche a GitHub. Il tuo sito viene distribuito con ricerca, analisi e un file `llms.txt` per gli strumenti AI.
  </Accordion>

  <Accordion title="Devo saper programmare?">
    No. MDX è testo semplice con formattazione essenziale. I componenti sono facoltativi.
  </Accordion>

  <Accordion title="Posso provare Jamdesk gratuitamente?">
    Sì. Offriamo una prova gratuita di 14 giorni con tutte le funzionalità.
  </Accordion>

  <Accordion title="Qual è la differenza tra Jamdesk e le altre piattaforme di documentazione?">
    La documentazione è composta da file MDX semplici in un repository GitHub, non è vincolata a un editor proprietario. Invia le modifiche a GitHub e il tuo sito viene distribuito in meno di 60 secondi. Non devi configurare build o pipeline CI/CD. Ogni sito include `llms.txt` e un server MCP. Gli strumenti AI come Claude e ChatGPT possono leggere direttamente la documentazione aggiornata. I visitatori possono usare un [assistente chat AI](/it/ai/chat) integrato, che risponde alle domande sulla tua documentazione.
  </Accordion>
</AccordionGroup>

## Build e distribuzione

<AccordionGroup>
  <Accordion title="Quanto tempo richiedono le build?">
    La maggior parte dei siti di documentazione viene compilata in 30-60 secondi. I siti più grandi, con molte pagine, potrebbero richiedere più tempo.
  </Accordion>

  <Accordion title="Posso visualizzare in anteprima le modifiche prima della pubblicazione?">
    Sì. Visualizza l'anteprima in locale con hot reload usando la CLI di Jamdesk (`jamdesk dev`). Le modifiche vengono pubblicate solo quando le invii a GitHub o esegui `jamdesk deploy`.
  </Accordion>

  <Accordion title="Posso distribuire il sito senza GitHub?">
    Sì. Esegui `jamdesk deploy` dalla directory del progetto. La CLI prepara e carica i file, quindi avvia una build. Non serve un repository Git. Per i dettagli, consulta la [guida alla distribuzione con la CLI](/it/cli/deploy).
  </Accordion>

  <Accordion title="Cosa avvia una build?">
    L'invio di modifiche al branch GitHub connesso. Puoi anche avviare una build dal dashboard o con `jamdesk deploy` dalla CLI.
  </Accordion>

  <Accordion title="Posso ripristinare una versione precedente?">
    Sì. Vai a **Deployments** nel tuo progetto. Trova la build precedente e fai clic su **Rollback**.
  </Accordion>
</AccordionGroup>

## Domini personalizzati

<AccordionGroup>
  <Accordion title="Posso usare il mio dominio?">
    Sì. Aggiungi un dominio personalizzato in **Settings** → **Domains**. Jamdesk configura il certificato SSL.
  </Accordion>

  <Accordion title="Quanto tempo richiede la propagazione DNS?">
    Di solito alcune ore, ma può richiedere fino a 48 ore.
  </Accordion>

  <Accordion title="Posso ospitare la documentazione in un sottopercorso come /docs?">
    Sì. Usa un reverse proxy (Cloudflare, AWS, nginx) per pubblicare Jamdesk in un sottopercorso. Consulta [Hosting in un sottopercorso](/it/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Team e collaborazione

<AccordionGroup>
  <Accordion title="Come invito un membro del team?">
    Apri il progetto e vai a **Settings** → **Members**. Inserisci l'indirizzo email della persona nel campo **Invite Member** e fai clic su **Invite**. Riceverà un'email con un link per unirsi al progetto.

      <img src="/images/dashboard/settings-team.webp" alt="Scheda Members nelle impostazioni del progetto, con il campo Invite Member e l'elenco dei membri attuali" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    Per ricevere un invito, è necessario avere un account Jamdesk. Se non ne hanno uno, il link li invita a crearne uno. Sei già un membro, ma il link d'invito dice che è "already been accepted"? Accedi: tornerai al progetto. Per i ruoli e i limiti dei membri, consulta [Membri del team](/it/help/projects/team-members).
  </Accordion>

  <Accordion title="Quanti membri può avere il mio team?">
    Illimitati, con qualsiasi piano e senza costi aggiuntivi.
  </Accordion>

  <Accordion title="I membri del team possono modificare la documentazione?">
    I membri del team possono visualizzare le build e avviarne di nuove. Le modifiche si effettuano nel repository GitHub. Chiunque abbia accesso al repository può modificare la documentazione.
  </Accordion>

  <Accordion title="Come trasferisco la proprietà del progetto?">
    Vai a **Settings** → **Members**. Fai clic su **Transfer Ownership** accanto al membro che vuoi promuovere. Il nuovo proprietario deve essere già membro del team.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Dove sono archiviate le credenziali della CLI?">
    In `~/.jamdeskrc`, un file JSON con permessi `0600` (solo tu puoi leggerlo). Contiene il token di aggiornamento, l'indirizzo email e l'ID utente. Esegui `jamdesk logout` per cancellarlo.
  </Accordion>

  <Accordion title='Perché la CLI dice "session expired"?'>
    Il token di aggiornamento non è più valido. Può succedere dopo una modifica della password, l'eliminazione dell'account o un lungo periodo di inattività. Esegui `jamdesk login` per avviare una nuova sessione.
  </Accordion>

  <Accordion title="Posso usare la CLI nelle pipeline CI/CD?">
    Sì. L'accesso tramite browser non funziona negli ambienti headless. Accedi dal computer locale, poi copia `~/.jamdeskrc` nel runner CI. Il token di aggiornamento consente l'autenticazione da lì.
  </Accordion>

  <Accordion title="Come correggo automaticamente i link non validi?">
    Esegui `jamdesk fix`. Corregge i link interni non validi quando esiste una sola destinazione corretta (ancore con errori di battitura e ancore non allineate tra versioni locali). Dopo un'anteprima, modifica i file `.mdx` locali. Prima di applicare le modifiche, visualizzale con `jamdesk fix --dry-run`. Interviene solo sui link la cui ancora corretta corrisponde a un titolo reale. I casi ambigui restano da verificare manualmente. Consulta [Correzione automatica dei link non validi](/it/cli/fix-broken-links).
  </Accordion>
</AccordionGroup>

## Contenuti e funzionalità

<AccordionGroup>
  <Accordion title="Quali formati di file sono supportati?">
    MDX (Markdown + JSX) e file Markdown standard.
  </Accordion>

  <Accordion title="Posso usare componenti React personalizzati?">
    Sì. Definisci componenti inline in MDX con `export const` oppure crea componenti riutilizzabili nella directory `/snippets`. Per componenti interattivi con hook, usa file `.tsx` con `'use client'`. Consulta [Componenti React personalizzati](/it/content/react-components) e [Snippet](/it/content/snippets).
  </Accordion>

  <Accordion title="C'è un limite al numero di pagine?">
    Non c'è un limite rigido. I siti con centinaia di pagine vengono compilati e funzionano senza problemi.
  </Accordion>

  <Accordion title="Jamdesk supporta più lingue?">
    Sì. Aggiungi un selettore di lingua con la proprietà `languages` nella configurazione di navigazione. Ogni lingua ha una propria struttura di navigazione e contenuti. Consulta [Supporto multilingue](/it/setup/languages).
  </Accordion>

  <Accordion title="Jamdesk traduce automaticamente i miei contenuti?">
    No. Devi fornire i file MDX tradotti. Jamdesk crea le route, la navigazione, il selettore di lingua e gli stili RTL. Puoi usare le traduzioni del tuo flusso di lavoro, realizzate da traduttori, con la traduzione automatica o con un LLM. Inseriscile in directory con il prefisso della lingua (`es/`, `fr/` e così via). Consulta [Supporto multilingue](/it/setup/languages) per la struttura delle directory e la configurazione.
  </Accordion>
</AccordionGroup>

## Chat IA

<AccordionGroup>
  <Accordion title="Il mio sito di documentazione include una chat AI?">
    Sì. Ogni sito Jamdesk include un assistente chat integrato che risponde alle domande dei visitatori usando la tua documentazione. È attivo per impostazione predefinita. Per i dettagli, consulta [Chat AI](/it/ai/chat).
  </Accordion>

  <Accordion title="La chat AI ha un costo aggiuntivo?">
    No. La chat AI è inclusa in tutti i piani.
  </Accordion>

  <Accordion title="Posso disattivare la chat AI?">
    Sì. Imposta `chat.enabled` su `false` nel tuo `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    La build successiva rimuove il pannello della chat e la scorciatoia da tastiera.
  </Accordion>

  <Accordion title="Quali dati usa la chat per rispondere alle domande?">
    Solo le pagine di documentazione pubblicate. Ogni build indicizza i contenuti in un database vettoriale. Jamdesk recupera le sezioni pertinenti alla domanda di un visitatore e le invia a Claude come contesto. L'AI non può accedere a dati al di fuori della documentazione.
  </Accordion>
</AccordionGroup>

## Privacy e accesso

<AccordionGroup>
  <Accordion title="Posso avere documentazione pubblica e privata nello stesso sito?">
    Sì. Contrassegna le pagine interne con `private: true` nel frontmatter oppure elencane i percorsi in `auth.password.private[]` in `docs.json`. Le pagine private mostrano una schermata di sblocco. Tutte le pagine restano in un unico progetto, con un solo repository e una sola build. Consulta [Controllo degli accessi](/it/setup/access-control) e [Protezione con password](/it/setup/password-protection).
  </Accordion>

  <Accordion title="Come proteggo con una password l'intero sito di documentazione?">
    Imposta `auth.password.enabled: true` in `docs.json` e invia la modifica. Imposta una password in **Project Settings → Password Protection** nel dashboard. I visitatori vedranno una schermata di sblocco finché non la inseriscono. Consulta [Protezione con password](/it/setup/password-protection).
  </Accordion>

  <Accordion title="I lettori possono accedere con il proprio account invece che con una password condivisa?">
    Sì, con i piani Enterprise. Il Single Sign-On consente ai lettori di autenticarsi tramite il tuo provider di identità (Okta, Google Workspace, Azure AD e così via), senza password condivise, con una traccia di audit completa e la revoca immediata degli accessi. Consulta [SSO](/it/setup/sso) oppure [contatta il team commerciale Enterprise](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="È meglio separare la documentazione interna ed esterna in due progetti?">
    Di solito no. Usa un unico progetto e imposta `private: true` sulle pagine interne. Avrai un solo repository e un solo dashboard. Usa due progetti solo se i diversi tipi di pubblico richiedono branding, domini personalizzati o analisi separati. Per i diversi approcci, consulta [Controllo degli accessi](/it/setup/access-control).
  </Accordion>

  <Accordion title="Qual è la differenza tra un editor e un lettore?">
    Gli **editor** scrivono la documentazione inviando commit MDX al repository GitHub connesso. Un invio avvia una build solo se chi lo ha effettuato è membro del progetto Jamdesk o un account di automazione autorizzato. I **lettori** consultano il sito pubblicato: chiunque, se è pubblico; chiunque abbia la password, se è protetto da password; oppure chiunque abbia effettuato l'accesso tramite il tuo IdP, se è protetto con SSO. I **membri del team del dashboard** gestiscono build, analisi e impostazioni. L'appartenenza al team consente anche di avviare build con i propri invii. Consulta [Controllo degli accessi](/it/setup/access-control).
  </Accordion>
</AccordionGroup>
