## Guida introduttiva

<AccordionGroup>
  <Accordion title="Che cos'è Jamdesk?">
    Jamdesk è una piattaforma di documentazione che crea siti di documentazione dai tuoi file Markdown. Scrivi in MDX, esegui il push su GitHub e il tuo sito viene distribuito automaticamente con ricerca, analisi e `llms.txt` pronto per l'IA.
  </Accordion>

  <Accordion title="Devo saper programmare?">
    Non è necessaria alcuna conoscenza di programmazione. Scrivere in MDX è come usare un editor di testo: scrivi testo semplice con una formattazione essenziale. I componenti sono disponibili se vuoi usarli, ma sono completamente facoltativi.
  </Accordion>

  <Accordion title="Posso provare Jamdesk gratuitamente?">
    Sì! Offriamo una prova gratuita di 14 giorni con accesso completo a tutte le funzionalità.  
  </Accordion>

  <Accordion title="Qual è la differenza tra Jamdesk e le altre piattaforme di documentazione?">
    Jamdesk si basa su MDX e GitHub: la documentazione è costituita da file di testo semplice in un repository, non è vincolata a un editor proprietario. Esegui il push su GitHub e il tuo sito viene distribuito in meno di 60 secondi, senza configurazione della build né pipeline CI/CD. Ogni sito riceve automaticamente `llms.txt` e un server MCP, così gli strumenti di IA come Claude e ChatGPT possono accedere direttamente alla documentazione aggiornata. I visitatori ricevono anche un [assistente chat IA](/it/ai/chat) integrato che risponde alle domande usando la tua documentazione.
  </Accordion>
</AccordionGroup>

## Build e distribuzione

<AccordionGroup>
  <Accordion title="Quanto tempo richiedono le build?">
    La maggior parte dei siti di documentazione viene compilata in 30-60 secondi. I siti più grandi, con molte pagine, possono richiedere più tempo.
  </Accordion>

  <Accordion title="Posso visualizzare in anteprima le modifiche prima di pubblicarle?">
    Sì! Usa la CLI di Jamdesk (`jamdesk dev`) per visualizzare l'anteprima localmente con hot reload. Le modifiche diventano effettive solo quando esegui il push su GitHub o esegui `jamdesk deploy`.
  </Accordion>

  <Accordion title="Posso eseguire il deploy senza GitHub?">
    Sì. Esegui `jamdesk deploy` dalla directory del progetto. La CLI prepara i tuoi file, li carica e avvia direttamente una build. Non è necessario alcun repository Git. Per maggiori dettagli, consulta la [guida al deploy con la CLI](/it/cli/deploy).
  </Accordion>

  <Accordion title="Cosa avvia una build?">
    Le build vengono avviate automaticamente quando esegui il push sul branch GitHub collegato. Puoi anche avviare manualmente le build dal dashboard o con `jamdesk deploy` dalla CLI.
  </Accordion>

  <Accordion title="Posso ripristinare una versione precedente?">
    Sì. Vai a **Deployments** nel tuo progetto, individua la build precedente e fai clic su **Rollback**.
  </Accordion>
</AccordionGroup>

## Domini personalizzati

<AccordionGroup>
  <Accordion title="Posso usare il mio dominio?">
    Sì! Aggiungi un dominio personalizzato in **Settings** → **Domains**. I certificati SSL vengono forniti automaticamente.
  </Accordion>

  <Accordion title="Quanto tempo richiede la propagazione DNS?">
    Le modifiche DNS in genere si propagano entro poche ore, ma possono richiedere fino a 48 ore.
  </Accordion>

  <Accordion title="Posso ospitare la documentazione in un sottopercorso come /docs?">
    Sì. Usa un proxy inverso (Cloudflare, AWS, nginx) per pubblicare Jamdesk in un sottopercorso. Consulta [Hosting in un sottopercorso](/it/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Team e collaborazione

<AccordionGroup>
  <Accordion title="Come invito un membro del team?">
    Apri il progetto, vai a **Settings** → **Members**, inserisci l'indirizzo email della persona nel campo **Invite Member** e fai clic su **Invite**. Riceverà un'email con un link per unirsi al progetto.

    <Frame>
      <img src="/images/dashboard/settings-team.webp" alt="Scheda Members nelle impostazioni del progetto con il campo Invite Member e l'elenco dei membri attuali" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    Gli utenti invitati devono avere un account Jamdesk; se non ne hanno uno, verrà chiesto loro di crearlo al momento dell'accettazione. Sei già un membro, ma il link di invito indica che è "already been accepted"? Non ti serve un nuovo invito. Accedi semplicemente e tornerai al progetto. Per informazioni su ruoli e limiti dei membri, consulta [Membri del team](/it/help/projects/team-members).
  </Accordion>

  <Accordion title="Quanti membri del team posso avere?">
    Ogni piano include membri del team illimitati per progetto, senza costi aggiuntivi.
  </Accordion>

  <Accordion title="I membri del team possono modificare la documentazione?">
    I membri del team possono visualizzare le build e avviare nuove build, ma le modifiche vengono effettuate nel repository GitHub. Chiunque abbia accesso al repository può modificare la documentazione.
  </Accordion>

  <Accordion title="Come trasferisco la proprietà del progetto?">
    Vai a **Settings** → **Members**, quindi fai clic su **Transfer Ownership** accanto al membro che vuoi promuovere. Il nuovo proprietario deve essere già un membro del team.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Dove vengono archiviate le credenziali della CLI?">
    In `~/.jamdeskrc`, un file JSON con permessi `0600` (leggibile solo dal tuo utente). Contiene il token di aggiornamento, l'email e l'ID utente. Esegui `jamdesk logout` per cancellarlo.
  </Accordion>

  <Accordion title='Perché la CLI indica "session expired"?'>
    Il tuo token di aggiornamento non è più valido. Può succedere dopo una modifica della password, l'eliminazione dell'account o un periodo prolungato di inattività. Esegui `jamdesk login` per ottenere una nuova sessione.
  </Accordion>

  <Accordion title="Posso usare la CLI nelle pipeline CI/CD?">
    Sì, ma l'accesso basato sul browser non funziona negli ambienti headless. Accedi dal tuo computer locale, quindi copia `~/.jamdeskrc` nel runner CI. Da quel momento, il token di aggiornamento gestirà l'autenticazione.
  </Accordion>

  <Accordion title="Come posso correggere automaticamente i link non funzionanti?">
    Esegui `jamdesk fix`. Ripara i link interni non funzionanti che hanno una destinazione corretta non ambigua (ancore con errori di battitura e ancore non aggiornate tra le lingue), modificando i file `.mdx` locali dopo un'anteprima. Usa `jamdesk fix --dry-run` per visualizzare prima le modifiche previste; vengono modificati solo i link la cui ancora corretta corrisponde a un'intestazione reale, mentre i casi ambigui vengono lasciati alla revisione manuale. Consulta [Correzione automatica dei link non funzionanti](/it/cli/fix-broken-links).
  </Accordion>
</AccordionGroup>

## Contenuti e funzionalità

<AccordionGroup>
  <Accordion title="Quali formati di file sono supportati?">
    Jamdesk supporta file MDX (Markdown + JSX) e file Markdown standard.
  </Accordion>

  <Accordion title="Posso usare componenti React personalizzati?">
    Sì. Definisci componenti inline direttamente in MDX con `export const`, oppure crea componenti riutilizzabili nella directory `/snippets`. Per i componenti interattivi con hook, usa file `.tsx` con `'use client'`. Consulta [Componenti React personalizzati](/it/content/react-components) e [Snippet](/it/content/snippets).
  </Accordion>

  <Accordion title="Esiste un limite al numero di pagine?">
    Non esiste un limite rigido al numero di pagine. La maggior parte dei siti di documentazione funziona bene con centinaia di pagine.
  </Accordion>

  <Accordion title="Jamdesk supporta più lingue?">
    Sì. Usa la proprietà `languages` nella configurazione di navigazione per creare un selettore della lingua. Ogni lingua dispone di una propria struttura di navigazione e dei propri contenuti. Consulta [Supporto multilingue](/it/setup/languages).
  </Accordion>

  <Accordion title="Jamdesk traduce automaticamente i miei contenuti?">
    No. Jamdesk non traduce i contenuti al posto tuo. Devi fornire i file MDX tradotti; Jamdesk gestisce il routing, la navigazione, il selettore della lingua e gli stili RTL. Usa le traduzioni del tuo flusso di lavoro (traduttori umani, traduzione automatica o un LLM) e inseriscile in directory con prefisso della lingua (`es/`, `fr/` ecc.). Consulta [Supporto multilingue](/it/setup/languages) per la struttura delle directory e la configurazione.
  </Accordion>
</AccordionGroup>

## Chat IA

<AccordionGroup>
  <Accordion title="Il mio sito di documentazione ha una chat IA?">
    Sì. Ogni sito Jamdesk include un assistente chat integrato che risponde alle domande dei visitatori usando la documentazione. È abilitato per impostazione predefinita e non richiede configurazione. Per maggiori dettagli, consulta [Chat IA](/it/ai/chat).
  </Accordion>

  <Accordion title="La chat IA ha un costo aggiuntivo?">
    No. La chat IA è inclusa in tutti i piani senza costi aggiuntivi.
  </Accordion>

  <Accordion title="Posso disattivare la chat IA?">
    Sì. Imposta `chat.enabled` su `false` nel tuo `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    Il pannello della chat e la scorciatoia da tastiera verranno rimossi dopo la prossima build.
  </Accordion>

  <Accordion title="Quali dati usa la chat per rispondere alle domande?">
    La chat usa solo le pagine di documentazione pubblicate. Durante ogni build, Jamdesk indicizza i contenuti in un database vettoriale. Quando un visitatore pone una domanda, le sezioni pertinenti vengono recuperate e inviate a Claude come contesto. L'IA non può accedere a dati esterni alla documentazione.
  </Accordion>
</AccordionGroup>

## Privacy e accesso

<AccordionGroup>
  <Accordion title="Posso avere documentazione pubblica e privata nello stesso sito?">
    Sì. Contrassegna le pagine interne con `private: true` nel frontmatter oppure elenca i relativi percorsi in `auth.password.private[]` in `docs.json`. Le pagine pubbliche restano pubbliche; quelle private mostrano una schermata di sblocco. Tutto rimane in un singolo progetto, quindi le pagine pubbliche e private condividono lo stesso repository e la stessa build. Consulta [Controllo degli accessi](/it/setup/access-control) e [Protezione con password](/it/setup/password-protection).
  </Accordion>

  <Accordion title="Come posso proteggere l'intero sito di documentazione con una password?">
    Imposta `auth.password.enabled: true` in `docs.json`, esegui il push della modifica, quindi imposta una password in **Project Settings → Password Protection** nel dashboard. Ogni visitatore vedrà una schermata di sblocco finché non la inserirà. Consulta [Protezione con password](/it/setup/password-protection).
  </Accordion>

  <Accordion title="I lettori possono accedere con il proprio account invece di usare una password condivisa?">
    Sì, nei piani Enterprise. Il Single Sign-On consente ai lettori di autenticarsi tramite il proprio provider di identità (Okta, Google Workspace, Azure AD ecc.), senza password condivise, con un audit trail completo e il deprovisioning immediato. Consulta [SSO](/it/setup/sso) o [contatta il team vendite Enterprise](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="Devo dividere la documentazione interna ed esterna in due progetti?">
    In genere no. Un singolo progetto con `private: true` sulle pagine interne è più semplice, perché conservi tutto in un unico repository e lo gestisci da un unico dashboard. Usa due progetti solo quando i destinatari richiedono branding, domini personalizzati o analisi completamente separati. Consulta [Controllo degli accessi](/it/setup/access-control) per conoscere le diverse configurazioni.
  </Accordion>

  <Accordion title="Qual è la differenza tra un editor e un lettore?">
    Gli **editor** scrivono la documentazione eseguendo il commit di MDX nel repository GitHub collegato, quindi chiunque abbia accesso push al branch della documentazione può pubblicare una modifica. I **lettori** visualizzano il sito pubblicato: tutti (sito pubblico), chiunque disponga della password (modalità con password) o chiunque abbia effettuato l'accesso tramite il tuo IdP (SSO). I **membri del team del dashboard** sono un concetto separato: gestiscono build e analisi, ma non creano direttamente contenuti. Consulta [Controllo degli accessi](/it/setup/access-control).
  </Accordion>
</AccordionGroup>
