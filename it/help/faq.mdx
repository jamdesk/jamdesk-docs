## Guida introduttiva

<AccordionGroup>
  <Accordion title="Che cos'è Jamdesk?">
    Jamdesk è una piattaforma di documentazione che crea siti di documentazione a partire dai tuoi file Markdown. Scrivi in MDX, invia le modifiche a GitHub e il tuo sito viene distribuito automaticamente, con ricerca, analisi e `llms.txt` pronto per l'AI.
  </Accordion>

  <Accordion title="Devo saper programmare?">
    Non serve saper programmare. Scrivere in MDX è come usare un editor di testo: scrivi testo semplice con una formattazione di base. Se vuoi, puoi usare i componenti, ma sono del tutto facoltativi.
  </Accordion>

  <Accordion title="Posso provare Jamdesk gratuitamente?">
    Sì! Offriamo una prova gratuita di 14 giorni con accesso completo a tutte le funzionalità.  
  </Accordion>

  <Accordion title="Qual è la differenza tra Jamdesk e le altre piattaforme di documentazione?">
    Jamdesk si basa su MDX e GitHub: la documentazione è costituita da file di testo semplice in un repository, non è vincolata a un editor proprietario. Invia le modifiche a GitHub e il tuo sito viene distribuito in meno di 60 secondi, senza configurazione di build né pipeline CI/CD. Ogni sito include automaticamente `llms.txt` e un server MCP, così gli strumenti AI come Claude e ChatGPT possono accedere direttamente alla documentazione aggiornata. Anche i visitatori possono usare un [assistente di chat AI](/it/ai/chat) integrato, che risponde alle domande basandosi sulla documentazione.
  </Accordion>
</AccordionGroup>

## Build e distribuzione

<AccordionGroup>
  <Accordion title="Quanto tempo richiedono le build?">
    La maggior parte dei siti di documentazione viene compilata in 30-60 secondi. I siti più grandi, con molte pagine, possono richiedere più tempo.
  </Accordion>

  <Accordion title="Posso visualizzare in anteprima le modifiche prima di pubblicarle?">
    Sì! Usa la CLI di Jamdesk (`jamdesk dev`) per visualizzare l'anteprima in locale con aggiornamento automatico. Le modifiche vengono pubblicate solo quando le invii a GitHub o esegui `jamdesk deploy`.
  </Accordion>

  <Accordion title="Posso distribuire il sito senza GitHub?">
    Sì. Esegui `jamdesk deploy` dalla directory del progetto. La CLI prepara i file, li carica e avvia direttamente una build. Non serve un repository Git. Per i dettagli, consulta la [guida alla distribuzione con la CLI](/it/cli/deploy).
  </Accordion>

  <Accordion title="Cosa avvia una build?">
    Le build si avviano automaticamente quando invii modifiche al branch GitHub collegato. Puoi anche avviare le build manualmente dal dashboard o eseguendo `jamdesk deploy` dalla CLI.
  </Accordion>

  <Accordion title="Posso ripristinare una versione precedente?">
    Sì. Nel progetto, vai a **Deployments**, trova la build precedente e fai clic su **Rollback**.
  </Accordion>
</AccordionGroup>

## Domini personalizzati

<AccordionGroup>
  <Accordion title="Posso usare un mio dominio?">
    Sì! Aggiungi un dominio personalizzato in **Settings** → **Domains**. I certificati SSL vengono predisposti automaticamente.
  </Accordion>

  <Accordion title="Quanto tempo richiede la propagazione DNS?">
    Le modifiche DNS si propagano in genere entro poche ore, ma possono richiedere fino a 48 ore.
  </Accordion>

  <Accordion title="Posso ospitare la documentazione in un percorso secondario come /docs?">
    Sì. Usa un proxy inverso (Cloudflare, AWS, nginx) per rendere disponibile Jamdesk in un percorso secondario. Consulta [Hosting in un percorso secondario](/it/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Team e collaborazione

<AccordionGroup>
  <Accordion title="Come invito un membro del team?">
    Apri il progetto, vai a **Settings** → **Members**, inserisci l'indirizzo email della persona nel campo **Invite Member** e fai clic su **Invite**. Riceverà un'email con un link per unirsi al progetto.

    <Frame>
      <img src="/images/dashboard/settings-team.webp" alt="Scheda Members nelle impostazioni del progetto con il campo Invite Member e l'elenco dei membri attuali" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    Gli utenti invitati devono avere un account Jamdesk; se non ne hanno uno, verrà chiesto loro di crearlo quando accettano l'invito. Se sei già un membro ma il link d'invito dice che è stato «già accettato», non serve un nuovo invito. Accedi e tornerai al progetto. Per informazioni sui ruoli e sui limiti di membri, consulta [Membri del team](/it/help/projects/team-members).
  </Accordion>

  <Accordion title="Quanti membri del team posso aggiungere?">
    Ogni piano include un numero illimitato di membri del team per progetto, senza costi aggiuntivi.
  </Accordion>

  <Accordion title="I membri del team possono modificare la documentazione?">
    I membri del team possono visualizzare le build e avviarne di nuove, ma le modifiche si apportano nel repository GitHub. Chiunque abbia accesso al repository può modificare la documentazione.
  </Accordion>

  <Accordion title="Come trasferisco la proprietà del progetto?">
    Vai a **Settings** → **Members**, quindi fai clic su **Transfer Ownership** accanto al membro a cui vuoi trasferire la proprietà. Il nuovo proprietario deve già far parte del team.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Dove sono archiviate le credenziali della CLI?">
    In `~/.jamdeskrc`, un file JSON con autorizzazioni `0600` (solo il tuo utente può leggerlo). Contiene il token di aggiornamento, l'email e l'ID utente. Esegui `jamdesk logout` per cancellarlo.
  </Accordion>

  <Accordion title='Perché la CLI mostra "session expired"?'>
    Il token di aggiornamento non è più valido. Succede dopo modifiche alla password, eliminazioni dell'account o periodi prolungati di inattività. Esegui `jamdesk login` per avviare una nuova sessione.
  </Accordion>

  <Accordion title="Posso usare la CLI nelle pipeline CI/CD?">
    Sì, ma l'accesso tramite browser non funziona negli ambienti headless. Accedi dal computer locale, poi copia `~/.jamdeskrc` nel runner CI. Da quel momento, il token di aggiornamento gestisce l'autenticazione.
  </Accordion>

  <Accordion title="Come correggo automaticamente i link non funzionanti?">
    Esegui `jamdesk fix`. Corregge i link interni non funzionanti quando la destinazione corretta è univoca (ancore con errori di battitura e ancore non aggiornate tra lingue), modificando i file `.mdx` locali dopo un'anteprima. Usa `jamdesk fix --dry-run` per visualizzare prima le modifiche previste; vengono modificati solo i link la cui ancora corretta corrisponde a un titolo effettivo, mentre i casi ambigui restano da esaminare manualmente. Consulta [Correzione automatica dei link non funzionanti](/it/cli/fix-broken-links).
  </Accordion>
</AccordionGroup>

## Contenuti e funzionalità

<AccordionGroup>
  <Accordion title="Quali formati di file sono supportati?">
    Jamdesk supporta MDX (Markdown + JSX) e i file Markdown standard.
  </Accordion>

  <Accordion title="Posso usare componenti React personalizzati?">
    Sì. Definisci componenti inline direttamente in MDX con `export const` oppure crea componenti riutilizzabili nella directory `/snippets`. Per i componenti interattivi con hook, usa file `.tsx` con `'use client'`. Consulta [Componenti React personalizzati](/it/content/react-components) e [Snippet](/it/content/snippets).
  </Accordion>

  <Accordion title="C'è un limite al numero di pagine?">
    Non c'è un limite rigido al numero di pagine. La maggior parte dei siti di documentazione funziona bene anche con centinaia di pagine.
  </Accordion>

  <Accordion title="Jamdesk supporta più lingue?">
    Sì. Usa la proprietà `languages` nella configurazione della navigazione per creare un selettore di lingua. Ogni lingua ha una propria struttura di navigazione e i propri contenuti. Consulta [Supporto multilingue](/it/setup/languages).
  </Accordion>

  <Accordion title="Jamdesk traduce automaticamente i miei contenuti?">
    No. Jamdesk non traduce i contenuti. Devi fornire i file MDX tradotti; Jamdesk gestisce il routing, la navigazione, il selettore di lingua e gli stili RTL. Usa le traduzioni prodotte dal tuo flusso di lavoro (da traduttori, servizi di traduzione automatica o un LLM) e inseriscile in directory con prefisso della lingua (`es/`, `fr/` e così via). Consulta [Supporto multilingue](/it/setup/languages) per la struttura delle directory e la configurazione.
  </Accordion>
</AccordionGroup>

## Chat IA

<AccordionGroup>
  <Accordion title="Il mio sito di documentazione include una chat AI?">
    Sì. Ogni sito Jamdesk include un assistente di chat integrato che risponde alle domande dei visitatori basandosi sulla documentazione. È attivo per impostazione predefinita e non richiede configurazione. Per i dettagli, consulta [Chat AI](/it/ai/chat).
  </Accordion>

  <Accordion title="La chat AI ha un costo aggiuntivo?">
    No. La chat AI è inclusa in tutti i piani senza costi aggiuntivi.
  </Accordion>

  <Accordion title="Posso disattivare la chat AI?">
    Sì. Imposta `chat.enabled` su `false` in `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    Il pannello della chat e la scorciatoia da tastiera verranno rimossi dopo la build successiva.
  </Accordion>

  <Accordion title="Quali dati usa la chat per rispondere alle domande?">
    La chat usa solo le pagine di documentazione pubblicate. Durante ogni build, Jamdesk indicizza i contenuti in un database vettoriale. Quando un visitatore pone una domanda, le sezioni pertinenti vengono recuperate e inviate a Claude come contesto. L'AI non può accedere a dati esterni alla documentazione.
  </Accordion>
</AccordionGroup>

## Privacy e accesso

<AccordionGroup>
  <Accordion title="Posso avere documentazione pubblica e privata nello stesso sito?">
    Sì. Contrassegna le pagine interne con `private: true` nel frontmatter oppure elencane i percorsi in `auth.password.private[]` in `docs.json`. Le pagine pubbliche restano accessibili a tutti; quelle private mostrano una schermata di sblocco. Tutto rimane in un unico progetto, quindi le pagine pubbliche e private condividono lo stesso repository e la stessa build. Consulta [Controllo degli accessi](/it/setup/access-control) e [Protezione con password](/it/setup/password-protection).
  </Accordion>

  <Accordion title="Come proteggo con una password l'intero sito di documentazione?">
    Imposta `auth.password.enabled: true` in `docs.json`, invia la modifica e poi imposta una password in **Project Settings → Password Protection** nel dashboard. Ogni visitatore vedrà una schermata di sblocco finché non inserirà la password. Consulta [Protezione con password](/it/setup/password-protection).
  </Accordion>

  <Accordion title="I lettori possono accedere con il proprio account invece che con una password condivisa?">
    Sì, con i piani Enterprise. Il Single Sign-On permette ai lettori di autenticarsi tramite il tuo provider di identità (Okta, Google Workspace, Azure AD e così via), senza password condivise, con una traccia di audit completa e la disattivazione immediata degli accessi. Consulta [SSO](/it/setup/sso) o [contatta il team vendite Enterprise](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="È meglio separare la documentazione interna ed esterna in due progetti?">
    In genere no. Un unico progetto con `private: true` sulle pagine interne è più semplice: tutto rimane in un solo repository ed è gestito da un unico dashboard. Usa due progetti solo se i diversi destinatari richiedono branding, domini personalizzati o analisi completamente separati. Per i diversi approcci, consulta [Controllo degli accessi](/it/setup/access-control).
  </Accordion>

  <Accordion title="Qual è la differenza tra un editor e un lettore?">
    Gli **editor** scrivono la documentazione inviando commit MDX al repository GitHub collegato; quindi chiunque abbia accesso push al branch della documentazione può pubblicare modifiche. I **lettori** consultano il sito pubblicato: tutti (sito pubblico), chiunque abbia la password (modalità password) oppure chiunque abbia effettuato l'accesso tramite il tuo IdP (SSO). I **membri del team nel dashboard** sono una categoria distinta: gestiscono le build e le analisi, ma non creano direttamente i contenuti. Consulta [Controllo degli accessi](/it/setup/access-control).
  </Accordion>
</AccordionGroup>
