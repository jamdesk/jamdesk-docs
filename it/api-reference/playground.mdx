Il playground API aggiunge un pulsante interattivo "Try it" alle pagine degli endpoint API. Gli sviluppatori compilano i parametri, vedono aggiornarsi gli esempi di codice in tempo reale e inviano richieste HTTP reali dalla pagina della documentazione.

## Avvio rapido

Il playground è attivo per impostazione predefinita, senza alcuna configurazione in `docs.json`. Ogni pagina con un campo frontmatter `openapi:` o `api:` riceve un pulsante "Try it". CORS non richiede alcuna configurazione.

## Modalità di visualizzazione

Il campo `display` controlla cosa può fare il playground:

| Modalità | Pulsante "Try it" | Compila parametri | Codice in tempo reale | Invia richiesta |
|------|:-:|:-:|:-:|:-:|
| `"interactive"` (predefinita) | ✓ | ✓ | ✓ | ✓ |
| `"simple"` | ✓ | ✓ | ✓ | ✗ |
| `"none"` | ✗ | ✗ | ✗ | ✗ |

<Tabs>
  <Tab title="Interactive">
    Esperienza completa del playground. Gli sviluppatori compilano i parametri, vedono aggiornarsi gli esempi di codice in tempo reale e inviano richieste HTTP reali. Le risposte vengono visualizzate in linea con codici di stato, tempi e corpi formattati.

    ```json docs.json
    {
      "api": {
        "playground": {
          "display": "interactive"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Simple">
    Modalità di sola lettura senza il pulsante Send. Gli sviluppatori possono compilare i parametri e copiare gli esempi di codice generati, ma non possono inviare richieste. Usala quando la tua API richiede un'autenticazione che non puoi condividere nella documentazione.

    ```json docs.json
    {
      "api": {
        "playground": {
          "display": "simple"
        }
      }
    }
    ```
  </Tab>
</Tabs>

## Autenticazione

Il playground mostra un campo di input per l'autenticazione in cima al modulo dei parametri quando la tua API richiede autenticazione (configurata tramite `api.mdx.auth.method` in `docs.json`). Gli sviluppatori inseriscono la propria chiave API o token nella finestra modale.

Le credenziali vengono mantenute solo in memoria per la sessione corrente. Non vengono mai salvate in `localStorage` né conservate tra una visita e l'altra.

## Precompilazione dei valori di esempio

Il playground può precompilare i valori `example` dei parametri e dei corpi delle richieste nella tua specifica OpenAPI:

```json docs.json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

Gli sviluppatori partono da valori realistici invece che da campi vuoti.

## Override per pagina

Sovrascrivi la modalità di visualizzazione globale su singole pagine usando il campo frontmatter `playground`:

```mdx
---
title: Create Ticket
openapi: POST /tickets
playground: interactive
---
```

Usalo per disattivare il playground globalmente ma attivarlo per specifici endpoint dimostrativi, o viceversa.

| Frontmatter | Comportamento |
|-------------|----------|
| `playground: interactive` | Playground completo su questa pagina |
| `playground: simple` | Playground solo codice su questa pagina |
| `playground: none` | Nessun playground su questa pagina |

## Come funziona

<Steps>
  <Step title="Clicca su 'Try it'">
    Il playground si apre come finestra modale a schermo intero sopra la pagina. La tua pagina della documentazione resta intatta sotto.
  </Step>
  <Step title="Compila i parametri">
    I parametri di percorso, query, header e corpo vengono mostrati come campi di un modulo. I campi obbligatori sono contrassegnati. L'URL base viene recuperato dal campo `servers` della tua specifica OpenAPI.
  </Step>
  <Step title="Osserva il codice aggiornarsi">
    Gli esempi di codice vengono rigenerati mentre digiti, in ogni linguaggio configurato. Copia qualsiasi esempio con un clic.
  </Step>
  <Step title="Invia la richiesta">
    In modalità interattiva, clicca su Send (o premi `Ctrl/Cmd+Enter`) per eseguire la richiesta. La risposta viene visualizzata sotto con codice di stato, durata e corpo formattato.
  </Step>
</Steps>

## Più server

Un selettore di server compare accanto all'URL dell'endpoint quando la specifica di un endpoint elenca più di una voce in `servers` (ad esempio produzione e sandbox). La scelta del lettore imposta l'URL base, il pulsante di copia dell'URL, gli esempi di codice della pagina e la richiesta inviata dal playground.

Gli endpoint con un solo server non mostrano il selettore e non aggiungono peso alla pagina.

## Scorciatoie da tastiera

| Scorciatoia | Azione |
|----------|--------|
| `Ctrl/Cmd + Enter` | Invia richiesta |
| `Escape` | Chiudi playground |

## Funziona con entrambi i tipi di pagina API

Il playground funziona sulle pagine che usano il formato frontmatter `openapi:` o `api:`:

<Tabs>
  <Tab title="Pagine OpenAPI">
    Jamdesk recupera parametri e schemi dalla tua specifica OpenAPI. Non serve alcuna configurazione.

    ```mdx
    ---
    openapi: POST /tickets
    ---
    ```
  </Tab>
  <Tab title="Pagine MDX api:">
    I parametri vengono estratti dai componenti `<ParamField>`. L'URL base proviene da `api.mdx.server` nel tuo docs.json.

    ```mdx
    ---
    api: GET /tickets/{ticket_id}
    ---
    ```
  </Tab>
</Tabs>

## Sviluppo locale

Il playground funziona solo in produzione. `jamdesk dev` mostra i pulsanti "Try it". Cliccandone uno compare una breve notifica invece di aprire la finestra modale. Distribuisci la documentazione per usare il playground completo.
