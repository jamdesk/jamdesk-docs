Questa pagina è un endpoint live generato da una [specifica OpenAPI](https://spec.openapis.org/oas/latest.html). Jamdesk genera lo schema della richiesta, i modelli di risposta e gli esempi di codice nel pannello destro a partire dalla specifica.

<Info>
Questo esempio usa l'API Acme Support. Punta `api.openapi` in `docs.json` al tuo file di specifica per generare i tuoi endpoint.
</Info>

<Info>
**Documentazione multilingua?** Fornisci un file `<spec>.<lang>.<ext>` accanto alla specifica sorgente (ad esempio `example-api.it.yaml`). Jamdesk mostra la versione tradotta nelle pagine sotto `/it/...`. Vedi [Traduzione delle specifiche OpenAPI](/it/setup/languages#translating-openapi-specs).
</Info>

<Tip>
Questa pagina ha il [Playground API](/it/api-reference/playground) abilitato. Clicca **Try it** sull'endpoint sopra per testare l'API in tempo reale.
</Tip>

## Cosa viene generato

Da una sola riga `openapi` nel frontmatter, Jamdesk genera:

- Un badge dell'endpoint che mostra metodo e percorso, con codifica a colori
- Documentazione dei parametri per path, query, header e body
- Schemi di richiesta e risposta, inclusi oggetti annidati e array
- Esempi di codice in cURL, Python, JavaScript, Go, Ruby, C#, Java, Rust e PHP (configurabili tramite `api.examples.languages`)
- Dettagli di autenticazione presi dagli security scheme della specifica

Jamdesk risolve ogni `$ref` nella tua specifica. Organizza gli schemi con `components/schemas` come di consueto.

Jamdesk visualizza le descrizioni della specifica come Markdown, non come testo grezzo. Le descrizioni di operazioni, parametri, request body, risposte e schemi supportano gli stessi **grassetto**, `codice`, liste, link e tabelle GFM che useresti in una pagina `.mdx`.

## Configurazione di OpenAPI

Inserisci la tua specifica OpenAPI 3.x (YAML o JSON) nella directory `openapi/`. Registrala in `docs.json` sotto `api.openapi`. Poi aggiungi `openapi: /openapi/your-spec.yaml METHOD /path` al frontmatter di qualsiasi pagina. Vedi la [guida alla configurazione OpenAPI](/it/setup/directory-structure#openapi) per i dettagli completi.

## Genera una pagina per ogni operazione

Punta una scheda di navigazione alla specifica per far generare a Jamdesk l'intera reference, invece di scrivere una pagina per ogni endpoint:

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": { "source": "/openapi/api.yaml", "generate": true }
      }
    ]
  }
}
```

Ogni operazione ottiene una pagina. La sidebar è raggruppata per tag. I file `.mdx` committati hanno la precedenza in caso di collisione di slug. Puoi adottarlo una pagina alla volta. Rinominare un percorso nella specifica reindirizza l'URL precedente invece di romperlo. Vedi [navigation openapi](/it/config/docs-json-reference#navigation-openapi-generated-pages) per le regole complete e i limiti attuali.

<Tip>
  Scrivi la specifica in YAML? Passala al [YAML Validator](https://jamdesk.com/utilities/yaml-validator) gratuito per individuare errori di indentazione e sintassi prima che la build la analizzi.
</Tip>
