## Ottimizzare i contenuti

### Scrivere un frontmatter efficace

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Inserisci le parole chiave all'inizio.** «Configurazione dell'autenticazione» è meglio di «Come configurare l'autenticazione».
</Tip>

### Titoli delle pagine

- Non superare i 60 caratteri per evitare il troncamento nei risultati di ricerca
- Inserisci la parola chiave principale vicino all'inizio
- Usa un titolo univoco per ogni pagina della documentazione

Per impostazione predefinita, il titolo della scheda del browser e dei risultati di ricerca è `Page title — Site name`. Per modificarlo, imposta `seo.titleTemplate` in `docs.json`. Ogni `%s` viene sostituito dal titolo della pagina:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Usa solo `"%s"` per omettere il nome del sito. Il modello modifica solo il titolo della scheda del browser e dei risultati di ricerca. Il titolo nelle anteprime social (`og:title`) rimane invariato. Se una pagina non ha un titolo o il titolo coincide con il nome del sito, viene mostrato il titolo del sito così com'è.

### Descrizioni

- Punta a 120-160 caratteri
- Riassumi cosa imparerà il lettore
- Includi le parole chiave pertinenti in modo naturale

<Note>
**Testo di ripiego generato automaticamente.** Se manca `description` nel frontmatter, Jamdesk estrae automaticamente il primo paragrafo discorsivo del contenuto della pagina, fino a 155 caratteri. Titoli, blocchi di codice, immagini e componenti MDX vengono ignorati. Il testo viene usato per `<meta name="description">`, Open Graph e le schede Twitter. Per ottenere i risultati migliori, è comunque consigliabile scrivere una descrizione esplicita.
</Note>

## Controllare l'indicizzazione

### Impostazioni globali del sito

In `docs.json`, configura il comportamento predefinito dei robot:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Controllo per singola pagina

Imposta una regola di indicizzazione specifica per una pagina nel frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Usa `noindex` per:
- Pagine in bozza o ancora in lavorazione
- Documentazione interna
- Contenuti obsoleti che vuoi conservare come riferimento

### Indicizzazione per la ricerca e acquisizione AI

I metadati `robots` e `noindex` controllano i **motori di ricerca**: determinano se una pagina appare su Google e in `sitemap.xml`. Non influiscono sui file `llms.txt` e `llms-full.txt` letti dagli strumenti AI. Per interromperne la pubblicazione, imposta `seo.ai.llmsTxt` su `false` (vedi [Disattivare llms.txt](/it/ai/llms-txt#disattiva-llmstxt)). I due controlli sono indipendenti: una pagina può essere indicizzata dai motori di ricerca ma esclusa dall'acquisizione AI, o viceversa.

## URL canonici

Se la documentazione è accessibile da più URL, imposta un URL canonico:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Puoi anche impostare una base canonica a livello di sito in `docs.json`. Jamdesk vi aggiunge il
percorso di ogni pagina, così ciascuna pagina riceve un URL canonico corretto:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Anteprime social e Open Graph

Jamdesk genera automaticamente per ogni pagina una scheda social brandizzata da 1200×630. Puoi sovrascrivere qualsiasi tag social nel frontmatter. Puoi usare **chiavi piatte di primo livello** oppure un blocco **`seo:`** annidato. Entrambe le opzioni funzionano; se la stessa chiave è impostata in entrambi i modi, prevale il valore di primo livello.

<Card title="Anteprima OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Scopri come viene visualizzata la scheda di una pagina su X, Facebook, LinkedIn e altre piattaforme e convalida i relativi tag Open Graph con lo strumento OpenGraph Preview.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Tag supportati

| Gruppo | Tag |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Articolo | `og:type: article` con `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, tag app-card |
| Altri | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` e qualsiasi tag personalizzato (inserisci i tag personalizzati in `seo:`) |

<Note>
**Dimensioni personalizzate delle immagini OG.** `og:image:width` e `og:image:height` si applicano solo quando
[`customImage`](#personalizzare-la-scheda-social) è `"replace"`. Impostale nello stesso punto di
`og:image` a cui si riferiscono, nel frontmatter della pagina o in `seo.metatags`. La scheda generata
è sempre da 1200×630.
</Note>

<Note>
**Tag personalizzati.** I tag meta arbitrari (ad esempio `x-pinterest`) vengono generati come `<meta name="...">`.
Inseriscili nel blocco `seo:`. Se aggiunti in forma piatta, vengono rilevate solo le chiavi SEO riconosciute.
</Note>

### Tipo di scheda Twitter / X

Il tag `twitter:card` controlla il layout usato da X e dalle altre piattaforme quando condividi un link:

| Valore | Aspetto |
|-------|--------------------|
| `summary` | Miniatura quadrata a sinistra, titolo e descrizione accanto. Compatta. |
| `summary_large_image` | Immagine grande a tutta larghezza in alto, titolo e descrizione sotto. La versione più grande e d'impatto. |

Per una scheda brandizzata da 1200×630, usa `summary_large_image` per visualizzare l'immagine a tutta larghezza.

### Immagine predefinita globale del sito

Imposta un'immagine social di ripiego per ogni pagina in `docs.json`. Qualsiasi pagina con un proprio `og:image` la sostituisce:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Controlla l'anteprima prima della pubblicazione.** Dopo una build, incolla l'URL della pagina nello strumento [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) per verificare come viene visualizzata la scheda su ogni piattaforma e convalidare i tag Open Graph. Lo strumento controlla anche le dimensioni dell'immagine e spiega come risolvere eventuali problemi.
</Tip>

### Personalizzare la scheda social

La scheda generata mantiene l'aspetto attuale, a meno che tu non aggiunga `seo.socialCard` a `docs.json`.
Imposta solo le chiavi che vuoi modificare:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Chiave | Predefinito | Effetto |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` usa testo chiaro su sfondo scuro e l'immagine `logo.dark`. |
| `brandColor` | `false` | `true` assegna a `colors.primary` il colore della barra inferiore e del badge della sezione. Se imposti `colors.light`, una scheda scura lo usa. Se non imposti `colors`, la scheda usa il colore di accento del tema. `false` mantiene il rosso predefinito. |
| `accentBar` | `true` | `false` rimuove la barra colorata lungo il bordo inferiore della scheda. |
| `siteName` | `true` | `false` nasconde il nome del sito sotto il logo. Usalo se il logo mostra già il nome. |
| `customImage` | `"background"` | `"background"` mostra il titolo della pagina sopra `og:image`. `"replace"` usa `og:image` come intera scheda. |

La scheda può visualizzare solo loghi SVG, PNG e JPG. Durante la build del sito, Jamdesk converte i file logo PNG e JPG nel repository in WebP, quindi di solito la scheda mostra la favicon e mantiene il nome del sito, anche con `siteName: false`. Usa un logo SVG per mostrare il logo completo sulla scheda e `logo.dark` per una scheda scura.

La scheda non può visualizzare testo all'interno di un logo SVG. Se il logo contiene testo, convertilo in tracciati prima di esportarlo. Se rileva testo nel logo SVG usato dalla scheda, la build mostra un suggerimento. I loghi collegati da un altro sito non vengono controllati.

Se il colore del brand non risalta abbastanza sulla scheda, il testo del badge usa il colore normale del testo. La barra mantiene il colore del brand, a meno che non sia quasi uguale allo sfondo della scheda; in tal caso, diventa grigia.

Per impostazione predefinita, Jamdesk mostra il titolo della pagina sopra `og:image`. Se l'immagine contiene già testo o una grafica, imposta `"customImage": "replace"` per mostrarla così com'è.

Quando `og:image` è lo sfondo della scheda, scegli il `theme` più adatto: `dark` per un'immagine scura, `light` per un'immagine chiara.

In modalità `replace`, Jamdesk non mostra alcun titolo sull'immagine. Se `seo.metatags` imposta `og:image`, tutte le pagine usano quell'immagine; una pagina con un proprio `og:image` usa invece quello. Solo le pagine senza nessuna delle due impostazioni ricevono una scheda generata. Usa un PNG o JPG da 1200×630. Alcune piattaforme non mostrano immagini WebP o SVG.

I social network memorizzano nella cache le anteprime dei link, quindi un link già condiviso può continuare a mostrare la vecchia scheda per un po' dopo la modifica di queste impostazioni. Controlla la nuova scheda con lo strumento
[OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Le versioni precedenti della CLI di Jamdesk rifiutano `seo.socialCard` e `seo.titleTemplate` in
`jamdesk validate` e `jamdesk dev`. Aggiorna con `npm i -g jamdesk@latest`.
</Note>

## Sitemap e robots.txt

Ogni sito Jamdesk genera automaticamente `sitemap.xml` e `robots.txt` a ogni build.

| File | Scopo |
|------|---------|
| `sitemap.xml` | Elenca tutte le pagine con le date di ultima modifica per i motori di ricerca |
| `robots.txt` | Consente l'accesso a tutti i crawler e indica loro la sitemap |

### Dove trovarli

Gli URL dipendono dal fatto che la documentazione si trovi su un dominio principale o in un sottopercorso `/docs`:

<Tabs>
  <Tab title="Dominio principale">
    Se la documentazione si trova nella radice del dominio (ad esempio `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Sottopercorso /docs">
    Se la documentazione si trova in `/docs` sul sito principale (come questo sito su `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Cosa contiene la sitemap

- Tutte le pagine pubblicate (tranne quelle con `noindex` o `hidden` nel frontmatter)
- Date di ultima modifica dal frontmatter, se disponibili
- Frequenza di aggiornamento settimanale

### Escludere pagine dalla sitemap

Aggiungi `noindex` al frontmatter per escludere una pagina sia dalla sitemap sia dai motori di ricerca:

```yaml
---
title: Internal Notes
noindex: true
---
```

Anche le pagine con `hidden: true` vengono escluse automaticamente.

## Dati strutturati JSON-LD

Ogni pagina include automaticamente dati strutturati [schema.org](https://schema.org) in un tag `<script type="application/ld+json">` con due schemi:

- `WebSite`: nome, URL e descrizione del sito (da `docs.json`).
- `BreadcrumbList`: percorso di navigazione dalla Home alla pagina corrente, derivato dalla configurazione `navigation`.

Non è necessaria alcuna configurazione. I motori di ricerca li usano per mostrare risultati avanzati, ad esempio percorsi di navigazione nei risultati di ricerca.

<Tip>
**Verifica il markup.** Incolla l'URL di una pagina nel [Test dei risultati avanzati di Google](https://search.google.com/test/rich-results) per verificare che i dati strutturati vengano rilevati.
</Tip>

## IndexNow

Dopo ogni build, Jamdesk invia automaticamente a [IndexNow](https://www.indexnow.org) gli URL delle pagine modificate, per accelerarne l'indicizzazione nei motori di ricerca. In questo modo Bing, Yandex e gli altri motori di ricerca aderenti vengono informati delle modifiche ai contenuti senza dover attendere il successivo ciclo di scansione.

- Si attiva dopo ogni build completata correttamente
- Invia solo le pagine effettivamente modificate
- Non blocca il processo, quindi non ritarda mai la build
- Non richiede configurazione

## Buone pratiche

Prima di pubblicare, verifica questi punti:

<Note>
**Checklist prima della pubblicazione**

- **Titoli univoci.** Ogni pagina ha un titolo distinto e descrittivo, inferiore a 60 caratteri.
- **Descrizioni accurate.** Le descrizioni riassumono la pagina in 120-160 caratteri.
- **Titoli gerarchici.** I titoli seguono una gerarchia chiara: un H1, poi H2 → H3.
- **Link descrittivi.** I link interni usano testi di ancoraggio significativi, mai «clicca qui».
- **Testo alternativo delle immagini.** Ogni immagine ha un testo alternativo per l'accessibilità e la ricerca per immagini.
- **Immagine social.** Imposta un `og:image` personalizzato nelle pagine principali oppure usa la scheda generata automaticamente. Verificalo con lo strumento [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
