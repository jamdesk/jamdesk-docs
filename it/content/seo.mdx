## Ottimizzare i contenuti

### Scrivere un frontmatter efficace

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Anticipa le parole chiave.** "Configurazione dell'autenticazione" è meglio di "Come configurare l'autenticazione."
</Tip>

### Titoli delle pagine

- Mantieni il titolo sotto i 60 caratteri, contando anche il nome del sito aggiunto dal formato del titolo. I titoli più lunghi vengono troncati nei risultati di ricerca
- Includi la parola chiave principale vicino all'inizio
- Rendi unico ogni titolo nella tua documentazione

Per impostazione predefinita, il titolo nella scheda del browser e nei risultati di ricerca è `Titolo della pagina — Nome del sito`. Cambialo con `seo.titleTemplate` in `docs.json`. Inserisci `%s` dove va il titolo della pagina:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Una pagina intitolata `Getting started` mostra quindi `Getting started | Acme`. Usa `"%s"` da solo per omettere il nome del sito. Un template senza `%s` fa fallire la build. `jamdesk validate` mostra l'errore. Le anteprime dei link (`og:title` e `twitter:title`) mostrano ancora solo il titolo della pagina.

Alcune pagine non usano il template. Una pagina senza `title` mostra il tuo `name` seguito da "Documentation", ad esempio `Acme Documentation`, oppure solo il tuo `name` se termina già con "Docs" o "Documentation". Una pagina il cui titolo coincide con il tuo `name` mostra solo quel titolo.

`jamdesk validate` e `jamdesk dev` accettano `seo.titleTemplate` dalla versione 1.1.220 della CLI. Aggiorna con `npm i -g jamdesk@latest`.

### Descrizioni

- Punta a 120-160 caratteri
- Riassumi ciò che il lettore imparerà
- Includi parole chiave pertinenti in modo naturale

<Note>
**Fallback generato automaticamente.** Jamdesk estrae il primo paragrafo di testo dal contenuto della pagina (fino a 155 caratteri) quando `description` manca nel frontmatter. Titoli, blocchi di codice, immagini e componenti MDX vengono saltati. Quel testo riempie `<meta name="description">`, Open Graph e le card Twitter. Una descrizione esplicita dà sempre i risultati migliori.
</Note>

## Controllare l'indicizzazione

### Impostazioni globali del sito

Imposta il comportamento predefinito dei robot in `docs.json`:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Controllo per singola pagina

Sovrascrivi l'indicizzazione per pagine specifiche nel frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Usa `noindex` per:
- Pagine in bozza o in lavorazione
- Documentazione interna
- Contenuti obsoleti che conservi come riferimento

### Indicizzazione per la ricerca e acquisizione AI

I metadati `robots` e `noindex` controllano i **motori di ricerca**: se una pagina compare su Google e nel tuo `sitemap.xml`. Non hanno effetto sui file `llms.txt` e `llms-full.txt` letti dagli strumenti AI. Imposta `seo.ai.llmsTxt` su `false` per smettere di pubblicarli (vedi [Disattivare llms.txt](/it/ai/llms-txt#disattivare-llmstxt)). I due controlli sono indipendenti: una pagina può essere indicizzata dai motori di ricerca ma esclusa dall'ingestione AI, o viceversa.

## URL canonici

Imposta un canonical se la tua documentazione è raggiungibile da più URL:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Puoi anche impostare una base canonical per l'intero sito in `docs.json`. Jamdesk aggiunge a essa il percorso di ogni pagina:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Anteprime social e Open Graph

Jamdesk genera una card social 1200×630 con il tuo brand per ogni pagina. Sovrascrivi qualsiasi tag social nel frontmatter con chiavi piatte di primo livello o con un blocco annidato `seo:`. Il valore piatto di primo livello prevale quando la stessa chiave è impostata in entrambi i modi.

<Card title="Anteprima OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Visualizza in anteprima la card di qualsiasi pagina su X, Facebook, LinkedIn e altri. Valida i suoi tag Open Graph.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Tag supportati

| Gruppo | Tag |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Article | `og:type: article` con `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, tag per app card |
| Altri | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color`, più qualsiasi tag personalizzato (inseriscili sotto `seo:`) |

<Note>
**Dimensioni dell'immagine OG personalizzata.** `og:image:width` e `og:image:height` si applicano solo quando [`customImage`](#personalizzare-la-scheda-social) è `"replace"`. Impostali nello stesso punto dell'`og:image` che descrivono, nel frontmatter della pagina o in `seo.metatags`. La card generata è sempre 1200×630.
</Note>

<Note>
**Tag personalizzati.** I meta tag arbitrari (ad esempio `x-pinterest`) vengono emessi come `<meta name="...">`. Inseriscili sotto il blocco `seo:`. Se posti in piano, vengono riconosciute solo le chiavi SEO riconosciute.
</Note>

### Tipo di scheda Twitter / X

Il tag `twitter:card` controlla quale layout usano X (e altre piattaforme) quando il tuo link viene condiviso:

| Valore | Aspetto |
|-------|--------------------|
| `summary` | Miniatura quadrata piccola a sinistra, titolo + descrizione accanto. Compatta. |
| `summary_large_image` | Immagine grande a tutta larghezza in alto, titolo + descrizione sotto. |

Usa `summary_large_image` per una card 1200×630 con il tuo brand. Mostra l'immagine a tutta larghezza.

### Immagine predefinita globale del sito

Imposta un'immagine social di riserva per ogni pagina in `docs.json`. Ogni pagina che imposta il proprio `og:image` la sovrascrive:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Visualizza l'anteprima prima di pubblicare.** Incolla l'URL della pagina nello strumento [Anteprima OpenGraph](https://jamdesk.com/utilities/opengraph-preview) dopo una build. Mostra come appare la card su ogni piattaforma e valida i tag Open Graph. Controlla anche le dimensioni dell'immagine e spiega come risolvere i problemi.
</Tip>

### Personalizzare la scheda social

La card generata mantiene l'aspetto attuale finché non aggiungi `seo.socialCard` a `docs.json`. Imposta solo le chiavi che vuoi cambiare:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Chiave | Predefinito | Effetto |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` usa testo chiaro su sfondo scuro e l'immagine `logo.dark`. |
| `brandColor` | `false` | `true` colora la barra inferiore e il badge di sezione con `colors.primary`. Su una card scura usa `colors.light`, se impostato. Se non hai `colors`, la card usa il colore di accento del tema. `false` mantiene il rosso predefinito. |
| `accentBar` | `true` | `false` rimuove la barra colorata lungo il fondo della card. |
| `siteName` | `true` | `false` nasconde il nome del sito sotto il logo. Usalo quando il tuo logo mostra già il nome. |
| `customImage` | `"background"` | `"background"` disegna il titolo della pagina sopra il tuo `og:image`. `"replace"` usa il tuo `og:image` come intera card. |

La card può disegnare solo logo SVG, PNG e JPG. Jamdesk converte i file logo PNG e JPG del tuo repository in WebP al momento della build. Di solito la card mostra invece la tua favicon e mantiene il nome del sito, anche con `siteName: false`. Usa un logo SVG per mostrare il logo completo sulla card. Usa un `logo.dark` SVG per una card scura.

La card non può disegnare testo dentro un logo SVG: quel testo risulta vuoto. Converti il testo in contorni (path) nello strumento di design ed esporta di nuovo l'SVG. In Figma, seleziona il testo e usa **Flatten**. In Illustrator, usa **Type > Create Outlines**. La build mostra un suggerimento quando trova testo nel logo SVG della card. I logo impostati con un URL completo (`https://...`) non vengono controllati.

Il testo del badge torna al colore di testo normale quando il tuo colore brand non si distingue dallo sfondo della card. La barra mantiene il tuo colore brand a meno che quel colore non coincida quasi con lo sfondo: in quel caso la barra è grigia.

Per impostazione predefinita, Jamdesk disegna il titolo della pagina sopra il tuo `og:image`. Imposta `"customImage": "replace"` per mostrare un'immagine che ha già il proprio testo o design così com'è.

Scegli il `theme` che corrisponde a un `og:image` usato come sfondo della card: `dark` per un'immagine scura, `light` per una chiara.

In modalità `replace`, Jamdesk non disegna alcun titolo sull'immagine. Un `og:image` in `seo.metatags` si applica a ogni pagina. Una pagina che imposta il proprio `og:image` usa quello. Solo le pagine senza nessuno dei due ricevono una card generata. Usa un PNG o JPG 1200×630. Alcune piattaforme non mostrano immagini WebP o SVG.

I siti social mettono in cache le anteprime dei link. Un link già condiviso può mantenere la vecchia card per un po' dopo che cambi queste impostazioni. Controlla la nuova card con lo strumento [Anteprima OpenGraph](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Le versioni precedenti della CLI di Jamdesk rifiutano `seo.socialCard` e `seo.titleTemplate` in `jamdesk validate` e `jamdesk dev`. Aggiorna con `npm i -g jamdesk@latest`.
</Note>

## Sitemap e robots.txt

Jamdesk genera `sitemap.xml` e `robots.txt` a ogni build.

| File | Scopo |
|------|---------|
| `sitemap.xml` | Elenca tutte le pagine con le date di ultima modifica per i motori di ricerca |
| `robots.txt` | Consente tutti i crawler e li indirizza alla sitemap |

### Dove trovarli

Gli URL dipendono dal fatto che la documentazione sia su un dominio radice o sotto un sottopercorso `/docs`:

<Tabs>
  <Tab title="Dominio radice">
    Se la documentazione è alla radice del dominio (ad esempio `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Sottopercorso /docs">
    Se la documentazione si trova sotto `/docs` sul sito principale (come questo sito su `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Cosa contiene la sitemap

- Tutte le pagine pubblicate (esclusi i casi con frontmatter `noindex` o `hidden`)
- Date di ultima modifica dal frontmatter quando disponibili
- Frequenza di modifica settimanale

### Escludere pagine dalla sitemap

Aggiungi `noindex` al frontmatter per tenere una pagina fuori dalla sitemap e dai motori di ricerca:

```yaml
---
title: Internal Notes
noindex: true
---
```

Anche le pagine con `hidden: true` sono escluse.

## Dati strutturati JSON-LD

Ogni pagina include dati strutturati [schema.org](https://schema.org) come tag `<script type="application/ld+json">` con due schemi:

- `WebSite`: il nome del sito, l'URL e la descrizione (da `docs.json`).
- `BreadcrumbList`: il percorso di navigazione da Home alla pagina corrente, derivato dalla configurazione `navigation`.

Non serve alcuna configurazione. I motori di ricerca li usano per risultati arricchiti come i percorsi di navigazione (breadcrumb) nei risultati di ricerca.

<Tip>
**Verifica il markup.** Incolla qualsiasi URL di pagina nello [Strumento di test dei risultati multimediali di Google](https://search.google.com/test/rich-results) per confermare che i dati strutturati vengano rilevati.
</Tip>

## IndexNow

Jamdesk invia gli URL delle pagine modificate a [IndexNow](https://www.indexnow.org) dopo ogni build. Bing, Yandex e altri motori di ricerca partecipanti vengono a conoscenza delle modifiche senza attendere il loro prossimo ciclo di scansione.

- Si attiva dopo ogni build riuscita
- Invia solo le pagine modificate
- Non bloccante: non ritarda mai la build
- Nessuna configurazione richiesta

## Buone pratiche

Passa in rassegna questa checklist prima di pubblicare:

<Note>
**Checklist prima della pubblicazione**

- **Titoli unici:** ogni pagina ha un titolo distinto e descrittivo sotto i 60 caratteri.
- **Descrizioni accurate:** le descrizioni riassumono la pagina in 120-160 caratteri.
- **Titoli logici:** i titoli seguono una gerarchia pulita: un H1, poi H2 → H3.
- **Link descrittivi:** i link interni usano testo di ancoraggio significativo, mai "clicca qui."
- **Testo alternativo delle immagini:** ogni immagine ha un testo alternativo per l'accessibilità e la ricerca di immagini.
- **Immagine social:** imposta un `og:image` personalizzato sulle pagine chiave, oppure affidati alla card generata automaticamente. Verificala con lo strumento [Anteprima OpenGraph](https://jamdesk.com/utilities/opengraph-preview).
</Note>
