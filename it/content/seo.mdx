## Ottimizzare i contenuti

### Scrivere un frontmatter efficace

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Metti le parole chiave all'inizio.** "Configurazione dell'autenticazione" è meglio di "Come configurare l'autenticazione".
</Tip>

### Titoli delle pagine

- Mantieni il titolo sotto i 60 caratteri, contando il nome del sito aggiunto dal formato del titolo, per evitare che venga troncato nei risultati di ricerca
- Includi la parola chiave principale vicino all'inizio
- Usa un titolo diverso per ogni pagina della documentazione

Per impostazione predefinita, il titolo nella scheda del browser e nei risultati di ricerca è `Page title — Site name`. Per modificarlo, imposta `seo.titleTemplate` in `docs.json`. Inserisci `%s` nel punto in cui deve comparire il titolo della pagina:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Una pagina intitolata `Getting started` verrà quindi visualizzata come `Getting started | Acme`. Usa solo `"%s"` per omettere il nome del sito. Se il modello non contiene `%s`, la build non riesce e `jamdesk validate` mostra l'errore. Le anteprime dei link (`og:title` e `twitter:title`) continuano a mostrare solo il titolo della pagina.

Due tipi di pagine non usano il modello. Se una pagina non ha `title`, mostra il tuo `name` seguito da "Documentation", ad esempio `Acme Documentation`, oppure solo il tuo `name` se termina già con "Docs" o "Documentation". Se il titolo di una pagina corrisponde al tuo `name`, viene mostrato solo quel titolo.

`jamdesk validate` e `jamdesk dev` supportano `seo.titleTemplate` dalla versione 1.1.220 della CLI. Aggiorna con `npm i -g jamdesk@latest`.

### Descrizioni

- Punta a 120-160 caratteri
- Riassumi cosa imparerà il lettore
- Includi naturalmente le parole chiave pertinenti

<Note>
**Fallback generato automaticamente.** Se nel frontmatter manca `description`, Jamdesk estrae automaticamente il primo paragrafo di testo della pagina, fino a 155 caratteri. Esclude titoli, blocchi di codice, immagini e componenti MDX. Il testo viene usato per `<meta name="description">`, Open Graph e le schede Twitter. Per ottenere i risultati migliori, è comunque consigliabile scrivere una descrizione esplicita.
</Note>

## Controllare l'indicizzazione

### Impostazioni globali del sito

Nel file `docs.json`, configura il comportamento predefinito dei robot:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Controllo per singola pagina

Puoi escludere dall'indicizzazione pagine specifiche nel frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Usa `noindex` per:
- Pagine in bozza o in fase di lavorazione
- Documentazione interna
- Contenuti obsoleti che vuoi conservare come riferimento

### Indicizzazione per la ricerca e acquisizione AI

I metadati `robots` e `noindex` controllano i **motori di ricerca**: stabiliscono se una pagina compare su Google e nel tuo `sitemap.xml`. Non hanno effetto sui file `llms.txt` e `llms-full.txt` letti dagli strumenti AI. Per interromperne la pubblicazione, imposta `seo.ai.llmsTxt` su `false` (vedi [Disattivare llms.txt](/it/ai/llms-txt#disattiva-llmstxt)). I due controlli sono indipendenti: una pagina può essere indicizzata dai motori di ricerca ma esclusa dall'acquisizione AI, o viceversa.

## URL canonici

Se la documentazione è accessibile da più URL, imposta un URL canonico:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Puoi anche impostare una base canonica globale per il sito in `docs.json`. Jamdesk vi aggiunge il percorso di ogni pagina, così ciascuna ottiene il proprio URL canonico corretto:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Anteprime social e Open Graph

Jamdesk genera automaticamente per ogni pagina una scheda social personalizzata da 1200×630. Puoi sovrascrivere qualsiasi tag social nel frontmatter. Puoi usare **chiavi di primo livello** oppure un blocco **`seo:`** annidato. Entrambe le opzioni funzionano e, se la stessa chiave è impostata in entrambi i modi, prevale il valore di primo livello.

<Card title="Anteprima OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Scopri come viene visualizzata la scheda di una pagina su X, Facebook, LinkedIn e altre piattaforme e convalida i relativi tag Open Graph con lo strumento OpenGraph Preview.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Tag supportati

| Gruppo | Tag |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Articolo | `og:type: article` con `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, tag app-card |
| Altro | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` e qualsiasi tag personalizzato (inserisci i tag personalizzati in `seo:`) |

<Note>
**Dimensioni personalizzate dell'immagine OG.** `og:image:width` e `og:image:height` si applicano solo quando
[`customImage`](#personalizzare-la-scheda-social) è `"replace"`. Impostali nello stesso punto di
`og:image`, nel frontmatter della pagina o in `seo.metatags`. La scheda generata è sempre 1200×630.
</Note>

<Note>
**Tag personalizzati.** I meta tag arbitrari (ad esempio `x-pinterest`) vengono generati come `<meta name="...">`.
Inseriscili nel blocco `seo:`. Se collocati al livello superiore, vengono rilevate solo le chiavi SEO riconosciute.
</Note>

### Tipo di scheda Twitter / X

Il tag `twitter:card` determina il layout usato da X e da altre piattaforme quando condividi un link:

| Valore | Aspetto |
|-------|--------------------|
| `summary` | Miniatura quadrata piccola a sinistra, titolo e descrizione accanto. Compatta. |
| `summary_large_image` | Immagine grande a tutta larghezza in alto, titolo e descrizione sotto. Più evidente. |

Per una scheda personalizzata da 1200×630, usa `summary_large_image` così l'immagine viene visualizzata a tutta larghezza.

### Immagine predefinita globale del sito

Imposta un'immagine social di fallback per ogni pagina in `docs.json`. Qualsiasi pagina con un proprio `og:image` sovrascrive questa impostazione:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Visualizza l'anteprima prima della pubblicazione.** Dopo una build, incolla l'URL della pagina nello strumento [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) per controllare l'aspetto della scheda su ogni piattaforma e convalidare i tag Open Graph. Controlla anche le dimensioni dell'immagine e spiega come risolvere eventuali problemi.
</Tip>

### Personalizzare la scheda social

La scheda generata mantiene l'aspetto attuale, a meno che tu non aggiunga `seo.socialCard` a `docs.json`.
Imposta solo le chiavi che vuoi modificare:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Chiave | Predefinito | Effetto |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` usa testo chiaro su sfondo scuro e l'immagine `logo.dark`. |
| `brandColor` | `false` | `true` colora la barra inferiore e il badge della sezione con `colors.primary`. Se imposti `colors.light`, una scheda scura la usa. Se non hai `colors`, la scheda usa il colore di accento del tema. `false` mantiene il rosso predefinito. |
| `accentBar` | `true` | `false` rimuove la barra colorata nella parte inferiore della scheda. |
| `siteName` | `true` | `false` nasconde il nome del sito sotto il logo. Usalo quando il logo mostra già il nome. |
| `customImage` | `"background"` | `"background"` sovrappone il titolo della pagina a `og:image`. `"replace"` usa `og:image` come scheda intera. |

La scheda può visualizzare solo loghi SVG, PNG e JPG. Durante la build del sito, Jamdesk converte i file logo PNG e JPG nel repository in WebP: di conseguenza, la scheda mostra solitamente la favicon e mantiene il nome del sito, anche con `siteName: false`. Usa un logo SVG per mostrare il logo completo sulla scheda e `logo.dark` per una scheda scura.

La scheda non può visualizzare il testo incorporato in un logo SVG, che quindi risulta vuoto. Per risolvere il problema, converti il testo in tracciati nel tuo strumento di progettazione ed esporta di nuovo l'SVG. In Figma, seleziona il testo e usa **Flatten**. In Illustrator, usa **Type > Create Outlines**. Se durante la build trova del testo nel logo SVG usato dalla scheda, viene mostrato un suggerimento. I loghi impostati con un URL completo (`https://...`) non vengono controllati.

Se il colore del brand non risalta abbastanza sulla scheda, il testo del badge usa il colore del testo normale. La barra mantiene il colore del brand, a meno che non sia quasi identico allo sfondo della scheda. In tal caso, la barra diventa grigia.

Per impostazione predefinita, Jamdesk sovrappone il titolo della pagina a `og:image`. Se l'immagine contiene già testo o un design, imposta `"customImage": "replace"` per mostrarla senza modifiche.

Se `og:image` viene usata come sfondo della scheda, scegli il `theme` più adatto: `dark` per un'immagine scura e `light` per una chiara.

In modalità `replace`, Jamdesk non sovrappone alcun titolo all'immagine. Se `seo.metatags` imposta `og:image`, tutte le pagine usano quell'immagine; una pagina che imposta un proprio `og:image` usa invece la propria. Solo le pagine senza nessuna di queste impostazioni ricevono una scheda generata. Usa un'immagine PNG o JPG da 1200×630. Alcune piattaforme non visualizzano immagini WebP o SVG.

I social network memorizzano nella cache le anteprime dei link: dopo aver modificato queste impostazioni, un link già condiviso potrebbe continuare a mostrare la vecchia scheda per un po'. Controlla la nuova scheda con lo strumento
[OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Le versioni precedenti della CLI Jamdesk rifiutano `seo.socialCard` e `seo.titleTemplate` in
`jamdesk validate` e `jamdesk dev`. Aggiorna con `npm i -g jamdesk@latest`.
</Note>

## Sitemap e robots.txt

Ogni sito Jamdesk genera automaticamente `sitemap.xml` e `robots.txt` a ogni build.

| File | Scopo |
|------|---------|
| `sitemap.xml` | Elenca tutte le pagine con le date di ultima modifica per i motori di ricerca |
| `robots.txt` | Consente l'accesso a tutti i crawler e indica loro dove trovare la sitemap |

### Dove trovarli

Gli URL dipendono dal fatto che la documentazione si trovi nel dominio principale o in un sottopercorso `/docs`:

<Tabs>
  <Tab title="Dominio principale">
    Se la documentazione si trova nella radice del dominio (ad es. `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Sottopercorso /docs">
    Se la documentazione si trova in `/docs` sul sito principale (come questo sito su `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Cosa contiene la sitemap

- Tutte le pagine pubblicate, tranne quelle con `noindex` o `hidden` nel frontmatter
- Le date di ultima modifica indicate nel frontmatter, se disponibili
- Frequenza di aggiornamento settimanale

### Escludere pagine dalla sitemap

Aggiungi `noindex` al frontmatter per escludere una pagina sia dalla sitemap sia dai motori di ricerca:

```yaml
---
title: Internal Notes
noindex: true
---
```

Anche le pagine con `hidden: true` vengono escluse automaticamente.

## Dati strutturati JSON-LD

Ogni pagina include automaticamente dati strutturati [schema.org](https://schema.org) in un tag `<script type="application/ld+json">` con due schemi:

- `WebSite`: nome del sito, URL e descrizione (da `docs.json`).
- `BreadcrumbList`: percorso di navigazione dalla Home alla pagina corrente, ricavato dalla configurazione `navigation`.

Non serve alcuna configurazione. I motori di ricerca li usano per mostrare risultati avanzati, come i percorsi di navigazione nei risultati di ricerca.

<Tip>
**Verifica il markup.** Incolla l'URL di una pagina nel [Test dei risultati avanzati di Google](https://search.google.com/test/rich-results) per verificare che i dati strutturati vengano rilevati.
</Tip>

## IndexNow

Dopo ogni build, Jamdesk invia automaticamente gli URL delle pagine modificate a [IndexNow](https://www.indexnow.org), per velocizzarne l'indicizzazione nei motori di ricerca. In questo modo Bing, Yandex e altri motori di ricerca aderenti vengono informati delle modifiche ai contenuti senza dover attendere il successivo ciclo di scansione.

- Si attiva dopo ogni build riuscita
- Invia solo le pagine effettivamente modificate
- Non è bloccante e non ritarda mai la build
- Non richiede configurazione

## Buone pratiche

Prima di pubblicare, verifica questi punti:

<Note>
**Checklist prima della pubblicazione**

- **Titoli univoci.** Ogni pagina ha un titolo descrittivo distinto, inferiore a 60 caratteri.
- **Descrizioni accurate.** Le descrizioni riassumono la pagina in 120-160 caratteri.
- **Titoli gerarchici.** I titoli seguono una gerarchia chiara: un H1, poi H2 → H3.
- **Link descrittivi.** I link interni usano un testo significativo, mai "fai clic qui".
- **Testo alternativo delle immagini.** Ogni immagine ha un testo alternativo per l'accessibilità e la ricerca per immagini.
- **Immagine social.** Imposta un `og:image` personalizzato per le pagine importanti oppure usa la scheda generata automaticamente. Verifica il risultato con lo strumento [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
