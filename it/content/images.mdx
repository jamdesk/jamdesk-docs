Jamdesk visualizza le immagini con angoli arrotondati e spaziatura uniforme. Aggiungi i file alla directory `/images` e inseriscili usando la sintassi Markdown standard.

Gli screenshot mostrano l'interfaccia in inglese.

## Markdown standard

Usa la consueta sintassi `![alt](path)`:

```markdown
![API response showing user data in JSON format](/images/tabs-preview.webp)
```

![Risposta API con dati utente in formato JSON](/images/tabs-preview.webp)

I percorsi partono dalla radice del progetto. Un'immagine in `your-docs/images/screenshot.webp` si richiama con `/images/screenshot.webp`.

## Dimensioni delle immagini

Aggiungi `=LARGHEZZAxALTEZZA` dopo l'URL dell'immagine, separandolo con uno spazio, per controllarne le dimensioni:

```markdown
![Dashboard overview](/images/tabs-preview.webp =400x300)
```

Imposta una sola dimensione e l'altra verrà ridimensionata proporzionalmente:

```markdown
![Wide banner](/images/tabs-preview.webp =800x)
![Tall graphic](/images/tabs-preview.webp =x200)
```

È utile quando vuoi visualizzare una colonna uniforme di screenshot della stessa larghezza o ridurre un'immagine ad alta risoluzione a dimensioni adeguate.

## Didascalie

Racchiudi un'immagine nel componente `<Frame>` per aggiungere un bordo e una didascalia sotto di essa:

```mdx
<Frame caption="Dashboard overview showing project statistics">
  ![Dashboard](/images/tabs-preview.webp)
</Frame>
```

<Frame caption="Esempio di immagine incorniciata con didascalia">
  ![Jamdesk](/images/jd-blueprint-transparent.webp)

</Frame>

`Frame` disegna un bordo discreto intorno all'immagine e posiziona la didascalia sotto di essa. Puoi inserirvi qualsiasi contenuto, non solo immagini.

## Clic per ingrandire

Sugli schermi larghi almeno 768 px, le immagini si aprono a schermo intero quando fai clic. Premi Escape o fai clic in un punto qualsiasi per chiudere l'immagine ingrandita.

Per impedire lo zoom di un'immagine, aggiungi `noZoom` a un tag `<img>`:

```mdx
<img src="/images/diagram.png" alt="Architecture diagram" noZoom />
```

Le immagini Markdown (`![alt](src)`) non supportano attributi, quindi non possono disattivare lo zoom. Se ti serve `noZoom`, usa un tag `<img>`.

## Modalità chiara e scura

I siti di documentazione spesso richiedono varianti delle immagini per ogni combinazione di colori: un logo su sfondo bianco, ad esempio, non ha un buon aspetto in modalità scura.

### L'attributo `srcDark`

È l'approccio più semplice. Jamdesk cambia la sorgente dell'immagine in base al tema attivo:

```mdx
<img
  src="/images/logo-light.webp"
  srcDark="/images/logo-dark.webp"
  alt="Company logo"
/>
```

Il browser carica solo l'immagine corrispondente alla combinazione di colori corrente.

### L'elemento HTML `<picture>`

Se ti serve HTML standard utilizzabile anche al di fuori di Jamdesk, usa `<picture>` con una media query:

```mdx
<picture>
  <source srcset="/images/logo-dark.webp" media="(prefers-color-scheme: dark)" />
  <img src="/images/logo-light.webp" alt="Company logo" />
</picture>
```

L'approccio `<picture>` rispetta l'impostazione della combinazione di colori del sistema operativo. L'attributo `srcDark`, invece, reagisce all'interruttore del tema di Jamdesk: di solito è la scelta più adatta per la documentazione.

## Formati supportati

| Formato | Ideale per | Note |
|--------|----------|-------|
| PNG | Screenshot, acquisizioni dell'interfaccia | Qualità senza perdita, supporta la trasparenza. File più grandi. |
| JPEG | Fotografie | Buona compressione, non supporta la trasparenza. |
| SVG | Icone, diagrammi, loghi | Formato vettoriale che si adatta a qualsiasi dimensione senza perdita di qualità. File molto piccoli. |
| GIF | Animazioni semplici | Le dimensioni possono aumentare rapidamente. Per sequenze di più di pochi fotogrammi, valuta brevi loop `.mp4`. |
| WebP | Uso generico | Più leggero di PNG e JPEG a qualità comparabile. Compatibile con tutti i browser moderni. |

<Tip>
Per la maggior parte delle immagini della documentazione, WebP offre il miglior rapporto tra dimensioni e qualità. Se ti serve la trasparenza, anche WebP la supporta, quindi non è necessario usare PNG.
</Tip>

## Buone pratiche

<AccordionGroup>
  <Accordion title="Scrivi testo alternativo descrittivo" icon="universal-access">
    Il testo alternativo ha due funzioni: viene letto dagli screen reader per l'accessibilità e compare come segnaposto se l'immagine non si carica. Descrivi ciò che l'immagine mostra davvero.

    ```markdown
    {/* Good -- says what's in the image */}
    ![API response showing user data in JSON format](/images/tabs-preview.webp)

    {/* Bad -- tells you nothing */}
    ![Screenshot](/images/tabs-preview.webp)
    ```

    Per le immagini decorative che non aggiungono informazioni, come motivi di sfondo e separatori, usa un testo alternativo vuoto: `![](/images/decoration.webp)`.
  </Accordion>

  <Accordion title="Mantieni ridotte le dimensioni dei file" icon="gauge-high">
    Le immagini pesanti rallentano il caricamento delle pagine, soprattutto con connessioni mobili. Punta a queste dimensioni:

    - **Screenshot/interfaccia:** PNG o WebP, meno di 500KB
    - **Foto:** JPEG o WebP, meno di 200KB
    - **Icone e diagrammi:** SVG, quando possibile

    [Squoosh](https://squoosh.app) e [TinyPNG](https://tinypng.com) comprimono le immagini senza perdite di qualità visibili. Prima di eseguire il commit, comprimi gli screenshot con uno di questi strumenti.

    Oppure lascia che se ne occupi Jamdesk durante la build. Attiva la [conversione automatica in WebP](/it/builds/image-optimization) nel tuo `docs.json`: a ogni build, i file PNG o JPG che aggiungi verranno ottimizzati.
  </Accordion>

  <Accordion title="Usa dimensioni uniformi" icon="ruler-combined">
    Gli screenshot con larghezze diverse risultano disordinati. Scegli una larghezza standard per le acquisizioni (1200 px è una buona misura) e usala in tutta la documentazione. Jamdesk ridimensiona automaticamente le immagini per adattarle all'area dei contenuti: dimensioni sorgente uniformi producono quindi risultati uniformi.
  </Accordion>

  <Accordion title="Controlla l'immagine per la condivisione social" icon="share-nodes">
    Jamdesk genera automaticamente una scheda social personalizzata da 1200×630 per ogni pagina. Puoi sostituirla per una singola pagina con `og:image` nel frontmatter. Dopo una build, inserisci l'URL della pagina nello strumento gratuito [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) per vedere come appare la scheda su X, Facebook, LinkedIn, Slack, Discord e altre piattaforme. Per la configurazione completa, consulta [Ottimizzazione SEO](/it/content/seo).
  </Accordion>
</AccordionGroup>

## Organizzazione dei file

Raggruppa le immagini in sottodirectory che rispecchiano la struttura dei contenuti. In questo modo sarà più facile trovarle man mano che la documentazione cresce:

```bash
your-docs/
├── images/
│   ├── getting-started/
│   │   ├── step-1.png
│   │   └── step-2.png
│   ├── api/
│   │   └── response.png
│   └── logo.svg
└── docs.json
```

Richiamale usando il percorso completo dalla radice del progetto:

```markdown
![GitHub repository access](/images/getting-started/step-1.png)
```

<Warning>
Evita gli spazi nei nomi dei file immagine. Usa i trattini: `api-response.webp`, non `api response.webp`.
</Warning>
