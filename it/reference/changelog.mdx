**Jamdesk traduce la documentazione in 27 lingue.** Seleziona le lingue desiderate, fino a cinque per progetto, in **Settings → Translations**: dopo ogni build, le pagine tradotte vengono salvate nel tuo repository GitHub. Le build successive ritraducono solo le pagine la cui origine inglese è cambiata. Le traduzioni già presenti o modificate manualmente vengono mantenute finché non fai clic su **Replace with AI translation**. Incluso in tutti i piani. [Traduzione AI →](/it/setup/ai-translation)

**Scegli l'URL della documentazione.** L'hosting su sottopercorso non è più legato a `/docs`. Inserisci un singolo segmento, come `help` o `guide`, nel campo del sottopercorso della scheda Custom Domain e salva. `/docs` continua a funzionare, i canonical vengono spostati immediatamente nel nuovo percorso e il precedente sottopercorso personalizzato reindirizza a quello nuovo per una singola modifica, così puoi aggiornare il proxy con i tuoi tempi. [Hosting su sottopercorso →](/it/deploy/subpath-hosting)

**Correggi con l'AI, ora più velocemente.** L'apertura dell'anteprima delle correzioni dal banner della build termina prima, anche sui siti più grandi, e riaprirla è quasi istantaneo perché Jamdesk conserva i risultati della scansione finché la documentazione non cambia. Il flusso è invariato: esamina ogni modifica proposta, applica quelle approvate e Jamdesk eseguirà il commit e una nuova build. [Correggi con l'AI →](/it/builds/fix-with-ai)

**Un quarto tema: Halo.** Imposta `"theme": "halo"` in `docs.json` per un aspetto caldo e arrotondato: carattere Figtree, sfondo color sabbia con il contenuto rialzato su una scheda e i raggi degli angoli più ampi tra tutti i temi integrati. Colori, caratteri e override CSS personalizzati funzionano come in Jam, Nebula e Pulsar. [Temi →](/it/customization/theming)

**Servi la documentazione solo dal tuo dominio.** Attiva **Custom domain only** nella scheda Custom Domain: una visita diretta a `YOUR_SLUG.jamdesk.app` restituisce 404, mentre CNAME o proxy continuano a funzionare. Jamdesk controlla il dominio attivo prima di attivare l'opzione; se il DNS si interrompe, il sottodominio torna a essere servito finché non viene ripristinato. Nasconde il sottodominio ai visitatori diretti, ma non controlla chi può leggere la documentazione: per questo, abbinalo alla protezione tramite password. [Solo dominio personalizzato →](/it/deploy/custom-domain-only)

**Genera l'intero riferimento API da una spec.** Collega una scheda di navigazione al tuo file OpenAPI con `"openapi": { "source": "/openapi/api.yaml", "generate": true }`: ogni build crea una pagina per operazione, raggruppata nella barra laterale per tag. Una pagina endpoint sottoposta a commit mantiene il proprio slug, così puoi effettuare la migrazione una pagina alla volta; un percorso rinominato reindirizza dal vecchio URL invece di restituire 404. [Pagine API generate →](/it/config/docs-json-reference#navigation-openapi-pagine-generate)

**I lettori scelgono il server API visualizzato.** Un endpoint la cui spec elenca più di una voce `servers` mostra un selettore accanto al relativo URL. Scegliendo sandbox cambiano l'URL di base, il pulsante di copia, ogni esempio di codice e la richiesta inviata dal playground, così nessuno copia un comando `curl` di produzione dalla documentazione sandbox. Gli endpoint con un solo server non cambiano. [API Playground →](/it/api-reference/playground#più-server)

**Markdown viene visualizzato in ogni descrizione OpenAPI.** Tabelle, elenchi, link, `code` e **grassetto** vengono visualizzati allo stesso modo nelle descrizioni dei parametri, del corpo della richiesta, della risposta e dello schema, proprio come già avveniva nella descrizione dell'operazione. Prima i nove punti non erano coerenti; ora condividono tutti lo stesso renderer. [Esempio OpenAPI →](/it/api-reference/openapi-example)

**Le esportazioni Markdown degli endpoint includono l'autenticazione.** Recupera la versione `.md` di una pagina di riferimento API: termina con una sezione `## Authentication` che elenca gli schemi richiesti dall'operazione, inclusi tipo, nome dell'header, formato bearer, ambiti OAuth 2 e combinazioni valide. Un agente che legge l'esportazione può creare una richiesta funzionante senza aprire la spec. [Sorgente Markdown →](/it/ai/markdown-source#cosa-esporta-una-pagina-endpoint)

**Escludi una pagina dalla ricerca senza nasconderla.** Aggiungi `search: false` al frontmatter di una pagina per rimuoverla dalla ricerca del sito, dalle risposte della chat AI e dal server MCP, mantenendola però nella barra laterale, nella sitemap e in llms.txt. Usalo per una pagina sostituita che vuoi mantenere accessibile tramite link e indicizzata. Anche le pagine nascoste e quelle con noindex vengono ora escluse dalle risposte AI. [Escludi una pagina solo dalla ricerca →](/it/content/hidden-pages#escludere-una-pagina-solo-dalla-ricerca)

**`jamdesk validate` segnala le configurazioni senza effetto.** Alcune chiavi di `docs.json` venivano accettate senza essere mai visualizzate, soprattutto `asyncapi`: la configurazione sembrava supportata finché, dopo la build del sito, non risultava assente. Il comando ora le identifica, insieme alle voci aggiuntive `api.mdx.server` oltre la prima, che sono sempre state scartate. [Panoramica CLI →](/it/cli/overview)

</Update>

**Modifica la documentazione direttamente nel dashboard.** L'editor web è ora disponibile per tutti e non richiede configurazione. Apri **Editor** nella barra laterale per sfogliare il repository collegato, modificare MDX con un'anteprima live ed eseguire il commit direttamente nel tuo branch GitHub, avviando automaticamente una build. [Editor web →](/it/development/web-editor)

**Correggi gli avvisi di build con l'AI dal dashboard.** Quando una build termina con link non validi o pagine prive di descrizione, sulla build compare un banner **Fix with AI** che mostra quanti problemi possono essere risolti. Aprilo per visualizzare l'anteprima di ogni modifica proposta, inclusi gli anchor riscritti e le descrizioni suggerite, quindi applica quelle approvate. Jamdesk esegue il commit nel tuo branch GitHub e avvia una nuova build. Tutto ciò che non può risolvere senza ambiguità viene elencato separatamente per la correzione manuale.

**Membri del team illimitati.** Ogni progetto ora include membri del team illimitati in tutti i piani, senza costi aggiuntivi. Il precedente limite di 10 membri e il prezzo per postazione sono stati eliminati: invita tutto il team.

**Consenti ai bot affidabili di pubblicare la documentazione.** Gli account di automazione come Dependabot, Renovate o un bot di pubblicazione del CMS non sono membri di Jamdesk, quindi per impostazione predefinita i loro push non avviano una build. Ora, quando uno di questi account viene rifiutato, la build mostra un pulsante **Authorize Bot Account** con un solo clic. Approvandolo, i push dell'account pubblicano sul sito attivo, proprio come quelli di un membro del team. Solo i membri del progetto possono autorizzare un account; puoi esaminare o revocare l'accesso in qualsiasi momento da **Allowed automation accounts** nelle impostazioni GitHub del progetto.

**La documentazione riceve un punteggio AI a ogni build.** Jamdesk valuta automaticamente, direttamente nel dashboard e dopo ogni build, quanto gli agenti AI riescono a leggere la documentazione pubblicata, sulla base dello standard AFDocs aperto. Visualizza il punteggio da 0 a 100 e la valutazione in lettere, osserva l'andamento tra le build e ricevi una correzione in linguaggio semplice per ogni problema, con un pulsante **Copy prompt to fix** che invia il risultato al tuo agente di programmazione AI. Attiva **Email team when score changes** per ricevere una notifica quando una build modifica in modo significativo il punteggio. [Punteggio AI →](/it/ai/ai-score)
</Update>

**Correggi automaticamente i link non validi.** Gli avvisi sui link interni non validi con una destinazione non ambigua, come anchor con errori di battitura e differenze tra anchor di lingue diverse, possono ora essere corretti con un solo comando. Esegui `jamdesk fix --dry-run` per visualizzare in anteprima le modifiche pianificate, quindi `jamdesk fix` per applicarle; vengono modificati solo gli avvisi in cui l'anchor corretto rimanda a un'intestazione reale, mentre i casi ambigui restano da esaminare manualmente. [Panoramica CLI →](/it/cli/overview)

**Annuncia qualsiasi cosa con un banner.** Aggiungi un `banner` a `docs.json` per fissare una barra di messaggio in cima a ogni pagina, sopra l'header e nel colore principale del tema. Usa link, **grassetto** e *corsivo* inline e imposta `dismissible: true` per fornire ai lettori un pulsante di chiusura, che mantiene il banner chiuso finché non modifichi il messaggio. [Banner →](/it/config/docs-json-reference#banner)

**Mostra quando ogni pagina è stata aggiornata.** Imposta `metadata.timestamp: true` in `docs.json` per aggiungere al piè di pagina di ogni pagina una riga come "Last updated on June 15, 2026". La data proviene dall'ultimo commit Git che ha modificato la pagina, quindi resta aggiornata a ogni build senza manutenzione manuale. [Metadati pagina →](/it/config/docs-json-reference#metadata)

**Personalizza lo stile delle icone di navigazione.** Le icone della barra laterale, dei gruppi, delle schede, degli anchor e della ricerca ora rispettano `style` in un oggetto icona (`{ "name": "rocket", "style": "duotone" }`) o un prefisso di stile (`duotone/rocket`): light, thin, duotone e la famiglia sharp, non solo solid. [Icone →](/it/content/icons#forma-a-oggetto-delle-icone)

**Personalizza la barra di ricerca.** Scegli il testo segnaposto con `search.prompt` e cura i link rapidi mostrati ai visitatori nel pannello di ricerca vuoto con `search.popularPages`, ciascuno con titolo, slug della pagina e icona Font Awesome. [Configurazione della ricerca →](/it/config/docs-json-reference#ricerca)

**Raccogli iscrizioni email senza embed.** Collega Resend, Mailchimp, Kit, Loops, beehiiv, Brevo o SendGrid da **Integrations → Email Signups**: un modulo ospitato da Jamdesk aggiunge i lettori direttamente al tuo pubblico, mentre la chiave API resta nel nostro backend e non viene mai pubblicata sul sito. Aggiungi il componente [`EmailSubscribe`](/it/components/email-subscribe) a qualsiasi pagina oppure imposta `placement: changelog` per inserire automaticamente un modulo di iscrizione in ogni pagina del changelog. [Iscrizioni email →](/it/integrations/email-signups)

**Proteggi le analisi con il consenso ai cookie.** Aggiungi la chiave `integrations.cookies` a `docs.json`: Jamdesk trattiene ogni script di analisi e monitoraggio, inclusi Google Analytics, GTM, Plausible, Crisp, JavaScript personalizzato e le proprie analisi integrate, finché il visitatore non presta il consenso, letto da un flag `localStorage` impostato dal banner. Puoi caricare un banner Osano o Termly direttamente da `docs.json`; un breve snippet di collegamento attiva il flag appena il lettore accetta e gli script vengono caricati senza ricaricare la pagina. [Consenso ai cookie →](/it/integrations/cookie-consent)

**llms.txt, in ordine.** Il file `llms.txt` di ogni sito segue ora la struttura di llmstxt.org: schede e gruppi di navigazione diventano sezioni `##`, così gli agenti AI vedono la documentazione organizzata come nella barra laterale. I siti multilingue ricevono un indice per lingua: il file principale elenca la lingua predefinita e collega ogni indice tradotto, ad esempio `/fr/llms.txt`, mantenendo ciascun file abbastanza piccolo da evitare il troncamento da parte degli agenti. [llms.txt →](/it/ai/llms-txt)

**Gli agenti trovano più rapidamente la documentazione.** Ogni pagina ora include una direttiva invisibile e silenziosa per gli screen reader che indirizza gli agenti AI verso `llms.txt` e la versione `.md` della pagina; ogni esportazione Markdown si apre inoltre con un blockquote che collega all'indice. Gli agenti che recuperano il tuo HTML non devono più dedurre l'esistenza di un percorso Markdown. [Panoramica AI →](/it/ai/overview)

**Incorpora il changelog ovunque.** Un launcher "What's new?" entra nella tua app con un solo tag `<script>` e apre il changelog Jamdesk in una finestra modale, con un indicatore dei contenuti non letti per visitatore. Genera lo snippet da **Integrations → What's New widget**, quindi regola modalità del launcher, angolo, dimensioni della finestra e colore dell'indicatore con attributi `data-`. Nella documentazione Jamdesk, il componente MDX [`<Widget>`](/it/components/widget) inserisce lo stesso launcher live in qualsiasi pagina con un solo tag e senza script. [Incorpora il changelog →](/it/development/embed-page)

**Scarica le spec API come archivio zip.** In qualsiasi pagina di riferimento API, il menu AI Actions ora include l'opzione **Download API spec**, che raccoglie in un unico `api-specs.zip` ogni spec OpenAPI utilizzata dal sito, sia da file locali sia da URL remoti. Le spec composte da più file mantengono la struttura delle cartelle `$ref`, così il download può essere importato direttamente in Postman, in un generatore di client o nei tuoi strumenti. [AI Actions →](/it/ai/ai-actions)

**Spec OpenAPI validate durante la build.** Ogni deploy ora valida rigorosamente le spec OpenAPI a cui fa riferimento `docs.json` e presenta qualsiasi problema come **non-fatal build warning**, invece di interrompere la build. La documentazione viene comunque pubblicata; ricevi solo un'indicazione precisa dell'errore, come un errore di parsing YAML con riga e colonna, un `$ref` non risolto o un `operationId` duplicato, via email e nell'elenco delle build del dashboard. In locale, `jamdesk dev` continua a interrompersi in presenza di una spec non valida, così puoi correggerla prima del push. [Panoramica CLI →](/it/cli/overview)
</Update>

**Chiedi all'AI direttamente dalla ricerca.** Inizia a digitare nella ricerca, quindi invia la domanda alla chat AI invece di aprire un risultato: premi ⌘/Ctrl+Enter oppure fai clic su **Ask AI** nel piè di pagina della ricerca. La domanda viene aggiunta alla conversazione, così puoi continuare lo stesso thread; Enter continua ad aprire il primo risultato. [Chat AI →](/it/ai/chat)

**Copia risposte e trascrizioni.** Ogni risposta della chat AI include un pulsante di copia che recupera la sorgente Markdown; l'azione **Copy transcript** nell'header della chat copia l'intera conversazione come Markdown con ruoli identificati, utile per incollarla in un issue o in un documento. [Chat AI →](/it/ai/chat)

**Scorrimento automatico della chat più intelligente.** La chat segue una risposta in streaming solo quando ti trovi già in fondo. Scorri verso l'alto per rileggere una risposta precedente e la posizione resta ferma invece di riportarti in basso; torna in fondo e lo scorrimento viene nuovamente agganciato.

**CSS personalizzato nell'anteprima locale (CLI).** `jamdesk dev` applica il CSS personalizzato come la build pubblicata, così puoi verificare lo stile prima del deploy. Inserisci un qualsiasi file `.css` nella root del progetto, `style.css` o più file combinati in ordine alfabetico, e verrà caricato al refresh del browser. Non è necessaria alcuna voce in `docs.json`, in linea con il modo in cui Mintlify include i fogli di stile nella root. [CSS personalizzato →](/it/customization/custom-css)

**Anteprime social personalizzate dal frontmatter.** Imposta qualsiasi meta tag Open Graph o Twitter/X direttamente nel frontmatter di una pagina: `og:title`, `og:description`, `og:image`, `twitter:card`, `keywords` e l'intero set di metatag. Usa chiavi piatte di primo livello o un blocco `seo:` annidato; entrambi funzionano e i valori per pagina hanno la precedenza sulle impostazioni predefinite di `docs.json`. [SEO →](/it/content/seo)

**Pagine nascoste.** Mantieni bozze, manuali interni o guide obsolete fuori dalla barra laterale e dai risultati di ricerca senza eliminarli. Aggiungi `hidden: true` al frontmatter di una pagina oppure a un gruppo o a una scheda in `docs.json`. Le pagine nascoste restano raggiungibili tramite URL diretto, ma scompaiono dalla navigazione, dalla sitemap, dalla ricerca del sito e dal contesto AI, oltre a ricevere automaticamente un tag `noindex`. Ti serve un gruppo nascosto le cui pagine continuino a comparire nella ricerca? Aggiungi `searchable: true` insieme a `hidden`. [Pagine nascoste →](/it/content/hidden-pages)

**Decorazioni a griglia e finestre.** Due nuovi motivi di sfondo si aggiungono al gradiente predefinito del tema Jam. Imposta `background.decoration` su `"grid"` per una sottile griglia di punti da 24px oppure su `"windows"` per due macchie effetto vetro smerigliato, nello stile di Windows 11, negli angoli superiori. Il gradiente e il riempimento uniforme `"none"` continuano a funzionare come prima: scegli l'aspetto più adatto al tuo brand. [Sfondo →](/it/customization/background)

**Personalizzazione dello sfondo.** Un nuovo blocco `background` in `docs.json` disabilita il gradiente della modalità chiara di Jam, sostituisce il colore della pagina per modalità o regola colore, dimensioni, posizione e opacità del gradiente. Non è necessario CSS personalizzato. [Sfondo →](/it/customization/background)

**Diagrammi D2.** Un secondo linguaggio per diagrammi affianca Mermaid. Contrassegna un blocco di codice delimitato con `d2` e Jamdesk lo renderizza come SVG durante la build, con temi chiaro e scuro integrati. Il flusso è uguale a quello di Mermaid: scegli il linguaggio più adatto al diagramma che stai creando. [Diagrammi D2 →](/it/components/d2)

**Risultati di ricerca raggruppati.** La ricerca non ripete più la stessa pagina per ogni corrispondenza di sezione. I risultati vengono raggruppati nella pagina principale all'interno della finestra di ricerca, con fino a tre sezioni visibili per impostazione predefinita e un espansore inline per le altre. L'evidenziazione degli snippet resta invariata: trovi la sezione corretta con meno scansioni.

**Rilevamento automatico di `docs.json` durante il collegamento.** Quando colleghi un repository GitHub, il sistema trova `docs.json` ovunque si trovi. Il flusso di collegamento analizza l'intero albero e segnala un `mint.json` di Mintlify se ne trova uno. Monorepo e configurazioni annidate funzionano senza configurazione manuale. [Collega GitHub →](/it/setup/connecting-github)

**Indicazioni sulla posizione di `docs.json` nella CLI.** È più semplice individuare le configurazioni fuori posto. `jamdesk validate`, `jamdesk dev` e `jamdesk doctor` indicano dove si trova realmente `docs.json`, o dove dovrebbe trovarsi, invece di mostrare un generico errore "not found". Correggi il problema in pochi secondi senza dover interpretare uno stack trace. [Panoramica CLI →](/it/cli/overview)

**Hreflang conforme agli standard.** I tag hreflang ora generano codici BCP 47 validi. Cartelle locali come `cn`, `jp` e `ja-jp` vengono associate ai codici attesi dai motori di ricerca (`zh`, `ja`), con URL della sitemap sottoposti a escape XML. Ogni pagina localizzata si posiziona nella propria area invece di essere trattata come contenuto duplicato. [Lingue →](/it/setup/languages)

**Esportazione PDF.** Esegui il rendering dell'intero sito della documentazione in un unico [PDF](/it/builds/pdf-export) da **Settings → PDF Exports** nel dashboard. Disponibile solo nei piani a pagamento. I progetti multilingue consentono di scegliere una lingua per esportazione; i risultati vengono memorizzati nella cache per commit e ricevi un'email con il link al download al termine del rendering.

**Spec OpenAPI multilingue.** Le pagine endpoint visualizzano le spec OpenAPI tradotte insieme all'MDX tradotto. Inserisci un file `<spec>.<lang>.<ext>` (ad esempio `openapi/api.fr.yaml`) accanto alla spec di origine: Jamdesk lo utilizza negli URL di quella lingua e ricorre alla spec inglese quando manca una variante linguistica. Sommari delle operazioni, descrizioni dei parametri, descrizioni delle risposte e descrizioni degli schemi vengono tutti localizzati. Configurazione: [Traduzione delle spec OpenAPI](/it/setup/languages#traduzione-delle-specifiche-openapi).

**Componente Visibility.** Il nuovo componente [`<Visibility for="humans|agents">`](/it/components/visibility) consente di separare i contenuti per lettori umani o agenti AI nella stessa pagina. I blocchi riservati agli umani vengono visualizzati nel browser ma rimossi dalle esportazioni `.md` e da `llms-full.txt`; quelli riservati agli agenti fanno l'opposto. Gli agenti che richiedono `Accept: text/markdown` sugli URL canonical ricevono automaticamente la vista per agenti.

**Protezione tramite password, ricostruita.** Blocca l'intero sito con una password condivisa oppure proteggi solo alcune pagine lasciando pubbliche le altre. Imposta `auth.password.enabled: true` per la modalità dell'intero sito oppure contrassegna singole pagine con `private: true` nel frontmatter, o elencale in `auth.password.private`, per la modalità dedicata a pagine specifiche. La pagina Settings del dashboard guida nella configurazione, nella rotazione e nella revoca della password. I visitatori vedono una schermata di sblocco con il logo del sito, il colore principale e un suggerimento opzionale definito in `docs.json`. Guida alla configurazione: [Protezione tramite password](/it/setup/password-protection).

**Conversione automatica delle immagini in WebP.** Jamdesk può convertire le immagini PNG e JPG in WebP durante la build. I file convertiti sono generalmente più piccoli del 60-80% rispetto agli originali, senza perdita visibile di qualità, così le pagine si caricano più velocemente senza elaborazione manuale. Attiva la funzione con `images.convertToWebp: true` in `docs.json`. Favicon, `og:image` e `twitter:image` mantengono il formato originale per la compatibilità con i crawler social. Un nuovo passaggio **Optimizing images** mostra l'avanzamento in tempo reale nel dashboard e nella CLI durante ogni build. [Conversione automatica delle immagini →](/it/builds/image-optimization)

**API Playground.** Le pagine endpoint ora includono un pulsante interattivo ["Try it"](/it/api-reference/playground). Compila i parametri, osserva gli esempi di codice aggiornarsi in tempo reale e invia richieste live senza uscire dalla documentazione. Attivo per impostazione predefinita in tutte le pagine API. Funziona sia con endpoint OpenAPI sia con endpoint creati in MDX.

**Plugin Claude Code.** Installa il [plugin Jamdesk per Claude Code](/it/claude-code-plugin) per fornire a Claude una conoscenza approfondita dei componenti MDX, della configurazione `docs.json`, dei modelli di navigazione e dei comandi CLI. Installazione in due passaggi dal marketplace dei plugin. Si integra con [CLAUDE.md](/it/ai/claude-code) e il [server MCP](/it/ai/mcp-server) per la scrittura assistita della documentazione.

**Avvisi di build per branding mancante.** Le build ora avvisano quando i percorsi `favicon` o `logo` in `docs.json` fanno riferimento a file inesistenti nel progetto. Gli avvisi compaiono nei dettagli della build del dashboard e nella CLI tramite `jamdesk dev` e `jamdesk validate`. Non viene inviata alcuna email: l'avviso è solo informativo.

**YouTube Shorts.** Il [componente `<YouTube>`](/it/content/youtube#youtube-shorts) supporta gli Shorts verticali tramite la prop `short`, visualizzando un player centrato in formato 9:16 senza barre nere. Usa `<YouTube id="VIDEO_ID" short />`.

**Menu AI Actions.** Un [menu a discesa su ogni pagina](/it/ai/ai-actions) consente ai lettori di copiare Markdown, aprire la pagina in ChatGPT/Claude/Perplexity, recuperare la configurazione del server MCP o installarla con un clic in Cursor o VS Code. Attivo per impostazione predefinita; scegli quali opzioni mostrare tramite `contextual` in `docs.json`.

**Analisi.** Analisi delle pagine senza cookie per monitorare visualizzazioni, fonti di traffico e tendenze dei visitatori, con [suddivisione per pagina](/it/setup/project-analytics). Non è necessario alcun banner di consenso. Panoramica: [Analisi](/it/setup/analytics-overview).

**Integrazioni.** [Google Analytics 4](/it/integrations/google-analytics), [Google Tag Manager](/it/integrations/google-tag-manager), [Plausible Analytics](/it/integrations/plausible-analytics) e [notifiche di build Slack](/it/integrations/slack) (Pro).

**Feed RSS per i changelog.** Le pagine con `rss: true` nel frontmatter ora generano automaticamente un feed RSS sottoscrivibile. Un'icona RSS compare accanto al titolo della pagina e un `feed.xml` viene creato dai componenti [Update](/it/components/update#feed-rss) durante ogni build. Usa la nuova prop `date` su Update per date corrette nel feed.

**Accesso e deploy dalla CLI.** [`jamdesk login`](/it/cli/authentication) esegue l'autenticazione tramite browser. [`jamdesk deploy`](/it/cli/deploy) impacchetta il progetto e avvia una build dal terminale. Non è necessaria una connessione GitHub. La CLI rispetta `.gitignore`, avvisa della presenza di file segreti e trasmette l'avanzamento della build inline.

**Controllo ortografico CLI.** `jamdesk spellcheck` verifica gli errori ortografici nella documentazione con oltre 180 termini tecnici integrati, solo in inglese. `jamdesk spellcheck --fix` avvia una modalità interattiva per correggere gli errori o aggiungere parole all'elenco di esclusione.

**Incorporamenti video.** Incorpora direttamente nella documentazione file `.mp4` e `.webm`. Inseriscili in una directory `/videos` e usa la sintassi Markdown (`![Demo](/videos/demo.mp4)`) oppure il [componente `<Video>`](/it/content/videos) per riproduzione automatica, loop e altri controlli.

**JavaScript personalizzato.** Aggiungi [script lato client](/it/customization/custom-javascript) per widget di chat, analisi o integrazioni di terze parti tramite `styling.js` in `docs.json`.
