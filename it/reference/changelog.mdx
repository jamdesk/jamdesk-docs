<Update label="Settembre 2026" date="2026-09-14">
**Fai accedere i lettori con il loro login.** L'autenticazione JWT protegge un sito di documentazione con il sistema di accesso che già utilizzi, così nessuno deve digitare una password condivisa. Attiva `auth.jwt` in `docs.json`, genera una chiave di firma Ed25519 in **Settings** e configura il backend affinché firmi un token a breve durata quando un utente apre la documentazione. Jamdesk lo verifica e avvia una sessione per utente della durata massima di 30 giorni. Aggiungi `groups: ["admin"]` a una pagina: solo i visitatori il cui token contiene quel gruppo potranno aprirla o visualizzarla nella barra laterale; per tutti gli altri restituirà un 404. I percorsi pubblici, `public: true` nel frontmatter e i gruppi di navigazione pubblici mantengono accessibile un changelog o una pagina di stato. Puoi anche precompilare il playground API con le credenziali del visitatore ricavate dal token. Incluso in ogni piano, consente di passare dalla protezione con password senza interruzioni. [Autenticazione JWT →](/it/setup/jwt-authentication)

**La radice del sito esporta anche Markdown.** Recupera la radice della documentazione, oppure una radice linguistica come `/fr`, con `Accept: text/markdown` o come `/index.md`: otterrai la prima pagina di quella navigazione, la stessa mostrata dalla radice HTML. In precedenza, i siti senza `index.mdx` restituivano qui un 404, interrompendo la prima richiesta effettuata dalla maggior parte degli agenti. [Sorgente Markdown →](/it/ai/markdown-source#radice-del-sito-e-radici-delle-lingue)
</Update>

**Jamdesk traduce la documentazione in 27 lingue.** Seleziona le lingue desiderate, fino a cinque per progetto, in **Settings → Translations**: dopo ogni build, le pagine tradotte vengono salvate nel tuo repository GitHub. Le build successive ritraducono solo le pagine la cui sorgente inglese è cambiata. Le traduzioni già esistenti o modificate manualmente vengono mantenute finché non fai clic su **Replace with AI translation**. Incluso in ogni piano. [Traduzione AI →](/it/setup/ai-translation)

**Scegli l'URL della documentazione.** L'hosting in sottopercorso non è più vincolato a `/docs`. Inserisci un singolo segmento, come `help` o `guide`, nel campo del sottopercorso nella scheda Custom Domain e salva. `/docs` continua a funzionare, gli URL canonici passano subito al nuovo percorso e il sottopercorso personalizzato precedente reindirizza al nuovo per una singola ridenominazione, così puoi aggiornare il proxy con i tuoi tempi. [Hosting in sottopercorso →](/it/deploy/subpath-hosting)

**Correggi con l'AI, più velocemente.** L'apertura dell'anteprima della correzione dal banner della build ora termina prima, anche sui siti grandi, e riaprirla è quasi istantaneo perché Jamdesk conserva i risultati della scansione finché la documentazione non cambia. Il flusso non cambia: esamina ogni modifica proposta, applica quelle approvate e Jamdesk le salva con un commit ed esegue una nuova build. [Correggi con l'AI →](/it/builds/fix-with-ai)

**Un quarto tema: Halo.** Imposta `"theme": "halo"` in `docs.json` per un aspetto caldo e arrotondato: carattere Figtree, sfondo color sabbia con il contenuto sollevato su una scheda e i raggi degli angoli più ampi tra tutti i temi integrati. Colori, caratteri e override CSS personalizzati funzionano come in Jam, Nebula e Pulsar. [Temi →](/it/customization/theming)

**Servi la documentazione solo dal tuo dominio.** Attiva **Custom domain only** nella scheda Custom Domain: una visita diretta a `YOUR_SLUG.jamdesk.app` restituirà 404, mentre il tuo CNAME o proxy continuerà a funzionare. Jamdesk verifica il dominio attivo prima di abilitare l'opzione; se il DNS si interrompe, il sottodominio tornerà a essere servito finché non sarà ripristinato. Questa opzione nasconde il sottodominio ai visitatori diretti, ma non controlla chi può leggere la documentazione: per questo, abbinala alla protezione con password. [Solo dominio personalizzato →](/it/deploy/custom-domain-only)

**Genera l'intero riferimento API da una specifica.** Collega una scheda di navigazione al tuo file OpenAPI con `"openapi": { "source": "/openapi/api.yaml", "generate": true }`: ogni build crea una pagina per operazione, raggruppata nella barra laterale per tag. Una pagina endpoint salvata mantiene il proprio slug, così puoi effettuare il passaggio una pagina alla volta; un percorso rinominato reindirizza dal vecchio URL invece di restituire 404. [Pagine API generate →](/it/config/docs-json-reference#navigation-openapi-pagine-generate)

**I lettori scelgono il server API da visualizzare.** Un endpoint la cui specifica elenca più di una voce `servers` mostra un selettore accanto al relativo URL. Scegliendo il sandbox cambiano l'URL di base, il pulsante di copia, ogni esempio di codice e la richiesta inviata dal playground, così nessuno copia un comando `curl` di produzione dalla documentazione sandbox. Gli endpoint con un solo server non cambiano. [Playground API →](/it/api-reference/playground#più-server)

**Il Markdown viene visualizzato in ogni descrizione OpenAPI.** Tabelle, elenchi, link, `code` e **grassetto** vengono visualizzati allo stesso modo nelle descrizioni dei parametri, dei corpi delle richieste, delle risposte e degli schemi, come già avveniva nella descrizione dell'operazione. Prima c'erano nove punti con comportamenti diversi; ora usano tutti lo stesso renderer. [Esempio OpenAPI →](/it/api-reference/openapi-example)

**Le esportazioni Markdown degli endpoint includono l'autenticazione.** Recupera la versione `.md` di una pagina di riferimento API: terminerà con una sezione `## Authentication` che elenca gli schemi richiesti dall'operazione: tipo, nome dell'header, formato bearer, ambiti OAuth 2 e combinazioni valide. Un agente che legge l'esportazione può creare una richiesta funzionante senza aprire la specifica. [Sorgente Markdown →](/it/ai/markdown-source#cosa-esporta-una-pagina-endpoint)

**Escludi una pagina dalla ricerca senza nasconderla.** Aggiungi `search: false` al frontmatter di una pagina per rimuoverla dalla ricerca del sito, dalle risposte della chat AI e dal server MCP, mantenendola però nella barra laterale, nella sitemap e in llms.txt. Usala per una pagina superata che vuoi comunque rendere collegabile e indicizzabile. Le pagine nascoste e quelle escluse dall'indicizzazione vengono inoltre omesse dalle risposte AI, cosa che prima non avveniva. [Escludi una pagina solo dalla ricerca →](/it/content/hidden-pages#escludere-una-pagina-solo-dalla-ricerca)

**`jamdesk validate` segnala le configurazioni senza effetto.** Alcune chiavi di `docs.json` venivano accettate senza essere mai visualizzate, soprattutto `asyncapi`, quindi la configurazione sembrava supportata finché la build non mostrava che non produceva nulla. Il comando le indica, insieme alle voci aggiuntive `api.mdx.server` oltre la prima, che sono sempre state ignorate. [Panoramica CLI →](/it/cli/overview)

**Modifica la documentazione direttamente nel dashboard.** L'editor web è ora disponibile per tutti e non richiede configurazione. **Correggi gli avvisi di build con l'AI dal dashboard.** Quando una build termina con link non validi o pagine senza descrizione, nella build appare un banner **Fix with AI** che mostra quanti problemi possono essere risolti. Aprilo per visualizzare in anteprima ogni modifica proposta, inclusi gli anchor riscritti e le descrizioni suggerite, quindi applica quelle approvate. Jamdesk le salva con un commit nel branch GitHub e avvia una nuova build. Tutto ciò che non può risolvere senza ambiguità viene elencato separatamente per la correzione manuale.

**Membri del team illimitati.** Ogni progetto ora include membri del team illimitati in tutti i piani, senza costi aggiuntivi. Il precedente limite di 10 membri e il prezzo per postazione sono stati eliminati: invita l'intero team.

**Consenti ai bot autorizzati di pubblicare la documentazione.** Gli account di automazione come Dependabot, Renovate o un bot che pubblica da un CMS non sono membri di Jamdesk, quindi per impostazione predefinita i loro push non avviano una build. Ora, quando uno viene rifiutato, la build mostra un pulsante **Authorize Bot Account** con un solo clic. Approvandolo, i push di quell'account pubblicheranno sul sito live, proprio come quelli di un membro del team. Solo i membri del progetto possono autorizzare un account; puoi esaminare o revocare l'accesso in qualsiasi momento in **Allowed automation accounts**, nelle impostazioni GitHub del progetto.

**La documentazione riceve un AI Score a ogni build.** Jamdesk valuta ora automaticamente, direttamente nel dashboard dopo ogni build, quanto gli agenti AI riescano a leggere la documentazione pubblicata, secondo lo standard AFDocs aperto. Visualizza il punteggio da 0 a 100 e la valutazione alfabetica, osserva l'andamento tra le build e ricevi una correzione in linguaggio semplice per ogni problema, con un pulsante **Copy prompt to fix** che invia il risultato al tuo agente di programmazione AI. Attiva **Email team when score changes** per ricevere una notifica quando una build modifica significativamente il punteggio. [AI Score →](/it/ai/ai-score)

**Correggi automaticamente i link non validi.** Gli avvisi sui link interni non validi con una destinazione non ambigua, come anchor con errori di battitura e deriva degli anchor tra le lingue, possono ora essere corretti con un solo comando. Esegui `jamdesk fix --dry-run` per visualizzare in anteprima le modifiche pianificate, quindi `jamdesk fix` per applicarle; vengono modificati solo gli avvisi in cui l'anchor corretto rimanda a un'intestazione reale, mentre i casi ambigui restano da esaminare manualmente. [Panoramica CLI →](/it/cli/overview)

**Annuncia qualsiasi cosa con un banner.** Aggiungi un `banner` a `docs.json` per fissare una barra di messaggio nella parte superiore di ogni pagina, sopra l'header e nel colore principale del tema. Usa link, **grassetto** e *corsivo* inline e imposta `dismissible: true` per offrire ai lettori un pulsante di chiusura, che resta chiuso finché non modifichi il messaggio. [Banner →](/it/config/docs-json-reference#banner)

**Mostra l'ultimo aggiornamento di ogni pagina.** Imposta `metadata.timestamp: true` in `docs.json` per aggiungere al piè di pagina di ogni pagina una riga come "Last updated on June 15, 2026". La data deriva dall'ultimo commit Git che ha modificato la pagina, quindi resta aggiornata a ogni build senza manutenzione manuale. [Metadati della pagina →](/it/config/docs-json-reference#metadata)

**Personalizza le icone di navigazione.** Le icone della barra laterale, dei gruppi, delle schede, degli anchor e della ricerca ora rispettano `style` in un oggetto icona (`{ "name": "rocket", "style": "duotone" }`) o un prefisso di stile (`duotone/rocket`): light, thin, duotone e la famiglia sharp, non solo solid. [Icone →](/it/content/icons#forma-a-oggetto-delle-icone)

**Personalizza la barra di ricerca.** Scegli il testo segnaposto con `search.prompt` e seleziona i link rapidi mostrati ai visitatori nel pannello di ricerca vuoto con `search.popularPages`, ciascuno con un titolo, uno slug di pagina e un'icona Font Awesome. [Configurazione della ricerca →](/it/config/docs-json-reference#ricerca)

**Raccogli iscrizioni email senza incorporamenti.** Collega Resend, Mailchimp, Kit, Loops, beehiiv, Brevo o SendGrid in **Integrations → Email Signups**: un modulo ospitato da Jamdesk aggiungerà i lettori direttamente al tuo pubblico, mentre la chiave API resterà nel nostro backend e non finirà mai nel sito pubblicato. Aggiungi il componente [`EmailSubscribe`](/it/components/email-subscribe) a qualsiasi pagina oppure imposta `placement: changelog` per inserire automaticamente una casella di iscrizione in ogni pagina del changelog. [Iscrizioni email →](/it/integrations/email-signups)

**Proteggi le analisi con il consenso ai cookie.** Aggiungi la chiave `integrations.cookies` a `docs.json`: Jamdesk blocca ogni script di analisi e tracciamento, inclusi Google Analytics, GTM, Plausible, Crisp, JavaScript personalizzato e le proprie analisi integrate, finché il visitatore non presta il consenso, letto da un flag `localStorage` impostato dal banner. Puoi caricare un banner Osano o Termly direttamente da `docs.json`; un breve snippet di collegamento attiva il flag nel momento in cui il lettore accetta e gli script vengono caricati senza ricaricare la pagina. [Consenso ai cookie →](/it/integrations/cookie-consent)

**llms.txt, organizzato.** Il file `llms.txt` di ogni sito ora segue la struttura di llmstxt.org: le schede e i gruppi di navigazione diventano sezioni `##`, così gli agenti AI vedono la documentazione nell'ordine della barra laterale. I siti multilingue ricevono un indice per lingua: il file radice elenca la lingua predefinita e collega ogni indice tradotto, ad esempio `/fr/llms.txt`, mantenendo ciascuno abbastanza piccolo da evitare il troncamento da parte degli agenti. [llms.txt →](/it/ai/llms-txt)

**Gli agenti trovano più rapidamente la documentazione.** Ogni pagina ora include una direttiva invisibile e silenziosa per gli screen reader che indirizza gli agenti AI a `llms.txt` e alla versione `.md` della pagina; ogni esportazione Markdown inizia inoltre con un blockquote che collega l'indice. Gli agenti che recuperano l'HTML non devono più intuire l'esistenza di un percorso Markdown. [Panoramica AI →](/it/ai/overview)

**Incorpora il changelog ovunque.** Un launcher "What's new?" entra nella tua app con un solo tag `<script>` e apre il changelog Jamdesk in una finestra modale, con un indicatore dei contenuti non letti per visitatore. Genera lo snippet da **Integrations → What's New widget**, quindi regola modalità del launcher, angolo, dimensioni della finestra e colore dell'indicatore con gli attributi `data-`. Nella documentazione Jamdesk, il componente MDX [`<Widget>`](/it/components/widget) inserisce lo stesso launcher live in qualsiasi pagina con un singolo tag e senza script. [Incorpora il changelog →](/it/development/embed-page)

**Scarica le specifiche API come archivio zip.** In qualsiasi pagina di riferimento API, il menu AI Actions include ora l'opzione **Download API spec**, che raccoglie in un unico `api-specs.zip` tutte le specifiche OpenAPI referenziate dal sito, sia file locali sia URL remoti. Le specifiche multi-file mantengono la struttura delle cartelle `$ref`, così il download può essere usato direttamente in Postman, in un generatore di client o nei tuoi strumenti. [Azioni AI →](/it/ai/ai-actions)

**Specifiche OpenAPI validate durante la build.** Ogni deploy ora convalida rigorosamente le specifiche OpenAPI referenziate da `docs.json` e mostra ogni problema come **non-fatal build warning**, invece di interrompere la build. La documentazione viene comunque pubblicata; riceverai solo l'indicazione esatta dell'errore, come un errore di analisi YAML con riga e colonna, un `$ref` irrisolto o un `operationId` duplicato, via email e nell'elenco delle build del dashboard. In locale, `jamdesk dev` continua a interrompersi in presenza di una specifica non valida, così puoi correggerla prima del push. [Panoramica CLI →](/it/cli/overview)

**Chiedi all'AI direttamente dalla ricerca.** Inizia a digitare nella ricerca, poi invia la domanda alla chat AI senza aprire un risultato: premi ⌘/Ctrl+Enter o fai clic su **Ask AI** nel piè di pagina della ricerca. La domanda viene aggiunta alla conversazione, così puoi continuare il filo; Enter semplice apre invece il primo risultato. [Chat AI →](/it/ai/chat)

**Copia risposte e trascrizioni.** Ogni risposta della chat AI ha un pulsante di copia che recupera la sorgente Markdown; l'azione **Copy transcript** nell'header della chat copia l'intera conversazione in Markdown con i ruoli indicati, utile per incollarla in un issue o in un documento. [Chat AI →](/it/ai/chat)

**Scorrimento automatico della chat più intelligente.** La chat segue una risposta in streaming solo quando ti trovi già in fondo. Se scorri verso l'alto per rileggere una risposta precedente, resta ferma invece di riportarti in basso; tornando in fondo, si blocca nuovamente sul fondo.

**CSS personalizzato nell'anteprima locale (CLI).** `jamdesk dev` applica il CSS personalizzato come la build pubblicata, così puoi verificare lo stile prima del deploy. Inserisci un file `.css` nella radice del progetto, come `style.css`, oppure più file combinati in ordine alfabetico: verranno caricati al refresh del browser. Non serve alcuna voce in `docs.json`, in linea con il modo in cui Mintlify include i fogli di stile nella radice. [CSS personalizzato →](/it/customization/custom-css)

**Anteprime social personalizzate dal frontmatter.** Imposta direttamente nel frontmatter di una pagina qualsiasi meta tag Open Graph o Twitter/X, tra cui `og:title`, `og:description`, `og:image`, `twitter:card`, `keywords` e l'intero set di metatag. Usa chiavi piatte di primo livello o un blocco `seo:` annidato: entrambi funzionano e i valori per pagina sostituiscono quelli predefiniti in `docs.json`. [SEO →](/it/content/seo)

**Pagine nascoste.** Mantieni bozze, manuali interni o guide obsolete fuori dalla barra laterale e dai risultati di ricerca senza eliminarli. Aggiungi `hidden: true` al frontmatter di una pagina oppure a un gruppo o a una scheda in `docs.json`. Le pagine nascoste restano raggiungibili tramite URL diretto, ma scompaiono dalla navigazione, dalla sitemap, dalla ricerca del sito e dal contesto AI, ricevendo automaticamente un tag `noindex`. Vuoi un gruppo nascosto le cui pagine continuino a comparire nella ricerca? Aggiungi `searchable: true` insieme a `hidden`. [Pagine nascoste →](/it/content/hidden-pages)

**Decorazioni a griglia e a finestre.** Due nuovi motivi di sfondo si aggiungono al gradiente predefinito del tema Jam. Imposta `background.decoration` su `"grid"` per una griglia di punti discreta da 24px oppure su `"windows"` per due macchie effetto vetro smerigliato, nello stile di Windows 11, negli angoli superiori. Il gradiente e il riempimento piatto `"none"` continuano a funzionare come prima: scegli l'aspetto più adatto al tuo brand. [Sfondo →](/it/customization/background)

**Personalizzazione dello sfondo.** Un nuovo blocco `background` in `docs.json` disabilita il gradiente della modalità chiara di Jam, sostituisce il colore della pagina per modalità o regola colore, dimensioni, posizione e opacità del gradiente. Non serve CSS personalizzato. [Sfondo →](/it/customization/background)

**Diagrammi D2.** Un secondo linguaggio per diagrammi si aggiunge a Mermaid. Contrassegna un blocco di codice delimitato con `d2` e Jamdesk lo renderizza come SVG durante la build, con temi chiaro e scuro integrati. Il flusso è uguale a quello di Mermaid: scegli il linguaggio più adatto al diagramma da disegnare. [Diagrammi D2 →](/it/components/d2)

**Risultati di ricerca raggruppati.** La ricerca non ripete più la stessa pagina per ogni corrispondenza di sezione. I risultati vengono raggruppati sotto la pagina principale nella finestra di ricerca, con un massimo di tre sezioni visibili per impostazione predefinita e un espansore inline per le altre. L'evidenziazione degli snippet resta invariata: trovi la sezione giusta con meno scansioni.

**Rilevamento automatico di `docs.json` durante la connessione.** Quando colleghi un repository GitHub, viene trovato `docs.json` ovunque si trovi. Il flusso di connessione analizza l'intero albero e segnala un `mint.json` di Mintlify se ne trova uno. Monorepo e configurazioni annidate funzionano senza configurazione manuale. [Collegare GitHub →](/it/setup/connecting-github)

**Indicazioni sulla posizione di `docs.json` nella CLI.** Le configurazioni fuori posto sono più facili da individuare. `jamdesk validate`, `jamdesk dev` e `jamdesk doctor` indicano dove si trova effettivamente `docs.json`, o dove dovrebbe essere, invece di mostrare un generico errore "not found". Puoi correggerlo in pochi secondi senza interpretare uno stack trace. [Panoramica CLI →](/it/cli/overview)

**Hreflang conforme agli standard.** I tag hreflang ora generano codici BCP 47 validi. Cartelle locali come `cn`, `jp` e `ja-jp` vengono associate ai codici previsti dai motori di ricerca (`zh`, `ja`) e gli URL della sitemap vengono sottoposti a escape XML. Ogni pagina localizzata si posiziona nella propria area invece di essere trattata come contenuto duplicato. [Lingue →](/it/setup/languages)

**Esportazione PDF.** Esegui il rendering dell'intero sito di documentazione in un unico [PDF](/it/builds/pdf-export) da **Settings → PDF Exports** nel dashboard. Solo per i piani a pagamento. I progetti multilingue consentono di scegliere una lingua per esportazione; i risultati vengono memorizzati per commit e, al termine del rendering, ricevi un'email con il link per il download.

**Specifiche OpenAPI multilingue.** Le pagine endpoint visualizzano specifiche OpenAPI tradotte insieme all'MDX tradotto. Inserisci un file `<spec>.<lang>.<ext>` (ad esempio `openapi/api.fr.yaml`) accanto alla specifica sorgente: Jamdesk lo utilizzerà per gli URL di quella lingua, tornando alla specifica inglese quando manca una variante. Riepiloghi delle operazioni, descrizioni dei parametri, descrizioni delle risposte e descrizioni degli schemi vengono tutti localizzati. Configurazione: [Tradurre le specifiche OpenAPI](/it/setup/languages#traduzione-delle-specifiche-openapi).

**Componente Visibility.** Il nuovo componente [`<Visibility for="humans|agents">`](/it/components/visibility) consente di separare nello stesso documento contenuti per lettori umani o agenti AI. I blocchi riservati agli esseri umani vengono visualizzati nel browser ma rimossi dalle esportazioni `.md` e da `llms-full.txt`; per i blocchi riservati agli agenti avviene l'opposto. Gli agenti che richiedono `Accept: text/markdown` sugli URL canonici ricevono automaticamente la vista per agenti.

**Protezione con password, ricostruita.** Blocca l'intero sito con una password condivisa oppure proteggi solo alcune pagine lasciando pubbliche le altre. Imposta `auth.password.enabled: true` per la modalità dell'intero sito oppure indica singole pagine con `private: true` nel frontmatter, o elencale in `auth.password.private`, per la modalità dedicata alle pagine. La pagina Settings del dashboard guida nella configurazione, rotazione e revoca della password. I visitatori vedranno una schermata di sblocco personalizzata con il logo e il colore principale del sito, oltre a un suggerimento facoltativo definito in `docs.json`. Guida: [Protezione con password](/it/setup/password-protection).

**Conversione automatica delle immagini in WebP.** Jamdesk può convertire le immagini PNG e JPG in WebP durante la build. I file convertiti sono in genere più piccoli del 60-80% rispetto agli originali, senza perdita visibile di qualità, quindi le pagine si caricano più rapidamente senza elaborazione manuale. Attivala con `images.convertToWebp: true` in `docs.json`. Favicon, `og:image` e `twitter:image` mantengono il formato originale per la compatibilità con i crawler social. Un nuovo passaggio **Optimizing images** mostra l'avanzamento live nel dashboard e nella CLI durante ogni build. [Conversione automatica delle immagini →](/it/builds/image-optimization)

**Playground API.** Le pagine endpoint ora includono un ["Try it" button](/it/api-reference/playground) interattivo. Compila i parametri, osserva gli esempi di codice aggiornarsi in tempo reale e invia richieste live senza lasciare la documentazione. Attivo per impostazione predefinita su tutte le pagine API. Funziona sia con endpoint OpenAPI sia con endpoint scritti in MDX.

Installazione in due passaggi dal marketplace dei plugin. Si integra con [CLAUDE.md](/it/ai/claude-code) e con il [server MCP](/it/ai/mcp-server) per la scrittura assistita della documentazione tramite AI.
