<Update label="Agosto 2026" date="2026-08-20">
**Jamdesk traduce la tua documentazione in 27 lingue.** Seleziona le lingue desiderate, fino a cinque per progetto, in **Settings → Translations**: dopo ogni build, le pagine tradotte vengono salvate nel tuo repository GitHub. Le build successive ritraducono solo le pagine il cui sorgente inglese è cambiato. Le traduzioni già presenti o modificate manualmente vengono conservate finché non fai clic su **Replace with AI translation**. Incluso in tutti i piani. [AI Translation →](/it/setup/ai-translation)

**Scegli l'URL della tua documentazione.** L'hosting su sottopercorso non è più legato a `/docs`. Inserisci un singolo segmento, come `help` o `guide`, nel campo del sottopercorso della scheda Custom Domain e salva. `/docs` continua a funzionare, gli URL canonici passano subito al nuovo percorso e il sottopercorso personalizzato precedente reindirizza al nuovo per una sola ridenominazione, così puoi aggiornare il proxy con i tuoi tempi. [Subpath Hosting →](/it/deploy/subpath-hosting)

**Correggi con l'AI, ora più velocemente.** L'apertura dell'anteprima della correzione dal banner della build termina prima, anche sui siti più grandi, e riaprirla è quasi immediato perché Jamdesk conserva i risultati della scansione finché la tua documentazione non cambia. Il flusso non cambia: esamina ogni modifica proposta, applica quelle approvate e Jamdesk le salva ed esegue una nuova build. [Fix with AI →](/it/builds/fix-with-ai)

**Un quarto tema: Halo.** Imposta `"theme": "halo"` in `docs.json` per un aspetto caldo e arrotondato: carattere Figtree, sfondo color sabbia con contenuto rialzato su una scheda e i raggi degli angoli più ampi tra tutti i temi integrati. Colori, caratteri e override CSS personalizzati funzionano come in Jam, Nebula e Pulsar. [Theming →](/it/customization/theming)

**Servi la documentazione solo dal tuo dominio.** Attiva **Custom domain only** nella scheda Custom Domain: una visita diretta a `YOUR_SLUG.jamdesk.app` restituisce 404, mentre il tuo CNAME o proxy continua a funzionare. Jamdesk verifica il dominio attivo prima di attivare l'opzione; se il DNS si interrompe, il sottodominio torna a essere disponibile finché il problema non viene risolto. Questa opzione nasconde il sottodominio ai visitatori diretti, ma non controlla chi può leggere la documentazione: per questo abbinala alla protezione tramite password. [Custom domain only →](/it/deploy/custom-domain-only)

**Genera l'intero riferimento API da una spec.** Collega una scheda di navigazione al tuo file OpenAPI con `"openapi": { "source": "/openapi/api.yaml", "generate": true }`: ogni build crea una pagina per operazione, raggruppata nella barra laterale per tag. Una pagina endpoint salvata mantiene il proprio slug, così puoi effettuare la migrazione una pagina alla volta; un percorso rinominato reindirizza dal vecchio URL invece di restituire 404. [Generated API pages →](/it/config/docs-json-reference#navigation-openapi-pagine-generate)

**I lettori scelgono il server API che stanno consultando.** Un endpoint la cui spec elenca più di una voce `servers` mostra un selettore accanto al relativo URL. Scegliendo il sandbox cambiano l'URL di base, il pulsante di copia, ogni esempio di codice e la richiesta inviata dal playground, così nessuno copia un comando `curl` di produzione dalla documentazione sandbox. Gli endpoint con un solo server non cambiano. [API Playground →](/it/api-reference/playground#più-server)

**Il Markdown viene visualizzato in ogni descrizione OpenAPI.** Tabelle, elenchi, link, `code` e **grassetto** vengono visualizzati allo stesso modo nelle descrizioni dei parametri, dei corpi delle richieste, delle risposte e degli schemi, come già avveniva nella descrizione dell'operazione. Prima nove aree si comportavano in modo diverso; ora usano tutte lo stesso renderer. [OpenAPI Example →](/it/api-reference/openapi-example)

**Le esportazioni Markdown degli endpoint includono l'autenticazione.** Scarica la versione `.md` di una pagina di riferimento API: termina con una sezione `## Authentication` che elenca gli schemi richiesti dall'operazione, inclusi tipo, nome dell'header, formato bearer, ambiti OAuth 2 e combinazioni valide. Un agente che legge l'esportazione può creare una richiesta funzionante senza aprire la spec. [Markdown Source →](/it/ai/markdown-source#cosa-esporta-una-pagina-endpoint)

**Escludi una pagina dalla ricerca senza nasconderla.** Aggiungi `search: false` al frontmatter di una pagina per rimuoverla dalla ricerca del sito, dalle risposte della chat AI e dal server MCP, mantenendola però nella barra laterale, nella sitemap e in llms.txt. Usala per una pagina superata che vuoi mantenere raggiungibile tramite link e indicizzata. Anche le pagine nascoste e quelle senza indicizzazione vengono escluse dalle risposte AI, cosa che prima non avveniva. [Keep a page out of search only →](/it/content/hidden-pages#escludere-una-pagina-solo-dalla-ricerca)

**`jamdesk validate` segnala le configurazioni senza effetto.** Alcune chiavi di `docs.json` venivano accettate senza essere mai visualizzate, soprattutto `asyncapi`, quindi una configurazione sembrava supportata finché la build non mostrava che non produceva nulla. Il comando le identifica, insieme alle voci aggiuntive di `api.mdx.server` oltre la prima, che sono sempre state ignorate. [CLI overview →](/it/cli/overview)

</Update>

**Correggi gli avvisi della build con l'AI dal dashboard.** Quando una build termina con link non funzionanti o pagine prive di descrizione, nella build compare un banner **Fix with AI** che mostra quanti problemi possono essere corretti. Aprilo per visualizzare l'anteprima di ogni modifica proposta, inclusi gli anchor riscritti e le descrizioni suggerite, quindi applica quelle approvate. Jamdesk le salva nel branch GitHub e avvia una nuova build. Tutto ciò che non può risolvere senza ambiguità viene elencato separatamente per la correzione manuale. [Fix with AI →](/it/builds/fix-with-ai)

**Membri del team illimitati.** Ogni progetto include ora membri del team illimitati in tutti i piani, senza costi aggiuntivi. Il precedente limite di 10 membri e il prezzo per postazione sono stati rimossi: invita l'intero team.

**Consenti ai bot autorizzati di pubblicare la documentazione.** Gli account di automazione come Dependabot, Renovate o un bot di pubblicazione CMS non sono membri di Jamdesk, quindi per impostazione predefinita i loro push non avviano una build. Ora, quando uno di questi account viene rifiutato, la build mostra un pulsante **Authorize Bot Account** con un solo clic. Autorizzalo e i push dell'account pubblicheranno sul sito live, proprio come quelli di un membro del team. Solo i membri del progetto possono autorizzare un account; puoi esaminare o revocare l'accesso in qualsiasi momento nella sezione **Allowed automation accounts** delle impostazioni GitHub del progetto.

**La tua documentazione riceve un AI Score a ogni build.** Jamdesk valuta ora automaticamente, dopo ogni build e direttamente nel dashboard, quanto bene gli agenti AI riescono a leggere la documentazione pubblicata, sulla base dello standard AFDocs aperto. Visualizza il punteggio da 0 a 100 e il voto alfabetico, osserva l'andamento tra le build e ricevi una correzione in linguaggio semplice per ogni problema, con un pulsante **Copy prompt to fix** che invia il risultato al tuo agente AI di programmazione. Attiva **Email team when score changes** per ricevere una notifica quando una build modifica in modo significativo il punteggio. [AI Score →](/it/ai/ai-score)

**Correggi automaticamente i link non funzionanti.** Gli avvisi relativi a link interni non funzionanti con destinazione non ambigua, come anchor errati e deriva degli anchor tra le lingue, possono ora essere corretti con un solo comando. Esegui `jamdesk fix --dry-run` per visualizzare in anteprima le modifiche pianificate, quindi `jamdesk fix` per applicarle; vengono modificati solo gli avvisi in cui l'anchor corretto conduce a un heading reale, mentre i casi ambigui restano da esaminare manualmente. [CLI overview →](/it/cli/overview)

**Annuncia qualsiasi cosa con un banner.** Aggiungi un `banner` a `docs.json` per fissare una barra con un messaggio in cima a ogni pagina, sopra l'header e nel colore principale del tema. Puoi usare link, **grassetto** e *corsivo* inline, oltre a impostare `dismissible: true` per offrire ai lettori un pulsante di chiusura, che mantiene la barra chiusa finché non modifichi il messaggio. [Banner →](/it/config/docs-json-reference#banner)

**Mostra quando ogni pagina è stata aggiornata l'ultima volta.** Imposta `metadata.timestamp: true` in `docs.json` per aggiungere al piè di pagina di ogni pagina una riga come "Last updated on June 15, 2026". La data proviene dall'ultimo commit Git che ha modificato la pagina, quindi resta aggiornata a ogni build senza manutenzione manuale. [Page Metadata →](/it/config/docs-json-reference#metadata)

**Personalizza le icone di navigazione.** Le icone di barra laterale, gruppo, scheda, anchor e ricerca rispettano ora `style` in un oggetto icona (`{ "name": "rocket", "style": "duotone" }`) o un prefisso di stile (`duotone/rocket`): light, thin, duotone e la famiglia sharp, non solo solid. [Icons →](/it/content/icons#forma-a-oggetto-delle-icone)

**Personalizza la barra di ricerca.** Scegli il testo segnaposto con `search.prompt` e cura i link rapidi mostrati ai visitatori nel pannello di ricerca vuoto con `search.popularPages`, ciascuno con un titolo, uno slug di pagina e un'icona Font Awesome. [Search configuration →](/it/config/docs-json-reference#ricerca)

**Raccogli iscrizioni email senza embed.** Collega Resend, Mailchimp, Kit, Loops, beehiiv, Brevo o SendGrid in **Integrations → Email Signups**: un modulo ospitato da Jamdesk aggiunge i lettori direttamente al tuo pubblico, mentre la chiave API resta sul nostro backend e non viene mai pubblicata sul sito. Aggiungi il componente [`EmailSubscribe`](/it/components/email-subscribe) a qualsiasi pagina oppure imposta `placement: changelog` per inserire automaticamente una casella di iscrizione in ogni pagina del changelog. [Email Signups →](/it/integrations/email-signups)

**Sottoponi le analisi al consenso dei cookie.** Aggiungi la chiave `integrations.cookies` a `docs.json`: Jamdesk sospende ogni script di analisi e tracciamento — Google Analytics, GTM, Plausible, Crisp, JavaScript personalizzato e le proprie analisi integrate — finché il visitatore non presta il consenso, letto da un flag `localStorage` impostato dal banner. Puoi caricare un banner Osano o Termly direttamente da `docs.json`; un breve snippet ponte attiva il flag appena il lettore accetta e gli script vengono caricati senza ricaricare la pagina. [Cookie Consent →](/it/integrations/cookie-consent)

**llms.txt, in ordine.** Il file `llms.txt` di ogni sito segue ora la struttura di llmstxt.org: schede e gruppi di navigazione diventano sezioni `##`, così gli agenti AI vedono la documentazione nell'ordine della barra laterale. I siti multilingue ricevono un indice per lingua: il file principale elenca la lingua predefinita e collega ogni indice tradotto, ad esempio `/fr/llms.txt`, mantenendo ciascun file abbastanza piccolo da evitare il troncamento da parte degli agenti. [llms.txt →](/it/ai/llms-txt)

**Gli agenti trovano più rapidamente la tua documentazione.** Ogni pagina include ora una direttiva invisibile e silenziosa per gli screen reader che indirizza gli agenti AI a `llms.txt` e alla versione `.md` della pagina; ogni esportazione Markdown inizia inoltre con un blockquote che collega l'indice. Gli agenti che recuperano il tuo HTML non devono più indovinare che esiste un percorso Markdown. [AI Overview →](/it/ai/overview)

**Incorpora il changelog ovunque.** Un launcher "What's new?" entra nella tua app con un solo tag `<script>` e apre il changelog Jamdesk in una finestra modale, con un punto che segnala i contenuti non letti per ogni visitatore. Genera lo snippet da **Integrations → What's New widget**, quindi regola modalità del launcher, angolo, dimensioni della finestra e colore del punto con attributi `data-`. Nella tua documentazione Jamdesk, il componente MDX [`<Widget>`](/it/components/widget) inserisce lo stesso launcher live in qualsiasi pagina con un solo tag e senza script. [Embed Your Changelog →](/it/development/embed-page)

**Scarica le spec API come archivio zip.** In qualsiasi pagina di riferimento API, il menu AI Actions include ora l'opzione **Download API spec**, che raccoglie in un unico `api-specs.zip` tutte le spec OpenAPI referenziate dal sito, sia file locali sia URL remoti. Le spec composte da più file mantengono la struttura delle cartelle `$ref`, così il download può essere usato direttamente in Postman, in un generatore di client o nei tuoi strumenti. [AI Actions →](/it/ai/ai-actions)

**Spec OpenAPI validate durante la build.** Ogni deploy valida rigorosamente le spec OpenAPI referenziate da `docs.json` e mostra ogni problema come **non-fatal build warning**, invece di interrompere la build. La documentazione viene comunque pubblicata; ricevi solo l'indicazione precisa dell'errore, come un errore di analisi YAML con riga e colonna, un `$ref` non risolto o un `operationId` duplicato, via email e nell'elenco delle build del dashboard. In locale, `jamdesk dev` continua a interrompersi in presenza di una spec non valida, così puoi correggerla prima del push. [CLI overview →](/it/cli/overview)
</Update>

**Copia risposte e trascrizioni.** Ogni risposta della chat AI ha un pulsante di copia che recupera il sorgente Markdown; l'azione **Copy transcript** nell'header della chat copia l'intera conversazione in Markdown con i ruoli indicati, utile per incollarla in un issue o in un documento. [AI Chat →](/it/ai/chat)

**Scorrimento automatico della chat più intelligente.** La chat segue una risposta in streaming solo quando ti trovi già in fondo. Scorri verso l'alto per rileggere una risposta precedente e la posizione resta invariata invece di riportarti in basso; torna in fondo e la chat riprende a seguire la risposta.

**CSS personalizzato nell'anteprima locale (CLI).** `jamdesk dev` applica il CSS personalizzato come la build pubblicata, così puoi verificare lo stile prima del deploy. Inserisci qualsiasi file `.css` nella root del progetto, ad esempio `style.css`, oppure più file combinati in ordine alfabetico: verrà caricato al refresh del browser. Non è necessaria alcuna voce in `docs.json`, in linea con il modo in cui Mintlify include i fogli di stile nella root. [Custom CSS →](/it/customization/custom-css)

**Anteprime social personalizzate dal frontmatter.** Imposta qualsiasi meta tag Open Graph o Twitter/X direttamente nel frontmatter di una pagina: `og:title`, `og:description`, `og:image`, `twitter:card`, `keywords` e l'intero set di metatag. Puoi usare chiavi piatte di primo livello o un blocco annidato `seo:`; entrambi funzionano e i valori per pagina sostituiscono quelli predefiniti in `docs.json`. [SEO →](/it/content/seo)

**Pagine nascoste.** Mantieni bozze, manuali interni o guide obsolete fuori dalla barra laterale e dai risultati di ricerca senza eliminarli. Aggiungi `hidden: true` al frontmatter di una pagina oppure a un gruppo o una scheda in `docs.json`. Le pagine nascoste restano raggiungibili tramite URL diretto, ma scompaiono dalla navigazione, dalla sitemap, dalla ricerca del sito e dal contesto AI, oltre a ricevere automaticamente un tag `noindex`. Vuoi un gruppo nascosto le cui pagine continuino a comparire nella ricerca? Aggiungi `searchable: true` insieme a `hidden`. [Hidden pages →](/it/content/hidden-pages)

**Decorazioni a griglia e finestre.** Due nuovi motivi di sfondo si aggiungono al gradiente predefinito del tema Jam. Imposta `background.decoration` su `"grid"` per una griglia discreta di punti da 24 px oppure su `"windows"` per due aree sfumate in stile Windows 11 negli angoli superiori. Il gradiente e il riempimento piatto `"none"` continuano a funzionare come prima: scegli l'aspetto più adatto al tuo brand. [Background →](/it/customization/background)

**Personalizzazione dello sfondo.** Un nuovo blocco `background` in `docs.json` disattiva il gradiente della modalità chiara di Jam, sostituisce il colore della pagina per modalità oppure regola colore, dimensioni, posizione e opacità del gradiente. Non serve CSS personalizzato. [Background →](/it/customization/background)

**Diagrammi D2.** Un secondo linguaggio per diagrammi si affianca a Mermaid. Contrassegna un blocco di codice delimitato con `d2` e Jamdesk lo renderizza come SVG durante la build, con temi chiaro e scuro integrati. Il flusso è lo stesso di Mermaid: scegli il linguaggio più adatto al diagramma che stai creando. [D2 Diagrams →](/it/components/d2)

**Risultati di ricerca raggruppati.** La ricerca non ripete più la stessa pagina per ogni corrispondenza di sezione. I risultati vengono raggruppati sotto la pagina principale nella finestra di ricerca, con fino a tre sezioni visibili per impostazione predefinita e un espansore inline per le altre. L'evidenziazione degli snippet resta disponibile, così trovi la sezione corretta con meno scansioni.

**Rilevamento automatico di `docs.json` durante il collegamento.** Quando colleghi un repository GitHub, il sistema trova `docs.json` ovunque si trovi. Il flusso di collegamento analizza l'intero albero e segnala un `mint.json` di Mintlify se ne trova uno. Monorepo e configurazioni annidate funzionano senza impostazioni manuali. [Connecting GitHub →](/it/setup/connecting-github)

**Indicazioni sulla posizione di `docs.json` nella CLI.** È più facile individuare le configurazioni nella posizione errata. `jamdesk validate`, `jamdesk dev` e `jamdesk doctor` indicano dove si trova effettivamente `docs.json`, o dove dovrebbe trovarsi, invece di mostrare un errore generico "not found". Puoi correggerlo in pochi secondi senza interpretare uno stack trace. [CLI overview →](/it/cli/overview)

**Hreflang conforme agli standard.** I tag hreflang generano ora codici BCP 47 validi. Le cartelle locali come `cn`, `jp` e `ja-jp` vengono convertite nei codici previsti dai motori di ricerca, `zh` e `ja`, con URL della sitemap sottoposti a escape XML. Ogni pagina localizzata si posiziona nella propria regione invece di essere trattata come contenuto duplicato. [Languages →](/it/setup/languages)

**Esportazione PDF.** Trasforma l'intero sito della documentazione in un singolo [PDF](/it/builds/pdf-export) da **Settings → PDF Exports** nel dashboard. Disponibile solo nei piani a pagamento. I progetti multilingue permettono di scegliere una lingua per esportazione; i risultati vengono memorizzati per commit e ricevi un'email con il link per il download al termine del rendering.

**Spec OpenAPI multilingue.** Le pagine endpoint visualizzano spec OpenAPI tradotte insieme all'MDX tradotto. Inserisci un file `<spec>.<lang>.<ext>` — ad esempio `openapi/api.fr.yaml` — accanto alla spec sorgente: Jamdesk lo usa negli URL di quella lingua e ricorre alla spec inglese quando manca una variante. Riepiloghi delle operazioni, descrizioni dei parametri, descrizioni delle risposte e descrizioni degli schemi vengono tutti localizzati. Configurazione: [Translating OpenAPI Specs](/it/setup/languages#traduzione-delle-specifiche-openapi).

**Componente Visibility.** Il nuovo componente [`<Visibility for="humans|agents">`](/it/components/visibility) permette di separare contenuti per lettori umani o agenti AI nella stessa pagina. I blocchi solo umani vengono visualizzati nel browser ma rimossi dalle esportazioni `.md` e da `llms-full.txt`; per i blocchi solo agenti avviene il contrario. Gli agenti che richiedono `Accept: text/markdown` sugli URL canonici ricevono automaticamente la vista per agenti.

**Protezione tramite password, ricostruita.** Blocca l'intero sito con una password condivisa oppure proteggi solo alcune pagine lasciando pubbliche le altre. Imposta `auth.password.enabled: true` per la modalità intero sito oppure contrassegna singole pagine con `private: true` nel frontmatter, o elencale in `auth.password.private`, per la modalità pagine specifiche. La pagina Settings del dashboard guida nella configurazione, rotazione e revoca della password. I visitatori vedono una schermata di sblocco con il logo del sito, il colore principale e un suggerimento opzionale definito in `docs.json`. Guida: [Password Protection](/it/setup/password-protection).

**Conversione automatica delle immagini in WebP.** Jamdesk può convertire le immagini PNG e JPG in WebP durante la build. I file convertiti sono generalmente più piccoli del 60-80% rispetto agli originali, senza perdita visibile di qualità, così le pagine si caricano più velocemente senza elaborazione manuale. Attiva la funzione con `images.convertToWebp: true` in `docs.json`. Favicon, `og:image` e `twitter:image` mantengono il formato originale per la compatibilità con i crawler social. Un nuovo passaggio **Optimizing images** mostra l'avanzamento in tempo reale nel dashboard e nella CLI durante ogni build. [Automatic Image Conversion →](/it/builds/image-optimization)

**API Playground.** Le pagine endpoint includono ora un ["Try it" button](/it/api-reference/playground) interattivo. Compila i parametri, osserva gli esempi di codice aggiornarsi in tempo reale e invia richieste live senza lasciare la documentazione. Attivo per impostazione predefinita su tutte le pagine API. Funziona sia con endpoint OpenAPI sia con endpoint scritti in MDX.

**Plugin Claude Code.** Installa il [plugin Jamdesk per Claude Code](/it/claude-code-plugin) per offrire a Claude una conoscenza approfondita dei componenti MDX, della configurazione `docs.json`, dei modelli di navigazione e dei comandi CLI. Installazione in due passaggi dal marketplace dei plugin. Si abbina a [CLAUDE.md](/it/ai/claude-code) e al [server MCP](/it/ai/mcp-server) per la scrittura assistita dalla AI.

**Avvisi della build per branding mancante.** Le build segnalano ora quando i percorsi `favicon` o `logo` in `docs.json` fanno riferimento a file inesistenti nel progetto. Gli avvisi compaiono nei dettagli della build nel dashboard e nella CLI tramite `jamdesk dev` e `jamdesk validate`. Non viene inviata alcuna email: l'avviso è solo informativo.

**YouTube Shorts.** Il [componente `<YouTube>`](/it/content/youtube#youtube-shorts) supporta ora gli Shorts verticali tramite la prop `short`, visualizzando un player centrato in formato 9:16 senza barre nere. Usa `<YouTube id="VIDEO_ID" short />`.

**Integrazioni.** [Google Analytics 4](/it/integrations/google-analytics), [Google Tag Manager](/it/integrations/google-tag-manager), [Plausible Analytics](/it/integrations/plausible-analytics) e [notifiche build Slack](/it/integrations/slack) (Pro).

**Feed RSS per i changelog.** Le pagine con `rss: true` nel frontmatter generano ora automaticamente un feed RSS sottoscrivibile. Un'icona RSS compare accanto al titolo della pagina e un `feed.xml` viene creato dai componenti [Update](/it/components/update#feed-rss) durante ogni build. Usa la nuova prop `date` su Update per date corrette nel feed.

**Login e deploy dalla CLI.** [`jamdesk login`](/it/cli/authentication) esegue l'autenticazione tramite browser. [`jamdesk deploy`](/it/cli/deploy) impacchetta il progetto e avvia una build dal terminale. Non è necessario collegare GitHub. La CLI rispetta `.gitignore`, segnala i file segreti e trasmette inline l'avanzamento della build.

**Controllo ortografico CLI.** `jamdesk spellcheck` verifica la presenza di errori ortografici nella documentazione usando oltre 180 termini tecnici integrati, solo in inglese. `jamdesk spellcheck --fix` avvia una modalità interattiva per correggere gli errori o aggiungere parole all'elenco da ignorare.

**Incorporamenti video.** Incorpora direttamente nella documentazione file `.mp4` e `.webm`. Inseriscili in una directory `/videos` e usa la sintassi Markdown (`![Demo](/videos/demo.mp4)`) oppure il [componente `<Video>`](/it/content/videos) per autoplay, loop e altri controlli.

**JavaScript personalizzato.** Aggiungi [script lato client](/it/customization/custom-javascript) per widget di chat, analisi o integrazioni di terze parti tramite `styling.js` in `docs.json`.
</Update>
