Usa l'API Builds per attivare ricostruzioni della documentazione senza inviare nuovi commit. È utile per pipeline CI, ricostruzioni pianificate o contenuti generati al di fuori della directory della documentazione.

## Autenticazione

Tutte le richieste usano una chiave API del progetto:

```http
Authorization: Bearer YOUR_API_KEY
```

Trova la tua chiave API in **Settings** → **API** per il progetto.

## Avvia una nuova build

**POST** `https://api.jamdesk.com/projects/{project_id}/rebuild`

### Esempio di richiesta

<CodeGroup>
```bash cURL
curl -X POST "https://api.jamdesk.com/projects/YOUR_PROJECT_ID/rebuild" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript JavaScript
const projectId = "YOUR_PROJECT_ID";
const apiKey = "YOUR_API_KEY";

const response = await fetch(
  `https://api.jamdesk.com/projects/${projectId}/rebuild`,
  {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${apiKey}`
    }
  }
);
const build = await response.json();
console.log(build.buildId, build.status);
```
</CodeGroup>

### Risposta

Le richieste riuscite restituiscono `200 OK` con i metadati della build che puoi usare per monitorarne l'avanzamento.

```json
{
  "buildId": "build_8f3k2j",
  "status": "queued",
  "createdAt": "2026-02-05T10:30:00Z",
  "commit": {
    "sha": "a1b2c3d",
    "message": "Update API docs",
    "author": "jane@example.com"
  },
  "project": {
    "id": "proj_abc123",
    "name": "My Docs"
  }
}
```

<Note>
Se ricevi una risposta `429`, riprova con backoff esponenziale. Contatta il supporto se ti servono limiti più alti.
</Note>

### Campi della risposta

<ResponseField name="buildId" type="string">
  Identificatore univoco della build. Usalo per fare riferimento alla build nella dashboard.
</ResponseField>

<ResponseField name="status" type="string">
  Stato corrente della build. Uno tra: `queued`, `building`, `deployed`, `failed`.
</ResponseField>

<ResponseField name="createdAt" type="string">
  Timestamp ISO 8601 della creazione della build.
</ResponseField>

<ResponseField name="commit.sha" type="string">
  Hash breve del commit che ha attivato la build.
</ResponseField>

<ResponseField name="commit.message" type="string">
  Messaggio del commit dal repository di origine.
</ResponseField>

<ResponseField name="commit.author" type="string">
  Indirizzo email dell'autore del commit.
</ResponseField>

<ResponseField name="project.id" type="string">
  Identificatore del progetto corrispondente al progetto nella dashboard.
</ResponseField>

<ResponseField name="project.name" type="string">
  Nome visualizzato del progetto.
</ResponseField>

## Monitoraggio dello stato della build

Lo stato della build è visibile nella dashboard in **Deployments**. Ogni build passa attraverso queste fasi:

1. **queued**: la build è in attesa nella coda.
2. **building**: il servizio di build sta compilando la tua documentazione.
3. **deployed**: la build è completata e il tuo sito è online.
4. **failed**: qualcosa è andato storto. Controlla i log della build per i dettagli.

Se il tuo repository è collegato a GitHub, i controlli di stato dei commit si aggiornano automaticamente. Un segno di spunta verde compare sul commit quando la build viene distribuita. Una X rossa compare se la build fallisce. Non è necessario interrogare l'API per ottenere aggiornamenti di stato.

## Formato della risposta di errore

Le risposte di errore seguono una struttura coerente:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API key",
    "status": 401
  }
}
```

<ResponseField name="error.code" type="string">
  Codice di errore leggibile dalla macchina. Vedi la tabella sotto per i valori possibili.
</ResponseField>

<ResponseField name="error.message" type="string">
  Descrizione leggibile di cosa è andato storto.
</ResponseField>

<ResponseField name="error.status" type="number">
  Codice di stato HTTP corrispondente allo stato della risposta.
</ResponseField>

### Codici di errore

| Status | Codice | Messaggio | Soluzione |
|--------|------|---------|-----|
| **401** | `unauthorized` | Invalid API key | Rigenera la chiave in **Settings** → **API** |
| **403** | `forbidden` | Unauthorized project access | Verifica che l'ID del progetto corrisponda al progetto della chiave API |
| **404** | `project_not_found` | Project not found | Verifica l'ID del progetto nella dashboard |
| **429** | `rate_limited` | Too many requests | Attendi e riprova con backoff esponenziale |
| **500** | `internal_error` | Internal server error | Riprova dopo alcuni secondi. Contatta il supporto se persiste |
