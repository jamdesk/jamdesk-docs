La CLI Jamdesk ti permette di visualizzare in anteprima la documentazione in locale, convalidare la configurazione, verificare i link interrotti e migrare da altre piattaforme. È open source e distribuita con la [Apache License 2.0](https://github.com/jamdesk/jamdesk-cli).

## Installazione

<Tabs>
  <Tab title="npm (consigliato)">
    Installa globalmente da [npm](https://www.npmjs.com/package/jamdesk) per usare `jamdesk` da qualsiasi percorso:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Installa con Homebrew:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Installa tramite script:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Aggiorna o disinstalla:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Installa tramite script:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Aggiorna o disinstalla:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Esegui senza installare:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Verifica l'installazione:

```bash
jamdesk --version
```

### Requisiti

- **Node.js** v20.0.0 o superiore
- **npm** v8 o superiore (consigliato)

## Avvio rapido

<Steps>
  <Step title="Crea un progetto">
    Crea un nuovo progetto di documentazione:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Avvia il server di sviluppo">
    Esegui il server di sviluppo locale con hot reload:

    ```bash
    jamdesk dev
    ```

    La tua documentazione è disponibile su **http://localhost:3000/docs**
  </Step>
  <Step title="Convalida prima del deploy">
    Controlla errori di configurazione, link interrotti e ortografia:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Comandi

Esegui `jamdesk <command> --help` per i dettagli di ciascun comando.

### Sviluppo

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Avvia il server di sviluppo locale con hot reload.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Funzionalità:**
  - Convalida automatica all'avvio (schema di docs.json, sintassi MDX e specifiche OpenAPI referenziate. Una specifica non valida arresta il server.)
  - Hot reload alla modifica dei file MDX
  - Ricostruzione automatica della navigazione alla modifica di docs.json
  - Ricaricamento di CSS personalizzato (`style.css`) al refresh del browser
  - Ricerca
  - Tutti i temi e tutti i componenti

  **Opzioni:**

  | Flag | Descrizione |
  |------|-------------|
  | `-p, --port <port>` | Porta su cui avviare il server (predefinita: 3000) |
  | `-v, --verbose` | Attiva l'output dettagliato |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Crea un nuovo progetto di documentazione.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Questo crea un nuovo progetto con:
  - file di configurazione `docs.json`
  - pagine MDX di esempio
  - struttura di cartelle consigliata
</Accordion>

### Convalida

<Accordion title="jamdesk validate" icon="check">
  Convalida la configurazione `docs.json`, la sintassi MDX e le specifiche OpenAPI.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Controlla:**
  - Sintassi JSON valida in docs.json
  - Campi obbligatori (name, navigation)
  - Valori di tema validi
  - Errori di sintassi MDX (ad esempio, caratteri `<` non escapati)
  - Convalida delle specifiche OpenAPI (se configurata)
  - Conformità allo schema

  **Opzioni:**

  | Flag | Descrizione |
  |------|-------------|
  | `--skip-mdx` | Salta la convalida della sintassi MDX |
  | `-v, --verbose` | Mostra l'output dettagliato della convalida |

  Eseguilo prima del deploy per individuare subito gli errori.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Analizza la documentazione alla ricerca di link interni interrotti.

  ```bash
  jamdesk broken-links
  ```

  **Esempio di output:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Rileva link verso pagine mancanti ed errori di battitura. Vedi [Link e navigazione](/it/content/links#come-vengono-rilevati-i-link-interni) per i dettagli.
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Corregge automaticamente gli avvisi sui link interni interrotti con una destinazione non ambigua. Gestisce due tipi di casi:
  - **Ancore con errori di battitura**: un frammento come `#instalation` che dovrebbe chiaramente essere `#installation`
  - **Disallineamento delle ancore tra lingue**: una pagina tradotta ha rinominato le sue intestazioni, ma i link in quella lingua puntano ancora al vecchio frammento in inglese

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **Esempio di output dell'anteprima:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  `jamdesk fix` scrive una correzione solo quando l'ancora corretta corrisponde a un'intestazione reale nella pagina di destinazione. Lascia i casi ambigui per la revisione manuale.

  **Opzioni:**

  | Flag | Descrizione |
  |------|-------------|
  | `--dry-run` | Mostra in anteprima le correzioni senza scrivere alcun file |
  | `-y, --yes` | Applica le correzioni senza chiedere conferma |
  | `--types <list>` | Tipi di avviso da correggere, separati da virgola (predefinito: tutti quelli supportati) |

  <Card title="Guida alla correzione dei link interrotti" icon="wrench" href="/it/cli/fix-broken-links">
    Procedura passo passo: anteprima, applicazione, revisione e commit
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Verifica la documentazione alla ricerca di errori ortografici.

  ```bash
  jamdesk spellcheck
  ```

  **Esempio di output:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Usa un dizionario inglese con oltre 150 termini tecnici integrati (API, GraphQL, Kubernetes, React, ecc.). Salta blocchi di codice, codice inline, frontmatter, JSX, URL e percorsi dei file. Per ora supporta solo l'inglese. Sono previsti dizionari multilingua.

  **Opzioni:**

  | Flag | Descrizione |
  |------|-------------|
  | `--fix` | Corregge o aggiunge alla lista di ignorati in modo interattivo |
  | `--json` | Output in JSON (per le pipeline CI) |
  | `-v, --verbose` | Mostra ogni file mentre viene controllato |

  **Modalità di correzione interattiva (`--fix`)** scorre ogni parola errata unica:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Correggi** sostituisce la parola con un suggerimento in tutti i file. Non modifica mai blocchi di codice o attributi JSX. Il prompt mostra fino a 3 suggerimenti e contrassegna quello migliore come consigliato.
  - **Ignora** aggiunge la parola a `spellcheck.ignore` nel tuo docs.json. Non verrà più segnalata.
  - **Salta** non fa nulla per questa esecuzione

  Puoi visualizzare in anteprima e confermare le modifiche prima che vengano applicate.

  **Lista di ignorati personalizzata:** aggiungi termini specifici del progetto al tuo docs.json:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  Spellcheck ignora il nome del progetto presente in `docs.json`.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Convalida un singolo file di specifica OpenAPI.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Convalida:**
  - Sintassi YAML/JSON valida
  - Conformità allo schema OpenAPI 3.x
  - Definizioni degli endpoint
  - Corretta risoluzione dei riferimenti `$ref`
</Accordion>

<Note>
  **Jamdesk convalida le specifiche OpenAPI in tre punti.** `jamdesk dev` si interrompe all'avvio se una specifica referenziata non è valida. `jamdesk validate` e `jamdesk openapi-check` controllano le specifiche su richiesta. La build nel cloud le controlla al deploy, dove una specifica non valida è un **avviso non bloccante**. Il resto della documentazione viene comunque pubblicato. L'email e l'elenco delle build nella dashboard indicano il problema: un errore di parsing con riga e colonna, un `$ref` non risolto o un `operationId` duplicato. Correggi la specifica e rifai il push per risolverlo.
</Note>

### Gestione dei file

<Accordion title="jamdesk rename" icon="file-pen">
  Rinomina una pagina e aggiorna ogni riferimento a essa.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Questo:**
  - Rinomina il file
  - Aggiorna la navigazione in docs.json
  - Aggiorna i link in tutti gli altri file MDX
  - Aggiorna i riferimenti agli snippet

  Usalo al posto della rinomina manuale. I riferimenti restano sincronizzati.
</Accordion>

### Migrazione

<Accordion title="jamdesk migrate" icon="right-left">
  Migra la documentazione da Mintlify a Jamdesk.

  ```bash
  jamdesk migrate
  ```

  Rileva la configurazione di Mintlify e la converte nel formato Jamdesk. Lo stesso passaggio:

  - Rinomina i componenti obsoleti (ad esempio `CardGroup` → `Columns`)
  - Sposta i file snippet MDX orfani in `/snippets/` e riscrive gli import relativi al genitore
  - Estrae i componenti inline che usano React hook in `/snippets/<name>.tsx` con `'use client'`
  - Corregge problemi meccanici di sintassi MDX

  Il comando è idempotente. Rieseguirlo è sicuro.

### Deploy

<Accordion title="jamdesk pull" icon="cloud-arrow-down">
  Scarica un progetto la cui documentazione è ospitata da Jamdesk (senza GitHub) come repository git, oppure unisci le nuove modifiche di Jamdesk in una copia già scaricata.

  ```bash
  jamdesk pull
  jamdesk pull --project your-project
  jamdesk pull --dir ./docs-copy
  ```

  Modifica i file, poi esegui `jamdesk deploy` in quella cartella per pubblicarli. Richiede CLI 1.1.227 o successiva e git.

  | Flag | Descrizione |
  |------|-------------|
  | `--project <id-or-slug>` | Scarica un progetto specifico (salta la selezione interattiva) |
  | `--dir <path>` | Cartella di destinazione (predefinita: `./<slug>`) |
  | `--force` | Trasforma una cartella che contiene già file, come una vecchia copia di sola lettura, in una copia git. I suoi file restano come modifiche non committate |

  <Card title="Modifica sul tuo computer" icon="laptop" href="/it/setup/without-github#modifica-sul-tuo-computer">
    Pubblicazione, unione delle modifiche di Jamdesk, conflitti e file che deploy rifiuta
  </Card>
</Accordion>

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Carica la documentazione e avvia una build dal terminale.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  La CLI mostra ogni fase della build al suo completamento. Disponibile anche come `jamdesk push`.

  | Flag | Descrizione |
  |------|-------------|
  | `--detach` | Mette in coda e termina subito |
  | `--full-rebuild` | Forza una ricostruzione completa (senza cache) |
  | `--project <id>` | Esegue il deploy su un progetto specifico |
  | `--allow-empty` | Consente il deploy con zero pagine di contenuto `.mdx` (rifiutato per impostazione predefinita) |
  | `-m, --message <text>` | Messaggio di commit in una cartella creata da `jamdesk pull` |
  | `--allow-secret-files` | Pubblica file dall'aspetto sensibile da una cartella creata da `jamdesk pull` |

  <Card title="Guida al deploy da CLI" icon="cloud-arrow-up" href="/it/cli/deploy">
    Pipeline di deploy completa, fasi della build, riferimento degli errori e risoluzione dei problemi
  </Card>
</Accordion>

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  Genera e pubblica un Cloudflare Worker che inoltra `/docs` sul tuo dominio al tuo sito Jamdesk.

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --yes
  ```

  Il comando è interattivo per impostazione predefinita. Verifica Wrangler, controlla l'account Cloudflare, rileva lo slug da `docs.json`, genera i file del Worker e propone il deploy. `--yes` genera i file e si ferma. Pubblicali con `npx wrangler deploy` dalla directory di output.

  | Flag | Descrizione |
  |------|-------------|
  | `--slug <slug>` | Slug del progetto Jamdesk |
  | `--domain <domain>` | Dominio di destinazione (ad esempio `example.com`) |
  | `--path <path>` | Prefisso del percorso (predefinito: `/docs`) |
  | `--output-dir <dir>` | Directory di output (predefinita: `cloudflare-worker/`) |
  | `--skip-deploy` | Salta la domanda "vuoi fare il deploy ora?" in un'esecuzione interattiva |
  | `--force` | Sovrascrive la directory di output se esiste già |
  | `--yes` | Risponde a ogni domanda con il valore predefinito (modalità CI). Non esegue mai il deploy e non sovrascrive una directory esistente |

  <Card title="Guida a Cloudflare Workers" icon="cloud" href="/it/deploy/cloudflare">
    Configurazione del Worker, pattern delle route e impostazioni della cache
  </Card>
</Accordion>

### Manutenzione

<Accordion title="jamdesk doctor" icon="stethoscope">
  Controlla l'ambiente e diagnostica i problemi.

  ```bash
  jamdesk doctor
  ```

  **Controlla:**
  - Versione di Node.js (richiede v20+)
  - Versione di npm
  - Esistenza e validità di docs.json
  - Stato della cache ~/.jamdesk
  - Permessi di scrittura

  Eseguilo quando la CLI non funziona correttamente.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Svuota la directory della cache ~/.jamdesk.

  ```bash
  jamdesk clean
  ```

  Rimuove dipendenze e artefatti di build in cache. Usalo per:
  - Liberare spazio su disco
  - Correggere una cache danneggiata
  - Forzare una nuova installazione delle dipendenze

  Il prossimo `jamdesk dev` reinstalla le dipendenze.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Aggiorna la CLI all'ultima versione.

  ```bash
  jamdesk update
  ```

  Puoi anche aggiornare manualmente:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Configurazione

Crea `~/.jamdeskrc` per impostare le opzioni predefinite:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Opzione | Tipo | Predefinito | Descrizione |
|---------|------|-------------|-------------|
| `defaultPort` | number | 3000 | Porta predefinita per il server di sviluppo |
| `verbose` | boolean | false | Attiva l'output dettagliato per impostazione predefinita |
| `checkUpdates` | boolean | true | Controlla gli aggiornamenti della CLI all'avvio |

## Risoluzione dei problemi

<AccordionGroup>
  <Accordion title="Errori di sintassi MDX">
    MDX viene interpretato come JSX. Alcuni caratteri hanno un significato speciale.

    **Problema comune:** il carattere `<` viene interpretato come l'inizio di un tag JSX.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Soluzioni:**
    - Usa `&lt;` per il simbolo "minore di" letterale: `Valori &lt;50% sono bassi`
    - Riscrivi per evitare il carattere: `"Sotto il 50%"` invece di `"<50%"`
    - Esegui `jamdesk validate` per messaggi di errore dettagliati con numeri di riga
  </Accordion>

  <Accordion title="docs.json non trovato">
    Esegui il comando da una directory che contiene un file `docs.json`.

    **Soluzioni:**
    - Esegui `jamdesk init` per creare un nuovo progetto
    - Verifica di trovarti nella directory corretta
    - Controlla che il file si chiami esattamente `docs.json` (non `doc.json` o simili)
  </Accordion>

  <Accordion title="Il server di sviluppo non si avvia">
    **Prova questi passaggi:**
    1. Esegui `jamdesk doctor` per verificare l'ambiente
    2. Esegui `jamdesk clean` per svuotare la cache
    3. Usa `jamdesk dev --verbose` per l'output dettagliato degli errori
    4. Verifica che Node.js v20+ sia installato: `node --version`
  </Accordion>

  <Accordion title="Primo avvio lento">
    Il primo avvio installa le dipendenze in `~/.jamdesk/node_modules`.

    Accade solo una volta. Gli avvii successivi sono più veloci.
  </Accordion>

  <Accordion title="Porta già in uso">
    Un altro processo sta usando la porta predefinita.

    **Soluzioni:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Errori di permesso negato">
    Potresti non avere i permessi di scrittura sulla directory della cache.

    **Soluzioni:**
    1. Controlla i permessi di `~/.jamdesk`: `ls -la ~/.jamdesk`
    2. Correggi la proprietà: `sudo chown -R $(whoami) ~/.jamdesk`
    3. Esegui `jamdesk clean` e riprova
  </Accordion>
</AccordionGroup>
