Il comando `deploy` impacchetta la documentazione, la carica su Jamdesk e avvia una build dal terminale. Usalo per iterazioni rapide, per testare modifiche o per progetti non collegati a un repository GitHub.

## Avvio rapido

```bash
jamdesk login        # First time only
jamdesk deploy       # From your project directory
```

## Opzioni

| Flag | Descrizione |
|------|-------------|
| `--detach` | Accoda la build ed esce immediatamente (stampa un link alla dashboard) |
| `--full-rebuild` | Forza una build completa, ignorando la cache di build |
| `--project <id>` | Esegue il deploy su un ID progetto specifico (salta la selezione interattiva) |
| `--allow-empty` | Consente il deploy con zero pagine di contenuto `.mdx`. Per impostazione predefinita la CLI rifiuta il deploy di un progetto vuoto. Questo impedisce che una directory di lavoro errata pubblichi un sito vuoto. Gli snippet non contano come pagine di contenuto |

`jamdesk push` è un alias di `jamdesk deploy`.

## Come funziona

<Steps>
  <Step title="Autenticazione">
    Verifica la sessione. Un token scaduto ti chiede di eseguire `jamdesk login`.
  </Step>
  <Step title="Caricamento configurazione">
    Legge e valida `docs.json` dalla directory corrente.
  </Step>
  <Step title="Risoluzione del progetto">
    Legge `projectId` da `docs.json`. Al primo deploy manca. La CLI ti chiede quindi di scegliere un progetto. La CLI salva la tua scelta in `docs.json`. Il deploy successivo salta la richiesta.

    Usa `--project <id>` per sovrascriverlo.
  </Step>
  <Step title="Impacchettamento dei file">
    Crea un tarball compresso della documentazione. I file presenti in `.gitignore` vengono esclusi. La CLI avvisa dei file che sembrano segreti. L'avviso non blocca il caricamento.
  </Step>
  <Step title="Caricamento">
    Invia il tarball a Jamdesk tramite un URL pre-firmato. La dimensione massima del caricamento è 100 MB.
  </Step>
  <Step title="Build">
    Accoda una build e interroga lo stato. Ogni fase viene stampata al completamento. Premi Ctrl+C per interrompere l'interrogazione. La build continua in background.
  </Step>
  <Step title="Completato">
    Stampa l'URL live al termine della build.
  </Step>
</Steps>

## Fasi della build

La CLI stampa ogni fase in ordine mentre interroga lo stato:

| Fase | Descrizione |
|------|-------------|
| Estrazione dei file | Decompressione del tarball caricato |
| Validazione della configurazione | Verifica dello schema e del contenuto di `docs.json` |
| Preparazione dei contenuti | Elaborazione dei file MDX e degli asset |
| Build della documentazione | Compilazione delle pagine e generazione degli artefatti statici |
| Caricamento sulla CDN | Invio dell'output compilato alla rete edge |
| Aggiornamento della cache | Eliminazione dei contenuti obsoleti dalla CDN |

## Esclusioni dei file

Questi elementi sono sempre esclusi dai caricamenti, indipendentemente dal contenuto di `.gitignore`:

`.git`, `node_modules`, `.next`, `.env`, `.env.*`, `*.pem`, `*.key`, `credentials.json`, `.gcloud`, `.DS_Store`, `Thumbs.db`

Anche tutto ciò che è presente nel tuo `.gitignore` viene escluso.

### Avvisi sui file segreti

La CLI avvisa (senza bloccare) quando rileva file che sembrano segreti:

- File `.env` e `.env.*`
- File `*.pem` e `*.key`
- `credentials.json`
- `service_account*.json`
- File il cui nome inizia con `secret`

Aggiungili a `.gitignore` per eliminare l'avviso ed escluderli dai caricamenti.

## Riferimento degli errori

| Errore | Codice | Causa | Soluzione |
|--------|--------|-------|-----------|
| Non autenticato | `AUTH_REQUIRED` | Nessuna credenziale salvata | `jamdesk login` |
| Sessione scaduta | `AUTH_EXPIRED` | Rinnovo del token non riuscito | `jamdesk login` |
| Accesso negato | `FORBIDDEN` | Non sei membro di questo progetto | Verifica l'appartenenza al progetto nella dashboard |
| Progetto non trovato | `NOT_FOUND` | ID progetto non valido | Verifica l'ID o rimuovi `projectId` da docs.json |
| Build in corso | `BUILD_IN_PROGRESS` | È in esecuzione un'altra build | Attendi o controlla la dashboard |
| Caricamento troppo grande | `TOO_LARGE` | Il server ha rifiutato il caricamento (limite 100 MB) | Escludi i file grandi tramite `.gitignore` |
| Progetto troppo grande | `PROJECT_TOO_LARGE` | Il tarball supera 100 MB durante l'impacchettamento | Escludi i file grandi tramite `.gitignore` |
| Nessun progetto | `NO_PROJECTS` | Nessun progetto nel tuo account | Crea prima un progetto nella dashboard |
| Nessun file | `EMPTY_PROJECT` | Tutti i file sono esclusi | Controlla `.gitignore` |
| Nessuna pagina di contenuto | `NO_CONTENT` | Non sono state trovate pagine di contenuto `.mdx` (gli snippet non contano) | Esegui dalla directory della documentazione, oppure usa `--allow-empty` se la pubblicazione vuota è intenzionale |
| Configurazione non valida | `CONFIG_NOT_FOUND` | `docs.json` mancante o non valido | Esegui dalla radice del progetto, verifica la configurazione |
| Caricamento non riuscito | `UPLOAD_FAILED` | Problema di rete durante il caricamento | Verifica la connessione e riprova |
| Build non riuscita | `BUILD_FAILED` | Errore del servizio di build | Controlla i log di build nella dashboard |

## Risoluzione dei problemi

<AccordionGroup>
  <Accordion title='"Una build è già in corso"'>
    Ogni progetto esegue una sola build alla volta. Attendi il completamento della build corrente. Controlla lo stato nella dashboard, in **Deployments**.
  </Accordion>

  <Accordion title='"docs.json non trovato o non valido"'>
    Esegui il comando dalla directory che contiene `docs.json`. Esegui `jamdesk validate` per verificare la presenza di errori di configurazione.
  </Accordion>

  <Accordion title='"Caricamento troppo grande"'>
    Il limite di 100 MB si applica al tarball compresso di tutti i file non esclusi. Immagini, video o file di dati di grandi dimensioni sono cause comuni. Aggiungili a `.gitignore` per escluderli.
  </Accordion>

  <Accordion title="Il deploy si blocca durante l'interrogazione">
    Premi Ctrl+C per uscire. La build continua in background. Controlla lo stato nella dashboard. Un blocco che si ripresenta può indicare che la rete interrompe le richieste di interrogazione.
  </Accordion>

  <Accordion title='"Nessun progetto trovato"'>
    Nel tuo account Jamdesk serve almeno un progetto. Creane uno su [dashboard.jamdesk.com](https://dashboard.jamdesk.com).
  </Accordion>
</AccordionGroup>

Per ulteriore risoluzione dei problemi della CLI, consulta la [guida CLI del Centro assistenza](/it/help/troubleshooting/cli-issues).
