---
title: Correggere i link interrotti
description: >-
  Scopri come jamdesk fix risolve automaticamente i link interni interrotti e gli anchor con refusi, mostrando in anteprima le modifiche prima di applicarle.
---

`jamdesk fix` è il comando di correzione automatica complementare a `jamdesk broken-links`. Legge gli stessi avvisi sui link interrotti e riscrive ogni file in cui la destinazione corretta può essere determinata senza ambiguità. I casi ambigui vengono segnalati per la revisione manuale e lasciati invariati.

<Tip>
  Preferisci usare il dashboard? [Fix with AI](/it/builds/fix-with-ai) esegue la stessa correzione durante una build, copre anche le descrizioni mancanti delle pagine e applica per te le modifiche su GitHub.
</Tip>

Corregge due tipi di link interni interrotti:

- **Anchor con refusi** — un frammento che contiene un errore evidente rispetto a un'intestazione esistente nella pagina di destinazione (ad esempio `#instalation` → `#installation`)
- **Deriva degli anchor tra locali** — una pagina tradotta ha rinominato le proprie intestazioni, ma i link in quella locale puntano ancora al vecchio frammento inglese (ad esempio `/fr/ai/selectors#ai-strategies` → `/fr/ai/selectors#stratégies-ia`)

## Passaggio 1: trovare i link interrotti

Esegui `jamdesk broken-links` per vedere cosa deve essere corretto:

```bash
jamdesk broken-links
```

Esamina l'output. `jamdesk fix` individua gli avvisi per i quali è possibile associare un anchor probabilmente corretto a un'intestazione esistente.

## Passaggio 2: visualizzare l'anteprima delle correzioni

Esegui il comando con `--dry-run` per vedere esattamente cosa cambierebbe prima di modificare i file:

```bash
jamdesk fix --dry-run
```

**Output di esempio:**

```text
Planned fixes:

  fr/ai/overview.mdx:9
    /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

(dry run — no files written)
```

Controlla ogni correzione pianificata. Se una modifica non sembra corretta, correggi manualmente il link invece di applicarla. `jamdesk fix` riscrive solo i link che può risolvere senza ambiguità.

## Passaggio 3: applicare le correzioni

Esegui il comando senza `--dry-run` per applicare le correzioni. Ti verrà chiesto di confermare:

```bash
jamdesk fix
```

```text
Apply 1 fix(es) to local files? (y/N)
```

Premi `y` per scrivere le modifiche. Per ignorare la richiesta di conferma in CI o negli script, usa `-y`:

```bash
jamdesk fix -y
```

Dopo l'applicazione, il comando stampa:

```text
Fixed 1 file(s); 0 warning(s) left for manual review.
```

Se la destinazione di un avviso è ambigua, `jamdesk fix` lascia il link invariato affinché tu possa risolverlo manualmente.

## Passaggio 4: esaminare il diff ed eseguire il commit

Controlla le modifiche prima di eseguire il commit:

```bash
git diff
```

Verifica che ogni link riscritto punti alla destinazione prevista. Quindi esegui il commit:

```bash
git add -A
git commit -m "fix(docs): auto-fix broken internal links"
```

## Opzioni

| Flag | Descrizione |
|------|-------------|
| `--dry-run` | Visualizza in anteprima le correzioni pianificate senza scrivere alcun file |
| `-y, --yes` | Applica le correzioni senza chiedere conferma |
| `--types <list>` | Tipi di avviso separati da virgole da correggere (impostazione predefinita: tutti quelli supportati) |
