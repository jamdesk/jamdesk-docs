`<EmailSubscribe>` inserisce un modulo di iscrizione via email direttamente in una pagina della documentazione. Con un provider [collegato nella dashboard](/it/integrations/email-signups), viene mostrato un modulo ospitato da Jamdesk che aggiunge i nuovi iscritti alla tua audience. Senza un provider, può ospitare l'embed incollabile di un altro servizio. Usalo nelle pagine di changelog e note di rilascio.

## Avvio rapido

Collega un provider nella dashboard. Poi aggiungi il tag con l'id di quel provider:

```mdx
<EmailSubscribe provider="resend" />
```

Viene visualizzato un campo email con etichetta e un pulsante Subscribe. Jamdesk aggiunge ogni indirizzo inviato all'audience collegata. Lo stesso tag funziona per qualsiasi provider nativo collegato (`mailchimp`, `kit`, `loops`, `beehiiv`, `brevo` o `sendgrid`).

Aggiungi un titolo e una riga descrittiva facoltativi:

```mdx
<EmailSubscribe
  provider="resend"
  title="Get release notes"
  description="One email when we ship something new. No spam."
/>
```

## Proprietà

| Prop | Tipo | Scopo |
|------|------|---------|
| `provider` | string | Id del provider: `resend`, `mailchimp`, `kit`, `loops`, `beehiiv`, `brevo`, `sendgrid`, `buttondown` o `substack`. |
| `title` | string | Titolo facoltativo mostrato sopra il modulo. |
| `description` | string | Riga di supporto facoltativa sotto il titolo. |
| `collapsed` | boolean | Solo provider nativi. Parte come un pulsante Subscribe compatto che si espande nel modulo completo al clic. |
| `username` | string | Username dell'account Buttondown / Substack (solo provider con embed). |
| `snippet` | string | Markup embed grezzo di qualsiasi provider. La via di fuga (vedi sotto). |
| `className` | string | Classe CSS extra sul wrapper. |

## Nativo vs. embed

Il `provider` che passi determina il comportamento del modulo:

- **Provider nativi** (`resend`, `mailchimp`, `kit`, `loops`, `beehiiv`, `brevo`, `sendgrid`) mostrano un modulo ospitato da Jamdesk. Jamdesk acquisisce l'indirizzo e lo aggiunge tramite la tua chiave collegata. Richiedono un provider [collegato nella dashboard](/it/integrations/email-signups).
- **Provider solo embed** (`buttondown`, `substack`) mostrano il modulo o l'iframe del servizio stesso. Non colleghi alcuna chiave. Passa il tuo `username`. Il visitatore invia i dati direttamente al provider.

<Note>
Un provider nativo non collegato nella dashboard non cattura nulla. Collega prima il provider.
</Note>

### Provider disponibili solo tramite embed

Buttondown e Substack funzionano senza una connessione nella dashboard. Passa lo username del tuo account:

```mdx
<EmailSubscribe provider="buttondown" username="acme" />
<EmailSubscribe provider="substack" username="acme" />
```

### Soluzione alternativa: incolla qualsiasi embed

Incolla il markup embed di qualsiasi provider in `snippet`. Viene renderizzato così com'è nella pagina pubblicata:

```mdx
<EmailSubscribe snippet={`<form action="https://example.com/subscribe">...</form>`} />
```

<Warning>
Uno `snippet` esegue il codice del provider sulla tua pagina. Alcuni provider forniscono uno script una tantum che non viene rieseguito quando il lettore naviga tra le pagine senza un ricaricamento completo. Posiziona gli embed basati su script in una pagina dedicata e caricata direttamente (come il tuo changelog), non in profondità in un flusso di navigazione.
</Warning>

## Modalità compatta

Imposta `collapsed` per avviare il modulo nativo come pulsante Subscribe. Cliccandolo si apre il campo completo in linea, senza ricaricare la pagina:

```mdx
<EmailSubscribe provider="resend" collapsed title="Subscribe to updates" />
```

L'etichetta del pulsante proviene da `title`. Il valore predefinito è "Subscribe to updates". La modalità compatta è solo per i provider nativi. I provider con embed mostrano il proprio markup.

## Iscritti esistenti

Il browser ricorda un lettore che si è iscritto tramite un modulo nativo. Alla visita successiva, il lettore vede una breve riga al posto del modulo: *You're subscribed to the newsletter.*

La riga include un controllo "Use a different email?" che riapre il modulo completo. La memoria è per browser. Risiede in `localStorage`, non nella tua audience. Cancellare i dati del sito o cambiare browser mostra di nuovo il modulo. I moduli nativi lo fanno senza alcuna configurazione.

## Posizionamento automatico nelle pagine di changelog

Monta il modulo nelle pagine di changelog senza aggiungere il tag a mano. Imposta `placement` su `changelog` nell'integrazione newsletter in `docs.json`:

```json
{
  "integrations": {
    "newsletter": {
      "provider": "resend",
      "title": "Get release notes",
      "placement": "changelog"
    }
  }
}
```

Il modulo viene quindi montato su ogni pagina di changelog (qualsiasi pagina con `rss: true`). Escluderlo da una singola pagina con `newsletter: false` nel frontmatter di quella pagina. Una pagina con un `<EmailSubscribe>` inserito a mano non riceve un secondo modulo.

Il blocco completo `integrations.newsletter` accetta gli stessi campi del componente (`provider`, `title`, `description`, `collapsed`, `username`, `snippet`, `height`) più `placement` (`none`, il valore predefinito, o `changelog`).

<Tip>
La card **Email Signups** nella dashboard ha i campi Form title e Form subtitle. Un modulo posizionato automaticamente usa questi valori quando `docs.json` omette `title` e `description`. Imposta `title`/`description` in `docs.json` solo per sovrascrivere i testi della dashboard.
</Tip>
