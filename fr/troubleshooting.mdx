## Échecs de build

Votre dashboard affiche un build comme « Échoué ». La plupart des échecs proviennent de l'une de ces trois causes : une page MDX avec un import ou un composant cassé, une modification invalide de `docs.json` (crochets non fermés, virgules finales après le dernier élément d'un tableau), ou une page listée dans la navigation `docs.json` qui n'existe pas en tant que fichier `.mdx`. Les deux premiers cas se manifestent localement avec `jamdesk dev` avant même d'atteindre un build déployé. Le lancer une fois avant de pousser permet souvent d'économiser un aller-retour.

<Tip>
Le journal de build dans votre dashboard indique le fichier et la ligne exacts où l'erreur s'est produite. Commencez par là. Cela pointe presque toujours vers le vrai problème, pas seulement le symptôme.
</Tip>

Pour des codes d'erreur spécifiques, consultez [Échecs de build](/fr/help/troubleshooting/build-failures) et la [Référence des erreurs](/fr/help/troubleshooting/error-reference).

## Le domaine personnalisé ne se vérifie pas

Le domaine reste bloqué sur « En attente » après l'ajout des enregistrements DNS ? Suivez ces étapes dans l'ordre :

1. Vérifiez que vous avez ajouté l'enregistrement **TXT** `_jamdesk.<hostname>`. Le routage ne s'active pas sans lui, et l'absence de cet enregistrement TXT est la cause la plus fréquente d'un domaine en attente. Le hostname est le domaine complet que vous vérifiez (pour `docs.example.com`, le nom de l'enregistrement TXT est `_jamdesk.docs.example.com`).
2. Vérifiez que vous avez ajouté un enregistrement **CNAME** (et non un enregistrement A) pour les sous-domaines.
3. Si vous utilisez Cloudflare, réglez le proxy sur **DNS uniquement** (nuage gris) pour les deux enregistrements.
4. Vérifiez la propagation sur [whatsmydns.net](https://www.whatsmydns.net/).

```bash
# Verify the TXT verification record
dig TXT _jamdesk.docs.yourdomain.com

# Verify your CNAME is resolving
dig CNAME docs.yourdomain.com
```

Un point non évident à connaître : même après que `dig` montre que vos enregistrements se résolvent, le dashboard peut continuer à afficher « En attente » pendant jusqu'à 30 minutes. Le vérificateur se trouve derrière des résolveurs en amont qui mettent en cache les réponses DNS négatives, et cette fenêtre de cache doit expirer avant que la nouvelle vérification réussisse. Si tout se résout localement mais que le dashboard n'a pas été mis à jour, laissez passer une demi-heure avant de supposer un problème plus profond.

[Dépannage DNS](/fr/help/troubleshooting/dns-issues) couvre les particularités propres à chaque fournisseur.

## Le dépôt GitHub n'apparaît pas

Si votre dépôt n'est pas dans la liste lors de la création d'un projet, l'application GitHub de Jamdesk n'est probablement pas installée sur l'organisation du dépôt, ou l'accès aux dépôts est réglé sur « Selected repositories » sans le vôtre inclus. Réautorisez sur [github.com/settings/installations](https://github.com/settings/installations) et accordez l'accès à « All repositories » ou au dépôt spécifique dont vous avez besoin.

Consultez [Problèmes GitHub](/fr/help/troubleshooting/github-issues) pour les problèmes de webhook et de permissions.

## Données d'analytique manquantes

Plusieurs raisons courantes expliquent pourquoi votre dashboard affiche zéro visiteur. L'analytique peut prendre jusqu'à 24 heures pour apparaître après le premier déploiement d'un site, donc les projets tout neufs paraissent vides pendant un moment. Les bloqueurs de publicités et le Do Not Track empêchent la comptabilisation d'une partie des visites, donc vos chiffres seront toujours en retrait par rapport à vos journaux serveur. Si aucun de ces cas ne s'applique, vérifiez que votre site est bien déployé et accessible publiquement.

[Problèmes d'analytique](/fr/help/troubleshooting/analytics-issues) approfondit le sujet des données retardées ou manquantes.

## Problèmes de connexion

Impossible de vous connecter, ou vous êtes renvoyé vers l'écran de connexion ? Videz le cache et les cookies pour `dashboard.jamdesk.com`, puis essayez une fenêtre de navigation privée. Si vous vous connectez avec GitHub, votre email GitHub doit correspondre à l'email de votre compte Jamdesk.

Consultez [Problèmes de connexion](/fr/help/troubleshooting/login-issues) pour les étapes de récupération de compte.
