## Échecs de build

Votre dashboard affiche un build comme « Failed ». La plupart des échecs proviennent de l'une de ces trois causes : une page MDX avec un import ou un composant cassé, une modification invalide de `docs.json` (crochets non fermés, virgules de fin après le dernier élément du tableau), ou une page référencée dans la navigation de `docs.json` qui n'existe pas en tant que fichier `.mdx`. Les deux premières se détectent localement avec `jamdesk dev` avant d'atteindre un build déployé. Lancer cette commande une fois avant de pousser permet généralement d'éviter un aller-retour inutile.

<Tip>
Le journal de build dans votre dashboard indique le fichier exact et la ligne où l'erreur s'est produite. Commencez par là — cela pointe presque toujours vers le vrai problème, pas seulement le symptôme.
</Tip>

Pour les codes d'erreur spécifiques, consultez [Échecs de build](/fr/help/troubleshooting/build-failures) et la [Référence des erreurs](/fr/help/troubleshooting/error-reference).

## Domaine personnalisé non vérifié

Domaine bloqué sur « Pending » après avoir ajouté les enregistrements DNS ? Suivez ces étapes dans l'ordre :

1. Confirmez que vous avez ajouté l'enregistrement **TXT** `_jamdesk.<hostname>`. Le routage ne s'active pas sans lui, et un TXT manquant est la cause la plus fréquente d'un domaine en attente. Le hostname est le domaine complet que vous vérifiez (pour `docs.example.com`, le nom de l'enregistrement TXT est `_jamdesk.docs.example.com`).
2. Confirmez que vous avez ajouté un enregistrement **CNAME** (et non un enregistrement A) pour les sous-domaines.
3. Si vous utilisez Cloudflare, réglez le proxy sur **DNS only** (nuage gris) pour les deux enregistrements.
4. Vérifiez la propagation sur [whatsmydns.net](https://www.whatsmydns.net/).

```bash
# Verify the TXT verification record
dig TXT _jamdesk.docs.yourdomain.com

# Verify your CNAME is resolving
dig CNAME docs.yourdomain.com
```

Un point non évident à savoir : même après que `dig` montre vos enregistrements résolus, le dashboard peut continuer à afficher « Pending » pendant jusqu'à 30 minutes. Le vérificateur est situé derrière des résolveurs en amont qui mettent en cache les réponses DNS négatives, et cette fenêtre de cache doit expirer avant qu'une nouvelle vérification réussisse. Si tout se résout localement mais que le dashboard n'a pas été mis à jour, attendez une demi-heure avant de supposer un problème plus profond.

[Dépannage DNS](/fr/help/troubleshooting/dns-issues) couvre les particularités spécifiques aux fournisseurs.

## Dépôt GitHub n'apparaissant pas

Si votre dépôt n'est pas dans la liste lors de la création d'un projet, l'application GitHub de Jamdesk n'est probablement pas installée sur l'organisation du dépôt, ou l'accès aux dépôts est défini sur « Selected repositories » sans que le vôtre soit inclus. Réautorisez sur [github.com/settings/installations](https://github.com/settings/installations) et accordez l'accès à « All repositories » ou au dépôt spécifique dont vous avez besoin.

Consultez [Problèmes GitHub](/fr/help/troubleshooting/github-issues) pour les problèmes de webhook et de permissions.

## Données analytiques manquantes

Plusieurs raisons courantes expliquent que votre dashboard affiche zéro visiteur. Les données analytiques peuvent prendre jusqu'à 24 heures à apparaître après le premier déploiement d'un site, donc les nouveaux projets semblent vides pendant un moment. Les bloqueurs de publicités et le Do Not Track empêchent une partie des visites d'être comptabilisées — vos chiffres seront toujours inférieurs à vos journaux serveur. Si aucune de ces situations ne s'applique, vérifiez que votre site est bien déployé et accessible publiquement.

[Problèmes analytiques](/fr/help/troubleshooting/analytics-issues) approfondit les données retardées ou manquantes.

## Problèmes de connexion

Impossible de se connecter, ou renvoyé à l'écran de connexion ? Videz le cache et les cookies pour `dashboard.jamdesk.com`, puis essayez une fenêtre de navigation privée. Si vous vous connectez avec GitHub, votre adresse e-mail GitHub doit correspondre à celle de votre compte Jamdesk.

Consultez [Problèmes de connexion](/fr/help/troubleshooting/login-issues) pour les étapes de récupération de compte.
