---
title: Tutoriel de bout en bout
description: "D’un dépôt vide à un site de doc en production : créez un projet, prévisualisez, déployez et configurez un domaine personnalisé si nécessaire."
---

Passez d'un dépôt vide à un site de documentation en production. Ajoutez un domaine personnalisé quand vous en avez besoin et ignorez les étapes déjà effectuées.

## Prérequis

- Un compte GitHub
- Un dépôt avec du contenu de documentation (ou utilisez le [Modèle de démarrage](https://github.com/jamdesk/starter-docs))
- Node.js 20+ si vous voulez installer le CLI avec npm

<Steps>
  <Step title="Créer un projet et connecter GitHub">
    Créez votre premier projet dans le dashboard Jamdesk et connectez un dépôt.

    - Suivez [Création de projets](/fr/setup/creating-projects) pour définir le nom du projet, le slug et le chemin de documentation
    - Si demandé, installez l'application GitHub et accordez l'accès au dépôt ([Connexion à GitHub](/fr/setup/connecting-github))
  </Step>

  <Step title="Modifier et prévisualiser les pages avec le CLI">
    Utilisez le CLI Jamdesk pour prévisualiser les modifications de pages avant de les pousser vers GitHub.

    <Tabs>
      <Tab title="npm">
        ```bash
        npm install -g jamdesk
        cd your-docs
        jamdesk dev
        ```
      </Tab>
      <Tab title="npx">
        ```bash
        cd your-docs
        npx jamdesk dev
        ```
      </Tab>
    </Tabs>

    Votre preview locale s'exécute sur **http://localhost:3000**. En savoir plus dans [Preview locale](/fr/development/local-preview).

    Ouvrez une page `.mdx` dans votre éditeur, enregistrez une modification et actualisez la preview locale. Quand le résultat vous convient, publiez avec le flux Git de l'étape suivante.
  </Step>

  <Step title="Déployer en poussant vers GitHub">
    Chaque push vers votre branche configurée déclenche un build et publie sur votre sous-domaine Jamdesk.

    ```bash
    git add .
    git commit -m "Add docs content"
    git push origin main
    ```

    Remplacez `main` par la branche configurée dans votre projet si vous utilisez une autre branche.

    Une fois le build terminé, votre documentation est accessible sur `your-project.jamdesk.app`. Voir [Déploiement](/fr/development/deployment) pour plus de détails.
  </Step>

  <Step title="Optionnel : Ajouter un domaine personnalisé">
    Rendez votre documentation prête pour la production avec votre propre domaine quand vous êtes prêt à l'utiliser hors du sous-domaine Jamdesk.

    1. Allez dans **Paramètres** → **Domaines** dans le dashboard Jamdesk
    2. Ajoutez votre domaine (par exemple, `docs.example.com`)
    3. Créez les enregistrements DNS affichés dans le dashboard
    4. Attendez la vérification et la finalisation du SSL

    Pour le dépannage, consultez [Domaines personnalisés](/fr/deploy/custom-domains).
  </Step>
</Steps>

## Valider le flux de bout en bout

- Votre sous-domaine Jamdesk se charge et affiche le dernier build
- La preview locale reflète le même contenu et la même navigation
- S'il est configuré, le domaine personnalisé est vérifié et sert le contenu en HTTPS
- L'historique des builds affiche le dernier commit et l'attribution de l'auteur

## Optionnel : Héberger à /docs

Si vous souhaitez déployer votre documentation sur un sous-chemin comme `example.com/docs`, consultez [Vue d'ensemble du déploiement](/fr/deploy/overview) et [Hébergement en sous-chemin](/fr/deploy/subpath-hosting).
