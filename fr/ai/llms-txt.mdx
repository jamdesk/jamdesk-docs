Si vous souhaitez que des outils IA comme ChatGPT, Claude ou Copilot donnent des réponses précises sur votre produit, ils ont besoin d'un accès structuré à vos docs — pas seulement de ce qui s'est retrouvé dans leurs données d'entraînement.

Chaque site Jamdesk génère `llms.txt` et `llms-full.txt` conformément à la spécification [llmstxt.org](https://llmstxt.org). Les outils IA lisent ces fichiers au lieu de parcourir les pages individuelles.

<Note>
  Google audite désormais `llms.txt` dans le cadre des [vérifications de navigation agentique de Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Les sites qui publient un `llms.txt` valide sont plus accessibles aux agents IA — et de plus en plus à Google lui-même pour le classement des réponses alimentées par l'IA. Jamdesk vous offre cela gratuitement.
</Note>

<Tip>
  **Vérifiez votre score.** Découvrez dans quelle mesure un site de documentation est prêt pour les agents grâce à l'outil gratuit [AI Score](https://jamdesk.com/ai-score) — la publication d'un `llms.txt` valide est l'une des premières choses vérifiées. Il existe également une [extension Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) pour noter les sites pendant votre navigation.
</Tip>

## Ce que Jamdesk génère

| Fichier | Contenu |
|------|---------|
| `llms.txt` | Titres de pages, descriptions et URL (une table des matières structurée) |
| `llms-full.txt` | Contenu complet de la documentation dans un seul fichier |

Jamdesk génère les deux au moment du build et les sert depuis le même CDN que vos docs.

## Vérifier vos fichiers

Vérifiez que vos fichiers existent après votre premier build :

<Tabs>
  <Tab title="Domaine racine">
    Si vos docs se trouvent à la racine de votre domaine (par exemple `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si vos docs se trouvent sous `/docs` sur votre site principal (comme ce site sur `jamdesk.com/docs`) :

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Format du fichier

Le fichier `llms.txt` liste chaque page avec son titre, sa description et son URL, regroupés en sections qui reflètent votre navigation :

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Le fichier `llms-full.txt` contient le contenu Markdown complet de chaque page, concaténé avec des limites de page marquées par des titres.

## Structure

`llms.txt` suit la proposition [llmstxt.org](https://llmstxt.org/) : un titre H1,
un résumé en blockquote, et vos onglets de navigation et groupes comme sections `##` de
liens Markdown.

Les sites multilingues reçoivent un index par langue. Le `llms.txt` racine liste votre
langue par défaut et renvoie vers chaque index traduit à la fin — par exemple
`/fr/llms.txt` pour le français. Chaque fichier de langue renvoie vers ses équivalents.

## Directive agent sur chaque page

Chaque page comporte également une note invisible et silencieuse pour les lecteurs d'écran, destinée aux agents IA,
pointant vers `llms.txt`, et chaque export Markdown commence par un blockquote
reliant l'index. Les agents qui arrivent sur votre HTML trouvent le chemin Markdown
sans avoir à parcourir le site.

## Comment c'est construit

- Généré au moment du build en même temps que votre HTML
- Servi depuis CDN avec la même politique de cache que vos docs
- Mis à jour automatiquement à chaque build
- Aucune configuration nécessaire ; toutes les pages sont incluses par défaut

## Désactiver llms.txt

`llms.txt` et `llms-full.txt` sont publiés par défaut. Pour arrêter de les générer — par exemple, si vous ne souhaitez pas que les outils IA ingèrent votre contenu — définissez `seo.ai.llmsTxt` à `false` dans votre `docs.json` :

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Lors de votre prochain build, Jamdesk ignore les deux fichiers et les URL `/llms.txt` et `/llms-full.txt` retournent `404`.

<Note>
  **L'ingestion IA et l'indexation par les moteurs de recherche sont des contrôles distincts.** `seo.ai.llmsTxt` régit uniquement les fichiers `llms.txt`/`llms-full.txt` que les outils IA lisent. Cela ne modifie pas la façon dont les moteurs de recherche indexent votre site — cela est contrôlé par les [métadonnées `robots` et le `noindex` par page](/fr/content/seo#contrôler-lindexation). Une page peut être indexée par Google tout en étant exclue de l'ingestion IA, ou inversement.
</Note>

## Robots d'exploration IA

Le `robots.txt` par défaut de Jamdesk autorise tous les principaux robots d'exploration IA (Claude, ChatGPT, Copilot, Gemini). Votre documentation est accessible aux outils IA sans configuration supplémentaire.

<Accordion title="En quoi llms.txt diffère de sitemap.xml">
  `sitemap.xml` liste les URL que les moteurs de recherche doivent parcourir et indexer. Il n'inclut aucun contenu, seulement des liens et des métadonnées comme les dates de dernière modification.

  `llms.txt` est conçu pour les modèles IA. Il inclut les titres de pages, les descriptions et (dans `llms-full.txt`) le contenu réel. Les outils IA peuvent lire le fichier complet pour comprendre votre documentation sans effectuer plusieurs requêtes HTTP.
</Accordion>
