Si vous voulez que des outils IA comme ChatGPT, Claude ou Copilot donnent des réponses précises sur votre produit, ils ont besoin d'un accès structuré à vos docs, pas seulement de ce qui a atterri dans leurs données d'entraînement.

Chaque site Jamdesk génère `llms.txt` et `llms-full.txt` en suivant la spécification [llmstxt.org](https://llmstxt.org). Les outils IA lisent ces fichiers au lieu de parcourir chaque page individuellement.

<Note>
  Google audite désormais `llms.txt` dans le cadre des [vérifications de navigation agentique de Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Les sites qui publient un `llms.txt` valide sont plus facilement découvrables par les agents IA, et de plus en plus par Google lui-même lors du classement de contenu pour les réponses générées par IA. Jamdesk vous offre cela gratuitement.
</Note>

<Tip>
  **Vérifiez votre score.** Découvrez à quel point un site de documentation est prêt pour les agents IA avec l'outil gratuit [AI Score](https://jamdesk.com/ai-score). Publier un `llms.txt` valide est l'une des premières choses qu'il vérifie. Il existe aussi une [extension Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) pour évaluer les sites pendant votre navigation.
</Tip>

## Ce que Jamdesk génère

| Fichier | Contenu |
|------|---------|
| `llms.txt` | Titres de page, descriptions et URLs (une table des matières structurée) |
| `llms-full.txt` | Contenu complet de la documentation dans un seul fichier |

Jamdesk génère les deux au moment du build et les sert depuis le même CDN que vos docs.

## Vérifiez vos fichiers

Vérifiez que vos fichiers existent après votre premier build :

<Tabs>
  <Tab title="Domaine racine">
    Si vos docs sont à la racine de votre domaine (par exemple, `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si vos docs se trouvent sous `/docs` sur votre site principal (comme ce site à `jamdesk.com/docs`) :

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Format du fichier

Le fichier `llms.txt` liste chaque page avec son titre, sa description et son URL, regroupées en sections qui reflètent votre navigation :

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Le fichier `llms-full.txt` contient le contenu Markdown complet de chaque page, concaténé avec des limites de page marquées par des titres.

## Structure

`llms.txt` suit la proposition [llmstxt.org](https://llmstxt.org/) : un titre H1,
un résumé en citation, et vos onglets et groupes de navigation en sections `##` de
liens Markdown.

Les sites multilingues obtiennent un index par langue. Le `llms.txt` racine liste votre
langue par défaut et renvoie vers chaque index traduit à la fin, par exemple
`/fr/llms.txt` pour le français. Chaque fichier de langue renvoie vers ses homologues.

## Directive agent sur chaque page

Chaque page comporte également une note invisible, silencieuse pour les lecteurs d'écran, destinée aux agents IA
et pointant vers `llms.txt`, et chaque export Markdown commence par une citation
renvoyant vers l'index. Les agents qui arrivent sur votre HTML trouvent le chemin Markdown
sans avoir à parcourir le site.

## Comment c'est construit

- Généré au moment du build en même temps que votre HTML
- Servi depuis le CDN avec la même politique de cache que vos docs
- Mis à jour automatiquement à chaque build
- Aucune configuration nécessaire ; toutes les pages sont incluses par défaut

## Désactiver llms.txt

`llms.txt` et `llms-full.txt` sont publiés par défaut. Pour arrêter de les générer (par exemple, si vous ne voulez pas que les outils IA ingèrent votre contenu), définissez `seo.ai.llmsTxt` sur `false` dans votre `docs.json` :

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Lors de votre prochain build, Jamdesk ignore les deux fichiers et les URLs actives `/llms.txt` et `/llms-full.txt` renvoient `404`.

<Note>
  **L'ingestion IA et l'indexation par les moteurs de recherche sont des contrôles distincts.** `seo.ai.llmsTxt` régit uniquement les fichiers `llms.txt`/`llms-full.txt` que les outils IA lisent. Cela ne change pas la façon dont les moteurs de recherche indexent votre site ; cela est contrôlé par les [métadonnées `robots` et le `noindex` par page](/fr/content/seo#contrôler-lindexation). Une page peut être indexée par Google tout en étant exclue de l'ingestion IA, ou inversement.
</Note>

## Crawlers IA

Le fichier `robots.txt` par défaut de Jamdesk autorise tous les principaux crawlers IA (Claude, ChatGPT, Copilot, Gemini). Votre documentation est accessible aux outils IA dès le départ.

<Accordion title="En quoi llms.txt diffère de sitemap.xml">
  `sitemap.xml` liste les URLs à parcourir et indexer pour les moteurs de recherche. Il ne contient aucun contenu, juste des liens et des métadonnées comme les dates de dernière modification.

  `llms.txt` est conçu pour les modèles IA. Il inclut les titres de page, les descriptions et (dans `llms-full.txt`) le contenu réel. Les outils IA peuvent lire le fichier complet pour comprendre votre documentation sans effectuer de multiples requêtes HTTP.
</Accordion>
