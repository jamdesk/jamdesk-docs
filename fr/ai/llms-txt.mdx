Pour que des outils d'IA comme ChatGPT, Claude ou Copilot donnent des réponses précises sur votre produit, ils ont besoin d'un accès structuré à votre documentation, pas seulement de ce qui a atterri dans leurs données d'entraînement.

Chaque site Jamdesk génère `llms.txt` et `llms-full.txt` en suivant la spécification [llmstxt.org](https://llmstxt.org). Les outils d'IA lisent ces fichiers au lieu d'explorer chaque page individuellement.

<Note>
  Google audite désormais `llms.txt` dans le cadre des [vérifications de navigation agentique de Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Les sites qui publient un `llms.txt` valide sont plus facilement détectables par les agents d'IA — et de plus en plus par Google lui-même lors du classement du contenu pour les réponses générées par IA. Jamdesk vous offre cela gratuitement.
</Note>

<Tip>
  **Vérifiez votre score.** Découvrez à quel point n'importe quel site de documentation est prêt pour les agents IA avec l'outil gratuit [AI Score](https://jamdesk.com/ai-score) — publier un `llms.txt` valide est l'une des premières choses qu'il vérifie. Il existe aussi une [extension Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) pour noter les sites pendant votre navigation.
</Tip>

## Ce que Jamdesk génère

| Fichier | Contenu |
|------|---------|
| `llms.txt` | Titres de page, descriptions et URL (une table des matières structurée) |
| `llms-full.txt` | Contenu complet de la documentation dans un seul fichier |

Jamdesk génère les deux au moment du build et les sert depuis le même CDN que votre documentation.

## Vérifier vos fichiers

Vérifiez que vos fichiers existent après votre premier build :

<Tabs>
  <Tab title="Domaine racine">
    Si votre documentation se trouve à la racine de votre domaine (par exemple, `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si votre documentation se trouve sous `/docs` sur votre site principal (comme ce site à `jamdesk.com/docs`) :

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Format de fichier

Le fichier `llms.txt` liste chaque page avec son titre, sa description et son URL, regroupées en sections qui reflètent votre navigation :

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Le fichier `llms-full.txt` contient le contenu Markdown complet de chaque page, concaténé avec des limites de page marquées par des titres.

## Structure

`llms.txt` suit la proposition [llmstxt.org](https://llmstxt.org/) : un titre H1,
une citation de résumé, et vos onglets et groupes de navigation sous forme de sections `##` de
liens Markdown.

Les sites multilingues obtiennent un index par langue. Le `llms.txt` racine liste votre
langue par défaut et renvoie vers chaque index traduit à la fin — par exemple
`/fr/llms.txt` pour le français. Chaque fichier de langue renvoie vers ses équivalents.

## Directive pour les agents sur chaque page

Chaque page comporte également une note invisible, silencieuse pour les lecteurs d'écran,
destinée aux agents IA et pointant vers `llms.txt`, et chaque export Markdown commence par une citation
renvoyant vers l'index. Les agents qui arrivent sur votre HTML trouvent le chemin Markdown
sans avoir besoin d'explorer le site.

## Comment c'est construit

- Généré au moment du build, en même temps que votre HTML
- Servi depuis le CDN avec la même politique de cache que votre documentation
- Se met à jour automatiquement à chaque build
- Aucune configuration nécessaire ; toutes les pages sont incluses par défaut

## Désactiver llms.txt

`llms.txt` et `llms-full.txt` sont publiés par défaut. Pour arrêter de les générer — par exemple, si vous ne voulez pas que les outils d'IA exploitent votre contenu — définissez `seo.ai.llmsTxt` sur `false` dans votre `docs.json` :

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Lors de votre prochain build, Jamdesk ignore les deux fichiers et les URL actives `/llms.txt` et `/llms-full.txt` renvoient une erreur `404`.

<Note>
  **L'ingestion par l'IA et l'indexation par les moteurs de recherche sont des contrôles distincts.** `seo.ai.llmsTxt` régit uniquement les fichiers `llms.txt`/`llms-full.txt` lus par les outils d'IA. Cela ne change pas la façon dont les moteurs de recherche indexent votre site — c'est contrôlé par les [métadonnées `robots` et le `noindex` par page](/fr/content/seo#contrôler-lindexation). Une page peut être indexée par Google tout en étant exclue de l'ingestion par l'IA, ou inversement.
</Note>

## Robots d'exploration IA

Le fichier `robots.txt` par défaut de Jamdesk autorise tous les principaux robots d'exploration IA (Claude, ChatGPT, Copilot, Gemini). Votre documentation est accessible aux outils d'IA dès le départ.

<Accordion title="En quoi llms.txt diffère de sitemap.xml">
  `sitemap.xml` liste les URL que les moteurs de recherche doivent explorer et indexer. Il ne contient aucun contenu, seulement des liens et des métadonnées comme les dates de dernière modification.

  `llms.txt` est conçu pour les modèles d'IA. Il inclut les titres de page, les descriptions et (dans `llms-full.txt`) le contenu réel. Les outils d'IA peuvent lire le fichier complet pour comprendre votre documentation sans effectuer plusieurs requêtes HTTP.
</Accordion>
