Si vous voulez que des outils d'IA comme ChatGPT, Claude ou Copilot donnent des réponses précises sur votre produit, ils ont besoin d'un accès structuré à votre documentation, pas seulement de ce qui a été inclus dans leurs données d'entraînement.

Chaque site Jamdesk génère `llms.txt` et `llms-full.txt` en suivant la spécification [llmstxt.org](https://llmstxt.org). Les outils d'IA lisent ces fichiers au lieu d'explorer chaque page individuellement.

<Note>
  Google audite désormais `llms.txt` dans le cadre des [vérifications de navigation agentique de Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Les sites qui publient un `llms.txt` valide sont plus facilement détectables par les agents d'IA, et de plus en plus par Google lui-même lors du classement du contenu pour les réponses basées sur l'IA. Jamdesk vous offre cela gratuitement.
</Note>

<Tip>
  **Vérifiez votre score.** Découvrez à quel point un site de documentation est prêt pour les agents grâce à l'outil gratuit [AI Score](https://jamdesk.com/ai-score). La publication d'un `llms.txt` valide est l'une des premières choses qu'il vérifie. Il existe aussi une [extension Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) pour évaluer les sites pendant votre navigation.
</Tip>

## Ce que Jamdesk génère

| Fichier | Contenu |
|------|---------|
| `llms.txt` | Titres de page, descriptions et URL (une table des matières structurée) |
| `llms-full.txt` | Contenu complet de la documentation dans un seul fichier |

Jamdesk génère les deux au moment du build et les diffuse depuis le même CDN que votre documentation.

## Vérifiez vos fichiers

Vérifiez que vos fichiers existent après votre premier build :

<Tabs>
  <Tab title="Domaine racine">
    Si votre documentation se trouve à la racine de votre domaine (par exemple, `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si votre documentation se trouve sous `/docs` sur votre site principal (comme ce site à `jamdesk.com/docs`) :

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Format de fichier

Le fichier `llms.txt` répertorie chaque page avec son titre, sa description et son URL, regroupées en sections qui reflètent votre navigation :

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

Le fichier `llms-full.txt` contient le contenu Markdown complet de chaque page, concaténé avec des limites de page marquées par des titres.

## Structure

`llms.txt` suit la proposition [llmstxt.org](https://llmstxt.org/) : un titre H1,
un résumé en citation, et vos onglets et groupes de navigation sous forme de sections `##`
de liens Markdown.

## Sites multilingues

Les sites disposant de plusieurs langues obtiennent un ensemble distinct de fichiers pour chaque
langue, afin qu'un outil d'IA puisse récupérer uniquement la langue dont il a besoin. Pour un site en
anglais (la langue par défaut) et en français :

| URL | Contenu |
|-----|---------|
| `/llms.txt` | Index anglais, avec des liens vers l'index de chaque autre langue à la fin |
| `/en/llms.txt` | Identique au fichier `/llms.txt` |
| `/fr/llms.txt` | Index français, renvoyant vers les autres langues |
| `/llms-full.txt` | Contenu complet de toutes les langues, les unes à la suite des autres |
| `/en/llms-full.txt` | Contenu complet des pages en anglais uniquement |
| `/fr/llms-full.txt` | Contenu complet des pages en français uniquement |

Le `llms-full.txt` racine conserve toutes les langues, donc les outils qui le lisent déjà
ne voient aucun changement. Pointez un agent vers le fichier propre à une langue lorsqu'il n'a besoin que de cette
langue :

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

Une langue obtient ses propres fichiers dès qu'elle compte au moins une page. Les sites
avec une seule langue ne conservent que les fichiers racine.

## Directive d'agent sur chaque page

Chaque page comporte également une note invisible, silencieuse pour les lecteurs d'écran, destinée aux agents d'IA
et pointant vers `llms.txt`, et chaque export Markdown commence par une citation
reliant l'index. Les agents qui arrivent sur votre HTML trouvent le chemin Markdown
sans avoir à explorer le site.

## Comment c'est construit

- Généré au moment du build, en même temps que votre HTML
- Diffusé depuis le CDN avec la même politique de cache que votre documentation
- Mis à jour automatiquement à chaque build
- Aucune configuration nécessaire ; toutes les pages sont incluses par défaut

## Désactiver llms.txt

`llms.txt` et `llms-full.txt` sont publiés par défaut. Pour arrêter de les générer (par exemple, si vous ne voulez pas que des outils d'IA exploitent votre contenu), définissez `seo.ai.llmsTxt` sur `false` dans votre `docs.json` :

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Lors de votre prochain build, Jamdesk ignore les deux fichiers, y compris chaque copie par langue, et les URL actives `/llms.txt` et `/llms-full.txt` renvoient `404`.

<Note>
  **L'ingestion par l'IA et l'indexation par les moteurs de recherche sont des contrôles distincts.** `seo.ai.llmsTxt` régit uniquement les fichiers `llms.txt`/`llms-full.txt` que lisent les outils d'IA. Cela ne change pas la façon dont les moteurs de recherche indexent votre site ; cela est contrôlé par les [métadonnées `robots` et le `noindex` par page](/fr/content/seo#contrôler-lindexation). Une page peut être indexée par Google tout en étant exclue de l'ingestion par l'IA, ou inversement.
</Note>

## Robots d'exploration IA

Le fichier `robots.txt` par défaut de Jamdesk autorise tous les principaux robots d'exploration IA (Claude, ChatGPT, Copilot, Gemini). Votre documentation est accessible aux outils d'IA dès le départ.

<Accordion title="En quoi llms.txt diffère de sitemap.xml">
  `sitemap.xml` répertorie les URL que les moteurs de recherche doivent explorer et indexer. Il ne contient aucun contenu, seulement des liens et des métadonnées comme les dates de dernière modification.

  `llms.txt` est conçu pour les modèles d'IA. Il inclut les titres de page, les descriptions et (dans `llms-full.txt`) le contenu réel. Les outils d'IA peuvent lire le fichier complet pour comprendre votre documentation sans effectuer plusieurs requêtes HTTP.
</Accordion>
