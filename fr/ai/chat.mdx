Chaque site Jamdesk inclut un assistant de chat qui répond aux questions des visiteurs à partir de votre documentation. Il récupère les sections pertinentes, les envoie à Claude et diffuse une réponse avec des liens vers les pages sources. Le chat est activé par défaut sur tous les plans, sans coût supplémentaire.

## Cas d'utilisation

<Tabs>
  <Tab title="Intégration API">
    Un développeur qui intègre votre API demande *« Comment authentifier les requêtes ? »* et obtient les étapes exactes avec un exemple de code, ainsi qu'un lien vers la page source.
  </Tab>
  <Tab title="Dépannage">
    *« Mon build échoue avec une erreur de timeout »*

    Au lieu de parcourir plusieurs pages, le visiteur obtient le correctif approprié depuis votre guide de dépannage en quelques secondes.
  </Tab>
  <Tab title="Référence rapide">
    Les utilisateurs récurrents posent des questions comme *« Quels paramètres accepte l'endpoint /users ? »* — le chat récupère la documentation de l'endpoint et renvoie directement le tableau des paramètres.
  </Tab>
</Tabs>

## Fonctionnement

<Steps>
  <Step title="Le build indexe votre documentation">
    À chaque build, Jamdesk divise vos pages en sections et les stocke sous forme d'embeddings interrogeables.
  </Step>
  <Step title="Le visiteur pose une question">
    Le bouton « Ask AI » (ou Cmd+I / Ctrl+I) ouvre un panneau de chat sur n'importe quelle page.
  </Step>
  <Step title="L'IA répond à partir de votre documentation">
    Les sections pertinentes sont récupérées, envoyées à Claude comme contexte, et la réponse est diffusée avec des liens de citation vers les pages sources.
  </Step>
</Steps>

## Fonctionnalités

| Fonctionnalité | Détail |
|---------|--------|
| Réponses en streaming | Les réponses arrivent en temps réel |
| Liens de citation | Chaque réponse renvoie vers les pages de documentation utilisées |
| Désambiguïsation | Quand une question correspond à plusieurs sujets, l'IA demande lequel le visiteur souhaite |
| Contexte de conversation | Historique de 10 messages, persisté par onglet de navigateur |
| Questions de démarrage | Générées automatiquement depuis votre documentation, ou définies dans docs.json |
| Raccourcis clavier | Cmd+I / Ctrl+I pour activer/désactiver, Échap pour fermer |
| Rendu Markdown | Les blocs de code, tableaux et listes s'affichent dans les réponses |

## Configuration

Le chat fonctionne sans configuration requise. Ajoutez un bloc `chat` à votre `docs.json` uniquement si vous souhaitez personnaliser les questions de démarrage ou désactiver le chat. Le champ `chat` est optionnel, et ses deux paramètres ont des valeurs par défaut sensées.

```json docs.json
{
  "chat": {
    "enabled": true,
    "starterQuestions": [
      "How do I get started?",
      "What API endpoints are available?"
    ]
  }
}
```

| Champ | Type | Défaut | Description |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Définir à `false` pour supprimer le bouton Ask AI, le panneau de chat et le raccourci clavier de votre site |
| `starterQuestions` | string[] | auto-généré | Jusqu'à 4 questions affichées à l'ouverture du panneau (5–200 caractères chacune). Générées automatiquement depuis votre documentation si omises ; définir à `[]` pour n'en afficher aucune |

### Questions de démarrage

Les questions de démarrage sont les suggestions affichées dans le panneau de chat avant que le visiteur ne saisisse quoi que ce soit — des exemples en un clic qui indiquent ce qu'il peut demander. Lorsque vous omettez `starterQuestions` de votre `docs.json`, Jamdesk les génère automatiquement depuis votre documentation à chaque build, afin qu'elles restent pertinentes au fil de la croissance de vos docs.

Pour définir les vôtres, listez-les dans le tableau `starterQuestions`. C'est utile lorsque votre équipe support reçoit toujours les mêmes questions et que vous souhaitez les mettre en avant :

```json docs.json
{
  "chat": {
    "starterQuestions": [
      "How do notifications work?",
      "Tell me more about analytics"
    ]
  }
}
```

Vous pouvez définir jusqu'à 4 questions de démarrage, chacune entre 5 et 200 caractères. Pour n'afficher aucune question de démarrage, définissez `starterQuestions` à un tableau vide (`[]`).

### Désactivation du chat

Le chat est activé par défaut sur tous les plans. Pour le désactiver, définissez `enabled` à `false`. Cela supprime le bouton Ask AI, le panneau de chat et le raccourci `Cmd+I` / `Ctrl+I` :

```json docs.json
{
  "chat": {
    "enabled": false
  }
}
```

<Note>
Désactiver le chat n'affecte pas la recherche. Le chat IA et la recherche sont des fonctionnalités distinctes, votre documentation reste donc entièrement consultable même avec le chat désactivé.
</Note>

## Limites

| Limite | Valeur |
|-------|-------|
| Longueur max du message | 2 000 caractères |
| Longueur max de la réponse | 2 048 tokens |
| Limite de débit | 10 requêtes / 60 secondes par visiteur par site |
| Historique de conversation | 10 messages par onglet |
| Questions de démarrage | 4 maximum |

Le chat fonctionne sur les [domaines personnalisés](/fr/deploy/custom-domains). L'endpoint `/_chat` est same-origin, il fonctionne donc sur tout domaine où votre documentation est servie.

<Accordion title="Fonctionnement du pipeline de récupération">
  À chaque build, Jamdesk divise vos pages en sections et stocke des embeddings vectoriels pour chacune. Quand un visiteur pose une question, le système effectue une recherche hybride (correspondance par mots-clés combinée à une similarité sémantique) pour trouver les sections les plus pertinentes dans vos docs. Ces sections sont envoyées à Claude comme contexte avec des instructions de répondre uniquement à partir de la documentation fournie. Les citations sont extraites en faisant correspondre les références de pages dans la réponse de Claude avec les sections récupérées.
</Accordion>
