<Update label="Août 2026" date="2026-08-01">
**Choisissez l'URL de votre documentation.** L'hébergement en sous-chemin ne vous enferme plus dans `/docs` : choisissez n'importe quel chemin à un seul segment (`/help`, `/guide`, ce qui convient le mieux à votre site) depuis la carte Custom Domain de votre dashboard. Le renommage est sans risque : `/docs` continue toujours de répondre, les URLs canoniques basculent immédiatement vers votre nouveau sous-chemin, et votre ancien sous-chemin personnalisé redirige vers le nouveau pour un seul renommage, si bien que rien de déjà indexé ou lié ne se casse. Mettez à jour la référence `/docs` de votre proxy en conséquence quand vous serez prêt. [Hébergement en sous-chemin →](/fr/deploy/subpath-hosting)

**Corriger avec l'IA, désormais plus rapide.** Les scans se terminent plus vite et de façon plus fiable — y compris sur les sites de documentation volumineux — et rouvrir le preview de correction est quasi instantané, car Jamdesk met en cache les résultats de vos scans et les réutilise tant que votre documentation ne change pas. Passez d'un avertissement de build à une correction validée en quelques secondes. [Corriger avec l'IA →](/fr/builds/fix-with-ai)

**Un quatrième thème : Halo.** Définissez `"theme": "halo"` dans votre `docs.json` pour un rendu chaud aux formes douces et arrondies — un arrière-plan sable avec votre contenu surélevé sur une carte, un accent caramel, et la police Figtree partout. C'est le membre le plus douillet de la famille, pensé pour une documentation qu'on lit de bout en bout. [Thèmes →](/fr/customization/theming)
</Update>

**Diffusez votre documentation uniquement depuis votre propre domaine.** Activez **Domaine personnalisé uniquement** dans les paramètres de domaine personnalisé de votre projet, et `YOUR_SLUG.jamdesk.app` cesse de répondre directement — votre documentation reste accessible via votre domaine, et nulle part ailleurs. Une vérification préalable s'exécute sur votre domaine en production avant que l'option puisse être activée, afin qu'un proxy mal configuré ne puisse pas couper l'accès de vos lecteurs par erreur ; et si votre DNS tombe en panne, le sous-domaine recommence à répondre plutôt que de rendre votre documentation inaccessible. Les domaines en simple CNAME ne nécessitent aucune configuration ; les proxys qui envoient déjà `X-Jamdesk-Forwarded-Host` n'en ont pas besoin non plus ; les utilisateurs des `rewrites` Vercel ajoutent `?jd_proxy=1` à chaque destination. Cela masque votre adresse Jamdesk aux moteurs de recherche et aux visiteurs occasionnels — ce n'est pas un mot de passe, associez donc cette option à la protection par mot de passe si vous souhaitez contrôler qui peut lire votre documentation. [Domaine personnalisé uniquement →](/fr/deploy/custom-domain-only)

<Update label="Juillet 2026" date="2026-07-29">
**Modifiez votre documentation directement dans le dashboard.** L'éditeur web est désormais disponible pour tous et ne nécessite aucune configuration. Ouvrez **Éditeur** dans la barre latérale pour parcourir votre dépôt connecté, modifier du MDX avec un preview en direct, et valider directement sur votre branche GitHub, ce qui déclenche automatiquement un build. [Éditeur web →](/fr/development/web-editor)

**Corrigez les avertissements de build avec l'IA, depuis le dashboard.** Lorsqu'un build se termine avec des liens rompus ou des pages sans description, une bannière **Corriger avec l'IA** apparaît désormais sur le build, indiquant combien de problèmes peuvent être réparés. Ouvrez-la pour voir le preview de chaque modification proposée (ancres réécrites et descriptions de page suggérées), puis appliquez celles que vous approuvez. Jamdesk les valide sur votre branche GitHub et démarre un nouveau build. Tout ce qu'elle ne peut pas résoudre sans ambiguïté est listé séparément pour que vous le corrigiez manuellement. [Corriger avec l'IA →](/fr/builds/fix-with-ai)

**Membres d'équipe illimités.** Chaque projet inclut désormais un nombre illimité de membres d'équipe sur tous les forfaits, sans frais supplémentaires. La limite précédente de 10 membres et la tarification par siège ont disparu — invitez toute votre équipe.

**Laissez des bots de confiance publier votre documentation.** Les comptes d'automatisation comme Dependabot, Renovate ou un bot de publication CMS ne sont pas des membres Jamdesk, leurs pushs ne déclenchent donc pas de build par défaut. Désormais, lorsqu'un tel compte est refusé, le build affiche un bouton **Autoriser le compte de bot** en un clic. Approuvez-le, et les pushs de ce compte se publient sur votre site en production, comme ceux d'un membre de l'équipe. Seuls les membres du projet peuvent autoriser un compte, et vous pouvez consulter ou révoquer l'accès à tout moment sous **Comptes d'automatisation autorisés** dans les paramètres GitHub de votre projet.

**Votre documentation reçoit un Score IA à chaque build.** Jamdesk évalue désormais la lisibilité de votre documentation publiée par les agents IA — notée selon la norme ouverte AFDocs — automatiquement après chaque build, directement dans le dashboard. Consultez votre score de 0 à 100 et sa note en lettre, suivez son évolution au fil des builds, et obtenez une correction en langage clair pour chaque problème, chacune accompagnée d'un bouton **Copier le prompt de correction** qui transmet le constat à votre agent de codage IA. Activez **Envoyer un e-mail à l'équipe en cas de changement de score** pour être averti dès qu'un build fait évoluer votre note. [Score IA →](/fr/ai/ai-score)
</Update>

**Corrigez automatiquement les liens rompus.** Les avertissements de liens internes rompus dont la cible n'est pas ambiguë — ancres mal orthographiées et dérive d'ancres inter-langues — peuvent désormais être corrigés en une seule commande. Exécutez `jamdesk fix --dry-run` pour prévisualiser les modifications prévues, puis `jamdesk fix` pour les appliquer ; seuls les avertissements dont l'ancre correcte correspond à un titre réel sont modifiés, les cas ambigus étant laissés pour une révision manuelle. [Vue d'ensemble du CLI →](/fr/cli/overview)

**Annoncez tout avec une bannière.** Ajoutez un champ `banner` à votre `docs.json` et une barre de message s'épingle en haut de chaque page — au-dessus de l'en-tête, dans la couleur d'accent de votre thème. Utilisez des liens, du **gras** et de l'*italique* en ligne, et définissez `dismissible: true` pour donner aux lecteurs un bouton de fermeture (elle reste fermée jusqu'à ce que vous changiez le message). [Bannière →](/fr/config/docs-json-reference#banner)

**Affichez la date de dernière mise à jour de chaque page.** Définissez `metadata.timestamp: true` dans votre `docs.json` et chaque page affiche dans son pied de page une ligne du type « Dernière mise à jour le 15 juin 2026 ». La date provient du dernier commit Git ayant modifié la page, elle reste donc exacte à chaque build sans maintenance manuelle des dates. [Métadonnées de page →](/fr/config/docs-json-reference#metadata)

**Personnalisez le style de vos icônes de navigation.** Les icônes de la barre latérale, des groupes, des onglets, des ancres et de la recherche respectent désormais le `style` défini sur un objet icône (`{ "name": "rocket", "style": "duotone" }`) ou un préfixe de style (`duotone/rocket`) — light, thin, duotone, et la famille sharp, pas seulement solid. [Icônes →](/fr/content/icons#forme-objet-de-licône)

**Personnalisez la barre de recherche.** Choisissez votre propre texte d'espace réservé avec `search.prompt`, et sélectionnez les liens rapides que les visiteurs voient dans le panneau de recherche vide avec `search.popularPages` — chacun avec un titre, un slug de page et une icône Font Awesome. [Configuration de la recherche →](/fr/config/docs-json-reference#search)

**Collectez des inscriptions par e-mail sans intégration requise.** Connectez Resend, Mailchimp, Kit, Loops, beehiiv, Brevo ou SendGrid dans **Paramètres → Inscriptions par e-mail**, et un formulaire hébergé par Jamdesk ajoute les lecteurs directement à votre propre audience — votre clé API reste sur notre backend, jamais sur votre site publié. Ajoutez le composant [`EmailSubscribe`](/fr/components/email-subscribe) à n'importe quelle page, ou définissez `placement: changelog` pour ajouter automatiquement un encart d'inscription sur chaque page de changelog. [Inscriptions par e-mail →](/fr/integrations/email-signups)

**Conditionnez l'analytique au consentement aux cookies.** Ajoutez une clé `integrations.cookies` à votre `docs.json` et Jamdesk retient tous les scripts d'analytique et de suivi — Google Analytics, GTM, Plausible, Crisp, JavaScript personnalisé et sa propre analytique intégrée — jusqu'à ce qu'un visiteur consente, en se basant sur un indicateur `localStorage` que votre bannière de consentement définit. Chargez aussi une bannière Osano ou Termly directement depuis `docs.json` ; un court extrait de liaison bascule l'indicateur dès qu'un lecteur accepte, et les scripts se chargent sans rechargement de page. [Consentement aux cookies →](/fr/integrations/cookie-consent)

**llms.txt organisé.** Le fichier `llms.txt` de chaque site suit désormais la structure de llmstxt.org — vos onglets et groupes de navigation deviennent des sections `##`, afin que les agents IA voient votre documentation de la même façon que votre barre latérale l'organise. Les sites multilingues obtiennent un index par langue : le fichier racine liste votre langue par défaut et renvoie vers chaque index traduit (par exemple `/fr/llms.txt`), chacun restant assez petit pour qu'aucun agent ne le tronque. [llms.txt →](/fr/ai/llms-txt)

**Les agents trouvent votre documentation plus vite.** Chaque page porte désormais une directive invisible et silencieuse pour les lecteurs d'écran, qui pointe les agents IA vers `llms.txt` et la version `.md` de la page, et chaque export Markdown s'ouvre par une citation en bloc renvoyant vers l'index. Les agents qui récupèrent votre HTML n'ont plus à deviner qu'un chemin Markdown existe. [Vue d'ensemble de l'IA →](/fr/ai/overview)

**Intégrez votre changelog n'importe où.** Un lanceur « Nouveautés » s'intègre dans votre propre application avec une seule balise `<script>` et ouvre votre changelog Jamdesk dans une fenêtre modale, avec un point de notification non lu par visiteur. Générez l'extrait depuis **Paramètres → Widget Nouveautés**, puis ajustez le mode du lanceur, le coin, la taille de la fenêtre modale et la couleur du point avec des attributs `data-`. Dans votre propre documentation Jamdesk, le composant MDX [`<Widget>`](/fr/components/widget) intègre ce même lanceur en direct dans n'importe quelle page avec une seule balise et sans script. [Intégrer votre changelog →](/fr/development/embed-page)

**Téléchargez vos spécifications API sous forme de zip.** Sur toute page de référence API, le menu Actions IA propose désormais une option **Télécharger la spécification API** qui regroupe toutes les spécifications OpenAPI référencées par votre site — fichiers locaux et URL distantes confondus — dans un seul fichier `api-specs.zip`. Les spécifications multi-fichiers conservent leur structure de dossiers `$ref`, si bien que le téléchargement s'intègre directement à Postman, à un générateur de client, ou à votre propre outillage. [Actions IA →](/fr/ai/ai-actions)

**Spécifications OpenAPI validées au moment du build.** Chaque déploiement valide désormais strictement les spécifications OpenAPI référencées par votre `docs.json` — et signale tout problème sous forme d'**avertissement de build non bloquant** plutôt que de faire échouer le build. Votre documentation se publie quand même ; vous êtes simplement informé précisément de ce qui ne va pas (une erreur d'analyse YAML avec ligne et colonne, un `$ref` non résolu, ou un `operationId` en double) par e-mail et dans la liste des builds du dashboard. En local, `jamdesk dev` s'arrête toujours sur une spécification invalide, afin que vous le remarquiez avant de pousser. [Vue d'ensemble du CLI →](/fr/cli/overview)
</Update>

**Posez une question à l'IA directement depuis la recherche.** Commencez à taper dans la recherche, puis transmettez votre question au chat IA au lieu d'ouvrir un résultat — appuyez sur ⌘/Ctrl+Entrée ou cliquez sur **Demander à l'IA** dans le pied de page de la recherche. La question est ajoutée à votre conversation de chat pour que vous puissiez poursuivre un fil, et un simple Entrée continue de vous emmener vers le premier résultat. [Chat IA →](/fr/ai/chat)

**Copiez les réponses et les transcriptions.** Chaque réponse du chat IA dispose d'un bouton de copie qui récupère la source Markdown, et une action **Copier la transcription** dans l'en-tête du chat copie toute la conversation en Markdown avec les rôles indiqués — pratique pour coller dans un ticket ou un document. [Chat IA →](/fr/ai/chat)

**Défilement automatique du chat plus intelligent.** Le chat ne suit une réponse en streaming que si vous êtes déjà en bas. Remontez pour relire une réponse précédente et il reste en place au lieu de vous ramener vers le bas ; redescendez tout en bas et il se réépingle.

**CSS personnalisé en preview local (CLI).** `jamdesk dev` applique votre CSS personnalisé de la même façon que le build publié, ce qui vous permet de vérifier le style avant de déployer. Placez n'importe quel fichier `.css` à la racine de votre projet — `style.css`, ou plusieurs fichiers combinés par ordre alphabétique — et il se charge au rechargement du navigateur. Aucune entrée `docs.json` n'est nécessaire, à l'image de la façon dont Mintlify inclut les feuilles de style à la racine. [CSS personnalisé →](/fr/customization/custom-css)

**Aperçus sociaux personnalisés depuis le frontmatter.** Définissez n'importe quelle balise meta Open Graph ou Twitter/X directement dans le frontmatter d'une page — `og:title`, `og:description`, `og:image`, `twitter:card`, `keywords`, et l'ensemble complet des balises meta. Utilisez des clés de premier niveau à plat ou un bloc `seo:` imbriqué ; les deux fonctionnent, et les valeurs par page remplacent les valeurs par défaut de votre `docs.json`. [SEO →](/fr/content/seo)

**Pages masquées.** Gardez les brouillons, les manuels internes ou les guides obsolètes hors de votre barre latérale et des résultats de recherche sans les supprimer. Ajoutez `hidden: true` au frontmatter d'une page, ou à un groupe ou un onglet dans `docs.json`. Les pages masquées restent accessibles par URL directe mais disparaissent de la navigation, du sitemap, de la recherche sur site et du contexte IA — et reçoivent automatiquement une balise `noindex`. Besoin d'un groupe masqué dont les pages sont quand même indexées dans la recherche ? Ajoutez `searchable: true` à côté de `hidden`. [Pages masquées →](/fr/content/hidden-pages)

**Décorations grille et fenêtres.** Deux nouveaux motifs d'arrière-plan rejoignent le dégradé par défaut du thème Jam. Définissez `background.decoration` sur `"grid"` pour une subtile grille de points de 24 px, ou sur `"windows"` pour deux taches givrées façon Windows 11 dans les coins supérieurs. Le dégradé et le remplissage uni `"none"` fonctionnent toujours comme avant — choisissez le style qui correspond à votre marque. [Arrière-plan →](/fr/customization/background)

**Personnalisation de l'arrière-plan.** Un nouveau bloc `background` dans `docs.json` désactive le dégradé du mode clair de Jam, remplace la couleur de page par mode, ou ajuste la couleur, la taille, la position et l'opacité du dégradé. Aucun CSS personnalisé n'est nécessaire. [Arrière-plan →](/fr/customization/background)

**Diagrammes D2.** Un second langage de diagramme rejoint Mermaid. Étiquetez un bloc de code délimité `d2` et Jamdesk le restitue sous forme de SVG au moment du build, avec les thèmes clair et sombre intégrés. Même workflow que Mermaid — choisissez le langage qui convient au diagramme que vous dessinez. [Diagrammes D2 →](/fr/components/d2)

**Résultats de recherche regroupés.** La recherche ne répète plus la même page pour chaque section correspondante. Les résultats se regroupent sous leur page parente dans la fenêtre modale de recherche, avec jusqu'à trois sections visibles par défaut et un bouton d'expansion en ligne pour le reste. La mise en évidence des extraits reste inchangée — vous trouvez la bonne section en moins de balayages.

**Détection automatique de `docs.json` à la connexion.** La connexion d'un dépôt GitHub trouve votre `docs.json` où qu'il se trouve. Le flux de connexion analyse toute l'arborescence et signale un `mint.json` Mintlify s'il en trouve un à la place. Les monorepos et les configurations imbriquées fonctionnent sans configuration manuelle. [Connexion à GitHub →](/fr/setup/connecting-github)

**Indications sur l'emplacement de `docs.json` dans le CLI.** Les configurations mal placées sont plus faciles à repérer. `jamdesk validate`, `jamdesk dev` et `jamdesk doctor` indiquent où se trouve réellement votre `docs.json` — ou où il devrait se trouver — au lieu d'une erreur générique « introuvable ». Corrigez le problème en quelques secondes au lieu de décoder une stack trace. [Vue d'ensemble du CLI →](/fr/cli/overview)

**Hreflang conforme aux standards.** Les balises hreflang émettent désormais des codes BCP 47 valides. Les dossiers de locale comme `cn`, `jp` et `ja-jp` sont associés aux codes réellement attendus par les moteurs de recherche (`zh`, `ja`), avec des URL de sitemap échappées en XML. Chaque page localisée se positionne dans sa propre région au lieu d'être traitée comme un contenu dupliqué. [Langues →](/fr/setup/languages)
</Update>

**Export PDF.** Générez tout votre site de documentation en un seul [PDF](/fr/builds/pdf-export) depuis **Paramètres → Exports PDF** dans le dashboard. Réservé aux forfaits payants. Les projets multilingues choisissent une locale par export, les résultats sont mis en cache par commit, et vous recevez un e-mail avec un lien de téléchargement une fois le rendu terminé.

**Spécifications OpenAPI multilingues.** Les pages d'endpoint affichent des spécifications OpenAPI traduites en même temps que le MDX traduit. Placez un fichier `<spec>.<lang>.<ext>` (par exemple `openapi/api.fr.yaml`) à côté de votre spécification source, et Jamdesk l'utilise sur les URL de cette langue, avec repli sur la spécification anglaise lorsqu'une variante linguistique est manquante. Les résumés d'opération, les descriptions de paramètres, les descriptions de réponse et les descriptions de schéma sont tous localisés. Configuration : [Traduire les spécifications OpenAPI](/fr/setup/languages#traduction-des-specs-openapi).

**Composant Visibility.** Le nouveau composant [`<Visibility for="humans|agents">`](/fr/components/visibility) vous permet de réserver du contenu aux lecteurs humains ou aux agents IA sur une même page. Les blocs réservés aux humains s'affichent dans le navigateur mais sont retirés des exports `.md` et de `llms-full.txt` ; les blocs réservés aux agents font l'inverse. Les agents qui demandent `Accept: text/markdown` sur les URL canoniques reçoivent automatiquement la vue agent.

**Protection par mot de passe, reconstruite.** Verrouillez tout votre site derrière un mot de passe partagé, ou ne protégez qu'une poignée de pages en laissant le reste public. Définissez `auth.password.enabled: true` pour le mode site entier, ou marquez des pages individuelles avec `private: true` dans le frontmatter (ou listez-les sous `auth.password.private`) pour le mode pages spécifiques. La page Paramètres du dashboard vous guide pour définir, faire tourner et révoquer le mot de passe. Les visiteurs arrivent sur un écran de déverrouillage à votre image, avec le logo de votre site, sa couleur principale, et un indice optionnel que vous définissez dans `docs.json`. Guide de configuration : [Protection par mot de passe](/fr/setup/password-protection).

**Conversion automatique des images en WebP.** Jamdesk peut convertir vos images PNG et JPG en WebP au moment du build. Les fichiers convertis sont généralement 60 à 80 % plus légers que les originaux, sans perte de qualité visible, donc vos pages se chargent plus vite sans aucun traitement d'image manuel. Activez cette option via `images.convertToWebp: true` dans `docs.json`. Les favicons, `og:image` et `twitter:image` conservent leur format d'origine pour rester compatibles avec les robots des réseaux sociaux. Une nouvelle étape **Optimisation des images** affiche la progression en direct dans le dashboard et le CLI à chaque build. [Conversion automatique des images →](/fr/builds/image-optimization)

**API Playground.** Les pages d'endpoint disposent désormais d'un [bouton « Essayer »](/fr/api-reference/playground) interactif. Renseignez les paramètres, observez les exemples de code se mettre à jour en temps réel, et envoyez des requêtes en direct sans quitter votre documentation. Activé par défaut sur toutes les pages API. Fonctionne aussi bien avec les endpoints OpenAPI qu'avec les endpoints rédigés en MDX.

**Plugin Claude Code.** Installez le [plugin Jamdesk pour Claude Code](/fr/claude-code-plugin) pour donner à Claude une connaissance approfondie des composants MDX, de la configuration `docs.json`, des schémas de navigation et des commandes CLI. Installation en deux étapes depuis la marketplace de plugins. Se combine avec [CLAUDE.md](/fr/ai/claude-code) et le [serveur MCP](/fr/ai/mcp-server) pour la rédaction de documentation assistée par IA.

**Avertissements de build pour l'image de marque manquante.** Les builds signalent désormais lorsque les chemins `favicon` ou `logo` dans `docs.json` référencent des fichiers absents de votre projet. Les avertissements apparaissent dans les détails de build du dashboard et dans le CLI via `jamdesk dev` et `jamdesk validate`. Aucun e-mail n'est envoyé ; l'avertissement est purement informatif.

**YouTube Shorts.** Le [composant `<YouTube>`](/fr/content/youtube#youtube-shorts) prend en charge les Shorts verticaux via la prop `short`, en affichant un lecteur centré au format 9:16 sans bandes noires. Utilisez `<YouTube id="VIDEO_ID" short />`.
</Update>

**Menu Actions IA.** Un [menu déroulant présent sur chaque page](/fr/ai/ai-actions) permet aux lecteurs de copier le Markdown, d'ouvrir la page dans ChatGPT/Claude/Perplexity, de récupérer la configuration du serveur MCP, ou de l'installer en un clic dans Cursor ou VS Code. Activé par défaut ; choisissez les options affichées via `contextual` dans `docs.json`.

**Analytique.** Une analytique de page sans cookies qui suit les vues, les sources de trafic et les tendances des visiteurs, avec une [répartition par page](/fr/setup/project-analytics). Aucune bannière de consentement n'est nécessaire. Vue d'ensemble : [Analytique](/fr/setup/analytics-overview).

**Intégrations.** [Google Analytics 4](/fr/integrations/google-analytics), [Google Tag Manager](/fr/integrations/google-tag-manager), [Plausible Analytics](/fr/integrations/plausible-analytics), et [notifications de build Slack](/fr/integrations/slack) (Pro).

**Flux RSS pour les changelogs.** Les pages avec `rss: true` dans le frontmatter génèrent désormais automatiquement un flux RSS auquel s'abonner. Une icône RSS apparaît à côté du titre de la page, et un fichier `feed.xml` est construit à partir de vos composants [Update](/fr/components/update#flux-rss) à chaque build. Utilisez la nouvelle prop `date` sur Update pour des dates de flux correctes.

**Connexion et déploiement CLI.** [`jamdesk login`](/fr/cli/authentication) authentifie via le navigateur. [`jamdesk deploy`](/fr/cli/deploy) empaquette votre projet et déclenche un build depuis le terminal. Aucune connexion GitHub n'est requise. Le CLI respecte `.gitignore`, avertit en cas de fichiers secrets, et diffuse la progression du build en direct.

**Vérification orthographique CLI.** `jamdesk spellcheck` vérifie les erreurs d'orthographe dans votre documentation avec plus de 180 termes techniques intégrés (anglais uniquement). `jamdesk spellcheck --fix` lance un mode interactif pour corriger les fautes de frappe ou ajouter des mots à votre liste d'exclusion.

**Intégrations vidéo.** Intégrez des fichiers `.mp4` et `.webm` directement dans votre documentation. Placez-les dans un répertoire `/videos` et utilisez la syntaxe markdown (`![Demo](/videos/demo.mp4)`) ou le [composant `<Video>`](/fr/content/videos) pour la lecture automatique, la boucle et d'autres contrôles.
