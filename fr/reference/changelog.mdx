<Update label="Septembre 2026" date="2026-09-23">
**Un llms-full.txt par langue.** Les sites multilingues publient désormais un fichier de contenu complet pour chaque langue, à côté de son index, comme `/fr/llms-full.txt` pour le français et `/en/llms-full.txt` pour votre langue par défaut. L'index de votre langue par défaut répond à la fois à `/en/llms.txt` et à `/llms.txt`, si bien que chaque langue suit le même modèle d'URL. Un agent peut charger uniquement la langue dont il a besoin, plutôt que toutes les pages dans toutes les langues. Le fichier racine `/llms-full.txt` contient toujours toutes les langues, donc les outils qui le lisent déjà ne voient aucun changement. Les sites monolingues restent inchangés. [llms.txt →](/fr/ai/llms-txt#sites-multilingues)

**Envoyez vos lecteurs directement vers leur propre langue.** Définissez `"localization": { "autoRedirect": true }` dans `docs.json` et un visiteur venu pour la première fois, dont le navigateur demande le français, arrive sur `/fr` au lieu de votre langue par défaut. Son choix est conservé pendant un an, et le fait de choisir une langue dans le sélecteur le remplace. Seule la racine de votre site est jamais redirigée : une URL de langue comme `/fr` et un lien profond comme `/guides/authentication` s'ouvrent tous deux exactement comme demandé, pour tout le monde, si bien qu'un lien que vous collez dans un ticket ouvre la même page pour la personne qui clique dessus. Les robots d'indexation ne sont eux non plus jamais redirigés, donc vos balises `hreflang` continuent de décider ce qui est indexé. Désactivé par défaut ; nécessite au moins deux langues configurées. [Routage automatique des langues →](/fr/setup/languages)

**Redéfinissez la date de « dernière mise à jour » d'une page.** Le `metadata.timestamp` de `docs.json` affiche déjà une ligne « Dernière mise à jour le … » construite à partir du dernier commit Git de la page. Ajoutez `lastUpdatedDate: "2026-09-01"` au frontmatter d'une page et cette date remplace celle du commit dans le pied de page. Elle alimente aussi le `<lastmod>` de votre sitemap et le `dateModified` des données structurées de la page, que le pied de page soit affiché ou non, afin que les moteurs de recherche et les assistants IA voient la même date que vos lecteurs. Utile après avoir relu une page, ou lorsqu'un commit de mise en forme a déplacé la date sans rien changer qu'un lecteur remarquerait. [Frontmatter →](/fr/content/frontmatter)

**Désactivez le bouton de copie d'un bloc de code.** Ajoutez `nocopy` à la balise de code et ce bloc perd son bouton de copie tandis que tous les autres le conservent ; cela se combine avec un titre et toutes les autres options de bloc, et fonctionne par onglet à l'intérieur d'un `<CodeGroup>`. Utilisez-le pour les transcriptions de terminal, les exemples caviardés et les extraits « ne faites pas ça » — partout où copier le texte affiché donnerait au lecteur quelque chose qui ne fonctionne pas. [Blocs de code →](/fr/content/code-blocks)

**Connectez un dépôt Bitbucket Cloud.** Jamdesk crée désormais des builds et déploie depuis Bitbucket Cloud comme depuis GitHub. Choisissez **Bitbucket** lorsque vous connectez le dépôt d'un projet, connectez-vous une fois, et Jamdesk crée un dépôt de documentation de démarrage dans votre espace de travail, ou connecte le dépôt et la branche que vous indiquez, puis lance un build à chaque push. Comme Bitbucket ne retente pas la livraison d'un webhook en échec, Jamdesk vérifie aussi votre branche toutes les cinq minutes, si bien qu'une livraison perdue finit quand même par déclencher un build ; l'éditeur web, Fix with AI et la traduction par IA restent pour l'instant réservés à GitHub. [Connecter Bitbucket →](/fr/setup/connecting-bitbucket)

**Connectez vos lecteurs avec votre propre système de connexion.** L'authentification JWT protège un site de documentation derrière le système de connexion que vous utilisez déjà, pour que personne n'ait à saisir un mot de passe partagé. Activez `auth.jwt` dans `docs.json`, générez une clé de signature Ed25519 dans **Settings**, et faites signer par votre backend un jeton de courte durée lorsqu'un utilisateur ouvre la documentation. Jamdesk le vérifie et démarre une session par utilisateur pouvant durer jusqu'à 30 jours. Ajoutez `groups: ["admin"]` à une page et seuls les visiteurs dont le jeton porte ce groupe pourront l'ouvrir ou la voir dans la barre latérale ; tous les autres obtiennent une 404. Les chemins publics, le `public: true` du frontmatter et les groupes de navigation publics laissent un journal des modifications ou une page de statut ouverts. Vous pouvez aussi préremplir le playground de l'API avec les identifiants du visiteur extraits du jeton. Inclus dans toutes les offres, et vous pouvez migrer depuis la protection par mot de passe sans aucune interruption de couverture. [Authentification JWT →](/fr/setup/jwt-authentication)

**La racine du site exporte aussi du Markdown.** Récupérez la racine de votre documentation, ou une racine de langue comme `/fr`, avec `Accept: text/markdown` ou via `/index.md`, et vous obtenez la première page de cette navigation, la même page que montre la racine HTML. Les sites sans `index.mdx` renvoyaient auparavant une 404 ici, ce qui cassait la première requête que font la plupart des agents. [Source Markdown →](/fr/ai/markdown-source#racine-du-site-et-racines-de-langue)
</Update>

**Jamdesk traduit votre documentation en 27 langues.** Cochez les langues que vous voulez, jusqu'à cinq par projet, dans **Settings → Translations**, et après chaque build, les pages traduites sont validées par un commit dans votre dépôt GitHub. Les builds suivants ne retraduisent que les pages dont la source anglaise a changé. Les traductions que vous aviez déjà, ou que vous avez modifiées à la main, sont conservées jusqu'à ce que vous cliquiez sur **Replace with AI translation**. Inclus dans toutes les offres. [Traduction par IA →](/fr/setup/ai-translation)

**Choisissez votre propre URL de documentation.** L'hébergement en sous-chemin n'est plus limité à `/docs`. Saisissez un seul segment, comme `help` ou `guide`, dans le champ de sous-chemin de la carte Custom Domain, puis enregistrez. `/docs` continue de fonctionner, les URL canoniques basculent immédiatement vers le nouveau chemin, et l'ancien sous-chemin personnalisé redirige vers le nouveau pour un seul renommage, ce qui vous permet de mettre à jour votre proxy à votre propre rythme. [Hébergement en sous-chemin →](/fr/deploy/subpath-hosting)

**Fix with AI, encore plus rapide.** Ouvrir l'aperçu des correctifs depuis la bannière de build se termine plus vite, y compris sur les grands sites, et le rouvrir est quasi instantané car Jamdesk conserve les résultats de l'analyse tant que votre documentation n'a pas changé. Le déroulé reste le même : passez en revue chaque modification proposée, appliquez celles que vous approuvez, et Jamdesk les valide par un commit et relance un build. [Fix with AI →](/fr/builds/fix-with-ai)

**Un quatrième thème : Halo.** Définissez `"theme": "halo"` dans `docs.json` pour un rendu chaleureux et arrondi : la police Figtree, un fond sable avec le contenu surélevé sur une carte, et les plus grands rayons d'angle de tous les thèmes intégrés. Les couleurs personnalisées, les polices et les surcharges CSS fonctionnent de la même façon que sur Jam, Nebula et Pulsar. [Thèmes →](/fr/customization/theming)

**Servez votre documentation uniquement depuis votre propre domaine.** Activez **Custom domain only** dans la carte Custom Domain et une visite directe à `YOUR_SLUG.jamdesk.app` renvoie une 404, tandis que votre CNAME ou votre proxy continuent de fonctionner. Jamdesk vérifie votre domaine actif avant d'activer le bouton, et si votre DNS tombe en panne, le sous-domaine recommence à servir jusqu'à ce qu'il soit rétabli. Cela masque le sous-domaine aux visiteurs directs mais ne contrôle pas qui peut lire votre documentation ; associez-le à la protection par mot de passe pour cela. [Domaine personnalisé uniquement →](/fr/deploy/custom-domain-only)

**Construisez toute votre référence API à partir d'une spécification.** Pointez un onglet de navigation vers votre fichier OpenAPI avec `"openapi": { "source": "/openapi/api.yaml", "generate": true }` et chaque build crée une page par opération, regroupées dans la barre latérale par tag. Une page d'endpoint commitée conserve son slug, ce qui vous permet de migrer une page à la fois, et un chemin renommé redirige depuis son ancienne URL au lieu de renvoyer une 404. [Pages API générées →](/fr/config/docs-json-reference#openapi)

**Les lecteurs choisissent le serveur d'API qu'ils regardent.** Un endpoint dont la spécification liste plus d'une entrée `servers` affiche un sélecteur à côté de son URL. Choisir sandbox change l'URL de base, le bouton de copie, chaque exemple de code et la requête envoyée par le playground, pour que personne ne copie un `curl` de production depuis votre documentation sandbox. Les endpoints à serveur unique restent inchangés. [Playground de l'API →](/fr/api-reference/playground#serveurs-multiples)

**Le Markdown s'affiche dans toutes les descriptions OpenAPI.** Les tableaux, les listes, les liens, le `code` et le **gras** s'affichent désormais de la même façon dans les descriptions de paramètre, de corps de requête, de réponse et de schéma que dans la description de l'opération. Neuf emplacements étaient auparavant incohérents, et ils partagent désormais tous le même moteur de rendu. [Exemple OpenAPI →](/fr/api-reference/openapi-example)

**Les exports Markdown des endpoints incluent l'authentification.** Récupérez la version `.md` d'une page de référence API et elle se termine par une section `## Authentication` listant les schémas dont l'opération a besoin : type, nom d'en-tête, format du bearer, scopes OAuth 2, et quelles combinaisons sont valides. Un agent qui lit l'export peut construire une requête fonctionnelle sans ouvrir votre spécification. [Source Markdown →](/fr/ai/markdown-source#ce-quexporte-une-page-endpoint)

**Gardez une page hors de la recherche sans la masquer.** Ajoutez `search: false` au frontmatter d'une page et elle disparaît de la recherche du site, des réponses du chat IA et du serveur MCP, tout en restant dans votre barre latérale, votre sitemap et votre llms.txt. Utilisez-le pour une page remplacée que vous voulez pouvoir encore lier et indexer. Les pages masquées et non indexées sont désormais elles aussi écartées des réponses IA, ce qui n'était pas le cas avant. [Garder une page hors de la recherche uniquement →](/fr/content/hidden-pages#exclure-une-page-uniquement-de-la-recherche)

**`jamdesk validate` signale la configuration qui ne fait rien.** Certaines clés de `docs.json` étaient acceptées sans jamais être rendues, `asyncapi` en tête, si bien qu'une configuration semblait prise en charge jusqu'à ce que vous construisiez le site et ne trouviez rien. La commande les nomme, ainsi que les entrées `api.mdx.server` au-delà de la première, qui ont toujours été ignorées. [Aperçu du CLI →](/fr/cli/overview)

</Update>

**Modifiez votre documentation directement dans le dashboard.** L'éditeur web est désormais disponible pour tout le monde et ne nécessite aucune configuration. Ouvrez **Editor** dans la barre latérale pour parcourir votre dépôt connecté, modifier du MDX avec un aperçu en direct, et valider directement sur votre branche GitHub par un commit, ce qui déclenche automatiquement un build. [Éditeur web →](/fr/development/web-editor)

**Corrigez les avertissements de build avec l'IA, depuis le dashboard.** Lorsqu'un build se termine avec des liens cassés ou des pages sans description, une bannière **Fix with AI** apparaît désormais sur le build, indiquant combien de problèmes peuvent être corrigés. Ouvrez-la pour prévisualiser chaque modification proposée (ancres réécrites et descriptions de page suggérées), puis appliquez celles que vous approuvez. Jamdesk les valide par un commit sur votre branche GitHub et démarre un nouveau build. Tout ce qui ne peut pas être résolu sans ambiguïté est listé séparément pour que vous le corrigiez à la main. [Fix with AI →](/fr/builds/fix-with-ai)

**Membres d'équipe illimités.** Chaque projet inclut désormais un nombre illimité de membres d'équipe sur toutes les offres, sans coût supplémentaire. La limite précédente de 10 membres et la tarification par siège ont disparu — invitez toute votre équipe.

**Laissez des bots de confiance publier votre documentation.** Les comptes d'automatisation comme Dependabot, Renovate ou un bot de publication CMS ne sont pas des membres Jamdesk, donc leurs push ne déclenchent pas de build par défaut. Désormais, quand l'un d'eux est refusé, le build affiche un bouton **Authorize Bot Account** en un clic. Approuvez-le, et les push de ce compte publient sur votre site en production, comme ceux d'un membre de l'équipe. Seuls les membres du projet peuvent autoriser un compte, et vous pouvez consulter ou révoquer l'accès à tout moment sous **Allowed automation accounts** dans les paramètres GitHub de votre projet.

**Votre documentation reçoit un score IA à chaque build.** Jamdesk évalue désormais la capacité des agents IA à lire votre documentation publiée — noté selon la norme ouverte AFDocs — automatiquement après chaque build, directement dans le dashboard. Consultez votre score de 0 à 100 et sa note en lettre, suivez son évolution build après build, et obtenez une correction en langage clair pour chaque problème, chacune avec un bouton **Copy prompt to fix** qui transmet le constat à votre agent de codage IA. Activez **Email team when score changes** pour être informé quand un build fait bouger votre score de façon significative. [Score IA →](/fr/ai/ai-score)
</Update>

**Corrigez automatiquement les liens cassés.** Les avertissements de lien interne cassé avec une cible non ambiguë — ancres mal orthographiées et dérive d'ancre entre langues — peuvent désormais être corrigés d'une seule commande. Lancez `jamdesk fix --dry-run` pour prévisualiser les changements prévus, puis `jamdesk fix` pour les appliquer ; seuls les avertissements dont l'ancre correcte correspond à un titre réel sont modifiés, laissant les cas ambigus pour une relecture manuelle. [Aperçu du CLI →](/fr/cli/overview)

**Annoncez n'importe quoi avec une bannière.** Ajoutez un `banner` à votre `docs.json` et une barre de message s'épingle en haut de chaque page — au-dessus de l'en-tête, dans la couleur d'accent de votre thème. Utilisez des liens, du **gras** et de l'*italique* en ligne, et définissez `dismissible: true` pour donner aux lecteurs un bouton de fermeture (elle reste fermée jusqu'à ce que vous changiez le message). [Bannière →](/fr/config/docs-json-reference#banner)

**Affichez la date de dernière mise à jour de chaque page.** Définissez `metadata.timestamp: true` dans votre `docs.json` et chaque page reçoit dans son pied de page une ligne du type « Dernière mise à jour le 15 juin 2026 ». La date provient du dernier commit Git ayant modifié la page, donc elle reste exacte à chaque build sans maintenance manuelle des dates. [Métadonnées de page →](/fr/config/docs-json-reference#metadata)

**Personnalisez vos icônes de navigation.** Les icônes de la barre latérale, des groupes, des onglets, des ancres et de la recherche respectent désormais le `style` défini sur un objet icône (`{ "name": "rocket", "style": "duotone" }`) ou un préfixe de style (`duotone/rocket`) — light, thin, duotone et la famille sharp, pas seulement solid. [Icônes →](/fr/content/icons#forme-objet-de-licône)

**Personnalisez la barre de recherche.** Choisissez votre propre texte d'espace réservé avec `search.prompt`, et composez les liens rapides que voient les visiteurs dans le panneau de recherche vide avec `search.popularPages` — chacun avec un titre, un slug de page et une icône Font Awesome. [Configuration de la recherche →](/fr/config/docs-json-reference#search)

**Collectez des inscriptions par e-mail sans intégration requise.** Connectez Resend, Mailchimp, Kit, Loops, beehiiv, Brevo ou SendGrid dans **Integrations → Email Signups**, et un formulaire hébergé par Jamdesk ajoute les lecteurs directement à votre propre audience — votre clé API reste sur notre backend, jamais dans votre site publié. Ajoutez le composant [`EmailSubscribe`](/fr/components/email-subscribe) à n'importe quelle page, ou définissez `placement: changelog` pour ajouter automatiquement un encart d'inscription sur chaque page de journal des modifications. [Inscriptions par e-mail →](/fr/integrations/email-signups)

**Bloquez l'analytique derrière le consentement aux cookies.** Ajoutez une clé `integrations.cookies` à votre `docs.json` et Jamdesk retient chaque script d'analytique et de suivi — Google Analytics, GTM, Plausible, Crisp, JavaScript personnalisé et son propre outil d'analytique intégré — jusqu'à ce qu'un visiteur consente, une valeur lue depuis un indicateur `localStorage` que votre bannière de consentement définit. Chargez aussi une bannière Osano ou Termly directement depuis `docs.json` ; un court script passerelle bascule l'indicateur dès qu'un lecteur accepte, et les scripts se chargent sans recharger la page. [Consentement aux cookies →](/fr/integrations/cookie-consent)

**llms.txt, organisé.** Le `llms.txt` de chaque site suit désormais la structure de llmstxt.org — vos onglets et groupes de navigation deviennent des sections `##`, si bien que les agents IA voient votre documentation comme votre barre latérale l'organise. Les sites multilingues obtiennent un index par langue : le fichier racine liste votre langue par défaut et renvoie vers chaque index traduit (par exemple `/fr/llms.txt`), en gardant chacun assez petit pour qu'aucun agent ne le tronque. [llms.txt →](/fr/ai/llms-txt)

**Les agents trouvent votre documentation plus vite.** Chaque page porte désormais une directive invisible, silencieuse pour les lecteurs d'écran, qui pointe les agents IA vers `llms.txt` et la version `.md` de la page, et chaque export Markdown s'ouvre par une citation renvoyant vers l'index. Les agents qui récupèrent votre HTML n'ont plus à deviner qu'un chemin Markdown existe. [Aperçu IA →](/fr/ai/overview)

**Intégrez votre journal des modifications n'importe où.** Un lanceur « Quoi de neuf ? » s'ajoute à votre propre application avec une seule balise `<script>` et ouvre votre journal des modifications Jamdesk dans une fenêtre modale, avec un point de notification non lu par visiteur. Générez l'extrait depuis **Integrations → What's New widget**, puis ajustez le mode du lanceur, le coin, la taille de la modale et la couleur du point avec des attributs `data-`. Dans votre propre documentation Jamdesk, le composant MDX [`<Widget>`](/fr/components/widget) place ce même lanceur en direct sur n'importe quelle page avec une seule balise et sans script. [Intégrer votre journal des modifications →](/fr/development/embed-page)

**Téléchargez vos spécifications API sous forme de zip.** Sur n'importe quelle page de référence API, le menu AI Actions propose désormais une option **Download API spec** qui regroupe chaque spécification OpenAPI référencée par votre site — fichiers locaux et URL distantes confondus — dans un unique `api-specs.zip`. Les spécifications multi-fichiers conservent leur arborescence de `$ref`, si bien que le téléchargement s'importe directement dans Postman, un générateur de client ou votre propre outillage. [AI Actions →](/fr/ai/ai-actions)

**Les spécifications OpenAPI sont validées au moment du build.** Chaque déploiement valide désormais strictement les spécifications OpenAPI référencées par votre `docs.json` — et signale tout problème comme un **avertissement de build non bloquant** au lieu de faire échouer le build. Votre documentation est quand même publiée ; vous êtes simplement informé précisément de ce qui ne va pas (une erreur d'analyse YAML avec ligne et colonne, un `$ref` non résolu, ou un `operationId` en double) par e-mail et dans la liste des builds du dashboard. En local, `jamdesk dev` s'arrête toujours sur une spécification invalide, pour que vous le remarquiez avant de pousser. [Aperçu du CLI →](/fr/cli/overview)

**Posez une question à l'IA directement depuis la recherche.** Commencez à taper dans la recherche, puis transmettez votre question au chat IA au lieu d'ouvrir un résultat — appuyez sur ⌘/Ctrl+Entrée ou cliquez sur **Ask AI** dans le pied de la recherche. La question est ajoutée à votre conversation de chat pour que vous puissiez garder un fil, et un simple Entrée continue de sauter au premier résultat. [Chat IA →](/fr/ai/chat)

**Copiez les réponses et les transcriptions.** Chaque réponse du chat IA a un bouton de copie qui récupère la source Markdown, et une action **Copy transcript** dans l'en-tête du chat copie toute la conversation en Markdown avec le rôle de chaque intervenant — pratique pour la coller dans un ticket ou une documentation. [Chat IA →](/fr/ai/chat)

**Défilement automatique du chat plus intelligent.** Le chat ne suit une réponse en streaming que si vous êtes déjà en bas. Remontez pour relire une réponse précédente et il reste en place au lieu de vous ramener en bas de force ; redescendez tout en bas et il se réépingle.

**CSS personnalisé en aperçu local (CLI).** `jamdesk dev` applique votre CSS personnalisé de la même façon que le build publié, pour que vous puissiez vérifier le style avant de déployer. Déposez n'importe quel fichier `.css` à la racine de votre projet — `style.css`, ou plusieurs combinés par ordre alphabétique — et il se charge au rafraîchissement du navigateur. Aucune entrée `docs.json` n'est nécessaire, comme Mintlify le fait pour les feuilles de style à la racine. [CSS personnalisé →](/fr/customization/custom-css)

**Aperçus sociaux personnalisés depuis le frontmatter.** Définissez n'importe quelle balise meta Open Graph ou Twitter/X directement dans le frontmatter d'une page — `og:title`, `og:description`, `og:image`, `twitter:card`, `keywords`, et l'ensemble complet des balises meta. Utilisez des clés plates de premier niveau ou un bloc `seo:` imbriqué ; les deux fonctionnent, et les valeurs par page surchargent les valeurs par défaut de votre `docs.json`. [SEO →](/fr/content/seo)

**Pages masquées.** Gardez des brouillons, des manuels internes ou des guides obsolètes hors de votre barre latérale et des résultats de recherche sans les supprimer. Ajoutez `hidden: true` au frontmatter d'une page, ou à un groupe ou un onglet dans `docs.json`. Les pages masquées restent accessibles par URL directe mais disparaissent de la navigation, du sitemap, de la recherche sur site et du contexte IA — et reçoivent automatiquement une balise `noindex`. Besoin d'un groupe masqué dont les pages se classent quand même dans la recherche ? Ajoutez `searchable: true` en plus de `hidden`. [Pages masquées →](/fr/content/hidden-pages)

**Décorations grille et fenêtres.** Deux nouveaux motifs de fond rejoignent le dégradé par défaut du thème Jam. Définissez `background.decoration` sur `"grid"` pour une subtile grille de points de 24 px, ou sur `"windows"` pour deux taches givrées façon Windows 11 dans les coins supérieurs. Le dégradé et le remplissage uni `"none"` fonctionnent toujours comme avant — choisissez le rendu qui correspond à votre marque. [Arrière-plan →](/fr/customization/background)

**Personnalisation de l'arrière-plan.** Un nouveau bloc `background` dans `docs.json` désactive le dégradé du mode clair de Jam, redéfinit la couleur de page par mode, ou ajuste la couleur, la taille, la position et l'opacité du dégradé. Aucun CSS personnalisé n'est nécessaire. [Arrière-plan →](/fr/customization/background)

**Diagrammes D2.** Un deuxième langage de diagrammes rejoint Mermaid. Balisez un bloc de code `d2` et Jamdesk le rend en SVG au moment du build, avec les thèmes clair et sombre intégrés. Même flux de travail que Mermaid — choisissez le langage qui convient au diagramme que vous dessinez. [Diagrammes D2 →](/fr/components/d2)

**Résultats de recherche regroupés.** La recherche ne répète plus la même page pour chaque section correspondante. Les résultats se regroupent sous leur page parente dans la fenêtre de recherche, avec jusqu'à trois sections visibles par défaut et un élément dépliant en ligne pour le reste. La mise en évidence des extraits reste en place — vous trouvez la bonne section en moins de passages.

**Détection automatique de `docs.json` à la connexion.** Connecter un dépôt GitHub trouve votre `docs.json` où qu'il se trouve. Le flux de connexion scanne tout l'arbre et signale un `mint.json` Mintlify s'il en trouve un à la place. Les monorepos et les configurations imbriquées fonctionnent sans configuration manuelle. [Connexion à GitHub →](/fr/setup/connecting-github)

**Indices d'emplacement de `docs.json` dans le CLI.** Les configurations mal placées sont plus faciles à repérer. `jamdesk validate`, `jamdesk dev` et `jamdesk doctor` indiquent où se trouve réellement votre `docs.json` — ou où il devrait aller — au lieu d'une erreur générique « introuvable ». Corrigez-le en quelques secondes au lieu de décoder une trace d'erreur. [Aperçu du CLI →](/fr/cli/overview)

**Hreflang conforme aux standards.** Les balises hreflang émettent désormais des codes BCP 47 valides. Les dossiers de locale comme `cn`, `jp` et `ja-jp` sont associés aux codes que les moteurs de recherche attendent réellement (`zh`, `ja`), avec des URL de sitemap correctement échappées en XML. Chaque page localisée se classe dans sa propre région au lieu d'être traitée comme un contenu dupliqué. [Langues →](/fr/setup/languages)

**Composant Visibility.** Le nouveau composant [`<Visibility for="humans|agents">`](/fr/components/visibility) permet de réserver du contenu aux lecteurs humains ou aux agents IA sur une même page. **Protection par mot de passe, reconstruite.** Verrouillez tout votre site derrière un mot de passe partagé, ou protégez seulement quelques pages en laissant le reste public. La page Settings du dashboard vous guide pour définir, faire tourner et révoquer le mot de passe. Les visiteurs arrivent sur un écran de déverrouillage à votre image, avec le logo de votre site, sa couleur principale et un indice optionnel que vous définissez dans `docs.json`. Guide de configuration : [Protection par mot de passe](/fr/setup/password-protection).

**Conversion automatique des images en WebP.** Jamdesk peut convertir vos images PNG et JPG en WebP au moment du build. Les fichiers convertis sont généralement 60 à 80 % plus légers que les originaux sans perte de qualité visible, si bien que vos pages se chargent plus vite sans aucun traitement d'image manuel. Activez-le via `images.convertToWebp: true` dans `docs.json`. Les favicons, `og:image` et `twitter:image` conservent leur format d'origine pour la compatibilité avec les robots des réseaux sociaux. Une nouvelle étape **Optimizing images** affiche une progression en direct dans le dashboard et le CLI à chaque build. [Conversion automatique des images →](/fr/builds/image-optimization)

**Playground de l'API.** Les pages d'endpoint ont désormais un bouton interactif [« Try it »](/fr/api-reference/playground). Fonctionne avec les endpoints OpenAPI comme avec ceux écrits en MDX.

**Plugin Claude Code.** Installez le [plugin Jamdesk pour Claude Code](/fr/claude-code-plugin) pour donner à Claude une connaissance approfondie des composants MDX, de la configuration `docs.json`, des schémas de navigation et des commandes du CLI. Installation en deux étapes depuis la marketplace de plugins. Se combine avec [CLAUDE.md](/fr/ai/claude-code) et le [serveur MCP](/fr/ai/mcp-server) pour la rédaction de documentation assistée par IA.

**Avertissements de build pour l'image de marque manquante.** Les builds signalent désormais quand les chemins `favicon` ou `logo` dans `docs.json` référencent des fichiers absents de votre projet. Les avertissements apparaissent dans le détail des builds du dashboard et dans le CLI via `jamdesk dev` et `jamdesk validate`. Aucun e-mail n'est envoyé ; l'avertissement est purement informatif.

**YouTube Shorts.** Le [composant `<YouTube>`](/fr/content/youtube#youtube-shorts) prend en charge les Shorts verticaux via la prop `short`, affichant un lecteur 9:16 centré sans bandes noires. Utilisez `<YouTube id="VIDEO_ID" short />`.
