---
title: Corriger les liens rompus
description: >-
  Découvrez comment jamdesk fix corrige automatiquement les liens internes
  rompus et les ancres mal orthographiées, avec aperçu avant application.
---

`jamdesk fix` est le compagnon de correction automatique de `jamdesk broken-links`. Il lit les mêmes avertissements de liens rompus et réécrit tout fichier pour lequel la cible correcte peut être déterminée sans ambiguïté. Les cas ambigus sont signalés pour une révision manuelle et laissés inchangés.

<Tip>
  Vous préférez rester dans le dashboard ? [Corriger avec l'IA](/fr/builds/fix-with-ai) effectue la même réparation sur un build, couvre aussi les descriptions de page manquantes, et commite les modifications sur GitHub pour vous.
</Tip>

Il corrige deux types de liens internes rompus :

- **Ancres mal orthographiées** — un fragment qui est une faute de frappe évidente d'un titre réel sur la page cible (par exemple `#instalation` → `#installation`)
- **Dérive d'ancre inter-locale** — une page traduite a renommé ses titres, mais les liens dans cette locale pointent toujours vers l'ancien fragment anglais (par exemple `/fr/ai/selectors#ai-strategies` → `/fr/ai/selectors#stratégies-ia`)

## Étape 1 : Trouver les liens rompus

Exécutez `jamdesk broken-links` pour voir ce qui doit être corrigé :

```bash
jamdesk broken-links
```

Examinez le résultat. `jamdesk fix` cible les avertissements pour lesquels une ancre probablement correcte peut être associée à un titre réel.

## Étape 2 : Prévisualiser les corrections

Exécutez avec `--dry-run` pour voir exactement ce qui changerait avant de modifier le moindre fichier :

```bash
jamdesk fix --dry-run
```

**Exemple de résultat :**

```text
Planned fixes:

  fr/ai/overview.mdx:9
    /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

(dry run — no files written)
```

Vérifiez chaque correction prévue. Si un changement ne semble pas correct, corrigez ce lien manuellement plutôt que d'appliquer la modification. `jamdesk fix` ne réécrit que les liens qu'il peut résoudre sans ambiguïté.

## Étape 3 : Appliquer les corrections

Exécutez sans `--dry-run` pour appliquer. Une confirmation vous sera demandée :

```bash
jamdesk fix
```

```text
Apply 1 fix(es) to local files? (y/N)
```

Appuyez sur `y` pour écrire les modifications. Pour ignorer l'invite en CI ou dans des scripts, utilisez `-y` :

```bash
jamdesk fix -y
```

Après application, la commande affiche :

```text
Fixed 1 file(s); 0 warning(s) left for manual review.
```

Si la cible d'un avertissement est ambiguë, `jamdesk fix` la laisse inchangée pour que vous la résolviez manuellement.

## Étape 4 : Vérifier le diff et commiter

Vérifiez les modifications avant de commiter :

```bash
git diff
```

Vérifiez que chaque lien réécrit pointe vers l'endroit attendu. Puis commitez :

```bash
git add -A
git commit -m "fix(docs): auto-fix broken internal links"
```

## Utiliser avec un agent IA

`jamdesk fix --json` affiche le plan de correction sous la forme d'un seul document JSON, destiné à un agent de code comme Claude Code. La commande n'écrit aucun fichier et ne pose aucune question. L'agent fait les modifications. Nécessite la CLI 1.1.229 ou une version ultérieure.

```bash
jamdesk fix --json
```

**Exemple de sortie (abrégée) :**

```json
{
  "version": 1,
  "fixes": [
    {
      "type": "broken_link",
      "file": "fr/ai/overview.mdx",
      "line": 9,
      "oldText": "/fr/ai/selectors#ai-strategies",
      "newText": "/fr/ai/selectors#stratégies-ia",
      "resolvedBy": "deterministic"
    },
    {
      "type": "description",
      "file": "setup.mdx",
      "text": "How to set up the CLI.",
      "resolvedBy": "ai"
    }
  ],
  "unfixable": [
    {
      "type": "broken_link",
      "file": "quickstart.mdx",
      "line": 4,
      "link": "/missing",
      "reason": "points at a page that doesn't exist; create it or fix the link"
    }
  ],
  "notes": []
}
```

Le document contient trois listes :

- `fixes` : les modifications à faire. Pour un `broken_link`, remplacez `oldText` par `newText` sur cette ligne. Une `description` est une suggestion de l'IA pour le frontmatter de la page. L'agent doit donc vous la montrer avant de l'écrire.
- `unfixable` : les problèmes à corriger à la main, chacun avec une raison.
- `notes` : les messages de l'exécution, par exemple quand les corrections par IA ont été sautées.

Si l'exécution échoue, la sortie est `{"version": 1, "error": "..."}` et la commande se termine avec le code 1.

Pour commencer, demandez par exemple à votre agent : « Lance `jamdesk fix --json`, applique les corrections de liens et montre-moi les descriptions avant de les ajouter. »

## Options

| Flag | Description |
|------|-------------|
| `--dry-run` | Prévisualiser les corrections prévues sans écrire aucun fichier |
| `-y, --yes` | Appliquer les corrections sans invite de confirmation |
| `--types <list>` | Liste de types d'avertissements séparés par des virgules à corriger (par défaut : tous les types pris en charge) |
| `--no-ai` | Saute les corrections par IA et n'utilise que celles que Jamdesk trouve sans IA |
| `--project <id>` | ID du projet pour les corrections par IA (par défaut : `projectId` dans `docs.json`) |
| `--json` | Affiche en JSON le plan de correction et les problèmes qu'elle ne peut pas corriger. N'écrit aucun fichier et ne pose aucune question |
