Déployez un site de documentation avec seulement deux fichiers : `docs.json` et une page MDX. Choisissez le chemin qui correspond à votre point de départ.

## Prérequis

Vous aurez besoin de :
- Un compte [GitHub](https://github.com)
- Un dépôt contenant votre documentation (ou nous en créerons un)

## Option 1 : Démarrer depuis le modèle de démarrage

La façon la plus rapide de commencer. Le [modèle de démarrage](https://github.com/jamdesk/starter-docs) inclut du contenu d'exemple, une spécification OpenAPI et des exemples de chaque composant afin que vous puissiez voir comment les choses fonctionnent avant de les remplacer par votre propre contenu.

<Steps>
  <Step title="Créer un compte Jamdesk">
    Rendez-vous sur [dashboard.jamdesk.com](https://dashboard.jamdesk.com) et inscrivez-vous avec GitHub.
  </Step>

  <Step title="Créer un projet depuis le modèle">
    Cliquez sur **Nouveau projet** → **Depuis un modèle** → **Starter Docs**.

    Jamdesk crée un dépôt GitHub pour vous avec tout préconfiguré.
  </Step>

  <Step title="Votre site est en ligne">
    Votre documentation est déployée sur `your-project.jamdesk.app`. Modifiez les fichiers MDX, poussez vos modifications, et le site est reconstruit automatiquement.
  </Step>
</Steps>

<Tip>
Vous pouvez également cloner le modèle directement : `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

## Option 2 : Connecter un dépôt existant

Vous avez déjà un dépôt avec de la documentation compatible Jamdesk ? Connectez-le directement. Si vous migrez depuis Mintlify ou une autre plateforme de documentation, utilisez d'abord l'Option 3.

<Steps>
  <Step title="Créer un compte Jamdesk">
    Rendez-vous sur [dashboard.jamdesk.com](https://dashboard.jamdesk.com) et inscrivez-vous avec GitHub.
  </Step>

  <Step title="Créer un projet">
    Cliquez sur **Nouveau projet** et connectez votre dépôt.

    1. Sélectionnez votre dépôt GitHub
    2. Choisissez la branche à déployer
    3. Jamdesk détecte votre `docs.json` automatiquement

    Si votre dépôt ne possède pas encore de `docs.json`, ajoutez le fichier minimal décrit dans [Contenu d'un projet de documentation](#contenu-d-un-projet-de-documentation) avant de le connecter.

    Pour les permissions du dépôt, la sélection de branche et les chemins de documentation, consultez [Connecter GitHub](/fr/setup/connecting-github).
  </Step>

  <Step title="Votre site est en ligne">
    Votre documentation est déployée sur `your-project.jamdesk.app` avec `llms.txt` généré automatiquement pour que les outils AI puissent lire votre documentation.

    Chaque push sur votre branche connectée déclenche une reconstruction automatique.
  </Step>
</Steps>

## Option 3 : Migrer depuis Mintlify ou une autre plateforme

Vous avez déjà de la documentation dans Mintlify, GitBook, Docusaurus, ReadMe, Confluence ou une autre plateforme ? Commencez par le guide de migration avant de créer un nouveau projet. Il couvre la commande `jamdesk migrate` pour Mintlify et les étapes manuelles pour les autres outils de documentation. Après la migration, connectez le dépôt migré en utilisant [l'Option 2](#option-2-connecter-un-d-p-t-existant).

## Contenu d'un projet de documentation

Un projet Jamdesk minimal contient deux éléments :

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Pour les sites plus importants, consultez [Structure des répertoires](/fr/setup/directory-structure) pour les dossiers recommandés, les ressources et les snippets.

### docs.json

Le fichier de configuration qui définit votre site :

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consultez la [référence docs.json](/fr/config/docs-json-reference) pour toutes les options de configuration.

### Pages MDX

Les pages de documentation rédigées en MDX :

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consultez [Les bases de MDX](/fr/content/mdx-basics) pour la syntaxe du frontmatter, des titres, des liens et des composants.

## Développement local

Le CLI Jamdesk vous permet de prévisualiser les modifications localement avant de les pousser sur GitHub. C'est utile pour détecter les erreurs de syntaxe MDX avant qu'elles n'atteignent votre site en production. Pour toutes les méthodes d'installation et les commandes, consultez la [présentation du CLI Jamdesk](https://jamdesk.com/docs/cli/overview).

Prévisualisez vos modifications localement :

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Ouvrez **http://localhost:3000** pour voir votre documentation avec le rechargement à chaud.

## Ajouter des pages

1. Créez un nouveau fichier MDX :

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Ajoutez-le dans `docs.json` :

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Poussez vos modifications sur GitHub — votre nouvelle page est déployée automatiquement.

Pour plus de modèles de liens, notamment les ancres et les cartes, consultez [Liens et navigation](/fr/content/links).

## Domaine personnalisé

Ajoutez votre propre domaine dans **Paramètres** → **Domaines** :

1. Saisissez votre domaine (ex. : `docs.example.com`)
2. Ajoutez les enregistrements DNS indiqués
3. Attendez la vérification (jusqu'à 48 heures)

Les certificats SSL sont provisionnés automatiquement. [Guide complet →](/fr/deploy/custom-domains)
