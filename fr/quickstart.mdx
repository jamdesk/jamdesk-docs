**Jamdesk est un logiciel de documentation** qui publie un dépôt GitHub de Markdown sous forme de site de documentation hébergé, avec une sortie lisible par IA (`llms.txt`, des endpoints `.md` par page, et un serveur MCP) générée automatiquement.

Déployez un site de documentation avec seulement deux fichiers : `docs.json` et une page MDX. Choisissez le chemin correspondant à votre point de départ.

## Prérequis

Vous aurez besoin de :
- Un compte [GitHub](https://github.com)
- Un dépôt contenant votre documentation (ou nous en créerons un)

## Option 1 : Démarrer à partir du modèle de départ

La façon la plus rapide de démarrer. Le [modèle de départ](https://github.com/jamdesk/starter-docs) inclut du contenu d'exemple, une spécification OpenAPI, et des exemples de chaque composant afin que vous puissiez voir comment les choses fonctionnent avant de les remplacer par votre propre contenu.

<Steps>
  <Step title="Créer un compte Jamdesk">
    Allez sur [dashboard.jamdesk.com](https://dashboard.jamdesk.com) et inscrivez-vous avec GitHub.
  </Step>

  <Step title="Créer un projet à partir d'un modèle">
    Cliquez sur **New Project** → **From Template** → **Starter Docs**.

    Jamdesk crée un dépôt GitHub pour vous avec tout préconfiguré.
  </Step>

  <Step title="Vous êtes en ligne">
    Votre documentation est déployée sur `your-project.jamdesk.app`. Modifiez les fichiers MDX, poussez (push), et le site se reconstruit automatiquement.
  </Step>
</Steps>

<Tip>
Vous pouvez aussi cloner le modèle de départ directement : `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

<Tip>
**Vous voulez garder certaines pages privées ?** Ajoutez `private: true` au frontmatter de n'importe quel fichier MDX, puis définissez un mot de passe dans **Project Settings** après le prochain build. Consultez [Contrôle d'accès](/fr/setup/access-control) pour les quatre options (public, mot de passe sur tout le site, mixte, SSO).
</Tip>

## Option 2 : Connecter un dépôt existant

Vous avez déjà un dépôt avec une documentation prête pour Jamdesk ? Connectez-le directement. Si vous migrez depuis Mintlify ou une autre plateforme de documentation, utilisez d'abord l'Option 3.

<Steps>
  <Step title="Créer un compte Jamdesk">
    Allez sur [dashboard.jamdesk.com](https://dashboard.jamdesk.com) et inscrivez-vous avec GitHub.
  </Step>

  <Step title="Créer un projet">
    Cliquez sur **New Project** et connectez votre dépôt.

    1. Sélectionnez votre dépôt GitHub
    2. Choisissez la branche à déployer
    3. Jamdesk détecte automatiquement votre `docs.json`

    Si votre dépôt n'a pas encore de `docs.json`, ajoutez le fichier minimal depuis [Contenu d'un projet de documentation](#contenu-dun-projet-de-documentation) avant de le connecter.

    Pour les autorisations de dépôt, la sélection de branche et les chemins de documentation, consultez [Connecter GitHub](/fr/setup/connecting-github).
  </Step>

  <Step title="Vous êtes en ligne">
    Votre documentation est déployée sur `your-project.jamdesk.app` avec `llms.txt` généré automatiquement afin que les outils d'IA puissent lire votre documentation.

    Chaque push sur votre branche connectée déclenche une reconstruction automatique.
  </Step>
</Steps>

## Option 3 : Migrer depuis Mintlify ou une autre documentation

Vous avez déjà une documentation sur Mintlify, GitBook, Docusaurus, ReadMe, Confluence, ou une autre plateforme ? Commencez par le guide de migration avant de créer un nouveau projet. Il couvre la commande `jamdesk migrate` pour Mintlify et les étapes manuelles pour les autres outils de documentation. Après la migration, connectez le dépôt migré en utilisant l'[Option 2](#option-2--connecter-un-dépôt-existant).

## Contenu d'un projet de documentation

Un projet Jamdesk minimal comporte deux éléments :

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Pour des sites plus volumineux, consultez [Structure des répertoires](/fr/setup/directory-structure) pour les dossiers, ressources et snippets recommandés.

### docs.json

Le fichier de configuration qui définit votre site :

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consultez la [Référence docs.json](/fr/config/docs-json-reference) pour toutes les options de configuration.

### Pages MDX

Pages de documentation écrites en MDX :

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consultez [Bases de MDX](/fr/content/mdx-basics) pour le frontmatter, les titres, les liens et la syntaxe des composants.

## Développement local

Le CLI Jamdesk vous permet de prévisualiser les changements localement avant de pousser vers GitHub. C'est utile pour détecter les erreurs de syntaxe MDX avant qu'elles n'atteignent votre site en ligne. Pour toutes les méthodes d'installation et commandes, consultez l'[aperçu du CLI Jamdesk](https://jamdesk.com/docs/cli/overview).

Prévisualisez les changements localement :

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Ouvrez **http://localhost:3000** pour voir votre documentation avec rechargement à chaud.

## Ajouter d'autres pages

1. Créez un nouveau fichier MDX :

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Ajoutez-le à `docs.json` :

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Poussez vers GitHub - votre nouvelle page se déploie automatiquement.

Pour plus de modèles de liens, y compris les ancres et les cartes, consultez [Liens et navigation](/fr/content/links).

## Domaine personnalisé

Ajoutez votre propre domaine dans **Settings** → **Domains** :

1. Entrez votre domaine (par exemple, `docs.example.com`)
2. Ajoutez les enregistrements DNS affichés
3. Attendez la vérification (jusqu'à 48 heures)

Les certificats SSL sont provisionnés automatiquement. [Guide complet →](/fr/deploy/custom-domains)
