Le fichier `docs.json` est la configuration centrale de votre site de documentation Jamdesk.

<Tip>
  Les paramètres clés de votre docs.json apparaissent dans le Dashboard sous
  **Project Settings → Configuration Highlights**. Cette vue est en lecture seule
  et se met à jour automatiquement après chaque build réussi.
</Tip>

## Champs obligatoires

### name

**Type :** `string` (obligatoire)

Le nom de votre site de documentation. Affiché dans l'en-tête et l'onglet du navigateur.

```json
{ "name": "Acme API Docs" }
```

### theme

**Type :** `"jam" | "nebula" | "pulsar" | "halo"` (obligatoire)

<Tabs>
  <Tab title="jam">
    Design épuré et moderne avec la police Inter. Navigation basée sur l'en-tête.

    **Meilleur pour :** La plupart des sites de documentation, références API
  </Tab>
  <Tab title="nebula">
    Ambiance aérée et détendue avec JetBrains Mono.

    **Meilleur pour :** Documentation narrative, guides
  </Tab>
  <Tab title="pulsar">
    Design tranchant et à fort contraste avec navigation par barre latérale.

    **Meilleur pour :** Référence technique dense
  </Tab>
  <Tab title="halo">
    Chaleureux et doux avec Figtree, surfaces très arrondies et contenu mis en valeur sur une carte.

    **Meilleur pour :** Lecture longue confortable, documentation produit accessible
  </Tab>
</Tabs>

### colors

**Type :** `object` (obligatoire)

| Champ | Type | Obligatoire | Description |
|-------|------|----------|-------------|
| `primary` | string (hex) | Oui | Couleur principale de la marque |
| `light` | string (hex) | Non | Accent du thème clair |
| `dark` | string (hex) | Non | Accent du thème sombre |

```json
{
  "colors": {
    "primary": "#635BFF",
    "light": "#7C75FF",
    "dark": "#4F46E5"
  }
}
```

## Image de marque

### favicon

**Type :** `string` ou `object`

Chemin vers votre fichier favicon (SVG recommandé). Fournissez une seule image pour les deux modes, ou des variantes `light` / `dark` distinctes.

| Champ | Type | Description |
|-------|------|-------------|
| `light` | string | Favicon pour le mode clair (obligatoire si vous utilisez la forme objet) |
| `dark` | string | Favicon pour le mode sombre (facultatif, revient à `light` par défaut) |

```json
{ "favicon": "/images/favicon.svg" }
```

```json
{
  "favicon": {
    "light": "/images/favicon.svg",
    "dark": "/images/favicon-dark.svg"
  }
}
```

### logo

**Type :** `object`

| Champ | Type | Description |
|-------|------|-------------|
| `light` | string | Logo pour le mode clair |
| `dark` | string | Logo pour le mode sombre |
| `href` | string | URL de destination au clic sur le logo |

```json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp",
    "href": "https://yoursite.com"
  }
}
```

## Typographie

### fonts

**Type :** `object` (facultatif)

Remplace la police par défaut du thème pour le texte du corps et les titres. Chaque thème est livré avec une police par défaut optimisée. Ne définissez `fonts` que si vous avez besoin d'un rendu différent.

Utiliser la même police partout :

```json
{
  "fonts": {
    "family": "Lora"
  }
}
```

Séparer le titre et le corps :

```json
{
  "fonts": {
    "heading": { "family": "Space Grotesk" },
    "body": { "family": "Inter" }
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `family` | string | Nom de la famille de police. Toute police Google Fonts fonctionne ; le build la récupère automatiquement |
| `weight` | number | Graisse unique à charger (par ex. `400`). Omettre pour charger `400, 500, 600, 700` |
| `source` | string | URL ou chemin relatif commençant par `/` vers un fichier de police auto-hébergé. Ignore Google Fonts |
| `format` | `"woff"` \| `"woff2"` | Obligatoire lorsque `source` est défini |

Les champs `heading` et `body` acceptent tous deux les mêmes champs. Consultez [Thèmes → Typographie](/fr/customization/theming#typographie) pour des conseils sur le choix des polices.

## Apparence

### appearance

**Type :** `object` (facultatif)

Contrôle le comportement par défaut du mode sombre de votre site.

```json
{
  "appearance": {
    "default": "dark",
    "strict": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `default` | `"system"` \| `"light"` \| `"dark"` | `"system"` | Mode initial pour les nouveaux visiteurs |
| `strict` | boolean | `false` | Lorsque `true`, masque le bouton de bascule dans la barre de navigation pour que les visiteurs restent sur `default` |

Consultez [Thèmes → Mode sombre](/fr/customization/theming#mode-sombre) pour comprendre le comportement du bouton de bascule.

## Métadonnées de page

### metadata

**Type :** `object` (facultatif)

Contrôle les métadonnées de page affichées sur chaque page de documentation.

```json
{
  "metadata": {
    "timestamp": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `timestamp` | boolean | `false` | Lorsque `true`, affiche une ligne de type « Dernière mise à jour le 15 juin 2026 » dans le pied de page de chaque page. La date provient du dernier commit Git ayant modifié cette page, donc elle reste exacte automatiquement à chaque build. |

La date s'affiche sur votre site publié et dans `jamdesk dev`. Elle reflète le commit le plus récent ayant modifié le fichier de chaque page, donc les pages que vous n'avez pas modifiées conservent leur date d'origine.

## Localisation

### localization

**Type :** `object` (facultatif)

Contrôle la façon dont les visiteurs accèdent à la version traduite de votre documentation.

```json
{
  "localization": {
    "autoRedirect": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `autoRedirect` | boolean | `false` | Lorsque `true`, un visiteur arrivant pour la première fois à la racine de votre documentation est redirigé vers la langue correspondant à l'en-tête `Accept-Language` de son navigateur. Nécessite au moins deux entrées dans `navigation.languages`. |

Seules les racines sont redirigées. Un lien profond comme `/guides/authentication` sert toujours la page qu'il désigne, donc un lien collé dans un ticket ouvre la même page pour tout le monde. Les robots des moteurs de recherche ne sont jamais redirigés, donc vos balises `hreflang` continuent de décider ce qui est indexé.

La langue du visiteur est mémorisée pendant un an. Choisir une langue dans le sélecteur de langue remplace ensuite la correspondance automatique.

Consultez [Langues → Routage automatique des langues](/fr/setup/languages#routage-automatique-de-la-langue) pour le comportement complet.

## Bannière

### banner

Affiche une barre d'annonce à l'échelle du site, épinglée en haut de chaque page, au-dessus de l'en-tête, en pleine largeur, dans la couleur d'accent de votre thème. Utilisez-la pour des lancements, des migrations, des fenêtres de maintenance ou tout message que chaque visiteur doit voir.

```json
{
  "banner": {
    "content": "🎉 Version 2.0 is live! Read the [changelog](/changelog).",
    "dismissible": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `content` | string | - | **Obligatoire.** Le texte de la bannière. Prend en charge une mise en forme intégrée basique : liens `[text](url)`, **gras** (`**text**`), et *italique* (`*text*`). Les composants MDX personnalisés ne sont pas pris en charge. |
| `dismissible` | boolean | `false` | Lorsque `true`, affiche un bouton de fermeture. Une fois que le visiteur ferme la bannière, elle reste masquée pour lui jusqu'à ce que vous modifiiez `content`. Modifier le message la fait réapparaître. |

La bannière s'affiche sur votre site publié et dans `jamdesk dev`. Elle est configurée globalement (une seule bannière pour tout le site) ; les bannières par onglet et par langue ne sont pas encore prises en charge.

## OpenAPI

### api.openapi

**Type :** `string | string[]`

Listez les fichiers de spécification OpenAPI 3.x que vous voulez que Jamdesk valide et utilise pour les pages d'endpoint. Utilisez des chemins relatifs à votre `docs.json`.

```json docs.json
{
  "api": {
    "openapi": ["/openapi/api.yaml"]
  }
}
```

Une fois configuré, vous pouvez générer des pages d'endpoint en ajoutant un champ `openapi` dans le frontmatter d'une page :

```mdx
---
title: Create Ticket
openapi: /openapi/api.yaml POST /tickets
---
```

Si vous n'avez qu'une seule spécification listée, vous pouvez aussi utiliser le format court :

```mdx
---
title: Create Ticket
openapi: POST /tickets
---
```

Consultez [Exemple OpenAPI](/fr/api-reference/openapi-example) pour une page d'endpoint en conditions réelles et [Structure des répertoires](/fr/setup/directory-structure) pour l'emplacement des fichiers.

Si votre site est multilingue, placez un fichier `<spec>.<lang>.<ext>` à côté de chaque spécification source (par exemple, `openapi/api.fr.yaml`) et Jamdesk le sert sur les URL de cette langue. Consultez [Traduire les spécifications OpenAPI](/fr/setup/languages#traduire-les-spécifications-openapi).

<Warning>
Une clé `asyncapi` est acceptée partout où `openapi` l'est, mais Jamdesk ne génère pas encore de rendu pour les spécifications AsyncAPI — rien n'en est généré. `jamdesk validate` émet un avertissement lorsqu'il en trouve une, afin qu'une configuration qui semble prise en charge ne le reste pas jusqu'à ce que vous construisiez le site.
</Warning>

### navigation openapi (pages générées)

**Type :** `object`

Placez un objet `openapi` sur un **onglet** de navigation et définissez `generate: true`, et Jamdesk génère une page d'endpoint par opération de cette spécification au moment du build — ainsi que les groupes de la barre latérale pour les contenir. Rien à rédiger, rien à committer.

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": { "source": "/openapi/api.yaml", "generate": true }
      }
    ]
  }
}
```

| Clé | Type | Description |
|-----|------|-------------|
| `source` | string | Chemin vers la spécification, relatif à votre `docs.json` |
| `generate` | boolean | `true` génère les pages et la barre latérale. Sans cette clé, elle reste inerte |

Les pages générées se trouvent sous le nom de l'onglet lui-même, slugifié, avec un slug construit à partir de la méthode et du chemin — l'onglet ci-dessus place `POST /tickets` à `/api-reference/post-tickets`. Les opérations sont regroupées par leur premier `tag` ; les spécifications sans tags reviennent au premier segment de chemin significatif, donc `/api/v1/auctions/{auctionId}` se retrouve sous **Auctions**. Les titres proviennent du `summary` de l'opération lorsque la spécification en a un, sinon de la méthode et du chemin — et une opération qui concerne une seule ressource est titrée au singulier (`GET /users/{id}` → « Get User »).

<Note>
`generate` est opt-in par construction. Un simple `"openapi": "/openapi/api.yaml"` sur un onglet, ou un objet sans `generate: true`, continue de faire exactement ce qu'il faisait avant — ainsi aucune configuration existante ne gagne une centaine de pages lors de son prochain build.
</Note>

Un fichier `.mdx` committé l'emporte toujours en cas de collision de slug, vous pouvez donc adopter la génération progressivement : activez-la, puis supprimez vos pages d'endpoint écrites à la main une par une, à votre rythme.

Si vous renommez ultérieurement un chemin dans votre spécification, le slug généré est mis à jour en conséquence. Jamdesk conserve un historique de slugs par opération et émet une redirection de chaque ancienne URL vers l'actuelle à chaque build, afin que les liens entrants et les favoris survivent au renommage. Vos propres [redirections](/fr/setup/redirects) et toute page existante restent prioritaires.

**Limites actuelles.** La génération ne fonctionne que sur `navigation.tabs` de premier niveau — pas sur les groupes, les ancres, ni sur les onglets imbriqués sous `languages` ou `versions` — et ne produit des pages que pour votre langue par défaut. Une clé `directory` est acceptée par le schéma mais n'a aucun effet sur l'emplacement des pages.

### api.mdx.server

**Type :** `string`

URL de base utilisée dans les exemples de code sur les pages avec frontmatter `api:` (le type rédigé en MDX, pas les pages `openapi:`, qui récupèrent leurs serveurs depuis la spécification).

```json
{
  "api": {
    "mdx": {
      "server": "https://api.example.com"
    }
  }
}
```

<Note>
Un tableau est accepté pour des raisons de compatibilité, mais seule la première entrée est jamais utilisée — tout ce qui suit est ignoré. `jamdesk validate` émet un avertissement si vous en listez plusieurs.
</Note>

### api.examples.languages

**Type :** `string[]`
**Par défaut :** `["curl", "python", "javascript"]`

Choisissez les langages de programmation qui apparaissent dans les exemples de code d'API générés automatiquement sur les pages `openapi:`. L'ordre du tableau détermine l'ordre d'affichage des onglets, et le premier langage est sélectionné par défaut.

**Valeurs prises en charge :** `curl`, `bash`, `python`, `javascript`, `go`, `ruby`, `csharp`, `java`, `rust`, `php`

<Note>`bash` est un alias de `curl` ; les deux produisent le même résultat. Utilisez l'étiquette que vous préférez.</Note>

```json All supported languages
{
  "api": {
    "examples": {
      "languages": ["curl", "python", "javascript", "go", "ruby", "csharp", "java", "rust", "php"]
    }
  }
}
```

```json Custom subset
{
  "api": {
    "examples": {
      "languages": ["python", "javascript", "go"]
    }
  }
}
```

### api.examples.defaults

**Type :** `"required" | "all"`
**Par défaut :** `"all"`

Contrôle quels paramètres apparaissent dans les exemples de code générés automatiquement.

| Valeur | Comportement |
|-------|----------|
| `"all"` | Les exemples incluent tous les paramètres avec des valeurs de substitution |
| `"required"` | Les exemples n'incluent que les paramètres marqués comme `required` dans la spécification |

```json
{
  "api": {
    "examples": {
      "defaults": "required"
    }
  }
}
```

### api.examples.prefill

**Type :** `boolean`
**Par défaut :** `false`

Lorsque `true`, l'[API Playground](/fr/api-reference/playground) pré-remplit les champs de paramètres avec les valeurs `example` de votre spécification OpenAPI.

```json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

### api.playground.display

**Type :** `"interactive" | "simple" | "none"`
**Par défaut :** `"interactive"`

Contrôle l'[API Playground](/fr/api-reference/playground) sur les pages d'endpoint. Un bouton « Try it » apparaît par défaut sur chaque page `openapi:` et `api:`.

| Valeur | Comportement |
|-------|----------|
| `"interactive"` | playground complet : remplir les paramètres, générer le code, envoyer des requêtes (par défaut) |
| `"simple"` | Remplir les paramètres et copier le code, mais pas de bouton Send |
| `"none"` | Playground désactivé |

```json
{
  "api": {
    "playground": {
      "display": "interactive"
    }
  }
}
```

Consultez l'[API Playground](/fr/api-reference/playground) pour les détails d'utilisation et les surcharges par page.

### api.mdx.auth.method

**Type :** `"bearer" | "basic" | "key" | "cobo"`

Méthode d'authentification utilisée dans les exemples de code générés automatiquement. Lorsqu'elle est définie, les exemples incluent l'en-tête d'authentification approprié.

| Valeur | Format de l'en-tête |
|-------|--------------|
| `"bearer"` | `Authorization: Bearer <token>` |
| `"basic"` | `Authorization: Basic <base64>` |
| `"key"` | En-tête personnalisé (voir `api.mdx.auth.name`) |
| `"cobo"` | Authentification spécifique à Cobo |

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
}
```

### api.mdx.auth.name

**Type :** `string`

Nom d'en-tête personnalisé pour l'authentification par clé. Utilisé uniquement lorsque `api.mdx.auth.method` vaut `"key"`.

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "key",
        "name": "X-API-Key"
      }
    }
  }
}
```

## Barre de navigation et pied de page

### navbar

**Type :** `object`

| Champ | Type | Description |
|-------|------|-------------|
| `links` | array | Liens de navigation |
| `links[].label` | string | Texte de bouton par défaut |
| `links[].labels` | object | Surcharges facultatives par langue, indexées par code de langue (par ex. `fr`, `es`). Revient à `label` par défaut |
| `links[].icon` | icon | Icône facultative à afficher à côté de l'étiquette |
| `links[].href` | string | URL de destination |
| `primary` | object | Bouton CTA principal |
| `primary.label` | string | Texte de bouton par défaut |
| `primary.labels` | object | Surcharges facultatives par langue, indexées par code de langue. Revient à `label` par défaut |

```json
{
  "navbar": {
    "links": [
      {
        "label": "Blog",
        "labels": { "fr": "Blog", "es": "Blog" },
        "href": "/blog"
      },
      {
        "label": "Pricing",
        "labels": { "fr": "Tarifs", "es": "Precios" },
        "href": "/pricing"
      }
    ],
    "primary": {
      "type": "button",
      "label": "Dashboard",
      "labels": { "fr": "Tableau de bord", "es": "Panel" },
      "href": "https://app.example.com"
    }
  }
}
```

<Note>
  `labels` est facultatif. Les documentations monolingues peuvent l'omettre. Lorsqu'elle est définie, la langue de l'URL actuelle (par ex. `/fr/...`) sélectionne la surcharge correspondante.
</Note>

### footer

**Type :** `object`

Configure le pied de page avec des liens sociaux et des colonnes de liens personnalisées.

```json
{
  "footer": {
    "socials": {
      "github": "https://github.com/yourorg",
      "x": "https://x.com/yourhandle",
      "discord": "https://discord.gg/yourserver"
    },
    "links": [
      {
        "header": "Resources",
        "items": [
          { "label": "Blog", "href": "https://example.com/blog" },
          { "label": "Changelog", "href": "/changelog" }
        ]
      }
    ]
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `socials` | object | URL des plateformes de réseaux sociaux |
| `links` | array | Configurations des colonnes de liens |
| `links[].header` | string | Titre de la colonne |
| `links[].items` | array | Tableau d'objets `{ label, href }` |

**Plateformes sociales prises en charge :** `github`, `x`, `twitter`, `linkedin`, `discord`, `slack`, `youtube`, `instagram`, `facebook`, `reddit`, `telegram`, `bluesky`, `threads`, `medium`, `hacker-news`, `website`

## Mise en forme

### styling.latex

**Type :** `boolean`

Active le rendu mathématique LaTeX avec KaTeX. Une fois activé, vous pouvez utiliser `$...$` pour les mathématiques en ligne et `$$...$$` pour les équations en bloc.

```json
{
  "styling": {
    "latex": true
  }
}
```

Consultez [Mathématiques et LaTeX](/fr/content/math) pour les détails d'utilisation.

### styling.js

**Type :** `string | string[]`

Fichier(s) JavaScript personnalisé(s) à inclure sur chaque page. Les chemins sont relatifs à votre répertoire de documentation et doivent commencer par `/`.

```json
{
  "styling": {
    "js": "/script.js"
  }
}
```

Passez un tableau pour plusieurs fichiers :

```json
{
  "styling": {
    "js": ["/chat.js", "/analytics.js"]
  }
}
```

Sans ce champ, Jamdesk détecte automatiquement les fichiers `.js` à la racine de votre projet. Consultez [JavaScript personnalisé](/fr/customization/custom-javascript) pour plus de détails.

## Recherche

### search

**Type :** `object` (facultatif)

Personnalisez la barre de recherche de la documentation. La recherche fonctionne dès l'installation ; vous n'avez besoin de ce champ que pour modifier le texte d'espace réservé ou mettre en avant des pages populaires dans l'état vide.

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `prompt` | string | `Search documentation…` | Texte d'espace réservé affiché dans le champ de recherche |
| `popularPages` | array | Démarrage rapide, Introduction | Liens d'accès rapide affichés avant que le visiteur ne tape une requête |

```json
{
  "search": {
    "prompt": "Ask me anything…",
    "popularPages": [
      { "title": "Quick Start", "slug": "quickstart", "icon": "rocket" },
      { "title": "Authentication", "slug": "guides/authentication", "icon": "key" }
    ]
  }
}
```

#### Pages populaires

Chaque entrée de `popularPages` accepte :

| Champ | Type | Obligatoire | Description |
|-------|------|----------|-------------|
| `title` | string | Oui | Étiquette affichée pour le lien |
| `slug` | string | Oui | Chemin de la page, sans slash initial ni extension `.mdx` (par exemple `quickstart`, ou `guides/authentication` pour le fichier `guides/authentication.mdx`) |
| `icon` | string | Non | Nom d'icône Font Awesome affiché à côté du lien (par exemple `rocket` ou `bell`) |

Le champ `icon` accepte aussi l'objet complet `{ "name", "style", "library" }`. Consultez [Forme objet de l'icône](/fr/content/icons#forme-objet-de-licône). Lorsque `popularPages` est omis, Jamdesk affiche Démarrage rapide et Introduction par défaut.

## Chat

### chat

**Type :** `object` (facultatif)

Configure l'assistant de chat IA intégré. Le chat est activé par défaut sur tous les sites ; vous n'avez besoin de ce champ que pour personnaliser les questions de démarrage ou le désactiver.

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Définissez `false` pour retirer le panneau de chat de votre site |
| `starterQuestions` | string[] | générées automatiquement | Jusqu'à 4 questions affichées à l'ouverture du chat (5 à 200 caractères chacune). Générées automatiquement pendant les builds si omis. Définissez `[]` pour n'en avoir aucune |

```json
{
  "chat": {
    "starterQuestions": [
      "How do I get started?",
      "What API endpoints are available?"
    ]
  }
}
```

Consultez [Chat IA](/fr/ai/chat) pour les détails sur le fonctionnement du chat et ce que voient les visiteurs.

## Menu des actions IA

### contextual

**Type :** `object` (facultatif)

Configure le menu déroulant Actions IA qui apparaît sur chaque page. Activé par défaut avec toutes les options ; vous n'avez besoin de ce champ que pour personnaliser les options affichées ou le désactiver.

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Définissez `false` pour retirer le menu Actions IA de votre site |
| `options` | array | toutes les options intégrées | Liste de clés d'options et/ou d'objets d'options personnalisées |

**Clés d'options intégrées :** `copy`, `view`, `chatgpt`, `claude`, `perplexity`, `gemini`, `mcp`, `cursor`, `vscode`

```json
{
  "contextual": {
    "options": ["copy", "claude", "mcp", "cursor"]
  }
}
```

Ajoutez des options personnalisées à côté des options intégrées :

```json
{
  "contextual": {
    "options": [
      "copy",
      "claude",
      {
        "title": "Ask on Discord",
        "description": "Get help from the community",
        "icon": "discord",
        "href": "https://discord.gg/your-server"
      }
    ]
  }
}
```

Consultez [Menu des actions IA](/fr/ai/ai-actions) pour la liste complète des options et le format des options personnalisées.

## Vérification orthographique

### spellcheck

**Type :** `object` (facultatif)

Configure la commande CLI `jamdesk spellcheck`. Vous n'avez besoin de ce champ que pour ajouter des mots spécifiques à votre projet à la liste d'exclusion.

| Champ | Type | Description |
|-------|------|-------------|
| `ignore` | string[] | Mots à ignorer lors de la vérification orthographique (noms de produits, termes techniques, etc.) |

```json
{
  "spellcheck": {
    "ignore": ["Acme", "kubectl", "Terraform"]
  }
}
```

Le CLI inclut plus de 180 termes techniques intégrés (API, GraphQL, Kubernetes, React, etc.) et ignore automatiquement le nom de votre projet issu du champ `name`. N'ajoutez que des mots spécifiques à votre projet.

Consultez [Aperçu du CLI : vérification orthographique](/fr/cli/overview) pour les détails d'utilisation et le mode de correction interactif.

## Images

### images.convertToWebp

**Type :** `boolean` (facultatif, par défaut `false`)

Active la conversion automatique en WebP pour les ressources PNG et JPG pendant les builds. Les fichiers convertis sont généralement 60 à 80 % plus légers que les originaux, sans perte de qualité visible. Les références dans votre MDX, votre CSS personnalisé, votre JS personnalisé et votre `docs.json` sont réécrites automatiquement, vous n'avez donc aucun chemin à modifier.

Les favicons, `og:image` et `twitter:image` conservent leur format d'origine. Tous les robots sociaux et clients de messagerie ne rendent pas WebP de manière fiable, et une carte d'aperçu cassée est pire qu'un JPG légèrement plus lourd.

```json
{
  "images": {
    "convertToWebp": true
  }
}
```

Consultez [Conversion automatique des images](/fr/builds/image-optimization) pour savoir ce qui est converti, comment fonctionne la mise en cache et l'indicateur de progression du build.

## Contrôle d'accès

### auth.password

**Type :** `object` (facultatif)

Optez pour la protection par mot de passe partagé sur votre site. Configuration déclarative uniquement. Vous définissez toujours le mot de passe réel dans le [dashboard](/fr/setup/password-protection#rotation-et-révocation-des-sessions) après l'exécution du prochain build.

Définissez `auth.password.enabled: true` pour verrouiller tout le site, ou listez des chemins sous `auth.password.private[]` pour ne protéger que ces pages. Les deux déclenchent la même invite de mot de passe du dashboard lors du prochain build.

```json
{
  "auth": {
    "password": {
      "enabled": true,
      "hint": "Ask your account manager",
      "public": ["/marketing/**", "/changelog"]
    }
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | Mode site entier. Lorsque `true`, chaque page nécessite le mot de passe (sauf celles marquées publiques). |
| `hint` | `string` (200 caractères max) | Indice en texte brut affiché sur l'écran de déverrouillage. Pas de HTML. |
| `public` | `string[]` | Motifs de chemin qui contournent le mot de passe. Prend en charge `*` (un segment) et `**` (récursif). Un `/` seul est rejeté. |
| `private` | `string[]` | Chemins exacts nécessitant le mot de passe. Le définir sans `enabled` active le mode pages spécifiques. |

Consultez [Protection par mot de passe](/fr/setup/password-protection) pour le guide complet, y compris le flux du dashboard et la façon dont le frontmatter `public: true` / `private: true` interagit avec ces tableaux.

### auth.jwt

**Type :** `object` (facultatif)

Verrouille tout le site derrière votre propre système de connexion. Votre backend signe un jeton de courte durée pour chaque utilisateur connecté, et Jamdesk l'échange contre un cookie de session. La clé de signature est générée dans le dashboard, pas dans ce fichier. `auth.jwt` et `auth.password` ne peuvent pas être activés tous les deux ; un build avec les deux activés échoue avec un `config_error`.

```json
{
  "auth": {
    "jwt": {
      "enabled": true,
      "loginUrl": "https://app.example.com/docs-login",
      "public": ["/changelog/**", "/status"]
    }
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | Active l'authentification JWT. Chaque page nécessite une session, sauf celles marquées publiques. |
| `loginUrl` | `string` | Obligatoire lorsque `enabled` vaut `true`. Une URL `https://` absolue de votre côté. Les visiteurs sans session y sont envoyés avec `?redirect=<path>` afin de pouvoir les ramener à la page demandée. |
| `public` | `string[]` | Motifs de chemin qui restent accessibles sans connexion. Même syntaxe que `auth.password.public`, fusionnée avec le frontmatter `public: true` et `"public": true` sur les groupes de navigation. |

L'accès par page vient en plus de `groups` dans le frontmatter de la page. Consultez [Authentification JWT](/fr/setup/jwt-authentication) pour le format du jeton, le flux de redirection, et le fonctionnement des groupes.
