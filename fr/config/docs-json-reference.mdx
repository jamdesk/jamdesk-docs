Le fichier `docs.json` est la configuration centrale de votre site de documentation Jamdesk.

<Tip>
  Les paramètres clés de votre docs.json apparaissent dans le dashboard sous
  **Project Settings → Configuration Highlights**. Cette vue est en lecture seule
  et se met à jour automatiquement après chaque build réussi.
</Tip>

## Champs obligatoires

### name

**Type :** `string` (obligatoire)

Le nom de votre site de documentation. Il s'affiche dans l'en-tête et dans l'onglet du navigateur. Pour changer le format du titre de l'onglet, consultez [`seo.titleTemplate`](#seotitletemplate).

```json
{ "name": "Acme API Docs" }
```

### theme

**Type :** `"jam" | "nebula" | "pulsar" | "halo" | "dusk"` (obligatoire)

<Tabs>
  <Tab title="jam">
    Design épuré et moderne avec la police Inter. Navigation dans l'en-tête.

    **Idéal pour :** la plupart des sites de documentation, les références d'API
  </Tab>
  <Tab title="nebula">
    Ambiance aérée et détendue avec JetBrains Mono.

    **Idéal pour :** la documentation narrative, les guides
  </Tab>
  <Tab title="pulsar">
    Style net et très contrasté, avec navigation dans la barre latérale.

    **Idéal pour :** les références techniques denses
  </Tab>
  <Tab title="halo">
    Chaleureux et doux, avec Figtree, des surfaces très arrondies et un contenu surélevé sur une carte.

    **Idéal pour :** une lecture longue et confortable, les documentations produit accessibles
  </Tab>
  <Tab title="dusk">
    Calme et plat, avec un corps de texte en Inter, des titres en IBM Plex Serif, un accent bleu encre et une surface unique délimitée par des bordures de 1 px plutôt que par des cartes surélevées.

    **Idéal pour :** une documentation posée, de style éditorial
  </Tab>
</Tabs>

### colors

**Type :** `object` (obligatoire)

| Champ | Type | Obligatoire | Description |
|-------|------|-------------|-------------|
| `primary` | string (hex) | Oui | Couleur principale de la marque |
| `light` | string (hex) | Non | Couleur d'accent du thème clair |
| `dark` | string (hex) | Non | Couleur d'accent du thème sombre |

```json
{
  "colors": {
    "primary": "#635BFF",
    "light": "#7C75FF",
    "dark": "#4F46E5"
  }
}
```

## Image de marque

### favicon

**Type :** `string` ou `object`

Chemin vers votre fichier favicon (SVG recommandé). Fournissez une seule image pour les deux modes, ou des variantes `light` / `dark` distinctes.

| Champ | Type | Description |
|-------|------|-------------|
| `light` | string | Favicon du mode clair (obligatoire avec la forme objet) |
| `dark` | string | Favicon du mode sombre (facultatif, retombe sur `light`) |

```json
{ "favicon": "/images/favicon.svg" }
```

```json
{
  "favicon": {
    "light": "/images/favicon.svg",
    "dark": "/images/favicon-dark.svg"
  }
}
```

### logo

**Type :** `object`

| Champ | Type | Description |
|-------|------|-------------|
| `light` | string | Logo du mode clair |
| `dark` | string | Logo du mode sombre |
| `href` | string | URL ouverte au clic sur le logo |

```json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp",
    "href": "https://yoursite.com"
  }
}
```

## Typographie

### fonts

**Type :** `object` (facultatif)

Remplacez la police par défaut du thème pour le corps de texte et les titres. Chaque thème est livré avec une police par défaut soigneusement choisie. Ne définissez `fonts` que si vous voulez un autre rendu.

Utiliser la même police partout :

```json
{
  "fonts": {
    "family": "Lora"
  }
}
```

Séparer les titres et le corps de texte :

```json
{
  "fonts": {
    "heading": { "family": "Space Grotesk" },
    "body": { "family": "Inter" }
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `family` | string | Nom de la famille de polices. N'importe quelle police Google Fonts convient ; le build la récupère automatiquement |
| `weight` | number | Graisse unique à charger (par exemple `400`). Omettez-la pour charger `400, 500, 600, 700` |
| `source` | string | URL ou chemin relatif commençant par `/` vers un fichier de police auto-hébergé. Contourne Google Fonts |
| `format` | `"woff"` \| `"woff2"` | Obligatoire lorsque `source` est défini |

`heading` et `body` acceptent les mêmes champs. Consultez [Thèmes → Typographie](/fr/customization/theming#typographie) pour des conseils sur le choix des polices.

## Apparence

### appearance

**Type :** `object` (facultatif)

Contrôlez le comportement par défaut du mode sombre sur votre site.

```json
{
  "appearance": {
    "default": "dark",
    "strict": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `default` | `"system"` \| `"light"` \| `"dark"` | `"system"` | Mode initial pour les nouveaux visiteurs |
| `strict` | boolean | `false` | Lorsque la valeur est `true`, masque le bouton de bascule de la barre de navigation : les visiteurs restent sur `default` |

Consultez [Thèmes → Mode sombre](/fr/customization/theming#mode-sombre) pour le fonctionnement du bouton de bascule.

## Métadonnées de page

### metadata

**Type :** `object` (facultatif)

Contrôlez les métadonnées affichées sur chaque page de la documentation.

```json
{
  "metadata": {
    "timestamp": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `timestamp` | boolean | `false` | Lorsque la valeur est `true`, affiche dans le pied de page de chaque page une ligne du type « Last updated on June 15, 2026 ». La date provient du dernier commit Git ayant modifié cette page, elle reste donc exacte automatiquement à chaque build. |

La date s'affiche sur votre site publié et dans `jamdesk dev`. Elle reflète le commit le plus récent ayant touché le fichier de chaque page : les pages que vous n'avez pas modifiées conservent donc leur date d'origine.

## SEO

### seo.titleTemplate

**Type :** `string` (facultatif)
**Valeur par défaut :** `%s — <nom>`, où `<nom>` est votre [`name`](#name)

Définissez le format du titre de page dans l'onglet du navigateur et dans les résultats de recherche. Placez `%s` à l'endroit où le titre de la page doit apparaître. Chaque `%s` est remplacé. Le modèle peut contenir jusqu'à 200 caractères. S'il ne contient pas `%s`, le build échoue et `jamdesk validate` affiche l'erreur.

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Une page intitulée `Getting started` affiche alors `Getting started | Acme`. Utilisez `"%s"` seul pour omettre le nom du site. Cela ne modifie pas `og:title` ni `twitter:title`. Consultez [Titres de page](/fr/content/seo#titres-de-page) pour les pages sans titre.

### seo.socialCard

**Type :** `object` (facultatif)

Modifiez la carte sociale que Jamdesk génère pour chaque page. Sans cette clé, les cartes conservent leur apparence par défaut.

```json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true
    }
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `theme` | `"light"` \| `"dark"` | `"light"` | `"dark"` utilise un texte clair sur un fond sombre, ainsi que votre image `logo.dark`. |
| `brandColor` | boolean | `false` | Colore la barre du bas et le badge de section avec `colors.primary` (`colors.light` sur une carte sombre). |
| `accentBar` | boolean | `true` | `false` supprime la barre située en bas de la carte. |
| `siteName` | boolean | `true` | `false` masque le nom du site sous le logo. Le nom reste affiché lorsque la carte montre votre favicon à la place du logo. |
| `customImage` | `"background"` \| `"replace"` | `"background"` | `"replace"` utilise votre `og:image` comme carte entière, sans aucun texte dessus. |

La carte ne peut dessiner que des logos SVG, PNG et JPG, et Jamdesk convertit les fichiers de logo PNG et JPG en WebP lors du build de votre site. Utilisez un logo SVG pour afficher votre logo complet sur la carte. La carte ne peut pas dessiner le texte d'un logo SVG : convertissez tout texte en contours (tracés) dans votre outil de conception, puis exportez de nouveau le SVG.

Consultez [Personnaliser la carte sociale](/fr/content/seo#personnaliser-la-carte-sociale) pour le détail de chaque option et l'image utilisée par une page.

## Localisation

### localization

**Type :** `object` (facultatif)

Contrôlez la manière dont les visiteurs accèdent à la version traduite de votre documentation.

```json
{
  "localization": {
    "autoRedirect": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `autoRedirect` | boolean | `false` | Lorsque la valeur est `true`, un visiteur qui arrive pour la première fois à la racine de votre documentation est redirigé vers la langue correspondant à l'en-tête `Accept-Language` de son navigateur. Nécessite au moins deux entrées dans `navigation.languages`. |

Seules les racines sont redirigées. Un lien profond tel que `/guides/authentication` renvoie toujours la page qu'il désigne : un lien que vous collez dans un ticket ouvre donc la même page pour tout le monde. Les robots des moteurs de recherche ne sont jamais redirigés, de sorte que vos balises `hreflang` continuent de déterminer ce qui est indexé.

La langue du visiteur est mémorisée pendant un an. Choisir une langue dans le sélecteur de langue remplace ensuite la correspondance automatique.

Consultez [Support multilingue → Routage automatique de la langue](/fr/setup/languages#routage-automatique-de-la-langue) pour le comportement complet.

## Bannière

### banner

Affichez une barre d'annonce sur tout le site, épinglée en haut de chaque page, au-dessus de l'en-tête, sur toute la largeur et dans la couleur d'accent de votre thème. Utilisez-la pour les lancements, les migrations, les fenêtres de maintenance ou tout message que chaque visiteur doit voir.

```json
{
  "banner": {
    "content": "🎉 Version 2.0 is live! Read the [changelog](/changelog).",
    "dismissible": true
  }
}
```

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `content` | string | - | **Obligatoire.** Le texte de la bannière. Prend en charge la mise en forme en ligne de base : liens `[text](url)`, **gras** (`**text**`) et *italique* (`*text*`). Les composants MDX personnalisés ne sont pas pris en charge. |
| `dismissible` | boolean | `false` | Lorsque la valeur est `true`, affiche un bouton de fermeture. Une fois la bannière fermée par un visiteur, elle reste masquée pour lui jusqu'à ce que vous modifiiez `content`. Modifier le message la fait réapparaître. |

La bannière s'affiche sur votre site publié et dans `jamdesk dev`. Elle est configurée globalement (une seule bannière pour tout le site) ; les bannières par onglet et par langue ne sont pas prises en charge pour le moment.

## OpenAPI

### api.openapi

**Type :** `string | string[]`

Listez les fichiers de spécification OpenAPI 3.x que Jamdesk doit valider et utiliser pour les pages d'endpoint. Utilisez des chemins relatifs à votre `docs.json`.

```json docs.json
{
  "api": {
    "openapi": ["/openapi/api.yaml"]
  }
}
```

Une fois cette option configurée, vous pouvez générer des pages d'endpoint en ajoutant un champ `openapi` dans le frontmatter d'une page :

```mdx
---
title: Create Ticket
openapi: /openapi/api.yaml POST /tickets
---
```

Si vous ne listez qu'une seule spécification, vous pouvez aussi utiliser le format court :

```mdx
---
title: Create Ticket
openapi: POST /tickets
---
```

Consultez [Exemple OpenAPI](/fr/api-reference/openapi-example) pour une page d'endpoint réelle et [Structure des répertoires](/fr/setup/directory-structure) pour l'emplacement des fichiers.

Si votre site est multilingue, placez un fichier `<spec>.<lang>.<ext>` à côté de chaque spécification source (par exemple `openapi/api.fr.yaml`) et Jamdesk le sert sur les URL de cette langue. Consultez [Traduire les spécifications OpenAPI](/fr/setup/languages#traduire-les-spécifications-openapi).

<Warning>
Une clé `asyncapi` est acceptée partout où `openapi` l'est, mais Jamdesk ne génère pas encore de rendu des spécifications AsyncAPI : rien n'est généré à partir de cette clé. `jamdesk validate` émet un avertissement lorsqu'il en trouve une, afin qu'une configuration qui semble prise en charge ne le reste pas jusqu'au build du site.
</Warning>

### navigation openapi (pages générées)

**Type :** `object`

Ajoutez un objet `openapi` à un **onglet** de navigation et définissez `generate: true` : Jamdesk crée au moment du build une page d'endpoint par opération de cette spécification, ainsi que les groupes de la barre latérale pour les accueillir. Rien à rédiger, rien à committer.

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": { "source": "/openapi/api.yaml", "generate": true }
      }
    ]
  }
}
```

| Clé | Type | Description |
|-----|------|-------------|
| `source` | string | Chemin vers la spécification, relatif à votre `docs.json` |
| `generate` | boolean | `true` génère les pages et la barre latérale. Sans cette valeur, la clé reste inerte |

Les pages générées se placent sous le nom de l'onglet, converti en slug, avec un slug construit à partir de la méthode et du chemin : l'onglet ci-dessus place `POST /tickets` à l'adresse `/api-reference/post-tickets`. Les opérations sont regroupées selon leur premier `tag` ; les spécifications sans tags se rabattent sur le premier segment de chemin significatif, de sorte que `/api/v1/auctions/{auctionId}` se retrouve sous **Auctions**. Les titres proviennent du `summary` de l'opération lorsque la spécification en fournit un, sinon de la méthode et du chemin. Une opération qui cible une seule ressource reçoit un titre au singulier (`GET /users/{id}` → « Get User »).

<Note>
`generate` est opt-in par construction. Un simple `"openapi": "/openapi/api.yaml"` sur un onglet, ou un objet sans `generate: true`, continue de faire exactement ce qu'il faisait auparavant : aucune configuration existante ne gagne donc une centaine de pages à son prochain build.
</Note>

Un fichier `.mdx` committé l'emporte toujours en cas de collision de slug : vous pouvez donc adopter la génération progressivement, en l'activant puis en supprimant vos pages d'endpoint écrites à la main une par une, à votre rythme.

Si vous renommez plus tard un chemin dans votre spécification, le slug généré suit le changement. Jamdesk conserve un historique des slugs par opération et émet à chaque build une redirection de chaque ancienne URL vers l'URL actuelle, afin que les liens entrants et les favoris survivent au renommage. Vos propres [redirections](/fr/setup/redirects) et toute page existante restent prioritaires.

**Limites actuelles.** La génération ne fonctionne que sur les `navigation.tabs` de premier niveau, pas sur les groupes, les ancres ni les onglets imbriqués sous `languages` ou `versions`, et elle ne produit des pages que pour votre langue par défaut. Une clé `directory` est acceptée par le schéma mais n'a aucun effet sur l'emplacement des pages.

### api.mdx.server

**Type :** `string`

URL de base utilisée dans les exemples de code des pages à frontmatter `api:` (celles rédigées en MDX, et non les pages `openapi:`, qui tirent leurs serveurs de la spécification).

```json
{
  "api": {
    "mdx": {
      "server": "https://api.example.com"
    }
  }
}
```

<Note>
Un tableau est accepté pour des raisons de compatibilité, mais seule la première entrée est utilisée : tout ce qui suit est ignoré. `jamdesk validate` émet un avertissement si vous en listez plusieurs.
</Note>

### api.examples.languages

**Type :** `string[]`
**Par défaut :** `["curl", "python", "javascript"]`

Choisissez les langages de programmation qui apparaissent dans les exemples de code d'API générés automatiquement sur les pages `openapi:`. L'ordre du tableau détermine l'ordre d'affichage des onglets, et le premier langage est sélectionné par défaut.

**Valeurs prises en charge :** `curl`, `bash`, `python`, `javascript`, `go`, `ruby`, `csharp`, `java`, `rust`, `php`

<Note>`bash` est un alias de `curl` ; les deux produisent le même résultat. Utilisez le libellé que vous préférez.</Note>

```json All supported languages
{
  "api": {
    "examples": {
      "languages": ["curl", "python", "javascript", "go", "ruby", "csharp", "java", "rust", "php"]
    }
  }
}
```

```json Custom subset
{
  "api": {
    "examples": {
      "languages": ["python", "javascript", "go"]
    }
  }
}
```

### api.examples.defaults

**Type :** `"required" | "all"`
**Par défaut :** `"all"`

Contrôlez les paramètres qui apparaissent dans les exemples de code générés automatiquement.

| Valeur | Comportement |
|--------|--------------|
| `"all"` | Les exemples incluent tous les paramètres avec des valeurs fictives |
| `"required"` | Les exemples n'incluent que les paramètres marqués `required` dans la spécification |

```json
{
  "api": {
    "examples": {
      "defaults": "required"
    }
  }
}
```

### api.examples.prefill

**Type :** `boolean`
**Par défaut :** `false`

Lorsque la valeur est `true`, le [playground d'API](/fr/api-reference/playground) préremplit les champs de paramètres avec les valeurs `example` de votre spécification OpenAPI.

```json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

### api.playground.display

**Type :** `"interactive" | "simple" | "none"`
**Par défaut :** `"interactive"`

Contrôle le [playground d'API](/fr/api-reference/playground) sur les pages d'endpoint. Un bouton « Try it » apparaît par défaut sur chaque page `openapi:` et `api:`.

| Valeur | Comportement |
|--------|--------------|
| `"interactive"` | Playground complet : renseigner les paramètres, générer du code, envoyer des requêtes (par défaut) |
| `"simple"` | Renseigner les paramètres et copier le code, mais sans bouton Send |
| `"none"` | Playground désactivé |

```json
{
  "api": {
    "playground": {
      "display": "interactive"
    }
  }
}
```

Consultez [playground d'API](/fr/api-reference/playground) pour les détails d'utilisation et les remplacements par page.

### api.mdx.auth.method

**Type :** `"bearer" | "basic" | "key" | "cobo"`

Méthode d'authentification utilisée dans les exemples de code générés automatiquement. Lorsqu'elle est définie, les exemples incluent l'en-tête d'authentification correspondant.

| Valeur | Format de l'en-tête |
|--------|---------------------|
| `"bearer"` | `Authorization: Bearer <token>` |
| `"basic"` | `Authorization: Basic <base64>` |
| `"key"` | En-tête personnalisé (voir `api.mdx.auth.name`) |
| `"cobo"` | Authentification spécifique à Cobo |

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
}
```

### api.mdx.auth.name

**Type :** `string`

Nom d'en-tête personnalisé pour l'authentification par clé. Utilisé uniquement lorsque `api.mdx.auth.method` vaut `"key"`.

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "key",
        "name": "X-API-Key"
      }
    }
  }
}
```

## Navigation

### tabsPosition

**Type :** `"top" | "left"`

Contrôle l'emplacement d'affichage des onglets de navigation.

| Valeur | Description |
|--------|-------------|
| `"top"` | Les onglets apparaissent dans la barre d'onglets de l'en-tête |
| `"left"` | Les onglets apparaissent en haut de la barre latérale |

La valeur par défaut dépend de votre thème :

| Thème | Par défaut |
|-------|------------|
| jam | `"left"` |
| nebula | `"left"` |
| pulsar | `"top"` |
| halo | `"left"` |
| dusk | `"left"` |

```json
{ "tabsPosition": "left" }
```

## Barre de navigation et pied de page

### navbar

**Type :** `object`

| Champ | Type | Description |
|-------|------|-------------|
| `links` | array | Liens de navigation |
| `links[].label` | string | Texte par défaut du bouton |
| `links[].labels` | object | Remplacements facultatifs par langue, indexés par code de langue (par exemple `fr`, `es`). Retombe sur `label` |
| `links[].icon` | icon | Icône facultative à afficher à côté du libellé |
| `links[].href` | string | URL de destination |
| `primary` | object | Bouton d'appel à l'action principal |
| `primary.label` | string | Texte par défaut du bouton |
| `primary.labels` | object | Remplacements facultatifs par langue, indexés par code de langue. Retombe sur `label` |

```json
{
  "navbar": {
    "links": [
      {
        "label": "Blog",
        "labels": { "fr": "Blog", "es": "Blog" },
        "href": "/blog"
      },
      {
        "label": "Pricing",
        "labels": { "fr": "Tarifs", "es": "Precios" },
        "href": "/pricing"
      }
    ],
    "primary": {
      "type": "button",
      "label": "Dashboard",
      "labels": { "fr": "Tableau de bord", "es": "Panel" },
      "href": "https://app.example.com"
    }
  }
}
```

<Note>
  `labels` est facultatif. Les documentations monolingues peuvent l'omettre. Lorsqu'il est défini, la langue de l'URL courante (par exemple `/fr/...`) sélectionne le remplacement correspondant.
</Note>

### footer

**Type :** `object`

Configurez le pied de page avec des liens vers les réseaux sociaux et des colonnes de liens personnalisées.

```json
{
  "footer": {
    "socials": {
      "github": "https://github.com/yourorg",
      "x": "https://x.com/yourhandle",
      "discord": "https://discord.gg/yourserver"
    },
    "links": [
      {
        "header": "Resources",
        "items": [
          { "label": "Blog", "href": "https://example.com/blog" },
          { "label": "Changelog", "href": "/changelog" }
        ]
      }
    ]
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `socials` | object | URL des plateformes de réseaux sociaux |
| `links` | array | Configurations des colonnes de liens |
| `links[].header` | string | Titre de la colonne |
| `links[].items` | array | Tableau d'objets `{ label, href }` |

**Plateformes sociales prises en charge :** `github`, `x`, `twitter`, `linkedin`, `discord`, `slack`, `youtube`, `instagram`, `facebook`, `reddit`, `telegram`, `bluesky`, `threads`, `medium`, `hacker-news`, `website`

## Style

### styling.latex

**Type :** `boolean`

Active le rendu des formules mathématiques LaTeX avec KaTeX. Une fois activé, vous pouvez utiliser `$...$` pour les formules en ligne et `$$...$$` pour les équations en bloc.

```json
{
  "styling": {
    "latex": true
  }
}
```

Consultez [Mathématiques et LaTeX](/fr/content/math) pour les détails d'utilisation.

### styling.js

**Type :** `string | string[]`

Fichier(s) JavaScript personnalisé(s) à inclure sur chaque page. Les chemins sont relatifs à votre répertoire de documentation et doivent commencer par `/`.

```json
{
  "styling": {
    "js": "/script.js"
  }
}
```

Passez un tableau pour plusieurs fichiers :

```json
{
  "styling": {
    "js": ["/chat.js", "/analytics.js"]
  }
}
```

Sans ce champ, Jamdesk détecte automatiquement les fichiers `.js` à la racine de votre projet. Consultez [JavaScript personnalisé](/fr/customization/custom-javascript) pour plus de détails.

## Recherche

### search

**Type :** `object` (facultatif)

Personnalisez la barre de recherche de la documentation. La recherche fonctionne immédiatement ; vous n'avez besoin de ce champ que pour modifier le texte indicatif ou mettre en avant des pages populaires dans l'état vide.

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `prompt` | string | `Search documentation…` | Texte indicatif affiché dans le champ de recherche |
| `popularPages` | array | Quick Start, Introduction | Liens d'accès rapide affichés avant que le visiteur ne saisisse une requête |

```json
{
  "search": {
    "prompt": "Ask me anything…",
    "popularPages": [
      { "title": "Quick Start", "slug": "quickstart", "icon": "rocket" },
      { "title": "Authentication", "slug": "guides/authentication", "icon": "key" }
    ]
  }
}
```

#### Pages populaires

Chaque entrée de `popularPages` accepte :

| Champ | Type | Obligatoire | Description |
|-------|------|-------------|-------------|
| `title` | string | Oui | Libellé affiché pour le lien |
| `slug` | string | Oui | Chemin de la page, sans barre oblique initiale ni extension `.mdx` (par exemple `quickstart`, ou `guides/authentication` pour le fichier `guides/authentication.mdx`) |
| `icon` | string | Non | Nom d'icône Font Awesome affiché à côté du lien (par exemple `rocket` ou `bell`) |

Le champ `icon` accepte aussi l'objet complet `{ "name", "style", "library" }`. Consultez [Forme objet de l'icône](/fr/content/icons#forme-objet-de-licône). Lorsque `popularPages` est omis, Jamdesk affiche Quick Start et Introduction par défaut.

## Menu des actions IA

### contextual

**Type :** `object` (facultatif)

Configurez le menu déroulant des actions IA qui apparaît sur chaque page. Il est activé par défaut avec toutes les options ; vous n'avez besoin de ce champ que pour choisir les options affichées ou le désactiver.

| Champ | Type | Par défaut | Description |
|-------|------|------------|-------------|
| `enabled` | boolean | `true` | Définissez `false` pour retirer le menu des actions IA de votre site |

| Champ | Type | Description |
|-------|------|-------------|

## Images

### images.convertToWebp

**Type :** `boolean` (facultatif, `false` par défaut)

Active la conversion automatique en WebP des ressources PNG et JPG pendant les builds. Les fichiers convertis sont généralement 60 à 80 % plus légers que les originaux, sans perte de qualité visible. Les références dans votre MDX, votre CSS personnalisé, votre JS personnalisé et `docs.json` sont réécrites automatiquement : vous n'avez à modifier aucun chemin.

Les favicons, `og:image` et `twitter:image` conservent leur format d'origine. Certains robots des réseaux sociaux et clients de messagerie n'affichent pas WebP de façon fiable, et une carte d'aperçu cassée est pire qu'un JPG légèrement plus lourd.

```json
{
  "images": {
    "convertToWebp": true
  }
}
```

Consultez [Conversion automatique des images](/fr/builds/image-optimization) pour savoir ce qui est converti, comment fonctionne le cache et à quoi sert l'indicateur de progression du build.

## Contrôle d'accès

### auth.password

**Type :** `object` (facultatif)

Activez la protection par mot de passe partagé pour votre site. Il s'agit d'une configuration déclarative uniquement : vous définissez le mot de passe lui-même dans le [dashboard](/fr/setup/password-protection#rotation-et-révocation-des-sessions) une fois le build suivant exécuté.

Définissez `auth.password.enabled: true` pour verrouiller tout le site, ou listez des chemins dans `auth.password.private[]` pour ne protéger que ces pages. Les deux déclenchent la même invite de mot de passe dans le dashboard au build suivant.

```json
{
  "auth": {
    "password": {
      "enabled": true,
      "hint": "Ask your account manager",
      "public": ["/marketing/**", "/changelog"]
    }
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | Mode site entier. Lorsque la valeur est `true`, chaque page exige le mot de passe (sauf celles marquées publiques). |
| `hint` | `string` (200 caractères max.) | Indice en texte brut affiché sur l'écran de déverrouillage. Pas de HTML. |
| `public` | `string[]` | Motifs de chemins qui contournent le mot de passe. Prend en charge `*` (un segment) et `**` (récursif). Un simple `/` est refusé. |
| `private` | `string[]` | Chemins exacts qui exigent le mot de passe. Le définir sans `enabled` active le mode pages spécifiques. |

Consultez [Protection par mot de passe](/fr/setup/password-protection) pour le guide complet, y compris le parcours dans le dashboard et la manière dont `public: true` / `private: true` dans le frontmatter interagissent avec ces tableaux.

### auth.jwt

**Type :** `object` (facultatif)

Protégez tout le site derrière votre propre système de connexion. Votre backend signe un jeton de courte durée pour chaque utilisateur connecté, et Jamdesk l'échange contre un cookie de session. La clé de signature est générée dans le dashboard, pas dans ce fichier. `auth.jwt` et `auth.password` ne peuvent pas être activés tous les deux ; un build où les deux sont activés échoue avec une erreur `config_error`.

```json
{
  "auth": {
    "jwt": {
      "enabled": true,
      "loginUrl": "https://app.example.com/docs-login",
      "public": ["/changelog/**", "/status"]
    }
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `enabled` | `boolean` | Active l'authentification JWT. Chaque page exige une session, sauf celles marquées publiques. |
| `loginUrl` | `string` | Obligatoire lorsque `enabled` vaut `true`. Une URL `https://` absolue de votre côté. Les visiteurs sans session y sont envoyés avec `?redirect=<path>`, ce qui vous permet de les ramener à la page qu'ils avaient demandée. |
| `public` | `string[]` | Motifs de chemins qui restent accessibles sans connexion. Même syntaxe que `auth.password.public`, fusionnés avec `public: true` dans le frontmatter et `"public": true` sur les groupes de navigation. |

L'accès par page se règle en plus grâce à `groups` dans le frontmatter des pages. Consultez [Authentification JWT](/fr/setup/jwt-authentication) pour le format du jeton, le flux de redirection et le fonctionnement des groupes.
