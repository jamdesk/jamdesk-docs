Chaque build traverse plusieurs phases, de la mise en file d'attente à la mise en ligne. Suivez la progression depuis l'onglet Deployments.

## Phases du build

<Steps>
  <Step title="Queued">
    Le build attend de démarrer. La plupart des builds démarrent en quelques secondes.
  </Step>
  <Step title="Cloning">
    Récupération du contenu de votre dépôt depuis GitHub.
  </Step>
  <Step title="Validating">
    Vérification de la configuration `docs.json` et de la syntaxe MDX.
  </Step>
  <Step title="Processing">
    Analyse des fichiers MDX et résolution des imports.
  </Step>
  <Step title="Building">
    Compilation du MDX en HTML, application de la coloration syntaxique.
  </Step>
  <Step title="Deploying">
    Envoi vers le CDN et purge du cache.
  </Step>
  <Step title="Live">
    Build terminé. Votre documentation est à jour.
  </Step>
</Steps>

## Consulter le statut du build

### Vue d'ensemble du dashboard

La page principale de votre projet affiche :

- Le statut du build en cours
- L'heure du dernier déploiement réussi
- L'historique récent des builds

### Détails du build

Cliquez sur un build pour voir :

- L'heure de début et de fin
- La durée
- Le déclencheur (push, manuel, CLI)
- Le hash et le message du commit
- Le log complet du build

### Avertissements et suggestions

Les builds terminés peuvent comporter deux niveaux de retour :

- **Avertissements** (badge orange) — problèmes à corriger, comme des liens cassés ou des ressources manquantes. Ils ne font jamais échouer le build.
- **Suggestions** (ampoule) — améliorations optionnelles pour l'image de marque et le SEO de votre site, comme l'ajout d'un [favicon, d'une description ou d'un logo](/fr/customization/branding). Les suggestions n'apparaissent que sur votre dernier build terminé, ne comptent pas dans le badge d'avertissement et ne sont jamais envoyées par e-mail.

De nombreux avertissements de liens cassés ou de descriptions manquantes peuvent être corrigés automatiquement. Lorsque votre dernier build comporte des problèmes corrigibles, utilisez [Fix with AI](/fr/builds/fix-with-ai) pour examiner et appliquer les modifications sans éditer le MDX manuellement.

## Logs de build

Des logs détaillés aident à déboguer les problèmes :

```text
[12:34:56] Starting build...
[12:34:57] Cloning repository...
[12:34:59] Found docs.json at root
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Notifications de build

Jamdesk peut vous alerter par e-mail ou Slack lorsqu'un build Jamdesk se termine ou échoue :

### E-mail

Activez les alertes d'échec de build dans **Settings** → **Notifications**.

### Slack

Connectez Slack pour recevoir les notifications de build dans votre canal. Voir [Intégration Slack](/fr/integrations/slack).

## Historique des builds

Consultez vos 30 derniers builds dans l'onglet **Deployments** :

- Statut du build (réussi, échoué, annulé)
- Durée
- Type de déclencheur
- Informations sur le commit

## Annuler un build

Pour annuler un build en cours :

1. Allez dans l'onglet **Deployments**
2. Trouvez le build en cours
3. Cliquez sur **Cancel**

Le dernier build réussi précédent reste en ligne.
