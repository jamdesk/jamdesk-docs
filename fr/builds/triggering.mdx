Poussez sur GitHub et Jamdesk build automatiquement. Vous pouvez aussi déclencher des builds depuis le dashboard.

## Builds automatiques

Chaque push sur votre branche connectée déclenche un build automatiquement :

1. Vous poussez des changements sur GitHub
2. GitHub envoie un webhook à Jamdesk
3. Jamdesk met en file d'attente et démarre votre build
4. La documentation générée est déployée sur le CDN

<Tip>
Les builds sont soumis à un debouncing. Si vous poussez plusieurs commits rapidement, Jamdesk attend 10 secondes que l'activité se stabilise avant de lancer le build.
</Tip>

## Builds manuels

Déclenchez un build sans pousser de changements :

<Steps>
  <Step title="Ouvrez votre projet">
    Accédez à votre projet dans le dashboard.
  </Step>
  <Step title="Accédez aux paramètres">
    Cliquez sur **Settings** dans la barre latérale.
  </Step>
  <Step title="Cliquez sur Rebuild">
    Sélectionnez **Rebuild** pour démarrer un nouveau build.
  </Step>
</Steps>

### Quand utiliser les builds manuels

- Après avoir modifié des variables d'environnement
- Pour actualiser après un build échoué
- Après des mises à jour de la plateforme Jamdesk
- Pour vider le contenu mis en cache

## File d'attente des builds

En cas de trafic élevé, les builds peuvent être mis en file d'attente brièvement. La position dans la file s'affiche dans le dashboard. Les builds sont traités dans l'ordre de réception.

## Builds simultanés

Chaque projet peut avoir un seul build en cours d'exécution à la fois. Les nouveaux déclenchements pendant qu'un build est en cours seront mis en file d'attente.

| Plan | Projets simultanés |
|------|---------------------|
| Trial | 1 |
| Pro | 3 |
