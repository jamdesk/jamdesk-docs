Chaque projet Jamdesk bénéficie d'un sous-domaine gratuit à l'adresse `yourproject.jamdesk.app`. Il s'agit de l'URL de documentation par défaut, active immédiatement après votre premier déploiement.

Les captures d'écran montrent l'interface en anglais.

## Fonctionnement des sous-domaines

Lorsque vous créez un projet, Jamdesk attribue automatiquement un sous-domaine basé sur le slug de votre projet :

| Slug du projet | Sous-domaine |
|--------------|-----------|
| `my-docs` | `my-docs.jamdesk.app` |
| `acme-api` | `acme-api.jamdesk.app` |
| `company-help` | `company-help.jamdesk.app` |

Votre sous-domaine est actif dès que votre premier build est terminé.

## Règles de nommage des sous-domaines

Les sous-domaines doivent respecter les règles suivantes :
- Lettres minuscules, chiffres et traits d'union uniquement
- Doit commencer par une lettre
- Ne peut pas commencer ou se terminer par un trait d'union
- Entre 3 et 63 caractères
- Doit être unique parmi tous les projets Jamdesk

## Modifier votre sous-domaine

Pour modifier votre sous-domaine :

1. Accédez à votre projet dans le [Dashboard](https://dashboard.jamdesk.com)
2. Ouvrez **Settings** → **General**
3. Mettez à jour le champ **Project Slug**
4. Cliquez sur **Save**

<Warning>
Modifier votre sous-domaine casse les liens existants. Les moteurs de recherche et les sites externes pointant vers votre ancien sous-domaine obtiendront des erreurs 404. Envisagez de configurer un domaine personnalisé si vous avez besoin de stabilité d'URL.
</Warning>

Après la modification :
- Votre nouveau sous-domaine est actif immédiatement
- L'ancien sous-domaine renvoie une erreur 404
- Les favoris et liens externes sont rompus
- Le classement dans les moteurs de recherche est réinitialisé

## Certificats SSL

Les certificats SSL sont provisionnés automatiquement pour tous les sous-domaines `*.jamdesk.app`. HTTPS est requis ; les requêtes HTTP sont redirigées vers HTTPS.

## Limites de débit

Les sous-domaines Jamdesk partagent l'infrastructure avec d'autres projets. Pour une documentation à fort trafic :
- Envisagez un domaine personnalisé pour des ressources dédiées
- Contactez le support si vous prévoyez un trafic élevé soutenu

## Quand utiliser un domaine personnalisé

Utilisez un domaine personnalisé lorsque :
- Vous avez besoin de stabilité d'URL (les changements de sous-domaine cassent les liens)
- Vous voulez que votre documentation soit sur `docs.yourcompany.com`
- Vous devez correspondre au domaine de votre entreprise
- Votre documentation est destinée aux clients

Consultez [Domaines personnalisés](/fr/deploy/custom-domains) pour les instructions de configuration.

## Sous-domaine vs. domaine personnalisé

| Fonctionnalité | Sous-domaine | Domaine personnalisé |
|---------|-----------|---------------|
| Délai de mise en place | Instantané | 10-30 minutes |
| Coût | Gratuit | Gratuit (vous fournissez le domaine) |
| Format d'URL | `project.jamdesk.app` | `docs.yourdomain.com` |
| SSL | Automatique | Automatique |
| Image de marque | Marque Jamdesk | Votre marque |
| Stabilité d'URL | Liée au slug du projet | Permanente |
