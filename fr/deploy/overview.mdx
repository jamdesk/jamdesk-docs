title: Aperçu du déploiement
description: "Hébergement pour votre documentation : sous-domaine Jamdesk, domaine personnalisé avec SSL, ou sous-chemin /docs derrière votre site via proxy inverse."
---

Jamdesk déploie automatiquement votre documentation sur un sous-domaine `*.jamdesk.app`. Lorsque vous êtes prêt à passer en production sur votre propre domaine, vous pouvez choisir un sous-domaine personnalisé (comme `docs.example.com`) ou héberger la documentation sur un sous-chemin de votre site principal : `/docs` par défaut, ou tout segment personnalisé de votre choix.

## Options de déploiement

| Option | Idéal pour | Complexité de configuration |
|--------|----------|------------------|
| **Sous-domaine Jamdesk** (`your-project.jamdesk.app`) | Lancement le plus rapide, aucune configuration DNS | Faible |
| **Sous-domaine personnalisé** (`docs.example.com`) | Documentation de production à votre image | Moyenne |
| **Hébergement en sous-chemin** (`example.com/docs`, personnalisable) | Garder la documentation sur le domaine principal | Élevée |

## Hébergement par défaut (sans configuration)

Chaque projet est mis en ligne sur un sous-domaine Jamdesk dès que vous connectez un dépôt. C'est l'option la plus simple pour la documentation interne, les preview, ou les lancements anticipés.

## Domaine personnalisé (sous-domaine)

Utilisez votre propre sous-domaine (par exemple, `docs.example.com`) pour une URL publique à votre image. Vous ajouterez des enregistrements DNS et vérifierez la propriété depuis le dashboard Jamdesk.

<Note>
La vérification DNS et le SSL sont gérés automatiquement une fois les enregistrements en place. Consultez [Domaines personnalisés](/fr/deploy/custom-domains) pour la configuration.
</Note>

## Hébergement en sous-chemin

Hébergez la documentation sur un sous-chemin de votre domaine en redirigeant le trafic vers Jamdesk via un proxy : `example.com/docs` par défaut, ou un segment personnalisé comme `example.com/help`. Utilisez cette option lorsque vous souhaitez que la documentation se trouve sous votre domaine marketing principal.

<Info>
L'hébergement en sous-chemin nécessite une couche proxy ou CDN pour transmettre les requêtes et définir l'en-tête `X-Jamdesk-Forwarded-Host`. Consultez [Hébergement en sous-chemin](/fr/deploy/subpath-hosting).
</Info>

### Exemple d'extrait de proxy (nginx)

```nginx nginx.conf
location /docs {
    proxy_pass https://YOUR_SLUG.jamdesk.app;
    proxy_set_header X-Jamdesk-Forwarded-Host $host;
}

location /_next/ {
    proxy_pass https://YOUR_SLUG.jamdesk.app;
}

location /_jd/ {
    proxy_pass https://YOUR_SLUG.jamdesk.app;
}
```

Pour une configuration complète avec SSL, en-têtes et conseils spécifiques au fournisseur, consultez le guide [Hébergement en sous-chemin](/fr/deploy/subpath-hosting).
