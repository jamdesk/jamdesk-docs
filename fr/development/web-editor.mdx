---
title: Éditeur web
description: "Modifiez vos docs Jamdesk dans le navigateur : repo connecté, MDX avec aperçu en direct, commit direct sur GitHub qui déclenche un build automatiquement."
---

L'éditeur web vous permet de modifier votre documentation directement dans le dashboard Jamdesk, sans cloner le repo ni toucher à un terminal. Ouvrez une page, éditez son MDX avec un aperçu en direct à côté, et commitez vos changements sur votre branche GitHub. Chaque commit déclenche automatiquement un build, si bien que vos changements sont mis en ligne exactement comme le ferait un `git push`.

C'est l'équivalent dans le navigateur de la [preview locale](/fr/development/local-preview) et de l'[extension VS Code](/fr/development/vscode-extension). Utilisez-le pour faire une modification rapide depuis n'importe où, ou lorsque vous préférez ne pas cloner le repo du tout.

## Ouvrir l'éditeur

Cliquez sur **Editor** dans la barre latérale du dashboard. L'éditeur s'ouvre sur le repository connecté de votre projet et sa branche par défaut.

<Note>
L'éditeur nécessite un [repository GitHub connecté](/fr/setup/connecting-github) et un écran large (ordinateur de bureau). Sur des fenêtres plus étroites, il affiche un message « navigateur plus large requis », car le code et l'aperçu ont besoin de place pour s'afficher côte à côte. Il est disponible pour tout propriétaire de projet et membre d'équipe, sur tous les plans.
</Note>

## L'interface

L'éditeur comporte trois volets :

| Volet | Ce qu'il fait |
|------|--------------|
| **Navigation** (gauche) | Les pages et groupes de votre site, lus depuis `docs.json`. Filtrez les pages, ouvrez l'éditeur de **Configuration** (`docs.json`), ou **Add page**. |
| **Editor** (centre) | Un éditeur de code MDX pour le fichier ouvert, avec coloration syntaxique et compteur de mots. |
| **Preview** (droite) | Un rendu en direct de la page, mis à jour au fur et à mesure que vous tapez. Basculez entre **Desktop / Mobile** et **Light / Dark** pour vérifier le rendu. |

La branche que vous éditez s'affiche en haut à gauche ; changez de branche avec le sélecteur de branche.

## Modifier une page

Cliquez sur une page dans la navigation pour l'ouvrir. Modifiez le MDX dans le volet central et observez l'aperçu se mettre à jour en direct. Vos modifications sont conservées comme brouillon local dans votre navigateur jusqu'à ce que vous commitiez, vous pouvez donc passer d'une page à l'autre sans perdre votre travail. Rien n'est écrit sur GitHub tant que vous n'avez pas choisi de commiter.

## Ajouter une page

Cliquez sur **Add page** pour créer une nouvelle page sans quitter l'éditeur :

1. Choisissez un modèle de départ.
2. Saisissez un titre. Le nom de fichier de la page en est dérivé automatiquement.
3. Choisissez à quel groupe de navigation elle appartient.

La nouvelle page s'ouvre comme brouillon. Lorsque vous commitez, Jamdesk écrit à la fois le nouveau fichier `.mdx` et l'entrée de navigation dans `docs.json` dans le même commit.

## Commiter les changements

Lorsque vous êtes prêt à publier, commitez vos changements en attente sur GitHub :

<Steps>
  <Step title="Ouvrir la boîte de dialogue de commit">
    Cliquez sur **Commit**. La boîte de dialogue liste chaque fichier que vous avez modifié (une page, `docs.json`, ou plusieurs à la fois).
  </Step>
  <Step title="Rédiger un message">
    Saisissez un message de commit, ou cliquez sur **Generate** pour que Jamdesk en rédige un à partir de votre diff.
  </Step>
  <Step title="Commiter">
    Jamdesk commite les changements sur votre branche actuelle et démarre immédiatement un build. Suivez-le sur la page **Builds** du projet.
  </Step>
</Steps>

Vous préférez abandonner les modifications à la place ? **Revert** annule les changements non enregistrés de la page actuelle et restaure la version commitée.

## Travailler avec des changements externes

Si quelqu'un d'autre pousse sur la même branche pendant que vous éditez, l'éditeur remarque que la branche a évolué et le signale. Lorsque vous commitez, tout fichier modifié en amont est présenté comme une fusion à trois voies afin que vous puissiez réconcilier les deux versions. Vos modifications locales ne sont jamais abandonnées.

<Tip>
Commiter depuis l'éditeur équivaut exactement à pousser depuis votre propre machine : cela écrit un vrai commit dans votre repo et déclenche le même pipeline de build. Si vos docs se trouvent dans un sous-répertoire du repo ([configuration monorepo](/fr/setup/monorepo-support)), l'éditeur y lit et y écrit automatiquement.
</Tip>

## Prérequis

| Prérequis | Détail |
|-------------|--------|
| **GitHub connecté** | Le projet doit avoir un repository et une branche connectés. |
| **Navigateur de bureau** | Un écran large (environ 1400px et plus) ; l'éditeur n'est pas disponible sur les largeurs mobiles. |
| **Accès** | Tout propriétaire ou membre du projet. La modification écrit dans votre repo, les verrous d'écriture habituels (par exemple, un abonnement en retard de paiement) s'appliquent donc. |
