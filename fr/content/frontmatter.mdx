Chaque fichier MDX commence par un bloc YAML délimité par des marqueurs `---`. Ces métadonnées contrôlent le titre de votre page, l'apparence de la barre latérale, ainsi que l'aspect de la page lorsqu'elle est partagée sur les réseaux sociaux ou dans les résultats de recherche.

## Frontmatter de base

Chaque page nécessite au moins un titre :

```yaml
---
title: Getting Started
description: Learn the basics in 5 minutes
---
```

## Champs disponibles

### Requis

| Champ | Type | Description |
|-------|------|-------------|
| `title` | string | Titre de la page affiché dans la navigation et l'onglet du navigateur |

### Recommandé

| Champ | Type | Description |
|-------|------|-------------|
| `description` | string | Résumé court pour le SEO et les résultats de recherche (50 à 160 caractères) |

### Facultatif

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `icon` | string | - | Icône Font Awesome affichée à côté du titre de la page dans la barre latérale |
| `sidebarTitle` | string | `title` | Titre plus court pour la barre latérale |
| `mode` | string | - | Réglez sur `"wide"` pour une mise en page pleine largeur |
| `hideFooter` | boolean | `false` | Masque le pied de page social sur cette page |
| `rss` | boolean | `false` | Active la génération d'un flux RSS à partir des composants [Update](/fr/components/update) présents sur cette page |
| `search` | boolean | `true` | Réglez sur `false` pour exclure la page de la recherche du site, des réponses du chat IA et du MCP. Elle reste dans votre barre latérale, votre sitemap et votre llms.txt. Voir [Garder une page hors de la recherche uniquement](/fr/content/hidden-pages#exclure-une-page-uniquement-de-la-recherche) |
| `private` | boolean | `false` | Exige le [mot de passe du site](/fr/setup/password-protection) pour consulter cette page. Activer ce champ sur une page déclenche le mode pages spécifiques au prochain build. |
| `public` | boolean | `false` | Exempte cette page de la protection par mot de passe ou de l'[authentification JWT](/fr/setup/jwt-authentication) lorsque le site entier est verrouillé. L'emporte sur `private: true` si les deux sont définis. |
| `groups` | string[] | - | Avec l'authentification JWT activée, seuls les visiteurs dont le jeton liste au moins un de ces groupes peuvent ouvrir la page ; les autres reçoivent une erreur 404 et ne la voient pas dans la navigation. Jusqu'à 32 groupes par page. Ignoré en mode mot de passe. Voir [Accès basé sur les groupes](/fr/setup/jwt-authentication#accès-basé-sur-les-groupes). |
| `lastUpdatedDate` | string | - | Remplace la date « Last updated on » (dernière mise à jour le) de cette page au lieu d'utiliser la date de son dernier commit Git. Mettez la valeur entre guillemets : `"2026-09-01"`. La ligne du pied de page nécessite `metadata.timestamp` dans `docs.json` ; votre sitemap et vos données structurées utilisent la date dans tous les cas. Voir [Date de dernière mise à jour](#date-de-dernière-mise-à-jour) |

### Date de dernière mise à jour

Lorsque `metadata.timestamp` est activé dans `docs.json`, chaque page affiche la date du dernier commit qui a modifié son fichier. `lastUpdatedDate` remplace cette date sur une page donnée :

```yaml
---
title: Authentication
lastUpdatedDate: "2026-09-01"
---
```

Utilisez ce champ lorsque vous avez révisé une page et souhaitez l'indiquer, ou lorsqu'un commit de mise en forme a modifié la date sans rien changer que le lecteur remarquerait.

Mettez la valeur entre guillemets. Un `2026-09-01` non entouré de guillemets est interprété comme un timestamp plutôt qu'une date et peut afficher un jour décalé. Une valeur qui n'est pas une date est ignorée et la date du commit s'affiche à la place, si bien qu'une faute de frappe ne vide jamais la ligne.

<Note>
La ligne du pied de page n'apparaît que si `metadata.timestamp` est activé, mais `lastUpdatedDate` n'est pas qu'un réglage du pied de page : le `<lastmod>` de votre sitemap et le `dateModified` des données structurées de la page l'utilisent tous les deux, que le pied de page soit activé ou non. Définissez-le lorsque la date est ce que vous voulez indiquer, pas seulement lorsque vous voulez qu'elle s'affiche.
</Note>

Cette substitution définit également `dateModified` dans les données structurées de la page, afin que les moteurs de recherche et les assistants IA voient la même date que vos lecteurs.

### SEO et réseaux sociaux

Contrôlez l'apparence de la page dans les résultats de recherche et les aperçus sociaux. Définissez ces champs comme des clés de premier niveau, ou dans un bloc imbriqué `seo:`. Les deux fonctionnent, et les valeurs propres à chaque page l'emportent sur les valeurs par défaut `seo.metatags` de votre `docs.json`.

| Champ | Type | Par défaut | Description |
|-------|------|---------|-------------|
| `keywords` | string[] | - | Mots-clés de recherche, générés sous forme de balise `<meta name="keywords">` |
| `canonical` | string | auto | URL canonique de cette page, remplaçant celle générée automatiquement |
| `noindex` | boolean | `false` | Exclut cette page des moteurs de recherche et du sitemap |
| `og:*` / `twitter:*` | string | - | Balises Open Graph et Twitter/X pour l'aperçu social (par ex. `og:title`, `og:image`, `twitter:card`) |
| `seo` | object | - | Bloc imbriqué regroupant les champs ci-dessus ainsi que des balises meta personnalisées |

```yaml
---
title: API Reference
description: REST endpoints and authentication
"og:image": /images/api-card.png
"twitter:card": summary_large_image
canonical: https://docs.acme.com/api-reference
---
```

Consultez [Optimisation SEO](/fr/content/seo) pour la liste complète des balises prises en charge et des exemples.

<Tip>
Après un build, collez l'URL de la page dans l'outil gratuit [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) pour voir le rendu de ces balises sur X, Facebook, LinkedIn, Slack, Discord et plus encore.
</Tip>

## Exemples

### Page de documentation standard

```yaml
---
title: Authentication
description: Secure your API with OAuth 2.0 and API keys
icon: lock
---
```

### Titre long avec substitution de barre latérale

```yaml
---
title: Configuring Single Sign-On with SAML 2.0
sidebarTitle: SSO Setup
description: Set up enterprise SSO for your organization
---
```

Le titre complet apparaît sur la page, tandis que le `sidebarTitle`, plus court, garde la navigation lisible.

### Mise en page large

```yaml
---
title: API Reference
description: Complete API documentation
mode: wide
---
```

Le mode large supprime la table des matières et étend le contenu sur toute la largeur. Utile pour les pages de référence API ou le contenu comportant des tableaux larges.

### Masquer le pied de page

```yaml
---
title: Custom Landing
description: A focused landing page experience
hideFooter: true
---
```

Utilisez `hideFooter` pour les pages d'atterrissage, les pages de changelog, ou toute page où vous souhaitez un bas de page plus épuré, sans liens sociaux.

## Bonnes pratiques SEO

<AccordionGroup>
  <Accordion title="Rédiger des titres percutants" icon="heading" defaultOpen>
    Votre titre apparaît dans :
    - Les onglets du navigateur
    - Les résultats des moteurs de recherche
    - La barre latérale de navigation
    - Les partages sur les réseaux sociaux

    Gardez les titres sous 60 caractères. Placez les mots-clés importants en premier.

    ```yaml
    # Good - clear and keyword-rich
    title: Deploy to Production

    # Avoid - vague or too long
    title: How to Deploy Your Application to Production Servers
    ```
  </Accordion>

  <Accordion title="Rédiger des descriptions utiles" icon="align-left">
    Les descriptions apparaissent dans les résultats de recherche et les aperçus sociaux. Visez 50 à 160 caractères qui :
    - Résument le contenu de la page
    - Incluent des mots-clés pertinents
    - Donnent envie de cliquer

    ```yaml
    # Good - actionable and specific
    description: Deploy your docs to production in under 2 minutes with zero configuration

    # Avoid - generic or missing
    description: Documentation page
    ```
  </Accordion>

  <Accordion title="Utiliser des icônes cohérentes" icon="icons">
    Les icônes aident les utilisateurs à parcourir la navigation rapidement. Utilisez la même icône pour les pages liées :

    | Sujet | Icône suggérée |
    |-------|----------------|
    | Démarrage | `rocket` |
    | Authentification | `lock` |
    | Référence API | `code` |
    | Paramètres | `gear` |
    | Facturation | `credit-card` |

    Parcourez les icônes sur [Font Awesome](https://fontawesome.com/icons).
  </Accordion>
</AccordionGroup>

## Validation

Jamdesk valide le frontmatter lors du build. Erreurs courantes :

<Accordion title="Champs requis manquants">
```text
Error: Page "api/auth.mdx" is missing required field: title
```

**Correction :** Ajoutez le champ `title` à votre frontmatter.
</Accordion>

<Accordion title="Syntaxe YAML invalide">
```text
Error: Invalid frontmatter in "guide.mdx": unexpected token
```

**Correction :** Vérifiez les points suivants :
- Guillemets manquants autour des chaînes contenant des caractères spéciaux
- Indentation incorrecte
- Deux-points manquants après les clés

Collez le bloc entre les marqueurs `---` dans l'outil gratuit [YAML Validator](https://jamdesk.com/utilities/yaml-validator) pour repérer la ligne et la colonne de l'erreur.
</Accordion>
