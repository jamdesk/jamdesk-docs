## Optimiser votre contenu

### Rédiger un frontmatter efficace

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Placez les mots-clés en tête.** « Configuration de l'authentification » est meilleur que « Comment configurer l'authentification ».
</Tip>

### Titres de page

- Limitez-vous à 60 caractères pour éviter la troncature dans les résultats de recherche
- Incluez votre mot-clé principal dès le début
- Donnez un titre unique à chaque page dans votre documentation

### Descriptions

- Visez 120 à 160 caractères
- Résumez ce que le lecteur va apprendre
- Intégrez les mots-clés pertinents de façon naturelle

<Note>
**Repli automatique.** Lorsque `description` est absent du frontmatter, Jamdesk extrait automatiquement le premier paragraphe de prose du contenu de la page (jusqu'à 155 caractères). Les titres, blocs de code, images et composants MDX sont ignorés. Ce texte est utilisé pour `<meta name="description">`, Open Graph et les cartes Twitter. Il est tout de même recommandé de rédiger une description explicite pour de meilleurs résultats.
</Note>

## Contrôler l'indexation

### Paramètres globaux du site

Dans votre `docs.json`, configurez le comportement par défaut des robots :

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Contrôle par page

Remplacez l'indexation pour des pages spécifiques dans le frontmatter :

```yaml
---
title: Internal Notes
noindex: true
---
```

Utilisez `noindex` pour :
- Les pages en brouillon ou en cours de rédaction
- La documentation interne
- Le contenu déprécié conservé pour référence

## URLs canoniques

Si votre documentation est accessible depuis plusieurs URLs, définissez une URL canonique :

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Vous pouvez également définir une base canonique à l'échelle du site dans `docs.json`. Jamdesk y ajoute le chemin de chaque page, afin que chaque page dispose d'une URL canonique correcte :

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Aperçus sociaux & Open Graph

Jamdesk génère automatiquement une carte sociale aux dimensions 1200×630 pour chaque page. Remplacez n'importe quelle balise sociale dans le frontmatter. Vous pouvez utiliser des **clés de premier niveau** (style Mintlify) ou un bloc **`seo:`** imbriqué. Les deux fonctionnent, et lorsqu'une même clé est définie des deux façons, la valeur de premier niveau l'emporte.

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  og:title: API Reference — Acme
  og:image: /images/api-social-card.png
  twitter:card: summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Balises prises en charge

| Groupe | Balises |
|--------|---------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Article | `og:type: article` avec `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, balises app-card |
| Autre | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color`, ainsi que toute balise personnalisée (placez les balises personnalisées sous `seo:`) |

<Note>
**Dimensions personnalisées de l'image OG.** Lorsque vous définissez un `og:image` personnalisé, renseignez également `og:image:width` et `og:image:height` afin que les robots d'exploration l'affichent correctement. La carte générée automatiquement est toujours en 1200×630.
</Note>

<Note>
**Balises personnalisées.** Les balises meta arbitraires (ex. `x-pinterest`) sont émises sous la forme `<meta name="...">`. Placez-les sous le bloc `seo:`. Seules les clés SEO reconnues sont prises en compte lorsqu'elles sont placées à plat.
</Note>

### Image par défaut à l'échelle du site

Définissez une image sociale de repli pour chaque page dans `docs.json`. Toute page qui définit son propre `og:image` la remplace :

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Prévisualisez avant de publier.** Après un build, collez l'URL de la page dans un outil de preview Open Graph (comme [opengraph.xyz](https://www.opengraph.xyz)) pour vérifier le rendu de la carte sur chaque plateforme.
</Tip>

## Sitemap & Robots.txt

Chaque site Jamdesk génère automatiquement `sitemap.xml` et `robots.txt` à chaque build.

| Fichier | Rôle |
|---------|------|
| `sitemap.xml` | Liste toutes les pages avec leurs dates de dernière modification pour les moteurs de recherche |
| `robots.txt` | Autorise tous les robots et les redirige vers le sitemap |

### Où les trouver

Les URLs dépendent de si votre documentation se trouve à la racine d'un domaine ou dans un sous-chemin `/docs` :

<Tabs>
  <Tab title="Domaine racine">
    Si votre documentation est à la racine de votre domaine (ex. `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si votre documentation est sous `/docs` sur votre site principal (comme ce site sur `jamdesk.com/docs`) :

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Contenu du sitemap

- Toutes les pages publiées (hors celles avec `noindex` ou `hidden` dans le frontmatter)
- Les dates de dernière modification issues du frontmatter lorsqu'elles sont disponibles
- Une fréquence de modification hebdomadaire

### Exclure des pages du sitemap

Ajoutez `noindex` au frontmatter pour exclure une page du sitemap et des moteurs de recherche :

```yaml
---
title: Internal Notes
noindex: true
---
```

Les pages avec `hidden: true` sont également exclues automatiquement.

## Données structurées JSON-LD

Chaque page inclut automatiquement des données structurées [schema.org](https://schema.org) sous forme de balise `<script type="application/ld+json">` avec deux schémas :

- `WebSite` : le nom, l'URL et la description de votre site (issus de `docs.json`).
- `BreadcrumbList` : le chemin de navigation de l'accueil jusqu'à la page actuelle, dérivé de votre configuration `navigation`.

Aucune configuration requise. Les moteurs de recherche utilisent ces données pour des résultats enrichis tels que les fils d'Ariane dans les listes de recherche.

<Tip>
**Vérifiez votre balisage.** Collez n'importe quelle URL de page dans le [Test des résultats enrichis de Google](https://search.google.com/test/rich-results) pour confirmer que les données structurées sont bien détectées.
</Tip>

## IndexNow

Après chaque build, Jamdesk soumet automatiquement les URLs de pages modifiées à [IndexNow](https://www.indexnow.org) pour une indexation plus rapide par les moteurs de recherche. Cela notifie Bing, Yandex et les autres moteurs participants de vos mises à jour de contenu, sans attendre leur prochain cycle d'exploration.

- Se déclenche après chaque build réussi
- Soumet uniquement les pages qui ont réellement changé
- Non bloquant, n'impacte jamais la durée du build
- Aucune configuration requise
