## Optimiser votre contenu

### Rédiger un frontmatter efficace

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Placez les mots-clés en tête.** « Configuration de l'authentification » est préférable à « Comment configurer l'authentification ».
</Tip>

### Titres de page

- Limitez-vous à 60 caractères pour éviter la troncature dans les résultats de recherche
- Incluez votre mot-clé principal dès le début
- Rendez chaque titre unique dans toute votre documentation

### Descriptions

- Visez 120 à 160 caractères
- Résumez ce que le lecteur va apprendre
- Intégrez naturellement les mots-clés pertinents

<Note>
**Texte de remplacement généré automatiquement.** Lorsque `description` est absent du frontmatter, Jamdesk extrait automatiquement le premier paragraphe de texte du contenu de la page (jusqu'à 155 caractères). Les titres, blocs de code, images et composants MDX sont ignorés. Ce texte est utilisé pour `<meta name="description">`, Open Graph et les cartes Twitter. Rédiger une description explicite reste recommandé pour de meilleurs résultats.
</Note>

## Contrôler l'indexation

### Paramètres globaux du site

Dans votre `docs.json`, configurez le comportement par défaut des robots :

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Contrôle par page

Remplacez le comportement d'indexation pour des pages spécifiques dans le frontmatter :

```yaml
---
title: Internal Notes
noindex: true
---
```

Utilisez `noindex` pour :
- Les pages en brouillon ou en cours de rédaction
- La documentation interne
- Le contenu obsolète que vous conservez à titre de référence

### Indexation par les moteurs de recherche et ingestion par l'IA

Les métadonnées `robots` et `noindex` contrôlent les **moteurs de recherche** — c'est-à-dire si une page apparaît dans Google et dans votre `sitemap.xml`. Elles n'ont aucun effet sur les fichiers `llms.txt` et `llms-full.txt` que les outils IA lisent. Pour cesser de publier ces fichiers, définissez `seo.ai.llmsTxt` à `false` — voir [Désactiver llms.txt](/fr/ai/llms-txt#désactiver-llmstxt). Les deux contrôles sont indépendants : une page peut être indexée par les moteurs de recherche mais exclue de l'ingestion IA, ou l'inverse.

## URL canoniques

Si votre documentation est accessible depuis plusieurs URL, définissez une URL canonique :

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Vous pouvez également définir une base canonique globale dans `docs.json`. Jamdesk y ajoute le chemin de chaque page, de sorte que chaque page obtient une URL canonique correcte :

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Aperçus sociaux et Open Graph

Jamdesk génère automatiquement une carte sociale de marque en 1200×630 pour chaque page. Remplacez n'importe quelle balise sociale dans le frontmatter. Vous pouvez utiliser des **clés plates au niveau supérieur** ou un bloc **`seo:`** imbriqué. Les deux fonctionnent, et lorsque la même clé est définie des deux façons, la valeur plate au niveau supérieur l'emporte.

<Card title="Aperçu OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Voyez exactement comment la carte de n'importe quelle page s'affiche sur X, Facebook, LinkedIn, Slack, Discord, WhatsApp, iMessage et Google — et validez ses balises Open Graph — avec notre outil gratuit OpenGraph Preview.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Balises prises en charge

| Groupe | Balises |
|--------|---------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Article | `og:type: article` avec `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, balises app-card |
| Autres | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color`, ainsi que tout tag personnalisé (placez les tags personnalisés sous `seo:`) |

<Note>
**Dimensions d'image OG personnalisée.** Lorsque vous définissez un `og:image` personnalisé, définissez également `og:image:width`
et `og:image:height` pour que les crawlers l'affichent avec netteté. La carte générée automatiquement est toujours
1200×630.
</Note>

<Note>
**Balises personnalisées.** Les balises meta arbitraires (p. ex. `x-pinterest`) sont émises sous la forme `<meta name="...">`.
Placez-les sous le bloc `seo:`. Seules les clés SEO reconnues sont prises en compte lorsqu'elles sont placées à plat.
</Note>

### Type de carte Twitter / X

La balise `twitter:card` contrôle la mise en page utilisée par X (et d'autres plateformes) lorsque votre lien est partagé :

| Valeur | Apparence |
|--------|-----------|
| `summary` | Petite vignette carrée à gauche, titre + description à côté. Compact. |
| `summary_large_image` | Grande image pleine largeur en haut, titre + description en dessous. L'option la plus percutante. |

Pour une carte de marque en 1200×630, utilisez `summary_large_image` afin que l'image s'affiche en pleine largeur.

### Image par défaut à l'échelle du site

Définissez une image sociale de secours pour toutes les pages dans `docs.json`. Toute page qui définit son propre `og:image` la remplace :

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Vérifiez avant de publier.** Après un build, collez l'URL de la page dans l'outil gratuit [Jamdesk OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) pour voir exactement comment votre carte s'affiche sur X, Facebook, LinkedIn, Slack, Discord, WhatsApp, iMessage et Google. Il valide également vos balises Open Graph, vérifie les dimensions des images et explique comment corriger les problèmes détectés.
</Tip>

## Sitemap et Robots.txt

Chaque site Jamdesk génère automatiquement `sitemap.xml` et `robots.txt` à chaque build.

| Fichier | Rôle |
|---------|------|
| `sitemap.xml` | Liste toutes les pages avec les dates de dernière modification pour les moteurs de recherche |
| `robots.txt` | Autorise tous les crawlers et les redirige vers le sitemap |

### Où les trouver

Les URL dépendent de si votre documentation se trouve à la racine d'un domaine ou sous un sous-chemin `/docs` :

<Tabs>
  <Tab title="Domaine racine">
    Si votre documentation est à la racine de votre domaine (par ex., `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si votre documentation se trouve sous `/docs` sur votre site principal (comme ce site à `jamdesk.com/docs`) :

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Contenu du sitemap

- Toutes les pages publiées (hors celles avec `noindex` ou `hidden` dans le frontmatter)
- Les dates de dernière modification du frontmatter lorsqu'elles sont disponibles
- Fréquence de modification hebdomadaire

### Exclure des pages du sitemap

Ajoutez `noindex` au frontmatter pour exclure une page à la fois du sitemap et des moteurs de recherche :

```yaml
---
title: Internal Notes
noindex: true
---
```

Les pages avec `hidden: true` sont également exclues automatiquement.

## Données structurées JSON-LD

Chaque page inclut automatiquement des données structurées [schema.org](https://schema.org) sous la forme d'une balise `<script type="application/ld+json">` avec deux schémas :

- `WebSite` : le nom, l'URL et la description de votre site (tirés de `docs.json`).
- `BreadcrumbList` : le chemin de navigation de l'accueil jusqu'à la page actuelle, dérivé de votre configuration `navigation`.

Aucune configuration n'est nécessaire. Les moteurs de recherche utilisent ces données pour les résultats enrichis, comme les fils d'Ariane dans les listes de résultats.

<Tip>
**Vérifiez votre balisage.** Collez n'importe quelle URL de page dans le [test des résultats enrichis de Google](https://search.google.com/test/rich-results) pour confirmer que les données structurées sont détectées.
</Tip>

## IndexNow

Après chaque build, Jamdesk soumet automatiquement les URL de pages modifiées à [IndexNow](https://www.indexnow.org) pour une indexation plus rapide par les moteurs de recherche. Cela notifie Bing, Yandex et d'autres moteurs participants de vos modifications de contenu sans attendre leur prochain cycle d'exploration.

- Se déclenche après chaque build réussi
- Ne soumet que les pages qui ont réellement changé
- Non bloquant — ne retarde jamais votre build
- Aucune configuration requise

## Bonnes pratiques

Parcourez cette liste de vérification avant de publier :

<Note>
**Liste de vérification avant publication**

- **Titres uniques** — Chaque page a un titre distinct et descriptif de moins de 60 caractères.
- **Descriptions précises** — Les descriptions résument la page en 120–160 caractères.
- **Structure de titres logique** — Les titres suivent une hiérarchie claire : un seul H1, puis H2 → H3.
- **Liens descriptifs** — Les liens internes utilisent un texte d'ancrage significatif, jamais « cliquez ici ».
- **Texte alternatif des images** — Chaque image possède un texte alternatif pour l'accessibilité et la recherche d'images.
- **Image sociale** — Définissez un `og:image` personnalisé sur les pages clés, ou utilisez la carte générée automatiquement. Vérifiez-la avec l'outil [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
