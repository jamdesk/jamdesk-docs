## Optimiser votre contenu

### Rédiger un frontmatter efficace

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Placez les mots-clés en début de titre.** « Configuration de l'authentification » est plus efficace que « Comment configurer l'authentification ».
</Tip>

### Titres de pages

- Restez sous 60 caractères pour éviter la troncature dans les résultats de recherche
- Incluez votre mot-clé principal en début de titre
- Donnez un titre unique à chaque page de votre documentation

### Descriptions

- Visez 120-160 caractères
- Résumez ce que le lecteur va apprendre
- Intégrez les mots-clés pertinents de façon naturelle

<Note>
**Fallback auto-généré.** Lorsque `description` est absent du frontmatter, Jamdesk extrait automatiquement le premier paragraphe de prose de votre page (jusqu'à 155 caractères). Les titres, blocs de code, images et composants MDX sont ignorés. Cette valeur est utilisée pour `<meta name="description">`, Open Graph et les cartes Twitter. Il est tout de même recommandé de rédiger une description explicite pour de meilleurs résultats.
</Note>

## Contrôler l'indexation

### Paramètres globaux du site

Dans votre `docs.json`, configurez le comportement robots par défaut :

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Contrôle par page

Remplacez le comportement d'indexation pour des pages spécifiques dans le frontmatter :

```yaml
---
title: Internal Notes
noindex: true
---
```

Utilisez `noindex` pour :
- Les pages en brouillon ou en cours de rédaction
- La documentation interne
- Le contenu déprécié conservé à titre de référence

## URL canoniques

Si votre documentation est accessible à plusieurs URL, définissez une URL canonique :

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Vous pouvez également définir une base canonique globale dans `docs.json`. Jamdesk ajoute le chemin de chaque page, de sorte que chaque page obtient une URL canonique correcte :

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Prévisualisations sociales & Open Graph

Jamdesk génère automatiquement une carte sociale 1200×630 pour chaque page. Vous pouvez remplacer n'importe quelle balise sociale dans le frontmatter. Vous pouvez utiliser des **clés à plat au niveau racine** ou un bloc **`seo:`** imbriqué. Les deux fonctionnent, et lorsque la même clé est définie des deux façons, la valeur à plat au niveau racine prend la priorité.

<Card title="OpenGraph Preview" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Voyez exactement comment la carte d'une page s'affiche sur X, Facebook, LinkedIn, Slack, Discord, WhatsApp, iMessage et Google — et validez ses balises Open Graph — avec notre outil gratuit OpenGraph Preview.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Balises supportées

| Groupe | Balises |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Article | `og:type: article` avec `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, balises app-card |
| Autres | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color`, plus toute balise personnalisée (placez les balises personnalisées sous `seo:`) |

<Note>
**Dimensions d'image OG personnalisée.** Lorsque vous définissez un `og:image` personnalisé, définissez également `og:image:width`
et `og:image:height` afin que les robots d'indexation l'affichent correctement. La carte auto-générée fait toujours
1200×630.
</Note>

<Note>
**Balises personnalisées.** Les balises méta arbitraires (ex. `x-pinterest`) sont émises sous forme de `<meta name="...">`.
Placez-les sous le bloc `seo:`. Seules les clés SEO reconnues sont prises en compte lorsqu'elles sont définies à plat.
</Note>

### Type de carte Twitter / X

La balise `twitter:card` contrôle la mise en page utilisée par X (et d'autres plateformes) lors du partage de votre lien :

| Valeur | Apparence |
|-------|--------------------|
| `summary` | Petite vignette carrée à gauche, titre + description à côté. Format compact. |
| `summary_large_image` | Grande image pleine largeur en haut, titre + description en dessous. Format accrocheur. |

Pour une carte 1200×630, utilisez `summary_large_image` afin que l'image s'affiche en pleine largeur.

### Image par défaut à l'échelle du site

Définissez une image sociale de secours pour toutes les pages dans `docs.json`. Toute page qui définit son propre `og:image` la remplace :

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Prévisualisez avant de publier.** Après un build, collez l'URL de la page dans l'outil gratuit [Jamdesk OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) pour voir exactement comment votre carte s'affiche sur X, Facebook, LinkedIn, Slack, Discord, WhatsApp, iMessage et Google. Il valide également vos balises Open Graph, vérifie les dimensions de l'image et explique comment corriger les problèmes détectés.
</Tip>

## Sitemap & Robots.txt

Chaque site Jamdesk génère automatiquement `sitemap.xml` et `robots.txt` à chaque build.

| Fichier | Rôle |
|------|---------|
| `sitemap.xml` | Liste toutes les pages avec leurs dates de dernière modification pour les moteurs de recherche |
| `robots.txt` | Autorise tous les robots d'indexation et les oriente vers le sitemap |

### Où les trouver

Les URL dépendent de si votre documentation est à un domaine racine ou sous un sous-chemin `/docs` :

<Tabs>
  <Tab title="Domaine racine">
    Si votre documentation est à la racine de votre domaine (ex. `docs.acme.com` ou `acme.jamdesk.app`) :

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Sous-chemin /docs">
    Si votre documentation est sous `/docs` sur votre site principal (comme ce site à `jamdesk.com/docs`) :

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Contenu du sitemap

- Toutes les pages publiées (sauf celles avec le frontmatter `noindex` ou `hidden`)
- Les dates de dernière modification du frontmatter lorsqu'elles sont disponibles
- Fréquence de modification hebdomadaire

### Exclure des pages du sitemap

Ajoutez `noindex` au frontmatter pour exclure une page du sitemap et des moteurs de recherche :

```yaml
---
title: Internal Notes
noindex: true
---
```

Les pages avec `hidden: true` sont également exclues automatiquement.

## Données structurées JSON-LD

Chaque page inclut automatiquement des données structurées [schema.org](https://schema.org) sous la forme d'une balise `<script type="application/ld+json">` avec deux schémas :

- `WebSite` : le nom de votre site, son URL et sa description (depuis `docs.json`).
- `BreadcrumbList` : le chemin de navigation de la page d'accueil jusqu'à la page courante, dérivé de votre configuration `navigation`.

Aucune configuration nécessaire. Les moteurs de recherche utilisent ces données pour les résultats enrichis, comme les fils d'Ariane dans les résultats de recherche.

<Tip>
**Vérifiez votre balisage.** Collez n'importe quelle URL de page dans le [Test des résultats enrichis de Google](https://search.google.com/test/rich-results) pour confirmer que les données structurées sont détectées.
</Tip>

## IndexNow

Après chaque build, Jamdesk soumet automatiquement les URL de pages modifiées à [IndexNow](https://www.indexnow.org) pour un indexage plus rapide par les moteurs de recherche. Cela notifie Bing, Yandex et d'autres moteurs participants de vos modifications de contenu, sans attendre leur prochain cycle d'exploration.

- Se déclenche après chaque build réussi
- Ne soumet que les pages réellement modifiées
- Non-bloquant, n'impacte jamais la durée de votre build
- Aucune configuration requise

## Bonnes pratiques

Parcourez cette liste de vérification avant de publier :

<Note>
**Liste de vérification avant publication**

- **Titres uniques** — Chaque page a un titre distinct et descriptif de moins de 60 caractères.
- **Descriptions précises** — Les descriptions résument la page en 120–160 caractères.
- **Hiérarchie logique des titres** — Les titres suivent une hiérarchie claire : un H1, puis H2 → H3.
- **Liens descriptifs** — Les liens internes utilisent un texte d'ancre significatif, jamais « cliquez ici ».
- **Texte alternatif des images** — Chaque image a un texte alternatif pour l'accessibilité et la recherche d'images.
- **Image sociale** — Définissez un `og:image` personnalisé sur les pages clés, ou utilisez la carte auto-générée. Vérifiez-la avec l'outil [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
