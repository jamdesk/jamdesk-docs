Jamdesk affiche les images avec des coins arrondis et un espacement cohérent. Déposez vos fichiers dans le répertoire `/images` et référencez-les avec du markdown standard.

Les captures d'écran montrent l'interface en anglais.

## Markdown standard

Utilisez la syntaxe familière `![alt](chemin)` :

```markdown
![API response showing user data in JSON format](/images/tabs-preview.webp)
```

![Réponse API affichant les données utilisateur au format JSON](/images/tabs-preview.webp)

Les chemins partent de la racine de votre projet. Une image à `your-docs/images/screenshot.webp` est référencée comme `/images/screenshot.webp`.

## Dimensions des images

Ajoutez `=LARGEURxHAUTEUR` après l'URL de l'image (séparé par un espace) pour contrôler la taille :

```markdown
![Dashboard overview](/images/tabs-preview.webp =400x300)
```

Définissez une seule dimension et l'autre s'adapte proportionnellement :

```markdown
![Wide banner](/images/tabs-preview.webp =800x)
![Tall graphic](/images/tabs-preview.webp =x200)
```

C'est utile lorsque vous souhaitez une colonne uniforme de captures d'écran à la même largeur, ou que vous devez réduire une image haute résolution à une taille d'affichage raisonnable.

## Légendes

Enveloppez une image dans le composant `<Frame>` pour ajouter une bordure et une légende en dessous :

```mdx
<Frame caption="Dashboard overview showing project statistics">
  ![Dashboard](/images/tabs-preview.webp)
</Frame>
```

<Frame caption="Exemple d'image encadrée avec légende">
  ![Jamdesk](/images/jd-blueprint-transparent.webp)

</Frame>

`Frame` dessine une bordure discrète autour de l'image et place le texte de légende en dessous. Il fonctionne avec tout contenu à l'intérieur, pas seulement les images.

## Mode clair/sombre

Les sites de documentation ont souvent besoin de variantes d'images différentes pour chaque schéma de couleurs — un logo sur fond blanc ne convient pas en mode sombre.

### L'attribut `srcDark`

L'approche la plus simple. Jamdesk remplace la source de l'image en fonction du thème actif :

```mdx
<img
  src="/images/logo-light.webp"
  srcDark="/images/logo-dark.webp"
  alt="Company logo"
/>
```

Le navigateur charge uniquement l'image qui correspond au schéma de couleurs actuel.

### L'élément HTML `<picture>`

Si vous avez besoin de HTML standard qui fonctionne également en dehors de Jamdesk, utilisez `<picture>` avec une media query :

```mdx
<picture>
  <source srcset="/images/logo-dark.webp" media="(prefers-color-scheme: dark)" />
  <img src="/images/logo-light.webp" alt="Company logo" />
</picture>
```

L'approche `<picture>` respecte le paramètre de schéma de couleurs du système d'exploitation. L'attribut `srcDark` répond au sélecteur de thème de Jamdesk, ce qui est généralement ce que vous souhaitez pour la documentation.

## Formats pris en charge

| Format | Idéal pour | Notes |
|--------|------------|-------|
| PNG | Captures d'écran, interfaces | Qualité sans perte, transparence supportée. Fichiers plus volumineux. |
| JPEG | Photographies | Bonne compression, pas de transparence. |
| SVG | Icônes, diagrammes, logos | Format vectoriel — s'adapte à toute taille sans perte de qualité. Fichiers très légers. |
| GIF | Animations simples | Peut devenir volumineux rapidement. Préférez les boucles `.mp4` courtes pour plus de quelques images. |
| WebP | Usage général | Plus léger que PNG et JPEG à qualité comparable. Fonctionne dans tous les navigateurs modernes. |

<Tip>
WebP offre le meilleur rapport taille/qualité pour la plupart des images de documentation. Si vous avez besoin de transparence, WebP la gère aussi — pas besoin de PNG.
</Tip>

## Bonnes pratiques

<AccordionGroup>
  <Accordion title="Rédigez un texte alt pertinent" icon="universal-access">
    Le texte alt remplit deux fonctions : les lecteurs d'écran l'utilisent pour l'accessibilité, et il s'affiche comme espace réservé lorsque l'image ne se charge pas. Décrivez ce que l'image montre réellement.

    ```markdown
    {/* Good -- says what's in the image */}
    ![API response showing user data in JSON format](/images/tabs-preview.webp)

    {/* Bad -- tells you nothing */}
    ![Screenshot](/images/tabs-preview.webp)
    ```

    Pour les images décoratives qui n'apportent pas d'information (motifs de fond, séparateurs), utilisez un texte alt vide : `![](/images/decoration.webp)`.
  </Accordion>

  <Accordion title="Gardez les fichiers légers" icon="gauge-high">
    Les images lourdes ralentissent le chargement des pages, surtout sur les connexions mobiles. Tailles cibles :

    - **Captures d'écran/interfaces :** PNG ou WebP, moins de 500 Ko
    - **Photos :** JPEG ou WebP, moins de 200 Ko
    - **Icônes et diagrammes :** SVG dans la mesure du possible

    [Squoosh](https://squoosh.app) et [TinyPNG](https://tinypng.com) compressent les images sans perte de qualité visible. Faites passer vos captures d'écran par l'un de ces outils avant de les commiter.

    Ou laissez Jamdesk s'en charger au moment du build. Activez la [conversion WebP automatique](/fr/builds/image-optimization) dans votre `docs.json` et tout PNG ou JPG que vous commitez sera optimisé à chaque build.
  </Accordion>

  <Accordion title="Conservez des dimensions cohérentes" icon="ruler-combined">
    Des captures d'écran qui varient entre différentes largeurs donnent un rendu désorganisé. Choisissez une largeur de capture standard (1200 px convient bien) et utilisez-la dans toute votre documentation. Jamdesk adapte automatiquement les images à la zone de contenu, donc des dimensions sources cohérentes produisent des résultats rendus cohérents.
  </Accordion>

  <Accordion title="Vérifiez votre image de partage social" icon="share-nodes">
    Jamdesk génère automatiquement une carte sociale 1200×630 aux couleurs de votre marque pour chaque page, et vous pouvez la remplacer par page avec `og:image` dans le frontmatter. Après un build, passez l'URL de la page dans l'outil gratuit [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) pour voir comment la carte s'affiche sur X, Facebook, LinkedIn, Slack, Discord et plus encore. Consultez [Optimisation SEO](/fr/content/seo) pour la configuration complète.
  </Accordion>
</AccordionGroup>

## Organisation des fichiers

Regroupez les images dans des sous-répertoires qui reflètent votre structure de contenu. Cela facilite la recherche au fur et à mesure que votre documentation grandit :

```bash
your-docs/
├── images/
│   ├── getting-started/
│   │   ├── step-1.png
│   │   └── step-2.png
│   ├── api/
│   │   └── response.png
│   └── logo.svg
└── docs.json
```

Référencez-les avec le chemin complet depuis la racine de votre projet :

```markdown
![GitHub repository access](/images/getting-started/step-1.png)
```

<Warning>
Évitez les espaces dans les noms de fichiers d'images. Utilisez des tirets à la place : `api-response.webp`, pas `api response.webp`.
</Warning>
