---
title: Pages masquées
description: Retirez des pages de la barre latérale et des résultats de recherche sans les supprimer. Utilisez le frontmatter, docs.json ou les contrôles seo.
---

Certaines pages n'ont pas leur place dans la barre latérale publique : brouillons, manuels internes, guides obsolètes que vous devez encore lier. Les pages masquées restent accessibles par URL directe mais disparaissent de la navigation, de la recherche, de votre sitemap et du contexte IA fourni aux LLM.

## Masquer une seule page

Ajoutez `hidden: true` au frontmatter de la page :

```mdx
---
title: Internal handbook
hidden: true
---
```

La page s'affiche normalement lorsqu'on visite son URL, mais Jamdesk :

- La retire de la barre latérale
- Ajoute `<meta name="robots" content="noindex, follow">` pour que les moteurs de recherche l'ignorent
- L'exclut de `sitemap.xml`, `llms.txt`, `llms-full.txt` et de la recherche sur site

## Masquer un groupe ou un onglet entier

Définissez `"hidden": true` sur un groupe ou un onglet dans `docs.json` :

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Public",
        "groups": [{ "group": "Guides", "pages": ["intro", "quickstart"] }]
      },
      {
        "tab": "Internal",
        "hidden": true,
        "groups": [{ "group": "Runbooks", "pages": ["oncall", "postmortems"] }]
      }
    ]
  }
}
```

Chaque page sous le nœud masqué hérite de la règle. Le même indicateur fonctionne sur `tabs`, `groups`, `anchors`, `dropdowns`, `products`, `languages` et `versions`.

## Garder les pages masquées dans la recherche

Si vous voulez qu'un onglet ou un groupe masqué reste hors de la barre latérale mais toujours indexé pour la recherche sur site, les réponses IA et le sitemap, ajoutez `"searchable": true` :

```json
{
  "tab": "Internal",
  "hidden": true,
  "searchable": true,
  "groups": [{ "group": "Runbooks", "pages": ["oncall"] }]
}
```

Le frontmatter `hidden: true` sur une page enfant l'emporte toujours. `searchable` ne rouvre que les descendants qui n'ont pas eux-mêmes fait ce choix.

## Contrôles à l'échelle du projet

Les deux indicateurs se trouvent sous `seo` dans `docs.json` :

| Indicateur | Par défaut | Effet |
|---|---|---|
| `seo.indexing` | `"navigable"` | Seules les pages listées dans votre navigation apparaissent dans les artefacts. Définissez sur `"all"` pour inclure tous les fichiers MDX de votre dépôt. |
| `seo.indexHiddenPages` | `false` | Définissez sur `true` pour inclure les pages `hidden: true` dans le sitemap, llms.txt et la recherche, et retirer la balise noindex automatique. |

Exemple :

```json
{
  "seo": {
    "indexing": "all"
  }
}
```

## Référence rapide

| Scénario | Frontmatter | docs.json | Visible dans la barre latérale | URL directe | Dans le sitemap |
|---|---|---|---|---|---|
| Page normale | — | listée | Oui | Oui | Oui |
| Masquée via frontmatter | `hidden: true` | listée | Non | Oui | Non |
| Page absente de la nav (orpheline) | — | omise | Non | Oui | Non |
| Groupe masqué | — | `hidden: true` sur le groupe | Non | Oui | Non |
| Groupe masqué + recherchable | — | `hidden: true, searchable: true` | Non | Oui | Oui |
| Le projet active l'indexation totale | — | quelconque | Comme ci-dessus | Oui | Oui |

## Quand utiliser chaque option

- **Brouillons et aperçus :** frontmatter `hidden: true` sur des pages individuelles
- **Sections internes** pour une petite équipe : un groupe ou un onglet masqué
- **Documents de conformité** qui doivent être publics mais non mis en avant : groupe masqué avec `searchable: true`
- **Indexation complète du dépôt** pour l'ancrage IA uniquement : `seo.indexing: "all"`

Les pages masquées ne constituent pas un contrôle d'accès. Quiconque possède l'URL peut les lire. Pour un véritable contrôle d'accès, consultez [Protection par mot de passe](/fr/setup/password-protection).
