MDX prend en charge les liens Markdown standard ainsi que des modèles spécifiques à Jamdesk pour créer des liens entre pages, ancrer vers des titres et référencer des URL externes.

## Liens internes

Créez des liens vers d'autres pages de votre documentation à l'aide de chemins relatifs :

```markdown
Read the [getting started guide](/quickstart) first.

See the [Card component](/components/card) for more options.
```

<Tip>
Utilisez des chemins relatifs à la racine de votre documentation, sans l'extension `.mdx`.
</Tip>

### Créer un lien vers des titres

Créez un lien direct vers une section à l'aide de liens d'ancrage :

```markdown
See [configuration options](/config/docs-json-reference#colors)
```

Les titres génèrent automatiquement des ancres à partir de leur texte :
- `## Getting Started` → `#getting-started`
- `## API Reference` → `#api-reference`

## Liens externes

Créez des liens vers des sites externes :

```markdown
Check the [GitHub repository](https://github.com/example/repo).
```

Les liens externes s'ouvrent automatiquement dans un nouvel onglet avec des paramètres sécurisés.

## Lien avec des Card

Pour une navigation plus visible, utilisez des Card plutôt que des liens en ligne :

```mdx
<Card title="Quickstart" icon="rocket" href="/quickstart">
  Get up and running in 5 minutes
</Card>
```

<Card title="Démarrage rapide" icon="rocket" href="/fr/quickstart">
  Soyez opérationnel en 5 minutes
</Card>

## Bonnes pratiques

<AccordionGroup>
  <Accordion title="Utilisez un texte de lien descriptif" icon="font" defaultOpen>
    Indiquez aux lecteurs où mène le lien :

    ```markdown
    {/* Good */}
    Learn more in our [authentication guide](/quickstart).

    {/* Avoid */}
    For more info, [click here](/quickstart).
    ```
  </Accordion>

  <Accordion title="Créez un lien vers le bon niveau" icon="sitemap">
    Créez un lien vers la section pertinente la plus précise :

    ```markdown
    {/* Good - links to specific section */}
    Configure [OAuth settings](/quickstart#whats-next).

    {/* Less helpful - links to entire page */}
    See the [auth docs](/quickstart) for OAuth settings.
    ```
  </Accordion>

  <Accordion title="Maintenez les liens à jour" icon="rotate">
    Les liens brisés frustrent les lecteurs. Effectuez régulièrement des vérifications de liens :

    ```bash
    jamdesk broken-links
    ```

    Cela analyse votre documentation et signale tout lien interne brisé.
  </Accordion>
</AccordionGroup>

## Vérification des liens brisés

La CLI Jamdesk peut analyser les liens brisés :

```bash
jamdesk broken-links
```

Exemple de résultat :

```text
docs/getting-started.mdx:15 - /docs/quikstart
  Did you mean: /docs/quickstart

Found 1 broken link in 45 files.
```

Exécutez cette commande avant le déploiement pour détecter les fautes de frappe et les références obsolètes.

### Corriger automatiquement les liens brisés

Lorsqu'un lien brisé a une cible correcte non ambiguë (une ancre comportant une faute de frappe, ou une dérive d'ancre inter-locale où une page traduite a renommé ses titres), `jamdesk fix` la corrige pour vous :

```bash
jamdesk fix --dry-run   # preview every planned fix, write nothing
jamdesk fix             # apply after a y/N confirmation
```

Il ne réécrit un lien que lorsque l'ancre corrigée correspond à un titre réel sur la page cible, laissant tout élément ambigu pour une révision manuelle. Voir [Correction automatique des liens brisés](/fr/cli/fix-broken-links).

### Comment les liens internes sont détectés

Les liens sans `https://` sont considérés comme internes et validés par rapport aux pages de votre documentation. Le validateur vérifie que la page cible existe dans la navigation de votre `docs.json`.

Pour les sites utilisant `hostAtDocs` (documentation hébergée sous un sous-chemin comme `/docs`), les liens internes sont **automatiquement préfixés** au moment de l'exécution. Écrivez des chemins relatifs à la racine de votre documentation ; le préfixe `/docs` est ajouté automatiquement :

```markdown
{/* Just write the docs path — auto-prefixed to /docs/config/docs-json-reference */}
See the [Reference](/config/docs-json-reference).
```

<Note>
  Les liens non liés à la documentation (comme les pages marketing) doivent utiliser des URL complètes : `https://example.com/pricing`.
  Tout lien `/chemin` dans le contenu de votre documentation est considéré comme un lien interne vers la documentation.
</Note>

## Renommage de pages

Lorsque vous renommez une page, les liens sont brisés. Utilisez la CLI pour mettre à jour toutes les références :

```bash
jamdesk rename api/old-name.mdx api/new-name.mdx
```

Cette commande effectue automatiquement les actions suivantes :
- Renomme le fichier
- Met à jour la navigation de `docs.json`
- Corrige les liens dans toutes les autres pages
