Ajoutez Plausible Analytics à votre site de documentation pour obtenir des données de trafic sans cookies ni scripts de suivi qui suivent les utilisateurs sur le web.

<Info>
Plausible est open source, pèse moins de 1 Ko et ne nécessite pas de bandeau de consentement aux cookies dans la plupart des juridictions. C'est une solution adaptée si vous souhaitez des analytics simples et conformes au RGPD.
</Info>

Si vous avez besoin d'un contrôle de consentement — ou si vous utilisez également GA, GTM ou Crisp — consultez [Consentement aux cookies](/fr/integrations/cookie-consent).

Il existe deux façons d'ajouter Plausible. Choisissez celle qui correspond à votre configuration :

| Configuration | Utiliser quand | Champ |
|---------------|----------------|-------|
| **Standard** | Vous êtes sur le plan gratuit de Plausible, ou payant sans besoin de proxy | `domain` |
| **Script proxy** | Vous êtes sur un plan payant et souhaitez contourner les bloqueurs de publicités | `scriptUrl` |

## Configuration standard (domain)

Il s'agit de la configuration par défaut pour la plupart des utilisateurs. Enregistrez votre site dans Plausible et indiquez le domaine.

<Steps>

### Créer un compte Plausible

Créez un compte sur [Plausible Analytics](https://plausible.io/) et ajoutez le domaine de votre site de documentation (ex. : `docs.example.com`).

### Ajouter le domaine dans docs.json

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "domain": "docs.example.com"
    }
  }
}
```

Utilisez le domaine exact que vous avez enregistré : `docs.example.com`, et non `www.docs.example.com`.

</Steps>

### Serveur auto-hébergé

Si vous utilisez la [Community Edition](https://github.com/plausible/community-edition), ajoutez le champ `server` pour que le script et l'API d'événements pointent vers votre instance :

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "domain": "docs.example.com",
      "server": "https://analytics.example.com"
    }
  }
}
```

`server` fonctionne uniquement avec `domain`. Les scripts proxy gèrent leur propre routage.

## Configuration par script proxy (scriptUrl)

Les plans payants de Plausible proposent des scripts proxy avec un nom de fichier unique (comme `pa-XXXXX.js`). Ils contournent la plupart des bloqueurs de publicités car l'URL du script ne correspond pas aux listes de filtres habituelles.

<Steps>

### Récupérer l'URL de votre script proxy

Dans les paramètres de votre site Plausible, trouvez la section du script proxy et copiez l'URL complète. Elle ressemble à `https://plausible.io/js/pa-XXXXX.js`.

### Ajouter l'URL du script dans docs.json

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "scriptUrl": "https://plausible.io/js/pa-XXXXX.js"
    }
  }
}
```

Les champs `domain` et `server` ne sont pas nécessaires. L'identité de votre site est intégrée dans l'identifiant du script, et le CDN de Plausible gère le routage en interne.

</Steps>

## Vérifier l'installation

Après avoir ajouté l'intégration :

1. Déclenchez un rebuild de votre documentation
2. Visitez votre site de documentation en ligne
3. Vérifiez votre dashboard Plausible. Votre visite devrait apparaître en quelques secondes.
4. Ou ouvrez les DevTools, allez dans l'onglet Réseau, et recherchez une requête vers `plausible.io/js/script.js` (standard) ou votre script `pa-XXXXX.js` (proxy)

<Note>
Plausible affiche les données en temps réel, sans période d'attente comme Google Analytics.
</Note>

## Référence de configuration

| Champ | Type | Requis | Description |
|-------|------|--------|-------------|
| `domain` | `string` | L'un des deux : `domain` ou `scriptUrl` | Le domaine de votre site tel qu'enregistré dans Plausible. Utilisé comme attribut `data-domain` sur la balise script. |
| `scriptUrl` | `string` | L'un des deux : `domain` ou `scriptUrl` | URL complète d'un script proxy payant Plausible (`pa-XXXXX.js`). L'identité du site est intégrée dans le script, le champ domain n'est donc pas nécessaire. |
| `server` | `string` | Non | URL d'un serveur Plausible auto-hébergé. Utilisé uniquement avec `domain`, pas `scriptUrl`. |

## Dépannage

<Accordion title="Aucune donnée n'apparaît dans Plausible">
  Dans neuf cas sur dix, c'est le domaine. Il doit correspondre exactement à ce que vous avez enregistré dans Plausible (`docs.example.com` et non `www.docs.example.com`).

  Si le domaine semble correct :

  1. Relancez un build de votre documentation. Les modifications de configuration ne prennent effet qu'après un nouveau build.
  2. Vérifiez les bloqueurs de publicités. Certaines extensions de navigateur bloquent les scripts analytics, y compris Plausible — passez à la [configuration par script proxy](#configuration-par-script-proxy-scripturl) si c'est la cause.
  3. Inspectez le code source de la page pour trouver une balise `<script>` avec `data-domain` (standard) ou votre nom de fichier `pa-XXXXX.js` (proxy). Si elle est absente, la configuration n'a pas été appliquée.
</Accordion>

<Accordion title="Utilisation d'un domaine personnalisé ou d'un sous-répertoire">
  Enregistrez le domaine que vos utilisateurs visitent réellement. Si votre documentation est sur `docs.example.com`, utilisez-le comme `domain`, et non votre domaine racine.
</Accordion>

<Accordion title="Script bloqué par les bloqueurs de publicités">
  Passez à la [configuration par script proxy](#configuration-par-script-proxy-scripturl). Le nom de fichier unique contourne la plupart des listes de filtres des bloqueurs de publicités. L'auto-hébergement donne le même résultat, car le script se charge depuis votre propre domaine.
</Accordion>

<Accordion title="Quand utiliser domain ou scriptUrl">
  Utilisez `domain` si vous êtes sur le plan gratuit ou si les bloqueurs de publicités ne vous préoccupent pas. Utilisez `scriptUrl` si vous êtes sur un plan payant et souhaitez une couverture maximale du suivi. Ne définissez pas les deux ; choisissez l'un ou l'autre.
</Accordion>
