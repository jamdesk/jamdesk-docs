title: Fournisseurs de support et chat
description: >-
  Ajoutez Intercom ou Front Chat à la documentation Jamdesk en configurant
  appId ou snippetId dans integrations de docs.json avec consentement
  optionnel.
---

Jamdesk peut charger un widget de chat en direct sur chaque page de votre site de documentation. Ajoutez le bloc du fournisseur sous `integrations` dans `docs.json`, et Jamdesk injecte le script du widget pour vous.

<Info>
Chaque valeur est vérifiée par rapport à un format strict avant que Jamdesk ne charge le widget. Une valeur au mauvais format est ignorée silencieusement et n'est jamais affichée — aucune page d'erreur, aucune balise de script cassée.
</Info>

## Configurer depuis le Dashboard

La façon la plus rapide de configurer l'un ou l'autre : **Dashboard → Integrations**. Choisissez la carte du fournisseur, collez son ID, et Jamdesk enregistre un commit du bloc `docs.json` pour vous et déclenche un rebuild (projets connectés à GitHub uniquement). Les sections ci-dessous concernent la modification directe de `docs.json`, ou les projets CLI uniquement.

## Intercom

**Format :** L'ID d'application comporte 6 à 16 lettres ou chiffres.

<Info>
Trouvez votre ID d'application dans **Settings → Installation → Web** dans Intercom — c'est l'ID de votre espace de travail.
</Info>

```json docs.json
{
  "integrations": {
    "intercom": {
      "appId": "abc12345"
    }
  }
}
```

## Front Chat

**Format :** L'ID de chat comporte 8 à 64 caractères hexadécimaux en minuscules (`0-9`, `a-f`).

```json docs.json
{
  "integrations": {
    "frontchat": {
      "snippetId": "3f8a2e1c9b6d4a7f"
    }
  }
}
```

## Contrôle par consentement

Les deux widgets respectent `integrations.cookies`. Lorsqu'il est défini, le script de chat ne se charge pas tant que votre bannière de consentement n'a pas enregistré l'approbation — voir [Consentement aux cookies](/fr/integrations/cookie-consent) pour la configuration complète. Sans cela, le widget se charge pour chaque visiteur au chargement de la page.
