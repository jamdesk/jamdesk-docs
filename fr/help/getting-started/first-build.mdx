Votre premier build démarre automatiquement dès que vous connectez un dépôt.

## Builds automatiques

Lorsque vous connectez un dépôt, Jamdesk déclenche immédiatement un build initial. Chaque push suivant vers votre branche connectée déclenche automatiquement un nouveau build.

## Progression du build

Suivez votre build dans le dashboard :

<Steps>
  <Step title="En attente">
    Votre build est en attente de démarrage. Aux heures de pointe, il peut y avoir un court délai.
  </Step>
  <Step title="Clonage">
    Jamdesk récupère le contenu de votre dépôt depuis GitHub.
  </Step>
  <Step title="Validation">
    Votre `docs.json` et vos fichiers MDX sont validés pour détecter les erreurs.
  </Step>
  <Step title="Build en cours">
    Le MDX est compilé en HTML optimisé avec coloration syntaxique et indexation de la recherche.
  </Step>
  <Step title="Déploiement">
    Les fichiers générés sont envoyés vers le CDN mondial.
  </Step>
  <Step title="En ligne">
    Votre documentation est disponible à l'URL de votre projet.
  </Step>
</Steps>

## Consulter votre documentation en ligne

Une fois le build terminé, cliquez sur **Voir le site** dans le dashboard ou rendez-vous sur `https://your-project.jamdesk.app`.

Si vous avez configuré un domaine personnalisé, votre documentation y sera également disponible.

## Rebuild manuel

Besoin de relancer un build sans pousser de modifications ?

1. Accédez à votre projet dans le [dashboard](https://dashboard.jamdesk.com)
2. Ouvrez **Paramètres**
3. Cliquez sur **Reconstruire**

Utilisez cette option après avoir modifié des variables d'environnement ou pour forcer un build complet.

## En cas d'échec du build

Les échecs de build affichent un message d'erreur dans le dashboard. Causes fréquentes :

- Syntaxe `docs.json` invalide
- Erreurs de syntaxe MDX
- Pages manquantes référencées dans la navigation
