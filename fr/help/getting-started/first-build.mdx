Votre premier build démarre automatiquement lorsque vous connectez un dépôt.

## Builds Automatiques

Lorsque vous connectez un dépôt, Jamdesk déclenche un build initial immédiatement. Chaque push suivant sur votre branche connectée déclenche automatiquement un nouveau build.

## Progression du Build

Suivez votre build dans le dashboard :

<Steps>
  <Step title="En file d'attente">
    Votre build attend de démarrer. Aux heures de pointe, il peut y avoir une brève file d'attente.
  </Step>
  <Step title="Clonage">
    Jamdesk récupère le contenu de votre dépôt depuis GitHub.
  </Step>
  <Step title="Validation">
    Votre fichier `docs.json` et vos fichiers MDX sont validés pour détecter les erreurs.
  </Step>
  <Step title="Build">
    Le MDX est compilé en HTML optimisé avec la coloration syntaxique et l'indexation de recherche.
  </Step>
  <Step title="Déploiement">
    Les fichiers buildés sont téléchargés vers le CDN mondial.
  </Step>
  <Step title="En ligne">
    Votre documentation est disponible à l'URL de votre projet.
  </Step>
</Steps>

## Consulter Votre Documentation en Ligne

Une fois le build terminé, cliquez sur **Voir le site** dans le dashboard ou rendez-vous sur `https://your-project.jamdesk.app`.

Si vous avez configuré un domaine personnalisé, votre documentation sera également disponible à cette adresse.

## Rebuild Manuel

Besoin de rebuilder sans pousser de modifications ?

1. Accédez à votre projet dans le [dashboard](https://dashboard.jamdesk.com)
2. Ouvrez **Paramètres**
3. Cliquez sur **Rebuild**

Utilisez cette option après avoir modifié des variables d'environnement ou pour forcer un build complet.

## En Cas d'Échec du Build

Les échecs de build affichent un message d'erreur dans le dashboard. Causes fréquentes :

- Syntaxe `docs.json` invalide
- Erreurs de syntaxe MDX
- Pages manquantes référencées dans la navigation
