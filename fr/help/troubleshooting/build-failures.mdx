Ouvrez le build échoué dans votre onglet Déploiements et associez le message d'erreur à une section ci-dessous.

## Trouver l'erreur

1. Accédez à l'onglet **Déploiements** de votre projet
2. Cliquez sur le build échoué
3. Examinez le message d'erreur et le journal

Le journal indique exactement ce qui a échoué et où.

## Échecs courants

### Configuration invalide

**Erreur :** "Invalid docs.json"

Votre `docs.json` contient des erreurs de syntaxe ou de schéma.

**Solution :**
1. Vérifiez les virgules, crochets ou guillemets manquants
2. Exécutez `jamdesk validate` localement
3. Comparez avec la [référence du schéma](/fr/config/docs-json-reference)

### Pages manquantes

**Erreur :** "Page 'path/to/page' not found"

Une page dans la navigation n'existe pas.

**Solution :**
- Vérifiez que le fichier existe
- Vérifiez que le chemin correspond exactement (sensible à la casse)
- N'incluez pas l'extension `.mdx` dans `docs.json`

### Erreurs de syntaxe MDX

**Erreur :** "MDX compilation failed"

Syntaxe MDX ou JSX invalide.

**Causes courantes :**
- Balises non fermées : `<Card>` sans `</Card>`
- Accolades non échappées : `{` au lieu de `\{`
- Props invalides : `title=value` au lieu de `title="value"`

### Images manquantes

**Erreur :** "Asset not found"

Une image référencée dans MDX n'existe pas.

**Solution :**
- Vérifiez que le chemin de l'image est correct
- Les chemins sont relatifs à votre répertoire docs
- Vérifiez que le fichier a été commité dans Git

## Étapes de débogage

<Steps>
  <Step title="Lire l'erreur">
    Le journal vous indique exactement ce qui a échoué et où.
  </Step>
  <Step title="Tester localement">
    Exécutez `jamdesk dev` pour reproduire l'erreur.
  </Step>
  <Step title="Valider la configuration">
    Exécutez `jamdesk validate` pour vérifier votre configuration.
  </Step>
  <Step title="Vérifier les modifications récentes">
    Examinez votre dernier commit pour identifier le problème.
  </Step>
</Steps>

## Toujours bloqué ?

Si vous ne parvenez pas à résoudre le problème :

1. Copiez le journal de build complet
2. Notez l'ID de votre projet
3. [Contactez le support](/fr/help/support/contact)
