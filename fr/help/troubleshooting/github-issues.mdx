La plupart des problèmes d'intégration GitHub proviennent de permissions, d'échecs de webhook ou d'incohérences de branche.

## L'organisation n'apparaît pas pendant la configuration

Pendant le flux de démarrage, Jamdesk affiche vos organisations GitHub afin que vous puissiez choisir où créer le dépôt. La liste provient de l'API OAuth de GitHub, qui masque certaines organisations dans deux cas :

- Restrictions d'application OAuth : votre organisation restreint l'accès aux applications tierces (paramètre par défaut de GitHub pour les nouvelles organisations) et n'a pas encore approuvé Jamdesk.
- SAML SSO : votre organisation exige une authentification SAML avant que l'API ne la retourne.

<Accordion title="Accordez vous-même l'accès (propriétaires d'organisation)">
  Si vous êtes propriétaire de l'organisation, vous pouvez approuver Jamdesk immédiatement, sans attendre :

  1. Cliquez sur **grant Jamdesk access on GitHub** (accordez l'accès à Jamdesk sur GitHub) sous le sélecteur d'organisation (ou allez sur GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. Sous **Organization access**, cliquez sur **Grant** en regard de votre organisation
  3. De retour dans le flux de configuration de Jamdesk, cliquez sur **refresh the list** (actualiser la liste) — votre organisation apparaît immédiatement

  Si vous êtes membre (et non propriétaire), vous verrez à la place un bouton **Request** ; cliquer dessus envoie une demande d'approbation aux administrateurs de votre organisation.
</Accordion>

<Accordion title="Demandez à l'administrateur de votre organisation d'approuver Jamdesk (membres)">
  Si vous êtes membre sans droits de propriétaire, envoyez d'abord une demande d'approbation à vos administrateurs :

  1. Allez sur GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. Sous **Organization access**, cliquez sur **Request** en regard de votre organisation — cela notifie les administrateurs de votre organisation
  3. Un administrateur l'approuve dans les **Settings** de l'organisation → **Third-party access** → **OAuth application policy** (les demandes en attente affichent un bouton **Approve**)
  4. Retournez au flux de configuration de Jamdesk et cliquez sur **refresh the list** (actualiser la liste) ; votre organisation devrait maintenant apparaître

  Consultez le guide GitHub sur [l'approbation des applications OAuth pour votre organisation](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization) pour les étapes détaillées.
</Accordion>

<Accordion title="Créez dans votre compte personnel et transférez plus tard">
  Vous ne voulez pas attendre l'approbation d'un administrateur ? Choisissez votre compte personnel pendant la configuration et transférez le dépôt vers votre organisation par la suite :

  1. Terminez la configuration de Jamdesk en utilisant votre compte personnel
  2. Accédez au dépôt créé sur GitHub
  3. Accédez à **Settings** → **General** → **Danger Zone**
  4. Cliquez sur **Transfer** et sélectionnez votre organisation comme destination
  5. Dans Jamdesk, déconnectez puis reconnectez le dépôt depuis la page **Settings** de votre projet

  <Warning>
    La déconnexion puis reconnexion génère une nouvelle URL de docs (par exemple, `your-project.jamdesk.app` peut changer). Si vous avez déjà partagé votre URL ou configuré un domaine personnalisé, contactez le [support](/fr/help/support/contact) avant de vous déconnecter afin que nous puissions préserver votre configuration.
  </Warning>
</Accordion>

## Le dépôt n'apparaît pas

Si votre dépôt n'apparaît pas dans la liste :

<Accordion title="Vérifier les permissions du dépôt">
  1. Allez sur GitHub → Settings → Applications → Jamdesk
  2. Vérifiez que l'accès a été accordé au dépôt
  3. Cliquez sur **Configure** pour ajouter d'autres dépôts
</Accordion>

<Accordion title="Dépôts d'organisation">
  Pour les dépôts d'organisation :
  1. Un administrateur de l'organisation doit approuver Jamdesk
  2. Accédez aux paramètres de l'organisation → Third-party access
  3. Approuvez la demande d'accès de Jamdesk
</Accordion>

<Accordion title="Dépôts privés">
  Les dépôts privés nécessitent une autorisation GitHub. Réautorisez Jamdesk si nécessaire.
</Accordion>

## Les builds ne se déclenchent pas

Si les push ne déclenchent pas de builds :

<Steps>
  <Step title="Vérifier le webhook">
    1. Accédez à votre dépôt sur GitHub
    2. Accédez à Settings → Webhooks
    3. Recherchez le webhook Jamdesk
    4. Vérifiez « Recent Deliveries » pour repérer les erreurs
  </Step>
  <Step title="Vérifier la branche">
    Les builds ne se déclenchent que sur la branche configurée. Vérifiez les **Settings** dans Jamdesk.
  </Step>
  <Step title="Resynchroniser la connexion">
    1. Accédez aux **Settings** du projet dans Jamdesk
    2. Cliquez sur **Re-sync GitHub**
  </Step>
</Steps>

## Erreurs de Webhook

### 404 Not Found

L'endpoint du webhook n'a pas pu être atteint.

**Solution :** Resynchronisez la connexion GitHub dans les paramètres du projet.

### 401 Unauthorized

L'authentification a échoué.

**Solution :**
1. Accédez aux paramètres de votre compte GitHub
2. Accédez à Applications → Authorized OAuth Apps
3. Révoquez Jamdesk
4. Réautorisez dans les paramètres de Jamdesk

### 500 Server Error

Problème temporaire de Jamdesk.

**Solution :** Attendez quelques minutes puis effectuez un nouveau push, ou déclenchez une reconstruction manuelle.

## Erreurs de permission

**« Dépôt introuvable »** pendant le build :

- Le dépôt a peut-être été supprimé ou renommé
- Jamdesk a peut-être perdu l'accès
- Réautorisez votre connexion GitHub

## Problèmes de branche

### Mauvaise branche en cours de build

Vérifiez votre branche configurée dans **Settings** → **Repository**.

### Branche renommée ou supprimée

Mettez à jour le paramètre de branche pour qu'il corresponde au nouveau nom de branche.
