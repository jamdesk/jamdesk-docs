La plupart des problèmes d'intégration GitHub proviennent de permissions, d'échecs de webhook ou de branches non concordantes.

## L'organisation n'apparaît pas lors de la configuration

Pendant le flux de démarrage de la documentation, Jamdesk affiche vos organisations GitHub afin que vous puissiez choisir où créer le dépôt. La liste provient de l'API OAuth de GitHub, et GitHub masque certaines organisations dans deux cas :

- Restrictions des applications OAuth : votre organisation restreint l'accès des applications tierces (paramètre par défaut de GitHub pour les nouvelles organisations) et n'a pas encore approuvé Jamdesk.
- SSO SAML : votre organisation exige une authentification SAML avant que l'API ne la renvoie.

<Accordion title="Accorder l'accès vous-même (propriétaires d'organisation)">
  Si vous êtes propriétaire de l'organisation, vous pouvez approuver Jamdesk immédiatement :

  1. Cliquez sur **grant Jamdesk access on GitHub** sous le sélecteur d'organisation (ou allez sur GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. Sous **Organization access**, cliquez sur **Grant** à côté de votre organisation
  3. Retournez dans le flux de configuration de Jamdesk et cliquez sur **refresh the list**. Votre organisation apparaît immédiatement

  Si vous êtes membre (et non propriétaire), un bouton **Request** s'affichera à la place ; cliquer dessus envoie une demande d'approbation aux administrateurs de votre organisation.
</Accordion>

<Accordion title="Demander à l'administrateur de votre organisation d'approuver Jamdesk (membres)">
  Si vous êtes membre sans droits de propriétaire, envoyez d'abord une requête d'approbation à vos administrateurs :

  1. Allez sur GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. Sous **Organization access**, cliquez sur **Request** à côté de votre organisation. Cette requête notifie les administrateurs de votre organisation GitHub
  3. Un administrateur l'approuve dans **Settings** → **Third-party access** → **OAuth application policy** de l'organisation (les requêtes en attente affichent un bouton **Approve**)
  4. Retournez au flux de configuration de Jamdesk et cliquez sur **refresh the list** ; votre organisation devrait maintenant apparaître

  Consultez le guide de GitHub sur [l'approbation des applications OAuth pour votre organisation](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization) pour des étapes détaillées.
</Accordion>

<Accordion title="Créer dans votre compte personnel et transférer plus tard">
  Vous ne voulez pas attendre l'approbation d'un administrateur ? Choisissez votre compte personnel lors de la configuration et transférez le dépôt vers votre organisation par la suite :

  1. Terminez la configuration de Jamdesk en utilisant votre compte personnel
  2. Allez sur le dépôt créé sur GitHub
  3. Naviguez vers **Settings** → **General** → **Danger Zone**
  4. Cliquez sur **Transfer** et sélectionnez votre organisation comme destination
  5. Dans Jamdesk, déconnectez et reconnectez le dépôt depuis la page **Settings** de votre projet

  <Warning>
    Déconnecter puis reconnecter génère une nouvelle URL de documentation (par exemple, `your-project.jamdesk.app` peut changer). Si vous avez déjà partagé votre URL ou configuré un domaine personnalisé, contactez le [support](/fr/help/support/contact) avant de déconnecter afin que nous puissions préserver votre configuration.
  </Warning>
</Accordion>

## Le dépôt n'apparaît pas

Si votre dépôt n'apparaît pas dans la liste :

<Accordion title="Vérifier les permissions du dépôt">
  1. Allez sur GitHub → Settings → Applications → Jamdesk
  2. Vérifiez que l'accès au dépôt est accordé
  3. Cliquez sur **Configure** pour ajouter d'autres dépôts
</Accordion>

<Accordion title="Dépôts d'organisation">
  Pour les dépôts d'organisation :
  1. Un administrateur de l'organisation doit approuver Jamdesk
  2. Allez dans les paramètres de l'organisation GitHub → Third-party access
  3. Approuvez la requête d'accès de Jamdesk
</Accordion>

<Accordion title="Dépôts privés">
  Les dépôts privés nécessitent une autorisation GitHub. Réautorisez Jamdesk si nécessaire.
</Accordion>

## Les builds ne se déclenchent pas

Si les push ne déclenchent pas de builds :

<Steps>
  <Step title="Vérifier le webhook">
    1. Allez sur votre dépôt sur GitHub
    2. Naviguez vers Settings → Webhooks
    3. Trouvez le Webhook Jamdesk
    4. Vérifiez « Recent Deliveries » pour détecter des erreurs
  </Step>
  <Step title="Vérifier la branche">
    Les builds ne se déclenchent que sur votre branche configurée. Vérifiez **Settings** dans Jamdesk.
  </Step>
  <Step title="Resynchroniser la connexion">
    1. Allez dans **Settings** du projet dans Jamdesk
    2. Cliquez sur **Re-sync GitHub**
  </Step>
</Steps>

## Erreurs de webhook

### 404 Not Found

L'endpoint du webhook n'a pas pu être atteint.

**Solution :** Resynchronisez la connexion GitHub dans les paramètres du projet.

### 401 Unauthorized

L'authentification a échoué.

**Solution :**
1. Allez dans les paramètres de votre compte GitHub
2. Naviguez vers Applications → Authorized OAuth Apps
3. Révoquez Jamdesk
4. Réautorisez dans les paramètres de Jamdesk

### 500 Server Error

Problème temporaire de Jamdesk.

**Solution :** Attendez quelques minutes puis effectuez à nouveau un push, ou déclenchez un rebuild manuel.

## Erreurs de permissions

**« Repository not found »** pendant un build :

- Le dépôt a peut-être été supprimé ou renommé
- Jamdesk a peut-être perdu l'accès
- Réautorisez votre connexion GitHub

## Problèmes de branche

### Mauvaise branche en cours de build

Vérifiez votre branche configurée dans **Settings** → **Repository**.

### Branche renommée ou supprimée

Mettez à jour le paramètre de branche pour correspondre au nouveau nom de branche.
