Questions courantes sur les tarifs, les builds, les domaines et les fonctionnalités.

## Premiers pas

<AccordionGroup>
  <Accordion title="Qu'est-ce que Jamdesk ?">
    Jamdesk est une plateforme de documentation qui génère des sites à partir de vos fichiers Markdown. Rédigez en MDX, poussez sur GitHub, et votre site est déployé automatiquement avec la recherche, les analytics et un fichier `llms.txt` prêt pour l'AI.
  </Accordion>

  <Accordion title="Ai-je besoin de savoir coder ?">
    Aucune compétence en développement n'est requise. Écrire en MDX ressemble à l'utilisation d'un éditeur de texte : vous rédigez du texte simple avec une mise en forme basique. Des composants sont disponibles si vous le souhaitez, mais ils sont entièrement optionnels.
  </Accordion>

  <Accordion title="Puis-je essayer Jamdesk gratuitement ?">
    Oui ! Nous proposons un essai gratuit de 14 jours avec un accès complet à toutes les fonctionnalités.
  </Accordion>

  <Accordion title="Quelle est la différence entre Jamdesk et les autres plateformes de documentation ?">
    Jamdesk est conçu autour de MDX et GitHub : vos docs sont des fichiers texte ordinaires dans un dépôt, non enfermés dans un éditeur propriétaire. Poussez sur GitHub et votre site est déployé en moins de 60 secondes, sans configuration de build ni pipeline CI/CD. Chaque site reçoit automatiquement un fichier `llms.txt` et un serveur MCP, afin que les outils AI comme Claude et ChatGPT puissent accéder directement à vos docs à jour. Les visiteurs bénéficient également d'un [assistant de chat AI](/fr/ai/chat) intégré qui répond aux questions à partir de vos docs.
  </Accordion>
</AccordionGroup>

## Builds et déploiement

<AccordionGroup>
  <Accordion title="Combien de temps prennent les builds ?">
    La plupart des sites de documentation sont buildés en 30 à 60 secondes. Les sites plus importants avec de nombreuses pages peuvent prendre plus de temps.
  </Accordion>

  <Accordion title="Puis-je prévisualiser les modifications avant de les publier ?">
    Oui ! Utilisez le CLI Jamdesk (`jamdesk dev`) pour un preview en local avec rechargement à chaud. Les modifications ne sont mises en ligne que lorsque vous poussez sur GitHub ou exécutez `jamdesk deploy`.
  </Accordion>

  <Accordion title="Puis-je déployer sans GitHub ?">
    Oui. Exécutez `jamdesk deploy` depuis le répertoire de votre projet. Le CLI empaquette vos fichiers, les téléverse et déclenche un build directement. Aucun dépôt Git n'est requis. Consultez le [guide CLI Deploy](/fr/cli/deploy) pour plus de détails.
  </Accordion>

  <Accordion title="Qu'est-ce qui déclenche un build ?">
    Les builds se déclenchent automatiquement lorsque vous poussez sur votre branche GitHub connectée. Vous pouvez également déclencher des builds manuellement depuis le dashboard ou avec `jamdesk deploy` via le CLI.
  </Accordion>

  <Accordion title="Puis-je revenir à une version précédente ?">
    Oui. Accédez à **Deployments** dans votre projet, trouvez le build précédent et cliquez sur **Rollback**.
  </Accordion>
</AccordionGroup>

## Domaines personnalisés

<AccordionGroup>
  <Accordion title="Puis-je utiliser mon propre domaine ?">
    Oui ! Ajoutez un domaine personnalisé dans **Settings** → **Domains**. Les certificats SSL sont provisionnés automatiquement.
  </Accordion>

  <Accordion title="Combien de temps prend la propagation DNS ?">
    Les modifications DNS se propagent généralement en quelques heures, mais peuvent prendre jusqu'à 48 heures.
  </Accordion>

  <Accordion title="Puis-je héberger mes docs sur un sous-chemin comme /docs ?">
    Oui. Utilisez un reverse proxy (Cloudflare, AWS, nginx) pour servir Jamdesk sur un sous-chemin. Consultez [Subpath Hosting](/fr/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Équipes et collaboration

<AccordionGroup>
  <Accordion title="Combien de membres d'équipe puis-je avoir ?">
    Les plans Pro incluent 10 membres d'équipe par projet.
  </Accordion>

  <Accordion title="Les membres de l'équipe peuvent-ils modifier la documentation ?">
    Les membres de l'équipe peuvent consulter les builds et déclencher des rebuilds, mais la modification s'effectue dans votre dépôt GitHub. Toute personne ayant accès au dépôt peut modifier les docs.
  </Accordion>

  <Accordion title="Comment transférer la propriété d'un projet ?">
    Accédez à **Settings** → **Team** → **Transfer Ownership**. Le nouveau propriétaire doit être un membre existant de l'équipe.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Où sont stockées mes identifiants CLI ?">
    Dans `~/.jamdeskrc`, un fichier JSON avec des permissions `0600` (seul votre utilisateur peut le lire). Il contient votre token de rafraîchissement, votre adresse e-mail et votre identifiant utilisateur. Exécutez `jamdesk logout` pour l'effacer.
  </Accordion>

  <Accordion title='Pourquoi le CLI indique-t-il "session expired" ?'>
    Votre token de rafraîchissement n'est plus valide. Cela se produit après des changements de mot de passe, des suppressions de compte ou une inactivité prolongée. Exécutez `jamdesk login` pour obtenir une nouvelle session.
  </Accordion>

  <Accordion title="Puis-je utiliser le CLI dans des pipelines CI/CD ?">
    Oui, mais la connexion via navigateur ne fonctionnera pas dans les environnements sans interface graphique. Connectez-vous sur votre machine locale, puis copiez `~/.jamdeskrc` sur votre runner CI. Le token de rafraîchissement gère l'authentification à partir de là.
  </Accordion>
</AccordionGroup>

## Contenu et fonctionnalités

<AccordionGroup>
  <Accordion title="Quels formats de fichiers sont pris en charge ?">
    Jamdesk prend en charge MDX (Markdown + JSX) et les fichiers Markdown standard.
  </Accordion>

  <Accordion title="Puis-je utiliser des composants React personnalisés ?">
    Oui. Définissez des composants inline directement dans MDX avec `export const`, ou créez des composants réutilisables dans le répertoire `/snippets`. Pour les composants interactifs avec hooks, utilisez des fichiers `.tsx` avec `'use client'`. Consultez [Custom React Components](/fr/content/react-components) et [Snippets](/fr/content/snippets).
  </Accordion>

  <Accordion title="Y a-t-il une limite de pages ?">
    Pas de limite stricte sur le nombre de pages. La plupart des sites de documentation fonctionnent bien avec des centaines de pages.
  </Accordion>

  <Accordion title="Jamdesk prend-il en charge plusieurs langues ?">
    Oui. Utilisez la propriété `languages` dans votre configuration de navigation pour créer un sélecteur de langue. Chaque langue dispose de sa propre structure de navigation et de son propre contenu. Consultez [Multi-Language Support](/fr/setup/languages).
  </Accordion>

  <Accordion title="Jamdesk traduit-il mon contenu automatiquement ?">
    Non. Jamdesk ne traduit pas le contenu à votre place. Vous fournissez les fichiers MDX traduits et Jamdesk gère le routage, la navigation, le sélecteur de langue et le style RTL. Apportez les traductions depuis votre propre flux de travail (traducteurs humains, traduction automatique ou un LLM) et placez-les dans des répertoires préfixés par la langue (`es/`, `fr/`, etc.). Consultez [Multi-Language Support](/fr/setup/languages) pour la structure des répertoires et la configuration.
  </Accordion>
</AccordionGroup>

## Chat AI

<AccordionGroup>
  <Accordion title="Mon site de documentation dispose-t-il du chat AI ?">
    Oui. Chaque site Jamdesk inclut un assistant de chat intégré qui répond aux questions des visiteurs à partir de votre documentation. Il est activé par défaut, aucune configuration n'est requise. Consultez [AI Chat](/fr/ai/chat) pour plus de détails.
  </Accordion>

  <Accordion title="Le chat AI a-t-il un coût supplémentaire ?">
    Non. Le chat AI est inclus dans tous les plans sans coût additionnel.
  </Accordion>

  <Accordion title="Puis-je désactiver le chat AI ?">
    Oui. Définissez `chat.enabled` sur `false` dans votre `docs.json` :

    ```json
    { "chat": { "enabled": false } }
    ```

    Le panneau de chat et le raccourci clavier seront supprimés après votre prochain build.
  </Accordion>

  <Accordion title="Quelles données le chat utilise-t-il pour répondre aux questions ?">
    Le chat utilise uniquement vos pages de documentation publiées. À chaque build, Jamdesk indexe votre contenu dans une base de données vectorielle. Lorsqu'un visiteur pose une question, les sections pertinentes sont récupérées et envoyées à Claude comme contexte. L'AI ne peut pas accéder à des données en dehors de vos docs.
  </Accordion>
</AccordionGroup>

## Confidentialité et accès

<AccordionGroup>
  <Accordion title="Puis-je avoir des docs publiques et privées sur le même site ?">
    Oui. Marquez les pages internes avec `private: true` dans le frontmatter, ou listez leurs chemins sous `auth.password.private[]` dans `docs.json`. Les pages publiques restent publiques ; les pages privées affichent un écran de déverrouillage. Un seul projet, un seul dépôt, un seul build. Consultez [Access Control](/fr/setup/access-control) et [Password Protection](/fr/setup/password-protection).
  </Accordion>

  <Accordion title="Comment protéger l'intégralité de mon site de documentation par un mot de passe ?">
    Définissez `auth.password.enabled: true` dans `docs.json`, poussez la modification, puis définissez un mot de passe dans **Project Settings → Password Protection** dans le dashboard. Chaque visiteur voit un écran de déverrouillage jusqu'à ce qu'il le saisisse. Consultez [Password Protection](/fr/setup/password-protection).
  </Accordion>

  <Accordion title="Les lecteurs peuvent-ils se connecter avec leur propre compte plutôt qu'un mot de passe partagé ?">
    Oui, sur les plans Enterprise. Le Single Sign-On permet aux lecteurs de s'authentifier auprès de votre fournisseur d'identité (Okta, Google Workspace, Azure AD, etc.) — pas de mots de passe partagés, piste d'audit complète, déprovisionnement instantané. Consultez [SSO](/fr/setup/sso) ou [contactez les ventes Enterprise](https://www.jamdesk.com/pricing).
  </Accordion>

  <Accordion title="Dois-je séparer les docs internes et externes en deux projets ?">
    En général, non. Un seul projet avec `private: true` sur les pages internes est plus simple — même dépôt, même build, un seul dashboard. Utilisez deux projets uniquement lorsque les audiences ont besoin d'un branding, de domaines personnalisés ou d'analytics entièrement distincts. Consultez [Access Control](/fr/setup/access-control) pour les cas d'usage.
  </Accordion>

  <Accordion title="Quelle est la différence entre un éditeur et un lecteur ?">
    Les **éditeurs** rédigent les docs — la modification s'effectue en committant du MDX dans votre dépôt GitHub connecté, donc toute personne ayant un accès en push sur votre branche de docs peut publier une modification. Les **lecteurs** consultent le site publié — tout le monde (public), toute personne disposant du mot de passe (mode mot de passe), ou toute personne connectée via votre IdP (SSO). Les **membres de l'équipe dashboard** sont un concept distinct : ils gèrent les builds et les analytics, mais ne contribuent pas directement au contenu. Consultez [Access Control](/fr/setup/access-control).
  </Accordion>
</AccordionGroup>
