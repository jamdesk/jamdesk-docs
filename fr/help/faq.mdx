Questions fréquentes sur la tarification, les builds, les domaines et les fonctionnalités.

## Pour commencer

<AccordionGroup>
  <Accordion title="Qu'est-ce que Jamdesk ?">
    Jamdesk est une plateforme de documentation qui génère des sites de docs à partir de vos fichiers Markdown. Rédigez en MDX, poussez sur GitHub, et votre site peut se déployer automatiquement avec la recherche, l'analytique et un fichier `llms.txt` prêt pour l'IA.
  </Accordion>

  <Accordion title="Dois-je savoir coder ?">
    Aucune compétence en programmation n'est requise. Écrire en MDX, c'est comme utiliser un éditeur de texte : vous rédigez du texte brut avec une mise en forme simple. Des composants sont disponibles si vous le souhaitez, mais ils sont entièrement optionnels.
  </Accordion>

  <Accordion title="Puis-je essayer Jamdesk gratuitement ?">
    Oui ! Nous proposons un essai gratuit de 14 jours avec un accès complet à toutes les fonctionnalités.  
  </Accordion>

  <Accordion title="Quelle est la différence entre Jamdesk et les autres plateformes de documentation ?">
    Jamdesk est conçu autour de MDX et GitHub : vos docs sont des fichiers texte brut dans un dépôt, non enfermés dans un éditeur propriétaire. Poussez sur GitHub et votre site peut se déployer en moins de 60 secondes sans configuration de build ni pipeline CI/CD. Chaque site obtient automatiquement un fichier `llms.txt` et un serveur MCP, afin que des outils IA comme Claude et ChatGPT puissent accéder directement à vos docs actuelles. Les visiteurs bénéficient également d'un [assistant de chat IA](/fr/ai/chat) intégré qui répond aux questions à partir de vos docs.
  </Accordion>
</AccordionGroup>

## Builds et déploiement

<AccordionGroup>
  <Accordion title="Combien de temps prennent les builds ?">
    La plupart des sites de documentation se construisent en 30 à 60 secondes. Les sites plus volumineux avec de nombreuses pages peuvent prendre plus de temps.
  </Accordion>

  <Accordion title="Puis-je prévisualiser les modifications avant de les publier ?">
    Oui ! Utilisez la CLI Jamdesk (`jamdesk dev`) pour prévisualiser localement avec le rechargement à chaud. Les modifications ne sont publiées que lorsque vous poussez sur GitHub ou exécutez `jamdesk deploy`.
  </Accordion>

  <Accordion title="Puis-je déployer sans GitHub ?">
    Oui. Exécutez `jamdesk deploy` depuis le répertoire de votre projet. La CLI emballe vos fichiers, les téléverse et déclenche un build directement. Aucun dépôt Git n'est requis. Consultez le [guide CLI Deploy](/fr/cli/deploy) pour plus de détails.
  </Accordion>

  <Accordion title="Qu'est-ce qui déclenche un build ?">
    Les builds se déclenchent automatiquement lorsque vous poussez vers votre branche GitHub connectée. Vous pouvez également déclencher des builds manuellement depuis le dashboard ou avec `jamdesk deploy` depuis la CLI.
  </Accordion>

  <Accordion title="Puis-je revenir à une version précédente ?">
    Oui. Allez dans **Deployments** de votre projet, trouvez le build précédent et cliquez sur **Rollback**.
  </Accordion>
</AccordionGroup>

## Domaines personnalisés

<AccordionGroup>
  <Accordion title="Puis-je utiliser mon propre domaine ?">
    Oui ! Ajoutez un domaine personnalisé dans **Settings** → **Domains**. Les certificats SSL sont provisionnés automatiquement.
  </Accordion>

  <Accordion title="Combien de temps prend la propagation DNS ?">
    Les modifications DNS se propagent généralement en quelques heures, mais peuvent prendre jusqu'à 48 heures.
  </Accordion>

  <Accordion title="Puis-je héberger mes docs sur un sous-chemin comme /docs ?">
    Oui. Utilisez un reverse proxy (Cloudflare, AWS, nginx) pour servir Jamdesk sur un sous-chemin. Consultez [Hébergement sur sous-chemin](/fr/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Équipes et collaboration

<AccordionGroup>
  <Accordion title="Combien de membres d'équipe puis-je avoir ?">
    Les plans Pro incluent 10 membres d'équipe par projet.
  </Accordion>

  <Accordion title="Les membres de l'équipe peuvent-ils modifier la documentation ?">
    Les membres de l'équipe peuvent consulter les builds et déclencher des reconstructions, mais la modification se fait dans votre dépôt GitHub. Toute personne ayant accès au dépôt peut modifier les docs.
  </Accordion>

  <Accordion title="Comment transférer la propriété d'un projet ?">
    Allez dans **Settings** → **Team** → **Transfer Ownership**. Le nouveau propriétaire doit être un membre existant de l'équipe.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Où sont stockées mes identifiants CLI ?">
    Dans `~/.jamdeskrc`, un fichier JSON avec des permissions `0600` (seul votre utilisateur peut le lire). Il stocke votre token de rafraîchissement, votre e-mail et votre identifiant utilisateur. Exécutez `jamdesk logout` pour le vider.
  </Accordion>

  <Accordion title='Pourquoi la CLI indique-t-elle "session expired" ?'>
    Votre token de rafraîchissement n'est plus valide. Cela se produit après des changements de mot de passe, des suppressions de compte ou une inactivité prolongée. Exécutez `jamdesk login` pour obtenir une nouvelle session.
  </Accordion>

  <Accordion title="Puis-je utiliser la CLI dans des pipelines CI/CD ?">
    Oui, mais la connexion par navigateur ne fonctionnera pas dans les environnements headless. Connectez-vous sur votre machine locale, puis copiez `~/.jamdeskrc` sur votre runner CI. Le token de rafraîchissement gère l'authentification à partir de là.
  </Accordion>
</AccordionGroup>

## Contenu et fonctionnalités

<AccordionGroup>
  <Accordion title="Quels formats de fichiers sont pris en charge ?">
    Jamdesk prend en charge MDX (Markdown + JSX) et les fichiers Markdown standard.
  </Accordion>

  <Accordion title="Puis-je utiliser des composants React personnalisés ?">
    Oui. Définissez des composants inline directement dans MDX avec `export const`, ou créez des composants réutilisables dans le répertoire `/snippets`. Pour les composants interactifs avec des hooks, utilisez des fichiers `.tsx` avec `'use client'`. Consultez [Composants React personnalisés](/fr/content/react-components) et [Snippets](/fr/content/snippets).
  </Accordion>

  <Accordion title="Y a-t-il une limite de pages ?">
    Aucune limite stricte sur les pages. La plupart des sites de documentation fonctionnent bien avec des centaines de pages.
  </Accordion>

  <Accordion title="Jamdesk prend-il en charge plusieurs langues ?">
    Oui. Utilisez la propriété `languages` dans votre configuration de navigation pour créer un sélecteur de langue. Chaque langue dispose de sa propre structure de navigation et de son contenu. Consultez [Support multilingue](/fr/setup/languages).
  </Accordion>

  <Accordion title="Jamdesk traduit-il mon contenu automatiquement ?">
    Non. Jamdesk ne traduit pas le contenu pour vous. Vous fournissez les fichiers MDX traduits et Jamdesk gère le routage, la navigation, le sélecteur de langue et le style RTL. Apportez les traductions depuis votre propre flux de travail (traducteurs humains, traduction automatique ou un LLM) et placez-les dans des répertoires préfixés par la langue (`es/`, `fr/`, etc.). Consultez [Support multilingue](/fr/setup/languages) pour la structure des répertoires et la configuration.
  </Accordion>
</AccordionGroup>

## Chat IA

<AccordionGroup>
  <Accordion title="Mon site de docs dispose-t-il d'un chat IA ?">
    Oui. Chaque site Jamdesk inclut un assistant de chat intégré qui répond aux questions des visiteurs à partir de votre documentation. Il est activé par défaut, aucune configuration n'est requise. Consultez [Chat IA](/fr/ai/chat) pour plus de détails.
  </Accordion>

  <Accordion title="Le chat IA est-il payant en supplément ?">
    Non. Le chat IA est inclus dans tous les plans sans coût supplémentaire.
  </Accordion>

  <Accordion title="Puis-je désactiver le chat IA ?">
    Oui. Définissez `chat.enabled` à `false` dans votre `docs.json` :

    ```json
    { "chat": { "enabled": false } }
    ```

    Le panneau de chat et le raccourci clavier seront supprimés après votre prochain build.
  </Accordion>

  <Accordion title="Quelles données le chat utilise-t-il pour répondre aux questions ?">
    Le chat utilise uniquement vos pages de documentation publiées. À chaque build, Jamdesk indexe votre contenu dans une base de données vectorielle. Lorsqu'un visiteur pose une question, les sections pertinentes sont récupérées et envoyées à Claude comme contexte. L'IA ne peut pas accéder à des données en dehors de vos docs.
  </Accordion>
</AccordionGroup>
