Voyez ce que les lecteurs recherchent, quelles requêtes ne donnent aucun résultat et ce sur quoi ils cliquent.

<Info>
Vous cherchez des données sur les pages vues et les visiteurs ? Consultez [Analytique du projet](/fr/setup/project-analytics).
</Info>

<Note>
Si les données de recherche sont manquantes ou retardées, consultez [Problèmes d'analytique](/fr/help/troubleshooting/analytics-issues).
</Note>

## Consulter l'analytique de recherche

Accédez à l'analytique de recherche depuis votre dashboard de projet :

<Steps>
  <Step title="Ouvrez votre projet">
    Rendez-vous sur [dashboard.jamdesk.com](https://dashboard.jamdesk.com) et sélectionnez votre projet.
  </Step>

  <Step title="Cliquez sur Analytique de recherche">
    Dans la barre latérale sous **Analytique**, cliquez sur **Recherche** pour afficher votre dashboard de recherche.
  </Step>

  <Step title="Sélectionnez une plage de dates">
    Utilisez le sélecteur de dates pour afficher les données de recherche sur différentes périodes. La valeur par défaut est 30 jours.
  </Step>
</Steps>

## Métriques clés

Le dashboard d'analytique de recherche affiche quatre métriques principales :

| Métrique | Description |
|--------|-------------|
| **Total des recherches** | Nombre de recherches effectuées au cours de la période sélectionnée |
| **Requêtes uniques** | Termes de recherche distincts utilisés |
| **Zéro résultat** | Recherches n'ayant retourné aucune correspondance |
| **Taux de clics** | Pourcentage de recherches où les utilisateurs ont cliqué sur un résultat |

Chaque métrique inclut une comparaison avec la période précédente, affichée sous forme de variation en pourcentage.

Exemple de snapshot :

```json
{
  "period": "Last 30 days",
  "total_searches": 940,
  "unique_queries": 312,
  "zero_results": 42,
  "top_queries": [
    { "query": "authentication", "searches": 84, "ctr": 0.82 },
    { "query": "api keys", "searches": 63, "ctr": 0.71 }
  ]
}
```

## Volume de recherche

Le graphique de volume de recherche affiche l'activité de recherche quotidienne sur la plage de temps sélectionnée. Utilisez-le pour :

- Identifier les schémas d'utilisation (trafic en semaine vs le week-end)
- Repérer les pics inhabituels pouvant indiquer des liens externes ou des annonces
- Suivre la croissance de l'utilisation de la documentation dans le temps

## Analyse des requêtes

### Recherches principales

Consultez les termes de recherche les plus courants saisis par les utilisateurs. Cela révèle :

- **Sujets populaires** - Ce dont les utilisateurs ont le plus souvent besoin
- **Problèmes de navigation** - Si les utilisateurs recherchent des éléments facilement trouvables dans la navigation
- **Écarts de terminologie** - Si les utilisateurs emploient des termes différents de ceux de votre documentation

Pour chaque requête, vous verrez :
- Nombre de recherches
- Nombre de clics sur les résultats
- Taux de clics (CTR)

### Lacunes de contenu

<Warning>
Les lacunes de contenu sont des recherches n'ayant retourné aucun résultat. Elles représentent des opportunités d'améliorer votre documentation.
</Warning>

L'onglet Lacunes de contenu affiche les requêtes où les utilisateurs ont cherché sans rien trouver. Causes courantes :

| Cause | Solution |
|-------|----------|
| Documentation manquante | Créer une nouvelle page couvrant le sujet |
| Terminologie différente | Ajouter des synonymes ou mettre à jour les titres |
| Fautes d'orthographe dans le contenu | Corriger l'orthographe dans votre documentation |
| Fonctionnalité non encore documentée | Ajouter à la feuille de route de votre documentation |

Examinez régulièrement les lacunes de contenu pour vous assurer que votre documentation couvre ce dont les utilisateurs ont réellement besoin.

## Insights de recherche

Le panneau d'insights fournit des réponses rapides :

| Insight | Signification |
|---------|---------------|
| **Position de clic moyenne** | La position dans les résultats sur laquelle les utilisateurs cliquent généralement (plus bas est mieux) |
| **Recherches par jour** | Volume de recherche quotidien moyen |
| **Requête principale** | Votre terme de recherche le plus courant |
| **Plus manqué** | La principale requête sans résultat à traiter |

## Bonnes pratiques

<Accordion title="Examiner les lacunes de contenu chaque semaine">
Définissez une tâche récurrente pour examiner les recherches sans résultat. Même quelques minutes par semaine évite l'accumulation d'une dette de documentation.
</Accordion>

<Accordion title="Utiliser un langage naturel dans les titres">
Les utilisateurs recherchent souvent avec des phrases naturelles. Si vos titres correspondent à la façon dont les utilisateurs pensent, ils trouveront le contenu plus rapidement.
</Accordion>

<Accordion title="Ajouter des synonymes aux pages importantes">
Si les utilisateurs recherchent « configuration » mais que votre page s'appelle « installation », mentionnez les deux termes dans votre contenu afin que la recherche la trouve.
</Accordion>

<Accordion title="Suivre les améliorations du CTR">
Après avoir comblé les lacunes de contenu, surveillez si les taux de clics s'améliorent. Un CTR faible sur des requêtes à fort volume indique que les résultats ne correspondent pas à l'intention des utilisateurs.
</Accordion>

## Score de qualité de la recherche

Jamdesk calcule un score de qualité de la recherche basé sur le taux de clics :

``` text
Score = (Searches with clicks / Total searches) × 100
```

| Score | Évaluation |
|-------|--------|
| 90%+ | Excellent |
| 70–89% | Bon |
| 50–69% | À améliorer |
| Moins de 50% | Mauvais |

## Export des données

Exportez les données de recherche pour une analyse approfondie :

1. Allez dans **Analytique** → **Recherche**
2. Cliquez sur **Exporter**
3. Choisissez le format CSV ou JSON

## Disponibilité des données

Les données d'analytique de recherche apparaissent après l'agrégation quotidienne effectuée à 2h00 UTC. Les recherches effectuées aujourd'hui apparaîtront dans le dashboard demain.

<Note>
Si vous venez de configurer votre documentation, attendez 24 à 48 heures pour que les données de recherche s'accumulent avant d'espérer des insights significatifs.
</Note>
