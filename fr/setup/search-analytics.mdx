Découvrez ce que recherchent les lecteurs, quelles requêtes ne renvoient aucun résultat, et sur quoi ils cliquent.

<Info>
Vous cherchez les pages vues et les données visiteurs ? Consultez [Project Analytics](/fr/setup/project-analytics).
</Info>

<Note>
Si les données de recherche sont manquantes ou retardées, consultez [Analytics Issues](/fr/help/troubleshooting/analytics-issues).
</Note>

## Consulter Search Analytics

Accédez à Search Analytics depuis votre dashboard de projet :

<Steps>
  <Step title="Ouvrez votre projet">
    Allez sur [dashboard.jamdesk.com](https://dashboard.jamdesk.com) et sélectionnez votre projet.
  </Step>

  <Step title="Cliquez sur Search Analytics">
    Dans la barre latérale, sous **Analytics**, cliquez sur **Search** pour afficher votre dashboard de recherche.
  </Step>

  <Step title="Sélectionnez une plage de dates">
    Utilisez le sélecteur de dates pour afficher les données de recherche sur différentes périodes. La valeur par défaut est 30 jours.
  </Step>
</Steps>

## Indicateurs clés

Le dashboard Search Analytics affiche quatre indicateurs principaux :

| Indicateur | Description |
|--------|-------------|
| **Total Searches** | Nombre de recherches effectuées pendant la période sélectionnée |
| **Unique Queries** | Termes de recherche distincts utilisés |
| **Zero Results** | Recherches n'ayant renvoyé aucun résultat |
| **Click-through Rate** | Pourcentage de recherches où les utilisateurs ont cliqué sur un résultat |

Chaque indicateur inclut une comparaison avec la période précédente, affichée sous forme de variation en pourcentage.

Exemple d'instantané :

```json
{
  "period": "Last 30 days",
  "total_searches": 940,
  "unique_queries": 312,
  "zero_results": 42,
  "top_queries": [
    { "query": "authentication", "searches": 84, "ctr": 0.82 },
    { "query": "api keys", "searches": 63, "ctr": 0.71 }
  ]
}
```

## Volume de recherche

Le graphique de volume de recherche affiche l'activité de recherche quotidienne sur la période sélectionnée. Utilisez-le pour :

- Identifier les tendances d'utilisation (trafic en semaine vs le week-end)
- Repérer les pics inhabituels pouvant indiquer des liens externes ou des annonces
- Suivre la croissance de l'utilisation de la documentation dans le temps

## Analyse des requêtes

### Recherches les plus fréquentes

Consultez les termes de recherche les plus courants saisis par les utilisateurs. Cela révèle :

- **Sujets populaires** - Ce dont les utilisateurs ont le plus souvent besoin
- **Problèmes de navigation** - Si les utilisateurs recherchent des éléments facilement trouvables dans la navigation
- **Écarts de terminologie** - Si les utilisateurs emploient des termes différents de ceux de votre documentation

Pour chaque requête, vous verrez :
- Le nombre de recherches
- Le nombre de clics sur les résultats
- Le taux de clics (CTR)

### Lacunes de contenu

<Warning>
Les lacunes de contenu sont des recherches n'ayant renvoyé aucun résultat. Chacune correspond à un sujet non encore couvert par votre documentation.
</Warning>

L'onglet Content Gaps affiche les requêtes pour lesquelles les utilisateurs ont effectué une recherche sans rien trouver. Causes courantes :

| Cause | Solution |
|-------|----------|
| Documentation manquante | Créez une nouvelle page couvrant le sujet |
| Terminologie différente | Ajoutez des synonymes ou mettez à jour les titres |
| Fautes de frappe dans le contenu | Corrigez l'orthographe dans votre documentation |
| Fonctionnalité pas encore documentée | Ajoutez-la à votre feuille de route documentaire |

Passez régulièrement en revue les lacunes de contenu. La section Bonnes pratiques ci-dessous suggère une fréquence hebdomadaire.

## Insights de recherche

Le panneau d'insights fournit des réponses rapides :

| Insight | Signification |
|---------|---------------|
| **Avg. Click Position** | La position moyenne des résultats sur lesquels les utilisateurs cliquent (plus bas est mieux) |
| **Searches per Day** | Volume de recherche quotidien moyen |
| **Top Query** | Votre terme de recherche le plus courant |
| **Most Missed** | La requête sans résultat la plus fréquente à traiter |

## Bonnes pratiques

<Accordion title="Passez en revue les lacunes de contenu chaque semaine">
Planifiez une tâche récurrente pour examiner les recherches sans résultat. Même quelques minutes par semaine évitent l'accumulation de dette documentaire.
</Accordion>

<Accordion title="Utilisez un langage naturel dans les titres">
Les utilisateurs recherchent souvent avec des expressions naturelles. Si vos titres correspondent à la façon dont les utilisateurs pensent, ils trouveront le contenu plus rapidement.
</Accordion>

<Accordion title="Ajoutez des synonymes aux pages importantes">
Si les utilisateurs recherchent « setup » mais que votre page s'appelle « installation », mentionnez les deux termes dans votre contenu pour que la recherche la trouve.
</Accordion>

<Accordion title="Suivez les améliorations du CTR">
Après avoir traité les lacunes de contenu, surveillez si le taux de clics s'améliore. Un CTR faible sur des requêtes à fort volume indique que les résultats ne correspondent pas à l'intention des utilisateurs.
</Accordion>

## Score de qualité de recherche

Jamdesk calcule un score de qualité de recherche basé sur le taux de clics :

``` text
Score = (Searches with clicks / Total searches) × 100
```

| Score | Évaluation |
|-------|--------|
| 90%+ | Excellent |
| 70-89% | Bon |
| 50-69% | À améliorer |
| Moins de 50% | Faible |

## Export des données

Exportez les données de recherche pour une analyse approfondie :

1. Allez dans **Analytics** → **Search**
2. Cliquez sur **Export**
3. Choisissez le format CSV ou JSON

## Disponibilité des données

Les données Search Analytics apparaissent après l'exécution du calcul quotidien à 2h UTC. Les recherches effectuées aujourd'hui apparaîtront dans le dashboard demain.

<Note>
Si vous venez de configurer votre documentation, laissez 24 à 48 heures pour que les données de recherche s'accumulent avant de vous attendre à des insights pertinents.
</Note>
