Cada build pasa por varias fases, desde en cola hasta activo. Supervisa el progreso desde la pestaña Deployments.

## Fases del build

<Steps>
  <Step title="En cola">
    El build está esperando para iniciar. La mayoría de los builds comienzan en segundos.
  </Step>
  <Step title="Clonando">
    Descargando el contenido de tu repositorio desde GitHub.
  </Step>
  <Step title="Validando">
    Comprobando la configuración de `docs.json` y la sintaxis de MDX.
  </Step>
  <Step title="Procesando">
    Analizando archivos MDX y resolviendo importaciones.
  </Step>
  <Step title="Compilando">
    Compilando MDX a HTML y aplicando resaltado de sintaxis.
  </Step>
  <Step title="Desplegando">
    Subiendo a la CDN y purgando la caché.
  </Step>
  <Step title="Activo">
    Build completado. Tu documentación está actualizada.
  </Step>
</Steps>

## Ver el estado del build

### Resumen del dashboard

La página principal de tu proyecto muestra:

- Estado actual del build
- Hora del último despliegue exitoso
- Historial reciente de builds

### Detalles del build

Haz clic en cualquier build para ver:

- Hora de inicio y finalización
- Duración
- Activado por (push, manual, CLI)
- Hash y mensaje del commit
- Registro completo del build

### Advertencias y sugerencias

Los builds completados pueden incluir dos niveles de comentarios:

- **Advertencias** (insignia naranja): problemas que vale la pena corregir, como enlaces rotos o recursos faltantes. Nunca hacen fallar el build.
- **Sugerencias** (bombilla): mejoras opcionales para el branding y el SEO de tu sitio, como agregar un [favicon, descripción o logo](/es/customization/branding). Las sugerencias solo aparecen en tu build completado más reciente, no cuentan para la insignia de advertencias y nunca se envían por correo electrónico.

Muchas advertencias de enlaces rotos y descripciones faltantes se pueden reparar automáticamente. Cuando tu build más reciente tiene problemas reparables, usa [Corregir con IA](/es/builds/fix-with-ai) para revisar y aplicar los cambios sin editar MDX manualmente.

## Notificaciones del build

Recibe notificaciones sobre el estado del build:

### Correo electrónico

Activa las alertas de fallos del build en **Settings** → **Notifications**.

### Slack

Conecta Slack para recibir notificaciones de build en tu canal. Consulta [Integración con Slack](/es/integrations/slack).

## Historial de builds

Consulta tus últimos 30 builds en la pestaña **Deployments**:

- Estado del build (success, failed, cancelled)
- Duración
- Tipo de activación
- Información del commit

## Cancelar builds

Para cancelar un build en ejecución:

1. Ve a la pestaña **Deployments**
2. Busca el build en ejecución
3. Haz clic en **Cancel**

El build exitoso anterior permanece activo.
