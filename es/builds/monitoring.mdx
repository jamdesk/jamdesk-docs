---

Cada build pasa por varias fases desde en cola hasta en vivo. Sigue el progreso desde la pestaña Deployments.

## Fases del build

<Steps>
  <Step title="En cola">
    El build está esperando para iniciar. La mayoría de los builds empiezan en segundos.
  </Step>
  <Step title="Clonando">
    Obteniendo el contenido de tu repositorio desde GitHub.
  </Step>
  <Step title="Validando">
    Comprobando la configuración de `docs.json` y la sintaxis MDX.
  </Step>
  <Step title="Procesando">
    Analizando los archivos MDX y resolviendo imports.
  </Step>
  <Step title="Compilando">
    Compilando MDX a HTML y aplicando resaltado de sintaxis.
  </Step>
  <Step title="Desplegando">
    Subiendo al CDN y purgando la caché.
  </Step>
  <Step title="En vivo">
    Build completo. Tu documentación está actualizada.
  </Step>
</Steps>

## Ver el estado del build

### Resumen del dashboard

La página principal de tu proyecto muestra:

- Estado actual del build
- Hora del último deploy exitoso
- Historial reciente de builds

### Detalles del build

Haz clic en cualquier build para ver:

- Hora de inicio y fin
- Duración
- Activado por (push, manual, CLI)
- Hash del commit y mensaje
- Log completo del build

### Advertencias y sugerencias

Los builds completados pueden llevar dos niveles de feedback:

- **Advertencias** (insignia naranja): problemas que vale la pena corregir, como enlaces rotos o assets faltantes. Nunca hacen fallar el build.
- **Sugerencias** (bombilla): mejoras opcionales para el branding y SEO de tu sitio, como agregar un [favicon, descripción o logo](/es/customization/branding). Las sugerencias solo aparecen en tu último build completado, no cuentan para la insignia de advertencias y nunca se envían por email.

Muchas advertencias de enlaces rotos y descripciones faltantes se pueden reparar automáticamente. Cuando tu último build tiene problemas corregibles, usa [Fix with AI](/es/builds/fix-with-ai) para revisar y aplicar los cambios sin editar MDX manualmente.

```text
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Notificaciones de build

Jamdesk puede avisarte por email o Slack cuando un build termina o falla:

### Email

Activa las alertas de fallo de build en **Settings** → **Notifications**.

### Slack

Conecta Slack para recibir notificaciones de build en tu canal. Consulta [Slack Integration](/es/integrations/slack).

## Historial de builds

Consulta tus últimos 30 builds en la pestaña **Deployments**:

- Estado del build (exitoso, fallido, cancelado)
- Duración
- Tipo de activación
- Información del commit

## Cancelar builds

Para cancelar un build en ejecución:

1. Ve a la pestaña **Deployments**
2. Busca el build en ejecución
3. Haz clic en **Cancel**

El último build exitoso anterior permanece en vivo.
