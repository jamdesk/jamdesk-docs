Haz push a GitHub y Jamdesk construye tu build automáticamente. También puedes activar builds desde el dashboard.

## Builds automáticos

Cada push a tu rama conectada activa un build automáticamente:

1. Haces push de cambios a GitHub
2. GitHub envía un webhook a Jamdesk
3. Jamdesk pone en cola e inicia tu build
4. Los docs generados se despliegan en el CDN

<Tip>
Los builds usan debouncing. Si haces push de varios commits rápidamente, Jamdesk espera 10 segundos de inactividad antes de construir.
</Tip>

## Builds manuales

Activa un build sin hacer push de cambios:

<Steps>
  <Step title="Abre tu proyecto">
    Ve a tu proyecto en el dashboard.
  </Step>
  <Step title="Ve a Settings">
    Haz clic en **Settings** en la barra lateral.
  </Step>
  <Step title="Haz clic en Rebuild">
    Selecciona **Rebuild** para iniciar un nuevo build.
  </Step>
</Steps>

### Cuándo usar builds manuales

- Después de cambiar variables de entorno
- Para actualizar tras un build fallido
- Después de actualizaciones de la plataforma Jamdesk
- Para limpiar contenido en caché

## Cola de builds

Durante periodos de alto tráfico, los builds pueden ponerse en cola brevemente. La posición en la cola se muestra en el dashboard. Los builds se procesan en el orden recibido.

## Builds concurrentes

Cada proyecto puede tener un build en ejecución a la vez. Los nuevos activadores mientras un build está en ejecución se pondrán en cola.

| Plan | Proyectos concurrentes |
|------|---------------------|
| Trial | 1 |
| Pro | 3 |
