Cuando un build falla, revisa el mensaje de error en el registro del build y encuentra la sección correspondiente a continuación.

Las capturas de pantalla muestran la interfaz en inglés.

## Visualización de detalles del error

1. Ve a la pestaña **Deployments** de tu proyecto
2. Haz clic en el build fallido
3. Revisa el mensaje de error y el registro del build

El registro muestra exactamente dónde y por qué falló el build.

## Errores comunes

### Errores de configuración

**"Invalid docs.json"** — Tu archivo de configuración tiene errores de sintaxis.

<Steps>
  <Step title="Verificar la sintaxis JSON">
    Busca comas, corchetes o comillas faltantes.
  </Step>
  <Step title="Validar localmente">
    Ejecuta `jamdesk validate` para ver los errores detallados.
  </Step>
  <Step title="Corregir y hacer push">
    Corrige los errores y haz push para iniciar un nuevo build.
  </Step>
</Steps>

### Páginas faltantes

**"Page not found"** — Una página en tu navegación no existe.

- Verifica que el nombre del archivo coincide con la ruta en `docs.json`
- Las rutas distinguen entre mayúsculas y minúsculas
- No incluyas la extensión `.mdx`

### Errores de sintaxis MDX

**"MDX compilation failed"** — Sintaxis MDX o JSX no válida.

Causas frecuentes:
- Etiquetas sin cerrar (`<Card>` sin `</Card>`)
- Caracteres especiales sin escapar (`{` en lugar de `\{`)
- Sintaxis de prop no válida

### Timeout del build

**"Build exceeded time limit"** — El build tardó demasiado.

Intenta:
- Optimizar imágenes grandes
- Dividir páginas muy extensas
- Reducir el número total de páginas

## Advertencias del build

Las advertencias nunca hacen fallar un build — tu sitio se publica igualmente. Señalan problemas que vale la pena corregir y aparecen en tres lugares: el correo de advertencias del build, la entrada del build en la pestaña **Deployments**, y localmente al ejecutar `jamdesk validate` o `jamdesk dev`.

### Imágenes faltantes

**"Image not found"** — Una página hace referencia a una imagen que no está en tu proyecto.

Jamdesk comprueba cada referencia de imagen — `![alt](/images/photo.webp)` en Markdown y atributos `src` de `<img>`/`<Image>` — contra los archivos del repositorio. Si el destino falta, la advertencia indica la página, el número de línea y la ruta no resuelta, de modo que una imagen rota nunca llega a producción como un 404 silencioso.

Para corregirlo:

- Sube la imagen al repositorio o corrige la ruta para apuntar a un archivo existente
- Las rutas distinguen entre mayúsculas y minúsculas y se resuelven desde la raíz del proyecto (con `/` inicial) o de forma relativa a la página
- Una referencia a `photo.png` se resuelve igualmente cuando la [optimización de imágenes](/es/builds/image-optimization) la convierte a WebP

Las referencias a URLs externas, URIs `data:` y la sintaxis de imágenes dentro de bloques de código se ignoran, por lo que los ejemplos en tu propia documentación nunca generan una advertencia falsa.

## Pasos de depuración

<Accordion title="Paso 1: Revisa el registro del build">
  El registro muestra la línea y el archivo exactos que provocan el error. Comienza por ahí.
</Accordion>

<Accordion title="Paso 2: Prueba localmente">
  Ejecuta `jamdesk dev` localmente para reproducir y depurar el problema.
</Accordion>

<Accordion title="Paso 3: Valida la configuración">
  Ejecuta `jamdesk validate` para comprobar tu `docs.json` y `jamdesk broken-links` para detectar enlaces internos rotos.
</Accordion>

<Accordion title="Paso 4: Revisa los cambios recientes">
  Revisa tu último commit. ¿Agregaste una nueva página? ¿Cambiaste la configuración?
</Accordion>

## ¿Sigues sin resolverlo?

Si no puedes resolver el problema:

1. Copia el registro completo del build
2. Anota el ID de tu proyecto (en la URL)
3. [Contacta con soporte](/es/help/support/contact)
