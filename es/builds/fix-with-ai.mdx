Cuando un build termina con enlaces rotos o páginas sin descripción, Jamdesk puede reparar muchos de ellos por ti. El botón **Fix with AI** lee esos avisos de build, propone una edición concreta para cada uno y hace commit de las correcciones que apruebes en tu repositorio de GitHub conectado, lo que inicia un nuevo build. Esta página es para cualquiera que mantenga un sitio Jamdesk y quiera resolver avisos de build sin editar MDX a mano.

Las capturas de pantalla muestran la interfaz en inglés.

Para una versión local basada en terminal de la misma idea, consulta el [comando de la CLI `jamdesk fix`](/es/cli/fix-broken-links). El flujo del dashboard de abajo hace commit de los cambios por ti; la CLI escribe en tu copia de trabajo y te deja el commit a ti.

## Qué corrige

Fix with AI funciona con tres tipos de avisos de build:

- **Enlaces internos rotos.** Un fragmento de enlace que apunta a un encabezado que ya no existe en la página de destino, como un error tipográfico (`#instalation` → `#installation`), o una página traducida cuyo encabezado fue renombrado.
- **Descripciones de página faltantes.** Una página sin `description` en su frontmatter. Jamdesk redacta un breve resumen a partir del contenido de la página para que lo revises.
- **Títulos de página faltantes.** Una página sin título recibe uno sugerido, extraído del contenido de la página, para que lo revises.

Solo propone un cambio cuando puede resolver el destino con confianza. Todo lo ambiguo se deja sin modificar y se lista por separado para que puedas corregirlo manualmente.

Fix with AI hace hasta 1,000 solicitudes de IA por proyecto en un periodo de 24 horas. Los resultados de las páginas que no han cambiado se reutilizan y no cuentan para el límite.

<Note>
  El número de elementos corregibles no es el mismo que el número de avisos. Un build puede mostrar cinco avisos mientras Fix with AI ofrece corregir tres de ellos, porque los otros dos no tienen una corrección inequívoca. El banner siempre refleja lo que realmente se puede corregir.
</Note>

## Elegir qué ocurre

El ajuste **AI Fixes** decide qué hace Jamdesk con los avisos corregibles. Para cambiarlo, haz clic en **Settings** en la barra lateral y busca la tarjeta **AI Fixes** en **General**.

| Modo | Qué ocurre |
|---|---|
| **Off** | Jamdesk no analiza los builds. El botón **Fix with AI** se oculta. |
| **Review first** | Jamdesk sugiere correcciones. Tú las revisas y las aplicas en el modal. Es el modo predeterminado. |
| **Auto-fix** | Jamdesk hace commit de las correcciones después de cada build. Puedes deshacer cada ejecución. |

### Cómo funciona Auto-fix

Auto-fix aplica las mismas correcciones que el modal, también las descripciones escritas por IA. Omite todo lo que hayas ignorado. Empieza con el siguiente build después de guardar el ajuste.

Después de un build, Jamdesk hace commit de las correcciones en la rama de build del proyecto. El mensaje del commit es `docs: auto-fix 3 issues (via Jamdesk)` y el autor es Jamdesk. El build muestra una insignia **Auto-fixed** en Build History. En la [documentación sin GitHub](/es/setup/without-github), Jamdesk guarda las correcciones en tu documentación.

<Warning>
  Jamdesk hace commit en tu rama. Haz pull antes de hacer push. Cada commit de Auto-fix también ejecuta el CI que tenga tu repositorio en esa rama.
</Warning>

Qué esperar de cada ejecución:

- Jamdesk no aplica Auto-fix al build de su propio commit. Si ese build todavía tiene avisos corregibles, muestra **Needs review** y tú los aplicas desde el modal.
- Una corrección se aplica una sola vez. Si la reviertes, Jamdesk no la vuelve a aplicar, así que tu revert se mantiene. Una corrección que reaparece se muestra en **Needs review**.
- Los builds cuyos avisos no cambiaron desde la última ejecución se omiten.
- Auto-fix se pausa cuando la rama de build está protegida o la GitHub App de Jamdesk pierde el acceso de escritura. La tarjeta muestra **Paused**. Corrige la causa y vuelve a guardar **Auto-fix**.
- Los límites diarios de IA son los mismos que en el modal. Cuando un proyecto llega al límite, la ejecución omite algunas correcciones y lo indica.
- Una descripción nueva cambia la página, así que la siguiente ejecución de traducción vuelve a traducir esa página.

## Requisitos previos

- Un [repositorio de GitHub conectado](/es/integrations/github) para el proyecto.
- Acceso de escritura para la GitHub App de Jamdesk, para que pueda hacer commit de las correcciones. Si falta el acceso, el modal muestra un enlace **Grant access** que te lleva a GitHub para agregarlo.
- Un build completado que tenga avisos de enlace roto o de descripción faltante.

## Encontrar el banner

Abre tu proyecto y desplázate hasta **Build History** en la página Project Home. Cuando tu build más reciente tiene problemas corregibles, aparece un banner encima de la lista de builds con un contador y un botón **Fix with AI**.

El banner solo aparece en tu build completado más reciente. Los builds anteriores del historial no lo muestran, porque las correcciones siempre se aplican al estado actual de tu documentación.

## Revisar y aplicar las correcciones

<Steps>
  <Step title="Abrir la preview">
    Haz clic en **Fix with AI**. El modal se abre y el agente de IA revisa tu documentación para preparar un plan de corrección. Esto tarda unos segundos.
  </Step>
  <Step title="Leer cada cambio propuesto">
    Las correcciones se agrupan por tipo. **Broken links** muestra cada ancla reescrita, **Missing descriptions** muestra el resumen sugerido para cada página y **Missing titles** muestra el título propuesto. Desmarca la casilla de lo que prefieras omitir esta vez, o usa el botón de ignorar para [silenciar una recomendación de forma definitiva](#ignorar-recomendaciones). Los problemas sin una corrección clara aparecen bajo **Can't be fixed automatically** y se dejan para que los resuelvas manualmente.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="El modal de Fix with AI. Una sección Broken links lista tres correcciones marcadas, cada una mostrando el ancla anterior tachada y el ancla corregida. Una sección Can't be fixed automatically lista dos problemas para corregir manualmente, encima de los botones Cancel y Apply 3 fixes." />
    </Frame>
  </Step>
  <Step title="Aplicar">
    Haz clic en **Apply fixes**. Jamdesk hace commit de los cambios seleccionados en tu rama conectada con el mensaje `docs: apply AI-suggested fixes (via Jamdesk)` e inicia un nuevo build.
  </Step>
  <Step title="Confirmar la reconstrucción">
    Observa el nuevo build en [Build History](/es/builds/monitoring). Cuando se publique, los avisos corregidos habrán desaparecido. Lo que quede es un aviso que Fix with AI no pudo resolver o un nuevo problema del contenido más reciente.
  </Step>
</Steps>

<Note>
  Aplicar escribe un commit real en tu repositorio, por lo que el cambio queda registrado en tu historial de Git y puedes revisarlo o revertirlo en GitHub como cualquier otro commit.
</Note>

## Cuando algunos problemas no se pueden corregir

Si un aviso no tiene una corrección clara, el modal lo lista bajo un encabezado independiente y lo deja como está. Motivos comunes:

- Un enlace roto cuya página o encabezado de destino no existe en ningún lugar, por lo que no hay nada hacia donde apuntarlo.
- Una entrada de navegación sin archivo fuente correspondiente.
- Una página para la que el agente no pudo generar una descripción automáticamente.

Estos casos necesitan una edición manual. Abre la página en el [editor](/es/development/local-preview) o en tu editor de código, corrige el enlace o agrega la descripción, y luego haz push para reconstruir.

## Ignorar recomendaciones

Algunos avisos no vale la pena atenderlos: un enlace que rompiste a propósito, o una página provisional que no necesita descripción. Desmarcar una corrección solo la omite una vez. Ignorarla la elimina del contador hasta que indiques lo contrario.

Cada fila del modal, corregible o no, tiene un botón de ignorar. Haz clic en él y el elemento pasa a una sección **Ignored** colapsada en la parte inferior. Al cerrar el modal, el contador del banner en la página Project Home baja para coincidir, y los avisos correspondientes desaparecen de Build History, tanto en el build actual como en todos los siguientes. **Ignore all** hace lo mismo con todo lo que quede listado.

Cómo se comportan los elementos ignorados:

- **Compartido y persistente.** Los elementos ignorados se aplican a todo el proyecto, así que todos los miembros ven la misma lista, y se mantiene entre builds. Jamdesk relaciona cada aviso con su contenido en lugar de con su número de línea, así que editar otras partes de la página no hará reaparecer un elemento ignorado.
- **Restaurar.** Expande la sección **Ignored** y haz clic en **Restore** en cualquier elemento. Si ignoras todo en un build, el banner desaparece y un pequeño enlace "N ignored recommendations" debajo de Build History vuelve a abrir el modal.
- **Los avisos modificados reaparecen.** Si el problema subyacente cambia, por ejemplo si el enlace roto ahora apunta a otro lugar, deja de coincidir con la entrada ignorada y vuelve a aparecer como una recomendación nueva.

## Deshacer un auto-fix

Cada ejecución de Auto-fix tiene un botón **Undo**. Abre el build en Build History y busca la sección **Auto-fix**. Muestra lo que cambió Jamdesk y enlaza al commit. Haz clic en **Undo** y luego en **Undo auto-fix** para confirmar.

Jamdesk hace commit de la versión anterior de los archivos en tu rama con el mensaje `docs: undo Jamdesk auto-fix (via Jamdesk)`. Si un archivo cambió después del auto-fix, Jamdesk lo omite y lo lista. Deshaz esos archivos a mano.

Las correcciones deshechas quedan ignoradas. Sus avisos se ocultan y Jamdesk no las vuelve a aplicar. Para recuperarlas, abre **Fix with AI** y restáuralas en **Ignored**.

## Pasar las correcciones a tu agente de IA

Puedes dejar que un agente de programación como Claude Code haga las ediciones en tu repositorio. En el modal de Fix with AI, haz clic en **Copy for your AI agent**. Jamdesk copia un prompt de texto plano que lista cada corrección sugerida con su archivo y su línea, además de los problemas que hay que corregir a mano. Los elementos ignorados no se incluyen. Pega el prompt en tu agente.

Desde la terminal, `jamdesk fix --json` le da a un agente la misma lista en JSON. Consulta [Uso con un agente de IA](/es/cli/fix-broken-links#uso-con-un-agente-de-ia).

## Fix with AI frente a la CLI

Ambas herramientas corrigen anclas de enlaces rotos. Se diferencian en dónde se ejecutan y cómo se aplica el cambio.

| | Fix with AI (dashboard) | [`jamdesk fix`](/es/cli/fix-broken-links) (CLI) |
|---|---|---|
| Ejecución | En el dashboard, sobre un build | En tu terminal, sobre archivos locales |
| Corrige | Enlaces rotos, descripciones faltantes y títulos faltantes | Anclas de enlaces rotos y, con IA, descripciones faltantes |
| Commit | Hace commit en tu rama por ti | Escribe archivos locales; tú haces commit |
| Activación | Un clic en el banner del build | `jamdesk fix` |

Usa el flujo del dashboard para una reparación rápida sin salir de Jamdesk. Usa la CLI cuando quieras tener primero los cambios en tu copia de trabajo, por ejemplo para agruparlos con otras ediciones.

Poner **AI Fixes** en **Off** detiene los análisis del dashboard. `jamdesk fix` sigue funcionando en tu equipo. Para cambiar el ajuste desde la terminal, ejecuta [`jamdesk ai-fix`](/es/cli/overview) con `off`, `review` o `auto`:

```bash
jamdesk ai-fix auto
```
