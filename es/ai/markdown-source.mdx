Las herramientas de IA procesan Markdown de forma más eficiente que el HTML renderizado. Jamdesk pone a disposición el Markdown sin procesar de cada página agregando `.md` a cualquier URL. No requiere autenticación.

## Extensión de URL `.md`

Agrega `.md` a cualquier URL de página de documentación para obtener la fuente sin procesar en lugar del HTML renderizado:

```bash
# Rendered page
https://acme.jamdesk.app/getting-started

# Raw Markdown source
https://acme.jamdesk.app/getting-started.md
```

Esto funciona para cualquier profundidad de ruta. Así es como se ve la respuesta:

```bash
curl https://acme.jamdesk.app/getting-started.md
```

```markdown
---
title: Getting Started
description: Set up your first project in 5 minutes.
---

Welcome to the getting started guide.

## Prerequisites

<Note>You'll need Node.js 18 or later.</Note>
```

La respuesta es el archivo fuente exacto de tu repositorio, incluyendo el frontmatter y las etiquetas de componentes.

### Dominios personalizados

El contenido sin procesar también funciona en dominios personalizados. Usa la misma URL que ven tus lectores, con `.md` agregado:

```bash
# Docs served at root
curl https://docs.example.com/getting-started.md

# Docs served at /docs subpath
curl https://docs.example.com/docs/getting-started.md
```

## Formato del contenido

El contenido sin procesar es Markdown extendido con etiquetas de componentes como `<Note>`, `<Steps>` y `<Tabs>`. Los parsers de Markdown estándar tratarán las etiquetas de componentes como HTML sin procesar. Consulta [Bases de Markdown](/es/content/mdx-basics) para la referencia completa de sintaxis.

## Especificaciones OpenAPI en páginas de referencia de la API

Cuando obtienes el Markdown de una página de referencia de la API (una cuyo frontmatter declara una especificación `api:` u `openapi:`), Jamdesk agrega un pie de página breve que dirige a los agentes de IA hacia cada especificación OpenAPI de tu proyecto, agrupadas en una sola descarga:

```markdown
---

📦 **OpenAPI specs:** Every OpenAPI specification referenced by this documentation is available as a single download — https://acme.jamdesk.app/api-specs.zip
```

Es la misma `api-specs.zip` que ofrece la acción [Descargar especificación de la API](/es/ai/ai-actions#download-api-spec), ensamblada de nuevo en cada solicitud. El objetivo es el alcance: un agente que lee la página de un endpoint descubre que puede obtener el contrato completo legible por máquina en una sola solicitud, en lugar de recorrer cada endpoint. El pie de página aparece solo en páginas de referencia de la API de proyectos que tienen al menos una especificación; las guías normales no se ven afectadas.

## Detalles de la respuesta

### Encabezados

| Header | Value | Purpose |
|--------|-------|---------|
| `Content-Type` | `text/markdown; charset=utf-8` | Identifica el contenido como Markdown |
| `Cache-Control` | `public, max-age=3600, s-maxage=86400` | Cacheado 1 hora en el navegador, 1 día en la CDN (URLs `.md`) |
| `Vary` | `Accept` | La misma URL sirve HTML o Markdown según el header `Accept` de la solicitud |
| `X-Robots-Tag` | `noindex, nofollow` | Evita la indexación en buscadores |
| `Content-Disposition` | `inline` | Se muestra en el navegador en lugar de descargarse |
| `X-Frame-Options` | `DENY` | Evita la incrustación en iframes |
| `Content-Security-Policy` | `default-src 'none'` | Bloquea la ejecución de scripts |

Solicitar la URL canónica de una página (sin `.md`) con el header `Accept: text/markdown` devuelve el mismo Markdown, pero con `Cache-Control: private, no-store`. Comparte clave de caché con la página HTML, por lo que esa respuesta nunca se cachea.

### Respuestas de error

| Status | Meaning |
|--------|---------|
| `308` | Redirección por barra final (p. ej., `/intro.md/` redirige a `/intro.md`) |
| `404` | La página no existe (devuelve un breve error en texto plano, no Markdown) |
| `500` | Error del servidor (devuelve una página de error HTML) |

## Uso con herramientas de IA

Las URLs de fuente Markdown funcionan bien junto con el [servidor MCP](/es/ai/mcp-server). Usa `searchDocs` para encontrar páginas por palabra clave y luego obtén la fuente sin procesar de la página encontrada:

```bash
# 1. Search for a topic via MCP
curl -X POST https://acme.jamdesk.app/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"searchDocs","arguments":{"query":"authentication"}}}'

# 2. Fetch the raw source of the top result
curl https://acme.jamdesk.app/guides/authentication.md
```

Esto le da a las herramientas de IA acceso tanto a la búsqueda como a la fuente completa de tu documentación.
