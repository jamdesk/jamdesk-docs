Todos los sitios de Jamdesk incluyen un servidor MCP (Model Context Protocol) integrado. Mientras que `llms.txt` ofrece a las herramientas de IA una instantánea estática de tu documentación, MCP les permite buscar y consultar de forma interactiva, algo útil cuando los agentes de IA necesitan encontrar respuestas concretas en lugar de leerlo todo.

## ¿Qué es MCP?

El [Model Context Protocol](https://modelcontextprotocol.io) es un estándar abierto que permite a las herramientas de IA acceder a fuentes de datos externas. Tu documentación de Jamdesk expone dos herramientas a través de MCP:

| Herramienta | Propósito |
|------|---------|
| `searchDocs` | Busca en la documentación por palabra clave y devuelve resultados clasificados |
| `getPage` | Recupera una página como Markdown completo |

## Tu URL de endpoint

Tu endpoint de MCP es la URL de tu documentación con `/_mcp` añadido. Si tienes un [dominio personalizado](/es/deploy/custom-domains) activo, úsalo:

| Configuración | Endpoint |
|-------|----------|
| Dominio personalizado en `docs.acme.com` | `https://docs.acme.com/_mcp` |
| Sin dominio personalizado | `https://my-project.jamdesk.app/_mcp` |

<Note>
  Prefiere el endpoint de dominio personalizado siempre que haya uno conectado: mantiene tu marca en cada URL que ven las herramientas de IA, y sigue funcionando aunque más adelante ocultes tu subdominio `.jamdesk.app` con [Solo dominio personalizado](/es/deploy/custom-domain-only).
</Note>

## Configuración rápida

<Tabs>
  <Tab title="Claude Code">
    Añade tu documentación como servidor MCP:

    ```bash
    claude mcp add --transport http my-docs https://docs.acme.com/_mcp
    ```

    Reemplaza `docs.acme.com` con el dominio de tu documentación, o con `my-project.jamdesk.app` si no has conectado un dominio personalizado.

    Ahora, cuando le preguntes a Claude sobre tu proyecto, podrá buscar y leer tu documentación directamente.
  </Tab>
  <Tab title="Cursor">
    Añade esto al `.cursor/mcp.json` de tu proyecto:

    ```json
    {
      "mcpServers": {
        "my-docs": {
          "url": "https://docs.acme.com/_mcp"
        }
      }
    }
    ```

    Cursor se conectará automáticamente a tu documentación cuando abras el proyecto.
  </Tab>
</Tabs>

## Herramientas disponibles

### searchDocs

Busca en tu documentación y obtén resultados clasificados.

**Parámetros:**

| Parámetro | Tipo | Obligatorio | Descripción |
|-----------|------|----------|-------------|
| `query` | string | Sí | Términos de búsqueda (p. ej., "autenticación", "primeros pasos") |
| `limit` | number | No | Resultados máximos (predeterminado: 10, máximo: 50) |
| `type` | string | No | Filtra por tipo de contenido: `all`, `api`, `guide`, `quickstart`, `help`, `component` |

**Solicitud de ejemplo:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "searchDocs",
    "arguments": {
      "query": "authentication",
      "limit": 5
    }
  }
}
```

**Respuesta de ejemplo:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"query\":\"authentication\",\"total\":1,\"results\":[{\"title\":\"Authentication\",\"description\":\"How to authenticate API requests\",\"url\":\"/docs/api/authentication\",\"type\":\"api\",\"score\":0.95}]}"
    }]
  }
}
```

### getPage

Recupera una página de documentación como Markdown. Las tablas, las listas y los bloques de código llegan intactos, en lugar de extractos cortos. Pasa la `url` que devolvió `searchDocs`, o la ruta simple de la página. Las páginas de más de 80 000 caracteres se cortan en esa longitud, con un enlace a la URL `.md` de la página para el resto.

**Parámetros:**

| Parámetro | Tipo | Obligatorio | Descripción |
|-----------|------|----------|-------------|
| `slug` | string | Sí | La `url` de un resultado de `searchDocs`, o la ruta de la página sin el prefijo `/docs` (p. ej., `api/authentication`) |

**Solicitud de ejemplo:**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "getPage",
    "arguments": {
      "slug": "api/authentication"
    }
  }
}
```

**Respuesta de ejemplo:**

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{
      "type": "text",
      "text": "{\"title\":\"Authentication\",\"description\":\"How to authenticate\",\"content\":\"## Overview\\n\\nUse API keys to authenticate...\",\"url\":\"/docs/api/authentication\"}"
    }]
  }
}
```

## Probar el endpoint

Puedes probar tu endpoint de MCP directamente con curl:

```bash
# List available tools
curl -X POST https://docs.acme.com/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

# Search for content
curl -X POST https://docs.acme.com/_mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"searchDocs","arguments":{"query":"getting started"}}}'
```

## Sitios protegidos con inicio de sesión

Si tu sitio usa autenticación por contraseña o JWT, el servidor MCP necesita una clave de API del proyecto. Crea una en **Project Settings > API Keys** y envíala como encabezado:

```bash
claude mcp add --transport http my-docs https://docs.example.com/_mcp \
  --header "Authorization: Bearer jd_live_..."
```

Con la clave, un cliente MCP puede buscar y leer las páginas con búsqueda habilitada del sitio, el mismo conjunto que cubre la búsqueda del sitio. Las páginas restringidas por grupo nunca están disponibles a través de MCP, con o sin clave. Las páginas ocultas y las páginas con `search: false` se omiten a menos que las hayas hecho buscables. Trata la clave como una contraseña y revócala en el dashboard si se filtra.

La misma clave también abre las URL de páginas `.md`, `llms.txt` y `llms-full.txt`. Consulta [llms.txt](/es/ai/llms-txt#sitios-protegidos-con-inicio-de-sesión) y [Fuente Markdown](/es/ai/markdown-source). La clave nunca abre las páginas HTML ni el chat de IA, que siguen requiriendo un inicio de sesión.

Sin clave, el servidor responde con `401` y un cuerpo JSON que explica cómo añadir una. Una clave de otro proyecto se rechaza. Los códigos de error son:

| Estado | `error` | Significado |
|--------|---------|-------------|
| 401 | `auth_required` | No se envió ninguna clave. |
| 401 | `invalid_api_key` | La clave no es válida para este sitio. |
| 503 | `auth_unavailable` | No se pudo comprobar la clave. Reintenta pasados los segundos indicados en el encabezado `Retry-After`. |

## Cómo funciona

El endpoint de MCP utiliza un índice de búsqueda que se genera junto con tu documentación:

- **Clasificación BM25** - Clasifica los resultados por relevancia
- **Coincidencia difusa** - Gestiona errores tipográficos (tolerancia de 1 carácter)
- **Ponderación de campos** - Los títulos y los encabezados de sección tienen más peso que el contenido del cuerpo
- **Filtrado por tipo** - Filtra los resultados por tipo de contenido (API, guía, etc.)

El índice se reconstruye con cada despliegue.

## Límites de frecuencia

Las solicitudes sin clave de API están limitadas a unas **60 por minuto** por dirección IP. Es suficiente para el uso normal de un asistente de IA.

En un sitio protegido con inicio de sesión, las solicitudes autenticadas con una clave comparten un límite de **120 por minuto** por clave. Cuentan las llamadas MCP, las solicitudes de páginas `.md` y las de `llms.txt` o `llms-full.txt`. La [API de búsqueda](/es/jamdesk-api/docs-search-api#límites-de-tasa) mantiene su propio límite de 60 por minuto por clave.

Al superar un límite, la respuesta es un `429` con `Retry-After: 60`.

## Solución de problemas

<Accordion title="El servidor MCP no se conecta">
  Verifica que la URL de tu endpoint sea correcta y accesible:

  ```bash
  curl https://docs.acme.com/_mcp
  ```

  Deberías ver una respuesta JSON con información del servidor. Si no es así, comprueba que se haya hecho al menos un build de tu documentación.
</Accordion>

<Accordion title="La búsqueda no devuelve resultados">
  El índice de búsqueda se genera durante el build. Si agregaste contenido recientemente, activa un nuevo build desde tu dashboard de Jamdesk para actualizar el índice.
</Accordion>

<Accordion title="getPage devuelve null">
  Asegúrate de que el slug coincida exactamente con la ruta de tu página (sin la extensión `.mdx`). Por ejemplo, si tu página está en `api/authentication.mdx`, usa `api/authentication` como slug.
</Accordion>

<Accordion title="401 auth_required en un sitio protegido">
  El sitio usa autenticación por contraseña o JWT, así que la solicitud necesita una clave de API del proyecto. Añade el encabezado `Authorization: Bearer` con una clave de **Project Settings > API Keys**. Consulta [Sitios protegidos con inicio de sesión](#sitios-protegidos-con-inicio-de-sesión).
</Accordion>
