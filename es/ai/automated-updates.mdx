El skill `/update-jamdesk` para Claude Code observa los cambios en tu código y genera actualizaciones de documentación coincidentes. Después de lanzar una función orientada al usuario, ejecuta el skill y determinará qué páginas de documentación deben crearse o editarse.

<Note>
**¿Buscas consejos generales de escritura con IA?** Esta página cubre el skill `/update-jamdesk` para actualizaciones automáticas de documentación. Para la configuración de la herramienta, consulta [Claude Code](/es/ai/claude-code). Para orientación más amplia sobre el uso de herramientas de IA para escribir documentación, consulta [Escribir con IA](/es/ai/writing-with-ai).
</Note>

## Cuándo usarlo

**Úsalo cuando:** hayas hecho cambios orientados al usuario en APIs, comandos CLI, la interfaz de usuario, opciones de configuración o el comportamiento de componentes.

**Omítelo cuando:** se trate de refactorizaciones internas, cambios solo de pruebas, configuración de build/CI o trabajo de rendimiento sin cambio de comportamiento. Estos no necesitan documentación orientada al usuario.

## Requisitos previos

- [Claude Code](https://claude.ai/code) instalado y configurado
- Un proyecto de documentación de Jamdesk con `docs.json`
- Opcional: [Jamdesk CLI](/es/cli/overview) para verificación (`npm install -g jamdesk`)

## Inicio rápido

<Steps>
  <Step title="Crear el archivo de configuración">
    Crea un archivo `.jamdesk-docs-path` en tu repositorio de código que apunte a tu documentación:

    ```yaml .jamdesk-docs-path
    docs_path: ../my-docs
    ```

    La ruta puede ser relativa (desde el archivo de configuración) o absoluta.
  </Step>
  <Step title="Ejecutar el skill">
    Después de implementar una función, ejecuta:

    ```text
    /update-jamdesk
    ```

    Claude analizará tus cambios y hará preguntas aclaratorias antes de escribir la documentación.
  </Step>
  <Step title="Revisar y confirmar el commit">
    Revisa la documentación generada; luego Claude la verificará con `jamdesk validate` y `jamdesk broken-links` antes de confirmar el commit.
  </Step>
</Steps>

## Formato del archivo de configuración

El archivo `.jamdesk-docs-path` le indica a Claude dónde está tu documentación.

**Formato simple**: solo la ruta:

```text
../my-docs
```

**Formato completo**: con opciones:

```yaml .jamdesk-docs-path
# Path to documentation repository
docs_path: ../my-docs

# Optional: Branch for doc updates (default: main)
docs_branch: main
```

<Note>
  El archivo de configuración se localiza recorriendo desde tu directorio actual hasta la raíz del repositorio git. Colócalo en la raíz de tu repositorio para obtener mejores resultados.
</Note>

## Cómo funciona

Cuando ejecutas `/update-jamdesk`, Claude:

1. **Localiza tu documentación**: encuentra el archivo de configuración `.jamdesk-docs-path`
2. **Hace preguntas**: aclara la estrategia de branches, el alcance y el contenido
3. **Analiza la documentación existente**: busca contenido relacionado para actualizar o ampliar
4. **Escribe la documentación**: crea o actualiza páginas siguiendo los estándares de Jamdesk, con ejemplos simples primero
5. **Revisa el tono**: comprueba si el resultado tiene relleno típico de IA. Claude escribe mejor con un CLAUDE.md que defina la voz (consulta [Claude Code](/es/ai/claude-code))
6. **Verifica**: ejecuta `jamdesk validate` y `jamdesk broken-links`
7. **Confirma el commit**: prepara los cambios y ofrece hacer commit/push/PR

<Tip>
  ¿No te gustan los cambios? Ejecuta `git checkout .` antes de confirmar el commit para revertir todas las ediciones.
</Tip>

<Accordion title="Cómo decide Claude qué crear frente a qué actualizar">
  | Escenario | Acción |
  |----------|--------|
  | Función nueva | Crear página nueva |
  | Cambio de comportamiento | Actualizar página existente |
  | Adición pequeña | Añadir sección a página existente |
  | Capacidad importante | Página independiente nueva |
  | Obsolescencia/eliminación | Actualizar existente + añadir notas de migración |
</Accordion>

## Sesión de ejemplo

```text
User: I just added a webhook feature. Can you document it?

Claude: I'm using the update-jamdesk skill to update your documentation.

Found .jamdesk-docs-path: ../customer-docs

How should I handle changes to the docs repository?
1. Create a new feature branch (recommended)
2. Update directly on main
3. Use current branch

User: 1

Claude: Based on the webhook implementation, I plan to:
- Create: webhooks/overview.mdx
- Update: getting-started.mdx (add link)

Any changes to this plan?

User: Looks good

Claude: [Creates documentation...]

✓ jamdesk validate passed
✓ jamdesk broken-links passed

Commit these changes?
```

## Modo preview

Ejecuta con `--preview` para ver qué cambiaría sin hacer ediciones:

```text
/update-jamdesk --preview
```

El modo preview te permite:
- Comprobar qué documentación necesita actualizarse
- Revisar los cambios propuestos antes de confirmar el commit
- Ver el análisis del skill sin efectos secundarios

## Sugerencias proactivas

Después de confirmar cambios de código orientados al usuario, Claude puede sugerir:

```text
Tip: These changes affect user-facing features.
Run /update-jamdesk to update your documentation.
```

Esto aparece cuando:
- Tienes un archivo de configuración `.jamdesk-docs-path`, Y
- Tu commit incluye archivos que coinciden con patrones orientados al usuario (API, CLI, componentes)

## Instalación del skill

Instala el skill `/update-jamdesk` usando la CLI de skills:

```bash
npx skills add jamdesk/skills --skill update-jamdesk
```

Esto instala el skill en `.claude/skills/update-jamdesk/` en tu proyecto.

<Tabs>
  <Tab title="Instalación de proyecto (predeterminada)">
    Instala en el directorio de tu proyecto actual:

    ```bash
    npx skills add jamdesk/skills --skill update-jamdesk
    ```

    El skill está disponible al trabajar en este proyecto.
  </Tab>
  <Tab title="Instalación global">
    Instala en tu directorio personal para usarlo en todos los proyectos:

    ```bash
    npx skills add jamdesk/skills --skill update-jamdesk -g
    ```

    El skill está disponible en cualquier proyecto.
  </Tab>
  <Tab title="Otros agentes">
    Instala en Cursor, Codex, Windsurf u otros agentes compatibles:

    ```bash
    # Install to Cursor
    npx skills add jamdesk/skills --skill update-jamdesk -a cursor

    # Install to multiple agents
    npx skills add jamdesk/skills --skill update-jamdesk -a claude-code -a cursor
    ```

    Ejecuta `npx skills add --help` para ver todos los agentes compatibles.
  </Tab>
</Tabs>

### Listado de skills disponibles

Consulta todos los skills de Jamdesk:

```bash
npx skills add jamdesk/skills --list
```

### Actualización

Vuelve a ejecutar el comando de instalación para obtener la última versión:

```bash
npx skills add jamdesk/skills --skill update-jamdesk
```

<Note>
  Después de instalar o actualizar, reinicia Claude Code o inicia una nueva sesión para que los cambios surtan efecto.
</Note>

## Solución de problemas

<Accordion title="Skill no reconocido">
  Asegúrate de que el archivo del skill esté en `.claude/skills/update-jamdesk/SKILL.md` y reinicia tu sesión de Claude Code.
</Accordion>

<Accordion title="Archivo de configuración no encontrado">
  Crea `.jamdesk-docs-path` en la raíz de tu repositorio con la ruta a tu directorio de documentación. El skill busca desde tu directorio actual hasta la raíz del repositorio git.
</Accordion>

<Accordion title="CLI de jamdesk no instalado">
  Instálala con `npm install -g jamdesk`. El skill funcionará sin ella pero no ejecutará la validación automática.
</Accordion>
