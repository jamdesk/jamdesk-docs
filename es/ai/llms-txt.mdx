Si quieres que herramientas de IA como ChatGPT, Claude o Copilot den respuestas precisas sobre tu producto, necesitan acceso estructurado a tu documentación, no solo lo que haya quedado en sus datos de entrenamiento.

Cada sitio de Jamdesk genera `llms.txt` y `llms-full.txt` siguiendo la especificación de [llmstxt.org](https://llmstxt.org). Las herramientas de IA leen estos archivos en lugar de rastrear páginas individuales.

<Note>
  Google ahora audita `llms.txt` como parte de las [verificaciones de navegación agéntica de Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Los sitios que publican un `llms.txt` válido son más descubribles para los agentes de IA — y cada vez más, para el propio Google cuando clasifica contenido para respuestas impulsadas por IA. Jamdesk te lo proporciona gratis.
</Note>

<Tip>
  **Comprueba tu puntuación.** Descubre qué tan listo para agentes está cualquier sitio de documentación con la herramienta gratuita [AI Score](https://www.jamdesk.com/ai-score) — publicar un `llms.txt` válido es una de las primeras cosas que verifica. También hay una [extensión de Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) para calificar sitios mientras navegas.
</Tip>

## Qué genera Jamdesk

| Archivo | Contenido |
|---------|-----------|
| `llms.txt` | Títulos de páginas, descripciones y URLs (una tabla de contenidos estructurada) |
| `llms-full.txt` | Contenido completo de la documentación en un único archivo |

Jamdesk genera ambos en tiempo de build y los sirve desde el mismo CDN que tu documentación.

## Verifica tus archivos

Comprueba que tus archivos existen después de tu primer build:

<Tabs>
  <Tab title="Dominio raíz">
    Si tu documentación está en la raíz de tu dominio (p. ej., `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Subruta /docs">
    Si tu documentación está bajo `/docs` en tu sitio principal (como este sitio en `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Formato del archivo

El archivo `llms.txt` lista cada página con su título, descripción y URL, agrupadas en secciones que reflejan tu navegación:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

El archivo `llms-full.txt` contiene el contenido Markdown completo de cada página, concatenado con límites de página marcados por encabezados.

## Estructura

`llms.txt` sigue la propuesta de [llmstxt.org](https://llmstxt.org/): un título H1,
un resumen en blockquote y tus pestañas y grupos de navegación como secciones `##` de
enlaces Markdown.

Los sitios multilingües obtienen un índice por idioma. El `llms.txt` raíz lista tu
idioma predeterminado y enlaza cada índice traducido al final — por ejemplo
`/fr/llms.txt` para francés. Cada archivo de idioma enlaza de vuelta a sus hermanos.

## Directiva de agente en cada página

Cada página también lleva una nota invisible y silenciosa para lectores de pantalla para los agentes de IA
que apunta a `llms.txt`, y cada exportación Markdown comienza con un blockquote
que enlaza el índice. Los agentes que llegan a tu HTML encuentran la ruta Markdown
sin rastrear.

## Cómo se construye

- Generado en tiempo de build junto con tu HTML
- Servido desde CDN con la misma política de caché que tu documentación
- Se actualiza automáticamente en cada build
- No requiere configuración; todas las páginas se incluyen por defecto

## Desactivar llms.txt

`llms.txt` y `llms-full.txt` se publican por defecto. Para dejar de generarlos — por ejemplo, si no quieres que las herramientas de IA ingieran tu contenido — establece `seo.ai.llmsTxt` en `false` en tu `docs.json`:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

En tu próximo build, Jamdesk omite ambos archivos y las URLs `/llms.txt` y `/llms-full.txt` en producción devuelven `404`.

<Note>
  **La ingesta de IA y la indexación en buscadores son controles separados.** `seo.ai.llmsTxt` rige únicamente los archivos `llms.txt`/`llms-full.txt` que leen las herramientas de IA. No cambia cómo los motores de búsqueda indexan tu sitio — eso se controla con los [metadatos `robots` y `noindex` por página](/es/content/seo#controlar-la-indexación). Una página puede estar indexada por Google y excluida de la ingesta de IA, o viceversa.
</Note>

## Rastreadores de IA

El `robots.txt` predeterminado de Jamdesk permite todos los principales rastreadores de IA (Claude, ChatGPT, Copilot, Gemini). Tu documentación es accesible para las herramientas de IA desde el primer momento.

<Accordion title="Cómo difiere llms.txt de sitemap.xml">
  `sitemap.xml` lista URLs para que los motores de búsqueda las rastreen e indexen. No incluye ningún contenido, solo enlaces y metadatos como fechas de última modificación.

  `llms.txt` está diseñado para modelos de IA. Incluye títulos de páginas, descripciones y (en `llms-full.txt`) el contenido real. Las herramientas de IA pueden leer el archivo completo para entender tu documentación sin realizar múltiples solicitudes HTTP.
</Accordion>
