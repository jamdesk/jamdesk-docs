Si quieres que herramientas de IA como ChatGPT, Claude o Copilot den respuestas precisas sobre tu producto, necesitan acceso estructurado a tu documentación, no solo lo que haya llegado a sus datos de entrenamiento.

Cada sitio de Jamdesk genera `llms.txt` y `llms-full.txt` siguiendo la especificación de [llmstxt.org](https://llmstxt.org). Las herramientas de IA leen estos archivos en lugar de rastrear páginas individuales.

<Note>
  Google ahora audita `llms.txt` como parte de las [comprobaciones de navegación agéntica de Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Los sitios que publican un `llms.txt` válido son más descubribles para los agentes de IA — y cada vez más, para el propio Google al clasificar contenido para respuestas impulsadas por IA. Jamdesk te da esto de forma gratuita.
</Note>

<Tip>
  **Comprueba tu puntuación.** Descubre qué tan preparado para agentes está cualquier sitio de documentación con la herramienta gratuita [AI Score](https://jamdesk.com/ai-score) — publicar un `llms.txt` válido es una de las primeras cosas que comprueba. También hay una [extensión de Chrome AI Score](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) para calificar sitios mientras navegas.
</Tip>

## Qué genera Jamdesk

| Archivo | Contenido |
|------|---------|
| `llms.txt` | Títulos de página, descripciones y URLs (un índice estructurado) |
| `llms-full.txt` | Contenido completo de la documentación en un solo archivo |

Jamdesk genera ambos en el momento del build y los sirve desde el mismo CDN que tu documentación.

## Verifica tus archivos

Comprueba que tus archivos existen después de tu primer build:

<Tabs>
  <Tab title="Dominio raíz">
    Si tu documentación está en la raíz de tu dominio (por ejemplo, `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Subruta /docs">
    Si tu documentación está bajo `/docs` en tu sitio principal (como este sitio en `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Formato del archivo

El archivo `llms.txt` enumera cada página con su título, descripción y URL, agrupadas en secciones que reflejan tu navegación:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

El archivo `llms-full.txt` contiene el contenido Markdown completo de cada página, concatenado con los límites de página marcados por encabezados.

## Estructura

`llms.txt` sigue la propuesta de [llmstxt.org](https://llmstxt.org/): un título H1, un resumen en cita en bloque, y tus pestañas y grupos de navegación como secciones `##` de enlaces Markdown.

Los sitios multilingües obtienen un índice por idioma. El `llms.txt` raíz enumera tu idioma predeterminado y enlaza cada índice traducido al final — por ejemplo `/fr/llms.txt` para francés. Cada archivo de idioma enlaza de vuelta a sus hermanos.

## Directiva para agentes en cada página

Cada página también incluye una nota invisible y silenciosa para lectores de pantalla, dirigida a los agentes de IA, que apunta a `llms.txt`, y cada exportación en Markdown comienza con una cita en bloque que enlaza al índice. Los agentes que llegan a tu HTML encuentran la ruta Markdown sin necesidad de rastrear.

## Cómo se construye

- Se genera en el momento del build junto con tu HTML
- Se sirve desde el CDN con la misma política de caché que tu documentación
- Se actualiza automáticamente en cada build
- No requiere configuración; todas las páginas se incluyen por defecto

## Desactivar llms.txt

`llms.txt` y `llms-full.txt` se publican de forma predeterminada. Para dejar de generarlos — por ejemplo, si no quieres que las herramientas de IA ingieran tu contenido — define `seo.ai.llmsTxt` como `false` en tu `docs.json`:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

En tu próximo build, Jamdesk omite ambos archivos y las URLs activas `/llms.txt` y `/llms-full.txt` devuelven `404`.

<Note>
  **La ingestión de IA y la indexación en buscadores son controles independientes.** `seo.ai.llmsTxt` solo controla los archivos `llms.txt`/`llms-full.txt` que leen las herramientas de IA. No cambia cómo los motores de búsqueda indexan tu sitio — eso lo controlan los [metadatos `robots` y el `noindex` por página](/es/content/seo#controlar-la-indexación). Una página puede estar indexada por Google mientras está excluida de la ingestión de IA, o viceversa.
</Note>

## Rastreadores de IA

El `robots.txt` predeterminado de Jamdesk permite todos los rastreadores de IA principales (Claude, ChatGPT, Copilot, Gemini). Tu documentación es accesible para las herramientas de IA desde el primer momento.

<Accordion title="En qué se diferencia llms.txt de sitemap.xml">
  `sitemap.xml` enumera URLs para que los motores de búsqueda las rastreen e indexen. No incluye ningún contenido, solo enlaces y metadatos como las fechas de última modificación.

  `llms.txt` está diseñado para modelos de IA. Incluye títulos de página, descripciones y (en `llms-full.txt`) el contenido real. Las herramientas de IA pueden leer el archivo completo para entender tu documentación sin hacer múltiples solicitudes HTTP.
</Accordion>
