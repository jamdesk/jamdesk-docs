Los proyectos de Mintlify tienen una ruta de un solo comando: `jamdesk migrate` lee `mint.json`, escribe `docs.json` y reescribe tu MDX en el mismo lugar. ¿Vienes de GitBook, Docusaurus, ReadMe, Confluence o algún otro lugar? La pestaña "Otras plataformas" recorre los pasos manuales. Son breves si puedes extraer tu contenido como Markdown.

<YouTube id="DvIHWeBliK0" />

<Info>
**Exporta como Markdown primero si puedes.** Jamdesk está construido sobre MDX, así que cualquier cosa que ya esté en Markdown se integra con solo renombrar a `.mdx` y añadir unas líneas de frontmatter.
</Info>

## Elige tu ruta

<Tabs>
  <Tab title="Desde Mintlify">
    La CLI hace la mayor parte del trabajo por ti.

    <Card title="Guía de Mintlify a Jamdesk" icon="book-open" href="https://jamdesk.com/blog/migrating-from-mintlify-to-jamdesk">
      Lee el recorrido de migración con contexto, ejemplos y consejos de migración.

    ### Migración automatizada

    <Steps>
      <Step title="Instala la CLI">
        ```bash
        npm install -g jamdesk
        ```
      </Step>
      <Step title="Ejecuta la migración">
        ```bash
        jamdesk migrate
        ```

        Desde la raíz del proyecto, esto se ejecuta en un solo paso:

        - Lee `mint.json` y escribe `docs.json`
        - Renombra componentes obsoletos en archivos MDX (por ejemplo, `CardGroup` → `Columns`)
        - Mueve archivos MDX de snippet huérfanos a `/snippets/` y reescribe cada importación relativa al padre (`../foo/bar.mdx`) a una relativa a la raíz (`/snippets/foo/bar.mdx`)
        - Extrae componentes en línea que usan React hooks a `/snippets/<name>.tsx` con la directiva `'use client'`, y luego reescribe el MDX original para importar desde `/snippets/`
        - Corrige automáticamente problemas mecánicos de sintaxis MDX que harían fallar el build

        El comando es idempotente: vuelve a ejecutarlo después de hacer cambios y solo detectará lo nuevo. Cualquier cosa que no pueda manejar de forma segura se imprime como advertencia con el archivo, la importación y la acción a tomar.
      </Step>
      <Step title="Revisa y ajusta">
        Revisa el `docs.json` generado y los archivos MDX. Verifica la estructura de navegación y cualquier advertencia impresa por la CLI.
      </Step>
    </Steps>

    ### Mapeo de configuración

    La CLI convierte `mint.json` a `docs.json` automáticamente. Estas son las diferencias clave para que puedas verificar el resultado.

    **Mintlify (`mint.json`):**
    ```json
    {
      "name": "My Docs",
      "navigation": [
        { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
      ],
      "colors": { "primary": "#0D9373" },
      "topbarLinks": [{ "name": "Blog", "url": "https://example.com/blog" }]
    }
    ```

    **Jamdesk (`docs.json`):**
    ```json
    {
      "$schema": "https://jamdesk.com/docs.json",
      "name": "My Docs",
      "theme": "jam",
      "colors": { "primary": "#0D9373" },
      "navbar": {
        "links": [{ "label": "Blog", "href": "https://example.com/blog" }]
      },
      "navigation": {
        "groups": [
          { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
        ]
      }
    }
    ```

    ### Compatibilidad de componentes

    La mayoría de los componentes de Mintlify tienen equivalentes directos en Jamdesk. Unos pocos tienen nombres o sintaxis diferentes.

    | Componente de Mintlify | Equivalente en Jamdesk | Notas |
    |---|---|---|
    | `<Card>` | `<Card>` | Misma sintaxis |
    | CardGroup | `<Columns>` | Usa la prop `cols` para el número de columnas |
    | `<Columns>` | `<Columns>` | Misma sintaxis |
    | `<Accordion>` | `<Accordion>` | Misma sintaxis |
    | `<Tabs>` / `<Tab>` | `<Tabs>` / `<Tab>` | Misma sintaxis |
    | `<Steps>` / `<Step>` | `<Steps>` / `<Step>` | Misma sintaxis |
    | `<CodeGroup>` | `<CodeGroup>` | Misma sintaxis |
    | `<Tip>`, `<Note>`, `<Warning>` | `<Tip>`, `<Note>`, `<Warning>` | Misma sintaxis |
    | `<ResponseField>` | `<ParamField>` | Nombre diferente |
    | `<Snippet>` | Importación desde `/snippets/` | Enfoque diferente |

    ### Problemas comunes

    <AccordionGroup>
      <Accordion title="CardGroup se convierte en Columns">
        `jamdesk migrate` renombra `CardGroup` a `Columns` por ti en todos los archivos MDX. La prop `cols` se mantiene sin cambios. Revisa cualquier archivo que hayas editado después de ejecutar la migración.
      </Accordion>
      <Accordion title="ResponseField se convierte en ParamField">
        Renombra `<ResponseField>` a `<ParamField>`. Las props se mantienen igual.

        ```mdx
        {/* Before */}
        <ResponseField name="id" type="string" required>
          The unique identifier
        </ResponseField>

        {/* After */}
        <ParamField name="id" type="string" required>
          The unique identifier
        </ParamField>
        ```
      </Accordion>
      <Accordion title="Los snippets se reubican y reconectan automáticamente">
        Jamdesk solo resuelve importaciones `/snippets/*` relativas a la raíz. Los proyectos de Mintlify a menudo mantienen archivos MDX de snippet en cualquier parte del árbol y los importan con rutas relativas al padre (`import X from '../shared/x.mdx'`).

        `jamdesk migrate` hace tres cosas aquí en un solo paso:

        - Detecta archivos MDX que se importan como snippets pero viven fuera de `/snippets/`, y los mueve bajo `/snippets/` preservando su ruta relativa (para que los snippets con prefijo de idioma como `de/foo.mdx` no colisionen).
        - Reescribe cada importación de snippet relativa al padre en cada archivo MDX a la nueva ruta relativa a la raíz.
        - Extrae cualquier componente en línea que use React hooks a un archivo `'use client'` en `/snippets/<name>.tsx` y reemplaza la exportación en línea con una importación desde `/snippets/`.

        Si usaste el elemento JSX `<Snippet file="my-snippet.mdx" />` de Mintlify, cámbialo por una importación MDX. Ese no se reescribe automáticamente:

        ```mdx
        {/* Before (Mintlify) */}
        <Snippet file="my-snippet.mdx" />

        {/* After (Jamdesk) */}
        import MySnippet from '/snippets/my-snippet.mdx'

        <MySnippet />
        ```

        El relocalizador es conservador. Si tu proyecto no tiene navegación resuelta, o los movimientos planeados exceden `max(5, 25%)` de todos los archivos MDX, aborta sin tocar nada y te dice por qué. Vuelve a ejecutarlo después de corregir el motivo del aborto.
      </Accordion>
      <Accordion title="topbarLinks se mapea a navbar.links">
        `topbarLinks` y `topbarCtaButton` de Mintlify se mapean ambos a `navbar.links` en `docs.json`. El campo `name` se convierte en `label`, y `url` se convierte en `href`.
      </Accordion>
    </AccordionGroup>
  </Tab>

    ### Desde GitBook

    GitBook almacena el contenido como Markdown con un archivo `SUMMARY.md` para la navegación.

    <Steps>
      <Step title="Exporta tu contenido">
        Exporta tu espacio de GitBook como Markdown. Si usas la sincronización Git de GitBook, tu contenido ya está en un repositorio Git como archivos `.md`.
      </Step>
      <Step title="Convierte los archivos a MDX">
        Renombra los archivos `.md` a `.mdx` y añade frontmatter a cada archivo:

        ```mdx
        ---
        title: Your Page Title
        description: A short description of the page
        ---

        Your existing Markdown content here.
        ```
      </Step>
      <Step title="Mapea la navegación desde SUMMARY.md">
        GitBook usa `SUMMARY.md` para definir su barra lateral. Convierte esto en grupos de navegación de `docs.json`.

        **GitBook (`SUMMARY.md`):**
        ```markdown
        # Summary

        ## Getting Started
        * [Introduction](introduction.md)
        * [Quick Start](quickstart.md)

        ## API Reference
        * [Authentication](api/auth.md)
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["introduction", "quickstart"]
              },
              {
                "group": "API Reference",
                "pages": ["api/auth"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Mueve las imágenes">
        Mueve todas las imágenes a un directorio `/images` y actualiza las referencias en tus archivos MDX para usar rutas absolutas (por ejemplo, `/images/screenshot.png`).
      </Step>
      <Step title="Prueba localmente">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Desde Docusaurus

    Los proyectos de Docusaurus ya usan MDX, así que la mayor parte del contenido se transfiere directamente.

    <Steps>
      <Step title="Copia tus archivos MDX">
        Copia el contenido de tu directorio `docs/` de Docusaurus a la raíz de tu proyecto Jamdesk. Mantén tu estructura de directorios existente.
      </Step>
      <Step title="Limpia el frontmatter">
        Elimina los campos de frontmatter específicos de Docusaurus. Mantén `title` y `description`, elimina el resto.

        ```yaml
        ---
        # Remove these Docusaurus fields
        sidebar_position: 3
        sidebar_label: "Custom Label"
        slug: /custom-url
        pagination_next: null

        # Keep these
        title: Your Page Title
        description: A short description
        ---
        ```
      </Step>
      <Step title="Mapea sidebars.js a docs.json">
        Convierte la estructura de categorías de tu `sidebars.js` en grupos de navegación de `docs.json`.

        **Docusaurus (`sidebars.js`):**
        ```javascript
        module.exports = {
          docs: [
            {
              type: 'category',
              label: 'Getting Started',
              items: ['intro', 'installation'],
            },
          ],
        };
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["intro", "installation"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Reemplaza los componentes de Docusaurus">
        Cambia los componentes específicos de Docusaurus por sus equivalentes en Jamdesk.

        | Docusaurus | Jamdesk | Ejemplo |
        |---|---|---|
        | `:::note` / `:::tip` / `:::warning` | `<Note>` / `<Tip>` / `<Warning>` | Consulta [componentes de aviso](/es/components/overview) |
        | `import Tabs from '@theme/Tabs'` | `<Tabs>` (disponible globalmente) | No se necesita importación |
        | `import TabItem from '@theme/TabItem'` | `<Tab>` (disponible globalmente) | Usa `title` en lugar de `label` |
      </Step>
      <Step title="Prueba localmente">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Desde otras herramientas

    Para Confluence, Notion, ReadMe o cualquier otra plataforma, el proceso es el mismo: lleva tu contenido a Markdown y luego configura la estructura del proyecto Jamdesk.

    <Steps>
      <Step title="Exporta como Markdown">
        La mayoría de las plataformas tienen una opción de exportación a Markdown o HTML. Usa Markdown si está disponible. Para HTML, convierte a Markdown usando una herramienta como [Pandoc](https://pandoc.org/).

        ```bash
        # Convert HTML to Markdown with Pandoc
        pandoc input.html -f html -t markdown -o output.md
        ```
      </Step>
      <Step title="Crea docs.json">
        Comienza con una configuración mínima y desarrolla tu navegación a medida que añades páginas.
      </Step>
      <Step title="Convierte los archivos a MDX">
        Renombra los archivos `.md` a `.mdx` y añade frontmatter (`title`, `description`) a cada archivo.
      </Step>
      <Step title="Mueve los recursos">
        Mueve las imágenes y otros recursos a un directorio `/images`. Actualiza las referencias de archivos para usar rutas absolutas.
      </Step>
      <Step title="Prueba localmente">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>
