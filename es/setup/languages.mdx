---
title: Soporte multilingüe
description: Ofrezca documentación en varios idiomas con un selector de idioma. Cada idioma tiene su propia navegación y su propio contenido traducido.
---

Si su documentación necesita llegar a usuarios en más de un idioma, puede definir árboles de navegación independientes por configuración regional y permitir que los lectores cambien de idioma mediante un menú desplegable en la barra superior.

<Note>
  Jamdesk puede traducir sus páginas por usted: consulte [Traducción con IA](/es/setup/ai-translation). Esta página cubre la configuración de la navegación y del selector de idioma, que se aplica tanto si las traducciones provienen de Jamdesk, de sus propios traductores o de otra herramienta.
</Note>

## Configuración

Envuelva su navegación en un array `languages`, donde cada idioma contiene su propia estructura de navegación:

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "tabs": [
          {
            "tab": "Documentation",
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["introduction", "quickstart"]
              }
            ]
          }
        ]
      },
      {
        "language": "es",
        "tabs": [
          {
            "tab": "Documentación",
            "groups": [
              {
                "group": "Comenzar",
                "pages": ["es/introduction", "es/quickstart"]
              }
            ]
          }
        ]
      }
    ]
  }
}
```

## Estructura de directorios

Organice el contenido traducido en directorios con prefijo de idioma:

```bash
my-docs/
├── docs.json
├── introduction.mdx          # English (default)
├── quickstart.mdx
├── es/
│   ├── introduction.mdx      # Spanish
│   └── quickstart.mdx
├── fr/
│   ├── introduction.mdx      # French
│   └── quickstart.mdx
└── de/
    ├── introduction.mdx      # German
    └── quickstart.mdx
```

Haga referencia a las páginas en la navegación usando su ruta completa (con el prefijo de idioma):

```json
{
  "language": "es",
  "tabs": [
    {
      "tab": "Documentación",
      "groups": [
        {
          "group": "Comenzar",
          "pages": ["es/introduction", "es/quickstart"]
        }
      ]
    }
  ]
}
```

## Configuración específica por idioma

Cada idioma puede tener su propia configuración:

```json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "tabs": [...]
      },
      {
        "language": "es",
        "tabs": [...]
      }
    ]
  }
}
```

<Note>
Los banners se configuran globalmente en el nivel superior de `docs.json` (consulte [Banner](/es/config/docs-json-reference#banner)), no por idioma. Un banner se muestra en todas las páginas y en todos los idiomas.
</Note>

## Traducir las etiquetas de la barra de navegación

Los enlaces de la barra de navegación superior y el CTA principal aceptan un objeto `labels` opcional con anulaciones por idioma. Cuando el lector está en una URL con prefijo de idioma (por ejemplo, `/fr/...`), se usa la anulación correspondiente; en caso contrario, se muestra el `label` predeterminado.

```json docs.json
{
  "navbar": {
    "links": [
      {
        "label": "Blog",
        "labels": { "fr": "Blog", "es": "Blog" },
        "href": "/blog"
      },
      {
        "label": "Pricing",
        "labels": { "fr": "Tarifs", "es": "Precios" },
        "href": "/pricing"
      }
    ],
    "primary": {
      "type": "button",
      "label": "Dashboard",
      "labels": { "fr": "Tableau de bord", "es": "Panel" },
      "href": "https://app.example.com"
    }
  }
}
```

Las cadenas de interfaz integradas (el botón **Search**, el botón **Ask AI** y el menú desplegable **More** de las pestañas) se traducen automáticamente para cada idioma admitido. No necesita configurarlas.

## Idioma predeterminado

El primer idioma del array es el predeterminado. Los usuarios que llegan a su documentación ven primero este idioma. El selector de idioma les permite cambiarlo.

## Estructura de URL

Los prefijos de idioma aparecen en las URL:

| Idioma | URL |
|----------|-----|
| Inglés (predeterminado) | `docs.example.com/introduction` |
| Español | `docs.example.com/es/introduction` |
| Francés | `docs.example.com/fr/introduction` |

## Enrutamiento automático de idioma

De forma predeterminada, todos llegan a su idioma predeterminado y cambian manualmente. Active `localization.autoRedirect` para enviar a los visitantes que llegan por primera vez directamente a su propio idioma:

```json docs.json
{
  "localization": {
    "autoRedirect": true
  }
}
```

Un visitante cuyo navegador solicita francés obtiene `/fr` en lugar de `/`. Su idioma se recuerda durante un año, por lo que solo se detecta una vez, y si elige un idioma en el selector, esa elección prevalece a partir de entonces.

**Solo la raíz de su sitio se redirige alguna vez.** Todo lo demás se deja exactamente como lo pidió el visitante:

- **Una URL de idioma siempre se abre en ese idioma.** `/fr/guides/authentication` — o simplemente `/fr` — sirve francés a todos, sea lo que sea que pida su navegador. Alguien eligió esa URL, así que un enlace que pegue en un ticket o en un resultado de búsqueda abre la misma página para quien haga clic en él.
- **Los enlaces profundos nunca se redirigen.** `/guides/authentication` sirve esa página a todos.
- **Los rastreadores nunca se redirigen.** Google y otros bots siguen viendo su idioma predeterminado en la raíz, y sus etiquetas `hreflang` siguen decidiendo qué se indexa.
- **Nunca inventa un idioma.** Si el navegador del visitante solicita un idioma que usted no publica, no sucede nada: permanece en su raíz predeterminada.

<Note>
Requiere dos o más entradas en `navigation.languages`. En un sitio de un solo idioma, este ajuste no hace nada.
</Note>

<Warning>
Si coloca su documentación detrás de su propia regla de caché de Cloudflare, deje las redirecciones sin caché y no active **Ignore cache-control header and use this TTL** en estas rutas. Almacenar en caché la respuesta de la raíz hace que la redirección se active para algunos lectores y para otros no, según qué nodo se haya precalentado. La plantilla de worker que proporciona Jamdesk ya maneja esto.
</Warning>

## llms.txt para cada idioma

Cada idioma que publique obtiene su propio índice [`llms.txt`](/es/ai/llms-txt) y su propio archivo de contenido completo, para que una herramienta de IA pueda leer su documentación en un idioma sin cargar los demás:

| Idioma | Índice | Contenido completo |
|----------|-------|--------------|
| Inglés (predeterminado) | `docs.example.com/en/llms.txt` | `docs.example.com/en/llms-full.txt` |
| Español | `docs.example.com/es/llms.txt` | `docs.example.com/es/llms-full.txt` |
| Francés | `docs.example.com/fr/llms.txt` | `docs.example.com/fr/llms-full.txt` |

La raíz `docs.example.com/llms.txt` sirve el mismo archivo que `/en/llms.txt`. La raíz `docs.example.com/llms-full.txt` sigue conteniendo todos los idiomas. Un idioma obtiene sus propios archivos en cuanto tiene al menos una página. [Sitios multilingües →](/es/ai/llms-txt#sitios-multilingües)

## Traducciones parciales

No es necesario traducir todas las páginas. Si una página no existe en un idioma, los usuarios ven un mensaje alternativo con un enlace a la versión en inglés.

Para las páginas que no deben traducirse (como la referencia de la API), puede hacer referencia a la misma página en todos los idiomas:

```json
{
  "language": "es",
  "tabs": [
    {
      "tab": "API",
      "groups": [
        {
          "group": "Endpoints",
          "pages": ["api/users", "api/posts"]  // Same as English
        }
      ]
    }
  ]
}
```

## Traducir especificaciones de OpenAPI

Las páginas de endpoint controladas por OpenAPI (las que tienen una directiva de frontmatter `openapi:`) renderizan el contenido a partir de un archivo de especificación YAML o JSON. Para traducir el resumen del endpoint, las descripciones, las indicaciones de los parámetros y las descripciones de los campos del esquema, proporcione un archivo de especificación específico para el idioma junto al archivo en inglés.

### Nomenclatura de archivos

Coloque la especificación traducida junto a la fuente, insertando el código de idioma antes de la extensión:

```bash
openapi/
├── api.yaml           # English (default)
├── api.fr.yaml        # French
├── api.es.yaml        # Spanish
└── api.zh.yaml        # Simplified Chinese
```

No se requiere ninguna configuración ni cambio en `docs.json`. Jamdesk resuelve la especificación correspondiente en el momento del renderizado, según el prefijo de idioma de la URL. Una página en `/fr/api-reference/create-ticket` busca primero `api.fr.yaml`, y recurre a `api.yaml` si no existe traducción.

### Qué traducir en la especificación

Traduzca el texto legible por humanos. Mantenga cada valor estructural idéntico en todos los idiomas.

| Traducir | Mantener idéntico |
|-----------|----------------|
| `info.title`, `info.description` | `openapi` / `swagger` version, `servers[*].url` |
| `summary` y `description` por operación | Rutas de URL, métodos HTTP, `operationId`, `tags` |
| `description` por parámetro | Nombres de los parámetros (`name`), nombres de los campos, claves de propiedades del esquema |
| `description` por respuesta | Claves de códigos de estado (`"200"`, `"400"`, etc.) |
| `requestBody.description` | Valores `enum` (`low`, `normal`, `high`), `type`, `format` |
| `description` de esquema, `description` de propiedad | Punteros `$ref`, contenido de los payloads `example` / `examples` |

### Comportamiento de reserva

Si se solicita una página bajo una URL localizada pero no existe una especificación traducida, Jamdesk renderiza la especificación en inglés dentro de la estructura de la página traducida. Los usuarios ven un bloque de endpoint en idioma mixto en lugar de un error 404. Esto coincide con el comportamiento más general de las traducciones parciales para páginas MDX.

<Note>
  La vista previa local del CLI `jamdesk` (`jamdesk dev`) resuelve las especificaciones OpenAPI solo por nombre de archivo. Todavía no aplica la búsqueda por sufijo de idioma. Al iterar sobre traducciones localmente, use la URL de vista previa de producción de Jamdesk (`<project>.jamdesk.app/<lang>/...`) o reemplace temporalmente el archivo fuente. Esto solo afecta al desarrollo local; los renderizados alojados e ISR seleccionan correctamente la especificación traducida.
</Note>

### Eliminar una especificación específica de un idioma

Eliminar `api.<lang>.yaml` hace que la página recurra a la especificación en inglés en el siguiente renderizado (no se requiere una nueva compilación). Para retraducir desde cero, elimine el archivo y vuelva a generarlo. No se necesita ningún cambio en `docs.json`: la resolución de la especificación se basa únicamente en el nombre del archivo.

### Ejemplo

Fuente `openapi/tickets.yaml`:

```yaml
info:
  title: Tickets API
  description: Manage support tickets.
paths:
  /tickets:
    post:
      summary: Create a ticket
      description: Create a new support ticket.
      operationId: createTicket
```

Traducción al francés `openapi/tickets.fr.yaml`:

```yaml
info:
  title: API Tickets
  description: Gérez les tickets de support.
paths:
  /tickets:
    post:
      summary: Créer un ticket
      description: Créer un nouveau ticket de support.
      operationId: createTicket
```

Observe que `/tickets`, `post` y `createTicket` permanecen idénticos. Solo cambia el texto.

## Flujo de traducción

<Steps>
  <Step title="Comenzar con el inglés">
    Escriba primero su documentación en inglés. Esto se convierte en su fuente de verdad.
  </Step>
  <Step title="Agregar directorios de idioma">
    Cree directorios para cada idioma de destino (`es/`, `fr/`, etc.).
  </Step>
  <Step title="Traducir el contenido">
    Copie los archivos en inglés a los directorios de idioma y tradúzcalos. Mantenga los mismos nombres de archivo.
  </Step>
  <Step title="Actualizar docs.json">
    Agregue entradas de idioma a su configuración de navegación.
  </Step>
</Steps>

## Idiomas RTL

Los idiomas de derecha a izquierda, como el árabe y el hebreo, son compatibles. Jamdesk aplica automáticamente el estilo RTL cuando estos idiomas están activos.
