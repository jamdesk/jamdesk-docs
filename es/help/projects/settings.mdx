Configura el nombre de visualización de tu proyecto, el repositorio conectado, la rama, las variables de entorno, el dominio personalizado y las opciones de zona de peligro desde la página de Configuración.

Las capturas de pantalla muestran la interfaz en inglés.

## Acceder a la configuración

1. Selecciona tu proyecto desde el dashboard
2. Haz clic en **Configuración** en la barra lateral

La página de configuración está dividida en secciones para visualización, repositorio, equipo, configuración y notificaciones.

## Configuración general

### Nombre del proyecto

El nombre de visualización que aparece en tu dashboard. Esto no afecta tu documentación publicada.

### Subdominio

Tu URL predeterminada en `*.jamdesk.app`. Para cambiarlo:

1. Introduce un nuevo subdominio
2. Haz clic en **Guardar**
3. Espera la propagación DNS (normalmente es instantánea)

<Note>
Los cambios de subdominio no rompen los enlaces existentes: la URL antigua redirige a la nueva.
</Note>

## Configuración del repositorio

### Repositorio conectado

Muestra tu repositorio de GitHub vinculado. Para cambiar de repositorio, deberás eliminar el proyecto y crear uno nuevo.

### Rama

La rama de Git que dispara los builds. Normalmente `main` o `master`.

### Ruta de la documentación

Para configuraciones de monorepo, especifica la ruta a tu `docs.json` (por ejemplo, `packages/docs`).

Déjalo vacío si `docs.json` está en la raíz del repositorio.

## Configuración de build

### Variables de entorno

Establece variables en tiempo de build para tu documentación:

1. Haz clic en **Añadir variable**
2. Introduce la clave y el valor
3. Haz clic en **Guardar**

Las variables están disponibles durante el build y pueden referenciarse en tu documentación.

### Reconstruir

Haz clic en **Reconstruir** para ejecutar un build nuevo sin hacer push a GitHub. Útil después de cambiar la configuración.

## Dominio personalizado

Añade tu propio dominio en la sección **Dominios**. Consulta [Dominios personalizados](/es/deploy/custom-domains) para obtener instrucciones de configuración.

## Zona de peligro

### Eliminar proyecto

Elimina permanentemente el proyecto y todos los datos asociados:

- Historial de builds
- Datos de analítica
- Configuración del dominio personalizado

<Warning>
Esta acción no se puede deshacer. Considera transferir la titularidad si los miembros del equipo necesitan acceso continuo.
</Warning>
