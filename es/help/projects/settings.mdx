Configura el nombre visible de tu proyecto, el repositorio conectado, la rama, las variables de entorno, el dominio personalizado y las opciones de la zona de peligro desde la página de Ajustes.

## Acceder a Ajustes

1. Selecciona tu proyecto desde el dashboard
2. Haz clic en **Settings** en la barra lateral

La página de ajustes está dividida en secciones para visualización, repositorio, equipo, configuración y notificaciones.

Las capturas de pantalla muestran la interfaz en inglés.

## Ajustes generales

### Nombre del proyecto

El nombre visible que se muestra en tu dashboard. Esto no afecta tu documentación en producción.

### Subdominio

Tu URL predeterminada en `*.jamdesk.app`. Para cambiarlo:

1. Introduce un nuevo subdominio
2. Haz clic en **Save**
3. Espera la propagación del DNS (normalmente instantánea)

<Note>
Los cambios de subdominio no rompen los enlaces existentes. La URL antigua redirige a la nueva.
</Note>

## Ajustes del repositorio

### Repositorio conectado

Muestra tu repositorio de GitHub vinculado. Para cambiar de repositorio, deberás eliminar el proyecto y crear uno nuevo.

### Rama

La rama de Git que activa los builds. Normalmente `main` o `master`.

### Ruta de la documentación

Para configuraciones de monorepo, especifica la ruta a tu `docs.json` (por ejemplo, `packages/docs`).

Déjalo vacío si `docs.json` está en la raíz del repositorio.

## Ajustes de build

### Variables de entorno

Define variables en tiempo de build para tu documentación:

1. Haz clic en **Add Variable**
2. Introduce la clave y el valor
3. Haz clic en **Save**

Las variables están disponibles durante el build y pueden referenciarse en tus docs.

### Rebuild

Haz clic en **Rebuild** para activar un nuevo build sin hacer push a GitHub. Útil después de cambiar ajustes.

## Dominio personalizado

Añade tu propio dominio en la sección **Domains**. Consulta [Dominios personalizados](/es/deploy/custom-domains) para conocer las instrucciones de configuración.

## Zona de peligro

### Eliminar proyecto

Elimina permanentemente el proyecto y todos los datos asociados:

- Historial de builds
- Datos de analítica
- Configuración del dominio personalizado

<Warning>
Esta acción no se puede deshacer. Considera transferir la propiedad si los miembros del equipo necesitan acceso continuado.
</Warning>
