Preguntas comunes sobre precios, builds, dominios y funcionalidades.

## Primeros Pasos

<AccordionGroup>
  <Accordion title="¿Qué es Jamdesk?">
    Jamdesk es una plataforma de documentación que genera sitios de docs a partir de tus archivos Markdown. Escribe en MDX, sube los cambios a GitHub y tu sitio se despliega automáticamente con búsqueda, analíticas y `llms.txt` listo para IA.
  </Accordion>

  <Accordion title="¿Necesito saber programar?">
    No se requieren conocimientos de programación. Escribir en MDX es como usar un editor de texto: escribes texto plano con formato sencillo. Los componentes están disponibles si los deseas, pero son completamente opcionales.
  </Accordion>

  <Accordion title="¿Puedo probar Jamdesk gratis?">
    ¡Sí! Ofrecemos una prueba gratuita de 14 días con acceso completo a todas las funcionalidades.  
  </Accordion>

  <Accordion title="¿Qué diferencia hay entre Jamdesk y otras plataformas de documentación?">
    Jamdesk está construido sobre MDX y GitHub: tus docs son archivos de texto plano en un repositorio, sin quedar atrapados en un editor propietario. Sube cambios a GitHub y tu sitio se despliega en menos de 60 segundos sin configuración de build ni pipeline de CI/CD. Cada sitio incluye `llms.txt` y un servidor MCP de forma automática, para que herramientas de IA como Claude y ChatGPT puedan acceder directamente a tu documentación actualizada. Los visitantes también cuentan con un [asistente de chat con IA](/es/ai/chat) que responde preguntas a partir de tus docs.
  </Accordion>
</AccordionGroup>

## Builds y Despliegue

<AccordionGroup>
  <Accordion title="¿Cuánto tarda un build?">
    La mayoría de los sitios de documentación hacen el build en 30-60 segundos. Los sitios más grandes con muchas páginas pueden tardar más.
  </Accordion>

  <Accordion title="¿Puedo previsualizar los cambios antes de publicarlos?">
    ¡Sí! Usa el CLI de Jamdesk (`jamdesk dev`) para hacer un preview en local con recarga en caliente. Los cambios solo se publican cuando subes a GitHub o ejecutas `jamdesk deploy`.
  </Accordion>

  <Accordion title="¿Puedo desplegar sin GitHub?">
    Sí. Ejecuta `jamdesk deploy` desde el directorio de tu proyecto. El CLI empaqueta tus archivos, los sube y lanza un build directamente. No se necesita repositorio Git. Consulta la [guía de CLI Deploy](/es/cli/deploy) para más detalles.
  </Accordion>

  <Accordion title="¿Qué dispara un build?">
    Los builds se lanzan automáticamente cuando subes cambios a tu rama de GitHub conectada. También puedes lanzarlos manualmente desde el dashboard o con `jamdesk deploy` desde el CLI.
  </Accordion>

  <Accordion title="¿Puedo volver a una versión anterior?">
    Sí. Ve a **Deployments** en tu proyecto, encuentra el build anterior y haz clic en **Rollback**.
  </Accordion>
</AccordionGroup>

## Dominios Personalizados

<AccordionGroup>
  <Accordion title="¿Puedo usar mi propio dominio?">
    ¡Sí! Añade un dominio personalizado en **Settings** → **Domains**. Los certificados SSL se provisionan automáticamente.
  </Accordion>

  <Accordion title="¿Cuánto tarda la propagación de DNS?">
    Los cambios de DNS suelen propagarse en unas pocas horas, pero pueden tardar hasta 48 horas.
  </Accordion>

  <Accordion title="¿Puedo alojar la documentación en una subruta como /docs?">
    Sí. Usa un proxy inverso (Cloudflare, AWS, nginx) para servir Jamdesk en una subruta. Consulta [Subpath Hosting](/es/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Equipos y Colaboración

<AccordionGroup>
  <Accordion title="¿Cuántos miembros puede tener mi equipo?">
    Los planes Pro incluyen 10 miembros de equipo por proyecto.
  </Accordion>

  <Accordion title="¿Pueden los miembros del equipo editar la documentación?">
    Los miembros del equipo pueden ver los builds y lanzar nuevas compilaciones, pero la edición se realiza en tu repositorio de GitHub. Cualquier persona con acceso al repositorio puede editar los docs.
  </Accordion>

  <Accordion title="¿Cómo transfiero la propiedad de un proyecto?">
    Ve a **Settings** → **Team** → **Transfer Ownership**. El nuevo propietario debe ser ya un miembro del equipo.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="¿Dónde se almacenan mis credenciales del CLI?">
    En `~/.jamdeskrc`, un archivo JSON con permisos `0600` (solo tu usuario puede leerlo). Almacena tu token de refresco, correo electrónico e ID de usuario. Ejecuta `jamdesk logout` para borrarlo.
  </Accordion>

  <Accordion title='¿Por qué el CLI indica "session expired"?'>
    Tu token de refresco ya no es válido. Esto ocurre tras cambios de contraseña, eliminaciones de cuenta o inactividad prolongada. Ejecuta `jamdesk login` para obtener una sesión nueva.
  </Accordion>

  <Accordion title="¿Puedo usar el CLI en pipelines de CI/CD?">
    Sí, pero el inicio de sesión basado en navegador no funcionará en entornos sin interfaz gráfica. Inicia sesión en tu máquina local, luego copia `~/.jamdeskrc` a tu runner de CI. El token de refresco se encargará de la autenticación desde ahí.
  </Accordion>
</AccordionGroup>

## Contenido y Funcionalidades

<AccordionGroup>
  <Accordion title="¿Qué formatos de archivo se admiten?">
    Jamdesk admite MDX (Markdown + JSX) y archivos Markdown estándar.
  </Accordion>

  <Accordion title="¿Puedo usar componentes React personalizados?">
    Sí. Define componentes en línea directamente en MDX con `export const`, o crea componentes reutilizables en el directorio `/snippets`. Para componentes interactivos con hooks, usa archivos `.tsx` con `'use client'`. Consulta [Componentes React Personalizados](/es/content/react-components) y [Snippets](/es/content/snippets).
  </Accordion>

  <Accordion title="¿Hay un límite de páginas?">
    No hay límite estricto de páginas. La mayoría de los sitios de documentación funcionan bien con cientos de páginas.
  </Accordion>

  <Accordion title="¿Jamdesk admite múltiples idiomas?">
    Sí. Usa la propiedad `languages` en tu configuración de navegación para crear un selector de idioma. Cada idioma tiene su propia estructura de navegación y contenido. Consulta [Soporte Multilingüe](/es/setup/languages).
  </Accordion>

  <Accordion title="¿Jamdesk traduce mi contenido automáticamente?">
    No. Jamdesk no traduce el contenido por ti. Tú proporcionas los archivos MDX traducidos y Jamdesk gestiona el enrutamiento, la navegación, el selector de idioma y el estilo RTL. Incorpora las traducciones desde tu propio flujo de trabajo (traductores humanos, traducción automática o un LLM) y colócalas en directorios con prefijo de idioma (`es/`, `fr/`, etc.). Consulta [Soporte Multilingüe](/es/setup/languages) para la estructura de directorios y la configuración.
  </Accordion>
</AccordionGroup>

## Chat con IA

<AccordionGroup>
  <Accordion title="¿Mi sitio de documentación tiene chat con IA?">
    Sí. Cada sitio de Jamdesk incluye un asistente de chat integrado que responde las preguntas de los visitantes a partir de tu documentación. Está habilitado por defecto, sin configuración necesaria. Consulta [AI Chat](/es/ai/chat) para más detalles.
  </Accordion>

  <Accordion title="¿El chat con IA tiene un costo adicional?">
    No. El chat con IA está incluido en todos los planes sin costo adicional.
  </Accordion>

  <Accordion title="¿Puedo desactivar el chat con IA?">
    Sí. Establece `chat.enabled` en `false` en tu `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    El panel de chat y el atajo de teclado se eliminarán tras tu próximo build.
  </Accordion>

  <Accordion title="¿Qué datos usa el chat para responder preguntas?">
    El chat solo usa las páginas de documentación publicadas. Durante cada build, Jamdesk indexa tu contenido en una base de datos vectorial. Cuando un visitante hace una pregunta, las secciones relevantes se recuperan y se envían a Claude como contexto. La IA no puede acceder a datos fuera de tus docs.
  </Accordion>
</AccordionGroup>

## Privacidad y Acceso

<AccordionGroup>
  <Accordion title="¿Puedo tener documentación pública y privada en el mismo sitio?">
    Sí. Marca las páginas internas con `private: true` en el frontmatter, o lista sus rutas en `auth.password.private[]` en `docs.json`. Las páginas públicas siguen siendo públicas; las privadas muestran una pantalla de desbloqueo. Un proyecto, un repositorio, un build. Consulta [Control de Acceso](/es/setup/access-control) y [Protección con Contraseña](/es/setup/password-protection).
  </Accordion>

  <Accordion title="¿Cómo bloqueo todo mi sitio de documentación con una contraseña?">
    Establece `auth.password.enabled: true` en `docs.json`, sube el cambio y luego define una contraseña en **Project Settings → Password Protection** en el dashboard. Todos los visitantes verán una pantalla de desbloqueo hasta que la introduzcan. Consulta [Protección con Contraseña](/es/setup/password-protection).
  </Accordion>

  <Accordion title="¿Pueden los lectores iniciar sesión con su propia cuenta en lugar de una contraseña compartida?">
    Sí, en los planes Enterprise. Single Sign-On permite a los lectores autenticarse contra tu proveedor de identidad (Okta, Google Workspace, Azure AD, etc.) sin contraseñas compartidas, con un registro de auditoría completo y desaprovisionamiento instantáneo. Consulta [SSO](/es/setup/sso) o [contacta con ventas Enterprise](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="¿Debo dividir la documentación interna y externa en dos proyectos?">
    Normalmente no. Un único proyecto con `private: true` en las páginas internas es más sencillo: mismo repositorio, mismo build, un dashboard. Usa dos proyectos solo cuando las audiencias necesiten branding completamente separado, dominios personalizados o analíticas distintas. Consulta [Control de Acceso](/es/setup/access-control) para los patrones.
  </Accordion>

  <Accordion title="¿Cuál es la diferencia entre un editor y un lector?">
    Los **editores** escriben los docs haciendo commits de MDX en tu repositorio de GitHub conectado, por lo que cualquier persona con acceso de push a tu rama de docs puede publicar un cambio. Los **lectores** visualizan el sitio publicado: cualquiera (público), cualquiera con la contraseña (modo contraseña) o cualquiera que haya iniciado sesión a través de tu IdP (SSO). Los **miembros del equipo en el dashboard** son un concepto aparte: gestionan los builds y las analíticas, pero no crean contenido directamente. Consulta [Control de Acceso](/es/setup/access-control).
  </Accordion>
</AccordionGroup>
