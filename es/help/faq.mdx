Preguntas comunes sobre precios, builds, dominios y funciones.

## Primeros Pasos

<AccordionGroup>
  <Accordion title="¿Qué es Jamdesk?">
    Jamdesk es una plataforma de documentación que construye sitios de docs a partir de tus archivos Markdown. Escribe en MDX, sube a GitHub y tu sitio se despliega automáticamente con búsqueda, analíticas y `llms.txt` listo para AI.
  </Accordion>

  <Accordion title="¿Necesito saber programar?">
    No se requieren conocimientos de programación. Escribir en MDX es como usar un editor de texto: escribes texto plano con formato sencillo. Los componentes están disponibles si los quieres, pero son completamente opcionales.
  </Accordion>

  <Accordion title="¿Puedo probar Jamdesk gratis?">
    ¡Sí! Ofrecemos una prueba gratuita de 14 días con acceso completo a todas las funciones.
  </Accordion>

  <Accordion title="¿Cuál es la diferencia entre Jamdesk y otras plataformas de documentación?">
    Jamdesk está construido en torno a MDX y GitHub: tus docs son archivos de texto plano en un repositorio, no están bloqueados en un editor propietario. Sube a GitHub y tu sitio se despliega en menos de 60 segundos sin configuración de build ni pipeline CI/CD. Cada sitio obtiene `llms.txt` y un servidor MCP automáticamente, para que herramientas AI como Claude y ChatGPT puedan acceder a tu documentación actualizada directamente. Los visitantes también disponen de un [asistente de chat AI](/es/ai/chat) integrado que responde preguntas desde tus docs.
  </Accordion>
</AccordionGroup>

## Builds y Despliegue

<AccordionGroup>
  <Accordion title="¿Cuánto tiempo tardan los builds?">
    La mayoría de los sitios de documentación se construyen en 30-60 segundos. Los sitios más grandes con muchas páginas pueden tardar más.
  </Accordion>

  <Accordion title="¿Puedo previsualizar los cambios antes de publicar?">
    ¡Sí! Usa el CLI de Jamdesk (`jamdesk dev`) para preview en local con recarga en caliente. Los cambios solo se publican cuando subes a GitHub o ejecutas `jamdesk deploy`.
  </Accordion>

  <Accordion title="¿Puedo desplegar sin GitHub?">
    Sí. Ejecuta `jamdesk deploy` desde el directorio de tu proyecto. El CLI empaqueta tus archivos, los sube y activa un build directamente. No se requiere repositorio Git. Consulta la [guía de despliegue CLI](/es/cli/deploy) para más detalles.
  </Accordion>

  <Accordion title="¿Qué activa un build?">
    Los builds se activan automáticamente cuando subes a tu rama de GitHub conectada. También puedes activar builds manualmente desde el dashboard o con `jamdesk deploy` desde el CLI.
  </Accordion>

  <Accordion title="¿Puedo revertir a una versión anterior?">
    Sí. Ve a **Deployments** en tu proyecto, encuentra el build anterior y haz clic en **Rollback**.
  </Accordion>
</AccordionGroup>

  </Accordion>

  <Accordion title="¿Hay un plan gratuito?">
    Ofrecemos una prueba gratuita de 14 días. Después, necesitarás una suscripción Pro para continuar.
  </Accordion>

  <Accordion title="¿Qué métodos de pago aceptan?">
    Aceptamos tarjetas de crédito Visa, Mastercard, American Express y Discover.
  </Accordion>

  <Accordion title="¿Puedo obtener un reembolso?">
    Ofrecemos reembolsos dentro de los 30 días posteriores a tu primer pago. Contacta con soporte para obtener ayuda.
  </Accordion>
</AccordionGroup>

## Dominios Personalizados

<AccordionGroup>
  <Accordion title="¿Puedo usar mi propio dominio?">
    ¡Sí! Añade un dominio personalizado en **Settings** → **Domains**. Los certificados SSL se provisionan automáticamente.
  </Accordion>

  <Accordion title="¿Cuánto tarda la propagación DNS?">
    Los cambios DNS generalmente se propagan en pocas horas, pero pueden tardar hasta 48 horas.
  </Accordion>

  <Accordion title="¿Puedo alojar la documentación en una subruta como /docs?">
    Sí. Usa un proxy inverso (Cloudflare, AWS, nginx) para servir Jamdesk en una subruta. Consulta [Alojamiento en Subruta](/es/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Equipos y Colaboración

<AccordionGroup>
  <Accordion title="¿Cuántos miembros puede tener mi equipo?">
    Los planes Pro incluyen 10 miembros de equipo por proyecto.
  </Accordion>

  <Accordion title="¿Pueden los miembros del equipo editar la documentación?">
    Los miembros del equipo pueden ver los builds y activar reconstrucciones, pero la edición ocurre en tu repositorio de GitHub. Cualquier persona con acceso al repositorio puede editar los docs.
  </Accordion>

  <Accordion title="¿Cómo transfiero la propiedad del proyecto?">
    Ve a **Settings** → **Team** → **Transfer Ownership**. El nuevo propietario debe ser un miembro existente del equipo.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="¿Dónde se almacenan mis credenciales del CLI?">
    En `~/.jamdeskrc`, un archivo JSON con permisos `0600` (solo tu usuario puede leerlo). Almacena tu token de actualización, correo electrónico e ID de usuario. Ejecuta `jamdesk logout` para borrarlo.
  </Accordion>

  <Accordion title='¿Por qué el CLI dice "session expired"?'>
    Tu token de actualización ya no es válido. Esto ocurre tras cambios de contraseña, eliminaciones de cuenta o inactividad prolongada. Ejecuta `jamdesk login` para obtener una sesión nueva.
  </Accordion>

  <Accordion title="¿Puedo usar el CLI en pipelines CI/CD?">
    Sí, pero el inicio de sesión basado en navegador no funcionará en entornos sin interfaz gráfica. Inicia sesión en tu máquina local y luego copia `~/.jamdeskrc` a tu runner de CI. El token de actualización gestiona la autenticación desde ahí.
  </Accordion>
</AccordionGroup>

## Contenido y Funciones

<AccordionGroup>
  <Accordion title="¿Qué formatos de archivo se admiten?">
    Jamdesk admite MDX (Markdown + JSX) y archivos Markdown estándar.
  </Accordion>

  <Accordion title="¿Puedo usar componentes React personalizados?">
    Sí. Define componentes inline directamente en MDX con `export const`, o crea componentes reutilizables en el directorio `/snippets`. Para componentes interactivos con hooks, usa archivos `.tsx` con `'use client'`. Consulta [Componentes React Personalizados](/es/content/react-components) y [Snippets](/es/content/snippets).
  </Accordion>

  <Accordion title="¿Hay un límite de páginas?">
    No hay límite fijo de páginas. La mayoría de los sitios de documentación funcionan bien con cientos de páginas.
  </Accordion>

  <Accordion title="¿Jamdesk admite múltiples idiomas?">
    Sí. Usa la propiedad `languages` en la configuración de navegación para crear un selector de idioma. Cada idioma obtiene su propia estructura de navegación y contenido. Consulta [Soporte Multilingüe](/es/setup/languages).
  </Accordion>

  <Accordion title="¿Jamdesk traduce mi contenido automáticamente?">
    No. Jamdesk no traduce el contenido por ti. Tú proporcionas los archivos MDX traducidos y Jamdesk gestiona el enrutamiento, la navegación, el selector de idioma y el estilo RTL. Aporta las traducciones desde tu propio flujo de trabajo (traductores humanos, traducción automática o un LLM) y colócalas en directorios con prefijo de idioma (`es/`, `fr/`, etc.). Consulta [Soporte Multilingüe](/es/setup/languages) para la estructura de directorios y la configuración.
  </Accordion>
</AccordionGroup>

## Chat AI

<AccordionGroup>
  <Accordion title="¿Mi sitio de documentación tiene chat AI?">
    Sí. Cada sitio de Jamdesk incluye un asistente de chat integrado que responde las preguntas de los visitantes a partir de tu documentación. Está habilitado por defecto, sin necesidad de configuración. Consulta [Chat AI](/es/ai/chat) para más detalles.
  </Accordion>

  <Accordion title="¿El chat AI tiene un coste adicional?">
    No. El chat AI está incluido en todos los planes sin coste adicional.
  </Accordion>

  <Accordion title="¿Puedo desactivar el chat AI?">
    Sí. Establece `chat.enabled` en `false` en tu `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    El panel de chat y el atajo de teclado se eliminarán tras tu próximo build.
  </Accordion>

  <Accordion title="¿Qué datos usa el chat para responder preguntas?">
    El chat solo usa las páginas de documentación publicadas. Durante cada build, Jamdesk indexa tu contenido en una base de datos vectorial. Cuando un visitante hace una pregunta, las secciones relevantes se recuperan y se envían a Claude como contexto. La AI no puede acceder a datos fuera de tus docs.
  </Accordion>
</AccordionGroup>

## Privacidad y Acceso

<AccordionGroup>
  <Accordion title="¿Puedo tener docs públicos y privados en el mismo sitio?">
    Sí. Marca las páginas internas con `private: true` en el frontmatter, o lista sus rutas en `auth.password.private[]` en `docs.json`. Las páginas públicas permanecen públicas; las privadas muestran una pantalla de desbloqueo. Un proyecto, un repositorio, un build. Consulta [Control de Acceso](/es/setup/access-control) y [Protección con Contraseña](/es/setup/password-protection).
  </Accordion>

  <Accordion title="¿Cómo protejo con contraseña todo mi sitio de documentación?">
    Establece `auth.password.enabled: true` en `docs.json`, sube el cambio y luego define una contraseña en **Project Settings → Password Protection** en el dashboard. Cada visitante verá una pantalla de desbloqueo hasta que la introduzca. Consulta [Protección con Contraseña](/es/setup/password-protection).
  </Accordion>

  <Accordion title="¿Pueden los lectores iniciar sesión con su propia cuenta en lugar de una contraseña compartida?">
    Sí, en los planes Enterprise. Single Sign-On permite a los lectores autenticarse con tu proveedor de identidad (Okta, Google Workspace, Azure AD, etc.), sin contraseñas compartidas, con registro de auditoría completo y desaprovisionamiento instantáneo. Consulta [SSO](/es/setup/sso) o [contacta con ventas Enterprise](https://www.jamdesk.com/pricing).
  </Accordion>

  <Accordion title="¿Debo dividir la documentación interna y externa en dos proyectos?">
    Normalmente no. Un solo proyecto con `private: true` en las páginas internas es más sencillo: mismo repositorio, mismo build, un dashboard. Usa dos proyectos solo cuando las audiencias necesiten una marca, dominios personalizados o analíticas completamente separados. Consulta [Control de Acceso](/es/setup/access-control) para los patrones.
  </Accordion>

  <Accordion title="¿Cuál es la diferencia entre un editor y un lector?">
    Los **editores** escriben los docs haciendo commit de MDX en tu repositorio de GitHub conectado, por lo que cualquier persona con acceso de push a tu rama de docs puede publicar un cambio. Los **lectores** ven el sitio publicado: todos (público), cualquier persona con la contraseña (modo contraseña) o cualquier persona autenticada mediante tu IdP (SSO). Los **miembros del equipo del dashboard** son un concepto separado: gestionan los builds y las analíticas, pero no crean contenido directamente. Consulta [Control de Acceso](/es/setup/access-control).
  </Accordion>
</AccordionGroup>
