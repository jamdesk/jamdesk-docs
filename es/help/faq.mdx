Preguntas frecuentes sobre precios, builds, dominios y características.

## Empezar

<AccordionGroup>
  <Accordion title="¿Qué es Jamdesk?">
    Jamdesk es una plataforma de documentación que crea sitios de documentación a partir de tus archivos Markdown. Escribe en MDX, haz push a GitHub, y tu sitio se despliega automáticamente con búsqueda, analítica y `llms.txt` listo para IA.
  </Accordion>

  <Accordion title="¿Necesito saber programar?">
    No se requieren conocimientos de programación. Escribir en MDX es como usar un editor de texto: escribes texto plano con formato simple. Los componentes están disponibles si los quieres, pero son completamente opcionales.
  </Accordion>

  <Accordion title="¿Puedo probar Jamdesk gratis?">
    ¡Sí! Ofrecemos una prueba gratuita de 14 días con acceso completo a todas las funcionalidades.  
  </Accordion>

  <Accordion title="¿Cuál es la diferencia entre Jamdesk y otras plataformas de documentación?">
    Jamdesk está construido alrededor de MDX y GitHub: tus documentos son archivos de texto plano en un repositorio, no están bloqueados en un editor propietario. Haz push a GitHub y tu sitio se despliega en menos de 60 segundos sin configuración de build ni pipeline de CI/CD. Cada sitio obtiene automáticamente `llms.txt` y un servidor MCP, para que herramientas de IA como Claude y ChatGPT puedan acceder directamente a tu documentación actualizada. Los visitantes también cuentan con un [asistente de chat con IA](/es/ai/chat) integrado que responde preguntas de tu documentación.
  </Accordion>
</AccordionGroup>

## Builds y despliegue

<AccordionGroup>
  <Accordion title="¿Cuánto tardan los builds?">
    La mayoría de los sitios de documentación se construyen en 30-60 segundos. Los sitios más grandes con muchas páginas pueden tardar más.
  </Accordion>

  <Accordion title="¿Puedo previsualizar los cambios antes de publicar?">
    ¡Sí! Usa el CLI de Jamdesk (`jamdesk dev`) para hacer preview localmente con recarga en caliente. Los cambios solo se publican cuando haces push a GitHub o ejecutas `jamdesk deploy`.
  </Accordion>

  <Accordion title="¿Puedo desplegar sin GitHub?">
    Sí. Ejecuta `jamdesk deploy` desde el directorio de tu proyecto. El CLI empaqueta tus archivos, los sube y activa un build directamente. No se requiere repositorio Git. Consulta la [guía de CLI Deploy](/es/cli/deploy) para más detalles.
  </Accordion>

  <Accordion title="¿Qué activa un build?">
    Los builds se activan automáticamente cuando haces push a tu rama de GitHub conectada. También puedes activar builds manualmente desde el dashboard o con `jamdesk deploy` desde el CLI.
  </Accordion>

  <Accordion title="¿Puedo revertir a una versión anterior?">
    Sí. Ve a **Deployments** en tu proyecto, encuentra el build anterior y haz clic en **Rollback**.
  </Accordion>
</AccordionGroup>

  </Accordion>

  <Accordion title="¿Hay un plan gratuito?">
    Ofrecemos una prueba gratuita de 14 días. Después, necesitarás una suscripción Pro para continuar.
  </Accordion>

  <Accordion title="¿Qué métodos de pago aceptan?">
    Aceptamos tarjetas de crédito Visa, Mastercard, American Express y Discover.
  </Accordion>

  <Accordion title="¿Puedo obtener un reembolso?">
    Ofrecemos reembolsos dentro de los 30 días de tu primer pago. Contacta al soporte para obtener ayuda.
  </Accordion>
</AccordionGroup>

## Dominios personalizados

<AccordionGroup>
  <Accordion title="¿Puedo usar mi propio dominio?">
    ¡Sí! Agrega un dominio personalizado en **Settings** → **Domains**. Los certificados SSL se provisionan automáticamente.
  </Accordion>

  <Accordion title="¿Cuánto tarda la propagación DNS?">
    Los cambios DNS generalmente se propagan en unas pocas horas, pero pueden tardar hasta 48 horas.
  </Accordion>

  <Accordion title="¿Puedo alojar la documentación en una subruta como /docs?">
    Sí. Usa un proxy inverso (Cloudflare, AWS, nginx) para servir Jamdesk en una subruta. Consulta [Alojamiento en subruta](/es/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Equipos y colaboración

<AccordionGroup>
  <Accordion title="¿Cuántos miembros del equipo puedo tener?">
    Los planes Pro incluyen 10 miembros del equipo por proyecto.
  </Accordion>

  <Accordion title="¿Pueden los miembros del equipo editar la documentación?">
    Los miembros del equipo pueden ver los builds y activar reconstrucciones, pero la edición ocurre en tu repositorio de GitHub. Cualquier persona con acceso al repositorio puede editar la documentación.
  </Accordion>

  <Accordion title="¿Cómo transfiero la propiedad del proyecto?">
    Ve a **Settings** → **Team** → **Transfer Ownership**. El nuevo propietario debe ser un miembro existente del equipo.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="¿Dónde se almacenan mis credenciales del CLI?">
    En `~/.jamdeskrc`, un archivo JSON con permisos `0600` (solo tu usuario puede leerlo). Almacena tu token de actualización, correo electrónico e ID de usuario. Ejecuta `jamdesk logout` para borrarlo.
  </Accordion>

  <Accordion title='¿Por qué el CLI dice "session expired"?'>
    Tu token de actualización ya no es válido. Esto ocurre después de cambios de contraseña, eliminaciones de cuenta o inactividad prolongada. Ejecuta `jamdesk login` para obtener una sesión nueva.
  </Accordion>

  <Accordion title="¿Puedo usar el CLI en pipelines de CI/CD?">
    Sí, pero el inicio de sesión basado en navegador no funcionará en entornos sin interfaz gráfica. Inicia sesión en tu máquina local, luego copia `~/.jamdeskrc` a tu runner de CI. El token de actualización gestiona la autenticación desde allí.
  </Accordion>
</AccordionGroup>

## Contenido y características

<AccordionGroup>
  <Accordion title="¿Qué formatos de archivo se admiten?">
    Jamdesk admite MDX (Markdown + JSX) y archivos Markdown estándar.
  </Accordion>

  <Accordion title="¿Puedo usar componentes React personalizados?">
    Sí. Define componentes en línea directamente en MDX con `export const`, o crea componentes reutilizables en el directorio `/snippets`. Para componentes interactivos con hooks, usa archivos `.tsx` con `'use client'`. Consulta [Componentes React personalizados](/es/content/react-components) y [Snippets](/es/content/snippets).
  </Accordion>

  <Accordion title="¿Hay un límite de páginas?">
    No hay un límite estricto de páginas. La mayoría de los sitios de documentación funcionan bien con cientos de páginas.
  </Accordion>

  <Accordion title="¿Jamdesk admite varios idiomas?">
    Sí. Usa la propiedad `languages` en tu configuración de navegación para crear un selector de idioma. Cada idioma obtiene su propia estructura de navegación y contenido. Consulta [Soporte multilingüe](/es/setup/languages).
  </Accordion>

  <Accordion title="¿Jamdesk traduce mi contenido automáticamente?">
    No. Jamdesk no traduce el contenido por ti. Tú proporcionas los archivos MDX traducidos y Jamdesk gestiona el enrutamiento, la navegación, el selector de idioma y el estilo RTL. Aporta traducciones de tu propio flujo de trabajo (traductores humanos, traducción automática o un LLM) y colócalas en directorios con prefijo de idioma (`es/`, `fr/`, etc.). Consulta [Soporte multilingüe](/es/setup/languages) para el diseño de directorios y la configuración.
  </Accordion>
</AccordionGroup>

## Chat con IA

<AccordionGroup>
  <Accordion title="¿Mi sitio de documentación tiene chat con IA?">
    Sí. Cada sitio de Jamdesk incluye un asistente de chat integrado que responde las preguntas de los visitantes a partir de tu documentación. Está habilitado por defecto, sin configuración requerida. Consulta [Chat con IA](/es/ai/chat) para más detalles.
  </Accordion>

  <Accordion title="¿El chat con IA tiene un costo adicional?">
    No. El chat con IA está incluido en todos los planes sin costo adicional.
  </Accordion>

  <Accordion title="¿Puedo desactivar el chat con IA?">
    Sí. Establece `chat.enabled` en `false` en tu `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    El panel de chat y el atajo de teclado se eliminarán después de tu próximo build.
  </Accordion>

  <Accordion title="¿Qué datos usa el chat para responder preguntas?">
    El chat solo usa las páginas de tu documentación publicada. Durante cada build, Jamdesk indexa tu contenido en una base de datos vectorial. Cuando un visitante hace una pregunta, las secciones relevantes se recuperan y se envían a Claude como contexto. La IA no puede acceder a datos fuera de tu documentación.
  </Accordion>
</AccordionGroup>
