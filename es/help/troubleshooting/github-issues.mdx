La mayoría de los problemas de integración con GitHub se deben a permisos, fallos de webhook o discrepancias de branch.

## La organización no aparece durante la configuración

Durante el flujo de configuración inicial de la documentación, Jamdesk muestra tus organizaciones de GitHub para que elijas dónde crear el repositorio. La lista proviene de la API OAuth de GitHub, y GitHub oculta organizaciones de ella en dos casos:

- Restricciones de la app OAuth: tu organización restringe el acceso de apps de terceros (valor predeterminado de GitHub para organizaciones nuevas) y aún no ha aprobado Jamdesk.
- SAML SSO: tu organización requiere autenticación SAML antes de que la API la devuelva.

<Accordion title="Otorga acceso tú mismo (propietarios de la organización)">
  Si eres propietario de la organización, puedes aprobar Jamdesk de inmediato:

  1. Haz clic en **grant Jamdesk access on GitHub** debajo del selector de organización (o ve a GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. En **Organization access**, haz clic en **Grant** junto a tu organización
  3. De vuelta en el flujo de configuración de Jamdesk, haz clic en **refresh the list**. Tu organización aparece de inmediato

  Si eres miembro (no propietario), verás en su lugar un botón **Request**; al hacer clic se envía una solicitud de aprobación a los administradores de tu organización.
</Accordion>

<Accordion title="Pide a tu administrador de organización que apruebe Jamdesk (miembros)">
  Si eres miembro sin permisos de propietario, primero envía una solicitud de aprobación a tus administradores:

  1. Ve a GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. En **Organization access**, haz clic en **Request** junto a tu organización. Esto notifica a los administradores de tu organización
  3. Un administrador la aprueba en **Settings** → **Third-party access** → **OAuth application policy** de la organización (las solicitudes pendientes muestran un botón **Approve**)
  4. Regresa al flujo de configuración de Jamdesk y haz clic en **refresh the list**; tu organización debería aparecer ahora

  Consulta la guía de GitHub sobre [cómo aprobar apps OAuth para tu organización](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization) para ver los pasos detallados.
</Accordion>

<Accordion title="Crea en tu cuenta personal y transfiere después">
  ¿No quieres esperar la aprobación del administrador? Elige tu cuenta personal durante la configuración y transfiere el repo a tu organización después:

  1. Completa la configuración de Jamdesk usando tu cuenta personal
  2. Ve al repositorio creado en GitHub
  3. Navega a **Settings** → **General** → **Danger Zone**
  4. Haz clic en **Transfer** y selecciona tu organización como destino
  5. En Jamdesk, desconecta y vuelve a conectar el repositorio desde la página **Settings** de tu proyecto

  <Warning>
    Desconectar y volver a conectar genera una nueva URL de documentación (por ejemplo, `your-project.jamdesk.app` puede cambiar). Si ya compartiste tu URL o configuraste un dominio personalizado, contacta a [soporte](/es/help/support/contact) antes de desconectar para que podamos preservar tu configuración.
  </Warning>
</Accordion>

## El repositorio no aparece

Si tu repositorio no aparece en la lista:

<Accordion title="Verifica los permisos del repositorio">
  1. Ve a GitHub → Settings → Applications → Jamdesk
  2. Verifica que el repositorio tenga el acceso otorgado
  3. Haz clic en **Configure** para agregar más repositorios
</Accordion>

<Accordion title="Repositorios de organización">
  Para repos de organización:
  1. Un administrador de la organización debe aprobar Jamdesk
  2. Ve a la configuración de la organización → Third-party access
  3. Aprueba la solicitud de acceso de Jamdesk
</Accordion>

<Accordion title="Repositorios privados">
  Los repos privados requieren autorización de GitHub. Vuelve a autorizar Jamdesk si es necesario.
</Accordion>

## Los builds no se activan

Si los pushes no activan builds:

<Steps>
  <Step title="Verifica el webhook">
    1. Ve a tu repo en GitHub
    2. Navega a Settings → Webhooks
    3. Busca el webhook de Jamdesk
    4. Revisa "Recent Deliveries" en busca de errores
  </Step>
  <Step title="Verifica el branch">
    Los builds solo se activan en tu branch configurado. Revisa **Settings** en Jamdesk.
  </Step>
  <Step title="Vuelve a sincronizar la conexión">
    1. Ve a **Settings** del proyecto en Jamdesk
    2. Haz clic en **Re-sync GitHub**
  </Step>
</Steps>

## Errores de Webhook

### 404 Not Found

No se pudo alcanzar el endpoint del webhook.

**Solución:** Vuelve a sincronizar la conexión de GitHub en la configuración del proyecto.

### 401 Unauthorized

Falló la autenticación.

**Solución:**
1. Ve a la configuración de tu cuenta de GitHub
2. Navega a Applications → Authorized OAuth Apps
3. Revoca Jamdesk
4. Vuelve a autorizar en la configuración de Jamdesk

### 500 Server Error

Problema temporal de Jamdesk.

**Solución:** Espera unos minutos y vuelve a hacer push, o activa un rebuild manual.

## Errores de permisos

**"Repository not found"** durante el build:

- Es posible que el repositorio haya sido eliminado o renombrado
- Jamdesk puede haber perdido el acceso
- Vuelve a autorizar tu conexión de GitHub

## Problemas de branch

### Se está compilando el branch incorrecto

Verifica tu branch configurado en **Settings** → **Repository**.

### Branch renombrado o eliminado

Actualiza la configuración de tu branch para que coincida con el nuevo nombre del branch.
