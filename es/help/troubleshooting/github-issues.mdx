---

La mayoría de los problemas de integración con GitHub se deben a permisos, fallos en los webhooks o discrepancias de rama.

## La organización no aparece durante la configuración

Durante el flujo de configuración inicial de la documentación, Jamdesk muestra tus organizaciones de GitHub para que puedas elegir dónde crear el repositorio. La lista proviene de la API de OAuth de GitHub, y GitHub oculta organizaciones de ella en dos casos:

- Restricciones de la app de OAuth: tu organización restringe el acceso de aplicaciones de terceros (la opción predeterminada de GitHub para organizaciones nuevas) y todavía no ha aprobado Jamdesk.
- SAML SSO: tu organización requiere autenticación SAML antes de que la API la devuelva.

<Accordion title="Otorga el acceso tú mismo (propietarios de la organización)">
  Si eres propietario de la organización, puedes aprobar Jamdesk de inmediato, sin esperas:

  1. Haz clic en **grant Jamdesk access on GitHub** debajo del selector de organización (o ve a GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**)
  2. En **Organization access**, haz clic en **Grant** junto a tu organización
  3. De vuelta en el flujo de configuración de Jamdesk, haz clic en **refresh the list**: tu organización aparecerá de inmediato

  Si eres miembro (no propietario), en su lugar verás un botón **Request**; al hacer clic se envía una solicitud de aprobación a los administradores de tu organización.
</Accordion>

<Accordion title="Pide a tu administrador de organización que apruebe Jamdesk (miembros)">
  Si eres miembro sin privilegios de propietario, primero envía una solicitud de aprobación a tus administradores:

  1. Ve a GitHub → **Settings** → **Applications** → **Authorized OAuth Apps** → **Jamdesk**
  2. En **Organization access**, haz clic en **Request** junto a tu organización: esto notifica a los administradores de tu organización
  3. Un administrador la aprueba en **Settings** → **Third-party access** → **OAuth application policy** de la organización (las solicitudes pendientes muestran un botón **Approve**)
  4. Vuelve al flujo de configuración de Jamdesk y haz clic en **refresh the list**; tu organización debería aparecer ahora

  Consulta la guía de GitHub sobre [cómo aprobar apps de OAuth para tu organización](https://docs.github.com/en/organizations/managing-oauth-access-to-your-organizations-data/approving-oauth-apps-for-your-organization) para conocer los pasos detallados.
</Accordion>

<Accordion title="Créalo en tu cuenta personal y transfiérelo después">
  ¿No quieres esperar la aprobación del administrador? Elige tu cuenta personal durante la configuración y transfiere el repositorio a tu organización más adelante:

  1. Completa la configuración de Jamdesk usando tu cuenta personal
  2. Ve al repositorio creado en GitHub
  3. Ve a **Settings** → **General** → **Danger Zone**
  4. Haz clic en **Transfer** y selecciona tu organización como destino
  5. En Jamdesk, desconecta y vuelve a conectar el repositorio desde la página **Settings** de tu proyecto

  <Warning>
    Desconectar y volver a conectar genera una nueva URL de la documentación (por ejemplo, `your-project.jamdesk.app` puede cambiar). Si ya compartiste tu URL o configuraste un dominio personalizado, contacta a [soporte](/es/help/support/contact) antes de desconectar para que podamos conservar tu configuración.
  </Warning>
</Accordion>

## El repositorio no aparece

Si tu repositorio no aparece en la lista:

<Accordion title="Verifica los permisos del repositorio">
  1. Ve a GitHub → Settings → Applications → Jamdesk
  2. Verifica que el repositorio tenga el acceso concedido
  3. Haz clic en **Configure** para añadir más repositorios
</Accordion>

<Accordion title="Repositorios de la organización">
  Para repositorios de organización:
  1. Un administrador de la organización debe aprobar Jamdesk
  2. Ve a la configuración de la organización → Third-party access
  3. Aprueba la solicitud de acceso de Jamdesk
</Accordion>

<Accordion title="Repositorios privados">
  Los repositorios privados requieren autorización de GitHub. Vuelve a autorizar Jamdesk si es necesario.
</Accordion>

## Los builds no se activan

Si los pushes no activan builds:

<Steps>
  <Step title="Verifica el webhook">
    1. Ve a tu repositorio en GitHub
    2. Ve a Settings → Webhooks
    3. Busca el webhook de Jamdesk
    4. Revisa "Recent Deliveries" para ver si hay errores
  </Step>
  <Step title="Verifica la rama">
    Los builds solo se activan en la rama configurada. Revisa **Settings** en Jamdesk.
  </Step>
  <Step title="Vuelve a sincronizar la conexión">
    1. Ve a **Settings** del proyecto en Jamdesk
    2. Haz clic en **Re-sync GitHub**
  </Step>
</Steps>

## Errores de Webhook

### 404 No encontrado

No se pudo acceder al endpoint del webhook.

**Solución:** Vuelve a sincronizar la conexión de GitHub en la configuración del proyecto.

### 401 No autorizado

La autenticación falló.

**Solución:**
1. Ve a la configuración de tu cuenta de GitHub
2. Ve a Applications → Authorized OAuth Apps
3. Revoca Jamdesk
4. Vuelve a autorizar desde la configuración de Jamdesk

### 500 Error del servidor

Problema temporal de Jamdesk.

**Solución:** Espera unos minutos y vuelve a hacer push, o activa una reconstrucción manual.

## Errores de permisos

**"Repository not found"** durante el build:

- Es posible que el repositorio se haya eliminado o renombrado
- Es posible que Jamdesk haya perdido el acceso
- Vuelve a autorizar tu conexión de GitHub

## Problemas de rama

### El build usa la rama incorrecta

Revisa la rama configurada en **Settings** → **Repository**.

### Rama renombrada o eliminada

Actualiza la configuración de rama para que coincida con el nuevo nombre de la rama.
