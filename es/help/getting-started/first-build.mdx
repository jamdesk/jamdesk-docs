Tu primer build se inicia automáticamente cuando conectas un repositorio.

## Builds automáticos

Cuando conectas un repositorio, Jamdesk lanza un build inicial de inmediato. Cada push posterior a tu rama conectada activa un nuevo build automáticamente.

## Progreso del build

Sigue tu build en el dashboard:

<Steps>
  <Step title="En cola">
    Tu build está esperando para iniciarse. En momentos de alta demanda, puede haber una breve espera.
  </Step>
  <Step title="Clonando">
    Jamdesk obtiene el contenido de tu repositorio desde GitHub.
  </Step>
  <Step title="Validando">
    Tu `docs.json` y los archivos MDX se validan en busca de errores.
  </Step>
  <Step title="Construyendo">
    MDX se compila a HTML optimizado con resaltado de sintaxis e indexación de búsqueda.
  </Step>
  <Step title="Desplegando">
    Los archivos construidos se suben al CDN global.
  </Step>
  <Step title="En línea">
    Tu documentación está disponible en la URL de tu proyecto.
  </Step>
</Steps>

## Ver tu documentación en línea

Una vez que el build finaliza, haz clic en **Ver sitio** en el dashboard o visita `https://your-project.jamdesk.app`.

Si configuraste un dominio personalizado, tu documentación también estará disponible allí.

## Rebuild manual

¿Necesitas reconstruir sin enviar cambios?

1. Ve a tu proyecto en el [dashboard](https://dashboard.jamdesk.com)
2. Abre **Settings**
3. Haz clic en **Rebuild**

Úsalo después de cambiar variables de entorno o para forzar un build limpio.

## Si tu build falla

Los fallos de build muestran un mensaje de error en el dashboard. Causas comunes:

- Sintaxis inválida en `docs.json`
- Errores de sintaxis MDX
- Páginas ausentes referenciadas en la navegación
