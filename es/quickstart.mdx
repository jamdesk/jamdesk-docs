Despliega un sitio de documentación con solo dos archivos: `docs.json` y una página MDX.

## Requisitos previos

Necesitarás:
- Una cuenta de [GitHub](https://github.com)
- Un repositorio con tu documentación (o crearemos uno)

<Tip title="¿Migrando desde otra plataforma?">
Si vienes de Mintlify u otra plataforma de documentación, consulta la [Guía de migración](/es/setup/migration).
</Tip>

## Opción 1: Empezar desde la plantilla de inicio

La forma más rápida de comenzar. La [plantilla de inicio](https://github.com/jamdesk/starter-docs) incluye contenido de ejemplo, una especificación OpenAPI y ejemplos de cada componente para que puedas ver cómo funciona todo antes de reemplazarlo con tu propio contenido.

<Steps>
  <Step title="Crea una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un proyecto desde la plantilla">
    Haz clic en **New Project** → **From Template** → **Starter Docs**.

    Jamdesk crea un repositorio de GitHub para ti con todo preconfigurado.
  </Step>

  <Step title="Ya estás en línea">
    Tu documentación está desplegada en `your-project.jamdesk.app`. Edita los archivos MDX, haz push y el sitio se reconstruye automáticamente.
  </Step>
</Steps>

<Tip>
También puedes clonar la plantilla directamente: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

## Opción 2: Conectar un repositorio existente

¿Ya tienes un repositorio con documentación? Conéctalo directamente.

<Steps>
  <Step title="Crea una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un proyecto">
    Haz clic en **New Project** y conecta tu repositorio.

    1. Selecciona tu repositorio de GitHub
    2. Elige la rama para desplegar
    3. Jamdesk detecta tu `docs.json` automáticamente

    Para permisos del repositorio, selección de rama y rutas de documentación, consulta [Conectar GitHub](/es/setup/connecting-github).
  </Step>

  <Step title="Ya estás en línea">
    Tu documentación está desplegada en `your-project.jamdesk.app` con `llms.txt` generado automáticamente para que las herramientas de IA puedan leer tu documentación.

    Cada push a tu rama conectada dispara una reconstrucción automática.
  </Step>
</Steps>

## Qué contiene un proyecto de documentación

Un proyecto Jamdesk mínimo tiene dos cosas:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Para sitios más grandes, consulta [Estructura de directorios](/es/setup/directory-structure) para carpetas, recursos y snippets recomendados.

### docs.json

El archivo de configuración que define tu sitio:

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consulta la [Referencia de docs.json](/es/config/docs-json-reference) para ver todas las opciones de configuración.

### Páginas MDX

Páginas de documentación escritas en MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consulta [Conceptos básicos de MDX](/es/content/mdx-basics) para frontmatter, encabezados, enlaces y sintaxis de componentes.

## Desarrollo local

El CLI de Jamdesk te permite hacer preview de los cambios localmente antes de hacer push a GitHub. Esto es útil para detectar errores de sintaxis MDX antes de que lleguen a tu sitio en vivo. Para todos los métodos de instalación y comandos, consulta la [descripción general del CLI de Jamdesk](/es/cli/overview).

Preview de cambios localmente:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Abre **http://localhost:3000** para ver tu documentación con recarga en caliente.

## Agregar más páginas

1. Crea un nuevo archivo MDX:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Agrégalo a `docs.json`:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Haz push a GitHub: tu nueva página se despliega automáticamente.

Para más patrones de enlaces, incluidos anchors y cards, consulta [Enlaces y navegación](/es/content/links).

## Dominio personalizado

Agrega tu propio dominio en **Settings** → **Domains**:

1. Ingresa tu dominio (p. ej., `docs.example.com`)
2. Agrega los registros DNS que se muestran
3. Espera la verificación (hasta 48 horas)

Los certificados SSL se aprovisionan automáticamente. [Guía completa →](/es/deploy/custom-domains)
