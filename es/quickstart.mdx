Despliega un sitio de documentación con solo dos archivos: `docs.json` y una página MDX.

## Requisitos previos

Necesitarás:
- Una cuenta de [GitHub](https://github.com)
- Un repositorio con tu documentación (o crearemos uno)

<Tip title="¿Migrando desde otra plataforma?">
Si estás migrando desde Mintlify u otra plataforma de documentación, consulta la [Guía de migración](/es/setup/migration).
</Tip>

## Opción 1: Comenzar desde la plantilla inicial

La forma más rápida de empezar. La [plantilla inicial](https://github.com/jamdesk/starter-docs) incluye contenido de ejemplo, una especificación OpenAPI y ejemplos de cada componente para que puedas ver cómo funciona todo antes de reemplazarlo con tu propio contenido.

<Steps>
  <Step title="Crea una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un proyecto desde la plantilla">
    Haz clic en **Nuevo proyecto** → **Desde plantilla** → **Starter Docs**.

    Jamdesk crea un repositorio de GitHub por ti con todo preconfigurado.
  </Step>

  <Step title="Ya está en línea">
    Tu documentación está desplegada en `your-project.jamdesk.app`. Edita los archivos MDX, haz push y el sitio se reconstruye automáticamente.
  </Step>
</Steps>

<Tip>
También puedes clonar el starter directamente: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

## Opción 2: Conectar un repositorio existente

¿Ya tienes un repositorio con documentación? Conéctalo directamente.

<Steps>
  <Step title="Crea una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un proyecto">
    Haz clic en **Nuevo proyecto** y conecta tu repositorio.

    1. Selecciona tu repositorio de GitHub
    2. Elige la rama a desplegar
    3. Jamdesk detecta tu `docs.json` automáticamente
  </Step>

  <Step title="Ya está en línea">
    Tu documentación está desplegada en `your-project.jamdesk.app` con `llms.txt` generado automáticamente para que las herramientas de IA puedan leer tu documentación.

    Cada push a tu rama conectada activa una reconstrucción automática.
  </Step>
</Steps>

## Qué contiene un proyecto de documentación

Un proyecto Jamdesk mínimo tiene dos elementos:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

### docs.json

El archivo de configuración que define tu sitio:

```json docs.json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

### Páginas MDX

Páginas de documentación escritas en MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

## Desarrollo local (opcional)

El CLI de Jamdesk te permite hacer preview de los cambios localmente antes de hacer push a GitHub. Esto es útil para detectar errores de sintaxis MDX, pero no es obligatorio.

<Note>
**¿Prefieres no instalar nada?** Omite esta sección. Edita tus archivos MDX, haz commit y push—tu documentación se construirá automáticamente.
</Note>

Haz preview de los cambios localmente:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Abre **http://localhost:3000** para ver tu documentación con recarga en caliente.

## Añadir más páginas

1. Crea un nuevo archivo MDX:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Agrégalo a `docs.json`:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Haz push a GitHub: tu nueva página se despliega automáticamente.

## Dominio personalizado

Añade tu propio dominio en **Configuración** → **Dominios**:

1. Ingresa tu dominio (por ejemplo, `docs.example.com`)
2. Añade los registros DNS que se muestran
3. Espera la verificación (hasta 48 horas)

Los certificados SSL se aprovisionan automáticamente. [Guía completa →](/es/deploy/custom-domains)
