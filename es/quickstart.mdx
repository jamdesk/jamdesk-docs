**Jamdesk es un software de documentación** que publica un repositorio de GitHub con Markdown como un sitio de documentación alojado, con salida legible por IA — `llms.txt`, endpoints `.md` por página y un servidor MCP — generados automáticamente.

Despliega un sitio de documentación con solo dos archivos: `docs.json` y una página MDX. Elige el camino que se adapte a tu punto de partida.

## Requisitos previos

Necesitarás:
- Una cuenta de [GitHub](https://github.com)
- Un repositorio con tu documentación (o crearemos uno)

## Opción 1: Empezar desde la plantilla de inicio

La forma más rápida de comenzar. La [plantilla de inicio](https://github.com/jamdesk/starter-docs) incluye contenido de muestra, una especificación OpenAPI y ejemplos de cada componente para que puedas ver cómo funciona todo antes de reemplazarlo con tu propio contenido.

<Steps>
  <Step title="Crear una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crear un proyecto desde la plantilla">
    Haz clic en **Nuevo proyecto** → **Desde plantilla** → **Starter Docs**.

    Jamdesk crea un repositorio de GitHub con todo preconfigurado.
  </Step>

  <Step title="Ya estás en línea">
    Tu documentación se despliega en `tu-proyecto.jamdesk.app`. Edita los archivos MDX, haz push y el sitio se reconstruye automáticamente.
  </Step>
</Steps>

<Tip>
También puedes clonar la plantilla de inicio directamente: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

<Tip>
**¿Quieres mantener algunas páginas privadas?** Añade `private: true` al frontmatter de cualquier archivo MDX y luego establece una contraseña en **Configuración del proyecto** después del siguiente build. Consulta [Control de acceso](/es/setup/access-control) para ver las cuatro opciones (público, contraseña para todo el sitio, mixto, SSO).
</Tip>

## Opción 2: Conectar un repositorio existente

¿Ya tienes un repositorio con documentación lista para Jamdesk? Conéctalo directamente. Si estás migrando desde Mintlify u otra plataforma de documentación, primero usa la Opción 3.

<Steps>
  <Step title="Crear una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crear un proyecto">
    Haz clic en **Nuevo proyecto** y conecta tu repositorio.

    1. Selecciona tu repositorio de GitHub
    2. Elige la rama para desplegar
    3. Jamdesk detecta tu `docs.json` automáticamente

    Si tu repositorio aún no tiene `docs.json`, añade el archivo mínimo de [Qué contiene un proyecto de documentación](#qué-contiene-un-proyecto-de-documentación) antes de conectarlo.

    Para permisos del repositorio, selección de rama y rutas de documentación, consulta [Conectar GitHub](/es/setup/connecting-github).
  </Step>

  <Step title="Ya estás en línea">
    Tu documentación se despliega en `tu-proyecto.jamdesk.app` con `llms.txt` generado automáticamente para que las herramientas de IA puedan leer tu documentación.

    Cada push a tu rama conectada activa una reconstrucción automática.
  </Step>
</Steps>

## Opción 3: Migrar desde Mintlify u otra documentación

¿Ya tienes documentación en Mintlify, GitBook, Docusaurus, ReadMe, Confluence u otra plataforma? Empieza con la guía de migración antes de crear un nuevo proyecto. Cubre el comando `jamdesk migrate` para Mintlify y los pasos manuales para otras herramientas de documentación. Después de la migración, conecta el repositorio migrado usando la [Opción 2](#opción-2-conectar-un-repositorio-existente).

## Qué contiene un proyecto de documentación

Un proyecto Jamdesk mínimo tiene dos elementos:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Para sitios más grandes, consulta [Estructura de directorios](/es/setup/directory-structure) para carpetas recomendadas, recursos y snippets.

### docs.json

El archivo de configuración que define tu sitio:

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consulta la [Referencia de docs.json](/es/config/docs-json-reference) para todas las opciones de configuración.

### Páginas MDX

Páginas de documentación escritas en MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consulta [Conceptos básicos de MDX](/es/content/mdx-basics) para frontmatter, encabezados, enlaces y sintaxis de componentes.

## Desarrollo local

El CLI de Jamdesk te permite obtener un preview de los cambios localmente antes de hacer push a GitHub. Esto es útil para detectar errores de sintaxis MDX antes de que lleguen a tu sitio en vivo. Para todos los métodos de instalación y comandos, consulta la [descripción general del CLI de Jamdesk](https://jamdesk.com/docs/cli/overview).

Obtén un preview de los cambios localmente:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Abre **http://localhost:3000** para ver tu documentación con recarga en caliente.

## Añadir más páginas

1. Crea un nuevo archivo MDX:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Añádelo a `docs.json`:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Haz push a GitHub: tu nueva página se despliega automáticamente.

Para más patrones de enlace, incluyendo anclas y tarjetas, consulta [Enlaces y navegación](/es/content/links).

## Dominio personalizado

Añade tu propio dominio en **Configuración** → **Dominios**:

1. Introduce tu dominio (p. ej., `docs.ejemplo.com`)
2. Añade los registros DNS que se muestran
3. Espera la verificación (hasta 48 horas)

Los certificados SSL se proporcionan automáticamente. [Guía completa →](/es/deploy/custom-domains)
