Despliega un sitio de documentación con solo dos archivos: `docs.json` y una página MDX. Elige la opción que corresponda a tu punto de partida.

## Requisitos previos

Necesitarás:
- Una cuenta de [GitHub](https://github.com)
- Un repositorio con tu documentación (o crearemos uno)

## Opción 1: Comenzar desde la plantilla de inicio

La forma más rápida de empezar. La [plantilla de inicio](https://github.com/jamdesk/starter-docs) incluye contenido de ejemplo, una especificación OpenAPI y ejemplos de cada componente para que puedas ver cómo funciona todo antes de reemplazarlo con tu propio contenido.

<Steps>
  <Step title="Crea una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un proyecto desde la plantilla">
    Haz clic en **New Project** → **From Template** → **Starter Docs**.

    Jamdesk crea un repositorio de GitHub por ti con todo preconfigurado.
  </Step>

  <Step title="Tu sitio está en línea">
    Tu documentación se despliega en `your-project.jamdesk.app`. Edita los archivos MDX, haz push y el sitio se reconstruye automáticamente.
  </Step>
</Steps>

<Tip>
También puedes clonar la plantilla directamente: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

## Opción 2: Conectar un repositorio existente

¿Ya tienes un repositorio con documentación lista para Jamdesk? Conéctalo directamente. Si estás migrando desde Mintlify u otra plataforma de documentación, usa primero la Opción 3.

<Steps>
  <Step title="Crea una cuenta de Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un proyecto">
    Haz clic en **New Project** y conecta tu repositorio.

    1. Selecciona tu repositorio de GitHub
    2. Elige la rama a desplegar
    3. Jamdesk detecta tu `docs.json` automáticamente

    Si tu repositorio aún no tiene `docs.json`, agrega el archivo mínimo de [¿Qué contiene un proyecto de documentación?](#qu-contiene-un-proyecto-de-documentaci-n) antes de conectarlo.

    Para permisos de repositorio, selección de rama y rutas de documentación, consulta [Conectar GitHub](/es/setup/connecting-github).
  </Step>

  <Step title="Tu sitio está en línea">
    Tu documentación se despliega en `your-project.jamdesk.app` con `llms.txt` generado automáticamente para que las herramientas de AI puedan leer tu documentación.

    Cada push a tu rama conectada activa una reconstrucción automática.
  </Step>
</Steps>

## Opción 3: Migrar desde Mintlify u otra plataforma de documentación

¿Ya tienes documentación en Mintlify, GitBook, Docusaurus, ReadMe, Confluence u otra plataforma? Comienza con la guía de migración antes de crear un nuevo proyecto. Cubre el comando `jamdesk migrate` para Mintlify y los pasos manuales para otras herramientas de documentación. Tras la migración, conecta el repositorio migrado usando la [Opción 2](#opci-n-2-conectar-un-repositorio-existente).

## ¿Qué contiene un proyecto de documentación?

Un proyecto Jamdesk mínimo tiene dos elementos:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Para sitios más grandes, consulta [Estructura de directorios](/es/setup/directory-structure) para ver las carpetas, recursos y snippets recomendados.

### docs.json

El archivo de configuración que define tu sitio:

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consulta la [Referencia de docs.json](/es/config/docs-json-reference) para todas las opciones de configuración.

### Páginas MDX

Páginas de documentación escritas en MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consulta [Conceptos básicos de MDX](/es/content/mdx-basics) para frontmatter, encabezados, enlaces y sintaxis de componentes.

## Desarrollo local

El CLI de Jamdesk te permite hacer preview de los cambios localmente antes de hacer push a GitHub. Esto es útil para detectar errores de sintaxis MDX antes de que lleguen a tu sitio en producción. Para todos los métodos de instalación y comandos, consulta la [descripción general del CLI de Jamdesk](https://jamdesk.com/docs/cli/overview).

Haz preview de los cambios localmente:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Abre **http://localhost:3000** para ver tu documentación con hot reload.

## Agregar más páginas

1. Crea un nuevo archivo MDX:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Agrégalo a `docs.json`:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Haz push a GitHub: tu nueva página se despliega automáticamente.

Para más patrones de enlaces, incluyendo anclas y tarjetas, consulta [Enlaces y navegación](/es/content/links).

## Dominio personalizado

Agrega tu propio dominio en **Settings** → **Domains**:

1. Ingresa tu dominio (p. ej., `docs.example.com`)
2. Agrega los registros DNS indicados
3. Espera la verificación (hasta 48 horas)

Los certificados SSL se aprovisionan automáticamente. [Guía completa →](/es/deploy/custom-domains)
