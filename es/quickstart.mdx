Despliega un sitio de documentación con solo dos archivos: `docs.json` y una página MDX. Elige la ruta que se ajuste a tu punto de partida.

## Requisitos Previos

Necesitarás:
- Una cuenta de [GitHub](https://github.com)
- Un repositorio con tu documentación (o crearemos uno)

## Opción 1: Empieza desde la Plantilla de Inicio

La forma más rápida de comenzar. La [plantilla de inicio](https://github.com/jamdesk/starter-docs) incluye contenido de ejemplo, una especificación OpenAPI y ejemplos de cada componente para que puedas ver cómo funcionan las cosas antes de reemplazarlos con tu propio contenido.

<Steps>
  <Step title="Crea una Cuenta en Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un Proyecto desde la Plantilla">
    Haz clic en **Nuevo Proyecto** → **Desde Plantilla** → **Starter Docs**.

    Jamdesk crea un repositorio de GitHub por ti con todo preconfigurado.
  </Step>

  <Step title="Ya Estás en Vivo">
    Tu documentación está desplegada en `your-project.jamdesk.app`. Edita los archivos MDX, haz push y el sitio se reconstruye automáticamente.
  </Step>
</Steps>

<Tip>
También puedes clonar la plantilla directamente: `git clone https://github.com/jamdesk/starter-docs.git my-docs`
</Tip>

<Tip>
**¿Quieres mantener algunas páginas privadas?** Añade `private: true` al frontmatter de cualquier archivo MDX, luego establece una contraseña en **Project Settings** tras el próximo build. Consulta [Control de Acceso](/es/setup/access-control) para las cuatro opciones (público, contraseña para todo el sitio, mixto, SSO).
</Tip>

## Opción 2: Conecta un Repositorio Existente

¿Ya tienes un repositorio con documentación lista para Jamdesk? Conéctalo directamente. Si estás migrando desde Mintlify u otra plataforma de documentación, usa primero la Opción 3.

<Steps>
  <Step title="Crea una Cuenta en Jamdesk">
    Ve a [dashboard.jamdesk.com](https://dashboard.jamdesk.com) y regístrate con GitHub.
  </Step>

  <Step title="Crea un Proyecto">
    Haz clic en **Nuevo Proyecto** y conecta tu repositorio.

    1. Selecciona tu repositorio de GitHub
    2. Elige la rama para desplegar
    3. Jamdesk detecta tu `docs.json` automáticamente

    Si tu repositorio todavía no tiene `docs.json`, añade el archivo mínimo de [¿Qué hay en un Proyecto de Documentación?](#qu-hay-en-un-proyecto-de-documentaci-n) antes de conectarlo.

    Para permisos del repositorio, selección de rama y rutas de documentación, consulta [Conectar GitHub](/es/setup/connecting-github).
  </Step>

  <Step title="Ya Estás en Vivo">
    Tu documentación está desplegada en `your-project.jamdesk.app` con `llms.txt` generado automáticamente para que las herramientas de AI puedan leer tu documentación.

    Cada push a tu rama conectada activa una reconstrucción automática.
  </Step>
</Steps>

## Opción 3: Migra desde Mintlify u Otra Documentación

¿Ya tienes documentación en Mintlify, GitBook, Docusaurus, ReadMe, Confluence u otra plataforma? Empieza con la guía de migración antes de crear un nuevo proyecto. Cubre el comando `jamdesk migrate` para Mintlify y los pasos manuales para otras herramientas de documentación. Después de la migración, conecta el repositorio migrado usando la [Opción 2](#opci-n-2-conecta-un-repositorio-existente).

## ¿Qué hay en un Proyecto de Documentación?

Un proyecto mínimo de Jamdesk tiene dos cosas:

```bash
my-docs/
├── docs.json           # Configuration
└── introduction.mdx    # Your first page
```

Para sitios más grandes, consulta [Estructura de Directorios](/es/setup/directory-structure) para carpetas recomendadas, recursos y snippets.

### docs.json

El archivo de configuración que define tu sitio:

```json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

Consulta la [Referencia de docs.json](/es/config/docs-json-reference) para todas las opciones de configuración.

### Páginas MDX

Páginas de documentación escritas en MDX:

```mdx
---
title: Introduction
description: Welcome to the docs
---

# Welcome

This is your first documentation page.
```

Consulta [MDX Básico](/es/content/mdx-basics) para frontmatter, encabezados, enlaces y sintaxis de componentes.

## Desarrollo Local

El CLI de Jamdesk te permite previsualizar cambios localmente antes de hacer push a GitHub. Esto es útil para detectar errores de sintaxis MDX antes de que lleguen a tu sitio en vivo. Para todos los métodos de instalación y comandos, consulta la [descripción general del CLI de Jamdesk](https://jamdesk.com/docs/cli/overview).

Previsualiza cambios localmente:

<Tabs>
  <Tab title="npm">
    ```bash
    npm install -g jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="Homebrew">
    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    cd my-docs
    jamdesk dev
    ```
  </Tab>
  <Tab title="npx">
    ```bash
    cd my-docs
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Abre **http://localhost:3000** para ver tu documentación con recarga en caliente.

## Añadir Más Páginas

1. Crea un nuevo archivo MDX:

```mdx
---
title: Getting Started
description: Learn the basics
---

Your content here...
```

2. Añádelo a `docs.json`:

```json docs.json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction", "getting-started"]
      }
    ]
  }
}
```

3. Haz push a GitHub: tu nueva página se despliega automáticamente.

Para más patrones de enlaces, incluyendo anclas y tarjetas, consulta [Enlaces y Navegación](/es/content/links).

## Dominio Personalizado

Añade tu propio dominio en **Configuración** → **Dominios**:

1. Ingresa tu dominio (p. ej., `docs.example.com`)
2. Añade los registros DNS indicados
3. Espera la verificación (hasta 48 horas)

Los certificados SSL se provisionan automáticamente. [Guía completa →](/es/deploy/custom-domains)
