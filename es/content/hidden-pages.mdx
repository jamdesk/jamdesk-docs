---
title: Páginas ocultas
description: Excluye páginas de la barra lateral y la búsqueda sin eliminarlas. Usa frontmatter, docs.json o los controles de seo para gestionar la visibilidad.
---

Algunas páginas no deben aparecer en la barra lateral pública: borradores, manuales internos, guías obsoletas que aún necesitas enlazar. Las páginas ocultas siguen siendo accesibles mediante URL directa, pero desaparecen de la navegación, la búsqueda, tu sitemap y el contexto de IA que se envía a los LLM.

## Ocultar una sola página

Añade `hidden: true` al frontmatter de la página:

```mdx
---
title: Internal handbook
hidden: true
---
```

La página se renderiza con normalidad cuando alguien visita su URL, pero Jamdesk:

- La elimina de la barra lateral
- Añade `<meta name="robots" content="noindex, follow">` para que los motores de búsqueda la omitan
- La excluye de `sitemap.xml`, `llms.txt`, `llms-full.txt` y la búsqueda en el sitio

## Ocultar un grupo o tab completo

Establece `"hidden": true` en un grupo o tab en `docs.json`:

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Public",
        "groups": [{ "group": "Guides", "pages": ["intro", "quickstart"] }]
      },
      {
        "tab": "Internal",
        "hidden": true,
        "groups": [{ "group": "Runbooks", "pages": ["oncall", "postmortems"] }]
      }
    ]
  }
}
```

Toda página bajo el nodo oculto hereda la regla. La misma marca funciona en `tabs`, `groups`, `anchors`, `dropdowns`, `products`, `languages` y `versions`.

## Mantener páginas ocultas en la búsqueda

Si quieres que un tab o grupo oculto no aparezca en la barra lateral pero siga indexado para la búsqueda del sitio, las respuestas de IA y el sitemap, añade `"searchable": true`:

```json
{
  "tab": "Internal",
  "hidden": true,
  "searchable": true,
  "groups": [{ "group": "Runbooks", "pages": ["oncall"] }]
}
```

El `hidden: true` del frontmatter en una página hija sigue teniendo prioridad. `searchable` solo reactiva a los descendientes que no lo hayan desactivado por su cuenta.

## Controles a nivel de proyecto

Ambas marcas viven bajo `seo` en `docs.json`:

| Marca | Predeterminado | Efecto |
|---|---|---|
| `seo.indexing` | `"navigable"` | Solo las páginas listadas en tu navegación aparecen en los artefactos. Configúralo como `"all"` para incluir todos los archivos MDX de tu repositorio. |
| `seo.indexHiddenPages` | `false` | Configúralo como `true` para incluir las páginas con `hidden: true` en el sitemap, llms.txt y la búsqueda, y eliminar la etiqueta noindex automática. |

Ejemplo:

```json
{
  "seo": {
    "indexing": "all"
  }
}
```

## Referencia rápida

| Escenario | Frontmatter | docs.json | Visible en la barra lateral | URL directa | En el sitemap |
|---|---|---|---|---|---|
| Página normal | — | listada | Sí | Sí | Sí |
| Oculta vía frontmatter | `hidden: true` | listada | No | Sí | No |
| Página fuera de la navegación (huérfana) | — | omitida | No | Sí | No |
| Grupo oculto | — | `hidden: true` en el grupo | No | Sí | No |
| Grupo oculto y buscable | — | `hidden: true, searchable: true` | No | Sí | Sí |
| El proyecto opta por indexar todo | — | cualquiera | Igual que arriba | Sí | Sí |

## Cuándo usar cada opción

- **Borradores y previsualizaciones:** frontmatter `hidden: true` en páginas individuales
- **Secciones internas** para un equipo pequeño: un grupo o tab oculto
- **Documentación de cumplimiento** que debe ser pública pero no promocionada: grupo oculto con `searchable: true`
- **Indexación de todo el repositorio** solo para el contexto de IA: `seo.indexing: "all"`

Las páginas ocultas no son control de acceso. Cualquiera que tenga la URL puede leerlas. Para un control de acceso real, consulta [Protección con contraseña](/es/setup/password-protection).
