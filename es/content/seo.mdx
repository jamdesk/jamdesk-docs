## Optimizar tu contenido

### Escribe un frontmatter efectivo

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Coloca las palabras clave al inicio.** "Authentication setup" es mejor que "How to set up authentication."
</Tip>

### Títulos de página

- Mantén menos de 60 caracteres para evitar truncamiento en los resultados de búsqueda
- Incluye tu palabra clave principal cerca del inicio
- Haz que cada título sea único en toda tu documentación

### Descripciones

- Apunta a entre 120 y 160 caracteres
- Resume lo que el lector aprenderá
- Incluye palabras clave relevantes de forma natural

<Note>
**Descripción generada automáticamente.** Cuando `description` no está en el frontmatter, Jamdesk extrae automáticamente el primer párrafo de texto de tu página (hasta 155 caracteres). Se omiten encabezados, bloques de código, imágenes y componentes MDX. Esto se usa para `<meta name="description">`, Open Graph y tarjetas de Twitter. Escribir una descripción explícita sigue siendo recomendable para obtener los mejores resultados.
</Note>

## Controlar la indexación

### Configuración global del sitio

En tu `docs.json`, configura el comportamiento predeterminado de los robots:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Control por página

Sobrescribe la indexación de páginas específicas en el frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Usa `noindex` para:
- Páginas en borrador o en progreso
- Documentación interna
- Contenido obsoleto que conservas como referencia

## URLs canónicas

Si tu documentación es accesible desde múltiples URLs, define una canónica:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

También puedes establecer una base canónica global en `docs.json`. Jamdesk agrega la ruta de cada página, de modo que cada una obtiene su propia URL canónica correcta:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Previsualizaciones sociales y Open Graph

Jamdesk genera automáticamente una tarjeta social de 1200×630 píxeles con tu marca para cada página. Puedes sobrescribir cualquier etiqueta social en el frontmatter. Puedes usar **claves planas de nivel superior** (estilo Mintlify) o un bloque **`seo:`** anidado. Ambas opciones funcionan; cuando la misma clave se define de las dos formas, el valor plano de nivel superior tiene prioridad.

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  og:title: API Reference — Acme
  og:image: /images/api-social-card.png
  twitter:card: summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Etiquetas compatibles

| Grupo | Etiquetas |
|-------|-----------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artículo | `og:type: article` con `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, etiquetas de app-card |
| Otros | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color`, además de cualquier etiqueta personalizada (coloca las etiquetas personalizadas bajo `seo:`) |

<Note>
**Dimensiones de imagen OG personalizada.** Cuando defines un `og:image` personalizado, incluye también `og:image:width`
y `og:image:height` para que los rastreadores la rendericen correctamente. La tarjeta generada automáticamente siempre mide
1200×630.
</Note>

<Note>
**Etiquetas personalizadas.** Las metaetiquetas arbitrarias (p. ej., `x-pinterest`) se emiten como `<meta name="...">`.
Colócalas bajo el bloque `seo:`. Solo las claves SEO reconocidas se procesan cuando se colocan de forma plana.
</Note>

### Imagen predeterminada para todo el sitio

Define una imagen social de reserva para todas las páginas en `docs.json`. Cualquier página que tenga su propio `og:image` la sobrescribirá:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Previsualiza antes de publicar.** Tras un build, pega la URL de la página en una herramienta de preview Open Graph (como [opengraph.xyz](https://www.opengraph.xyz)) para verificar cómo se renderiza la tarjeta en cada plataforma.
</Tip>

## Sitemap y robots.txt

Cada sitio de Jamdesk genera `sitemap.xml` y `robots.txt` automáticamente en cada build.

| Archivo | Propósito |
|---------|-----------|
| `sitemap.xml` | Lista todas las páginas con fechas de última modificación para los motores de búsqueda |
| `robots.txt` | Permite el acceso a todos los rastreadores y los dirige al sitemap |

### Dónde encontrarlos

Las URLs dependen de si tu documentación está en un dominio raíz o bajo una subruta `/docs`:

<Tabs>
  <Tab title="Dominio raíz">
    Si tu documentación está en la raíz de tu dominio (p. ej., `docs.acme.com` o `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Subruta /docs">
    Si tu documentación está bajo `/docs` en tu sitio principal (como este sitio en `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### Qué se incluye en el sitemap

- Todas las páginas publicadas (excepto las que tienen frontmatter `noindex` o `hidden`)
- Fechas de última modificación del frontmatter cuando están disponibles
- Frecuencia de cambio semanal

### Excluir páginas del sitemap

Agrega `noindex` al frontmatter para excluir una página tanto del sitemap como de los motores de búsqueda:

```yaml
---
title: Internal Notes
noindex: true
---
```

Las páginas con `hidden: true` también se excluyen automáticamente.

## Datos estructurados JSON-LD

Cada página incluye automáticamente datos estructurados de [schema.org](https://schema.org) como una etiqueta `<script type="application/ld+json">` con dos esquemas:

- `WebSite`: el nombre, URL y descripción de tu sitio (desde `docs.json`).
- `BreadcrumbList`: la ruta de navegación desde Inicio hasta la página actual, derivada de tu configuración de `navigation`.

No se requiere ninguna configuración. Los motores de búsqueda utilizan estos datos para resultados enriquecidos, como rutas de navegación en los listados de búsqueda.

<Tip>
**Verifica tu marcado.** Pega cualquier URL de página en la [herramienta de prueba de resultados enriquecidos de Google](https://search.google.com/test/rich-results) para confirmar que los datos estructurados se detectan correctamente.
</Tip>

## IndexNow

Tras cada build, Jamdesk envía automáticamente las URLs de las páginas modificadas a [IndexNow](https://www.indexnow.org) para una indexación más rápida. Esto notifica a Bing, Yandex y otros motores de búsqueda participantes sobre los cambios en tu contenido sin esperar su próximo ciclo de rastreo.

- Se activa después de cada build exitoso
- Solo envía las páginas que realmente han cambiado
- No bloquea el proceso, por lo que nunca retrasa tu build
- No requiere ninguna configuración
