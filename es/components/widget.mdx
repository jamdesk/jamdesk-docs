---
title: Widget
description: Incrusta un widget What's New en tu documentación con el componente Widget MDX: un botón que abre tu changelog en un modal, sin etiqueta script.
---

`<Widget>` agrega un disparador What's New directamente en una página de documentación. Al hacer clic, tu changelog de Jamdesk se abre en el mismo modal que tus clientes ven cuando [incrustas el widget en tu app](/es/development/embed-page) — excepto que aquí escribes una etiqueta MDX en lugar de un `<script>`, y la página resuelve tu sitio automáticamente.

## Inicio rápido

```mdx
<Widget />
```

Esto renderiza un botón que abre `/changelog` (la ruta por defecto) en un modal. Si tu changelog está en otro lugar, establece `page` con su ruta real, o el modal abrirá un 404. (El changelog propio de Jamdesk está en `/reference/changelog`, por ejemplo.)

```mdx
<Widget page="/reference/changelog" label="What's new" />
```

<Note>
`<Widget>` resuelve tu origen canónico `*.jamdesk.app` por su cuenta, por lo que funciona igual tanto si tu documentación está en un subdominio `jamdesk.app` como en un dominio personalizado. El modal siempre carga desde el subdominio, que es el único origen que puede renderizar la vista incrustada.
</Note>

## Props

| Prop | Type | Default | Purpose |
|------|------|---------|---------|
| `page` | string | `/changelog` | Ruta de documentación que abre el modal. |
| `label` | string | `What's new` | Texto del botón disparador. |
| `theme` | `auto` \| `light` \| `dark` | `auto` | Esquema de color del modal. |
| `trigger` | CSS selector | _(none)_ | Vincula a tu propio elemento en lugar de renderizar un botón. |
| `width` / `height` | CSS length | `560px` / `680px` | Tamaño del modal. |
| `radius` | CSS length | `12px` | Radio de las esquinas del modal. |
| `unread` | boolean | `true` | Muestra el punto de no leído. Establece `false` para ocultarlo. |
| `unreadColor` | hex / CSS color | `#e5484d` | Color del punto de no leído. |
| `project` | string | derived | Sobreescribe la clave "seen" almacenada. |

<Note>
Cuando estableces `trigger`, asegúrate de que el selector coincida con un elemento que ya esté en la página. Si no coincide con nada, el widget recurre a su propio lanzador flotante en la esquina en lugar de no hacer nada.
</Note>

El estado "seen" del punto de no leído se almacena por navegador **y por origen** (la página donde corre el widget), por lo que el estado visto de un visitante en tu documentación y en tu app se rastrean por separado. No se sincronizan. Para un botón de demo, establece `unread={false}` para omitir el punto por completo.

## Ejemplo en vivo

<Widget page="/reference/changelog" label="See what's new in Jamdesk" unread={false} />

<Note>
Este botón abre el modal en el sitio de documentación desplegado, donde `<Widget>` se vincula a tu origen canónico `*.jamdesk.app`. En el preview local de `jamdesk dev` no hay un origen publicado desde donde cargar el modal, por lo que el disparador no puede abrirlo — en su lugar muestra un texto "Live preview" junto al botón. Despliega la página (o ábrela en tu sitio en vivo) para probar la versión real.
</Note>
