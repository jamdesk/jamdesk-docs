Jamdesk puede cargar un widget de chat en vivo en cada página de tu sitio de documentación. Agrega el bloque del proveedor bajo `integrations` en `docs.json`, y Jamdesk inyecta el script del widget por ti.

<Info>
Cada valor se verifica contra un formato estricto antes de que Jamdesk cargue el widget. Un valor con el formato incorrecto se omite silenciosamente y nunca se renderiza — sin página de error, sin etiqueta de script rota.
</Info>

## Configurar desde el Dashboard

La forma más rápida de configurar cualquiera de los dos: **Dashboard → Integrations**. Elige la tarjeta del proveedor, pega su ID, y Jamdesk hace un commit del bloque `docs.json` por ti y activa un rebuild (solo proyectos conectados a GitHub). Las secciones a continuación son para editar `docs.json` directamente, o para proyectos solo de CLI.

## Intercom

**Formato:** El ID de la aplicación tiene entre 6 y 16 letras o números.

<Info>
Encuentra tu ID de aplicación en **Settings → Installation → Web** en Intercom — es el ID de tu espacio de trabajo.
</Info>

```json docs.json
{
  "integrations": {
    "intercom": {
      "appId": "abc12345"
    }
  }
}
```

## Front Chat

**Formato:** El ID de chat tiene entre 8 y 64 caracteres hexadecimales en minúsculas (`0-9`, `a-f`).

```json docs.json
{
  "integrations": {
    "frontchat": {
      "snippetId": "3f8a2e1c9b6d4a7f"
    }
  }
}
```

## Control de consentimiento

Ambos widgets respetan `integrations.cookies`. Cuando está configurado, el script de chat no se carga hasta que tu banner de consentimiento registra la aprobación — consulta [Consentimiento de cookies](/es/integrations/cookie-consent) para la configuración completa. Sin él, el widget se carga para cada visitante al cargar la página.
