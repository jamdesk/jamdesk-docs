Agrega Plausible Analytics a tu sitio de documentación para obtener datos de tráfico sin cookies ni scripts de seguimiento que siguen a los usuarios por la web.

<Info>
Plausible es de código abierto, pesa menos de 1 KB y no requiere un banner de consentimiento de cookies en la mayoría de las jurisdicciones. Es una buena opción si quieres analítica simple y conforme con el RGPD.
</Info>

Si necesitas gestión de consentimiento (o también usas GA, GTM o Crisp), consulta [Cookie Consent](/es/integrations/cookie-consent).

Hay dos formas de agregar Plausible. Elige la que coincida con tu configuración:

| Configuración | Cuándo usarla | Campo |
|-------|----------|-------|
| **Estándar** | Estás en el plan gratuito de Plausible, o en un plan de pago sin necesidad de proxy | `domain` |
| **Script proxy** | Estás en un plan de pago y quieres evitar los bloqueadores de anuncios | `scriptUrl` |

## Configuración estándar (domain)

Esta es la opción predeterminada para la mayoría de los usuarios. Registra tu sitio en Plausible y pasa el dominio.

<Steps>

### Regístrate en Plausible

Crea una cuenta en [Plausible Analytics](https://plausible.io/) y agrega el dominio de tu sitio de documentación (por ejemplo, `docs.example.com`).

### Agrega el dominio a docs.json

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "domain": "docs.example.com"
    }
  }
}
```

Usa exactamente el dominio que registraste: `docs.example.com`, no `www.docs.example.com`.

</Steps>

### Servidor autoalojado

Si ejecutas la [Community Edition](https://github.com/plausible/community-edition), agrega el campo `server` para que el script y la API de eventos apunten a tu instancia:

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "domain": "docs.example.com",
      "server": "https://analytics.example.com"
    }
  }
}
```

`server` solo funciona con `domain`. Los scripts proxy manejan su propio enrutamiento.

## Configuración de script proxy (scriptUrl)

Los planes de pago de Plausible ofrecen scripts proxy con un nombre de archivo único (como `pa-XXXXX.js`). Estos evitan la mayoría de los bloqueadores de anuncios porque la URL del script no coincide con las listas de filtros comunes.

<Steps>

### Obtén la URL de tu script proxy

En la configuración de tu sitio en Plausible, busca la sección de script proxy y copia la URL completa. Se ve así: `https://plausible.io/js/pa-XXXXX.js`.

### Agrega la URL del script a docs.json

```json docs.json
{
  "name": "My Docs",
  "integrations": {
    "plausible": {
      "scriptUrl": "https://plausible.io/js/pa-XXXXX.js"
    }
  }
}
```

No se necesitan los campos `domain` ni `server`. La identidad de tu sitio está integrada en el ID del script, y el CDN de Plausible gestiona el enrutamiento internamente.

</Steps>

## Verificar la instalación

Después de agregar la integración:

1. Activa un rebuild de tu documentación
2. Visita tu sitio de documentación en vivo
3. Revisa tu dashboard de Plausible. Tu visita debería aparecer en unos segundos.
4. O abre DevTools, ve a la pestaña Network y busca una solicitud a `plausible.io/js/script.js` (estándar) o tu script `pa-XXXXX.js` (proxy)

<Note>
Plausible muestra datos en tiempo real, sin el período de espera de Google Analytics.
</Note>

## Referencia de configuración

| Campo | Tipo | Obligatorio | Descripción |
|-------|------|----------|-------------|
| `domain` | `string` | Uno de `domain` o `scriptUrl` | El dominio de tu sitio tal como está registrado en Plausible. Se usa como el atributo `data-domain` en la etiqueta del script. |
| `scriptUrl` | `string` | Uno de `domain` o `scriptUrl` | URL completa a un script proxy de pago de Plausible (`pa-XXXXX.js`). La identidad del sitio está integrada en el script, por lo que no se necesita el campo domain. |
| `server` | `string` | No | URL de un servidor de Plausible autoalojado. Solo se usa con `domain`, no con `scriptUrl`. |

## Solución de problemas

<Accordion title="No se ven datos en Plausible">
  Nueve de cada diez veces, es el dominio. Debe coincidir exactamente con lo que registraste en Plausible (es decir, `docs.example.com`, no `www.docs.example.com`).

  Si el dominio parece correcto:

  1. Reconstruye tu documentación. Los cambios de configuración solo tienen efecto después de un nuevo build.
  2. Revisa si hay bloqueadores de anuncios. Algunas extensiones del navegador bloquean scripts de analítica, incluido Plausible. Si esa es la causa, cambia a la [configuración de script proxy](#configuración-de-script-proxy-scripturl).
  3. Inspecciona el código fuente de la página en busca de una etiqueta `<script>` con `data-domain` (estándar) o el nombre de tu archivo `pa-XXXXX.js` (proxy). Si no está ahí, la configuración no se aplicó.
</Accordion>

<Accordion title="Usar un dominio personalizado o subdirectorio">
  Registra el dominio que tus usuarios realmente visitan. Si tu documentación está en `docs.example.com`, usa eso como el `domain`, no tu dominio raíz.
</Accordion>

<Accordion title="Script bloqueado por bloqueadores de anuncios">
  Cambia a la [configuración de script proxy](#configuración-de-script-proxy-scripturl). El nombre de archivo único evita la mayoría de las listas de filtros de bloqueadores de anuncios. El autoalojamiento logra el mismo resultado, ya que el script se carga desde tu propio dominio.
</Accordion>

<Accordion title="Cuándo usar domain vs scriptUrl">
  Usa `domain` si estás en el plan gratuito o no te preocupan los bloqueadores de anuncios. Usa `scriptUrl` si estás en un plan de pago y quieres la máxima cobertura de seguimiento. No configures ambos; elige uno.
</Accordion>
