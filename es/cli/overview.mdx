El CLI de Jamdesk te permite previsualizar la documentación localmente, validar la configuración, detectar enlaces rotos y migrar desde otras plataformas. Es de código abierto bajo la [Apache License 2.0](https://github.com/jamdesk/jamdesk-cli).

## Instalación

<Tabs>
  <Tab title="npm (Recomendado)">
    Instala de forma global desde [npm](https://www.npmjs.com/package/jamdesk) para usar `jamdesk` desde cualquier lugar:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Instala mediante Homebrew en macOS o Linux:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Instala mediante un script:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Actualizar o desinstalar:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Instala mediante un script:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Actualizar o desinstalar:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Ejecuta sin instalar:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Después de instalar, verifica que funciona:

```bash
jamdesk --version
```

### Requisitos

- **Node.js** v20.0.0 o superior
- **npm** v8 o superior (recomendado)

## Inicio rápido

<Steps>
  <Step title="Crear un proyecto">
    Crea un nuevo proyecto de documentación:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Iniciar el servidor de desarrollo">
    Ejecuta el servidor de desarrollo local con recarga en caliente:

    ```bash
    jamdesk dev
    ```

    Tu documentación estará disponible en **http://localhost:3000/docs**
  </Step>
  <Step title="Validar antes de desplegar">
    Revisa errores de configuración, enlaces rotos y ortografía:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Comandos

Ejecuta `jamdesk <command> --help` para obtener información detallada sobre cualquier comando.

### Desarrollo

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Inicia el servidor de desarrollo local con recarga en caliente.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Características:**
  - Validación automática al iniciar (esquema de docs.json, sintaxis de MDX y especificaciones de OpenAPI referenciadas: una especificación no válida detiene el servidor para que la detectes antes de desplegar)
  - Recarga en caliente al cambiar archivos MDX
  - Reconstrucción automática de la navegación al cambiar docs.json
  - CSS personalizado (`style.css`) recargado al actualizar el navegador
  - Funcionalidad de búsqueda completa
  - Todos los temas y componentes disponibles

  **Opciones:**

  | Flag | Descripción |
  |------|-------------|
  | `-p, --port <port>` | Puerto en el que se ejecuta (por defecto: 3000) |
  | `-v, --verbose` | Habilita la salida detallada |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Crea un nuevo proyecto de documentación.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Esto crea un nuevo proyecto con:
  - Archivo de configuración `docs.json`
  - Páginas MDX de ejemplo
  - Estructura de carpetas recomendada
</Accordion>

### Autenticación

<Accordion title="jamdesk login" icon="right-to-bracket">

  ```bash

  ```

  Abre el dashboard de Jamdesk en tu navegador para la autenticación. Las credenciales se almacenan localmente en `~/.jamdeskrc`.

### Validación

<Accordion title="jamdesk validate" icon="check">
  Valida la configuración de tu `docs.json`, la sintaxis de MDX y las especificaciones de OpenAPI.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Comprueba:**
  - Sintaxis JSON válida en docs.json
  - Campos obligatorios (name, navigation)
  - Valores de tema válidos
  - Errores de sintaxis MDX (por ejemplo, caracteres `<` sin escapar)
  - Validación de especificaciones de OpenAPI (si está configurado)
  - Cumplimiento del esquema

  **Opciones:**

  | Flag | Descripción |
  |------|-------------|
  | `--skip-mdx` | Omite la validación de sintaxis MDX |
  | `-v, --verbose` | Muestra la salida detallada de la validación |

  Ejecuta esto antes de desplegar para detectar errores a tiempo.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Escanea tu documentación en busca de enlaces internos rotos.

  ```bash
  jamdesk broken-links
  ```

  **Ejemplo de salida:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Detecta enlaces a páginas faltantes y errores tipográficos. Consulta [Enlaces y Navegación](/es/content/links#cómo-se-detectan-los-enlaces-internos) para más detalles.
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Corrige automáticamente las advertencias de enlaces internos rotos que tienen un destino inequívoco. Gestiona dos categorías:
  - **Anclas con errores tipográficos** — un fragmento como `#instalation` que claramente debería ser `#installation`
  - **Desfase de anclas entre idiomas** — una página traducida cambió el nombre de sus encabezados, pero los enlaces de ese idioma aún apuntan al fragmento original en inglés

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **Ejemplo de salida de dry-run:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  Una corrección solo se escribe cuando el ancla corregida corresponde a un encabezado real en la página de destino. Los casos ambiguos se dejan para revisión manual.

  **Opciones:**

  | Flag | Descripción |
  |------|-------------|
  | `--dry-run` | Muestra una vista previa de las correcciones planeadas sin escribir archivos |
  | `-y, --yes` | Aplica las correcciones sin solicitar confirmación |
  | `--types <list>` | Tipos de advertencia a corregir, separados por comas (por defecto: todos los admitidos) |

  <Card title="Guía para corregir enlaces rotos" icon="wrench" href="/es/cli/fix-broken-links">
    Recorrido paso a paso: previsualizar, aplicar, revisar y confirmar
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Revisa tu documentación en busca de errores ortográficos.

  ```bash
  jamdesk spellcheck
  ```

  **Ejemplo de salida:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Usa un diccionario en inglés con más de 150 términos técnicos incorporados (API, GraphQL, Kubernetes, React, etc.) para que la jerga común no se marque como error. Omite bloques de código, código en línea, frontmatter, JSX, URLs y rutas de archivo. Actualmente solo en inglés; el soporte de diccionarios multilingüe está previsto.

  **Opciones:**

  | Flag | Descripción |
  |------|-------------|
  | `--fix` | Corrige errores ortográficos de forma interactiva o los agrega a la lista de ignorados |
  | `--json` | Genera la salida en JSON (para pipelines de CI) |
  | `-v, --verbose` | Muestra cada archivo a medida que se verifica |

  **El modo de corrección interactivo (`--fix`)** recorre cada palabra mal escrita única:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** reemplaza la palabra con una sugerencia en todos los archivos (seguro para el texto: no modifica bloques de código ni atributos JSX). Se muestran hasta 3 sugerencias, con la mejor coincidencia marcada como recomendada.
  - **Ignore** agrega la palabra a `spellcheck.ignore` en tu docs.json para que no se vuelva a marcar
  - **Skip** no hace nada en esta ejecución

  Los cambios se muestran en una vista previa y se confirman antes de aplicarse.

  **Lista de ignorados personalizada:** agrega términos específicos del proyecto a tu docs.json:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  El nombre de tu proyecto definido en `docs.json` se ignora automáticamente.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Valida un único archivo de especificación de OpenAPI.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Valida:**
  - Sintaxis YAML/JSON válida
  - Cumplimiento del esquema OpenAPI 3.x
  - Definiciones de endpoint
  - Las referencias `$ref` se resuelven correctamente
</Accordion>

<Note>
  **Tus especificaciones de OpenAPI se validan en tres lugares.** `jamdesk dev` se detiene al iniciar si una especificación referenciada no es válida, y `jamdesk validate` / `jamdesk openapi-check` verifican las especificaciones bajo demanda. Cuando despliegas, el build en la nube también valida tus especificaciones referenciadas, pero ahí se trata de una **advertencia no fatal**: el resto de tu documentación se publica igualmente y se te indica exactamente qué está mal (un error de análisis con línea y columna, una `$ref` sin resolver o un operationId duplicado) por correo electrónico y en la lista de builds del dashboard. Corrige la especificación y vuelve a hacer push para resolverlo.
</Note>

### Gestión de archivos

<Accordion title="jamdesk rename" icon="file-pen">
  Cambia el nombre de una página y actualiza automáticamente todas las referencias.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Esto hará lo siguiente:**
  - Cambiar el nombre del archivo
  - Actualizar la navegación en docs.json
  - Actualizar los enlaces en todos los demás archivos MDX
  - Actualizar las referencias a snippets

  Usa esto en lugar de renombrar manualmente para mantener todas las referencias sincronizadas.
</Accordion>

### Migración

<Accordion title="jamdesk migrate" icon="right-left">
  Migra documentación de Mintlify a Jamdesk.

  ```bash
  jamdesk migrate
  ```

  Detecta tu configuración de Mintlify y la convierte al formato de Jamdesk. En el mismo proceso, renombra componentes obsoletos (por ejemplo, `CardGroup` → `Columns`), reubica archivos MDX de snippets huérfanos en `/snippets/` y reescribe los imports relativos al directorio padre, extrae componentes en línea que usan React hooks a `/snippets/<name>.tsx` con `'use client'`, y corrige automáticamente problemas mecánicos de sintaxis MDX. Es idempotente: puedes volver a ejecutarlo con seguridad.

  </Card>
</Accordion>

### Despliegue

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Sube tu documentación e inicia un build directamente desde la terminal.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  El progreso se muestra en vivo a medida que se completa cada fase del build. También está disponible como `jamdesk push`.

  | Flag | Descripción |
  |------|-------------|
  | `--detach` | Encola y sale de inmediato |
  | `--full-rebuild` | Fuerza una reconstrucción completa (sin caché) |
  | `--project <id>` | Despliega en un proyecto específico |
  | `--allow-empty` | Permite desplegar con cero páginas de contenido `.mdx` (rechazado por defecto) |

  <Card title="Guía de despliegue del CLI" icon="cloud-arrow-up" href="/es/cli/deploy">
    Pipeline completo de despliegue, fases del build, referencia de errores y solución de problemas
  </Card>
</Accordion>

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  Genera y despliega un Cloudflare Worker que hace de proxy de `/docs` en tu propio dominio hacia tu sitio de Jamdesk.

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --skip-deploy --yes
  ```

  Interactivo de forma predeterminada: verifica Wrangler, comprueba tu cuenta de Cloudflare, detecta automáticamente tu slug a partir de `docs.json`, genera los archivos del Worker y, opcionalmente, despliega.

  | Flag | Descripción |
  |------|-------------|
  | `--slug <slug>` | Slug del proyecto de Jamdesk |
  | `--domain <domain>` | Dominio de destino (por ejemplo, `example.com`) |
  | `--path <path>` | Prefijo de ruta (por defecto: `/docs`) |
  | `--output-dir <dir>` | Directorio de salida (por defecto: `cloudflare-worker/`) |
  | `--skip-deploy` | Genera solo los archivos, sin desplegar |
  | `--force` | Sobrescribe el directorio existente sin preguntar |
  | `--yes` | Omite todas las solicitudes de confirmación (modo CI) |

    Configuración del Worker, patrones de rutas y configuración de caché

### Mantenimiento

<Accordion title="jamdesk doctor" icon="stethoscope">
  Verifica tu entorno y diagnostica problemas.

  ```bash
  jamdesk doctor
  ```

  **Comprueba:**
  - Versión de Node.js (requiere v20+)
  - Versión de npm
  - Que docs.json exista y sea válido
  - Estado de la caché en ~/.jamdesk
  - Permisos de escritura

  Ejecuta esto si tienes problemas con el CLI.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Limpia el directorio de caché ~/.jamdesk.

  ```bash
  jamdesk clean
  ```

  Esto elimina las dependencias en caché y los artefactos de build. Úsalo para:
  - Liberar espacio en disco
  - Solucionar problemas de caché corrupta
  - Forzar una instalación limpia de dependencias

  Las dependencias se reinstalarán en el siguiente `jamdesk dev`.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Actualiza el CLI a la última versión.

  ```bash
  jamdesk update
  ```

  También puedes actualizar manualmente:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Configuración

Crea `~/.jamdeskrc` para establecer opciones predeterminadas:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Opción | Tipo | Valor por defecto | Descripción |
|--------|------|---------|-------------|
| `defaultPort` | number | 3000 | Puerto por defecto del servidor de desarrollo |
| `verbose` | boolean | false | Habilita la salida detallada por defecto |
| `checkUpdates` | boolean | true | Comprueba actualizaciones del CLI al iniciar |

## Solución de problemas

<AccordionGroup>
  <Accordion title="Errores de sintaxis MDX">
    Los archivos MDX se procesan como JSX, por lo que ciertos caracteres tienen un significado especial.

    **Problema común:** el carácter `<` se interpreta como el inicio de una etiqueta JSX.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Soluciones:**
    - Usa `&lt;` para el signo menor-que literal: `Values &lt;50% are low`
    - Reescribe para evitar el carácter: `"Below 50%"` en lugar de `"<50%"`
    - Ejecuta `jamdesk validate` para obtener mensajes de error detallados con números de línea
  </Accordion>

  <Accordion title="docs.json no encontrado">
    Asegúrate de estar en un directorio que contenga un archivo `docs.json`.

    **Soluciones:**
    - Ejecuta `jamdesk init` para crear un nuevo proyecto
    - Comprueba que estás en el directorio correcto
    - Verifica que el archivo se llame exactamente `docs.json` (no `doc.json` ni similar)
  </Accordion>

  <Accordion title="El servidor de desarrollo no inicia">
    El servidor de desarrollo puede fallar al iniciar por varios motivos.

    **Prueba estos pasos:**
    1. Ejecuta `jamdesk doctor` para verificar tu entorno
    2. Ejecuta `jamdesk clean` para limpiar la caché
    3. Usa `jamdesk dev --verbose` para obtener una salida de error detallada
    4. Comprueba que Node.js v20+ esté instalado: `node --version`
  </Accordion>

  <Accordion title="Primera ejecución lenta">
    La primera ejecución instala las dependencias en `~/.jamdesk/node_modules`.

    Esto es normal y solo ocurre una vez. Las siguientes ejecuciones serán mucho más rápidas.
  </Accordion>

  <Accordion title="Puerto ya en uso">
    Otro proceso está usando el puerto predeterminado.

    **Soluciones:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Errores de permiso denegado">
    Es posible que no tengas permisos de escritura en el directorio de caché.

    **Soluciones:**
    1. Comprueba los permisos de `~/.jamdesk`: `ls -la ~/.jamdesk`
    2. Corrige la propiedad: `sudo chown -R $(whoami) ~/.jamdesk`
    3. Ejecuta `jamdesk clean` y vuelve a intentarlo
  </Accordion>
</AccordionGroup>
