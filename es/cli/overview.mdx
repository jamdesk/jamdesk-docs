title: Descripción general del CLI
description: >-
  Aprende a instalar el CLI de Jamdesk y usar comandos como dev, validate y
  login para gestionar tu documentación localmente.
---

El CLI de Jamdesk te permite previsualizar documentación localmente, validar la configuración, verificar enlaces rotos y migrar desde otras plataformas. Es de código abierto bajo la [Licencia Apache 2.0](https://github.com/jamdesk/jamdesk-cli).

## Instalación

<Tabs>
  <Tab title="npm (Recomendado)">
    Instala globalmente desde [npm](https://www.npmjs.com/package/jamdesk) para usar `jamdesk` desde cualquier lugar:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Instala mediante Homebrew en macOS o Linux:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Instala mediante script:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Actualizar o desinstalar:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Instala mediante script:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Actualizar o desinstalar:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Ejecuta sin instalar:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Después de instalar, verifica que funciona:

```bash
jamdesk --version
```

### Requisitos

- **Node.js** v20.0.0 o superior
- **npm** v8 o superior (recomendado)

## Inicio rápido

<Steps>
  <Step title="Crear un proyecto">
    Crea un nuevo proyecto de documentación:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Iniciar el servidor de desarrollo">
    Ejecuta el servidor de desarrollo local con recarga en caliente:

    ```bash
    jamdesk dev
    ```

    Tu documentación estará disponible en **http://localhost:3000/docs**
  </Step>
  <Step title="Validar antes de desplegar">
    Comprueba errores de configuración, enlaces rotos y ortografía:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Comandos

Ejecuta `jamdesk <comando> --help` para obtener información detallada sobre cualquier comando.

### Desarrollo

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Inicia el servidor de desarrollo local con recarga en caliente.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Características:**
  - Validación automática al iniciar (esquema de docs.json, sintaxis MDX y specs OpenAPI referenciadas — una spec inválida detiene el servidor para que lo detectes antes de desplegar)
  - Recarga en caliente al modificar archivos MDX
  - Reconstrucción automática de la navegación al cambiar docs.json
  - CSS personalizado (`style.css`) recargado al actualizar el navegador
  - Funcionalidad de búsqueda completa
  - Todos los temas y componentes disponibles

  **Opciones:**

  | Opción | Descripción |
  |--------|-------------|
  | `-p, --port <port>` | Puerto en el que ejecutar (por defecto: 3000) |
  | `-v, --verbose` | Activar salida detallada |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Crea un nuevo proyecto de documentación.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Esto crea un nuevo proyecto con:
  - Archivo de configuración `docs.json`
  - Páginas MDX de ejemplo
  - Estructura de carpetas recomendada
</Accordion>

### Autenticación

<Accordion title="jamdesk login" icon="right-to-bracket">
  Inicia sesión en Jamdesk a través de tu navegador. Requerido antes de desplegar.

  ```bash
  jamdesk login
  ```

  Abre el dashboard de Jamdesk en tu navegador para la autenticación. Las credenciales se almacenan localmente en `~/.jamdeskrc`.

  <Card title="Guía de autenticación" icon="key" href="/es/cli/authentication">

  </Card>
</Accordion>

<Accordion title="jamdesk logout" icon="right-from-bracket">
  Elimina las credenciales almacenadas.

  ```bash
  jamdesk logout
  ```
</Accordion>

<Accordion title="jamdesk whoami" icon="circle-user">

  ```bash
  jamdesk whoami
  ```
</Accordion>

### Validación

<Accordion title="jamdesk validate" icon="check">
  Valida tu configuración de `docs.json`, la sintaxis MDX y los specs OpenAPI.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Comprueba:**
  - Sintaxis JSON válida en docs.json
  - Campos obligatorios (name, navigation)
  - Valores de tema válidos
  - Errores de sintaxis MDX (p. ej., caracteres `<` sin escapar)
  - Validación de spec OpenAPI (si está configurado)
  - Cumplimiento del esquema

  **Opciones:**

  | Opción | Descripción |
  |--------|-------------|
  | `--skip-mdx` | Omitir la validación de sintaxis MDX |
  | `-v, --verbose` | Mostrar salida de validación detallada |

  Ejecuta esto antes de desplegar para detectar errores con anticipación.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Analiza tu documentación en busca de enlaces internos rotos.

  ```bash
  jamdesk broken-links
  ```

  **Ejemplo de salida:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Detecta enlaces a páginas inexistentes y erratas. Consulta [Enlaces y navegación](/es/content/links#cómo-se-detectan-los-enlaces-internos) para más detalles.
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Corrige automáticamente los avisos de enlaces internos rotos que tienen un destino no ambiguo. Gestiona dos categorías:
  - **Anclas con erratas** — un fragmento como `#instalation` que claramente debería ser `#installation`
  - **Desfase de ancla entre idiomas** — una página traducida renombró sus títulos, pero los enlaces en ese idioma siguen apuntando al fragmento inglés antiguo

  ```bash
  # Previsualizar los cambios sin tocar ningún archivo
  jamdesk fix --dry-run

  # Aplicar las correcciones (solicita confirmación)
  jamdesk fix
  ```

  **Ejemplo de salida en modo previsualización:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  Una corrección solo se escribe cuando el ancla corregida apunta a un título real en la página de destino. Los casos ambiguos se dejan para revisión manual.

  **Opciones:**

  | Opción | Descripción |
  |------|-------------|
  | `--dry-run` | Previsualizar las correcciones planificadas sin escribir ningún archivo |
  | `-y, --yes` | Aplicar las correcciones sin solicitar confirmación |
  | `--types <lista>` | Tipos de advertencias a corregir separados por comas (por defecto: todos los compatibles) |

  <Card title="Guía para corregir enlaces rotos" icon="wrench" href="/es/cli/fix-broken-links">
    Procedimiento paso a paso: previsualizar, aplicar, revisar y confirmar
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Comprueba tu documentación en busca de errores ortográficos.

  ```bash
  jamdesk spellcheck
  ```

  **Ejemplo de salida:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Utiliza un diccionario en inglés con más de 150 términos técnicos integrados (API, GraphQL, Kubernetes, React, etc.) para que el vocabulario técnico habitual no genere alertas. Omite bloques de código, código en línea, frontmatter, JSX, URLs y rutas de archivo. Actualmente solo en inglés — el soporte para diccionarios en varios idiomas está planificado.

  **Opciones:**

  | Opción | Descripción |
  |--------|-------------|
  | `--fix` | Corregir errores ortográficos de forma interactiva o añadir a la lista de ignorados |
  | `--json` | Salida en formato JSON (para pipelines de CI) |
  | `-v, --verbose` | Mostrar cada archivo a medida que se verifica |

  **Modo de corrección interactivo (`--fix`)** recorre cada palabra mal escrita de forma única:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** reemplaza la palabra con una sugerencia en todos los archivos (seguro para prosa — no modifica bloques de código ni atributos JSX). Se muestran hasta 3 sugerencias, con la mejor coincidencia marcada como recomendada.
  - **Ignore** añade la palabra a `spellcheck.ignore` en tu docs.json para que no vuelva a marcarse
  - **Skip** no hace nada en esta ejecución

  Los cambios se previsualizan y confirman antes de aplicarse.

  **Lista de ignorados personalizada:** Añade términos específicos del proyecto a tu docs.json:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  El nombre de tu proyecto en `docs.json` se ignora automáticamente.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Valida un único archivo de especificación OpenAPI.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Valida:**
  - Sintaxis YAML/JSON válida
  - Cumplimiento del esquema OpenAPI 3.x
  - Definiciones de endpoint
  - Las referencias `$ref` se resuelven correctamente
</Accordion>

<Note>
  **Tus specs OpenAPI se validan en tres lugares.** `jamdesk dev` se detiene al iniciar si una spec referenciada es inválida, y `jamdesk validate` / `jamdesk openapi-check` comprueban las specs bajo demanda. Al desplegar, el build en la nube también valida tus specs referenciadas — pero allí es una **advertencia no fatal**: el resto de tu documentación se publica igualmente, y se te indica exactamente qué está mal (un error de análisis con línea y columna, una referencia `$ref` no resuelta, o un `operationId` duplicado) por correo electrónico y en la lista de builds del dashboard. Corrige la spec y vuelve a enviar para resolverlo.
</Note>

### Gestión de archivos

<Accordion title="jamdesk rename" icon="file-pen">
  Renombra una página y actualiza automáticamente todas las referencias.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Esto hará:**
  - Renombrar el archivo
  - Actualizar la navegación de docs.json
  - Actualizar los enlaces en todos los demás archivos MDX
  - Actualizar las referencias de snippets

  Usa esto en lugar de renombrar manualmente para mantener todas las referencias sincronizadas.
</Accordion>

### Migración

<Accordion title="jamdesk migrate" icon="right-left">
  Migra documentación de Mintlify a Jamdesk.

  ```bash
  jamdesk migrate
  ```

  Detecta tu configuración de Mintlify y la convierte al formato de Jamdesk. En el mismo proceso renombra componentes obsoletos (p. ej., `CardGroup` → `Columns`), reubica archivos MDX de snippets huérfanos en `/snippets/` y reescribe las importaciones relativas al padre, extrae componentes en línea que usan hooks de React en `/snippets/<name>.tsx` con `'use client'`, y corrige automáticamente problemas mecánicos de sintaxis MDX. Es idempotente — puedes ejecutarlo de nuevo de forma segura.

</Accordion>

### Despliegue

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Sube tu documentación y activa un build directamente desde la terminal.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  El progreso se muestra en tiempo real a medida que se completa cada fase del build. También disponible como `jamdesk push`.

  | Opción | Descripción |
  |--------|-------------|
  | `--detach` | Encolar y salir inmediatamente |
  | `--full-rebuild` | Forzar reconstrucción completa (sin caché) |
  | `--project <id>` | Desplegar en un proyecto específico |
  | `--allow-empty` | Permitir desplegar con cero páginas de contenido `.mdx` (rechazado por defecto) |

  <Card title="Guía de despliegue CLI" icon="cloud-arrow-up" href="/es/cli/deploy">
    Pipeline de despliegue completo, fases del build, referencia de errores y resolución de problemas
  </Card>
</Accordion>

### Mantenimiento

<Accordion title="jamdesk doctor" icon="stethoscope">
  Comprueba tu entorno y diagnostica problemas.

  ```bash
  jamdesk doctor
  ```

  **Comprueba:**
  - Versión de Node.js (requiere v20+)
  - Versión de npm
  - docs.json existe y es válido
  - Estado de la caché de ~/.jamdesk
  - Permisos de escritura

  Ejecuta esto si tienes problemas con el CLI.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Limpia el directorio de caché ~/.jamdesk.

  ```bash
  jamdesk clean
  ```

  Esto elimina las dependencias en caché y los artefactos de build. Úsalo para:
  - Liberar espacio en disco
  - Solucionar problemas de caché corrupta
  - Forzar una instalación de dependencias nueva

  Las dependencias se reinstalarán en el próximo `jamdesk dev`.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Actualiza el CLI a la última versión.

  ```bash
  jamdesk update
  ```

  También puedes actualizar manualmente:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Configuración

Crea `~/.jamdeskrc` para establecer opciones predeterminadas:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Opción | Tipo | Valor por defecto | Descripción |
|--------|------|-------------------|-------------|
| `defaultPort` | number | 3000 | Puerto por defecto para el servidor de desarrollo |
| `verbose` | boolean | false | Activar salida detallada por defecto |
| `checkUpdates` | boolean | true | Comprobar actualizaciones del CLI al iniciar |

## Solución de problemas

<AccordionGroup>
  <Accordion title="Errores de sintaxis MDX">
    Los archivos MDX se analizan como JSX, por lo que ciertos caracteres tienen significado especial.

    **Problema frecuente:** El carácter `<` se interpreta como el inicio de una etiqueta JSX.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Soluciones:**
    - Usa `&lt;` para el símbolo menor que literal: `Values &lt;50% are low`
    - Reescribe para evitar el carácter: `"Below 50%"` en lugar de `"<50%"`
    - Ejecuta `jamdesk validate` para mensajes de error detallados con números de línea
  </Accordion>

  <Accordion title="docs.json no encontrado">
    Asegúrate de estar en un directorio que contenga un archivo `docs.json`.

    **Soluciones:**
    - Ejecuta `jamdesk init` para crear un nuevo proyecto
    - Verifica que estás en el directorio correcto
    - Comprueba que el archivo se llama exactamente `docs.json` (no `doc.json` ni similar)
  </Accordion>

  <Accordion title="El servidor de desarrollo no arranca">
    El servidor de desarrollo puede fallar al iniciar por varias razones.

    **Prueba estos pasos:**
    1. Ejecuta `jamdesk doctor` para comprobar tu entorno
    2. Ejecuta `jamdesk clean` para limpiar la caché
    3. Usa `jamdesk dev --verbose` para obtener una salida de error detallada
    4. Verifica que Node.js v20+ está instalado: `node --version`
  </Accordion>

  <Accordion title="Primera ejecución lenta">
    La primera ejecución instala dependencias en `~/.jamdesk/node_modules`.

    Esto es normal y solo ocurre una vez. Las ejecuciones posteriores serán mucho más rápidas.
  </Accordion>

  <Accordion title="Puerto ya en uso">
    Otro proceso está usando el puerto por defecto.

    **Soluciones:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Errores de permiso denegado">
    Es posible que no tengas permisos de escritura en el directorio de caché.

    **Soluciones:**
    1. Comprueba los permisos de `~/.jamdesk`: `ls -la ~/.jamdesk`
    2. Corrige la propiedad: `sudo chown -R $(whoami) ~/.jamdesk`
    3. Ejecuta `jamdesk clean` e inténtalo de nuevo
  </Accordion>
</AccordionGroup>
