---
title: Corregir enlaces rotos
description: >-
  Aprende cómo jamdesk fix resuelve enlaces internos rotos y anclas mal
  escritas, previsualizando los cambios antes de aplicarlos.
---

`jamdesk fix` es el complemento de corrección automática de `jamdesk broken-links`. Lee las mismas advertencias de enlaces rotos y reescribe cualquier archivo donde el destino correcto se pueda determinar sin ambigüedad. Los casos ambiguos se marcan para revisión manual y se dejan sin modificar.

<Tip>
  ¿Prefieres quedarte en el dashboard? [Corregir con IA](/es/builds/fix-with-ai) realiza la misma reparación en un build, también cubre las descripciones de página faltantes y confirma los cambios en GitHub por ti.
</Tip>

Corrige dos tipos de enlaces internos rotos:

- **Anclas mal escritas** — un fragmento que es un error ortográfico evidente de un encabezado real en la página de destino (por ejemplo, `#instalation` → `#installation`)
- **Desfase de anclas entre idiomas** — una página traducida cambió el nombre de sus encabezados, pero los enlaces de esa versión en el idioma siguen apuntando al fragmento en inglés antiguo (por ejemplo, `/fr/ai/selectors#ai-strategies` → `/fr/ai/selectors#stratégies-ia`)

## Paso 1: Encontrar enlaces rotos

Ejecuta `jamdesk broken-links` para ver qué se debe corregir:

```bash
jamdesk broken-links
```

Revisa la salida. `jamdesk fix` se enfoca en las advertencias donde es posible hacer coincidir un ancla probablemente correcta con un encabezado real.

## Paso 2: Previsualizar las correcciones

Ejecuta con `--dry-run` para ver exactamente qué cambiaría antes de tocar ningún archivo:

```bash
jamdesk fix --dry-run
```

**Ejemplo de salida:**

```text
Planned fixes:

  fr/ai/overview.mdx:9
    /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

(dry run — no files written)
```

Revisa cada corrección planificada. Si un cambio no se ve bien, corrige ese enlace a mano en lugar de aplicarlo. `jamdesk fix` solo reescribe enlaces que puede resolver sin ambigüedad.

## Paso 3: Aplicar las correcciones

Ejecuta sin `--dry-run` para aplicar los cambios. Se te pedirá que confirmes:

```bash
jamdesk fix
```

```text
Apply 1 fix(es) to local files? (y/N)
```

Presiona `y` para escribir los cambios. Para omitir la confirmación en CI o en scripts, usa `-y`:

```bash
jamdesk fix -y
```

Después de aplicar los cambios, el comando imprime:

```text
Fixed 1 file(s); 0 warning(s) left for manual review.
```

Si el destino de una advertencia es ambiguo, `jamdesk fix` lo deja sin modificar para que lo resuelvas a mano.

## Paso 4: Revisar el diff y confirmar los cambios

Revisa los cambios antes de confirmarlos:

```bash
git diff
```

Verifica que cada enlace reescrito apunte adonde esperas. Luego confirma los cambios:

```bash
git add -A
git commit -m "fix(docs): auto-fix broken internal links"
```

## Opciones

| Opción | Descripción |
|------|-------------|
| `--dry-run` | Previsualiza las correcciones planificadas sin escribir ningún archivo |
| `-y, --yes` | Aplica las correcciones sin pedir confirmación |
| `--types <list>` | Lista de tipos de advertencia separados por comas para corregir (por defecto: todos los admitidos) |
