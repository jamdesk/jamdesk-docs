El archivo `docs.json` es la configuración central de tu sitio de documentación Jamdesk.

<Tip>
  Los ajustes clave de tu docs.json se muestran en el Dashboard, en
  **Project Settings → Configuration Highlights**. Esta vista es de solo lectura
  y se actualiza automáticamente después de cada build correcto.
</Tip>

## Campos obligatorios

### name

**Tipo:** `string` (obligatorio)

El nombre de tu sitio de documentación. Se muestra en la cabecera y en la pestaña del navegador.

```json
{ "name": "Acme API Docs" }
```

### theme

**Tipo:** `"jam" | "nebula" | "pulsar" | "halo"` (obligatorio)

<Tabs>
  <Tab title="jam">
    Diseño limpio y moderno con la fuente Inter. Navegación basada en la cabecera.

    **Ideal para:** La mayoría de los sitios de documentación, referencias de API
  </Tab>
  <Tab title="nebula">
    Sensación ligera y relajada con JetBrains Mono.

    **Ideal para:** Documentación narrativa, guías
  </Tab>
  <Tab title="pulsar">
    Diseño nítido y de alto contraste con navegación por barra lateral.

    **Ideal para:** Referencia técnica densa
  </Tab>
  <Tab title="halo">
    Cálido y suave con Figtree, superficies muy redondeadas y contenido elevado sobre una tarjeta.

    **Ideal para:** Lectura larga y cómoda, documentación de producto cercana
  </Tab>
</Tabs>

### colors

**Tipo:** `object` (obligatorio)

| Campo | Tipo | Obligatorio | Descripción |
|-------|------|----------|-------------|
| `primary` | string (hex) | Sí | Color principal de la marca |
| `light` | string (hex) | No | Acento del tema claro |
| `dark` | string (hex) | No | Acento del tema oscuro |

```json
{
  "colors": {
    "primary": "#635BFF",
    "light": "#7C75FF",
    "dark": "#4F46E5"
  }
}
```

## Marca

### favicon

**Tipo:** `string` u `object`

Ruta a tu archivo de favicon (se recomienda SVG). Proporciona una sola imagen para ambos modos, o variantes `light` / `dark` independientes.

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `light` | string | Favicon para el modo claro (obligatorio si usas la forma de objeto) |
| `dark` | string | Favicon para el modo oscuro (opcional, recurre a `light` por defecto) |

```json
{ "favicon": "/images/favicon.svg" }
```

```json
{
  "favicon": {
    "light": "/images/favicon.svg",
    "dark": "/images/favicon-dark.svg"
  }
}
```

### logo

**Tipo:** `object`

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `light` | string | Logo para el modo claro |
| `dark` | string | Logo para el modo oscuro |
| `href` | string | URL a la que se accede al hacer clic en el logo |

```json
{
  "logo": {
    "light": "/images/logo-light.webp",
    "dark": "/images/logo-dark.webp",
    "href": "https://yoursite.com"
  }
}
```

## Tipografía

### fonts

**Tipo:** `object` (opcional)

Sustituye la fuente predeterminada del tema para el texto del cuerpo y los títulos. Cada tema incluye un valor predeterminado ya ajustado. Define `fonts` solo cuando necesites un aspecto diferente.

Usar la misma fuente en todas partes:

```json
{
  "fonts": {
    "family": "Lora"
  }
}
```

Separar título y cuerpo:

```json
{
  "fonts": {
    "heading": { "family": "Space Grotesk" },
    "body": { "family": "Inter" }
  }
}
```

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `family` | string | Nombre de la familia tipográfica. Funciona cualquier fuente de Google Fonts; el build la obtiene automáticamente |
| `weight` | number | Grosor único a cargar (por ejemplo, `400`). Omítelo para cargar `400, 500, 600, 700` |
| `source` | string | URL o ruta relativa que empieza por `/` hacia un archivo de fuente autoalojado. Omite Google Fonts |
| `format` | `"woff"` \| `"woff2"` | Obligatorio cuando se define `source` |

Tanto `heading` como `body` aceptan los mismos campos. Consulta [Temas → Tipografía](/es/customization/theming#tipografía) para orientación sobre cómo elegir fuentes.

## Apariencia

### appearance

**Tipo:** `object` (opcional)

Controla el comportamiento predeterminado del modo oscuro de tu sitio.

```json
{
  "appearance": {
    "default": "dark",
    "strict": true
  }
}
```

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `default` | `"system"` \| `"light"` \| `"dark"` | `"system"` | Modo inicial para los visitantes que llegan por primera vez |
| `strict` | boolean | `false` | Cuando es `true`, oculta el interruptor de la barra de navegación para que los visitantes permanezcan en `default` |

Consulta [Temas → Modo oscuro](/es/customization/theming#modo-oscuro) para saber cómo se comporta el interruptor.

## Metadatos de página

### metadata

**Tipo:** `object` (opcional)

Controla los metadatos de página que se muestran en cada página de documentación.

```json
{
  "metadata": {
    "timestamp": true
  }
}
```

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `timestamp` | boolean | `false` | Cuando es `true`, muestra una línea de tipo «Última actualización el 15 de junio de 2026» en el pie de cada página. La fecha proviene del último commit de Git que modificó esa página, así que se mantiene precisa automáticamente en cada build. |

La fecha se muestra en tu sitio publicado y en `jamdesk dev`. Refleja el commit más reciente que modificó el archivo de cada página, así que las páginas que no has editado conservan su fecha original.

## Localización

### localization

**Tipo:** `object` (opcional)

Controla cómo llegan los visitantes a la versión traducida de tu documentación.

```json
{
  "localization": {
    "autoRedirect": true
  }
}
```

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `autoRedirect` | boolean | `false` | Cuando es `true`, un visitante que llega por primera vez a la raíz de tu documentación es redirigido al idioma que coincide con la cabecera `Accept-Language` de su navegador. Requiere dos o más entradas en `navigation.languages`. |

Solo se redirigen las raíces. Un enlace profundo como `/guides/authentication` siempre sirve la página que nombra, así que un enlace que pegas en un ticket abre la misma página para todos. Los rastreadores de los motores de búsqueda nunca se redirigen, así que tus etiquetas `hreflang` siguen decidiendo qué se indexa.

El idioma del visitante se recuerda durante un año. Elegir un idioma en el selector de idioma anula la coincidencia automática a partir de ese momento.

Consulta [Idiomas → Enrutamiento automático de idioma](/es/setup/languages#enrutamiento-automático-de-idioma) para el comportamiento completo.

## Banner

### banner

Muestra una barra de aviso para todo el sitio, fijada en la parte superior de cada página, encima de la cabecera, a todo lo ancho, con el color de acento de tu tema. Úsala para lanzamientos, migraciones, ventanas de mantenimiento o cualquier mensaje que deban ver todos los visitantes.

```json
{
  "banner": {
    "content": "🎉 Version 2.0 is live! Read the [changelog](/changelog).",
    "dismissible": true
  }
}
```

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `content` | string | - | **Obligatorio.** El texto del banner. Admite formato básico en línea: enlaces `[text](url)`, **negrita** (`**text**`), y *cursiva* (`*text*`). No se admiten componentes MDX personalizados. |
| `dismissible` | boolean | `false` | Cuando es `true`, muestra un botón de cierre. Después de que un visitante cierra el banner, permanece oculto para él hasta que cambies `content`. Editar el mensaje lo hace reaparecer. |

El banner se muestra en tu sitio publicado y en `jamdesk dev`. Se configura de forma global (un solo banner para todo el sitio); los banners por pestaña y por idioma todavía no son compatibles.

## OpenAPI

### api.openapi

**Tipo:** `string | string[]`

Enumera los archivos de especificación OpenAPI 3.x que quieres que Jamdesk valide y use para las páginas de endpoint. Usa rutas relativas a tu `docs.json`.

```json docs.json
{
  "api": {
    "openapi": ["/openapi/api.yaml"]
  }
}
```

Una vez configurado, puedes generar páginas de endpoint añadiendo un campo `openapi` en el frontmatter de una página:

```mdx
---
title: Create Ticket
openapi: /openapi/api.yaml POST /tickets
---
```

Si solo tienes una especificación en la lista, también puedes usar el formato corto:

```mdx
---
title: Create Ticket
openapi: POST /tickets
---
```

Consulta [Ejemplo de OpenAPI](/es/api-reference/openapi-example) para ver una página de endpoint real y [Estructura de directorios](/es/setup/directory-structure) para la ubicación de los archivos.

Si tu sitio es multilingüe, coloca un archivo `<spec>.<lang>.<ext>` junto a cada especificación de origen (por ejemplo, `openapi/api.fr.yaml`) y Jamdesk lo sirve en las URL de ese idioma. Consulta [Traducir especificaciones OpenAPI](/es/setup/languages#traducir-especificaciones-de-openapi).

<Warning>
Se acepta una clave `asyncapi` en cualquier lugar donde se acepte `openapi`, pero Jamdesk todavía no renderiza especificaciones AsyncAPI — no se genera nada a partir de ella. `jamdesk validate` muestra un aviso cuando encuentra una, para que una configuración que parece compatible no lo siga pareciendo hasta que construyas el sitio.
</Warning>

### navigation openapi (páginas generadas)

**Tipo:** `object`

Coloca un objeto `openapi` en una **pestaña** de navegación y define `generate: true`, y Jamdesk genera una página de endpoint por cada operación de esa especificación en el momento del build — además de los grupos de la barra lateral que las contienen. Nada que redactar, nada que commitear.

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API Reference",
        "openapi": { "source": "/openapi/api.yaml", "generate": true }
      }
    ]
  }
}
```

| Clave | Tipo | Descripción |
|-----|------|-------------|
| `source` | string | Ruta a la especificación, relativa a tu `docs.json` |
| `generate` | boolean | `true` genera las páginas y la barra lateral. Sin ella, la clave permanece inactiva |

Las páginas generadas se ubican bajo el propio nombre de la pestaña, convertido en slug, con un slug construido a partir del método y la ruta — la pestaña anterior coloca `POST /tickets` en `/api-reference/post-tickets`. Las operaciones se agrupan por su primer `tag`; las especificaciones sin tags recurren al primer segmento de ruta significativo, así que `/api/v1/auctions/{auctionId}` queda bajo **Auctions**. Los títulos provienen del `summary` de la operación cuando la especificación tiene uno, y si no, del método y la ruta — y una operación que se refiere a un único recurso se titula en singular (`GET /users/{id}` → «Get User»).

<Note>
`generate` es opt-in por construcción. Un simple `"openapi": "/openapi/api.yaml"` en una pestaña, o un objeto sin `generate: true`, sigue haciendo exactamente lo mismo que antes — así ninguna configuración existente gana un centenar de páginas en su próximo build.
</Note>

Un archivo `.mdx` commiteado siempre gana en caso de colisión de slug, así que puedes adoptar la generación de forma gradual: actívala y luego elimina tus páginas de endpoint escritas a mano una por una, a tu ritmo.

Si más tarde renombras una ruta en tu especificación, el slug generado se actualiza con ella. Jamdesk mantiene un historial de slugs por operación y emite una redirección de cada URL anterior a la actual en cada build, así que los enlaces entrantes y los marcadores sobreviven al cambio de nombre. Tus propias [redirecciones](/es/setup/redirects) y cualquier página existente siguen teniendo prioridad.

**Límites actuales.** La generación solo funciona en `navigation.tabs` de nivel superior — no en grupos, anchors, ni en pestañas anidadas bajo `languages` o `versions` — y solo produce páginas para tu idioma predeterminado. El esquema acepta una clave `directory`, pero no tiene ningún efecto sobre dónde acaban las páginas.

### api.mdx.server

**Tipo:** `string`

URL base usada en los ejemplos de código de las páginas con frontmatter `api:` (el tipo escrito en MDX, no las páginas `openapi:`, que obtienen sus servidores de la especificación).

```json
{
  "api": {
    "mdx": {
      "server": "https://api.example.com"
    }
  }
}
```

<Note>
Se acepta un array por compatibilidad, pero solo se usa la primera entrada — todo lo que va después se descarta. `jamdesk validate` muestra un aviso si incluyes más de una.
</Note>

### api.examples.languages

**Tipo:** `string[]`
**Valor por defecto:** `["curl", "python", "javascript"]`

Elige qué lenguajes de programación aparecen en los ejemplos de código de API generados automáticamente en las páginas `openapi:`. El orden del array determina el orden de visualización de las pestañas, y el primer lenguaje se selecciona por defecto.

**Valores admitidos:** `curl`, `bash`, `python`, `javascript`, `go`, `ruby`, `csharp`, `java`, `rust`, `php`

<Note>`bash` es un alias de `curl`; ambos producen el mismo resultado. Usa la etiqueta que prefieras.</Note>

```json All supported languages
{
  "api": {
    "examples": {
      "languages": ["curl", "python", "javascript", "go", "ruby", "csharp", "java", "rust", "php"]
    }
  }
}
```

```json Custom subset
{
  "api": {
    "examples": {
      "languages": ["python", "javascript", "go"]
    }
  }
}
```

### api.examples.defaults

**Tipo:** `"required" | "all"`
**Valor por defecto:** `"all"`

Controla qué parámetros aparecen en los ejemplos de código generados automáticamente.

| Valor | Comportamiento |
|-------|----------|
| `"all"` | Los ejemplos incluyen todos los parámetros con valores de marcador de posición |
| `"required"` | Los ejemplos solo incluyen los parámetros marcados como `required` en la especificación |

```json
{
  "api": {
    "examples": {
      "defaults": "required"
    }
  }
}
```

### api.examples.prefill

**Tipo:** `boolean`
**Valor por defecto:** `false`

Cuando es `true`, el [API Playground](/es/api-reference/playground) rellena previamente los campos de parámetros con los valores `example` de tu especificación OpenAPI.

```json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

### api.playground.display

**Tipo:** `"interactive" | "simple" | "none"`
**Valor por defecto:** `"interactive"`

Controla el [API Playground](/es/api-reference/playground) en las páginas de endpoint. Por defecto aparece un botón «Try it» en cada página `openapi:` y `api:`.

| Valor | Comportamiento |
|-------|----------|
| `"interactive"` | playground completo: rellenar parámetros, generar código, enviar solicitudes (por defecto) |
| `"simple"` | Rellenar parámetros y copiar código, pero sin botón Send |
| `"none"` | Playground desactivado |

```json
{
  "api": {
    "playground": {
      "display": "interactive"
    }
  }
}
```

Consulta el [API Playground](/es/api-reference/playground) para conocer los detalles de uso y las anulaciones por página.

### api.mdx.auth.method

**Tipo:** `"bearer" | "basic" | "key" | "cobo"`

Método de autenticación usado en los ejemplos de código generados automáticamente. Cuando se define, los ejemplos incluyen la cabecera de autenticación adecuada.

| Valor | Formato de la cabecera |
|-------|--------------|
| `"bearer"` | `Authorization: Bearer <token>` |
| `"basic"` | `Authorization: Basic <base64>` |
| `"key"` | Cabecera personalizada (consulta `api.mdx.auth.name`) |
| `"cobo"` | Autenticación específica de Cobo |

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
}
```

### api.mdx.auth.name

**Tipo:** `string`

Nombre de cabecera personalizado para la autenticación basada en clave. Solo se usa cuando `api.mdx.auth.method` es `"key"`.

```json
{
  "api": {
    "mdx": {
      "auth": {
        "method": "key",
        "name": "X-API-Key"
      }
    }
  }
}
```

## Navegación

### tabsPosition

**Tipo:** `"top" | "left"`

Controla dónde se muestran las pestañas de navegación.

| Valor | Descripción |
|-------|-------------|
| `"top"` | Las pestañas aparecen en la barra de pestañas de la cabecera |
| `"left"` | Las pestañas aparecen en la parte superior de la barra lateral |

El valor por defecto depende de tu tema:

| Tema | Valor por defecto |
|-------|---------|
| jam | `"left"` |
| nebula | `"left"` |
| pulsar | `"top"` |
| halo | `"left"` |

```json
{ "tabsPosition": "left" }
```

### anchors

**Tipo:** `array`

Enlaces externos que aparecen en la parte superior de la barra lateral en todas las páginas.

| Campo | Tipo | Obligatorio | Descripción |
|-------|------|----------|-------------|
| `name` | string | Sí | Texto que se muestra |
| `href` | string | Sí | URL (enlace externo) |
| `icon` | string | No | Nombre de icono de Font Awesome |

```json
{
  "anchors": [
    { "name": "Blog", "href": "https://blog.example.com", "icon": "newspaper" }
  ]
}
```

### navigation (estructura)

**Tipo:** `object`

La estructura de navegación de tu documentación. Consulta [Navegación](/es/navigation/overview) para la documentación detallada.

Las páginas pueden ser cadenas (título generado automáticamente a partir del nombre de archivo) u objetos con un título personalizado:

```json
"pages": [
  "introduction",
  { "page": "content/mdx-basics", "title": "MDX Basics" }
]
```

<Accordion title="Ejemplo básico de navegación">
```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Docs",
        "icon": "book-open",
        "groups": [
          {
            "group": "Getting Started",
            "pages": ["introduction", "quickstart"]
          }
        ]
      }
    ]
  }
}
```
</Accordion>

## Barra de navegación y pie de página

### navbar

**Tipo:** `object`

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `links` | array | Enlaces de navegación |
| `links[].label` | string | Texto de botón por defecto |
| `links[].labels` | object | Anulaciones opcionales por idioma, indexadas por código de idioma (por ejemplo, `fr`, `es`). Recurre a `label` |
| `links[].icon` | icon | Icono opcional que se muestra junto a la etiqueta |
| `links[].href` | string | URL de destino |
| `primary` | object | Botón CTA principal |
| `primary.label` | string | Texto de botón por defecto |
| `primary.labels` | object | Anulaciones opcionales por idioma, indexadas por código de idioma. Recurre a `label` |

```json
{
  "navbar": {
    "links": [
      {
        "label": "Blog",
        "labels": { "fr": "Blog", "es": "Blog" },
        "href": "/blog"
      },
      {
        "label": "Pricing",
        "labels": { "fr": "Tarifs", "es": "Precios" },
        "href": "/pricing"
      }
    ],
    "primary": {
      "type": "button",
      "label": "Dashboard",
      "labels": { "fr": "Tableau de bord", "es": "Panel" },
      "href": "https://app.example.com"
    }
  }
}
```

<Note>
  `labels` es opcional. La documentación monolingüe puede omitirlo. Cuando se define, el idioma de la URL actual (por ejemplo, `/fr/...`) selecciona la anulación correspondiente.
</Note>

### footer

**Tipo:** `object`

Configura el pie de página con enlaces sociales y columnas de enlaces personalizadas.

```json
{
  "footer": {
    "socials": {
      "github": "https://github.com/yourorg",
      "x": "https://x.com/yourhandle",
      "discord": "https://discord.gg/yourserver"
    },
    "links": [
      {
        "header": "Resources",
        "items": [
          { "label": "Blog", "href": "https://example.com/blog" },
          { "label": "Changelog", "href": "/changelog" }
        ]
      }
    ]
  }
}
```

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `socials` | object | URL de las plataformas de redes sociales |
| `links` | array | Configuraciones de columnas de enlaces |
| `links[].header` | string | Título de la columna |
| `links[].items` | array | Array de objetos `{ label, href }` |

**Plataformas sociales admitidas:** `github`, `x`, `twitter`, `linkedin`, `discord`, `slack`, `youtube`, `instagram`, `facebook`, `reddit`, `telegram`, `bluesky`, `threads`, `medium`, `hacker-news`, `website`

## Estilos

### styling.latex

**Tipo:** `boolean`

Activa el renderizado matemático LaTeX con KaTeX. Una vez activado, puedes usar `$...$` para matemáticas en línea y `$$...$$` para ecuaciones en bloque.

```json
{
  "styling": {
    "latex": true
  }
}
```

Consulta [Matemáticas y LaTeX](/es/content/math) para los detalles de uso.

### styling.js

**Tipo:** `string | string[]`

Archivo(s) de JavaScript personalizado(s) para incluir en cada página. Las rutas son relativas a tu directorio de documentación y deben empezar por `/`.

```json
{
  "styling": {
    "js": "/script.js"
  }
}
```

Pasa un array para varios archivos:

```json
{
  "styling": {
    "js": ["/chat.js", "/analytics.js"]
  }
}
```

Sin este campo, Jamdesk detecta automáticamente los archivos `.js` en la raíz de tu proyecto. Consulta [JavaScript personalizado](/es/customization/custom-javascript) para más detalles.

## Búsqueda

### search

**Tipo:** `object` (opcional)

Personaliza la barra de búsqueda de la documentación. La búsqueda funciona de fábrica; solo necesitas este campo para cambiar el texto de marcador de posición o mostrar páginas populares en el estado vacío.

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `prompt` | string | `Search documentation…` | Texto de marcador de posición mostrado en el campo de búsqueda |
| `popularPages` | array | Quick Start, Introduction | Enlaces de acceso rápido mostrados antes de que el visitante escriba una consulta |

```json
{
  "search": {
    "prompt": "Ask me anything…",
    "popularPages": [
      { "title": "Quick Start", "slug": "quickstart", "icon": "rocket" },
      { "title": "Authentication", "slug": "guides/authentication", "icon": "key" }
    ]
  }
}
```

#### Páginas populares

Cada entrada de `popularPages` acepta:

| Campo | Tipo | Obligatorio | Descripción |
|-------|------|----------|-------------|
| `title` | string | Sí | Etiqueta que se muestra para el enlace |
| `slug` | string | Sí | Ruta de la página, sin barra inicial ni extensión `.mdx` (por ejemplo, `quickstart`, o `guides/authentication` para el archivo `guides/authentication.mdx`) |
| `icon` | string | No | Nombre de icono de Font Awesome que se muestra junto al enlace (por ejemplo, `rocket` o `bell`) |

El campo `icon` también acepta el objeto completo `{ "name", "style", "library" }`. Consulta [Forma de objeto del icono](/es/content/icons#forma-de-objeto-de-icono). Cuando se omite `popularPages`, Jamdesk muestra Quick Start e Introduction (Inicio rápido e Introducción) por defecto.

## Chat

### chat

**Tipo:** `object` (opcional)

Configura el asistente de chat con IA integrado. El chat está activado por defecto en todos los sitios; solo necesitas este campo para personalizar las preguntas iniciales o desactivarlo.

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Define `false` para quitar el panel de chat de tu sitio |
| `starterQuestions` | string[] | generadas automáticamente | Hasta 4 preguntas mostradas al abrir el chat (de 5 a 200 caracteres cada una). Se generan automáticamente durante los builds si se omite. Define `[]` para no tener ninguna |

```json
{
  "chat": {
    "starterQuestions": [
      "How do I get started?",
      "What API endpoints are available?"
    ]
  }
}
```

Consulta [Chat con IA](/es/ai/chat) para conocer los detalles de cómo funciona el chat y qué ven los visitantes.

## Menú de acciones de IA

### contextual

**Tipo:** `object` (opcional)

Configura el menú desplegable de Acciones de IA que aparece en cada página. Está activado por defecto con todas las opciones; solo necesitas este campo para personalizar qué opciones aparecen o desactivarlo.

| Campo | Tipo | Valor por defecto | Descripción |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | Define `false` para quitar el menú de Acciones de IA de tu sitio |
| `options` | array | todas las integradas | Lista de claves de opciones y/o objetos de opciones personalizadas |

**Claves de opciones integradas:** `copy`, `view`, `chatgpt`, `claude`, `perplexity`, `gemini`, `mcp`, `cursor`, `vscode`

```json
{
  "contextual": {
    "options": ["copy", "claude", "mcp", "cursor"]
  }
}
```

Añade opciones personalizadas junto a las integradas:

```json
{
  "contextual": {
    "options": [
      "copy",
      "claude",
      {
        "title": "Ask on Discord",
        "description": "Get help from the community",
        "icon": "discord",
        "href": "https://discord.gg/your-server"
      }
    ]
  }
}
```

Consulta [Menú de acciones de IA](/es/ai/ai-actions) para la lista completa de opciones y el formato de las opciones personalizadas.

## Corrector ortográfico

### spellcheck

**Tipo:** `object` (opcional)

Configura el comando de CLI `jamdesk spellcheck`. Solo necesitas este campo para añadir palabras específicas de tu proyecto a la lista de exclusión.

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `ignore` | string[] | Palabras que se omiten durante la corrección ortográfica (nombres de producto, términos técnicos, etc.) |

```json
{
  "spellcheck": {
    "ignore": ["Acme", "kubectl", "Terraform"]
  }
}
```

El CLI incluye más de 180 términos técnicos integrados (API, GraphQL, Kubernetes, React, etc.) e ignora automáticamente el nombre de tu proyecto tomado del campo `name`. Añade solo palabras específicas de tu proyecto.

Consulta [Resumen del CLI: corrector ortográfico](/es/cli/overview) para los detalles de uso y el modo de corrección interactivo.

## Imágenes

### images.convertToWebp

**Tipo:** `boolean` (opcional, por defecto `false`)

Activa la conversión automática a WebP para los recursos PNG y JPG durante los builds. Los archivos convertidos suelen ser entre un 60 % y un 80 % más ligeros que los originales, sin pérdida de calidad visible. Las referencias en tu MDX, tu CSS personalizado, tu JS personalizado y tu `docs.json` se reescriben automáticamente, así que no cambias ninguna ruta.

Los favicons, `og:image` y `twitter:image` conservan su formato original. No todos los rastreadores sociales ni clientes de correo renderizan WebP de forma fiable, y una tarjeta de vista previa rota es peor que un JPG algo más pesado.

```json
{
  "images": {
    "convertToWebp": true
  }
}
```

Consulta [Conversión automática de imágenes](/es/builds/image-optimization) para saber qué se convierte, cómo funciona el almacenamiento en caché y el indicador de progreso del build.

## Control de acceso

### auth.password

**Tipo:** `object` (opcional)

Activa la protección por contraseña compartida para tu sitio. Solo configuración declarativa. La contraseña real la sigues definiendo en el [dashboard](/es/setup/password-protection#rotación-y-revocación-de-sesiones) después de que se ejecute el siguiente build.

Define `auth.password.enabled: true` para bloquear todo el sitio, o enumera rutas en `auth.password.private[]` para proteger solo esas páginas. Ambas opciones activan la misma solicitud de contraseña del dashboard en el siguiente build.

```json
{
  "auth": {
    "password": {
      "enabled": true,
      "hint": "Ask your account manager",
      "public": ["/marketing/**", "/changelog"]
    }
  }
}
```

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `enabled` | `boolean` | Modo de sitio completo. Cuando es `true`, cada página necesita la contraseña (excepto las marcadas como públicas). |
| `hint` | `string` (máx. 200 caracteres) | Pista en texto plano mostrada en la pantalla de desbloqueo. Sin HTML. |
| `public` | `string[]` | Patrones de ruta que evitan la contraseña. Admite `*` (un segmento) y `**` (recursivo). Se rechaza un `/` solo. |
| `private` | `string[]` | Rutas exactas que requieren la contraseña. Definir esto sin `enabled` activa el modo de páginas específicas. |

Consulta [Protección por contraseña](/es/setup/password-protection) para la guía completa, incluido el flujo del dashboard y cómo interactúa el frontmatter `public: true` / `private: true` con estos arrays.

### auth.jwt

**Tipo:** `object` (opcional)

Bloquea todo el sitio detrás de tu propio sistema de inicio de sesión. Tu backend firma un token de corta duración para cada usuario que ha iniciado sesión, y Jamdesk lo intercambia por una cookie de sesión. La clave de firma se genera en el dashboard, no en este archivo. `auth.jwt` y `auth.password` no se pueden activar a la vez; un build con ambas activadas falla con un `config_error`.

```json
{
  "auth": {
    "jwt": {
      "enabled": true,
      "loginUrl": "https://app.example.com/docs-login",
      "public": ["/changelog/**", "/status"]
    }
  }
}
```

| Campo | Tipo | Descripción |
|-------|------|-------------|
| `enabled` | `boolean` | Activa la autenticación JWT. Cada página necesita una sesión, excepto las marcadas como públicas. |
| `loginUrl` | `string` | Obligatorio cuando `enabled` es `true`. Una URL `https://` absoluta de tu lado. Los visitantes sin sesión son enviados aquí con `?redirect=<path>` para que puedas devolverlos a la página que pidieron. |
| `public` | `string[]` | Patrones de ruta que siguen siendo accesibles sin iniciar sesión. Misma sintaxis que `auth.password.public`, combinada con el frontmatter `public: true` y `"public": true` en los grupos de navegación. |

El acceso por página, además de esto, proviene de `groups` en el frontmatter de la página. Consulta [Autenticación JWT](/es/setup/jwt-authentication) para el formato del token, el flujo de redirección y cómo funcionan los grupos.
