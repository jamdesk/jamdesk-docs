Usa la API de builds para activar reconstrucciones de la documentación sin enviar nuevos commits. Esto resulta útil para pipelines de CI, reconstrucciones programadas o contenido generado fuera del directorio de documentación.

## Autenticación

Todas las solicitudes usan una clave de API del proyecto:

```http
Authorization: Bearer YOUR_API_KEY
```

Busca tu clave de API en **Settings** → **API** del proyecto.

## Activar una reconstrucción

**POST** `https://api.jamdesk.com/projects/{project_id}/rebuild`

### Solicitud de ejemplo

<CodeGroup>
```bash cURL
curl -X POST "https://api.jamdesk.com/projects/YOUR_PROJECT_ID/rebuild" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript JavaScript
const projectId = "YOUR_PROJECT_ID";
const apiKey = "YOUR_API_KEY";

const response = await fetch(
  `https://api.jamdesk.com/projects/${projectId}/rebuild`,
  {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${apiKey}`
    }
  }
);
const build = await response.json();
console.log(build.buildId, build.status);
```
</CodeGroup>

### Respuesta

Las solicitudes correctas devuelven `200 OK` con metadatos del build que puedes usar para hacer un seguimiento del progreso.

```json
{
  "buildId": "build_8f3k2j",
  "status": "queued",
  "createdAt": "2026-02-05T10:30:00Z",
  "commit": {
    "sha": "a1b2c3d",
    "message": "Update API docs",
    "author": "jane@example.com"
  },
  "project": {
    "id": "proj_abc123",
    "name": "My Docs"
  }
}
```

<Note>
Si recibes una respuesta `429`, vuelve a intentarlo con un retroceso exponencial. Contacta con soporte si necesitas límites superiores.
</Note>

### Campos de respuesta

<ResponseField name="buildId" type="string">
  Identificador único del build. Úsalo para hacer referencia al build en el dashboard.
</ResponseField>

<ResponseField name="status" type="string">
  Estado actual del build. Puede ser: `queued`, `building`, `deployed` o `failed`.
</ResponseField>

<ResponseField name="createdAt" type="string">
  Marca de tiempo ISO 8601 de la creación del build.
</ResponseField>

<ResponseField name="commit.sha" type="string">
  Hash corto del commit que activó el build.
</ResponseField>

<ResponseField name="commit.message" type="string">
  Mensaje del commit del repositorio de origen.
</ResponseField>

<ResponseField name="commit.author" type="string">
  Dirección de correo electrónico del autor del commit.
</ResponseField>

<ResponseField name="project.id" type="string">
  Identificador del proyecto que coincide con el proyecto del dashboard.
</ResponseField>

<ResponseField name="project.name" type="string">
  Nombre visible del proyecto.
</ResponseField>

## Seguir el estado del build

El estado del build está visible en el dashboard, en **Deployments**. Cada build pasa por estas etapas:

1. **queued** -- El build está esperando en la cola.
2. **building** -- El servicio de builds está compilando tu documentación.
3. **deployed** -- El build se completó y tu sitio está disponible.
4. **failed** -- Se produjo un error. Consulta los registros del build para obtener más información.

Si tu repositorio está conectado a GitHub, las comprobaciones del estado de los commits se actualizan automáticamente. Aparece una marca verde en el commit cuando se despliega el build, o una X roja si el build falla. No necesitas consultar la API periódicamente para recibir actualizaciones de estado.

## Formato de respuesta de error

Las respuestas de error siguen una estructura coherente:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API key",
    "status": 401
  }
}
```

<ResponseField name="error.code" type="string">
  Código de error legible por máquinas. Consulta la tabla siguiente para ver los valores posibles.
</ResponseField>

<ResponseField name="error.message" type="string">
  Descripción legible por personas de lo que salió mal.
</ResponseField>

<ResponseField name="error.status" type="number">
  Código de estado HTTP que coincide con el estado de la respuesta.
</ResponseField>

### Códigos de error

| Estado | Código | Mensaje | Solución |
|--------|------|---------|-----|
| **401** | `unauthorized` | Invalid API key | Regenera la clave en **Settings** → **API** |
| **403** | `forbidden` | Unauthorized project access | Confirma que el ID del proyecto coincide con el proyecto de la clave de API |
| **404** | `project_not_found` | Project not found | Verifica el ID del proyecto en el dashboard |
| **429** | `rate_limited` | Too many requests | Espera y vuelve a intentarlo con un retroceso exponencial |
| **500** | `internal_error` | Internal server error | Vuelve a intentarlo después de unos segundos. Contacta con soporte si el problema persiste |
