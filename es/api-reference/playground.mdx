El API playground añade un botón interactivo "Inténtalo" a las páginas de endpoints de tu API. Los desarrolladores pueden rellenar parámetros, ver cómo se actualizan los ejemplos de código en tiempo real y enviar solicitudes HTTP reales, todo sin salir de tu documentación.

Las capturas de pantalla muestran la interfaz en inglés.

<Frame>
  <img src="/images/playground/playground-modal.webp" alt="API playground modal showing parameter form on the left and live code examples on the right" />
</Frame>

## Inicio rápido

El playground está habilitado por defecto. Cada página con un campo `openapi:` o `api:` en el frontmatter obtiene automáticamente un botón "Inténtalo". CORS se gestiona de forma automática.

No se necesita configuración en `docs.json`. Añade un campo `openapi:` o `api:` al frontmatter de tu página y el playground aparecerá.

## Modos de visualización

El campo `display` controla qué puede hacer el playground:

| Modo | Botón "Inténtalo" | Rellenar parámetros | Código en vivo | Enviar solicitud |
|------|:-:|:-:|:-:|:-:|
| `"interactive"` (predeterminado) | ✓ | ✓ | ✓ | ✓ |
| `"simple"` | ✓ | ✓ | ✓ | ✗ |
| `"none"` | ✗ | ✗ | ✗ | ✗ |

<Tabs>
  <Tab title="Interactive">
    Experiencia completa del playground. Los desarrolladores rellenan parámetros, ven cómo se actualizan los ejemplos de código en vivo y envían solicitudes HTTP reales. Las respuestas se muestran en línea con códigos de estado, tiempos y cuerpos formateados.

    ```json docs.json
    {
      "api": {
        "playground": {
          "display": "interactive"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Simple">
    Modo de solo lectura sin botón de envío. Los desarrolladores pueden rellenar parámetros y copiar los ejemplos de código generados, pero no pueden ejecutar solicitudes. Útil cuando tu API requiere autenticación que no se puede compartir en la documentación.

    ```json docs.json
    {
      "api": {
        "playground": {
          "display": "simple"
        }
      }
    }
    ```
  </Tab>
</Tabs>

## Autenticación

Si tu API requiere autenticación (configurada mediante `api.mdx.auth.method` en `docs.json`), el playground muestra un campo de entrada de autenticación en la parte superior del formulario de parámetros. Los desarrolladores introducen su clave de API o token directamente en el modal.

Las credenciales se mantienen en memoria únicamente durante la sesión actual. Nunca se guardan en `localStorage` ni se conservan entre visitas.

## Precompletar valores de ejemplo

Cuando tu especificación OpenAPI incluye valores `example` en parámetros y cuerpos de solicitud, el playground puede precompletarlos:

```json docs.json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

Esto ahorra tiempo a los desarrolladores al mostrar valores realistas que pueden modificar en lugar de empezar con campos vacíos.

## Anulación por página

Anula el modo de visualización global en páginas individuales usando el campo `playground` del frontmatter:

```mdx
---
title: Create Ticket
openapi: POST /tickets
playground: interactive
---
```

Útil cuando quieres que el playground esté deshabilitado globalmente pero habilitado en endpoints de demostración específicos, o viceversa.

| Frontmatter | Comportamiento |
|-------------|----------|
| `playground: interactive` | playground completo en esta página |
| `playground: simple` | playground solo de código en esta página |
| `playground: none` | Sin playground en esta página |

## Cómo funciona

<Steps>
  <Step title="Haz clic en 'Inténtalo'">
    El playground se abre como un modal de superposición a pantalla completa. La página de tus docs permanece intacta debajo.
  </Step>
  <Step title="Rellena los parámetros">
    Los parámetros de ruta, consulta, encabezado y cuerpo se muestran como campos de formulario. Los campos obligatorios están marcados. La URL base se obtiene del campo `servers` de tu especificación OpenAPI.
  </Step>
  <Step title="Observa cómo se actualiza el código">
    A medida que escribes, los ejemplos de código se regeneran en tiempo real en todos los lenguajes configurados. Copia cualquier ejemplo con un solo clic.
  </Step>
  <Step title="Envía la solicitud">
    En el modo interactivo, haz clic en Enviar (o pulsa `Ctrl/Cmd+Enter`) para ejecutar la solicitud. La respuesta se muestra a continuación con el código de estado, la duración y el cuerpo formateado.
  </Step>
</Steps>

<Frame>
  <img src="/images/playground/playground-response.webp" alt="API playground showing a 201 Created response with JSON body after sending a request" />

<Tip>
Cuando el playground está abierto, la URL se actualiza para incluir `?playground=open`. Comparte esta URL para enlazar a alguien directamente a la vista del playground de un endpoint.
</Tip>

## Atajos de teclado

| Atajo | Acción |
|----------|--------|
| `Ctrl/Cmd + Enter` | Enviar solicitud |
| `Escape` | Cerrar el playground |

## Compatible con ambos tipos de páginas API

El playground funciona en páginas que usan el formato de frontmatter `openapi:` o `api:`:

<Tabs>
  <Tab title="OpenAPI pages">
    Los parámetros y esquemas se obtienen automáticamente de tu especificación OpenAPI. No se necesita configuración adicional.

    ```mdx
    ---
    openapi: POST /tickets
    ---
    ```
  </Tab>
  <Tab title="MDX api: pages">
    Los parámetros se extraen de tus componentes `<ParamField>`. La URL base proviene de `api.mdx.server` en tu docs.json.

    ```mdx
    ---
    api: GET /tickets/{ticket_id}
    ---
    ```
  </Tab>
</Tabs>

## Desarrollo local

Al ejecutar `jamdesk dev`, los botones "Inténtalo" son visibles, pero el playground en sí es una función exclusiva de producción. Al hacer clic en "Inténtalo" en desarrollo local se muestra una breve notificación en lugar de abrir el modal. Despliega tu documentación para usar el playground completo.
