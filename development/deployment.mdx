## CLI Deploy

Deploy from the terminal without pushing to GitHub. Use it for quick iterations, testing changes, or projects not connected to a repo.

```bash
jamdesk login     # First time only
jamdesk deploy
```

The CLI packages and uploads your files. It shows build progress live. Use `--detach` to queue the build and exit immediately.

## The Workflow

<Steps>
  <Step title="Make changes locally">
    Edit your MDX files and preview with `jamdesk dev`.
  </Step>
  <Step title="Push to GitHub">
    Commit and push to your connected branch:

    ```bash
    git add .
    git commit -m "Update authentication docs"
    git push
    ```
  </Step>
  <Step title="Automatic deployment">
    Jamdesk detects your push and builds your docs. It deploys them to the CDN. Most sites build in 30-90 seconds.
  </Step>
</Steps>

## Deployment Status

Check status in the dashboard under **Deployments**:

| Status | Meaning |
|--------|---------|
| **Building** | Build in progress |
| **Deployed** | Live at your domain |
| **Failed** | Build error - check logs |
| **Queued** | Waiting for previous build |

## Manual Rebuild

Trigger a rebuild without pushing:

1. Go to **Settings** in your project
2. Click **Rebuild**

Use this after you update environment variables or to fix a stuck build.

## Build Logs

Open **Deployments**, click a deployment, and read the logs. Common errors:
- Invalid MDX syntax
- Missing images
- Broken internal links
- Configuration errors

## Rollbacks

1. Go to **Deployments**
2. Find the deployment to restore
3. Click **Rollback**

The previous version goes live immediately.
