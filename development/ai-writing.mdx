Use AI tools like Claude and Cursor to draft, edit, and maintain Jamdesk documentation. This guide covers recommended workflows and how to keep AI output aligned with your docs.

## Why MDX Works Well with AI

- **Familiar syntax** — AI models are trained on millions of Markdown files
- **Structured components** — `<Card>`, `<Steps>`, `<Tabs>` have predictable patterns
- **Plain text** — No binary formats or proprietary schemas

## Tool-Specific Workflows

<Tabs>
  <Tab title="Cursor">
    **Inline editing (Cmd+K):** Select text, describe the change.

    **Chat with context (Cmd+L):** Ask questions with your docs as context.

    **Cursor Rules:** Add `.cursor/rules/docs.mdc` for documentation standards.
  </Tab>
  <Tab title="Claude Code">
    **Generate from implementation:** Reference source files to generate accurate docs.

    **Use the /update-jamdesk skill:** Automatically suggest documentation updates when code changes.

    **Full codebase context:** Claude Code can read your entire project to understand naming conventions and patterns.
  </Tab>
  <Tab title="Copilot">
    **Autocomplete components:** Start typing `<Card` and Copilot completes the structure.

    **Generate from comments:** Write a comment describing what you want, then let Copilot generate.

    **Tab completion:** Accept suggestions line-by-line as you write.
  </Tab>
</Tabs>

## Keep Docs in Sync

<Tabs>
  <Tab title="Manual prompting">
    After implementing a feature, prompt your AI tool:

    ```
    I just added [feature]. Update the documentation in /docs to reflect this change.
    Reference the implementation in /src/[file] for accuracy.
    ```
  </Tab>
  <Tab title="Automated with skills">
    If using Claude Code with the Jamdesk monorepo, run `/update-jamdesk` after implementing user-facing changes. This skill automatically identifies which docs need updates.
  </Tab>
</Tabs>

## Example MDX Skeleton

Use this as a starting point for AI-generated pages:

```mdx
---
title: Feature Overview
description: What this feature does and why it matters
---

One paragraph explaining the problem and audience.

## How It Works

<Steps>
  <Step title="Step one">Describe the first action.</Step>
  <Step title="Step two">Describe the second action.</Step>
</Steps>
```

## LLM-Friendly Output

Jamdesk automatically generates files that make your docs consumable by AI tools:

| File | Purpose |
|------|---------|
| `/llms.txt` | Table of contents following llmstxt.org spec |
| `/llms-full.txt` | Complete documentation in one file |

These files help AI assistants understand your product when users ask questions about it.
