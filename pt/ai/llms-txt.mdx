Se você quer que ferramentas de IA como ChatGPT, Claude ou Copilot forneçam respostas precisas sobre seu produto, elas precisam de acesso estruturado à sua documentação, não apenas do conteúdo incluído nos dados usados para treiná-las.

Todo site Jamdesk gera `llms.txt` e `llms-full.txt` de acordo com a especificação [llmstxt.org](https://llmstxt.org). As ferramentas de IA leem esses arquivos em vez de rastrear páginas individuais.

<Note>
  Atualmente, o Google audita `llms.txt` como parte das [verificações de navegação agentiva do Lighthouse](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Sites que publicam um `llms.txt` válido são mais fáceis de descobrir para agentes de IA e, cada vez mais, para o próprio Google ao classificar conteúdo destinado a respostas baseadas em IA. O Jamdesk oferece isso gratuitamente.
</Note>

<Tip>
  **Verifique sua pontuação.** Veja o quanto qualquer site de documentação está pronto para agentes com a ferramenta gratuita [AI Score](https://jamdesk.com/ai-score). A publicação de um `llms.txt` válido é uma das primeiras verificações realizadas. Também há uma [extensão AI Score para Chrome](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) que avalia sites enquanto você navega.
</Tip>

## O que o Jamdesk gera

| Arquivo | Conteúdo |
|------|---------|
| `llms.txt` | Títulos, descrições e URLs das páginas (um índice estruturado) |
| `llms-full.txt` | Conteúdo completo da documentação em um único arquivo |

O Jamdesk gera os dois arquivos durante o build e os disponibiliza pela mesma CDN usada pela sua documentação.

## Verifique seus arquivos

Confirme que os arquivos existem após o primeiro build:

<Tabs>
  <Tab title="Domínio raiz">
    Se sua documentação está na raiz do domínio (por exemplo, `docs.acme.com` ou `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="Subcaminho /docs">
    Se sua documentação está em `/docs` no site principal (como neste site, em `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## Formato do arquivo

O arquivo `llms.txt` lista cada página com seu título, descrição e URL, agrupados em seções que refletem sua navegação:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

O arquivo `llms-full.txt` contém o conteúdo Markdown completo de cada página, concatenado com limites entre páginas marcados por títulos.

## Estrutura

`llms.txt` segue a proposta [llmstxt.org](https://llmstxt.org/): um título H1,
um resumo em bloco de citação e suas abas e grupos de navegação como seções `##` de
links Markdown.

Sites multilíngues têm um índice por idioma. O `llms.txt` raiz lista seu idioma
padrão e inclui links para cada índice traduzido ao final, por exemplo
`/fr/llms.txt` para francês. Cada arquivo de idioma inclui links de volta para
seus equivalentes.

Cada idioma também recebe seu próprio arquivo com o conteúdo completo, como
`/fr/llms-full.txt`. O idioma padrão também tem um arquivo desse tipo (por exemplo,
`/en/llms-full.txt`). O `llms-full.txt` raiz ainda contém todos os idiomas.

## Diretiva para agentes em todas as páginas

Cada página também contém uma observação invisível e silenciosa para leitores de tela, direcionada a agentes de IA e apontando para `llms.txt`, e toda exportação Markdown começa com um link em bloco de citação para o índice. Agentes que acessam seu HTML encontram o caminho Markdown sem precisar rastrear o site.

## Como isso é criado

- Gerado durante o build junto com seu HTML
- Disponibilizado pela CDN com a mesma política de cache da sua documentação
- Atualizado automaticamente a cada build
- Nenhuma configuração é necessária; todas as páginas são incluídas por padrão

## Desativar llms.txt

`llms.txt` e `llms-full.txt` são publicados por padrão. Para interromper a geração deles (por exemplo, se você não quiser que ferramentas de IA incorporem seu conteúdo), defina `seo.ai.llmsTxt` como `false` no seu `docs.json`:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

No próximo build, o Jamdesk ignorará os dois arquivos, e as URLs ativas `/llms.txt` e `/llms-full.txt` retornarão `404`.

<Note>
  **A incorporação por IA e a indexação de busca são controles separados.** `seo.ai.llmsTxt` controla apenas os arquivos `llms.txt`/`llms-full.txt` lidos pelas ferramentas de IA. Isso não altera a forma como os mecanismos de busca indexam seu site; esse comportamento é controlado pelos [metadados `robots` e pelo `noindex` por página](/pt/content/seo#controlando-a-indexação). Uma página pode ser indexada pelo Google e excluída da incorporação por IA, ou o contrário.
</Note>

## Rastreadores de IA

O `robots.txt` padrão do Jamdesk permite todos os principais rastreadores de IA (Claude, ChatGPT, Copilot, Gemini). Sua documentação fica acessível às ferramentas de IA desde o início.

<Accordion title="Como llms.txt difere de sitemap.xml">
  `sitemap.xml` lista URLs para que os mecanismos de busca as rastreiem e indexem. Ele não inclui conteúdo, apenas links e metadados, como datas da última modificação.

  `llms.txt` foi projetado para modelos de IA. Ele inclui títulos e descrições das páginas e, em `llms-full.txt`, o conteúdo propriamente dito. As ferramentas de IA podem ler o arquivo completo para entender sua documentação sem fazer várias solicitações HTTP.
</Accordion>
