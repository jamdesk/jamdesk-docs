Estas estratégias funcionam com qualquer ferramenta de IA, incluindo Claude Code, Cursor, Codex e Copilot. Consulte [Claude Code](/pt/ai/claude-code), [Cursor](/pt/ai/cursor) ou [Codex](/pt/ai/codex) para a configuração específica de cada ferramenta.

## Por que o MDX funciona bem com IA

MDX é um dos formatos mais fáceis para ferramentas de IA escreverem:

- Sintaxe familiar: modelos de IA são treinados com milhões de arquivos Markdown. Eles produzem MDX válido com pouca orientação.
- Componentes estruturados: `<Card>`, `<Steps>` e `<Tabs>` têm padrões previsíveis que os modelos aprendem rapidamente.
- Texto puro: o MDX não tem formatos binários, esquemas proprietários nem artefatos de build que uma ferramenta de IA precise interpretar.

## Escreva prompts melhores

O prompt geralmente separa uma documentação de IA medíocre de uma boa. Seja específico sobre o que você quer.

<Tabs>
  <Tab title="Prompts fracos">
    ```text
    Write docs for the webhook feature.
    ```

    ```text
    Document authentication.
    ```

    ```text
    Create a getting started guide.
    ```

    Esses prompts produzem resultados genéricos e inchados. A IA não tem restrições.
  </Tab>
  <Tab title="Prompts fortes">
    ```text
    Write a page documenting our webhook feature. The reader is a developer
    integrating webhooks for the first time. Start with a 3-step quickstart,
    then cover payload format and retry behavior. Reference /src/webhooks
    for the implementation.
    ```

    ```text
    Add a troubleshooting section to the authentication page. Cover these
    three errors: expired tokens, missing scopes, and rate limits. Use
    Accordions for each error. Keep each answer under 4 lines.
    ```

    ```text
    Create a getting started guide that gets the reader from zero to a
    working hello-world in under 2 minutes. Skip the theory and background,
    and jump straight into the install command.
    ```

    Restrições produzem resultados focados. Diga à IA quem é o leitor, qual estrutura usar e o que pular.
  </Tab>
</Tabs>

### Padrões de prompting que funcionam

| Padrão | Exemplo |
|---------|---------|
| **Especifique o leitor** | "O leitor é um desenvolvedor backend que nunca usou nossa API" |
| **Nomeie a estrutura** | "Use Steps para o fluxo de configuração, depois Tabs para variantes de linguagem" |
| **Defina limites de tamanho** | "Mantenha a introdução em até 2 frases" ou "Cada resposta do accordion deve ter 3-4 linhas" |
| **Aponte para o código-fonte** | "Consulte a implementação em /src/auth para garantir precisão" |
| **Diga o que pular** | "Não explique o que é REST. Pule a teoria." |
| **Dê uma página de exemplo** | "Siga o tom e a estrutura de /quickstart" |

## Revise o conteúdo gerado pela IA

Ferramentas de IA produzem MDX estruturalmente correto na maioria das vezes. Os problemas mais sutis são tom, precisão e excesso de texto. Passe por esta checklist antes de confirmar.

### Verificação do estilo

Leia a saída em voz alta. Se soar como um chatbot, reescreva. Observe:

- Frases de preenchimento: "É importante notar que", "Isso permite que você", "A fim de"
- Ressalvas: "Você pode querer considerar", "Geralmente é recomendado"
- Transições vazias: "Agora que cobrimos X, vamos para Y"
- Jargões de marketing: "perfeitamente", "robusto", "aproveitar", "otimizar"

Corte tudo isso.

### Verificação da precisão

Ferramentas de IA produzem informações erradas com confiança. Verifique:

- Os exemplos de código funcionam de fato? Copie, cole e execute.
- As opções de configuração são reais? Confira no código-fonte.
- Os nomes dos componentes estão corretos? Use apenas [componentes que existem](/pt/components/overview).
- A página descreve o comportamento atual, não funcionalidades aspiracionais?

### Verificação da estrutura

- [ ] O frontmatter tem `title` e `description`
- [ ] Existe um parágrafo de abertura antes de qualquer heading
- [ ] A página termina com cards "What's Next?" dentro de um wrapper `<Columns>`
- [ ] Novas páginas são adicionadas à navegação do `docs.json`
- [ ] Nenhum componente inventado; apenas os da [referência de componentes](/pt/components/overview)

## Erros comuns de IA

<AccordionGroup>
  <Accordion title="Inventar componentes que não existem">
    Ferramentas de IA geram `<CodeBlock>`, `<Alert>`, `<Section>`, `<Callout>` e outros componentes que não existem no Jamdesk. Use apenas os componentes listados na [visão geral](/pt/components/overview).
  </Accordion>
  <Accordion title="Esquecer a navegação do docs.json">
    Criar uma página sem adicioná-la ao `docs.json` é o erro mais comum. A página existe, mas não aparece na barra lateral. Adicione toda nova página à navegação.
  </Accordion>
  <Accordion title="Usar callouts em excesso">
    Ferramentas de IA adoram envolver cada outro parágrafo em um `<Note>` ou `<Warning>`. Um ou dois callouts por página bastam.
  </Accordion>
  <Accordion title="Escrever demais">
    Uma página de 200 linhas gerada por IA geralmente tem 100 linhas de conteúdo real. Procure explicações repetidas, contexto desnecessário e parágrafos que dizem a mesma coisa com outras palavras. Corte sem piedade.
  </Accordion>
  <Accordion title="Descrições genéricas">
    "Este recurso poderoso permite que você..." não diz nada ao leitor. Diga o que ele faz: "Envie requisições HTTP POST para seu endpoint quando eventos forem disparados."
  </Accordion>
</AccordionGroup>

## Mantenha a documentação sincronizada

Escrever documentação é a parte fácil. Mantê-la atualizada quando o código muda é mais difícil.

<Tabs>
  <Tab title="Prompt manual">
    Peça à sua ferramenta de IA depois de lançar um recurso:

    ```text
    I just added [feature]. Update the docs to reflect this change.
    Reference the implementation in /src/[file] for accuracy.
    ```
  </Tab>
  <Tab title="Automatizado com /update-jamdesk">
    A skill `/update-jamdesk` para Claude Code analisa as mudanças no seu código e gera atualizações correspondentes na documentação. Execute-a depois de implementar recursos voltados ao usuário:

    ```text
    /update-jamdesk
    ```

    Veja [Atualizações automatizadas](/pt/ai/automated-updates) para a configuração completa.
  </Tab>
</Tabs>

```mdx
---
title: Feature Name
description: One sentence summarizing what this page covers.
---

## Quick Start

<Steps>
  <Step title="First step">What to do.</Step>
  <Step title="Second step">What to do next.</Step>
</Steps>

## How It Works

Explain the mechanics. Use code examples.

## What's Next?

<Columns cols={2}>
  <Card title="Related Page" icon="arrow-right" href="/path">
    Why the reader would go here next

</Columns>
```

</Prompt>
