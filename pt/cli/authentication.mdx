A CLI faz login na sua conta Jamdesk pelo navegador. Faça login antes de fazer o deploy.

## Login

```bash
jamdesk login
```

Isso abre o dashboard do Jamdesk no seu navegador. O fluxo:

1. A CLI inicia um servidor HTTP local em `127.0.0.1:9876` (usa uma porta atribuída pelo sistema operacional se a 9876 estiver ocupada)
2. Seu navegador abre em `dashboard.jamdesk.com/cli-auth`
3. Você se autentica usando qualquer método de login do dashboard (e-mail/senha, Google, GitHub)
4. O dashboard envia suas credenciais de volta ao servidor local da CLI
5. As credenciais são armazenadas em `~/.jamdeskrc`

A CLI verifica um parâmetro de estado no callback para prevenir falsificação de requisição entre sites (CSRF). O fluxo de login expira após 2 minutos.

```bash Expected output
$ jamdesk login
ℹ Open this URL in your browser to log in:

  https://dashboard.jamdesk.com/cli-auth?port=9876&state=abc123...

ℹ Waiting for authentication...
✔ Logged in as you@example.com
```

**Ambientes headless e SSH**: A CLI sempre imprime a URL no terminal, mesmo quando não consegue abrir um navegador. Cole a URL em qualquer navegador.

## Logout

```bash
jamdesk logout
```

Limpa as credenciais armazenadas em `~/.jamdeskrc`. Não faz nada se você não estiver logado.

```bash Expected output
$ jamdesk logout
✔ Logged out (you@example.com)
```

## Whoami

```bash
jamdesk whoami
```

Mostra o e-mail com o qual você está logado. Ele atualiza o token para validar a sessão. Nunca lê um cache local.

Estados possíveis:

<CodeGroup>
```bash Logged in
$ jamdesk whoami
✔ Logged in as you@example.com
```

```bash Session expired
$ jamdesk whoami
⚠ Logged in as you@example.com (session expired)
  Run `jamdesk login` to re-authenticate.
```

```bash Not logged in
$ jamdesk whoami
ℹ Not logged in. Run `jamdesk login` to authenticate.
```
</CodeGroup>

## Como funcionam as sessões

As credenciais são armazenadas em `~/.jamdeskrc` como JSON com permissões `0600` (somente leitura e escrita pelo proprietário):

```json ~/.jamdeskrc
{
  "auth": {
    "refreshToken": "AGK...",
    "email": "you@example.com",
    "uid": "abc123",
    "expiresAt": 1700000000000
  }
}
```

A CLI usa uma arquitetura de **refresh token + ID token**:

- **Os ID tokens** expiram em cerca de 1 hora e são usados nas chamadas de API
- A CLI **renova automaticamente** os ID tokens com o refresh token armazenado 5 minutos antes da expiração
- Os refresh tokens têm longa duração, mas podem ser revogados (troca de senha, exclusão da conta)
- A CLI limpa a autenticação armazenada quando o refresh token é permanentemente inválido (`TOKEN_EXPIRED`, `USER_NOT_FOUND`, `INVALID_REFRESH_TOKEN`)

A CLI renova os tokens em todo comando autenticado. Você nunca precisa renová-los manualmente.

## Solução de problemas

<AccordionGroup>
  <Accordion title="O login expira após 2 minutos">
    Um firewall pode estar bloqueando o servidor de callback local da CLI. Copie a URL impressa e abra-a no seu navegador.

    A CLI escolhe outra porta quando outro processo usa a 9876. Verifique a URL na saída do terminal.
  </Accordion>

  <Accordion title='"Session expired" em todo comando'>
    Seu refresh token não é mais válido. Isso acontece após trocas de senha ou longos períodos de inatividade.

    Execute `jamdesk login` para obter uma nova sessão.
  </Accordion>

  <Accordion title="O navegador não abre">
    Ambientes headless (SSH, Docker, CI) não conseguem abrir um navegador. Copie a URL do terminal e abra-a em qualquer navegador que consiga alcançar a porta de callback da sua máquina.
  </Accordion>

  <Accordion title='"Not logged in" logo após fazer login'>
    Verifique se `~/.jamdeskrc` existe e contém uma chave `auth`:

    ```bash
    cat ~/.jamdeskrc
    ```

    As permissões do arquivo devem ser `0600`. Um arquivo ausente pode indicar um problema de permissão no seu diretório home. Verifique com `ls -la ~`.
  </Accordion>
</AccordionGroup>

Para mais solução de problemas da CLI, consulte o [guia da CLI na Central de ajuda](/pt/help/troubleshooting/cli-issues).
