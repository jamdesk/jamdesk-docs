A CLI Jamdesk permite visualizar a documentação localmente, validar a configuração, verificar links quebrados e migrar de outras plataformas. Ela é de código aberto sob a [Licença Apache 2.0](https://github.com/jamdesk/jamdesk-cli).

## Instalação

<Tabs>
  <Tab title="npm (Recomendado)">
    Instale globalmente pelo [npm](https://www.npmjs.com/package/jamdesk) para usar `jamdesk` de qualquer lugar:

    ```bash
    npm install -g jamdesk
    ```
  </Tab>
  <Tab title="Homebrew (macOS/Linux)">
    Instale com o Homebrew:

    ```bash
    brew tap jamdesk/tap
    brew install jamdesk
    ```
  </Tab>
  <Tab title="curl (macOS/Linux)">
    Instale via script:

    ```bash
    curl -fsSL https://get.jamdesk.com | bash
    ```

    Atualize ou desinstale:

    ```bash
    curl -fsSL https://get.jamdesk.com/upgrade | bash
    curl -fsSL https://get.jamdesk.com/uninstall | bash
    ```
  </Tab>
  <Tab title="PowerShell (Windows)">
    Instale via script:

    ```powershell
    iwr https://get.jamdesk.com/win | iex
    ```

    Atualize ou desinstale:

    ```powershell
    iwr https://get.jamdesk.com/upgrade | iex
    iwr https://get.jamdesk.com/uninstall | iex
    ```
  </Tab>
  <Tab title="npx">
    Execute sem instalar:

    ```bash
    npx jamdesk dev
    ```
  </Tab>
</Tabs>

Verifique a instalação:

```bash
jamdesk --version
```

### Requisitos

- **Node.js** v20.0.0 ou superior
- **npm** v8 ou superior (recomendado)

## Início rápido

<Steps>
  <Step title="Crie um projeto">
    Crie um novo projeto de documentação:

    ```bash
    jamdesk init my-docs
    cd my-docs
    ```
  </Step>
  <Step title="Inicie o servidor de desenvolvimento">
    Execute o servidor de desenvolvimento local com recarregamento automático:

    ```bash
    jamdesk dev
    ```

    Sua documentação ficará disponível em **http://localhost:3000/docs**
  </Step>
  <Step title="Valide antes de implantar">
    Verifique erros de configuração, links quebrados e ortografia:

    ```bash
    jamdesk validate
    jamdesk broken-links
    jamdesk fix --dry-run
    jamdesk fix
    jamdesk spellcheck
    ```
  </Step>
</Steps>

## Comandos

Execute `jamdesk <command> --help` para ver os detalhes de qualquer comando.

### Desenvolvimento

<Accordion title="jamdesk dev" icon="play" defaultOpen>
  Inicie o servidor de desenvolvimento local com recarregamento automático.

  ```bash
  jamdesk dev
  jamdesk dev --port 3001
  ```

  **Recursos:**
  - Validação automática na inicialização (schema do docs.json, sintaxe MDX e especificações OpenAPI referenciadas. Uma especificação inválida interrompe o servidor.)
  - Recarregamento automático ao alterar arquivos MDX
  - Reconstrução automática da navegação ao alterar o docs.json
  - CSS personalizado (`style.css`) recarregado ao atualizar o navegador
  - Busca
  - Todos os temas e componentes

  **Opções:**

  | Flag | Descrição |
  |------|-------------|
  | `-p, --port <port>` | Porta em que o servidor será executado (padrão: 3000) |
  | `-v, --verbose` | Ativa a saída detalhada |
</Accordion>

<Accordion title="jamdesk init" icon="folder-plus">
  Crie um novo projeto de documentação.

  ```bash
  jamdesk init              # Interactive mode
  jamdesk init my-docs      # Create in new directory
  ```

  Isso cria um novo projeto com:
  - Arquivo de configuração `docs.json`
  - Páginas MDX de exemplo
  - Estrutura de pastas recomendada
</Accordion>

### Validação

<Accordion title="jamdesk validate" icon="check">
  Valide a configuração do `docs.json`, a sintaxe MDX e as especificações OpenAPI.

  ```bash
  jamdesk validate
  jamdesk validate --skip-mdx
  ```

  **Verifica:**
  - Sintaxe JSON válida no docs.json
  - Campos obrigatórios (name, navigation)
  - Valores de tema válidos
  - Erros de sintaxe MDX (por exemplo, caracteres `<` sem escape)
  - Validação de especificações OpenAPI (se configurada)
  - Conformidade com o schema

  **Opções:**

  | Flag | Descrição |
  |------|-------------|
  | `--skip-mdx` | Pula a validação de sintaxe MDX |
  | `-v, --verbose` | Mostra a saída detalhada da validação |

  Execute isso antes de implantar para identificar erros cedo.
</Accordion>

<Accordion title="jamdesk broken-links" icon="link-slash">
  Verifique sua documentação em busca de links internos quebrados.

  ```bash
  jamdesk broken-links
  ```

  **Exemplo de saída:**
  ```text
  docs/getting-started.mdx:15 - /docs/quikstart
    Did you mean: /docs/quickstart

  Found 1 broken link in 45 files.
  ```

  Detecta links para páginas inexistentes e erros de digitação. Consulte [Links e navegação](/pt/content/links#como-os-links-internos-são-detectados) para mais detalhes.
</Accordion>

<Accordion title="jamdesk fix" icon="wrench">
  Corrige automaticamente avisos de links internos quebrados que têm um destino inequívoco. Corrige dois tipos:
  - **Âncoras com erro de digitação**: um fragmento como `#instalation` que claramente deveria ser `#installation`
  - **Desvio de âncora entre idiomas**: uma página traduzida renomeou seus títulos, mas os links nesse idioma ainda apontam para o fragmento antigo em inglês

  ```bash
  # Preview what would change without touching any files
  jamdesk fix --dry-run

  # Apply fixes (prompts for confirmation)
  jamdesk fix
  ```

  **Exemplo de saída do dry-run:**
  ```text
  Planned fixes:

    fr/ai/overview.mdx:9
      /fr/ai/selectors#ai-strategies  →  /fr/ai/selectors#stratégies-ia

  (dry run — no files written)
  ```

  `jamdesk fix` só grava uma correção quando a âncora corrigida corresponde a um título real na página de destino. Casos ambíguos são deixados para revisão manual.

  **Opções:**

  | Flag | Descrição |
  |------|-------------|
  | `--dry-run` | Visualiza as correções planejadas sem gravar arquivos |
  | `-y, --yes` | Aplica as correções sem pedir confirmação |
  | `--types <list>` | Tipos de aviso separados por vírgula a corrigir (padrão: todos os suportados) |
  | `--no-ai` | Ignora as correções com IA e usa apenas as correções que o Jamdesk consegue determinar sem IA |
  | `--project <id>` | ID do projeto para as correções com IA (padrão: `projectId` no `docs.json`) |
  | `--json` | Imprime o plano de correção e os problemas que não pode corrigir em JSON, para um agente de IA. Não grava arquivos nem faz perguntas. Requer CLI 1.1.229 ou superior |

  <Card title="Guia de correção de links quebrados" icon="wrench" href="/pt/cli/fix-broken-links">
    Passo a passo: visualizar, aplicar, revisar e fazer commit
  </Card>
</Accordion>

<Accordion title="jamdesk ai-fix" icon="wand-magic-sparkles">
  Mostra ou altera a configuração **AI Fixes** do projeto, a mesma das Configurações no painel.

  ```bash
  # Show the current setting
  jamdesk ai-fix

  # Commit fixes to your build branch after each build
  jamdesk ai-fix auto

  # Suggest fixes for you to review in the dashboard
  jamdesk ai-fix review

  # Turn off dashboard scans
  jamdesk ai-fix off
  ```

  **Exemplo de saída:**
  ```text
  ✓ AI Fixes set to Auto-fix
  Jamdesk commits fixes to main after the next build. Pull before you push. Undo runs from the dashboard.
  ```

  Execute `jamdesk login` primeiro. O comando usa o `projectId` do `docs.json`, ou o projeto que você passar com `--project`. Requer CLI 1.1.229 ou superior.

  | Flag | Descrição |
  |------|-------------|
  | `--project <id>` | ID do projeto (padrão: `projectId` no `docs.json`) |

  <Card title="Corrigir com IA" icon="wand-magic-sparkles" href="/pt/builds/fix-with-ai#escolha-o-que-acontece">
    O que cada modo faz e como desfazer uma correção automática
  </Card>
</Accordion>

<Accordion title="jamdesk spellcheck" icon="spell-check">
  Verifique a sua documentação em busca de erros de ortografia.

  ```bash
  jamdesk spellcheck
  ```

  **Exemplo de saída:**
  ```text
  getting-started.mdx:14 - "recieve"
    └─ Did you mean: receive

  Found 3 misspellings across 24 pages.
  Tip: Run "jamdesk spellcheck --fix" to interactively fix or ignore words.
  ```

  Usa um dicionário de inglês com mais de 150 termos técnicos embutidos (API, GraphQL, Kubernetes, React etc.). Ignora blocos de código, código inline, frontmatter, JSX, URLs e caminhos de arquivo. Por enquanto, apenas inglês. Dicionários em outros idiomas estão planejados.

  **Opções:**

  | Flag | Descrição |
  |------|-------------|
  | `--fix` | Corrige interativamente os erros de ortografia ou adiciona à lista de ignorados |
  | `--json` | Saída em JSON (para pipelines de CI) |
  | `-v, --verbose` | Mostra cada arquivo à medida que é verificado |

  **Modo de correção interativo (`--fix`)** percorre cada palavra com erro de ortografia única:

  ```text
  1/10  "recieve" — found in 3 files
        intro.mdx:14, setup.mdx:7, guide.mdx:22

  ? What do you want to do?
  ❯ Fix → receive (recommended)
    Fix → relieve
    Ignore in the future (add to docs.json)
    Skip
  ```

  - **Fix** substitui a palavra por uma sugestão em todos os arquivos. Nunca altera blocos de código nem atributos JSX. O prompt mostra até 3 sugestões e marca a melhor como recomendada.
  - **Ignore** adiciona a palavra a `spellcheck.ignore` no seu docs.json. A palavra não será mais marcada.
  - **Skip** não faz nada nesta execução

  Você pode visualizar e confirmar as alterações antes de elas serem aplicadas.

  **Lista de ignorados personalizada:** adicione termos específicos do projeto ao seu docs.json:

  ```json docs.json
  {
    "spellcheck": {
      "ignore": ["YourProduct", "kubectl", "Terraform"]
    }
  }
  ```

  O spellcheck ignora o nome do seu projeto no `docs.json`.
</Accordion>

<Accordion title="jamdesk openapi-check" icon="file-code">
  Valide um único arquivo de especificação OpenAPI.

  ```bash
  jamdesk openapi-check openapi.yaml
  jamdesk openapi-check api/spec.json
  ```

  **Valida:**
  - Sintaxe YAML/JSON válida
  - Conformidade com o schema OpenAPI 3.x
  - Definições de endpoints
  - Referências `$ref` resolvidas corretamente
</Accordion>

<Note>
  **O Jamdesk valida especificações OpenAPI em três lugares.** O `jamdesk dev` interrompe a inicialização se uma especificação referenciada for inválida. O `jamdesk validate` e o `jamdesk openapi-check` verificam as especificações sob demanda. O build na nuvem verifica as especificações referenciadas no deploy, onde uma especificação inválida gera um **aviso não fatal**. O restante da documentação continua sendo publicado. O e-mail e a lista de builds no painel indicam o problema: um erro de análise com linha e coluna, um `$ref` não resolvido ou um `operationId` duplicado. Corrija a especificação e envie novamente para limpar o aviso.
</Note>

### Gerenciamento de arquivos

<Accordion title="jamdesk rename" icon="file-pen">
  Renomeie uma página e atualize todas as referências a ela.

  ```bash
  jamdesk rename docs/old-name.mdx docs/new-name.mdx
  ```

  **Isso irá:**
  - Renomear o arquivo
  - Atualizar a navegação do docs.json
  - Atualizar os links em todos os outros arquivos MDX
  - Atualizar as referências de snippets

  Use isso em vez de renomear manualmente. As referências ficam sincronizadas.
</Accordion>

### Migração

<Accordion title="jamdesk migrate" icon="right-left">
  Migre a documentação do Mintlify para o Jamdesk.

  ```bash
  jamdesk migrate
  ```

  Detecta sua configuração do Mintlify e a converte para o formato Jamdesk. A mesma execução também:

  - Renomeia componentes obsoletos (por exemplo, `CardGroup` → `Columns`)
  - Move arquivos MDX de snippets órfãos para `/snippets/` e reescreve importações relativas ao diretório pai
  - Extrai componentes inline que usam hooks do React para `/snippets/<name>.tsx` com `'use client'`
  - Corrige problemas mecânicos de sintaxe MDX

  O comando é idempotente. Executá-lo novamente é seguro.

### Implantação

<Accordion title="jamdesk pull" icon="cloud-arrow-down">
  Baixe um projeto cuja documentação o Jamdesk hospeda (sem GitHub) como um repositório git, ou mescle novas alterações do Jamdesk em uma cópia que você já baixou.

  ```bash
  jamdesk pull
  jamdesk pull --project your-project
  jamdesk pull --dir ./docs-copy
  ```

  Edite os arquivos e depois execute `jamdesk deploy` nessa pasta para publicá-los. Requer CLI 1.1.227 ou superior e git.

  | Flag | Descrição |
  |------|-------------|
  | `--project <id-or-slug>` | Baixa um projeto específico (pula a seleção interativa) |
  | `--dir <path>` | Pasta de destino (padrão: `./<slug>`) |
  | `--force` | Transforma uma pasta que já tem arquivos, como uma cópia antiga somente leitura, em uma cópia git. Os arquivos dela permanecem como alterações não commitadas |

  <Card title="Edite no seu computador" icon="laptop" href="/pt/setup/without-github#editar-no-seu-computador">
    Publicação, mesclagem de alterações do Jamdesk, conflitos e arquivos que o deploy recusa
  </Card>
</Accordion>

<Accordion title="jamdesk deploy" icon="cloud-arrow-up">
  Envie sua documentação e dispare um build pelo terminal.

  ```bash
  jamdesk deploy
  jamdesk deploy --detach
  jamdesk deploy --full-rebuild
  ```

  A CLI mostra cada fase do build à medida que ela é concluída. Também disponível como `jamdesk push`.

  | Flag | Descrição |
  |------|-------------|
  | `--detach` | Enfileira e encerra imediatamente |
  | `--full-rebuild` | Força um build completo (sem cache) |
  | `--project <id>` | Implanta em um projeto específico |
  | `--allow-empty` | Permite implantar sem páginas de conteúdo `.mdx` (recusado por padrão) |
  | `-m, --message <text>` | Mensagem de commit pasta criada por `jamdesk pull` |
  | `--allow-secret-files` | Publica arquivos com aparência de segredo de uma pasta criada por `jamdesk pull` |

  <Card title="Guia de deploy pela CLI" icon="cloud-arrow-up" href="/pt/cli/deploy">
    Pipeline completo de implantação, fases do build, referência de erros e solução de problemas
  </Card>
</Accordion>

<Accordion title="jamdesk deploy-proxy cloudflare" icon="cloud">
  Gere a estrutura e implante um Cloudflare Worker que faz proxy de `/docs` no seu próprio domínio para o seu site Jamdesk.

  ```bash
  jamdesk deploy-proxy cloudflare
  jamdesk deploy-proxy cloudflare --slug myproject --domain example.com --yes
  ```

  O comando é interativo por padrão. Ele verifica o Wrangler, valida sua conta Cloudflare, detecta seu slug a partir do `docs.json`, gera os arquivos do Worker e oferece a opção de implantar. `--yes` apenas gera os arquivos e para. Implante-os com `npx wrangler deploy` no diretório de saída.

  | Flag | Descrição |
  |------|-------------|
  | `--slug <slug>` | Slug do projeto Jamdesk |
  | `--domain <domain>` | Domínio de destino (por exemplo, `example.com`) |
  | `--path <path>` | Prefixo do caminho (padrão: `/docs`) |
  | `--output-dir <dir>` | Diretório de saída (padrão: `cloudflare-worker/`) |
  | `--skip-deploy` | Pula a pergunta "implantar agora?" em uma execução interativa |
  | `--force` | Sobrescreve o diretório de saída se ele já existir |
  | `--yes` | Responde a todas as perguntas com o padrão (modo CI). Nunca implanta e nunca sobrescreve um diretório existente |

### Manutenção

<Accordion title="jamdesk doctor" icon="stethoscope">
  Verifique seu ambiente e diagnostique problemas.

  ```bash
  jamdesk doctor
  ```

  **Verificações:**
  - Versão do Node.js (requer v20+)
  - Versão do npm
  - docs.json existe e é válido
  - Status do cache ~/.jamdesk
  - Permissões de escrita

  Execute isso quando a CLI apresentar comportamento inesperado.
</Accordion>

<Accordion title="jamdesk clean" icon="broom">
  Limpe o diretório de cache ~/.jamdesk.

  ```bash
  jamdesk clean
  ```

  Isso remove dependências em cache e artefatos de build. Use para:
  - Liberar espaço em disco
  - Corrigir um cache corrompido
  - Forçar a reinstalação das dependências

  O próximo `jamdesk dev` reinstala as dependências.
</Accordion>

<Accordion title="jamdesk update" icon="arrow-up">
  Atualize a CLI para a versão mais recente.

  ```bash
  jamdesk update
  ```

  Você também pode atualizar manualmente:

  ```bash
  npm update -g jamdesk
  ```
</Accordion>

## Configuração

Crie `~/.jamdeskrc` para definir opções padrão:

```json
{
  "defaultPort": 3001,
  "verbose": false,
  "checkUpdates": true
}
```

| Opção | Tipo | Padrão | Descrição |
|--------|------|---------|-------------|
| `defaultPort` | number | 3000 | Porta padrão do servidor de desenvolvimento |
| `verbose` | boolean | false | Ativa a saída detalhada por padrão |
| `checkUpdates` | boolean | true | Verifica atualizações da CLI na inicialização |

## Solução de problemas

<AccordionGroup>
  <Accordion title="Erros de sintaxe MDX">
    O MDX é interpretado como JSX. Alguns caracteres têm significado especial.

    **Problema comum:** o caractere `<` é interpretado como o início de uma tag JSX.

    ```text
    ✗ Found 1 MDX syntax error(s)

      getting-started.mdx:42
        Unexpected character `5` (U+0035) before name
        Fix: A < character is being parsed as JSX. Use &lt; or rewrite
    ```

    **Soluções:**
    - Use `&lt;` para o símbolo de menor que literal: `Values &lt;50% are low`
    - Reescreva para evitar o caractere: `"Below 50%"` em vez de `"<50%"`
    - Execute `jamdesk validate` para mensagens de erro detalhadas com números de linha
  </Accordion>

  <Accordion title="docs.json não encontrado">
    Execute o comando a partir de um diretório que contenha um arquivo `docs.json`.

    **Soluções:**
    - Execute `jamdesk init` para criar um novo projeto
    - Verifique se você está no diretório correto
    - Confirme que o arquivo se chama exatamente `docs.json` (não `doc.json` ou similar)
  </Accordion>

  <Accordion title="O servidor de desenvolvimento não inicia">
    **Tente estes passos:**
    1. Execute `jamdesk doctor` para verificar seu ambiente
    2. Execute `jamdesk clean` para limpar o cache
    3. Use `jamdesk dev --verbose` para uma saída de erro detalhada
    4. Verifique se o Node.js v20+ está instalado: `node --version`
  </Accordion>

  <Accordion title="Primeira execução lenta">
    A primeira execução instala as dependências em `~/.jamdesk/node_modules`.

    Isso acontece apenas uma vez. As execuções seguintes são mais rápidas.
  </Accordion>

  <Accordion title="Porta já em uso">
    Outro processo está usando a porta padrão.

    **Soluções:**
    ```bash
    # Use a different port
    jamdesk dev --port 3001

    # Or set a default in ~/.jamdeskrc
    { "defaultPort": 3001 }
    ```
  </Accordion>

  <Accordion title="Erros de permissão negada">
    Você pode não ter permissão de escrita no diretório de cache.

    **Soluções:**
    1. Verifique as permissões de `~/.jamdesk`: `ls -la ~/.jamdesk`
    2. Corrija a propriedade: `sudo chown -R $(whoami) ~/.jamdesk`
    3. Execute `jamdesk clean` e tente novamente
  </Accordion>
</AccordionGroup>

**Ainda com problemas?** Consulte o [guia de solução de problemas da CLI](/pt/help/troubleshooting/cli-issues) ou [abra uma issue no GitHub](https://github.com/jamdesk/jamdesk-cli/issues).
