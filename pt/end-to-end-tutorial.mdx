Vá de um repositório vazio até um site de documentação no ar. Pule as etapas que você já fez.

## Pré-requisitos

- Uma conta no GitHub
- Um repositório com conteúdo de documentação (ou use o [Starter Template](https://github.com/jamdesk/starter-docs))
- Node.js 20+ se quiser instalar a CLI com npm

<Steps>
  <Step title="Crie um projeto e conecte o GitHub">
    Crie um projeto no dashboard do Jamdesk e conecte um repositório.

    - Siga [Criando projetos](/pt/setup/creating-projects) para definir o nome do projeto, o slug e o caminho da documentação
    - Se solicitado, instale o GitHub App e conceda acesso ao repositório ([Conectando o GitHub](/pt/setup/connecting-github))
  </Step>

  <Step title="Edite e visualize páginas com a CLI">
    Visualize as edições das páginas com a CLI do Jamdesk antes de enviá-las ao GitHub.

    <Tabs>
      <Tab title="npm">
        ```bash
        npm install -g jamdesk
        cd your-docs
        jamdesk dev
        ```
      </Tab>
      <Tab title="npx">
        ```bash
        cd your-docs
        npx jamdesk dev
        ```
      </Tab>
    </Tabs>

    Sua visualização local fica em **http://localhost:3000**. Saiba mais em [Visualização local](/pt/development/local-preview).

    Abra uma página `.mdx` no seu editor. Salve uma alteração e atualize a visualização local. Publique-a com o fluxo do Git na próxima etapa.
  </Step>

  <Step title="Faça o deploy enviando para o GitHub">
    Cada push para a branch configurada dispara um build. O build é publicado no seu subdomínio Jamdesk.

    ```bash
    git add .
    git commit -m "Add docs content"
    git push origin main
    ```

    Substitua `main` pela branch configurada no seu projeto.

    Sua documentação entra no ar em `your-project.jamdesk.app` quando o build terminar. Veja [Deployment](/pt/development/deployment) para mais detalhes.
  </Step>

  <Step title="Opcional: adicione um domínio personalizado">
    Sirva sua documentação a partir do seu próprio domínio, em vez do subdomínio Jamdesk.

    1. Acesse **Settings** → **Domains** no dashboard do Jamdesk
    2. Adicione seu domínio (por exemplo, `docs.example.com`)
    3. Crie os registros DNS exibidos no dashboard
    4. Aguarde a verificação e a conclusão do SSL

    Para solução de problemas, veja [Domínios personalizados](/pt/deploy/custom-domains).
  </Step>
</Steps>

## Valide o fluxo de ponta a ponta

- Seu subdomínio Jamdesk carrega e mostra o build mais recente
- A visualização local reflete o mesmo conteúdo e a mesma navegação
- Se configurado, o domínio personalizado está verificado e servindo HTTPS
- O histórico de builds mostra o commit mais recente e a autoria

## Opcional: hospede em /docs

Para servir a documentação em um subcaminho como `example.com/docs`, veja [Visão geral de deploy](/pt/deploy/overview) e [Hospedagem em subcaminho](/pt/deploy/subpath-hosting).
