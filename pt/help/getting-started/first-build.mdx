## Builds automáticos

A Jamdesk inicia seu primeiro build assim que você conecta um repositório. Cada push posterior para a branch conectada dispara um novo build.

## Progresso do build

Acompanhe seu build no painel:

<Steps>
  <Step title="Na fila">
    Seu build está aguardando para começar. Em horários de pico, pode haver uma breve fila.
  </Step>
  <Step title="Clonando">
    A Jamdesk baixa o conteúdo do seu repositório do GitHub.
  </Step>
  <Step title="Validando">
    A Jamdesk verifica seu `docs.json` e seus arquivos MDX em busca de erros.
  </Step>
  <Step title="Construindo">
    A Jamdesk compila o MDX para HTML com realce de sintaxe e um índice de busca.
  </Step>
  <Step title="Implantando">
    Os arquivos gerados são enviados para a CDN global.
  </Step>
  <Step title="Ao vivo">
    Sua documentação está disponível na URL do seu projeto.
  </Step>
</Steps>

## Visualizar sua documentação online

Clique em **View Site** no painel ou acesse `https://your-project.jamdesk.app`.

Sua documentação também aparece no seu domínio personalizado, caso você tenha configurado um.

## Novo build manual

Reconstrua sem enviar alterações:

1. Acesse seu projeto no [painel](https://dashboard.jamdesk.com)
2. Abra **Settings**
3. Clique em **Rebuild**

Use isso depois de alterar variáveis de ambiente ou para forçar um build novo.

## Se o build falhar

O painel mostra uma mensagem de erro para um build com falha. Causas comuns:

- Sintaxe inválida no `docs.json`
- Erros de sintaxe no MDX
- Páginas referenciadas na navegação que não existem
