Seu primeiro build é iniciado automaticamente quando você conecta um repositório.

## Builds automáticos

Quando você conecta um repositório, o Jamdesk inicia imediatamente um build inicial. Cada push posterior para sua branch conectada inicia automaticamente um novo build.

## Progresso do build

Acompanhe seu build no dashboard:

<Steps>
  <Step title="Na fila">
    Seu build está aguardando para começar. Em períodos de pico, pode haver uma breve fila.
  </Step>
  <Step title="Clonando">
    O Jamdesk obtém o conteúdo do seu repositório no GitHub.
  </Step>
  <Step title="Validando">
    Seu `docs.json` e seus arquivos MDX são validados em busca de erros.
  </Step>
  <Step title="Compilando">
    O MDX é compilado em HTML otimizado, com destaque de sintaxe e indexação de pesquisa.
  </Step>
  <Step title="Fazendo deploy">
    Os arquivos compilados são enviados para a CDN global.
  </Step>
  <Step title="Online">
    Sua documentação está disponível no URL do projeto.
  </Step>
</Steps>

## Visualizar sua documentação online

Quando o build for concluído, clique em **View Site** no dashboard ou acesse `https://your-project.jamdesk.app`.

Se você configurou um domínio personalizado, sua documentação também estará disponível nele.

## Novo build manual

Precisa fazer um novo build sem enviar alterações?

1. Acesse seu projeto no [dashboard](https://dashboard.jamdesk.com)
2. Abra **Settings**
3. Clique em **Rebuild**

Use esta opção depois de alterar variáveis de ambiente ou para forçar um novo build.

## Se o build falhar

As falhas de build exibem uma mensagem de erro no dashboard. Causas comuns:

- Sintaxe inválida em `docs.json`
- Erros de sintaxe MDX
- Páginas ausentes referenciadas na navegação
