Encontre seu erro de CLI em uma das seções abaixo.

## Problemas de autenticação

<AccordionGroup>
  <Accordion title='"Not logged in" ou "Session expired"'>
    Suas credenciais armazenadas estão ausentes ou o refresh token não é mais válido.

    **Correção:** Execute `jamdesk login` para iniciar uma nova sessão. Isso substitui o conteúdo de `~/.jamdeskrc`.

    Se o erro continuar aparecendo logo após o login, verifique se `~/.jamdeskrc` foi gravado:

    ```bash
    cat ~/.jamdeskrc
    ```

    O arquivo deve conter um objeto `auth` com `refreshToken`, `email` e `uid`. Se estiver vazio ou ausente, seu diretório home pode ter problemas de permissão.
  </Accordion>

  <Accordion title="Login times out">
    A CLI inicia um servidor local na porta 9876 para receber o callback de autenticação do seu navegador. O login expira se o callback não chegar em 2 minutos.

    **Causas comuns:**
    - Um firewall está bloqueando o servidor local
    - A aba do navegador foi fechada antes de concluir a autenticação
    - A porta 9876 está em uso (a CLI escolhe automaticamente outra porta, mas a URL precisa corresponder)

    **Correção:** Copie a URL exibida no terminal e abra-a manualmente. Verifique se o número da porta na URL corresponde à porta em que a CLI está escutando.
  </Accordion>

  <Accordion title="Browser doesn't open during login">
    Comportamento normal em ambientes headless (sessões SSH, contêineres Docker, runners de CI). A CLI sempre exibe a URL de login no terminal.

    Copie-a e abra em qualquer navegador que consiga acessar sua máquina na porta de callback.
  </Accordion>

  <Accordion title='"session expired" após alteração de senha'>
    Alterar sua senha do Jamdesk invalida todos os refresh tokens existentes. A CLI detecta isso (`TOKEN_EXPIRED` ou `INVALID_REFRESH_TOKEN`) e limpa automaticamente a autenticação armazenada.

    Execute `jamdesk login` novamente.
  </Accordion>
</AccordionGroup>

## Erros de deploy

<AccordionGroup>
  <Accordion title='"A build is already in progress"'>
    Apenas uma build é executada por vez em cada projeto. A CLI retorna este erro (código `BUILD_IN_PROGRESS`) quando uma build está na fila ou em execução.

    **Correção:** Aguarde a build atual terminar. Verifique **Deployments** no dashboard para ver o status. Se uma build parecer travada, peça ao proprietário do projeto para verificar o dashboard.
  </Accordion>

  <Accordion title='"docs.json not found or invalid"'>
    Não há `docs.json` no diretório atual, ou ele contém erros de sintaxe JSON.

    **Correção:**
    1. Certifique-se de estar no diretório correto: `ls docs.json`
    2. Execute `jamdesk validate` para detalhes específicos do erro
    3. Verifique vírgulas ausentes, colchetes não fechados ou vírgulas finais (a CLI usa JSON, não JSON5, para o `docs.json`)
  </Accordion>

  <Accordion title='"Upload too large"'>
    Seu tarball compactado excede o limite de 100 MB. Tudo o que não for excluído pelo `.gitignore` ou pela lista de exclusão integrada é empacotado.

    **Correção:** Verifique o que está sendo incluído. Causas comuns: arquivos de vídeo, PDFs grandes, imagens não compactadas, dumps de dados. Adicione-os ao `.gitignore`.

    Sempre excluídos, independentemente do `.gitignore`: `.git`, `node_modules`, `.next`, `.env*`, `*.pem`, `*.key`, `credentials.json`, `.DS_Store`.
  </Accordion>

  <Accordion title='"No files to deploy"'>
    Todos os arquivos correspondem a um padrão de exclusão.

    **Correção:** Verifique se seu `.gitignore` não exclui arquivos MDX nem o `docs.json`.
  </Accordion>

  <Accordion title='"Project not found" ou "Access denied"'>
    Ou o `projectId` no `docs.json` não corresponde a nenhum projeto da sua conta, ou você não é membro desse projeto.

    **Correção:**
    - Remova o campo `projectId` do `docs.json` e execute `jamdesk deploy` novamente para escolher um novo projeto
    - Verifique se você está logado com a conta correta: `jamdesk whoami`
    - Confira a participação no projeto no dashboard
  </Accordion>

  <Accordion title="Deploy hangs during build polling">
    A CLI consulta o status da build a cada 2 segundos. Ela desiste após 3 falhas consecutivas de consulta.

    **Correção:** Pressione Ctrl+C. A build continua executando em segundo plano. Verifique o status no dashboard. A CLI exibe um link ao sair.
  </Accordion>

  <Accordion title="Build failed">
    O upload foi concluído, mas a build falhou. O terminal mostra o erro do serviço de build.

    **Correção:** Verifique o log da build no dashboard em **Deployments**. Causas comuns: erros de sintaxe MDX, páginas ausentes referenciadas na navegação, especificações OpenAPI inválidas. Execute `jamdesk validate` localmente para detectar esses problemas antes do deploy.
  </Accordion>

  <Accordion title="Secret file warnings">
    A CLI alerta sobre arquivos que parecem segredos (`.env`, `*.pem`, `*.key`, `credentials.json`, arquivos que começam com `secret`). O aviso não bloqueia o deploy.

    **Correção:** Adicione os arquivos ao `.gitignore` para excluí-los dos uploads. Se forem intencionais (por exemplo, arquivos de chave de exemplo na sua documentação), ignore o aviso.
  </Accordion>
</AccordionGroup>

## Problemas do servidor de desenvolvimento

<AccordionGroup>
  <Accordion title="Dev server won't start">
    **Tente nesta ordem:**
    1. `jamdesk doctor` para verificar a versão do Node.js (v20+ necessária) e o ambiente
    2. `jamdesk clean` para limpar as dependências em cache
    3. `jamdesk dev --verbose` para saída detalhada de erros
    4. `jamdesk dev --clean` para limpar o cache de build antes de iniciar
  </Accordion>

  <Accordion title="Port already in use">
    A CLI tenta 10 portas consecutivas a partir da porta solicitada (padrão 3000). Se todas as 10 estiverem ocupadas, ela falha.

    **Correção:**
    ```bash
    # Find what's using the port
    lsof -i :3000

    # Pick a different port
    jamdesk dev --port 3001
    ```

    Defina um padrão permanente adicionando `"defaultPort": 3001` ao seu arquivo `~/.jamdeskrc`. Não sobrescreva o arquivo, pois ele pode conter suas credenciais de autenticação.
  </Accordion>

  <Accordion title="Turbopack cache corruption">
    Encerrar o servidor de desenvolvimento no meio da compilação (força de encerramento, falha do sistema) pode corromper o cache `.next`. A próxima inicialização exibe erros de "corrupted database" ou panic.

    **Correção:**
    ```bash
    jamdesk dev --clean
    ```

    Isso apaga o diretório `.next` e inicia do zero.
  </Accordion>

  <Accordion title="Slow first run">
    O primeiro `jamdesk dev` instala as dependências de runtime em `~/.jamdesk/node_modules`. Isso acontece apenas uma vez e pode levar de 1 a 2 minutos em conexões mais lentas.

    As execuções seguintes pulam a instalação, a menos que a versão da CLI mude.
  </Accordion>

  <Accordion title="Dependency install fails or hangs">
    O `npm install` na primeira execução expira após 5 minutos.

    **Correção:**
    1. Verifique sua conexão com a internet
    2. `jamdesk clean` para limpar instalações parciais
    3. Tente novamente
    4. Se o npm estiver consistentemente lento, verifique a configuração do registry do npm: `npm config get registry`
  </Accordion>
</AccordionGroup>

## Validação e verificação de links

<AccordionGroup>
  <Accordion title="MDX syntax errors">
    O MDX trata `<` como o início de uma tag JSX. Escrever `<50%` causa um erro de análise.

    **Correção:** Escape com `&lt;` ou reescreva. Execute `jamdesk validate` para obter números de linha e sugestões.
  </Accordion>

  <Accordion title="Broken links found">
    `jamdesk broken-links` encontrou links internos apontando para páginas que não existem.

    **Correção:** Verifique os caminhos dos arquivos. Erros comuns: diferença de maiúsculas e minúsculas (`Quickstart` em vez de `quickstart`), inclusão da extensão `.mdx` ou caminhos antigos que foram renomeados.

    A CLI sugere correções para correspondências próximas (com até 3 caracteres de diferença em relação a um erro de digitação).

    **Corrija automaticamente.** Se um link quebrado tiver um destino correto e inequívoco (uma âncora com erro de digitação ou deslocamento de âncora entre locales), execute `jamdesk fix --dry-run` para visualizar as alterações e depois `jamdesk fix` para aplicá-las. Ela só reescreve links cuja âncora corrigida seja um cabeçalho real na página de destino. Corrija os casos ambíguos manualmente. Consulte [Corrigir links quebrados automaticamente](/pt/cli/fix-broken-links).
  </Accordion>

  <Accordion title="OpenAPI spec validation fails">
    A CLI valida as especificações OpenAPI referenciadas no `docs.json`. As falhas incluem referências `$ref` inválidas, campos obrigatórios ausentes ou erros de sintaxe.

    **Correção:** Execute `jamdesk openapi-check path/to/spec.yaml` para uma saída detalhada. Use o [Swagger Editor](https://editor.swagger.io) para depurar especificações complexas.

    <Note>Especificações Swagger 2.0 exibem um aviso, mas ainda passam na validação.</Note>
  </Accordion>
</AccordionGroup>

## Problemas gerais

<AccordionGroup>
  <Accordion title="Command not found: jamdesk">
    Não instalado globalmente, ou seu shell não consegue encontrar o binário.

    **Correção:**
    ```bash
    npm install -g jamdesk
    ```

    Se você instalou com `curl`, verifique se `~/.jamdesk/bin` está no seu `PATH`.
  </Accordion>

  <Accordion title="Permission denied errors">
    A CLI precisa de acesso de escrita a `~/.jamdesk` (cache) e `~/.jamdeskrc` (credenciais).

    **Correção:**
    ```bash
    ls -la ~/.jamdesk ~/.jamdeskrc
    sudo chown -R $(whoami) ~/.jamdesk ~/.jamdeskrc
    ```
  </Accordion>

  <Accordion title="Update fails">
    `jamdesk update` executa `npm install -g jamdesk@latest`. Ela falha quando o npm tem problemas de permissão ou o registry está inacessível.

    **Correção:** Atualize manualmente:
    ```bash
    npm install -g jamdesk@latest
    ```

    Se isso também falhar, verifique `npm config get registry` e tente `sudo npm install -g jamdesk@latest`.
  </Accordion>
</AccordionGroup>
