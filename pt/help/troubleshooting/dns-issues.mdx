Problemas de DNS são a causa mais comum de falhas em domínios personalizados.

## Verificar a propagação de DNS

Alterações de DNS podem levar até 48 horas para se propagar. A maioria se completa em algumas horas.

Verifique o status da propagação:

```bash
# Check if your CNAME is resolving
dig CNAME docs.yourdomain.com

# Or use nslookup
nslookup -type=CNAME docs.yourdomain.com
```

A saída esperada mostra seu CNAME apontando para `cname.jamdesk.com`:

```text
docs.yourdomain.com. 300 IN CNAME cname.jamdesk.com.
```

Ferramentas online como [whatsmydns.net](https://www.whatsmydns.net/) mostram a propagação em várias regiões.

## Problemas comuns

### CNAME não resolve

**Sintoma**: `dig` não mostra nenhum registro CNAME ou mostra um destino incorreto.

**Causas**:
- Registro não salvo no provedor de DNS
- Erro de digitação no nome ou valor do registro
- Propagação do DNS ainda em andamento

**Correção**:
1. Acesse seu provedor de DNS
2. Verifique se o registro CNAME existe com os valores corretos
3. Aguarde de 15 a 30 minutos e verifique novamente

### CNAME no domínio raiz

**Sintoma**: O provedor de DNS rejeita um registro CNAME para `yourdomain.com` (sem subdomínio).

**Causa**: Os padrões de DNS (RFC 1034) proíbem registros CNAME no apex da zona (domínio raiz).

**Correção**: O painel da Jamdesk mostra automaticamente um registro A (`76.76.21.21`) em vez de CNAME para domínios apex. Se o painel ainda exibir um CNAME para um domínio apex, clique em **Refresh** para obter os registros atualizados.

### Conflitos com o proxy da Cloudflare

**Sintoma**: Erros de SSL ou loops de redirecionamento ao usar o Cloudflare.

**Causa**: O proxy do Cloudflare (nuvem laranja) pode interferir no SSL da Vercel.

**Correção**:
1. Nas configurações de DNS do Cloudflare, clique no ícone da nuvem laranja
2. Mude para "DNS only" (nuvem cinza) para o subdomínio da sua documentação
3. Deixe a Vercel emitir o certificado SSL

### Registros conflitantes

**Sintoma**: A verificação do CNAME falha mesmo com o registro aparentemente correto.

**Causa**: Um registro A existente entra em conflito com o CNAME.

**Correção**:
1. Verifique se há registros A no mesmo subdomínio
2. Exclua os registros A conflitantes
3. Garanta que apenas o CNAME permaneça

```bash
# Check for A records
dig A docs.yourdomain.com
```

### Falha na verificação TXT

**Sintoma**: O registro TXT para hospedagem em subcaminho não é verificado.

**Causas**:
- Registro adicionado ao domínio errado
- Erro de digitação no valor do registro
- Registros TXT conflitantes

**Correção**:
1. Verifique se o registro TXT está em `_jamdesk.yourdomain.com`
2. Copie o valor de verificação exato do painel
3. Verifique se há registros TXT conflitantes

```bash
# Check TXT records
dig TXT _jamdesk.yourdomain.com
```

### Certificado SSL não é emitido

**Sintoma**: O domínio permanece com status "pending" indefinidamente.

**Causas**:
- Registros CAA bloqueando a emissão do certificado
- DNS não totalmente propagado
- Domínio inacessível

**Correção**:

Verifique os registros CAA:
```bash
dig CAA yourdomain.com
```

Se existirem registros CAA, adicione um que permita o Let's Encrypt:
```text
yourdomain.com. CAA 0 issue "letsencrypt.org"
```

## Comandos de diagnóstico

```bash
# Full DNS lookup
dig +trace docs.yourdomain.com

# Check all record types
dig ANY docs.yourdomain.com

# Check specific nameservers
dig @8.8.8.8 docs.yourdomain.com

# Check TTL (time to live)
dig +noall +answer docs.yourdomain.com
```

## Observações específicas dos provedores de DNS

### Cloudflare
- Defina o status do proxy como "DNS only" (nuvem cinza) durante a verificação do domínio
- Volte para proxy (nuvem laranja) após a conclusão da verificação
- Um Worker só executa quando o registro DNS está com proxy (nuvem laranja). Use a nuvem cinza apenas durante a verificação.
- Desative "Always Use HTTPS" para o subdomínio da documentação para evitar conflitos de SSL com a Vercel

### GoDaddy
- O destino do CNAME não deve terminar com ponto
- As alterações podem levar mais tempo para se propagar

### Namecheap
- Use o tipo "CNAME Record"
- O campo Host deve conter apenas o subdomínio (`docs`, não `docs.yourdomain.com`)

### Route 53
- O destino do CNAME deve terminar com ponto (`cname.jamdesk.com.`)
- Avaliar a integridade do destino: No

## Quando entrar em contato com o suporte

Entre em contato com o suporte se:
- Os registros DNS estiverem corretos, mas o domínio continuar pendente após 48 horas
- Erros de certificado SSL persistirem após seguir todos os passos
- Ocorrerem erros específicos da infraestrutura da Jamdesk

Inclua na sua solicitação de suporte:
- O nome do seu domínio
- O nome do provedor de DNS
- A saída dos comandos `dig`
- Uma captura de tela da configuração de DNS
