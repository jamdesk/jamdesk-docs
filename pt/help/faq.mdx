## Primeiros passos

<AccordionGroup>
  <Accordion title="O que é o Jamdesk?">
    O Jamdesk é uma plataforma de documentação que gera sites de docs a partir dos seus arquivos Markdown. Escreva em MDX e envie para o GitHub. Seu site é publicado com busca, análise e um arquivo `llms.txt` para ferramentas de IA.
  </Accordion>

  <Accordion title="Preciso saber programar?">
    Não. MDX é texto simples com formatação básica. Os componentes são opcionais.
  </Accordion>

  <Accordion title="Posso testar o Jamdesk gratuitamente?">
    Sim. Oferecemos um teste gratuito de 14 dias com todos os recursos.
  </Accordion>

  <Accordion title="Qual é a diferença entre o Jamdesk e outras plataformas de documentação?">
    Sua documentação são arquivos MDX simples em um repositório do GitHub, e não fica presa a um editor proprietário. Ao enviar para o GitHub, seu site é publicado em menos de 60 segundos. Não é preciso configurar build nem pipeline de CI/CD. Todo site recebe `llms.txt` e um servidor MCP. Ferramentas de IA como Claude e ChatGPT podem ler sua documentação atual diretamente. Os visitantes têm um [assistente de chat com IA](/pt/ai/chat) integrado que responde perguntas com base na sua documentação.
  </Accordion>
</AccordionGroup>

## Builds e implantação

<AccordionGroup>
  <Accordion title="Quanto tempo leva um build?">
    A maioria dos sites de documentação é gerada em 30 a 60 segundos. Sites maiores, com muitas páginas, podem levar mais tempo.
  </Accordion>

  <Accordion title="Posso visualizar as alterações antes de publicar?">
    Sim. Visualize localmente com hot reload usando a CLI do Jamdesk (`jamdesk dev`). As alterações só vão ao ar quando você envia para o GitHub ou executa `jamdesk deploy`.
  </Accordion>

  <Accordion title="Posso publicar sem o GitHub?">
    Sim. Execute `jamdesk deploy` no diretório do seu projeto. A CLI empacota e envia seus arquivos e depois dispara um build. Não é necessário um repositório Git. Veja o [guia de deploy da CLI](/pt/cli/deploy) para mais detalhes.
  </Accordion>

  <Accordion title="O que dispara um build?">
    Um push para o branch do GitHub conectado. Você também pode disparar um build pelo dashboard ou com `jamdesk deploy` na CLI.
  </Accordion>

  <Accordion title="Posso voltar para uma versão anterior?">
    Sim. Acesse **Deployments** no seu projeto. Encontre o build anterior e clique em **Rollback**.
  </Accordion>
</AccordionGroup>

## Domínios personalizados

<AccordionGroup>
  <Accordion title="Posso usar meu próprio domínio?">
    Sim. Adicione um domínio personalizado em **Settings** → **Domains**. O Jamdesk provisiona o certificado SSL.
  </Accordion>

  <Accordion title="Quanto tempo leva a propagação do DNS?">
    Geralmente algumas horas. Pode levar até 48 horas.
  </Accordion>

  <Accordion title="Posso hospedar a documentação em um subcaminho como /docs?">
    Sim. Use um proxy reverso (Cloudflare, AWS, nginx) para servir o Jamdesk em um subcaminho. Veja [Hospedagem em subcaminho](/pt/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Equipes e colaboração

<AccordionGroup>
  <Accordion title="Como convido um membro da equipe?">
    Abra seu projeto e acesse **Settings** → **Members**. Digite o e-mail da pessoa no campo **Invite Member** e clique em **Invite**. Ela receberá um e-mail com um link para entrar no projeto.

    <Frame>
      <img src="/images/dashboard/settings-team.webp" alt="Aba Members nas configurações do projeto, mostrando o campo Invite Member e a lista atual de membros" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    Os convidados precisam de uma conta no Jamdesk. O convite pede que criem uma caso não tenham. Já é membro, mas o link de convite diz que "já foi aceito"? Faça login. Você voltará ao projeto. Veja [Membros da equipe](/pt/help/projects/team-members) para funções e limites de membros.
  </Accordion>

  <Accordion title="Quantos membros da equipe posso ter?">
    Ilimitados, em todos os planos, sem custo extra.
  </Accordion>

  <Accordion title="Membros da equipe podem editar a documentação?">
    Os membros da equipe podem visualizar builds e disparar novas gerações. A edição acontece no seu repositório do GitHub. Quem tem acesso ao repositório pode editar a documentação.
  </Accordion>

  <Accordion title="Como transfiro a propriedade do projeto?">
    Acesse **Settings** → **Members**. Clique em **Transfer Ownership** ao lado do membro que você quer promover. O novo proprietário precisa ser um membro existente da equipe.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Onde ficam armazenadas as minhas credenciais da CLI?">
    Em `~/.jamdeskrc`, um arquivo JSON com permissões `0600` (apenas o seu usuário pode lê-lo). Ele armazena seu refresh token, e-mail e ID de usuário. Execute `jamdesk logout` para limpá-lo.
  </Accordion>

  <Accordion title='Por que a CLI diz "session expired"?'>
    Seu refresh token não é mais válido. Isso acontece após alterações de senha, exclusão de conta ou inatividade prolongada. Execute `jamdesk login` para obter uma nova sessão.
  </Accordion>

  <Accordion title="Posso usar a CLI em pipelines de CI/CD?">
    Sim. O login pelo navegador não funciona em ambientes headless. Faça login na sua máquina local. Copie `~/.jamdeskrc` para o seu runner de CI. O refresh token autentica a partir daí.
  </Accordion>

  <Accordion title="Como corrijo links quebrados automaticamente?">
    Execute `jamdesk fix`. Ele corrige links internos quebrados que têm um único destino correto (âncoras com erro de digitação e desvio de âncora entre locales). Ele edita seus arquivos `.mdx` locais após uma pré-visualização. Veja antes as alterações planejadas com `jamdesk fix --dry-run`. Ele só altera links cuja âncora corrigida é um cabeçalho real. Casos ambíguos ficam para revisão manual. Veja [Corrigir links quebrados automaticamente](/pt/cli/fix-broken-links).
  </Accordion>
</AccordionGroup>

## Conteúdo e recursos

<AccordionGroup>
  <Accordion title="Quais formatos de arquivo são suportados?">
    Arquivos MDX (Markdown + JSX) e Markdown padrão.
  </Accordion>

  <Accordion title="Posso usar componentes React personalizados?">
    Sim. Defina componentes inline no MDX com `export const`, ou crie componentes reutilizáveis no diretório `/snippets`. Para componentes interativos com hooks, use arquivos `.tsx` com `'use client'`. Veja [Componentes React personalizados](/pt/content/react-components) e [Snippets](/pt/content/snippets).
  </Accordion>

  <Accordion title="Existe limite de páginas?">
    Não há limite fixo. Sites com centenas de páginas são gerados e funcionam normalmente.
  </Accordion>

  <Accordion title="O Jamdesk oferece suporte a vários idiomas?">
    Sim. Adicione um seletor de idioma com a propriedade `languages` na configuração de navegação. Cada idioma tem sua própria estrutura de navegação e conteúdo. Veja [Suporte a vários idiomas](/pt/setup/languages).
  </Accordion>

  <Accordion title="O Jamdesk traduz meu conteúdo automaticamente?">
    Não. Você fornece os arquivos MDX traduzidos. O Jamdesk cuida do roteamento, da navegação, do seletor de idioma e da estilização RTL. Use traduções do seu próprio fluxo de trabalho (tradutores humanos, tradução automática ou um LLM). Coloque-as em diretórios com prefixo de idioma (`es/`, `fr/` etc.). Veja [Suporte a vários idiomas](/pt/setup/languages) para a estrutura de diretórios e a configuração.
  </Accordion>
</AccordionGroup>

## Chat com IA

<AccordionGroup>
  <Accordion title="Meu site de documentação tem chat com IA?">
    Sim. Todo site do Jamdesk inclui um assistente de chat integrado que responde às perguntas dos visitantes com base na sua documentação. Ele vem ativado por padrão. Veja [Chat com IA](/pt/ai/chat) para detalhes.
  </Accordion>

  <Accordion title="O chat com IA tem custo extra?">
    Não. O chat com IA está incluído em todos os planos.
  </Accordion>

  <Accordion title="Posso desativar o chat com IA?">
    Sim. Defina `chat.enabled` como `false` no seu `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    Seu próximo build remove o painel de chat e o atalho de teclado.
  </Accordion>

  <Accordion title="Quais dados o chat usa para responder às perguntas?">
    Somente as páginas da sua documentação publicada. Cada build indexa seu conteúdo em um banco de dados vetorial. O Jamdesk recupera as seções relevantes para a pergunta do visitante e as envia ao Claude como contexto. A IA não tem acesso a dados fora da sua documentação.
  </Accordion>
</AccordionGroup>

## Privacidade e acesso

<AccordionGroup>
  <Accordion title="Posso ter documentação pública e privada no mesmo site?">
    Sim. Marque páginas internas com `private: true` no frontmatter, ou liste os caminhos delas em `auth.password.private[]` no `docs.json`. Páginas privadas exibem uma tela de desbloqueio. Todas as páginas ficam em um só projeto, com um repositório e um build. Veja [Controle de acesso](/pt/setup/access-control) e [Proteção por senha](/pt/setup/password-protection).
  </Accordion>

  <Accordion title="Como protejo todo o meu site de documentação com uma senha?">
    Defina `auth.password.enabled: true` no `docs.json` e envie a alteração. Defina uma senha em **Project Settings → Password Protection** no dashboard. Os visitantes veem uma tela de desbloqueio até informá-la. Veja [Proteção por senha](/pt/setup/password-protection).
  </Accordion>

  <Accordion title="Os leitores podem fazer login com a própria conta em vez de uma senha compartilhada?">
    Sim, nos planos Enterprise. O Single Sign-On permite que os leitores se autentiquem no seu provedor de identidade (Okta, Google Workspace, Azure AD etc.), sem senhas compartilhadas, com trilha de auditoria completa e desprovisionamento imediato. Veja [SSO](/pt/setup/sso) ou [entre em contato com o time de vendas Enterprise](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="Devo separar a documentação interna e a externa em dois projetos?">
    Geralmente não. Use um projeto com `private: true` nas páginas internas. Você mantém um repositório e um dashboard. Use dois projetos apenas quando os públicos precisarem de marcas, domínios personalizados ou análises separados. Veja [Controle de acesso](/pt/setup/access-control) para os padrões.
  </Accordion>

  <Accordion title="Qual é a diferença entre um editor e um leitor?">
    **Editores** escrevem a documentação enviando MDX para o repositório do GitHub conectado. Um push só gera build se quem enviou for membro do projeto Jamdesk ou uma conta de automação autorizada por você. **Leitores** visualizam o site publicado: todos (público), quem tiver a senha (modo senha) ou quem fizer login pelo seu IdP (SSO). **Membros da equipe do dashboard** controlam builds, análises e configurações. A participação também permite que os pushes deles gerem build. Veja [Controle de acesso](/pt/setup/access-control).
  </Accordion>
</AccordionGroup>
