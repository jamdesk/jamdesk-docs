## Primeiros passos

<AccordionGroup>
  <Accordion title="O que é o Jamdesk?">
    O Jamdesk é uma plataforma de documentação que cria sites de documentação a partir dos seus arquivos Markdown. Escreva em MDX, envie para o GitHub e seu site será publicado automaticamente com busca, análise e `llms.txt` pronto para IA.
  </Accordion>

  <Accordion title="Preciso saber programar?">
    Não é necessário saber programar. Escrever em MDX é como usar um editor de texto: você escreve texto simples com formatação básica. Há componentes disponíveis se quiser usá-los, mas são totalmente opcionais.
  </Accordion>

  <Accordion title="Posso testar o Jamdesk gratuitamente?">
    Sim! Oferecemos um teste gratuito de 14 dias com acesso completo a todos os recursos.  
  </Accordion>

  <Accordion title="Qual é a diferença entre o Jamdesk e outras plataformas de documentação?">
    O Jamdesk é desenvolvido em torno de MDX e GitHub: sua documentação fica em arquivos de texto simples em um repositório, sem ficar presa a um editor proprietário. Envie para o GitHub e seu site será publicado em menos de 60 segundos, sem configuração de build ou pipeline de CI/CD. Todo site recebe automaticamente `llms.txt` e um servidor MCP, para que ferramentas de IA como Claude e ChatGPT possam acessar diretamente a documentação atualizada. Os visitantes também contam com um [assistente de chat com IA](/pt/ai/chat) integrado, que responde a perguntas com base na sua documentação.
  </Accordion>
</AccordionGroup>

## Builds e implantação

<AccordionGroup>
  <Accordion title="Quanto tempo levam os builds?">
    A maioria dos sites de documentação é compilada em 30 a 60 segundos. Sites maiores, com muitas páginas, podem levar mais tempo.
  </Accordion>

  <Accordion title="Posso visualizar as alterações antes de publicar?">
    Sim! Use a CLI do Jamdesk (`jamdesk dev`) para visualizar localmente com atualização automática. As alterações só entram no ar quando você envia para o GitHub ou executa `jamdesk deploy`.
  </Accordion>

  <Accordion title="Posso fazer o deploy sem o GitHub?">
    Sim. Execute `jamdesk deploy` no diretório do projeto. A CLI empacota seus arquivos, faz o upload e inicia um build diretamente. Não é necessário ter um repositório Git. Consulte o [guia de deploy pela CLI](/pt/cli/deploy) para saber mais.
  </Accordion>

  <Accordion title="O que inicia um build?">
    Os builds são iniciados automaticamente quando você envia alterações para a branch do GitHub conectada. Você também pode iniciar builds manualmente pelo dashboard ou com `jamdesk deploy` pela CLI.
  </Accordion>

  <Accordion title="Posso reverter para uma versão anterior?">
    Sim. Acesse **Deployments** no seu projeto, encontre o build anterior e clique em **Rollback**.
  </Accordion>
</AccordionGroup>

## Domínios personalizados

<AccordionGroup>
  <Accordion title="Posso usar meu próprio domínio?">
    Sim! Adicione um domínio personalizado em **Settings** → **Domains**. Os certificados SSL são provisionados automaticamente.
  </Accordion>

  <Accordion title="Quanto tempo leva a propagação do DNS?">
    As alterações de DNS geralmente se propagam em algumas horas, mas podem levar até 48 horas.
  </Accordion>

  <Accordion title="Posso hospedar a documentação em um subcaminho, como /docs?">
    Sim. Use um proxy reverso (Cloudflare, AWS, nginx) para disponibilizar o Jamdesk em um subcaminho. Consulte [Hospedagem em subcaminho](/pt/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Equipes e colaboração

<AccordionGroup>
  <Accordion title="Como convido um membro da equipe?">
    Abra seu projeto, acesse **Settings** → **Members**, digite o e-mail da pessoa no campo **Invite Member** e clique em **Invite**. Ela receberá um e-mail com um link para entrar no projeto.

    <Frame>
      <img src="/images/dashboard/settings-team.webp" alt="A guia Members nas configurações do projeto, mostrando o campo Invite Member e a lista atual de membros" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    As pessoas convidadas precisam ter uma conta Jamdesk; se ainda não tiverem, receberão uma solicitação para criá-la ao aceitar o convite. Já é membro, mas o link do convite informa que ele "já foi aceito"? Não é necessário enviar outro convite. Basta entrar na sua conta para voltar ao projeto. Consulte [Membros da equipe](/pt/help/projects/team-members) para saber mais sobre funções e limites de membros.
  </Accordion>

  <Accordion title="Quantos membros posso ter na equipe?">
    Todos os planos incluem membros ilimitados por projeto, sem custo adicional.
  </Accordion>

  <Accordion title="Os membros da equipe podem editar a documentação?">
    Os membros da equipe podem visualizar builds e iniciar novos builds, mas a edição é feita no repositório do GitHub. Qualquer pessoa com acesso ao repositório pode editar a documentação.
  </Accordion>

  <Accordion title="Como transfiro a propriedade do projeto?">
    Acesse **Settings** → **Members** e clique em **Transfer Ownership** ao lado do membro que deseja promover. A nova pessoa proprietária precisa já fazer parte da equipe.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Onde ficam armazenadas minhas credenciais da CLI?">
    Em `~/.jamdeskrc`, um arquivo JSON com permissões `0600` (somente você pode ler o arquivo). Ele armazena seu token de atualização, e-mail e ID de usuário. Execute `jamdesk logout` para apagá-lo.
  </Accordion>

  <Accordion title='Por que a CLI informa "session expired"?'>
    Seu token de atualização não é mais válido. Isso acontece após alterações de senha, exclusões de conta ou longos períodos de inatividade. Execute `jamdesk login` para iniciar uma nova sessão.
  </Accordion>

  <Accordion title="Posso usar a CLI em pipelines de CI/CD?">
    Sim, mas o login pelo navegador não funciona em ambientes sem interface gráfica. Entre na sua conta na máquina local e copie `~/.jamdeskrc` para o executor de CI. A partir daí, o token de atualização cuida da autenticação.
  </Accordion>

  <Accordion title="Como corrijo links quebrados automaticamente?">
    Execute `jamdesk fix`. O comando corrige links internos quebrados que tenham um destino correto inequívoco (âncoras com erros de digitação e âncoras desalinhadas entre idiomas), editando seus arquivos `.mdx` locais após uma prévia. Use `jamdesk fix --dry-run` para ver primeiro as alterações planejadas; somente links cuja âncora corrigida corresponda a um título existente serão alterados, deixando os casos ambíguos para revisão manual. Consulte [Correção automática de links quebrados](/pt/cli/fix-broken-links).
  </Accordion>
</AccordionGroup>

## Conteúdo e recursos

<AccordionGroup>
  <Accordion title="Quais formatos de arquivo são compatíveis?">
    O Jamdesk é compatível com MDX (Markdown + JSX) e arquivos Markdown padrão.
  </Accordion>

  <Accordion title="Posso usar componentes React personalizados?">
    Sim. Defina componentes diretamente em MDX com `export const` ou crie componentes reutilizáveis no diretório `/snippets`. Para componentes interativos com hooks, use arquivos `.tsx` com `'use client'`. Consulte [Componentes React personalizados](/pt/content/react-components) e [Snippets](/pt/content/snippets).
  </Accordion>

  <Accordion title="Há um limite de páginas?">
    Não há um limite fixo de páginas. A maioria dos sites de documentação funciona bem com centenas de páginas.
  </Accordion>

  <Accordion title="O Jamdesk é compatível com vários idiomas?">
    Sim. Use a propriedade `languages` na configuração de navegação para criar um seletor de idioma. Cada idioma tem sua própria estrutura de navegação e conteúdo. Consulte [Suporte a vários idiomas](/pt/setup/languages).
  </Accordion>

  <Accordion title="O Jamdesk traduz meu conteúdo automaticamente?">
    Não. O Jamdesk não traduz o conteúdo por você. Você fornece os arquivos MDX traduzidos, e o Jamdesk cuida do roteamento, da navegação, do seletor de idioma e do estilo RTL. Use traduções do seu próprio fluxo de trabalho (tradutores humanos, tradução automática ou um LLM) e coloque-as em diretórios com prefixo de idioma (`es/`, `fr/` etc.). Consulte [Suporte a vários idiomas](/pt/setup/languages) para ver a estrutura de diretórios e a configuração.
  </Accordion>
</AccordionGroup>

## Chat com IA

<AccordionGroup>
  <Accordion title="Meu site de documentação tem chat com IA?">
    Sim. Todo site Jamdesk inclui um assistente de chat integrado que responde às perguntas dos visitantes com base na sua documentação. O recurso vem ativado por padrão e não exige configuração. Consulte [Chat com IA](/pt/ai/chat) para saber mais.
  </Accordion>

  <Accordion title="O chat com IA tem custo adicional?">
    Não. O chat com IA está incluído em todos os planos, sem custo adicional.
  </Accordion>

  <Accordion title="Posso desativar o chat com IA?">
    Sim. Defina `chat.enabled` como `false` em `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    O painel de chat e o atalho de teclado serão removidos após o próximo build.
  </Accordion>

  <Accordion title="Quais dados o chat usa para responder às perguntas?">
    O chat usa apenas as páginas de documentação publicadas. Durante cada build, o Jamdesk indexa seu conteúdo em um banco de dados vetorial. Quando um visitante faz uma pergunta, as seções relevantes são recuperadas e enviadas ao Claude como contexto. A IA não pode acessar dados fora da sua documentação.
  </Accordion>
</AccordionGroup>

## Privacidade e acesso

<AccordionGroup>
  <Accordion title="Posso ter documentação pública e privada no mesmo site?">
    Sim. Marque as páginas internas com `private: true` no frontmatter ou liste os caminhos delas em `auth.password.private[]` no `docs.json`. As páginas públicas continuam públicas; as privadas exibem uma tela de desbloqueio. Tudo fica em um único projeto, então as páginas públicas e privadas compartilham o mesmo repositório e build. Consulte [Controle de acesso](/pt/setup/access-control) e [Proteção por senha](/pt/setup/password-protection).
  </Accordion>

  <Accordion title="Como protejo todo o site de documentação com uma senha?">
    Defina `auth.password.enabled: true` em `docs.json`, envie a alteração e, em seguida, defina uma senha em **Project Settings → Password Protection** no dashboard. Todos os visitantes verão uma tela de desbloqueio até inserir a senha. Consulte [Proteção por senha](/pt/setup/password-protection).
  </Accordion>

  <Accordion title="Os leitores podem entrar com a própria conta em vez de usar uma senha compartilhada?">
    Sim, nos planos Enterprise. O Single Sign-On permite que os leitores se autentiquem pelo seu provedor de identidade (Okta, Google Workspace, Azure AD etc.), sem senhas compartilhadas, com um registro de auditoria completo e desprovisionamento instantâneo. Consulte [SSO](/pt/setup/sso) ou [entre em contato com a equipe de vendas Enterprise](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="Devo separar a documentação interna e externa em dois projetos?">
    Geralmente, não. É mais simples manter um único projeto e definir `private: true` nas páginas internas, pois assim tudo fica em um só repositório e é gerenciado em um só dashboard. Use dois projetos apenas quando os públicos precisarem de identidade visual, domínios personalizados ou análise totalmente separados. Consulte [Controle de acesso](/pt/setup/access-control) para ver as opções.
  </Accordion>

  <Accordion title="Qual é a diferença entre um editor e um leitor?">
    **Editores** escrevem a documentação enviando MDX por commit para o repositório conectado do GitHub. Um envio inicia um build somente se a pessoa que o fez for membro do projeto Jamdesk ou uma conta de automação autorizada por você. **Leitores** visualizam o site publicado: qualquer pessoa (site público), qualquer pessoa com a senha (modo com senha) ou qualquer pessoa conectada pelo seu IdP (SSO). **Membros da equipe no dashboard** gerenciam builds, análise e configurações; além disso, a associação ao projeto permite que os envios dessas pessoas iniciem builds. Consulte [Controle de acesso](/pt/setup/access-control).
  </Accordion>
</AccordionGroup>
