Veja como a Jamdesk protege sua documentação e os dados da sua conta.

## Segurança da infraestrutura

### Hospedagem

A Jamdesk opera em provedores de nuvem em conformidade com SOC 2. Os builds, os dados da aplicação e a documentação compilada ficam em serviços gerenciados e reforçados desses provedores. O tráfego é servido por uma CDN global com proteção contra DDoS integrada.

### Criptografia

| Estado dos dados | Proteção |
|------------------|----------|
| Em trânsito | TLS 1.3 entre você, nossa borda e nossos servidores de origem |
| Em repouso | AES-256 para tudo o que armazenamos, incluindo registros do banco de dados, armazenamento de objetos e logs |
| Backups | Criptografados com as mesmas chaves e replicados em várias regiões |

## Controles de acesso

### Login

Você pode entrar no dashboard com e-mail e senha ou por login único usando Google ou GitHub. As senhas nunca são armazenadas em texto simples; nosso provedor de autenticação mantém apenas hashes unidirecionais.

Se você entrar com Google ou GitHub, qualquer MFA configurada nessa conta (TOTP, chaves de segurança, passkeys) também se aplica ao seu login na Jamdesk. Para obter a proteção mais robusta, recomendamos ativar a MFA na sua conta do Google ou GitHub e usar SSO.

### Acesso da equipe

O acesso baseado em funções (Owner, Admin, Member) é aplicado tanto nas regras de segurança do nosso banco de dados quanto em cada chamada ao backend. As sessões expiram automaticamente após períodos de inatividade, e as alterações no faturamento, nos membros, nos domínios personalizados ou nas chaves de API são registradas em um log de auditoria por projeto.

### Integração com GitHub

A Jamdesk se conecta aos seus repositórios por meio de um GitHub App com as permissões necessárias:

- Acesso de leitura e gravação ao conteúdo dos repositórios
- Entrega de Webhooks para acionar builds

A Jamdesk só grava no seu repositório quando você solicita: ao salvar alterações no editor do dashboard, aceitar sugestões do Fix with AI ou ativar a tradução, que faz commit das páginas traduzidas. Os builds só leem. Você pode revogar o acesso da Jamdesk a qualquer momento nas [Applications settings](https://github.com/settings/installations) do GitHub.

### Tokens e segredos

Todos os segredos que você confia a nós são criptografados em repouso. Isso inclui:

- Conexões do GitHub App, para as quais mantemos apenas o ID numérico da instalação. Os tokens de instalação de curta duração (válidos por uma hora) são gerados sob demanda e nunca são armazenados.
- Tokens OAuth do GitHub usados durante o fluxo de repositório inicial: eles são trocados uma vez, usados para clonar o modelo e, em seguida, descartados.
- Credenciais de integrações de terceiros, como URLs de Webhook de entrada do Slack, tokens de verificação de domínio personalizado e chaves de API de análise.

Após serem salvos, esses valores nunca são enviados pelo dashboard ao navegador; somente o pipeline de build no servidor pode acessá-los.

As chaves de API programáticas são armazenadas como hashes unidirecionais. O texto simples é exibido para você apenas uma vez, no momento da criação. Se você o perder, gere uma nova chave.

## Tratamento de dados

### O que armazenamos

- Sua configuração `docs.json` e quaisquer recursos de marca enviados
- Documentação compilada (HTML, CSS, JS)
- Logs de build, mantidos por 30 dias
- Eventos de visualização de página do seu site de documentação (caminho, referenciador, país, navegador, tipo de dispositivo, ID de sessão por aba e endereço IP do visitante), excluídos após 90 dias
- Perguntas feitas no chat de IA (os primeiros 200 caracteres, sem a resposta), excluídas após 30 dias
- Segredos criptografados de quaisquer integrações de terceiros que você tenha configurado

### O que não armazenamos

- Seu código-fonte. Clonamos o repositório no momento do build e descartamos a árvore de trabalho quando o contêiner de build é destruído.
- Credenciais de longa duração do GitHub. Consulte **Tokens e segredos** acima.
- Senhas de usuários em qualquer formato reversível.
- Números de cartões de pagamento. O Stripe processa todos os dados de cartão; mantemos apenas o ID do cliente e os metadados da assinatura.

### Acesso interno

O acesso aos dados de produção é limitado a um pequeno número de funcionários que precisam deles para operar o serviço ou responder a solicitações de suporte. O acesso é registrado.

## Isolamento de builds

Cada build da documentação é executado em um contêiner dedicado:

- Sem acesso aos dados de outros clientes
- Ambiente novo a cada build, com segredos injetados somente quando necessário
- O contêiner é destruído após a conclusão ou falha do build

## Conformidade

### GDPR

A Jamdesk está em conformidade com os requisitos do GDPR:

- Um [Adendo de Processamento de Dados](https://jamdesk.com/dpa) que se aplica automaticamente; uma cópia assinada por ambas as partes está disponível mediante solicitação pelo endereço `privacy@jamdesk.com`
- Uma lista pública de subprocessadores em [jamdesk.com/subprocessors](https://jamdesk.com/subprocessors)
- Solicitações de exclusão de dados atendidas em até 30 dias
- Portabilidade de dados disponível por meio de exportação

### Privacidade

Nossa ferramenta de análise integrada:

- Não usa cookies. Um ID de sessão aleatório é mantido no armazenamento de sessão do navegador e apagado quando a aba é fechada
- Não compartilha dados com redes de publicidade
- Armazena os endereços IP dos visitantes junto aos eventos de visualização de página; esses dados são excluídos após 90 dias

Consulte nossa [Política de Privacidade](https://jamdesk.com/privacy) para saber mais.

## Resposta a incidentes

Se um incidente de segurança afetar sua conta ou seus dados, tomaremos três medidas:

1. Investigar e conter o problema.
2. Notificar os clientes afetados em até 72 horas, de acordo com nossas obrigações sob o GDPR.
3. Fornecer um relatório escrito após o incidente assim que a causa for confirmada.

## Comunicação de vulnerabilidades

Encontrou um problema de segurança? Relate-o de forma responsável:

- Envie um e-mail para `security@jamdesk.com`
- Inclua uma descrição, as etapas para reproduzir o problema e uma avaliação do impacto
- Confirmaremos o recebimento em até 48 horas

Atualmente, não oferecemos um programa pago de recompensa por bugs, mas teremos prazer em dar crédito a pesquisadores que relatarem problemas de boa-fé.
