Migre um projeto Mintlify com um único comando: `jamdesk migrate` lê `mint.json`, grava `docs.json` e reescreve os arquivos MDX no próprio local. Para GitBook, Docusaurus, ReadMe, Confluence ou outra plataforma, siga as etapas manuais na aba "Outras plataformas".

<YouTube id="DvIHWeBliK0" />

<Info>
**Se puder, exporte primeiro como Markdown.** O Jamdesk é baseado em MDX. Basta renomear um arquivo Markdown para `.mdx` e adicionar algumas linhas de frontmatter.
</Info>

    ### Migração automatizada

    <Steps>
      <Step title="Instale a CLI">
        ```bash
        npm install -g jamdesk
        ```
      </Step>
      <Step title="Execute a migração">
        ```bash
        jamdesk migrate
        ```

        Execute o comando na raiz do projeto. Ele faz o seguinte:

        - Lê `mint.json` e grava `docs.json`
        - Renomeia componentes obsoletos nos arquivos MDX (por exemplo, `CardGroup` → `Columns`)
        - Move arquivos MDX de snippets sem referência para `/snippets/` e reescreve todas as importações relativas ao diretório pai (`../foo/bar.mdx`) para caminhos relativos à raiz (`/snippets/foo/bar.mdx`)
        - Extrai componentes inline que usam hooks do React para `/snippets/<name>.tsx` com a diretiva `'use client'` e reescreve o MDX original para importar de `/snippets/`
        - Corrige automaticamente problemas mecânicos de sintaxe MDX que causariam falha no build

        O comando é idempotente. Execute-o novamente após as edições para processar apenas o que há de novo. Tudo o que não puder corrigir com segurança será exibido como aviso, com o arquivo, a importação e a ação necessária.
      </Step>
      <Step title="Revise e ajuste">
        Confira o `docs.json` e os arquivos MDX gerados. Verifique a estrutura de navegação e corrija os avisos exibidos pela CLI.
      </Step>
    </Steps>

    ### Mapeamento de configuração

    A CLI converte `mint.json` em `docs.json`. Use estas diferenças para verificar o resultado.

    **Mintlify (`mint.json`):**
    ```json
    {
      "name": "My Docs",
      "navigation": [
        { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
      ],
      "colors": { "primary": "#0D9373" },
      "topbarLinks": [{ "name": "Blog", "url": "https://example.com/blog" }]
    }
    ```

    **Jamdesk (`docs.json`):**
    ```json
    {
      "$schema": "https://jamdesk.com/docs.json",
      "name": "My Docs",
      "theme": "jam",
      "colors": { "primary": "#0D9373" },
      "navbar": {
        "links": [{ "label": "Blog", "href": "https://example.com/blog" }]
      },
      "navigation": {
        "groups": [
          { "group": "Getting Started", "pages": ["introduction", "quickstart"] }
        ]
      }
    }
    ```

    ### Compatibilidade de componentes

    A maioria dos componentes do Mintlify tem equivalentes diretos no Jamdesk. Alguns têm nomes ou sintaxe diferentes.

    | Componente do Mintlify | Equivalente no Jamdesk | Observações |
    |---|---|---|
    | `<Card>` | `<Card>` | Mesma sintaxe |
    | CardGroup | `<Columns>` | Use a propriedade `cols` para definir o número de colunas |
    | `<Columns>` | `<Columns>` | Mesma sintaxe |
    | `<Accordion>` | `<Accordion>` | Mesma sintaxe |
    | `<Tabs>` / `<Tab>` | `<Tabs>` / `<Tab>` | Mesma sintaxe |
    | `<Steps>` / `<Step>` | `<Steps>` / `<Step>` | Mesma sintaxe |
    | `<CodeGroup>` | `<CodeGroup>` | Mesma sintaxe |
    | `<Tip>`, `<Note>`, `<Warning>` | `<Tip>`, `<Note>`, `<Warning>` | Mesma sintaxe |
    | `<ResponseField>` | `<ParamField>` | Nome diferente |
    | `<Snippet>` | Importação de `/snippets/` | Abordagem diferente |

    ### Problemas comuns

    <AccordionGroup>
      <Accordion title="CardGroup se torna Columns">
        `jamdesk migrate` renomeia `CardGroup` para `Columns` em todos os arquivos MDX. A propriedade `cols` é mantida sem alterações. Confira os arquivos editados após executar a migração.
      </Accordion>
      <Accordion title="ResponseField se torna ParamField">
        Renomeie `<ResponseField>` para `<ParamField>`. As propriedades permanecem iguais.

        ```mdx
        {/* Before */}
        <ResponseField name="id" type="string" required>
          The unique identifier
        </ResponseField>

        {/* After */}
        <ParamField name="id" type="string" required>
          The unique identifier
        </ParamField>
        ```
      </Accordion>
      <Accordion title="Snippets são movidos e ajustados automaticamente">
        O Jamdesk resolve apenas importações `/snippets/*` relativas à raiz. Em projetos Mintlify, os arquivos MDX de snippets costumam estar em qualquer lugar da árvore e ser importados com caminhos relativos ao diretório pai (`import X from '../shared/x.mdx'`).

        `jamdesk migrate` corrige isso:

        - Move para `/snippets/` os arquivos MDX importados como snippets que estejam fora desse diretório. Mantém o caminho relativo para evitar colisões entre snippets com prefixo de localidade, como `de/foo.mdx`.
        - Reescreve todas as importações de snippets relativas ao diretório pai em todos os arquivos MDX para usar o novo caminho relativo à raiz.
        - Extrai qualquer componente inline que use hooks do React para um arquivo `'use client'` em `/snippets/<name>.tsx` e substitui a exportação inline por uma importação de `/snippets/`.

        Substitua o elemento JSX `<Snippet file="my-snippet.mdx" />` do Mintlify por uma importação MDX. A CLI não o reescreve:

        ```mdx
        {/* Before (Mintlify) */}
        <Snippet file="my-snippet.mdx" />

        {/* After (Jamdesk) */}
        import MySnippet from '/snippets/my-snippet.mdx'

        <MySnippet />
        ```

        O processo de realocação é interrompido sem alterar nada se o projeto não tiver navegação resolvida ou se as mudanças planejadas excederem `max(5, 25%)` de todos os arquivos MDX. O motivo é exibido. Corrija o problema e execute novamente.
      </Accordion>
      <Accordion title="topbarLinks é mapeado para navbar.links">
        `topbarLinks` e `topbarCtaButton` do Mintlify são mapeados para `navbar.links` em `docs.json`. O campo `name` se torna `label`. O campo `url` se torna `href`.
      </Accordion>
    </AccordionGroup>

    ### Do GitBook

    O GitBook armazena o conteúdo em Markdown e usa um arquivo `SUMMARY.md` para a navegação.

    <Steps>
      <Step title="Exporte seu conteúdo">
        Exporte seu espaço do GitBook como Markdown. Com a sincronização Git do GitBook, seu conteúdo já estará em um repositório Git como arquivos `.md`.
      </Step>
      <Step title="Converta os arquivos para MDX">
        Renomeie os arquivos `.md` para `.mdx` e adicione frontmatter a cada arquivo:

        ```mdx
        ---
        title: Your Page Title
        description: A short description of the page
        ---

        Your existing Markdown content here.
        ```
      </Step>
      <Step title="Mapeie a navegação de SUMMARY.md">
        Converta a barra lateral de `SUMMARY.md` em grupos de navegação de `docs.json`.

        **GitBook (`SUMMARY.md`):**
        ```markdown
        # Summary

        ## Getting Started
        * [Introduction](introduction.md)
        * [Quick Start](quickstart.md)

        ## API Reference
        * [Authentication](api/auth.md)
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["introduction", "quickstart"]
              },
              {
                "group": "API Reference",
                "pages": ["api/auth"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Mova as imagens">
        Mova todas as imagens para um diretório `/images` e atualize as referências nos arquivos MDX para usar caminhos absolutos (por exemplo, `/images/screenshot.png`).
      </Step>
      <Step title="Teste localmente">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### Do Docusaurus

    Os projetos Docusaurus já usam MDX. A maior parte do conteúdo pode ser transferida diretamente.

    <Steps>
      <Step title="Copie seus arquivos MDX">
        Copie o conteúdo do diretório `docs/` do Docusaurus para a raiz do projeto Jamdesk. Mantenha a estrutura de diretórios existente.
      </Step>
      <Step title="Limpe o frontmatter">
        Remova os campos de frontmatter específicos do Docusaurus. Mantenha `title` e `description` e remova os demais.

        ```yaml
        ---
        # Remove these Docusaurus fields
        sidebar_position: 3
        sidebar_label: "Custom Label"
        slug: /custom-url
        pagination_next: null

        # Keep these
        title: Your Page Title
        description: A short description
        ---
        ```
      </Step>
      <Step title="Mapeie sidebars.js para docs.json">
        Converta a estrutura de categorias de `sidebars.js` em grupos de navegação de `docs.json`.

        **Docusaurus (`sidebars.js`):**
        ```javascript
        module.exports = {
          docs: [
            {
              type: 'category',
              label: 'Getting Started',
              items: ['intro', 'installation'],
            },
          ],
        };
        ```

        **Jamdesk (`docs.json`):**
        ```json
        {
          "navigation": {
            "groups": [
              {
                "group": "Getting Started",
                "pages": ["intro", "installation"]
              }
            ]
          }
        }
        ```
      </Step>
      <Step title="Substitua os componentes do Docusaurus">
        Substitua os componentes específicos do Docusaurus pelos equivalentes do Jamdesk.

        | Docusaurus | Jamdesk | Exemplo |
        |---|---|---|
        | `:::note` / `:::tip` / `:::warning` | `<Note>` / `<Tip>` / `<Warning>` | Consulte [componentes de destaque](/pt/components/overview) |
        | `import Tabs from '@theme/Tabs'` | `<Tabs>` (disponível globalmente) | Não é necessária uma importação |
        | `import TabItem from '@theme/TabItem'` | `<Tab>` (disponível globalmente) | Use `title` em vez de `label` |
      </Step>
      <Step title="Teste localmente">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>

    ### De outras ferramentas

    Para Confluence, Notion, ReadMe ou outra plataforma, converta o conteúdo para Markdown. Em seguida, configure a estrutura do projeto Jamdesk.

    <Steps>
      <Step title="Exporte como Markdown">
        A maioria das plataformas oferece uma opção de exportação para Markdown ou HTML. Use Markdown se estiver disponível. Converta HTML para Markdown com uma ferramenta como [Pandoc](https://pandoc.org/).

        ```bash
        # Convert HTML to Markdown with Pandoc
        pandoc input.html -f html -t markdown -o output.md
        ```
      </Step>
      <Step title="Crie docs.json">
        Comece com uma configuração mínima. Adicione páginas à navegação à medida que forem sendo criadas.
      </Step>
      <Step title="Converta os arquivos para MDX">
        Renomeie os arquivos `.md` para `.mdx` e adicione frontmatter (`title`, `description`) a cada arquivo.
      </Step>
      <Step title="Mova os recursos">
        Mova as imagens e outros recursos para um diretório `/images`. Atualize as referências aos arquivos para usar caminhos absolutos.
      </Step>
      <Step title="Teste localmente">
        ```bash
        jamdesk dev
        ```
      </Step>
    </Steps>
