---
title: Suporte a monorepo
description: >-
  Configure o modo monorepo nas configurações do projeto Jamdesk informando o caminho do diretório da sua documentação para que o Jamdesk compile apenas ela e ignore o restante
---

Se o seu `docs.json` estiver em um subdiretório (`docs/`, `packages/docs/` ou qualquer outro), ative o modo monorepo nas configurações do projeto e informe o caminho. O Jamdesk compila apenas esse diretório.

As capturas de tela mostram a interface em inglês.

<Note>
**Pré-requisitos:** Você precisa de um [projeto Jamdesk](/pt/setup/creating-projects) conectado a um [repositório GitHub](/pt/setup/connecting-github) antes de configurar o suporte a monorepo.
</Note>

## Como o Jamdesk limita seu build

## Configuração rápida

<Steps>
  <Step title="Abra as configurações do projeto">
    Abra o seu projeto no [painel Jamdesk](https://dashboard.jamdesk.com) e acesse **Settings**.
  </Step>

  <Step title="Ative o modo monorepo">
    Na seção **Git Repository**, ative **Set up as monorepo**.

    <Frame>
      <img src="/images/help-center/dashboard/monorepo-toggle.webp" alt="Monorepo toggle in project settings" />
    </Frame>
  </Step>

  <Step title="Informe o caminho da documentação">
    Informe o caminho do diretório que contém o seu arquivo `docs.json`.

    <Frame>
      <img src="/images/help-center/dashboard/docs-path-input.webp" alt="Docs path input showing preview" />
    </Frame>

    A pré-visualização mostra onde o Jamdesk procura o seu arquivo de configuração.
  </Step>

  <Step title="Salve e recompile">
    Clique em **Save Changes**. A sua próxima compilação usa o novo caminho.
  </Step>
</Steps>

## Entenda o caminho da documentação

<Warning>
Informe apenas o caminho do diretório, não o nome do arquivo. Use `docs`, não `docs/docs.json`.
</Warning>

### Exemplos de caminhos

| Estrutura do repositório | Valor do caminho da documentação |
|---------------------|-----------------|
| `my-repo/docs/docs.json` | `docs` |
| `my-repo/packages/docs/docs.json` | `packages/docs` |
| `my-repo/apps/website/docs/docs.json` | `apps/website/docs` |
| `my-repo/documentation/docs.json` | `documentation` |

### O que é incluído

O Jamdesk processa apenas os arquivos dentro do caminho da documentação:

- **Arquivos de conteúdo** (`.mdx`, `.md`) são compilados em páginas
- **Recursos** em subdiretórios (como `images/`) são incluídos
- **Configuração** (`docs.json`) define o seu site

Arquivos fora do caminho da documentação são ignorados durante as compilações.

## Padrões comuns de monorepo

<Tabs>
  <Tab title="/docs dedicado">
    Documentação em um diretório de nível superior.

    ```bash
    monorepo/
    ├── packages/
    ├── apps/
    └── docs/                    # Docs path: docs
        ├── docs.json
        ├── introduction.mdx
        └── guides/
    ```

    **Caminho da documentação:** `docs`
  </Tab>

  <Tab title="Pacote em /packages">
    Documentação como um pacote de workspace.

    ```bash
    monorepo/
    ├── packages/
    │   ├── core/
    │   ├── cli/
    │   └── docs/                # Docs path: packages/docs
    │       ├── docs.json
    │       └── pages/
    └── apps/
    ```

    **Caminho da documentação:** `packages/docs`
  </Tab>

  <Tab title="Dentro de um app">
    Documentação aninhada dentro de uma aplicação.

    ```bash
    monorepo/
    ├── apps/
    │   └── website/
    │       ├── src/
    │       └── docs/            # Docs path: apps/website/docs
    │           ├── docs.json
    │           └── introduction.mdx
    └── packages/
    ```

    **Caminho da documentação:** `apps/website/docs`
  </Tab>

  <Tab title="Diretório personalizado">
    Qualquer nome de diretório personalizado.

    ```bash
    monorepo/
    ├── src/
    ├── tests/
    └── documentation/           # Docs path: documentation
        ├── docs.json
        └── getting-started.mdx
    ```

    **Caminho da documentação:** `documentation`
  </Tab>
</Tabs>

## Trabalhando com assets

Os caminhos de recursos no `docs.json` são sempre relativos ao diretório da sua documentação, não à raiz do repositório.

### Exemplo

Para a documentação em `packages/docs/`:

```json packages/docs/docs.json
{
  "logo": {
    "light": "/images/logo.svg"
  },
  "favicon": "/images/favicon.svg"
}
```

Esses caminhos referenciam:
- `packages/docs/images/logo.svg`
- `packages/docs/images/favicon.svg`

<Warning>
Não use caminhos absolutos a partir da raiz do repositório. Isto falha:

```json
"favicon": "/packages/docs/images/favicon.svg"
```
</Warning>

### Em arquivos MDX

As imagens em MDX seguem a mesma regra:

```mdx
![Screenshot](/images/tabs-preview.png)
```

Isso referencia uma imagem em `[caminho-da-documentação]/images/tabs-preview.png`.

## Links internos

Os links internos não dependem da estrutura do seu repositório. Use caminhos relativos à raiz da sua documentação:

```mdx
[See the quickstart guide](/quickstart)
[Installation steps](/quickstart#installation)
```

Esses caminhos correspondem à estrutura de navegação, não ao seu sistema de arquivos.

## Comportamento dos builds

Apenas alterações dentro do caminho da documentação disparam uma compilação:

- Alterações em `packages/docs/**` disparam uma compilação
- Alterações em `packages/core/**` não disparam uma compilação

<Tip>
**Precisa recompilar quando outro código muda?**

Para documentação gerada a partir do código-fonte (como a documentação de API a partir de comentários no código), dispare uma recompilação manual pelo painel ou configure um webhook no seu pipeline de CI.
</Tip>

## Compatibilidade com ferramentas de workspace

Defina o caminho da documentação. Nenhuma outra configuração é necessária para estas ferramentas de monorepo.

| Ferramenta | Suportada |
|------|-----------|
| npm workspaces | Sim |
| Yarn workspaces | Sim |
| pnpm workspaces | Sim |
| Turborepo | Sim |
| Nx | Sim |
| Lerna | Sim |

## Solução de problemas

<AccordionGroup>
  <Accordion title="Erro: docs.json não encontrado" icon="circle-exclamation">
    1. Verifique se o caminho exato no seu repositório corresponde ao que você informou
    2. Confirme que `docs.json` existe nesse local
    3. Verifique erros de digitação. Os caminhos diferenciam maiúsculas de minúsculas
    4. Lembre-se: use `docs`, não `docs/docs.json`

    **Verificação rápida:** no seu repositório, o arquivo deve existir em `[seu-caminho-da-documentação]/docs.json`
  </Accordion>

  <Accordion title="Recursos não carregam" icon="image">
    Os caminhos de recursos devem ser relativos ao diretório da sua documentação.

    **Correto** (relativo ao diretório da documentação):
    ```json
    "favicon": "/images/favicon.svg"
    ```

    **Errado** (absoluto a partir da raiz do repositório):
    ```json
    "favicon": "/packages/docs/images/favicon.svg"
    ```

    Verifique se as suas imagens existem em `[caminho-da-documentação]/images/`.
  </Accordion>

  <Accordion title="Alterações não disparam compilações" icon="rotate">
    Apenas alterações dentro do caminho da documentação disparam compilações automáticas.

    1. Verifique se você está modificando arquivos dentro do caminho da documentação
    2. Confirme que você está enviando para o branch correto
    3. Veja o status das entregas de webhook nas configurações do repositório no GitHub

    Para compilar com alterações fora do caminho da documentação, use recompilações manuais ou webhooks de CI.
  </Accordion>
</AccordionGroup>
