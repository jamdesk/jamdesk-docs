Antes de escrever a documentação, você precisa de um projeto. Você pode começar com um modelo (o Jamdesk cria o repositório para você no GitHub ou no Bitbucket Cloud) ou conectar um repositório existente que já tenha um `docs.json`. De qualquer forma, seu site ficará disponível em poucos minutos.

## Criar um novo projeto

<Steps>
  <Step title="Acessar o Jamdesk">
    Acesse [dashboard.jamdesk.com](https://dashboard.jamdesk.com) e entre com sua conta do GitHub.

    Na primeira vez, você precisará autorizar o Jamdesk GitHub App.
  </Step>

  <Step title="Clicar em New Project">
    No dashboard, clique em **New Project** no canto superior direito.
  </Step>

  <Step title="Escolher um ponto de partida">
    <Tabs>
      <Tab title="A partir de um modelo">
        Comece com um modelo pré-configurado. O Jamdesk cria um novo repositório GitHub para você, com conteúdo de exemplo, navegação e componentes já configurados.

        O [Starter Template](https://github.com/jamdesk/starter-docs) padrão inclui páginas de exemplo, uma especificação OpenAPI e exemplos de todos os componentes. Substitua o conteúdo pelo seu e pronto.
      </Tab>
      <Tab title="A partir de um repositório">
        Conecte um repositório GitHub existente:

        1. Selecione o repositório no menu suspenso
        2. Escolha a branch para deploy (geralmente `main`)
        3. Especifique o caminho para `docs.json` se o arquivo não estiver na raiz

        O repositório está no Bitbucket Cloud? Informe-o como `workspace/repository-slug`. Consulte [Conectar Bitbucket](/pt/setup/connecting-bitbucket).
      </Tab>
    </Tabs>
  </Step>

  <Step title="Configurar as definições do projeto">
    Defina as informações básicas do projeto:

    | Campo | Descrição |
    |-------|-------------|
    | **Name** | Nome de exibição mostrado no dashboard |
    | **Slug** | Identificador compatível com URLs (por exemplo, `my-docs`) |
    | **Domain** | Seu subdomínio `*.jamdesk.app` |
  </Step>
</Steps>

## Estrutura mínima do repositório

Um projeto Jamdesk precisa apenas de um `docs.json` e de pelo menos uma página:

```bash
my-docs/
├── docs.json
└── introduction.mdx
```

Exemplo de `docs.json`:

```json docs.json
{
  "$schema": "https://jamdesk.com/docs.json",
  "name": "My Docs",
  "theme": "jam",
  "navigation": {
    "groups": [
      {
        "group": "Getting Started",
        "pages": ["introduction"]
      }
    ]
  }
}
```

## Configurações do projeto

Após a criação, configure o projeto em **Settings**:

### General

- **Name** - Atualize o nome de exibição
- **Slug** - Altere o identificador do projeto
- **Delete Project** - Remova o projeto permanentemente

### Repository

- **Branch** - A branch que aciona os deploys
- **Docs Path** - Localização de `docs.json` em monorepos

### Domain

- **Subdomain** - Sua URL `*.jamdesk.app`
- **Custom Domain** - Adicione seu próprio domínio
- **Host at a subpath** - Disponibilize a documentação em um caminho como `/docs` ou `/help`, em vez da raiz do site

### Build

- **Show Jamdesk Branding** - Exiba o link "Powered by Jamdesk" no rodapé (ativado por padrão)
- **Rebuild** - Acione manualmente um novo build

<Note>
As alterações nas definições de build exigem um novo build para entrar em vigor.
</Note>

## Limites do projeto
