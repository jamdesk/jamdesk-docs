O Jamdesk renderiza imagens com cantos arredondados e espaçamento consistente. Adicione arquivos ao diretório `/images` e faça referência a eles com Markdown padrão.

As capturas de tela mostram a interface em inglês.

## Markdown padrão

Use a sintaxe familiar `![alt](path)`:

```markdown
![API response showing user data in JSON format](/images/tabs-preview.webp)
```

![Resposta da API mostrando dados do usuário em formato JSON](/images/tabs-preview.webp)

Os caminhos começam na raiz do projeto. Uma imagem em `your-docs/images/screenshot.webp` é referenciada como `/images/screenshot.webp`.

## Dimensões da imagem

Adicione `=WIDTHxHEIGHT` após o URL da imagem (separado por um espaço) para controlar o tamanho:

```markdown
![Dashboard overview](/images/tabs-preview.webp =400x300)
```

Defina apenas uma dimensão para que a outra seja ajustada proporcionalmente:

```markdown
![Wide banner](/images/tabs-preview.webp =800x)
![Tall graphic](/images/tabs-preview.webp =x200)
```

Isso é útil quando você quer uma coluna uniforme de capturas de tela com a mesma largura ou precisa reduzir uma imagem de alta resolução para um tamanho de exibição adequado.

## Legendas

Envolva uma imagem com o componente `<Frame>` para adicionar uma borda e uma legenda abaixo dela:

```mdx
<Frame caption="Dashboard overview showing project statistics">
  ![Dashboard](/images/tabs-preview.webp)
</Frame>
```

<Frame caption="Exemplo de imagem emoldurada com legenda">
  ![Jamdesk](/images/jd-blueprint-transparent.webp)

</Frame>

`Frame` desenha uma borda discreta ao redor da imagem e posiciona o texto da legenda abaixo dela. O componente funciona com qualquer conteúdo, não apenas imagens.

## Clique para ampliar

As imagens são abertas em tela cheia quando você clica nelas em telas com 768 px de largura ou mais. Pressione Escape ou clique em qualquer lugar para fechar a imagem ampliada.

Para impedir que uma imagem seja ampliada, adicione `noZoom` a uma tag `<img>`:

```mdx
<img src="/images/diagram.png" alt="Architecture diagram" noZoom />
```

Imagens Markdown (`![alt](src)`) não têm sintaxe de atributos, então não podem desativar a ampliação. Use uma tag `<img>` quando precisar de `noZoom`.

## Modo claro/escuro

Os sites de documentação geralmente precisam de variantes de imagem para cada esquema de cores: um logotipo com fundo branco fica estranho no modo escuro.

### O atributo `srcDark`

A abordagem mais simples. O Jamdesk troca a origem da imagem conforme o tema ativo:

```mdx
<img
  src="/images/logo-light.webp"
  srcDark="/images/logo-dark.webp"
  alt="Company logo"
/>
```

O navegador carrega apenas a imagem correspondente ao esquema de cores atual.

### O elemento HTML `<picture>`

Se você precisa de HTML padrão que também funcione fora do Jamdesk, use `<picture>` com uma consulta de mídia:

```mdx
<picture>
  <source srcset="/images/logo-dark.webp" media="(prefers-color-scheme: dark)" />
  <img src="/images/logo-light.webp" alt="Company logo" />
</picture>
```

A abordagem com `<picture>` respeita a configuração de esquema de cores do sistema operacional. Já o atributo `srcDark` responde ao alternador de tema do Jamdesk, que geralmente é o que você quer para a documentação.

## Formatos compatíveis

| Formato | Ideal para | Observações |
|--------|----------|-------|
| PNG | Capturas de tela, imagens da interface | Qualidade sem perdas, compatível com transparência. Arquivos maiores. |
| JPEG | Fotografias | Boa compactação, sem suporte a transparência. |
| SVG | Ícones, diagramas, logotipos | Formato vetorial que pode ser redimensionado sem perda de qualidade. Arquivo minúsculo. |
| GIF | Animações simples | Os arquivos podem crescer rapidamente. Considere loops curtos em `.mp4` para animações com mais de alguns quadros. |
| WebP | Uso geral | Arquivos menores que PNG e JPEG com qualidade comparável. Funciona em todos os navegadores modernos. |

<Tip>
WebP oferece a melhor relação entre tamanho e qualidade para a maioria das imagens de documentação. Se precisar de transparência, WebP também é compatível, então não é necessário usar PNG.
</Tip>

## Boas práticas

<AccordionGroup>
  <Accordion title="Escreva um texto alternativo significativo" icon="universal-access">
    O texto alternativo tem duas funções: leitores de tela o usam para acessibilidade, e ele aparece como espaço reservado quando a imagem não carrega. Descreva o que a imagem realmente mostra.

    ```markdown
    {/* Good -- says what's in the image */}
    ![API response showing user data in JSON format](/images/tabs-preview.webp)

    {/* Bad -- tells you nothing */}
    ![Screenshot](/images/tabs-preview.webp)
    ```

    Para imagens decorativas que não acrescentam informações (padrões de fundo, divisórias), use um texto alternativo vazio: `![](/images/decoration.webp)`.
  </Accordion>

  <Accordion title="Mantenha os arquivos pequenos" icon="gauge-high">
    Imagens pesadas tornam o carregamento das páginas mais lento, especialmente em conexões móveis. Busque estes tamanhos:

    - **Capturas de tela/interface:** PNG ou WebP, menos de 500 KB
    - **Fotos:** JPEG ou WebP, menos de 200 KB
    - **Ícones e diagramas:** SVG sempre que possível

    [Squoosh](https://squoosh.app) e [TinyPNG](https://tinypng.com) compactam imagens sem perda visível de qualidade. Comprima as capturas de tela com uma dessas ferramentas antes de enviar as alterações.

    Ou deixe o Jamdesk cuidar disso durante o build. Ative a [conversão automática para WebP](/pt/builds/image-optimization) no seu `docs.json`, e todos os arquivos PNG ou JPG que você enviar serão otimizados a cada build.
  </Accordion>

  <Accordion title="Mantenha dimensões consistentes" icon="ruler-combined">
    Capturas de tela com larguras diferentes ficam desorganizadas. Escolha uma largura padrão para as capturas (1200 px funciona bem) e use-a em toda a documentação. O Jamdesk ajusta automaticamente as imagens à área de conteúdo, então dimensões de origem consistentes produzem resultados renderizados consistentes.
  </Accordion>

  <Accordion title="Confira a imagem de compartilhamento social" icon="share-nodes">
    O Jamdesk gera automaticamente um cartão social com a marca, de 1200×630, para cada página. Você pode substituí-lo por página com `og:image` no frontmatter. Depois de um build, insira o URL da página na ferramenta gratuita [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) para ver como o cartão aparece no X, Facebook, LinkedIn, Slack, Discord e outros. Consulte [Otimização para SEO](/pt/content/seo) para ver a configuração completa.
  </Accordion>
</AccordionGroup>

## Organização de arquivos

Agrupe as imagens em subdiretórios que reflitam a estrutura do conteúdo. Isso facilita encontrá-las à medida que a documentação cresce:

```bash
your-docs/
├── images/
│   ├── getting-started/
│   │   ├── step-1.png
│   │   └── step-2.png
│   ├── api/
│   │   └── response.png
│   └── logo.svg
└── docs.json
```

Faça referência a elas usando o caminho completo a partir da raiz do projeto:

```markdown
![GitHub repository access](/images/getting-started/step-1.png)
```

<Warning>
Evite espaços nos nomes dos arquivos de imagem. Use hífens: `api-response.webp`, não `api response.webp`.
</Warning>
