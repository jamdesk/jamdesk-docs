O Jamdesk exibe imagens com cantos arredondados e espaçamento uniforme. Adicione arquivos ao diretório `/images` e faça referência a eles usando a sintaxe padrão do Markdown.

As capturas de tela mostram a interface em inglês.

## Markdown padrão

Use a sintaxe `![alt](path)`:

```markdown
![API response showing user data in JSON format](/images/tabs-preview.webp)
```

![Resposta da API mostrando dados do usuário em formato JSON](/images/tabs-preview.webp)

Os caminhos começam na raiz do projeto. Uma imagem em `your-docs/images/screenshot.webp` é referenciada como `/images/screenshot.webp`.

## Dimensões da imagem

Adicione `=WIDTHxHEIGHT` após o URL da imagem (separado por um espaço) para controlar o tamanho:

```markdown
![Dashboard overview](/images/tabs-preview.webp =400x300)
```

Defina apenas uma dimensão para que a outra seja ajustada proporcionalmente:

```markdown
![Wide banner](/images/tabs-preview.webp =800x)
![Tall graphic](/images/tabs-preview.webp =x200)
```

Use esse recurso para manter a mesma largura em uma coluna de capturas de tela ou reduzir uma imagem de alta resolução para exibição.

## Legendas

Envolva uma imagem com o componente `<Frame>` para adicionar uma borda e uma legenda abaixo dela:

```mdx
<Frame caption="Dashboard overview showing project statistics">
  ![Dashboard](/images/tabs-preview.webp)
</Frame>
```

<Frame caption="Exemplo de imagem emoldurada com legenda">
  ![Jamdesk](/images/jd-blueprint-transparent.webp)

</Frame>

`Frame` funciona com qualquer conteúdo, não apenas com imagens.

## Clique para ampliar

Clique em uma imagem para abri-la em tela cheia em telas com 768 px de largura ou mais. Feche a imagem ampliada pressionando Escape ou clicando em qualquer lugar.

Adicione `noZoom` a uma tag `<img>` para impedir a ampliação:

```mdx
<img src="/images/diagram.png" alt="Architecture diagram" noZoom />
```

Imagens Markdown (`![alt](src)`) não têm sintaxe de atributos. Não é possível desativar a ampliação nelas. Use uma tag `<img>` quando precisar de `noZoom`.

## Modo claro/escuro

Os sites de documentação geralmente precisam de variantes de imagem para cada esquema de cores: um logotipo em fundo branco fica estranho no modo escuro.

### O atributo `srcDark`

O Jamdesk troca a origem da imagem para corresponder ao tema ativo:

```mdx
<img
  src="/images/logo-light.webp"
  srcDark="/images/logo-dark.webp"
  alt="Company logo"
/>
```

O navegador carrega apenas a imagem correspondente ao esquema de cores atual.

### O elemento HTML `<picture>`

Use `<picture>` com uma consulta de mídia para usar HTML padrão que também funciona fora do Jamdesk:

```mdx
<picture>
  <source srcset="/images/logo-dark.webp" media="(prefers-color-scheme: dark)" />
  <img src="/images/logo-light.webp" alt="Company logo" />
</picture>
```

A abordagem com `<picture>` respeita a configuração de esquema de cores do sistema operacional. Já o atributo `srcDark` segue a alternância de tema do Jamdesk. Essa geralmente é a opção desejada para sites de documentação.

## Formatos compatíveis

| Formato | Ideal para | Observações |
|--------|----------|-------|
| PNG | Capturas de tela, capturas da interface | Qualidade sem perdas, com suporte a transparência. Arquivos maiores. |
| JPEG | Fotografias | Boa compactação, sem suporte a transparência. |
| SVG | Ícones, diagramas, logotipos | Formato vetorial que se ajusta a qualquer tamanho sem perda de qualidade. Arquivos minúsculos. |
| GIF | Animações simples | Os arquivos podem ficar grandes rapidamente. Para animações com mais de alguns quadros, considere loops curtos em `.mp4`. |
| WebP | Uso geral | Arquivos menores que PNG e JPEG com qualidade comparável. Compatível com todos os navegadores modernos. |

<Tip>
WebP oferece a melhor relação entre tamanho e qualidade para a maioria das imagens de documentação. Também é compatível com transparência. Não é necessário usar PNG para isso.
</Tip>

## Boas práticas

<AccordionGroup>
  <Accordion title="Escreva textos alternativos descritivos" icon="universal-access">
    Leitores de tela leem o texto alternativo em voz alta. Ele também aparece como texto provisório quando a imagem não carrega. Descreva o que a imagem mostra.

    ```markdown
    {/* Good -- says what's in the image */}
    ![API response showing user data in JSON format](/images/tabs-preview.webp)

    {/* Bad -- tells you nothing */}
    ![Screenshot](/images/tabs-preview.webp)
    ```

    Para imagens decorativas que não acrescentam informações (padrões de fundo, divisórias), use um texto alternativo vazio: `![](/images/decoration.webp)`.
  </Accordion>

  <Accordion title="Mantenha os arquivos pequenos" icon="gauge-high">
    Imagens pesadas deixam o carregamento das páginas mais lento, especialmente em conexões móveis. Tamanhos recomendados:

    - **Capturas de tela/interface:** PNG ou WebP, menos de 500 KB
    - **Fotos:** JPEG ou WebP, menos de 200 KB
    - **Ícones e diagramas:** SVG sempre que possível

    [Squoosh](https://squoosh.app) e [TinyPNG](https://tinypng.com) compactam imagens sem perda de qualidade visível. Otimize as capturas de tela com uma dessas ferramentas antes de confirmar as alterações.

    O Jamdesk também pode compactar imagens durante o build. Ative a [conversão automática para WebP](/pt/builds/image-optimization) no seu `docs.json`. Com esse recurso ativado, o Jamdesk otimiza cada arquivo PNG ou JPG confirmado em cada build.
  </Accordion>

  <Accordion title="Use dimensões consistentes" icon="ruler-combined">
    Capturas de tela com larguras diferentes ficam desorganizadas. Escolha uma largura padrão para as capturas (1200 px funciona bem) e use-a em toda a documentação. O Jamdesk ajusta as imagens à área de conteúdo. Dimensões de origem consistentes produzem resultados de exibição consistentes.
  </Accordion>

  <Accordion title="Verifique a imagem de compartilhamento social" icon="share-nodes">
    O Jamdesk gera um cartão social de marca, com dimensões de 1200×630, para cada página. Substitua-o por página com `og:image` no frontmatter. Depois de um build, acesse o URL da página na ferramenta gratuita [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) para ver como o cartão aparece no X, Facebook, LinkedIn, Slack, Discord e outros. Consulte [Otimização para SEO](/pt/content/seo) para ver a configuração completa.
  </Accordion>
</AccordionGroup>

## Organização de arquivos

Agrupe imagens em subdiretórios que espelhem a estrutura do seu conteúdo:

```bash
your-docs/
├── images/
│   ├── getting-started/
│   │   ├── step-1.png
│   │   └── step-2.png
│   ├── api/
│   │   └── response.png
│   └── logo.svg
└── docs.json
```

Faça referência a elas usando o caminho completo a partir da raiz do projeto:

```markdown
![GitHub repository access](/images/getting-started/step-1.png)
```

<Warning>
Evite espaços nos nomes de arquivos de imagem. Use hífens: `api-response.webp`, não `api response.webp`.
</Warning>
