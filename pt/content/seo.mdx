## Como otimizar seu conteúdo

### Escreva um frontmatter eficaz

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Coloque as palavras-chave no início.** "Authentication setup" é melhor que "How to set up authentication."
</Tip>

### Títulos de página

- Use menos de 60 caracteres, contando o nome do site adicionado pelo formato do título, para evitar cortes nos resultados de busca
- Inclua a palavra-chave principal perto do início
- Use um título exclusivo para cada página da documentação

Por padrão, o título da aba do navegador e do resultado de busca é `Page title — Site name`. Para alterá-lo, defina `seo.titleTemplate` em `docs.json`. Coloque `%s` no local em que o título da página deve aparecer:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Uma página intitulada `Getting started` será exibida como `Getting started | Acme`. Use apenas `"%s"` para omitir o nome do site. Se o modelo não contiver `%s`, o build falhará e `jamdesk validate` exibirá o erro. As prévias de links (`og:title` e `twitter:title`) continuam mostrando apenas o título da página.

Dois tipos de página não usam o modelo. Uma página sem `title` exibe seu `name` seguido de "Documentation", como em `Acme Documentation`, ou apenas seu `name` se ele já terminar com "Docs" ou "Documentation". Uma página cujo título seja igual ao seu `name` exibe apenas esse título.

`jamdesk validate` e `jamdesk dev` aceitam `seo.titleTemplate` a partir da versão 1.1.220 da CLI. Atualize com `npm i -g jamdesk@latest`.

### Descrições

- Procure usar de 120 a 160 caracteres
- Resuma o que o leitor vai aprender
- Inclua palavras-chave relevantes de forma natural

<Note>
**Alternativa gerada automaticamente.** Quando não há `description` no frontmatter, o Jamdesk extrai automaticamente o primeiro parágrafo de texto do conteúdo da página (até 155 caracteres). Títulos, blocos de código, imagens e componentes MDX são ignorados. Esse texto é usado em `<meta name="description">`, no Open Graph e nos cartões do Twitter. Ainda é recomendável escrever uma descrição explícita para obter os melhores resultados.
</Note>

## Como controlar a indexação

### Configurações para todo o site

No seu `docs.json`, configure o comportamento padrão dos robôs:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Controle por página

Substitua a configuração de indexação para páginas específicas no frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Use `noindex` para:
- Rascunhos ou páginas em andamento
- Documentação interna
- Conteúdo desatualizado que você mantém como referência

### Indexação de busca e ingestão por IA

Os metadados `robots` e `noindex` controlam os **mecanismos de busca**: determinam se uma página aparece no Google e no seu `sitemap.xml`. Eles não afetam os arquivos `llms.txt` e `llms-full.txt` lidos por ferramentas de IA. Para deixar de publicá-los, defina `seo.ai.llmsTxt` como `false` (consulte [Desativar llms.txt](/pt/ai/llms-txt#desativar-o-llmstxt)). Os dois controles são independentes: uma página pode ser indexada por mecanismos de busca e excluída da ingestão por IA, ou o contrário.

## URLs canônicas

Se a documentação estiver disponível em várias URLs, defina uma URL canônica:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Você também pode definir uma base canônica para todo o site em `docs.json`. O Jamdesk acrescenta a ela o caminho de cada página, para que todas tenham uma URL canônica correta:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Prévia social e Open Graph

O Jamdesk gera automaticamente um cartão social de marca com 1200×630 para cada página. Substitua qualquer tag social no frontmatter. Você pode usar **chaves planas no nível superior** ou um bloco aninhado **`seo:`**. Ambos funcionam; se a mesma chave for definida das duas formas, o valor no nível superior prevalece.

<Card title="Prévia OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Veja como o cartão de qualquer página aparece no X, Facebook, LinkedIn e outras plataformas. Com a ferramenta OpenGraph Preview, você também pode validar as tags Open Graph.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Tags compatíveis

| Grupo | Tags |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artigo | `og:type: article` com `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, tags de app-card |
| Outros | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` e qualquer tag personalizada (adicione tags personalizadas em `seo:`) |

<Note>
**Dimensões de imagem OG personalizadas.** `og:image:width` e `og:image:height` só se aplicam quando
[`customImage`](#personalizar-o-cartão-social) é `"replace"`. Defina essas opções no mesmo lugar que
o `og:image` correspondente: no frontmatter da página ou em `seo.metatags`. O cartão gerado
sempre tem 1200×630.
</Note>

<Note>
**Tags personalizadas.** Tags meta arbitrárias (por exemplo, `x-pinterest`) são emitidas como `<meta name="...">`.
Adicione-as ao bloco `seo:`. Quando colocadas no nível superior, somente chaves de SEO reconhecidas são usadas.
</Note>

### Tipo de card do Twitter / X

A tag `twitter:card` controla o layout usado pelo X (e por outras plataformas) quando alguém compartilha seu link:

| Valor | Aparência |
|-------|-----------|
| `summary` | Miniatura quadrada pequena à esquerda, com título e descrição ao lado. Compacto. |
| `summary_large_image` | Imagem grande em toda a largura na parte superior, com título e descrição abaixo. Mais chamativo. |

Para um cartão de marca com 1200×630, use `summary_large_image` para que a imagem seja exibida em toda a largura.

### Imagem padrão para todo o site

Defina uma imagem social alternativa para todas as páginas em `docs.json`. Qualquer página que definir seu próprio `og:image` substituirá essa imagem:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Pré-visualize antes de publicar.** Após um build, cole a URL da página na ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) para verificar como o cartão aparece em cada plataforma e validar as tags Open Graph. A ferramenta também verifica as dimensões da imagem e explica como corrigir os problemas encontrados.
</Tip>

### Personalizar o cartão social

O cartão gerado mantém a aparência atual, a menos que você adicione `seo.socialCard` a `docs.json`.
Defina somente as chaves que deseja alterar:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Chave | Padrão | Efeito |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` usa texto claro sobre fundo escuro e a imagem `logo.dark`. |
| `brandColor` | `false` | `true` colore a barra inferior e o selo da seção com `colors.primary`. Em um cartão escuro, usa `colors.light` se definido. Se você não tiver `colors`, o cartão usa a cor de destaque do tema. `false` mantém o vermelho padrão. |
| `accentBar` | `true` | `false` remove a barra colorida na parte inferior do cartão. |
| `siteName` | `true` | `false` oculta o nome do site sob o logotipo. Use essa opção quando o logotipo já mostrar o nome. |
| `customImage` | `"background"` | `"background"` coloca o título da página sobre o `og:image`. `"replace"` usa o `og:image` como cartão inteiro. |

O cartão só pode renderizar logotipos SVG, PNG e JPG. Durante o build do site, o Jamdesk converte os arquivos de logotipo PNG e JPG do repositório para WebP. Por isso, o cartão geralmente exibe o favicon em vez do logotipo e mantém o nome do site, mesmo com `siteName: false`. Use um logotipo SVG para exibir o logotipo completo no cartão e `logo.dark` em um cartão escuro.

O cartão não consegue renderizar texto dentro de um logotipo SVG, então o texto aparece em branco. Para corrigir isso, converta o texto em contornos (paths) na ferramenta de design e exporte o SVG novamente. No Figma, selecione o texto e use **Flatten**. No Illustrator, use **Type > Create Outlines**. Se o cartão encontrar texto no logotipo SVG que está usando, o build exibirá uma sugestão. Logotipos definidos com uma URL completa (`https://...`) não são verificados.

Se a cor da marca não tiver contraste suficiente com o cartão, o texto do selo usará a cor de texto normal. A barra mantém a cor da marca, a menos que ela seja quase igual à cor de fundo do cartão. Nesse caso, a barra fica cinza.

Por padrão, o Jamdesk coloca o título da página sobre o `og:image`. Se a imagem já tiver texto ou design próprios, defina `"customImage": "replace"` para exibi-la sem alterações.

Quando o `og:image` for o plano de fundo do cartão, escolha o `theme` correspondente: `dark` para uma imagem escura e `light` para uma imagem clara.

No modo `replace`, o Jamdesk não coloca título sobre a imagem. Se `seo.metatags` definir `og:image`, todas as páginas usarão essa imagem, exceto as que definirem seu próprio `og:image`. Somente páginas sem nenhuma dessas opções recebem um cartão gerado. Use uma imagem PNG ou JPG de 1200×630. Algumas plataformas não exibem imagens WebP ou SVG.

As redes sociais armazenam em cache as prévias de links. Portanto, um link que já foi compartilhado pode continuar exibindo o cartão antigo por algum tempo após a alteração dessas configurações. Confira o novo cartão com a ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Versões mais antigas da CLI do Jamdesk rejeitam `seo.socialCard` e `seo.titleTemplate` em
`jamdesk validate` e `jamdesk dev`. Atualize com `npm i -g jamdesk@latest`.
</Note>

## Sitemap e robots.txt

Todos os sites Jamdesk geram automaticamente `sitemap.xml` e `robots.txt` a cada build.

| Arquivo | Finalidade |
|------|---------|
| `sitemap.xml` | Lista todas as páginas com as datas da última modificação para mecanismos de busca |
| `robots.txt` | Permite o acesso de todos os rastreadores e aponta para o sitemap |

### Onde encontrá-los

As URLs dependem de a documentação estar em um domínio raiz ou em um subcaminho `/docs`:

<Tabs>
  <Tab title="Domínio raiz">
    Se a documentação estiver na raiz do domínio (por exemplo, `docs.acme.com` ou `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Subcaminho /docs">
    Se a documentação estiver em `/docs` no site principal (como neste site em `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### O que o sitemap inclui

- Todas as páginas publicadas (exceto as que têm `noindex` ou `hidden` no frontmatter)
- Datas da última modificação do frontmatter, quando disponíveis
- Frequência de alteração semanal

### Excluir páginas do sitemap

Adicione `noindex` ao frontmatter para excluir uma página do sitemap e dos mecanismos de busca:

```yaml
---
title: Internal Notes
noindex: true
---
```

Páginas com `hidden: true` também são excluídas automaticamente.

## Dados estruturados JSON-LD

Todas as páginas incluem automaticamente dados estruturados do [schema.org](https://schema.org) em uma tag `<script type="application/ld+json">` com dois esquemas:

- `WebSite`: nome, URL e descrição do site (de `docs.json`).
- `BreadcrumbList`: caminho de navegação da página inicial até a página atual, derivado da configuração `navigation`.

Não é necessário configurar nada. Os mecanismos de busca usam esses dados para exibir resultados avançados, como trilhas de navegação nos resultados de busca.

<Tip>
**Verifique a marcação.** Cole a URL de qualquer página no [Teste de pesquisa aprimorada do Google](https://search.google.com/test/rich-results) para confirmar se os dados estruturados foram detectados.
</Tip>

## IndexNow

Após cada build, o Jamdesk envia automaticamente as URLs das páginas alteradas ao [IndexNow](https://www.indexnow.org) para acelerar a indexação nos mecanismos de busca. Isso notifica o Bing, o Yandex e outros mecanismos de busca participantes sobre as alterações no conteúdo, sem esperar pelo próximo ciclo de rastreamento.

- É executado após cada build bem-sucedido
- Envia somente as páginas que realmente foram alteradas
- Não bloqueia o processo, portanto nunca atrasa o build
- Não requer configuração

## Práticas recomendadas

Use esta lista de verificação antes de publicar:

<Note>
**Lista de verificação pré-publicação**

- **Títulos exclusivos.** Cada página tem um título distinto e descritivo com menos de 60 caracteres.
- **Descrições precisas.** As descrições resumem a página em 120 a 160 caracteres.
- **Títulos hierárquicos.** Os títulos seguem uma hierarquia clara: um H1, seguido de H2 → H3.
- **Links descritivos.** Os links internos usam textos de âncora significativos, nunca "clique aqui".
- **Texto alternativo das imagens.** Todas as imagens têm texto alternativo para acessibilidade e busca de imagens.
- **Imagem social.** Defina um `og:image` personalizado nas páginas principais ou use o cartão gerado automaticamente. Verifique-o com a ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
