## Como otimizar seu conteúdo

### Escreva um frontmatter eficaz

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Coloque as palavras-chave no início.** "Configuração de autenticação" é melhor do que "Como configurar a autenticação".
</Tip>

### Títulos de página

- Use menos de 60 caracteres para evitar cortes nos resultados de busca
- Inclua a palavra-chave principal perto do início
- Use um título exclusivo para cada página da documentação

Por padrão, o título da aba do navegador e dos resultados de busca é `Page title — Site name`. Para alterá-lo, defina `seo.titleTemplate` em `docs.json`. Cada `%s` é substituído pelo título da página:

```json
{
  "seo": {
    "titleTemplate": "%s | Acme"
  }
}
```

Use apenas `"%s"` para omitir o nome do site. O modelo altera apenas o título da aba do navegador e dos resultados de busca. O título nas prévias sociais (`og:title`) permanece igual. Uma página sem título, ou cujo título seja igual ao nome do site, exibe o título do site como está.

### Descrições

- Use entre 120 e 160 caracteres
- Resuma o que o leitor vai aprender
- Inclua palavras-chave relevantes de forma natural

<Note>
**Alternativa gerada automaticamente.** Quando `description` não está no frontmatter, o Jamdesk extrai automaticamente o primeiro parágrafo em prosa do conteúdo da página (até 155 caracteres). Títulos, blocos de código, imagens e componentes MDX são ignorados. Esse texto é usado em `<meta name="description">`, no Open Graph e nos cartões do Twitter. Ainda recomendamos escrever uma descrição explícita para obter os melhores resultados.
</Note>

## Como controlar a indexação

### Configurações para todo o site

No seu `docs.json`, configure o comportamento padrão dos robôs:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Controle por página

Substitua a configuração de indexação para páginas específicas no frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Use `noindex` para:
- Páginas em rascunho ou em andamento
- Documentação interna
- Conteúdo obsoleto que você mantém como referência

### Indexação de busca e ingestão por IA

Os metadados `robots` e `noindex` controlam os **mecanismos de busca**: determinam se uma página aparece no Google e no seu `sitemap.xml`. Eles não afetam os arquivos `llms.txt` e `llms-full.txt` lidos por ferramentas de IA. Para deixar de publicá-los, defina `seo.ai.llmsTxt` como `false` (consulte [Desativar llms.txt](/pt/ai/llms-txt#desativar-o-llmstxt)). Os dois controles são independentes: uma página pode ser indexada pelos mecanismos de busca e excluída da ingestão por IA, ou o contrário.

## URLs canônicas

Se sua documentação estiver disponível em várias URLs, defina uma URL canônica:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Você também pode definir uma base canônica para todo o site em `docs.json`. O Jamdesk acrescenta a ela o caminho de cada página, garantindo uma URL canônica correta para cada página:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Prévia social e Open Graph

O Jamdesk gera automaticamente um cartão social de marca, com dimensões de 1200×630, para cada página. Substitua qualquer tag social no frontmatter. Você pode usar **chaves planas no nível superior** ou um bloco **`seo:`** aninhado. Ambos funcionam; se a mesma chave for definida das duas formas, o valor plano do nível superior prevalece.

<Card title="Prévia do OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Veja como o cartão de qualquer página aparece no X, Facebook, LinkedIn e outras plataformas. Use a ferramenta OpenGraph Preview para validar as tags Open Graph.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Tags compatíveis

| Grupo | Tags |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artigo | `og:type: article` com `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, tags de cartão de aplicativo |
| Outros | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` e qualquer tag personalizada (adicione tags personalizadas em `seo:`) |

<Note>
**Dimensões personalizadas da imagem Open Graph.** `og:image:width` e `og:image:height` só se aplicam quando
[`customImage`](#personalizar-o-cartão-social) é `"replace"`. Defina-as no mesmo local que
`og:image`, que elas descrevem: no frontmatter da página ou em `seo.metatags`. O cartão gerado
sempre tem dimensões de 1200×630.
</Note>

<Note>
**Tags personalizadas.** Tags meta arbitrárias (por exemplo, `x-pinterest`) são emitidas como `<meta name="...">`.
Adicione-as ao bloco `seo:`. Quando definidas como chaves planas, somente as chaves de SEO reconhecidas são utilizadas.
</Note>

### Tipo de card do Twitter / X

A tag `twitter:card` controla o layout usado pelo X e por outras plataformas quando alguém compartilha seu link:

| Valor | Aparência |
|-------|--------------------|
| `summary` | Miniatura quadrada pequena à esquerda, com título e descrição ao lado. Compacto. |
| `summary_large_image` | Imagem grande em toda a largura na parte superior, com título e descrição abaixo. Maior destaque. |

Para um cartão de marca de 1200×630, use `summary_large_image` para exibir a imagem em toda a largura.

### Imagem padrão para todo o site

Defina uma imagem social alternativa para todas as páginas em `docs.json`. Qualquer página que defina seu próprio `og:image` substituirá essa imagem:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Confira antes de publicar.** Após um build, cole a URL da página na ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) para conferir a aparência do cartão em cada plataforma e validar as tags Open Graph. A ferramenta também verifica as dimensões da imagem e explica como corrigir os problemas encontrados.
</Tip>

### Personalizar o cartão social

O cartão gerado mantém a aparência atual, a menos que você adicione `seo.socialCard` ao `docs.json`.
Defina apenas as chaves que deseja alterar:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Chave | Padrão | Efeito |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` usa texto claro em um fundo escuro e a imagem `logo.dark`. |
| `brandColor` | `false` | `true` aplica `colors.primary` à barra inferior e ao selo da seção. Em cartões escuros, usa `colors.light`, se definido. Se você não tiver `colors`, o cartão usa a cor de destaque do tema. `false` mantém o vermelho padrão. |
| `accentBar` | `true` | `false` remove a barra colorida na parte inferior do cartão. |
| `siteName` | `true` | `false` oculta o nome do site abaixo do logotipo. Use essa opção quando o logotipo já exibir o nome. |
| `customImage` | `"background"` | `"background"` coloca o título da página sobre seu `og:image`. `"replace"` usa seu `og:image` como o cartão inteiro. |

O cartão só consegue renderizar logotipos SVG, PNG e JPG. Durante o build do site, o Jamdesk converte os arquivos de logotipo PNG e JPG do seu repositório para WebP. Por isso, o cartão geralmente exibe seu favicon e mantém o nome do site, mesmo com `siteName: false`. Use um logotipo SVG para exibir o logotipo completo no cartão e `logo.dark` em cartões escuros.

O cartão não consegue renderizar texto dentro de um logotipo SVG. Se o seu logotipo tiver texto, converta-o em contornos (paths) antes de exportá-lo. Seu build exibirá uma sugestão quando encontrar texto no logotipo SVG usado pelo cartão. Logotipos vinculados de outro site não são verificados.

Se a cor da sua marca não tiver contraste suficiente com o cartão, o texto do selo usará a cor de texto normal. A barra mantém a cor da marca, a menos que ela seja muito parecida com a cor de fundo do cartão. Nesse caso, a barra fica cinza.

Por padrão, o Jamdesk coloca o título da página sobre seu `og:image`. Se sua imagem já tiver texto ou design próprio, defina `"customImage": "replace"` para exibi-la como está.

Quando seu `og:image` for o plano de fundo do cartão, escolha o `theme` correspondente: `dark` para uma imagem escura e `light` para uma imagem clara.

No modo `replace`, o Jamdesk não coloca título sobre a imagem. Se `seo.metatags` definir `og:image`, todas as páginas usarão essa imagem; uma página que definir seu próprio `og:image` usará essa imagem em vez dela. Somente páginas que não tiverem nenhum dos dois receberão um cartão gerado. Use uma imagem PNG ou JPG de 1200×630. Algumas plataformas não exibem imagens WebP ou SVG.

Os sites de redes sociais armazenam em cache as prévias de links. Por isso, um link que já foi compartilhado pode continuar exibindo o cartão antigo por algum tempo após a alteração dessas configurações. Confira o novo cartão com a ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Versões mais antigas da CLI do Jamdesk rejeitam `seo.socialCard` e `seo.titleTemplate` em
`jamdesk validate` e `jamdesk dev`. Atualize com `npm i -g jamdesk@latest`.
</Note>

## Sitemap e robots.txt

Todo site Jamdesk gera automaticamente `sitemap.xml` e `robots.txt` a cada build.

| Arquivo | Finalidade |
|------|---------|
| `sitemap.xml` | Lista todas as páginas com as datas da última modificação para os mecanismos de busca |
| `robots.txt` | Permite o acesso de todos os rastreadores e indica o sitemap |

### Onde encontrá-los

As URLs dependem de a documentação estar em um domínio raiz ou em um subcaminho `/docs`:

<Tabs>
  <Tab title="Domínio raiz">
    Se sua documentação estiver na raiz do domínio (por exemplo, `docs.acme.com` ou `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Subcaminho /docs">
    Se sua documentação estiver em `/docs` no site principal (como neste site em `jamdesk.com/docs`):

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### O que o sitemap inclui

- Todas as páginas publicadas (exceto as que têm `noindex` ou `hidden` no frontmatter)
- Datas da última modificação do frontmatter, quando disponíveis
- Frequência de alteração semanal

### Excluir páginas do sitemap

Adicione `noindex` ao frontmatter para excluir uma página do sitemap e dos mecanismos de busca:

```yaml
---
title: Internal Notes
noindex: true
---
```

Páginas com `hidden: true` também são excluídas automaticamente.

## Dados estruturados JSON-LD

Todas as páginas incluem automaticamente dados estruturados de [schema.org](https://schema.org) em uma tag `<script type="application/ld+json">` com dois esquemas:

- `WebSite`: nome, URL e descrição do site (de `docs.json`).
- `BreadcrumbList`: caminho de navegação da página inicial até a página atual, derivado da configuração `navigation`.

Não é necessária nenhuma configuração. Os mecanismos de busca usam esses dados em resultados avançados, como trilhas de navegação nos resultados de busca.

<Tip>
**Verifique a marcação.** Cole a URL de qualquer página no [Teste de pesquisa aprimorada do Google](https://search.google.com/test/rich-results) para confirmar que os dados estruturados foram detectados.
</Tip>

## IndexNow

Após cada build, o Jamdesk envia automaticamente as URLs das páginas alteradas ao [IndexNow](https://www.indexnow.org) para acelerar a indexação nos mecanismos de busca. Isso notifica o Bing, o Yandex e outros mecanismos de busca participantes sobre as alterações no seu conteúdo, sem esperar o próximo ciclo de rastreamento.

- Executado após cada build bem-sucedido
- Envia somente páginas que realmente foram alteradas
- Não bloqueia o processo, portanto nunca atrasa o build
- Não requer configuração

## Práticas recomendadas

Siga esta lista de verificação antes de publicar:

<Note>
**Lista de verificação antes de publicar**

- **Títulos exclusivos.** Cada página tem um título descritivo e exclusivo com menos de 60 caracteres.
- **Descrições precisas.** As descrições resumem a página em 120 a 160 caracteres.
- **Títulos hierárquicos.** Os títulos seguem uma hierarquia clara: um H1, depois H2 → H3.
- **Links descritivos.** Os links internos usam um texto de âncora significativo, nunca "clique aqui".
- **Texto alternativo das imagens.** Todas as imagens têm texto alternativo para acessibilidade e busca por imagens.
- **Imagem social.** Defina um `og:image` personalizado nas páginas principais ou use o cartão gerado automaticamente. Valide-o com a ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
