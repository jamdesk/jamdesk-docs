## Como otimizar seu conteúdo

### Escreva um frontmatter eficaz

```yaml
---
title: User Authentication    # Under 60 characters
description: Set up OAuth, JWT, and session-based authentication  # 120-160 characters
---
```

<Tip>
**Coloque as palavras-chave no início.** "Configuração de autenticação" é melhor que "Como configurar a autenticação".
</Tip>

### Títulos de página

- Use menos de 60 caracteres para evitar que sejam truncados nos resultados de busca
- Inclua sua palavra-chave principal perto do início
- Use um título exclusivo para cada página da documentação

### Descrições

- Tente usar de 120 a 160 caracteres
- Resuma o que o leitor vai aprender
- Inclua palavras-chave relevantes de forma natural

<Note>
**Alternativa gerada automaticamente.** Quando não há `description` no frontmatter, o Jamdesk extrai automaticamente o primeiro parágrafo em prosa do conteúdo da página (até 155 caracteres). Títulos, blocos de código, imagens e componentes MDX são ignorados. O texto é usado em `<meta name="description">`, no Open Graph e nos cards do Twitter. Ainda recomendamos escrever uma descrição explícita para obter os melhores resultados.
</Note>

## Como controlar a indexação

### Configurações para todo o site

No seu `docs.json`, configure o comportamento padrão dos robôs:

```json docs.json
{
  "seo": {
    "metatags": {
      "robots": "index, follow"
    }
  }
}
```

### Controle por página

Substitua a configuração de indexação para páginas específicas no frontmatter:

```yaml
---
title: Internal Notes
noindex: true
---
```

Use `noindex` para:
- Páginas de rascunho ou em andamento
- Documentação interna
- Conteúdo obsoleto mantido para consulta

### Indexação de busca e ingestão por IA

Os metadados `robots` e `noindex` controlam os **mecanismos de busca**: determinam se uma página aparece no Google e no seu `sitemap.xml`. Eles não afetam os arquivos `llms.txt` e `llms-full.txt` lidos pelas ferramentas de IA. Para deixar de publicá-los, defina `seo.ai.llmsTxt` como `false` (consulte [Desativar llms.txt](/pt/ai/llms-txt#desativar-o-llmstxt)). Os dois controles são independentes: uma página pode ser indexada pelos mecanismos de busca e excluída da ingestão por IA, ou o contrário.

## URLs canônicas

Se sua documentação estiver acessível em várias URLs, defina uma URL canônica:

```yaml
---
title: Getting Started
canonical: https://docs.example.com/getting-started
---
```

Você também pode definir uma base canônica para todo o site em `docs.json`. O Jamdesk acrescenta o
caminho de cada página a ela, para que todas as páginas tenham uma URL canônica correta:

```json docs.json
{
  "seo": {
    "metatags": {
      "canonical": "https://docs.acme.com"
    }
  }
}
```

## Prévia social e Open Graph

O Jamdesk gera automaticamente um card social com sua marca, no formato 1200×630, para cada página. Substitua qualquer tag social no frontmatter. Você pode usar **chaves planas no nível superior** ou um bloco **`seo:`** aninhado. Ambos funcionam e, quando a mesma chave é definida das duas formas, o valor plano do nível superior prevalece.

<Card title="Prévia do OpenGraph" icon="share-nodes" href="https://jamdesk.com/utilities/opengraph-preview" horizontal>
  Veja como o card de qualquer página aparece no X, Facebook, LinkedIn e outras plataformas. Valide também as tags Open Graph com a ferramenta OpenGraph Preview.
</Card>

<CodeGroup>
```yaml Flat (top-level)
---
title: API Reference
description: REST API endpoints and authentication
"og:title": API Reference — Acme
"og:description": Everything you need to call the Acme API
"og:image": /images/api-social-card.png
"twitter:card": summary_large_image
"twitter:creator": "@acme"
keywords: ["api", "rest", "authentication"]
canonical: https://docs.acme.com/api-reference
---
```

```yaml Nested (seo block)
---
title: API Reference
description: REST API endpoints and authentication
seo:
  "og:title": API Reference — Acme
  "og:image": /images/api-social-card.png
  "twitter:card": summary_large_image
  x-custom-tag: any custom meta value
---
```
</CodeGroup>

### Tags compatíveis

| Grupo | Tags |
|-------|------|
| Open Graph | `og:title`, `og:description`, `og:image`, `og:image:width`, `og:image:height`, `og:image:alt`, `og:url`, `og:type`, `og:site_name`, `og:locale`, `og:video`, `og:audio` |
| Artigo | `og:type: article` com `article:published_time`, `article:modified_time`, `article:author`, `article:section`, `article:tag` |
| Twitter / X | `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:image:alt`, `twitter:site`, `twitter:creator`, `twitter:player`, tags de app-card |
| Outros | `keywords`, `author`, `robots`, `googlebot`, `google-site-verification`, `theme-color` e qualquer tag personalizada (coloque tags personalizadas em `seo:`) |

<Note>
**Dimensões personalizadas da imagem OG.** `og:image:width` e `og:image:height` só se aplicam quando
[`customImage`](#personalizar-o-cartão-social) é `"replace"`. Defina-as no mesmo local que
o `og:image` que descrevem: no frontmatter da página ou em `seo.metatags`. O card gerado
sempre tem o formato 1200×630.
</Note>

<Note>
**Tags personalizadas.** Tags meta arbitrárias (por exemplo, `x-pinterest`) são emitidas como `<meta name="...">`.
Coloque-as no bloco `seo:`. Quando definidas no nível superior, somente chaves de SEO reconhecidas são consideradas.
</Note>

### Tipo de card do Twitter / X

A tag `twitter:card` controla o layout usado pelo X e por outras plataformas quando seu link é compartilhado:

| Valor | Aparência |
|-------|--------------------|
| `summary` | Miniatura quadrada pequena à esquerda, com título e descrição ao lado. Compacto. |
| `summary_large_image` | Imagem grande em toda a largura no topo, com título e descrição abaixo. Mais chamativo. |

Para um card de marca no formato 1200×630, use `summary_large_image` para exibir a imagem em toda a largura.

### Imagem padrão para todo o site

Defina uma imagem social alternativa para todas as páginas em `docs.json`. Qualquer página que defina seu próprio `og:image` substituirá essa imagem:

```json docs.json
{
  "seo": {
    "metatags": {
      "og:image": "https://docs.acme.com/images/default-card.png"
    }
  }
}
```

<Tip>
**Confira antes de publicar.** Depois de um build, cole a URL da página na ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview) para conferir a aparência do card em cada plataforma e validar as tags Open Graph. A ferramenta também verifica as dimensões da imagem e explica como corrigir os problemas encontrados.
</Tip>

### Personalizar o cartão social

O card gerado mantém a aparência atual, a menos que você adicione `seo.socialCard` ao `docs.json`.
Defina apenas as chaves que deseja alterar:

```json docs.json
{
  "seo": {
    "socialCard": {
      "theme": "dark",
      "brandColor": true,
      "accentBar": false,
      "siteName": false,
      "customImage": "replace"
    }
  }
}
```

| Chave | Padrão | Efeito |
|-----|---------|--------|
| `theme` | `"light"` | `"dark"` usa texto claro em um fundo escuro e a imagem `logo.dark`. |
| `brandColor` | `false` | `true` colore a barra inferior e o selo da seção com `colors.primary`. Se você definir `colors.light`, um card escuro usará essa cor. Se não houver `colors`, o card usará a cor de destaque do tema. `false` mantém o vermelho padrão. |
| `accentBar` | `true` | `false` remove a barra colorida na parte inferior do card. |
| `siteName` | `true` | `false` oculta o nome do site abaixo do logotipo. Use quando o próprio logotipo já exibir o nome. |
| `customImage` | `"background"` | `"background"` coloca o título da página sobre o `og:image`. `"replace"` usa o `og:image` como o card inteiro. |

O card só pode exibir logotipos SVG, PNG e JPG. Ao gerar o site, o Jamdesk converte arquivos de logotipo PNG e JPG do seu
repositório para WebP. Por isso, o card geralmente exibe o favicon no lugar do logotipo e
mantém o nome do site, mesmo com `siteName: false`. Use um logotipo SVG para exibir o logotipo completo no
card e `logo.dark` em um card escuro.

Se a cor da marca não tiver contraste suficiente com o card, o texto do selo usará a cor de texto
normal. A barra mantém a cor da marca, a menos que ela seja muito parecida com a cor do fundo do card.
Nesse caso, a barra fica cinza.

Por padrão, o Jamdesk coloca o título da página sobre o `og:image`. Se sua imagem já
contiver texto ou design, defina `"customImage": "replace"` para exibi-la sem alterações.

Quando o `og:image` for o fundo do card, escolha o `theme` correspondente: `dark` para uma
imagem escura e `light` para uma imagem clara.

No modo `replace`, o Jamdesk não coloca um título sobre a imagem. Se `seo.metatags` definir `og:image`,
todas as páginas usarão essa imagem, e uma página que definir seu próprio `og:image` usará essa imagem no lugar.
Somente páginas que não tiverem nenhuma dessas opções receberão um card gerado. Use um PNG ou JPG de 1200×630. Algumas plataformas
não exibem imagens WebP ou SVG.

Sites de redes sociais armazenam em cache as prévias dos links, então um link que já foi compartilhado pode continuar exibindo o card antigo por algum tempo após a alteração destas configurações. Confira o novo card com a ferramenta
[OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).

<Note>
Versões antigas da CLI do Jamdesk rejeitam `seo.socialCard` nos comandos `jamdesk validate` e
`jamdesk dev`. Atualize com `npm i -g jamdesk@latest`.
</Note>

## Sitemap e robots.txt

Todo site Jamdesk gera automaticamente `sitemap.xml` e `robots.txt` a cada build.

| Arquivo | Finalidade |
|------|---------|
| `sitemap.xml` | Lista todas as páginas com as datas da última modificação para os mecanismos de busca |
| `robots.txt` | Permite todos os rastreadores e os direciona ao sitemap |

### Onde encontrá-los

As URLs dependem de a documentação estar em um domínio raiz ou em um subcaminho `/docs`:

<Tabs>
  <Tab title="Domínio raiz">
    Se a documentação estiver na raiz do domínio (por exemplo, `docs.acme.com` ou `acme.jamdesk.app`):

    ```bash
    https://docs.acme.com/sitemap.xml
    https://docs.acme.com/robots.txt
    ```
  </Tab>
  <Tab title="Subcaminho /docs">
    Se a documentação estiver em `/docs` no site principal, como neste site em `jamdesk.com/docs`:

    ```bash
    https://jamdesk.com/docs/sitemap.xml
    https://jamdesk.com/docs/robots.txt
    ```
  </Tab>
</Tabs>

### O que o sitemap inclui

- Todas as páginas publicadas (exceto as que têm `noindex` ou `hidden` no frontmatter)
- Datas da última modificação do frontmatter, quando disponíveis
- Frequência de alteração semanal

### Excluir páginas do sitemap

Adicione `noindex` ao frontmatter para excluir uma página do sitemap e dos mecanismos de busca:

```yaml
---
title: Internal Notes
noindex: true
---
```

Páginas com `hidden: true` também são excluídas automaticamente.

## Dados estruturados JSON-LD

Cada página inclui automaticamente dados estruturados [schema.org](https://schema.org) em uma tag `<script type="application/ld+json">` com dois esquemas:

- `WebSite`: nome, URL e descrição do site (de `docs.json`).
- `BreadcrumbList`: caminho de navegação da página inicial até a página atual, derivado da configuração `navigation`.

Não é necessária nenhuma configuração. Os mecanismos de busca usam esses dados para resultados avançados, como trilhas de navegação nos resultados de busca.

<Tip>
**Valide a marcação.** Cole a URL de qualquer página no [Teste de pesquisa aprimorada do Google](https://search.google.com/test/rich-results) para confirmar se os dados estruturados foram detectados.
</Tip>

## IndexNow

Após cada build, o Jamdesk envia automaticamente as URLs das páginas alteradas para o [IndexNow](https://www.indexnow.org), acelerando a indexação nos mecanismos de busca. Isso notifica o Bing, o Yandex e outros mecanismos de busca participantes sobre as alterações no seu conteúdo, sem esperar pelo próximo ciclo de rastreamento.

- É executado após cada build bem-sucedido
- Envia somente páginas que realmente mudaram
- Não bloqueia o processo, portanto nunca atrasa o build
- Não requer configuração

## Práticas recomendadas

Confira esta lista antes de publicar:

<Note>
**Lista de verificação antes da publicação**

- **Títulos exclusivos.** Cada página tem um título descritivo e diferente, com menos de 60 caracteres.
- **Descrições precisas.** As descrições resumem a página em 120 a 160 caracteres.
- **Títulos organizados.** Os títulos seguem uma hierarquia clara: um H1, depois H2 → H3.
- **Links descritivos.** Os links internos usam um texto de âncora significativo, nunca "clique aqui".
- **Texto alternativo das imagens.** Todas as imagens têm texto alternativo para acessibilidade e buscas por imagens.
- **Imagem social.** Defina um `og:image` personalizado nas páginas principais ou use o card gerado automaticamente. Valide-o com a ferramenta [OpenGraph Preview](https://jamdesk.com/utilities/opengraph-preview).
</Note>
