---
title: Consentimento de cookies
description: Bloqueie scripts de análise até o consentimento de cookies com integrations.cookies e carregue um banner de consentimento Osano ou Termly no seu site de docs.
---

A Jamdesk pode reter todos os scripts de análise e rastreamento (Google Analytics, Google Tag Manager, Plausible, chat do Crisp, JavaScript personalizado e a análise integrada da própria Jamdesk) até que o visitante consinta com os cookies. A Jamdesk lê o consentimento do `localStorage` do navegador. Qualquer plataforma de gerenciamento de consentimento (CMP) que registre o consentimento ali funciona, incluindo Osano e Termly.

Nenhum rastreamento é executado antes que o visitante concorde. Isso ajuda você a cumprir regulamentações de privacidade como LGPD, GDPR, CCPA e a Diretiva ePrivacy.

## Como funciona

Defina uma chave de `localStorage` e o valor que significa "consentimento concedido" no `docs.json`:

```json docs.json
{
  "integrations": {
    "cookies": {
      "key": "jamdesk_consent",
      "value": "granted"
    }
  }
}
```

Com `integrations.cookies` definido, nenhum script de análise é carregado até que `localStorage["jamdesk_consent"]` seja igual a `"granted"`. Os scripts são carregados assim que o seu banner de consentimento registra a aceitação, sem recarregar a página. A revogação do consentimento tem efeito no próximo carregamento completo da página do visitante. Scripts já em execução na página atual continuam executando até que o visitante navegue para outra página ou recarregue.

<Info>
`key` e `value` são obrigatórios. Uma `key` ou `value` ausente ou vazia desativa o controle de consentimento. Nesse caso, os scripts são carregados normalmente.
</Info>

<Warning>
O controle também se aplica à análise integrada da Jamdesk. Visitantes que nunca consentirem não são contabilizados. Espere números de visualizações de página menores no painel do seu projeto após ativar esta opção.
</Warning>

## Conectando seu banner de consentimento

A maioria das CMPs (incluindo Osano e Termly) não expõe uma flag estável de `localStorage` que a Jamdesk possa ler. Elas armazenam o consentimento em cookies ou em valores que mudam por visitante. Em vez disso, adicione um pequeno **snippet de ponte** na área de código personalizado da própria CMP. Ele grava `jamdesk_consent` quando um visitante aceita. O snippet é executado como parte da CMP, portanto sempre roda. O JavaScript personalizado da Jamdesk não consegue fazer essa tarefa, pois ele mesmo está sujeito ao controle.

O snippet grava `granted` ao consentir e remove a chave quando o consentimento é retirado. O controle então é reaplicado no próximo carregamento da página.

## Osano

Adicione seu script do Osano no `docs.json`:

```json docs.json
{
  "integrations": {
    "osano": {
      "scriptSource": "https://cmp.osano.com/YOUR_CUSTOMER_ID/YOUR_CONFIG_ID/osano.js"
    }
  }
}
```

A URL do script vem do seu painel do Osano. Ela sempre começa com `https://cmp.osano.com/` e termina com `/osano.js`.

Depois, adicione esta ponte no Osano (Consent Manager → sua configuração → JavaScript personalizado):

```js
function jdOsanoBridge(consent) {
  if (consent && consent.ANALYTICS === 'ACCEPT') {
    localStorage.setItem('jamdesk_consent', 'granted');
  } else {
    localStorage.removeItem('jamdesk_consent');
  }
}
if (window.Osano && window.Osano.cm) {
  jdOsanoBridge(window.Osano.cm.getConsent());
  window.Osano.cm.addEventListener('osano-cm-consent-saved', jdOsanoBridge);
} else {
  window.addEventListener('osano-cm-initialized', function () {
    jdOsanoBridge(window.Osano.cm.getConsent());
    window.Osano.cm.addEventListener('osano-cm-consent-saved', jdOsanoBridge);
  });
}
```

## Termly

Adicione seu script do Termly no `docs.json`:

```json docs.json
{
  "integrations": {
    "termly": {
      "scriptSource": "https://app.termly.io/resource-blocker/YOUR-WEBSITE-UUID?autoBlock=on"
    }
  }
}
```

A URL vem das instruções de incorporação do Termly para o seu site (o script Resource Blocker). A query `?autoBlock=on` é opcional e ativa o bloqueio automático de scripts do Termly.

Depois, adicione esta ponte no Termly (seu site → HTML/JavaScript personalizado):

```js
function jdTermlyBridge() {
  var s = Termly.getConsentState();
  if (s && s.analytics) {
    localStorage.setItem('jamdesk_consent', 'granted');
  } else {
    localStorage.removeItem('jamdesk_consent');
  }
}
(function register() {
  if (window.Termly && typeof Termly.on === 'function') {
    Termly.on('consent', jdTermlyBridge);
    try { jdTermlyBridge(); } catch (e) {}
  } else {
    setTimeout(register, 200);
  }
})();
```

Osano e Termly são carregados primeiro no `<head>` da página, antes de qualquer outro script. O bloqueio automático deles depende disso.

<Warning>
Se a sua CMP rodar em modo estrito ou de bloqueio automático, inclua na lista de permissões `*.jamdesk.app` e o seu domínio de docs personalizado nas regras gerenciadas dela (Osano: classificação/lista de permissões; Termly: Domain Rules ou Custom Blocking Map). Caso contrário, a CMP pode bloquear os recursos do seu site de docs e quebrar a página.
</Warning>

## Testando sua configuração

O controle só funciona no seu site publicado. A prévia local `jamdesk dev` ignora a configuração de consentimento. Para testar:

1. Abra o seu site de docs publicado com o `localStorage` vazio. A análise não deve carregar (verifique a aba Network do navegador: nenhuma requisição ao Google, Plausible ou `/api/ev`).
2. No console do navegador, execute `localStorage.setItem("jamdesk_consent", "granted")`. Os scripts devem carregar em cerca de um segundo, sem recarregar a página.

## Desativando completamente as análises do Jamdesk

Desative a análise integrada (sem cookies) da Jamdesk para todos os visitantes, independentemente do consentimento:

```json docs.json
{
  "analytics": { "enabled": false }
}
```
