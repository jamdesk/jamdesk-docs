O Jamdesk pode reparar muitos dos links quebrados e das descrições de página ausentes que um build reporta. O botão **Fix with AI** lê esses avisos de build e propõe uma edição para cada um. Ele faz commit das correções que você aprovar no seu repositório GitHub conectado. O commit inicia um novo build.

As capturas de tela mostram a interface em inglês.

O [comando de CLI `jamdesk fix`](/pt/cli/fix-broken-links) faz o mesmo no seu terminal. Ele grava na sua cópia de trabalho e deixa o commit por sua conta.

## O que ele corrige

Fix with AI repara três tipos de aviso de build:

- **Links internos quebrados:** um fragmento de link que aponta para um cabeçalho que não existe mais na página de destino, como um erro de digitação (`#instalation` → `#installation`), ou uma página traduzida cujo cabeçalho foi renomeado.
- **Descrições de página ausentes:** uma página sem `description` no frontmatter. O Jamdesk escreve um resumo curto a partir do conteúdo da página para você revisar.
- **Títulos de página ausentes:** uma página sem título recebe um título sugerido a partir do conteúdo, para você revisar.

Ele propõe uma alteração somente quando consegue resolver o destino com confiança. Qualquer coisa ambígua é listada separadamente para você corrigir manualmente.

Fix with AI faz até 1.000 requisições de IA por projeto em um período de 24 horas. Resultados de páginas que não mudaram são reutilizados e não contam para o limite.

<Note>
  A contagem de itens corrigíveis não é a mesma que a contagem de avisos. Um build pode mostrar cinco avisos enquanto Fix with AI oferece para reparar três deles. Os outros dois não têm uma correção inequívoca.
</Note>

## Pré-requisitos

- Um [repositório GitHub conectado](/pt/integrations/github) para o projeto.
- Acesso de escrita para o GitHub App do Jamdesk fazer commit das correções. O modal mostra um link **Grant access** para o GitHub quando o acesso está ausente.
- Um build concluído que contenha avisos de links quebrados ou descrições ausentes.

## Encontre o banner

Abra seu projeto e role até **Build History** na página inicial do projeto. Um banner com uma contagem e um botão **Fix with AI** aparece acima da lista de builds quando seu build mais recente tem problemas corrigíveis.

O banner aparece somente no seu build concluído mais recente. As correções sempre se aplicam ao estado atual da sua documentação.

## Revise e aplique as correções

<Steps>
  <Step title="Abra a prévia">
    Clique em **Fix with AI**. O modal se abre. O agente de IA leva alguns segundos para revisar sua documentação e montar um plano de correção.
  </Step>
  <Step title="Leia cada alteração proposta">
    As correções são agrupadas por tipo. **Broken links** mostra cada âncora reescrita. **Missing descriptions** mostra o resumo sugerido para cada página. **Missing titles** mostra o título proposto. Desmarque a caixa de qualquer item para ignorá-lo desta vez. Use o botão de ignorar para [silenciar uma recomendação de vez](#ignorar-recomendações). Problemas sem correção clara aparecem em **Can't be fixed automatically** para você corrigir manualmente.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="The Fix with AI modal. A Broken links section lists three checked fixes, each showing the old anchor struck through and the corrected anchor. A Can't be fixed automatically section lists two issues to fix by hand, above Cancel and Apply 3 fixes buttons." />
    </Frame>
  </Step>
  <Step title="Aplique">
    Clique em **Apply fixes**. O Jamdesk faz commit das alterações selecionadas na sua branch conectada com a mensagem `docs: apply AI-suggested fixes (via Jamdesk)` e inicia um novo build.
  </Step>
  <Step title="Confirme a reconstrução">
    Acompanhe o novo build em [Build History](/pt/builds/monitoring). Os avisos corrigidos desaparecem assim que ele entra no ar. O que restar é um aviso que o Fix with AI não conseguiu resolver ou um novo problema do conteúdo mais recente.
  </Step>
</Steps>

<Note>
  Aplicar grava um commit real no seu repositório. Revise ou reverta-o no GitHub como qualquer outro commit.
</Note>

## Quando alguns problemas não podem ser corrigidos

O modal lista, sob um título separado, os avisos sem correção clara e não os altera. Motivos comuns:

- Um link quebrado cuja página ou cabeçalho de destino não existe em lugar nenhum.
- Uma entrada de navegação sem arquivo de origem correspondente.
- Uma página para a qual o agente não conseguiu gerar uma descrição.

Esses casos exigem uma edição manual. Abra a página no [editor](/pt/development/local-preview) ou no seu editor de código. Corrija o link ou adicione a descrição. Envie as alterações para reconstruir.

## Ignorar recomendações

Alguns avisos não valem a pena: um link que você quebrou de propósito, ou uma página stub que não precisa de descrição. Desmarcar uma correção só a ignora uma vez. Ignorar a remove da contagem até que você a restaure.

Cada linha do modal tem um botão de ignorar, corrigível ou não. Clicar nele move o item para uma seção recolhida **Ignored** na parte inferior. A contagem do banner na página inicial do projeto diminui de acordo depois que você fecha o modal. Os avisos correspondentes desaparecem do Build History no build atual e em todos os seguintes. **Ignore all** faz o mesmo com tudo o que ainda está listado.

Como os ignorados se comportam:

- **Compartilhados e persistentes:** os ignorados se aplicam ao projeto inteiro. Todos os membros veem a mesma lista. Eles persistem entre builds. O Jamdesk identifica cada aviso pelo conteúdo, não pelo número da linha. Editar outras partes da página não faz um item ignorado voltar.
- **Restaurando:** expanda a seção **Ignored** e clique em **Restore** em qualquer item. Ignorar tudo em um build oculta o banner. Um pequeno link "N ignored recommendations" abaixo de Build History então reabre o modal.
- **Avisos alterados voltam:** um item ignorado retorna como nova recomendação quando o problema subjacente muda, por exemplo quando o link quebrado agora aponta para outro lugar.

## Fix with AI vs. a CLI

O painel e a CLI corrigem âncoras de links quebrados. Elas diferem em onde rodam e em como a alteração chega.

| | Fix with AI (painel) | [`jamdesk fix`](/pt/cli/fix-broken-links) (CLI) |
|---|---|---|
| Executa | No painel, em um build | No seu terminal, sobre arquivos locais |
| Corrige | Links quebrados e descrições ausentes | Âncoras de links quebrados |
| Commit | Faz commit na sua branch por você | Grava arquivos locais; você faz o commit |
| Gatilho | Um clique no banner do build | `jamdesk fix` |

Use o fluxo do painel para um reparo rápido sem sair do Jamdesk. Use a CLI quando quiser as alterações primeiro na sua cópia de trabalho, por exemplo para agrupá-las com outras edições.
