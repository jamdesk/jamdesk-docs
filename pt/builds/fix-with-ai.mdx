O Jamdesk pode reparar muitos dos links quebrados e das descrições de página ausentes que um build reporta. O botão **Corrigir com IA** lê esses avisos de build e propõe uma edição para cada um. Ele faz commit das correções que você aprovar no seu repositório GitHub conectado. O commit inicia um novo build.

As capturas de tela mostram a interface em inglês.

O [comando de CLI `jamdesk fix`](/pt/cli/fix-broken-links) faz o mesmo no seu terminal. Ele grava na sua cópia de trabalho e deixa o commit por sua conta.

## O que ele corrige

Corrigir com IA repara três tipos de aviso de build:

- **Links internos quebrados:** um fragmento de link que aponta para um título que não existe mais na página de destino, como um erro de digitação (`#instalation` → `#installation`), ou uma página traduzida cujo título foi renomeado.
- **Descrições de página ausentes:** uma página sem `description` no seu frontmatter. O Jamdesk escreve um resumo curto a partir do conteúdo da página para você revisar.
- **Títulos de página ausentes:** uma página sem título recebe um título sugerido a partir do conteúdo da página, para você revisar.

Ele propõe uma alteração apenas quando consegue resolver o destino com confiança. Qualquer item ambíguo é listado separadamente para você corrigir manualmente.

Corrigir com IA faz até 1.000 requisições de IA por projeto em um período de 24 horas. Resultados para páginas que não mudaram são reutilizados e não contam para o limite.

<Note>
  A contagem de itens corrigíveis não é a mesma que a contagem de avisos. Um build pode mostrar cinco avisos enquanto Corrigir com IA oferece reparar três deles. Os outros dois não têm uma correção inequívoca.
</Note>

## Escolha o que acontece

A configuração **Correções de IA** decide o que o Jamdesk faz com os avisos corrigíveis. Para alterá-la, clique em **Configurações** na barra lateral e encontre o cartão **Correções de IA** em **Geral**.

| Modo | O que acontece |
|---|---|
| **Desativado** | O Jamdesk não analisa os builds. O botão **Corrigir com IA** fica oculto. |
| **Revisar primeiro** | O Jamdesk sugere correções. Você revisa e aplica no modal. Este é o padrão. |
| **Correção automática** | O Jamdesk faz commit das correções após cada build. Você pode desfazer cada execução. |

### Como funciona a Correção automática

A Correção automática aplica as mesmas correções do modal, incluindo descrições escritas por IA. Ela ignora qualquer item que você tenha ignorado. Começa com o próximo build após você salvar a configuração.

Após um build, o Jamdesk faz commit das correções na branch de build do projeto. A mensagem do commit é `docs: auto-fix 3 issues (via Jamdesk)` e o autor é o Jamdesk. O build mostra um selo **Corrigido automaticamente** no Histórico de Builds. Para [documentação sem GitHub](/pt/setup/without-github), o Jamdesk salva as correções na sua documentação.

<Warning>
  O Jamdesk faz commit na sua branch. Faça pull antes de fazer push. Cada commit de correção automática também executa qualquer CI que seu repositório tenha nessa branch.
</Warning>

O que esperar de cada execução:

- O Jamdesk não corrige automaticamente o build do próprio commit. Se esse build ainda tiver avisos corrigíveis, ele mostra **Precisa de revisão** e você os aplica pelo modal.
- Uma correção é aplicada uma única vez. Se você a reverter, o Jamdesk não a aplica novamente, então sua reversão permanece. Uma correção que volta aparece em **Precisa de revisão**.
- Builds cujos avisos não mudaram desde a última execução são ignorados.
- A correção automática pausa quando a branch de build está protegida ou o GitHub App do Jamdesk perde acesso de escrita. O cartão mostra **Pausado**. Corrija a causa e salve **Correção automática** novamente.
- Os limites diários de IA são os mesmos do modal. Quando um projeto atinge o limite, a execução pula algumas correções e informa isso.
- Uma nova descrição altera a página, então a próxima execução de tradução traduz essa página novamente.

## Pré-requisitos

- Um [repositório GitHub conectado](/pt/integrations/github) para o projeto.
- Acesso de escrita para o GitHub App do Jamdesk fazer commit das correções. O modal mostra um link **Conceder acesso** para o GitHub quando o acesso está ausente.
- Um build concluído que contenha avisos de links quebrados ou descrições ausentes.

## Encontre o banner

Abra seu projeto e role até **Histórico de Builds** na página Início do Projeto. Um banner com uma contagem e um botão **Corrigir com IA** aparece acima da lista de builds quando seu build mais recente tem problemas corrigíveis.

## Revise e aplique as correções

<Steps>
  <Step title="Abra a prévia">
    Clique em **Corrigir com IA**. O modal abre. O agente de IA leva alguns segundos para revisar sua documentação e montar um plano de correção.
  </Step>
  <Step title="Leia cada alteração proposta">
    As correções são agrupadas por tipo. **Links quebrados** mostra cada âncora reescrita. **Descrições ausentes** mostra o resumo sugerido para cada página. **Títulos ausentes** mostra o título proposto. Desmarque a caixa de qualquer item para pulá-lo desta vez. Use o botão de ignorar para [silenciar uma recomendação de forma definitiva](#ignorar-recomendações). Problemas sem uma correção clara aparecem em **Não pode ser corrigido automaticamente** para você corrigir manualmente.

    <Frame>
      <img src="/images/fix-with-ai/modal.webp" alt="O modal Corrigir com IA. Uma seção Links quebrados lista três correções marcadas, cada uma mostrando a âncora antiga riscada e a âncora corrigida. Uma seção Não pode ser corrigido automaticamente lista dois problemas para corrigir manualmente, acima dos botões Cancelar e Aplicar 3 correções." />
    </Frame>
  </Step>
  <Step title="Aplique">
    Clique em **Aplicar correções**. O Jamdesk faz commit das alterações selecionadas na sua branch conectada com a mensagem `docs: apply AI-suggested fixes (via Jamdesk)` e inicia um novo build.
  </Step>
  <Step title="Confirme a reconstrução">
    Acompanhe o novo build no [Histórico de Builds](/pt/builds/monitoring). Os avisos corrigidos desaparecem quando ele for publicado. O que restar é um aviso que a Corrigir com IA não conseguiu resolver ou um novo problema do conteúdo mais recente.
  </Step>
</Steps>

<Note>
  Aplicar grava um commit real no seu repositório. Revise ou reverta-o no GitHub como qualquer outro commit.
</Note>

## Quando alguns problemas não podem ser corrigidos

O modal lista, sob um título separado, os avisos sem uma correção clara e não os altera. Motivos comuns:

- Um link quebrado cuja página ou título de destino não existe em lugar nenhum.
- Uma entrada de navegação sem um arquivo de origem correspondente.
- Uma página em que o agente não conseguiu gerar uma descrição.

Estes exigem uma edição manual. Abra a página no [editor](/pt/development/local-preview) ou no seu editor de código. Corrija o link ou adicione a descrição. Envie as alterações para reconstruir.

## Ignorar recomendações

Alguns avisos não valem a pena ser tratados: um link que você quebrou de propósito, ou uma página stub que não precisa de descrição. Desmarcar uma correção só a pula uma vez. Ignorar a remove da contagem até que você a restaure.

Cada linha do modal tem um botão de ignorar, corrigível ou não. Clicar nele move o item para uma seção recolhida **Ignorados** no final. A contagem do banner na página Início do Projeto diminui de acordo depois que você fecha o modal. Os avisos correspondentes desaparecem do Histórico de Builds no build atual e em todos os seguintes. **Ignorar tudo** faz o mesmo para tudo o que ainda estiver listado.

Como os ignorados se comportam:

- **Compartilhados e persistentes:** os ignorados se aplicam ao projeto inteiro. Todos os membros veem a mesma lista. Eles persistem entre builds. O Jamdesk identifica cada aviso pelo conteúdo, não pelo número da linha. Editar outras partes da página não traz de volta um item ignorado.
- **Restauração:** expanda a seção **Ignorados** e clique em **Restaurar** em qualquer item. Ignorar tudo em um build oculta o banner. Um pequeno link "N recomendações ignoradas" sob o Histórico de Builds reabre o modal.
- **Avisos alterados voltam:** um item ignorado retorna como uma nova recomendação quando o problema subjacente muda, por exemplo quando o link quebrado agora aponta para outro lugar.

## Desfazer uma correção automática

Cada execução de correção automática tem um botão **Desfazer**. Abra o build no Histórico de Builds e encontre a seção **Correção automática**. Ela lista o que o Jamdesk alterou e tem um link para o commit. Clique em **Desfazer** e depois em **Desfazer correção automática** para confirmar.

O Jamdesk faz commit da versão anterior dos arquivos na sua branch com a mensagem `docs: undo Jamdesk auto-fix (via Jamdesk)`. Se um arquivo mudou após a correção automática, o Jamdesk o pula e o lista. Desfaça essas alterações manualmente.

Correções desfeitas são ignoradas. Seus avisos ficam ocultos, e o Jamdesk não as aplica novamente. Para trazê-las de volta, abra **Corrigir com IA** e restaure-as em **Ignorados**.

## Entregue as correções ao seu agente de IA

Você pode deixar um agente de programação, como o Claude Code, fazer as edições no seu repositório. No modal Corrigir com IA, clique em **Copiar para o seu agente de IA**. O Jamdesk copia um prompt em texto simples que lista cada correção sugerida com seu arquivo e linha, além dos problemas a corrigir manualmente. Itens ignorados ficam de fora. Cole o prompt no seu agente.

No terminal, `jamdesk fix --json` fornece a um agente a mesma lista em JSON. Veja [Usar com um agente de IA](/pt/cli/fix-broken-links#uso-com-um-agente-de-ia).

## Fix with AI vs. a CLI

O painel e a CLI corrigem âncoras de links quebrados. Eles diferem em onde executam e em como a alteração é aplicada.

| | Corrigir com IA (painel) | [`jamdesk fix`](/pt/cli/fix-broken-links) (CLI) |
|---|---|---|
| Executa | No painel, em um build | No seu terminal, em arquivos locais |
| Corrige | Links quebrados, descrições ausentes e títulos ausentes | Âncoras de links quebrados, além de descrições ausentes com IA |
| Commit | Faz commit na sua branch por você | Grava arquivos locais; você faz o commit |
| Gatilho | Um clique no banner do build | `jamdesk fix` |

Use o fluxo do painel para um reparo rápido sem sair do Jamdesk. Use a CLI quando quiser as alterações na sua cópia de trabalho primeiro, por exemplo para agrupá-las com outras edições.

Definir **Correções de IA** como **Desativado** interrompe as análises do painel. O `jamdesk fix` continua executando no seu computador. Para alterar a configuração pelo terminal, execute [`jamdesk ai-fix`](/pt/cli/overview) com `off`, `review` ou `auto`:

```bash
jamdesk ai-fix auto
```
