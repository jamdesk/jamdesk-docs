Cada build passa por várias fases, da fila até entrar no ar. Monitore o progresso na aba **Deployments**.

## Fases do build

<Steps>
  <Step title="Na fila">
    O build está aguardando para começar. A maioria dos builds começa em poucos segundos.
  </Step>
  <Step title="Clonando">
    Extraindo o conteúdo do seu repositório do GitHub.
  </Step>
  <Step title="Validando">
    Verificando a configuração `docs.json` e a sintaxe MDX.
  </Step>
  <Step title="Processando">
    Analisando arquivos MDX e resolvendo imports.
  </Step>
  <Step title="Buildando">
    Compilando MDX para HTML e aplicando realce de sintaxe.
  </Step>
  <Step title="Fazendo deploy">
    Enviando para a CDN e limpando o cache.
  </Step>
  <Step title="No ar">
    Build concluído. Sua documentação está atualizada.
  </Step>
</Steps>

## Visualizando o status do build

### Visão geral do dashboard

A página principal do seu projeto mostra:

- Status atual do build
- Horário do último deploy bem-sucedido
- Histórico recente de builds

### Detalhes do build

Clique em qualquer build para ver:

- Horário de início e término
- Duração
- Iniciado por (push, manual, CLI)
- Hash e mensagem do commit
- Log completo do build

### Avisos e sugestões

Os builds concluídos podem apresentar dois níveis de feedback:

- **Avisos** (badge laranja) — problemas que vale a pena corrigir, como links quebrados ou recursos ausentes. Eles nunca fazem o build falhar.
- **Sugestões** (lâmpada) — melhorias opcionais para a identidade visual e o SEO do seu site, como adicionar um [favicon, uma descrição ou um logotipo](/pt/customization/branding). As sugestões aparecem somente no build concluído mais recente, não contam para o badge de avisos e nunca são enviadas por e-mail.

Muitos avisos sobre links quebrados e descrições ausentes podem ser corrigidos automaticamente. Quando o build mais recente tiver problemas corrigíveis, use [Fix with AI](/pt/builds/fix-with-ai) para revisar e aplicar as alterações sem editar MDX manualmente.

## Logs do build

Logs detalhados ajudam a depurar problemas:

```text
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Notificações de build

O Jamdesk pode enviar alertas por e-mail ou Slack quando um build é concluído ou falha:

### E-mail

Ative os alertas de falha do build em **Settings** → **Notifications**.

### Slack

Conecte o Slack para receber notificações de build no seu canal. Consulte [Slack Integration](/pt/integrations/slack).

## Histórico de builds

Veja seus últimos 30 builds na aba **Deployments**:

- Status do build (bem-sucedido, com falha, cancelado)
- Duração
- Tipo de acionamento
- Informações do commit

## Cancelando builds

Para cancelar um build em execução:

1. Acesse a aba **Deployments**
2. Encontre o build em execução
3. Clique em **Cancel**

O build bem-sucedido anterior continua no ar.
