---

Cada build passa por várias fases, da fila até ficar ao vivo. Acompanhe o progresso na aba Deployments.

## Fases do build

<Steps>
  <Step title="Na fila">
    O build está aguardando para começar. A maioria dos builds inicia em poucos segundos.
  </Step>
  <Step title="Clonagem">
    Baixando o conteúdo do seu repositório do GitHub.
  </Step>
  <Step title="Validação">
    Verificando a configuração em `docs.json` e a sintaxe MDX.
  </Step>
  <Step title="Processamento">
    Analisando os arquivos MDX e resolvendo as importações.
  </Step>
  <Step title="Build">
    Compilando MDX para HTML e aplicando o destaque de sintaxe.
  </Step>
  <Step title="Deploy">
    Enviando para a CDN e limpando o cache.
  </Step>
  <Step title="Ao vivo">
    Build concluído. Sua documentação foi atualizada.
  </Step>
</Steps>

## Visualizando o status do build

### Visão geral do dashboard

A página principal do seu projeto mostra:

- Status atual do build
- Horário do último deploy bem-sucedido
- Histórico recente de builds

### Detalhes do build

Clique em qualquer build para ver:

- Horário de início e de término
- Duração
- Acionado por (push, manual, CLI)
- Hash e mensagem do commit
- Log completo do build

### Avisos e sugestões

Builds concluídos podem trazer dois níveis de feedback:

- **Avisos** (selo laranja): problemas que vale corrigir, como links quebrados ou recursos ausentes. Eles nunca fazem o build falhar.
- **Sugestões** (lâmpada): ajustes opcionais para a identidade visual e o SEO do seu site, como adicionar um [favicon, descrição ou logo](/pt/customization/branding). As sugestões aparecem apenas no seu build concluído mais recente. Elas não contam para o selo de avisos. A Jamdesk nunca as envia por e-mail.

[Fix with AI](/pt/builds/fix-with-ai) corrige muitos avisos de links quebrados e de descrições ausentes no seu build mais recente. Revise e aplique as alterações sem editar o MDX manualmente.

## Logs do build

Logs detalhados ajudam a depurar problemas:

```text
[12:34:56] Starting build...
[12:34:57] Cloning repository...
[12:34:59] Found docs.json at root
[12:35:00] Validating configuration...
[12:35:01] Processing 45 pages...
[12:35:15] Building search index...
[12:35:18] Deploying to CDN...
[12:35:22] Build complete!
```

## Notificações de build

A Jamdesk pode avisar por e-mail ou Slack quando um build termina ou falha:

### E-mail

Ative os alertas de falha de build em **Settings** → **Notifications**.

### Slack

Conecte o Slack para receber notificações de build no seu canal. Veja [Integração com Slack](/pt/integrations/slack).

## Histórico de builds

Veja seus últimos 30 builds na aba **Deployments**:

- Status do build (sucesso, falhou, cancelado)
- Duração
- Tipo de gatilho
- Informações do commit

## Cancelando builds

Para cancelar um build em execução:

1. Acesse a aba **Deployments**
2. Localize o build em execução
3. Clique em **Cancel**

O build bem-sucedido anterior continua ativo.
