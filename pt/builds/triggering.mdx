title: Acionando builds
description: Os builds são acionados automaticamente ao fazer push no Git ou manualmente pelo dashboard, com suporte a debounce e comportamento da fila.
---

Faça push para o GitHub e o Jamdesk iniciará os builds automaticamente. Você também pode acionar builds pelo dashboard.

## Builds automáticos

Cada push para sua branch conectada aciona um build automaticamente:

1. Você envia alterações para o GitHub
2. O GitHub envia um Webhook para o Jamdesk
3. O Jamdesk coloca o build na fila e o inicia
4. A documentação compilada é publicada na CDN

<Tip>
Os builds usam debounce. Se você enviar vários commits rapidamente, o Jamdesk aguardará 10 segundos para que a atividade se estabilize antes de iniciar o build.
</Tip>

## Builds manuais

Acione um build sem enviar alterações:

<Steps>
  <Step title="Abra seu projeto">
    Acesse seu projeto no dashboard.
  </Step>
  <Step title="Acesse Settings">
    Clique em **Settings** na barra lateral.
  </Step>
  <Step title="Clique em Rebuild">
    Selecione **Rebuild** para iniciar um novo build.
  </Step>
</Steps>

### Quando usar builds manuais

- Depois de alterar variáveis de ambiente
- Para atualizar após uma falha no build
- Depois de atualizações da plataforma Jamdesk
- Para limpar o conteúdo armazenado em cache

## Fila de builds

Durante períodos de tráfego intenso, os builds podem aguardar brevemente na fila. A posição na fila é exibida no dashboard. Os builds são processados na ordem em que foram recebidos.

## Builds simultâneos

Cada projeto pode ter um build em execução por vez. Novos acionamentos enquanto um build está em execução serão adicionados à fila.

| Plano | Projetos simultâneos |
|------|----------------------|
| Trial | 1 |
| Pro | 3 |
