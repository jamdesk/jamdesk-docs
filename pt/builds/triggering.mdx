title: Acionando builds

---

O Jamdesk gera a build da sua documentação a cada push para o GitHub. Você também pode acionar uma build pelo dashboard.

## Builds automáticos

Cada push para o branch conectado aciona uma build:

1. Você envia as alterações para o GitHub
2. O GitHub envia um webhook para o Jamdesk
3. O Jamdesk coloca sua build na fila e a inicia
4. A documentação gerada é publicada na CDN

<Tip>
As builds passam por debounce. O Jamdesk aguarda 10 segundos sem nenhum novo push e só então inicia a build.
</Tip>

## Builds manuais

Aciona uma build sem enviar alterações:

<Steps>
  <Step title="Abra seu projeto">
    Acesse seu projeto no dashboard.
  </Step>
  <Step title="Acesse Settings">
    Clique em **Settings** na barra lateral.
  </Step>
  <Step title="Clique em Rebuild">
    Selecione **Rebuild**. Uma nova build é iniciada.
  </Step>
</Steps>

### Quando usar builds manuais

- Após alterar variáveis de ambiente
- Para atualizar depois de uma build com falha
- Após atualizações da plataforma Jamdesk
- Para limpar o conteúdo em cache

## Fila de builds

As builds podem entrar brevemente na fila durante picos de tráfego. O dashboard mostra a posição na fila. As builds são executadas na ordem em que foram recebidas.

## Builds simultâneos

Cada projeto executa uma build por vez. Um acionamento que chega durante uma build em execução aguarda na fila.

| Plano | Projetos simultâneos |
|------|---------------------|
| Trial | 1 |
| Pro | 3 |
