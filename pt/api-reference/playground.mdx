O playground da API adiciona um botão interativo "Try it" às páginas de endpoint da API. Os desenvolvedores preenchem parâmetros, veem exemplos de código serem atualizados em tempo real e enviam requisições HTTP reais diretamente da página da documentação.

As capturas de tela mostram a interface em inglês.

  <img src="/images/playground/playground-modal.webp" alt="Modal do playground da API com um formulário de parâmetros à esquerda e exemplos de código em tempo real à direita" />
</Frame>

## Início rápido

O playground fica ativado por padrão, sem necessidade de configuração em `docs.json`. Todas as páginas com um campo `openapi:` ou `api:` no frontmatter exibem o botão "Try it". Não é necessário configurar o CORS.

## Modos de exibição

O campo `display` controla o que o playground pode fazer:

| Modo | Botão "Try it" | Preencher parâmetros | Código em tempo real | Enviar requisição |
|------|:-:|:-:|:-:|:-:|
| `"interactive"` (padrão) | ✓ | ✓ | ✓ | ✓ |
| `"simple"` | ✓ | ✓ | ✓ | ✗ |
| `"none"` | ✗ | ✗ | ✗ | ✗ |

<Tabs>
  <Tab title="Interativo">
    Experiência completa do playground. Os desenvolvedores preenchem parâmetros, veem exemplos de código serem atualizados em tempo real e enviam requisições HTTP reais. As respostas aparecem em linha, com códigos de status, duração e corpos formatados.

    ```json docs.json
    {
      "api": {
        "playground": {
          "display": "interactive"
        }
      }
    }
    ```
  </Tab>
  <Tab title="Simples">
    Modo somente leitura, sem botão Send. Os desenvolvedores podem preencher parâmetros e copiar exemplos de código gerados, mas não podem enviar requisições. Use este modo quando sua API exigir autenticação que você não pode compartilhar na documentação.

    ```json docs.json
    {
      "api": {
        "playground": {
          "display": "simple"
        }
      }
    }
    ```
  </Tab>
</Tabs>

## Autenticação

O playground exibe um campo de autenticação no início do formulário de parâmetros quando sua API exige autenticação, configurada por meio de `api.mdx.auth.method` em `docs.json`. Os desenvolvedores inserem a chave ou o token da API no modal.

As credenciais permanecem apenas na memória durante a sessão atual. Elas nunca são salvas em `localStorage` nem persistidas entre visitas.

## Preenchimento prévio de valores de exemplo

O playground pode pré-preencher os valores `example` dos parâmetros e dos corpos das requisições na sua especificação OpenAPI:

```json docs.json
{
  "api": {
    "examples": {
      "prefill": true
    }
  }
}
```

Assim, os desenvolvedores começam com valores realistas em vez de campos vazios.

## Substituição por página

Substitua o modo de exibição global em páginas individuais usando o campo `playground` no frontmatter:

```mdx
---
title: Create Ticket
openapi: POST /tickets
playground: interactive
---
```

Use essa opção para desativar o playground globalmente e ativá-lo em endpoints de demonstração específicos, ou vice-versa.

| Frontmatter | Comportamento |
|-------------|----------|
| `playground: interactive` | Playground completo nesta página |
| `playground: simple` | Playground apenas com código nesta página |
| `playground: none` | Sem playground nesta página |

## Como funciona

<Steps>
  <Step title="Clique em 'Try it'">
    O playground é aberto como um modal em tela cheia. A página da documentação permanece intacta ao fundo.
  </Step>
  <Step title="Preencha os parâmetros">
    Os parâmetros de caminho, consulta, cabeçalho e corpo aparecem como campos de formulário. Os campos obrigatórios são identificados. A URL base é obtida do campo `servers` da sua especificação OpenAPI.
  </Step>
  <Step title="Veja o código ser atualizado">
    Os exemplos de código são gerados novamente enquanto você digita, em cada linguagem configurada. Copie qualquer exemplo com um clique.
  </Step>
  <Step title="Envie a requisição">
    No modo interativo, clique em Send (ou pressione `Ctrl/Cmd+Enter`) para executar a requisição. A resposta aparece abaixo, com o código de status, a duração e o corpo formatado.
  </Step>
</Steps>

## Vários servidores

Um seletor de servidor aparece ao lado da URL do endpoint quando a especificação de um endpoint lista mais de uma entrada em `servers` (produção e sandbox, por exemplo). A seleção do leitor define a URL base, o botão para copiar a URL, os exemplos de código na página e a requisição enviada pelo playground.

Endpoints com apenas um servidor não exibem o seletor nem aumentam o peso da página.

## Atalhos de teclado

| Atalho | Ação |
|----------|--------|
| `Ctrl/Cmd + Enter` | Enviar requisição |
| `Escape` | Fechar o playground |

## Compatibilidade com os dois tipos de página de API

O playground funciona em páginas que usam o formato `openapi:` ou `api:` no frontmatter:

<Tabs>
  <Tab title="Páginas OpenAPI">
    O Jamdesk obtém os parâmetros e esquemas da sua especificação OpenAPI. Não é necessário configurar nada.

    ```mdx
    ---
    openapi: POST /tickets
    ---
    ```
  </Tab>
  <Tab title="Páginas MDX api:">
    Os parâmetros são extraídos dos componentes `<ParamField>`. A URL base vem de `api.mdx.server` em `docs.json`.

    ```mdx
    ---
    api: GET /tickets/{ticket_id}
    ---
    ```
  </Tab>
</Tabs>

## Desenvolvimento local

O playground funciona apenas em produção. `jamdesk dev` exibe os botões "Try it". Ao clicar em um deles, uma breve notificação aparece em vez de abrir o modal. Faça o deploy da documentação para usar o playground completo.

## Teste ao vivo

Este site está com o playground ativado. Abra a página [Exemplo de OpenAPI](/pt/api-reference/openapi-example) e clique em "Try it" para enviar uma requisição à API de demonstração.
