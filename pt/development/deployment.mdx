Faça push para a branch do GitHub conectada. Sua documentação fica online em poucos minutos.

## Implantação via CLI

Faça o deploy pelo terminal sem fazer push no GitHub. Use para iterações rápidas, testes de alterações ou projetos que não estão conectados a um repositório.

```bash
jamdesk login     # First time only
jamdesk deploy
```

A CLI empacota e envia seus arquivos. Ela mostra o progresso do build em tempo real. Use `--detach` para colocar o build na fila e encerrar imediatamente.

## O fluxo

<Steps>
  <Step title="Faça alterações localmente">
    Edite seus arquivos MDX e visualize com `jamdesk dev`.
  </Step>
  <Step title="Faça push para o GitHub">
    Faça commit e push para a branch conectada:

    ```bash
    git add .
    git commit -m "Update authentication docs"
    git push
    ```
  </Step>
  <Step title="Deploy automático">
    O Jamdesk detecta seu push e gera a documentação. Em seguida, publica tudo na CDN. A maioria dos sites termina o build em 30 a 90 segundos.
  </Step>
</Steps>

## Status da implantação

Verifique o status no dashboard, em **Deployments**:

| Status | Significado |
|--------|---------|
| **Building** | Build em andamento |
| **Deployed** | Publicado no seu domínio |
| **Failed** | Erro de build - verifique os logs |
| **Queued** | Aguardando o build anterior |

## Rebuild manual

Dispare um rebuild sem fazer push:

1. Acesse **Settings** no seu projeto
2. Clique em **Rebuild**

Use isso depois de atualizar variáveis de ambiente ou para corrigir um build travado.

## Logs de build

Abra **Deployments**, clique em um deployment e leia os logs. Erros comuns:
- Sintaxe MDX inválida
- Imagens ausentes
- Links internos quebrados
- Erros de configuração

## Rollbacks

1. Acesse **Deployments**
2. Localize o deployment que deseja restaurar
3. Clique em **Rollback**

A versão anterior volta ao ar imediatamente.
