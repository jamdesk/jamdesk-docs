Use a API de Builds para acionar reconstruções da documentação sem enviar novos commits. Isso é útil para pipelines de CI, reconstruções agendadas ou conteúdo gerado fora do diretório da sua documentação.

## Autenticação

Todas as requisições usam uma chave de API do projeto:

```http
Authorization: Bearer YOUR_API_KEY
```

Encontre sua chave de API em **Settings** → **API** do projeto.

## Acionar uma reconstrução

**POST** `https://api.jamdesk.com/projects/{project_id}/rebuild`

### Exemplo de solicitação

<CodeGroup>
```bash cURL
curl -X POST "https://api.jamdesk.com/projects/YOUR_PROJECT_ID/rebuild" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript JavaScript
const projectId = "YOUR_PROJECT_ID";
const apiKey = "YOUR_API_KEY";

const response = await fetch(
  `https://api.jamdesk.com/projects/${projectId}/rebuild`,
  {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${apiKey}`
    }
  }
);
const build = await response.json();
console.log(build.buildId, build.status);
```
</CodeGroup>

### Resposta

Requisições bem-sucedidas retornam `200 OK` com metadados do build que você pode usar para acompanhar o progresso.

```json
{
  "buildId": "build_8f3k2j",
  "status": "queued",
  "createdAt": "2026-02-05T10:30:00Z",
  "commit": {
    "sha": "a1b2c3d",
    "message": "Update API docs",
    "author": "jane@example.com"
  },
  "project": {
    "id": "proj_abc123",
    "name": "My Docs"
  }
}
```

<Note>
Se você receber uma resposta `429`, tente novamente com backoff exponencial. Entre em contato com o suporte se precisar de limites maiores.
</Note>

### Campos da resposta

<ResponseField name="buildId" type="string">
  Identificador único do build. Use-o para referenciar o build no dashboard.
</ResponseField>

<ResponseField name="status" type="string">
  Status atual do build. Um de: `queued`, `building`, `deployed`, `failed`.
</ResponseField>

<ResponseField name="createdAt" type="string">
  Timestamp ISO 8601 de quando o build foi criado.
</ResponseField>

<ResponseField name="commit.sha" type="string">
  Hash curto do commit que acionou o build.
</ResponseField>

<ResponseField name="commit.message" type="string">
  Mensagem do commit no repositório de origem.
</ResponseField>

<ResponseField name="commit.author" type="string">
  Endereço de e-mail do autor do commit.
</ResponseField>

<ResponseField name="project.id" type="string">
  Identificador do projeto correspondente ao seu projeto no dashboard.
</ResponseField>

<ResponseField name="project.name" type="string">
  Nome de exibição do projeto.
</ResponseField>

## Acompanhar o status do build

O status do build fica visível no dashboard, em **Deployments**. Cada build passa por estas etapas:

1. **queued**: o build está aguardando na fila.
2. **building**: o serviço de build está compilando sua documentação.
3. **deployed**: o build foi concluído e seu site está no ar.
4. **failed**: algo deu errado. Verifique os logs do build para mais detalhes.

Se o seu repositório estiver conectado ao GitHub, as verificações de status do commit são atualizadas automaticamente. Um check verde aparece no commit quando o build é publicado. Um X vermelho aparece se o build falhar. Você não precisa consultar a API para obter atualizações de status.

## Formato da resposta de erro

As respostas de erro seguem uma estrutura consistente:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API key",
    "status": 401
  }
}
```

<ResponseField name="error.code" type="string">
  Código de erro legível por máquina. Veja a tabela abaixo para os valores possíveis.
</ResponseField>

<ResponseField name="error.message" type="string">
  Descrição legível por humanos do que deu errado.
</ResponseField>

<ResponseField name="error.status" type="number">
  Código de status HTTP correspondente ao status da resposta.
</ResponseField>

### Códigos de erro

| Status | Código | Mensagem | Correção |
|--------|------|---------|-----|
| **401** | `unauthorized` | Invalid API key | Gere novamente a chave em **Settings** → **API** |
| **403** | `forbidden` | Unauthorized project access | Confirme que o ID do projeto corresponde ao projeto da chave de API |
| **404** | `project_not_found` | Project not found | Verifique o ID do projeto no dashboard |
| **429** | `rate_limited` | Too many requests | Aguarde e tente novamente com backoff exponencial |
| **500** | `internal_error` | Internal server error | Tente novamente após alguns segundos. Entre em contato com o suporte se persistir |
