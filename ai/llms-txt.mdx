AI tools like ChatGPT, Claude, or Copilot give accurate answers about your product only with structured access to your docs. Their training data isn't enough.

Every Jamdesk site generates `llms.txt` and `llms-full.txt` following the [llmstxt.org](https://llmstxt.org) spec. AI tools read these files instead of crawling individual pages.

<Note>
  Google now audits `llms.txt` as part of [Lighthouse's agentic browsing checks](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt). Sites that publish a valid `llms.txt` are easier for AI agents to discover. Google also uses it more and more when ranking content for AI-powered answers. Jamdesk publishes it for free.
</Note>

<Tip>
  **Check your score.** The free [AI Score](https://jamdesk.com/ai-score) tool grades how agent-ready any docs site is. A valid `llms.txt` is one of the first things it checks. The [AI Score Chrome extension](https://chromewebstore.google.com/detail/jamdesk-ai-score/mhihkkgpcbmapmojnakhjfhjmiagkhlj) grades sites as you browse.
</Tip>

## What Jamdesk Generates

| File | Content |
|------|---------|
| `llms.txt` | Page titles, descriptions, and URLs (a structured table of contents) |
| `llms-full.txt` | Complete documentation content in a single file |

Jamdesk generates the files at build time. It serves them from the same CDN as your docs.

## Verify Your Files

Check that your files exist after your first build:

<Tabs>
  <Tab title="Root domain">
    If your docs are at the root of your domain (e.g., `docs.acme.com` or `acme.jamdesk.app`):

    ```bash
    curl https://docs.acme.com/llms.txt
    curl https://docs.acme.com/llms-full.txt
    ```
  </Tab>
  <Tab title="/docs subpath">
    If your docs are under `/docs` on your main site (like this site at `jamdesk.com/docs`):

    ```bash
    curl https://jamdesk.com/docs/llms.txt
    curl https://jamdesk.com/docs/llms-full.txt
    ```
  </Tab>
</Tabs>

## File Format

The `llms.txt` file lists every page with its title, description, and URL, grouped into sections that mirror your navigation:

```text
# Your Project Documentation

> Documentation for Your Project

## Get Started

- [Getting Started](https://your-project.jamdesk.app/getting-started): Set up your first project in 5 minutes
- [Configuration](https://your-project.jamdesk.app/configuration): Configure your project settings

## API Reference

- [Authentication](https://your-project.jamdesk.app/authentication): How to authenticate API requests
```

The `llms-full.txt` file contains the complete Markdown content of every page, concatenated with page boundaries marked by headings.

## Structure

`llms.txt` follows the [llmstxt.org](https://llmstxt.org/) proposal: an H1 title,
a blockquote summary, and your navigation tabs and groups as `##` sections of
Markdown links.

## Multilingual Sites

Sites with more than one language get a separate set of files per
language. An AI tool can fetch only the language it needs. For a site in
English (the default) and French:

| URL | Content |
|-----|---------|
| `/llms.txt` | English index, with links to every other language's index at the end |
| `/en/llms.txt` | Same file as `/llms.txt` |
| `/fr/llms.txt` | French index, linking back to the other languages |
| `/llms-full.txt` | Full content of every language, one after another |
| `/en/llms-full.txt` | Full content of the English pages only |
| `/fr/llms-full.txt` | Full content of the French pages only |

The root `llms-full.txt` keeps every language. Tools that already read it
see no change. Point an agent at a language's own file when it only needs that
language:

```bash
curl https://jamdesk.com/docs/fr/llms-full.txt
```

A language gets its own files once it has at least one page. Single-language
sites keep only the root files.

## Agent directive on every page

Every page carries an invisible, screen-reader-silent note that points AI
agents at `llms.txt`. Every Markdown export starts with a blockquote linking
the index. Agents that land on your HTML find the Markdown path
without crawling.

## How It's Built

- Generated at build time alongside your HTML
- Served from CDN with the same cache policy as your docs
- Updates automatically on every build
- No configuration needed. Every page is included by default

## Turning Off llms.txt

Jamdesk publishes `llms.txt` and `llms-full.txt` by default. Set `seo.ai.llmsTxt` to `false` in `docs.json` to stop generating them, for example to keep AI tools from ingesting your content:

```json docs.json
{
  "seo": {
    "ai": {
      "llmsTxt": false
    }
  }
}
```

Jamdesk skips the files on your next build, including every per-language copy. The live `/llms.txt` and `/llms-full.txt` URLs return `404`.

<Note>
  **AI ingestion and search indexing are separate controls.** `seo.ai.llmsTxt` controls only the `llms.txt`/`llms-full.txt` files that AI tools read. It does not change how search engines index your site. [`robots` metadata and per-page `noindex`](/content/seo#controlling-indexing) control indexing. A page can be indexed by Google while excluded from AI ingestion, or the reverse.
</Note>

## AI Crawlers

Jamdesk's default `robots.txt` allows all major AI crawlers (Claude, ChatGPT, Copilot, Gemini).

<Accordion title="How llms.txt differs from sitemap.xml">
  `sitemap.xml` lists URLs for search engines to crawl and index. It has no content, only links and metadata like last-modified dates.

  `llms.txt` is for AI models. It has page titles, descriptions, and (in `llms-full.txt`) the page content. AI tools read the full file in one HTTP request instead of many.
</Accordion>
