Common questions about pricing, builds, domains, and features.

## Getting Started

<AccordionGroup>
  <Accordion title="What is Jamdesk?">
    Jamdesk is a documentation platform that builds docs sites from your Markdown files. Write in MDX and push to GitHub. Your site deploys with search, analytics, and an `llms.txt` file for AI tools.
  </Accordion>

  <Accordion title="Do I need to know how to code?">
    No. MDX is plain text with simple formatting. Components are optional.
  </Accordion>

  <Accordion title="Can I try Jamdesk for free?">
    Yes. We offer a 14-day free trial with every feature.
  </Accordion>

  <Accordion title="What's the difference between Jamdesk and other docs platforms?">
    Your docs are plain MDX files in a GitHub repo, not locked in a proprietary editor. Push to GitHub and your site deploys in under 60 seconds. There is no build configuration or CI/CD pipeline to set up. Every site gets `llms.txt` and an MCP server. AI tools like Claude and ChatGPT can read your current docs directly. Visitors get a built-in [AI chat assistant](/ai/chat) that answers questions from your docs.
  </Accordion>
</AccordionGroup>

## Builds & Deployment

<AccordionGroup>
  <Accordion title="How long do builds take?">
    Most documentation sites build in 30-60 seconds. Larger sites with many pages may take longer.
  </Accordion>

  <Accordion title="Can I preview changes before publishing?">
    Yes. Preview locally with hot reload using the Jamdesk CLI (`jamdesk dev`). Changes go live only when you push to GitHub or run `jamdesk deploy`.
  </Accordion>

  <Accordion title="Can I deploy without GitHub?">
    Yes. Run `jamdesk deploy` from your project directory. The CLI packages and uploads your files, then triggers a build. No Git repo required. See the [CLI Deploy guide](/cli/deploy) for details.
  </Accordion>

  <Accordion title="What triggers a build?">
    A push to your connected GitHub branch. You can also trigger a build from the dashboard, or with `jamdesk deploy` from the CLI.
  </Accordion>

  <Accordion title="Can I roll back to a previous version?">
    Yes. Go to **Deployments** in your project. Find the previous build and click **Rollback**.
  </Accordion>
</AccordionGroup>

## Custom Domains

<AccordionGroup>
  <Accordion title="Can I use my own domain?">
    Yes. Add a custom domain in **Settings** → **Domains**. Jamdesk provisions the SSL certificate.
  </Accordion>

  <Accordion title="How long does DNS propagation take?">
    Usually a few hours. It can take up to 48 hours.
  </Accordion>

  <Accordion title="Can I host docs at a subpath like /docs?">
    Yes. Use a reverse proxy (Cloudflare, AWS, nginx) to serve Jamdesk at a subpath. See [Subpath Hosting](/deploy/subpath-hosting).
  </Accordion>
</AccordionGroup>

## Teams & Collaboration

<AccordionGroup>
  <Accordion title="How do I invite a team member?">
    Open your project and go to **Settings** → **Members**. Type the person's email in the **Invite Member** field and click **Invite**. They get an email with a link to join the project.

    <Frame>
      <img src="/images/dashboard/settings-team.webp" alt="Members tab in project settings showing the Invite Member field and the current member list" style={{ display: 'block', margin: '0 auto' }} />
    </Frame>

    Invitees need a Jamdesk account. The invite prompts them to create one if they don't have it. Already a member, but the invite link says it's "already been accepted"? Sign in. You'll land back in the project. See [Team Members](/help/projects/team-members) for roles and member limits.
  </Accordion>

  <Accordion title="How many team members can I have?">
    Unlimited, on every plan, at no extra charge.
  </Accordion>

  <Accordion title="Can team members edit documentation?">
    Team members can view builds and trigger rebuilds. Editing happens in your GitHub repository. Anyone with repository access can edit the docs.
  </Accordion>

  <Accordion title="How do I transfer project ownership?">
    Go to **Settings** → **Members**. Click **Transfer Ownership** next to the member you want to promote. The new owner must be an existing team member.
  </Accordion>
</AccordionGroup>

## CLI

<AccordionGroup>
  <Accordion title="Where are my CLI credentials stored?">
    In `~/.jamdeskrc`, a JSON file with `0600` permissions (only your user can read it). It stores your refresh token, email, and user ID. Run `jamdesk logout` to clear it.
  </Accordion>

  <Accordion title='Why does the CLI say "session expired"?'>
    Your refresh token is no longer valid. This happens after password changes, account deletions, or extended inactivity. Run `jamdesk login` to get a fresh session.
  </Accordion>

  <Accordion title="Can I use the CLI in CI/CD pipelines?">
    Yes. The browser-based login won't work in headless environments. Log in on your local machine. Copy `~/.jamdeskrc` to your CI runner. The refresh token authenticates from there.
  </Accordion>

  <Accordion title="How do I fix broken links automatically?">
    Run `jamdesk fix`. It repairs broken internal links that have one clear correct target (typo'd anchors and cross-locale anchor drift). It edits your local `.mdx` files after a preview. See the planned changes first with `jamdesk fix --dry-run`. It touches only links whose corrected anchor is a real heading. Ambiguous cases stay for manual review. See [Auto-fix broken links](/cli/fix-broken-links).
  </Accordion>
</AccordionGroup>

## Content & Features

<AccordionGroup>
  <Accordion title="What file formats are supported?">
    MDX (Markdown + JSX) and standard Markdown files.
  </Accordion>

  <Accordion title="Can I use custom React components?">
    Yes. Define inline components in MDX with `export const`, or create reusable components in the `/snippets` directory. For interactive components with hooks, use `.tsx` files with `'use client'`. See [Custom React Components](/content/react-components) and [Snippets](/content/snippets).
  </Accordion>

  <Accordion title="Is there a page limit?">
    No hard limit. Sites with hundreds of pages build and run fine.
  </Accordion>

  <Accordion title="Does Jamdesk support multiple languages?">
    Yes. Add a language switcher with the `languages` property in your navigation config. Each language gets its own navigation structure and content. See [Multi-Language Support](/setup/languages).
  </Accordion>

  <Accordion title="Does Jamdesk translate my content automatically?">
    No. You provide the translated MDX files. Jamdesk builds the routing, navigation, language switcher, and RTL styling. Bring translations from your own workflow (human translators, machine translation, or an LLM). Place them in language-prefixed directories (`es/`, `fr/`, etc.). See [Multi-Language Support](/setup/languages) for the directory layout and config.
  </Accordion>
</AccordionGroup>

## AI Chat

<AccordionGroup>
  <Accordion title="Does my docs site have AI chat?">
    Yes. Every Jamdesk site includes a built-in chat assistant that answers visitor questions from your documentation. It's on by default. See [AI Chat](/ai/chat) for details.
  </Accordion>

  <Accordion title="Does AI chat cost extra?">
    No. AI chat is included on every plan.
  </Accordion>

  <Accordion title="Can I turn off the AI chat?">
    Yes. Set `chat.enabled` to `false` in your `docs.json`:

    ```json
    { "chat": { "enabled": false } }
    ```

    Your next build removes the chat panel and keyboard shortcut.
  </Accordion>

  <Accordion title="What data does the chat use to answer questions?">
    Only your published documentation pages. Each build indexes your content into a vector database. Jamdesk retrieves the sections relevant to a visitor's question and sends them to Claude as context. The AI cannot access data outside your docs.
  </Accordion>
</AccordionGroup>

## Privacy & Access

<AccordionGroup>
  <Accordion title="Can I have public and private docs in the same site?">
    Yes. Mark internal pages with `private: true` in frontmatter, or list their paths under `auth.password.private[]` in `docs.json`. Private pages show an unlock screen. Every page stays in one project, with one repo and one build. See [Access Control](/setup/access-control) and [Password Protection](/setup/password-protection).
  </Accordion>

  <Accordion title="How do I lock my entire docs site behind a password?">
    Set `auth.password.enabled: true` in `docs.json` and push the change. Set a password in **Project Settings → Password Protection** in the dashboard. Visitors see an unlock screen until they enter it. See [Password Protection](/setup/password-protection).
  </Accordion>

  <Accordion title="Can readers log in with their own account instead of a shared password?">
    Yes, on Enterprise plans. Single Sign-On lets readers authenticate against your identity provider (Okta, Google Workspace, Azure AD, etc.) with no shared passwords, a full audit trail, and instant deprovisioning. See [SSO](/setup/sso) or [contact Enterprise sales](https://jamdesk.com/pricing).
  </Accordion>

  <Accordion title="Should I split internal and external docs into two projects?">
    Usually no. Use one project with `private: true` on the internal pages. You keep one repo and one dashboard. Use two projects only when the audiences need separate branding, custom domains, or analytics. See [Access Control](/setup/access-control) for the patterns.
  </Accordion>

  <Accordion title="What's the difference between an editor and a reader?">
    **Editors** write the docs by committing MDX to your connected GitHub repo. A push builds only if the person who pushed is a member of the Jamdesk project or an automation account you've authorized. **Readers** view the published site: everyone (public), anyone with the password (password mode), or anyone signed in via your IdP (SSO). **Dashboard team members** control builds, analytics, and settings. Membership also lets their pushes build. See [Access Control](/setup/access-control).
  </Accordion>
</AccordionGroup>
